Cloud Storage buckets: storage classes, locations, lifecycle rules and Object Versioning

▶ Watch the overview video

Last reviewed September 25, 2026

Cloud Storage stores objects (files and their metadata) in buckets. Bucket names are globally unique. You create a bucket with gcloud storage buckets create gs://my-bucket --location=us-central1 --default-storage-class=STANDARD, and you choose its location when you create it; you can't change a bucket's location later.

Locations come in three kinds. A region, such as us-central1, keeps data in one region at the lowest cost, good for data used by compute in that region. A dual-region, such as a predefined pair of regions or a configurable pair, keeps data in two regions for higher availability. A multi-region, such as US, EU or ASIA, spreads data across a large geographic area for content served widely.

Storage classes trade storage price against access cost. Standard is for frequently accessed (hot) data and has no minimum storage duration. Nearline is for data accessed about once a month or less, with a 30-day minimum storage duration. Coldline is for data accessed about once a quarter or less, with a 90-day minimum. Archive is for data accessed less than once a year, such as long-term compliance archives, with a 365-day minimum. Colder classes charge retrieval fees and early-deletion charges if you delete data before the minimum. Unlike some other clouds' archive tiers, all classes have the same fast access (milliseconds) when you do read. Autoclass can move objects between classes automatically based on access.

Object Lifecycle Management applies rules to objects automatically. Each rule has an action, such as SetStorageClass or Delete, and conditions, such as age in days, creation date, storage class, or number of newer versions. A typical policy moves objects to Coldline after 90 days and deletes them after 3 years.

Object Versioning keeps a noncurrent version whenever a live object is overwritten or deleted, so you can restore it. Noncurrent versions are billed as storage, so combine versioning with a lifecycle rule that deletes old versions after some time. Soft delete additionally retains deleted objects for a retention period. A retention policy, which can be locked with Bucket Lock, does the opposite of a lifecycle delete: it prevents objects from being deleted or overwritten until they reach a certain age, for compliance.

Key terms

Storage class
The Standard, Nearline, Coldline or Archive setting that sets storage price, access cost and minimum duration.
Lifecycle rule
An automatic action, such as changing class or deleting, applied when an object meets conditions.
Object Versioning
A bucket setting that keeps noncurrent versions of overwritten or deleted objects.
Retention policy
A minimum time objects must be kept before they can be deleted or replaced, lockable with Bucket Lock.
Real-world example

A hospital stores scanned records in a regional bucket in Standard class. A lifecycle rule moves objects to Coldline after 90 days and Archive after one year, and a locked retention policy guarantees nothing can be deleted for 7 years, satisfying the regulator.

Exam tip: Match access frequency to the class: monthly is Nearline, quarterly is Coldline, yearly or less is Archive. Remember the 30, 90 and 365-day minimums, and that a bucket's location can't be changed later.

Check yourself

Which class suits backups that are read about once a quarter?

Coldline, which has a 90-day minimum storage duration.

What happens when you overwrite an object in a bucket with versioning on?

The previous content becomes a noncurrent version that you can restore.
