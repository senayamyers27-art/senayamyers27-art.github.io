Google Cloud Associate Cloud Engineer Associate Cloud Engineer · Domain 2: Planning and implementing a cloud solution

Choosing a compute option: Compute Engine, GKE, Cloud Run, Cloud Run functions and App Engine

▶ Watch the overview video

Last reviewed September 25, 2026

Google Cloud offers a spectrum of compute services, from full control to fully managed. A large share of exam questions come down to picking the right one, so learn what each is for and what it takes off your plate.

Compute Engine is infrastructure as a service (IaaS): virtual machines where you choose the machine type, OS image and disks and you manage the operating system. Choose it for lift-and-shift migrations, software that needs a specific OS, kernel module or license, long-running stateful servers, or when you need GPUs with full control. Managed instance groups add autoscaling and self-healing.

Google Kubernetes Engine (GKE) is managed Kubernetes. Google runs the control plane; you deploy containers using Kubernetes objects such as Deployments and Services. Choose it for containerized microservices that need Kubernetes features, portability, fine control over networking and scheduling, or many services on shared capacity. Autopilot mode removes node management; Standard mode gives you control over nodes.

Cloud Run is a serverless platform for containers. You give it a container image that listens for HTTP requests (a service) or runs to completion (a job), and Google handles servers, scaling (including to zero) and HTTPS endpoints. You pay for resources used while handling requests (or for instance time, depending on billing settings). Choose it for stateless web apps and APIs with variable traffic when you don't need Kubernetes. Cloud Run functions (formerly Cloud Functions) let you deploy just a function in a supported language, triggered by HTTP or by events such as a file uploaded to Cloud Storage or a Pub/Sub message; they run on Cloud Run infrastructure.

App Engine is Google's original platform as a service (PaaS) for web apps. The standard environment runs apps in language-specific sandboxes and can scale to zero; the flexible environment runs apps in containers on managed VMs. Each project can have one App Engine application, in one region chosen at creation. New projects are generally steered toward Cloud Run, but App Engine still appears in exam scenarios, for example traffic splitting between versions.

A useful rule: the less you want to manage, the further toward Cloud Run and functions you go; the more control or special OS requirements you have, the further toward Compute Engine.

Key terms

Compute Engine
Google Cloud's IaaS virtual machines, where you manage the operating system.
GKE
Google Kubernetes Engine, a managed Kubernetes service for running containers.
Cloud Run
A serverless platform that runs stateless containers and scales automatically, including to zero.
Cloud Run functions
Event-driven or HTTP-triggered functions deployed as source code, formerly Cloud Functions.
Real-world example

A company moves a legacy ERP server that needs a licensed agent to Compute Engine, runs its 30 microservices on GKE Autopilot, hosts a marketing API with bursty traffic on Cloud Run, and uses a Cloud Run function to generate thumbnails whenever an image lands in a bucket.

Exam tip: Keywords decide it: 'kernel', 'OS control', 'license' mean Compute Engine; 'Kubernetes' or 'Helm' mean GKE; 'stateless container, scale to zero, no infrastructure' means Cloud Run; 'run code when a file is uploaded' means Cloud Run functions.

Check yourself

Which service fits a stateless HTTP container that should cost nothing when idle?

Cloud Run, because it scales to zero and needs no servers or clusters.

How many App Engine applications can a project have?

One, and its region can't be changed after creation.
