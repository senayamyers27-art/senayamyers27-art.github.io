Installing and configuring the Google Cloud CLI: gcloud init, named configurations, default project, region and zone

▶ Watch the overview video

Last reviewed September 25, 2026

The Google Cloud CLI is the command-line toolset for Google Cloud. It includes gcloud for most services, gsutil (the older Cloud Storage tool, now largely replaced by gcloud storage), and bq for BigQuery, and it can install extra components such as kubectl. You can install it on Linux, macOS or Windows, and it comes preinstalled in Cloud Shell.

After installing, run gcloud init. It opens a browser to authorize your user account, then creates or updates a configuration and asks you to pick a default project and, optionally, a default region and zone. gcloud auth login authorizes a user account without the rest of the setup, and gcloud auth list shows which accounts are credentialed and which is active. Keep in mind that gcloud auth application-default login is different: it creates Application Default Credentials used by client libraries in your code, not by gcloud itself.

A configuration is a named set of properties. The main ones are core/account, core/project, compute/region and compute/zone. You set them with gcloud config set project my-proj or gcloud config set compute/zone us-central1-a, and view them with gcloud config list. If a command needs a zone and none is set or passed with --zone, gcloud will prompt you or fail.

Named configurations are how professionals avoid running commands in the wrong place. gcloud config configurations create prod creates and activates a new configuration; you then set its account, project and defaults. gcloud config configurations activate dev switches back, and gcloud config configurations list shows them all with the active one marked. You can also override for a single command with flags such as --project and --configuration.

Keep the CLI current with gcloud components update (on package-manager installs, update through the package manager instead). Many new features appear first under gcloud beta or gcloud alpha command groups, which need their components installed.

Key terms

gcloud init
An interactive command that authorizes an account and sets up a configuration with defaults.
Named configuration
A saved set of gcloud properties, such as account, project, region and zone, that you can switch between.
Application Default Credentials
Credentials that client libraries find automatically; set locally with gcloud auth application-default login.
gcloud config set
The command to set a property, such as compute/zone, in the active configuration.
Real-world example

An engineer supports two customers. She creates configurations named acme and globex, each with its own account, project and region. Before a change she runs gcloud config configurations activate acme, and her shell prompt shows the active configuration, so she never deploys to the wrong customer.

Exam tip: Know the exact syntax: gcloud config set compute/zone ZONE, gcloud config set project ID and gcloud config configurations activate NAME. Distractors often invent commands like gcloud compute zones set.

Check yourself

What does gcloud config configurations create do?

It creates a new named configuration and makes it active, so you can set its properties.

How is gcloud auth application-default login different from gcloud auth login?

The first creates credentials for client libraries in your code; the second authorizes the gcloud CLI itself.
