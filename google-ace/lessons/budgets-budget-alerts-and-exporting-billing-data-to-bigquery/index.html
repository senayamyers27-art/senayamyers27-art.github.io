Budgets, budget alerts and exporting billing data to BigQuery

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Cloud Billing gives you several ways to watch spending. Reports in the console show cost trends by project, service, SKU, label and time. For proactive control you create budgets, and for deep analysis you export billing data to BigQuery.

A budget is set on a billing account and can be scoped to all of it or to selected projects, services or labels. You give it an amount, either a fixed number or last month's spend, and threshold rules such as 50%, 90% and 100%. Thresholds can be based on actual spend or forecasted spend, so you can be warned before a month ends over budget. When a threshold is crossed, billing admins and users get email alerts, and you can also send alerts to Cloud Monitoring notification channels or publish them to a Pub/Sub topic.

The most important fact about budgets: they don't cap spending. A budget never stops a VM or disables billing on its own. If you need automatic action, for example turning off a sandbox project's billing when it reaches its limit, you publish budget notifications to Pub/Sub and trigger your own code, such as a Cloud Run function, to take that action. Also note that billing data isn't real time; there can be a delay of hours before usage appears.

Billing export to BigQuery writes detailed rows of cost and usage data to a dataset you choose, on an ongoing basis. There are standard usage cost data, detailed usage cost data (with resource-level detail) and pricing data exports. Once enabled, you can write SQL to break down cost by project, service, label or day and build dashboards in Looker Studio. The export only includes data from when you enable it onward, so turn it on early. You need a role such as Billing Account Costs Manager or Administrator to configure it, plus permissions on the dataset.

Labels make these reports useful. Consistent keys such as env, team and app, applied to resources, flow into billing data so you can answer 'what does the checkout app cost' across shared projects.

Key terms

Budget
An amount and set of threshold rules that trigger alerts as actual or forecasted spend grows.
Threshold rule
A percentage of the budget that sends a notification when crossed.
Billing export
A continuous feed of detailed Cloud Billing data into a BigQuery dataset.
Forecasted spend
Google's estimate of what the month's total will be, which budgets can alert on.
Real-world example

A university gives each research lab a project with a $200 budget alerting at 50%, 90% and 100% of forecasted spend. Alerts publish to Pub/Sub, and a small function emails the lab lead. Finance also exports billing data to BigQuery and runs a monthly query grouped by the lab label.

Exam tip: If a question expects spending to stop automatically, a budget alone is wrong; it needs Pub/Sub notifications and code. For SQL analysis of costs, the answer is billing export to BigQuery, not audit logs.

Check yourself

Does a budget stop resources when it reaches 100%?

No. It sends alerts. Automatic action requires handling Pub/Sub notifications with your own code.

When does billing export start including data?

From the time you enable it; it doesn't backfill all history, so enable it early.
