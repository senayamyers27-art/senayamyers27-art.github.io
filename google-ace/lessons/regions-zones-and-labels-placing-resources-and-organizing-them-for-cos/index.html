Regions, zones and labels: placing resources and organizing them for cost reporting

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Google Cloud infrastructure is divided into regions and zones. A region is a specific geographic location, such as us-central1 (Iowa), europe-west1 (Belgium) or asia-northeast1 (Tokyo). Each region contains several zones, such as us-central1-a, us-central1-b and us-central1-c. A zone is an isolated deployment area with its own power, cooling and networking, so a failure in one zone shouldn't affect others in the same region.

Resources have a scope that affects how you design for availability. Zonal resources, such as a VM or a zonal persistent disk, live in one zone. Regional resources, such as a regional managed instance group, a regional persistent disk, a regional GKE cluster or a Cloud SQL instance with high availability, span zones in one region. Global resources, such as VPC networks, firewall rules, global load balancers and images, aren't tied to one region. Cloud Storage adds multi-region and dual-region locations.

When choosing a region, think about latency to users, data residency and compliance, availability of the products and machine types you need, and price, which varies by region. For resilience, spread workloads across multiple zones; for disaster recovery, consider a second region.

Labels are key-value pairs, such as env=prod or team=payments, that you attach to resources like VMs, disks, buckets and projects. They're used to organize, filter and, most importantly, break down costs, because labels appear in billing reports and in the BigQuery billing export. Keys and values must be lowercase and follow simple character rules. Set them in the console or with commands such as gcloud compute instances update web-1 --update-labels=env=prod.

Don't confuse labels with network tags. Network tags are plain strings on VMs used to target firewall rules and routes. There are also resource manager tags, which are defined centrally at the organization or project level and can be used in IAM conditions and organization policies. For cost reporting across apps, the usual answer is labels.

Key terms

Region
An independent geographic area, such as us-central1, made up of zones.
Zone
An isolated deployment area within a region, such as us-central1-a.
Label
A key-value pair on a resource used to organize, filter and report costs.
Network tag
A string on a VM used to apply firewall rules and routes to it.
Real-world example

A media company runs its video API on instances in three zones of europe-west4 so a zone outage doesn't take it down. Every resource carries labels app=video and env=prod, so finance can see the app's monthly cost in the billing export even though it shares projects with other apps.

Exam tip: Zone failure means spread across zones in a region; region failure means another region. For cost by application, choose labels, not network tags.

Check yourself

Name a global, a regional and a zonal resource.

Global: a VPC network. Regional: a subnet or regional persistent disk. Zonal: a VM instance.

What are network tags used for?

Targeting firewall rules and routes to specific VMs.
