Quotas: viewing usage, understanding quota errors and requesting increases

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Quotas protect both you and Google Cloud from unexpected usage. They limit how much of a resource a project can use (allocation quotas, such as the number of CPUs in a region or the number of static IP addresses) or how often you can call an API (rate quotas, such as requests per minute). Separately, system limits are fixed values that can't be raised, such as the maximum size of a single object or disk.

Many Compute Engine quotas are regional. The CPUS quota in us-central1 is separate from europe-west1, and there are separate quotas for specific families, GPUs, Spot and preemptible capacity, persistent disk capacity, and in-use IP addresses. So a deployment can fail in one region while it would succeed in another. New projects and free trial accounts start with conservative quotas.

When a request would exceed a quota, it fails with a message such as Quota 'CPUS' exceeded. Limit: 24.0 in region us-central1. API rate quota errors usually return HTTP 429 (Too Many Requests) or RESOURCE_EXHAUSTED. Read the message carefully; it names the metric and region, which tells you exactly which quota to raise.

To view and manage quotas, go to IAM and admin > Quotas and system limits in the console (or open a service's Quotas tab). You can filter by service, metric and region and see current usage against each limit. To raise one, select it, choose Edit quota, enter the new value and a justification, and submit. Some increases are granted automatically within minutes; others are reviewed and may take longer, so plan ahead of big launches. You need a role that includes serviceusage.quotas.update, such as Quota Administrator or Owner.

You can also set lower quotas yourself, for example capping an API's requests per day to control cost, and you can create Cloud Monitoring alerts on quota usage so you're warned before hitting a limit.

Key terms

Allocation quota
A limit on how much of a resource a project can hold, such as regional CPUs.
Rate quota
A limit on how many API requests can be made in a time period.
System limit
A fixed maximum that can't be increased by request.
Quota increase request
A request made from the Quotas page to raise a limit, sometimes approved automatically.
Real-world example

A team plans a 200-VM load test in us-east1. A week before, they check the Quotas page, see a CPUS limit that is too low for their machine type, and request an increase with a short justification. The request is approved before the test, avoiding a launch-day failure.

Exam tip: Quota errors are fixed by requesting an increase for the named metric and region (or deploying elsewhere). Re-enabling APIs, changing IAM or moving folders doesn't change quotas.

Check yourself

Are Compute Engine CPU quotas global or regional?

Mostly regional; each region has its own CPU quota.

Which HTTP status often indicates a rate quota was exceeded?

429 Too Many Requests (RESOURCE_EXHAUSTED).
