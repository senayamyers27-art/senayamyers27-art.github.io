Load balancing, Cloud NAT and hybrid connectivity with Cloud VPN and Cloud Interconnect

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Cloud Load Balancing is a family of managed load balancers. Pick one by asking three questions: is the traffic HTTP(S) (layer 7) or other TCP/UDP (layer 4), is it from the internet (external) or from inside your network (internal), and is it global or regional?

Application Load Balancers are layer 7 proxies for HTTP and HTTPS. The global external Application Load Balancer gives one anycast IP address worldwide, routes by host and path with URL maps, terminates TLS with Google-managed or your own certificates, and integrates with Cloud CDN and Cloud Armor. Regional external and internal Application Load Balancers serve traffic in one region. Network Load Balancers are layer 4. Proxy Network Load Balancers terminate TCP (optionally with TLS offload); passthrough Network Load Balancers forward packets without proxying, so backends see the original client IP, and they support TCP, UDP and other protocols. Internal passthrough Network Load Balancers distribute traffic inside a VPC.

All of them use health checks and backend services pointing at managed instance groups, network endpoint groups (for GKE pods or serverless services like Cloud Run), or buckets for static content.

Cloud NAT provides outbound internet access for resources without external IP addresses, such as private VMs and GKE nodes, while blocking unsolicited inbound connections. It's configured per region on a Cloud Router and doesn't use a proxy VM. Private Google Access, a subnet setting, lets VMs without external IPs reach Google APIs such as Cloud Storage without NAT.

To connect on-premises networks, Cloud VPN creates IPsec tunnels over the internet. HA VPN uses two interfaces and, with two tunnels configured correctly, offers a 99.99% availability SLA; it uses Cloud Router to exchange routes dynamically with BGP. VPN is quick to set up but limited by internet performance. Cloud Interconnect provides private, high-bandwidth connections: Dedicated Interconnect is a direct physical link to Google in a colocation facility, and Partner Interconnect goes through a service provider when you can't reach a Google facility or need less bandwidth. Interconnect traffic doesn't cross the public internet, but it isn't encrypted by default. Direct and carrier peering reach Google's public services, such as Workspace, not your VPC.

Key terms

Application Load Balancer
A layer 7 proxy load balancer for HTTP(S) with URL-based routing.
Passthrough Network Load Balancer
A layer 4 load balancer that forwards packets and preserves client IP addresses.
Cloud NAT
Managed network address translation that gives private resources outbound internet access.
HA VPN
Highly available IPsec VPN to Google Cloud using two interfaces and BGP through Cloud Router.
Real-world example

A retailer serves its storefront through a global external Application Load Balancer with Cloud CDN, runs back-end VMs without external IPs that download updates through Cloud NAT, and connects its warehouses over HA VPN while a Partner Interconnect is being provisioned.

Exam tip: HTTP(S) plus global plus URL routing or CDN: global external Application Load Balancer. Private VMs needing outbound internet: Cloud NAT. Fast to set up over the internet: HA VPN. Private, high bandwidth: Interconnect.

Check yourself

Which load balancers preserve the client's source IP to the backend?

Passthrough Network Load Balancers, because they don't proxy connections.

What does Cloud NAT need to be configured on?

A Cloud Router in the region where the private resources are.
