Google Kubernetes Engine clusters: Autopilot vs Standard, zonal vs regional, and node pools

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

A GKE cluster has a control plane, which runs the Kubernetes API server, scheduler and controllers, and nodes, which are Compute Engine VMs that run your pods. Google always manages the control plane. What differs between cluster modes is who manages the nodes.

In Autopilot mode, Google provisions, scales, secures and upgrades nodes for you. You deploy workloads, and GKE creates the right capacity based on each pod's resource requests. You're billed mainly for the CPU, memory and storage your pods request, not for whole nodes. Autopilot applies security best practices and restricts some low-level settings, such as privileged containers. It's Google's recommended mode for most workloads. Create one with gcloud container clusters create-auto my-cluster --region=us-central1.

In Standard mode, you manage node pools: you choose machine types, node counts, autoscaling, and settings such as Spot VMs or GPUs, and you pay for the node VMs whether pods use them or not. Choose Standard when you need that control, for example specific machine types or node-level configuration. Create one with gcloud container clusters create my-cluster --zone=us-central1-a --num-nodes=3.

Clusters also have a location type. A zonal cluster has a single control plane in one zone, and nodes in that zone (or several zones for a multi-zonal cluster). If that zone fails, you can't manage the cluster, and control plane upgrades cause short API unavailability. A regional cluster runs control plane replicas in multiple zones of a region and, by default, nodes in three zones, so it survives a zone outage. Autopilot clusters are always regional. Note that --num-nodes in a regional Standard cluster is per zone, so 1 means three nodes in total.

A node pool is a group of nodes with the same configuration within a Standard cluster. You can add pools with different machine types (for example a GPU pool or a high-memory pool) with gcloud container node-pools create, and steer pods to them with node selectors, node affinity or taints and tolerations. Cluster autoscaler can add and remove nodes per pool. Private clusters give nodes only internal IP addresses, and many teams add release channels (Rapid, Regular, Stable) to receive automatic upgrades.

Key terms

Autopilot
A GKE mode where Google manages nodes and billing is based mainly on pod resource requests.
Standard cluster
A GKE mode where you configure and pay for node pools.
Regional cluster
A cluster with control plane replicas and nodes spread across multiple zones in a region.
Node pool
A group of nodes in a cluster that share the same configuration.
Real-world example

A fintech runs its customer API on a regional Autopilot cluster so it doesn't have to manage nodes. Its ML team needs GPUs with specific drivers and node settings, so they run a separate Standard cluster with a default pool for general services and a GPU node pool tainted so only training pods land there.

Exam tip: 'Don't manage nodes' means Autopilot. 'Control plane must survive a zone outage' means a regional cluster. 'Different machine types in one cluster' means node pools.

Check yourself

In a regional Standard cluster across three zones, how many nodes does --num-nodes=2 create?

Six: two per zone.

How are Autopilot clusters billed?

Mainly by the resources pods request, rather than by node VMs.
