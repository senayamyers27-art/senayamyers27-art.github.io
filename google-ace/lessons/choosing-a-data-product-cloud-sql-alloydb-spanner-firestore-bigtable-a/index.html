Choosing a data product: Cloud SQL, AlloyDB, Spanner, Firestore, Bigtable and BigQuery

▶ Watch the overview video

Last reviewed September 25, 2026

Choosing the right data product is one of the most tested skills. Start by asking: is the data relational or not, is it for transactions (OLTP) or analytics (OLAP), how big will it get, and does it need to span regions?

Cloud SQL is fully managed MySQL, PostgreSQL and SQL Server. Google handles patching, backups, replication and failover, and you connect with normal drivers and tools. It scales vertically (bigger machines) and with read replicas, and it's regional. It's the default answer for typical web and business apps that need a relational database. AlloyDB for PostgreSQL is a PostgreSQL-compatible database with higher performance for demanding transactional and mixed analytical workloads; choose it when a question stresses PostgreSQL compatibility with high performance.

Spanner is a relational database that scales horizontally, offers strong consistency and supports multi-region configurations with very high availability. Choose it for global, mission-critical transactional systems such as inventory, trading or gaming platforms that outgrow a single Cloud SQL instance.

Firestore is a serverless NoSQL document database for web, mobile and server apps, with real-time listeners, offline support for mobile clients and automatic scaling. Bigtable is a wide-column NoSQL database for huge volumes of data with very high read and write throughput and low latency by row key, such as time series, IoT telemetry, ad tech and financial ticks. It isn't relational and doesn't support SQL joins across tables in the usual way. Memorystore offers managed Redis and Memcached for caching.

BigQuery is the serverless data warehouse. You load or stream data and query it with standard SQL at petabyte scale, paying for storage and for queries (by bytes processed on demand, or by reserved capacity). It's for analytics and reporting, not for serving an app's transactions. It can also query some external data in place.

Cloud Storage holds unstructured objects such as images, videos, backups and data lake files. It's often part of the answer alongside these databases.

Key terms

Cloud SQL
Managed MySQL, PostgreSQL and SQL Server for regional relational workloads.
Spanner
A horizontally scalable, strongly consistent relational database that can span regions.
Bigtable
A wide-column NoSQL database for massive, low-latency key-based workloads such as time series.
BigQuery
A serverless data warehouse for SQL analytics at very large scale.
Real-world example

A gaming company keeps player profiles in Firestore for its mobile app, match telemetry in Bigtable for fast writes, a global item store in Spanner for consistent purchases across regions, and exports everything into BigQuery for daily analytics.

Exam tip: Relational and regional: Cloud SQL. Relational and global scale: Spanner. Time series or IoT at huge scale: Bigtable. Mobile or web documents: Firestore. Analytics with SQL: BigQuery.

Check yourself

Which product fits a regional app that needs a managed MySQL database?

Cloud SQL for MySQL.

Why isn't BigQuery the right store for an app's shopping cart?

It's an analytics warehouse, optimized for large scans, not for low-latency transactional updates.
