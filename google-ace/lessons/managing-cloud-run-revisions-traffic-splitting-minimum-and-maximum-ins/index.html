Managing Cloud Run: revisions, traffic splitting, minimum and maximum instances

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Every deployment to a Cloud Run service creates a new immutable revision, named something like web-00007-abc. Revisions keep their image and settings, so you can move traffic back to an earlier one at any time. By default, a new revision receives 100% of traffic as soon as it's healthy.

Traffic splitting lets you release gradually. Deploy the new revision without sending it traffic using gcloud run deploy web --image=... --no-traffic --tag=green, which gives it a tagged URL (the tag, three hyphens and the service's hostname) for testing. Then move traffic with gcloud run services update-traffic web --to-revisions=web-00007-abc=10,web-00006-def=90 for a 10% canary, and later --to-latest to send everything to the newest revision. Rolling back is just moving traffic to the previous revision; no rebuild is needed.

Scaling is automatic, but you control its limits. Maximum instances caps how many container instances can run, which protects downstream systems such as a database with a limited connection pool and limits cost. Minimum instances keeps a number of instances warm even with no traffic, which reduces cold-start latency (the delay while a new instance starts and initializes) at the cost of paying for idle instances. Concurrency sets how many requests one instance handles at once; the default is 80, and setting it to 1 suits code that isn't thread-safe but increases the number of instances needed.

Other settings you'll adjust include CPU and memory per instance, request timeout, environment variables and secrets, the service account the service runs as, and billing mode: with request-based billing CPU is allocated only during requests, while instance-based billing (CPU always allocated) suits background work between requests.

To observe a service, the Cloud Run console shows request counts, latencies, instance counts and logs for each revision. gcloud run services describe web shows the current traffic split, and gcloud run revisions list shows all revisions.

Key terms

Revision
An immutable version of a Cloud Run service created by each deployment.
Traffic split
Percentages of requests sent to different revisions of one service.
Minimum instances
A setting that keeps instances warm to reduce cold starts, billed while idle.
Cold start
The delay when Cloud Run starts a new container instance to handle a request.
Real-world example

A bank's API team deploys a new revision with --no-traffic, runs tests against its tagged URL, then sends 5% of traffic to it. After an hour of clean error metrics they move to 50% and then 100%. They keep minimum instances at 2 so customers never hit a cold start during business hours.

Exam tip: Gradual release on Cloud Run is traffic splitting between revisions of the same service. Slow first request is fixed with minimum instances; protecting a database is done with maximum instances.

Check yourself

How do you roll back a Cloud Run service to the previous version?

Send 100% of traffic to the previous revision with gcloud run services update-traffic (or the console).

What's the trade-off of setting minimum instances above zero?

Fewer cold starts, but you pay for those instances even when there is no traffic.
