Compute Engine disks: Persistent Disk and Hyperdisk types, regional disks and local SSD

▶ Watch the overview video

Last reviewed September 25, 2026

Compute Engine VMs use block storage for their boot and data disks. The main choices are Persistent Disk, Hyperdisk and local SSD, and they differ in performance, durability and how they're priced.

Persistent Disk is network-attached, durable block storage that lives independently of the VM, so you can stop the VM, detach the disk and attach it elsewhere. Types include standard (pd-standard, HDD-backed and cheapest, for sequential or less demanding workloads), balanced (pd-balanced, SSD-backed, a good default for most boot and data disks), SSD (pd-ssd, higher IOPS for databases) and extreme (pd-extreme, where you provision IOPS). Performance of most Persistent Disk types grows with disk size and the VM's vCPU count. You can grow a disk while it's attached, then resize the file system; you can't shrink it.

Hyperdisk is the newer generation of network block storage. With Hyperdisk you provision capacity and performance (IOPS and throughput) separately, depending on the type, such as Hyperdisk Balanced, Hyperdisk Extreme and Hyperdisk Throughput. It's supported on newer machine series, and some of those series support only Hyperdisk. Check machine series compatibility before choosing.

By default a disk is zonal: it lives in one zone. A regional persistent disk (and regional Hyperdisk Balanced High Availability) synchronously replicates data across two zones in the same region. If the primary zone fails, you can force-attach the disk to a VM in the other zone, which gives a low recovery point objective for stateful apps without application-level replication. It costs more and adds some write latency.

Local SSD is physically attached to the server that hosts the VM. It offers very high IOPS and very low latency, but data is ephemeral: it doesn't survive the VM being stopped or deleted, or a host failure (Google tries to preserve it during live migration). Use it for caches, scratch space and temporary processing, never as the only copy of important data. It comes in fixed sizes per device.

Other storage options appear in the same questions: Filestore for managed NFS file shares, and Cloud Storage for objects. Mounting a bucket with Cloud Storage FUSE is convenient but isn't a replacement for block storage.

Key terms

Persistent Disk
Durable network-attached block storage for VMs, in standard, balanced, SSD and extreme types.
Hyperdisk
Network block storage where capacity and performance are provisioned separately.
Regional persistent disk
A disk replicated synchronously across two zones in one region.
Local SSD
High-performance storage physically attached to the host, whose data doesn't persist when the VM stops.
Real-world example

A team running a self-managed PostgreSQL VM puts its data on a regional persistent disk. When a zone has an outage, they start a standby VM in the second zone, force-attach the regional disk and are serving again with no lost writes.

Exam tip: Survive a zone failure without losing writes: regional disk. Fastest scratch storage and data loss is acceptable: local SSD. Cheapest bulk block storage: standard persistent disk.

Check yourself

Can you shrink a persistent disk?

No. You can increase its size, but not reduce it.

What happens to local SSD data when you stop the VM?

It's discarded, so local SSD must only hold data you can recreate.
