Infrastructure as code with Terraform and Cloud Marketplace solutions

▶ Watch the overview video

Last reviewed September 25, 2026

Infrastructure as code (IaC) means describing your infrastructure in files that are stored in version control, reviewed like code and applied automatically. It gives you repeatable environments, peer review of changes and a history of who changed what. For Google Cloud, the most common tool is Terraform, an open source tool from HashiCorp, used with the Google Cloud provider.

In Terraform you write declarative configuration in HashiCorp Configuration Language (HCL). For example, a google_compute_instance resource block describes a VM's name, zone, machine type and boot disk. The workflow is: terraform init downloads providers and modules; terraform plan compares your configuration with the recorded state and shows what will be created, changed or destroyed; terraform apply makes the changes; terraform destroy removes everything the configuration manages.

Terraform keeps a state file that maps configuration to real resources. For teams, store state remotely in a Cloud Storage bucket (with Object Versioning on) using the gcs backend, so everyone shares one state and changes are locked while running. Don't keep state only on a laptop, and treat it as sensitive because it can contain secrets.

Modules package reusable configuration, such as a standard VPC or a project factory. Google's Cloud Foundation Toolkit publishes modules that follow best practices. Terraform is preinstalled in Cloud Shell, and many console pages can show equivalent Terraform. Infrastructure Manager is a Google Cloud service that runs Terraform deployments for you and stores their state. Google's older Deployment Manager, which used YAML templates, has been deprecated in favor of Infrastructure Manager, so new work should use Terraform or Infrastructure Manager. Config Connector is another option: it lets you manage Google Cloud resources as Kubernetes objects from a GKE cluster.

Cloud Marketplace offers prebuilt solutions from Google and partners, such as WordPress stacks, databases, security appliances and developer tools, that you can deploy in a few clicks. Some are free, some are billed through your Cloud Billing account under the vendor's license terms. Marketplace is the answer when a question asks for the quickest way to deploy a common third-party product.

Key terms

Infrastructure as code
Managing infrastructure through versioned, declarative configuration files.
terraform plan
Shows the changes Terraform would make without applying them.
Terraform state
A file that records which real resources correspond to the configuration.
Cloud Marketplace
A catalog of ready-to-deploy solutions from Google and partners.
Real-world example

A platform team keeps its network, projects and GKE clusters in a git repository of Terraform modules. Each pull request runs terraform plan so reviewers see the exact changes, and merging runs terraform apply with state stored in a versioned Cloud Storage bucket.

Exam tip: 'Preview changes before applying', 'version-controlled', 'reusable modules' all point to Terraform. 'Deploy a common third-party product quickly' points to Cloud Marketplace.

Check yourself

Where should a team store shared Terraform state on Google Cloud?

In a Cloud Storage bucket using the gcs backend, ideally with Object Versioning enabled.

What does terraform plan do?

It shows what would be created, changed or destroyed, without changing anything.
