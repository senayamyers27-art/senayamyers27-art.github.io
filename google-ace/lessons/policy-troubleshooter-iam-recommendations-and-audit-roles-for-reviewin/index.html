Google Cloud Associate Cloud Engineer Associate Cloud Engineer · Domain 4: Configuring access and security

Policy Troubleshooter, IAM recommendations and audit roles for reviewing access

▶ Watch the overview video

Last reviewed September 25, 2026

Granting access is only half the job; you also need to understand and review it. Google Cloud's Policy Intelligence tools help you answer 'why can or can't this person do this?', 'who has access to this?', and 'what access is no longer needed?'.

Policy Troubleshooter answers the first question. You give it a principal, a resource and a permission (for example bigquery.tables.getData on a dataset), and it evaluates all the relevant allow policies up the hierarchy, deny policies and principal access boundary policies. It reports whether access is granted, which binding grants it, or which binding is missing or which deny rule blocks it. It's the first stop when a user says 'I get permission denied'. You can also troubleshoot from the error message link in many console pages.

Policy Analyzer answers 'who has access to what'. It searches IAM policies across a project, folder or organization, for example to list every principal that can read a sensitive bucket, including through group membership and inherited grants. It relies on Cloud Asset Inventory, which also lets you search and export resource metadata and IAM policies.

The IAM recommender, part of Active Assist, answers 'what can be removed'. It compares the permissions each principal has with the permissions they have actually used over a recent observation period (90 days), and recommends removing unused roles or replacing broad roles with smaller ones. Applying recommendations steadily moves you toward least privilege. Related insights flag things like service accounts that haven't been used for a long time, which may be good candidates to disable.

For people who review access rather than change it, use read-only roles. Security Reviewer (roles/iam.securityReviewer) can list resources and view IAM policies without changing them, which suits auditors. Viewer-type roles such as Logs Viewer, Private Logs Viewer (for Data Access audit logs) and Cloud Asset Viewer support investigations. Security Command Center adds a centralized view of misconfigurations and threats, such as public buckets or overly permissive firewall rules, across the organization.

Key terms

Policy Troubleshooter
A tool that explains whether a principal has a permission on a resource and why.
Policy Analyzer
A tool that finds which principals have which access across the hierarchy.
IAM recommender
An Active Assist feature that suggests removing or reducing roles based on permission usage.
Security Reviewer
A read-only role for listing resources and viewing IAM policies.
Real-world example

Each quarter, a security engineer applies IAM recommender suggestions that shrink Editor grants to predefined roles, runs Policy Analyzer to list everyone who can read the payroll bucket, and grants the external auditors Security Reviewer at the organization. When a developer reports a permission error, Policy Troubleshooter shows the missing BigQuery role in seconds.

Exam tip: 'Why is this user denied' is Policy Troubleshooter. 'Who can access this resource' is Policy Analyzer. 'Which roles are unused' is the IAM recommender. 'Auditor can view but not change' is Security Reviewer.

Check yourself

What inputs does Policy Troubleshooter need?

A principal, a resource and a permission.

What data does the IAM recommender use?

Permission usage over a recent observation period compared with the permissions granted.
