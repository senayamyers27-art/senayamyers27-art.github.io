Cloud Storage access: uniform bucket-level access, public access prevention and signed URLs

▶ Watch the overview video

Last reviewed September 25, 2026

Cloud Storage has two access control systems. IAM grants roles on the project or on a bucket (and, with managed folders, on prefixes), such as Storage Object Viewer, Storage Object Creator or Storage Admin. Access control lists (ACLs) are an older, finer-grained system that can grant access on individual objects. Using both makes it hard to know who can read what.

Uniform bucket-level access disables ACLs on a bucket so that only IAM (at the bucket and project levels, plus managed folders) controls access. It's recommended for almost all buckets and is required for some features, such as IAM Conditions on buckets and managed folders. Once enabled, you have a limited window to turn it off before it becomes permanent. Fine-grained access is the mode that keeps ACLs, for special cases like per-object sharing in legacy apps.

A bucket or object becomes public when access is granted to allUsers (anyone on the internet) or allAuthenticatedUsers (anyone with a Google account). Public access prevention blocks these grants. You can enforce it on a bucket, or across projects, folders or the whole organization with the storage.publicAccessPrevention organization policy constraint. With it enforced, even an administrator can't make data public by mistake; hosting a public website then needs a bucket in a project where it isn't enforced, or a load balancer and Cloud CDN setup designed for that.

Signed URLs give time-limited access to a specific object to someone who doesn't have a Google identity, without making the bucket public. The URL contains a signature created with a service account's credentials and an expiry time, up to 7 days for V4 signatures. Anyone holding the URL can perform the specified action (for example GET to download or PUT to upload) until it expires. Create one with gcloud storage sign-url gs://bucket/report.pdf --duration=1h --private-key-file=key.json or, better, with impersonation instead of a key file. Signed policy documents do the same for browser form uploads.

Other controls include retention policies and holds, Requester Pays, VPC Service Controls perimeters around storage, and CMEK for encryption. Data Access audit logs record who read objects when enabled.

Key terms

Uniform bucket-level access
A bucket setting that disables ACLs so only IAM controls access.
Public access prevention
A setting or organization policy that blocks access grants to allUsers and allAuthenticatedUsers.
Signed URL
A URL that grants time-limited access to an object without requiring a Google identity.
allUsers
A special principal meaning anyone on the internet.
Real-world example

A law firm needs to share a 2 GB file with a client who has no Google account. The bucket has uniform bucket-level access and public access prevention enforced, so the admin generates a V4 signed URL valid for 24 hours. The client downloads the file, and the link stops working the next day.

Exam tip: Only IAM, no ACLs: uniform bucket-level access. Never public, even by mistake: enforce public access prevention (org policy for everything). Temporary access for someone without an account: signed URL.

Check yourself

What is the maximum lifetime of a V4 signed URL?

7 days.

Does uniform bucket-level access by itself stop a bucket from being made public?

No. IAM can still grant allUsers access unless public access prevention is enforced.
