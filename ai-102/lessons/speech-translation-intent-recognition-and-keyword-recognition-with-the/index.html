Speech translation, intent recognition and keyword recognition with the Speech SDK

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Beyond plain transcription and synthesis, the Speech SDK combines recognition with other tasks. Three appear in the AI-102 objectives: translating speech, recognizing what a speaker wants, and listening for a wake word.

Speech translation converts spoken audio in one language into text in one or more other languages, in real time, and can also produce synthesized audio of the translation. You create a SpeechTranslationConfig (instead of SpeechConfig) with your key and region, set speech_recognition_language to the source language (such as en-US), and call add_target_language for each target (such as es and fr). A TranslationRecognizer then works like a speech recognizer: recognize_once_async for one phrase or continuous recognition for longer speech. The result contains the recognized source text and a translations dictionary keyed by target language. To hear the translation, set a voice name for synthesis on the config and handle the synthesizing event, or pass the translated text to a speech synthesizer.

cfg = speechsdk.translation.SpeechTranslationConfig(subscription=key, region=region)
cfg.speech_recognition_language = "en-US"
cfg.add_target_language("es")
recognizer = speechsdk.translation.TranslationRecognizer(translation_config=cfg)
result = recognizer.recognize_once_async().get()
print(result.text, '->', result.translations["es"])

Intent recognition works out what a spoken command means, such as turning 'switch off the kitchen lights' into an intent like TurnOff with an entity for the room. The Speech SDK's IntentRecognizer can use simple pattern matching, where you define phrases with placeholders for entities, which works offline-friendly for a small set of fixed commands. For natural, varied phrasing, you transcribe the speech and send the text to a conversational language understanding (CLU) model in Azure AI Language, which returns the top intent and entities; the Speech SDK can do both steps together with a CLU model.

Keyword recognition listens continuously for a specific word or phrase, the wake word, such as 'Hey Contoso', before activating full recognition. It runs on the device with a keyword model, so audio is not streamed to the cloud until the keyword is heard, saving cost and protecting privacy. You create a custom keyword model in Speech Studio by typing the phrase; it generates a model file (a .table file) that you load with KeywordRecognitionModel and pass to a KeywordRecognizer or to a speech recognizer's keyword recognition method. Optional cloud verification rechecks the keyword to reduce false activations.

A typical voice assistant chains all three ideas: keyword recognition wakes it, speech to text or translation captures the request, CLU extracts intent and entities, and text to speech answers.

Key terms

SpeechTranslationConfig
The Speech SDK configuration for translating speech, with source language and target languages.
TranslationRecognizer
The Speech SDK recognizer that returns recognized text and its translations.
Intent recognition
Determining the purpose of an utterance and extracting its entities.
Keyword recognition
On-device detection of a wake word using a custom keyword model before full recognition starts.
Real-world example

A museum audio guide listens for 'Hey Guide' with a keyword model, then uses a TranslationRecognizer to translate visitors' spoken questions from their language into English, sends the English text to a CLU model to find the intent (such as FindExhibit), and answers with neural text to speech in the visitor's language.

Exam tip: Live speech into another language: SpeechTranslationConfig with add_target_language and a TranslationRecognizer. A wake word: keyword recognition with a custom keyword model. Understanding commands: CLU intents and entities.

Check yourself

Where does keyword recognition run, and why does that matter?

On the device with a local keyword model, so audio is not sent to the cloud until the wake word is detected, saving cost and protecting privacy.

How do you translate speech into two languages at once?

Call add_target_language twice on the SpeechTranslationConfig; the result's translations contain both.
