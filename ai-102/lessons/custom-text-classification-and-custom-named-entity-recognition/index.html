Custom text classification and custom named entity recognition

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Prebuilt Language features know general categories, but businesses often need their own: route tickets into their own queues, find clauses in their contracts, pull fields that only their documents contain. Azure AI Language provides two custom features for this, both trained on your labeled documents: custom text classification and custom named entity recognition (custom NER).

Custom text classification assigns categories you define to whole documents. It comes in two project types. Single-label classification assigns exactly one class per document, such as routing each email to one department. Multi-label classification assigns zero or more classes per document, such as tagging a support ticket with both billing and outage. The choice mirrors multiclass versus multilabel in Custom Vision.

Custom NER extracts entities you define from unstructured text, such as a contract's party names, effective date, governing law and termination clause, or a loan application's income and employer. Unlike CLU, which works on short utterances, custom NER is designed for longer documents.

The workflow is the same for both. Create a Language resource and connect it to a Blob Storage account (the resource's managed identity needs access), upload your text documents to a container, and create a project in Language Studio. Label the data: assign classes to documents, or highlight entity spans and assign entity types. Label consistently, include enough examples for every class or entity, and make the data represent real variation. Microsoft's guidance is to aim for balanced, varied examples; too few labels for a class gives a weak model.

Train the model, choosing an automatic or manual split of training and testing data. Review evaluation metrics per class or entity: precision, recall and F1 score (the harmonic mean of precision and recall), plus a confusion matrix showing which classes or entity types are confused. Improve weak ones by adding or fixing labels and retrain. Then deploy the model to a named deployment and call it through the asynchronous analyze-text jobs API, passing the project and deployment names, and poll for results.

Choose carefully between features: short user commands with actions are CLU; FAQ answers are question answering; categorizing or extracting from longer documents is custom classification or custom NER; standard entity types like people and dates are prebuilt NER, needing no training.

Key terms

Single-label classification
Custom text classification where each document receives exactly one class.
Multi-label classification
Custom text classification where each document can receive zero or more classes.
Custom NER
A trained model that extracts your own entity types from unstructured documents.
F1 score
The harmonic mean of precision and recall, a single measure of model accuracy.
Real-world example

A law firm labels 400 contracts in Language Studio with entities Party, EffectiveDate, GoverningLaw and TerminationClause, trains a custom NER model, and finds low recall for TerminationClause. After labeling 100 more contracts with varied termination wording, F1 for that entity rises enough to deploy.

Exam tip: One category per document: single-label. Any number: multi-label. Your own entity types from long documents: custom NER. Training data lives in a Blob Storage container connected to the Language resource.

Check yourself

What does F1 score combine?

Precision and recall, as their harmonic mean.

Where must training documents be stored for custom text classification?

In a Blob Storage container connected to the Language resource.
