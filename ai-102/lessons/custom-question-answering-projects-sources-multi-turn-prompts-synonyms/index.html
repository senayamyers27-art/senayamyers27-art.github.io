Custom question answering: projects, sources, multi-turn prompts, synonyms and confidence thresholds

▶ Watch the overview video

Last reviewed September 25, 2026

Custom question answering, a feature of Azure AI Language, builds a knowledge base of question-and-answer pairs from your existing content and answers users' natural language questions from it. It replaced the retired QnA Maker service. Typical uses are FAQ bots for HR, IT and customer support, where answers should be exactly the approved text rather than generated.

You create a custom question answering project in Language Studio. Enabling the feature on a Language resource requires an Azure AI Search resource, which stores the project's index. Add sources: URLs of FAQ pages, files such as PDF, Word or Excel documents with question and answer structure, or pairs you type by hand. The service extracts question and answer pairs automatically. You can also add a chit-chat source, prebuilt pairs in a chosen personality (professional, friendly, witty and so on) that handle small talk like 'how are you?'.

Then refine the pairs. Alternate questions add other phrasings for the same answer, improving matching. Metadata tags (name and value pairs, such as product: laptop) let the app filter answers by context. Synonyms are defined at project level, such as treating 'PTO', 'leave' and 'vacation' as equivalent across all questions. Multi-turn conversations use follow-up prompts: an answer can offer buttons or suggestions that lead to other pairs, so a general question ('How do I reset my password?') can narrow down ('For email or VPN?') to the right answer. Follow-up prompts can be marked as context-only so they are shown only within that flow.

Test in the portal, then deploy the project, which publishes it to a production endpoint. Apps call it with the project and deployment names and the user's question, and receive answers with confidence scores. Settings on the query include top (how many answers to return), a confidence threshold below which no answer is returned, and a default answer used when nothing meets the threshold. Tune the threshold: too low and the bot answers wrongly; too high and it says 'I don't know' too often.

Active learning improves the project over time: when user questions are close to several pairs, the service suggests alternate questions for you to accept or reject. Precise answering can return a short exact span within a longer answer. Question answering is often combined with CLU in an orchestration workflow so one bot can both answer FAQs and perform actions.

Key terms

Project
A custom question answering knowledge base of question and answer pairs built from sources.
Follow-up prompt
A link from an answer to related pairs, enabling multi-turn conversations.
Synonyms
Project-level word alternatives treated as equivalent when matching questions.
Confidence threshold
The minimum score an answer needs to be returned; below it the default answer is used.
Real-world example

An IT team imports its FAQ web page and a Word troubleshooting guide, adds professional chit-chat, defines 'MFA' and 'two-factor' as synonyms and adds follow-up prompts for printer questions by building. With a confidence threshold of 0.5 and a default answer pointing to the help desk, the bot answers 70% of queries without an agent.

Exam tip: Clarifying follow-ups: multi-turn prompts. Equivalent words across the whole project: synonyms. Wrong answers to unrelated questions: raise the confidence threshold and set a default answer. It needs an Azure AI Search resource.

Check yourself

What extra Azure resource does custom question answering require?

An Azure AI Search resource, which stores the project's index.

What is the difference between alternate questions and synonyms?

Alternate questions add phrasings to one specific pair; synonyms define equivalent words that apply across the whole project.
