Querying an index: simple and full Lucene syntax, OData filters, facets, sorting and paging

▶ Watch the overview video

Last reviewed September 25, 2026

Queries are sent to an index's docs/search endpoint with a POST body or query string, or through the SDK's search method on a SearchClient, using a query key for read-only access. A query combines several parts, each with its own syntax, and the exam often shows a query and asks what it returns or how to fix it.

The search parameter holds the full-text query. With the default simple syntax (queryType=simple), you get terms, quoted phrases, + for required terms, - to exclude, | for OR and * for a prefix at the end of a term. The full Lucene syntax (queryType=full) adds fielded search (title:budget), fuzzy search with ~ (colour~ also matches 'color'), proximity search ("hotel airport"~5 for words within five positions), term boosting with ^ (beach^3 pool), regular expressions between slashes and wildcards within terms. searchMode decides whether any term (default) or all terms must match. searchFields limits which searchable fields are searched, and search=* matches everything, useful with filters.

Filters use OData expression syntax in $filter and apply to filterable fields. Comparison operators are words: eq, ne, gt, ge, lt, le, combined with and, or and not, with strings in single quotes. Examples: rating ge 4 and category eq 'Budget', tags/any(t: t eq 'wifi') for collections, search.in(city, 'Oslo,Bergen') for many values, and geo.distance(location, geography'POINT(-122.1 47.6)') le 10 for distance in kilometers. Filters restrict results without affecting relevance scores and are also how security trimming works (filtering on a field of allowed group IDs).

POST /indexes/hotels/docs/search?api-version=<version>
{ "search": "quiet beach^2", "queryType": "full", "filter": "rating ge 4",
  "facets": ["city,count:10", "rating"], "orderby": "price asc",
  "select": "name,city,price", "top": 10, "skip": 20, "count": true, "highlight": "description" }

Other parameters shape the response. facets returns counts per value (or per range) of facetable fields for navigation. $orderby sorts by sortable fields or by search.score(); by default results are ordered by relevance score. $select chooses the retrievable fields to return. $top and $skip page through results, and $count=true returns the total number of matches. highlight wraps matching terms in the chosen fields with tags for display. Separate endpoints handle autocomplete and suggest, which require a suggester.

When a query does not behave as expected, check the attributes (is the field filterable or sortable?), the analyzer (is the text tokenized the way you think?) and whether you need the full syntax.

Key terms

queryType
The query parser: simple (default), full (Lucene) or semantic.
$filter
An OData expression that restricts results by filterable field values without affecting scoring.
Fuzzy search
A full Lucene query that matches terms with small spelling differences, written with ~.
Facets
Counts of matching documents per field value or range, used for faceted navigation.
Real-world example

A job board's query uses search set to 'data engineer' with searchMode all, a filter on location within 30 km and salary ge 50000, facets on company and remote, orderby postedDate desc, top 20 with skip for paging, and highlight on description to show why each job matched.

Exam tip: Fuzzy, proximity, boosting, regex and fielded queries need queryType full. Filters are OData with word operators (eq, ge, and), not symbols like == or &&.

Check yourself

Write a filter for hotels in the Luxury category with rating above 4.

category eq 'Luxury' and rating gt 4

How do you return results 21 to 30?

Set top to 10 and skip to 20.
