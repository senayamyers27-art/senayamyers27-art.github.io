Conversational language understanding (CLU): intents, entities, utterances, training and deployment

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Conversational language understanding (CLU) is the Azure AI Language feature that interprets what a user wants from a natural language command or question. It replaced the older Language Understanding service (LUIS), which has been retired. You build a CLU project in Language Studio (or the Foundry portal) or through the authoring REST API, train a custom model on your examples, deploy it and query it from apps and bots.

The model predicts intents and extracts entities. An intent is what the user wants to do: BookFlight, CheckOrderStatus, CancelSubscription. Every project also has a None intent for utterances outside the app's scope; adding varied out-of-scope examples to it stops the model forcing unrelated input into a real intent. An entity is a piece of information the app needs to act, such as destination, date or order number.

CLU has several entity component types, which can be combined. Learned entities are learned from labeled examples in context, for values that vary, like a destination city in 'fly me to Lisbon next week'. List entities match a fixed set of values with synonyms exactly, such as store names or product sizes with their alternative names. Prebuilt entities recognize common types such as date and time, numbers, email and URL without labeling. Regular expression entities match patterns such as order numbers like ORD-12345.

Utterances are example sentences for each intent. You add them and label the entity spans inside them. Good data has varied phrasing, lengths and word orders, similar numbers of utterances across intents, and realistic user language rather than only textbook sentences. Then train the model. Standard training is faster and free; advanced training can give better results, and multilingual projects let one model understand several languages.

After training, review evaluation results on a test set: precision, recall and F1 score for each intent and entity, and a confusion matrix showing which intents get mixed up. Fix confusion with clearer or more varied examples. Then deploy the model to a named deployment (such as production). Apps query the prediction endpoint with the project name, deployment name and the user's utterance, and receive the top intent with a confidence score, scores for other intents and extracted entities. Your app decides what to do when the top score is low, such as asking the user to rephrase.

CLU can also be one part of an orchestration workflow project, which routes utterances to CLU projects or custom question answering projects.

Key terms

Intent
The goal or action a user expresses in an utterance, such as BookFlight.
Entity
A piece of information in an utterance the app needs, such as a date or destination.
Utterance
An example phrase a user might say, used to train and test the model.
None intent
The built-in intent that captures utterances outside the app's scope.
Real-world example

A pizza chain's CLU project has intents OrderPizza, TrackOrder and None, a list entity for sizes with synonyms (large, big, family), a prebuilt datetime entity for delivery time and a regex entity for order numbers. After the confusion matrix showed TrackOrder and OrderPizza mixing, the team added 20 varied tracking utterances and retrained.

Exam tip: Out-of-scope input landing in a real intent: add examples to None. A fixed set of values with synonyms: list entity. Patterns like codes: regex entity. Values that vary in context: learned entity.

Check yourself

What does a CLU prediction return?

The top intent with its confidence, scores for other intents and the extracted entities.

Why keep utterance counts balanced across intents?

An intent with many more examples can bias predictions toward itself, causing misclassification of other intents.
