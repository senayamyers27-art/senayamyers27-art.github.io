Azure AI Content Understanding: extracting fields from documents, images, audio and video with analyzers

▶ Watch the overview video

Last reviewed September 25, 2026

Azure AI Content Understanding is a newer Azure AI service that turns unstructured content of any type (documents, images, audio and video) into structured output that applications, search indexes and agents can use. It combines capabilities that previously required several services, such as OCR, layout analysis, speech transcription and video analysis, with generative AI models that extract or generate the specific fields you ask for.

The central concept is the analyzer. An analyzer defines how to process one type of content and what to produce. It includes the content type (document, image, audio or video), configuration options (for example whether to return layout, transcripts with speaker labels or video segments) and a field schema: the list of fields you want, each with a name, a type (such as string, number, date, boolean, array or object), a description and a method. Extract fields pull values that appear in the content, like an invoice number. Generate fields ask the model to produce a value from the content, like a one-sentence summary of a call. Classify fields choose from a fixed set of categories, like the call's topic. Good descriptions in the schema guide the model, much like prompt engineering.

Prebuilt analyzers cover common scenarios, and you can create custom analyzers from templates in the Foundry portal: define the schema, test it on sample files, refine descriptions and then build the analyzer so it has an ID your code can call. You call the analyze operation with the analyzer ID and the content URL or bytes; like Document Intelligence, the operation is asynchronous and you poll for the result. The output contains the content extraction (such as markdown text, transcripts or video segments with timestamps) plus the fields, and for many fields grounding information and confidence scores showing where in the content the value came from.

Compared with other services: Document Intelligence remains the specialist for document field extraction with trained custom models and many prebuilt document types. Content Understanding is attractive when you have mixed content types, want to define fields by description instead of labeling training data, or need generated or classified fields alongside extracted ones. Video Indexer offers a broad set of video insights for media libraries; Content Understanding focuses on schema-driven output for downstream processing.

Typical uses include post-call analytics (transcript, sentiment, topic and action items from call recordings), processing claims that include photos and forms, extracting product details from marketing images, and turning video into searchable, time-coded chapters for RAG. As with any generative extraction, validate outputs, use confidence scores and keep human review for high-stakes decisions.

Key terms

Content Understanding
An Azure AI service that extracts structured, schema-defined output from documents, images, audio and video.
Analyzer
A Content Understanding definition of the content type, options and field schema used to process files.
Field schema
The list of named, typed and described fields an analyzer should return.
Generate field
A schema field whose value the model produces from the content, such as a summary.
Real-world example

A contact center defines an audio analyzer with fields for customer intent (classify), products mentioned (extract), a summary (generate) and whether the issue was resolved (classify). Every recorded call is analyzed overnight, and the fields feed a dashboard and a search index for supervisors.

Exam tip: One service with a field schema across documents, images, audio and video points to Content Understanding. The analyzer holds the schema; extract, generate and classify are the field methods.

Check yourself

What is the difference between extract and generate fields?

Extract fields return values that appear in the content; generate fields have the model produce a value, such as a summary, from the content.

When would you still choose Document Intelligence over Content Understanding?

For document-only workloads that fit its prebuilt models or need custom models trained on labeled examples, such as fixed forms.
