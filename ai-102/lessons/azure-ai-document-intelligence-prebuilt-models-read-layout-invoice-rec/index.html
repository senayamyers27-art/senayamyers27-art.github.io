Azure AI Document Intelligence prebuilt models: read, layout, invoice, receipt and ID document

▶ Watch the overview video

Last reviewed September 25, 2026

Azure AI Document Intelligence (formerly Form Recognizer) extracts text, structure and data from documents such as PDFs, scanned images and Office files. Where OCR alone gives you lines of text, Document Intelligence understands documents: paragraphs, tables, checkboxes and named fields like invoice totals. Prebuilt models work immediately without training.

The foundational models are general. The read model (prebuilt-read) extracts printed and handwritten text lines and words with positions, detects languages and handles multi-page documents; it is the OCR engine for documents. The layout model (prebuilt-layout) adds structure: paragraphs with roles such as title and section heading, tables with rows, columns and merged cells, selection marks (checkboxes and radio buttons) and figures, and it can output the document as markdown, which is very useful for chunking documents in RAG pipelines.

Prebuilt scenario models extract named fields for common document types. The invoice model returns fields such as VendorName, CustomerName, InvoiceId, InvoiceDate, DueDate, line items and InvoiceTotal. The receipt model returns MerchantName, TransactionDate, Items, Subtotal, Tax and Total from printed and photographed receipts. The ID document model reads passports and driver's licenses, returning fields such as name, date of birth, document number and expiration date. There are more, such as US tax forms, health insurance cards, contracts, bank statements, pay stubs and business cards, depending on the API version. Each field comes with a value, a type, its location and a confidence score.

Analysis is asynchronous. In REST, you POST the document (a URL or file bytes) to the model's analyze operation; the response is 202 Accepted with an Operation-Location header, which you poll with GET until the status is succeeded and the result is included. The SDK hides this with a poller: begin_analyze_document("prebuilt-invoice", body) returns a poller, and .result() waits for completion.

poller = client.begin_analyze_document("prebuilt-receipt", AnalyzeDocumentRequest(url_source=receipt_url))
receipt = poller.result().documents[0]
total = receipt.fields.get("Total")
print(total.content, total.confidence)

Use confidence scores to decide what to automate: accept high-confidence fields and route low-confidence ones to human review. Document Intelligence Studio lets you try every model on your own files before writing code. The Free tier processes only a limited number of pages, fine for learning. If no prebuilt model fits your documents, train a custom model, which is the next lesson.

Key terms

Read model
The Document Intelligence model that extracts text lines and words from documents.
Layout model
The model that extracts text plus structure: paragraphs, tables, selection marks and figures.
Prebuilt model
A ready-to-use model that extracts named fields from a common document type such as invoices or receipts.
Confidence score
A value from 0 to 1 indicating how certain the model is about an extracted field.
Real-world example

An expense app sends photos of receipts to prebuilt-receipt, automatically accepts totals with confidence above 0.9, and asks the employee to confirm the rest. Supplier invoices go to prebuilt-invoice, and scanned policy documents go to prebuilt-layout, whose markdown output is chunked for the company's RAG assistant.

Exam tip: Text only: read. Tables, checkboxes and structure without named fields: layout. Named fields from common documents: the matching prebuilt model. 202 plus Operation-Location means poll for the result.

Check yourself

Which model would you use to extract tables from quarterly reports?

prebuilt-layout, which returns tables with rows, columns and cells along with other structure.

What does a 202 response from an analyze call mean?

The analysis was accepted and is running; poll the Operation-Location URL until it succeeds.
