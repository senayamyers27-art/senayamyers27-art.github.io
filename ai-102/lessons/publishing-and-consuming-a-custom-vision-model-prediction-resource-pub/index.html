Publishing and consuming a Custom Vision model: prediction resource, published iterations and exporting compact models

▶ Watch the overview video

Last reviewed September 25, 2026

A trained iteration is not yet available to your app. You make it available by publishing it to a prediction resource, or by exporting it to run somewhere else. Knowing this step explains a classic exam scenario: the model was retrained, but the app still behaves the same.

Publishing takes a chosen iteration and deploys it to a prediction resource under a publish name that you pick, such as productModel. Your app calls the prediction endpoint with the project ID and that publish name, sending an image URL or image bytes, with the prediction resource's key in the Prediction-Key header (or with the prediction client in the SDK). The response lists each tag with its probability for classification, or each detected object's tag, probability and bounding box for detection. The bounding box is given as left, top, width and height as fractions of the image size, so multiply by the image dimensions to draw it.

The publish name is a stable pointer. When you train a better iteration, the app keeps calling the same publish name, so you must publish the new iteration under that name (unpublishing the old one first, or publishing it and moving the name). Until you do, the endpoint serves the old model. This makes rollback easy: republish the previous iteration under the name. You can also publish several iterations under different names to test them side by side.

To run a model offline or at the edge, export it. Export is only available for iterations trained with a compact domain. Formats include TensorFlow and TensorFlow Lite for Android and general use, Core ML for iOS, ONNX for Windows ML and many runtimes, and Dockerfiles that build a container for Linux, Windows or ARM devices, such as Azure IoT Edge modules. Exported models run without calling Azure, so they work with no connectivity and have no per-prediction charge, but you must redeploy them yourself when you retrain.

Keep the two resource roles separate in your head: the training resource and key are for managing projects, uploading images and training; the prediction resource and key are for calling published models. Using the training key against the prediction endpoint, or calling an unpublished iteration, results in errors.

Key terms

Publish name
The name under which an iteration is published to a prediction resource and called by apps.
Prediction resource
The Custom Vision resource that hosts published iterations and serves prediction requests.
Prediction-Key
The HTTP header carrying the prediction resource's key when calling a published model.
Export
Downloading a compact-domain model in a format such as ONNX, TensorFlow, Core ML or a Docker container for offline use.
Real-world example

A retailer's app calls the publish name shelfModel. After training iteration 6 with new product images, testers report no improvement. The engineer notices iteration 4 still holds the publish name, publishes iteration 6 as shelfModel, and the app immediately uses the new model without code changes.

Exam tip: Retrained but no change in the app: the new iteration was not published under the name the app calls. Offline use: export, which requires a compact domain.
