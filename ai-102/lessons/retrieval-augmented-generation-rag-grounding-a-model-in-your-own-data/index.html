Retrieval augmented generation (RAG): grounding a model in your own data with Azure AI Search

▶ Watch the overview video

Last reviewed September 25, 2026

A language model knows only what was in its training data, which is out of date and does not include your company's private documents. Asked about them, it may invent a plausible answer. Retrieval augmented generation (RAG) fixes this by retrieving relevant passages from your own data at question time and adding them to the prompt, with instructions to answer only from those passages. The model's job changes from remembering facts to reading and summarizing the facts you hand it.

A RAG app has two phases. Ingestion happens ahead of time: documents are extracted to text, split into chunks, optionally converted to vectors with an embedding model, and stored in a search index. Query time happens for each question: the app turns the user's question into a search query (often rewriting it using the conversation history), retrieves the top matching chunks, builds a prompt containing the system instructions, the chunks with their source names and the question, and calls the chat model. The answer can cite the sources because they were in the prompt.

Azure AI Search is the usual retrieval engine on Azure. It supports keyword search, vector search, hybrid search that combines them, and semantic ranking that re-orders results with a language model, all of which improve which chunks reach the prompt. Better retrieval is usually the biggest lever on RAG quality: if the right passage is not retrieved, the model cannot use it.

Azure AI Foundry offers a shortcut often called 'add your data' (Azure OpenAI On Your Data). In the chat playground you connect a data source such as an Azure AI Search index or files uploaded to Blob Storage, choose the search type, and the service handles retrieval, prompt building and citations. Options include limiting answers to your data only, the strictness of relevance filtering and the number of documents retrieved. You can deploy the result as a web app or call it from code. For full control, build the pipeline yourself or with prompt flow, an agent with an Azure AI Search tool, or a framework such as Semantic Kernel.

RAG has clear advantages: answers stay current because you update the index, not the model; sources can be cited; access can be limited per user with security filters on the index; and no training is needed. Its costs are the search service and the extra prompt tokens for retrieved passages.

Key terms

RAG
Retrieval augmented generation: retrieving relevant data at query time and adding it to the prompt to ground the answer.
Grounding
Supplying the model with source content it should base its answer on.
Ingestion
The offline process of extracting, chunking, embedding and indexing documents for retrieval.
Citation
A reference in the answer to the source document or chunk that supported it.
Real-world example

An IT help desk connects its knowledge base articles to an Azure AI Search index and uses the add your data feature. When a user asks how to reset VPN tokens, the bot answers from the current article and shows it as a citation. When the article changes, the answer changes after the next indexer run.

Exam tip: Up-to-date facts, private documents and citations point to RAG, not fine-tuning. If answers are wrong because the right passage is missing, fix retrieval (hybrid search, semantic ranking, better chunking) before changing the model.

Check yourself

What are the two phases of a RAG solution?

Ingestion (extract, chunk, embed and index documents ahead of time) and query time (retrieve relevant chunks and include them in the prompt).

Why can a RAG app cite sources while a fine-tuned model usually cannot?

The retrieved passages and their source names are in the prompt, so the model can reference them; fine-tuned knowledge has no traceable source.
