Azure AI Foundry Agent Service: agents, threads, messages and runs

▶ Watch the overview video

Last reviewed September 25, 2026

Azure AI Foundry Agent Service is a managed service for building and hosting agents. It handles the parts that are tedious to build yourself: storing conversation state, calling tools, managing files and vector stores, applying content filters and tracing. You define the agent, and the service runs the loop of model calls and tool calls. You can create agents in the Agents page of a Foundry project or in code with the Azure AI Projects or Agents SDKs for Python, C# and other languages.

Four objects matter. An agent is a definition: a model deployment, a name, instructions and a set of tools (with their resources, such as files for file search). A thread is a conversation session between a user and an agent; it stores messages and grows as the conversation continues, and the service manages truncation to fit the model's context window. A message is one entry in a thread, from the user or the agent, and can contain text, images or file references. A run is one activation of an agent on a thread: it reads the thread, calls the model and any tools, and appends the agent's response messages.

The basic flow in code is: create the project client with your project endpoint and DefaultAzureCredential; create an agent with a model, instructions and tools; create a thread; add a user message to the thread; create a run (or use a helper that creates and processes the run); then list the thread's messages to read the reply. For the next user turn, add another message to the same thread and create another run.

A run moves through statuses. It starts as queued, then in_progress. If the agent calls a function that your code must execute, the run pauses in requires_action: your app reads the tool calls, runs the functions and submits the tool outputs, and the run continues. It ends as completed, failed, cancelled or expired (for example if tool outputs were not submitted in time). Each run is made of run steps, such as a message creation or a tool call, which you can inspect to see exactly what the agent did.

Agents, threads and files persist until you delete them, so production apps usually map each user conversation to a thread ID and clean up old threads. The service can use Microsoft-managed storage or your own resources (a standard setup with your own storage, Cosmos DB and search) when you need data to stay in resources you control.

Key terms

Agent
In Agent Service, a definition combining a model deployment, instructions and tools.
Run
One activation of an agent on a thread that processes messages and tool calls and appends replies.
requires_action
A run status meaning the app must execute requested function calls and submit their outputs.
Run step
An individual action within a run, such as a tool call or message creation, used for inspection and debugging.
Real-world example

A university help desk creates one agent with instructions and a file search tool over course policies. Each student chat maps to a thread. When a student asks a question, the app adds a message and creates a run; when the run completes, it shows the newest agent message with its citations.

Exam tip: Conversation history lives in the thread, behavior in the agent, and processing in the run. requires_action means your code must run the function and submit tool outputs.

Check yourself

How do you continue a conversation with an Agent Service agent?

Add a new user message to the same thread and create another run on it.

What should an app do when a run's status is requires_action?

Read the requested tool calls, execute the functions, and submit the tool outputs so the run can continue.
