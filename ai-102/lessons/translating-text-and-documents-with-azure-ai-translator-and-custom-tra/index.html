Translating text and documents with Azure AI Translator and Custom Translator

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Azure AI Translator translates text between more than 100 languages using neural machine translation. It has three parts you should know: text translation for strings in real time, document translation for whole files, and Custom Translator for training models on your own terminology.

Text translation is a REST call to the Translator endpoint's translate operation with api-version=3.0, one from parameter (optional, since the source language is detected automatically if omitted) and one or more to parameters. Sending several to values translates into all those languages in a single request. The body is a JSON array of objects with a Text property. Authentication uses the Ocp-Apim-Subscription-Key header; when the key belongs to a regional or multi-service resource you must also send Ocp-Apim-Subscription-Region with the resource's region, or the call fails with 401.

curl -X POST "$TRANSLATOR_ENDPOINT/translate?api-version=3.0&to=fr&to=de" \
  -H "Ocp-Apim-Subscription-Key: $KEY" -H "Ocp-Apim-Subscription-Region: westeurope" \
  -H "Content-Type: application/json" -d '[{"Text": "Your order has shipped."}]'

Other text operations include detect (identify the language), transliterate (convert script, such as Japanese kanji to Latin letters, without translating), dictionary/lookup (alternative translations for a word) and breaksentence. Options on translate include profanityAction (NoAction, Marked or Deleted), textType=html to preserve markup, and includeAlignment. To keep specific terms untranslated or force a translation, you can use markup such as the dynamic dictionary or mark text with a no-translate class.

Document translation translates whole files, such as Word, PDF, PowerPoint, Excel and HTML, while preserving their structure and formatting. The batch version is asynchronous: you put source files in an Azure Blob Storage container, create a target container, give the Translator resource access (SAS tokens or a managed identity with a storage role), and submit a job naming the source, target and languages. You then poll the job status. A synchronous single-document option exists for small files. A glossary file can enforce specific term translations.

Custom Translator lets you train a translation model on your own parallel documents: sentence-aligned pairs in the source and target language from your domain, such as approved product manuals. After training and publishing, the model has a category ID, and your requests include category=<id> to use it instead of the general model. Use it when the general model keeps mistranslating your industry's terminology or style.

Key terms

Text translation
Real-time translation of strings through the Translator translate operation.
Document translation
Asynchronous translation of whole files in Blob Storage that preserves formatting.
Custom Translator
A service for training translation models on your own parallel documents, used by category ID.
Transliteration
Converting text from one script to another without translating its meaning.
Real-world example

An e-commerce site translates product reviews into English, French and German with one translate call per review and three to parameters, uses document translation for its 300-page seller handbook, and calls a Custom Translator model by category ID for technical product descriptions.

Exam tip: Several target languages in one call: multiple to parameters. 401 with a regional key: add the Ocp-Apim-Subscription-Region header. Whole files with formatting: document translation. Domain terminology: Custom Translator with a category ID.

Check yourself

What does transliteration do?

It converts text from one script to another, such as Cyrillic to Latin letters, without translating the words.

What does document translation need to access your files?

Source and target Blob Storage containers, with access granted by SAS tokens or a managed identity.
