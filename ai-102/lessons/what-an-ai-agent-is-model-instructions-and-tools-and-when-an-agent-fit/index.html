What an AI agent is: model, instructions and tools, and when an agent fits better than a plain chat app

▶ Watch the overview video

Last reviewed September 25, 2026

An AI agent is software that uses a language model to pursue a goal on a user's behalf by deciding what to do next and taking actions through tools. A plain chat app sends a prompt and shows the reply. An agent runs a loop: it reads the request, decides whether it needs information or an action, calls a tool, looks at the result, and repeats until it can give a final answer or complete the task.

Every agent has three core parts. The model provides the reasoning and language ability; it is usually a chat or reasoning model deployed in your Foundry project. The instructions, like a system message, define the agent's role, goals, rules, tone and when to ask for help or hand off. The tools are the agent's hands: functions, APIs, search indexes, a code interpreter or other agents it can call. Agent platforms add state, usually a thread that keeps the conversation and tool results, so the agent can work across many turns.

Agents fit tasks that need several steps, live data or actions. 'Check the status of order 1234, and if it shipped more than ten days ago, open a claim and email the customer a label' requires calling an order API, applying a rule, calling a claims API and sending email: that is an agent task. Other good fits are research that combines several sources, data analysis where the agent writes and runs code, and IT or HR assistants that can file tickets. Agents are also a good way to package a RAG app, with search as one tool among others.

A plain chat completion is better when the task is a single transformation of text you already have: rewrite this paragraph, translate this sentence, summarize this document, classify this ticket. Adding an agent there only adds latency, cost and more ways to fail. The same is true for fixed workflows where the steps never change; ordinary code or a workflow service is more predictable than letting a model choose.

Autonomy brings risk. An agent that can send email or issue refunds can do damage if it misunderstands or is manipulated by injected instructions. Good agent design gives the fewest tools with the least privilege, requires human approval for consequential actions, validates tool inputs and traces every step, topics covered later in this domain.

On Azure you can build agents with Azure AI Foundry Agent Service, which hosts agents for you, or in code with frameworks such as Semantic Kernel, AutoGen and the Microsoft Agent Framework.

Key terms

AI agent
Software that uses a model to plan and take actions through tools in a loop to achieve a goal.
Tool
A capability an agent can invoke, such as a function, API, search index or code interpreter.
Instructions
The agent's system-level guidance defining its role, goals, rules and behavior.
Thread
Stored conversation state, including messages and tool results, that an agent works from across turns.
Real-world example

A travel company first built a chatbot that answered policy questions. Customers kept asking it to change bookings, so the company built an agent with tools to look up bookings, check fare rules and request changes, requiring the customer to confirm before any change was submitted.

Exam tip: Multi-step tasks that call APIs or take actions suggest an agent. Single-shot text transformations (rewrite, translate, summarize one document) suggest a plain chat completion.

Check yourself

What are the three core components of an agent?

A model for reasoning, instructions defining its role and rules, and tools it can call to get information or take actions.

Why not use an agent to translate one sentence?

It is a single text transformation; an agent adds latency, cost and failure points without benefit.
