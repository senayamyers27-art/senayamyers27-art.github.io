Semantic ranking, vector search and hybrid queries in Azure AI Search

▶ Watch the overview video

Last reviewed September 25, 2026

Classic full-text search ranks results with BM25, a formula based on how often query terms appear in a document and how rare they are. It is fast and excellent for exact terms, but it does not understand meaning. Azure AI Search adds three capabilities that improve relevance, and RAG solutions usually combine them.

Vector search compares meaning. Documents are stored with vector fields produced by an embedding model, and the query is embedded with the same model. The engine finds the nearest vectors using an algorithm defined in the vector search configuration: HNSW for fast approximate search (the usual choice) or exhaustive k-nearest neighbors (KNN) for exact but slower search. A vector query specifies the field, the number of nearest neighbors k and either the vector itself or text to be converted by a vectorizer attached to the field (integrated vectorization, which calls an embedding model such as an Azure OpenAI deployment for you). Filters can be applied before or after the vector search.

Hybrid search runs a full-text query and one or more vector queries in the same request and merges the result lists with Reciprocal Rank Fusion (RRF), which scores each document by its rank positions in each list. Hybrid combines the strengths of both: vectors catch paraphrases and concepts, keywords catch exact names, codes and rare terms. Microsoft's own testing shows hybrid retrieval generally outperforms either method alone for RAG, which is why it is the recommended default.

Semantic ranking (the semantic ranker) is a second stage. It takes the top results from a keyword or hybrid query (up to 50) and re-scores them with a language understanding model trained by Microsoft, producing a reranker score that better reflects how well each document answers the query. It can also return semantic captions (the most relevant passages with highlights) and semantic answers (a direct answer extracted from a document when the query is a question). You enable it by defining a semantic configuration in the index, which names the title field, content fields and keyword fields in priority order, and by sending queryType=semantic with semanticConfiguration. It is available on Basic and higher tiers, with a free monthly allowance and a paid plan for more queries.

Putting it together, a strong RAG retrieval call is a hybrid query (keywords plus vectors) with semantic ranking on top, returning the best few chunks to the chat model. Tune k, the number of results passed to the model and chunk sizes using evaluation data rather than guesswork.

Key terms

Vector search
Finding documents whose embedding vectors are closest to the query's vector.
Hybrid search
Combining keyword and vector queries in one request, merged with Reciprocal Rank Fusion.
Reciprocal Rank Fusion
A method that merges ranked lists by scoring documents on their rank positions in each list.
Semantic ranker
A second-stage model that re-ranks top results by meaning and can return captions and answers.
Real-world example

A support portal's vector-only search missed exact error codes like 0x80070005, while keyword-only search missed questions phrased differently from the articles. Switching to hybrid search with semantic ranking and captions put the right article in the top three for 90% of test queries.

Exam tip: Exact codes plus meaning: hybrid search. Better ordering of the top results and extracted answers: semantic ranking with a semantic configuration and queryType semantic. Queries must use the same embedding model as the documents.

Check yourself

How are keyword and vector results combined in hybrid search?

With Reciprocal Rank Fusion, which merges the lists based on each document's rank in each.

What must the index define before semantic ranking can be used?

A semantic configuration naming the title, content and keyword fields.
