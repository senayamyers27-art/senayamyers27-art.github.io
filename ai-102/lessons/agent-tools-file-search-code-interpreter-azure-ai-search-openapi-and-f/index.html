Microsoft Certified: Azure AI Engineer Associate AI-102 · Domain 3: Implement an agentic solution

Agent tools: file search, code interpreter, Azure AI Search, OpenAPI and function calling

▶ Watch the overview video

Last reviewed September 25, 2026

Tools are what make an agent more than a chatbot. Azure AI Foundry Agent Service offers built-in tools that the service runs for you, and ways to connect your own code and APIs. Choosing the right tool for a scenario is a common exam task.

Knowledge tools ground the agent in data. File search lets you upload files (such as PDFs, Word documents or text) into a vector store; the service chunks and embeds them and the agent retrieves relevant passages, citing the files in its answers. It is the quickest way to give an agent a set of documents. The Azure AI Search tool connects the agent to an existing search index you manage, which suits large or frequently updated enterprise content and lets you reuse indexes, filters and security trimming you already built. Grounding with Bing Search lets the agent search the public web for current information. Other knowledge connectors, such as SharePoint or Microsoft Fabric, are available for specific data sources.

Code interpreter lets the agent write and run Python in a secure sandbox. It can read uploaded files such as CSV or Excel, perform calculations, transform data and produce charts or new files for the user to download. Use it whenever the task needs accurate math or data processing, since language models alone are unreliable at arithmetic.

Action tools let the agent do things. Function calling lets you describe your own functions with names, descriptions and JSON schema parameters; when the model decides to call one, the run pauses with requires_action, and your code executes the function and returns the result. This keeps your code and credentials in your app. The Azure Functions tool lets the agent call functions hosted in Azure Functions, typically through queues, without your client code running them. The OpenAPI tool lets you give the agent an OpenAPI 3 specification of an existing REST API, with anonymous, API key or managed identity authentication, so it can call the API's operations directly from the service. Agents can also call other agents as tools (connected agents) and connect to Model Context Protocol (MCP) servers.

Tool descriptions matter. The model decides which tool to call based on the names and descriptions you give, so write them clearly and keep the set small and relevant. Give each tool only the permissions it needs.

Key terms

File search
A built-in agent tool that indexes uploaded files in a vector store and retrieves passages with citations.
Code interpreter
A built-in agent tool that writes and runs Python in a sandbox for calculations, data processing and charts.
OpenAPI tool
A tool that lets an agent call a REST API described by an OpenAPI specification.
Vector store
The managed store of chunked, embedded files that file search queries.
Real-world example

A finance agent has three tools: file search over the expense policy, code interpreter to total a spreadsheet of expenses and chart spending by category, and an OpenAPI tool that submits approved reports to the expense system's REST API.

Exam tip: Calculations or charts from uploaded data: code interpreter. Answers from uploaded documents: file search. Existing enterprise index: Azure AI Search tool. Existing REST API with a spec: OpenAPI. Your own code in your app: function calling.

Check yourself

An agent must answer questions from an existing, security-filtered Azure AI Search index. Which tool fits?

The Azure AI Search tool, which connects the agent to that existing index.

Why use code interpreter rather than asking the model to add up numbers?

It runs real Python, so the calculation is exact, while models alone are unreliable at arithmetic.
