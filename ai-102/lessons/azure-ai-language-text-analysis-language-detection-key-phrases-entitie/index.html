Azure AI Language text analysis: language detection, key phrases, entities, entity linking and sentiment with opinion mining

▶ Watch the overview video

Last reviewed September 25, 2026

Azure AI Language offers prebuilt natural language processing (NLP) features that analyze text without any training. You send documents (plain text with an id and optionally a language code) and choose the kind of analysis. The REST call posts to the language/:analyze-text path with a kind such as LanguageDetection, KeyPhraseExtraction, EntityRecognition, EntityLinking or SentimentAnalysis; the SDKs expose methods such as detect_language and analyze_sentiment. Results come back per document, with errors reported per document so one bad input does not fail the batch. Larger jobs, and combining several analyses in one request, use the asynchronous analyze-text jobs endpoint.

Language detection returns the language of each document as a name and ISO 639-1 code (such as 'fr') with a confidence score. It is often the first step in a pipeline, so later calls or translation can use the right language. Very short or mixed-language text lowers confidence, and you can pass a country hint to resolve ambiguity.

Key phrase extraction returns the main talking points of a text, such as 'battery life' and 'customer service', useful for tagging, summarizing trends and search. Named entity recognition (NER) finds entities and categorizes them into types such as Person, Location, Organization, DateTime, Quantity, Email and URL, with subcategories and confidence scores. Entity linking goes a step further and disambiguates entities by linking them to an entry in a knowledge base (Wikipedia), so 'Mars' in 'Mars released a new chocolate bar' links to the company, not the planet.

Sentiment analysis labels each document and each sentence as positive, negative, neutral or mixed, with confidence scores for positive, neutral and negative. Mixed means sentences disagree. Opinion mining (aspect-based sentiment) adds detail: it finds targets (aspects such as 'room' or 'breakfast') and the assessments about them ('spacious', 'cold'), each with its own sentiment. Turn it on with show_opinion_mining=True in the SDK or the opinionMining parameter in REST. It answers questions like 'what exactly are customers unhappy about?'.

Other prebuilt features include summarization (extractive, which picks key sentences, and abstractive, which writes new summary text), Text Analytics for health (medical entities and relations), and PII detection, covered next. Documents have size limits per request, so long texts are split. Many features can also run in containers.

Key terms

Language detection
Identifying the language of text, returned as a name, ISO code and confidence score.
Named entity recognition
Finding entities in text and classifying them into categories such as Person, Location and Organization.
Entity linking
Disambiguating an entity by linking it to a specific knowledge base entry.
Opinion mining
Aspect-based sentiment that connects sentiment to specific targets mentioned in text.
Real-world example

A hotel chain runs 50,000 reviews through Language each month. Language detection routes them, key phrases show trending topics, and opinion mining reveals that 'Wi-Fi' is the most frequent negative target at two sites, so the chain upgrades the network there first.

Exam tip: Overall positive or negative is sentiment; which aspect is liked or disliked is opinion mining. Categorizing entities is NER; resolving which real thing an entity refers to is entity linking.

Check yourself

What does a sentiment result of mixed mean?

The document contains sentences with different sentiments, such as some positive and some negative.

Which feature would distinguish Paris the city from Paris the person?

Entity linking, which links each mention to a specific knowledge base entry.
