Testing, securing and monitoring agents: tracing, human approval and least-privilege tools

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Agents act, so their failures have consequences beyond a bad paragraph: a wrong refund, a leaked record, an email to the wrong person. Testing, security and monitoring must be designed in from the start.

Testing starts in the Foundry agent playground, where you chat with the agent and see each run step and tool call. Beyond manual tests, build a test set of realistic tasks with the expected tool calls and outcomes, and run it after every change to instructions, tools or model. Agent evaluators score things such as whether the agent resolved the user's intent, chose the right tools with correct arguments and followed its instructions. Include difficult cases: ambiguous requests where the agent should ask a question, requests it should refuse, and attempts to manipulate it.

Security starts with least privilege. Give the agent only the tools it needs, and give each tool the narrowest permissions: a read-only database role for lookups, a managed identity scoped to one resource, an API key limited to specific operations. Never let the model's output directly build database queries or shell commands without validation. Keep secrets in Key Vault or managed identities, not in instructions, since instructions can leak.

Human-in-the-loop approval is essential for consequential or irreversible actions such as payments, deletions, sending external email or changing permissions. With function calling this is natural: when the run requires action, your app shows the proposed action and waits for a person to approve before executing it. Set business limits in code, for example refunds above a set amount always need approval, rather than relying on the model to remember a rule.

Defend against prompt injection. Agents read untrusted content (web pages, emails, documents, tool results) that may contain instructions. Enable content filters and prompt shields for document attacks, tell the agent in its instructions to treat retrieved content as data, and limit what a manipulated agent could do through tool permissions.

Monitoring uses tracing: connect the Foundry project to Application Insights so each run records model calls, tool calls, arguments, results, tokens and latency with OpenTelemetry. Review traces for failures, watch metrics for error rates and cost, run continuous evaluation on sampled production conversations, and keep audit logs of every action the agent took on behalf of whom.

Key terms

Least privilege
Granting an agent and its tools only the minimum permissions needed for their task.
Human-in-the-loop
Requiring a person to review or approve an AI action before it takes effect.
Prompt injection
An attack that inserts instructions into model input to override the intended behavior.
OpenTelemetry
An open standard for traces, metrics and logs, used to trace agent runs into Application Insights.
Real-world example

An HR agent can update employee addresses and reset passwords. The team restricts its database identity to the address table, requires the employee to confirm with multifactor authentication before a reset, enables prompt shields, and reviews Application Insights traces weekly for unusual tool calls.

Exam tip: Risky or irreversible actions need human approval enforced in code. Limit damage with least-privilege tool permissions. Finding out which tool call went wrong needs tracing.

Check yourself

Why enforce refund limits in code instead of in the agent's instructions?

Instructions can be ignored or manipulated; code checks are always applied regardless of what the model decides.

What does tracing an agent run record?

Each model call and tool call with arguments, results, token usage and timings, so you can see what the agent did and why.
