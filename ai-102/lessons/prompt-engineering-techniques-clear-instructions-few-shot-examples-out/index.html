Prompt engineering techniques: clear instructions, few-shot examples, output formats and step-by-step reasoning

▶ Watch the overview video

Last reviewed September 25, 2026

Prompt engineering is the practice of writing inputs that reliably get the output you need. It is the cheapest way to improve a generative AI app, so it comes before RAG or fine-tuning. The model only knows what is in its training and in the prompt, and it cannot ask you what you meant, so ambiguity in the prompt becomes inconsistency in the output.

Start with clear, specific instructions in the system message. Say who the model is, who the audience is, what it should and should not do, and what to do when it does not know ('If the answer is not in the provided sources, say you don't know'). Put instructions before the content, and separate content from instructions with clear delimiters such as triple quotes, XML-style tags or markdown headings, so the model does not confuse a document's text with your commands. Break complex tasks into numbered steps.

Few-shot prompting means including a few examples of inputs and the exact outputs you want. Zero-shot means no examples, relying only on instructions. Examples are the most reliable way to teach a format or style: if you want a specific JSON shape or a particular tone, show two or three examples. Examples can be written into the system message or given as earlier user and assistant message pairs. Choose varied examples so the model does not copy one pattern too literally.

Specify the output format explicitly: a JSON schema, a table, a bullet list, a maximum length. Many models support a JSON mode or structured outputs, which guarantee the response is valid JSON matching a schema you provide; use them when code will parse the result.

For problems with several steps, asking the model to reason step by step (chain-of-thought prompting) before giving a final answer often improves accuracy, because the reasoning becomes part of the context for the answer. You can ask for the reasoning in a separate section and show users only the final answer. Reasoning models already do this internally, so for them keep prompts simple and direct instead of prescribing the steps.

Other techniques include giving the model a role, grounding it with relevant facts in the prompt (the basis of RAG), repeating the key instruction at the end of long prompts, and asking the model to check its answer against the rules. Iterate: change one thing at a time and test against the same set of inputs.

Key terms

Few-shot prompting
Including example inputs and desired outputs in the prompt to show the model the task and format.
Zero-shot prompting
Asking the model to perform a task with instructions only and no examples.
Chain-of-thought
Prompting the model to reason step by step before giving its final answer.
Delimiter
Markers such as triple quotes or tags that separate instructions from the content being processed.
Real-world example

An HR tool classifies leave requests. Instructions alone produced labels such as 'Vacation', 'vacation leave' and 'PTO'. Adding a list of allowed labels, three few-shot examples and a JSON output format made every response use exactly one allowed label.

Exam tip: When the scenario is about getting an exact format or style, the answer is usually few-shot examples or structured output. Instructions and rules belong in the system message; content should be clearly delimited.

Check yourself

What is the difference between zero-shot and few-shot prompting?

Zero-shot gives only instructions; few-shot adds example input and output pairs that demonstrate the task.

Why use delimiters around a document you ask the model to summarize?

They separate the content from your instructions, so text inside the document is not treated as a command.
