Microsoft Certified: Azure AI Engineer Associate AI-102 · Domain 3: Implement an agentic solution

Building agents in code with Semantic Kernel, AutoGen and the Microsoft Agent Framework

▶ Watch the overview video

Last reviewed September 25, 2026

Agent Service hosts agents for you, but many teams also build agent logic in their own code with an open-source framework. Frameworks give you abstractions for models, tools, memory and multi-agent patterns, and let you run agents inside your own app or service. The AI-102 objectives name Semantic Kernel and AutoGen, and Microsoft has since introduced the Microsoft Agent Framework, which brings the two together.

Semantic Kernel is Microsoft's SDK for integrating AI models into apps, available for C#, Python and Java. At its center is the kernel, a container that holds AI services (such as an Azure OpenAI chat completion connection) and plugins. A plugin is a group of functions the model can call; in C# you mark a method with the KernelFunction attribute and a description, and in Python you use the kernel_function decorator. With automatic function calling enabled, the kernel sends the plugin functions to the model as tools, runs whichever ones the model chooses and returns the results, so you do not write the tool-call loop yourself. Semantic Kernel's agent framework adds agent types such as a chat completion agent and an Azure AI agent that wraps Agent Service, plus group chat and orchestration patterns for several agents.

AutoGen is an open-source framework from Microsoft Research focused on multi-agent conversation. You define agents with roles, such as an assistant that writes code and a user proxy that executes it or asks a human, and they exchange messages to solve a task. AutoGen made patterns like group chats with a selector deciding who speaks next easy to prototype, and it is popular for research and experimentation.

The Microsoft Agent Framework is the newer open-source SDK that combines Semantic Kernel's enterprise features (connectors, telemetry, type safety) with AutoGen's multi-agent patterns, adding graph-based workflows for deterministic steps. Microsoft positions it as the path forward for both, so expect newer documentation and samples to use it.

Choose based on control and hosting. Agent Service is fastest when you want managed state, built-in tools and little infrastructure. A framework in your own code gives more control over orchestration, lets you mix models and providers and keeps logic in your codebase; frameworks can also use Agent Service agents as building blocks. Whatever you choose, keep tools small and well described, and add tracing.

Key terms

Semantic Kernel
Microsoft's open-source SDK for integrating AI models, plugins and agents into C#, Python and Java apps.
Kernel
The Semantic Kernel container holding AI service connections and plugins.
Plugin
A group of functions, described for the model, that Semantic Kernel exposes as callable tools.
AutoGen
A Microsoft Research open-source framework for building conversations between multiple agents.
Real-world example

A developer wraps the company's C# inventory methods in a Semantic Kernel plugin with KernelFunction attributes and descriptions, enables automatic function calling, and the chat agent can now answer 'Do we have size 42 in stock in Leeds?' by calling the inventory method itself.

Exam tip: Exposing your own methods to the model in Semantic Kernel means a plugin with kernel functions. AutoGen is associated with multi-agent conversations. Agent Service is the managed, hosted option.

Check yourself

What is a Semantic Kernel plugin?

A group of functions, annotated with descriptions, that the kernel can expose to the model as tools.

When would you choose a framework in code over Agent Service?

When you need full control of orchestration in your own codebase, want to mix models or providers, or run agents inside your existing app.
