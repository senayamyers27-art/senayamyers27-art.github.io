Microsoft Certified: Azure AI Engineer Associate AI-102 · Domain 6: Implement knowledge mining and information extraction solutions

Custom skills: calling an Azure Function or web API from a skillset

▶ Watch the overview video

Last reviewed September 25, 2026

Built-in skills cover common AI tasks, but many organizations need enrichment only they can provide: classifying documents with their own model, looking up a customer ID in an internal system, extracting a proprietary code format or calling a specialized service. A custom skill plugs your own code into the enrichment pipeline.

The main type is the custom Web API skill (#Microsoft.Skills.Custom.WebApiSkill). You give it the URI of an HTTPS endpoint, often an Azure Function, plus inputs and outputs just like a built-in skill, and optional settings such as HTTP headers, timeout, batch size (how many documents per request) and degree of parallelism. Authentication can use a function key in the URI or header, or a managed identity of the search service with an Entra ID-protected endpoint. The AML skill variant calls a model deployed in Azure Machine Learning or the Foundry model catalog.

The skill must follow a fixed interface. The search service POSTs a JSON body containing a values array; each item has a recordId and a data object with the named inputs. Your endpoint must return a values array with one item per input record, with the same recordId, a data object containing the named outputs, and optional errors and warnings arrays. Returning the recordIds correctly is essential; that is how results are matched back to documents.

{ "values": [ { "recordId": "1",
    "data": { "documentType": "invoice", "confidence": 0.93 },
    "errors": [], "warnings": [] } ] }

In the skillset definition, the custom skill's context, inputs (paths into the enrichment tree such as /document/content) and outputs (names that become new nodes) connect it with other skills. Its outputs can then be used by later skills, mapped to index fields with output field mappings or projected to a knowledge store.

Design the function for scale: handle batches efficiently, respond within the timeout, return per-record errors rather than failing the whole batch, and make it idempotent since indexers may retry. Test it with the portal's debug session or by posting sample payloads directly. Keep in mind that the search service calls your endpoint for every document, so the function's cost and throughput matter for large corpora.

Key terms

Custom skill
A skill that calls your own code, such as an Azure Function, during AI enrichment.
WebApiSkill
The skill type that calls an external HTTPS endpoint with a defined JSON interface.
recordId
The identifier that links each input record to its output in the custom skill interface.
values array
The top-level array of records sent to and returned from a custom skill.
Real-world example

An insurer wants every indexed claim tagged with its internal fraud risk band. It wraps its existing risk model in an Azure Function that accepts the custom skill values array, adds a WebApiSkill with a batch size of 10, maps the riskBand output to a filterable index field, and investigators filter search results by high risk.

Exam tip: Your own model or lookup during indexing means a custom Web API skill. The endpoint must accept and return a values array with matching recordIds and a data object.

Check yourself

What must each output record from a custom skill include?

The same recordId as the input record and a data object with the output values, plus optional errors and warnings.

How can the search service authenticate to a custom skill endpoint without a key?

By using the search service's managed identity to obtain an Entra ID token for an endpoint protected with Entra ID.
