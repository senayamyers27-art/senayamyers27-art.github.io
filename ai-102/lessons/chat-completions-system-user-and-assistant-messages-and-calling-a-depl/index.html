Chat completions: system, user and assistant messages, and calling a deployment with the Azure OpenAI SDK

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Most generative AI apps use the chat completions API. You send a list of messages, and the model returns the next assistant message. Each message has a role. The system message (in newer models sometimes called the developer message) sets the model's behavior: persona, tone, rules, what topics to stay within, what to do when unsure and the output format. User messages are what the person typed. Assistant messages are the model's earlier replies. You can also include tool messages that return the results of function calls.

The API is stateless. The deployment does not remember anything between requests, so to hold a conversation your app keeps the history and sends the earlier user and assistant messages every time. That history counts toward the context window and the token bill, so long chats are usually trimmed or summarized, keeping the system message and the most recent turns.

In Python, the openai package includes an AzureOpenAI client. You give it your resource endpoint, an API version and either a key or a token provider from Azure Identity. The model argument is your deployment name.

from openai import AzureOpenAI
from azure.identity import DefaultAzureCredential, get_bearer_token_provider

token = get_bearer_token_provider(DefaultAzureCredential(), scope)  # the Cognitive Services token scope
client = AzureOpenAI(azure_endpoint=endpoint, azure_ad_token_provider=token, api_version=api_version)

resp = client.chat.completions.create(
    model="support-chat",  # deployment name
    messages=[
        {"role": "system", "content": "You are a polite support agent for Contoso bikes. Answer only about Contoso products."},
        {"role": "user", "content": "How often should I service my e-bike?"}
    ])
print(resp.choices[0].message.content, resp.choices[0].finish_reason, resp.usage.total_tokens)

The response contains choices, each with a message and a finish_reason: stop means the model finished naturally or hit a stop sequence, length means it hit the token limit, content_filter means output was filtered, and tool_calls means the model wants to call a function. The usage object reports prompt, completion and total tokens, which is what you are billed for. In C#, the Azure.AI.OpenAI package provides an AzureOpenAIClient, from which you get a ChatClient for a deployment and call CompleteChat with SystemChatMessage and UserChatMessage objects. Microsoft also offers the Azure AI Inference and Foundry project SDKs, which can call many catalog models with one interface.

Streaming (stream=True) returns tokens as they are generated, so users see the answer appear quickly even when the full reply takes several seconds.

Key terms

System message
The instruction message that sets the model's behavior, rules and format for the whole conversation.
Stateless API
An API that keeps no memory between calls, so the client must resend context each time.
finish_reason
A field explaining why generation stopped: stop, length, content_filter or tool_calls.
Streaming
Returning generated tokens incrementally as they are produced instead of in one final response.
Real-world example

A support bot kept forgetting the customer's order number after two turns. The developer found the app only sent the latest user message. After changing it to send the system message plus the last ten user and assistant messages, the bot answered follow-ups correctly.

Exam tip: Rules and persona go in the system message. Memory in a chat app comes from resending prior messages, not from the deployment. finish_reason length means raise max tokens.

Check yourself

What argument holds the deployment name in the Python AzureOpenAI client?

The model argument of chat.completions.create.

Why do long conversations get more expensive per turn?

The whole history is resent with every request, so prompt tokens grow each turn.
