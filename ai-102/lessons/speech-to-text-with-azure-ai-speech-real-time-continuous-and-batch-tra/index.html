Speech to text with Azure AI Speech: real-time, continuous and batch transcription

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Azure AI Speech converts spoken audio into text, a capability called speech recognition or speech to text. It supports many languages and powers captions, dictation, voice commands and call-center analytics. Your choice of method depends on whether the audio is live or recorded and how much of it there is.

Real-time recognition uses the Speech SDK (Python, C#, JavaScript, Java and more). You create a SpeechConfig with your key and region (or an endpoint and token), set the recognition language, create an AudioConfig from the default microphone, a WAV file or a stream, and create a SpeechRecognizer. For a single short utterance, such as a voice command, call recognize_once_async: it listens until a pause (or about 15 seconds) and returns one result. The result's reason tells you what happened: RecognizedSpeech with the text, NoMatch if speech could not be recognized, or Canceled with error details such as a wrong key or region.

import azure.cognitiveservices.speech as speechsdk
speech_config = speechsdk.SpeechConfig(subscription=key, region=region)
speech_config.speech_recognition_language = "en-GB"
recognizer = speechsdk.SpeechRecognizer(speech_config=speech_config)
result = recognizer.recognize_once_async().get()
if result.reason == speechsdk.ResultReason.RecognizedSpeech:
    print(result.text)

For longer audio, such as a meeting or a live broadcast, use continuous recognition. You connect handlers to events: recognizing gives interim partial results as the person speaks (good for live captions), recognized gives the final result for each phrase, canceled reports errors and session_stopped signals the end. Then call start_continuous_recognition_async and later stop_continuous_recognition_async. Options include automatic language detection among a list of candidate languages, profanity masking, word-level timestamps and conversation transcription with diarization, which labels which speaker said each phrase.

Batch transcription is for large volumes of recorded audio, such as a day's call-center recordings in Blob Storage. It is a REST API rather than an SDK method: you submit a job with the audio file URLs or a container, the locale and options such as diarization, then poll until it succeeds and download JSON transcripts. It is asynchronous and cost-effective for bulk work. For single recorded files where you want a result quickly, the fast transcription API returns a transcript synchronously, faster than real time.

Accuracy depends on audio quality, background noise and vocabulary. If standard recognition struggles with product names or a noisy setting, a phrase list can boost specific words at runtime, and custom speech models, covered later, adapt recognition further.

Key terms

SpeechConfig
The Speech SDK object holding credentials, region or endpoint, and settings such as recognition language.
recognize_once_async
A Speech SDK method that recognizes a single utterance, ending at a pause.
Continuous recognition
Event-driven recognition of long audio, with interim and final results, until stopped.
Batch transcription
An asynchronous REST API for transcribing large sets of stored audio files.
Real-world example

A radio network uses continuous recognition with the recognizing event to show live captions on its web stream, while its archive team submits a nightly batch transcription job over the day's recorded shows in Blob Storage to make them searchable.

Exam tip: One short command: recognize once. Long live audio: continuous recognition with events. Thousands of stored files: batch transcription. A Canceled result usually means credential, region or connection problems.

Check yourself

Which event gives interim results for live captions?

The recognizing event, which fires with partial text as the person speaks; recognized gives the final text.

Why is batch transcription not available as recognize_once in the SDK?

It is designed for large sets of stored files processed asynchronously through a REST API job, not for live audio.
