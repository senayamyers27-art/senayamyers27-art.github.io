Tuning model output with parameters: temperature, top_p, max tokens, stop sequences and penalties

▶ Watch the overview video

Last reviewed September 25, 2026

A language model generates text one token at a time. At each step it produces a probability for every possible next token and then samples one. Request parameters change how that sampling works and when generation stops, so the same prompt can produce focused, repeatable answers or varied, creative ones. The exam expects you to choose the right parameter for a described behavior.

Temperature scales the probability distribution. Values near 0 make the model almost always pick the most likely token, giving consistent, factual-sounding output; higher values (up to 2) flatten the distribution so less likely tokens are chosen more often, giving more varied and creative text but also more mistakes. top_p (nucleus sampling) limits sampling to the smallest set of tokens whose probabilities add up to p; 0.1 means only the top 10% of probability mass is considered. Both control randomness, so the usual advice is to adjust one and leave the other at its default.

Max tokens (max_tokens, or max_completion_tokens for newer and reasoning models) caps the length of the generated output. If the model reaches it, the answer is cut off and finish_reason is length. It also caps cost, since output tokens are billed. Stop sequences are up to four strings that end generation as soon as the model produces one, useful when you want exactly one item or want to stop before the model starts a new section; the stop string itself is not returned.

Frequency penalty and presence penalty (each from -2 to 2) discourage repetition. The frequency penalty grows with how often a token has already appeared, reducing repeated words and phrases. The presence penalty applies once a token has appeared at all, nudging the model toward new topics. Positive values reduce repetition; high values can make text strange.

Other useful options include n for several alternative completions, seed to make sampling more repeatable, and response_format to request JSON output. Reasoning models have their own controls, such as a reasoning effort setting, and may not support sampling parameters like temperature, so check the model's documentation.

Rules of thumb: extraction, classification and code, low temperature; brainstorming and marketing copy, higher temperature; answers cut off, raise max tokens; repeated phrases, add a small frequency penalty.

Key terms

Temperature
A parameter from 0 to 2 that controls randomness; lower values give more deterministic output.
top_p
Nucleus sampling: only tokens within the top cumulative probability p are considered.
Stop sequence
A string that ends generation when the model produces it.
Frequency penalty
A parameter that reduces the likelihood of tokens in proportion to how often they have already appeared.
Real-world example

A data team extracts fields from contracts into JSON and gets slightly different keys on every run. Setting temperature to 0, providing an example in the prompt and requesting JSON output make the results consistent. Meanwhile the marketing team keeps temperature at 0.9 for slogan ideas.

Exam tip: Consistency means lower temperature. Cut-off answers with finish_reason length mean raise max tokens. Repetition means frequency or presence penalty. Change temperature or top_p, not both.

Check yourself

A model repeats the same phrase many times in long answers. Which parameter helps?

A positive frequency penalty, which lowers the probability of tokens the more they have already been used.

What happens to a stop sequence when the model generates it?

Generation ends immediately and the stop sequence itself is not included in the returned text.
