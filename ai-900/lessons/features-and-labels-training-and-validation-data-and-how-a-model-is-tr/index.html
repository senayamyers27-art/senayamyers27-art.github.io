Microsoft Certified: Azure AI Fundamentals AI-900 · Domain 2: Fundamental principles of machine learning on Azure

Features and labels, training and validation data, and how a model is trained and then used for inference

▶ Watch the overview video

Last reviewed September 25, 2026

Machine learning starts with data, usually arranged as a table. Each row is an observation (one house, one patient, one transaction) and each column is a value describing it. Understanding what the columns are for is the foundation of every other ML topic on AI-900.

Features are the input columns the model uses to make a prediction. For a house-price model, features might be floor area, number of bedrooms, age and distance to the station. The label is the column you want to predict, here the sale price. Mathematically, a model is a function y = f(x), where x is the set of feature values and y is the predicted label. Training is the process of finding a function that maps x to y well.

When the training data includes known labels, the approach is called supervised learning: the algorithm is supervised by the correct answers. Regression and classification are supervised. When the data has no labels, as in clustering, it is unsupervised learning: the algorithm finds structure on its own.

You never evaluate a model only on the data it learned from, because a model can memorize its training examples and still fail on new ones. Instead you split the data. Most rows (often around 70 to 80 percent) form the training set that the algorithm learns from. The rest are held back as a validation (or test) set. After training, you use the model to predict labels for the validation rows and compare the predictions with the actual labels to calculate metrics.

Overfitting is when a model fits the training data too closely, including its noise, and performs much worse on validation data. Underfitting is when a model is too simple to capture the pattern and performs poorly on both. The goal is a model that generalizes: it performs well on data it has not seen.

Training is iterative. Data scientists try different algorithms, adjust settings called hyperparameters, engineer better features and retrain until validation metrics are good enough. The chosen model is then deployed, and applications send it new feature values to get predictions. That use of the model is inferencing. At inference time there is no label; predicting it is the whole point.

Key terms

Feature
An input value the model uses to make a prediction, such as age or floor area.
Label
The value a supervised model is trained to predict, such as price or a yes/no outcome.
Validation data
Data held back from training and used to measure how well the model performs on unseen examples.
Overfitting
When a model learns the training data too closely and performs poorly on new data.
Real-world example

A bike-sharing company has two years of daily records: temperature, rainfall, day of week, holiday flag and number of rentals. It trains on 80 percent of the days, checks predictions against the other 20 percent, and then deploys the model so tomorrow's weather forecast produces a rental estimate for staffing.

Exam tip: If the question asks which column is the label, pick the value being predicted. A big gap between training and validation performance means overfitting.

Check yourself

In a dataset for predicting whether an email is spam, what is the label?

The spam or not spam column, because that is what the model predicts; the email's words and sender are features.

Why must validation data be kept separate from training data?

So you can measure how the model performs on data it has not seen, which reveals overfitting.
