Creating and using Azure AI services resources: multi-service vs single-service resources, endpoints, keys and the free F0 tier

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Before your app can call any Azure AI service, you need a resource for it in your Azure subscription. The resource gives you an endpoint to call, credentials to authenticate and a place for billing. AI-900 tests the choices you make when creating one.

A multi-service resource, named Azure AI services in the portal, provides access to several AI services, such as Vision, Language, Speech, Translator and Document Intelligence, through one resource with one set of keys and consolidated billing. It suits developers who use several services and want to manage them together. Azure OpenAI models and other generative AI models can also be used through Foundry resources, covered in domain 5.

A single-service resource provides access to just one service, such as Azure AI Vision or Azure AI Language. Choose it when you use only that service, want to track its costs separately, need a separate access boundary, or want the free tier. Most single-service resources offer a free F0 pricing tier with limited transactions per month, which is enough for learning and prototypes; the standard tiers (such as S0) are paid per use. The multi-service resource does not have a free tier.

Every resource has an endpoint, a URL your app sends requests to, and two keys. Clients authenticate by sending a key in a request header, or, preferably in production, by using Microsoft Entra ID so that no key is stored in code. There are two keys so you can regenerate one while apps use the other, then switch, without downtime. Keys should be kept in a secure store such as Azure Key Vault, never in source code.

You also choose a region, which affects latency, data residency and which features are available, and a resource group for management. After creating the resource, you can test it without code in the Foundry portal or the service's studio (such as Vision Studio or Language Studio), then use the REST API or SDKs from your application.

When you finish a lab, delete the resource or its resource group so nothing keeps billing, and prefer F0 where the service offers it.

Key terms

Multi-service resource
An Azure AI services resource that gives one endpoint and set of keys for several AI services with one bill.
Single-service resource
A resource for one AI service, such as Azure AI Vision, often with a free F0 tier.
Endpoint
The URL an application calls to use the AI service.
Resource key
A secret value sent with requests to authenticate to an AI service; each resource has two.
Real-world example

A student building a class demo creates a single-service Azure AI Vision resource on the F0 tier, stores the endpoint and key in environment variables, and tests the caption feature. Her employer's production app instead uses one multi-service Azure AI services resource for Vision, Language and Translator, with Microsoft Entra ID authentication and one consolidated bill.

Exam tip: One key and endpoint for many services, one bill: multi-service. Free F0 tier or separate billing for one service: single-service. An app needs the endpoint plus a key (or Entra ID) to call it.

Check yourself

Why does each Azure AI services resource have two keys?

So you can rotate keys without downtime: apps switch to the second key while the first is regenerated.

Which resource type should you pick to experiment with Azure AI Language at no cost?

A single-service Language resource on the free F0 tier, where available.
