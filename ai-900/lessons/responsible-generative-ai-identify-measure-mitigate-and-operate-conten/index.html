Microsoft Certified: Azure AI Fundamentals AI-900 · Domain 5: Generative AI workloads on Azure

Responsible generative AI: identify, measure, mitigate and operate; content filters and Azure AI Content Safety

▶ Watch the overview video

Last reviewed September 25, 2026

Generative AI brings new kinds of risk: output that is harmful, biased, false or leaks information, and users who try to misuse the system. Microsoft's guidance for responsible generative AI organizes the work into four stages: identify, measure, mitigate and operate. AI-900 tests the stages and the Azure tools that support them.

Identify potential harms. List what could go wrong for this specific solution, such as offensive content, dangerous advice, fabricated facts, privacy leaks or being tricked into ignoring instructions, and prioritize them by likelihood and impact. Red teaming (testing by deliberately trying to provoke failures) helps find them. Document the results.

Measure the harms. Create test prompts that are likely to trigger each harm, run them through the system, and measure how often and how severely harmful output occurs, using manual review and automated evaluations. Measuring gives a baseline to compare mitigations against.

Mitigate the harms in layers. At the model layer, choose a model suited to the use case and, if needed, fine-tune it. At the safety system layer, use content filters and abuse monitoring. At the system message and grounding layer, write instructions that define behavior and ground answers in trusted data. At the user experience layer, design the interface to limit misuse, disclose that content is AI-generated, and encourage users to verify output. Each layer catches what others miss.

Operate responsibly. Before release, complete legal, privacy and security reviews; then roll out gradually, monitor usage and feedback, have an incident response plan and be ready to roll back.

Azure OpenAI deployments include a content filtering system by default. It classifies both prompts and completions into harm categories (hate, sexual, violence and self-harm) at severity levels, and blocks content above the configured threshold. Optional filters detect jailbreak attempts (prompt attacks), protected material such as known copyrighted text or code, and ungrounded content. Azure AI Content Safety is a standalone service that offers the same kinds of analysis for any app: moderating user-generated text and images, detecting prompt attacks and checking groundedness. Filters reduce risk but do not remove it, which is why the other layers matter.

Key terms

Identify, measure, mitigate, operate
Microsoft's four stages for developing and running generative AI responsibly.
Content filter
A safety system that classifies prompts and responses for harmful content and blocks it above a set severity.
Azure AI Content Safety
A service that detects harmful content in text and images and offers features such as prompt attack detection.
Jailbreak
A prompt designed to trick a model into ignoring its instructions or safety rules.
Real-world example

A school builds a homework helper. The team identifies harms (inappropriate content, giving answers instead of guidance), measures them with 500 test prompts, mitigates with strict content filter thresholds, a system message that tells the model to coach rather than solve, and an interface that shows students it is AI, then operates it with teacher feedback and weekly reviews.

Exam tip: Memorize the order: identify, measure, mitigate, operate. Mitigation has four layers: model, safety system, system message and grounding, user experience. Content filters cover hate, sexual, violence and self-harm.

Check yourself

Which mitigation layer does a content filter belong to?

The safety system layer.

What does Azure AI Content Safety offer beyond the built-in Azure OpenAI filters?

It is a standalone service you can use to moderate any app's text and images, with features such as prompt attack detection and groundedness checks.
