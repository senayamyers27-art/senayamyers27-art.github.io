Azure OpenAI models in Foundry: GPT chat models, embeddings models and image generation models

▶ Watch the overview video

Last reviewed September 25, 2026

Azure OpenAI gives organizations access to OpenAI's models, hosted in Azure. It is available through Microsoft Foundry, where Azure OpenAI models appear in the model catalog alongside models from other providers. What Azure adds is enterprise hosting: Azure identity and access control, private networking options, regional deployment choices, built-in content filtering and Microsoft's data protection commitments.

The models fall into a few families, and AI-900 expects you to match each family to a job. GPT chat (chat completion) models, such as the GPT-4o and later GPT model series, take a conversation of messages and generate a response. They power chat assistants, copilots, summarization, drafting, classification by prompt and code generation. Some accept images as input as well as text (multimodal). Reasoning models spend more computation working through complex problems before answering, which helps with multi-step tasks such as math and planning.

Embeddings models convert text into vectors that represent meaning. They do not generate readable text. They are used for semantic search, recommendations, clustering and, above all, the retrieval step of RAG, where document chunks and user questions are embedded so the most relevant chunks can be found.

Image generation models create images from text descriptions (DALL-E and the newer GPT image models are examples). Use them for marketing visuals, concept art and design ideas; content filters also apply to image prompts and outputs. Audio-capable models handle speech input and output for voice experiences, and Azure AI Speech remains the service for classic speech to text and text to speech.

To use a model, you deploy it in your Foundry resource or project, choosing a deployment type and capacity; your app then calls the deployment's endpoint using the deployment name. Usage is billed, typically per input and output token for language models; there is no free tier for Azure OpenAI, so delete deployments you are not using. Microsoft states that prompts and completions are not used to train OpenAI's or Microsoft's foundation models.

The exam angle is fit: chat and text generation, choose a GPT chat model; search by meaning, choose an embeddings model; create pictures, choose an image generation model.

Key terms

Azure OpenAI
OpenAI models hosted in Azure with Azure security, networking, content filtering and data protection.
Chat completion model
A model that takes a conversation of messages and generates the next response, such as a GPT model.
Embeddings model
A model that converts text into vectors for semantic search and similarity, not readable text.
Deployment
An instance of a model in your resource, with a name and endpoint that your app calls.
Real-world example

A publisher builds a research assistant. An embeddings model vectorizes 20 years of articles for semantic search, a GPT chat model answers readers' questions using the retrieved articles, and an image generation model creates illustrations for newsletters.

Exam tip: Vectors for search and RAG: embeddings model. Conversation and text generation: GPT chat model. Pictures from text: image generation model. Azure OpenAI is billed, with no free tier.

Check yourself

Which model type is used to index documents for semantic search in a RAG solution?

An embeddings model, which converts text into vectors.

What does an app use to call a specific model in Azure OpenAI?

The endpoint and the name of the model deployment, with a key or Microsoft Entra ID authentication.
