Prompt engineering: system messages, user prompts, few-shot examples and clear instructions

▶ Watch the overview video

Last reviewed September 25, 2026

A prompt is everything you send a generative model to get a response. Prompt engineering is the practice of designing prompts that produce accurate, relevant and consistently formatted output. It is the cheapest and fastest way to improve a generative AI app, before considering grounding or fine-tuning.

Chat models receive messages with roles. The system message comes first and sets the model's behavior for the whole conversation: its role and persona, the task, rules and boundaries, tone and output format. For example: 'You are a support assistant for Contoso Outdoor. Answer only questions about Contoso products. If you don't know, say so. Reply in no more than three bullet points.' The user message contains the user's actual request. Assistant messages hold the model's earlier replies, so the conversation history gives context for follow-up questions.

Clear instructions matter. Be specific about what you want, the audience, the length and the format (a table, JSON, bullet points). Break complex tasks into steps. Provide the relevant context rather than assuming the model knows it. Say what to do rather than only what not to do. Use delimiters, such as triple quotes or headings, to separate instructions from content the model should work on.

Few-shot prompting includes a small number of examples of input and desired output in the prompt, so the model copies the pattern: for example, three product reviews each followed by the category you want. Zero-shot prompting gives only the instruction with no examples. One-shot gives a single example. Examples are especially effective for enforcing a format or a style.

Other techniques include asking the model to work through a problem step by step before answering (chain-of-thought style prompting), asking it to cite which provided source supports each statement, and specifying a fallback answer when information is missing. Prompts are also a safety layer: a well-written system message can reduce off-topic, ungrounded or harmful responses, though it does not replace content filters.

Prompt engineering is iterative: try a prompt, inspect results, adjust and test again, ideally with a set of representative test inputs. In Microsoft Foundry, the chat playground lets you edit the system message, add examples and compare results without writing code.

Key terms

System message
Instructions sent before the conversation that set the model's role, rules, tone and output format.
User prompt
The user's request or question sent to the model.
Few-shot prompting
Including a few examples of input and desired output in the prompt so the model follows the pattern.
Zero-shot prompting
Giving the model only an instruction, with no examples.
Real-world example

A retailer's classification prompt returned inconsistent labels. The team added a system message listing the five allowed categories, asked for output as a single word, and included three labeled examples (few-shot). Consistency improved immediately, with no retraining.

Exam tip: Role, rules and format that apply to the whole conversation go in the system message. Examples in the prompt are few-shot. Changing the model's weights is fine-tuning, not prompt engineering.

Check yourself

Where should you put 'Always answer in formal English and never give legal advice'?

In the system message, because it sets rules for the whole conversation.

What is few-shot prompting?

Including a few examples of input and desired output in the prompt so the model follows the same pattern.
