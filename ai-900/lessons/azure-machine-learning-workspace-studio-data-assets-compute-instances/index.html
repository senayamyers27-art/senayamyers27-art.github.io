Azure Machine Learning: workspace, studio, data assets, compute instances and compute clusters

▶ Watch the overview video

Last reviewed September 25, 2026

Azure Machine Learning is Microsoft's cloud platform for data scientists and ML engineers to train, deploy and manage their own machine learning models. Where Azure AI services give you pretrained models through an API, Azure Machine Learning is for when you need a model trained on your own data for your own prediction task.

Everything starts with a workspace, the top-level Azure resource that holds all your machine learning assets: data, compute, experiments, models and endpoints. When you create a workspace, Azure also creates or links supporting resources, including a storage account (for data and files), a key vault (for secrets), Application Insights (for monitoring) and optionally a container registry (for model images).

Azure Machine Learning studio is the web portal for working in the workspace. From it you can upload and browse data, run notebooks, start automated ML jobs, build pipelines in the designer, view job results and metrics, register models and deploy endpoints. Developers can do the same with the Python SDK or the Azure CLI machine learning extension.

Data assets are references to data you use for training, such as a file or folder in Azure Blob Storage or a table. Registering data as an asset gives it a name and version, so experiments are reproducible and teammates reuse the same data. Datastores hold the connection information to the underlying storage.

Compute is where the work runs, and it is where the cost is. A compute instance is a managed cloud virtual machine for one data scientist, used for notebooks and development; you should stop it when you are not using it. A compute cluster is a set of VMs that scales out automatically to run training jobs and can scale down to zero nodes when idle, so you only pay while jobs run. Models can also be deployed to managed online endpoints, and you can attach existing compute such as a Kubernetes cluster.

Azure Machine Learning also tracks each training job, its parameters, metrics and outputs, and keeps a model registry with versions. That history supports accountability and makes it possible to reproduce or roll back a model later.

Key terms

Workspace
The top-level Azure Machine Learning resource that holds data, compute, jobs, models and endpoints.
Azure Machine Learning studio
The web portal for working with an Azure Machine Learning workspace.
Compute instance
A managed development VM for one user's notebooks and experiments.
Compute cluster
A group of VMs that scales automatically for training jobs and can scale to zero when idle.
Real-world example

A retail analytics team creates one workspace per project. Each analyst has a small compute instance that auto-stops in the evening, training jobs run on a compute cluster that scales from zero to eight nodes, and the sales history is registered as a versioned data asset so every experiment uses the same data.

Exam tip: Compute instance is for development by one person; compute cluster is for scalable training jobs. Azure Machine Learning is for training your own models; Azure AI services give you prebuilt ones.

Check yourself

Which Azure Machine Learning compute type can scale to zero nodes to save cost between training jobs?

A compute cluster.

When would you choose Azure Machine Learning over an Azure AI service?

When you need to train a custom model on your own data for a prediction task that prebuilt services do not cover, such as predicting your own sales.
