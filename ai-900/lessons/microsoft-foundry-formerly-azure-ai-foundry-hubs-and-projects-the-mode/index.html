Microsoft Foundry (formerly Azure AI Foundry): hubs and projects, the model catalog and the playgrounds

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Microsoft Foundry is Microsoft's platform and portal for building generative AI apps and agents on Azure. It was previously called Azure AI Studio and then Azure AI Foundry, and you may still see those names in older training material and exam questions. Product names in this area change often; the concepts below are what matter.

Work in Foundry is organized into projects. A project is a workspace for one solution: it holds your model deployments, agents, data connections, evaluations and files, and lets a team collaborate with shared access. Projects sit on top of Azure resources that provide the models, storage, security and billing. In the current design, a Foundry resource contains projects directly. An older design used a hub resource that held shared settings and connections (such as to Azure AI Search or storage) for several projects; hub-based projects still exist, so recognize both terms.

The model catalog is where you discover and compare models. It includes Azure OpenAI models, other Microsoft models (such as the small Phi family), and models from providers such as Meta, Mistral and others, plus open-source models. Each model has a model card describing its capabilities, intended uses, limitations and deployment options. Benchmarks and leaderboards help compare quality, cost and speed. From the catalog you deploy a model to your project, which gives it an endpoint your app can call. Some models are billed per token as a managed service; others run on compute you provision.

The playgrounds let you try things without code. The chat playground lets you pick a deployed chat model, write a system message, add examples, adjust parameters such as temperature and max tokens, add your own data for grounding and see the results immediately. There are also playgrounds for agents, images and some Azure AI services such as speech and language. When a prompt works well, you can view sample code to use it in an application.

Foundry also provides tools for the rest of the lifecycle: connecting data and Azure AI Search for RAG, building agents, running evaluations, configuring content filters and guardrails, and monitoring deployed apps. Azure AI services such as Vision, Language, Speech and Content Safety can be used from the same portal.

For AI-900, remember what each part is for: projects organize the work, the model catalog helps you choose and deploy models, and the playgrounds let you experiment before writing code.

Key terms

Microsoft Foundry
Microsoft's platform and portal for building generative AI apps and agents, formerly Azure AI Studio and Azure AI Foundry.
Project
A Foundry workspace that holds a solution's model deployments, agents, data connections and evaluations.
Model catalog
The Foundry library for discovering, comparing and deploying models from Microsoft, OpenAI and other providers.
Model card
Documentation describing a model's capabilities, intended uses, limitations and deployment options.
Real-world example

A developer creates a Foundry project for an internal policy assistant, compares two chat models in the model catalog using their model cards and benchmarks, deploys the cheaper one, and iterates on the system message in the chat playground before copying the sample code into her app.

Exam tip: Compare and choose models: model catalog. Try prompts and settings without code: playground. Organize a solution's assets and team access: project. Expect both the Azure AI Foundry and Microsoft Foundry names.
