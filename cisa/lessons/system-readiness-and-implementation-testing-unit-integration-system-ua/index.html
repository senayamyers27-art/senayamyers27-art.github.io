ISACA Certified Information Systems Auditor (CISA) 2024 job practice · Domain 3: Information systems acquisition, development and implementation

System readiness and implementation testing: unit, integration, system, UAT and regression

▶ Watch the overview video

Last reviewed September 29, 2026 · Leer en español

Testing shows whether a system does what it should, including its controls, before it is trusted with real work. A system that goes live untested can corrupt data, expose information or stop business operations.

Testing happens at several levels. Unit testing checks individual modules, usually by developers. Integration testing checks that modules and interfaces work together and pass data correctly. System testing checks the whole system against functional and non-functional requirements, including performance, stress, security, recovery and usability. User acceptance testing (UAT) lets business users confirm the system meets their requirements in realistic scenarios; the system owner signs off. Regression testing reruns earlier tests after changes to confirm nothing that previously worked has broken. Final acceptance may also include quality assurance review and security testing, such as vulnerability scans or penetration tests.

Testing techniques include black-box testing, which checks outputs for given inputs without looking at code, and white-box testing, which examines internal logic and paths. Test data should cover valid, invalid and boundary cases, and should not use real personal data unless it is masked or anonymized. Tests should run in a separate test environment that mirrors production, so tests cannot damage live data.

Readiness also covers operations: documentation, trained users and support staff, backup and recovery procedures, monitoring, and a rollback plan. The auditor reviews test plans, results, defect logs and sign-offs, and checks that serious defects were fixed or formally accepted by the owner before go-live.

Key terms

Unit testing
Testing individual program modules in isolation, usually by developers.
User acceptance testing (UAT)
Testing by business users to confirm the system meets their requirements before go-live.
Regression testing
Rerunning previous tests after a change to confirm existing functions still work.
Black-box testing
Testing functionality by checking outputs for given inputs without examining internal code.
Real-world example

Before launching a new billing system, users run UAT scripts covering normal bills, credits and edge cases. Two defects remain open; the finance director signs an acceptance that one is minor and requires the other, which misstates tax, to be fixed and retested before go-live.

Exam tip: UAT sign-off belongs to the business users and system owner, not IT. And production data used in testing should be masked to protect privacy.

Check yourself

What is the purpose of regression testing?

To confirm that changes have not broken functions that previously worked.

Why should testing use a separate environment?

So tests cannot damage live data or disrupt operations, and so test activity is kept apart from production.
