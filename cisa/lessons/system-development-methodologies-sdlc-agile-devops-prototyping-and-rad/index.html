ISACA Certified Information Systems Auditor (CISA) 2024 job practice · Domain 3: Information systems acquisition, development and implementation

System development methodologies: SDLC, agile, DevOps, prototyping and RAD

▶ Watch the overview video

Last reviewed September 29, 2026 · Leer en español

A system development methodology is the structured way an organization turns requirements into working software. Auditors do not need to prefer one method, but they must understand where controls sit in each and what evidence to expect.

The traditional system development life cycle (SDLC), or waterfall model, moves through phases in sequence: feasibility, requirements definition, design, development, testing, implementation and post-implementation. Each phase ends with deliverables and sign-off, which makes control points easy to identify. Its weakness is inflexibility: requirements are fixed early, and problems found late are expensive to fix.

Agile methods, such as Scrum, deliver working software in short iterations called sprints. Requirements are captured as user stories in a prioritized product backlog, each with acceptance criteria. Roles include the product owner, who prioritizes the backlog; the development team; and a facilitator such as a Scrum master. Documentation is lighter but still exists. Auditors look for security and control requirements in the backlog, definition of done criteria, testing within each sprint, and controlled release. DevOps extends agile by joining development and operations with automated build, test and deployment pipelines. Controls then become automated gates: code review, automated security tests and approval before production deployment. DevSecOps emphasizes building security into these pipelines.

Prototyping builds quick models to clarify requirements with users; the risk is that a prototype is pushed into production without proper controls. Rapid application development (RAD) uses prototypes, reusable components and time-boxing to deliver fast. Whatever the method, the auditor checks that requirements include controls, that testing is adequate, and that changes to production are authorized.

Key terms

Waterfall (SDLC)
A sequential development approach where each phase is completed and signed off before the next begins.
Product backlog
A prioritized list of features and requirements, usually written as user stories, used in agile development.
DevOps
Practices that combine development and operations with automation to deliver changes quickly and reliably.
Prototyping
Building an early working model of a system to refine requirements with users.
Real-world example

An auditor reviews a team using Scrum and DevOps. She finds user stories for security requirements in the backlog, automated tests in the pipeline and a rule that the pipeline blocks deployment without a peer-approved pull request, which gives evidence of change control without heavy documents.

Exam tip: Agile and DevOps do not mean no controls. Look for controls in different places: backlog acceptance criteria, definition of done, automated tests and pipeline approval gates.

Check yourself

What is a major risk of prototyping?

The prototype may be moved into production without proper controls, testing or documentation.

Where are change controls typically found in a DevOps environment?

In automated pipeline gates such as required code reviews, automated tests and approvals before deployment.
