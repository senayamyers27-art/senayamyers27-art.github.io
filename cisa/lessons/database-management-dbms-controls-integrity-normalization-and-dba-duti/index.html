Database management: DBMS controls, integrity, normalization and DBA duties

▶ Watch the overview video

Last reviewed September 29, 2026 · Leer en español

Databases hold the organization's most valuable data, so they deserve focused audit attention. A database management system (DBMS) stores data and controls access to it, enforces integrity rules, manages concurrent use and supports backup and recovery.

Relational databases organize data in tables of rows and columns linked by keys. A primary key uniquely identifies each row; a foreign key links to a primary key in another table. Referential integrity ensures a foreign key always points to a real record, for example no orders for a customer who does not exist. Entity integrity ensures each row has a unique, non-null primary key. Normalization organizes tables to store each fact once, reducing redundancy and update anomalies; denormalization intentionally adds some redundancy for performance and must be controlled so copies stay consistent. Transactions follow ACID properties (atomicity, consistency, isolation and durability) so that updates are all-or-nothing and survive failures.

The database administrator (DBA) has powerful access: defining structures, managing performance, backups and recovery, and often granting access. Because DBA privileges can bypass application controls, compensating controls are essential: limiting the number of DBAs, using individual named accounts, logging DBA activity to a store they cannot modify, independent review of those logs, and change management for schema changes. Direct changes to production data outside the application should be rare, approved and logged.

Other controls include access through views or roles that show users only the data they need, encryption of sensitive fields, database activity monitoring, and tested backups including transaction logs for point-in-time recovery.

Key terms

Referential integrity
A rule ensuring that foreign key values always match an existing primary key in the related table.
Normalization
Structuring a database so each fact is stored only once, reducing redundancy and inconsistency.
ACID
Properties of reliable transactions: atomicity, consistency, isolation and durability.
Database activity monitoring
Tools that record and analyze database access and changes, especially by privileged users.
Real-world example

An auditor finds that three DBAs share one administrator account and that database logs are stored where the DBAs can delete them. She recommends named accounts, forwarding logs to the security team's system, and a monthly review of direct data changes by someone outside the DBA team.

Exam tip: DBAs can bypass application controls. The best answers involve logging DBA activity to a protected location and having someone independent review it.

Check yourself

What does referential integrity prevent?

Records that refer to non-existent related records, such as orders for a customer that does not exist.

Why is a shared DBA account a problem?

Actions cannot be traced to an individual, which destroys accountability.
