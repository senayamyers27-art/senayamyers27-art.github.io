System migration, infrastructure deployment and data conversion

▶ Watch the overview video

Last reviewed September 29, 2026 · Leer en español

Moving to a new system usually means moving data and often infrastructure too, for example from on-premises servers to the cloud. Migrations fail when data is lost, altered or mismapped, or when the new environment is not configured securely.

Data conversion follows a planned sequence: identify source data and owners, clean it, map fields from old to new formats, define conversion rules, run trial conversions, reconcile results, fix exceptions, and perform the final conversion. Reconciliation is the key control. Record counts, control totals of amounts and hash totals of key fields are compared between source and target, and samples of records are checked in detail. The data owner signs off that the converted data is complete and accurate. The old data and system should be kept, in read-only form, until the new system is verified and any retention requirements are met.

Controls during conversion include restricting who can run conversion programs, logging all manual corrections, keeping an audit trail of conversion runs and protecting sensitive data in transit and in staging areas. Developers should not change production data directly to fix errors.

Infrastructure deployment needs its own controls: approved build standards and hardened configurations, infrastructure as code reviewed like application code, network segmentation, backup and monitoring set up before go-live, and capacity sized for expected load. In cloud migrations, the organization must understand the shared responsibility model and configure identity, encryption and logging properly. The auditor checks conversion plans and reconciliation evidence, sign-offs and the security configuration of the new environment.

Key terms

Data conversion
Transforming and moving data from an old system's format to a new system's format.
Data mapping
Defining how each field in the source system corresponds to fields in the target system.
Control total
A sum of a numeric field, such as amounts, used to confirm that all data was processed or transferred.
Infrastructure as code
Defining and deploying infrastructure through version-controlled configuration files instead of manual setup.
Real-world example

A credit union migrates 200,000 member accounts. Record counts match, but the sum of balances differs by $1,240. Investigation finds that accounts with negative balances were mapped incorrectly; the mapping is fixed, the trial rerun and reconciled, and the finance director signs off.

Exam tip: Reconciliation with record counts, control totals and hash totals, signed off by the data owner, is the key data conversion control. Keep the old data until the conversion is verified.

Check yourself

Who should sign off converted data?

The data owner in the business, after reviewing reconciliation results.

Why should old data be retained after conversion?

To allow verification, correction or rollback and to meet retention requirements.
