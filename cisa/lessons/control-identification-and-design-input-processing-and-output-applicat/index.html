Control identification and design: input, processing and output application controls

▶ Watch the overview video

Last reviewed September 29, 2026 · Leer en español

Controls are cheapest and most effective when designed into a system rather than added after go-live. During requirements and design, the project team, with advice from security, risk and audit, should identify the risks in the business process and build in application controls to address them. The auditor can advise on what controls are needed but should not design them, to protect independence.

Input controls ensure data entering the system is authorized, complete and accurate. Examples include authorization of source transactions, edit and validation checks such as validity checks (the value is allowed), range checks, limit checks, reasonableness checks, format checks, existence checks against master data, check digits on account numbers, and completeness checks for required fields. Batch controls such as record counts, control totals and hash totals help confirm that a batch was entered completely.

Processing controls ensure data is processed completely and accurately. Examples include run-to-run totals that carry control figures between processing steps, recalculation and reasonableness checks, exception reports for items that fail rules, and controls to prevent duplicate processing. Data file controls protect master data from unauthorized change, for example by logging and reviewing changes to vendor bank details.

Output controls ensure results are complete, accurate and delivered only to authorized recipients. They include reconciling output totals with input and processing totals, controlled distribution of sensitive reports, retention rules and secure disposal. Audit trails that record who did what and when support both detection and investigation. The auditor checks that controls match the risks, are tested, and cannot be bypassed.

Key terms

Validity check
An edit check that accepts only values that are permitted for a field, such as real dates or valid codes.
Hash total
A total of a non-financial field, such as account numbers, used to detect changes or missing items in a batch.
Run-to-run totals
Control totals carried from one processing step to the next to confirm nothing was lost or added.
Check digit
A calculated digit appended to a number that detects transcription errors when the number is entered.
Real-world example

In a new expense system, the design team adds a limit check that flags claims over $5,000 for director approval, a validity check that rejects future dates, a duplicate check on receipt numbers and a monthly reconciliation of paid claims to the general ledger.

Exam tip: Match the control to the error: validity or range checks for bad individual values, record counts and hash totals for missing or altered batch items, reconciliations for completeness of output.

Check yourself

Which control detects a transposed digit in an account number?

A check digit.

Why should controls be designed in rather than added later?

It is cheaper and more effective, and it avoids gaps between the system and the controls built around it.
