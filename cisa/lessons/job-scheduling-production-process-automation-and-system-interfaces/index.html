ISACA Certified Information Systems Auditor (CISA) 2024 job practice · Domain 4: Information systems operations and business resilience

Job scheduling, production process automation and system interfaces

▶ Watch the overview video

Last reviewed September 29, 2026 · Leer en español

Much IT processing happens without anyone pressing a button. Batch jobs run overnight to post transactions, calculate interest or produce reports, and interfaces move data between systems. If these automated processes fail, run twice or are altered, the damage can be large and quiet.

Job scheduling software runs jobs in the right order at the right time and handles dependencies, such as not running payroll before timesheets load. Controls include restricting who can add or change scheduled jobs, requiring change management for schedule changes, monitoring job completion and failures, reviewing exception and rerun logs, and keeping developers out of production scheduling. Automated scheduling reduces human error compared with manual operation, but only if the schedule itself is protected.

System interfaces move data between applications, in batch files or in real time through application programming interfaces (APIs). Each interface is a point where data can be lost, duplicated, altered or exposed. Controls include record counts and control totals compared at the sending and receiving ends, sequence numbers to detect missing or duplicate transmissions, error handling and exception queues that someone reviews, authentication between systems, encryption in transit and logging. Interfaces should be inventoried with owners, so it is clear who investigates when reconciliation fails.

Production process automation, including robotic process automation (RPA) bots, needs the same discipline: bots should have their own accounts with least privilege, changes to bot logic should go through change control, and their outputs should be monitored. The auditor reviews schedule access, change records, exception handling and interface reconciliations.

Key terms

Job scheduler
Software that runs batch jobs automatically in a defined order and time.
System interface
A connection that transfers data between two applications, by file or in real time.
Application programming interface (API)
A defined way for software components to request and exchange data with each other.
Robotic process automation (RPA)
Software bots that mimic user actions to automate repetitive tasks.
Real-world example

Each night an interface sends approved invoices from procurement to accounts payable. A reconciliation report compares count and total amount at both ends; one morning it shows 412 sent and 409 received, and the AP supervisor investigates the three missing invoices before payments run.

Exam tip: For interfaces, the best completeness control is reconciliation of counts and totals between sending and receiving systems. Encryption protects confidentiality but does not prove completeness.

Check yourself

Why should developers not be able to change the production job schedule?

They could run or alter jobs in production without change control, bypassing segregation of duties.

Name two controls over an interface.

Any two of: record counts and control totals reconciled at both ends, sequence checks, error queues reviewed by an owner, authentication, encryption and logging.
