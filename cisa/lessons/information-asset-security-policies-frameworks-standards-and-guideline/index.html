ISACA Certified Information Systems Auditor (CISA) 2024 job practice · Domain 5: Protection of information assets

Information asset security policies, frameworks, standards and guidelines

▶ Watch the overview video

Last reviewed September 29, 2026 · Leer en español

Protecting information assets starts with clear direction. An information security program sets out what must be protected, how much protection it needs and who is responsible, and it gives auditors criteria to test against.

The core document is the information security policy, approved by senior management, which states objectives, scope, roles and the commitment to protect information. Supporting policies cover topics such as acceptable use, access control, classification, encryption, remote work and incident response. Standards set mandatory specifics, such as minimum password or key lengths. Security baselines or hardening standards define minimum secure configurations for each platform, often based on recognized benchmarks. Procedures describe how to perform tasks, and guidelines offer recommended practice. Everything should be reviewed regularly and approved exceptions tracked with owners and expiry dates.

Frameworks give structure and a common language. ISO/IEC 27001 specifies requirements for an information security management system (ISMS) and can be certified; ISO/IEC 27002 gives guidance on controls. The NIST Cybersecurity Framework organizes outcomes into functions including govern, identify, protect, detect, respond and recover. The CIS Critical Security Controls give a prioritized set of technical safeguards. COBIT connects security to overall IT governance. Organizations often map their controls to several frameworks at once.

Roles matter: senior management is accountable, the information security manager or CISO runs the program, data owners decide protection needs, custodians implement controls and all users follow policy. The auditor checks that policies exist and are approved, current, communicated and enforced, and that baselines are applied consistently, for example by comparing actual server settings with the hardening standard.

Key terms

Information security management system (ISMS)
A systematic approach to managing information security risks through policies, processes and controls, as defined in ISO/IEC 27001.
Security baseline
The minimum set of security settings required for a type of system.
Policy exception
A formally approved and time-limited deviation from a policy or standard, with an accountable owner.
Hardening
Reducing a system's attack surface by removing unneeded services and applying secure settings.
Real-world example

An auditor compares 30 servers with the company's hardening standard using a configuration scanning tool. Six have remote administration services enabled that the standard prohibits and no approved exceptions exist, so she reports the deviation and asks for either remediation or formal exceptions.

Exam tip: A baseline makes configuration consistent and testable, but it does not eliminate the need for vulnerability scanning or monitoring. Exceptions must be formal, approved and time-limited.

Check yourself

Which framework defines certifiable requirements for an ISMS?

ISO/IEC 27001.

What should an auditor check about policies?

That they are approved by management, current, communicated to staff, enforced and matched by actual practice.
