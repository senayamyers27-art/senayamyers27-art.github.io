ISACA Certified Information Systems Auditor (CISA) 2024 job practice · Domain 4: Information systems operations and business resilience

System resiliency and data backup, storage and restoration

▶ Watch the overview video

Last reviewed September 29, 2026 · Leer en español

Resilience means keeping services running, or restoring them quickly, when components fail or disasters strike. It combines designs that avoid single points of failure with backups that allow data to be recovered.

Resilient designs use redundancy at several levels: RAID for disks, redundant power supplies and network paths, clustered servers, load balancers that spread traffic and remove failed nodes, and replication of data to another site or cloud region. RAID 1 mirrors disks; RAID 5 and 6 use parity to survive one or two disk failures; RAID 10 combines mirroring and striping. RAID 0 only stripes and has no redundancy. Uninterruptible power supplies and generators protect against power loss. Fault tolerance keeps a service running through a failure, while high availability minimizes downtime through quick failover.

Backups protect against data loss from failure, error, corruption and ransomware. A full backup copies everything; an incremental backup copies changes since the last backup of any kind, making backups fast but restores slower; a differential backup copies changes since the last full backup, so restores need only the full backup and the latest differential. Backup frequency follows the RPO. Copies should be stored offsite or in another region, and at least one copy should be offline or immutable so ransomware cannot encrypt it. Backups need encryption, access control and documented retention.

Restoration is what matters. Organizations should regularly test restores of files, systems and full applications to confirm backups are complete and usable within the RTO. The auditor reviews backup schedules against RPOs, job logs, offsite and immutable storage, and evidence of successful restore tests.

Key terms

Incremental backup
A backup of data changed since the last backup of any type.
Differential backup
A backup of data changed since the last full backup.
Immutable backup
A backup copy that cannot be changed or deleted for a set period, protecting against ransomware.
Single point of failure
A component whose failure stops the whole service because it has no redundancy.
Real-world example

A law firm backs up nightly to a disk in the same server room. After ransomware encrypts both servers and the backup disk, recovery takes weeks. The new design keeps daily backups in a cloud region with immutability and tests a restore each month.

Exam tip: A successful backup job does not prove recoverability. Periodic restore tests are the best evidence that backups work, and at least one copy should be offsite and protected from ransomware.

Check yourself

Which backup type needs only the last full backup and one other set to restore?

Differential.

Why is RAID not a substitute for backups?

RAID protects against disk failure but copies deletions, corruption and ransomware encryption instantly, so it cannot restore earlier data.
