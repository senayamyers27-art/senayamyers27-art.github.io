CompTIA Security+ SY0-701 · Domain 3: Security architecture

Virtualization risks: VM escape, sprawl

▶ Watch the overview video

Last reviewed October 6, 2026 · Leer en español

Explain it simpler

Virtualization lets one physical computer run many virtual machines (VMs), each acting like a separate computer. A program called a hypervisor manages them and keeps them apart. VM escape is when an attacker breaks out of one virtual machine and reaches the hypervisor or other VMs on the same hardware, which is serious because it breaks the wall between them. VM sprawl is when so many virtual machines get created that nobody keeps track of them, leaving forgotten, unpatched machines that become easy targets. Think of an apartment building: each unit is a VM, and the building manager is the hypervisor. Escape is a tenant breaking through the wall into a neighbor's place, and sprawl is having so many empty, unlocked units that no one knows who is living in them.

Marcus inherits the virtualization cluster at Summit Regional Bank on his first day as infrastructure lead, along with a spreadsheet the previous admin called the inventory. The cluster console shows 410 virtual machines. The spreadsheet lists 290. Scrolling through the difference, he finds names like test-db-copy2, marketing-promo-2021 and do-not-delete. Some are powered on. One answers on a public address. Nobody can tell him who owns them, what data they hold or when they were last patched. That afternoon, the hypervisor vendor publishes an urgent advisory about a flaw that could let code in a guest reach the host. Marcus now has two very different problems on the same cluster. Which one is about technology, and which one is about governance?

Virtualization lets one physical server run many virtual machines (VMs), each with its own operating system, managed by a hypervisor. It is the foundation of modern data centers and public cloud. It saves money and makes systems easy to create, copy and move, but it introduces risks of its own. Security+ focuses on two named risks, VM escape and VM sprawl, plus resource reuse and the security of the hypervisor itself. Understanding them helps you see why hypervisors must be patched promptly and why every VM needs an owner.
