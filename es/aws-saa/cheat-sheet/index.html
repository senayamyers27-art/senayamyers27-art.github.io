Dominio 1: Design Secure Architectures (30%)

Consejos para el examen

  • Cuando una pregunta plantea por qué se deniega el acceso a pesar de un Allow, busca un Deny explícito, una SCP o un permissions boundary. Cuando pregunta cómo dar acceso a una instancia EC2 o a una función Lambda, la respuesta es un rol, nunca access keys guardadas en la instancia.
  • Las SCPs filtran, no otorgan, y no se aplican a la management account. Si la pregunta busca un inicio de sesión centralizado para personas en muchas cuentas, elige IAM Identity Center; si busca que una aplicación de la cuenta A actúe en la cuenta B, elige un rol entre cuentas.
  • Si una app móvil o web necesita que sus usuarios llamen directamente a servicios de AWS, la respuesta involucra un Cognito identity pool. Si la pregunta trata solo del registro e inicio de sesión de los usuarios de la app, es un user pool. Usuarios corporativos y SAML apuntan a IAM Identity Center o AssumeRoleWithSAML.
  • Stateful y solo de permiso significa security group; stateless con reglas de denegación y orden significa network ACL. Cuando una pregunta pida acceso de shell sin puertos entrantes abiertos y sin gestión de claves, elige Session Manager en lugar de un bastion host.
  • S3 o DynamoDB, desde dentro de la VPC, al menor costo: gateway endpoint. Cualquier otro servicio, o acceso desde on-premises, o compartir un servicio con otras VPC: interface endpoint (PrivateLink).
  • SQL injection, cross-site scripting, limitación de tasa o bloqueo geográfico apuntan a AWS WAF. Un DDoS grande con soporte experto y protección de costos apunta a Shield Advanced. Mantener privado un origen S3 detrás de CloudFront apunta a origin access control.
  • Auditoría del uso de la clave, control de la key policy o capacidad de deshabilitar la clave: SSE-KMS con una customer managed key. El cliente debe proporcionar y conservar la clave por sí mismo: SSE-C. Lo más simple sin gestión de claves: SSE-S3.
  • Un certificado de CloudFront debe estar en us-east-1. Exigir HTTPS en un bucket de S3 es una bucket policy que deniega las solicitudes donde aws:SecureTransport es false, no una configuración del bucket.
  • La palabra clave es rotación. La rotación automática de credenciales de bases de datos apunta a Secrets Manager; el almacenamiento de bajo costo de configuración y secretos estáticos apunta a Parameter Store SecureString.
  • El governance mode lo pueden eludir usuarios con un permiso especial; el compliance mode no lo puede eludir nadie. Para dar acceso temporal a un objeto sin crear usuarios de IAM, elige una presigned URL.
  • Historial de la API: CloudTrail. Historial de configuración y cumplimiento: Config. Amenazas: GuardDuty. Vulnerabilidades: Inspector. Datos sensibles en S3: Macie. Panel único de hallazgos: Security Hub.

Términos clave

IAM role (rol de IAM)
Una identidad con permisos pero sin credenciales de largo plazo, que un principal de confianza asume para recibir credenciales temporales.
Resource-based policy (política basada en recursos)
Una política adjunta a un recurso, como una bucket policy de S3, que indica los principales autorizados a acceder a él.
Explicit deny (denegación explícita)
Una declaración Deny que coincide con una solicitud; anula cualquier Allow de cualquier política.
Permissions boundary (límite de permisos)
Una política administrada que fija los permisos máximos que puede tener un usuario o rol de IAM, sin otorgar ninguno por sí misma.
Organizational unit (OU, unidad organizativa)
Un contenedor de cuentas dentro de AWS Organizations al que se pueden adjuntar políticas como las SCPs.
Service control policy (SCP)
Una política de Organizations que fija los permisos máximos de las identidades en las cuentas miembro; nunca otorga acceso.
Permission set (conjunto de permisos)
Una plantilla de políticas de IAM Identity Center que se convierte en un rol en cada cuenta a la que se asigna.
External ID
Un valor secreto exigido en la trust policy de un rol entre cuentas para protegerse del problema del confused deputy.
AWS STS
El Security Token Service, que emite credenciales temporales que caducan para roles y usuarios federados.
SAML 2.0
Un estándar basado en XML para intercambiar aserciones de autenticación, muy usado para la federación de la fuerza laboral.
Cognito user pool
Un directorio de usuarios administrado que gestiona el registro y el inicio de sesión y devuelve JWTs.
Cognito identity pool
Un servicio que intercambia tokens de identidad por credenciales temporales de AWS asociadas a roles de IAM.
Security group (grupo de seguridad)
Un firewall virtual stateful que solo permite, adjunto a interfaces de red.
Network ACL (lista de control de acceso de red)
Un firewall stateless a nivel de subred con reglas numeradas de permiso y denegación evaluadas en orden.
NAT gateway
Un servicio administrado en una subred pública que permite a las instancias privadas iniciar conexiones salientes a internet.
Session Manager
Una función de Systems Manager que da acceso de shell a las instancias mediante una conexión saliente del agente, controlada por IAM.
Gateway endpoint
Un destino de route table que da acceso privado y gratuito a S3 o DynamoDB desde dentro de una VPC.
Interface endpoint
Una interfaz de red de PrivateLink con IP privadas en tus subredes que actúa como frente de un servicio de AWS o de un socio.
Endpoint policy (política de endpoint)
Una política de recurso en un VPC endpoint que restringe qué acciones y recursos se pueden alcanzar a través de él.
aws:SourceVpce
Una clave de condición que coincide con el ID del VPC endpoint por el que llegó una solicitud.
Web ACL
El recurso de AWS WAF que contiene las reglas y se asocia con CloudFront, ALB, API Gateway y otros recursos compatibles.
Rate-based rule (regla basada en tasa)
Una regla de WAF que bloquea las IP de origen que superan un número de solicitudes dentro de una ventana de tiempo.
Shield Advanced
Un nivel de pago de protección DDoS con soporte del SRT, detección avanzada y protección de costos por DDoS.
Origin access control (OAC, control de acceso al origen)
Una función de CloudFront que firma las solicitudes a un origen S3 para que el bucket pueda permanecer privado y aceptar solo esa distribución.
Customer managed key (clave administrada por el cliente)
Una clave de KMS que creas y controlas, incluidas su key policy, rotación, deshabilitación y eliminación.
Key policy (política de clave)
La política basada en recursos de una clave de KMS, que es el control principal sobre quién puede usarla y administrarla.
Envelope encryption (cifrado de sobre)
Cifrar los datos con una data key y luego cifrar esa data key con una clave de KMS.
SSE-KMS
Cifrado del lado del servidor de S3 con una clave de KMS, con uso de clave auditable y control mediante key policy.
AWS Certificate Manager (ACM)
Un servicio que emite, almacena y renueva automáticamente certificados TLS para servicios de AWS integrados.
TLS termination (terminación de TLS)
Descifrar TLS en un componente frontal, como un balanceador de carga, antes de pasar la solicitud.
Viewer protocol policy
La configuración de CloudFront que controla si los espectadores pueden usar HTTP, se redirigen a HTTPS o deben usar HTTPS.
aws:SecureTransport
Una clave de condición que es verdadera cuando la solicitud se envió por TLS.
Secrets Manager
Un servicio administrado que almacena, cifra, audita y rota automáticamente los secretos.
Parameter Store
Una función de Systems Manager para datos de configuración jerárquicos y secretos, sin rotación integrada.
SecureString
Un tipo de parámetro de Parameter Store cuyo valor se cifra con una clave de KMS.
Rotation (rotación)
Reemplazar periódicamente un secreto por un valor nuevo y actualizar cada lugar que lo usa.
Block Public Access
Opciones de cuenta y de bucket que anulan cualquier ACL o política que haría públicos los datos de S3.
Presigned URL (URL prefirmada)
Una URL de duración limitada, firmada con las credenciales de una identidad autorizada, que otorga una operación de S3 sobre un objeto.
Object Lock compliance mode (modo de cumplimiento)
Un modo de retención WORM que nadie, ni siquiera root, puede acortar ni eliminar antes de que expire.
Legal hold (retención legal)
Un indicador de Object Lock que impide eliminar una versión hasta que se quite la retención, sin fecha de expiración.
CloudTrail
El servicio que registra la actividad de la API en las cuentas de AWS para auditoría e investigación.
AWS Config
El servicio que registra el historial de configuración de los recursos y evalúa el cumplimiento de reglas.
GuardDuty
Un servicio administrado de detección de amenazas que analiza logs para encontrar actividad maliciosa o no autorizada.
Macie
Un servicio que descubre y clasifica datos sensibles, como la PII, en Amazon S3.

Dominio 2: Design Resilient Architectures (26%)

Consejos para el examen

  • Enrutamiento basado en ruta o en host significa ALB. IP estática, UDP o millones de solicitudes por segundo con latencia ultrabaja significa NLB. Si un ASG no reemplaza las instancias que el balanceador de carga dice que no están sanas, cambia el ASG al tipo de health check ELB.
  • Mensajes procesados dos veces suelen significar que el visibility timeout es más corto que el tiempo de procesamiento. Orden estricto y sin duplicados significa FIFO. Un evento entregado a varios consumidores independientes significa fan-out de SNS hacia SQS.
  • Fíjate en los límites de tiempo: un trabajo de más de 15 minutos descarta Lambda. Orquestar varios pasos con reintentos apunta a Step Functions; enrutar eventos de servicios de AWS o apps SaaS según su contenido apunta a EventBridge.
  • Conocimientos previos de Kubernetes o portabilidad: EKS. Orquestación nativa de AWS más simple: ECS. Sin servidores que administrar: Fargate. Necesidad de GPUs, control a nivel de host o precios Reserved en los hosts: EC2 launch type.
  • Multi-AZ equivale a disponibilidad, no a rendimiento; el standby clásico no puede atender lecturas. Read replicas equivalen a rendimiento de lectura, con replicación asíncrona. DR relacional entre Regiones con RPO de segundos equivale a Aurora Global Database.
  • La replicación no es un respaldo: las global tables también copian los errores. Para recuperarte de una eliminación o corrupción accidental a un momento exacto, elige point-in-time recovery; las restauraciones siempre van a una tabla nueva.
  • Contenido que debe restringirse o localizarse por país: geolocation, no latency. Mejor rendimiento para los usuarios: latency. Canary o reparto por porcentaje: weighted. DR activo-pasivo: failover. El zone apex apuntando a un ALB: un alias record.
  • Relaciona la redacción con la estrategia: el menor costo y horas de RTO es backup and restore; base de datos principal en ejecución pero servidores apagados es pilot light; copia reducida pero totalmente funcional es warm standby; RTO y RPO cercanos a cero es multi-site active-active.
  • Respaldo centralizado y basado en etiquetas para varios servicios, con copias entre Regiones y entre cuentas: AWS Backup. Copiar automáticamente los objetos nuevos de S3 a otra Región: CRR (requiere versionado). Replicación continua a nivel de bloque de servidores completos para DR: Elastic Disaster Recovery.
  • Necesitas conectividad esta semana o a bajo costo: Site-to-Site VPN. Enlace privado constante y de gran ancho de banda: Direct Connect, que tarda más en aprovisionarse. La opción resiliente más barata para Direct Connect: agregar una VPN de respaldo. Muchas VPC más on-premises: Transit Gateway.
  • Desplegar los mismos recursos en muchas cuentas o Regiones: StackSets. Ver los cambios antes de actualizar: change set. Los planes de DR deben incluir aumentos de cuota en la Región de recuperación. Los errores de throttling se manejan con reintentos con exponential backoff.

Términos clave

Availability Zone (zona de disponibilidad)
Uno o más centros de datos aislados en una Región, con energía y red independientes.
Application Load Balancer
Un balanceador de carga de capa 7 que enruta solicitudes HTTP y HTTPS según el contenido, como la ruta y el host.
Network Load Balancer
Un balanceador de carga de capa 4 para TCP, UDP y TLS, con IP estáticas por AZ y un rendimiento muy alto.
ELB health check type
Una opción del Auto Scaling group que reemplaza las instancias que el balanceador de carga reporta como no sanas.
Visibility timeout (tiempo de visibilidad)
El período durante el cual un mensaje de SQS recibido queda oculto a los demás consumidores mientras se procesa.
Dead-letter queue (cola de mensajes fallidos)
Una cola que recibe los mensajes que fallaron en su procesamiento más veces que el maxReceiveCount.
FIFO queue
Un tipo de cola de SQS que conserva el orden dentro de un message group y evita duplicados.
Fan-out
Publicar un mensaje una sola vez en un topic de SNS para que muchos suscriptores, a menudo colas SQS, reciban cada uno una copia.
AWS Lambda
Un servicio de cómputo serverless que ejecuta funciones en respuesta a eventos, hasta 15 minutos por invocación.
Amazon API Gateway
Un servicio administrado para crear, proteger y limitar APIs REST, HTTP y WebSocket.
Amazon EventBridge
Un bus de eventos serverless que enruta eventos a destinos según reglas de coincidencia de patrones.
AWS Step Functions
Un servicio que orquesta flujos de trabajo como state machines con reintentos, ramas y manejo de errores.
Task definition (definición de tarea)
El plano de ECS que describe los contenedores, recursos, red y roles de IAM de una tarea.
Amazon EKS
Un servicio administrado de Kubernetes que ejecuta el control plane por ti.
AWS Fargate
Un motor de cómputo serverless para contenedores que elimina la necesidad de administrar hosts EC2.
ECS task role
El rol de IAM cuyos permisos usa la aplicación dentro de una tarea de ECS.
Multi-AZ deployment (despliegue Multi-AZ)
Una configuración de RDS con un standby replicado de forma síncrona en otra AZ y failover automático.
Read replica (réplica de lectura)
Una copia de una base de datos replicada de forma asíncrona que se usa para descargar lecturas; puede promoverse manualmente.
Aurora Replica
Una instancia lectora que comparte el cluster volume de Aurora, atiende lecturas y es un destino de failover automático.
Aurora Global Database
Una configuración de Aurora que replica un clúster a Regiones secundarias con un retraso típico de menos de un segundo.
Global table (tabla global)
Una tabla de DynamoDB replicada en varias Regiones, donde cada réplica acepta lecturas y escrituras.
Point-in-time recovery (PITR)
Respaldos continuos de DynamoDB que permiten restaurar a cualquier segundo dentro de la ventana de recuperación de hasta 35 días.
On-demand backup (respaldo bajo demanda)
Un respaldo completo de DynamoDB creado manualmente y conservado hasta que lo eliminas.
Last writer wins (gana el último escritor)
La regla de resolución de conflictos de las global tables en la que prevalece la escritura más reciente a un elemento.
Alias record (registro alias)
Un registro de Route 53 que apunta a un recurso de AWS, funciona en el zone apex y no tiene cargo por consulta para destinos de AWS.
Failover routing
Una política activo-pasivo que devuelve el registro secundario solo cuando falla el health check del primario.
Latency-based routing
Una política que devuelve el endpoint de la Región con la menor latencia para el usuario.
Geolocation routing
Una política que devuelve respuestas según la ubicación geográfica del usuario.
RPO
Recovery point objective (objetivo de punto de recuperación): la pérdida máxima aceptable de datos, medida como tiempo antes del desastre.
RTO
Recovery time objective (objetivo de tiempo de recuperación): el tiempo máximo aceptable para restaurar el servicio después de un desastre.
Pilot light (luz piloto)
Una estrategia de DR que mantiene los datos replicados en la Región de recuperación con la capa de aplicación apagada hasta que se necesite.
Warm standby (espera en caliente)
Una estrategia de DR que ejecuta una copia reducida pero totalmente funcional de la carga de trabajo en la Región de recuperación.
Backup plan (plan de respaldo)
Una política de AWS Backup que define la frecuencia, retención, ciclo de vida y reglas de copia de los respaldos para los recursos asignados.
Vault Lock
Una función de AWS Backup que hace inmutable la configuración de retención de un backup vault.
Cross-Region Replication (replicación entre Regiones)
Copia asíncrona de objetos de S3 a un bucket de otra Región; requiere versionado en ambos buckets.
AWS Elastic Disaster Recovery
Un servicio que replica continuamente servidores a AWS y lanza instancias de recuperación bajo demanda.
Customer gateway
El dispositivo VPN on-premises, o su representación en AWS, en tu extremo de una Site-to-Site VPN.
AWS Direct Connect
Una conexión de red privada dedicada entre las redes on-premises y AWS.
Virtual interface (VIF, interfaz virtual)
Una conexión lógica en Direct Connect: privada, pública o de tránsito.
Transit Gateway
Un hub de red regional que conecta VPC y redes on-premises con enrutamiento centralizado.
CloudFormation stack
Un conjunto de recursos de AWS creados y administrados juntos a partir de una plantilla.
Change set (conjunto de cambios)
Una vista previa de los cambios que hará CloudFormation al actualizar un stack.
StackSets
Una función de CloudFormation que despliega una plantilla en varias cuentas y Regiones.
Exponential backoff (espera exponencial)
Una estrategia de reintentos que espera cada vez más entre intentos, normalmente con jitter aleatorio.

Dominio 3: Design High-Performing Architectures (24%)

Consejos para el examen

  • Menor latencia entre nodos: cluster. Máximo aislamiento para unas pocas instancias: spread. Grandes clústeres replicados como Kafka o HDFS: partition. MPI u OS-bypass: EFA, no solo ENA.
  • Volumen predeterminado o de arranque: gp3. Máximas IOPS sostenidas para bases de datos críticas: io2 Block Express. Gran rendimiento secuencial a bajo costo: st1; el más frío y barato: sc1. El espacio temporal más rápido que se puede perder: instance store.
  • Archivos compartidos en Linux: EFS. Windows o SMB con Active Directory: FSx for Windows File Server. Rendimiento para HPC o ML, sobre todo con datos en S3: FSx for Lustre. Funciones de NetApp o NFS más SMB más iSCSI juntos: FSx for NetApp ONTAP.
  • Usuarios globales que suben a un bucket a larga distancia: Transfer Acceleration. Archivos grandes y redes poco confiables: multipart upload. Descargas paralelas más rápidas o leer parte de un archivo: byte-range fetches. Mayores tasas de solicitudes: más prefijos.
  • Leaderboards, pub/sub, persistencia o alta disponibilidad: Redis. La caché de clave-valor multihilo más simple: Memcached. Lecturas de microsegundos para DynamoDB con cambios mínimos de código: DAX. Caché siempre actualizada a costa de latencia de escritura: write-through.
  • Caché y contenido HTTP significa CloudFront. Direcciones IP estáticas, tráfico UDP o TCP que no es HTTP, o failover regional instantáneo sin DNS significa Global Accelerator.
  • Relaciona las pistas con los motores: relaciones y recorrido de grafos es Neptune; compatibilidad con MongoDB es DocumentDB; analítica o data warehouse es Redshift; clave-valor a cualquier escala con operación serverless es DynamoDB; demasiadas conexiones desde Lambda es RDS Proxy.
  • Throttling mientras la capacidad total no se usa apunta a una hot partition y a un mal diseño de claves. Tráfico desconocido o con picos apunta a on-demand; tráfico estable y predecible apunta a provisioned con auto scaling. ¿Necesitas un nuevo patrón de consulta después del lanzamiento? Agrega un GSI, porque los LSI deben crearse junto con la tabla.
  • Entregar a S3, Redshift u OpenSearch sin código y sin gestión de capacidad: Firehose. Consumidores personalizados en tiempo real, orden por clave o replay: Kinesis Data Streams. Cargas de Kafka existentes o APIs de Kafka: MSK.
  • SQL ad hoc sobre S3 sin servidores: Athena. Descubrir esquemas y ETL: Glue. Permisos a nivel de columna o fila en varias herramientas de analítica: Lake Formation. Clústeres de Hadoop o Spark con control: EMR. Combinar tablas de Redshift con datos en S3: Redshift Spectrum. Tableros: QuickSight.
  • Mantener una métrica en un valor: target tracking. Horarios conocidos: scheduled. Patrones diarios o semanales recurrentes con instancias que tardan en arrancar: predictive. Respuestas distintas según la magnitud de la violación: step. Flotas de workers de SQS: escalar según el backlog por instancia.
  • Migración de archivos en línea: DataSync. Enormes cantidades de datos y ancho de banda limitado: Snow Family. Acceso continuo on-premises al almacenamiento en la nube: Storage Gateway (file, volume o tape). SFTP para socios: Transfer Family. Traslado de bases de datos con tiempo de inactividad mínimo: DMS, más SCT cuando los motores difieren.

Términos clave

Cluster placement group
Instancias agrupadas muy cerca en una AZ para una red de baja latencia y alto rendimiento.
Spread placement group
Cada instancia en hardware distinto, con un límite de siete instancias en ejecución por AZ por grupo.
Partition placement group
Instancias divididas en particiones sobre racks separados, para grandes sistemas distribuidos y replicados.
Elastic Fabric Adapter (EFA)
Una interfaz de red con OS-bypass para cargas de trabajo de HPC y ML fuertemente acopladas.
gp3
SSD de uso general con una base de 3,000 IOPS y 125 MB/s, con IOPS y rendimiento aprovisionados independientemente del tamaño.
io2 Block Express
El SSD de EBS de mayor rendimiento para bases de datos exigentes, con latencia inferior a un milisegundo y alta durabilidad.
st1
HDD optimizado para rendimiento para cargas secuenciales grandes como big data y logs; no puede ser de arranque.
Instance store (almacén de instancia)
Almacenamiento en bloque temporal conectado físicamente al host; los datos se pierden al detener o terminar la instancia.
Amazon EFS
Un sistema de archivos NFS administrado y elástico para Linux que muchas instancias en varias AZs pueden montar simultáneamente.
FSx for Windows File Server
Un servidor de archivos Windows administrado que usa SMB con integración con Active Directory.
FSx for Lustre
Un sistema de archivos paralelo de alto rendimiento administrado para HPC y ML, con integración opcional con S3.
FSx for NetApp ONTAP
Un sistema de archivos NetApp ONTAP administrado que admite NFS, SMB e iSCSI con las funciones de datos de ONTAP.
Prefix (prefijo)
La parte inicial de la clave de un objeto de S3; los límites de tasa de solicitudes se aplican por prefijo.
Multipart upload (carga multiparte)
Subir un objeto en partes transferidas de forma independiente que S3 luego ensambla; obligatorio por encima de 5 GB.
Byte-range fetch (descarga por rango de bytes)
Descargar un rango específico de bytes de un objeto con el encabezado HTTP Range, a menudo en paralelo.
S3 Transfer Acceleration
Una función del bucket que enruta las transferencias por las edge locations de CloudFront a través del backbone de AWS.
ElastiCache for Redis
Un almacén de datos en memoria administrado con tipos de datos ricos, replicación, persistencia y failover Multi-AZ.
ElastiCache for Memcached
Una caché de clave-valor administrada y multihilo, sin replicación ni persistencia.
DAX
DynamoDB Accelerator, una caché en memoria compatible con la API de DynamoDB con latencia de lectura de microsegundos.
Lazy loading (carga diferida)
Una estrategia de caché que carga los datos en la caché solo después de un cache miss.
Edge location (ubicación de borde)
Un sitio de AWS cercano a los usuarios donde CloudFront almacena contenido en caché y Global Accelerator acepta tráfico.
TTL
Time to live: cuánto tiempo CloudFront mantiene un objeto en caché antes de volver a consultar el origen.
Invalidation (invalidación)
Una solicitud a CloudFront para eliminar objetos de las cachés de borde antes de que expire su TTL.
AWS Global Accelerator
Un servicio que proporciona IPs anycast estáticas que enrutan tráfico TCP y UDP por el backbone de AWS hacia endpoints sanos.
OLTP vs OLAP
El procesamiento de transacciones en línea maneja muchas lecturas y escrituras pequeñas; el procesamiento analítico en línea ejecuta grandes consultas de agregación.
Amazon Redshift
Un data warehouse columnar administrado para analítica sobre grandes conjuntos de datos.
Amazon Neptune
Una base de datos de grafos administrada para datos definidos por las relaciones entre entidades.
RDS Proxy
Un proxy de base de datos administrado que agrupa las conexiones a RDS y Aurora y acelera el failover.
Partition key (clave de partición)
El atributo clave al que DynamoDB aplica un hash para distribuir los elementos entre particiones.
Hot partition (partición caliente)
Una partición que recibe una proporción desmedida del tráfico, lo que provoca throttling.
Global secondary index (índice secundario global)
Un índice con una partition key diferente que se puede agregar en cualquier momento y admite lecturas eventualmente consistentes.
On-demand capacity (capacidad bajo demanda)
Un modo de facturación de DynamoDB que cobra por solicitud sin planificación de capacidad.
Shard
La unidad de capacidad de un Kinesis data stream en modo provisioned, con rendimiento de lectura y escritura fijo.
Partition key (Kinesis)
El valor que determina qué shard recibe un registro, conservando el orden por clave.
Amazon Data Firehose
Un servicio totalmente administrado que almacena en búfer los datos de streaming y los entrega a destinos como S3 y Redshift.
Amazon MSK
Amazon Managed Streaming for Apache Kafka, un servicio de Kafka administrado.
AWS Glue Data Catalog
Un almacén central de metadatos con definiciones de tablas compartido por Athena, EMR, Redshift Spectrum y Glue.
Amazon Athena
Un servicio de consultas SQL serverless para datos en S3, con precio según los datos escaneados.
AWS Lake Formation
Un servicio para construir data lakes y administrar de forma centralizada el acceso detallado a ellos.
Redshift Spectrum
Una función de Redshift que consulta datos directamente en S3 y los combina con las tablas del warehouse.
Target tracking scaling
Una política que ajusta la capacidad para mantener una métrica elegida cerca de un valor objetivo.
Step scaling (escalado por pasos)
Una política que hace ajustes mayores ante violaciones mayores de las alarmas de CloudWatch.
Scheduled scaling (escalado programado)
Cambiar la capacidad de un Auto Scaling group en momentos fijos para patrones de carga conocidos.
Predictive scaling (escalado predictivo)
Pronosticar la carga a partir del historial con machine learning para agregar capacidad antes de que se necesite.
AWS DataSync
Un servicio de transferencia de datos en línea para mover archivos entre el almacenamiento on-premises, otras nubes y el almacenamiento de AWS.
Storage Gateway
Un servicio híbrido que da a las aplicaciones on-premises interfaces de archivo, volumen o cinta respaldadas por almacenamiento de AWS.
Change data capture (CDC, captura de datos de cambios)
Replicar continuamente los cambios en curso de la base de datos de origen al destino después de la carga inicial.
AWS SCT
La Schema Conversion Tool, que convierte esquemas y código de bases de datos entre motores diferentes.

Dominio 4: Design Cost-Optimized Architectures (20%)

Consejos para el examen

  • Estable y a largo plazo: Savings Plans o RIs. Interrumpible y flexible: Spot. Corto, impredecible e ininterrumpible: On-Demand. Licencias BYOL por socket o por núcleo: Dedicated Hosts, no Dedicated Instances. Flexibilidad entre familias, Regiones o Fargate y Lambda: Compute Savings Plan.
  • Reduce las interrupciones de Spot diversificando los tipos de instancia y las AZs y usando la asignación price-capacity-optimized o capacity-optimized. El aviso es de dos minutos. Mantén una pequeña base On-Demand para la capacidad que siempre debe existir.
  • Obtener recomendaciones a partir de datos de utilización: Compute Optimizer. Mejor relación precio-rendimiento con lenguajes que no requieren recompilar: Graviton. Las cargas ociosas o con picos favorecen serverless; la utilización estable y alta favorece la capacidad aprovisionada con compromisos. Ajusta el tamaño antes de comprometerte.
  • Acceso desconocido o cambiante: Intelligent-Tiering. Rara vez se lee pero debe ser instantáneo: Standard-IA o Glacier Instant Retrieval. Datos que se pueden recrear: One Zone-IA. Archivo donde se aceptan horas de recuperación al menor precio: Deep Archive.
  • Versiones antiguas llenando un bucket versionado: agrega una regla de expiración de versiones no actuales. Visibilidad del almacenamiento en toda la organización: Storage Lens. Que quienes descargan tu gran conjunto de datos público paguen la transferencia: Requester Pays, que requiere solicitantes autenticados.
  • Pasar de gp2 a gp3 es un cambio sin tiempo de inactividad que suele ahorrar dinero. Automatizar la retención de snapshots por etiqueta: Data Lifecycle Manager. Snapshots a largo plazo que rara vez se restauran: Snapshots Archive. Los volúmenes no adjuntos siguen costando dinero.
  • Impredecible o con picos: DynamoDB on-demand o Aurora Serverless v2. Estable y predecible: capacidad provisioned con reservas. Una base de datos RDS detenida se reinicia a los siete días, así que para largos períodos de inactividad toma un snapshot y elimínala.
  • Costo alto de NAT gateway con tráfico hacia S3 o DynamoDB: agrega un gateway endpoint. Egress alto a internet para contenido estático o almacenable en caché: ponlo detrás de CloudFront. Los datos entrantes son gratuitos; el tráfico entre AZs y entre Regiones no lo es.
  • Alertar antes de gastar de más: Budgets. Analizar tendencias y obtener recomendaciones de Savings Plans: Cost Explorer. Los datos más granulares para reportes personalizados: Cost and Usage Report. Costos por equipo o proyecto: activa las cost allocation tags. Verificaciones de buenas prácticas: Trusted Advisor.
  • Los descuentos de Reserved Instances y Savings Plans se comparten entre las cuentas de una organización por defecto. Si una cuenta no debe compartirlos ni recibirlos, desactiva el uso compartido para esa cuenta en las preferencias de facturación de la management account.

Términos clave

Reserved Instance (instancia reservada)
Un compromiso de uno o tres años con una configuración de instancia a cambio de una tarifa más baja.
Compute Savings Plan
Un compromiso en dólares por hora que aplica descuento a EC2 en todas las familias y Regiones, además de Fargate y Lambda.
Spot Instance
Capacidad sobrante de EC2 con un gran descuento que AWS puede recuperar con un aviso de dos minutos.
Dedicated Host (host dedicado)
Un servidor físico dedicado a ti, con visibilidad de sockets y núcleos para licencias por núcleo o por socket.
Spot interruption notice (aviso de interrupción de Spot)
Una advertencia de dos minutos, mediante los metadatos de la instancia y EventBridge, de que EC2 recuperará una Spot Instance.
Rebalance recommendation
Una señal temprana de que una Spot Instance tiene un riesgo elevado de interrupción.
Mixed instances policy (política de instancias mixtas)
Una configuración del Auto Scaling group que combina varios tipos de instancia y las opciones de compra On-Demand y Spot.
Price-capacity-optimized
Una estrategia de asignación de Spot que favorece los pools con alta capacidad disponible y luego el precio bajo.
Right-sizing (ajuste de tamaño)
Ajustar los tipos y tamaños de los recursos para que coincidan con la utilización real y las necesidades de rendimiento.
AWS Compute Optimizer
Un servicio que usa métricas de utilización para recomendar configuraciones óptimas de EC2, EBS, Lambda, ECS y otros.
AWS Graviton
Procesadores basados en Arm diseñados por AWS que ofrecen una gran relación precio-rendimiento para cargas compatibles.
CloudWatch agent
Software que publica en CloudWatch métricas adicionales de las instancias, como la utilización de memoria.
Standard-IA
Una clase de S3 para datos de acceso poco frecuente con acceso en milisegundos, tarifas de recuperación y un mínimo de 30 días.
One Zone-IA
Una clase de acceso poco frecuente de menor costo que guarda los datos en una sola Availability Zone.
Intelligent-Tiering
Una clase de S3 que mueve automáticamente los objetos entre niveles de acceso según su uso, sin tarifas de recuperación.
Glacier Deep Archive
La clase de S3 de menor costo, para archivos a largo plazo que se recuperan en horas, con un mínimo de 180 días.
Lifecycle rule (regla de ciclo de vida)
Una configuración de bucket que transiciona o expira objetos automáticamente según su antigüedad y filtros.
Noncurrent version (versión no actual)
Una versión antigua de un objeto en un bucket versionado, que las lifecycle rules pueden transicionar o expirar por separado.
S3 Storage Lens
Un tablero de analítica que proporciona el uso, la actividad y recomendaciones de almacenamiento a nivel de toda la organización.
Requester Pays
Una configuración de bucket que hace que los solicitantes autenticados paguen las solicitudes y la transferencia de datos.
Elastic Volumes
Una función de EBS para cambiar el tipo, tamaño, IOPS o rendimiento de un volumen mientras está en uso.
Data Lifecycle Manager
Un servicio que automatiza la creación, retención y copias entre Regiones de snapshots de EBS y AMIs mediante políticas basadas en etiquetas.
EBS Snapshots Archive
Un nivel de bajo costo para snapshots de acceso poco frecuente, con un mínimo de 90 días y restauraciones que tardan hasta 72 horas.
Unattached volume (volumen no adjunto)
Un volumen EBS en estado available, no adjunto a ninguna instancia pero que se sigue facturando.
Aurora capacity unit (ACU)
La unidad de capacidad de Aurora Serverless v2, que combina memoria con la CPU y la red correspondientes.
Reserved DB Instance
Un compromiso de uno o tres años en RDS o Aurora que reduce el precio por hora de la instancia.
DynamoDB reserved capacity (capacidad reservada)
Un compromiso con capacidad provisioned de DynamoDB a cambio de una tarifa con descuento.
Stopped DB instance (instancia de base de datos detenida)
Una instancia RDS que no se factura por horas de instancia y que se reinicia automáticamente después de siete días.
Egress (salida)
Datos que salen de AWS hacia internet, cobrados por GB.
Inter-AZ transfer (transferencia entre AZs)
Tráfico entre Availability Zones de una Región, cobrado por GB en cada dirección.
NAT gateway data processing (procesamiento de datos del NAT gateway)
Un cargo por GB sobre todo el tráfico que pasa por un NAT gateway, además de su cargo por hora.
Price class
Una configuración de CloudFront que limita qué edge locations sirven el contenido, sacrificando alcance a cambio de costo.
Cost Explorer
Una herramienta interactiva para analizar, visualizar y pronosticar los costos y el uso de AWS.
AWS Budgets
Un servicio que alerta, y puede tomar acciones, cuando los costos o el uso superan, o se pronostica que superarán, los umbrales.
Cost and Usage Report
El conjunto de datos de facturación de AWS más detallado, entregado a S3 para analizarlo con herramientas como Athena.
Cost allocation tag (etiqueta de asignación de costos)
Una etiqueta de recurso activada en la facturación para poder agrupar y filtrar los costos por ella.
Consolidated billing (facturación consolidada)
Una función de AWS Organizations que combina los cargos de todas las cuentas miembro en una sola factura pagada por la management account.
Management account (cuenta de administración)
La cuenta que crea la organización y paga por todas las cuentas miembro; también llamada payer account.
Volume pricing tier (nivel de precio por volumen)
Un precio por unidad más bajo que se aplica una vez que el uso combinado supera un umbral.
Discount sharing (uso compartido de descuentos)
Aplicar los beneficios de Reserved Instances y Savings Plans entre las cuentas de una organización.
