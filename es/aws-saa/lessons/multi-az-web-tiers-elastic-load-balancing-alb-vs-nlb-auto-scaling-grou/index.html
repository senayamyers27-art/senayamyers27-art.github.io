Capas web Multi-AZ: Elastic Load Balancing (ALB vs NLB), Auto Scaling groups y health checks de ELB

Cada Región de AWS contiene varias Availability Zones (AZs, zonas de disponibilidad): grupos de centros de datos con energía, refrigeración y red independientes, conectados por enlaces de baja latencia. Una capa web resiliente se ejecuta en al menos dos AZs, de modo que la pérdida de un centro de datos, o de una AZ, no tumbe la aplicación. Tres servicios lo hacen práctico: Elastic Load Balancing reparte el tráfico, Amazon EC2 Auto Scaling mantiene la cantidad correcta de instancias sanas y los health checks (comprobaciones de estado) los unen.

Un Application Load Balancer (ALB) trabaja en la capa 7, el nivel de HTTP y HTTPS. Puede enrutar por nombre de host, ruta, encabezados HTTP, query strings e IP de origen, así que un solo ALB puede enviar /api/* a un target group y /images/* a otro. Los destinos pueden ser instancias EC2, direcciones IP, funciones Lambda o contenedores. Termina TLS, admite WebSockets y HTTP/2, puede autenticar usuarios mediante Cognito o un proveedor OIDC y se integra con AWS WAF. Un Network Load Balancer (NLB) trabaja en la capa 4 con TCP, UDP y TLS. Maneja un rendimiento muy alto con baja latencia, conserva la IP de origen del cliente y proporciona una dirección IP estática por AZ, a la que puedes asociar Elastic IPs. Elige el NLB para protocolos que no son HTTP, IP estáticas o rendimiento extremo, y para exponer un servicio mediante PrivateLink. Un Gateway Load Balancer es un tercer tipo que se usa para insertar appliances virtuales de terceros, como firewalls.

Un Auto Scaling group (ASG) lanza instancias a partir de un launch template en las subredes que elijas, manteniendo la cantidad entre un mínimo y un máximo alrededor de una capacidad deseada. Equilibra las instancias entre AZs y, si una AZ falla, lanza reemplazos en las restantes. Asociar el ASG a un target group del balanceador de carga registra automáticamente las nuevas instancias.

Los health checks deciden qué pasa con una instancia defectuosa. El balanceador de carga ejecuta su propio health check, por ejemplo un HTTP GET a /health que espera una respuesta 200, y deja de enviar tráfico a los destinos que fallan. El ASG, por defecto, usa solo los EC2 status checks, que detectan fallas de hardware y del sistema operativo, pero no un servidor web caído. Habilitar el tipo de health check ELB en el ASG hace que reemplace las instancias que el balanceador de carga marca como no sanas. Esa configuración es una respuesta frecuente en el examen.

Por último, mantén la capa web sin estado (stateless). Guarda los datos de sesión en ElastiCache o DynamoDB en lugar de en la instancia, y guarda los archivos subidos en S3 o EFS. Las sticky sessions existen en el ALB, pero hacen que el escalado y la conmutación por error sean menos uniformes, así que son un parche más que un objetivo de diseño.

Términos clave

Availability Zone (zona de disponibilidad)
Uno o más centros de datos aislados en una Región, con energía y red independientes.
Application Load Balancer
Un balanceador de carga de capa 7 que enruta solicitudes HTTP y HTTPS según el contenido, como la ruta y el host.
Network Load Balancer
Un balanceador de carga de capa 4 para TCP, UDP y TLS, con IP estáticas por AZ y un rendimiento muy alto.
ELB health check type
Una opción del Auto Scaling group que reemplaza las instancias que el balanceador de carga reporta como no sanas.
Ejemplo real

Una tienda en línea ejecuta un ALB delante de un Auto Scaling group que abarca tres AZs con un mínimo de tres instancias. Cuando un despliegue defectuoso hace que el servidor web de una instancia devuelva errores, el health check del ALB falla, el ASG (que usa health checks de ELB) la termina y lanza una instancia nueva, y los clientes nunca lo notan.

Consejo para el examen: Enrutamiento basado en ruta o en host significa ALB. IP estática, UDP o millones de solicitudes por segundo con latencia ultrabaja significa NLB. Si un ASG no reemplaza las instancias que el balanceador de carga dice que no están sanas, cambia el ASG al tipo de health check ELB.

Comprueba lo que sabes

Un servidor de juegos usa UDP y los clientes deben poner en su lista de permitidos direcciones IP fijas. ¿Qué balanceador de carga sirve?

Un Network Load Balancer, que admite UDP y da una dirección IP estática por AZ (opcionalmente Elastic IPs).

¿Por qué los servidores web detrás de un ASG no deben guardar las sesiones de usuario en memoria local?

Las instancias pueden terminarse o agregarse en cualquier momento; guardar las sesiones en ElastiCache o DynamoDB permite que cualquier instancia atienda a cualquier usuario.
