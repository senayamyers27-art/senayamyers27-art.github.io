AWS Certified Solutions Architect – Associate SAA-C03

Servicios de detección y cumplimiento: CloudTrail, reglas de AWS Config, GuardDuty, Inspector, Macie y Security Hub

AWS tiene varios servicios de detección con nombres parecidos, y las preguntas del examen a menudo describen una necesidad y preguntan qué servicio la cubre. El truco es recordar la única pregunta que responde cada servicio. En conjunto, cubren la auditoría de quién hizo qué, el seguimiento de cómo están configurados los recursos, la detección de amenazas, la búsqueda de vulnerabilidades, el descubrimiento de datos sensibles y la reunión de todos esos hallazgos en un solo lugar para que alguien actúe sobre ellos.

AWS CloudTrail responde quién hizo qué, cuándo y desde dónde. Registra las llamadas a la API realizadas en tu cuenta, ya sea desde la consola, la CLI, los SDKs o los servicios de AWS, incluidos la identidad, la dirección IP de origen, la hora y los parámetros. El historial de eventos (event history) conserva 90 días de eventos de administración sin cargo adicional; un trail entrega los eventos a un bucket de S3 para retenerlos a largo plazo y puede enviarlos a CloudWatch Logs para filtros de métricas y alarmas. Un trail de organización (organization trail) cubre todas las cuentas de AWS Organizations. Los eventos de datos (data events), como las lecturas de objetos de S3 o las invocaciones de Lambda, no se registran por defecto y deben habilitarse, normalmente de forma selectiva por su volumen. La validación de integridad de los archivos de registro te permite demostrar que los archivos no se alteraron, y CloudTrail Lake te permite consultar los eventos con SQL.

AWS Config responde cómo era este recurso y si cumple nuestras reglas. Registra a lo largo del tiempo los cambios de configuración de los recursos compatibles, así que puedes ver, por ejemplo, el historial completo de un security group y las relaciones entre recursos. Las reglas de Config evalúan los recursos frente a configuraciones deseadas, como que los buckets de S3 deben bloquear el acceso público o que los volúmenes de EBS deben estar cifrados, usando reglas administradas por AWS o reglas personalizadas respaldadas por Lambda o por políticas de Guard. Los recursos que no cumplen pueden corregirse automáticamente con acciones de remediación basadas en documentos de Systems Manager Automation. Los paquetes de conformidad (conformance packs) agrupan reglas para marcos normativos, y un agregador muestra el cumplimiento entre cuentas y regiones.

Amazon GuardDuty responde si está ocurriendo algo malicioso. Es un servicio administrado de detección de amenazas que analiza los eventos de administración de CloudTrail, los VPC Flow Logs y los registros de consultas DNS, además de planes de protección opcionales para eventos de datos de S3, registros de auditoría de EKS, monitoreo en tiempo de ejecución, actividad de inicio de sesión en RDS y análisis de malware, usando inteligencia de amenazas y aprendizaje automático. Lo habilitas con un clic; para las fuentes básicas no se requieren agentes ni configuración de registros. Los hallazgos incluyen minería de criptomonedas, comunicación con IPs maliciosas conocidas y llamadas a la API inusuales desde ubicaciones inesperadas. Amazon Inspector responde cuáles de mis cargas de trabajo tienen vulnerabilidades de software o exposición de red no deseada, y analiza continuamente instancias EC2, imágenes de contenedores en Amazon Elastic Container Registry (ECR) y funciones Lambda en busca de Common Vulnerabilities and Exposures (CVEs) conocidas. Amazon Macie responde dónde hay datos sensibles en S3, usando aprendizaje automático y coincidencia de patrones para descubrir información de identificación personal (PII) y otros datos sensibles, y señala los buckets que son públicos o no están cifrados.

AWS Security Hub lo une todo. Agrega los hallazgos de GuardDuty, Inspector, Macie, Config, IAM Access Analyzer y herramientas de socios en una sola vista con un formato estándar, y ejecuta verificaciones de estándares de seguridad como AWS Foundational Security Best Practices. Los hallazgos fluyen hacia Amazon EventBridge, donde las reglas pueden activar notificaciones o respuestas automatizadas, como una función Lambda que aísla una instancia. Amazon Detective, un servicio relacionado, construye grafos a partir de los registros para ayudar a investigar la causa raíz de un hallazgo.

Veamos un ejemplo práctico. Después de un incidente, un equipo de seguridad usa CloudTrail para descubrir qué rol eliminó una regla de un security group y desde qué dirección IP, y luego usa AWS Config para ver el conjunto de reglas antes y después del cambio. Habilita una regla de Config con remediación automática para que cualquier security group que abra SSH a 0.0.0.0/0 se corrija en minutos. GuardDuty, Inspector y Macie se habilitan en toda la organización con una cuenta de seguridad como administrador delegado, y Security Hub agrega sus hallazgos; una regla de EventBridge envía los hallazgos de alta severidad al canal de guardia mediante SNS.

Errores comunes: esperar que CloudTrail muestre el historial de configuración (eso es Config) o que Config muestre quién hizo la llamada (eso es CloudTrail); esperar que GuardDuty busque vulnerabilidades de software (eso es Inspector); esperar que Macie analice bases de datos o volúmenes de EBS en lugar de S3; y suponer que las lecturas a nivel de objeto de S3 aparecen en CloudTrail sin habilitar los eventos de datos. Otra trampa es pensar que Security Hub detecta amenazas por sí mismo; principalmente agrega hallazgos y verifica la postura de seguridad.

Relaciona la pista con el servicio. 'Quién eliminó', 'historial de la API' o 'registro de auditoría' apunta a CloudTrail. 'Historial de configuración', 'cumplimiento de reglas' o 'remediar automáticamente una mala configuración' apunta a Config. 'Actividad maliciosa', 'instancia comprometida' o 'minería de criptomonedas' apunta a GuardDuty. 'Vulnerabilidades', 'CVE' o 'estado de parches de las imágenes de contenedores' apunta a Inspector. 'PII en S3' apunta a Macie. 'Un solo panel de hallazgos para todas las cuentas' apunta a Security Hub, e 'investigar la causa raíz' apunta a Detective.

Términos clave

CloudTrail
El servicio que registra la actividad de la API en las cuentas de AWS para auditoría e investigación.
Eventos de datos (data events)
Eventos de CloudTrail de alto volumen, como lecturas y escrituras de objetos de S3, que deben habilitarse explícitamente.
AWS Config
El servicio que registra el historial de configuración de los recursos y evalúa su cumplimiento de reglas.
GuardDuty
Un servicio administrado de detección de amenazas que analiza registros para encontrar actividad maliciosa o no autorizada.
Inspector
Un servicio que analiza continuamente EC2, imágenes de contenedores y funciones Lambda en busca de vulnerabilidades conocidas.
Macie
Un servicio que descubre y clasifica datos sensibles, como PII, en Amazon S3.
Security Hub
Un servicio que agrega hallazgos de seguridad y ejecuta verificaciones de buenas prácticas en todas las cuentas.
Ejemplo real

GuardDuty genera un hallazgo de que una instancia EC2 está consultando un dominio asociado con la minería de criptomonedas. Una regla de EventBridge que coincide con ese tipo de hallazgo activa una función Lambda que cambia el security group de la instancia por un grupo de aislamiento y toma snapshots de sus volúmenes. Luego los investigadores usan Detective y CloudTrail para descubrir que una clave de acceso expuesta lanzó la instancia, e Inspector muestra que la imagen usada tenía una vulnerabilidad sin parchear.

Consejo para el examen: Historial de la API: CloudTrail. Historial de configuración y cumplimiento: Config. Amenazas: GuardDuty. Vulnerabilidades: Inspector. Datos sensibles en S3: Macie. Panel único de hallazgos: Security Hub.

Comprueba lo que sabes

¿Qué servicio detectaría una instancia EC2 que se comunica con un servidor de comando y control conocido?

Amazon GuardDuty, que analiza los VPC Flow Logs y los registros DNS frente a inteligencia de amenazas.

Necesitas conocer cada cambio hecho a las reglas de un security group durante el último mes y si cumple la política. ¿Qué servicio?

AWS Config, que registra el historial de configuración y evalúa reglas de cumplimiento.

Los auditores preguntan quién descargó un objeto específico de S3 la semana pasada, pero CloudTrail no muestra nada. ¿Por qué?

El acceso a nivel de objeto de S3 es un evento de datos, que CloudTrail no registra a menos que se hayan habilitado los eventos de datos para ese bucket.

¿Qué servicio analiza imágenes de contenedores en ECR en busca de CVEs conocidas?

Amazon Inspector.
