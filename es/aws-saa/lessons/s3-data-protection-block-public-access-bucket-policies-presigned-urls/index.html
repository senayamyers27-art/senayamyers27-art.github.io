AWS Certified Solutions Architect – Associate SAA-C03

Protección de datos en S3: Block Public Access, bucket policies, presigned URLs, versionado, MFA Delete y modos de Object Lock

Amazon S3 guarda una gran parte de los datos en la nube del mundo, y los buckets mal configurados son una causa conocida de brechas. S3 te da capas de protección contra dos amenazas distintas: la exposición, es decir, que las personas equivocadas lean los datos, y la pérdida, es decir, que los datos se eliminen o sobrescriban por error, por un bug o por ransomware. El examen te pide elegir el control adecuado para cada amenaza, así que ayuda clasificar cada función en uno de esos dos grupos.

Para la exposición, empieza por S3 Block Public Access. Sus cuatro configuraciones bloquean nuevas listas de control de acceso (ACLs) públicas, ignoran las ACLs públicas existentes, bloquean nuevas bucket policies públicas y restringen el acceso a los buckets con políticas públicas. Puede configurarse a nivel de cuenta y por bucket, y anula cualquier política o ACL que haría públicos los datos. Los buckets nuevos lo tienen activado por defecto, y las ACLs están deshabilitadas por defecto mediante la configuración de Object Ownership 'bucket owner enforced', así que el acceso se rige solo por políticas. Mantenerlo activado a nivel de cuenta es la forma más sencilla de evitar buckets públicos por accidente.

Las bucket policies son políticas JSON basadas en recursos que otorgan o deniegan acceso a principales, incluidas otras cuentas, con condiciones como aws:SourceIp, aws:SourceVpce, aws:PrincipalOrgID (solo principales de tu organización) o aws:SecureTransport. Cuando alguien fuera de tu cuenta necesita acceso temporal a un objeto, usa una URL prefirmada (presigned URL): una URL firmada con las credenciales de una identidad que tiene acceso, válida hasta su hora de vencimiento. Cualquiera que tenga la URL puede realizar esa única operación, como GET para descargar o PUT para subir, sin credenciales de AWS propias. La URL no puede otorgar más que los permisos del propio firmante, y si se firmó con credenciales temporales deja de funcionar cuando estas caducan.

aws s3 presign s3://contracts-bucket/client-42/contract.pdf --expires-in 900

Para la pérdida, activa el versionado (versioning). Con el versionado, una sobrescritura crea una versión nueva y una eliminación agrega un marcador de eliminación (delete marker), de modo que las versiones anteriores pueden restaurarse. Una vez habilitado, el versionado puede suspenderse pero no desactivarse. Las reglas de ciclo de vida (lifecycle rules) pueden hacer caducar las versiones antiguas no actuales para controlar el costo. MFA Delete agrega el requisito de autenticación multifactor para eliminar permanentemente una versión o cambiar el estado del versionado; solo el usuario raíz puede habilitarlo, usando la CLI o la API. S3 Object Lock proporciona protección de escritura única y lectura múltiple (WORM) en buckets con versionado. El modo de gobierno (governance mode) protege las versiones contra eliminación o sobrescritura durante el período de retención, pero los usuarios con el permiso s3:BypassGovernanceRetention pueden anularlo. El modo de cumplimiento (compliance mode) no puede acortarse ni eliminarse por nadie, ni siquiera por el usuario raíz, hasta que termine el período de retención. Una retención legal (legal hold) protege una versión de forma indefinida, independientemente de cualquier período de retención, hasta que alguien con permiso la quite.

Veamos un ejemplo práctico. Un despacho de abogados debe conservar sin cambios los contratos firmados durante siete años para cumplir una regulación, y los clientes deben poder descargar sus propios documentos sin cuentas de AWS. Crea un bucket con Block Public Access activado, versionado y Object Lock, y establece una retención predeterminada de siete años en modo de cumplimiento. El portal de clientes genera, para cada descarga, presigned URLs que vencen después de 15 minutos. Cuando comienza un litigio sobre un asunto, el despacho coloca una legal hold sobre esas versiones de los contratos para que sigan protegidas incluso después de los siete años, hasta que se quite la retención.

Errores comunes: desactivar Block Public Access para compartir un archivo con una persona, cuando bastaría una presigned URL; creer que una eliminación en un bucket con versionado destruye los datos (solo agrega un marcador); elegir el modo de gobierno para una regulación que exige que nadie pueda eliminar registros; esperar habilitar MFA Delete desde la consola o como administrador de IAM; y olvidar que Object Lock requiere versionado. Además, la replicación o el versionado por sí solos no son inmutabilidad; solo Object Lock en modo de cumplimiento impide que incluso los usuarios privilegiados eliminen.

Las preguntas del examen usan palabras señal. 'Evitar que cualquier bucket de la cuenta llegue a ser público' apunta a Block Public Access a nivel de cuenta. 'Acceso temporal a un objeto para un usuario sin credenciales de AWS' apunta a una presigned URL. 'Recuperarse de una sobrescritura o eliminación accidental' apunta al versionado. 'WORM', 'retención regulatoria' o 'nadie, incluido root, puede eliminar' apunta al modo de cumplimiento de Object Lock; 'los administradores pueden anularlo si hace falta' apunta al modo de gobierno. 'Exigir MFA para eliminar versiones permanentemente' apunta a MFA Delete.

Términos clave

Block Public Access
Configuraciones de cuenta y de bucket que anulan cualquier ACL o política que haría públicos los datos de S3.
URL prefirmada (presigned URL)
Una URL de tiempo limitado, firmada con las credenciales de una identidad autorizada, que otorga una operación de S3 sobre un objeto.
Versionado (versioning)
Una configuración de bucket de S3 que conserva todas las versiones de un objeto para que las sobrescrituras y eliminaciones puedan deshacerse.
MFA Delete
Una opción del versionado, que solo el usuario raíz puede habilitar, que exige MFA para eliminar versiones permanentemente o cambiar el versionado.
Modo de cumplimiento de Object Lock (compliance mode)
Un modo de retención WORM que nadie, ni siquiera root, puede acortar ni quitar antes de que venza.
Modo de gobierno de Object Lock (governance mode)
Un modo de retención WORM que los usuarios con un permiso especial de omisión pueden anular.
Retención legal (legal hold)
Un indicador de Object Lock que impide eliminar una versión hasta que se quite la retención, sin fecha de vencimiento.
Ejemplo real

Un atacante de ransomware roba las claves de acceso de un administrador e intenta eliminar y sobrescribir los archivos de respaldo de una empresa en S3. Como el bucket de respaldos tiene versionado y Object Lock en modo de cumplimiento con una retención de 30 días, las eliminaciones solo agregan marcadores y las sobrescrituras crean versiones nuevas, mientras que las versiones protegidas no pueden eliminarse. La empresa rota las claves y restaura las versiones anteriores en pocas horas.

Consejo para el examen: El modo de gobierno puede omitirse por usuarios con un permiso especial; el modo de cumplimiento no puede omitirlo nadie. Para dar acceso temporal a un objeto sin crear usuarios de IAM, elige una presigned URL.

Comprueba lo que sabes

Un usuario eliminó un objeto en un bucket con versionado. ¿Cómo lo recuperas?

Elimina el delete marker (o copia de vuelta la versión anterior). El versionado conservó la versión previa; la eliminación solo agregó un marcador.

¿Qué modo de Object Lock permite que un administrador privilegiado quite la retención antes de tiempo?

El modo de gobierno, para usuarios con el permiso s3:BypassGovernanceRetention. El modo de cumplimiento no se lo permite a nadie.

Se generó una presigned URL con las credenciales de un usuario, pero ese usuario no tiene s3:GetObject sobre el objeto. ¿Funcionará la URL?

No. Una presigned URL solo puede otorgar lo que la identidad que firma tiene permitido hacer.

¿Quién puede habilitar MFA Delete en un bucket, y cómo?

Solo el usuario raíz del propietario del bucket, usando la CLI o la API con un dispositivo MFA.
