Protección de datos en S3: Block Public Access, bucket policies, presigned URLs, versionado, MFA Delete y modos de Object Lock

Amazon S3 guarda una gran parte de los datos en la nube del mundo, y los buckets mal configurados son una causa famosa de brechas. S3 te da capas de protección contra dos amenazas diferentes: la exposición (que las personas equivocadas lean los datos) y la pérdida (que los datos se eliminen o sobrescriban, por error o por ransomware).

Para la exposición, empieza con S3 Block Public Access. Sus cuatro opciones bloquean las nuevas ACLs públicas, ignoran las ACLs públicas existentes, bloquean las nuevas bucket policies públicas y restringen el acceso a los buckets con políticas públicas. Se puede configurar a nivel de cuenta y por bucket, y anula cualquier política o ACL que haría públicos los datos. Los buckets nuevos lo tienen activado por defecto, y las ACLs están deshabilitadas por defecto mediante la opción de Object Ownership 'bucket owner enforced', así que el acceso se rige solo por políticas.

Las bucket policies son políticas JSON basadas en recursos que otorgan o deniegan acceso a principales, incluidas otras cuentas, con condiciones como aws:SourceIp, aws:SourceVpce, aws:PrincipalOrgID o aws:SecureTransport. Cuando un usuario fuera de tu cuenta necesita acceso temporal a un objeto, usa una presigned URL (URL prefirmada): una URL firmada con las credenciales de una identidad que tiene acceso, válida hasta su hora de expiración. Cualquiera que tenga la URL puede realizar esa única operación, como GET para descargar o PUT para subir, sin credenciales de AWS propias. La URL no puede otorgar más que los propios permisos de quien la firmó.

Para la pérdida, activa el versioning (versionado). Con el versionado, una sobrescritura crea una nueva versión y una eliminación agrega un delete marker (marcador de eliminación), así que las versiones anteriores se pueden restaurar. Una vez habilitado, el versionado se puede suspender pero no desactivar. MFA Delete agrega el requisito de autenticación multifactor para eliminar permanentemente una versión o para cambiar el estado del versionado; solo el usuario root puede habilitarlo, usando la CLI o la API.

S3 Object Lock proporciona protección write-once-read-many (WORM, una escritura y muchas lecturas) en buckets versionados. El governance mode (modo de gobernanza) protege las versiones contra la eliminación durante el período de retención, pero los usuarios con el permiso s3:BypassGovernanceRetention pueden anularlo. El compliance mode (modo de cumplimiento) no lo puede acortar ni eliminar nadie, ni siquiera el usuario root, hasta que termine el período de retención. Un legal hold (retención legal) protege una versión indefinidamente, independientemente de la retención, hasta que alguien con permiso lo quite. El compliance mode es la respuesta para regulaciones que exigen registros inmutables; el governance mode es para protección con una vía de escape para los administradores.

Términos clave

Block Public Access
Opciones de cuenta y de bucket que anulan cualquier ACL o política que haría públicos los datos de S3.
Presigned URL (URL prefirmada)
Una URL de duración limitada, firmada con las credenciales de una identidad autorizada, que otorga una operación de S3 sobre un objeto.
Object Lock compliance mode (modo de cumplimiento)
Un modo de retención WORM que nadie, ni siquiera root, puede acortar ni eliminar antes de que expire.
Legal hold (retención legal)
Un indicador de Object Lock que impide eliminar una versión hasta que se quite la retención, sin fecha de expiración.
Ejemplo real

Un despacho de abogados debe conservar sin cambios los contratos firmados durante siete años para cumplir una regulación. Crea un bucket con versionado y Object Lock, establece una retención predeterminada de siete años en compliance mode y da a sus clientes presigned URLs que expiran a los 15 minutos para descargar sus propios documentos.

Consejo para el examen: El governance mode lo pueden eludir usuarios con un permiso especial; el compliance mode no lo puede eludir nadie. Para dar acceso temporal a un objeto sin crear usuarios de IAM, elige una presigned URL.

Comprueba lo que sabes

Un usuario eliminó un objeto en un bucket versionado. ¿Cómo lo recuperas?

Elimina el delete marker (o copia de nuevo la versión anterior). El versionado conservó la versión previa; la eliminación solo agregó un marcador.

¿Qué modo de Object Lock permite que un administrador privilegiado quite la retención antes de tiempo?

El governance mode, para usuarios con el permiso s3:BypassGovernanceRetention. El compliance mode no se lo permite a nadie.
