Cifrado en tránsito: certificados de ACM, TLS en ALB y CloudFront, y cómo exigir HTTPS con aws:SecureTransport

El cifrado en tránsito protege los datos mientras se mueven entre clientes y servicios, y entre los propios servicios. En AWS eso casi siempre significa Transport Layer Security (TLS), el protocolo detrás de HTTPS. Para ofrecer TLS necesitas un certificado X.509 para tu dominio, y AWS Certificate Manager (ACM) es el servicio que los proporciona y administra.

ACM emite certificados públicos sin cargo adicional para usarlos con servicios integrados, valida la propiedad del dominio por DNS o correo electrónico y los renueva automáticamente mientras la validación por DNS se mantenga. Los certificados de ACM se pueden desplegar en Elastic Load Balancing, Amazon CloudFront, API Gateway y algunos otros servicios integrados, pero un certificado público estándar de ACM no se puede exportar, así que no puedes instalarlo en tu propio servidor web que corre en EC2. También puedes importar certificados de terceros a ACM, pero ACM no renueva los importados. Los certificados de ACM son recursos regionales, con una excepción importante: un certificado usado por CloudFront debe solicitarse o importarse en la Región US East (N. Virginia), us-east-1.

El patrón común es la terminación de TLS en el balanceador de carga. Un listener HTTPS de un Application Load Balancer usa un certificado de ACM, descifra el tráfico, aplica reglas de enrutamiento y lo reenvía a los destinos por HTTP o, cuando se requiere cifrado de extremo a extremo, lo vuelve a cifrar por HTTPS hacia los destinos. Una security policy en el listener define las versiones de TLS y los cifrados permitidos. Server Name Indication (SNI) permite que un listener tenga varios certificados para distintos dominios. Un listener HTTP en el puerto 80 puede tener una acción de redirección a HTTPS en el 443. Un Network Load Balancer puede terminar TLS con un listener TLS, o dejar pasar el tráfico TCP para que lo terminen los destinos.

CloudFront tiene dos tramos de TLS. La viewer protocol policy controla la conexión desde los usuarios: permitir todo, redirigir HTTP a HTTPS o solo HTTPS. La origin protocol policy controla la conexión de CloudFront al origen. Para un cifrado completo de extremo a extremo, exiges HTTPS en ambos.

Para exigir cifrado en S3 y otros servicios con políticas de recursos, usa la clave de condición aws:SecureTransport, que es verdadera cuando una solicitud llegó por TLS. Una declaración de bucket policy con Effect: Deny, Principal: *, Action: s3:* y Condition: {"Bool": {"aws:SecureTransport": "false"}} rechaza cualquier solicitud HTTP sin cifrar. La misma idea funciona en las políticas de SQS y SNS. Para bases de datos, RDS admite conexiones TLS y un parámetro puede exigirlas, como rds.force_ssl para PostgreSQL.

Términos clave

AWS Certificate Manager (ACM)
Un servicio que emite, almacena y renueva automáticamente certificados TLS para servicios de AWS integrados.
TLS termination (terminación de TLS)
Descifrar TLS en un componente frontal, como un balanceador de carga, antes de pasar la solicitud.
Viewer protocol policy
La configuración de CloudFront que controla si los espectadores pueden usar HTTP, se redirigen a HTTPS o deben usar HTTPS.
aws:SecureTransport
Una clave de condición que es verdadera cuando la solicitud se envió por TLS.
Ejemplo real

Una empresa sirve su sitio a través de CloudFront con un ALB como origen. Solicita un certificado de ACM para www.example.com en us-east-1 para CloudFront y otro en la Región del ALB, configura la viewer protocol policy para redirigir HTTP a HTTPS y la origin protocol policy como solo HTTPS, de modo que el tráfico va cifrado todo el camino hasta el balanceador de carga.

Consejo para el examen: Un certificado de CloudFront debe estar en us-east-1. Exigir HTTPS en un bucket de S3 es una bucket policy que deniega las solicitudes donde aws:SecureTransport es false, no una configuración del bucket.

Comprueba lo que sabes

Creaste un certificado de ACM en eu-west-1 pero no puedes seleccionarlo en CloudFront. ¿Por qué?

CloudFront solo usa certificados de ACM de us-east-1. Solicita o importa el certificado allí.

¿Cómo haces que un bucket de S3 rechace las solicitudes HTTP?

Agrega una bucket policy que deniegue todas las acciones de S3 cuando aws:SecureTransport sea false.
