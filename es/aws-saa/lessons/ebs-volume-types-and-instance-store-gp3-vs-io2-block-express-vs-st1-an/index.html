Tipos de volúmenes EBS e instance store: gp3 vs io2 Block Express vs st1 y sc1

Amazon Elastic Block Store (EBS) proporciona volúmenes de almacenamiento en bloque conectados por red para EC2, como discos duros virtuales. Un volumen vive en una Availability Zone, se replica dentro de esa AZ, persiste de forma independiente de la instancia y se puede respaldar con snapshots. Normalmente un volumen se adjunta a una instancia a la vez; los volúmenes io1 e io2 admiten Multi-Attach a varias instancias Nitro en la misma AZ para aplicaciones en clúster que gestionan escrituras concurrentes.

Los tipos de volúmenes EBS se dividen en respaldados por SSD y respaldados por HDD. El SSD de uso general gp3 es la opción predeterminada para volúmenes de arranque y la mayoría de las cargas de trabajo. Su característica clave es que el rendimiento es independiente del tamaño: cada volumen gp3 obtiene una base de 3,000 IOPS y 125 MB/s, y puedes aprovisionar más IOPS y rendimiento por separado sin comprar más almacenamiento. El antiguo gp2 vincula las IOPS al tamaño del volumen y usa créditos de ráfaga para los volúmenes pequeños, por lo que migrar de gp2 a gp3 normalmente reduce el costo o mejora el rendimiento.

Los SSD de IOPS aprovisionadas, io1 e io2, son para bases de datos con uso intensivo de E/S que necesitan IOPS sostenidas y constantes y baja latencia. io2 Block Express ofrece el nivel de EBS de mayor rendimiento, con latencia inferior a un milisegundo, muchas más IOPS y rendimiento por volumen que gp3, y mayor durabilidad que los demás tipos de volumen. Elígelo para bases de datos grandes y de misión crítica como SAP HANA, Oracle o SQL Server cuando los máximos de gp3 no sean suficientes.

Los volúmenes HDD están optimizados para el rendimiento (throughput), medido en MB/s, en lecturas y escrituras secuenciales grandes, y no pueden ser volúmenes de arranque. El HDD optimizado para rendimiento (st1) se adapta a big data, data warehouses, procesamiento de logs y cargas de streaming que leen archivos grandes en secuencia. El Cold HDD (sc1) es la opción de EBS de menor costo para datos orientados al rendimiento a los que se accede con poca frecuencia. La E/S aleatoria pequeña en volúmenes HDD rinde mal, así que nunca los elijas para bases de datos transaccionales.

El instance store es diferente: es almacenamiento en bloque temporal en discos conectados físicamente al host. Ofrece un rendimiento de E/S muy alto y no tiene costo adicional, pero los datos se pierden cuando la instancia se detiene, hiberna o termina, o si falla la unidad subyacente. Los datos solo sobreviven a un reinicio. Úsalo para cachés, búferes, datos temporales o datos replicados donde la aplicación mantiene copias en otros nodos. Solo ciertos tipos de instancia lo incluyen, y no puedes desconectarlo y conectarlo en otro lugar.

Términos clave

gp3
SSD de uso general con una base de 3,000 IOPS y 125 MB/s, con IOPS y rendimiento aprovisionados independientemente del tamaño.
io2 Block Express
El SSD de EBS de mayor rendimiento para bases de datos exigentes, con latencia inferior a un milisegundo y alta durabilidad.
st1
HDD optimizado para rendimiento para cargas secuenciales grandes como big data y logs; no puede ser de arranque.
Instance store (almacén de instancia)
Almacenamiento en bloque temporal conectado físicamente al host; los datos se pierden al detener o terminar la instancia.
Ejemplo real

Una empresa ejecuta una gran base de datos Oracle que necesita IOPS sostenidas muy altas y elige io2 Block Express. Sus servidores web usan volúmenes de arranque gp3. Un clúster de analítica de logs que lee terabytes en secuencia usa st1, y los reportes mensuales archivados que rara vez se escanean están en sc1. Una capa de caché usa el instance store de instancias optimizadas para almacenamiento porque la caché se puede reconstruir.

Consejo para el examen: Volumen predeterminado o de arranque: gp3. Máximas IOPS sostenidas para bases de datos críticas: io2 Block Express. Gran rendimiento secuencial a bajo costo: st1; el más frío y barato: sc1. El espacio temporal más rápido que se puede perder: instance store.

Comprueba lo que sabes

Detienes e inicias una instancia. ¿Qué pasa con los datos de su volumen de instance store?

Se pierden. Los datos del instance store solo sobreviven a los reinicios, no a las detenciones, la hibernación ni la terminación.

¿Por qué gp3 suele ser más barato que gp2 para el mismo rendimiento?

gp3 te permite aprovisionar IOPS y rendimiento independientemente del tamaño, así que ya no necesitas sobreaprovisionar almacenamiento para obtener IOPS.
