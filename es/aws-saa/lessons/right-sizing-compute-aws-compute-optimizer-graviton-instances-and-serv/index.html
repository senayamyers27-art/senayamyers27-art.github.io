Ajuste de tamaño del cómputo: AWS Compute Optimizer, instancias Graviton y modelos de costo serverless vs siempre encendidos

Right-sizing (ajuste de tamaño) significa adecuar los recursos a lo que una carga de trabajo realmente usa. Muchas instancias se lanzan más grandes de lo necesario y nunca se revisan, así que el right-sizing suele ser la forma más rápida de ahorrar dinero, y debe hacerse antes de comprar compromisos, para no fijar descuentos sobre el desperdicio.

AWS Compute Optimizer analiza las métricas de utilización de CloudWatch, como CPU, red y, cuando el CloudWatch agent la publica, memoria, para instancias EC2, Auto Scaling groups, volúmenes EBS, funciones Lambda, servicios ECS en Fargate y algunas bases de datos RDS. Clasifica los recursos como sobreaprovisionados, subaprovisionados u optimizados, y recomienda tipos de instancia, configuraciones de volumen o tamaños de memoria de Lambda específicos, con el riesgo de rendimiento y el ahorro proyectados. Las métricas de memoria no se recopilan por defecto en EC2, así que instalar el CloudWatch agent hace posibles las recomendaciones que tienen en cuenta la memoria. Cost Explorer también ofrece recomendaciones de rightsizing, y Trusted Advisor señala las instancias con baja utilización.

Los procesadores AWS Graviton son chips basados en Arm diseñados por AWS. Los tipos de instancia Graviton, marcados con una g en el nombre como m7g o c7g, suelen ofrecer una mejor relación precio-rendimiento que las instancias x86 comparables para muchas cargas de trabajo, además de un menor consumo de energía. El inconveniente es la compatibilidad: el software debe ejecutarse en la arquitectura Arm64. Los lenguajes interpretados y compilados JIT como Python, Node.js, Java y .NET suelen migrar con facilidad, y muchas imágenes de contenedores son multiarquitectura; los binarios nativos deben recompilarse. Graviton también está disponible para Lambda, Fargate, RDS, Aurora y ElastiCache, lo que puede dar logros rápidos.

La decisión de fondo es el modelo de costo. Una instancia EC2 o un contenedor siempre encendido cuesta lo mismo si atiende una solicitud o un millón, así que es eficiente para una utilización estable y alta, sobre todo con Savings Plans. Los servicios serverless como Lambda, Fargate para tareas cortas, DynamoDB on-demand y Aurora Serverless v2 cobran por el uso real, así que son eficientes para cargas ociosas, con picos o impredecibles, y eliminan trabajo operativo. Con volúmenes muy altos y constantes, una flota de instancias bien utilizada puede resultar más barata que el precio por solicitud, así que la respuesta correcta depende del patrón de tráfico.

Además, apaga lo que no necesites: programa los entornos de desarrollo para que se detengan fuera del horario laboral con Instance Scheduler o reglas de EventBridge, elimina las Elastic IPs y los balanceadores de carga sin usar, y etiqueta los recursos para poder encontrar a sus responsables.

Términos clave

Right-sizing (ajuste de tamaño)
Ajustar los tipos y tamaños de los recursos para que coincidan con la utilización real y las necesidades de rendimiento.
AWS Compute Optimizer
Un servicio que usa métricas de utilización para recomendar configuraciones óptimas de EC2, EBS, Lambda, ECS y otros.
AWS Graviton
Procesadores basados en Arm diseñados por AWS que ofrecen una gran relación precio-rendimiento para cargas compatibles.
CloudWatch agent
Software que publica en CloudWatch métricas adicionales de las instancias, como la utilización de memoria.
Ejemplo real

La flota de 40 instancias m5.2xlarge de una empresa promedia un 12 por ciento de CPU. Compute Optimizer, con los datos de memoria del CloudWatch agent, recomienda m7g.large. La aplicación Java se ejecuta sin cambios en Arm tras reconstruir el contenedor, y luego el equipo cubre la flota más pequeña con un Savings Plan. Una herramienta interna que se usa unas pocas veces al día pasa de una instancia siempre encendida a Lambda.

Consejo para el examen: Obtener recomendaciones a partir de datos de utilización: Compute Optimizer. Mejor relación precio-rendimiento con lenguajes que no requieren recompilar: Graviton. Las cargas ociosas o con picos favorecen serverless; la utilización estable y alta favorece la capacidad aprovisionada con compromisos. Ajusta el tamaño antes de comprometerte.

Comprueba lo que sabes

¿Por qué Compute Optimizer podría dar recomendaciones de EC2 menos precisas por defecto?

EC2 no reporta la utilización de memoria sin el CloudWatch agent, así que las cargas limitadas por memoria pueden evaluarse mal.

¿Qué debes verificar antes de trasladar una aplicación a Graviton?

Que su código y sus dependencias sean compatibles con Arm64; los binarios nativos y algunas bibliotecas pueden necesitar recompilarse o reemplazarse.
