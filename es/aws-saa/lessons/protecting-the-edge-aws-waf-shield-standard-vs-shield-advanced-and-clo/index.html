Protección del borde: AWS WAF, Shield Standard vs Shield Advanced y CloudFront con origin access control

El borde (edge) es donde tu aplicación se encuentra con internet, y es el mejor lugar para detener el tráfico malicioso antes de que llegue a tus servidores. AWS ofrece tres servicios que trabajan juntos allí: AWS WAF para el filtrado en la capa de aplicación, AWS Shield para la protección contra la denegación de servicio distribuida (DDoS) y Amazon CloudFront como la red de entrega de contenido que absorbe y filtra el tráfico en cientos de edge locations (ubicaciones de borde).

AWS WAF es un web application firewall (firewall de aplicaciones web). Creas una web access control list (web ACL) y la adjuntas a una distribución de CloudFront, un Application Load Balancer, una REST API de API Gateway, una API GraphQL de AppSync o un Cognito user pool. Inspecciona las solicitudes HTTP(S) en la capa 7 y aplica reglas: managed rule groups (grupos de reglas administrados) para amenazas comunes como SQL injection y cross-site scripting, reglas de IP set para bloquear o permitir rangos de direcciones, reglas de coincidencia geográfica y rate-based rules (reglas basadas en tasa) que bloquean una dirección IP que envía demasiadas solicitudes en una ventana de tiempo. WAF no se puede adjuntar a un Network Load Balancer ni directamente a una instancia EC2.

AWS Shield Standard es automático y gratuito para todos los clientes de AWS. Protege contra ataques comunes de las capas de red y transporte (capas 3 y 4), como SYN floods y UDP reflection. Shield Advanced es una suscripción de pago para una protección mayor sobre recursos específicos: CloudFront, hosted zones de Route 53, Global Accelerator, Elastic Load Balancers y direcciones Elastic IP. Agrega detección y mitigación ajustadas a tu tráfico, visibilidad de ataques casi en tiempo real, acceso al AWS Shield Response Team (SRT) durante los ataques, AWS WAF sin costo adicional para los recursos protegidos y protección de costos que acredita los cargos de escalado causados por un ataque DDoS.

CloudFront en sí es una defensa sólida porque los ataques se reparten por la red global de borde. Para asegurarte de que los usuarios no puedan saltarse CloudFront y atacar directamente un origen S3, usa origin access control (OAC). Habilitas OAC en la distribución, mantienes el bucket privado con Block Public Access activado y agregas una bucket policy que permite s3:GetObject solo cuando el principal es el servicio CloudFront y aws:SourceArn es tu distribución. OAC reemplaza a la antigua origin access identity (OAI) y admite objetos cifrados con SSE-KMS. Para orígenes personalizados como un ALB, un patrón común es que CloudFront agregue un encabezado personalizado secreto y que el ALB rechace las solicitudes que no lo tengan, o permitir solo la managed prefix list de CloudFront en el security group del ALB.

Términos clave

Web ACL
El recurso de AWS WAF que contiene las reglas y se asocia con CloudFront, ALB, API Gateway y otros recursos compatibles.
Rate-based rule (regla basada en tasa)
Una regla de WAF que bloquea las IP de origen que superan un número de solicitudes dentro de una ventana de tiempo.
Shield Advanced
Un nivel de pago de protección DDoS con soporte del SRT, detección avanzada y protección de costos por DDoS.
Origin access control (OAC, control de acceso al origen)
Una función de CloudFront que firma las solicitudes a un origen S3 para que el bucket pueda permanecer privado y aceptar solo esa distribución.
Ejemplo real

Un sitio de comercio minorista ve bots golpeando su página de inicio de sesión. El equipo adjunta a su distribución de CloudFront una web ACL de WAF con el conjunto de reglas comunes administrado por AWS y una rate-based rule en la ruta /login. Como se acerca una gran venta, también se suscriben a Shield Advanced para que el Shield Response Team pueda ayudar durante un ataque y se acrediten los costos de escalado que este provoque.

Consejo para el examen: SQL injection, cross-site scripting, limitación de tasa o bloqueo geográfico apuntan a AWS WAF. Un DDoS grande con soporte experto y protección de costos apunta a Shield Advanced. Mantener privado un origen S3 detrás de CloudFront apunta a origin access control.

Comprueba lo que sabes

¿Puedes adjuntar AWS WAF a un Network Load Balancer?

No. WAF trabaja en la capa 7 y se adjunta a CloudFront, ALB, REST APIs de API Gateway, AppSync y Cognito user pools, no a NLBs.

¿Qué nivel de Shield está habilitado por defecto sin costo?

Shield Standard, que protege a todos los clientes contra los ataques DDoS comunes de capas 3 y 4.
