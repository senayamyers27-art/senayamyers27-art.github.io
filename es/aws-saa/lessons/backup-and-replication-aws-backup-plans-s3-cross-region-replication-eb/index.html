Respaldo y replicación: planes de AWS Backup, S3 Cross-Region Replication, copias de snapshots de EBS y AMIs, AWS Elastic Disaster Recovery

Toda estrategia de DR depende de que las copias de los datos y de las imágenes de máquina estén en el lugar correcto. AWS te ofrece funciones específicas de cada servicio y un servicio central para administrarlas, y el examen te pide elegir la que cumple un requisito con el menor esfuerzo.

AWS Backup centraliza los respaldos de muchos servicios, incluidos EBS, EC2, RDS, Aurora, DynamoDB, EFS, FSx, S3 y Storage Gateway. Un backup plan (plan de respaldo) define reglas: con qué frecuencia respaldar, la ventana de respaldo, cuánto tiempo conservar los recovery points, cuándo moverlos a almacenamiento en frío y si copiarlos a otra Región o cuenta. Los recursos se asignan a un plan por etiquetas o IDs de recurso, así que etiquetar una base de datos nueva con backup=daily basta para protegerla. Los recovery points se almacenan en backup vaults. AWS Backup Vault Lock puede hacer inmutable la retención de un vault, protegiendo los respaldos contra la eliminación incluso por administradores, lo que importa para la defensa contra ransomware. Con AWS Organizations, las backup policies se pueden aplicar en varias cuentas.

Amazon S3 Replication copia objetos de forma asíncrona a otro bucket. Cross-Region Replication (CRR) los envía a un bucket de otra Región, para recuperación ante desastres, cumplimiento o menor latencia; Same-Region Replication (SRR) se usa para agregar logs o hacer copias entre cuentas. Ambas requieren versionado en los buckets de origen y destino y un rol de IAM que S3 usa para replicar. La replicación se aplica a los objetos nuevos escritos después de crear la regla; los objetos existentes necesitan S3 Batch Replication. Los delete markers no se replican a menos que lo habilites, y las eliminaciones permanentes de versiones nunca se replican, lo que protege contra eliminaciones maliciosas. S3 Replication Time Control agrega un tiempo de replicación predecible respaldado por un acuerdo de nivel de servicio.

Los snapshots de EBS son respaldos incrementales a un momento dado de los volúmenes, que AWS almacena en S3. Puedes copiar un snapshot a otra Región o compartirlo con otra cuenta, y cifrarlo o volver a cifrarlo durante la copia. Una Amazon Machine Image (AMI) captura los volúmenes raíz y de datos de una instancia más su configuración de lanzamiento; las AMIs son regionales, así que para lanzar el mismo servidor en una Región de recuperación copias la AMI allí. Amazon Data Lifecycle Manager puede automatizar la creación, retención y copias entre Regiones de snapshots y AMIs.

AWS Elastic Disaster Recovery (AWS DRS) replica continuamente servidores, físicos, virtuales o en la nube, a nivel de bloque hacia un área de staging de bajo costo en una Región de AWS. Durante un desastre o un simulacro lanza instancias de recuperación en minutos, lo que da un RPO de segundos y un RTO de minutos para muchas cargas de trabajo, sin ejecutar servidores de tamaño completo todo el tiempo. Es la respuesta para llevar servidores completos, incluidos los on-premises, a AWS para DR.

Términos clave

Backup plan (plan de respaldo)
Una política de AWS Backup que define la frecuencia, retención, ciclo de vida y reglas de copia de los respaldos para los recursos asignados.
Vault Lock
Una función de AWS Backup que hace inmutable la configuración de retención de un backup vault.
Cross-Region Replication (replicación entre Regiones)
Copia asíncrona de objetos de S3 a un bucket de otra Región; requiere versionado en ambos buckets.
AWS Elastic Disaster Recovery
Un servicio que replica continuamente servidores a AWS y lanza instancias de recuperación bajo demanda.
Ejemplo real

Una empresa debe conservar respaldos diarios de todos los volúmenes EBS, bases de datos RDS y sistemas de archivos EFS de producción durante 35 días, con copias en una segunda Región que nadie pueda eliminar. Crea un único plan de AWS Backup con una regla de copia a la otra Región, asigna los recursos mediante la etiqueta env=prod y habilita Vault Lock en el vault de destino.

Consejo para el examen: Respaldo centralizado y basado en etiquetas para varios servicios, con copias entre Regiones y entre cuentas: AWS Backup. Copiar automáticamente los objetos nuevos de S3 a otra Región: CRR (requiere versionado). Replicación continua a nivel de bloque de servidores completos para DR: Elastic Disaster Recovery.

Comprueba lo que sabes

Creaste una regla de CRR, pero los objetos subidos el año pasado no están en el bucket de destino. ¿Por qué?

Las reglas de replicación se aplican a los objetos nuevos. Usa S3 Batch Replication para copiar los objetos existentes.

¿Cómo lanzas la misma imagen de EC2 en otra Región?

Copia la AMI a esa Región, ya que las AMIs son recursos regionales, y luego lanza desde la copia.
