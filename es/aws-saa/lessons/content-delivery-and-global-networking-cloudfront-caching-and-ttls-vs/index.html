Entrega de contenido y redes globales: caché y TTLs de CloudFront vs AWS Global Accelerator

Los usuarios lejanos a tu Región de AWS experimentan latencia simplemente por la distancia y los muchos saltos de internet de por medio. AWS tiene dos servicios que llevan a los usuarios a la red global de AWS cerca de donde se encuentran: Amazon CloudFront y AWS Global Accelerator. Suenan parecidos, y distinguirlos es un clásico del examen.

CloudFront es una content delivery network (CDN, red de entrega de contenido). Almacena contenido en caché en edge locations de todo el mundo, así que las solicitudes repetidas se responden cerca del usuario sin volver al origen. Los orígenes pueden ser buckets de S3, ALBs, instancias EC2, API Gateway o cualquier servidor HTTP. Los behaviors asignan patrones de ruta URL, como /images/*, a orígenes y configuraciones de caché. Una cache policy controla la cache key (clave de caché), es decir, qué encabezados, cookies y query strings hacen única una respuesta, y los TTLs: los tiempos mínimo, predeterminado y máximo que un objeto permanece en caché. El origen puede influir en el TTL con los encabezados Cache-Control o Expires dentro de esos límites. Incluir demasiados valores en la cache key reduce el cache hit ratio (tasa de aciertos). Para eliminar contenido antes de que expire, puedes crear una invalidation (invalidación) o, mejor aún, usar nombres de archivo versionados como app.v2.js. CloudFront también acelera el contenido dinámico, admite signed URLs y signed cookies para contenido privado, y ejecuta código en el borde con CloudFront Functions y Lambda@Edge.

AWS Global Accelerator no almacena en caché. Te da dos direcciones IP anycast estáticas anunciadas desde las edge locations de AWS. Los usuarios se conectan al borde más cercano, y luego el tráfico viaja por el backbone de AWS hasta tus endpoints, que pueden ser ALBs, NLBs, instancias EC2 o Elastic IPs en una o más Regiones. Funciona para cualquier tráfico TCP o UDP, no solo HTTP. Los health checks y los traffic dials enrutan a los usuarios hacia endpoints sanos, haciendo failover entre Regiones en segundos sin demoras por caché de DNS, porque las direcciones IP nunca cambian.

¿Entonces cómo eliges? Para contenido HTTP almacenable en caché, como imágenes, video, sitios web estáticos y respuestas de API, elige CloudFront. Para protocolos que no son HTTP, como juegos por UDP, IoT por MQTT o VoIP, para clientes que necesitan direcciones IP fijas que poner en su lista de permitidos, o para un failover multirregión rápido sin depender de los TTL de DNS, elige Global Accelerator. Ambos se integran con AWS Shield para la protección contra DDoS.

Términos clave

Edge location (ubicación de borde)
Un sitio de AWS cercano a los usuarios donde CloudFront almacena contenido en caché y Global Accelerator acepta tráfico.
TTL
Time to live: cuánto tiempo CloudFront mantiene un objeto en caché antes de volver a consultar el origen.
Invalidation (invalidación)
Una solicitud a CloudFront para eliminar objetos de las cachés de borde antes de que expire su TTL.
AWS Global Accelerator
Un servicio que proporciona IPs anycast estáticas que enrutan tráfico TCP y UDP por el backbone de AWS hacia endpoints sanos.
Ejemplo real

Las imágenes y artículos de un sitio de noticias se almacenan en caché en CloudFront con un TTL de un día para las imágenes y un TTL corto para la página de inicio, lo que reduce drásticamente la carga en el origen. Su empresa hermana ejecuta un juego multijugador por UDP en tres Regiones y usa Global Accelerator para que los jugadores se conecten a dos IP fijas y se enruten a la Región sana más cercana.

Consejo para el examen: Caché y contenido HTTP significa CloudFront. Direcciones IP estáticas, tráfico UDP o TCP que no es HTTP, o failover regional instantáneo sin DNS significa Global Accelerator.

Comprueba lo que sabes

Los clientes deben poner en su lista de permitidos exactamente dos direcciones IP para una API servida desde dos Regiones. ¿Qué servicio?

AWS Global Accelerator, que proporciona dos direcciones IP anycast estáticas para endpoints en varias Regiones.

Desplegaste un nuevo archivo CSS con el mismo nombre, pero los usuarios siguen recibiendo el anterior. ¿Cuáles son dos soluciones?

Crear una invalidation de CloudFront para esa ruta, o usar nombres de archivo versionados para que el archivo nuevo tenga una nueva cache key.
