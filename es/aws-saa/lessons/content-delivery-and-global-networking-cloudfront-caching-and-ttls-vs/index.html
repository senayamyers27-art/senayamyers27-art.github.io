Entrega de contenido y redes globales: caché y TTLs de CloudFront vs AWS Global Accelerator

Los usuarios lejos de tu Región de AWS sufren latencia simplemente por la distancia y los muchos saltos de internet que hay en medio, y la internet pública añade congestión impredecible. AWS tiene dos servicios que llevan a los usuarios a la red global de AWS cerca de donde están: Amazon CloudFront y AWS Global Accelerator. Ambos usan edge locations de AWS, ambos mejoran el rendimiento para usuarios lejanos y ambos se integran con AWS Shield para la protección contra denegación de servicio distribuida (DDoS), por eso distinguirlos es una pregunta clásica del examen.

CloudFront es una red de entrega de contenido (CDN). Almacena contenido en caché en edge locations de todo el mundo, de modo que las solicitudes repetidas se responden cerca del usuario sin volver al origen. Los orígenes pueden ser buckets de S3, Application Load Balancers (ALB), instancias EC2, API Gateway o cualquier servidor HTTP. Los cache behaviors asocian patrones de ruta de URL, como /images/* o /api/*, con orígenes y configuraciones. Para un origen S3, origin access control (OAC) permite que CloudFront lea un bucket privado para que los usuarios no puedan saltarse la distribución. CloudFront también acelera el contenido dinámico mediante conexiones persistentes, admite signed URLs y signed cookies para contenido privado, y ejecuta código en el edge con CloudFront Functions y Lambda@Edge.

La caché se controla con una cache policy. La política define la clave de caché, es decir, qué encabezados, cookies y query strings hacen única una respuesta, y la configuración del tiempo de vida (TTL): los tiempos mínimo, predeterminado y máximo que un objeto permanece en caché. El origen puede influir en el TTL con encabezados Cache-Control o Expires dentro de esos límites; por ejemplo, Cache-Control: max-age=86400 pide un día. Incluir demasiados valores en la clave de caché reduce la tasa de aciertos, porque respuestas que de otro modo serían idénticas se almacenan por separado, así que reenvía solo lo que el origen realmente necesita (una origin request policy puede enviar valores adicionales al origen sin agregarlos a la clave). Para quitar contenido antes de que expire puedes crear una invalidación, como aws cloudfront create-invalidation --distribution-id E123 --paths '/css/*', pero los nombres de archivo con versión como app.v2.js son mejores, porque un nombre nuevo es una clave de caché nueva y las versiones anteriores se mantienen consistentes.

AWS Global Accelerator no almacena nada en caché. Te da dos direcciones IP anycast estáticas anunciadas desde edge locations de AWS. Los usuarios se conectan al edge más cercano, y luego el tráfico viaja por la red troncal de AWS hasta tus endpoints, que pueden ser Network Load Balancers (NLB), ALB, instancias EC2 o direcciones Elastic IP en una o más Regiones. Funciona para cualquier tráfico TCP o UDP, no solo HTTP. Los health checks y los traffic dials enrutan a los usuarios hacia endpoints sanos y hacen conmutación por error entre Regiones en segundos, sin esperar a que expiren las cachés de DNS, porque las direcciones IP que usan los clientes nunca cambian. Los pesos de los endpoints te permiten desplazar el tráfico gradualmente, lo que ayuda en los despliegues blue/green.

Veamos un ejemplo práctico. Un sitio de noticias pone CloudFront delante de un bucket de S3 para las imágenes y de un ALB para los artículos. Las imágenes tienen un TTL de un día, la página principal un TTL de 60 segundos, y la clave de caché de los artículos incluye solo el query string lang, lo que eleva mucho la tasa de aciertos y reduce la carga del origen. Su empresa hermana ejecuta un juego multijugador sobre UDP en tres Regiones. Usa Global Accelerator para que los jugadores se conecten a dos direcciones IP fijas y sean enrutados a la Región sana más cercana; cuando una Región tiene una interrupción, el tráfico pasa a la siguiente en segundos, y los clientes corporativos que tienen las dos direcciones IP en su lista de permitidos no necesitan cambiar su firewall.

Errores comunes: elegir CloudFront para tráfico de juegos UDP o para un requisito de direcciones IP fijas (CloudFront usa IP de edge que cambian detrás de nombres DNS); elegir Global Accelerator para archivos estáticos que se pueden almacenar en caché (no tiene caché); depender de invalidaciones en cada despliegue en lugar de nombres de archivo con versión; y reenviar todos los encabezados y cookies al origen, lo que destruye la tasa de aciertos de caché. Otra trampa es confundir Global Accelerator con el enrutamiento por latencia de Route 53: Route 53 responde consultas DNS y depende de que los clientes respeten los TTL, mientras que Global Accelerator mantiene las mismas IP y mueve el tráfico detrás de ellas.

La redacción del examen suele ser decisiva. 'Caché', 'contenido estático', 'imágenes y video', 'reducir la carga en el origen' o 'TTL' apuntan a CloudFront. 'Direcciones IP estáticas', 'lista de permitidos', 'UDP', 'protocolos no HTTP como MQTT o VoIP', 'conmutación por error multi-Región rápida y determinista' o 'sin retrasos por caché de DNS' apuntan a Global Accelerator. 'Los usuarios reciben contenido viejo después de un despliegue' apunta a una invalidación o, mejor, a nombres de objeto con versión. 'Contenido privado de S3 solo a través de la CDN' apunta a CloudFront con origin access control, más signed URLs o cookies cuando el acceso es por usuario.

Términos clave

Edge location
Un sitio de AWS cercano a los usuarios donde CloudFront almacena contenido en caché y Global Accelerator recibe tráfico.
Clave de caché (cache key)
La combinación de URL y de los encabezados, cookies y query strings seleccionados que identifica un objeto único en caché.
TTL
Tiempo de vida: cuánto tiempo mantiene CloudFront un objeto en caché antes de volver a consultar el origen.
Invalidación (invalidation)
Una solicitud a CloudFront para eliminar objetos de las cachés del edge antes de que expire su TTL.
Origin access control (OAC)
Una funcionalidad de CloudFront que permite a una distribución leer un bucket de S3 privado para que los usuarios no puedan acceder directamente al bucket.
AWS Global Accelerator
Un servicio que proporciona dos direcciones IP anycast estáticas que enrutan tráfico TCP y UDP por la red troncal de AWS hacia endpoints sanos.
IP anycast
Una dirección IP anunciada desde muchas ubicaciones a la vez, de modo que cada cliente llega a la más cercana.
Ejemplo real

Las imágenes y los artículos de un sitio de noticias se almacenan en caché con CloudFront, con un TTL de un día para las imágenes y un TTL corto para la página principal, lo que reduce drásticamente la carga del origen. Su empresa hermana ejecuta un juego multijugador sobre UDP en tres Regiones y usa Global Accelerator, así que los jugadores se conectan a dos direcciones IP fijas y se enrutan a la Región sana más cercana, con conmutación por error en segundos y sin cambios de DNS.

Consejo para el examen: Caché y contenido HTTP significan CloudFront. Direcciones IP estáticas, UDP u otro tráfico no HTTP, o conmutación por error regional inmediata sin depender del DNS significan Global Accelerator.

Comprueba lo que sabes

Los clientes deben incluir exactamente dos direcciones IP en su lista de permitidos para una API servida desde dos Regiones. ¿Qué servicio usas?

AWS Global Accelerator, que proporciona dos direcciones IP anycast estáticas para endpoints en varias Regiones.

Desplegaste un archivo CSS nuevo con el mismo nombre, pero los usuarios siguen recibiendo el anterior. ¿Cuáles son dos soluciones?

Crear una invalidación de CloudFront para la ruta, o usar nombres de archivo con versión para que el archivo nuevo tenga una clave de caché nueva.

¿Por qué agregar todas las cookies a la clave de caché puede perjudicar el rendimiento?

Cada combinación única de cookies crea una copia separada en caché, lo que reduce la tasa de aciertos y envía más solicitudes al origen.

¿Global Accelerator almacena contenido en caché en el edge?

No. Enruta tráfico TCP y UDP por la red troncal de AWS hacia endpoints sanos; la caché es trabajo de CloudFront.
