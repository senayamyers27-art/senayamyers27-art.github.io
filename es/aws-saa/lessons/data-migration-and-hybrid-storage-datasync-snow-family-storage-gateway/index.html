Migración de datos y almacenamiento híbrido: DataSync, Snow Family, Storage Gateway, Transfer Family, DMS y SCT

Trasladar datos a AWS, o mantener los sistemas locales conectados al almacenamiento de AWS, forma parte de muchas arquitecturas. La herramienta correcta depende de cuatro preguntas: cuántos datos hay, qué tan rápida y fiable es la red, si la transferencia es única o continua, y si los datos son archivos, volúmenes en bloque, cintas o bases de datos. El examen te da estos datos en el escenario y espera que elijas el servicio correspondiente.

AWS DataSync mueve archivos en línea entre almacenamiento local (Network File System (NFS), Server Message Block (SMB), Hadoop Distributed File System (HDFS) o almacenamiento de objetos autoadministrado), otras nubes y servicios de almacenamiento de AWS como Amazon S3, Amazon EFS y los sistemas de archivos FSx. Despliegas un agente de DataSync cerca del origen, creas las ubicaciones de origen y destino, y defines una tarea. El servicio se encarga de la transferencia en paralelo, el cifrado en tránsito, la verificación de integridad, la programación, los límites de ancho de banda y las copias incrementales solo de los archivos modificados. Es la respuesta para migraciones de archivos únicas o recurrentes por la red, incluso a través de AWS Direct Connect.

Cuando la red es demasiado lenta, envía los datos físicamente. La AWS Snow Family proporciona dispositivos robustos que AWS te envía: copias los datos localmente, devuelves el dispositivo y AWS los importa a S3. Los dispositivos Snowball Edge almacenan decenas de terabytes cada uno y añaden cómputo local para procesamiento en el edge en ubicaciones sin conexión. Una regla aproximada: si mover los datos con tu ancho de banda disponible tardaría más de una semana, considera Snow. Por ejemplo, 100 TB por un enlace de 100 Mbps completamente usado tardan aproximadamente tres meses. AWS ha cambiado la línea de dispositivos Snow con el tiempo, así que para proyectos nuevos verifica qué dispositivos se ofrecen actualmente; lo que evalúa el examen es el concepto de transferencia física sin conexión.

AWS Storage Gateway conecta las aplicaciones locales con el almacenamiento de AWS para un uso híbrido continuo, y se ejecuta como máquina virtual o dispositivo de hardware con una caché local para baja latencia. S3 File Gateway presenta recursos compartidos NFS o SMB cuyos archivos se almacenan como objetos en S3. FSx File Gateway, que aparece en el material del examen aunque AWS lo cerró a clientes nuevos, da a los usuarios Windows locales acceso con caché a los recursos compartidos de FSx for Windows File Server. Volume Gateway presenta volúmenes en bloque iSCSI respaldados por S3 con snapshots de EBS, en modo cached (datos principales en AWS, datos de uso frecuente en caché local) o en modo stored (datos principales en local, respaldados de forma asíncrona en AWS). Tape Gateway presenta una biblioteca de cintas virtual para que el software de respaldo existente pueda escribir en S3 y en las clases de almacenamiento S3 Glacier en lugar de cintas físicas.

AWS Transfer Family proporciona endpoints administrados SFTP, FTPS, FTP y AS2 que almacenan los archivos en S3 o EFS, para que los socios sigan usando sus herramientas y scripts de transferencia de archivos existentes. AWS Database Migration Service (DMS) migra bases de datos a AWS con un tiempo de inactividad mínimo: una instancia de replicación realiza una carga completa y luego captura de datos de cambios (CDC) para mantener el destino sincronizado hasta el corte final. Las migraciones homogéneas, como de Oracle a Oracle, solo necesitan DMS o herramientas nativas. Las migraciones heterogéneas, como de Oracle a Aurora PostgreSQL, primero necesitan convertir el esquema: la AWS Schema Conversion Tool (SCT), o la más reciente DMS Schema Conversion, convierte el esquema, los procedimientos almacenados y otros objetos de código, y luego DMS mueve los datos.

Veamos un ejemplo práctico. Un hospital debe trasladar un archivo de imágenes de 600 TB pero solo tiene un enlace a internet de 200 Mbps, así que pide dispositivos Snowball Edge para la copia masiva y luego usa DataSync por la red para copiar los archivos modificados desde que se cargaron los dispositivos. Su base de datos Oracle pasa a Aurora PostgreSQL usando SCT para el esquema y DMS con CDC para los datos, de modo que la aplicación solo está fuera de servicio durante el corte final. Un laboratorio socio que envía resultados por SFTP se conecta a un endpoint de Transfer Family en lugar de a un servidor FTP obsoleto, y el equipo de respaldos apunta su software de respaldo existente a un Tape Gateway para retirar su biblioteca de cintas.

Errores comunes: elegir Snow para una cantidad modesta de datos en una red rápida (DataSync es más sencillo); elegir DataSync para acceso local continuo de baja latencia (eso es Storage Gateway); usar solo DMS para una migración heterogénea sin convertir el esquema; confundir el modo cached de Volume Gateway (datos principales en AWS) con el modo stored (datos principales en las instalaciones locales); y construir un servidor SFTP personalizado en EC2 cuando Transfer Family es administrado. Otra trampa es olvidar que DMS mantiene el origen en línea durante la migración, por eso es la respuesta de tiempo de inactividad mínimo.

La redacción del examen suele seguir un patrón. 'Migrar o sincronizar archivos en línea', 'programar', 'de NFS o SMB a S3 o EFS' apuntan a DataSync. 'Petabytes', 'ancho de banda limitado', 'semanas para transferir' o 'sin conectividad' apuntan a la Snow Family. 'Las aplicaciones locales necesitan acceso continuo al almacenamiento en la nube con caché local' apunta a Storage Gateway, eligiendo file, volume o tape según la interfaz. 'Los socios usan SFTP' apunta a Transfer Family. 'Migrar una base de datos con tiempo de inactividad mínimo' apunta a DMS, más SCT o DMS Schema Conversion cuando los motores son distintos.

Términos clave

AWS DataSync
Un servicio de transferencia de datos en línea para mover archivos entre almacenamiento local, otras nubes y el almacenamiento de AWS.
Snow Family
Dispositivos físicos de AWS que se usan para mover grandes cantidades de datos sin conexión y para ejecutar cómputo en el edge.
Storage Gateway
Un servicio híbrido que da a las aplicaciones locales interfaces de archivos, volúmenes o cintas respaldadas por almacenamiento de AWS con caché local.
Tape Gateway
Un tipo de Storage Gateway que presenta una biblioteca de cintas virtual al software de respaldo existente y almacena las cintas en S3 y en las clases Glacier.
AWS Transfer Family
Endpoints administrados SFTP, FTPS, FTP y AS2 que almacenan los archivos en S3 o EFS.
Captura de datos de cambios (CDC)
Replicar continuamente los cambios en curso de la base de datos de origen al destino después de la carga inicial.
AWS SCT
La Schema Conversion Tool, que convierte esquemas y código de bases de datos entre motores distintos.
Ejemplo real

Un hospital traslada un archivo de imágenes de 600 TB con solo un enlace a internet de 200 Mbps, así que pide dispositivos Snowball Edge para la copia masiva y luego usa DataSync para los cambios hechos desde entonces. Su base de datos Oracle pasa a Aurora PostgreSQL usando SCT para el esquema y DMS con CDC para los datos, y un socio que envía archivos por SFTP se conecta a Transfer Family en lugar de a un servidor FTP antiguo.

Consejo para el examen: Migración de archivos en línea: DataSync. Datos enormes y ancho de banda limitado: Snow Family. Acceso local continuo al almacenamiento en la nube: Storage Gateway (file, volume o tape). SFTP para socios: Transfer Family. Traslado de bases de datos con tiempo de inactividad mínimo: DMS, más SCT cuando los motores son distintos.

Comprueba lo que sabes

¿Qué tipo de Storage Gateway permite que una aplicación de respaldo existente escriba en cintas virtuales almacenadas en AWS?

Tape Gateway, que presenta una biblioteca de cintas virtual respaldada por S3 y las clases de almacenamiento Glacier.

Para migrar SQL Server a Aurora MySQL, ¿qué herramientas se necesitan?

Una herramienta de conversión de esquemas (AWS SCT o DMS Schema Conversion) para el esquema y el código, y luego AWS DMS para los datos, opcionalmente con CDC.

Una empresa tiene 2 PB que mover y un enlace de 100 Mbps que ya está ocupado. ¿Qué debe usar?

La Snow Family, porque transferir 2 PB por ese enlace tardaría demasiado; en su lugar, envía los datos en dispositivos.

Los servidores locales deben seguir usando recursos compartidos NFS, pero los archivos deben almacenarse como objetos en S3. ¿Qué servicio usas?

S3 File Gateway de Storage Gateway, que presenta recursos compartidos NFS o SMB respaldados por S3 con una caché local.
