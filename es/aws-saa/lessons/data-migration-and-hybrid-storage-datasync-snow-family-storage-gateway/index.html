Migración de datos y almacenamiento híbrido: DataSync, Snow Family, Storage Gateway, Transfer Family, DMS y SCT

Mover datos a AWS, o mantener los sistemas on-premises conectados al almacenamiento de AWS, es una gran parte de muchas arquitecturas. La herramienta correcta depende de cuántos datos hay, qué tan rápida es la red, si la transferencia es única o continua, y si los datos son archivos, bloques o bases de datos.

AWS DataSync mueve archivos en línea entre el almacenamiento on-premises (NFS, SMB, HDFS o almacenamiento de objetos), otras nubes y los servicios de almacenamiento de AWS como S3, EFS y los sistemas de archivos FSx. Despliegas un DataSync agent cerca del origen, y el servicio se encarga de la transferencia en paralelo, el cifrado, las verificaciones de integridad, la programación y las copias incrementales. Es la respuesta para migraciones de archivos únicas o recurrentes por la red, incluso a través de Direct Connect.

Cuando la red es demasiado lenta, envía los datos físicamente. La AWS Snow Family proporciona dispositivos resistentes que AWS te envía por correo: cargas los datos localmente y devuelves el dispositivo, y AWS los importa a S3. Los dispositivos Snowball Edge ofrecen decenas de terabytes cada uno más cómputo local para procesamiento en el borde. Una regla aproximada: si mover los datos con tu ancho de banda disponible tardaría más de una semana, considera Snow. AWS ha cambiado la línea de dispositivos Snow con el tiempo, así que para proyectos nuevos verifica qué dispositivos se ofrecen actualmente; el concepto de transferencia física y fuera de línea es lo que evalúa el examen.

AWS Storage Gateway conecta las aplicaciones on-premises con el almacenamiento de AWS para un uso híbrido continuo, con una caché local para baja latencia. S3 File Gateway presenta recursos compartidos NFS o SMB cuyos archivos se almacenan como objetos en S3. FSx File Gateway da a los usuarios de Windows on-premises acceso en caché y de baja latencia a los recursos compartidos de FSx for Windows File Server. Volume Gateway presenta volúmenes de bloque iSCSI respaldados por S3 con snapshots de EBS, en modo cached (datos principales en AWS) o stored (datos principales locales, respaldados en AWS). Tape Gateway presenta una biblioteca de cintas virtual para que el software de respaldo existente pueda escribir en S3 y Glacier en lugar de cintas físicas.

AWS Transfer Family proporciona endpoints administrados de SFTP, FTPS, FTP y AS2 que almacenan los archivos en S3 o EFS, para que los socios puedan seguir usando sus herramientas de transferencia de archivos existentes. AWS Database Migration Service (DMS) migra bases de datos a AWS con un tiempo de inactividad mínimo, haciendo una carga completa y luego change data capture (CDC, captura de datos de cambios) para mantener sincronizado el destino hasta el cambio definitivo (cutover). Las migraciones homogéneas, como Oracle a Oracle, solo necesitan DMS. Las migraciones heterogéneas, como Oracle a Aurora PostgreSQL, primero necesitan conversión de esquema: la AWS Schema Conversion Tool (SCT), o la más reciente DMS Schema Conversion, convierte el esquema y los objetos de código, y luego DMS mueve los datos.

Términos clave

AWS DataSync
Un servicio de transferencia de datos en línea para mover archivos entre el almacenamiento on-premises, otras nubes y el almacenamiento de AWS.
Storage Gateway
Un servicio híbrido que da a las aplicaciones on-premises interfaces de archivo, volumen o cinta respaldadas por almacenamiento de AWS.
Change data capture (CDC, captura de datos de cambios)
Replicar continuamente los cambios en curso de la base de datos de origen al destino después de la carga inicial.
AWS SCT
La Schema Conversion Tool, que convierte esquemas y código de bases de datos entre motores diferentes.
Ejemplo real

Un hospital traslada un archivo de imágenes de 600 TB con solo un enlace a internet de 200 Mbps, así que pide dispositivos Snowball Edge para la copia masiva y luego usa DataSync para los cambios hechos desde entonces. Su base de datos Oracle pasa a Aurora PostgreSQL usando SCT para el esquema y DMS con CDC para los datos, y un socio que envía archivos por SFTP se conecta a Transfer Family en lugar de a un viejo servidor FTP.

Consejo para el examen: Migración de archivos en línea: DataSync. Enormes cantidades de datos y ancho de banda limitado: Snow Family. Acceso continuo on-premises al almacenamiento en la nube: Storage Gateway (file, volume o tape). SFTP para socios: Transfer Family. Traslado de bases de datos con tiempo de inactividad mínimo: DMS, más SCT cuando los motores difieren.

Comprueba lo que sabes

¿Qué tipo de Storage Gateway permite que una aplicación de respaldo existente escriba en cintas virtuales almacenadas en AWS?

Tape Gateway, que presenta una biblioteca de cintas virtual respaldada por las clases de almacenamiento de S3 y Glacier.

Migrar de SQL Server a Aurora MySQL: ¿qué herramientas se necesitan?

Una herramienta de conversión de esquema (AWS SCT o DMS Schema Conversion) para el esquema y el código, y luego AWS DMS para los datos, opcionalmente con CDC.
