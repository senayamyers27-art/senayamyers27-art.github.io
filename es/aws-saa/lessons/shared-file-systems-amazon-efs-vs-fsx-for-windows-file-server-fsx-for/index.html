Sistemas de archivos compartidos: Amazon EFS vs FSx for Windows File Server, FSx for Lustre y FSx for NetApp ONTAP

Los volúmenes EBS generalmente se adjuntan a una sola instancia, y S3 es almacenamiento de objetos al que se accede por HTTP. Cuando muchos servidores necesitan leer y escribir los mismos archivos mediante una interfaz de sistema de archivos normal, necesitas un sistema de archivos compartido. AWS ofrece Amazon EFS y la familia Amazon FSx, y el examen decide entre ellos por protocolo, sistema operativo y perfil de rendimiento.

Amazon Elastic File System (EFS) es un Network File System (NFS) totalmente administrado para cargas de trabajo Linux. Miles de instancias EC2, contenedores y funciones Lambda pueden montarlo a la vez, en varias AZs, mediante mount targets en cada AZ. Crece y se reduce automáticamente sin capacidad que aprovisionar, y pagas por el almacenamiento usado. Los sistemas de archivos Regional guardan los datos de forma redundante en varias AZs; los sistemas de archivos One Zone cuestan menos para datos que no lo necesitan. Las clases de almacenamiento y la gestión del ciclo de vida mueven los archivos poco usados a las clases Infrequent Access y Archive. Los modos de rendimiento incluyen elastic, que escala automáticamente con la demanda. EFS no es compatible con Windows.

Amazon FSx for Windows File Server proporciona recursos compartidos de archivos de Windows totalmente administrados mediante el protocolo Server Message Block (SMB), integrado con Microsoft Active Directory para los permisos mediante listas de control de acceso NTFS. Admite funciones de Windows como los espacios de nombres DFS, shadow copies y la deduplicación de datos, y despliegues Multi-AZ para alta disponibilidad. Elígelo para aplicaciones Windows, directorios personales y cargas de SharePoint o SQL Server que esperan SMB.

Amazon FSx for Lustre es un sistema de archivos paralelo de alto rendimiento para HPC, entrenamiento de machine learning, renderizado de medios y modelado financiero, con un rendimiento de cientos de gigabytes por segundo y latencias inferiores a un milisegundo. Puede vincularse a un bucket de S3, presentando los objetos como archivos y escribiendo los resultados de vuelta. Los sistemas de archivos scratch son para procesamiento temporal y de corto plazo sin replicación de datos; los sistemas de archivos persistent replican dentro de una AZ para trabajos de mayor duración.

Amazon FSx for NetApp ONTAP ejecuta el sistema de archivos ONTAP de NetApp como servicio administrado. Admite NFS, SMB e iSCSI al mismo tiempo, de modo que clientes Linux, Windows y macOS pueden compartir datos, y ofrece funciones de ONTAP como snapshots, replicación SnapMirror, clonación, compresión y deduplicación. Es la respuesta natural cuando una empresa ya usa NetApp on-premises o necesita acceso multiprotocolo. Una cuarta opción, FSx for OpenZFS, se adapta a cargas que migran desde ZFS u otros servidores de archivos Linux.

Términos clave

Amazon EFS
Un sistema de archivos NFS administrado y elástico para Linux que muchas instancias en varias AZs pueden montar simultáneamente.
FSx for Windows File Server
Un servidor de archivos Windows administrado que usa SMB con integración con Active Directory.
FSx for Lustre
Un sistema de archivos paralelo de alto rendimiento administrado para HPC y ML, con integración opcional con S3.
FSx for NetApp ONTAP
Un sistema de archivos NetApp ONTAP administrado que admite NFS, SMB e iSCSI con las funciones de datos de ONTAP.
Ejemplo real

Una empresa de medios renderiza fotogramas de video en 500 instancias Linux. Los recursos de origen están en S3; un sistema de archivos FSx for Lustre vinculado al bucket da a los nodos de renderizado un acceso rápido a los archivos y escribe los fotogramas terminados de vuelta en S3. Sus editores con estaciones de trabajo Windows usan recursos compartidos de FSx for Windows File Server unidos al Active Directory corporativo, y sus servidores web comparten las imágenes subidas en EFS.

Consejo para el examen: Archivos compartidos en Linux: EFS. Windows o SMB con Active Directory: FSx for Windows File Server. Rendimiento para HPC o ML, sobre todo con datos en S3: FSx for Lustre. Funciones de NetApp o NFS más SMB más iSCSI juntos: FSx for NetApp ONTAP.

Comprueba lo que sabes

Una aplicación .NET de Windows necesita una unidad compartida con permisos NTFS de Active Directory. ¿Qué servicio?

Amazon FSx for Windows File Server, que usa SMB y se integra con Active Directory.

¿Qué sistema de archivos puede presentar los objetos de un bucket de S3 como archivos para un trabajo de entrenamiento de machine learning?

Amazon FSx for Lustre, vinculado al bucket de S3 como repositorio de datos.
