Sistemas de archivos compartidos: Amazon EFS vs FSx for Windows File Server, FSx for Lustre y FSx for NetApp ONTAP

Los volúmenes de Amazon Elastic Block Store (EBS) generalmente se adjuntan a una sola instancia, y Amazon S3 es almacenamiento de objetos al que se accede mediante API HTTP y no como una unidad montada. Cuando muchos servidores necesitan leer y escribir los mismos archivos a través de una interfaz de sistema de archivos normal, con directorios, bloqueo de archivos y permisos, necesitas un sistema de archivos compartido. AWS ofrece Amazon Elastic File System (EFS) y la familia Amazon FSx, y el examen decide entre ellos según el protocolo, el sistema operativo y el perfil de rendimiento. Acertar desde el principio ahorra migraciones dolorosas más adelante, porque las aplicaciones se escriben esperando un protocolo concreto.

Amazon EFS es un Network File System (NFS) totalmente administrado para cargas de trabajo Linux. Miles de instancias EC2, contenedores y funciones Lambda pueden montarlo al mismo tiempo, en varias zonas de disponibilidad (AZ), a través de un mount target en cada AZ. Crece y se reduce automáticamente sin capacidad que aprovisionar, y pagas por el almacenamiento que usas. Los sistemas de archivos Regional almacenan los datos de forma redundante en varias AZ; los sistemas de archivos One Zone cuestan menos para datos que no necesitan esa resiliencia. La administración del ciclo de vida mueve los archivos poco usados a las clases de almacenamiento Infrequent Access y Archive. Los modos de rendimiento incluyen elastic, que escala automáticamente con la demanda y es el predeterminado habitual, y provisioned, para un nivel de rendimiento fijo. En una instancia lo montas con el asistente de montaje de EFS, por ejemplo sudo mount -t efs -o tls fs-0123abcd:/ /mnt/shared. EFS no admite clientes Windows.

Amazon FSx for Windows File Server proporciona recursos compartidos de Windows totalmente administrados mediante el protocolo Server Message Block (SMB), integrados con Microsoft Active Directory para que los permisos usen listas de control de acceso (ACL) de NTFS. Admite funcionalidades de Windows como los espacios de nombres de Distributed File System (DFS), las shadow copies que permiten a los usuarios restaurar versiones anteriores y la deduplicación de datos, y ofrece implementaciones Multi-AZ para alta disponibilidad. Elígelo para aplicaciones Windows, directorios personales de usuarios y cargas de SharePoint o SQL Server que esperan recursos compartidos SMB.

Amazon FSx for Lustre es un sistema de archivos paralelo de alto rendimiento para HPC, entrenamiento de machine learning, renderizado de medios y modelado financiero, que entrega un rendimiento agregado muy alto con latencias inferiores a un milisegundo. Puede vincularse a un bucket de S3 como repositorio de datos, presentando los objetos como archivos, cargándolos de forma diferida en el primer acceso y exportando los resultados de vuelta a S3. Las implementaciones scratch son para procesamiento temporal de corto plazo sin replicación de datos, así que un servidor que falla pierde sus datos; las implementaciones persistent replican dentro de una AZ para trabajos de mayor duración. Amazon FSx for NetApp ONTAP ejecuta el sistema de archivos ONTAP de NetApp como servicio administrado. Sirve NFS, SMB e iSCSI (almacenamiento en bloque sobre IP) al mismo tiempo, de modo que clientes Linux, Windows y macOS pueden compartir datos, y ofrece funcionalidades de ONTAP como snapshots, replicación SnapMirror, clonación, compresión y deduplicación. Una cuarta opción, FSx for OpenZFS, conviene a cargas que se trasladan desde ZFS u otros servidores de archivos NFS de Linux y que necesitan latencia muy baja.

Veamos un ejemplo práctico. Una empresa de medios renderiza fotogramas de video en 500 instancias Linux. Los recursos originales viven en S3, así que el equipo crea un sistema de archivos FSx for Lustre vinculado al bucket; los nodos de renderizado leen los recursos como archivos normales con alto rendimiento, y los fotogramas terminados se exportan de vuelta a S3 para almacenamiento a largo plazo. Los editores en estaciones de trabajo Windows usan recursos compartidos de FSx for Windows File Server unidos al Active Directory corporativo, así que sus permisos de grupo existentes siguen funcionando. Los servidores web de gestión de contenido de la empresa, que ejecutan Linux en tres AZ, comparten las imágenes subidas en un sistema de archivos EFS Regional. Una subsidiaria que ya ejecuta arreglos NetApp en sus instalaciones replica a FSx for NetApp ONTAP con SnapMirror para recuperación ante desastres.

Errores comunes: elegir EFS para servidores Windows (es NFS para Linux); elegir FSx for Windows File Server para HPC en Linux (es SMB y no está hecho para rendimiento paralelo); usar un sistema de archivos scratch de FSx for Lustre para datos que deben sobrevivir a una falla; y olvidar que EFS necesita un mount target en cada AZ donde se ejecutan clientes, con grupos de seguridad que permitan tráfico NFS en el puerto 2049. Otra trampa es elegir S3 cuando la aplicación necesita semántica de archivos POSIX, como el bloqueo de archivos o las ediciones in situ; S3 son objetos, no un sistema de archivos.

Las preguntas del examen suelen darte la pista en el protocolo o el sistema operativo. 'Linux', 'NFS', 'POSIX', 'compartido entre AZ' o 'elástico, pagas por lo que usas' apuntan a EFS. 'Windows', 'SMB', 'Active Directory', 'permisos NTFS' o 'DFS' apuntan a FSx for Windows File Server. 'HPC', 'entrenamiento de machine learning', 'paralelo', 'cientos de GB/s' o 'procesar datos de S3 como archivos' apuntan a FSx for Lustre. 'NetApp', 'multiprotocolo', 'NFS, SMB e iSCSI a la vez' o 'SnapMirror' apuntan a FSx for NetApp ONTAP. 'Migrar ZFS' apunta a FSx for OpenZFS.

Términos clave

Amazon EFS
Un sistema de archivos NFS administrado y elástico para Linux que muchas instancias en varias AZ pueden montar simultáneamente.
Mount target
Un endpoint de red de EFS en una subred de cada AZ a través del cual los clientes montan el sistema de archivos.
FSx for Windows File Server
Un servidor de archivos Windows administrado que usa SMB con integración con Active Directory y permisos NTFS.
FSx for Lustre
Un sistema de archivos paralelo de alto rendimiento administrado para HPC y ML, con integración opcional con S3 como repositorio de datos.
FSx for NetApp ONTAP
Un sistema de archivos NetApp ONTAP administrado que admite NFS, SMB e iSCSI con las funcionalidades de gestión de datos de ONTAP.
Server Message Block (SMB)
El protocolo para compartir archivos que usan los clientes y servidores Windows.
Scratch vs persistent (Lustre)
Los sistemas de archivos scratch no replican datos y sirven para trabajos temporales; los persistent replican dentro de una AZ.
Ejemplo real

Una empresa de medios renderiza fotogramas de video en 500 instancias Linux. Los recursos originales viven en S3; un sistema de archivos FSx for Lustre vinculado al bucket da a los nodos de renderizado acceso rápido a los archivos y escribe los fotogramas terminados de vuelta en S3. Sus editores en estaciones de trabajo Windows usan recursos compartidos de FSx for Windows File Server unidos al Active Directory corporativo, y sus servidores web en tres AZ comparten las imágenes subidas en EFS.

Consejo para el examen: Archivos compartidos en Linux: EFS. Windows o SMB con Active Directory: FSx for Windows File Server. Rendimiento para HPC o ML, sobre todo con datos en S3: FSx for Lustre. Funcionalidades de NetApp o NFS, SMB e iSCSI a la vez: FSx for NetApp ONTAP.

Comprueba lo que sabes

Una aplicación .NET en Windows necesita una unidad compartida con permisos NTFS de Active Directory. ¿Qué servicio usas?

Amazon FSx for Windows File Server, que usa SMB y se integra con Active Directory.

¿Qué sistema de archivos puede presentar los objetos de un bucket de S3 como archivos para un trabajo de entrenamiento de machine learning?

Amazon FSx for Lustre, vinculado al bucket de S3 como repositorio de datos.

Una empresa necesita que clientes Linux y Windows accedan a los mismos datos por NFS y SMB, y quiere replicación SnapMirror. ¿Qué servicio usas?

Amazon FSx for NetApp ONTAP, que sirve varios protocolos y admite funcionalidades de ONTAP como SnapMirror.

Las instancias EC2 de una AZ nueva no pueden montar un sistema de archivos EFS existente. ¿Cuál es una causa probable?

No hay un mount target en esa AZ, o su grupo de seguridad no permite tráfico NFS en el puerto 2049.
