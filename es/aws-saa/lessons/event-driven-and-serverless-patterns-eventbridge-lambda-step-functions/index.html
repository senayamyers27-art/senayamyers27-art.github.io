Patrones orientados a eventos y serverless: EventBridge, Lambda, Step Functions y API Gateway

Los servicios serverless ejecutan tu código y enrutan tus eventos sin que tengas que administrar servidores. Escalan automáticamente, incluso hasta cero, y pagas por el uso en lugar de por capacidad ociosa. El diseño orientado a eventos significa que los componentes reaccionan a eventos, como un objeto subido o un pedido realizado, en lugar de llamarse directamente entre sí, lo que los mantiene débilmente acoplados. En el examen, serverless suele ser la respuesta cuando una pregunta destaca la menor carga operativa, un tráfico impredecible o con picos, o no pagar nada cuando no hay uso. AWS Lambda ejecuta funciones en respuesta a eventos: una solicitud de API, un objeto nuevo en S3, un mensaje en SQS, un registro en un stream de DynamoDB o de Kinesis, o una programación. Eliges el tamaño de la memoria, que también determina la porción de CPU, y un tiempo de espera de hasta 15 minutos. Cada función tiene un rol de ejecución que le otorga sus permisos de AWS. Lambda escala ejecutando más copias concurrentes; la concurrencia reservada (reserved concurrency) garantiza y limita la capacidad de una función, lo que además protege a una base de datos posterior de saturarse, y la concurrencia aprovisionada (provisioned concurrency) mantiene instancias inicializadas para evitar la latencia de arranque en frío (cold start). Las invocaciones asíncronas pueden enviar las fallas a un destino o a una DLQ. Lambda puede ejecutarse en una VPC para llegar a recursos privados como RDS, a menudo a través de RDS Proxy para agrupar conexiones. Todo lo que dure más de 15 minutos o necesite un proceso persistente corresponde a contenedores, AWS Batch o EC2.

Amazon API Gateway coloca una puerta de entrada HTTPS delante de tus back ends, casi siempre Lambda. Las REST APIs ofrecen las funciones más completas, como API keys y planes de uso (usage plans), validación de solicitudes, caché de respuestas e integración con AWS WAF. Las HTTP APIs son más simples y de menor costo, con autorizadores JWT integrados. Las WebSocket APIs admiten conexiones bidireccionales de larga duración, como un chat. API Gateway gestiona la autorización con IAM, Cognito user pools o autorizadores Lambda, y los límites de throttling protegen tu back end de las ráfagas. Los endpoints optimizados para el borde (edge-optimized) usan CloudFront; también hay endpoints regionales y privados.

Amazon EventBridge es un bus de eventos serverless. Los servicios de AWS, tus aplicaciones y los socios de software como servicio (SaaS) envían eventos a un bus; las reglas coinciden con los eventos por patrón y los enrutan a destinos como Lambda, SQS, SNS, Step Functions, API destinations o el bus de otra cuenta. EventBridge Scheduler y las reglas programadas reemplazan a los servidores cron, y el archivo y la reproducción (archive and replay) ayudan a recuperarse de bugs. En comparación con SNS, EventBridge ofrece filtrado basado en el contenido de cualquier campo del evento, muchos más tipos de destinos y fuentes de eventos de terceros; SNS ofrece mayor rendimiento de fan-out y entrega por correo electrónico, SMS y notificaciones push móviles.

AWS Step Functions coordina flujos de trabajo de varios pasos como máquinas de estados definidas en Amazon States Language. Cada estado puede invocar a Lambda o llamar directamente a muchos servicios de AWS, con reintentos integrados, captura de errores, ramas paralelas, decisiones, iteraciones (map) sobre listas y esperas. Los flujos Standard pueden ejecutarse hasta un año, registran el historial completo y se adaptan a procesos de negocio de larga duración, incluida la espera de una aprobación humana con un task token; los flujos Express se adaptan al procesamiento de eventos breve y de alto volumen.

Veamos un ejemplo práctico. Una aplicación de reclamaciones de seguros acepta archivos a través de API Gateway y Lambda. Luego un flujo Standard de Step Functions extrae los datos, busca fraude en paralelo con una consulta de la póliza, espera la aprobación de un ajustador y realiza el pago, reintentando con espera progresiva (backoff) los pasos que fallan. Una regla de EventBridge notifica al equipo de auditoría cada vez que se aprueba una reclamación por encima de un umbral, sin que el código de pagos sepa siquiera que existe el equipo de auditoría.

Errores comunes: elegir Lambda para trabajos de más de 15 minutos; encadenar funciones Lambda que se llaman entre sí de forma síncrona, lo que multiplica el costo y dificulta el manejo de errores, en lugar de usar Step Functions; ejecutar una instancia EC2 con cron solo para disparar tareas programadas; dejar que una función Lambda escale sin límite contra una base de datos pequeña; y olvidar que API Gateway tiene su propio tiempo de espera de integración, por lo que el trabajo lento debe delegarse de forma asíncrona a una cola o a un flujo de trabajo.

Las pistas del examen se corresponden con claridad. 'Menor carga operativa', 'escalar a cero' o 'tráfico con picos' apunta a Lambda y otros servicios serverless. 'Orquestar varios pasos con reintentos', 'aprobación humana' o 'flujo de trabajo de larga duración' apunta a Step Functions. 'Reaccionar a eventos de servicios de AWS o aplicaciones SaaS', 'filtrar por el contenido del evento' o 'reemplazar un servidor cron' apunta a EventBridge. 'Exponer un endpoint REST con throttling, API keys o caché' apunta a API Gateway, y 'más de 15 minutos' descarta Lambda.

Términos clave

AWS Lambda
Un servicio de cómputo serverless que ejecuta funciones en respuesta a eventos, durante un máximo de 15 minutos por invocación.
Concurrencia reservada (reserved concurrency)
Una configuración de Lambda que garantiza y limita la cantidad de ejecuciones concurrentes de una función.
Concurrencia aprovisionada (provisioned concurrency)
Entornos de ejecución de Lambda preinicializados que eliminan la latencia de arranque en frío.
Amazon API Gateway
Un servicio administrado para crear, proteger y limitar (throttling) APIs REST, HTTP y WebSocket.
Amazon EventBridge
Un bus de eventos serverless que enruta eventos a destinos según reglas de coincidencia de patrones.
AWS Step Functions
Un servicio que orquesta flujos de trabajo como máquinas de estados con reintentos, ramas y manejo de errores.
Ejemplo real

Una startup ejecutaba una pequeña instancia EC2 cuyo único trabajo era cron: cada noche redimensionaba las imágenes subidas y enviaba un informe por correo electrónico. El equipo la reemplaza por una notificación de eventos de S3 que dispara una función Lambda en cada subida, y por una programación de EventBridge Scheduler que inicia cada noche un flujo de Step Functions para generar y enviar el informe. La instancia se elimina, los costos bajan casi a cero en los días tranquilos y los pasos fallidos se reintentan automáticamente.

Consejo para el examen: Presta atención a los límites de tiempo: un trabajo de más de 15 minutos descarta Lambda. Orquestar varios pasos con reintentos apunta a Step Functions; enrutar eventos de servicios de AWS o aplicaciones SaaS según su contenido apunta a EventBridge.

Comprueba lo que sabes

Un trabajo por lotes nocturno se ejecuta durante dos horas. ¿Lambda es una buena opción?

No. Las invocaciones de Lambda están limitadas a 15 minutos. Usa AWS Batch, ECS en Fargate o EC2.

¿Qué servicio ejecutaría una función Lambda cada vez que se detenga cualquier instancia EC2 de la cuenta?

Amazon EventBridge, con una regla que coincida con los eventos de cambio de estado de instancias EC2 para el estado stopped.

Una función Lambda satura una base de datos RDS durante las ráfagas. Menciona dos soluciones.

Configurar la concurrencia reservada para limitar las ejecuciones en paralelo, y usar RDS Proxy para agrupar conexiones (o acumular el trabajo en SQS).

¿Qué tipo de API Gateway admite conexiones persistentes bidireccionales para una aplicación de chat?

Una WebSocket API.
