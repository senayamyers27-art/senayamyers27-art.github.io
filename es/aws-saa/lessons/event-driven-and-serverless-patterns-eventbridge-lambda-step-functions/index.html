Patrones orientados a eventos y serverless: EventBridge, Lambda, Step Functions y API Gateway

Los servicios serverless (sin servidor) ejecutan tu código y enrutan tus eventos sin que administres servidores, y escalan automáticamente, incluso hasta cero. Pagas por el uso y no por capacidad ociosa. En el examen, serverless suele ser la respuesta cuando una pregunta enfatiza la menor sobrecarga operativa o un tráfico impredecible y con picos.

AWS Lambda ejecuta funciones en respuesta a eventos: una solicitud a una API, un objeto nuevo en S3, un mensaje en SQS, un registro en un DynamoDB stream o un horario programado. Eliges el tamaño de memoria, que también define la proporción de CPU, y un timeout de hasta 15 minutos. Cada función tiene un execution role que le otorga sus permisos de AWS. Lambda escala ejecutando más copias concurrentes; la reserved concurrency garantiza y limita la capacidad de una función, y la provisioned concurrency mantiene instancias inicializadas para evitar la latencia de cold start (arranque en frío). Cualquier cosa que dure más de 15 minutos, o que necesite un proceso persistente, corresponde a contenedores o a EC2. Lambda puede ejecutarse en una VPC para llegar a recursos privados como RDS.

Amazon API Gateway pone una puerta de entrada HTTPS delante de tus back ends, casi siempre Lambda. Las REST APIs ofrecen las funciones más completas, como API keys y usage plans, validación de solicitudes, caché e integración con WAF. Las HTTP APIs son más simples y de menor costo. Las WebSocket APIs admiten conexiones bidireccionales. API Gateway gestiona la autorización con IAM, Cognito user pools o Lambda authorizers, y el throttling (limitación) protege tu back end de ráfagas.

Amazon EventBridge es un bus de eventos serverless. Los servicios de AWS, tus aplicaciones y los socios SaaS envían eventos a un bus; las reglas hacen coincidir los eventos por patrón, como un cambio de estado de una instancia EC2 a stopped, y los enrutan a destinos como Lambda, SQS, SNS, Step Functions o el bus de otra cuenta. EventBridge Scheduler y las reglas programadas reemplazan a los servidores cron. Comparado con SNS, EventBridge ofrece filtrado basado en contenido sobre cualquier campo del evento, muchos más tipos de destino y fuentes de eventos de terceros; SNS ofrece mayor rendimiento de fan-out y entrega a correo electrónico, SMS y endpoints HTTP.

AWS Step Functions coordina flujos de trabajo de varios pasos como state machines (máquinas de estado) definidas en Amazon States Language. Cada estado puede invocar Lambda o llamar directamente a servicios de AWS, con reintentos integrados, captura de errores, ramas paralelas, decisiones y esperas. Los Standard workflows pueden ejecutarse hasta un año y se adaptan a procesos de negocio de larga duración, incluida la espera de una aprobación humana; los Express workflows se adaptan al procesamiento de eventos cortos y de alto volumen. Step Functions es la respuesta cuando una pregunta describe orquestar varias funciones Lambda con manejo de errores, en lugar de encadenar funciones que se llaman entre sí.

Términos clave

AWS Lambda
Un servicio de cómputo serverless que ejecuta funciones en respuesta a eventos, hasta 15 minutos por invocación.
Amazon API Gateway
Un servicio administrado para crear, proteger y limitar APIs REST, HTTP y WebSocket.
Amazon EventBridge
Un bus de eventos serverless que enruta eventos a destinos según reglas de coincidencia de patrones.
AWS Step Functions
Un servicio que orquesta flujos de trabajo como state machines con reintentos, ramas y manejo de errores.
Ejemplo real

Una app de reclamos de seguros acepta archivos subidos mediante API Gateway y Lambda. Luego un flujo de Step Functions extrae los datos, verifica si hay fraude, espera la aprobación de un ajustador y paga, reintentando automáticamente los pasos fallidos. Una regla de EventBridge notifica al equipo de auditoría cada vez que se aprueba un reclamo por encima de un umbral.

Consejo para el examen: Fíjate en los límites de tiempo: un trabajo de más de 15 minutos descarta Lambda. Orquestar varios pasos con reintentos apunta a Step Functions; enrutar eventos de servicios de AWS o apps SaaS según su contenido apunta a EventBridge.

Comprueba lo que sabes

Un trabajo por lotes nocturno dura dos horas. ¿Es Lambda una buena opción?

No. Las invocaciones de Lambda están limitadas a 15 minutos. Usa AWS Batch, ECS en Fargate o EC2.

¿Qué servicio ejecutaría una función Lambda cada vez que se detenga cualquier instancia EC2 de la cuenta?

Amazon EventBridge, con una regla que coincida con los eventos de cambio de estado de instancias EC2 para el estado stopped.
