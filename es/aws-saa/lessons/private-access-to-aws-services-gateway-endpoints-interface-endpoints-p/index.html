Acceso privado a servicios de AWS: gateway endpoints, interface endpoints (PrivateLink) y endpoint policies

La mayoría de los servicios de AWS, como S3, DynamoDB, SQS y Secrets Manager, se alcanzan mediante endpoints públicos del servicio. Una instancia privada puede llegar a ellos a través de un NAT gateway, pero entonces el tráfico sale del espacio de direcciones privadas de tu VPC y pagas cargos de procesamiento de datos del NAT. Los VPC endpoints permiten que los recursos de tu VPC lleguen a los servicios de AWS de forma privada, sin internet gateway, sin dispositivo NAT y sin direcciones IP públicas.

Los gateway endpoints existen exactamente para dos servicios: Amazon S3 y Amazon DynamoDB. Creas el endpoint y seleccionas route tables; AWS agrega una ruta cuyo destino es la prefix list (lista de prefijos, una lista administrada de los rangos de IP del servicio) y cuyo objetivo es el endpoint. Los gateway endpoints no tienen cargo por hora ni por datos. Solo funcionan para el tráfico desde dentro de la VPC; no se pueden alcanzar desde on-premises a través de VPN o Direct Connect, ni desde una VPC emparejada (peered).

Los interface endpoints funcionan con AWS PrivateLink. Cada uno coloca una elastic network interface con una dirección IP privada en las subredes que elijas, una por AZ para resiliencia, protegida por un security group. Con private DNS habilitado, el nombre de host normal del servicio se resuelve a esas IP privadas, así que las aplicaciones no necesitan cambios de código. Hay interface endpoints para la mayoría de los servicios de AWS, incluido S3, y también para tus propios servicios o los de socios publicados como endpoint services detrás de un Network Load Balancer. Se facturan por hora por AZ más por GB procesado. Como son direcciones IP reales, se pueden alcanzar desde redes on-premises a través de VPN o Direct Connect.

Las endpoint policies son políticas basadas en recursos sobre el propio endpoint que limitan lo que se puede hacer a través de él. Por ejemplo, una endpoint policy de un gateway endpoint de S3 puede permitir acceso solo a los buckets de la propia empresa, lo que ayuda a evitar que se copien datos a un bucket personal. El otro lado del control está en el recurso: una bucket policy puede usar la condición aws:SourceVpce para denegar cualquier solicitud que no haya llegado por un endpoint específico, o aws:SourceVpc para una VPC específica. Juntas forman un perímetro de datos (data perimeter).

PrivateLink también resuelve un problema de red: exponer un servicio a muchas VPC consumidoras, incluso en otras cuentas, sin emparejar redes completas y sin preocuparse por rangos CIDR superpuestos, porque los consumidores solo ven un interface endpoint en su propia VPC.

Términos clave

Gateway endpoint
Un destino de route table que da acceso privado y gratuito a S3 o DynamoDB desde dentro de una VPC.
Interface endpoint
Una interfaz de red de PrivateLink con IP privadas en tus subredes que actúa como frente de un servicio de AWS o de un socio.
Endpoint policy (política de endpoint)
Una política de recurso en un VPC endpoint que restringe qué acciones y recursos se pueden alcanzar a través de él.
aws:SourceVpce
Una clave de condición que coincide con el ID del VPC endpoint por el que llegó una solicitud.
Ejemplo real

Una flota de analítica en subredes privadas lee terabytes al día desde S3 a través de un NAT gateway, y los cargos de procesamiento del NAT son altos. El arquitecto agrega un gateway endpoint de S3 a las route tables privadas. Ahora el tráfico se queda en la red de AWS, desaparecen los cargos de NAT por ese tráfico y una bucket policy deniega las solicitudes que no llegan por el endpoint.

Consejo para el examen: S3 o DynamoDB, desde dentro de la VPC, al menor costo: gateway endpoint. Cualquier otro servicio, o acceso desde on-premises, o compartir un servicio con otras VPC: interface endpoint (PrivateLink).

Comprueba lo que sabes

Unos servidores on-premises conectados por Direct Connect necesitan acceso privado a S3. ¿Pueden usar un gateway endpoint?

No. Los gateway endpoints solo atienden tráfico que se origina en la VPC. Usa un interface endpoint de S3, que tiene IP privadas alcanzables por Direct Connect.

¿Cómo aseguras que un bucket sea accesible solo a través de un VPC endpoint específico?

Agrega una bucket policy que deniegue las solicitudes cuando aws:SourceVpce no sea igual al ID de ese endpoint.
