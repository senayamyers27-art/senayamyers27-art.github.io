AWS Certified Solutions Architect – Associate SAA-C03

Servicios de analítica: Athena, AWS Glue, Lake Formation, EMR, Redshift Spectrum y QuickSight

Un data lake almacena datos en bruto y procesados de cualquier forma, normalmente en Amazon S3, y permite que muchas herramientas los analicen sin copiarlos primero a un sistema separado. Como S3 es barato, duradero y prácticamente ilimitado, puedes conservar años de historial y decidir más adelante cómo usarlo. AWS tiene un conjunto de servicios que catalogan, protegen, procesan, consultan y visualizan esos datos, y el examen espera que conozcas la función de cada uno y cuál responde a un requisito dado.

AWS Glue es un servicio de integración de datos serverless. Los crawlers de Glue escanean datos en S3 y otras fuentes, infieren esquemas y crean o actualizan tablas en el AWS Glue Data Catalog, un repositorio central de metadatos que usan Athena, Redshift Spectrum y EMR. Los jobs de Glue ejecutan código de extracción, transformación y carga (ETL) sobre Apache Spark serverless, por ejemplo para convertir CSV a Parquet y particionarlo por fecha, con job bookmarks para que cada ejecución procese solo los datos nuevos. Glue también ofrece creación visual de jobs en Glue Studio y reglas de calidad de datos que revisan los datos a medida que se mueven.

Amazon Athena es un servicio de consultas interactivas serverless: escribes SQL estándar sobre datos en S3, usando tablas definidas en el Data Catalog, y pagas por la cantidad de datos que escanea cada consulta. No hay clústeres que administrar. Como el precio es por escaneo, almacenar los datos en formatos columnares comprimidos como Apache Parquet u ORC y particionarlos, por ejemplo por año, mes y día, reduce tanto el costo como el tiempo de consulta. Una consulta que filtra por columnas de partición lee solo las carpetas que coinciden: ```sql SELECT srcaddr, SUM(bytes) FROM vpc_flow_logs WHERE year='2026' AND month='09' GROUP BY srcaddr ORDER BY 2 DESC LIMIT 10; ```

AWS Lake Formation se basa en el Glue Data Catalog para configurar y proteger data lakes. Su funcionalidad clave es el control de acceso centralizado y detallado: concedes a un equipo acceso a bases de datos, tablas, columnas o filas específicas, y esos permisos se aplican de forma consistente en Athena, Redshift Spectrum, EMR y Glue, en lugar de administrar políticas de bucket de S3 complejas. Es la respuesta cuando una pregunta pide permisos a nivel de columna o de fila en un data lake administrados en un solo lugar, o compartir tablas del data lake entre cuentas con gobernanza.

Amazon EMR ejecuta frameworks de big data como Apache Spark, Hive, Presto, HBase y Flink en clústeres de instancias EC2, en Amazon EKS o con EMR Serverless. Conviene para procesamiento a gran escala, preparación de datos para machine learning y cargas que necesitan control a nivel de framework o versiones específicas; los clústeres pueden usar Spot Instances para los task nodes y así reducir costos. Amazon Redshift Spectrum permite que un clúster de Redshift consulte datos directamente en S3 mediante tablas externas y los combine con tablas cargadas en Redshift, de modo que mantienes los datos calientes en el data warehouse y el historial frío en el data lake. Amazon QuickSight es el servicio serverless de inteligencia de negocios (BI) para dashboards interactivos y visualizaciones, que se conecta a Athena, Redshift, RDS, S3 y otras fuentes, con precio por usuario y un motor en memoria llamado SPICE para dashboards rápidos.

Veamos un ejemplo práctico. Un minorista deposita cada hora archivos CSV de ventas en bruto en S3. Un crawler de Glue los cataloga, y un job de Glue programado los convierte a Parquet particionado en un prefijo curado. Los analistas ejecutan SQL ad hoc con Athena, y los costos de consulta bajan drásticamente porque ahora cada consulta escanea una fracción de los datos. Los analistas de finanzas ven solo las columnas sin información de identificación personal (PII) gracias a los permisos de columna de Lake Formation, mientras que el equipo antifraude lo ve todo. El data warehouse mantiene el último año en Redshift y consulta los años anteriores a través de Spectrum, y los directivos ven dashboards de QuickSight construidos sobre los mismos datos.

Errores comunes: elegir EMR para SQL ad hoc sencillo sobre S3 (Athena no necesita clúster); elegir Athena para una carga de BI pesada y constante que un data warehouse atendería mejor; olvidar que el costo de Athena crece con los datos escaneados, así que el JSON en bruto sin comprimir sale caro; y usar políticas de bucket de S3 para intentar lograr seguridad a nivel de columna, que es lo que proporciona Lake Formation. Otra trampa es pensar que un crawler transforma datos; los crawlers solo descubren esquemas, mientras que los jobs de Glue transforman.

La redacción del examen se asocia con claridad. 'SQL ad hoc sobre S3', 'serverless', 'sin infraestructura' o 'consultar logs de CloudTrail o de ALB' apuntan a Athena. 'Descubrir esquemas', 'crawler', 'Data Catalog' o 'ETL serverless' apuntan a Glue. 'Permisos a nivel de columna o de fila', 'gobernanza centralizada del data lake' apuntan a Lake Formation. 'Hadoop', 'clúster de Spark', 'HBase' o 'control sobre el framework' apuntan a EMR. 'Combinar tablas del data warehouse con datos en S3 sin cargarlos' apunta a Redshift Spectrum. 'Dashboards' y 'visualizaciones de BI' apuntan a QuickSight.

Términos clave

Data lake
Un repositorio central, normalmente en S3, que almacena datos en bruto y procesados de cualquier formato para muchas herramientas de analítica.
AWS Glue Data Catalog
Un almacén central de metadatos con definiciones de tablas que comparten Athena, EMR, Redshift Spectrum y Glue.
Crawler de Glue
Un componente de Glue que escanea fuentes de datos, infiere esquemas y crea o actualiza tablas del Data Catalog.
Amazon Athena
Un servicio serverless de consultas SQL para datos en S3, con precio según los datos escaneados.
AWS Lake Formation
Un servicio para construir data lakes y administrar de forma centralizada el acceso detallado a tablas, columnas y filas.
Redshift Spectrum
Una funcionalidad de Redshift que consulta datos directamente en S3 y los combina con tablas del data warehouse.
Amazon QuickSight
Un servicio serverless de inteligencia de negocios para dashboards y visualizaciones.
Ejemplo real

Un minorista deposita archivos CSV de ventas en bruto en S3. Un crawler de Glue los cataloga y un job de Glue los convierte a Parquet particionado. Los analistas ejecutan SQL ad hoc con Athena, finanzas ve solo las columnas sin PII gracias a los permisos de Lake Formation, los años anteriores se consultan desde Redshift a través de Spectrum, y los directivos ven dashboards de QuickSight construidos sobre los mismos datos.

Consejo para el examen: SQL ad hoc sobre S3 sin servidores: Athena. Descubrir esquemas y ETL: Glue. Permisos a nivel de columna o fila en varias herramientas de analítica: Lake Formation. Clústeres de Hadoop o Spark con control: EMR. Combinar tablas de Redshift con datos en S3: Redshift Spectrum. Dashboards: QuickSight.

Comprueba lo que sabes

¿Cómo puedes reducir los costos de consultas de Athena sobre un conjunto grande de logs?

Convirtiendo los datos a un formato columnar comprimido como Parquet y particionándolos para que las consultas escaneen menos datos.

¿Qué servicio crea tablas en el Data Catalog escaneando datos en S3?

Un crawler de AWS Glue.

Los analistas deben ver todas las columnas de una tabla excepto el salario, y eso debe aplicarse tanto en Athena como en EMR. ¿Qué servicio usas?

AWS Lake Formation, que concede permisos a nivel de columna aplicados en todos los servicios de analítica integrados.

Un equipo de Redshift quiere consultar cinco años de datos archivados en S3 sin cargarlos. ¿Qué usa?

Redshift Spectrum con tablas externas definidas sobre los datos de S3.
