Federación y credenciales temporales: STS AssumeRole, federación SAML y OIDC, Cognito user pools vs identity pools

La federación permite que personas y aplicaciones usen una identidad que ya tienen, en lugar de un usuario de IAM, para obtener acceso a AWS. El motor que hay debajo es AWS Security Token Service (STS), que emite credenciales temporales: un access key ID, una secret access key y un session token, válidos por un tiempo limitado. Como caducan por sí solas, las credenciales temporales son mucho más seguras que las access keys de largo plazo.

Vale la pena conocer por su nombre las llamadas principales de STS. AssumeRole la usa una identidad de IAM o un servicio de AWS para adoptar un rol, incluso entre cuentas. AssumeRoleWithSAML intercambia una aserción SAML 2.0 de un proveedor de identidad corporativo, como Active Directory Federation Services, por credenciales de un rol. AssumeRoleWithWebIdentity intercambia un token de un proveedor OpenID Connect (OIDC); también es lo que permite que los pods de Kubernetes en Amazon EKS y los sistemas de CI/CD como GitHub Actions obtengan roles de AWS sin claves almacenadas. GetSessionToken se usa para obtener credenciales temporales para un usuario de IAM, a menudo después de una verificación MFA.

La federación SAML es el patrón tradicional para la fuerza laboral: los empleados inician sesión en el proveedor de identidad de la empresa, que envía una aserción firmada con los roles que pueden usar, y el usuario llega a la consola de AWS con los permisos de un rol. Hoy IAM Identity Center encapsula esto para entornos multicuenta. La federación OIDC es el patrón moderno para identidades web y cargas de trabajo: registras el proveedor en IAM, y la trust policy del rol restringe qué audiencias y sujetos del token pueden asumirlo.

Amazon Cognito atiende aplicaciones web y móviles orientadas a clientes y tiene dos partes que al examen le encanta contrastar. Un Cognito user pool es un directorio de usuarios y un servicio de inicio de sesión: registro, inicio de sesión, MFA, restablecimiento de contraseña e inicio de sesión social o SAML, que devuelve JSON Web Tokens (JWTs). Esos tokens pueden autorizar llamadas a API Gateway o a un Application Load Balancer. Un Cognito identity pool (identidades federadas) intercambia un token, de un user pool o de un proveedor como Google, por credenciales temporales de AWS vinculadas a un rol de IAM, para que la app pueda llamar directamente a servicios de AWS como S3 o DynamoDB. Los identity pools también pueden dar acceso limitado de invitado a usuarios no autenticados.

En resumen: los user pools responden quién es este usuario, y los identity pools responden qué credenciales de AWS recibe este usuario. Muchas apps usan ambos juntos. El acceso detallado, como permitir que cada usuario lea solo su propia carpeta en S3, se logra con variables de política como el Cognito identity ID en la política del rol del identity pool.

Términos clave

AWS STS
El Security Token Service, que emite credenciales temporales que caducan para roles y usuarios federados.
SAML 2.0
Un estándar basado en XML para intercambiar aserciones de autenticación, muy usado para la federación de la fuerza laboral.
Cognito user pool
Un directorio de usuarios administrado que gestiona el registro y el inicio de sesión y devuelve JWTs.
Cognito identity pool
Un servicio que intercambia tokens de identidad por credenciales temporales de AWS asociadas a roles de IAM.
Ejemplo real

Una app móvil de fotos permite que los clientes inicien sesión con correo electrónico o Google mediante un Cognito user pool. Luego la app intercambia el token del user pool en un identity pool por credenciales temporales cuyo rol solo permite subir archivos a photos/${cognito-identity.amazonaws.com:sub}/ en S3, de modo que cada usuario solo puede escribir en su propio prefijo.

Consejo para el examen: Si una app móvil o web necesita que sus usuarios llamen directamente a servicios de AWS, la respuesta involucra un Cognito identity pool. Si la pregunta trata solo del registro e inicio de sesión de los usuarios de la app, es un user pool. Usuarios corporativos y SAML apuntan a IAM Identity Center o AssumeRoleWithSAML.

Comprueba lo que sabes

¿Qué operación de STS llama un pipeline de CI/CD que usa un token OIDC para obtener credenciales de AWS?

AssumeRoleWithWebIdentity, que intercambia el token OIDC por las credenciales temporales de un rol.

Una API de API Gateway debe aceptar solo usuarios de la app que hayan iniciado sesión. ¿Qué componente de Cognito proporciona el authorizer?

Un Cognito user pool, cuyos JWTs API Gateway puede validar con un Cognito user pool authorizer.
