AWS Certified Solutions Architect – Associate SAA-C03

Federación y credenciales temporales: STS AssumeRole, federación SAML y OIDC, Cognito user pools vs identity pools

La federación permite que personas y aplicaciones usen una identidad que ya tienen, como un inicio de sesión corporativo, una cuenta de Google o un token de un sistema de compilación, para obtener acceso a AWS en lugar de un usuario de IAM. El motor que está debajo es AWS Security Token Service (STS), que emite credenciales temporales: un ID de clave de acceso, una clave de acceso secreta y un token de sesión, válidos durante un tiempo limitado que configuras en el rol dentro de los márgenes permitidos. Como caducan por sí solas, las credenciales temporales son mucho más seguras que las claves de acceso de largo plazo: un conjunto filtrado deja de funcionar al poco tiempo, y no hay nada que rotar.

Conviene conocer por su nombre las llamadas principales de STS. AssumeRole la usa una identidad de IAM o un servicio de AWS para adoptar un rol, incluso entre cuentas. AssumeRoleWithSAML intercambia una aserción SAML 2.0 (Security Assertion Markup Language) emitida por un proveedor de identidad corporativo, como Active Directory Federation Services, por credenciales del rol. AssumeRoleWithWebIdentity intercambia un token de un proveedor OpenID Connect (OIDC); así es como los sistemas de integración y entrega continuas (CI/CD), como GitHub Actions, obtienen roles de AWS sin claves almacenadas, y como los pods de Kubernetes en Amazon EKS usan roles de IAM para cuentas de servicio (IAM roles for service accounts). GetSessionToken devuelve credenciales temporales para un usuario de IAM, a menudo después de una verificación MFA. GetFederationToken es una opción más antigua para la federación mediante un intermediario (broker).

La federación SAML es el patrón tradicional para empleados. Un empleado inicia sesión en el IdP de la empresa, que envía al endpoint de inicio de sesión de AWS una aserción firmada con la lista de roles que el usuario puede usar; AWS valida la firma con los metadatos del IdP que registraste en IAM y el usuario llega a la consola con los permisos de ese rol. Hoy IAM Identity Center envuelve este patrón para organizaciones multicuenta, y es la respuesta preferida en el examen para el acceso de empleados. La federación OIDC es el patrón moderno para identidades web y cargas de trabajo: registras el proveedor en IAM, y la trust policy del rol restringe qué valores de audiencia (aud) y sujeto (sub) del token pueden asumirlo, por ejemplo solo un repositorio y una rama.

Amazon Cognito atiende aplicaciones web y móviles orientadas a clientes y tiene dos partes que al examen le encanta contrastar. Un Cognito user pool es un directorio de usuarios y un servicio de inicio de sesión: registro, inicio de sesión, MFA, restablecimiento de contraseña, recuperación de cuenta e inicio de sesión mediante proveedores sociales o SAML, y devuelve JSON Web Tokens (JWTs). Esos tokens pueden autorizar llamadas a API Gateway mediante un autorizador de Cognito, o un Application Load Balancer puede autenticar usuarios contra el user pool. Un Cognito identity pool (identidades federadas) intercambia un token, de un user pool o de un proveedor como Google o Apple, por credenciales temporales de AWS vinculadas a un rol de IAM, para que la aplicación pueda llamar directamente a servicios de AWS como S3 o DynamoDB. Los identity pools también pueden dar acceso limitado de invitado a usuarios no autenticados mediante un rol separado.

En resumen: los user pools responden quién es este usuario, y los identity pools responden qué credenciales de AWS recibe este usuario. Muchas aplicaciones usan ambos. El acceso detallado (fine-grained), como permitir que cada usuario lea solo su propia carpeta en S3 o sus propios elementos en DynamoDB, usa variables de política como ${cognito-identity.amazonaws.com:sub} en la política del rol del identity pool, o la condición dynamodb:LeadingKeys.

Veamos un ejemplo práctico. Una aplicación móvil de fotos permite que los clientes inicien sesión con correo electrónico o con Google mediante un Cognito user pool. La aplicación intercambia el token de ID del user pool en un identity pool por credenciales temporales. El rol autenticado permite s3:PutObject solo sobre photos/${cognito-identity.amazonaws.com:sub}/*, de modo que cada usuario solo puede escribir en su propio prefijo. Por otro lado, el pipeline de compilación de la empresa despliega el back end de la aplicación llamando a AssumeRoleWithWebIdentity con su token OIDC; la trust policy del rol de despliegue acepta solo tokens cuyo sujeto nombra la rama principal de un único repositorio, así que no hay ninguna clave de largo plazo en la configuración del pipeline.

Errores comunes: elegir un user pool cuando la aplicación debe llamar directamente a servicios de AWS (eso requiere un identity pool); crear usuarios de IAM para millones de clientes de la aplicación; guardar claves de acceso en una aplicación móvil o en un sistema de CI cuando existe la federación; y confiar en un proveedor OIDC sin restringir la audiencia y el sujeto, lo que podría permitir que cualquier token de ese proveedor asuma el rol. Recuerda también que las credenciales temporales no pueden revocarse una por una, pero puedes denegar las sesiones emitidas antes de cierto momento agregando una política con la condición aws:TokenIssueTime, que es lo que hace por ti el botón de revocar sesiones de la consola.

La redacción del examen suele ser clara una vez que conoces el mapa. 'Directorio corporativo', 'Active Directory' o 'SAML' para empleados apunta a IAM Identity Center o a AssumeRoleWithSAML. 'Los usuarios de la aplicación móvil necesitan subir archivos directamente a S3' apunta a un Cognito identity pool. 'Registro e inicio de sesión para usuarios de la aplicación', 'inicio de sesión social' o 'JWT para autorizar API Gateway' apunta a un Cognito user pool. 'CI/CD sin claves de larga duración' apunta a OIDC y AssumeRoleWithWebIdentity, y 'credenciales temporales' en cualquier contexto apunta a STS.

Términos clave

AWS STS
El Security Token Service, que emite credenciales temporales con caducidad para roles y usuarios federados.
Federación (federation)
Otorgar acceso a AWS a identidades administradas fuera de IAM, como un IdP corporativo o un proveedor de identidad web.
SAML 2.0
Un estándar basado en XML para intercambiar aserciones de autenticación firmadas, muy usado en la federación de empleados.
OpenID Connect (OIDC)
Una capa de identidad sobre OAuth 2.0 cuyos tokens firmados pueden intercambiarse por credenciales de un rol de AWS.
Cognito user pool
Un directorio de usuarios administrado que gestiona el registro y el inicio de sesión y devuelve JWTs.
Cognito identity pool
Un servicio que intercambia tokens de identidad por credenciales temporales de AWS asociadas a roles de IAM.
Ejemplo real

Una aplicación de ejercicio tiene dos millones de usuarios. El equipo crea un Cognito user pool para el registro con correo electrónico e inicio de sesión con Apple, y protege sus endpoints de API Gateway con un autorizador de Cognito user pool. Para subir videos de entrenamiento, la aplicación usa un identity pool cuyo rol permite escribir solo en el prefijo de S3 de cada usuario, de modo que las subidas grandes van directo a S3 sin pasar por la API ni requerir usuarios de IAM.

Consejo para el examen: Si una aplicación móvil o web necesita que sus usuarios llamen directamente a servicios de AWS, la respuesta incluye un Cognito identity pool. Si la pregunta trata solo del registro e inicio de sesión de los usuarios de la aplicación, es un user pool. Los usuarios corporativos y SAML apuntan a IAM Identity Center o a AssumeRoleWithSAML.

Comprueba lo que sabes

¿Qué operación de STS llama un pipeline de CI/CD que usa un token OIDC para obtener credenciales de AWS?

AssumeRoleWithWebIdentity, que intercambia el token OIDC por las credenciales temporales de un rol.

Una API de API Gateway debe aceptar solo a usuarios de la aplicación que hayan iniciado sesión. ¿Qué componente de Cognito proporciona el autorizador?

Un Cognito user pool, cuyos JWTs API Gateway puede validar con un autorizador de Cognito user pool.

¿Por qué las credenciales temporales son más seguras que las claves de acceso de un usuario de IAM?

Caducan automáticamente después de un tiempo limitado, así que un conjunto filtrado tiene una vida útil corta y no hay nada de larga duración que rotar.

¿Cómo restringes un rol federado por OIDC para que solo la rama principal de un repositorio pueda asumirlo?

Agrega condiciones en la trust policy del rol sobre los claims de audiencia y sujeto del token que coincidan con ese repositorio y esa rama.
