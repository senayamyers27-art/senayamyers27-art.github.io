AWS Certified Solutions Architect – Associate SAA-C03

Cómo elegir una base de datos: RDS, Aurora, DynamoDB, Redshift, DocumentDB, Neptune y RDS Proxy para el pooling de conexiones

AWS adopta un enfoque de bases de datos construidas para un propósito: en lugar de obligar a una sola base de datos a hacerlo todo, eliges el motor que encaja con el modelo de datos y el patrón de acceso. Una base de datos relacional es excelente para joins y transacciones, pero incómoda a escala masiva de clave-valor; un almacén de clave-valor es lo contrario. Las preguntas del examen suelen darte pistas, como joins y transacciones, búsquedas por clave a escala enorme, analítica sobre años de datos, documentos JSON o relaciones entre entidades, y esperan que las asocies con un servicio. Aprender esas pistas es la mayor parte del trabajo.

Amazon Relational Database Service (RDS) ejecuta motores relacionales conocidos (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server y Db2) como servicios administrados, y se encarga de los parches, los respaldos, la conmutación por error Multi-AZ y las réplicas de lectura. Elígelo para datos estructurados con SQL, joins y transacciones ACID (atomicidad, consistencia, aislamiento, durabilidad), sobre todo cuando una aplicación ya espera un motor específico o necesita uno comercial como Oracle o SQL Server. Amazon Aurora es el motor relacional nativo de la nube de AWS, compatible con MySQL y PostgreSQL. Su capa de almacenamiento distribuido mantiene seis copias de los datos en tres zonas de disponibilidad (AZ), admite hasta 15 réplicas de lectura con poco retraso y conmutación por error rápida, y ofrece opciones como Aurora Serverless v2 y Aurora Global Database para lecturas entre Regiones y recuperación ante desastres. Elige Aurora cuando quieres más rendimiento y disponibilidad que RDS estándar con compatibilidad con MySQL o PostgreSQL.

Amazon DynamoDB es una base de datos NoSQL serverless de clave-valor y documentos con rendimiento de milisegundos de un solo dígito a cualquier escala, sin servidores que administrar, y con funcionalidades como global tables para replicación activa-activa multi-Región, DynamoDB Streams para eventos de cambio y TTL para expiración automática. Elígela para cargas web, móviles, de videojuegos e Internet de las cosas (IoT) de gran escala con patrones de acceso conocidos, y cuando se busca una base de datos serverless con esquema flexible. Amazon Redshift es un data warehouse columnar para procesamiento analítico en línea (OLAP): consultas SQL complejas y agregaciones sobre grandes conjuntos de datos históricos para inteligencia de negocios. No está diseñado para actualizaciones fila por fila de alto volumen propias del procesamiento de transacciones en línea (OLTP).

Amazon DocumentDB (with MongoDB compatibility) almacena documentos JSON y admite las API y los drivers de MongoDB, así que es la respuesta para trasladar cargas de MongoDB a un servicio administrado con cambios mínimos de código. Amazon Neptune es una base de datos de grafos para datos muy conectados, como redes sociales, motores de recomendación, redes de fraude y grafos de conocimiento, que se consulta con Gremlin, openCypher o SPARQL. Otros motores construidos para un propósito que puedes ver son Amazon Keyspaces (for Apache Cassandra), Amazon Timestream para datos de series temporales, Amazon MemoryDB como base de datos en memoria duradera compatible con Redis, y Amazon OpenSearch Service para búsqueda de texto completo y analítica de logs.

RDS Proxy se sitúa entre las aplicaciones y RDS o Aurora, y agrupa y comparte las conexiones a la base de datos. Importa sobre todo en diseños serverless: miles de funciones AWS Lambda concurrentes pueden abrir cada una una conexión y agotar el límite de conexiones de la base de datos, y abrir conexiones ya es costoso en sí. El proxy multiplexa muchas conexiones de clientes sobre menos conexiones a la base de datos, reduce el tiempo de conmutación por error manteniendo abiertas las conexiones de los clientes mientras la base de datos conmuta, y puede exigir autenticación de AWS Identity and Access Management (IAM) con las credenciales de la base de datos almacenadas en AWS Secrets Manager. Las aplicaciones simplemente cambian su endpoint de conexión por el endpoint del proxy. RDS Proxy no es una caché y no acelera las consultas individuales.

Veamos un ejemplo práctico. La API serverless de una startup usa Lambda con Aurora PostgreSQL, y durante los picos de tráfico la base de datos se queda sin conexiones y devuelve errores. Agregar RDS Proxy permite que miles de instancias de funciones compartan un pequeño pool de conexiones, y la conmutación por error se vuelve más rápida para la aplicación. Para su funcionalidad de recomendación de amigos, el equipo agrega Neptune, porque consultas como 'amigos de amigos a quienes les gustó este artículo' son recorridos de grafos que en SQL requerirían muchos joins costosos. Los informes nocturnos de ventas pasan a Redshift para que las consultas de agregación pesadas ya no ralenticen la base de datos transaccional, y el carrito de compras, que necesita búsquedas simples por clave a escala enorme, pasa a DynamoDB.

Errores comunes: elegir Redshift para una aplicación OLTP; elegir DynamoDB cuando el requisito enfatiza joins complejos y consultas relacionales ad hoc; elegir réplicas de lectura de RDS para resolver un problema de agotamiento de conexiones (ese es el trabajo de RDS Proxy); y elegir ElastiCache cuando se requiere un almacenamiento duradero como fuente de verdad. Otra trampa es elegir RDS for Oracle cuando la pregunta dice que la empresa quiere evitar licencias comerciales; migrar a Aurora PostgreSQL puede ser la respuesta esperada.

La redacción del examen se asocia claramente con los motores. 'Relaciones', 'grafo' o 'red social' es Neptune; 'compatibilidad con MongoDB' es DocumentDB; 'data warehouse', 'OLAP' o 'analítica de petabytes' es Redshift; 'clave-valor', 'cualquier escala', 'serverless' o 'milisegundos de un solo dígito' es DynamoDB; 'compatible con MySQL o PostgreSQL con más rendimiento y disponibilidad' es Aurora; 'demasiadas conexiones desde Lambda' es RDS Proxy.

Términos clave

OLTP vs OLAP
El procesamiento de transacciones en línea maneja muchas lecturas y escrituras pequeñas; el procesamiento analítico en línea ejecuta grandes consultas de agregación sobre datos históricos.
Amazon Aurora
Un motor relacional compatible con MySQL y PostgreSQL con almacenamiento distribuido en tres AZ y hasta 15 réplicas de lectura.
Amazon DynamoDB
Una base de datos NoSQL serverless de clave-valor y documentos con rendimiento consistente de milisegundos de un solo dígito a cualquier escala.
Amazon Redshift
Un data warehouse columnar administrado para analítica sobre grandes conjuntos de datos.
Amazon DocumentDB
Una base de datos de documentos JSON administrada, compatible con las API y los drivers de MongoDB.
Amazon Neptune
Una base de datos de grafos administrada para datos definidos por las relaciones entre entidades.
RDS Proxy
Un proxy de base de datos administrado que agrupa las conexiones a RDS y Aurora y acelera la conmutación por error.
Ejemplo real

La API serverless de una startup usa Lambda con Aurora PostgreSQL, y durante los picos de tráfico la base de datos se queda sin conexiones. Agregar RDS Proxy permite que miles de instancias de funciones compartan un pequeño pool de conexiones. Para su funcionalidad de recomendación de amigos, el equipo agrega Neptune, y para los informes nocturnos de ventas carga los datos en Redshift para que las consultas analíticas ya no compitan con las transacciones de los clientes.

Consejo para el examen: Asocia las pistas con los motores: relaciones y recorrido de grafos es Neptune; compatibilidad con MongoDB es DocumentDB; analítica o data warehouse es Redshift; clave-valor a cualquier escala con operación serverless es DynamoDB; demasiadas conexiones desde Lambda es RDS Proxy.

Comprueba lo que sabes

Una empresa quiere trasladar una base de datos MongoDB autoadministrada a un servicio administrado de AWS con cambios mínimos de código. ¿Qué servicio usas?

Amazon DocumentDB (with MongoDB compatibility).

Las funciones Lambda agotan las conexiones de una base de datos RDS durante las ráfagas. ¿Qué debes agregar?

RDS Proxy, que agrupa y comparte las conexiones a la base de datos entre muchos clientes.

Un equipo antifraude necesita encontrar redes de cuentas vinculadas por dispositivos y direcciones compartidos. ¿Qué base de datos encaja?

Amazon Neptune, una base de datos de grafos hecha para recorrer relaciones entre entidades.

¿Por qué Redshift no es adecuado para una aplicación de registro de pedidos?

Redshift es un data warehouse OLAP columnar optimizado para grandes consultas analíticas, no para muchas inserciones y actualizaciones transaccionales pequeñas.
