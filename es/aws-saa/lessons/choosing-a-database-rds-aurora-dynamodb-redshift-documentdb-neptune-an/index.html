AWS Certified Solutions Architect – Associate SAA-C03

Cómo elegir una base de datos: RDS, Aurora, DynamoDB, Redshift, DocumentDB, Neptune y RDS Proxy para el pooling de conexiones

AWS adopta un enfoque de bases de datos creadas para un propósito específico (purpose-built): en lugar de una sola base de datos para todo, eliges el motor que encaja con el modelo de datos y el patrón de acceso. Las preguntas del examen suelen darte pistas, como joins y transacciones, búsquedas de clave-valor a escala masiva, analítica sobre años de datos o relaciones entre entidades, y esperan que las relaciones con un servicio.

Amazon RDS ejecuta motores relacionales conocidos (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server y Db2) como servicios administrados. Elígelo para datos estructurados con SQL, joins y transacciones ACID, sobre todo cuando una aplicación ya espera un motor específico o necesita uno comercial. Amazon Aurora es el motor relacional nativo de la nube de AWS, compatible con MySQL y PostgreSQL, con una capa de almacenamiento distribuida en tres AZs, hasta 15 réplicas de bajo retraso, failover rápido y opciones como Aurora Serverless v2 y Global Database. Elige Aurora cuando quieras mayor rendimiento y disponibilidad que RDS estándar con compatibilidad con MySQL o PostgreSQL.

Amazon DynamoDB es una base de datos NoSQL serverless de clave-valor y documentos con rendimiento de milisegundos de un solo dígito a cualquier escala, sin servidores que administrar y con funciones como global tables, streams y TTL. Elígela para cargas de trabajo web, móviles, de videojuegos e IoT de gran escala con patrones de acceso conocidos, y cuando se busca una base de datos serverless con esquema flexible. Amazon Redshift es un data warehouse columnar para procesamiento analítico en línea (OLAP): consultas SQL complejas y agregaciones sobre grandes conjuntos de datos históricos, para inteligencia de negocios. No está pensado para actualizaciones transaccionales de gran volumen.

Amazon DocumentDB (with MongoDB compatibility) almacena documentos JSON y admite las APIs y los drivers de MongoDB, así que es la respuesta para migrar cargas de trabajo de MongoDB a un servicio administrado. Amazon Neptune es una base de datos de grafos para datos muy conectados, como redes sociales, motores de recomendación, redes de fraude y grafos de conocimiento, que se consulta con Gremlin, openCypher o SPARQL. Otras que puedes encontrar: Amazon Keyspaces for Apache Cassandra, Amazon Timestream para series temporales y Amazon MemoryDB como base de datos duradera compatible con Redis.

RDS Proxy se sitúa entre las aplicaciones y RDS o Aurora y agrupa (pooling) y comparte las conexiones a la base de datos. Importa sobre todo en serverless: miles de funciones Lambda concurrentes pueden abrir cada una una conexión y agotar el límite de conexiones de la base de datos. El proxy las multiplexa sobre menos conexiones, reduce el tiempo de failover manteniendo abiertas las conexiones de los clientes mientras la base de datos hace failover, y puede exigir autenticación de IAM con credenciales guardadas en Secrets Manager. RDS Proxy no es una caché y no acelera las consultas individuales.

Términos clave

OLTP vs OLAP
El procesamiento de transacciones en línea maneja muchas lecturas y escrituras pequeñas; el procesamiento analítico en línea ejecuta grandes consultas de agregación.
Amazon Redshift
Un data warehouse columnar administrado para analítica sobre grandes conjuntos de datos.
Amazon Neptune
Una base de datos de grafos administrada para datos definidos por las relaciones entre entidades.
RDS Proxy
Un proxy de base de datos administrado que agrupa las conexiones a RDS y Aurora y acelera el failover.
Ejemplo real

La API serverless de una startup usa Lambda con Aurora PostgreSQL, y durante los picos de tráfico la base de datos se queda sin conexiones. Agregar RDS Proxy permite que miles de instancias de funciones compartan un pequeño pool de conexiones. Para su función de recomendación de amigos, el equipo agrega Neptune, y para los reportes nocturnos de ventas carga los datos en Redshift.

Consejo para el examen: Relaciona las pistas con los motores: relaciones y recorrido de grafos es Neptune; compatibilidad con MongoDB es DocumentDB; analítica o data warehouse es Redshift; clave-valor a cualquier escala con operación serverless es DynamoDB; demasiadas conexiones desde Lambda es RDS Proxy.

Comprueba lo que sabes

Una empresa quiere trasladar una base de datos MongoDB autoadministrada a un servicio administrado de AWS con cambios mínimos de código. ¿Qué servicio?

Amazon DocumentDB (with MongoDB compatibility).

Unas funciones Lambda agotan las conexiones de una base de datos RDS durante las ráfagas. ¿Qué debes agregar?

RDS Proxy, que agrupa y comparte las conexiones a la base de datos.
