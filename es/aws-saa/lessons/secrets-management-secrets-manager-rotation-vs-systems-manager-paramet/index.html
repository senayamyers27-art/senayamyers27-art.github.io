Gestión de secretos: rotación en Secrets Manager vs SecureString de Systems Manager Parameter Store

Las aplicaciones necesitan contraseñas de bases de datos, API keys y tokens. Escribirlos directamente en el código fuente, en AMIs o en archivos de entorno es un error de seguridad clásico: los secretos terminan en el control de versiones, en los logs y en los respaldos, y cambiarlos implica volver a desplegar. AWS te ofrece dos lugares administrados para guardarlos, y el examen te pide elegir entre ellos.

AWS Secrets Manager está hecho para secretos. Cifra cada secreto con una clave de KMS, controla el acceso con IAM y políticas de recursos, registra el acceso en CloudTrail y, lo más importante, rota los secretos automáticamente según un calendario. Para Amazon RDS, Aurora, Redshift y DocumentDB ofrece managed rotation (rotación administrada): cambia la contraseña en la base de datos y en el secreto al mismo tiempo, así que las aplicaciones que obtienen el secreto en tiempo de ejecución siguen funcionando. Para otros tipos de secretos, la rotación ejecuta una función Lambda que tú proporcionas o adaptas a partir de las plantillas de AWS. Secrets Manager también puede replicar secretos a otras Regiones para recuperación ante desastres, y RDS puede administrar por ti la contraseña del usuario maestro en Secrets Manager. Cobra por secreto al mes y por llamada a la API.

AWS Systems Manager Parameter Store es un almacén jerárquico para datos de configuración, como /prod/app/db-host. Los parámetros son de tres tipos: String, StringList y SecureString. Un SecureString se cifra con una clave de KMS, ya sea la AWS managed key aws/ssm o una customer managed key. Los parámetros estándar no tienen cargo adicional de almacenamiento, lo que hace atractivo a Parameter Store para configuración y secretos simples. Sin embargo, Parameter Store no tiene rotación integrada; tendrías que construirla tú mismo con EventBridge y Lambda.

¿Cómo eliges? Si el requisito menciona rotación automática, sobre todo de credenciales de bases de datos, elige Secrets Manager. Si se trata de configuración general, feature flags o secretos que rara vez cambian, y el costo importa, Parameter Store SecureString está bien. Ambos se integran con las dynamic references de CloudFormation, las task definitions de ECS y Lambda, para que las aplicaciones puedan cargar los valores al arrancar. Parameter Store incluso puede hacer referencia a secretos de Secrets Manager mediante una ruta de parámetro especial, de modo que una sola API puede leer ambos.

Elijas el que elijas, el rol de la aplicación necesita permiso para leer el secreto y para usar la clave de KMS que lo cifra. Obtén los secretos en tiempo de ejecución y guárdalos en caché brevemente, en lugar de incluirlos en las imágenes.

Términos clave

Secrets Manager
Un servicio administrado que almacena, cifra, audita y rota automáticamente los secretos.
Parameter Store
Una función de Systems Manager para datos de configuración jerárquicos y secretos, sin rotación integrada.
SecureString
Un tipo de parámetro de Parameter Store cuyo valor se cifra con una clave de KMS.
Rotation (rotación)
Reemplazar periódicamente un secreto por un valor nuevo y actualizar cada lugar que lo usa.
Ejemplo real

Una auditoría de seguridad exige que la contraseña de la base de datos de producción cambie cada 30 días sin tiempo de inactividad. El equipo mueve las credenciales de un archivo de entorno a Secrets Manager, habilita la managed rotation para la base de datos RDS y cambia la aplicación para que obtenga el secreto al arrancar y lo actualice cuando falle un inicio de sesión.

Consejo para el examen: La palabra clave es rotación. La rotación automática de credenciales de bases de datos apunta a Secrets Manager; el almacenamiento de bajo costo de configuración y secretos estáticos apunta a Parameter Store SecureString.

Comprueba lo que sabes

¿Qué servicio rota automáticamente las credenciales de RDS sin código personalizado?

AWS Secrets Manager, mediante la managed rotation para RDS.

¿Qué cifra un parámetro SecureString?

Una clave de AWS KMS, ya sea la AWS managed key aws/ssm o una customer managed key.
