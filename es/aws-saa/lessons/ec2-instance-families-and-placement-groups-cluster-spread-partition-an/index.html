AWS Certified Solutions Architect – Associate SAA-C03

Familias de instancias EC2 y placement groups (cluster, spread, partition), y enhanced networking con ENA y EFA

Amazon Elastic Compute Cloud (EC2) ofrece cientos de tipos de instancia, pero se agrupan en unas pocas familias, y el examen SAA-C03 espera que sepas asociar cada carga de trabajo con la adecuada. Elegir bien importa por partida doble: una instancia demasiado pequeña perjudica el rendimiento, y una con la forma equivocada desperdicia dinero, porque pagas por CPU, memoria o almacenamiento que tu aplicación nunca usa. Además del tipo de instancia, hay dos decisiones más que determinan el rendimiento de flotas muy interconectadas: dónde se ubican físicamente las instancias y cómo se conectan en red.

El nombre de la instancia codifica lo que obtienes. En m7g.large, m es la familia, 7 la generación, g un atributo (aquí AWS Graviton, un procesador basado en Arm diseñado por AWS) y large el tamaño. Otras letras de atributo que verás son i para Intel, a para AMD, d para almacenamiento de instancia NVMe local y n para ancho de banda de red adicional. Las instancias de propósito general (M, y T para las burstable) equilibran CPU, memoria y red, y sirven para servidores web y bases de datos pequeñas. Las instancias T acumulan créditos de CPU mientras están inactivas y los gastan en ráfagas; en modo unlimited pueden superar sus créditos a cambio de un cargo adicional. Las optimizadas para cómputo (C) sirven para procesamiento por lotes, codificación de medios, servidores de juegos y modelado científico. Las optimizadas para memoria (R, X y otras) sirven para bases de datos en memoria, cachés y analítica en tiempo real. Las optimizadas para almacenamiento (I, D y otras) tienen almacenamiento de instancia local rápido para mucha E/S aleatoria o cargas secuenciales densas. Las de cómputo acelerado (P, G, Inf, Trn y otras) añaden unidades de procesamiento gráfico (GPU) o chips de machine learning de AWS.

Los placement groups influyen en dónde quedan las instancias dentro de la infraestructura física, y hay tres estrategias. Un cluster placement group agrupa las instancias muy juntas dentro de una sola zona de disponibilidad (Availability Zone, AZ) para lograr la menor latencia y el mayor rendimiento entre ellas, lo que conviene a la computación de alto rendimiento (HPC) fuertemente acoplada. La contrapartida es la falla correlacionada: un problema en un rack o en la AZ puede afectar a muchas instancias a la vez. Un spread placement group coloca cada instancia en hardware subyacente distinto, con un límite de siete instancias en ejecución por AZ por grupo, para minimizar las fallas correlacionadas de un número pequeño de instancias críticas. Un partition placement group divide las instancias en particiones lógicas, cada una en su propio conjunto de racks con red y energía separadas, de modo que sistemas distribuidos grandes como Hadoop, Cassandra y Kafka puedan colocar réplicas en dominios de falla diferentes. Las instancias pueden leer su número de partición desde los metadatos de la instancia para que la aplicación tome decisiones conscientes de las réplicas.

El rendimiento de red depende del tipo de instancia y del enhanced networking, que usa single root I/O virtualization (SR-IOV) para dar más ancho de banda, más paquetes por segundo y una latencia más baja y consistente que la red virtualizada tradicional. El Elastic Network Adapter (ENA) proporciona enhanced networking en los tipos de instancia de generación actual y viene habilitado en las Amazon Machine Images (AMI) actuales que proporciona AWS. Puedes confirmarlo con aws ec2 describe-instances --instance-ids i-0abc --query 'Reservations[].Instances[].EnaSupport'. El Elastic Fabric Adapter (EFA) es un dispositivo de red para HPC y machine learning que añade bypass del sistema operativo: las aplicaciones que usan Message Passing Interface (MPI) o NVIDIA Collective Communications Library (NCCL) hablan directamente con el hardware de red, saltándose el kernel, para obtener una latencia muy baja y predecible. EFA solo está disponible en ciertos tipos de instancia, lo adjuntas como tipo de interfaz de red al lanzar la instancia y normalmente se combina con un cluster placement group.

Veamos un ejemplo práctico. Un equipo de investigación ejecuta una simulación meteorológica en 64 instancias que intercambian datos constantemente mediante MPI. El arquitecto elige un tipo de instancia optimizado para cómputo y orientado a HPC que admite EFA, crea un cluster placement group con aws ec2 create-placement-group --group-name wx-sim --strategy cluster y lanza todos los nodos en él, en una sola AZ, con una interfaz EFA. Como un cluster group concentra el riesgo, el trabajo guarda puntos de control de su estado con regularidad en Amazon FSx for Lustre, de modo que una sola falla de hardware cuesta minutos de trabajo en lugar de toda la ejecución. Por separado, cada uno de los tres servidores de licencias del equipo se ejecuta en un spread placement group para que ninguno comparta hardware con otro.

Errores comunes: elegir un spread placement group para una flota grande (tiene un tope de siete instancias en ejecución por AZ por grupo, así que los clústeres replicados grandes van en un partition group); suponer que un cluster placement group abarca varias AZ (no lo hace, así que no ofrece resiliencia a nivel de AZ); tratar ENA y EFA como si fueran lo mismo (ENA es enhanced networking general; EFA añade bypass del sistema operativo para MPI y NCCL); y elegir una instancia T burstable para una carga con CPU alta constante, lo que agota los créditos y provoca throttling o cargos del modo unlimited. Otra trampa es lanzar tipos de instancia mezclados en un cluster group; lo mejor es lanzar todo el grupo de una vez con el mismo tipo para reducir los errores de capacidad.

Las preguntas del examen suelen describir la carga de trabajo y pedir la opción de ubicación o de red. 'Fuertemente acoplado', 'la menor latencia entre nodos', 'HPC' o 'MPI' apuntan a un cluster placement group más EFA. 'Un número pequeño de instancias críticas que no deben compartir hardware' apunta a un spread placement group. 'Cientos de nodos para HDFS, Cassandra o Kafka, con réplicas en racks separados' apunta a un partition placement group. 'Base de datos en memoria' apunta a una familia optimizada para memoria, 'mucha E/S aleatoria en disco local' a optimizada para almacenamiento, y 'entrenamiento o inferencia con GPU' a cómputo acelerado. Cuando una pregunta menciona mejor relación precio-rendimiento y compatibilidad con Arm, piensa en Graviton.

Términos clave

Familia de instancias (instance family)
Un grupo de tipos de instancia EC2 optimizados para un perfil de recursos, como propósito general, cómputo, memoria, almacenamiento o cómputo acelerado.
Cluster placement group
Instancias agrupadas muy juntas en una sola zona de disponibilidad para tener red de baja latencia y alto rendimiento entre ellas.
Spread placement group
Cada instancia en hardware distinto, con un límite de siete instancias en ejecución por AZ por grupo, para reducir las fallas correlacionadas.
Partition placement group
Instancias divididas en particiones sobre racks separados, para sistemas distribuidos y replicados de gran tamaño.
Elastic Network Adapter (ENA)
La interfaz de red que proporciona enhanced networking con mucho ancho de banda y alta tasa de paquetes en los tipos de instancia actuales.
Elastic Fabric Adapter (EFA)
Una interfaz de red con bypass del sistema operativo para cargas de HPC y machine learning fuertemente acopladas que usan MPI o NCCL.
Instancia burstable
Una instancia de la familia T que acumula créditos de CPU cuando está inactiva y los gasta para superar en ráfagas un nivel base.
Ejemplo real

Un equipo de investigación ejecuta una simulación meteorológica en 64 instancias que intercambian datos constantemente mediante MPI. El arquitecto elige un tipo de instancia orientado a HPC con EFA, lanza todos los nodos en un cluster placement group en una sola AZ y guarda puntos de control de los resultados en Amazon FSx for Lustre para que una falla de hardware no haga perder toda la ejecución. En cambio, el clúster de Kafka del equipo se ejecuta en un partition placement group para que las réplicas de cada broker queden en racks diferentes.

Consejo para el examen: La menor latencia entre nodos: cluster. Máximo aislamiento para unas pocas instancias críticas: spread (siete por AZ). Clústeres replicados grandes como Kafka, Cassandra o HDFS: partition. MPI o bypass del sistema operativo: EFA, no solo ENA.

Comprueba lo que sabes

¿Qué placement group es mejor para un clúster de Cassandra de 30 nodos que debe mantener las réplicas en racks separados?

Un partition placement group, que coloca cada partición en sus propios racks y expone el número de partición a la aplicación a través de los metadatos.

¿Qué indica la 'g' en m7g?

Que la instancia usa un procesador AWS Graviton (basado en Arm), por lo que el software debe ser compatible con la arquitectura Arm64.

¿Por qué un spread placement group no es adecuado para una flota web de 50 instancias en dos AZ?

Los spread groups permiten solo siete instancias en ejecución por AZ por grupo, así que están pensados para unas pocas instancias críticas, no para flotas grandes.

Una aplicación MPI necesita la menor latencia posible entre nodos. ¿Qué dos funcionalidades debes combinar?

Un cluster placement group en una sola AZ y el Elastic Fabric Adapter, cuyo bypass del sistema operativo permite que MPI llegue directamente al hardware de red.
