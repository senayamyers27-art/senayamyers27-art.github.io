AWS Certified Solutions Architect – Associate SAA-C03

Familias de instancias EC2 y placement groups (cluster, spread, partition), y enhanced networking con ENA y EFA

Amazon EC2 ofrece cientos de tipos de instancia, pero se agrupan en unas pocas familias, y el examen espera que relaciones una carga de trabajo con una familia. El nombre lo codifica: en m7g.large, m es la familia, 7 la generación, g un atributo (aquí AWS Graviton, un procesador basado en Arm) y large el tamaño. Uso general (M, y T para las de ráfaga) equilibra CPU, memoria y red. Optimizadas para cómputo (C) se adaptan al procesamiento por lotes, servidores web y modelado científico. Optimizadas para memoria (R, X y otras) se adaptan a bases de datos y cachés en memoria. Optimizadas para almacenamiento (I, D y otras) tienen almacenamiento de instancia local rápido para E/S aleatoria alta o cargas secuenciales densas. Cómputo acelerado (P, G, Inf, Trn y otras) agrega GPUs o chips de machine learning de AWS. Las instancias T acumulan créditos de CPU mientras están inactivas y los gastan en ráfagas; en modo unlimited pueden superar sus créditos con un cargo adicional.

Los placement groups (grupos de ubicación) influyen en dónde se colocan las instancias dentro de la infraestructura física. Un cluster placement group agrupa las instancias muy cerca en una AZ para lograr la menor latencia y el mayor rendimiento entre ellas, lo que se adapta a la computación de alto rendimiento (HPC) fuertemente acoplada. La contrapartida es que un problema en un solo rack o AZ afecta a muchas instancias. Un spread placement group coloca cada instancia en hardware distinto, con un límite de siete instancias en ejecución por AZ por grupo, para minimizar las fallas correlacionadas en un número pequeño de instancias críticas. Un partition placement group divide las instancias en particiones, cada una en su propio conjunto de racks, para que grandes sistemas distribuidos como Hadoop, Cassandra y Kafka puedan colocar réplicas en dominios de falla distintos; las instancias pueden conocer su partición mediante los metadatos.

El rendimiento de red depende del tipo de instancia y del enhanced networking (red mejorada), que usa single root I/O virtualization (SR-IOV) para lograr mayor ancho de banda, mayores tasas de paquetes y menor latencia. El Elastic Network Adapter (ENA) proporciona enhanced networking en los tipos de instancia actuales, y está habilitado en las AMIs actuales proporcionadas por AWS. El Elastic Fabric Adapter (EFA) es un dispositivo de red para HPC y machine learning que agrega capacidades de OS-bypass (omisión del sistema operativo), permitiendo que las aplicaciones que usan Message Passing Interface (MPI) o NVIDIA Collective Communications Library (NCCL) se comuniquen directamente con el hardware de red para una latencia muy baja. EFA está disponible en tipos de instancia seleccionados y normalmente se combina con un cluster placement group.

Cuando una pregunta describe nodos HPC fuertemente acoplados que necesitan la menor latencia entre ellos, la respuesta combina un tipo de instancia optimizado para cómputo u orientado a HPC, un cluster placement group y EFA. Cuando describe un puñado de instancias críticas que no deben compartir hardware, es un spread placement group.

Términos clave

Cluster placement group
Instancias agrupadas muy cerca en una AZ para una red de baja latencia y alto rendimiento.
Spread placement group
Cada instancia en hardware distinto, con un límite de siete instancias en ejecución por AZ por grupo.
Partition placement group
Instancias divididas en particiones sobre racks separados, para grandes sistemas distribuidos y replicados.
Elastic Fabric Adapter (EFA)
Una interfaz de red con OS-bypass para cargas de trabajo de HPC y ML fuertemente acopladas.
Ejemplo real

Un equipo de investigación ejecuta una simulación meteorológica en 64 instancias que intercambian datos constantemente mediante MPI. El arquitecto elige un tipo de instancia orientado a HPC con EFA, lanza todos los nodos en un cluster placement group en una AZ y guarda puntos de control de los resultados en Amazon FSx for Lustre para que una falla no haga perder toda la ejecución.

Consejo para el examen: Menor latencia entre nodos: cluster. Máximo aislamiento para unas pocas instancias: spread. Grandes clústeres replicados como Kafka o HDFS: partition. MPI u OS-bypass: EFA, no solo ENA.

Comprueba lo que sabes

¿Qué placement group es el mejor para un clúster de Cassandra de 30 nodos que debe mantener las réplicas en racks separados?

Un partition placement group, que coloca cada partición en sus propios racks y expone la información de partición a la aplicación.

¿Qué indica la 'g' en m7g?

Que la instancia usa un procesador AWS Graviton (basado en Arm).
