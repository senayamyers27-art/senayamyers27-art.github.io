Resiliencia de DynamoDB: global tables, point-in-time recovery y respaldos bajo demanda

Amazon DynamoDB es una base de datos de clave-valor y de documentos, totalmente administrada y serverless. La resiliencia viene incluida: los datos de cada tabla se replican automáticamente en varias Availability Zones de su Región, así que no configuras Multi-AZ como lo haces con RDS. Lo que sí eliges es cómo manejar otros dos riesgos: un problema de toda la Región y datos corrompidos o eliminados por personas o por errores de software.

Las global tables (tablas globales) manejan la resiliencia regional y la latencia global. Agregas Regiones de réplica a una tabla, y DynamoDB replica los cambios entre ellas, normalmente en uno o dos segundos. Cada réplica acepta lecturas y escrituras (activo-activo), así que los usuarios de cada Región obtienen latencia local y una aplicación puede seguir funcionando en otra Región si una deja de estar disponible. Cuando el mismo elemento se escribe en dos Regiones casi al mismo tiempo, los conflictos se resuelven con last writer wins (gana el último escritor). Las global tables requieren DynamoDB Streams, que DynamoDB habilita por ti.

La replicación no te protege de las escrituras incorrectas, porque una eliminación errónea se replica a todas partes con la misma rapidez. Para eso necesitas respaldos. La point-in-time recovery (PITR, recuperación a un momento dado), una vez habilitada, mantiene respaldos continuos y te permite restaurar la tabla a cualquier segundo dentro de una ventana de recuperación de hasta 35 días. Los on-demand backups (respaldos bajo demanda) son respaldos completos que tomas manualmente o según un calendario y conservas hasta que los eliminas, útiles para retención a largo plazo y cumplimiento normativo. Ningún tipo de respaldo afecta el rendimiento de la tabla.

Las restauraciones siempre crean una tabla nueva; nunca sobrescriben la existente. Después de una restauración, debes volver a configurar algunas opciones en la tabla nueva, como las políticas de auto scaling, las políticas de IAM, las alarmas de CloudWatch y las etiquetas, y apuntar tu aplicación hacia ella. AWS Backup también puede administrar de forma centralizada los respaldos de DynamoDB, agregando copias entre Regiones y entre cuentas, ciclo de vida hacia almacenamiento en frío y bloqueos de backup vault.

Dos funciones relacionadas ayudan con la recuperación y la auditoría. DynamoDB Streams captura los cambios a nivel de elemento durante 24 horas, que Lambda puede procesar para registros de auditoría o para replicar a otros sistemas. Time to Live (TTL) elimina automáticamente los elementos vencidos, lo que reduce el almacenamiento pero también significa que las eliminaciones por TTL son esperadas, no un incidente. Para el examen, recuerda: global tables para disponibilidad multirregión y baja latencia, PITR para restaurar a un momento preciso tras escrituras o eliminaciones accidentales, y on-demand backups o AWS Backup para retención a largo plazo.

Términos clave

Global table (tabla global)
Una tabla de DynamoDB replicada en varias Regiones, donde cada réplica acepta lecturas y escrituras.
Point-in-time recovery (PITR)
Respaldos continuos de DynamoDB que permiten restaurar a cualquier segundo dentro de la ventana de recuperación de hasta 35 días.
On-demand backup (respaldo bajo demanda)
Un respaldo completo de DynamoDB creado manualmente y conservado hasta que lo eliminas.
Last writer wins (gana el último escritor)
La regla de resolución de conflictos de las global tables en la que prevalece la escritura más reciente a un elemento.
Ejemplo real

Un error en una versión sobrescribió miles de perfiles de clientes a las 14:05. Como PITR estaba habilitado, el equipo restauró la tabla a una tabla nueva al estado de las 14:04, comparó ambas y copió de vuelta los elementos correctos. La misma tabla es una global table en dos Regiones, de modo que la app de clientes sigue disponible aunque una Región sufra una interrupción.

Consejo para el examen: La replicación no es un respaldo: las global tables también copian los errores. Para recuperarte de una eliminación o corrupción accidental a un momento exacto, elige point-in-time recovery; las restauraciones siempre van a una tabla nueva.

Comprueba lo que sabes

Un ingeniero eliminó elementos por accidente hace 10 minutos. La tabla es una global table en tres Regiones. ¿Puede ayudar la réplica de otra Región?

No. Las eliminaciones se replicaron a todas las Regiones. Restaura con point-in-time recovery o con un respaldo.

¿Una restauración de DynamoDB sobrescribe la tabla de origen?

No. Las restauraciones siempre crean una tabla nueva, que luego configuras y hacia la que apuntas la aplicación.
