Modelos de servicio en la nube: IaaS, PaaS, SaaS

Los modelos de servicio en la nube describen qué parte de la pila tecnológica administra el proveedor y qué parte administra el cliente. Piensa en la pila como capas: el hardware físico y la red abajo, luego la virtualización, el sistema operativo, el middleware y el runtime, y luego las aplicaciones y los datos arriba. Cada modelo entrega más de esas capas al proveedor.

IaaS (infrastructure as a service, infraestructura como servicio) ofrece los bloques básicos: máquinas virtuales, almacenamiento, redes y balanceadores de carga, rentados bajo demanda. El proveedor administra el centro de datos físico, el hardware y la virtualización. El cliente administra todo lo que está por encima: instalar y parchear el sistema operativo, configurar los firewalls, instalar aplicaciones y proteger los datos. IaaS da el mayor control y flexibilidad y es lo más parecido a operar tus propios servidores. Algunos ejemplos son rentar servidores virtuales o almacenamiento de bloques a un gran proveedor de nube. Conviene a las organizaciones que trasladan servidores existentes a la nube con cambios mínimos.

PaaS (platform as a service, plataforma como servicio) ofrece una plataforma lista para usar para crear y ejecutar aplicaciones. El proveedor también administra el sistema operativo, el runtime, el middleware y a menudo las bases de datos, incluidos los parches y el escalado. El cliente se concentra solo en el código de su aplicación y sus datos. Los desarrolladores simplemente suben el código y la plataforma lo ejecuta. Algunos ejemplos son los servicios administrados de alojamiento de aplicaciones y los servicios administrados de bases de datos. PaaS acelera el desarrollo, pero da menos control sobre el entorno subyacente y puede crear cierta dependencia de la plataforma específica del proveedor.

SaaS (software as a service, software como servicio) ofrece aplicaciones completas a través de internet, normalmente mediante un navegador web o una aplicación, por suscripción. El proveedor administra todo, incluida la propia aplicación; el cliente solo la usa y administra sus propios usuarios, configuraciones y datos. Algunos ejemplos son el correo y las suites de oficina basados en web, los sistemas de gestión de relaciones con clientes (CRM) y los servicios de uso compartido de archivos en línea. SaaS requiere el menor esfuerzo técnico, pero ofrece el menor control sobre el funcionamiento del software.

El modelo de responsabilidad compartida se deriva de estas capas. En todos los modelos el proveedor protege la infraestructura física, y en todos los modelos el cliente sigue siendo responsable de sus datos y de quién tiene acceso a ellos. Con IaaS el cliente también parchea el sistema operativo; con PaaS lo hace el proveedor. Una analogía sencilla: IaaS es rentar una cocina vacía y cocinar tú mismo, PaaS es una cocina con cocineros e ingredientes listos mientras tú aportas la receta, y SaaS es pedir un platillo terminado. Algunas fuentes agregan otros modelos como servicio, pero IaaS, PaaS y SaaS son los tres en los que se centra el examen.

Términos clave

IaaS
Infrastructure as a service: máquinas virtuales, almacenamiento y redes rentados; el cliente administra el sistema operativo y lo que está por encima.
PaaS
Platform as a service: una plataforma administrada en la que el cliente aporta solo el código de la aplicación y los datos.
SaaS
Software as a service: una aplicación completa ofrecida a través de internet por suscripción.
Shared responsibility model (modelo de responsabilidad compartida)
La división de las tareas de seguridad y administración entre el proveedor de nube y el cliente.
Ejemplo real

Una pequeña empresa reemplaza su servidor de correo local por una suscripción de correo basado en web (SaaS). Sus desarrolladores implementan un nuevo portal para clientes subiendo el código a una plataforma de aplicaciones administrada (PaaS). Un antiguo servidor de inventario que necesita una configuración de sistema operativo específica se traslada a una máquina virtual rentada en la nube (IaaS), donde el equipo de TI sigue aplicando los parches del sistema operativo.

Consejo para el examen: Pregunta quién parchea el sistema operativo: el cliente en IaaS, el proveedor en PaaS y SaaS. En SaaS el cliente solo usa la aplicación. Los datos y el acceso siempre son responsabilidad del cliente.

Comprueba lo que sabes

¿En qué modelo de servicio el cliente es responsable de parchear el sistema operativo?

IaaS.

Un equipo de desarrollo quiere implementar código sin administrar servidores ni sistemas operativos. ¿Qué modelo encaja?

PaaS.

El correo basado en web que se usa mediante un navegador por suscripción es un ejemplo de, ¿qué modelo?

SaaS.
