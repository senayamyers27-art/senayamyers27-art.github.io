Modelos de servicio en la nube: IaaS, PaaS, SaaS

Los modelos de servicio en la nube describen qué administra el proveedor de nube por ti y qué sigues administrando tú. Piensa en una pila de capas: el centro de datos físico, la red, el almacenamiento, los servidores y la virtualización en la base; luego el sistema operativo y el middleware; y luego el runtime, las aplicaciones y los datos en la parte superior. Cada modelo de servicio entrega al proveedor una parte diferente de esa pila. Cuanto más administra el proveedor, menos control tienes y menos trabajo haces.

IaaS (infraestructura como servicio) te da recursos de cómputo virtualizados: máquinas virtuales, almacenamiento y red. El proveedor administra el hardware físico, las instalaciones, la red y el hipervisor. Tú administras todo desde el sistema operativo hacia arriba, lo que incluye instalar actualizaciones, configurar firewalls, instalar aplicaciones y proteger tus datos. IaaS ofrece el mayor control y flexibilidad de los tres y se adapta a organizaciones que quieren mover servidores existentes a la nube sin rediseñarlos, lo que a menudo se llama lift and shift. Algunos ejemplos son las máquinas virtuales de Amazon EC2, Azure Virtual Machines y Google Compute Engine.

PaaS (plataforma como servicio) proporciona una plataforma lista para usar para crear y ejecutar aplicaciones. El proveedor administra la infraestructura más el sistema operativo, el runtime y el middleware, como los servidores web y los motores de bases de datos. Tú subes tu código y administras tu aplicación y tus datos, sin aplicar parches a servidores ni sistemas operativos. PaaS se adapta a desarrolladores que quieren concentrarse en escribir software en lugar de mantener servidores. Algunos ejemplos son Azure App Service, Google App Engine y Heroku, así como los servicios de bases de datos administradas. La contrapartida es menos control: trabajas dentro de los lenguajes, versiones y configuraciones que admite la plataforma.

SaaS (software como servicio) entrega una aplicación completa a través de internet, normalmente mediante un navegador web o una aplicación cliente ligera. El proveedor administra todo: la infraestructura, la plataforma y la propia aplicación, incluidas las actualizaciones y la disponibilidad. Tú simplemente usas el software y administras tus propios datos, cuentas de usuario y configuración. Microsoft 365, Google Workspace, Salesforce y el correo electrónico basado en web son ejemplos conocidos. SaaS requiere el menor esfuerzo técnico por parte del cliente y normalmente se paga por usuario mediante suscripción. La contrapartida es que aceptas las funciones, el calendario de actualizaciones y las opciones de configuración del proveedor, y dependes de la disponibilidad del proveedor.

El modelo de responsabilidad compartida se deriva de estas capas. La seguridad de la nube, es decir, los centros de datos físicos y la infraestructura del proveedor, siempre es tarea del proveedor. La seguridad en la nube depende del modelo. En IaaS aplicas parches al sistema operativo y configuras la seguridad; en PaaS proteges tu código y tus datos; en SaaS sigues controlando quién tiene acceso, qué tan fuerte es su autenticación y cómo se comparten tus datos. El cliente siempre es responsable de sus datos y de administrar sus propios usuarios. Muchos incidentes de seguridad en la nube no provienen de fallas del proveedor sino de configuraciones erróneas del cliente, como almacenamiento abierto al público o cuentas sin autenticación multifactor, y por eso importa entender tu parte del modelo.

Veamos un ejemplo práctico. Una pequeña empresa tiene tres necesidades. Quiere correo electrónico y aplicaciones de oficina sin operar servidores, así que se suscribe a una suite SaaS. Sus desarrolladores quieren implementar una aplicación web para clientes sin aplicar parches a servidores, así que usan PaaS. También tiene una aplicación de inventario antigua que necesita una configuración específica de sistema operativo, así que la ejecuta en una máquina virtual IaaS que administra ella misma, incluidas las actualizaciones mensuales del sistema operativo y las reglas de firewall.

Errores comunes: pensar que un proveedor SaaS es responsable de las contraseñas débiles de los usuarios o de los archivos compartidos de más; suponer que IaaS significa que el proveedor aplica parches a tu sistema operativo invitado; mezclar los modelos de servicio con los modelos de implementación; y tratar PaaS simplemente como 'hosting', cuando su sentido es que el proveedor mantiene el runtime y el sistema operativo. Una ayuda útil para recordarlo es comparar los modelos con el transporte: IaaS es rentar un auto, que tú manejas y le cargas combustible; PaaS es un taxi, en el que tú eliges el destino; SaaS es un autobús, en el que simplemente viajas.

Las preguntas de examen suelen describir quién hace qué. 'El cliente administra el sistema operativo y las aplicaciones, el proveedor administra el hardware' apunta a IaaS. 'Los desarrolladores implementan código sin administrar servidores' apunta a PaaS. 'Los usuarios acceden a una aplicación terminada en un navegador' apunta a SaaS. 'El mayor control' significa IaaS; 'la menor administración' significa SaaS. 'Quién es responsable del acceso de los usuarios y de los datos' siempre es el cliente.

Términos clave

IaaS
Infraestructura como servicio (infrastructure as a service), que proporciona máquinas virtuales, almacenamiento y red mientras el cliente administra el sistema operativo y lo que está por encima.
PaaS
Plataforma como servicio (platform as a service), que proporciona un runtime y un sistema operativo administrados para que los clientes implementen solo código y datos.
SaaS
Software como servicio (software as a service), que proporciona una aplicación completa administrada en su totalidad por el proveedor.
Modelo de responsabilidad compartida (shared responsibility model)
La división de las tareas de seguridad y administración entre el proveedor de nube y el cliente, que varía según el modelo de servicio.
Lift and shift
Mover servidores existentes a VM en la nube con poco o ningún rediseño, normalmente usando IaaS.
Middleware
Software como los servidores web y los motores de bases de datos que se ubica entre el sistema operativo y las aplicaciones.
Ejemplo real

Una startup mueve su portal de clientes a la nube. Al principio renta máquinas virtuales IaaS y dedica horas cada mes a aplicar parches a los sistemas operativos. Luego traslada el portal a una oferta PaaS, de modo que el proveedor mantiene el sistema operativo y el runtime mientras los desarrolladores solo implementan código. Para el correo electrónico y la colaboración en documentos, la empresa usa una suite SaaS y administra solo las cuentas de usuario, la autenticación multifactor y la configuración de uso compartido.

Consejo para el examen: Recuerda las capas: IaaS significa que administras el sistema operativo y lo que está encima, PaaS significa que administras solo tu código y tus datos, SaaS significa que solo usas la aplicación. Sea cual sea el modelo, el cliente siempre es dueño de sus datos y del acceso de sus usuarios.

Comprueba lo que sabes

En IaaS, ¿quién es responsable de aplicar parches al sistema operativo?

El cliente, porque el proveedor administra solo el hardware, la red y la capa de virtualización.

Un equipo de desarrollo quiere implementar código sin administrar servidores ni sistemas operativos. ¿Qué modelo encaja?

PaaS.

¿Qué modelo de servicio le da al cliente el mayor control y cuál el menor?

IaaS da el mayor control; SaaS da el menor.

Con SaaS, ¿quién es responsable de exigir una autenticación fuerte a los usuarios de la empresa?

El cliente, que administra sus propias cuentas, accesos y datos aunque el proveedor opere la aplicación.
