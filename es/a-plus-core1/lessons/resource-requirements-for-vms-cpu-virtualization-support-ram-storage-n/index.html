CompTIA A+ Core 1 220-1201

Requisitos de recursos para VM: soporte de virtualización en la CPU, RAM, almacenamiento, red (NAT, puente, interna)

Toda VM (máquina virtual) usa hardware real de su anfitrión, así que planificar los recursos es parte de configurarla. Si les das muy poco a las VM, funcionan lento; si les das demasiado, el propio anfitrión sufre. El examen espera que conozcas los requisitos de CPU, memoria, almacenamiento y red, y que elijas el modo de red virtual adecuado para cada situación.

La CPU debe admitir virtualización asistida por hardware, Intel VT-x o AMD-V, y esta debe estar habilitada en el firmware. Muchos hipervisores también se benefician de SLAT (traducción de direcciones de segundo nivel), conocida como Intel EPT o AMD RVI, que acelera el manejo de la memoria para los invitados. A cada VM le asignas una cantidad de CPU virtuales (vCPU). Puedes repartir en total más vCPU de los núcleos físicos que tiene el anfitrión, porque no todas las VM están ocupadas a la vez, pero sobreasignar demasiado vuelve todo lento. Un anfitrión con más núcleos e hilos puede ejecutar más VM con fluidez. Revisa también los requisitos mínimos del propio sistema operativo invitado, porque una VM que recibe menos de lo que necesita el sistema operativo se instalará mal o no se instalará.

La RAM suele ser el recurso más ajustado. Cada VM necesita suficiente memoria para su propio sistema operativo y aplicaciones, y el anfitrión necesita que le quede suficiente para sí mismo y para el hipervisor. Un hábito útil es sumar la RAM de todas las VM que ejecutarás al mismo tiempo más las necesidades del anfitrión, y luego agregar margen. Algunos hipervisores admiten memoria dinámica, que ajusta hacia arriba y hacia abajo la asignación de una VM según la demanda. Cuando el anfitrión se queda sin memoria física, empieza a paginar al disco y todas las VM se ralentizan drásticamente. El Administrador de tareas o la vista de rendimiento del propio hipervisor muestra cuánta memoria usan realmente cada VM y el anfitrión.

El almacenamiento guarda los archivos de disco virtual de cada VM, y algunos hipervisores también guardan junto a ellos las instantáneas, la configuración y el estado de memoria guardado. Los discos virtuales pueden ser de tamaño fijo, que reserva todo el espacio desde el principio para un rendimiento más estable, o de expansión dinámica (thin provisioned), que crece a medida que se escriben datos y ahorra espacio al principio pero puede llenar inesperadamente la unidad del anfitrión. Coloca las VM en almacenamiento rápido, como un SSD, para un buen rendimiento, y vigila el espacio libre, porque una unidad del anfitrión llena puede impedir que las VM funcionen. Las instantáneas también consumen espacio a medida que se acumulan los cambios.

La red permite que las VM se comuniquen con el anfitrión, entre sí y con el mundo exterior. Con NAT (traducción de direcciones de red), la VM comparte la dirección IP del anfitrión; puede llegar a internet y a la red local, pero los dispositivos externos no pueden iniciar conexiones hacia ella con facilidad. Suele ser el modo predeterminado y sirve para navegación general o actualizaciones. La red en modo puente (bridged) conecta la VM directamente a la red física como si fuera una computadora separada, así que obtiene su propia dirección IP del servidor DHCP (Dynamic Host Configuration Protocol) de la red y otros dispositivos pueden alcanzarla. Usa el modo puente para una VM que funciona como servidor. La red interna, a veces llamada privada, permite que las VM se comuniquen solo entre sí, y en algunos hipervisores un modo solo anfitrión (host-only) agrega al anfitrión. La red interna es ideal para laboratorios de prueba aislados y análisis de malware.

Veamos un ejemplo práctico. La laptop de una estudiante tiene 16 GB de RAM y una CPU de cuatro núcleos, y ella quiere ejecutar una VM de Windows Server y una VM cliente de Windows para un laboratorio de dominio. Confirmas que VT-x está habilitado, le das a cada VM dos vCPU y 4 GB de RAM, dejando 8 GB para el anfitrión, y guardas ambos discos en el SSD como de expansión dinámica. Como el laboratorio no debe filtrarse a la red del campus, conectas ambas VM a una red interna, y luego agregas un adaptador NAT al servidor solo cuando necesita actualizaciones.

Errores comunes: asignar toda la RAM del anfitrión a los invitados sin dejar nada para el anfitrión; olvidar que los discos de expansión dinámica pueden llenar la unidad del anfitrión; elegir NAT para una VM a la que otras computadoras deben llegar como servidor; elegir el modo puente para un laboratorio de malware que debería estar aislado; y culpar al hipervisor cuando simplemente VT-x o AMD-V está deshabilitado en el firmware.

Las preguntas de examen relacionan necesidades con configuraciones. 'Otras PC deben conectarse a la VM' o 'la VM necesita su propia IP en la LAN' significa modo puente. 'La VM necesita internet pero debe compartir la dirección del anfitrión' significa NAT. 'Las VM solo deben comunicarse entre sí' significa red interna o privada. 'El anfitrión se vuelve lentísimo con varias VM en ejecución' significa RAM insuficiente. 'La VM no inicia, virtualización no disponible' significa habilitar VT-x o AMD-V.

Términos clave

vCPU
Un procesador virtual asignado a una VM, respaldado por los núcleos e hilos físicos del anfitrión.
SLAT
Traducción de direcciones de segundo nivel (second level address translation), una función de la CPU (Intel EPT, AMD RVI) que acelera el manejo de memoria para las VM.
Disco de expansión dinámica (dynamically expanding disk)
Un disco virtual que crece a medida que se escriben datos en lugar de reservar todo su espacio desde el principio.
Red NAT
Un modo de red de VM en el que la VM comparte la dirección IP del anfitrión para llegar a redes externas.
Red en modo puente (bridged)
Un modo de red de VM que conecta la VM directamente a la red física con su propia dirección IP.
Red interna (internal)
Un modo de red de VM que permite que las VM se comuniquen solo entre sí, aisladas de las redes externas.
Ejemplo real

Una técnica configura una VM de servidor web en un anfitrión con 32 GB de RAM. Confirma que AMD-V está habilitado, le da a la VM cuatro vCPU y 8 GB de RAM, y guarda su disco virtual de tamaño fijo en el SSD del anfitrión. Elige la red en modo puente para que la VM obtenga su propia dirección IP del servidor DHCP de la oficina y otras computadoras puedan acceder a ella desde el navegador, y verifica que el anfitrión conserve suficiente memoria y espacio en disco libres.

Consejo para el examen: NAT comparte la dirección del anfitrión (la salida funciona, la entrada es difícil); el modo puente le da a la VM su propia dirección en la LAN (úsalo para servidores); la red interna aísla las VM de todo lo demás (úsala para laboratorios). Deja RAM para el anfitrión.

Comprueba lo que sabes

¿Qué modo de red de VM debes usar si otras computadoras de la LAN necesitan conectarse a una VM que funciona como servidor?

El modo puente, porque le da a la VM su propia dirección IP en la red física.

¿Qué le pasa al anfitrión si asignas demasiada RAM a las VM en ejecución?

El anfitrión se queda corto de memoria, pagina al disco y se ralentiza, arrastrando consigo a todas sus VM.

¿Qué modo de red aísla un laboratorio de análisis de malware del resto de la red?

La red interna (privada), que permite que las VM se comuniquen solo entre sí.

¿Cuál es el riesgo de los discos virtuales de expansión dinámica?

Crecen a medida que se escriben datos y pueden llenar inesperadamente la unidad del anfitrión, impidiendo que las VM funcionen.
