CompTIA A+ Core 1 220-1201

Requisitos de recursos para VM: soporte de virtualización en la CPU, RAM, almacenamiento, red (NAT, puente, interna)

Cada máquina virtual consume recursos de hardware reales del host. Planificar una VM significa asegurarse de que el host tenga suficiente capacidad de CPU, memoria y almacenamiento para sí mismo más cada invitado que se ejecutará al mismo tiempo, y elegir un modo de red que dé a la VM el tipo de acceso adecuado.

Empieza por la CPU. Los hipervisores modernos dependen de la virtualización asistida por hardware, identificada como Intel VT-x o AMD-V, que el procesador debe admitir y que debe estar habilitada en la configuración de UEFI o BIOS. La traducción de direcciones de segundo nivel (Second Level Address Translation: Intel EPT o AMD RVI) mejora aún más el rendimiento de la memoria y algunos hipervisores la exigen. A cada VM le asignas un número de CPU virtuales (vCPU). Un host puede ejecutar más vCPU en total que núcleos físicos porque no todas las VM están ocupadas a la vez, pero sobreasignar demasiado vuelve lentas todas las VM. Más núcleos en el host te permiten ejecutar más VM con holgura.

La RAM suele ser el primer límite que encuentras. Cada VM en ejecución necesita su propia asignación de memoria, lo bastante grande para su sistema operativo invitado y sus aplicaciones, y el sistema operativo anfitrión o el hipervisor también necesita su parte. Por ejemplo, un host con 16 GB que ejecuta Windows más dos VM de 4 GB cada una deja poco espacio para el propio host. Algunos hipervisores admiten memoria dinámica, que ajusta la asignación de una VM a medida que cambia la demanda, pero aun así necesitas suficiente RAM física en total. Si el host se queda corto, paginará al disco y todo se volverá drásticamente lento.

El almacenamiento de una VM es un archivo de disco virtual en el host, como VHD o VHDX para Hyper-V, VMDK para VMware y VDI para VirtualBox. Un disco de expansión dinámica, o con aprovisionamiento ligero (thin provisioning), empieza pequeño y crece a medida que se escriben datos, lo que ahorra espacio. Un disco de tamaño fijo, o con aprovisionamiento grueso (thick provisioning), asigna todo su tamaño desde el principio, lo que puede rendir un poco mejor y evita quedarse sin espacio en el host de forma inesperada. Las instantáneas también consumen espacio en disco. Colocar los archivos de las VM en un SSD rápido mejora mucho el rendimiento.

La red virtual ofrece varios modos, y los nombres varían un poco entre productos. El modo NAT permite que la VM comparta la dirección IP del host: la VM puede llegar a la red del host y a internet, pero los dispositivos de la red no pueden iniciar conexiones hacia ella fácilmente. Es el valor predeterminado habitual y la opción más sencilla. El modo puente (bridged) conecta la VM directamente a la red física como si fuera una computadora aparte, así que obtiene su propia dirección IP del servidor DHCP de la red y otros dispositivos pueden llegar a ella; úsalo para una VM que ejecuta un servidor al que otros deben acceder. La red interna permite que las VM se comuniquen solo entre sí en una red virtual aislada sin acceso externo, lo cual es ideal para pruebas de seguridad y laboratorios de malware. Algunos hipervisores también ofrecen la red solo con el host (host-only), en la que las VM pueden comunicarse entre sí y con el host, pero no con la red más amplia.

Términos clave

vCPU
Un procesador virtual asignado a una VM y programado sobre los núcleos físicos del host.
NAT mode (modo NAT)
Un modo de red de VM en el que el invitado comparte la dirección IP del host para llegar a redes externas.
Bridged mode (modo puente)
Un modo de red de VM en el que el invitado aparece en la red física con su propia dirección IP.
Internal network (red interna)
Un modo de red de VM que permite a los invitados comunicarse solo entre sí, aislados de las redes externas.
Thin provisioning (aprovisionamiento ligero)
Crear un disco virtual que crece a medida que se escriben datos en lugar de asignar todo su tamaño desde el principio.
Ejemplo real

Un desarrollador ejecuta un servidor web en una VM en modo NAT, y sus colegas no pueden llegar a él desde sus PC. Cambiar el adaptador de la VM a modo puente le da una dirección del servidor DHCP de la oficina, y ahora el equipo puede navegar hasta ella directamente. Una VM aparte para análisis de malware permanece en una red interna sin acceso externo.

Consejo para el examen: NAT: la VM sale, pero los de afuera no pueden entrar fácilmente. Puente: la VM es un par completo en la LAN con su propia IP. Interna: las VM solo se comunican entre sí. Si una VM no inicia, revisa VT-x o AMD-V en el firmware; si todo es lento, revisa la RAM del host.

Comprueba lo que sabes

¿Qué modo de red de VM debes elegir para que otras computadoras de la LAN puedan conectarse a un servidor que se ejecuta en la VM?

El modo puente (bridged), que le da a la VM su propia dirección en la red física.

¿Qué ajuste debe estar habilitado en el firmware para que la mayoría de los hipervisores modernos ejecuten VM?

El soporte de virtualización por hardware: Intel VT-x o AMD-V.

¿Cuál es la ventaja de un disco virtual de expansión dinámica?

Usa solo el almacenamiento del host que el invitado realmente ha escrito, ahorrando espacio hasta que se necesita.
