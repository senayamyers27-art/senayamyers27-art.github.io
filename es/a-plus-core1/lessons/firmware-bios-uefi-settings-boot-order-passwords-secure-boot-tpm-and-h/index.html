CompTIA A+ Core 1 220-1201

Firmware: configuración de BIOS/UEFI, orden de arranque, contraseñas, Secure Boot, TPM y HSM, soporte de virtualización, monitoreo de ventiladores y temperatura

El firmware es el software de bajo nivel almacenado en un chip de la placa base que inicia la computadora antes de que se cargue el sistema operativo. Ejecuta la POST (power-on self-test, autoprueba de encendido), inicializa el hardware y luego entrega el control a un cargador de arranque. El estándar antiguo era BIOS (Basic Input/Output System). Los sistemas modernos usan UEFI (Unified Extensible Firmware Interface), que admite unidades grandes particionadas con GPT (GUID partition table), un arranque más rápido, una pantalla de configuración gráfica con soporte para mouse y funciones de seguridad como Secure Boot. Mucha gente sigue llamando BIOS a la configuración de UEFI.

Entras a la configuración del firmware presionando una tecla durante el arranque, a menudo Delete, F2, F10 o Esc según el fabricante, o desde las opciones de inicio avanzado de Windows. Los ajustes comunes incluyen la fecha y la hora, que mantiene la batería CMOS de la placa base, habilitar o deshabilitar dispositivos integrados como el audio o los puertos de red, y el modo del controlador de almacenamiento. El orden de arranque (boot order) define qué dispositivos intenta el sistema primero, como el SSD interno, una unidad USB o el arranque por red (PXE). Para instalar un sistema operativo desde una unidad USB, coloca USB por encima de la unidad interna o usa el menú de arranque de una sola vez.

Las contraseñas del firmware agregan una capa de protección. Una contraseña de supervisor o administrador impide cambios no autorizados en la configuración del firmware. Una contraseña de usuario o de encendido debe ingresarse antes de que el sistema arranque siquiera. Algunos sistemas también admiten una contraseña de unidad. Estas protegen contra alguien que cambie el orden de arranque para iniciar su propio sistema operativo y eludir la seguridad de Windows.

Secure Boot es una función de UEFI que verifica las firmas digitales de los cargadores de arranque y controladores frente a claves de confianza guardadas en el firmware, y bloquea la ejecución al arrancar de código sin firmar o alterado, como el malware del sector de arranque. Algunos sistemas operativos o herramientas antiguos pueden requerir que Secure Boot esté desactivado. Un TPM (Trusted Platform Module) es un procesador criptográfico seguro, ya sea un chip en la placa o integrado en el firmware de la CPU, que almacena claves de cifrado y mide el proceso de arranque. El cifrado de unidades BitLocker usa el TPM para proteger sus claves, y Windows 11 requiere TPM 2.0. Un HSM (hardware security module, módulo de seguridad de hardware) es un dispositivo dedicado, a menudo externo o conectado a la red, que usan las organizaciones para generar y proteger grandes cantidades de claves criptográficas, por ejemplo para autoridades de certificación y sistemas de pago.

El soporte de virtualización debe habilitarse en el firmware antes de que los hipervisores puedan usar las funciones de virtualización por hardware de la CPU, identificadas como Intel VT-x o AMD-V (a veces SVM). Si una máquina virtual no inicia e informa que la virtualización no está disponible, revisa primero este ajuste. El firmware también muestra el monitoreo del hardware: temperaturas de la CPU y del sistema, velocidades de los ventiladores y voltajes. Puedes configurar curvas de ventilador para que los ventiladores aceleren cuando suben las temperaturas y configurar alertas o umbrales de apagado. Después de cambiar la configuración del firmware, guarda y sal para que los cambios surtan efecto.

Términos clave

UEFI
Unified Extensible Firmware Interface, el reemplazo moderno de BIOS que admite unidades GPT y Secure Boot.
Secure Boot
Una función de UEFI que permite que solo se ejecuten al arrancar cargadores de arranque y controladores firmados y de confianza.
TPM
Trusted Platform Module, un procesador criptográfico seguro que almacena claves y admite funciones como BitLocker.
HSM
Hardware security module, un dispositivo dedicado para generar y proteger claves criptográficas a gran escala.
Boot order (orden de arranque)
La secuencia de dispositivos que el firmware prueba al buscar un sistema operativo para iniciar.
Ejemplo real

Un desarrollador instala un hipervisor, pero la máquina virtual se niega a iniciar con un mensaje de que la virtualización por hardware está deshabilitada. Reinicias y entras a la configuración de UEFI, habilitas Intel VT-x en el menú de configuración de la CPU, guardas y sales, y la VM inicia con normalidad.

Consejo para el examen: Conoce qué ajuste resuelve qué síntoma: la VM no inicia significa habilitar VT-x o AMD-V; no se puede arrancar desde USB significa cambiar el orden de arranque o usar el menú de arranque; la actualización a Windows 11 bloqueada a menudo significa que TPM 2.0 o Secure Boot están desactivados; el reloj se reinicia significa la batería CMOS.

Comprueba lo que sabes

¿Contra qué protege Secure Boot?

Contra la ejecución durante el arranque de cargadores de arranque y controladores sin firmar o alterados, como el malware a nivel de arranque.

¿En qué se diferencia un TPM de un HSM?

Un TPM está integrado en una sola computadora para proteger sus claves; un HSM es un dispositivo dedicado para administrar muchas claves de una organización o aplicación.

¿Qué contraseña del firmware impide que el sistema arranque en absoluto sin ella?

La contraseña de usuario o de encendido.
