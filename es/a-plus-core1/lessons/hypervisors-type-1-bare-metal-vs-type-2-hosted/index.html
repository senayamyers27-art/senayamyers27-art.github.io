Hipervisores: Tipo 1 (bare metal) vs. Tipo 2 (alojado)

Un hipervisor, también llamado monitor de máquinas virtuales (VMM, virtual machine monitor), es el software que crea y ejecuta máquinas virtuales. Se ubica entre el hardware físico y los sistemas operativos invitados, le da a cada VM su parte de tiempo de CPU, memoria, almacenamiento y acceso a la red, y mantiene las VM aisladas entre sí. Como controla a todos los invitados del anfitrión, también es la pieza de software más importante de mantener con parches y protegida. El examen divide los hipervisores en dos tipos según dónde se ejecutan, y necesitas reconocer cada uno a partir de una descripción.

Un hipervisor Tipo 1, también llamado bare metal o nativo, se instala directamente sobre el hardware físico en lugar de un sistema operativo normal. Controla el propio hardware y ejecuta las VM encima. Como no hay un sistema operativo anfitrión completo de por medio, los hipervisores Tipo 1 son eficientes, estables y seguros, y son el estándar en centros de datos y proveedores de nube. Ejemplos conocidos incluyen VMware ESXi, Microsoft Hyper-V, Xen y KVM (Kernel-based Virtual Machine), que está integrado en el kernel de Linux. Los anfitriones Tipo 1 normalmente se administran de forma remota mediante una consola web o una herramienta de administración central, en lugar de sentarse frente al servidor.

Un hipervisor Tipo 2, también llamado alojado (hosted), se ejecuta como una aplicación sobre un sistema operativo normal como Windows, macOS o Linux. Lo instalas como cualquier otro programa y creas VM dentro de él. Ejemplos incluyen Oracle VirtualBox, VMware Workstation, VMware Fusion en macOS y Parallels Desktop. Los hipervisores Tipo 2 son fáciles de configurar e ideales para equipos de escritorio y laptops, donde un técnico, estudiante o desarrollador quiere ejecutar algunas VM junto con su trabajo normal. La VM aparece en una ventana del escritorio, y funciones como las carpetas compartidas, el portapapeles compartido y las instantáneas sencillas la hacen práctica para pruebas, capacitación y para ejecutar ocasionalmente un programa hecho para otro sistema operativo.

La contrapartida es el rendimiento y la sobrecarga. Un hipervisor Tipo 2 debe pasar por el sistema operativo anfitrión para acceder al hardware, lo que agrega sobrecarga, y el propio sistema operativo anfitrión consume recursos y debe recibir parches. Si el sistema operativo anfitrión falla o se reinicia por actualizaciones, todas las VM se detienen con él. El Tipo 1 evita esa capa, así que se elige para servidores de producción que deben ejecutar muchas VM de forma confiable. Ambos tipos dependen del soporte de virtualización por hardware, Intel VT-x o AMD-V, habilitado en el firmware. En resumen, elige Tipo 1 cuando importan la disponibilidad, la densidad y el rendimiento, y Tipo 2 cuando importa más la comodidad en una computadora de uso diario.

Microsoft Hyper-V merece una nota porque genera confusión. Cuando habilitas la característica Hyper-V en Windows, Hyper-V se instala por debajo de Windows, y el propio Windows pasa a ejecutarse como una partición privilegiada encima de él. Eso convierte a Hyper-V en un hipervisor Tipo 1, aunque lo hayas activado desde dentro de Windows. Hyper-V de cliente está disponible en las ediciones Pro, Enterprise y Education de Windows, no en Home. Habilitarlo también puede afectar a otros hipervisores Tipo 2 en la misma computadora, que entonces pueden funcionar más lento o necesitar un cambio de configuración para convivir con él.

Veamos un ejemplo práctico. Una pequeña empresa quiere consolidar tres servidores envejecidos, un servidor de archivos, un servidor de base de datos y un controlador de dominio, en una sola máquina nueva. Instalas un hipervisor Tipo 1 directamente en el servidor nuevo, creas tres VM y migras cada carga de trabajo, administrándolas desde una consola web. Por otro lado, una técnica de mesa de ayuda quiere practicar comandos de Linux en su laptop con Windows, así que instala un hipervisor Tipo 2 como VirtualBox y ejecuta una VM de Linux en una ventana junto a su correo.

Errores comunes: pensar que Tipo 1 significa 'primero' o 'mejor para todo', cuando simplemente significa que se ejecuta sobre el hardware; llamar Tipo 2 a Hyper-V porque lo habilitas desde Windows; suponer que los hipervisores Tipo 2 no necesitan VT-x o AMD-V; y olvidar que la disponibilidad de un invitado Tipo 2 depende del sistema operativo anfitrión. Tampoco confundas un hipervisor con un motor de contenedores, que comparte un solo kernel de sistema operativo en lugar de ejecutar invitados completos.

Las preguntas de examen dependen de unas pocas palabras clave. 'Instalado directamente en el hardware', 'bare metal', 'centro de datos' o 'sin sistema operativo anfitrión' apunta a Tipo 1. 'Se ejecuta como aplicación en Windows o macOS', 'alojado', 'pruebas en una laptop' apunta a Tipo 2. 'El mejor rendimiento para servidores de producción' apunta a Tipo 1. 'La VM no inicia, virtualización no disponible' apunta a habilitar VT-x o AMD-V en el firmware, sea cual sea el tipo que se use.

Términos clave

Hipervisor (hypervisor)
Software que crea, ejecuta y aísla máquinas virtuales repartiendo entre ellas el hardware físico.
Hipervisor Tipo 1
Un hipervisor bare metal instalado directamente en el hardware, usado en centros de datos y servidores.
Hipervisor Tipo 2
Un hipervisor alojado que se ejecuta como aplicación sobre un sistema operativo normal.
Bare metal
Ejecución directa sobre el hardware físico, sin un sistema operativo de uso general debajo.
KVM
Kernel-based Virtual Machine, un hipervisor Tipo 1 integrado en el kernel de Linux.
VT-x / AMD-V
Funciones de virtualización por hardware de Intel y AMD que deben habilitarse en el firmware para los hipervisores.
Ejemplo real

Una empresa de capacitación necesita que cada laptop de los estudiantes ejecute una VM de Windows Server y una VM de Linux durante la clase. Instalas un hipervisor Tipo 2 en cada laptop, confirmas que VT-x o AMD-V está habilitado en el firmware e implementas imágenes de VM preparadas. Mientras tanto, los servidores de archivos y web de la propia empresa se ejecutan como VM en un hipervisor Tipo 1 en su sala de servidores, administrados desde una consola central.

Consejo para el examen: El Tipo 1 se ejecuta sobre el hardware (bare metal) y es para servidores y centros de datos; el Tipo 2 se ejecuta sobre un sistema operativo y es para equipos de escritorio y pruebas. Hyper-V es Tipo 1 aunque se habilite desde Windows.

Comprueba lo que sabes

¿Cuál es la diferencia clave entre un hipervisor Tipo 1 y uno Tipo 2?

El Tipo 1 se ejecuta directamente sobre el hardware; el Tipo 2 se ejecuta como aplicación sobre un sistema operativo anfitrión.

¿Qué tipo de hipervisor es el más adecuado para un centro de datos que ejecuta muchas VM de producción, y por qué?

El Tipo 1, porque tiene menos sobrecarga y no depende de un sistema operativo anfitrión de uso general, lo que lo hace más eficiente y estable.

Menciona dos ejemplos de hipervisores Tipo 2.

Oracle VirtualBox y VMware Workstation (también VMware Fusion o Parallels Desktop).

¿Por qué reiniciar el sistema operativo anfitrión afecta a las VM de un hipervisor Tipo 2?

El hipervisor es una aplicación de ese sistema operativo, así que cuando el anfitrión se reinicia, todas sus VM se detienen.
