CompTIA A+ Core 1 220-1201

Propósitos de la virtualización: sandbox, pruebas/desarrollo, virtualización de aplicaciones, software y sistemas operativos heredados

La virtualización permite que una computadora física, el anfitrión (host), ejecute una o más máquinas virtuales (VM), llamadas invitados (guests). Cada VM se comporta como una computadora completa con su propia CPU virtual, memoria, disco y tarjeta de red, y ejecuta su propio sistema operativo. Un software llamado hipervisor reparte el hardware real entre ellas. Como una VM se almacena como un conjunto de archivos, se puede copiar, mover a otro anfitrión, respaldar o revertir con mucha más facilidad que una computadora física, y varios servidores poco utilizados se pueden consolidar en un solo anfitrión para ahorrar energía, espacio y costo de hardware. Para A+ necesitas saber por qué las organizaciones virtualizan, porque las preguntas de examen suelen describir un objetivo y preguntar qué enfoque lo cumple.

Un sandbox es un entorno aislado donde puedes ejecutar algo sin arriesgar el anfitrión ni la red. Los equipos de seguridad abren archivos adjuntos sospechosos o programas desconocidos dentro de una VM tipo sandbox y observan lo que hacen. Si el software resulta dañino, descartas la VM o vuelves a una instantánea, y el sistema real queda intacto. Windows incluye Windows Sandbox en algunas ediciones, un escritorio ligero y desechable que se borra cada vez que se cierra. El valor de un sandbox proviene de que es desechable: nada de lo que hagas dentro está pensado para sobrevivir, y nada de su interior debería poder alcanzar tus archivos reales. Por eso, las VM tipo sandbox suelen mantenerse fuera de la red de producción, y se desactivan las funciones que comparten archivos o el portapapeles con el anfitrión.

Los entornos de prueba y desarrollo son otro uso importante. Los desarrolladores pueden crear y probar software en varios sistemas operativos o versiones desde una sola estación de trabajo. El personal de TI puede probar parches, controladores, cambios de configuración y actualizaciones en copias virtuales de los servidores de producción antes de implementarlos, lo que encaja de forma natural con la gestión de cambios. Las instantáneas (snapshots) lo hacen rápido: tomas una instantánea, pruebas el cambio y, si falla, reviertes en segundos y lo intentas de nuevo. Como las VM son solo archivos, puedes clonar todo un laboratorio de máquinas a partir de una plantilla. Los laboratorios de capacitación y certificación funcionan igual, y por eso muchos estudiantes de A+ practican en VM en lugar de hardware de repuesto.

La virtualización de aplicaciones ejecuta una sola aplicación en un paquete aislado en lugar de instalarla normalmente en el sistema operativo. La aplicación puede transmitirse desde un servidor o ejecutarse en una burbuja parecida a un contenedor en el cliente, y el usuario la ve como un programa común. Esto evita conflictos entre aplicaciones que necesitan diferentes versiones del mismo componente, permite a TI entregar y actualizar aplicaciones de forma centralizada y permite que una aplicación siga al usuario en diferentes dispositivos. Es diferente de una VM completa porque solo se virtualiza la aplicación, no todo un sistema operativo.

El software y los sistemas operativos heredados son una razón muy común para virtualizar. Una empresa puede depender de un programa antiguo que solo funciona en un sistema operativo que ya no tiene soporte, o en un hardware que está fallando. Ejecutar ese sistema operativo antiguo como VM en hardware moderno mantiene el programa funcionando. Como un sistema operativo sin soporte ya no recibe actualizaciones de seguridad, la VM debe aislarse de internet y del resto de la red tanto como sea posible, y el plan debe ser reemplazar el software con el tiempo.

Veamos un ejemplo práctico. El programa de citas de una clínica solo funciona en un sistema operativo antiguo, y la PC envejecida donde vive empezó a fallar. En lugar de buscar piezas de repuesto, conviertes la PC en una VM y la ejecutas en una estación de trabajo nueva y con soporte usando un hipervisor. Le das a la VM una red solo interna para que pueda llegar a la base de datos local pero no a internet, tomas una instantánea antes de cualquier cambio y documentas que el software debe reemplazarse dentro del año.

Errores comunes: tratar un sandbox como almacenamiento permanente cuando está diseñado para desecharse; confundir la virtualización de aplicaciones, que aísla una aplicación, con una VM completa; suponer que una VM heredada es segura por ser virtual, cuando un invitado sin parches sigue siendo vulnerable; y olvidar que la virtualización agrega sobrecarga, así que el anfitrión necesita suficiente CPU, RAM y almacenamiento. Otra trampa es pensar que las instantáneas son respaldos; dependen del disco original y están pensadas para revertir a corto plazo.

Las preguntas de examen relacionan objetivos con propósitos. 'Abrir de forma segura un archivo sospechoso' apunta a un sandbox. 'Probar un parche antes de producción' o 'desarrollar en varios sistemas operativos' apunta a pruebas/desarrollo. 'Entregar una aplicación sin instalarla, evitar conflictos de DLL' apunta a la virtualización de aplicaciones. 'Un programa antiguo solo funciona en un sistema operativo obsoleto' apunta a software heredado en una VM. 'Revertir rápidamente después de un cambio fallido' apunta a las instantáneas.

Términos clave

Máquina virtual (virtual machine)
Una computadora basada en software, con su propio hardware virtual y sistema operativo, que se ejecuta en un anfitrión físico.
Anfitrión (host)
La computadora física cuyo hardware se comparte entre las máquinas virtuales.
Invitado (guest)
Un sistema operativo que se ejecuta dentro de una máquina virtual.
Sandbox
Un entorno aislado y desechable para ejecutar software no confiable sin riesgo para el anfitrión.
Virtualización de aplicaciones
Ejecutar una sola aplicación aislada del sistema operativo, a menudo transmitida desde un servidor.
Instantánea (snapshot)
Un estado guardado de una VM en un momento dado al que puedes volver.
Sistema heredado (legacy system)
Un sistema operativo o aplicación antiguo que sigue en uso, a menudo ya sin actualizaciones.
Ejemplo real

Una analista de mesa de ayuda recibe un archivo adjunto de factura inesperado de un remitente desconocido. En lugar de abrirlo en su estación de trabajo, lo copia a una VM sandbox desechable sin acceso a la red de la empresa, lo abre y observa si hay comportamiento inusual. El archivo intenta ejecutar un script, así que lo reporta a seguridad, cierra el sandbox y el entorno se borra sin dejar nada atrás.

Consejo para el examen: Relaciona el objetivo con el propósito: un archivo sospechoso significa sandbox, probar cambios con seguridad significa pruebas/desarrollo, una aplicación sin instalarla significa virtualización de aplicaciones, y un programa antiguo en un sistema operativo obsoleto significa una VM heredada mantenida en aislamiento.

Comprueba lo que sabes

¿Por qué un sandbox es útil para abrir archivos adjuntos sospechosos?

Aísla el archivo del anfitrión y de la red, y el entorno se puede descartar o revertir después.

¿En qué se diferencia la virtualización de aplicaciones de ejecutar una máquina virtual completa?

Aísla o transmite una sola aplicación en lugar de ejecutar todo un sistema operativo invitado.

¿Qué precaución debes tomar al ejecutar un sistema operativo sin soporte en una VM para software heredado?

Aislarlo de internet y de otros sistemas tanto como sea posible, porque ya no recibe actualizaciones de seguridad.

¿Cómo ayudan las instantáneas en un entorno de pruebas?

Puedes guardar el estado de la VM antes de un cambio y volver a él en segundos si el cambio falla.
