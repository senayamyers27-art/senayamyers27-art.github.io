Contenedores vs. máquinas virtuales

Tanto los contenedores como las máquinas virtuales te permiten ejecutar aplicaciones en entornos aislados sobre hardware compartido, pero aíslan en niveles distintos. Entender la diferencia te ayuda a ver por qué las aplicaciones modernas a menudo se empaquetan en contenedores mientras que las VM siguen siendo esenciales para ejecutar sistemas operativos completos.

Una máquina virtual virtualiza el hardware. El hipervisor presenta dispositivos virtuales de CPU, memoria, disco y red, y cada VM ejecuta sobre ellos un sistema operativo invitado completo con su propio kernel. Eso hace que las VM sean pesadas: cada una puede necesitar gigabytes de disco y memoria y tarda un rato en arrancar. A cambio, ofrecen un aislamiento fuerte y flexibilidad. Un host puede ejecutar Windows, Linux y otros sistemas operativos lado a lado, porque cada VM lleva su propio sistema operativo.

Un contenedor, en cambio, virtualiza el sistema operativo. Los contenedores de un host comparten el kernel del sistema operativo del host, y un motor de contenedores, como Docker u otro runtime, usa funciones del kernel para dar a cada contenedor su propia vista aislada de archivos, procesos y red. Una imagen de contenedor empaqueta una aplicación solo con las bibliotecas y configuraciones que necesita, no con un sistema operativo completo. Como resultado, los contenedores son pequeños, a menudo de megabytes en lugar de gigabytes, arrancan en segundos o menos y te permiten meter muchos más en un solo host.

Las principales desventajas se derivan del kernel compartido. Los contenedores deben coincidir con el tipo de kernel del host, así que los contenedores Linux necesitan un kernel Linux; ejecutarlos en Windows o macOS depende de una VM Linux ligera en segundo plano. El aislamiento es más débil que el de una VM porque una vulnerabilidad del kernel podría afectar a todos los contenedores del host, por lo que en entornos de nube los contenedores a menudo se ejecutan dentro de VM para mayor protección. Los contenedores también están diseñados para ser desechables; los datos que deben persistir se guardan en volúmenes fuera del contenedor.

Los contenedores resuelven el clásico problema del software que funciona en una máquina pero no en otra, porque la imagen lleva todo lo que la aplicación necesita y se ejecuta igual en todas partes. Son fundamentales para los microservicios, en los que una aplicación se divide en muchos servicios pequeños, y normalmente se administran a escala con plataformas de orquestación como Kubernetes. Elige una VM cuando necesites un sistema operativo completo, un sistema operativo distinto al del host, un aislamiento fuerte o una aplicación heredada. Elige contenedores cuando quieras una implementación ligera, rápida y portátil de muchas instancias de aplicaciones modernas.

Términos clave

Container (contenedor)
Un paquete ligero y aislado de una aplicación y sus dependencias que comparte el kernel del sistema operativo del host.
Container image (imagen de contenedor)
Una plantilla de solo lectura que empaqueta una aplicación con sus bibliotecas y configuraciones, usada para iniciar contenedores.
Kernel
El núcleo de un sistema operativo que administra el hardware y los procesos; los contenedores comparten el kernel del host.
Orchestration (orquestación)
La administración automatizada de muchos contenedores en varios hosts, por ejemplo con Kubernetes.
Ejemplo real

La aplicación web de un equipo de desarrollo funciona en la laptop de un desarrollador pero falla en el servidor de pruebas por una versión distinta de una biblioteca. Empaquetan la aplicación como una imagen de contenedor que incluye la biblioteca correcta, y ahora se ejecuta de forma idéntica en las laptops, en el servidor de pruebas y en la nube, arrancando en segundos cada vez.

Consejo para el examen: La distinción clave: cada VM tiene su propio sistema operativo y kernel completos sobre un hipervisor; los contenedores comparten el kernel del host mediante un motor de contenedores. Los contenedores son más ligeros y rápidos; las VM aíslan con más fuerza y pueden ejecutar sistemas operativos distintos.

Comprueba lo que sabes

¿Por qué los contenedores arrancan más rápido y ocupan menos espacio que las VM?

Comparten el kernel del host e incluyen solo la aplicación y sus dependencias, no un sistema operativo invitado completo.

¿Cuándo es mejor opción una VM que un contenedor?

Cuando necesitas un sistema operativo completo o distinto, un aislamiento más fuerte o soporte para una aplicación heredada.

¿Qué hace un motor de contenedores como Docker?

Crea y ejecuta contenedores a partir de imágenes, aislándolos mediante funciones del kernel compartido del host.
