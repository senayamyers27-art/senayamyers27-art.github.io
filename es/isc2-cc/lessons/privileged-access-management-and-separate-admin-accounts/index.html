ISC2 Certified in Cybersecurity 2026 outline

Gestión de accesos privilegiados y cuentas de administrador separadas

Algunas cuentas pueden hacer mucho más que otras. Las cuentas de administrador y root pueden instalar software, cambiar la configuración de seguridad, crear usuarios, leer cualquier archivo y borrar registros. Las cuentas de servicio pueden ejecutar aplicaciones críticas con derechos amplios. Estas son cuentas privilegiadas, y los atacantes las buscan porque controlar una a menudo significa controlar todo el entorno. La gestión de accesos privilegiados (PAM, privileged access management) es el conjunto de prácticas y herramientas que protegen, limitan y monitorean estas cuentas.

La primera práctica es separar las cuentas privilegiadas de las de uso diario. Un administrador debe tener una cuenta de usuario normal para el correo, la navegación web y los documentos, y una cuenta de administrador separada que use solo para tareas administrativas. Si el administrador lee el correo o navega por la web con una sesión con todos los derechos, un solo adjunto o sitio web malicioso puede ejecutarse con esos derechos. Con cuentas separadas, la cuenta de uso diario puede ser víctima de phishing sin entregar las llaves del reino. Las cuentas de administrador también deben tener nombres claros, exigir una MFA fuerte y usarse, cuando sea posible, desde estaciones de trabajo protegidas.

La segunda práctica es minimizar los privilegios permanentes (standing privilege). En lugar de mantener derechos de administrador de forma permanente, los usuarios pueden solicitar una elevación para una tarea y un tiempo específicos, lo que se llama acceso justo a tiempo (just-in-time access). Las cuentas integradas y predeterminadas deben renombrarse o deshabilitarse cuando sea posible, y las contraseñas predeterminadas siempre deben cambiarse. En Linux verás esta idea con sudo, que permite a un usuario común ejecutar comandos individuales con derechos elevados y registra cada uso, en lugar de iniciar sesión como root. En Windows, el Control de cuentas de usuario (User Account Control) pide confirmación antes de las acciones que necesitan derechos de administrador.

Las herramientas de PAM agregan más controles. Una bóveda de contraseñas (password vault) almacena las credenciales privilegiadas, las rota automáticamente y las presta (check-out) a los usuarios aprobados, de modo que los administradores nunca necesitan conocer contraseñas de larga duración. La gestión de sesiones puede grabar las sesiones privilegiadas para revisarlas después. Los flujos de aprobación pueden exigir que una segunda persona apruebe los accesos de alto riesgo, lo que apoya la separación de funciones. El acceso de emergencia, a veces mediante cuentas break-glass (romper el cristal), ofrece una forma de entrar si fallan los sistemas normales, pero esas credenciales se protegen estrictamente y cada uso se investiga.

El monitoreo completa el panorama. La actividad privilegiada debe registrarse en un lugar que los administradores no puedan alterar, y deben dispararse alertas ante eventos inusuales, como la creación de una nueva cuenta de administrador o un administrador que inicia sesión a una hora extraña. El número de cuentas privilegiadas también es un indicador clave de riesgo útil: si no deja de crecer, el mínimo privilegio se está deteriorando.

Recuerda que las cuentas de servicio también son privilegiadas. Deben tener solo los derechos que necesita su aplicación, no deben usarse para inicios de sesión interactivos y deben tener dueños y credenciales rotadas.

Términos clave

Privileged account (cuenta privilegiada)
Una cuenta con derechos elevados, como administrador, root o una cuenta de servicio con muchos permisos.
Privileged access management (PAM, gestión de accesos privilegiados)
Prácticas y herramientas para controlar, limitar y monitorear las cuentas privilegiadas.
Just-in-time access (acceso justo a tiempo)
Otorgar privilegios elevados solo cuando se necesitan para una tarea específica y retirarlos después.
Password vault (bóveda de contraseñas)
Un sistema seguro que almacena, rota y controla el préstamo de credenciales privilegiadas.
Break-glass account (cuenta de emergencia)
Una cuenta de emergencia estrictamente controlada que solo se usa cuando fallan los métodos normales de acceso.
Ejemplo real

Una técnica de TI normalmente inicia sesión como j.lee para el correo y los tickets. Cuando necesita cambiar una configuración de un servidor, retira de la bóveda las credenciales de su cuenta de administrador separada, aprueba un aviso de MFA y hace el trabajo. La sesión queda grabada, la contraseña se rota después, y un correo de phishing que abrió más temprano ese día no pudo alcanzar los derechos de administrador.

Consejo para el examen: Los administradores nunca deben usar su cuenta privilegiada para tareas diarias como el correo y la navegación web. Cuentas separadas más MFA y registro de eventos es la mejor respuesta esperada.

Comprueba lo que sabes

¿Por qué los administradores deben tener una cuenta separada para el trabajo administrativo?

Para que las actividades diarias como el correo y la navegación, que están expuestas al phishing y al malware, no se ejecuten con privilegios completos.

¿Qué hace una bóveda de contraseñas en una solución de PAM?

Almacena de forma segura las credenciales privilegiadas, controla quién puede retirarlas y las rota automáticamente.

¿Cuál es el beneficio de seguridad del acceso justo a tiempo?

Reduce los privilegios permanentes, de modo que los derechos elevados existen solo brevemente y están menos disponibles para los atacantes.
