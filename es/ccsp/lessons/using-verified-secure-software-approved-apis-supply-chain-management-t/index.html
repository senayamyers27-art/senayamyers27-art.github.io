ISC2 Certified Cloud Security Professional 2026 outline (effective Aug 1, 2026)

Uso de software seguro verificado: API aprobadas, gestión de la cadena de suministro y componentes de terceros y de código abierto

Las aplicaciones modernas en la nube se ensamblan más de lo que se escriben. Un servicio típico combina el código propio del equipo con decenas o cientos de paquetes de código abierto, imágenes base de contenedores, SDK del proveedor y API de terceros. Cada uno es una decisión de confianza, y los atacantes apuntan cada vez más a la cadena de suministro porque comprometer un componente popular puede alcanzar a miles de víctimas.

Las API aprobadas son interfaces que la organización revisó y permitió. Revisar una API significa verificar cómo autentica a quienes la llaman, si cifra el tráfico, qué datos recibe y devuelve, los límites de tasa, el registro, la postura de seguridad y los términos contractuales del proveedor, y qué pasa si cambia o desaparece. Mantener un catálogo de API aprobadas y bloquear las no aprobadas evita que los desarrolladores envíen datos sensibles a servicios desconocidos. Internamente, publica tus propias API mediante una puerta de enlace (gateway) que aplique autenticación y límites de tasa.

La gestión de la cadena de suministro aplica a los proveedores de software y al propio proceso de compilación. Para los proveedores, evalúa sus prácticas de desarrollo seguro, pide evidencia como SBOM o atestaciones y pon obligaciones de seguridad en los contratos. Para tu propio flujo, protégelo como un sistema de producción: restringe quién puede cambiar las definiciones de compilación, fija las versiones de las dependencias, obtén los paquetes de un repositorio o proxy interno curado en lugar de directamente de los registros públicos, verifica firmas y sumas de verificación, firma los artefactos que produces y registra su procedencia. Marcos como el Secure Software Development Framework de NIST y los niveles SLSA describen estas prácticas.

Los componentes de código abierto no son menos seguros por naturaleza, pero necesitan gestión. Rastréalos con análisis de composición de software, vigila las nuevas vulnerabilidades, revisa las licencias para verificar su compatibilidad legal, prefiere proyectos con mantenimiento activo y ten un proceso para parchar o reemplazar componentes rápidamente cuando se anuncie una falla grave. Cuidado con los ataques de typosquatting y de confusión de dependencias, en los que paquetes maliciosos imitan nombres legítimos. Valida las imágenes de contenedores de la misma forma: usa imágenes base mínimas y confiables, escanéalas y permite ejecutar solo imágenes firmadas de registros aprobados.

Términos clave

Cadena de suministro de software
Todos los componentes, herramientas, procesos y proveedores que participan en construir y entregar software.
Confusión de dependencias
Un ataque en el que un paquete público malicioso con el mismo nombre que uno interno se incorpora a una compilación en lugar del paquete real.
Firma de artefactos
Firmar digitalmente los resultados de la compilación para que quienes los usan puedan verificar que vienen de la fuente esperada y no fueron alterados.
API aprobada
Una interfaz externa o interna que pasó una revisión de seguridad y fue autorizada para su uso por la organización.
Ejemplo real

Después de que se descubre una puerta trasera en una biblioteca de código abierto muy usada, una empresa que obtiene todos sus paquetes mediante un repositorio interno curado bloquea la versión comprometida en minutos y usa su inventario de SBOM para confirmar que ningún servicio de producción se compiló con ella.

Consejo para el examen: El código abierto no es automáticamente riesgoso ni seguro; el examen favorece las respuestas que lo gestionan con inventario (SCA/SBOM), fuentes confiables, versiones fijas, verificación de firmas y parches rápidos.

Comprueba lo que sabes

Nombra dos formas de proteger un flujo de compilación contra ataques a la cadena de suministro.

Por ejemplo: obtener paquetes de un repositorio interno curado, fijar versiones, verificar firmas y sumas de verificación, restringir cambios a las definiciones de compilación, firmar los artefactos.

¿Qué es el typosquatting en los ecosistemas de paquetes?

Publicar paquetes maliciosos con nombres parecidos a los populares para que los desarrolladores los instalen por error.

¿Qué debe revisarse antes de aprobar una API de terceros?

La autenticación, el cifrado, los datos intercambiados, los límites de tasa, el registro, la postura de seguridad del proveedor y los términos contractuales.
