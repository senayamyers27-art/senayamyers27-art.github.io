ISC2 Certified Cloud Security Professional 2026 outline (effective Aug 1, 2026)

Protección de los datos de IA y ML: integridad de los datos de entrenamiento, envenenamiento de datos y seguridad de modelos y prompts

El temario del CCSP de 2026 agrega un subdominio sobre la protección de los datos que usan los sistemas de inteligencia artificial y aprendizaje automático. Un sistema de IA solo es tan confiable como los datos con los que aprende y las entradas que recibe, y esos conjuntos de datos a menudo combinan registros sensibles de muchas fuentes guardados en almacenamiento en la nube.

La integridad de los datos de entrenamiento va primero. Si un atacante o un proceso descuidado puede cambiar los datos de entrenamiento, el modelo aprende lecciones equivocadas. El envenenamiento de datos inserta registros diseñados para que el modelo clasifique mal ciertas entradas, a veces solo cuando está presente un disparador oculto, lo que se llama puerta trasera (backdoor). Las defensas son controles conocidos de seguridad de datos aplicados a un activo nuevo: restringir el acceso de escritura a los datos y flujos de entrenamiento, registrar de dónde vino cada conjunto de datos (procedencia de los datos), validar y limpiar los datos antes de entrenar, conservar copias versionadas y con hash para detectar cambios y poder revertir, y revisar con especial cuidado los datos de fuentes externas o generados por usuarios.

Los datos de entrenamiento también crean riesgos de confidencialidad y privacidad. Los modelos pueden memorizar y luego revelar fragmentos de sus datos de entrenamiento, y ataques como la inferencia de pertenencia pueden mostrar si se usó el registro de una persona. Minimiza los datos personales antes de entrenar, aplica enmascaramiento, seudonimización o datos sintéticos cuando sea posible, respeta la finalidad para la que se recolectaron los datos y aplica a los conjuntos de entrenamiento, los embeddings y las bases de datos vectoriales las mismas reglas de clasificación y residencia que a los datos de origen.

Los modelos y los prompts también son activos de datos. Los archivos y pesos de los modelos deben guardarse en registros con control de acceso, firmados o con hash para detectar manipulaciones y cifrados en reposo. Los prompts y el contexto recuperado pueden llevar datos confidenciales a un modelo y también pueden llevar ataques: la inyección indirecta de prompts esconde instrucciones en un documento o página web que el modelo lee después. Los controles incluyen filtrar y etiquetar el contenido no confiable, limitar a qué datos puede llegar un sistema de recuperación según los permisos del propio usuario, registrar prompts y salidas y tratar la salida del modelo como una entrada no confiable para otros sistemas.

Términos clave

Procedencia de los datos
Un registro de dónde vinieron los datos y cómo se han modificado, que se usa para establecer confianza en ellos.
Puerta trasera (en ML)
Un comportamiento oculto implantado en un modelo mediante datos de entrenamiento envenenados que se activa con un disparador específico.
Inferencia de pertenencia
Un ataque que determina si un registro particular formó parte de los datos de entrenamiento de un modelo.
Inyección indirecta de prompts
Instrucciones maliciosas escondidas en contenido, como una página web o un documento, que un sistema de IA lee y sigue.
Ejemplo real

Una empresa construye un asistente interno que responde preguntas a partir de su repositorio de documentos. Para evitar que revele archivos de sueldos a todos, la capa de recuperación ejecuta cada búsqueda con los permisos del propio empleado que pregunta, así el modelo solo ve documentos que ese empleado ya podía abrir.

Consejo para el examen: La mayoría de las respuestas sobre protección de datos de IA son controles comunes de seguridad de datos (control de acceso, verificación de integridad, clasificación, cifrado, registro) aplicados a los datos de entrenamiento, los modelos y los prompts. Elige la respuesta que protege la integridad cuando el escenario es de envenenamiento.

Comprueba lo que sabes

¿Qué es el envenenamiento de datos?

Insertar o alterar deliberadamente datos de entrenamiento para que un modelo aprenda un comportamiento incorrecto o malicioso.

¿Cómo ayudan los conjuntos de entrenamiento versionados y con hash?

Hacen detectables los cambios no autorizados y permiten volver a una versión conocida y confiable.

¿Por qué un asistente con recuperación aumentada debe usar los permisos del propio usuario al buscar documentos?

Para que el modelo no pueda exponer documentos que el usuario no está autorizado a ver.
