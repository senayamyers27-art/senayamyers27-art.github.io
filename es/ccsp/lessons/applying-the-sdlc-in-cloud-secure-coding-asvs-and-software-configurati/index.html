Aplicación del SDLC en la nube: codificación segura, ASVS y gestión de la configuración del software

Conocer las fases del SDLC es una cosa; aplicarlas a proyectos reales en la nube es otra. Este objetivo abarca tres herramientas prácticas: las prácticas de codificación segura, el Estándar de Verificación de Seguridad de Aplicaciones de OWASP (ASVS) y la gestión de la configuración del software.

La codificación segura significa escribir código que maneje de forma segura las entradas no confiables y use correctamente las funciones de seguridad de la plataforma. Las prácticas centrales incluyen validar las entradas contra los formatos esperados, codificar la salida según su contexto para evitar el cross-site scripting, usar consultas parametrizadas para evitar la inyección, aplicar la autorización en cada solicitud del lado del servidor, manejar los errores sin filtrar trazas de pila ni secretos, usar bibliotecas criptográficas probadas en lugar de escribir las tuyas y obtener las credenciales de un gestor de secretos o de una identidad de carga de trabajo en lugar del código. Las organizaciones convierten esto en un estándar de codificación escrito, respaldado por linters y reglas de análisis estático, y lo verifican en la revisión de código.

El ASVS te da una lista detallada y verificable de requisitos de seguridad para aplicaciones web y API. Tiene tres niveles de verificación. El nivel 1 es un nivel básico adecuado para todas las aplicaciones y en gran parte puede probarse desde fuera. El nivel 2 es el nivel recomendado para la mayoría de las aplicaciones que manejan datos sensibles. El nivel 3 es para las aplicaciones más críticas, como las que manejan transacciones de alto valor o datos médicos sensibles, y requiere una verificación profunda que incluye la revisión del diseño. Los equipos usan el ASVS como fuente de requisitos al inicio de un proyecto, como lista de verificación para las revisiones de diseño y como alcance de las pruebas, lo que hace que la seguridad sea medible y no una cuestión de opinión.

La gestión de la configuración del software (SCM) controla los cambios en el código, las dependencias, los scripts de compilación, las plantillas de infraestructura y los ajustes de las aplicaciones. Usa control de versiones para todo, ramas principales protegidas con revisiones obligatorias, commits y artefactos firmados, compilaciones reproducibles y un registro exacto de qué versión está desplegada en cada lugar. La configuración se mantiene separada del código y los secretos nunca se guardan en ninguno de los dos. En la nube, donde la infraestructura es código, la SCM es la forma de prevenir y rastrear cambios no autorizados y de revertir rápidamente cuando un cambio sale mal.

Términos clave

ASVS
El Estándar de Verificación de Seguridad de Aplicaciones de OWASP, una lista de requisitos de seguridad verificables organizada en tres niveles.
Consulta parametrizada
Una consulta a la base de datos donde la entrada del usuario se pasa como parámetros separados, de modo que nunca puede ejecutarse como código.
Gestión de la configuración del software
La disciplina de rastrear y controlar los cambios en el código, las dependencias y la configuración de compilación y despliegue.
Codificación de salida
Transformar los datos antes de mostrarlos para que el navegador los trate como texto y no como código ejecutable.
Ejemplo real

Una startup de tecnología financiera adopta el nivel 2 del ASVS como el conjunto de requisitos de seguridad de su portal de clientes. Cada historia de usuario hace referencia a los requisitos del ASVS correspondientes, las pruebas automatizadas los verifican en el flujo de CI/CD y una revisión trimestral informa qué requisitos se cumplen, lo que da al consejo una medida concreta de la seguridad de la aplicación.

Consejo para el examen: El nivel 1 del ASVS es el mínimo para todas las aplicaciones, el nivel 2 se recomienda para aplicaciones con datos sensibles y el nivel 3 es para aplicaciones críticas. Elige el nivel que corresponda a los datos y al impacto en el negocio del escenario.

Comprueba lo que sabes

¿Qué nivel del ASVS se recomienda para la mayoría de las aplicaciones que manejan datos sensibles?

El nivel 2.

¿Cuál es la mejor defensa contra la inyección SQL?

Las consultas parametrizadas (sentencias preparadas), apoyadas por la validación de entradas.

¿Por qué es importante la gestión de la configuración del software para la infraestructura como código?

Controla y registra cada cambio en las definiciones de infraestructura, lo que evita cambios no autorizados y permite revertir rápidamente.
