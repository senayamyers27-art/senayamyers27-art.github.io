ISC2 Certified Cloud Security Professional 2026 outline (effective Aug 1, 2026)

Tecnologías de seguridad de datos: cifrado y gestión de llaves, hashing, ofuscación de datos (enmascaramiento, anonimización) y tokenización

Varias tecnologías protegen los datos transformándolos. El examen evalúa si eliges la correcta para el objetivo: mantener los datos en secreto pero recuperables, demostrar que no han cambiado, ocultar los valores reales a quien no los necesita o eliminar por completo los valores sensibles de un sistema.

El cifrado convierte datos legibles en texto cifrado que solo el poseedor de una llave puede revertir. Los algoritmos simétricos como AES son rápidos y se usan para grandes volúmenes de datos en reposo y en tránsito; los algoritmos asimétricos como RSA y la criptografía de curva elíptica se usan para el intercambio de llaves y las firmas digitales. En la nube el cifrado puede hacerse a nivel de almacenamiento, de base de datos, de aplicación o en el cliente antes de subir los datos, y cada nivel protege contra amenazas distintas. El cifrado a nivel de almacenamiento impide que alguien lea un disco robado, pero no hace nada contra un atacante que inicia sesión en la aplicación. El cifrado solo es tan fuerte como su gestión de llaves: las llaves deben generarse de forma segura, guardarse separadas de los datos, rotarse y destruirse cuando ya no se necesiten.

El hashing produce un resumen de longitud fija a partir de los datos de entrada con una función unidireccional como SHA-256. No se puede revertir, así que se usa para verificar la integridad y para almacenar contraseñas (con una sal y un algoritmo deliberadamente lento), no para proteger datos que necesitas volver a leer. La ofuscación de datos oculta los valores reales. El enmascaramiento reemplaza los datos con valores realistas pero falsos o parcialmente ocultos, por ejemplo mostrando solo los últimos cuatro dígitos de una tarjeta. El enmascaramiento estático crea una copia enmascarada permanente, a menudo para entornos de prueba; el enmascaramiento dinámico oculta los valores al vuelo según quién los consulta. La anonimización elimina o altera los identificadores para que las personas ya no puedan ser identificadas, mientras que la seudonimización reemplaza los identificadores con códigos que pueden volver a vincularse mediante información guardada por separado. Solo los datos verdaderamente anonimizados quedan fuera de leyes de privacidad como el RGPD.

La tokenización reemplaza un valor sensible, como un número de tarjeta, con un token aleatorio que no tiene relación matemática con él. El valor real se guarda en una bóveda de tokens separada y muy protegida. Los sistemas que solo manejan tokens quedan fuera del alcance de gran parte de la carga de cumplimiento, por eso la tokenización es popular para PCI DSS.

Términos clave

Tokenización
Reemplazar un valor sensible con un sustituto aleatorio, guardando la correspondencia en una bóveda separada y protegida.
Enmascaramiento dinámico
Ocultar o alterar los valores de los datos en el momento de la consulta según el rol del usuario, sin cambiar los datos almacenados.
Seudonimización
Reemplazar identificadores con códigos que pueden volver a vincularse a la persona usando información adicional guardada por separado.
Sal (salt)
Datos aleatorios que se agregan a una contraseña antes del hashing para que contraseñas idénticas produzcan hashes distintos.
Ejemplo real

Una tienda en línea envía los números de tarjeta a un servicio de tokenización de pagos y guarda solo los tokens que recibe. Su base de datos de pedidos, su plataforma de analítica y sus herramientas de soporte nunca ven números de tarjeta reales, lo que reduce la parte del entorno que deben examinar los evaluadores de PCI DSS.

Consejo para el examen: Los tokens no tienen vínculo matemático con el original; los valores cifrados sí y se pueden revertir con la llave. Si una pregunta enfatiza reducir el alcance de cumplimiento, la tokenización suele ser la respuesta buscada.

Comprueba lo que sabes

¿Por qué el hashing no sirve para proteger datos que deben leerse después?

El hashing es unidireccional; el original no se puede recuperar a partir del resumen.

¿Qué distingue la anonimización de la seudonimización?

Los datos anonimizados no pueden vincularse de nuevo a una persona; los seudonimizados pueden reidentificarse usando información guardada por separado.

¿Qué tipo de enmascaramiento conviene más para crear una copia segura de los datos de producción para pruebas?

El enmascaramiento estático, que produce una copia enmascarada permanente.
