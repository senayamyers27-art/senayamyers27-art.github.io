Azure OpenAI y el catálogo de modelos de Azure AI Foundry: modelos de chat, razonamiento, embeddings e imágenes, y cómo elegir e implementar uno

La IA generativa en Azure empieza por elegir un modelo. El catálogo de modelos de Azure AI Foundry incluye modelos de OpenAI (que se venden como Azure OpenAI), de Microsoft y de otros proveedores como Meta, Mistral y Cohere. Los modelos de OpenAI y algunos otros se implementan en tu recurso de Azure OpenAI o de Foundry; muchos modelos de terceros se ofrecen como API serverless facturadas por token, y algunos pueden implementarse en proceso administrado (managed compute) que pagas por hora. Cada entrada del catálogo tiene una ficha del modelo (model card) que describe su propósito, longitud de contexto, regiones admitidas y opciones de implementación.

Los modelos se agrupan en familias según lo que producen. Los modelos de chat completion, como las familias GPT-4o y GPT-4.1, reciben una conversación y devuelven texto; muchos también aceptan imágenes, y las versiones 'mini' más pequeñas sacrifican algo de calidad a cambio de menor costo y latencia. Los modelos de razonamiento, como la serie o de OpenAI, dedican cómputo adicional a trabajar internamente un problema antes de responder, lo que ayuda en matemáticas, lógica, planificación y código complejo a costa de latencia y tokens. Los modelos de embeddings, como text-embedding-3-small y text-embedding-3-large, convierten texto en vectores de números para búsqueda y similitud; nunca generan texto. Los modelos de generación de imágenes, como DALL-E 3 y los modelos de imagen GPT más recientes, crean imágenes a partir de prompts de texto. Los modelos de audio se encargan de la transcripción y la voz.

Elige primero por tarea y luego por costo y latencia. Clasificar tickets de soporte o responder preguntas frecuentes suele funcionar bien con un modelo de chat pequeño. Un análisis de varios pasos puede justificar un modelo de razonamiento. La búsqueda necesita un modelo de embeddings, y hay que usar el mismo modelo de embeddings para indexar y para las consultas. Revisa la ventana de contexto del modelo (cuántos tokens de entrada y salida puede manejar), si admite las funciones que necesitas (function calling, salida JSON estructurada, entrada de imágenes, fine-tuning) y si está disponible en tu región y tipo de implementación. Las versiones de los modelos se retiran según un calendario, así que planifica las actualizaciones.

Para implementar, abre el modelo en el catálogo o en la página Deployments de tu proyecto, elige Deploy, escribe un nombre de implementación, selecciona el tipo de implementación y establece la capacidad en tokens por minuto. También puedes implementar con az cognitiveservices account deployment create o con Bicep. Después, el código llama al nombre de la implementación. Prueba primero los prompts en el chat playground; muestra el mensaje del sistema, los parámetros y una opción 'view code' con código de ejemplo para tu implementación.

Los benchmarks y las tablas de clasificación del catálogo ayudan a comparar modelos, pero siempre evalúa con tus propios datos antes de comprometerte, algo que se trata en una lección posterior.

Términos clave

Model catalog (catálogo de modelos)
La lista de Azure AI Foundry con modelos de Microsoft, OpenAI y socios, con fichas de modelo y opciones de implementación.
Reasoning model (modelo de razonamiento)
Un modelo que trabaja internamente un problema antes de responder, lo que mejora la precisión en tareas complejas con mayor latencia y costo.
Embedding model (modelo de embeddings)
Un modelo que convierte texto en un vector numérico que representa su significado, usado para búsqueda y similitud.
Context window (ventana de contexto)
El número máximo de tokens que un modelo puede procesar entre entrada y salida en una solicitud.
Ejemplo real

Una startup crea un asistente de productos. Implementa un modelo de chat pequeño para las preguntas cotidianas porque es rápido y barato, text-embedding-3-small para indexar el catálogo de productos y envía solo los cálculos complicados de garantías a una implementación de un modelo de razonamiento.

Consejo para el examen: Vectores para búsqueda significa un modelo de embeddings; imágenes nuevas significa un modelo de imágenes; lógica difícil de varios pasos sugiere un modelo de razonamiento; todo lo conversacional es un modelo de chat. El código llama al nombre de la implementación, no al del modelo.

Comprueba lo que sabes

¿Por qué hay que usar el mismo modelo de embeddings para los documentos y las consultas?

Los vectores de distintos modelos de embeddings viven en espacios y dimensiones diferentes, así que la similitud entre ellos no tiene sentido.

¿Qué significa una implementación como API serverless para un modelo del catálogo?

Microsoft aloja el modelo y pagas por token sin administrar proceso, en lugar de pagar por hora por proceso administrado.
