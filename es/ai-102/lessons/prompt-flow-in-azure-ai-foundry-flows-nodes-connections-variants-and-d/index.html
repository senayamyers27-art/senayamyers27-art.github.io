Prompt flow en Azure AI Foundry: flujos, nodos, conexiones, variantes e implementación

Las aplicaciones reales de IA generativa son más que un solo prompt. Una aplicación de chat RAG podría reescribir la pregunta, convertirla en embedding, buscar en un índice, dar formato a los resultados, llamar al modelo y posprocesar la respuesta. Prompt flow es una herramienta de desarrollo de Azure AI Foundry (y de Azure Machine Learning) para crear, probar, evaluar e implementar estas canalizaciones de varios pasos como un grafo visual respaldado por archivos que puedes mantener en control de código fuente.

Un flujo (flow) es un grafo dirigido de nodos. Cada nodo es una herramienta: una herramienta LLM llama a un modelo de chat con una plantilla de prompt escrita en Jinja, con marcadores como {{question}}; una herramienta Prompt renderiza una plantilla sin llamar a un modelo; una herramienta Python ejecuta tu propia función; y otras herramientas cubren tareas como la búsqueda en índices para RAG o las comprobaciones de seguridad de contenido. Los nodos pasan sus salidas a las entradas de nodos posteriores, y el flujo tiene entradas y salidas definidas. La definición del flujo se guarda en un archivo flow.dag.yaml, con los archivos de Python y Jinja al lado.

Hay tres tipos de flujo. Un flujo estándar (standard flow) recibe entradas y produce salidas, para tareas generales. Un flujo de chat (chat flow) agrega el historial del chat como entrada integrada y una interfaz de chat para probar, para aplicaciones conversacionales. Un flujo de evaluación (evaluation flow) recibe las salidas de otro flujo más la verdad de referencia (ground truth) y calcula métricas; se usa para puntuar un flujo sobre un conjunto de datos.

Las conexiones guardan cómo llegar a recursos externos, como una implementación de Azure OpenAI, un índice de Azure AI Search o una API personalizada, incluidos el endpoint y las credenciales. Los nodos LLM hacen referencia a una conexión en lugar de contener una clave, así que los secretos quedan fuera de los archivos del flujo y el mismo flujo puede apuntar a distintos recursos en distintos entornos. Los flujos se ejecutan en proceso; en Foundry suele ser proceso serverless que se inicia por ti.

Las variantes permiten que un nodo LLM tenga varias versiones de su prompt o de sus parámetros, por ejemplo un mensaje del sistema corto y uno detallado, o temperature 0.2 y 0.8. Ejecutas el flujo con un lote de entradas de prueba en todas las variantes y comparas las salidas y las métricas de evaluación para elegir la mejor.

Cuando el flujo funciona, impleméntalo en un endpoint en línea administrado (managed online endpoint), que expone una API REST que tu aplicación puede llamar, con autenticación, escalado y supervisión. El seguimiento (tracing) registra las entradas, salidas, latencia y uso de tokens de cada nodo, lo que ayuda a encontrar qué paso causó una mala respuesta.

Términos clave

Flow (flujo)
Un grafo dirigido de nodos de herramientas que define una canalización de IA generativa en prompt flow.
Variant (variante)
Una versión alternativa del prompt o de los parámetros de un nodo LLM, que se ejecuta en paralelo para comparar.
Connection (conexión)
Una configuración guardada y reutilizable del endpoint y las credenciales de un recurso externo que usan los nodos del flujo.
Evaluation flow (flujo de evaluación)
Un flujo que puntúa las salidas de otro flujo frente a la verdad de referencia o a criterios de calidad.
Ejemplo real

Un equipo que crea un asistente de políticas arma un flujo de chat con nodos para reescribir la pregunta, buscar en un índice y responder. Agrega dos variantes del prompt de respuesta, ejecuta ambas contra 50 preguntas de prueba con un flujo de evaluación de fundamentación, se queda con la mejor variante e implementa el flujo en un endpoint en línea administrado.

Consejo para el examen: Comparar versiones de prompt en un nodo significa variantes; guardar endpoints y claves significa conexiones; un flujo conversacional con historial es un flujo de chat; publicarlo como API significa un endpoint en línea administrado.

Comprueba lo que sabes

¿Cuáles son los tres tipos de flujo de prompt flow?

Flujo estándar, flujo de chat y flujo de evaluación.

¿Por qué usar una conexión en lugar de pegar una clave de API en un nodo LLM?

Las conexiones mantienen las credenciales fuera de los archivos del flujo y permiten que el mismo flujo apunte a distintos recursos según el entorno.
