Modelos personalizados de Document Intelligence: template frente a neural, clasificadores personalizados y modelos compuestos

Los modelos precompilados cubren documentos comunes, pero la mayoría de las organizaciones también tienen sus propios formularios: un formulario interno de reclamaciones, la orden de compra de un proveedor, un informe de laboratorio. Document Intelligence te permite entrenar modelos personalizados con un número pequeño de tus propios ejemplos etiquetados para extraer exactamente los campos que necesitas.

El proceso se realiza en Document Intelligence Studio. Coloca documentos de muestra en un contenedor de Blob Storage, crea un proyecto de extracción personalizada conectado a él y etiqueta los campos: dibuja regiones o selecciona palabras para cada campo (como PatientName o TotalAmount), y etiqueta tablas y firmas si es necesario. Solo necesitas unas pocas muestras para empezar; la guía de Microsoft es al menos cinco ejemplos de cada tipo de formulario, y más para documentos variables. El entrenamiento produce un modelo con un ID de modelo que llamas igual que a un modelo precompilado.

Hay dos tipos de modelo de extracción personalizada. Los modelos custom template (antes custom form) convienen para documentos con un diseño coherente y fijo, en los que los campos siempre están en el mismo lugar, como un formulario gubernamental estándar. Se entrenan rápido y son precisos para ese diseño, pero tienen problemas cuando el diseño varía. Los modelos custom neural usan aprendizaje profundo para entender el contenido y la estructura del documento, así que manejan documentos estructurados, semiestructurados y algunos no estructurados cuyo diseño varía, como facturas u órdenes de compra de muchos proveedores. Los modelos neural son el punto de partida recomendado en la mayoría de los casos; usa template cuando los diseños son realmente fijos o cuando neural no admite tu idioma o tipo de campo.

Un modelo de clasificación personalizado identifica el tipo de cada documento, o de cada rango de páginas en un archivo combinado, antes de la extracción. Lo entrenas con ejemplos de cada clase de documento, como W-2, recibo de nómina y estado de cuenta bancario. Es útil cuando los documentos llegan mezclados, por ejemplo un PDF de solicitud de hipoteca que contiene varios tipos de documentos; el clasificador los divide y etiqueta para que cada uno vaya al modelo de extracción correcto.

Un modelo compuesto (composed model) agrupa varios modelos de extracción personalizados bajo un solo ID de modelo. Cuando analizas un documento con el modelo compuesto, el servicio determina cuál de los modelos componentes encaja mejor y lo usa, e indica cuál se usó (en la versión actual de la API, el enrutamiento usa un clasificador personalizado). Tu aplicación llama a un solo ID de modelo para muchos tipos de formulario en lugar de elegir ella misma el modelo, y puedes actualizar los modelos componentes sin cambiar la aplicación.

Evalúa los modelos personalizados con documentos de prueba que no se usaron en el entrenamiento, revisa la exactitud y la confianza por campo, y agrega muestras etiquetadas más variadas donde los campos sean débiles. Mantén los datos de entrenamiento representativos de los documentos reales, incluidos los escaneos de mala calidad si los recibes.

Términos clave

Custom template model
Un modelo de extracción personalizado para documentos con un diseño coherente y fijo.
Custom neural model
Un modelo de extracción personalizado de aprendizaje profundo que maneja documentos con diseños variables.
Custom classifier (clasificador personalizado)
Un modelo que identifica los tipos de documento, y divide los archivos combinados, antes de la extracción.
Composed model (modelo compuesto)
Varios modelos personalizados agrupados bajo un ID de modelo que enruta cada documento al que mejor coincide.
Ejemplo real

Una empresa de logística recibe conocimientos de embarque de 200 transportistas con diseños diferentes. Etiqueta 60 muestras de distintos transportistas y entrena un modelo custom neural. Su propio comprobante de entrega estándar, que nunca cambia, recibe un modelo custom template, y ambos se colocan en un modelo compuesto para que la aplicación de recepción llame a un solo ID de modelo.

Consejo para el examen: Diseño fijo: template. Diseños variables de muchas fuentes: neural. Tipos de documento mezclados en un solo flujo: clasificador personalizado. Un ID de modelo para varios modelos personalizados: modelo compuesto.

Comprueba lo que sabes

¿Por qué podría fallar un modelo template con facturas de muchos proveedores?

Los modelos template esperan los campos en posiciones coherentes; los diseños variados necesitan un modelo neural.

¿Qué hace un modelo compuesto cuando recibe un documento?

Determina qué modelo personalizado componente encaja mejor con el documento y extrae los campos con ese modelo, indicando qué modelo se usó.
