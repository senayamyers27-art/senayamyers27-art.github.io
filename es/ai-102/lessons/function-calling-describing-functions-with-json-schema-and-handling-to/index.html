Function calling: describir funciones con JSON schema y manejar las llamadas a herramientas en código

Function calling (también llamado tool calling) es el mecanismo que permite que un modelo de lenguaje use tu código. El modelo nunca ejecuta nada por sí mismo. Tú describes las funciones que puede usar; cuando decide que una le serviría, devuelve una solicitud estructurada que nombra la función y sus argumentos, tu código ejecuta la función y le devuelves el resultado para que el modelo pueda continuar. Esto funciona tanto en chat completions simples como dentro de Agent Service.

Cada función se describe con un nombre, una descripción y parámetros escritos en JSON schema: un objeto con propiedades, sus tipos, descripciones, valores permitidos (enum) y cuáles son obligatorias. El modelo lee estas descripciones para decidir cuándo llamar a la función y cómo llenar los argumentos, así que las descripciones claras son esenciales.

{"type": "function", "function": {
  "name": "get_order_status",
  "description": "Look up the shipping status of a customer order by its order number.",
  "parameters": {"type": "object",
    "properties": {"order_id": {"type": "string", "description": "Order number, for example ORD-1234"}},
    "required": ["order_id"]}}}

En chat completions pasas la lista en el parámetro tools. Si el modelo quiere una función, la respuesta tiene finish_reason tool_calls y el mensaje del asistente contiene tool_calls, cada una con un ID, el nombre de la función y los argumentos como cadena JSON. Tu código analiza los argumentos, ejecuta la función, luego agrega el mensaje del asistente y un mensaje con rol tool con el tool_call_id correspondiente y el resultado, y vuelve a llamar al modelo. El modelo puede solicitar varias llamadas a la vez (llamadas paralelas a herramientas) o encadenar llamadas a lo largo de varias rondas. tool_choice puede dejar que el modelo decida (auto), forzar una función específica o deshabilitar las herramientas.

En Agent Service la misma idea aparece como una ejecución en estado requires_action. La acción requerida de la ejecución lista las llamadas a herramientas; las ejecutas y envías las salidas de las herramientas con sus ID, y la ejecución se reanuda. Los SDK también pueden llamar automáticamente a funciones de Python si las registras.

Trata los argumentos como entradas no confiables. El modelo puede producir valores incorrectos o maliciosos, sobre todo si el usuario intenta manipularlo, así que valida tipos y rangos, comprueba que el usuario tenga permitido hacer lo que pide y exige confirmación para acciones como pagos o eliminaciones. Las salidas estructuradas (modo de esquema strict) pueden garantizar que los argumentos coincidan con el esquema, pero no pueden garantizar que los valores sean sensatos.

Términos clave

Function calling (llamada a funciones)
Una función del modelo que devuelve una solicitud estructurada para llamar a una función descrita con argumentos, que la aplicación ejecuta.
JSON schema
Un estándar para describir la estructura, los tipos y los campos obligatorios de datos JSON, que se usa para los parámetros de las funciones.
tool_call_id
El identificador que vincula un mensaje de resultado de herramienta con la solicitud específica de llamada a herramienta del modelo.
tool_choice
Un parámetro que permite que el modelo elija herramientas automáticamente, fuerza una específica o las deshabilita.
Ejemplo real

Un usuario le pregunta al bot de una tienda '¿Dónde está mi pedido ORD-5521?'. El modelo devuelve una llamada a la herramienta get_order_status con order_id ORD-5521. La aplicación comprueba que el pedido pertenece al usuario que inició sesión, llama a la API de pedidos, devuelve 'enviado, llega el jueves' como mensaje de herramienta y el modelo redacta una respuesta amable.

Consejo para el examen: El modelo solo propone llamadas; tu código las ejecuta y debe devolver los resultados con el ID de llamada correspondiente. Las descripciones determinan qué función elige el modelo.

Comprueba lo que sabes

¿Qué significa finish_reason tool_calls?

El modelo quiere que la aplicación ejecute una o más funciones; los argumentos están en tool_calls del mensaje del asistente.

¿Por qué deberías validar los argumentos de funciones que genera el modelo?

Son texto generado y pueden ser incorrectos o estar manipulados, así que deben revisarse como cualquier entrada no confiable antes de actuar.
