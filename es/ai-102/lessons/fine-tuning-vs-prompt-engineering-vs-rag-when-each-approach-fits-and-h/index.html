Fine-tuning frente a ingeniería de prompts frente a RAG: cuándo conviene cada enfoque y cómo se preparan los datos de fine-tuning

Cuando un modelo base no hace lo que quieres, hay tres formas principales de mejorarlo, y el examen a menudo pregunta cuál usar. Resuelven problemas distintos y a menudo se combinan, así que piensa en qué es lo que realmente está mal.

La ingeniería de prompts cambia las instrucciones y los ejemplos que envías. Es rápida, barata, no requiere entrenamiento y siempre es el primer paso. Encaja cuando el modelo puede hacer la tarea pero necesita una dirección más clara, un formato o algunos ejemplos. Sus límites son la longitud del prompt, que cuesta tokens en cada llamada, y las tareas en las que incluso los buenos prompts son inconsistentes.

La generación aumentada por recuperación (RAG) agrega conocimiento en el momento de la consulta recuperando datos relevantes al prompt. Encaja cuando el problema son hechos que faltan o que cambian: políticas de la empresa, catálogos de productos, eventos recientes. Mantiene las respuestas actualizadas y citables, y respeta los permisos si el índice filtra por usuario. No cambia cómo escribe o razona el modelo.

El fine-tuning continúa el entrenamiento de un modelo base con tus propios ejemplos y produce una versión personalizada del modelo que luego implementas. Encaja cuando necesitas un estilo, tono o formato coherente que los prompts no logran de forma fiable, cuando quieres acortar los prompts incorporando instrucciones largas o muchos ejemplos, o cuando un modelo más pequeño con fine-tuning puede igualar a uno más grande en una tarea específica con menor costo y latencia. Es una mala forma de agregar hechos que cambian, porque el modelo debe volver a entrenarse para actualizarlos y no puede citar de dónde vino el conocimiento. También cuesta tiempo de entrenamiento, el alojamiento de la implementación con fine-tuning y el reentrenamiento continuo cuando se retiran los modelos base.

Los datos de fine-tuning supervisado para modelos de chat son un archivo JSONL (un objeto JSON por línea), donde cada línea contiene un arreglo messages con mensajes de sistema, usuario y asistente que muestran la respuesta ideal. Cargas un archivo de entrenamiento y, preferiblemente, un archivo de validación, eliges un modelo base que admita fine-tuning en tu región e inicias un trabajo en el portal de Foundry o con el SDK; puedes definir hiperparámetros como el número de épocas. La calidad importa más que el volumen: los ejemplos deben ser precisos, coherentes y representativos. Evalúa el modelo con fine-tuning frente al modelo base antes de cambiar el tráfico.

{"messages": [{"role": "system", "content": "You are Contoso's support assistant."}, {"role": "user", "content": "My order is late."}, {"role": "assistant", "content": "Sorry about the delay. Could you share your order number so I can check it?"}]}

Términos clave

Fine-tuning (ajuste fino)
Entrenar más a fondo un modelo base con tus propios ejemplos para producir una versión personalizada del modelo.
JSONL
Un formato de archivo con un objeto JSON por línea, que se usa para los datos de entrenamiento de fine-tuning.
Epoch (época)
Una pasada completa de entrenamiento sobre todo el conjunto de datos de entrenamiento.
Validation file (archivo de validación)
Ejemplos reservados que se usan durante el fine-tuning para medir qué tan bien generaliza el modelo.
Ejemplo real

El chatbot de un banco necesita conocer las tasas de interés vigentes y responder siempre con un estilo regulado estricto. El equipo usa RAG sobre las hojas de tasas diarias para los hechos y hace fine-tuning de un modelo pequeño con 800 conversaciones aprobadas para el estilo, lo que además eliminó una larga lista de reglas de estilo de cada prompt.

Consejo para el examen: Hechos que cambian y requieren citas: RAG. Estilo o formato coherente, o prompts más cortos en una tarea específica: fine-tuning. En todos los casos, prueba primero la ingeniería de prompts.

Comprueba lo que sabes

¿Qué formato se usa para los datos de fine-tuning de chat?

JSONL, un ejemplo por línea, cada uno con un arreglo messages de mensajes de sistema, usuario y asistente.

¿Por qué el fine-tuning es una mala forma de enseñarle a un modelo los precios de esta semana?

Los precios cambian, así que el modelo necesitaría reentrenarse cada vez y no podría citar una fuente; RAG recupera los datos actuales en su lugar.
