Voz a texto con Azure AI Speech: transcripción en tiempo real, continua y por lotes

Azure AI Speech convierte el audio hablado en texto, una capacidad llamada reconocimiento de voz o voz a texto (speech to text). Admite muchos idiomas y hace posibles los subtítulos, el dictado, los comandos de voz y el análisis de centros de llamadas. El método que elijas depende de si el audio es en vivo o grabado y de cuánto hay.

El reconocimiento en tiempo real usa el Speech SDK (Python, C#, JavaScript, Java y más). Creas un SpeechConfig con tu clave y tu región (o un endpoint y un token), estableces el idioma de reconocimiento, creas un AudioConfig a partir del micrófono predeterminado, un archivo WAV o una secuencia, y creas un SpeechRecognizer. Para una sola expresión corta, como un comando de voz, llama a recognize_once_async: escucha hasta una pausa (o unos 15 segundos) y devuelve un resultado. El reason del resultado te dice qué pasó: RecognizedSpeech con el texto, NoMatch si no se pudo reconocer la voz, o Canceled con detalles del error, como una clave o región incorrecta.

import azure.cognitiveservices.speech as speechsdk
speech_config = speechsdk.SpeechConfig(subscription=key, region=region)
speech_config.speech_recognition_language = "en-GB"
recognizer = speechsdk.SpeechRecognizer(speech_config=speech_config)
result = recognizer.recognize_once_async().get()
if result.reason == speechsdk.ResultReason.RecognizedSpeech:
    print(result.text)

Para audio más largo, como una reunión o una transmisión en vivo, usa el reconocimiento continuo. Conectas controladores a los eventos: recognizing da resultados parciales intermedios mientras la persona habla (bueno para subtítulos en vivo), recognized da el resultado final de cada frase, canceled informa errores y session_stopped indica el final. Luego llamas a start_continuous_recognition_async y, más tarde, a stop_continuous_recognition_async. Las opciones incluyen la detección automática de idioma entre una lista de idiomas candidatos, el enmascaramiento de groserías, las marcas de tiempo por palabra y la transcripción de conversaciones con diarización, que etiqueta qué hablante dijo cada frase.

La transcripción por lotes es para grandes volúmenes de audio grabado, como las grabaciones de un día de un centro de llamadas en Blob Storage. Es una API REST y no un método del SDK: envías un trabajo con las URL de los archivos de audio o un contenedor, la configuración regional y opciones como la diarización, luego consultas hasta que termine correctamente y descargas las transcripciones en JSON. Es asíncrona y rentable para trabajo masivo. Para archivos grabados individuales de los que quieres un resultado rápido, la API de transcripción rápida (fast transcription) devuelve una transcripción de forma síncrona, más rápido que en tiempo real.

La precisión depende de la calidad del audio, del ruido de fondo y del vocabulario. Si el reconocimiento estándar tiene problemas con nombres de productos o en un entorno ruidoso, una lista de frases (phrase list) puede reforzar palabras específicas en tiempo de ejecución, y los modelos de voz personalizados, que se tratan más adelante, adaptan aún más el reconocimiento.

Términos clave

SpeechConfig
El objeto del Speech SDK que contiene las credenciales, la región o el endpoint, y configuraciones como el idioma de reconocimiento.
recognize_once_async
Un método del Speech SDK que reconoce una sola expresión y termina en una pausa.
Continuous recognition (reconocimiento continuo)
Reconocimiento basado en eventos de audio largo, con resultados intermedios y finales, hasta que se detiene.
Batch transcription (transcripción por lotes)
Una API REST asíncrona para transcribir grandes conjuntos de archivos de audio almacenados.
Ejemplo real

Una cadena de radio usa el reconocimiento continuo con el evento recognizing para mostrar subtítulos en vivo en su transmisión web, mientras que su equipo de archivo envía cada noche un trabajo de transcripción por lotes sobre los programas grabados del día en Blob Storage para que se puedan buscar.

Consejo para el examen: Un comando corto: recognize once. Audio largo en vivo: reconocimiento continuo con eventos. Miles de archivos almacenados: transcripción por lotes. Un resultado Canceled suele significar problemas de credenciales, región o conexión.

Comprueba lo que sabes

¿Qué evento da resultados intermedios para subtítulos en vivo?

El evento recognizing, que se activa con texto parcial mientras la persona habla; recognized da el texto final.

¿Por qué la transcripción por lotes no está disponible como recognize_once en el SDK?

Está diseñada para grandes conjuntos de archivos almacenados que se procesan de forma asíncrona mediante un trabajo de API REST, no para audio en vivo.
