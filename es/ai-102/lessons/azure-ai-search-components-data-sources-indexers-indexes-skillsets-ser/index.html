Componentes de Azure AI Search: orígenes de datos, indexadores, índices, skillsets, niveles de servicio, réplicas y particiones

Azure AI Search (antes Azure Cognitive Search) es un servicio de búsqueda administrado. Guarda tu contenido en índices y responde rápidamente consultas por palabras clave, vectoriales e híbridas, y puede enriquecer el contenido con IA mientras se importa. Es la columna vertebral de la minería de conocimiento (hacer que grandes volúmenes de documentos sean buscables y analizables) y de la recuperación para aplicaciones RAG.

Varios componentes trabajan juntos. Un índice es el almacén buscable, como una tabla de base de datos de documentos JSON con un esquema de campos. Un origen de datos (data source) es una conexión al lugar donde vive tu contenido, como Azure Blob Storage, Azure Data Lake Storage Gen2, Azure SQL Database, Azure Cosmos DB o Azure Table Storage. Un indexador (indexer) es un rastreador que lee de un origen de datos, abre los documentos (document cracking) para extraer texto y metadatos, asigna los campos de origen a los campos del índice (field mappings) y escribe los documentos en el índice; puede ejecutarse de forma programada y usa la detección de cambios para procesar solo los elementos nuevos o modificados. Un skillset es un conjunto opcional de pasos de enriquecimiento con IA que un indexador ejecuta durante la indexación, como OCR, detección de idioma o extracción de entidades. Un knowledge store guarda opcionalmente la salida enriquecida en Azure Storage para otros usos.

También puedes prescindir de los indexadores y enviar los datos (push): tu código envía documentos JSON al índice con la API push o el SDK, lo que conviene para orígenes de datos que los indexadores no admiten o para actualizaciones casi en tiempo real.

El nivel de servicio define la capacidad y las funciones. El nivel Free es compartido, pequeño y pensado para aprender, sin SLA ni escalado. Basic conviene para cargas de producción pequeñas. Los niveles Standard (S1, S2, S3) aumentan los límites de almacenamiento e índices, y los niveles Storage Optimized (L1, L2) alojan índices muy grandes a menor costo por gigabyte con mayor latencia de consulta. No puedes cambiar el nivel de un servicio existente; creas uno nuevo y reconstruyes los índices, así que elige con cuidado.

Dentro de un nivel escalas con réplicas y particiones. Las réplicas son copias del índice completo que atienden consultas en paralelo; agrégalas para obtener más rendimiento de consultas y alta disponibilidad. El SLA de Microsoft para la disponibilidad de lectura (consultas) requiere al menos dos réplicas, y la disponibilidad de lectura y escritura requiere tres. Las particiones dividen el almacenamiento del índice y el trabajo de indexación entre más máquinas; agrégalas cuando el índice crece o la indexación es lenta. La facturación es por unidad de búsqueda, que es réplicas multiplicadas por particiones, por hora, lo consultes o no.

Las opciones de seguridad incluyen claves de API (claves de administrador para control total, claves de consulta para búsqueda de solo lectura), Microsoft Entra ID con roles como Search Index Data Reader, reglas de firewall por IP y endpoints privados.

Términos clave

Index (índice)
La colección buscable de documentos y su esquema de campos en Azure AI Search.
Indexer (indexador)
Un rastreador que lee un origen de datos, abre los documentos, asigna campos, ejecuta skillsets y carga el índice.
Replica (réplica)
Una copia del índice que atiende consultas, que se agrega para obtener rendimiento y disponibilidad.
Partition (partición)
Una unidad de capacidad de almacenamiento e indexación, que se agrega para índices más grandes e indexación más rápida.
Ejemplo real

Un despacho legal indexa 2 millones de contratos de Blob Storage con un indexador programado cada hora. Las consultas se vuelven lentas a fin de mes, así que el equipo agrega una tercera réplica, lo que además cumple el SLA de lectura y escritura; más adelante, a medida que crece el archivo, agrega una partición para el almacenamiento.

Consejo para el examen: Consultas lentas o disponibilidad: agrega réplicas. Índice más grande o indexación lenta: agrega particiones. Extraer datos de Azure de forma programada: indexador. El nivel no puede cambiarse después de la creación.

Comprueba lo que sabes

¿Cuántas réplicas se necesitan para el SLA de disponibilidad de consultas?

Al menos dos réplicas para la disponibilidad de lectura; tres para la disponibilidad de lectura y escritura.

¿Cuándo usarías la API push en lugar de un indexador?

Cuando los indexadores no admiten el origen de datos o necesitas enviar cambios al índice de inmediato desde tu propio código.
