Chat completions: mensajes de sistema, usuario y asistente, y cómo llamar a una implementación con el SDK de Azure OpenAI

La mayoría de las aplicaciones de IA generativa usan la API de chat completions. Envías una lista de mensajes y el modelo devuelve el siguiente mensaje del asistente. Cada mensaje tiene un rol. El mensaje del sistema (en los modelos más nuevos a veces llamado mensaje del desarrollador) define el comportamiento del modelo: personaje, tono, reglas, de qué temas no salirse, qué hacer cuando no está seguro y el formato de salida. Los mensajes del usuario son lo que escribió la persona. Los mensajes del asistente son las respuestas anteriores del modelo. También puedes incluir mensajes de herramienta que devuelven los resultados de llamadas a funciones.

La API no tiene estado (stateless). La implementación no recuerda nada entre solicitudes, así que para mantener una conversación tu aplicación guarda el historial y envía los mensajes anteriores del usuario y del asistente cada vez. Ese historial cuenta para la ventana de contexto y para la factura de tokens, por lo que los chats largos suelen recortarse o resumirse, conservando el mensaje del sistema y los turnos más recientes.

En Python, el paquete openai incluye un cliente AzureOpenAI. Le das el endpoint de tu recurso, una versión de la API y una clave o un proveedor de tokens de Azure Identity. El argumento model es el nombre de tu implementación.

from openai import AzureOpenAI
from azure.identity import DefaultAzureCredential, get_bearer_token_provider

token = get_bearer_token_provider(DefaultAzureCredential(), scope)  # el ámbito de token de Cognitive Services
client = AzureOpenAI(azure_endpoint=endpoint, azure_ad_token_provider=token, api_version=api_version)

resp = client.chat.completions.create(
    model="support-chat",  # nombre de la implementación
    messages=[
        {"role": "system", "content": "You are a polite support agent for Contoso bikes. Answer only about Contoso products."},
        {"role": "user", "content": "How often should I service my e-bike?"}
    ])
print(resp.choices[0].message.content, resp.choices[0].finish_reason, resp.usage.total_tokens)

La respuesta contiene choices, cada una con un message y un finish_reason: stop significa que el modelo terminó de forma natural o encontró una secuencia de detención, length significa que alcanzó el límite de tokens, content_filter significa que se filtró la salida y tool_calls significa que el modelo quiere llamar a una función. El objeto usage informa los tokens del prompt, de la completion y el total, que es lo que se te factura. En C#, el paquete Azure.AI.OpenAI proporciona un AzureOpenAIClient, del que obtienes un ChatClient para una implementación y llamas a CompleteChat con objetos SystemChatMessage y UserChatMessage. Microsoft también ofrece los SDK de Azure AI Inference y de proyectos de Foundry, que pueden llamar a muchos modelos del catálogo con una sola interfaz.

El streaming (stream=True) devuelve los tokens a medida que se generan, así que los usuarios ven aparecer la respuesta rápidamente aunque la respuesta completa tarde varios segundos.

Términos clave

System message (mensaje del sistema)
El mensaje de instrucciones que define el comportamiento, las reglas y el formato del modelo durante toda la conversación.
Stateless API (API sin estado)
Una API que no guarda memoria entre llamadas, así que el cliente debe reenviar el contexto cada vez.
finish_reason
Un campo que explica por qué se detuvo la generación: stop, length, content_filter o tool_calls.
Streaming
Devolver los tokens generados de forma incremental a medida que se producen, en lugar de en una sola respuesta final.
Ejemplo real

Un bot de soporte olvidaba el número de pedido del cliente después de dos turnos. El desarrollador descubrió que la aplicación solo enviaba el último mensaje del usuario. Después de cambiarla para enviar el mensaje del sistema más los últimos diez mensajes del usuario y del asistente, el bot respondió correctamente las preguntas de seguimiento.

Consejo para el examen: Las reglas y el personaje van en el mensaje del sistema. La memoria de una aplicación de chat viene de reenviar los mensajes anteriores, no de la implementación. finish_reason length significa aumentar el máximo de tokens.

Comprueba lo que sabes

¿Qué argumento contiene el nombre de la implementación en el cliente AzureOpenAI de Python?

El argumento model de chat.completions.create.

¿Por qué las conversaciones largas se vuelven más caras en cada turno?

Todo el historial se reenvía con cada solicitud, así que los tokens del prompt crecen en cada turno.
