Creación de agentes en código con Semantic Kernel, AutoGen y Microsoft Agent Framework

Agent Service aloja los agentes por ti, pero muchos equipos también construyen la lógica de sus agentes en su propio código con un framework de código abierto. Los frameworks te dan abstracciones para modelos, herramientas, memoria y patrones multiagente, y te permiten ejecutar agentes dentro de tu propia aplicación o servicio. Los objetivos de AI-102 mencionan Semantic Kernel y AutoGen, y desde entonces Microsoft presentó Microsoft Agent Framework, que une a ambos.

Semantic Kernel es el SDK de Microsoft para integrar modelos de IA en aplicaciones, disponible para C#, Python y Java. En su centro está el kernel, un contenedor que guarda servicios de IA (como una conexión de chat completion de Azure OpenAI) y plugins. Un plugin es un grupo de funciones que el modelo puede llamar; en C# marcas un método con el atributo KernelFunction y una descripción, y en Python usas el decorador kernel_function. Con la llamada automática a funciones habilitada, el kernel envía las funciones del plugin al modelo como herramientas, ejecuta las que el modelo elija y devuelve los resultados, así que no escribes tú el ciclo de llamadas a herramientas. El framework de agentes de Semantic Kernel agrega tipos de agentes como un agente de chat completion y un agente de Azure AI que envuelve Agent Service, además de patrones de chat grupal y orquestación para varios agentes.

AutoGen es un framework de código abierto de Microsoft Research centrado en la conversación entre varios agentes. Defines agentes con roles, como un asistente que escribe código y un proxy de usuario que lo ejecuta o consulta a una persona, y ellos intercambian mensajes para resolver una tarea. AutoGen facilitó crear prototipos de patrones como chats grupales con un selector que decide quién habla a continuación, y es popular para investigación y experimentación.

Microsoft Agent Framework es el SDK de código abierto más reciente que combina las funciones empresariales de Semantic Kernel (conectores, telemetría, seguridad de tipos) con los patrones multiagente de AutoGen, y agrega flujos de trabajo basados en grafos para pasos deterministas. Microsoft lo presenta como el camino a seguir para ambos, así que espera que la documentación y los ejemplos más nuevos lo usen.

Elige según el control y el alojamiento. Agent Service es lo más rápido cuando quieres estado administrado, herramientas integradas y poca infraestructura. Un framework en tu propio código da más control sobre la orquestación, te permite combinar modelos y proveedores y mantiene la lógica en tu código base; los frameworks también pueden usar agentes de Agent Service como bloques de construcción. Elijas lo que elijas, mantén las herramientas pequeñas y bien descritas, y agrega seguimiento.

Términos clave

Semantic Kernel
El SDK de código abierto de Microsoft para integrar modelos de IA, plugins y agentes en aplicaciones de C#, Python y Java.
Kernel
El contenedor de Semantic Kernel que guarda las conexiones a servicios de IA y los plugins.
Plugin
Un grupo de funciones, descritas para el modelo, que Semantic Kernel expone como herramientas invocables.
AutoGen
Un framework de código abierto de Microsoft Research para crear conversaciones entre varios agentes.
Ejemplo real

Un desarrollador envuelve los métodos de inventario en C# de la empresa en un plugin de Semantic Kernel con atributos KernelFunction y descripciones, habilita la llamada automática a funciones, y ahora el agente de chat puede responder '¿Tenemos talla 42 en existencia en Leeds?' llamando él mismo al método de inventario.

Consejo para el examen: Exponer tus propios métodos al modelo en Semantic Kernel significa un plugin con kernel functions. AutoGen se asocia con conversaciones entre varios agentes. Agent Service es la opción administrada y alojada.

Comprueba lo que sabes

¿Qué es un plugin de Semantic Kernel?

Un grupo de funciones, anotadas con descripciones, que el kernel puede exponer al modelo como herramientas.

¿Cuándo elegirías un framework en código en lugar de Agent Service?

Cuando necesitas control total de la orquestación en tu propio código base, quieres combinar modelos o proveedores, o ejecutar agentes dentro de tu aplicación existente.
