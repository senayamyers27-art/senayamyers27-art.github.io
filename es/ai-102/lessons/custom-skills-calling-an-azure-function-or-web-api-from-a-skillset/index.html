Skills personalizadas: llamar a una Azure Function o a una API web desde un skillset

Las skills integradas cubren las tareas de IA comunes, pero muchas organizaciones necesitan enriquecimientos que solo ellas pueden proporcionar: clasificar documentos con su propio modelo, buscar un ID de cliente en un sistema interno, extraer un formato de código propietario o llamar a un servicio especializado. Una skill personalizada conecta tu propio código a la canalización de enriquecimiento.

El tipo principal es la skill personalizada Web API (#Microsoft.Skills.Custom.WebApiSkill). Le das el URI de un endpoint HTTPS, a menudo una Azure Function, más entradas y salidas igual que a una skill integrada, y configuraciones opcionales como encabezados HTTP, tiempo de espera, tamaño de lote (cuántos documentos por solicitud) y grado de paralelismo. La autenticación puede usar una clave de función en el URI o en un encabezado, o una identidad administrada del servicio de búsqueda con un endpoint protegido por Entra ID. La variante AML skill llama a un modelo implementado en Azure Machine Learning o en el catálogo de modelos de Foundry.

La skill debe seguir una interfaz fija. El servicio de búsqueda hace un POST con un cuerpo JSON que contiene un arreglo values; cada elemento tiene un recordId y un objeto data con las entradas con nombre. Tu endpoint debe devolver un arreglo values con un elemento por cada registro de entrada, con el mismo recordId, un objeto data que contenga las salidas con nombre y arreglos opcionales errors y warnings. Devolver correctamente los recordId es esencial; así es como los resultados se vuelven a asociar con los documentos.

{ "values": [ { "recordId": "1",
    "data": { "documentType": "invoice", "confidence": 0.93 },
    "errors": [], "warnings": [] } ] }

En la definición del skillset, el contexto, las entradas (rutas en el árbol de enriquecimiento como /document/content) y las salidas (nombres que se convierten en nodos nuevos) de la skill personalizada la conectan con otras skills. Sus salidas pueden usarse luego en skills posteriores, asignarse a campos del índice con output field mappings o proyectarse a un knowledge store.

Diseña la función para que escale: maneja los lotes de forma eficiente, responde dentro del tiempo de espera, devuelve errores por registro en lugar de hacer fallar todo el lote y hazla idempotente, ya que los indexadores pueden reintentar. Pruébala con la sesión de depuración del portal o enviando directamente cargas de ejemplo. Ten en cuenta que el servicio de búsqueda llama a tu endpoint por cada documento, así que el costo y el rendimiento de la función importan en corpus grandes.

Términos clave

Custom skill (skill personalizada)
Una skill que llama a tu propio código, como una Azure Function, durante el enriquecimiento con IA.
WebApiSkill
El tipo de skill que llama a un endpoint HTTPS externo con una interfaz JSON definida.
recordId
El identificador que vincula cada registro de entrada con su salida en la interfaz de la skill personalizada.
values array (arreglo values)
El arreglo de nivel superior de registros que se envía a una skill personalizada y que esta devuelve.
Ejemplo real

Una aseguradora quiere que cada reclamación indexada se etiquete con su banda interna de riesgo de fraude. Envuelve su modelo de riesgo existente en una Azure Function que acepta el arreglo values de la skill personalizada, agrega una WebApiSkill con un tamaño de lote de 10, asigna la salida riskBand a un campo filtrable del índice, y los investigadores filtran los resultados de búsqueda por riesgo alto.

Consejo para el examen: Tu propio modelo o búsqueda durante la indexación significa una skill personalizada Web API. El endpoint debe aceptar y devolver un arreglo values con recordId coincidentes y un objeto data.

Comprueba lo que sabes

¿Qué debe incluir cada registro de salida de una skill personalizada?

El mismo recordId que el registro de entrada y un objeto data con los valores de salida, además de errors y warnings opcionales.

¿Cómo puede el servicio de búsqueda autenticarse en el endpoint de una skill personalizada sin una clave?

Usando la identidad administrada del servicio de búsqueda para obtener un token de Entra ID para un endpoint protegido con Entra ID.
