Operación de aplicaciones de IA generativa: uso de tokens, límites de velocidad, latencia, seguimiento y supervisión

Lograr que un prototipo responda bien es la mitad del trabajo; ejecutarlo para miles de usuarios es la otra mitad. Operar una aplicación de IA generativa significa controlar el costo, mantenerse dentro de los límites de velocidad, mantener una latencia aceptable y poder ver por qué se produjo una respuesta determinada.

Los tokens determinan el costo y la velocidad. Cada solicitud se factura por tokens de entrada (prompt) y tokens de salida (completion), que se informan en el campo usage. Los mensajes del sistema largos, los historiales de chat completos y muchos fragmentos recuperados agregan tokens de entrada en cada llamada. Redúcelos recortando o resumiendo el historial, recuperando menos fragmentos pero mejores y eligiendo instrucciones concisas. Limita la salida con el máximo de tokens y pidiendo respuestas breves. Usa el modelo más pequeño que cumpla tu nivel de calidad y reserva los modelos grandes o de razonamiento para las solicitudes que los necesiten. El prompt caching puede reducir el costo y la latencia cuando muchas solicitudes comparten el mismo prefijo largo de prompt, así que coloca primero el contenido fijo, como el mensaje del sistema.

Los límites de velocidad protegen la capacidad compartida. Las implementaciones de pago por uso tienen límites de tokens por minuto y de solicitudes por minuto. Cuando se superan, el servicio devuelve 429 con un encabezado retry-after. Los clientes deben reintentar con espera exponencial (exponential backoff) y variación aleatoria (jitter); los SDK de OpenAI reintentan algunos errores automáticamente. A escala, reparte el tráfico entre varias implementaciones o regiones, a menudo detrás de Azure API Management actuando como gateway de IA que puede balancear la carga, imponer límites de tokens por aplicación y registrar el uso. Para un volumen alto y constante, el rendimiento aprovisionado da capacidad reservada, y las implementaciones batch manejan trabajos grandes sin conexión de forma económica.

La latencia proviene sobre todo de la longitud de la salida y del tamaño del modelo. Transmite las respuestas por streaming para que los usuarios vean el texto de inmediato, mantén las salidas cortas, ejecuta en paralelo los pasos independientes y elige una región cercana a los usuarios.

La observabilidad lo une todo. Las métricas de Azure Monitor en el recurso muestran solicitudes, conteos de tokens, errores y limitaciones a lo largo del tiempo. Las configuraciones de diagnóstico envían registros a Log Analytics. Dentro de la aplicación, el seguimiento (tracing) con OpenTelemetry registra cada paso (recuperación, llamadas al modelo, llamadas a herramientas) con entradas, salidas, tokens y tiempos, y Azure AI Foundry muestra esas trazas cuando el proyecto está conectado a Application Insights. El seguimiento es la forma de descubrir que una mala respuesta vino de un mal resultado de recuperación y no del modelo. Combínalo con la evaluación continua de una muestra del tráfico de producción y con la retroalimentación de los usuarios, como pulgar arriba o abajo.

Por último, planifica los retiros de versiones de modelos: fija las versiones para tener estabilidad, prueba las versiones nuevas con tu conjunto de evaluación y luego actualiza la implementación.

Términos clave

Prompt tokens (tokens del prompt)
Los tokens de entrada de una solicitud, incluidos el mensaje del sistema, el historial y el contexto recuperado.
Exponential backoff (espera exponencial)
Reintentar las solicitudes fallidas con tiempos de espera crecientes para no saturar un servicio.
Tracing (seguimiento)
Registrar cada paso de una solicitud con entradas, salidas, tiempos y uso de tokens para depurar.
AI gateway (gateway de IA)
Una capa como Azure API Management delante de las implementaciones de modelos que balancea la carga, impone límites y registra el uso.
Ejemplo real

El chatbot de una tienda empieza a devolver errores 429 en Black Friday. El equipo agrega espera exponencial, coloca API Management delante de dos implementaciones regionales para repartir la carga, recorta el historial del chat a los últimos seis turnos y activa el seguimiento, que muestra que la recuperación agrega ocho fragmentos innecesarios por llamada.

Consejo para el examen: 429 significa límites de velocidad: espera y reintenta, agrega cuota o implementaciones, o usa rendimiento aprovisionado. Encontrar qué paso causó una respuesta lenta o mala significa seguimiento con Application Insights.

Comprueba lo que sabes

Menciona tres formas de reducir el costo en tokens de una aplicación de chat RAG.

Recortar o resumir el historial del chat, recuperar menos fragmentos y más pequeños, acortar las instrucciones, limitar la longitud de la salida o usar un modelo más pequeño.

¿Qué muestra el seguimiento que las métricas del recurso no muestran?

Los pasos individuales de cada solicitud, como la recuperación y las llamadas al modelo, con sus entradas, salidas, tiempos y tokens.
