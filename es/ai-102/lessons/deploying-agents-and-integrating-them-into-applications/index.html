Implementación de agentes e integración en aplicaciones

Un agente que funciona en el playground todavía tiene que llegar a los usuarios. Implementar significa poner el agente a disposición de las aplicaciones con la identidad, las redes, el control de versiones y las operaciones adecuados, e integrar significa conectarlo con los canales y sistemas donde los usuarios ya trabajan.

Con Azure AI Foundry Agent Service, el agente en sí lo aloja el servicio. Tu aplicación, como una aplicación web, una API o una función, llama al servicio a través del endpoint del proyecto de Foundry usando el SDK o la API REST, y se autentica con Microsoft Entra ID, idealmente mediante una identidad administrada con un rol adecuado en el proyecto. La aplicación es responsable de asignar usuarios a hilos, enviar sus mensajes, iniciar ejecuciones, manejar requires_action para las funciones locales y mostrar las respuestas, incluidas las citas y los archivos generados. Transmite las respuestas por streaming para que los usuarios vean el progreso. Guarda los ID de hilo con la sesión del usuario para que las conversaciones puedan reanudarse.

Los agentes creados con un framework como Semantic Kernel o Microsoft Agent Framework se ejecutan dentro de tu propio código, así que los implementas como cualquier otra aplicación: imágenes de contenedor en Azure Container Apps o Azure Kubernetes Service, Azure App Service o Azure Functions. Tú administras el escalado, el almacenamiento del estado y los secretos, lo que te da más control.

Los canales de integración varían. Una interfaz de chat web es común. Los agentes pueden publicarse en Microsoft Teams y Microsoft 365 Copilot mediante Microsoft 365 Agents SDK o Copilot Studio, y exponerse a otros sistemas mediante API. Los agentes también pueden activarse por eventos, como un correo nuevo, un mensaje en una cola o un trabajo programado, en lugar de por una persona que chatea.

Trata la configuración del agente como código. Mantén las instrucciones, las definiciones de herramientas y las elecciones de modelo en control de código fuente, impleméntalas mediante una canalización en proyectos separados de desarrollo, pruebas y producción, y ejecuta tu conjunto de pruebas de evaluación como puerta de calidad antes de promoverlas. Fija las versiones de los modelos y prueba las actualizaciones antes de cambiar.

En entornos empresariales, usa redes privadas (la configuración estándar permite traer tu propia red virtual y tus propios recursos), conserva los datos en tu propio almacenamiento cuando sea necesario, aplica filtros de contenido y configura la supervisión y las alertas desde el primer día.

Términos clave

Project endpoint (endpoint del proyecto)
La URL del proyecto de Foundry que usan las aplicaciones con el SDK para llamar a Agent Service.
Thread mapping (asignación de hilos)
Guardar el ID de hilo de cada usuario para que su conversación pueda continuar entre solicitudes.
Quality gate (puerta de calidad)
Una evaluación automatizada que debe aprobarse antes de promover un cambio al siguiente entorno.
Standard setup (configuración estándar)
Una configuración de Agent Service que usa tus propios recursos de almacenamiento, búsqueda y red para los datos de los agentes.
Ejemplo real

Una empresa implementa su agente de soporte de TI en un proyecto de desarrollo, pasa 100 tickets de prueba por una canalización de evaluación y luego promueve las mismas instrucciones y herramientas a producción. Una aplicación web con una identidad administrada llama al proyecto de producción, y el agente también se publica en Teams para que los empleados puedan chatear donde trabajan.

Consejo para el examen: Las aplicaciones llaman a los agentes alojados a través del endpoint del proyecto con Entra ID, idealmente con una identidad administrada. Los agentes basados en frameworks se implementan como cualquier aplicación (Container Apps, App Service, Functions).

Comprueba lo que sabes

¿Qué debe rastrear una aplicación para continuar la conversación de un usuario con un agente alojado?

El ID de hilo del usuario, para que los mensajes nuevos se agreguen al mismo hilo.

¿Cómo deberían llegar de forma segura a producción los cambios en las instrucciones de un agente?

Mediante control de código fuente y una canalización que ejecute un conjunto de pruebas de evaluación como puerta de calidad antes de promoverlos.
