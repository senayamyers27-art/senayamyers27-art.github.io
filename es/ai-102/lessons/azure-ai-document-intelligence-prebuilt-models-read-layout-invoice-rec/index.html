Modelos precompilados de Azure AI Document Intelligence: read, layout, facturas, recibos y documentos de identidad

Azure AI Document Intelligence (antes Form Recognizer) extrae texto, estructura y datos de documentos como PDF, imágenes escaneadas y archivos de Office. Mientras que el OCR por sí solo te da líneas de texto, Document Intelligence entiende los documentos: párrafos, tablas, casillas de verificación y campos con nombre como los totales de las facturas. Los modelos precompilados funcionan de inmediato sin entrenamiento.

Los modelos fundamentales son generales. El modelo read (prebuilt-read) extrae líneas y palabras de texto impreso y manuscrito con sus posiciones, detecta idiomas y maneja documentos de varias páginas; es el motor de OCR para documentos. El modelo layout (prebuilt-layout) agrega estructura: párrafos con roles como título y encabezado de sección, tablas con filas, columnas y celdas combinadas, marcas de selección (casillas y botones de opción) y figuras, y puede generar el documento como markdown, lo que es muy útil para fragmentar documentos en canalizaciones RAG.

Los modelos precompilados por escenario extraen campos con nombre para tipos de documentos comunes. El modelo de facturas devuelve campos como VendorName, CustomerName, InvoiceId, InvoiceDate, DueDate, las partidas (line items) e InvoiceTotal. El modelo de recibos devuelve MerchantName, TransactionDate, Items, Subtotal, Tax y Total de recibos impresos y fotografiados. El modelo de documentos de identidad lee pasaportes y licencias de conducir, y devuelve campos como nombre, fecha de nacimiento, número de documento y fecha de vencimiento. Hay más, como formularios fiscales de EE. UU., tarjetas de seguro médico, contratos, estados de cuenta bancarios, recibos de nómina y tarjetas de presentación, según la versión de la API. Cada campo viene con un valor, un tipo, su ubicación y una puntuación de confianza.

El análisis es asíncrono. En REST, haces un POST del documento (una URL o los bytes del archivo) a la operación analyze del modelo; la respuesta es 202 Accepted con un encabezado Operation-Location, que consultas con GET hasta que el estado sea succeeded y se incluya el resultado. El SDK oculta esto con un poller: begin_analyze_document("prebuilt-invoice", body) devuelve un poller, y .result() espera a que termine.

poller = client.begin_analyze_document("prebuilt-receipt", AnalyzeDocumentRequest(url_source=receipt_url))
receipt = poller.result().documents[0]
total = receipt.fields.get("Total")
print(total.content, total.confidence)

Usa las puntuaciones de confianza para decidir qué automatizar: acepta los campos con confianza alta y envía los de confianza baja a revisión humana. Document Intelligence Studio te permite probar todos los modelos con tus propios archivos antes de escribir código. El nivel gratuito procesa solo un número limitado de páginas, suficiente para aprender. Si ningún modelo precompilado encaja con tus documentos, entrena un modelo personalizado, que es la siguiente lección.

Términos clave

Read model (modelo read)
El modelo de Document Intelligence que extrae líneas y palabras de texto de los documentos.
Layout model (modelo layout)
El modelo que extrae texto más estructura: párrafos, tablas, marcas de selección y figuras.
Prebuilt model (modelo precompilado)
Un modelo listo para usar que extrae campos con nombre de un tipo de documento común, como facturas o recibos.
Confidence score (puntuación de confianza)
Un valor de 0 a 1 que indica qué tan seguro está el modelo sobre un campo extraído.
Ejemplo real

Una aplicación de gastos envía fotos de recibos a prebuilt-receipt, acepta automáticamente los totales con confianza superior a 0.9 y le pide al empleado que confirme el resto. Las facturas de proveedores van a prebuilt-invoice, y los documentos de políticas escaneados van a prebuilt-layout, cuya salida en markdown se fragmenta para el asistente RAG de la empresa.

Consejo para el examen: Solo texto: read. Tablas, casillas y estructura sin campos con nombre: layout. Campos con nombre de documentos comunes: el modelo precompilado correspondiente. 202 más Operation-Location significa consultar periódicamente el resultado.

Comprueba lo que sabes

¿Qué modelo usarías para extraer tablas de informes trimestrales?

prebuilt-layout, que devuelve tablas con filas, columnas y celdas junto con el resto de la estructura.

¿Qué significa una respuesta 202 de una llamada analyze?

Que el análisis se aceptó y está en curso; consulta la URL de Operation-Location hasta que termine correctamente.
