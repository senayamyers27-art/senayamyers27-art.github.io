Protección de claves y redes: Azure Key Vault, rotación de claves, endpoints privados y restricciones de red

Incluso cuando planeas pasar a Microsoft Entra ID, muchas aplicaciones siguen usando claves, y todo recurso es accesible por la red. Proteger una solución de Azure AI significa proteger los secretos y limitar quién puede siquiera llegar al endpoint.

Azure Key Vault es el lugar para las claves y las cadenas de conexión. Guarda la clave del recurso de IA como un secreto de Key Vault, dale a la identidad administrada de la aplicación permiso para leer secretos (por ejemplo, el rol Key Vault Secrets User) y haz que la aplicación obtenga el secreto al iniciar o mediante una referencia de Key Vault de App Service. Key Vault registra cada acceso, admite versiones y te permite cambiar el secreto en un solo lugar. Nunca pongas claves en el código fuente, en Dockerfiles, en JavaScript del lado del cliente ni en aplicaciones móviles, de donde cualquiera puede extraerlas.

Cada recurso tiene dos claves para que puedas rotarlas sin tiempo de inactividad. El patrón es: pasa todos los clientes a la clave 2, regenera la clave 1 y, más adelante, vuelve a pasar los clientes a la clave 1 y regenera la clave 2. Si la clave vive en Key Vault, mover los clientes significa actualizar un solo secreto. Regenera de inmediato si una clave se filtra. Puedes regenerar con az cognitiveservices account keys regenerate --key-name key1.

Los controles de red limitan desde dónde pueden llegar las llamadas. En la página Networking del recurso puedes permitir todas las redes, permitir solo redes virtuales e intervalos de IP públicas seleccionados (el firewall del recurso) o deshabilitar por completo el acceso público. Las redes seleccionadas pueden usar endpoints de servicio de red virtual para que se reconozca el tráfico de una subred. Un endpoint privado va más allá: le da al recurso una dirección IP privada dentro de tu red virtual y, con una zona DNS privada, el nombre de host normal del recurso se resuelve a esa IP privada para los clientes de la red, de las redes emparejadas y de las redes locales conectadas por VPN o ExpressRoute. Combina un endpoint privado con el acceso de red pública deshabilitado para mantener el recurso fuera de internet.

Algunas funciones llaman a otros servicios en tu nombre (por ejemplo, Azure AI Search accediendo a una cuenta de almacenamiento, o Azure OpenAI usando tus datos). Cuando restringes las redes, concede acceso a esos servicios con identidades administradas, excepciones de servicios de confianza o shared private links para que la solución siga funcionando. El cifrado en reposo está activado de forma predeterminada con claves administradas por Microsoft, y muchos servicios admiten claves administradas por el cliente en Key Vault cuando la directiva exige controlar las claves de cifrado.

Términos clave

Azure Key Vault
Un servicio administrado para guardar y auditar secretos, claves y certificados.
Key rotation (rotación de claves)
Reemplazar las claves con regularidad, usando el patrón de dos claves para que los clientes nunca pierdan el acceso.
Private endpoint (endpoint privado)
Una interfaz de red con una IP privada en tu red virtual que se conecta de forma privada a un recurso de Azure.
Customer-managed key (clave administrada por el cliente)
Una clave de cifrado que te pertenece, guardada en Key Vault, que se usa para cifrar los datos en reposo de un servicio en lugar de una clave administrada por Microsoft.
Ejemplo real

Después de que se encuentra una clave de Language en un repositorio público, el equipo regenera la clave 1 de inmediato, guarda la clave 2 como secreto de Key Vault que lee la identidad administrada de la aplicación, agrega un endpoint privado al recurso y deshabilita el acceso de red pública, de modo que una clave filtrada ya no podría usarse desde internet.

Consejo para el examen: La rotación sin tiempo de inactividad siempre es: cambia a la otra clave y luego regenera. Mantener un recurso fuera de internet es un endpoint privado más deshabilitar el acceso de red pública.

Describe la rotación de claves sin tiempo de inactividad.

Pasa los clientes a la clave 2, regenera la clave 1; después pasa los clientes a la clave 1 y regenera la clave 2.

¿Qué necesita un endpoint privado para que los clientes sigan usando el nombre de host normal?

Una zona DNS privada que resuelva el nombre de host del recurso a la dirección IP privada.
