Azure AI Foundry Agent Service: agentes, hilos, mensajes y ejecuciones

Azure AI Foundry Agent Service es un servicio administrado para crear y alojar agentes. Se encarga de las partes que son tediosas de construir por tu cuenta: guardar el estado de la conversación, llamar a herramientas, administrar archivos y almacenes vectoriales, aplicar filtros de contenido y hacer seguimiento. Tú defines el agente y el servicio ejecuta el ciclo de llamadas al modelo y a las herramientas. Puedes crear agentes en la página Agents de un proyecto de Foundry o en código con los SDK de Azure AI Projects o Agents para Python, C# y otros lenguajes.

Hay cuatro objetos importantes. Un agente (agent) es una definición: una implementación de modelo, un nombre, instrucciones y un conjunto de herramientas (con sus recursos, como archivos para la búsqueda de archivos). Un hilo (thread) es una sesión de conversación entre un usuario y un agente; guarda los mensajes y crece a medida que avanza la conversación, y el servicio administra el truncamiento para que quepa en la ventana de contexto del modelo. Un mensaje (message) es una entrada en un hilo, del usuario o del agente, y puede contener texto, imágenes o referencias a archivos. Una ejecución (run) es una activación de un agente sobre un hilo: lee el hilo, llama al modelo y a las herramientas necesarias, y agrega los mensajes de respuesta del agente.

El flujo básico en código es: crea el cliente del proyecto con el endpoint de tu proyecto y DefaultAzureCredential; crea un agente con un modelo, instrucciones y herramientas; crea un hilo; agrega un mensaje del usuario al hilo; crea una ejecución (o usa un método auxiliar que crea y procesa la ejecución); luego lista los mensajes del hilo para leer la respuesta. Para el siguiente turno del usuario, agrega otro mensaje al mismo hilo y crea otra ejecución.

Una ejecución pasa por distintos estados. Empieza como queued y luego in_progress. Si el agente llama a una función que tu código debe ejecutar, la ejecución se pausa en requires_action: tu aplicación lee las llamadas a herramientas, ejecuta las funciones y envía las salidas de las herramientas, y la ejecución continúa. Termina como completed, failed, cancelled o expired (por ejemplo, si las salidas de las herramientas no se enviaron a tiempo). Cada ejecución se compone de pasos de ejecución (run steps), como la creación de un mensaje o una llamada a una herramienta, que puedes inspeccionar para ver exactamente qué hizo el agente.

Los agentes, hilos y archivos persisten hasta que los eliminas, así que las aplicaciones en producción suelen asignar cada conversación de usuario a un ID de hilo y limpiar los hilos antiguos. El servicio puede usar almacenamiento administrado por Microsoft o tus propios recursos (una configuración estándar con tu propio almacenamiento, Cosmos DB y búsqueda) cuando necesitas que los datos permanezcan en recursos que controlas.

Términos clave

Agent (agente)
En Agent Service, una definición que combina una implementación de modelo, instrucciones y herramientas.
Run (ejecución)
Una activación de un agente sobre un hilo que procesa mensajes y llamadas a herramientas y agrega respuestas.
requires_action
Un estado de ejecución que significa que la aplicación debe ejecutar las llamadas a funciones solicitadas y enviar sus salidas.
Run step (paso de ejecución)
Una acción individual dentro de una ejecución, como una llamada a herramienta o la creación de un mensaje, que se usa para inspeccionar y depurar.
Ejemplo real

La mesa de ayuda de una universidad crea un agente con instrucciones y una herramienta de búsqueda de archivos sobre las políticas de los cursos. Cada chat de estudiante se asigna a un hilo. Cuando un estudiante hace una pregunta, la aplicación agrega un mensaje y crea una ejecución; cuando la ejecución termina, muestra el mensaje más reciente del agente con sus citas.

Consejo para el examen: El historial de la conversación vive en el hilo, el comportamiento en el agente y el procesamiento en la ejecución. requires_action significa que tu código debe ejecutar la función y enviar las salidas de las herramientas.

Comprueba lo que sabes

¿Cómo continúas una conversación con un agente de Agent Service?

Agrega un nuevo mensaje del usuario al mismo hilo y crea otra ejecución sobre él.

¿Qué debe hacer una aplicación cuando el estado de una ejecución es requires_action?

Leer las llamadas a herramientas solicitadas, ejecutar las funciones y enviar las salidas de las herramientas para que la ejecución pueda continuar.
