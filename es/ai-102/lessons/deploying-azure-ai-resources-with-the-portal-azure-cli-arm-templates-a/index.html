Implementación de recursos de Azure AI con el portal, la CLI de Azure, plantillas ARM y Bicep

Puedes crear cualquier recurso de Azure AI haciendo clic en el portal de Azure o en el portal de Foundry, y es una buena manera de aprender. Sin embargo, en producción los equipos implementan con scripts e infraestructura como código para que los entornos sean repetibles, revisados y fáciles de reconstruir. El examen espera que reconozcas las opciones principales y que sepas leer una plantilla corta.

Con la CLI de Azure, los recursos de IA se administran con el grupo de comandos az cognitiveservices. Por ejemplo, az cognitiveservices account create --name lang-demo --resource-group rg-ai --kind TextAnalytics --sku F0 --location eastus --custom-domain lang-demo crea un recurso de Language con un subdominio personalizado. az cognitiveservices account keys list muestra sus claves, y az cognitiveservices account deployment create crea una implementación de modelo en un recurso de Azure OpenAI o de AI services. PowerShell ofrece cmdlets equivalentes de Az.CognitiveServices, como New-AzCognitiveServicesAccount.

En las plantillas, el tipo de recurso es Microsoft.CognitiveServices/accounts. Hay tres propiedades que importan más. kind decide qué servicio es el recurso: por ejemplo TextAnalytics para Language, SpeechServices, ComputerVision, FormRecognizer para Document Intelligence, OpenAI o AIServices para el recurso multiservicio. sku.name establece el nivel de precios, como F0 o S0. Dentro de properties, customSubDomainName define el nombre de endpoint único necesario para la autenticación con Microsoft Entra ID y los endpoints privados, publicNetworkAccess puede establecerse en Disabled y disableLocalAuth: true desactiva la autenticación con claves.

resource lang 'Microsoft.CognitiveServices/accounts@2023-05-01' = {
  name: 'lang-demo'
  location: 'eastus'
  kind: 'TextAnalytics'
  sku: { name: 'F0' }
  identity: { type: 'SystemAssigned' }
  properties: {
    customSubDomainName: 'lang-demo'
    publicNetworkAccess: 'Enabled'
  }
}

Las implementaciones de modelos son un recurso secundario, Microsoft.CognitiveServices/accounts/deployments, con el nombre y la versión del modelo y un sku cuyo nombre es el tipo de implementación (como Standard o GlobalStandard) y cuya capacidad establece la cuota. Implementa un archivo Bicep con az deployment group create --resource-group rg-ai --template-file main.bicep. Bicep se compila a una plantilla ARM en JSON, así que ambos describen los mismos recursos; Bicep simplemente es más fácil de leer y escribir.

La infraestructura como código también hace que la configuración de seguridad sea coherente: cada entorno recibe la misma identidad administrada, las mismas reglas de red y el mismo acceso con claves deshabilitado, en lugar de depender de que alguien recuerde marcar las casillas correctas.

Términos clave

kind
La propiedad de la plantilla que establece qué servicio de IA proporciona un recurso Microsoft.CognitiveServices/accounts.
Bicep
Un lenguaje específico de dominio para infraestructura como código en Azure que se compila a plantillas ARM en JSON.
customSubDomainName
La propiedad que da a un recurso un nombre de endpoint único, necesario para la autenticación con Entra ID y los endpoints privados.
disableLocalAuth
Una propiedad que desactiva la autenticación basada en claves para que solo funcionen los tokens de Microsoft Entra ID.
Ejemplo real

Un equipo de plataforma mantiene un módulo de Bicep para recursos de IA. Cada equipo de aplicación lo implementa con una canalización, pasando el kind y el SKU. El módulo siempre habilita una identidad asignada por el sistema, define un subdominio personalizado y establece disableLocalAuth en true, para que ningún entorno dependa por accidente de las claves.

Consejo para el examen: En una pregunta sobre plantillas, mira kind para identificar el servicio y sku.name para el nivel. customSubDomainName es la propiedad ligada a la autenticación con Entra ID.

Comprueba lo que sabes

¿Qué propiedad cambiarías para convertir la plantilla de un recurso de Language en un recurso de Speech?

kind, de TextAnalytics a SpeechServices.

¿Cómo impides el acceso basado en claves a un recurso en una plantilla?

Establece disableLocalAuth en true dentro de properties para que solo se acepten tokens de Entra ID.
