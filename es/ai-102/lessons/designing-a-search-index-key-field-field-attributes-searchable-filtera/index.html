Diseño de un índice de búsqueda: campo clave, atributos de campo (searchable, filterable, sortable, facetable, retrievable), analizadores y suggesters

El esquema de un índice define los campos de cada documento de búsqueda y cómo puede usarse cada campo. Un buen diseño decide qué pueden buscar, filtrar, ordenar y ver los usuarios, y afecta el tamaño de almacenamiento y la relevancia. Algunos atributos no pueden cambiarse en un campo existente sin reconstruir el índice, así que diseña pensando en las consultas.

Todo índice necesita exactamente un campo clave de tipo Edm.String que identifique de forma única cada documento; los indexadores suelen asignarlo a partir de una ruta de almacenamiento o de la clave principal de una base de datos (codificando en base64 los valores que contienen caracteres no permitidos en las claves). Otros tipos de campo incluyen Edm.Int32, Edm.Int64, Edm.Double, Edm.Boolean, Edm.DateTimeOffset, Edm.GeographyPoint, colecciones como Collection(Edm.String) para listas de etiquetas, tipos complejos para objetos anidados y Collection(Edm.Single) para vectores.

Los atributos controlan el comportamiento. Searchable significa que el texto del campo se analiza y se incluye en la búsqueda de texto completo. Filterable permite usar el campo en expresiones $filter, como category eq 'Budget'. Sortable permite $orderby. Facetable permite conteos por faceta, como el número de hoteles por ciudad para una barra lateral de navegación. Retrievable significa que el campo puede devolverse en los resultados; desactívalo para campos que solo se usan para buscar o filtrar, como los vectores o puntuaciones internas. Cada atributo extra agrega almacenamiento, así que habilita solo lo que necesitas.

Los analizadores procesan el texto buscable en el momento de la indexación y de la consulta: dividen el texto en tokens, los pasan a minúsculas y pueden eliminar palabras vacías o reducir las palabras a su raíz. El predeterminado es el analizador estándar de Lucene. Los analizadores de idioma, como en.microsoft o fr.lucene, entienden las formas de las palabras de un idioma, así que una búsqueda de 'running' coincide con 'ran'. Los analizadores especializados como keyword (tratar todo el valor como un solo token) convienen para códigos e ID, y puedes crear analizadores personalizados. El analizador se define por campo.

Un suggester habilita el autocompletado (completar la palabra que se está escribiendo) y las sugerencias (devolver documentos coincidentes mientras el usuario escribe). Defines un suggester por índice, indicando los campos que usa como campos de origen, normalmente nombres y títulos. Debe definirse cuando se crean esos campos.

Otras funciones del esquema incluyen los perfiles de puntuación (scoring profiles), que aumentan la relevancia mediante pesos por campo o funciones de actualidad y distancia; los mapas de sinónimos asociados a campos para que 'USA' también coincida con 'United States'; las configuraciones semánticas para la clasificación semántica; los perfiles de búsqueda vectorial; y las opciones de CORS para clientes de navegador.

Términos clave

Key field (campo clave)
El único campo Edm.String que identifica de forma única cada documento de un índice.
Facetable
Un atributo de campo que habilita conteos de documentos por valor para la navegación por facetas.
Analyzer (analizador)
Un componente que divide en tokens y normaliza el texto para la búsqueda de texto completo, como un analizador de idioma.
Suggester
Una definición del índice que habilita el autocompletado y las sugerencias mientras se escribe en los campos elegidos.
Ejemplo real

Un sitio de búsqueda de hoteles marca name y description como searchable con el analizador en.microsoft, city y rating como filterable y facetable, price como sortable, y agrega un suggester sobre name. El campo vectorial de la descripción no es retrievable, lo que ahorra ancho de banda en cada respuesta.

Consejo para el examen: Relaciona la función de consulta con el atributo: $filter necesita filterable, $orderby necesita sortable, las facetas necesitan facetable, el texto completo necesita searchable y devolverse en los resultados necesita retrievable. El autocompletado necesita un suggester.

Comprueba lo que sabes

Una consulta con $orderby=price desc falla. ¿Cuál es la causa probable?

El campo price no está marcado como sortable.

¿Por qué usar un analizador de idioma en lugar del analizador estándar?

Entiende las formas de las palabras del idioma, así que distintas inflexiones como 'run' y 'running' coinciden, lo que mejora el recall.
