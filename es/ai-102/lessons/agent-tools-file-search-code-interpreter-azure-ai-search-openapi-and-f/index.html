Herramientas de agentes: file search, code interpreter, Azure AI Search, OpenAPI y function calling

Las herramientas son lo que hace que un agente sea más que un chatbot. Azure AI Foundry Agent Service ofrece herramientas integradas que el servicio ejecuta por ti, y formas de conectar tu propio código y tus API. Elegir la herramienta correcta para un escenario es una tarea frecuente en el examen.

Las herramientas de conocimiento fundamentan al agente en datos. File search te permite cargar archivos (como PDF, documentos de Word o texto) en un almacén vectorial; el servicio los fragmenta y genera sus embeddings, y el agente recupera pasajes relevantes y cita los archivos en sus respuestas. Es la forma más rápida de darle a un agente un conjunto de documentos. La herramienta Azure AI Search conecta el agente a un índice de búsqueda existente que tú administras, lo que conviene para contenido empresarial grande o que se actualiza con frecuencia, y te permite reutilizar índices, filtros y recorte por seguridad (security trimming) que ya construiste. Grounding with Bing Search permite que el agente busque en la web pública información actual. Hay otros conectores de conocimiento, como SharePoint o Microsoft Fabric, para orígenes de datos específicos.

Code interpreter permite que el agente escriba y ejecute Python en un entorno aislado (sandbox) seguro. Puede leer archivos cargados como CSV o Excel, realizar cálculos, transformar datos y producir gráficas o archivos nuevos que el usuario puede descargar. Úsalo siempre que la tarea requiera matemáticas precisas o procesamiento de datos, ya que los modelos de lenguaje por sí solos no son fiables en aritmética.

Las herramientas de acción permiten que el agente haga cosas. Function calling te permite describir tus propias funciones con nombres, descripciones y parámetros en JSON schema; cuando el modelo decide llamar a una, la ejecución se pausa con requires_action y tu código ejecuta la función y devuelve el resultado. Esto mantiene tu código y tus credenciales en tu aplicación. La herramienta Azure Functions permite que el agente llame a funciones alojadas en Azure Functions, normalmente mediante colas, sin que tu código cliente las ejecute. La herramienta OpenAPI te permite darle al agente una especificación OpenAPI 3 de una API REST existente, con autenticación anónima, por clave de API o por identidad administrada, para que pueda llamar a las operaciones de la API directamente desde el servicio. Los agentes también pueden llamar a otros agentes como herramientas (connected agents) y conectarse a servidores Model Context Protocol (MCP).

Las descripciones de las herramientas importan. El modelo decide qué herramienta llamar según los nombres y las descripciones que le das, así que escríbelas con claridad y mantén el conjunto pequeño y pertinente. Dale a cada herramienta solo los permisos que necesita.

Términos clave

File search
Una herramienta integrada de agentes que indexa archivos cargados en un almacén vectorial y recupera pasajes con citas.
Code interpreter
Una herramienta integrada de agentes que escribe y ejecuta Python en un sandbox para cálculos, procesamiento de datos y gráficas.
OpenAPI tool (herramienta OpenAPI)
Una herramienta que permite a un agente llamar a una API REST descrita por una especificación OpenAPI.
Vector store (almacén vectorial)
El almacén administrado de archivos fragmentados y convertidos en embeddings que consulta file search.
Ejemplo real

Un agente de finanzas tiene tres herramientas: file search sobre la política de gastos, code interpreter para sumar una hoja de cálculo de gastos y graficar el gasto por categoría, y una herramienta OpenAPI que envía los informes aprobados a la API REST del sistema de gastos.

Consejo para el examen: Cálculos o gráficas a partir de datos cargados: code interpreter. Respuestas a partir de documentos cargados: file search. Índice empresarial existente: herramienta Azure AI Search. API REST existente con especificación: OpenAPI. Tu propio código en tu aplicación: function calling.

Comprueba lo que sabes

Un agente debe responder preguntas a partir de un índice existente de Azure AI Search con filtrado de seguridad. ¿Qué herramienta encaja?

La herramienta Azure AI Search, que conecta el agente a ese índice existente.

¿Por qué usar code interpreter en lugar de pedirle al modelo que sume números?

Ejecuta Python real, así que el cálculo es exacto, mientras que los modelos por sí solos no son fiables en aritmética.
