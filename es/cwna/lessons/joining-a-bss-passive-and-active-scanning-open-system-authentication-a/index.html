CWNP Certified Wireless Network Administrator CWNA-109

Unirse a un BSS: escaneo pasivo y activo, autenticación Open System, asociación y el 4-way handshake

Antes de que un cliente pueda enviar datos a través de un AP, pasa por una secuencia fija: descubrir la red, autenticarse a nivel 802.11, asociarse y, en una red protegida, completar el intercambio de seguridad que crea las claves de cifrado. Conocer esta secuencia trama por trama te permite identificar con exactitud dónde falla una conexión.

El descubrimiento se hace mediante escaneo. En el escaneo pasivo, el cliente escucha en cada canal los beacons que los APs envían unas diez veces por segundo. En el escaneo activo, el cliente envía probe requests en cada canal, ya sea para un SSID específico (un directed probe) o para cualquier SSID (un wildcard o null probe), y los APs responden con probe responses que contienen el mismo tipo de información que los beacons. La mayoría de los clientes usa ambos métodos, y muchos escanean periódicamente en segundo plano. En los canales DFS y en 6 GHz, los clientes tienen restricciones para el sondeo activo y dependen más de los métodos pasivos.

Después viene la autenticación 802.11. La autenticación Open System es un intercambio de dos tramas: el cliente envía una solicitud de autenticación y el AP devuelve una respuesta de éxito. No realiza ninguna verificación real de identidad; existe por compatibilidad con la máquina de estados. El antiguo método Shared Key usaba WEP y está obsoleto. En WPA3-Personal, SAE (Simultaneous Authentication of Equals) usa esas mismas tramas de autenticación para realizar un intercambio seguro basado en contraseña.

Tras la autenticación, el cliente envía una association request que enumera sus capacidades, las tasas soportadas, las opciones de seguridad elegidas en el RSN element y el SSID solicitado. El AP responde con una association response que contiene un código de estado y un association identifier (AID), un número que se usa más adelante en la administración de energía. El estándar 802.11 describe esto como pasar de no autenticado y no asociado, a autenticado y no asociado, y luego a autenticado y asociado.

En una red abierta, los datos ya pueden fluir. En una red WPA2 o WPA3, el controlled port del AP sigue bloqueado para el tráfico de usuario hasta que se establecen las claves. Con seguridad Enterprise, a continuación se ejecuta la autenticación 802.1X/EAP entre el cliente, el AP (como authenticator) y un servidor RADIUS, lo que produce una Pairwise Master Key (PMK). Con seguridad Personal, la PMK proviene de la passphrase (WPA2) o de SAE (WPA3).

Luego, el 4-way handshake usa tramas EAPOL-Key para demostrar que ambas partes tienen la PMK y derivar claves nuevas sin enviar la PMK en sí. En el mensaje 1, el AP envía un número aleatorio llamado ANonce. El cliente combina la PMK, ambos nonces y ambas direcciones MAC para derivar la Pairwise Transient Key (PTK). En el mensaje 2, el cliente envía su SNonce con un message integrity code (MIC). El AP deriva la misma PTK y, en el mensaje 3, confirma y entrega, cifrada, la Group Temporal Key (GTK) que se usa para broadcast y multicast. El mensaje 4 confirma la recepción. Ahora pueden fluir los datos cifrados.

Al diagnosticar problemas, encuentra el último paso exitoso. La ausencia de probe response sugiere problemas de descubrimiento o de SSID; un rechazo de asociación apunta a capacidades o políticas; una falla después de EAP sugiere credenciales o RADIUS; una falla en el mensaje 2 o 3 del 4-way handshake suele indicar una passphrase incorrecta.

Términos clave

Passive scanning (escaneo pasivo)
Descubrir redes escuchando los beacons en cada canal.
Active scanning (escaneo activo)
Descubrir redes enviando probe requests y recibiendo probe responses.
Open System authentication
Un intercambio de autenticación 802.11 de dos tramas que no realiza ninguna verificación real de identidad.
Association identifier (AID)
Un número que el AP asigna a un cliente en la association response y que se usa en el TIM para la administración de energía.
4-way handshake
Un intercambio EAPOL-Key que confirma que ambas partes tienen la PMK, deriva la PTK y entrega la GTK.
Ejemplo real

Un usuario reporta que un teléfono nuevo no puede unirse a la red WPA2-Personal. La captura muestra que el probe, la autenticación y la asociación tienen éxito; luego el AP envía el mensaje 1 del 4-way handshake, el teléfono responde con el mensaje 2 y el AP nunca envía el mensaje 3. El MIC del mensaje 2 falló, lo que apunta a una passphrase mal escrita.

Consejo para el examen: El orden importa: escaneo, autenticación 802.11, asociación, luego 802.1X/EAP (si es Enterprise) y después el 4-way handshake. La autenticación Open System no es seguridad; la autenticación real ocurre con 802.1X/EAP o SAE.

Comprueba lo que sabes

¿Cuál es la diferencia entre el escaneo pasivo y el activo?

El escaneo pasivo escucha beacons; el escaneo activo envía probe requests y espera probe responses.

¿Qué clave se entrega al cliente en el mensaje 3 del 4-way handshake?

La Group Temporal Key (GTK), que se usa para el tráfico broadcast y multicast.

¿La autenticación Open System verifica la identidad del usuario?

No. Es un simple intercambio de dos tramas; la identidad se verifica después mediante 802.1X/EAP, SAE o la PSK.
