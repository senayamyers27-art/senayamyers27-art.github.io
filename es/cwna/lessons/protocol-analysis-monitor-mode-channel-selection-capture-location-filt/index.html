CWNP Certified Wireless Network Administrator CWNA-109

Análisis de protocolos: monitor mode, selección de canal, ubicación de captura y filtros

Un analizador de protocolos captura y decodifica tramas 802.11 para que puedas ver exactamente lo que los dispositivos se dicen entre sí: probes, authentication, association, 4-way handshakes, datos, reintentos y desconexiones. Es la herramienta que explica por qué un cliente se comporta como lo hace, en lugar de solo mostrar que algo está mal.

Para capturar correctamente las tramas Wi-Fi, el adaptador debe estar en monitor mode (también llamado RF monitor mode). En modo normal, un adaptador está asociado a una red y solo le pasa al sistema operativo su propio tráfico, ya convertido a Ethernet. En monitor mode, no está asociado y pasa hacia arriba cada trama 802.11 que puede oír en el canal sintonizado, incluidas las tramas de administración y de control y las tramas dirigidas a otros dispositivos, normalmente con un encabezado radiotap que agrega información de intensidad de señal, tasa de datos y canal. El soporte de monitor mode depende del adaptador y del driver; en Linux podrías activarlo con comandos iw, y algunos productos de análisis incluyen adaptadores compatibles.

Un radio solo puede escuchar en un canal a la vez. Debes elegir el canal del AP y del cliente que estás diagnosticando, y hacer coincidir el ancho de canal si quieres capturar tramas de canales anchos. Si vas cambiando de canal, perderás las tramas de cada canal mientras estás fuera. Para capturar un evento de roaming entre APs en canales distintos, necesitas varios adaptadores, uno por canal, capturando al mismo tiempo. Ten en cuenta también que un adaptador no puede decodificar tramas que usan más spatial streams o una PHY más nueva de las que soporta.

La ubicación de captura importa. El adaptador solo registra lo que puede oír, y lo que oye no es necesariamente lo que oyen el AP o el cliente. Para ver lo que vive un cliente, incluidos los reintentos y las tramas que no recibe, coloca el analizador cerca del cliente. Para ver la perspectiva del AP, captura cerca del AP. Los problemas de hidden node, por ejemplo, solo se hacen visibles cuando entiendes dónde está cada dispositivo. Muchos APs empresariales también pueden capturar desde su propio radio y enviar las tramas a un analizador.

Los filtros hacen manejables las capturas grandes. Los capture filters (filtros de captura) limitan lo que se guarda; los display filters (filtros de visualización) ocultan las tramas que no necesitas mientras revisas. En Wireshark, algunos display filters útiles son wlan.addr == aa:bb:cc:dd:ee:ff para un dispositivo, eapol para los 4-way handshakes, wlan.fc.type_subtype == 0x08 para los beacons, wlan.fc.type_subtype == 0x0c para las tramas de deauthentication y wlan.fc.retry == 1 para las retransmisiones.

Recuerda que las tramas de datos cifradas solo se pueden decodificar si tienes las claves y capturaste el handshake; de lo contrario, solo ves los encabezados. Las tramas de administración y el propio handshake suelen ser suficientes para diagnosticar la mayoría de los problemas de conexión. Captura solo en redes que tengas autorización para analizar.

Términos clave

Monitor mode
Un modo del adaptador que captura todas las tramas 802.11 de un canal sin asociarse a una red.
Radiotap header (encabezado radiotap)
Metadatos que se agregan a las tramas capturadas, como la intensidad de señal, el canal y la tasa de datos.
Display filter (filtro de visualización)
Una regla en un analizador que muestra solo las tramas de una captura que coinciden con ella.
Capture location (ubicación de captura)
La posición física del analizador, que determina qué tramas puede oír.
Ejemplo real

Una laptop se desconecta del Wi-Fi cada pocos minutos. Con un adaptador en monitor mode en el canal del AP junto a la laptop, el ingeniero aplica el filtro de la MAC de la laptop y ve que el AP envía tramas de deauthentication con un reason code de inactividad, lo que lo lleva a un problema del driver de ahorro de energía en la laptop.

Consejo para el examen: Un radio, un canal. Para capturar el roaming entre canales necesitas varios adaptadores o capturas desde los APs, y para ver la experiencia de un cliente capturas cerca del cliente.

Comprueba lo que sabes

¿Por qué se necesita monitor mode para el análisis de protocolos Wi-Fi?

Sin él, el adaptador solo pasa su propio tráfico asociado convertido a Ethernet, no todas las tramas 802.11 de administración, control y datos del canal.

¿Dónde debes colocar el analizador para ver lo que vive un cliente con problemas?

Cerca del cliente, para que oiga aproximadamente lo mismo que el cliente, incluidas las tramas que el cliente podría perder.
