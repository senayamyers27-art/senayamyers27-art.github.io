CWNP Certified Wireless Network Administrator CWNA-109

Administración de energía: bit de power save, TIM, DTIM, U-APSD y Target Wake Time

Los dispositivos Wi-Fi con batería ahorran energía apagando sus radios entre transmisiones. El AP retiene, o almacena en búfer, el tráfico para los clientes dormidos y les avisa cuando tiene algo que entregar. 802.11 y la Wi-Fi Alliance definen varios métodos de administración de energía, y el examen espera que sepas cómo funcionan.

Un cliente anuncia que va a dormir activando el bit Power Management en el campo Frame Control de una trama que envía al AP, a menudo una null data frame. Entonces el AP almacena en búfer las tramas unicast para ese cliente. Un cliente en modo de ahorro de energía se despierta periódicamente para escuchar los beacons. La frecuencia con la que se despierta está relacionada con el listen interval que declaró en su association request.

Cada beacon contiene un elemento Traffic Indication Map (TIM). El TIM incluye un mapa de bits indexado por association identifier (AID). Si el bit del AID de un cliente está activado, el AP tiene tramas unicast en búfer para ese cliente. Entonces, un cliente con ahorro de energía heredado envía una trama de control PS-Poll, y el AP entrega una trama almacenada; el bit More Data de esa trama le indica al cliente si hay más esperando, y el cliente sigue sondeando hasta que no quede ninguna.

Las tramas broadcast y multicast necesitan otro enfoque porque se envían a todos. Algunos beacons son DTIM beacons, Delivery Traffic Indication Message. El DTIM period, configurado en el AP, fija cuántos beacons hay entre DTIMs; un DTIM period de 1 hace que cada beacon sea un DTIM beacon, mientras que 3 hace que lo sea uno de cada tres. El AP transmite el tráfico broadcast y multicast almacenado inmediatamente después de un DTIM beacon, y los clientes en ahorro de energía deben estar despiertos para recibirlo. Un DTIM period más largo ahorra batería, pero retrasa el multicast y el broadcast, lo que puede afectar aplicaciones como push-to-talk que dependen de multicast.

U-APSD, Unscheduled Automatic Power Save Delivery, forma parte de la certificación WMM Power Save y mejora a PS-Poll, especialmente para voz. En lugar de sondear una trama a la vez, el cliente envía una trigger frame, cualquier trama QoS data o QoS null en una access category con trigger habilitado. El AP responde entregando todas las tramas almacenadas para las categorías con entrega habilitada del cliente en un service period, que termina con el bit EOSP (end of service period). Un teléfono durante una llamada puede enviar su trama de voz y recibir las tramas de voz en espera en un solo periodo de actividad, y luego volver a dormir.

Target Wake Time (TWT), de 802.11ax, programa los momentos de activación mediante negociación. Un cliente y un AP acuerdan cuándo estará despierto el cliente, así que el cliente puede dormir durante muchos beacons, incluso por periodos largos. Broadcast TWT permite que un AP fije horarios para grupos de clientes. TWT es especialmente valioso para los sensores IoT que envían pequeñas cantidades de datos de vez en cuando.

Términos clave

Power Management bit (bit Power Management)
Un bit del campo Frame Control que el cliente activa para avisarle al AP que entra en modo de ahorro de energía.
TIM
Traffic Indication Map, un elemento del beacon con un mapa de bits por AID que muestra qué clientes dormidos tienen tráfico unicast en búfer.
DTIM
Delivery Traffic Indication Message, un TIM especial después del cual el AP envía las tramas broadcast y multicast almacenadas.
U-APSD
Unscheduled Automatic Power Save Delivery, el método de WMM Power Save en el que una trigger frame del cliente provoca la entrega de las tramas almacenadas.
PS-Poll
Una trama de control heredada que un cliente envía para obtener del AP una trama unicast almacenada.
Ejemplo real

Las credenciales de voz (voice badges) de un hospital agotan su batería al mediodía. El ingeniero descubre que el DTIM period está en 1 y U-APSD está deshabilitado. Habilitar WMM Power Save y ajustar el DTIM period, después de revisar la recomendación del fabricante de las credenciales, permite que duerman más tiempo sin dejar de recibir llamadas y el multicast de voceo.

Consejo para el examen: El TIM es para el tráfico unicast en búfer y aparece en todos los beacons; el DTIM rige el broadcast y multicast en búfer. Un DTIM period más largo ahorra batería, pero retrasa el multicast. U-APSD reemplaza el PS-Poll de una trama a la vez por un trigger y una ráfaga.

Comprueba lo que sabes

¿Cómo sabe un cliente que el AP tiene tramas unicast en búfer para él?

El bit que corresponde a su AID está activado en el elemento TIM de un beacon.

¿Cuándo envía un AP las tramas broadcast y multicast almacenadas?

Inmediatamente después de un DTIM beacon.

¿Qué envía un cliente U-APSD para iniciar la entrega de las tramas almacenadas?

Una trigger frame, es decir, una trama QoS data o QoS null en una access category con trigger habilitado.
