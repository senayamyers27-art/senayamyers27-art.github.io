CWNP Certified Wireless Network Administrator CWNA-109

Roles de 802.1X: supplicant, authenticator y authentication server (RADIUS)

IEEE 802.1X es un estándar de control de acceso a la red basado en puertos. Diseñado originalmente para los puertos de switches cableados, es la base de la seguridad Wi-Fi empresarial. La idea es sencilla: a un dispositivo no se le permite enviar tráfico normal a través de un puerto hasta que demuestre quién es. En Wi-Fi, el puerto es la conexión lógica entre un cliente y un AP después de la asociación.

Hay tres roles. El supplicant (solicitante) es el dispositivo cliente o, más precisamente, el software que en él solicita el acceso y proporciona credenciales como un nombre de usuario y contraseña o un certificado. El authenticator (autenticador) es el dispositivo que controla el puerto; en una WLAN es el AP en los diseños autónomos y en muchos distribuidos, o el WLAN controller en los diseños basados en controlador. El authentication server (servidor de autenticación) verifica las credenciales y toma la decisión de acceso; en la práctica, casi siempre es un servidor RADIUS (Remote Authentication Dial-In User Service), que a su vez puede consultar un directorio como LDAP o Active Directory.

El authenticator no verifica las credenciales por sí mismo. Retransmite los mensajes de autenticación entre el supplicant y el servidor. Entre el supplicant y el authenticator, el Extensible Authentication Protocol (EAP) se transporta directamente en tramas usando EAP over LAN (EAPOL). Entre el authenticator y el servidor RADIUS, los mensajes EAP se transportan dentro de paquetes RADIUS sobre UDP. El authenticator y el servidor RADIUS comparten un secreto que protege este intercambio, y cada AP o controlador debe estar configurado como RADIUS client en el servidor.

Hasta que la autenticación tiene éxito, el puerto está en estado no autorizado: el authenticator bloquea todo lo que viene del cliente excepto las tramas EAPOL. Cuando el servidor RADIUS devuelve Access-Accept, el puerto pasa a estar autorizado. El servidor también entrega material de claves (la master session key) al authenticator, del cual se deriva la PMK; el supplicant deriva por su cuenta la misma PMK. Luego, el 4-way handshake crea las claves de cifrado. Si el servidor devuelve Access-Reject, el cliente sigue bloqueado.

RADIUS puede devolver atributos adicionales con Access-Accept, como una asignación de VLAN o un nombre de rol, lo que permite que la WLAN aplique políticas por usuario. Los mensajes de RADIUS accounting también pueden registrar el inicio, el fin y el uso de la sesión.

Al diagnosticar problemas, piensa en términos de los tres roles. Un nombre de usuario incorrecto es un problema del supplicant o del directorio; un AP que no está registrado como RADIUS client, o un shared secret que no coincide, es un problema entre el authenticator y el servidor; un servidor inalcanzable o un certificado de servidor vencido afecta a todos. Los logs del servidor RADIUS suelen ser el lugar más rápido para encontrar el motivo de un rechazo.

Términos clave

Supplicant (solicitante)
El software cliente que solicita el acceso a la red y proporciona las credenciales en 802.1X.
Authenticator (autenticador)
El dispositivo que controla el puerto, como un AP o un WLAN controller, y que retransmite EAP entre el supplicant y el servidor.
Authentication server (servidor de autenticación)
El servidor, normalmente RADIUS, que valida las credenciales y devuelve aceptación o rechazo.
EAPOL
EAP over LAN, la encapsulación que se usa para transportar EAP entre el supplicant y el authenticator.
Ejemplo real

Después de agregar un nuevo controlador en una sucursal, ningún usuario puede iniciar sesión en el SSID corporativo, pero las mismas cuentas funcionan en la oficina central. El log de RADIUS muestra solicitudes desde una IP de cliente desconocida. El nuevo controlador nunca se agregó como RADIUS client con el shared secret; agregarlo resuelve el problema.

Consejo para el examen: El AP o el controlador es el authenticator, no el authentication server. Solo deja pasar EAP; el servidor RADIUS toma la decisión.

Comprueba lo que sabes

¿Qué protocolo transporta EAP entre el authenticator y el authentication server?

RADIUS, normalmente sobre UDP, protegido por un shared secret configurado en ambos dispositivos.

¿Qué tráfico se permite desde un cliente antes de que termine la autenticación 802.1X?

Solo las tramas EAPOL; todo el demás tráfico se bloquea en el puerto no autorizado.
