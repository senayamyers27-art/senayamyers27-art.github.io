Modelos de nube y responsabilidad compartida (IaaS, PaaS, SaaS)

La computación en la nube entrega recursos de cómputo bajo demanda a través de una red. La definición de NIST, muy utilizada, enumera cinco características esenciales: autoservicio bajo demanda, amplio acceso a la red, agrupación de recursos (multi-tenancy), elasticidad rápida y servicio medido (pagas por lo que usas). Entender los modelos de servicio y de despliegue es esencial, porque determinan quién es responsable de qué controles de seguridad.

Hay tres modelos de servicio principales. La infraestructura como servicio (IaaS) proporciona máquinas virtuales, almacenamiento y redes; el cliente administra el sistema operativo, el middleware, las aplicaciones y los datos, mientras que el proveedor administra el centro de datos físico, el hardware y la capa de virtualización. La plataforma como servicio (PaaS) proporciona una plataforma administrada, como un servicio de base de datos, un entorno de ejecución de aplicaciones o una plataforma de contenedores; el proveedor también administra el sistema operativo y el entorno de ejecución, y el cliente administra el código de la aplicación, la configuración y los datos. El software como servicio (SaaS) entrega aplicaciones completas, como el correo web o un CRM; el proveedor administra casi todo, y el cliente administra las cuentas de usuario, los permisos de acceso, los ajustes de configuración y los datos que introduce. Términos más recientes como la función como servicio (serverless) se ubican entre PaaS y SaaS.

El modelo de responsabilidad compartida describe cómo se reparten las tareas de seguridad. El proveedor es responsable de la seguridad de la nube: las instalaciones físicas, el hardware, la red global y la infraestructura de virtualización. El cliente es responsable de la seguridad en la nube: lo que construye y configura encima. A medida que pasas de IaaS a PaaS y a SaaS, el proveedor asume más, pero algunas tareas siempre siguen siendo del cliente. El cliente siempre es dueño de sus datos, de su clasificación y de quién puede acceder a ellos, de la gestión de identidades y accesos de sus usuarios, y de la configuración de los servicios que usa. La rendición de cuentas (accountability) por proteger los datos regulados no se puede tercerizar, aunque las tareas sí.

Una forma práctica de verlo: en IaaS, si el sistema operativo de una VM está sin parchear, es tu problema. En PaaS, el proveedor parchea el motor de base de datos, pero tú decides si está expuesto a internet y quién puede iniciar sesión. En SaaS, el proveedor asegura la aplicación, pero si tu administrador desactiva la MFA o comparte documentos públicamente, eso es responsabilidad tuya. La mayoría de las brechas en la nube provienen de configuraciones erróneas del lado del cliente y del compromiso de credenciales, no de fallas del proveedor.

Los modelos de despliegue describen quién usa la infraestructura. La nube pública es compartida por muchos clientes sobre la infraestructura del proveedor. La nube privada está dedicada a una sola organización, en sus instalaciones o alojada por un tercero. La nube comunitaria es compartida por organizaciones con requisitos comunes, como las agencias gubernamentales. La nube híbrida combina dos o más, a menudo sistemas locales con nube pública, conectados para que las cargas de trabajo y los datos puedan moverse entre ellos. Multi-cloud significa usar varios proveedores públicos.

Antes de adoptar un servicio, revisa el contrato y el acuerdo de nivel de servicio (SLA) del proveedor, los informes de auditoría independientes como SOC 2 o la certificación ISO 27001, la ubicación de los datos, los términos de notificación de brechas y las opciones de salida. La documentación del proveedor incluirá una matriz de responsabilidades; léela en lugar de suponer.

Términos clave

IaaS
Infrastructure as a service: el proveedor suministra cómputo, almacenamiento y redes virtualizados; el cliente administra el sistema operativo y lo que está encima.
PaaS
Platform as a service: el proveedor administra la infraestructura, el sistema operativo y el entorno de ejecución; el cliente administra las aplicaciones y los datos.
SaaS
Software as a service: el proveedor entrega una aplicación completa; el cliente administra los usuarios, la configuración y los datos.
Shared responsibility model (modelo de responsabilidad compartida)
La división de las tareas de seguridad entre el proveedor de nube (seguridad de la nube) y el cliente (seguridad en la nube).
Ejemplo real

Una startup ejecuta su sitio web en máquinas virtuales IaaS, su base de datos en un servicio de base de datos PaaS administrado y su correo en una suite SaaS. Parchea ella misma los sistemas operativos de las VM, confía en que el proveedor parchee el motor de base de datos, y configura la MFA y las restricciones para compartir en la consola de administración del SaaS, porque las tres cosas siguen siendo su responsabilidad.

Consejo para el examen: Los datos y la identidad siempre son responsabilidad del cliente en todos los modelos. El centro de datos físico siempre es del proveedor. Todo lo intermedio se desplaza hacia el proveedor a medida que pasas de IaaS a SaaS.

Comprueba lo que sabes

¿Quién parchea el sistema operativo invitado en IaaS?

El cliente.

En SaaS, menciona dos responsabilidades que siguen siendo del cliente.

Administrar las cuentas de usuario y el acceso, configurar los ajustes de seguridad como la MFA y el uso compartido, y proteger y clasificar sus datos.

¿Qué es una nube híbrida?

Una combinación de dos o más modelos de despliegue, como infraestructura privada local conectada a una nube pública.
