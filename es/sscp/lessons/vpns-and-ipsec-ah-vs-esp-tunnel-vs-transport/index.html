VPN e IPsec (AH vs ESP, modo túnel vs transporte)

Una red privada virtual (VPN) crea un túnel cifrado a través de una red no confiable, normalmente internet, para que el tráfico esté protegido como si viajara por un enlace privado. Las VPN de sitio a sitio conectan redes completas, como una sucursal con la sede central, usando puertas de enlace (gateways) en cada extremo; los usuarios no se dan cuenta de ellas. Las VPN de acceso remoto conectan los dispositivos de usuarios individuales a la red corporativa mediante software cliente. Las tecnologías comunes incluyen IPsec, las VPN basadas en TLS (a menudo llamadas VPN SSL, que pueden funcionar desde un navegador o un cliente) y protocolos más nuevos como WireGuard.

Una decisión de diseño clave para el acceso remoto es el túnel dividido (split tunneling). En un túnel completo (full tunnel), todo el tráfico del usuario pasa por la VPN, así que los controles de seguridad corporativos lo inspeccionan todo, a costa del ancho de banda. En un túnel dividido, solo el tráfico destinado a las redes corporativas pasa por la VPN y todo lo demás va directamente a internet, lo que es eficiente pero significa que el tráfico de internet elude los controles corporativos. La VPN siempre activa (always-on) se conecta automáticamente cada vez que el dispositivo tiene acceso a la red.

IPsec es un conjunto de protocolos en la capa de red. Usa Internet Key Exchange (IKE, ahora IKEv2) para autenticar a los pares, con claves precompartidas o certificados, y para negociar las asociaciones de seguridad (security associations, SA). Una SA es un acuerdo unidireccional sobre algoritmos y claves, así que una conexión bidireccional necesita un par. IKE funciona en UDP 500, y el paso a través de NAT (NAT traversal) encapsula el tráfico en UDP 4500.

IPsec tiene dos protocolos. Authentication Header (AH), protocolo IP 51, brinda integridad, autenticación del origen de los datos y protección contra la repetición, pero no cifrado. También protege partes del encabezado IP externo, lo que significa que se rompe cuando NAT cambia las direcciones. Encapsulating Security Payload (ESP), protocolo IP 50, brinda confidencialidad mediante cifrado, además de integridad, autenticación y protección contra la repetición. Como ESP hace todo lo que la mayoría de las organizaciones necesitan y funciona con NAT traversal, es por mucho el más usado; AH es raro en la práctica.

IPsec también tiene dos modos. El modo transporte (transport mode) protege solo la carga útil del paquete IP original y conserva el encabezado IP original, así que se usa para la protección de extremo a extremo entre dos hosts. El modo túnel (tunnel mode) cifra todo el paquete original, encabezado incluido, y lo envuelve en un nuevo encabezado IP con las direcciones de las puertas de enlace. Eso oculta las direcciones internas y se usa para las VPN de sitio a sitio entre puertas de enlace y para la mayor parte del acceso remoto. Combinando términos, una VPN de sitio a sitio típica es ESP en modo túnel.

En la operación, las puertas de enlace VPN son objetivos de alto valor expuestos a internet, así que necesitan parches oportunos, autenticación multifactor para los usuarios remotos, una configuración de cifrado robusta y registro de las conexiones. Muchas organizaciones están agregando acceso a la red zero trust junto a las VPN, o en su lugar, para limitar a qué puede llegar un usuario conectado.

Términos clave

AH
Authentication Header: protocolo de IPsec que brinda integridad, autenticación del origen y protección contra la repetición, sin cifrado.
ESP
Encapsulating Security Payload: protocolo de IPsec que brinda cifrado, además de integridad y autenticación.
Tunnel mode (modo túnel)
Modo de IPsec que encapsula y protege todo el paquete original dentro de un nuevo encabezado IP; se usa entre puertas de enlace.
Split tunneling (túnel dividido)
Enviar por la VPN solo el tráfico destinado a la red corporativa, mientras el resto del tráfico va directamente a internet.
Ejemplo real

Una empresa conecta sus tres sucursales con la sede central mediante VPN IPsec de sitio a sitio usando IKEv2 con certificados, ESP y modo túnel en cada firewall. El personal remoto usa una VPN cliente siempre activa con MFA y túnel completo, para que su navegación web siga pasando por la puerta de enlace web segura corporativa.

Consejo para el examen: AH autentica pero nunca cifra; ESP cifra. El modo transporte protege la carga útil entre hosts; el modo túnel protege todo el paquete entre puertas de enlace. Si una pregunta necesita confidencialidad, AH nunca es la respuesta.

Comprueba lo que sabes

¿Qué protocolo de IPsec brinda confidencialidad?

ESP; AH solo brinda integridad y autenticación.

¿Por qué se usa el modo túnel para las VPN de sitio a sitio?

Cifra todo el paquete original, incluidas las direcciones internas, y agrega un nuevo encabezado dirigido entre las puertas de enlace.

¿Cuál es la desventaja de seguridad del túnel dividido?

El tráfico con destino a internet elude los controles de seguridad corporativos, como el filtrado web y el monitoreo.
