ISC2 SSCP Oct 2025 outline

Gestión de claves: generación, distribución, almacenamiento, rotación, custodia y destrucción; HSM y TPM

Los algoritmos sólidos no valen nada si las claves son débiles, están expuestas o se pierden. La mayoría de las fallas criptográficas del mundo real son fallas de gestión de claves: claves codificadas en el código fuente, claves privadas copiadas en unidades compartidas, certificados que vencen sin que nadie lo note. La gestión de claves abarca todo el ciclo de vida de una clave, y el examen espera que conozcas cada etapa.

Generación. Las claves deben crearse con un generador de números aleatorios criptográficamente seguro y con una longitud adecuada para el algoritmo. La aleatoriedad predecible ha roto sistemas reales. Las claves deben generarse en un entorno seguro, idealmente dentro del hardware que las usará, para que la clave privada nunca salga de él.

Distribución. Las claves simétricas necesitan un canal seguro: entrega fuera de banda, envoltura de claves (key wrapping, cifrar una clave con otra clave) o un intercambio de claves asimétrico como Diffie-Hellman. Las claves públicas pueden distribuirse abiertamente, pero deben estar vinculadas a la identidad correcta, que es el trabajo de los certificados y la PKI.

Almacenamiento y uso. Las claves deben almacenarse cifradas y separadas de los datos que protegen, con un control de acceso estricto y registro. El conocimiento dividido (split knowledge) y el control dual reducen el riesgo interno: ninguna persona tiene sola una clave maestra completa, y las operaciones sensibles necesitan a dos personas autorizadas. Las claves también deben tener un único propósito; no reutilices una clave de cifrado para firmar.

Rotación y vencimiento. Cada clave tiene un criptoperíodo (cryptoperiod), el tiempo durante el cual está autorizada para usarse. Rotar las claves limita cuántos datos quedan expuestos si una se ve comprometida y cuánto texto cifrado puede reunir un atacante. Las claves también deben revocarse de inmediato si se sospecha un compromiso, y los certificados deben renovarse antes de su vencimiento.

Custodia y recuperación. La custodia de claves (key escrow) significa que un tercero de confianza o una función interna de recuperación guarda una copia de una clave para que los datos cifrados puedan recuperarse si el propietario se va o pierde la clave, o cuando la ley lo exige. Debe controlarse estrictamente porque es un objetivo concentrado. Los agentes de recuperación de claves (key recovery agents) de las herramientas de cifrado empresariales cumplen el mismo propósito. La destrucción cierra el ciclo de vida: las claves retiradas deben borrarse de forma segura de todo el almacenamiento, incluidos los respaldos, y el crypto-shredding (destruir la clave) puede hacer irrecuperables los datos cifrados al desecharlos.

Dos componentes de hardware aparecen a menudo. Un módulo de seguridad de hardware (hardware security module, HSM) es un dispositivo dedicado y resistente a manipulaciones, a menudo un equipo de red o un servicio en la nube, que genera, almacena y usa claves para muchas aplicaciones, como autoridades de certificación, sistemas de pago y bases de datos; las claves se usan dentro del HSM y están diseñadas para no salir de él en texto plano. Un módulo de plataforma confiable (trusted platform module, TPM) es un chip integrado en la placa base de una sola computadora que almacena claves para ese dispositivo, admite el arranque medido o seguro (measured o secure boot) registrando mediciones de los componentes de arranque, y protege las claves de cifrado de disco, por ejemplo para BitLocker. Los proveedores de nube también ofrecen servicios de gestión de claves (KMS) respaldados por HSM.

Términos clave

Cryptoperiod (criptoperíodo)
El lapso autorizado durante el cual una clave específica puede usarse antes de tener que rotarse o retirarse.
Key escrow (custodia de claves)
Guardar una copia de una clave con una parte de confianza para poder recuperar los datos si se pierde la clave original o si la ley exige el acceso.
HSM
Hardware security module (módulo de seguridad de hardware): un dispositivo resistente a manipulaciones que genera, almacena y usa claves de forma segura para muchos sistemas.
TPM
Trusted platform module (módulo de plataforma confiable): un chip en un solo dispositivo que protege sus claves y admite el arranque seguro o medido y el cifrado de disco.
Ejemplo real

Una empresa almacena la clave de firma de su autoridad de certificación en un HSM que requiere que dos administradores con tarjetas inteligentes separadas lo activen (control dual). Las laptops de los empleados usan BitLocker con claves selladas en el TPM de cada una, y las claves de recuperación están en custodia en el directorio para que la mesa de ayuda pueda desbloquear un disco si cambia el hardware de una laptop.

Consejo para el examen: HSM frente a TPM: un HSM sirve a muchos sistemas y aplicaciones y a menudo es un equipo separado; un TPM está integrado en un solo dispositivo (como chip o firmware) y protege ese dispositivo. El control dual y el conocimiento dividido son las respuestas para evitar que una sola persona haga mal uso de una clave maestra.

Comprueba lo que sabes

¿Por qué rotar las claves aunque no se sospeche ningún compromiso?

Limita la cantidad de datos expuestos si una clave se compromete más adelante y reduce el texto cifrado disponible para un ataque.

¿Qué es el crypto-shredding?

Destruir de forma segura la clave de cifrado para que los datos cifrados con ella se vuelvan irrecuperables.

¿Qué componente de hardware admite el arranque medido en una laptop?

El TPM, que registra las mediciones de los componentes de arranque y puede sellar claves a un estado conocido y confiable.
