ISC2 SSCP Oct 2025 outline

Documentar y verificar controles de seguridad funcionales; líneas base

Poner un control en marcha es solo la mitad del trabajo. Un SSCP también debe documentar lo que se supone que hace el control y verificar que realmente lo haga. Los controles se desvían con el tiempo: alguien agrega una excepción al firewall, un servicio se reinstala con la configuración predeterminada, un agente de registros deja de enviar datos. La documentación y la verificación detectan esa desviación antes de que lo haga un atacante.

La documentación comienza con el propósito del control y el requisito que cumple, a menudo vinculado a una política, un estándar o una regulación. Para cada control registras su responsable, su alcance, cómo está configurado, cómo se opera y qué evidencia demuestra que funciona. Este registro permite que auditores, nuevos integrantes del equipo y quienes responden a incidentes entiendan el entorno sin adivinar. Una buena documentación también registra las excepciones conocidas, con una aprobación y una fecha de vencimiento, para que las desviaciones sean deliberadas y no accidentales.

Una línea base de seguridad (security baseline) es un conjunto mínimo documentado de configuraciones de seguridad que todo sistema de un tipo determinado debe cumplir. Una línea base para servidores Windows podría especificar la política de contraseñas, la política de auditoría, los servicios deshabilitados, los parches requeridos y las reglas del firewall del host. Una línea base para Linux podría exigir que el inicio de sesión de root por SSH esté deshabilitado y ciertos permisos de archivos específicos. Las organizaciones a menudo parten de guías de endurecimiento (hardening) ampliamente usadas, como los CIS Benchmarks del Center for Internet Security o las guías de seguridad de los fabricantes, y las adaptan. La línea base se convierte en la vara de medición: cualquier sistema puede compararse con ella, y los sistemas nuevos se construyen a partir de ella, a menudo usando imágenes doradas (golden images) o herramientas de gestión de configuración para que cada instalación comience en cumplimiento.

Verificar significa probar que el control funciona como se pretende. Los métodos incluyen escaneos automatizados de configuración que comparan los sistemas con la línea base, escaneos de vulnerabilidades, revisar los registros para confirmar que se capturan los eventos, la inspección manual y pruebas funcionales, como intentar una conexión bloqueada para confirmar que el firewall la rechaza. La idea clave es probar la función, no solo la existencia: un firewall instalado que permite todo el tráfico, o un agente antivirus que no se ha actualizado en meses, da una falsa sensación de seguridad.

La verificación debe hacerse en momentos definidos: cuando un control se despliega por primera vez, después de cambios significativos y según un calendario regular. Los resultados retroalimentan la documentación y la gestión de cambios. Cuando se encuentra una desviación, se corrige para que coincida con la línea base o se acepta formalmente como excepción con la aprobación del responsable del riesgo.

En un laboratorio podrías ejecutar una herramienta de escaneo de benchmarks contra una máquina virtual, leer el informe de configuraciones aprobadas y fallidas, corregir algunas fallas y luego volver a escanear para demostrar que el cambio funcionó. Ese ciclo de documentar, medir, corregir y volver a medir es exactamente lo que el examen quiere decir con verificar controles.

Términos clave

Security baseline (línea base de seguridad)
Un conjunto mínimo documentado de configuraciones de seguridad que todos los sistemas de un tipo determinado deben cumplir.
Configuration drift (desviación de configuración)
La divergencia gradual, con el tiempo, entre la configuración real de un sistema y su línea base aprobada.
Golden image (imagen dorada)
Una imagen de sistema preconfigurada y endurecida que se usa para construir sistemas nuevos de forma consistente con la línea base.
Exception (excepción)
Una desviación documentada, aprobada y normalmente con límite de tiempo respecto de una línea base o política.
Ejemplo real

Un escaneo trimestral de configuración muestra que tres servidores web ahora permiten inicios de sesión SSH con contraseña, aunque la línea base de Linux exige solo autenticación basada en claves. El equipo rastrea el cambio hasta una sesión de soporte de un proveedor, revierte la configuración mediante la gestión de cambios y agrega una comprobación al escaneo mensual para detectar la desviación antes.

Consejo para el examen: Verificar significa demostrar que un control funciona, no solo que existe. Si una opción de respuesta realmente prueba la función (por ejemplo, intentar una conexión que debería ser rechazada o revisar si llegan los registros), suele ganarle a una que solo confirma la instalación.

Comprueba lo que sabes

¿Para qué se usa una línea base de seguridad?

Como la configuración mínima aprobada para una clase de sistemas, que se usa tanto para construir sistemas como para medirlos y detectar desviaciones.

¿Cuándo deben verificarse los controles?

Cuando se despliegan por primera vez, después de cambios significativos y de forma periódica según un calendario establecido.

¿Qué debe pasar cuando se encuentra que un sistema se desvía de la línea base?

Corregirlo para que vuelva a la línea base o documentar una excepción aprobada con un responsable del riesgo e, idealmente, una fecha de vencimiento.
