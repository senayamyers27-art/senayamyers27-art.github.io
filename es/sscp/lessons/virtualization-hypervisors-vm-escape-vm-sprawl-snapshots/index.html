ISC2 SSCP Oct 2025 outline

Virtualización: hipervisores, VM escape, VM sprawl y snapshots

La virtualización permite que una máquina física ejecute muchas máquinas virtuales (VM) aisladas, cada una con su propio sistema operativo. Es la base de los centros de datos y de la computación en la nube, mejora el aprovechamiento del hardware y hace que los sistemas sean fáciles de copiar y restaurar. También introduce nuevos riesgos, porque ahora muchas cargas de trabajo comparten un host y una capa de administración.

El hipervisor, o monitor de máquinas virtuales, es el software que crea y ejecuta las VM y les asigna CPU, memoria, almacenamiento y red. Un hipervisor Type 1 (bare-metal) se ejecuta directamente sobre el hardware sin un sistema operativo de propósito general debajo; algunos ejemplos son VMware ESXi, Microsoft Hyper-V y las plataformas basadas en KVM. Tiene una superficie de ataque más pequeña y mejor rendimiento, y se usa en centros de datos y nubes. Un hipervisor Type 2 (alojado) se ejecuta como una aplicación sobre un sistema operativo normal, como VirtualBox o VMware Workstation, y es común en computadoras de escritorio y laboratorios. Su seguridad también depende del sistema operativo anfitrión. Los contenedores son una tecnología relacionada pero distinta: comparten el kernel del host y aíslan procesos en lugar de virtualizar hardware, así que son más livianos pero ofrecen un aislamiento más débil que las VM.

El VM escape es un ataque en el que el código que se ejecuta dentro de una VM invitada rompe su aislamiento para interactuar con el hipervisor o con otras VM del mismo host. Es raro pero grave, porque comprometer el hipervisor compromete todas las VM que aloja. Las defensas incluyen mantener parcheados los hipervisores y las herramientas de las VM, minimizar funciones como las carpetas compartidas, el portapapeles compartido y los dispositivos virtuales innecesarios, separar las cargas de trabajo de distinta sensibilidad en distintos hosts o clústeres, y proteger de cerca la interfaz de administración. La consola de administración del hipervisor, como vCenter, es en sí misma un objetivo principal; debe estar en una red de administración aislada, con MFA y cuentas de administrador restringidas.

El VM sprawl (proliferación de VM) ocurre cuando las VM se crean con tanta facilidad que la organización les pierde el rastro. Las VM olvidadas no se parchean, no se monitorean ni se respaldan, pueden ejecutar software desactualizado con credenciales antiguas, y consumen recursos y licencias. Los controles incluyen un proceso formal de aprovisionamiento vinculado a la gestión de cambios, etiquetar cada VM con un responsable y un propósito, inventario y descubrimiento automatizados, revisiones periódicas y retiro de las VM que no se usan, y fechas de vencimiento para los sistemas de prueba.

Los snapshots capturan el estado de una VM, su disco y opcionalmente su memoria, en un momento dado, para que puedas revertirla rápidamente tras una actualización fallida o una infección de malware. Son útiles antes de parchear o probar. Pero los snapshots no son respaldos: normalmente residen en el mismo almacenamiento que la VM y dependen del disco original, así que una falla o un borrado del almacenamiento puede hacer que se pierdan ambos. Los snapshots de larga duración también degradan el rendimiento y consumen espacio. Desde el punto de vista de la seguridad, los snapshots pueden contener datos sensibles de la memoria, incluidas claves y contraseñas, por lo que su acceso debe controlarse, y revertir una VM puede reintroducir vulnerabilidades antiguas o deshacer parches de seguridad, así que siempre vuelve a parchear después de revertir.

Otras preocupaciones de la virtualización incluyen el tráfico entre VM que nunca pasa por la red física (así que el monitoreo de red tradicional no puede verlo sin controles en el switch virtual), el agotamiento de recursos por parte de una VM que afecta a las demás, y proteger las imágenes y plantillas de VM para que los sistemas nuevos arranquen ya endurecidos.

Términos clave

Type 1 hypervisor (hipervisor tipo 1)
Un hipervisor bare-metal que se ejecuta directamente sobre el hardware, usado en centros de datos por su rendimiento y seguridad.
Type 2 hypervisor (hipervisor tipo 2)
Un hipervisor alojado que se ejecuta como una aplicación sobre un sistema operativo convencional.
VM escape (escape de VM)
Un ataque en el que el código de una VM invitada rompe el aislamiento para llegar al hipervisor o a otras VM.
VM sprawl (proliferación de VM)
El crecimiento descontrolado de VM que ya no se rastrean, parchean ni administran.
Ejemplo real

Una auditoría de un clúster de virtualización encuentra 40 VM sin etiqueta de responsable, incluido un antiguo servidor web de prueba que todavía ejecuta un framework sin parchear con la contraseña de administrador predeterminada. El equipo introduce etiquetas obligatorias de responsable y vencimiento, retira las VM abandonadas y traslada la interfaz de administración de vCenter a una red de administración aislada con MFA.

Consejo para el examen: El VM escape amenaza al hipervisor y a todas las VM alojadas en el mismo host; las principales defensas son el parcheo y el aislamiento de las cargas de trabajo sensibles. Los snapshots sirven para revertir rápidamente, no como estrategia de respaldo.

Comprueba lo que sabes

¿Por qué un hipervisor Type 1 se considera en general más seguro que uno Type 2?

Se ejecuta directamente sobre el hardware con una superficie de ataque más pequeña, sin depender de un sistema operativo anfitrión de propósito general.

¿Qué riesgos crea el VM sprawl?

Las VM olvidadas quedan sin parchear, sin monitorear y sin respaldar, lo que crea sistemas vulnerables y no administrados, y desperdicio de recursos.

¿Qué problema de seguridad puede causar revertir una VM a un snapshot antiguo?

Puede eliminar parches y restaurar vulnerabilidades o configuraciones antiguas, así que la VM debe volver a parchearse.
