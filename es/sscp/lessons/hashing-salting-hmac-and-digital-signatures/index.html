Hash, salting, HMAC y firmas digitales

Una función hash criptográfica toma una entrada de cualquier tamaño y produce una salida de tamaño fijo llamada resumen (digest) o hash. Es unidireccional: no es factible recuperar la entrada a partir del resumen. Es determinista: la misma entrada siempre produce el mismo resumen. Y un cambio mínimo en la entrada produce una salida completamente distinta, lo que hace que los hashes sean ideales para detectar cambios. Un buen hash también debe ser resistente a colisiones, es decir, debe ser inviable encontrar dos entradas distintas con el mismo resumen. La familia SHA-2 (como SHA-256 y SHA-512) y SHA-3 son las opciones actuales. MD5 y SHA-1 tienen ataques de colisión prácticos y no deben usarse con fines de seguridad, aunque todavía se ven usados para sumas de verificación (checksums) sin fines de seguridad.

El hash no es cifrado. No hay clave ni forma de descifrar. Su función es la integridad: publicas o almacenas el hash, y cualquiera puede volver a calcularlo después para confirmar que los datos no cambiaron. Las descargas de software, las imágenes forenses y las herramientas de monitoreo de integridad de archivos dependen de esto.

El almacenamiento de contraseñas es un caso especial. Los sistemas nunca deben almacenar contraseñas en texto plano ni con cifrado reversible; almacenan un hash. Pero los hashes simples son vulnerables: las contraseñas idénticas producen hashes idénticos, y los atacantes usan tablas precalculadas (rainbow tables) o adivinación rápida. Una sal (salt) es un valor aleatorio único generado para cada contraseña y combinado con ella antes de aplicar el hash, que luego se almacena junto al hash. Las sales hacen que cada hash sea único y vencen a las tablas precalculadas. Una buena práctica también usa funciones de hash de contraseñas o de estiramiento de claves (key stretching) deliberadamente lentas y diseñadas para ese fin, como bcrypt, scrypt, Argon2 o PBKDF2, que hacen costoso cada intento. Una pimienta (pepper) es un valor secreto adicional que se guarda por separado de la base de datos.

Un hash por sí solo demuestra la integridad solo si el propio hash está protegido; un atacante que cambia un mensaje puede simplemente volver a calcular el hash. Un código de autenticación de mensajes basado en hash (HMAC) resuelve esto mezclando una clave secreta compartida en el cálculo del hash. Solo alguien con la clave puede producir un HMAC válido, así que brinda tanto integridad como autenticación del origen del mensaje. Sin embargo, como la clave es compartida, el HMAC no brinda no repudio. Los HMAC se usan en protocolos como TLS e IPsec y para firmar solicitudes a API.

Una firma digital brinda integridad, autenticación y no repudio. El remitente calcula el hash del mensaje y luego firma ese hash con su clave privada. El destinatario usa la clave pública del remitente para verificar la firma y la compara con su propio hash del mensaje recibido. Si coinciden, el mensaje no fue alterado y lo firmó quien tiene la clave privada. Los certificados de una autoridad de confianza vinculan la clave pública con una identidad. Ten en cuenta que una firma no brinda confidencialidad; si se necesita secreto, el mensaje también debe cifrarse.

Términos clave

Salt (sal)
Un valor aleatorio único que se agrega a cada contraseña antes de aplicar el hash para que las contraseñas idénticas produzcan hashes distintos y las rainbow tables fallen.
HMAC
Un hash calculado con una clave secreta compartida, que brinda integridad y autenticación del origen, pero no no repudio.
Collision (colisión)
Dos entradas distintas que producen el mismo resumen hash; un buen hash hace inviable encontrar colisiones.
Digital signature (firma digital)
Un hash de un mensaje firmado con la clave privada del remitente, que brinda integridad, autenticación y no repudio.
Ejemplo real

Un fabricante de software publica un instalador con un hash SHA-256 y firma el archivo con su clave privada de firma de código. Tu sistema operativo verifica la firma con la clave pública del fabricante que está en su certificado, lo que confirma tanto que el archivo no cambió como que realmente provino de ese fabricante.

Consejo para el examen: Relaciona la herramienta con el objetivo: hash para la integridad; HMAC para integridad más autenticación con una clave compartida; firma digital para integridad, autenticación y no repudio. El salting defiende contra las rainbow tables, no contra una contraseña débil.

Comprueba lo que sabes

¿Qué clave usa un remitente para crear una firma digital y cuál usa el destinatario para verificarla?

El remitente firma con su clave privada; el destinatario verifica con la clave pública del remitente.

¿Qué ataque vence el salting?

Las búsquedas de hashes precalculados, como las rainbow tables, porque cada hash de contraseña se vuelve único.

¿Por qué el HMAC no brinda no repudio?

Ambas partes comparten la clave secreta, así que cualquiera de ellas pudo haber generado el HMAC.
