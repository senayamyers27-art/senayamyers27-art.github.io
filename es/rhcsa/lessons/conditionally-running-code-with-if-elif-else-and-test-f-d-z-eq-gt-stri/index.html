Red Hat Certified System Administrator EX200 (RHEL 10)

Ejecutar código de forma condicional con if, elif, else y test / [ ] (-f, -d, -z, -eq, -gt, comparaciones de cadenas)

Los scripts se vuelven útiles cuando toman decisiones: crear un directorio solo si falta, negarse a ejecutarse sin un argumento, avisar cuando un disco está casi lleno. Bash toma decisiones con if, que ejecuta un comando y se ramifica según su código de salida: cero significa verdadero (éxito) y cualquier otro valor significa falso.

El comando que más se usa en un if es test, normalmente escrito en su forma de corchetes [ ... ]. El [ es en sí un comando cuyo último argumento debe ser ], por eso los espacios son obligatorios: [ -f file ] funciona, mientras que [-f file] es un error. Bash también ofrece [[ ... ]], una forma interna más tolerante, pero [ ] simple es portable y es lo que usa la mayoría del material de examen.

#!/bin/bash
if [ -d /backup ]; then
    echo "/backup exists"
elif [ -f /backup ]; then
    echo "/backup is a file, not a directory"
else
    mkdir -p /backup
fi

Las pruebas de archivos revisan el sistema de archivos. -e es verdadero si la ruta existe, -f si es un archivo regular, -d si es un directorio, -r, -w y -x si puedes leerlo, escribirlo o ejecutarlo, y -s si el archivo existe y no está vacío. Las pruebas de cadenas comparan texto: -z "$var" es verdadero si la cadena está vacía, -n "$var" si no lo está, = prueba la igualdad y != la desigualdad. Pon siempre las variables entre comillas dentro de [ ]; una variable vacía sin comillas desaparece y deja a la prueba sin un operando.

Los números usan operadores distintos porque < y > son redirecciones para el shell. Usa -eq (igual), -ne (distinto), -lt (menor que), -le, -gt (mayor que) y -ge. Así, [ "$count" -gt 10 ] compara numéricamente, mientras que [ "$a" = "$b" ] compara cadenas. Confundirlos es un error clásico: [ 10 = 10.0 ] es falso como cadenas, y -eq con valores no numéricos da el error 'integer expression expected'. ! niega una prueba: [ ! -d /data ].

La estructura siempre es if condition; then ... fi, con ramas opcionales elif condition; then y un else final. Cada if debe terminar con fi. Puedes combinar pruebas con && y || entre corchetes separados: if [ -f "$1" ] && [ -r "$1" ]; then. Cualquier comando puede ser la condición, no solo test: if grep -q '^harry:' /etc/passwd; then se ramifica según si grep encontró una coincidencia, y -q lo mantiene en silencio.

Indenta el cuerpo de cada rama de forma consistente. Al shell no le importa, pero leerás y depurarás el script más rápido bajo la presión de tiempo del examen.

Términos clave

test / [ ]
Comando que evalúa una condición y devuelve el código de salida 0 (verdadero) o 1 (falso); los espacios alrededor de los corchetes son obligatorios.
-f / -d / -e
Pruebas de archivo regular, de directorio o de cualquier ruta existente.
-z / -n
Prueban si una cadena está vacía o no.
-eq / -gt / -lt
Operadores de comparación numérica: igual, mayor que, menor que (también -ne, -ge, -le).
elif
Condición adicional que solo se revisa si el if o elif anterior fue falso.
Ejemplo real

Un script debe imprimir 'large' si el archivo que recibe como argumento ocupa más de 1024 bytes. Obtienes el tamaño con size=$(stat -c %s "$1") y pruebas if [ "$size" -gt 1024 ]; then echo large; else echo small; fi, comprobando primero [ -f "$1" ] para que un archivo inexistente dé un mensaje claro.

Consejo para el examen: Usa -eq/-gt/-lt para números y = / != para cadenas, deja espacios dentro de los corchetes y pon entre comillas todas las variables de una prueba.

Comprueba lo que sabes

¿Por qué falla ["$a" = "b"]?

Debe haber espacios después de [ y antes de ], porque [ es un comando y ] su último argumento.

¿Qué prueba es verdadera si una variable está vacía?

[ -z "$var" ].

¿Cómo pruebas si el número de $n es mayor que 5?

[ "$n" -gt 5 ]; > se trataría como una redirección.
