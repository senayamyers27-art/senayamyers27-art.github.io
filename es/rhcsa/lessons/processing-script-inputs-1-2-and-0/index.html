Procesar las entradas de un script: $1, $2, $#, $@ y $0

Los scripts son mucho más útiles cuando aceptan entradas en la línea de comandos, como hacen los comandos normales. Cuando ejecutas ./adduser.sh harry 2001, las palabras después del nombre del script son sus argumentos, también llamados parámetros posicionales, y Bash los pone a disposición mediante variables especiales. Las tareas del examen suelen especificar exactamente cómo debe responder un script a sus argumentos, incluido qué hacer cuando faltan.

$1 es el primer argumento, $2 el segundo, y así sucesivamente; a partir del décimo necesitas llaves, ${10}. $0 contiene el nombre con el que se ejecutó el script, incluida cualquier ruta que hayas escrito, así que es ideal para los mensajes de uso. $# es el número de argumentos, lo que te permite comprobar que el usuario proporcionó lo que el script necesita.

$@ se expande a todos los argumentos. Escrito entre comillas dobles, "$@", se expande a cada argumento como una palabra separada, conservando los argumentos que contienen espacios, lo que lo convierte en la opción correcta para bucles y para pasar los argumentos a otro comando. $* también significa todos los argumentos, pero "$*" los une en una sola palabra separada por espacios; es útil principalmente para imprimirlos juntos.

#!/bin/bash
# mkusers.sh - crear cada usuario nombrado en la línea de comandos
if [ $# -eq 0 ]; then
    echo "Usage: $0 user [user...]" >&2
    exit 1
fi
echo "Creating $# user(s)"
for u in "$@"; do
    useradd "$u" && echo "created $u"
done

Pon siempre entre comillas los parámetros posicionales cuando los uses: "$1" en lugar de $1. Si un argumento está vacío o contiene espacios, una referencia sin comillas se divide o desaparece, lo que puede hacer que las pruebas fallen con errores confusos o que se pasen nombres equivocados a los comandos. Comprobar $# al inicio del script e imprimir una línea de uso en stderr con un código de salida distinto de cero es el patrón defensivo estándar.

shift descarta $1 y mueve todos los demás argumentos una posición hacia abajo, así que $2 se convierte en $1 y $# disminuye en uno. Es útil para tratar un primer argumento especial y luego tratar el resto como una lista, o para procesar los argumentos uno a uno en un bucle while [ $# -gt 0 ]. También puedes dar valores predeterminados: ${1:-/tmp} usa el primer argumento si se proporciona y /tmp en caso contrario.

Prueba tu script con cero, uno y varios argumentos, incluido uno que contenga un espacio, antes de dar por terminada una tarea del examen. bash -x ./script a 'b c' muestra exactamente cómo se expandió cada parámetro.

Términos clave

Positional parameters (parámetros posicionales)
Los argumentos pasados a un script, disponibles como $1, $2, etc.
$0
El nombre del script tal como se invocó.
$#
El número de argumentos pasados al script.
"$@"
Todos los argumentos como palabras separadas y correctamente entrecomilladas; la forma correcta para bucles y para pasar los argumentos a otro comando.
shift
Descarta $1 y renumera hacia abajo los argumentos restantes.
Ejemplo real

Una tarea quiere /usr/local/bin/greet, que imprima 'Hello NAME' con su primer argumento, o que imprima 'Usage: greet name' y salga con 1 si no se da ninguno. Pruebas [ $# -lt 1 ] para la rama de uso, luego usas echo "Hello $1", y lo pruebas sin argumento y con 'Ada Lovelace' entre comillas.

Consejo para el examen: Usa "$@" (con comillas) para recorrer o pasar todos los argumentos; $@ o $* sin comillas dividen los argumentos que contienen espacios.

Comprueba lo que sabes

Si un script se ejecuta como ./s.sh a b c, ¿cuánto valen $# y $2?

$# es 3 y $2 es b.

¿Qué contiene $0?

El nombre (y la ruta, tal como se escribió) usado para ejecutar el script.

¿Por qué se prefiere "$@" a $* en un bucle for?

"$@" mantiene cada argumento como una sola palabra aunque contenga espacios; $* los divide o los une.
