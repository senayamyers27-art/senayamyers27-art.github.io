Red Hat Certified System Administrator EX200 (RHEL 10)

Comprobar direcciones, rutas y resolución de nombres: ip addr, ip route, ping, getent hosts

Cuando la red falla, prueba capa por capa: ¿tiene la interfaz la dirección correcta?, ¿sabe el sistema a dónde enviar el tráfico?, ¿puede llegar al siguiente salto y al destino?, ¿puede resolver nombres? Un puñado de comandos responde cada pregunta, y son los mismos que usas para verificar tu propio trabajo en el examen.

ip addr (abreviado ip a) lista las interfaces y sus direcciones. Busca state UP, la línea inet con la dirección IPv4 y el prefijo, y las líneas inet6 para IPv6. ip link muestra solo el estado del enlace y las direcciones MAC (media access control). Que falte una dirección normalmente significa que el perfil de conexión no está activo o está mal configurado.

ip route (abreviado ip r) muestra la tabla de enrutamiento. La línea default via es la puerta de enlace predeterminada, usada para todo lo que no esté en una red local. Las redes conectadas directamente aparecen como rutas proto kernel. ip -6 route muestra las rutas IPv6, e ip route get 8.8.8.8 muestra qué ruta e interfaz usaría un destino concreto.

ip -br addr                # breve: una línea por interfaz
ip route
# default via 192.168.10.1 dev enp1s0 proto static metric 100
ping -c 3 192.168.10.1     # ¿se alcanza la puerta de enlace?
ping -c 3 server2          # nombre + alcance
getent hosts server2       # solo resolución
ss -tlnp                   # puertos TCP en escucha

ping envía peticiones de eco ICMP (Internet Control Message Protocol). Usa siempre -c para fijar una cantidad, o se ejecutará hasta que presiones Ctrl+C. Haz ping primero a la puerta de enlace, luego a una dirección remota y luego a un nombre. Si la dirección funciona pero el nombre no, el problema es la resolución, no la conectividad. Ten en cuenta que algunos hosts y firewalls descartan ICMP, así que un ping fallido es una pista, no una prueba.

getent hosts name resuelve un nombre exactamente como lo hacen las aplicaciones, siguiendo /etc/nsswitch.conf: primero /etc/hosts y luego DNS. Herramientas como dig y host (del paquete bind-utils) consultan directamente a los servidores DNS y se saltan /etc/hosts, lo que es útil para probar el propio DNS pero puede confundirte sobre lo que ven las aplicaciones.

Por último, ss -tulpn lista los sockets TCP y UDP en escucha con el proceso dueño, lo que te dice si un servicio está escuchando realmente antes de culpar al firewall.

Términos clave

ip addr
Muestra las interfaces de red con su estado y sus direcciones IPv4 e IPv6.
Default gateway (puerta de enlace predeterminada)
El router que recibe el tráfico destinado a redes que no están conectadas directamente; aparece como default via en ip route.
getent hosts
Resuelve un nombre usando el orden configurado del sistema (nsswitch), incluidos /etc/hosts y DNS.
ICMP
Internet Control Message Protocol, usado por ping para las peticiones y respuestas de eco.
Ejemplo real

Un servidor no puede instalar paquetes desde el host del repositorio. ip addr muestra la dirección correcta, el ping a la puerta de enlace funciona y el ping a la IP del repositorio funciona, pero getent hosts con su nombre no devuelve nada. El problema es la resolución de nombres, así que corriges ipv4.dns en la conexión en lugar de tocar las rutas.

Consejo para el examen: getent hosts muestra lo que resolverán las aplicaciones; dig y host se saltan /etc/hosts. Elige la herramienta que corresponde a la pregunta que te haces.

Comprueba lo que sabes

¿Qué línea de la salida de ip route muestra la puerta de enlace predeterminada?

La línea que empieza con default via, seguida de la dirección de la puerta de enlace y la interfaz.

El ping a una dirección IP funciona pero el ping a su nombre falla. ¿Dónde está el problema?

En la resolución de nombres: /etc/hosts, la configuración del servidor DNS o el propio servidor DNS.

¿Por qué dig puede dar una respuesta distinta a getent hosts?

dig consulta directamente el DNS e ignora /etc/hosts y el orden de nsswitch, mientras que getent usa el mismo camino de búsqueda que las aplicaciones.
