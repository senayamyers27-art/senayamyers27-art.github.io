Red Hat Certified System Administrator EX200 (RHEL 10)

Diagnosticar y corregir problemas de permisos de archivos (ls -l, namei -l, chmod, chown)

Cuando un usuario recibe Permission denied, la causa es casi siempre una de unas pocas cosas: el propietario o el grupo equivocados, faltan bits de permiso en el archivo o falta permiso en algún directorio a lo largo de la ruta. SELinux y las ACL (listas de control de acceso) también pueden bloquear el acceso, pero empieza por los permisos estándar, porque se revisan primero y son el problema más común en el examen.

Todo archivo tiene un propietario, un grupo y tres conjuntos de bits: user (propietario), group y other. ls -l los muestra, y ls -ld dir muestra el propio directorio en lugar de su contenido. Linux revisa solo un conjunto: si eres el propietario, se aplican los bits del propietario; si no, y estás en el grupo, se aplican los bits del grupo; si no, se aplican los bits de other. Eso significa que un propietario con menos derechos que other sigue limitado por los bits del propietario.

Los bits significan cosas distintas en los directorios. r te permite listar los nombres, w te permite crear, borrar y renombrar entradas (junto con x) y x te permite entrar en el directorio y llegar a cualquier cosa que contenga. Para abrir /srv/app/conf/app.ini, necesitas x en cada directorio de la ruta más r en el archivo. namei -l muestra el propietario y el modo de cada componente, lo que hace fácil detectar una x que falta.

namei -l /srv/app/conf/app.ini
# f: /srv/app/conf/app.ini
# dr-xr-xr-x root root   /
# drwxr-xr-x root root   srv
# drwx------ root root   app      <- los otros no pueden atravesarlo
# drwxr-xr-x app  app    conf
# -rw-r----- app  app    app.ini

Corrige con el cambio más pequeño que cumpla el requisito. chown user:group file cambia el propietario y el grupo, chgrp cambia solo el grupo y -R actúa recursivamente. chmod acepta modos simbólicos como g+rw u o-rwx y modos numéricos como 750 (r=4, w=2, x=1 por conjunto). Una X mayúscula en chmod -R g+rX añade ejecución solo a los directorios y a los archivos que ya la tienen, lo que es ideal para abrir un árbol sin volver ejecutables todos los archivos.

Prueba como el usuario afectado, no como root, porque root se salta las comprobaciones normales de permisos: su - alice -c 'cat /srv/app/conf/app.ini' o sudo -u alice cat .... Si los permisos parecen correctos y el acceso sigue fallando, busca ACL con getfacl (un + después del modo en ls -l indica que hay una) y denegaciones de SELinux en el log de auditoría. Evita el arreglo rápido chmod 777; oculta el problema real y abre el archivo a todos los usuarios.

Términos clave

namei -l
Lista cada componente de una ruta con su propietario, grupo y modo; se usa para encontrar dónde falla el recorrido.
Execute bit on a directory (bit de ejecución en un directorio)
Permiso para entrar en un directorio y acceder a sus entradas, necesario en cada directorio de una ruta.
chmod
Cambia los bits de permiso usando modos simbólicos (u+x, g-w) o numéricos (755).
chown
Cambia el propietario, y opcionalmente el grupo, de archivos con la forma user:group.
Ejemplo real

Los miembros del grupo devs no pueden leer /opt/project/notes.txt aunque el archivo es -rw-rw---- root:devs. namei -l muestra que /opt/project es drwx------, así que el grupo no puede atravesarlo. Ejecutas chgrp devs /opt/project y chmod 750 /opt/project, y ahora su - dev1 -c 'cat /opt/project/notes.txt' funciona.

Consejo para el examen: Linux aplica solo la primera clase que coincide: propietario, luego grupo, luego other. Y el acceso necesita x en cada directorio padre, lo que namei -l revela con un solo comando.

Comprueba lo que sabes

Un archivo tiene modo 644 pero un usuario sigue recibiendo Permission denied al leerlo. ¿Qué revisas primero?

Los directorios de la ruta; el usuario necesita permiso de ejecución en cada uno, lo que muestra namei -l.

¿Qué hace chmod -R g+rX de forma distinta a g+rx?

La X mayúscula añade ejecución solo a los directorios y a los archivos que ya tienen un bit de ejecución, así que los archivos normales no se vuelven ejecutables.

¿Por qué debes probar el acceso como el usuario y no como root?

Root se salta las comprobaciones de permisos estándar, así que una prueba como root no demuestra nada sobre lo que puede hacer el usuario.
