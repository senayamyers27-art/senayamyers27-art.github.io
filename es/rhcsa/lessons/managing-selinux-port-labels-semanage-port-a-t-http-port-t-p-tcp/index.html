Red Hat Certified System Administrator EX200 (RHEL 10)

Gestionar las etiquetas de puertos de SELinux (semanage port -a -t http_port_t -p tcp)

SELinux etiqueta los puertos de red además de los archivos. La política dice qué tipos de proceso pueden enlazarse (bind), es decir, escuchar, en qué tipos de puerto. Por ejemplo, httpd_t puede enlazarse a los puertos etiquetados como http_port_t, que por defecto incluyen el 80, el 443 y algunos otros como el 8008 y el 8443 (el 8080 está etiquetado como http_cache_port_t). Si configuras un servicio para escuchar en un puerto que no tiene su tipo, SELinux bloquea el enlace y el servicio no arranca, aunque la configuración por lo demás sea perfecta.

semanage port -l lista los tipos de puerto y sus números. Fíltralo para encontrar lo que un servicio ya permite, por ejemplo semanage port -l | grep http_port_t o grep ssh_port_t. Esto te dice tanto si tu puerto ya está cubierto como qué nombre de tipo usar.

semanage port -l | grep -w http_port_t
# http_port_t   tcp   80, 81, 443, 488, 8008, 8009, 8443, 9000
semanage port -a -t http_port_t -p tcp 82
semanage port -l | grep -w http_port_t

Para permitir un puerto nuevo, añádelo con semanage port -a -t type -p protocol port. -a añade, -t da el tipo y -p da el protocolo, tcp o udp. El cambio se guarda en la política y sobrevive a los reinicios. Si el puerto ya está asignado a otro tipo, -a falla con un error que dice que ya está definido; usa en su lugar -m para modificarlo al nuevo tipo. -d borra una adición local. También funcionan los rangos, como 8100-8110.

Una tarea típica del examen: el servidor web debe servir contenido en el puerto 82. Eso necesita tres cambios, y si falta cualquiera la tarea falla. Pon Listen 82 en la configuración de httpd. Añade la etiqueta de puerto de SELinux con semanage port -a -t http_port_t -p tcp 82. Abre el firewall con firewall-cmd --permanent --add-port=82/tcp y recarga. Luego systemctl restart httpd y prueba con curl desde otro host.

El mismo patrón se aplica a SSH en un puerto no estándar (ssh_port_t) y a otros servicios con sus propios tipos de puerto. Cuando un servicio no arranca después de un cambio de puerto, systemctl status muestra un error de enlace como permission denied, y el log de auditoría muestra una denegación AVC (access vector cache) con name_bind, lo que apunta directamente a una etiqueta de puerto que falta.

Términos clave

Port type (tipo de puerto)
Una etiqueta de SELinux en un puerto de red, como http_port_t o ssh_port_t, que controla qué tipos de proceso pueden usarlo.
name_bind
El permiso que necesita un proceso para escuchar en un puerto; sus denegaciones indican que falta una etiqueta de puerto.
semanage port -a
Añade un número de puerto y un protocolo a un tipo de puerto de SELinux.
semanage port -m
Modifica un puerto que ya está definido con otro tipo.
Ejemplo real

SSH también debe escuchar en el puerto 2222. Añades Port 22 y Port 2222 a un drop-in en /etc/ssh/sshd_config.d/, ejecutas semanage port -a -t ssh_port_t -p tcp 2222, abres 2222/tcp en firewalld de forma permanente, recargas y reinicias sshd. ss -tlnp muestra sshd escuchando en ambos puertos.

Consejo para el examen: Un servicio movido a un puerto no estándar necesita tres cosas: su propia configuración, una etiqueta de puerto de SELinux y una regla de firewall. Si el puerto ya tiene otro tipo, usa -m en lugar de -a.

Comprueba lo que sabes

¿Cómo compruebas en qué puertos puede enlazarse el servidor web?

semanage port -l | grep http_port_t.

semanage port -a informa que el puerto ya está definido. ¿Qué haces ahora?

Usa semanage port -m con las mismas opciones para cambiar su tipo.

httpd no arranca después de cambiar Listen a 8888. ¿Qué permiso de SELinux probablemente se deniega?

name_bind en el puerto 8888, porque no está etiquetado como http_port_t.
