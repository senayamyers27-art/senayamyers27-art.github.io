Enlaces duros vs. enlaces simbólicos (ln, ln -s) y sus límites

Para entender los enlaces primero necesitas la idea de inodo. Los datos y metadatos de un archivo (propietario, permisos, marcas de tiempo, tamaño, dónde están los bloques de datos) viven en un inodo, identificado por un número. Un nombre de archivo es solo una entrada de directorio que apunta a un inodo. ls -i muestra los números de inodo, y la segunda columna de ls -l muestra el contador de enlaces: cuántos nombres apuntan a ese inodo.

Un enlace duro (hard link) es simplemente otro nombre para el mismo inodo, creado con ln target linkname. Ambos nombres son iguales; ninguno es el 'original'. Editar el archivo a través de un nombre cambia lo que ves a través del otro, y siempre comparten permisos y propietario porque solo hay un inodo. Borrar un nombre solo reduce el contador de enlaces; los datos se liberan cuando el contador llega a cero y ningún proceso tiene todavía el archivo abierto.

Un enlace simbólico (soft link) es un archivo pequeño separado cuyo contenido es una ruta, creado con ln -s target linkname. Cuando abres el enlace, el sistema sigue la ruta. ls -l lo muestra con el tipo l y una flecha: lrwxrwxrwx ... current -> /opt/app-2.1. Si el destino se mueve o se borra, el enlace simbólico permanece pero no apunta a nada; esto se llama enlace colgante o roto (dangling link), y ls normalmente lo resalta en rojo.

ln /data/report.txt /data/report-hard.txt
ln -s /etc/httpd/conf/httpd.conf /root/httpd.conf
ls -li /data                  # mismo número de inodo, contador de enlaces 2
readlink -f /root/httpd.conf  # a dónde apunta realmente el enlace simbólico

Los límites son lo que pregunta el examen. Los enlaces duros no pueden cruzar sistemas de archivos, porque los números de inodo solo son únicos dentro de un sistema de archivos; intentarlo da el error 'Invalid cross-device link'. No se permiten enlaces duros a directorios (ni siquiera para root), lo que evita bucles en el árbol. Los enlaces simbólicos no tienen ninguna de esas restricciones: pueden apuntar a directorios y a archivos de otros sistemas de archivos, o incluso a rutas que todavía no existen. El precio es que se rompen cuando el destino se mueve.

Presta atención al orden de los argumentos: ln recibe primero el destino existente y después el nombre nuevo, igual que cp. Con los enlaces simbólicos, un destino relativo se interpreta respecto al directorio del propio enlace, no a tu directorio actual, así que ln -s ../conf/app.conf /etc/app.conf apunta a /conf/app.conf. Usar destinos absolutos evita esa confusión.

Ten en cuenta también que los permisos propios de un enlace simbólico (siempre mostrados como rwxrwxrwx) se ignoran; el acceso lo deciden los permisos del destino.

Términos clave

Inode (inodo)
La estructura en disco que contiene los metadatos de un archivo y la ubicación de sus datos, identificada por un número único dentro de su sistema de archivos.
Hard link (enlace duro)
Una entrada de directorio adicional que apunta al mismo inodo; se crea con ln.
Symbolic link (enlace simbólico)
Un archivo especial que contiene una ruta a otro archivo o directorio; se crea con ln -s.
Link count (contador de enlaces)
El número de enlaces duros (nombres) que hacen referencia a un inodo, mostrado en la segunda columna de ls -l.
Dangling link (enlace colgante)
Un enlace simbólico cuyo destino ya no existe.
Ejemplo real

Una aplicación espera su configuración en /etc/app.conf, pero mantienes el archivo real en un sistema de archivos /data separado. Un enlace duro falla con 'Invalid cross-device link', así que creas ln -s /data/app/app.conf /etc/app.conf y lo confirmas con ls -l /etc/app.conf.

Consejo para el examen: Enlaces duros: mismo inodo, solo en el mismo sistema de archivos, sin directorios, sobreviven al borrado del otro nombre. Enlaces simbólicos: archivo separado que contiene una ruta, pueden cruzar sistemas de archivos y apuntar a directorios, se rompen si el destino se mueve.

Comprueba lo que sabes

Si borras el nombre original de un archivo que tiene un enlace duro, ¿qué pasa con los datos?

No se pierde nada; los datos siguen accesibles a través del otro nombre hasta que se elimina el último enlace.

¿Por qué no puedes crear un enlace duro de un archivo de /home a /boot cuando son sistemas de archivos distintos?

Los enlaces duros hacen referencia a números de inodo, que solo tienen sentido dentro de un sistema de archivos.

¿Cómo reconoces un enlace simbólico en la salida de ls -l?

El primer carácter es l y el nombre va seguido de -> y la ruta de destino.
