Red Hat Certified System Administrator EX200 (RHEL 10)

Crear, borrar y modificar grupos locales y sus miembros (groupadd -g, usermod -aG, gpasswd)

Los grupos te permiten conceder permisos a varios usuarios a la vez: le das un directorio a un grupo y controlas la pertenencia en lugar de cambiar los permisos de los archivos para cada persona. Los grupos locales viven en /etc/group, con las contraseñas y los administradores de grupo en /etc/gshadow. En RHEL, cada usuario recibe además un grupo privado con su mismo nombre, así que el acceso compartido necesita grupos adicionales.

groupadd name crea un grupo con el siguiente GID libre. -g establece un GID concreto, algo que las tareas suelen exigir para que los ID coincidan entre sistemas, y -r crea un grupo de sistema. groupmod -n newname oldname cambia el nombre de un grupo y groupmod -g cambia su GID. groupdel name lo borra, pero se negará a borrar un grupo que siga siendo el grupo primario de algún usuario.

groupadd -g 3000 sysadmins
groupmod -n admins sysadmins
getent group admins
# admins:x:3000:
groupdel admins

La pertenencia se puede gestionar desde el lado del usuario o desde el lado del grupo. Desde el lado del usuario, usermod -aG sysadmins alice añade un grupo suplementario; recuerda que -G sin -a reemplaza la lista. Desde el lado del grupo, gpasswd -a alice sysadmins añade un usuario y gpasswd -d alice sysadmins quita uno, sin tocar los demás grupos del usuario. gpasswd -M alice,bob sysadmins establece de una vez toda la lista de miembros.

gpasswd -a bob sysadmins
gpasswd -d bob sysadmins
gpasswd -A alice sysadmins   # alice puede gestionar ella misma los miembros
id bob
groups bob

gpasswd -A convierte a un usuario en administrador del grupo, que entonces puede añadir y quitar miembros sin ser root. newgrp group inicia un nuevo shell con ese grupo como grupo primario, lo que es útil para crear archivos con un grupo concreto.

La pertenencia a un grupo surte efecto al iniciar sesión. Después de añadir un usuario a un grupo, id user desde root muestra el nuevo grupo de inmediato, pero las sesiones existentes del usuario no lo tienen hasta que vuelva a iniciar sesión. Patrón común en el examen: crear un grupo con un GID dado, añadir usuarios como miembros suplementarios, crear un directorio compartido que pertenezca a ese grupo y establecer los permisos, a menudo con el bit setgid para que los archivos nuevos hereden el grupo.

Términos clave

GID
Group ID, el número que identifica a un grupo en /etc/group.
groupadd -g
Crea un grupo con un GID concreto.
gpasswd
Administra /etc/group y /etc/gshadow: añade o quita miembros, establece la lista de miembros y asigna administradores de grupo.
/etc/gshadow
El archivo de grupos seguro que contiene las contraseñas, los administradores y los miembros de los grupos.
Ejemplo real

Creas el grupo sysadmins con GID 4000 y haces miembros a natasha y harry: groupadd -g 4000 sysadmins, luego usermod -aG sysadmins natasha y gpasswd -a harry sysadmins. getent group sysadmins muestra sysadmins:x:4000:natasha,harry.

Consejo para el examen: Tanto usermod -aG como gpasswd -a añaden un grupo sin quitar los demás. La trampa es usermod -G sin -a, que borra los grupos suplementarios existentes de un usuario.

Comprueba lo que sabes

¿Cómo creas el grupo devops con GID 5000?

groupadd -g 5000 devops.

¿Qué comando quita a carol solo del grupo finance?

gpasswd -d carol finance.

¿Por qué groupdel podría negarse a borrar un grupo?

Sigue siendo el grupo primario de al menos un usuario.
