Red Hat Certified System Administrator EX200 (RHEL 10)

Crear, borrar y modificar cuentas de usuario locales (useradd -u -G -s -c, usermod, userdel -r)

Las cuentas de usuario locales se definen en archivos del propio sistema, a diferencia de las cuentas que vienen de un directorio central. Las tareas del RHCSA te piden crear usuarios con propiedades concretas, cambiarlos después y eliminarlos limpiamente. Las tres herramientas son useradd, usermod y userdel, y comparten la mayoría de sus opciones.

useradd name crea la cuenta con los valores predeterminados: el siguiente UID (ID de usuario) libre a partir de 1000, un grupo privado con el mismo nombre, un directorio personal en /home copiado de /etc/skel y el shell predeterminado /bin/bash. La cuenta no tiene una contraseña utilizable hasta que estableces una con passwd. Las opciones anulan los valores predeterminados.

useradd -u 2001 -G wheel,devs -s /bin/bash -c 'Alice Ng' alice
passwd alice
id alice
# uid=2001(alice) gid=2001(alice) groups=2001(alice),10(wheel),1005(devs)

Opciones clave: -u establece el UID, -g establece el grupo primario (que debe existir), -G establece una lista separada por comas de grupos suplementarios, -s establece el shell de inicio de sesión, -c establece el campo de comentario (normalmente el nombre completo), -d establece el directorio personal y -m o -M fuerzan u omiten su creación. Las cuentas de sistema para servicios usan -r, que elige un UID menor que 1000 y omite el directorio personal.

usermod cambia una cuenta existente con las mismas letras: usermod -s /sbin/nologin alice, usermod -c 'New Name' alice, usermod -u 3001 alice. La opción que la gente usa mal es -G. Por sí sola, usermod -G devs alice reemplaza todos los grupos suplementarios de alice por solo devs. Para añadir un grupo conservando los demás, usa -aG, que significa añadir (append). Otras opciones útiles: -l cambia el nombre de inicio de sesión, y -d newhome -m mueve el directorio personal.

userdel name elimina la cuenta pero deja el directorio personal y el buzón de correo, que pasan a pertenecer a un UID que ya no tiene nombre. userdel -r name también elimina el directorio personal y el buzón de correo. Los archivos que el usuario tenía en otros lugares permanecen; encuéntralos con find / -nouser y reasígnalos o elimínalos. Un usuario posterior al que se le dé el mismo UID sería su dueño, por eso importa borrar correctamente.

Verifica siempre con id user y getent passwd user. Los cambios en la pertenencia a grupos se aplican a los nuevos inicios de sesión, así que un usuario que ya tiene la sesión iniciada debe cerrarla y volver a entrar para obtener un grupo nuevo.

Términos clave

UID
User ID, el número que usa el kernel para identificar a un usuario; los usuarios normales empiezan en 1000 en RHEL.
Primary group (grupo primario)
El grupo asignado a los archivos nuevos que crea un usuario; se establece con -g y se guarda en /etc/passwd.
Supplementary group (grupo suplementario)
Una pertenencia adicional a un grupo que otorga los permisos de grupo; se establece con -G.
usermod -aG
Añade grupos suplementarios a un usuario sin quitar los existentes.
Ejemplo real

Una tarea pide el usuario harry con UID 3000, comentario Harry Potter y pertenencia al grupo sysadmins. Ejecutas useradd -u 3000 -c 'Harry Potter' -G sysadmins harry, luego estableces su contraseña, e id harry muestra uid=3000 con sysadmins entre sus grupos.

Consejo para el examen: usermod -G sin -a reemplaza todos los grupos suplementarios. Cuando una tarea diga añadir un usuario a un grupo, usa usermod -aG group user.

Comprueba lo que sabes

¿Qué hace userdel -r que no hace userdel simple?

También borra el directorio personal y el buzón de correo del usuario.

¿Qué opción establece los grupos suplementarios de un usuario al crearlo?

-G seguida de una lista de grupos separada por comas.

Después de usermod -aG devs bob, bob sigue sin poder usar el grupo devs en su sesión abierta. ¿Por qué?

La pertenencia a grupos se lee al iniciar sesión; bob debe cerrar la sesión y volver a entrar.
