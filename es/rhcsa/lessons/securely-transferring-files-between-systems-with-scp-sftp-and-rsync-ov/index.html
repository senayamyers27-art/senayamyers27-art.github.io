Transferir archivos de forma segura entre sistemas con scp, sftp y rsync sobre ssh

Los administradores mueven archivos entre sistemas constantemente: archivos de configuración, respaldos, logs para analizar. Hacerlo sobre SSH significa que la transferencia va cifrada y autenticada con las mismas cuentas y claves que ya usas para iniciar sesión, así que no se necesita un servicio de transferencia de archivos aparte. RHEL ofrece tres herramientas que lo hacen: scp, sftp y rsync.

scp (secure copy) funciona como cp, con las ubicaciones remotas escritas como user@host:path. scp file.txt root@serverb:/tmp/ copia un archivo local a serverb, y scp root@serverb:/etc/hosts . copia un archivo remoto al directorio actual. -r copia directorios recursivamente, -p conserva las horas de modificación y los modos, y -P (mayúscula) establece un puerto SSH no predeterminado. Una ruta después de los dos puntos sin barra inicial es relativa al directorio personal del usuario remoto. Ten en cuenta que las versiones actuales de OpenSSH implementan scp usando por debajo el protocolo SFTP, pero la línea de comandos no cambia.

sftp es interactivo, como un cliente FTP, pero funciona sobre SSH. sftp user@host abre una sesión con un prompt sftp> donde ls y cd actúan en el lado remoto, lls y lcd en el lado local, get descarga, put sube, mkdir crea un directorio remoto y exit sale. Es práctico cuando necesitas explorar antes de decidir qué transferir.

scp -p /etc/chrony.conf root@serverb:/etc/
scp -r root@serverb:/var/log/httpd ./serverb-logs
sftp student@serverb
  sftp> cd /tmp
  sftp> put report.txt
  sftp> get data.csv
rsync -av /srv/web/ root@serverb:/srv/web/
rsync -avn --delete /srv/web/ root@serverb:/srv/web/   # simulación (dry run)

rsync sincroniza archivos de forma eficiente. Compara el origen y el destino y envía solo lo que cambió, incluso solo las partes cambiadas de archivos grandes, así que las transferencias repetidas son rápidas. Por la red usa SSH por defecto. -a (archive) recorre recursivamente y conserva permisos, marcas de tiempo, enlaces simbólicos, propietario y grupo (el propietario solo cuando se ejecuta como root en el lado que recibe), y -v lista lo que se transfiere. Añade -X para los atributos extendidos, como los contextos de SELinux, y -A para las listas de control de acceso. --delete elimina del destino los archivos que ya no existen en el origen, así que ejecútalo primero con -n (simulación) para ver qué pasaría. rsync debe estar instalado en ambas máquinas.

La barra final en el origen de rsync cambia el resultado. rsync -a /srv/web/ host:/backup/web/ copia el contenido de web en el destino, mientras que rsync -a /srv/web host:/backup/ crea /backup/web y copia dentro de él. Cuando los resultados acaban un directorio más abajo de lo esperado, esta suele ser la razón.

Las tres herramientas se autentican como ssh, así que el inicio de sesión con claves te permite automatizar transferencias sin contraseñas, y una advertencia de clave de host significa lo mismo que en ssh. Elige scp para copias rápidas y puntuales, sftp para explorar de forma interactiva y rsync para transferencias grandes o repetidas y para respaldos.

Términos clave

scp
Secure copy: copia archivos hacia o desde hosts remotos sobre SSH usando la sintaxis user@host:path.
sftp
Cliente interactivo de transferencia de archivos sobre SSH, con comandos como get, put, ls y lcd.
rsync
Sincroniza archivos transfiriendo solo las diferencias, sobre SSH por defecto.
rsync -a
Modo archivo: recursivo, conservando permisos, horas, enlaces y el propietario cuando es posible.
--delete
Opción de rsync que elimina los archivos del destino que no están en el origen; pruébala primero con -n.
Ejemplo real

Necesitas una copia nocturna de /srv/web en serverb. El primer rsync -av /srv/web/ root@serverb:/srv/web/ tarda varios minutos, pero la siguiente ejecución envía solo los tres archivos que cambiaron y termina en segundos. Añadir --delete después de una simulación con -n mantiene la copia como un espejo exacto.

Consejo para el examen: En rsync, una barra final en el origen significa 'el contenido de este directorio'; sin ella, se copia el propio directorio dentro del destino. scp usa -P para el puerto, mientras que ssh usa -p.

Comprueba lo que sabes

¿Cómo copias /etc/hosts de serverb al directorio local actual?

scp user@serverb:/etc/hosts .

¿Por qué rsync es más rápido que scp para respaldos repetidos?

Transfiere solo los archivos y partes de archivos que cambiaron desde la última ejecución.

En sftp, ¿cuál es la diferencia entre cd y lcd?

cd cambia el directorio remoto; lcd cambia el directorio local.
