Red Hat Certified System Administrator EX200 (RHEL 10)

Crear sistemas de archivos vfat, ext4 y xfs (mkfs.vfat, mkfs.ext4, mkfs.xfs)

Una partición o un volumen lógico es solo espacio de bloques en bruto hasta que le pones un sistema de archivos. El sistema de archivos decide cómo se registran los archivos, los directorios, los permisos y el espacio libre. RHEL usa XFS como predeterminado, admite ext4 como alternativa madura y usa vfat (la familia FAT) donde otros sistemas operativos o el firmware deben leer el disco, como la partición del sistema EFI (Extensible Firmware Interface) o una memoria USB.

Cada tipo tiene su propio ayudante mkfs. mkfs.xfs viene del paquete xfsprogs, mkfs.ext4 de e2fsprogs y mkfs.vfat de dosfstools. También puedes ejecutar mkfs -t xfs /dev/vdb1, que simplemente llama al ayudante correcto. Las etiquetas son opcionales pero prácticas: XFS y ext4 aceptan -L label, mientras que vfat usa -n LABEL.

mkfs.xfs  /dev/vg1/data        # sistema de archivos predeterminado de RHEL
mkfs.ext4 -L logs /dev/vdb1    # ext4 con una etiqueta
mkfs.vfat -n USBDATA /dev/vdc1 # FAT, legible por otros sistemas
lsblk -f                       # muestra FSTYPE, LABEL, UUID
blkid /dev/vdb1                # imprime UUID y TYPE

Conoce las diferencias en las que se apoya el examen. XFS es rápido con archivos grandes y E/S en paralelo, se puede ampliar mientras está montado, pero no se puede reducir. ext4 se puede ampliar en línea y reducir sin montar. vfat no tiene en absoluto bits de propietario ni de permisos de Linux; el propietario y el modo que ves se establecen al montar con opciones como uid=, gid= y umask=, así que chmod y chown sobre los archivos que contiene no funcionan como esperarías.

mkfs destruye lo que hubiera en el dispositivo. Si el dispositivo ya contiene un sistema de archivos, mkfs.xfs se niega y pide -f para forzarlo; mkfs.ext4 pide confirmación. Esa negativa es una comprobación de seguridad útil, así que lee el mensaje antes de forzar. Verifica dos veces el nombre del dispositivo con lsblk primero, sobre todo en una VM con varios discos parecidos.

Crear el sistema de archivos todavía no lo hace utilizable: aún necesitas un directorio como punto de montaje, un montaje y normalmente una línea en /etc/fstab. Después de mkfs, ejecuta blkid para obtener el nuevo UUID para esa línea de fstab. Ten en cuenta que volver a ejecutar mkfs en el mismo dispositivo genera un UUID nuevo, así que hay que actualizar cualquier entrada de fstab que usara el anterior.

Términos clave

XFS
El sistema de archivos predeterminado de RHEL; de alto rendimiento y ampliable en línea, pero no se puede reducir.
ext4
El cuarto sistema de archivos extendido (fourth extended file system); maduro, ampliable en línea y reducible mientras está desmontado.
vfat
El controlador de Linux para los sistemas de archivos FAT, usado en particiones EFI y medios extraíbles; no guarda propietarios ni permisos de Linux.
blkid
Imprime el UUID, la etiqueta y el tipo de sistema de archivos de los dispositivos de bloques; se usa al escribir entradas de /etc/fstab.
Ejemplo real

Una tarea pide un sistema de archivos ext4 con la etiqueta archive en el volumen lógico /dev/vgdata/lvarch. Ejecutas mkfs.ext4 -L archive /dev/vgdata/lvarch, confirmas con lsblk -f que FSTYPE es ext4 y LABEL es archive, y luego usas blkid para copiar su UUID en /etc/fstab.

Consejo para el examen: Usa exactamente el tipo que se pide. Un evaluador que busca ext4 dará por fallido un volumen XFS aunque se monte y funcione, así que confírmalo con lsblk -f o blkid antes de continuar.

Comprueba lo que sabes

¿Qué opción establece una etiqueta en XFS y ext4, y cuál en vfat?

XFS y ext4 usan -L label; mkfs.vfat usa -n LABEL.

¿Por qué no puedes corregir el propietario dentro de un sistema de archivos vfat con chown?

FAT no guarda bits de propietario ni de permisos de Linux; el propietario y el modo se establecen para todo el sistema de archivos al montar, con opciones como uid=, gid= y umask=.

¿Qué le pasa al UUID si vuelves a ejecutar mkfs en el mismo dispositivo?

Se genera un UUID nuevo, así que hay que actualizar cualquier entrada de /etc/fstab que use el UUID anterior.
