Montar sistemas de archivos al arrancar por UUID o etiqueta en /etc/fstab

Montar conecta un sistema de archivos a un directorio, su punto de montaje, para que su contenido aparezca ahí. Un comando mount dura solo hasta el reinicio. Para que un sistema de archivos se monte automáticamente en cada arranque, debe tener una entrada en /etc/fstab (file system table). El RHCSA califica tu trabajo de almacenamiento después de un reinicio, así que una entrada de fstab correcta es esencial, y una incorrecta puede detener el sistema en un shell de emergencia.

Cada línea de /etc/fstab que no es un comentario tiene seis campos separados por espacios en blanco. Primero, el dispositivo, preferiblemente identificado con UUID=... o LABEL=.... Segundo, el punto de montaje, o none para swap. Tercero, el tipo de sistema de archivos, como xfs, ext4, vfat o swap. Cuarto, las opciones de montaje, donde defaults significa un conjunto estándar (lectura-escritura, permitir archivos de dispositivo y ejecutables, montar automáticamente, etc.); varias opciones se separan con comas sin espacios. Quinto, el campo dump, casi siempre 0. Sexto, el orden de fsck: 0 significa no revisar al arrancar, 1 es para el sistema de archivos raíz y 2 para otros que deban revisarse; los sistemas de archivos XFS normalmente usan 0 porque XFS no usa fsck al arrancar.

UUID=4f3c1d2e-...-9a7b  /data     xfs   defaults         0 0
LABEL=backup             /backup   ext4  defaults,noatime 0 2
/dev/datavg/weblv        /web      xfs   defaults         0 0
UUID=91b2...             none      swap  defaults         0 0

¿Por qué UUID o etiqueta en lugar de /dev/vdb1? Los nombres de dispositivo se asignan en el orden en que el kernel detecta los discos y pueden cambiar cuando se añaden o quitan discos, así que un nombre que hoy es correcto podría apuntar mañana a otro disco. Un UUID se crea cuando se crea el sistema de archivos y sigue siendo el mismo dondequiera que aparezca el disco. Obtenlo con blkid /dev/vdb1 o lsblk -f. Una etiqueta es un nombre que asignas tú, por ejemplo con xfs_admin -L backup /dev/vdb1 para XFS o e2label /dev/vdb1 backup para ext4, o con -L al ejecutar mkfs. Las rutas de LVM como /dev/datavg/weblv también son estables, porque vienen de los nombres de LVM, así que también son aceptables.

mkdir -p /data
blkid /dev/vdb1                  # copiar el UUID
vim /etc/fstab                   # añadir la línea
systemctl daemon-reload          # systemd regenera las unidades de montaje
mount -a                         # montar todo lo de fstab, informa de errores
findmnt --verify                 # revisar la sintaxis de fstab y los dispositivos
findmnt /data ; df -h /data

Prueba siempre antes de reiniciar. mount -a monta cada entrada de fstab que todavía no esté montada e imprime un error por cada línea incorrecta, lo que es mucho mejor que descubrir el error al arrancar. findmnt --verify revisa fstab en busca de errores. En RHEL, systemd convierte las entradas de fstab en unidades de montaje, así que ejecuta systemctl daemon-reload después de editar para evitar un aviso de que el archivo cambió. El directorio del punto de montaje debe existir antes de montar.

Si una entrada incorrecta llega a pasar, el arranque normalmente se detiene en el modo de emergencia; corrige fstab ahí como se describe en la lección de los targets de arranque. Para discos extraíbles u opcionales, la opción nofail permite que el arranque continúe si falta el dispositivo.

Términos clave

/etc/fstab
Archivo que lista los sistemas de archivos que se montan al arrancar: dispositivo, punto de montaje, tipo, opciones, dump y orden de fsck.
Mount point (punto de montaje)
Un directorio existente donde se conecta el contenido de un sistema de archivos.
UUID=
Sintaxis de dispositivo en fstab que usa el identificador único universal de un sistema de archivos, estable aunque cambie el nombre del dispositivo.
LABEL=
Sintaxis de dispositivo en fstab que usa una etiqueta de sistema de archivos asignada por una persona.
mount -a
Monta todas las entradas de fstab que aún no están montadas; se usa para probar fstab antes de reiniciar.
Ejemplo real

Formateas /dev/vdb1 con XFS y lo necesitas en /archive de forma permanente. blkid /dev/vdb1 te da su UUID; añades UUID=<that value> /archive xfs defaults 0 0 a /etc/fstab, creas /archive, ejecutas systemctl daemon-reload y mount -a, y findmnt /archive lo confirma antes de reiniciar para estar seguro.

Consejo para el examen: Ejecuta siempre mount -a (e idealmente findmnt --verify) después de editar /etc/fstab. Un error de escritura que detectas ahora se corrige en dos segundos; el mismo error al arrancar te lleva al modo de emergencia.

Comprueba lo que sabes

¿Por qué se prefieren los UUID a los nombres /dev/sdX en fstab?

Los nombres de dispositivo pueden cambiar cuando se añaden discos o se detectan en otro orden; los UUID permanecen con el sistema de archivos.

¿Qué controla el sexto campo de fstab?

El orden de fsck al arrancar: 0 sin revisión, 1 la raíz, 2 los demás sistemas de archivos.

¿Cómo pruebas nuevas entradas de fstab sin reiniciar?

Ejecuta mount -a (después de systemctl daemon-reload) y revisa si hay errores; findmnt --verify también ayuda.
