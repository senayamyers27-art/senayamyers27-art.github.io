Iniciar, detener y comprobar servicios de red (systemctl status, ss -tlnp)

Un servicio de red es un demonio, un programa en segundo plano, que escucha en un puerto de red a la espera de clientes: sshd en el puerto 22, un servidor web en el 80 y el 443, chronyd para la hora. En RHEL, systemd gestiona los demonios como unidades de servicio, como sshd.service o httpd.service, y systemctl es la forma de controlarlos. Una tarea de servicio solo está terminada cuando el servicio está en ejecución ahora, arrancará al iniciar el sistema y realmente escucha donde los clientes lo esperan.

Dos ideas distintas son fáciles de confundir. Iniciar o detener cambia el estado actual: systemctl start httpd, systemctl stop httpd, systemctl restart httpd (detener y luego iniciar) y systemctl reload httpd (volver a leer la configuración sin cortar las conexiones, si el servicio lo admite). Habilitar o deshabilitar cambia lo que ocurre al arrancar: systemctl enable httpd hace que se inicie automáticamente, disable lo impide. systemctl enable --now httpd hace ambas cosas a la vez y es el comando habitual en el examen.

systemctl enable --now httpd
systemctl status httpd          # estado, PID, líneas de log recientes
systemctl is-active httpd       # active / inactive / failed
systemctl is-enabled httpd      # enabled / disabled / masked
systemctl list-units --type=service --state=running
systemctl mask telnet.socket    # impedir cualquier inicio

systemctl status UNIT es la herramienta principal de diagnóstico. Muestra si la unidad está cargada y habilitada, su estado activo (active (running), inactive (dead) o failed), el PID principal, el uso de memoria y CPU, y las líneas más recientes del journal, que normalmente explican un fallo. is-active e is-enabled devuelven solo el estado y un código de salida correspondiente, lo que resulta práctico en scripts. systemctl --failed lista las unidades que fallaron. Enmascarar una unidad con systemctl mask la enlaza a la nada para que no pueda iniciarse en absoluto, ni siquiera como dependencia, hasta que la desenmascares con unmask.

ss (socket statistics) muestra en qué está escuchando realmente el sistema, lo que prueba que el servicio es accesible a nivel de red. ss -tlnp significa TCP (-t), solo sockets en escucha (-l), direcciones y puertos numéricos en lugar de nombres (-n) y el proceso dueño de cada socket (-p, que necesita root para mostrar los procesos de otros usuarios). Añade -u para UDP. La columna Local Address te dice dónde escucha: 0.0.0.0:22 o [::]:22 significa todas las direcciones IPv4 o IPv6, mientras que 127.0.0.1:631 significa solo localhost, inaccesible desde cualquier otro lugar.

Si un servicio está en ejecución pero los clientes siguen sin poder conectarse, revisa las siguientes capas. El firewall debe permitir el puerto (firewall-cmd --list-all), y SELinux debe permitir que el servicio use un puerto no estándar. Si un servicio no arranca en absoluto, lee systemctl status y journalctl -u UNIT, corrige la configuración y usa la comprobación de sintaxis propia del servicio si la tiene, como sshd -t o apachectl configtest.

Después de cambiar el propio archivo de una unidad, ejecuta systemctl daemon-reload para que systemd vuelva a leer sus definiciones antes de reiniciar el servicio.

Términos clave

Service unit (unidad de servicio)
Una unidad de systemd (name.service) que describe cómo ejecutar y gestionar un demonio.
start vs enable
start ejecuta el servicio ahora; enable hace que arranque al iniciar el sistema. enable --now hace ambas cosas.
systemctl status
Muestra el estado de carga, habilitación y actividad de una unidad, su PID principal y las líneas de log recientes.
ss -tlnp
Lista numéricamente los sockets TCP en escucha con el proceso dueño.
mask
Enlaza una unidad a /dev/null para que no pueda iniciarse hasta que se desenmascare.
Ejemplo real

Instalas httpd y ejecutas systemctl enable --now httpd. systemctl status httpd muestra active (running), y ss -tlnp | grep ':80' muestra httpd escuchando en *:80. Una prueba desde otro host falla, así que añades el servicio http en firewalld y la página carga.

Consejo para el examen: Una tarea que dice que el servicio debe estar en ejecución y ser persistente necesita tanto start como enable: systemctl enable --now. Luego pruébalo con systemctl is-enabled, is-active y ss -tlnp.

Comprueba lo que sabes

¿Cuál es la diferencia entre systemctl start y systemctl enable?

start ejecuta el servicio ahora; enable lo configura para que arranque automáticamente al iniciar el sistema.

¿Qué significan las letras de ss -tlnp?

TCP, sockets en escucha, salida numérica y mostrar el proceso dueño.

¿Qué te dice 127.0.0.1:25 en la salida de ss?

Que el servicio escucha solo en la interfaz de loopback, así que los hosts remotos no pueden conectarse.
