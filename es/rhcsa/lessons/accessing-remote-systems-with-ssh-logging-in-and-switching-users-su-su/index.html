Red Hat Certified System Administrator EX200 (RHEL 10)

Acceder a sistemas remotos con ssh; iniciar sesión y cambiar de usuario (su -, sudo -i) en targets multiusuario

Los servidores RHEL normalmente se ejecutan en el target multiusuario (multi-user target), un estado en modo texto con la red y los servicios en funcionamiento pero sin escritorio gráfico. Llegas a ellos con una consola de texto o, mucho más a menudo, por la red con SSH (Secure Shell), que cifra toda la sesión. En el examen harás ssh entre máquinas y cambiarás de cuenta constantemente, así que estos comandos deberían volverse automáticos.

La forma básica es ssh user@host. Si omites el usuario, ssh usa tu nombre de usuario actual. La primera vez que te conectas a un host, ssh muestra la huella (fingerprint) de la clave del servidor y te pide que la aceptes; las claves aceptadas se guardan en ~/.ssh/known_hosts, y una discrepancia posterior genera una advertencia que podría significar que el servidor se reinstaló o que alguien está interceptando la conexión. También puedes ejecutar un solo comando de forma remota: ssh root@serverb 'systemctl is-active sshd'. Escribe exit o presiona Ctrl+D para cerrar la sesión.

La autenticación basada en claves reemplaza las contraseñas con un par de claves. ssh-keygen crea una clave privada (por ejemplo ~/.ssh/id_ed25519) y una clave pública correspondiente que termina en .pub. ssh-copy-id user@host añade la clave pública a ~/.ssh/authorized_keys en el servidor. Después de eso inicias sesión sin contraseña, y la clave privada nunca sale de tu máquina, así que protégela con una frase de contraseña (passphrase) y permisos estrictos.

Una vez dentro, a menudo necesitas otra identidad. su (substitute user) inicia un shell como otro usuario después de pedir la contraseña de ese usuario. El guion importa: su - harry inicia un shell de inicio de sesión (login shell) que carga el entorno, el PATH y el directorio personal de harry, mientras que su harry simple conserva la mayor parte de tu entorno actual, lo que puede hacer que los comandos se comporten de forma inesperada. su - sin nombre significa root.

sudo ejecuta un solo comando como root (u otro usuario) después de pedir tu propia contraseña, y solo si la política de sudo en /etc/sudoers y /etc/sudoers.d/ lo permite. En RHEL, los miembros del grupo wheel tienen permiso por defecto. sudo -i abre un shell de inicio de sesión interactivo como root, similar a su -, pero te autentica con tu propia contraseña y registra la acción en los logs, por eso los administradores lo prefieren a compartir la contraseña de root.

ssh student@servera
sudo -i          # shell de inicio de sesión como root usando tu contraseña
su - harry       # inicio de sesión completo como harry usando la contraseña de harry
whoami; id       # confirmar quién eres ahora
exit             # volver a la identidad anterior

Cada su o sudo -i apila un nuevo shell encima del anterior, así que exit te regresa un nivel a la vez. Revisa whoami y el prompt antes de hacer algo importante.

Términos clave

SSH
Secure Shell: un protocolo cifrado y un cliente (ssh) para iniciar sesión y ejecutar comandos en sistemas remotos.
su -
Cambia de usuario con un shell de inicio de sesión completo y el entorno de ese usuario; pide la contraseña del usuario de destino.
sudo -i
Inicia un shell de inicio de sesión como root después de autenticarte con tu propia contraseña, según lo permita la política de sudoers.
wheel group (grupo wheel)
El grupo cuyos miembros pueden ejecutar cualquier comando con sudo según la política sudoers predeterminada de RHEL.
multi-user.target
El target de systemd para un sistema en modo texto con red y servicios pero sin inicio de sesión gráfico.
Ejemplo real

Inicias sesión en servera como student y luego ejecutas ssh root@serverb para terminar una tarea allí. De vuelta en servera usas sudo -i para editar /etc/fstab, escribes exit para volver a student y whoami confirma que ya no eres root.

Consejo para el examen: su pide la contraseña del usuario de DESTINO; sudo pide TU contraseña. Y usa siempre el guion (su -) cuando necesites el entorno completo del otro usuario.

Comprueba lo que sabes

¿Cuál es la diferencia práctica entre su harry y su - harry?

su - harry inicia un shell de inicio de sesión con el entorno, el PATH y el directorio personal de harry; su harry conserva gran parte del entorno actual.

¿La contraseña de quién pide sudo -i?

La contraseña del propio usuario que lo invoca, y solo si sudoers se lo permite a ese usuario.

¿Qué archivo del servidor contiene las claves públicas que pueden iniciar sesión en una cuenta?

~/.ssh/authorized_keys en el directorio personal de esa cuenta.
