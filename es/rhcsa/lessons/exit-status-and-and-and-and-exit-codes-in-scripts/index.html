Código de salida ($?), && y ||, y códigos de salida en scripts

Todo comando que termina devuelve un código de salida (exit status), un número de 0 a 255. Por convención, 0 significa éxito y cualquier valor distinto de cero significa algún tipo de fallo; el valor concreto puede identificar el error, y la página man de un comando suele documentar sus códigos. El shell usa los códigos de salida para dirigir if, while, && y ||, así que entenderlos es la clave para escribir scripts que reaccionen correctamente ante los fallos.

La variable especial $? contiene el código de salida del último comando que terminó. Revísala de inmediato, porque el siguiente comando, incluso echo, la reemplaza. Por ejemplo, grep -q harry /etc/passwd; echo $? imprime 0 si harry existe y 1 si no; grep usa 2 para errores como un archivo inexistente.

ls /nonexistent
echo $?                    # 2 para ls: problema serio
mkdir -p /backup && cp -a /etc /backup/   # copiar solo si mkdir funcionó
ping -c1 -W1 serverb || echo "serverb unreachable"
systemctl is-active sshd && echo up || echo down

&& y || encadenan comandos según el código de salida. cmd1 && cmd2 ejecuta cmd2 solo si cmd1 tuvo éxito; cmd1 || cmd2 ejecuta cmd2 solo si cmd1 falló. Te permiten escribir líneas de protección cortas como cd /data || exit 1, que detiene un script en lugar de continuar en el directorio equivocado. La combinación a && b || c se usa a menudo como un if/else compacto, pero cuidado: c también se ejecuta si a tuvo éxito y b falló, así que usa un if de verdad cuando eso importe.

Los scripts también devuelven códigos de salida. El comando interno exit termina el script inmediatamente con el número que le des, exit 0 para éxito o exit 1 (u otro valor distinto de cero) para fallo. Sin un exit explícito, un script devuelve el código del último comando que ejecutó. Establecer un código claro importa porque otras herramientas dependen de él: una tarea programada, un servicio de systemd u otro script solo pueden saber que tu script falló si devuelve un valor distinto de cero. Una tarea podría decir 'si no se da ningún argumento, imprime un mensaje de uso y sal con el código 2'.

#!/bin/bash
if [ $# -ne 1 ]; then
    echo "Usage: $0 username" >&2
    exit 2
fi
id "$1" &> /dev/null || { echo "no such user" >&2; exit 1; }
echo "$1 exists"
exit 0

En ese script, >&2 envía los mensajes de error a stderr, lo cual es una buena práctica, y las llaves agrupan varios comandos para ejecutarlos después de ||. Puedes verificar el código de un script igual que el de cualquier comando: ejecútalo y luego echo $?. Algunos administradores también añaden set -e para detenerse ante cualquier comando que falle, pero tiene excepciones sorprendentes, así que las comprobaciones explícitas son más claras para los scripts del examen.

Términos clave

Exit status (código de salida)
Un número de 0 a 255 que devuelve todo comando; 0 significa éxito y un valor distinto de cero, fallo.
$?
Variable especial que contiene el código de salida del último comando que terminó.
&&
Ejecuta el siguiente comando solo si el anterior tuvo éxito (código de salida 0).
||
Ejecuta el siguiente comando solo si el anterior falló (código de salida distinto de cero).
exit
Comando interno que termina un script inmediatamente con un código de salida dado.
Ejemplo real

Un script de respaldo empieza con mountpoint -q /backup || { echo 'backup disk not mounted' >&2; exit 1; }. Cuando falta el disco, el script se detiene con el código 1 en lugar de llenar el sistema de archivos raíz, y el fallo de la tarea cron queda visible en los logs.

Consejo para el examen: $? se sobrescribe con cada comando, incluidos echo y [ ]; guárdalo de inmediato en una variable (rc=$?) si lo necesitas después.

Comprueba lo que sabes

¿Qué código de salida indica éxito?

0; cualquier valor distinto de cero indica fallo.

En mkdir /data && touch /data/ok, ¿cuándo se ejecuta touch?

Solo si mkdir tuvo éxito.

¿Qué código devuelve un script que no tiene comando exit?

El código de salida del último comando que ejecutó.
