Red Hat Certified System Administrator EX200 (RHEL 10)

Listar e identificar contextos de SELinux de archivos y procesos (ls -Z, ps -eZ, id -Z)

Todo lo que decide SELinux se basa en etiquetas llamadas contextos de seguridad. Cada archivo, directorio, proceso, puerto y sesión de usuario tiene uno. Antes de poder corregir un problema de SELinux, necesitas leer estas etiquetas y darte cuenta de cuándo una está mal. Casi todas las tareas de SELinux del RHCSA empiezan con una opción -Z.

Un contexto tiene cuatro campos separados por dos puntos: usuario, rol, tipo y nivel, por ejemplo system_u:object_r:httpd_sys_content_t:s0. El usuario y el rol de SELinux importan poco en la política targeted predeterminada. El tipo, que termina en _t, es la parte que importa: las reglas de la política targeted se escriben como qué tipo de proceso puede hacer qué con qué tipo de objeto. Esto se llama type enforcement (aplicación de tipos). El nivel (s0) se usa para la seguridad multinivel y normalmente se puede ignorar.

Muchos comandos estándar aceptan -Z. ls -Z muestra los contextos de los archivos, y ls -dZ muestra el propio directorio. ps -eZ (o ps axZ) muestra el contexto de cada proceso, así que puedes ver que el servidor web se ejecuta como httpd_t. id -Z muestra tu propio contexto, normalmente unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023 para un inicio de sesión normal, lo que significa que la política targeted no confina tu shell. ss -Z muestra los sockets con los contextos de los procesos.

ls -Z /var/www/html/index.html
# unconfined_u:object_r:httpd_sys_content_t:s0 /var/www/html/index.html
ps -eZ | grep httpd
# system_u:system_r:httpd_t:s0   1234 ?  00:00:00 httpd
id -Z

Leerlos explica la mayoría de los fallos. Un proceso de tipo httpd_t puede leer archivos etiquetados como httpd_sys_content_t, pero no archivos etiquetados como user_home_t o admin_home_t. Así que cuando el archivo de una página web muestra el tipo equivocado, ese es tu problema, aunque sus bits de permiso estén bien.

¿De dónde vienen las etiquetas de los archivos? Un archivo nuevo normalmente hereda el tipo del directorio en el que se crea. Por eso cp hacia /var/www/html da la etiqueta correcta, mientras que mv desde un directorio personal conserva la antigua etiqueta de home, porque mover no crea un archivo nuevo. cp -a y tar con la opción --selinux conservan las etiquetas originales. La lista de la política con la etiqueta que debería tener cada ruta se muestra con semanage fcontext -l, y matchpathcon /path imprime la etiqueta esperada para una ruta.

Compara la etiqueta real de ls -Z con la esperada; una discrepancia es lo que corrige restorecon, de la siguiente lección.

Términos clave

Security context (contexto de seguridad)
Una etiqueta de SELinux de la forma user:role:type:level asociada a archivos, procesos y puertos.
Type (tipo)
El campo del contexto que termina en _t y que usa la política targeted para decidir el acceso.
Type enforcement (aplicación de tipos)
Reglas de la política de SELinux que permiten a un tipo de proceso un acceso concreto a tipos de objeto.
unconfined_t
El tipo de las sesiones de inicio de sesión de los usuarios normales, que la política targeted no restringe.
Ejemplo real

Una página que moviste a /var/www/html da 403 Forbidden mientras las demás funcionan. ls -Z muestra que el archivo nuevo es admin_home_t mientras que los demás son httpd_sys_content_t, y ps -eZ muestra que el servidor se ejecuta como httpd_t. La discrepancia viene de usar mv en lugar de cp, y reetiquetar el archivo lo corrige.

Consejo para el examen: mv conserva el contexto anterior de un archivo, mientras que cp crea un archivo nuevo con el contexto del directorio. Un archivo movido con el tipo equivocado es una trampa clásica del examen.

Comprueba lo que sabes

¿Qué campo de un contexto de SELinux es el más importante en la política targeted?

El campo del tipo, que termina en _t.

¿Cómo ves el contexto de los procesos httpd en ejecución?

ps -eZ | grep httpd (o ps axZ).

¿Por qué un archivo movido con mv conserva el contexto equivocado?

mv conserva el archivo existente y su etiqueta, mientras que un archivo recién creado hereda el tipo del directorio.
