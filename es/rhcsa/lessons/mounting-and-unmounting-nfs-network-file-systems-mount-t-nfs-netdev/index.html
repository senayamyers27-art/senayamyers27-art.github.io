Red Hat Certified System Administrator EX200 (RHEL 10)

Montar y desmontar sistemas de archivos de red NFS (mount -t nfs, _netdev)

NFS (Network File System) permite que un servidor comparta, o exporte, directorios que los clientes montan por la red como si fueran locales. El RHCSA evalúa el lado del cliente: encontrar un recurso compartido, montarlo a mano y hacer que se monte al arrancar. Las herramientas del cliente vienen del paquete nfs-utils, que a menudo ya está instalado.

Un origen NFS se escribe server:/exported/path. Para ver lo que exporta un servidor, showmount -e server funciona cuando el servidor también ofrece los servicios más antiguos de NFSv3; con un servidor solo NFSv4 puede fallar, y en su lugar puedes montar la exportación raíz del servidor y explorarla. Los clientes RHEL intentan primero la versión 4 de NFS por defecto, y puedes forzar una versión con -o nfsvers=4.2 o vers=3.

dnf install -y nfs-utils
mkdir -p /mnt/share
mount -t nfs server1.example.com:/exports/share /mnt/share
findmnt /mnt/share      # muestra el tipo nfs4 y las opciones
umount /mnt/share

Para un montaje persistente, la línea de fstab usa el origen NFS como dispositivo, nfs como tipo, e incluye _netdev. Esa opción marca el sistema de archivos como dependiente de la red, así que systemd espera a que la red esté activa antes de montarlo y lo desmonta antes de que la red se detenga al apagar. Dump y fsck son 0 porque no hay nada local que revisar.

server1.example.com:/exports/share  /mnt/share  nfs  defaults,_netdev  0 0

La resolución de problemas sigue el camino de la petición. ¿Puedes resolver y alcanzar el servidor (ping, getent hosts server1)? ¿La ruta de exportación está escrita exactamente como se exportó? ¿Importa el firewall del cliente? Normalmente no, porque el cliente hace conexiones salientes, pero el firewall del servidor debe permitir el servicio nfs. Los errores de acceso denegado suelen significar que el servidor no exporta a la dirección de tu cliente. Los errores de permisos después de montar suelen deberse a UID que no coinciden o a root squash, donde el servidor asigna el usuario root del cliente a un usuario sin privilegios.

Si un servidor está caído, los montajes NFS pueden dejar colgados los procesos que los tocan, ya que el montaje hard predeterminado reintenta para siempre. Es así por diseño para proteger los datos, pero es otra razón para probar los montajes antes de reiniciar. Cuando la tarea pida montaje bajo demanda en lugar de uno permanente, usa autofs, que se trata a continuación.

Términos clave

NFS
Network File System; un protocolo para compartir directorios desde un servidor para que los clientes puedan montarlos por la red.
Export (exportación)
Un directorio que un servidor NFS pone a disposición de los clientes.
_netdev
Una opción de fstab que marca un sistema de archivos como dependiente de la red para que se monte después de que la red arranque.
Root squash
Un comportamiento del servidor NFS que asigna el usuario root del cliente a una cuenta sin privilegios; es lo predeterminado en las exportaciones.
Ejemplo real

Una tarea dice que montes server1:/exports/projects en /projects en cada arranque. Creas /projects, lo pruebas con mount -t nfs server1:/exports/projects /projects, lo desmontas, añades server1:/exports/projects /projects nfs defaults,_netdev 0 0 a /etc/fstab y luego ejecutas systemctl daemon-reload y mount -a para confirmarlo.

Consejo para el examen: Incluye _netdev en los montajes de red de /etc/fstab. Documenta que el montaje necesita la red, mantiene correcto el orden de arranque y apagado, y es la opción que buscan las respuestas del examen.

Comprueba lo que sabes

¿Cuál es el campo de dispositivo de un montaje NFS en /etc/fstab?

El nombre o la dirección del servidor y la ruta exportada, escritos server:/path.

¿Por qué showmount -e podría fallar contra un servidor NFS que funciona?

Depende de los servicios de NFSv3; un servidor que solo ofrece NFSv4 puede no responderle, aunque los montajes funcionen.

Los archivos que creas como root en un montaje NFS aparecen con propietario nobody. ¿Por qué?

El servidor usa root squash, que asigna el root del cliente a un usuario sin privilegios.
