Configurar servicios de red para que arranquen automáticamente al iniciar el sistema

Un servicio de red solo es útil si está escuchando cuando llegan los clientes, incluso después de un reinicio. En RHEL, hacer que un servicio de red arranque al iniciar el sistema implica los mismos comandos de systemd que cualquier servicio, más dos comprobaciones específicas de red: la propia conexión de red debe activarse automáticamente, y los clientes deben poder pasar por el firewall.

El primer paso es la unidad de servicio. Después de instalar un paquete como httpd, vsftpd o nfs-utils, el servicio normalmente queda instalado pero deshabilitado. Ejecuta systemctl enable --now httpd para que arranque ahora y en cada inicio, y luego confírmalo con systemctl is-enabled httpd y systemctl is-active httpd. ss -tlnp confirma que el proceso escucha en el puerto esperado.

El segundo paso es la propia red. NetworkManager debe estar habilitado (lo está por defecto) y el perfil de conexión debe tener connection.autoconnect yes. Compruébalo con systemctl is-enabled NetworkManager y nmcli -f NAME,AUTOCONNECT con show. Un servicio puede estar perfectamente habilitado y aun así ser inaccesible tras reiniciar porque la interfaz no se activó con la dirección correcta.

El tercer paso es el acceso. Abre el servicio en firewalld de forma permanente, por ejemplo firewall-cmd --permanent --add-service=http seguido de firewall-cmd --reload. Si el servicio usa un puerto no estándar, puede que SELinux también necesite una etiqueta de puerto, lo que se trata en las lecciones de SELinux.

dnf install -y httpd
systemctl enable --now httpd
firewall-cmd --permanent --add-service=http
firewall-cmd --reload
systemctl is-enabled httpd NetworkManager
ss -tlnp | grep ':80'

Algunos servicios necesitan esperar a que la red esté completamente configurada, no solo a que NetworkManager haya arrancado. Las unidades que lo necesitan se ordenan después de network-online.target; NetworkManager proporciona ese target mediante su servicio wait-online. La mayoría de los servicios empaquetados ya lo gestionan, pero esto explica por qué existe _netdev para los montajes de red y por qué una unidad personalizada que se enlaza a una dirección concreta podría arrancar demasiado pronto.

La prueba final y más fiable es un reinicio. Después, revisa el estado del servicio, el puerto en escucha, la dirección de la interfaz y una conexión desde otro host.

Términos clave

enable --now
Habilita una unidad para que arranque al iniciar el sistema y la inicia de inmediato.
network-online.target
Un target de systemd que se alcanza cuando la red está completamente configurada; se usa para ordenar los servicios que necesitan red operativa.
ss -tlnp
Lista los sockets TCP en escucha con puertos numéricos y los procesos dueños.
Permanent firewall rule (regla de firewall permanente)
Un cambio de firewalld guardado con --permanent para que sobreviva a las recargas y los reinicios.
Ejemplo real

Configuras vsftpd y funciona, pero tras el reinicio del evaluador los clientes no pueden conectarse. systemctl is-enabled vsftpd imprime disabled. Ejecutar systemctl enable --now vsftpd y añadir el servicio ftp al firewall con --permanent y --reload hace que sobreviva al siguiente reinicio.

Consejo para el examen: Para los servicios de red, revisa tres cosas antes de dar por terminada una tarea: el servicio está habilitado, la conexión se conecta automáticamente y la regla del firewall es permanente. Luego reinicia y prueba.

Comprueba lo que sabes

¿Qué dos comprobaciones de systemctl confirman que un servicio se ejecutará tras reiniciar y que se está ejecutando ahora?

systemctl is-enabled para el arranque y systemctl is-active para el estado actual.

El servicio está habilitado pero es inaccesible tras reiniciar. Nombra dos causas de red.

El perfil de conexión no se conectó automáticamente o se activó con la dirección equivocada, o la regla del firewall era solo de tiempo de ejecución (runtime).

¿Para qué sirve network-online.target?

Marca el momento en que la red está completamente configurada, para que los servicios que necesitan red operativa puedan ordenarse después.
