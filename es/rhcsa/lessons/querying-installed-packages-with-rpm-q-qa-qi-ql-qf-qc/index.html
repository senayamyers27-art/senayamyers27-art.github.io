Consultar paquetes instalados con rpm -q, -qa, -qi, -ql, -qf, -qc

Mientras dnf se ocupa de los repositorios y las dependencias, el comando de más bajo nivel rpm lee directamente la base de datos RPM local, que describe cada paquete instalado en el sistema. Su modo de consulta, -q, es rápido, funciona sin conexión y es la forma estándar de responder preguntas como '¿está instalado esto?', '¿qué archivos instaló?' o '¿qué paquete es dueño de este archivo?'.

rpm -q package comprueba si un paquete está instalado e imprime su nombre completo con versión, release y arquitectura, como openssh-server-9.x-y.el10.x86_64, o 'package X is not installed'. Como establece su código de salida en consecuencia, también es práctico en scripts. rpm -qa lista todos los paquetes instalados; pásalo por grep o dale un glob, como en rpm -qa 'kernel*', para acotar la lista.

Las demás opciones añaden detalles sobre un paquete. rpm -qi package muestra información similar a dnf info: versión, fecha de instalación, proveedor, firma, resumen y descripción. rpm -ql package lista todos los archivos que instaló el paquete. rpm -qc package lista solo sus archivos de configuración, que suele ser la forma más rápida de descubrir dónde guarda un servicio sus ajustes. rpm -qd lista sus archivos de documentación.

rpm -qf /path/to/file funciona en sentido inverso: te dice qué paquete instalado es dueño de un archivo. rpm -qf /etc/ssh/sshd_config devuelve openssh-server. Si la respuesta es 'not owned by any package', el archivo lo creó localmente un administrador o una aplicación en tiempo de ejecución. Combínalo con $(which command) para encontrar el paquete de un comando: rpm -qf $(which ss).

rpm -q httpd
rpm -qa | wc -l
rpm -qi chrony
rpm -ql chrony | grep bin
rpm -qc chrony            # /etc/chrony.conf y compañía
rpm -qf /usr/bin/ssh
rpm -qp --list ./app.rpm  # consultar un archivo de paquete aún no instalado

Añadir -p consulta un archivo RPM en lugar de la base de datos de instalados, así que rpm -qpl file.rpm muestra qué instalaría un paquete descargado antes de que lo instales. rpm -V package verifica los archivos instalados contra la base de datos e informa de tamaños, sumas de verificación o permisos cambiados, lo que ayuda a detectar archivos modificados o dañados.

Usa rpm para consultas, pero instala y elimina con dnf. Instalar con rpm -i no resuelve las dependencias desde los repositorios y no queda registrado en el historial de dnf.

Términos clave

RPM database (base de datos RPM)
La base de datos local que registra cada paquete instalado y sus archivos, consultada con rpm -q.
rpm -qa
Lista todos los paquetes instalados.
rpm -ql / -qc
Lista todos los archivos, o solo los archivos de configuración, instalados por un paquete.
rpm -qf
Muestra qué paquete instalado es dueño de un archivo dado.
rpm -qi
Muestra información detallada sobre un paquete instalado.
Ejemplo real

Necesitas cambiar los servidores NTP pero no estás seguro de cuál es el archivo. rpm -qc chrony lista /etc/chrony.conf, así que lo editas, añades tu línea de servidor y reinicias chronyd. Después, rpm -qf /etc/chrony.conf confirma que pertenece a chrony.

Consejo para el examen: Asocia las letras: a = all (todos), i = info, l = listar archivos, c = archivos de configuración, f = qué paquete es dueño de este archivo, p = consultar un archivo de paquete en lugar de la base de datos.

Comprueba lo que sabes

¿Qué comando muestra el paquete dueño de /usr/sbin/sshd?

rpm -qf /usr/sbin/sshd.

¿Cómo listas solo los archivos de configuración del paquete httpd?

rpm -qc httpd.

¿Cómo puedes ver qué archivos instalaría un RPM descargado sin instalarlo?

rpm -qpl package.rpm.
