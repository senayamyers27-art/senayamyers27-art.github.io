Red Hat Certified System Administrator EX200 (RHEL 10)

Líneas shebang, hacer scripts ejecutables y ejecutarlos desde el PATH

Un script de shell es un archivo de texto que contiene comandos que podrías escribir en el prompt, guardados para que se puedan volver a ejecutar de forma fiable. El RHCSA te pide escribir scripts sencillos, y un script solo cuenta si se ejecuta como describe la tarea: normalmente por su nombre, desde cualquier lugar y con el intérprete correcto. Tres cosas lo hacen posible: la línea shebang, el permiso de ejecución y el PATH.

El shebang es la primera línea del script y empieza con #! seguido de la ruta absoluta del intérprete; para los scripts de Bash, #!/bin/bash. Cuando ejecutas el archivo como programa, el kernel lee esta línea e inicia ese intérprete con el script como entrada. Sin shebang, normalmente es tu shell actual quien ejecuta el archivo, lo que puede funcionar por casualidad pero no es fiable. El shebang debe ser exactamente la primera línea, sin ninguna línea en blanco ni espacio antes.

#!/bin/bash
# report.sh - mostrar el nombre del host y el uso de disco
echo "Host: $(hostname)"
df -h /

Después, el archivo necesita permiso de ejecución: chmod +x report.sh (o chmod 755). Sin él, ejecutar ./report.sh da 'Permission denied'. Aun así puedes ejecutar un script no ejecutable pasándoselo explícitamente al intérprete, bash report.sh, lo que es útil para probar, pero las tareas normalmente esperan que el propio archivo sea ejecutable. Ten en cuenta también que el script se ejecuta en un nuevo proceso hijo, así que las variables que define y los cambios de directorio que hace no afectan a tu shell actual; source report.sh (o . report.sh) lo ejecuta en cambio en el shell actual.

Por último, el shell encuentra los comandos buscando, en orden, en los directorios listados en la variable de entorno PATH. echo $PATH la muestra. El directorio actual no está en el PATH a propósito, por eso debes escribir ./report.sh para ejecutar un script que está en el directorio actual. Para ejecutarlo solo por su nombre, colócalo en un directorio que esté en el PATH. /usr/local/bin es el lugar convencional para los scripts de administrador disponibles para todos los usuarios, y ~/bin o ~/.local/bin se añaden al PATH de cada usuario mediante los archivos de inicio del shell predeterminados de RHEL.

vim /usr/local/bin/report.sh
chmod 755 /usr/local/bin/report.sh
report.sh              # funciona desde cualquier directorio
which report.sh        # /usr/local/bin/report.sh

Si un script se comporta de forma extraña, ejecútalo con bash -x script para imprimir cada comando a medida que se ejecuta. Y revisa si tiene finales de línea de Windows si lo copiaste de otro lugar: un retorno de carro sobrante después de /bin/bash produce un confuso error 'bad interpreter'.

Términos clave

Shebang
La primera línea #! que nombra el intérprete, p. ej. #!/bin/bash, usada cuando se ejecuta el archivo.
Execute permission (permiso de ejecución)
El permiso x que permite ejecutar un archivo como programa; se establece con chmod +x.
PATH
Variable de entorno que lista los directorios en los que el shell busca comandos, en orden.
/usr/local/bin
Directorio convencional de todo el sistema, incluido en el PATH, para scripts y programas creados localmente.
source
Ejecuta un script en el shell actual en lugar de en un proceso hijo; también se escribe con un punto.
Ejemplo real

Una tarea pide un comando llamado sysinfo que cualquier usuario pueda ejecutar. Creas /usr/local/bin/sysinfo empezando con #!/bin/bash, añades los comandos, ejecutas chmod 755 /usr/local/bin/sysinfo y luego inicias sesión como usuario normal y escribes sysinfo desde /tmp para probar que funciona desde el PATH.

Consejo para el examen: Ejecutar un script por su nombre necesita las tres cosas: un shebang correcto en la línea 1, permiso de ejecución y una ubicación en el PATH. Si no, debes usar ./script o bash script.

Comprueba lo que sabes

¿Por qué debes escribir ./myscript.sh aunque estés en su directorio?

El directorio actual no está en el PATH, así que debes dar una ruta al archivo.

¿Qué error obtienes al ejecutar un script sin permiso x, y cómo lo corriges?

Permission denied; se corrige con chmod +x (o ejecutándolo con bash script).

¿Dónde debe colocarse un script de administración para todo el sistema para que cualquier usuario pueda ejecutarlo por su nombre?

En /usr/local/bin, que está en el PATH predeterminado.
