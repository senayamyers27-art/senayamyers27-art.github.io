Red Hat Certified System Administrator EX200 (RHEL 10)

Configurar el acceso a repositorios RPM: archivos .repo en /etc/yum.repos.d/ (baseurl, enabled, gpgcheck, gpgkey)

RHEL instala software como paquetes RPM (RPM originalmente significaba Red Hat Package Manager). La herramienta dnf descarga paquetes de repositorios: directorios de archivos RPM más metadatos que los describen. En el examen los sistemas a menudo no están registrados con Red Hat, así que una tarea te dará la ubicación de los repositorios BaseOS y AppStream y te pedirá configurar la máquina para usarlos. Si este paso está mal, todas las tareas de instalación posteriores fallan, así que vale la pena dejarlo perfecto.

Los repositorios se definen en archivos que terminan en .repo dentro de /etc/yum.repos.d/. El directorio todavía lleva el nombre de yum, el predecesor de dnf. Cada archivo puede contener una o más secciones. Una sección empieza con un ID de repositorio entre corchetes, que debe ser único y no contener espacios, seguido de ajustes clave=valor.

[BaseOS]
name=RHEL BaseOS
baseurl=file:///mnt/rhel/BaseOS
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-redhat-release

[AppStream]
name=RHEL AppStream
baseurl=file:///mnt/rhel/AppStream
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-redhat-release

Los ajustes clave son estos. name es una descripción legible para humanos. baseurl es la ubicación del repositorio, el directorio que contiene el subdirectorio repodata/; puede ser una URL HTTP, HTTPS, FTP o file:// (fíjate en las tres barras de file:///mnt/...: dos del esquema más la barra inicial de la ruta). En el examen usarás exactamente la dirección que te dé la tarea. enabled=1 hace que dnf use el repositorio, mientras que enabled=0 conserva la definición pero lo ignora.

gpgcheck=1 le indica a dnf que verifique la firma GPG (GNU Privacy Guard) de cada paquete antes de instalarlo, lo que prueba que el paquete vino del publicador y no fue alterado. gpgkey apunta a la clave pública usada para esa verificación; las claves de Red Hat se instalan en /etc/pki/rpm-gpg/. Si la tarea no proporciona una clave, o dice que no hace falta verificar las firmas, pon gpgcheck=0; con gpgcheck activado y sin una clave utilizable, las instalaciones fallan con un error de firma o de clave. Las claves también se pueden importar directamente con rpm --import keyfile.

Después de escribir el archivo, pruébalo: dnf repolist debe mostrar ambos IDs de repositorio con el número de paquetes, y un dnf install de un paquete pequeño debe funcionar. Los errores típicos son un baseurl que apunta un nivel demasiado arriba o abajo (debe contener repodata), un error de escritura en el esquema, que falte enabled=1 y un ajuste de gpgcheck que no coincide con las claves disponibles. Ejecutar dnf clean all después de corregir un archivo hace que dnf descarte los metadatos antiguos en caché.

Términos clave

Repository (repositorio)
Una colección de paquetes RPM más metadatos (repodata) desde la que dnf puede descargar.
Repository ID (ID de repositorio)
El nombre único entre corchetes con el que empieza una sección de un archivo .repo.
baseurl
La URL del directorio que contiene el repodata del repositorio; puede usar los esquemas http, https, ftp o file.
gpgcheck
Ajuste que hace que dnf verifique las firmas de los paquetes (1) o que omita la verificación (0).
gpgkey
Ubicación de la clave pública usada para verificar las firmas de los paquetes cuando gpgcheck=1.
Ejemplo real

La tarea te da las URLs de BaseOS y AppStream en content.example.com. Creas /etc/yum.repos.d/exam.repo con dos secciones que usan esas URLs como baseurl, enabled=1 y gpgcheck=0 porque no se proporcionó ninguna clave; luego dnf repolist lista ambos y dnf install -y tree funciona.

Consejo para el examen: baseurl debe apuntar al directorio que contiene repodata/. En RHEL, BaseOS y AppStream son repositorios separados, así que normalmente necesitas dos secciones, cada una con su propio ID único.

Comprueba lo que sabes

¿Qué hace enabled=0 en una sección de repositorio?

Conserva la definición del repositorio, pero dnf lo ignora a menos que se habilite, por ejemplo con --enablerepo.

¿Qué pasa con gpgcheck=1 y sin un gpgkey válido?

La instalación de paquetes falla porque dnf no puede verificar sus firmas.

¿Dónde se guardan los archivos de definición de repositorios?

En archivos que terminan en .repo dentro de /etc/yum.repos.d/.
