Red Hat Certified System Administrator EX200 (RHEL 10)

Bases de datos de cuentas: /etc/passwd, /etc/shadow, /etc/group; id y getent

Las cuentas locales se guardan en archivos de texto plano, una línea por entrada, con los campos separados por dos puntos. Leer estos archivos con soltura te permite verificar cualquier tarea de usuarios o grupos en segundos y detectar errores como un shell equivocado o un miembro de grupo que falta. Debes examinarlos libremente, pero cambiarlos con las herramientas adecuadas (useradd, usermod, chage, groupmod) o, si debes editarlos a mano, con vipw y vigr, que bloquean los archivos de forma segura.

/etc/passwd lo puede leer cualquiera y tiene siete campos: nombre de inicio de sesión, marcador de contraseña (x significa que el hash está en shadow), UID, GID primario, comentario GECOS (normalmente el nombre completo), directorio personal y shell de inicio de sesión.

alice:x:2001:2001:Alice Ng:/home/alice:/bin/bash

/etc/shadow solo lo puede leer root y contiene el hash de la contraseña y los datos de caducidad en nueve campos: nombre de inicio de sesión, hash, fecha del último cambio (días desde el 1 de enero de 1970), edad mínima, edad máxima, periodo de aviso, periodo de inactividad, fecha de caducidad de la cuenta y un campo reservado. Un hash que empieza con ! o !! significa que la contraseña está bloqueada o nunca se estableció; * significa que no es posible iniciar sesión con contraseña. Los hashes de RHEL empiezan con un identificador como $6$ para SHA-512 o $y$ para yescrypt.

/etc/group tiene cuatro campos: nombre del grupo, marcador de contraseña, GID y una lista separada por comas de los miembros suplementarios. Los usuarios para los que este es su grupo primario normalmente no aparecen en el último campo, porque esa pertenencia viene del GID de /etc/passwd. Por eso revisar solo /etc/group puede hacer parecer que un grupo no tiene miembros.

# nombre:contraseña:GID:miembros
sysadmins:x:4000:natasha,harry

Dos comandos dan respuestas fiables. id user imprime el UID, el GID primario y todos los grupos a los que pertenece el usuario, combinando ambas fuentes. getent consulta las bases de datos del sistema a través de NSS (Name Service Switch), así que incluye los archivos locales y cualquier fuente de red como LDAP (Lightweight Directory Access Protocol): getent passwd alice, getent group sysadmins y, como root, getent shadow alice. Prefiérelos a hacer grep sobre los archivos, porque en los sistemas unidos a un directorio los usuarios de red no aparecen en absoluto en /etc/passwd.

id alice
getent passwd alice | cut -d: -f7   # solo el shell
getent group sysadmins

Términos clave

/etc/passwd
El archivo de cuentas legible por todos, con siete campos: nombre, x, UID, GID, comentario, directorio personal y shell.
/etc/shadow
El archivo, solo para root, que contiene los hashes de las contraseñas y los campos de caducidad de cada cuenta.
/etc/group
El archivo de grupos con nombre, x, GID y una lista de miembros suplementarios.
getent
Consulta bases de datos del sistema como passwd y group a través de NSS, incluidas las fuentes locales y de red.
Ejemplo real

Tras crear el usuario sarah con un shell nologin y pertenencia a sysadmins, lo verificas con getent passwd sarah, que termina en /sbin/nologin, e id sarah, que lista sysadmins. getent shadow sarah muestra un hash que empieza con $, lo que prueba que hay una contraseña establecida.

Consejo para el examen: El grupo primario de un usuario lo establece el campo GID de /etc/passwd; no aparece en /etc/group. Usa id para ver todas las pertenencias a la vez.

Comprueba lo que sabes

¿Qué significa la x en el segundo campo de /etc/passwd?

Que el hash de la contraseña se guarda en /etc/shadow.

¿Qué indica !! al inicio del campo de hash de shadow?

La cuenta todavía no tiene contraseña establecida o está bloqueada, así que no es posible iniciar sesión con contraseña.

¿Por qué usar getent passwd en lugar de grep sobre /etc/passwd?

getent sigue NSS e incluye fuentes de red como LDAP, así que muestra todas las cuentas que conoce el sistema.
