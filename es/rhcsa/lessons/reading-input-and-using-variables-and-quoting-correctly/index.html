Leer entradas y usar variables y comillas correctamente

Las variables guardan valores en un script: nombres, rutas, cantidades. En Bash se asigna con name=value y no debe haber espacios alrededor del =; name = value intentaría ejecutar un comando llamado name. Usas el valor con $name, o ${name} cuando al nombre le siguen otros caracteres, como en ${file}.bak. Los nombres de variable distinguen mayúsculas y minúsculas, y por convención los scripts usan minúsculas para sus propias variables y dejan las mayúsculas para las variables de entorno como PATH y HOME.

Una variable existe solo en el shell actual a menos que la exportes. export NAME=value la hace parte del entorno que se pasa a los procesos hijos, y así es como la ven los programas iniciados desde tu script. Las variables definidas dentro de un script desaparecen cuando el script termina, porque el script se ejecuta en su propio proceso.

read toma la entrada del usuario o de stdin. read name espera una línea y la guarda en name; read -p 'Enter user: ' user muestra primero un mensaje. -s oculta lo que se escribe, útil para contraseñas, y -t 10 expira después de diez segundos. Con varios nombres de variable, read divide la línea por los espacios en blanco y pone el resto en la última variable.

#!/bin/bash
read -p "Directory to archive: " dir
if [ -z "$dir" ] || [ ! -d "$dir" ]; then
    echo "Not a directory: '$dir'" >&2
    exit 1
fi
dest="/backup/$(basename "$dir")-$(date +%F).tar.gz"
tar -czf "$dest" "$dir" && echo "Saved to $dest"

Las comillas controlan lo que expande el shell, y de ahí vienen la mayoría de los errores en los scripts. Las comillas dobles, "...", permiten la expansión de variables, la sustitución de comandos y los escapes con barra invertida, pero impiden la división en palabras y la expansión de globs, así que "$dir" sigue siendo un solo argumento aunque contenga espacios. Las comillas simples, '...', impiden toda expansión: echo '$HOME' imprime el texto literal $HOME. Una barra invertida escapa un solo carácter: echo \$HOME también imprime $HOME.

La regla práctica es sencilla: pon comillas dobles alrededor de cada variable y cada sustitución de comandos a menos que tengas una razón concreta para no hacerlo. Usa comillas simples para cadenas fijas que contienen caracteres especiales, como expresiones regulares para grep o programas de awk. Puedes combinarlas: echo "User $USER said 'hello'" funciona porque las comillas simples dentro de comillas dobles son caracteres normales.

La aritmética tiene su propia sintaxis. $(( )) evalúa expresiones enteras: count=$((count + 1)) o echo $((60 * 60)). Dentro de los dobles paréntesis no necesitas $ antes de los nombres de variable. La aritmética de Bash solo trabaja con enteros, así que $((7 / 2)) es 3.

Términos clave

Variable assignment (asignación de variables)
name=value sin espacios alrededor de =; después se referencia como $name o ${name}.
export
Marca una variable para incluirla en el entorno de los procesos hijos.
read -p
Lee una línea de entrada en variables después de mostrar un mensaje.
Double quotes (comillas dobles)
Permiten la expansión de $ pero impiden la división en palabras y los globs.
Single quotes (comillas simples)
Impiden toda expansión; el texto se toma de forma literal.
Ejemplo real

Un script pide un nombre de usuario con read -p 'User: ' u y ejecuta id $u. Cuando alguien presiona Enter sin escribir nada, $u sin comillas desaparece e id informa en cambio sobre el usuario actual (root). Cambiar la prueba a [ -z "$u" ] && exit 1 y usar id "$u" corrige el error.

Consejo para el examen: Sin espacios alrededor de = en las asignaciones, comillas dobles alrededor de cada $variable y comillas simples cuando quieras el texto de forma literal. '$HOME' imprime $HOME; "$HOME" imprime /root.

Comprueba lo que sabes

¿Qué está mal en count = 5?

Los espacios alrededor de = hacen que Bash ejecute un comando llamado count; debe ser count=5.

¿Qué imprime echo '$USER'?

El texto literal $USER, porque las comillas simples impiden la expansión.

¿Cómo sumas 1 a la variable n?

n=$((n + 1)).
