Red Hat Certified System Administrator EX200 (RHEL 10)

Montar, desmontar y usar sistemas de archivos; mount -a y findmnt --verify

Linux tiene un único árbol de directorios que empieza en /. Montar conecta un sistema de archivos a un directorio de ese árbol, llamado punto de montaje, para que su contenido aparezca ahí. Lo que hubiera antes dentro del directorio del punto de montaje queda oculto hasta que desmontas. En RHEL montas manualmente para probar y usas /etc/fstab para que los montajes persistan tras los reinicios.

Un montaje manual recibe un dispositivo y un directorio. El dispositivo puede ser una ruta, UUID=... o LABEL=.... El kernel normalmente detecta el tipo de sistema de archivos, pero puedes indicarlo con -t. Las opciones van después de -o, por ejemplo ro para solo lectura o noexec para bloquear la ejecución de programas desde ese sistema de archivos.

mkdir -p /data
mount UUID=5b2e...c7 /data        # o: mount /dev/vg1/data /data
mount -o remount,ro /data          # cambiar las opciones sin desmontar
findmnt /data                      # mostrar origen, tipo, opciones
df -h /data                        # tamaño y espacio libre
umount /data                       # desconectarlo

Desmontar falla con target is busy si algún proceso tiene un archivo abierto ahí o un shell lo tiene como directorio actual, que a menudo es tu propio shell. Ejecuta cd / y vuelve a intentarlo. Para encontrar al culpable, lsof /data o fuser -vm /data lista los procesos que lo usan. No te acostumbres a los desmontajes diferidos (lazy); corrige la causa.

Para montajes persistentes, añade una línea a /etc/fstab y luego pruébala. mount -a monta cada entrada de fstab que todavía no esté montada, así que un error ahí apunta a tu nueva línea. findmnt --verify va más allá: analiza todo el archivo e informa de problemas como un directorio de punto de montaje inexistente, un tipo de sistema de archivos desconocido o un UUID que no existe, sin montar nada. Ejecuta ambos antes de reiniciar.

En RHEL, systemd convierte cada línea de fstab en una unidad de montaje al arrancar. Después de editar el archivo, ejecuta systemctl daemon-reload para que systemd tome el cambio; si no, mount puede avisar que fstab se modificó y que systemd sigue usando la versión anterior. Una línea de fstab incorrecta que no esté marcada con nofail puede llevar el sistema al modo de emergencia al arrancar, donde debes iniciar sesión como root, corregir el archivo y reiniciar.

Para usar el sistema de archivos montado, simplemente trabaja en el punto de montaje. Recuerda que el propietario y los permisos del punto de montaje son los del directorio raíz del sistema de archivos montado, no los del directorio vacío que creaste, así que aplica chown y chmod después de montar.

Términos clave

Mount point (punto de montaje)
Un directorio existente donde se conecta un sistema de archivos al árbol de directorios.
mount -a
Monta todos los sistemas de archivos listados en /etc/fstab que aún no están montados; se usa para probar entradas nuevas.
findmnt --verify
Revisa /etc/fstab en busca de errores como puntos de montaje inexistentes, tipos incorrectos o dispositivos desconocidos, sin montar.
target is busy
El error de umount que aparece cuando un proceso tiene archivos abiertos o un directorio de trabajo dentro del sistema de archivos.
Ejemplo real

Después de añadir una línea de fstab para /backup, ejecutas systemctl daemon-reload y luego findmnt --verify, que avisa de que /backup no existe. Creas el directorio, ejecutas mount -a sin errores y findmnt /backup muestra el dispositivo y las opciones correctas, así que el reinicio es seguro.

Consejo para el examen: Nunca reinicies después de editar /etc/fstab sin ejecutar mount -a y findmnt --verify. Un error de escritura puede dejar el sistema del examen en modo de emergencia y costarte tiempo en todas las demás tareas.

Comprueba lo que sabes

umount /data informa target is busy. ¿Cuál es la causa habitual y cómo se soluciona?

Un proceso o tu propio shell está usando un archivo o directorio ahí; sal de él con cd, o encuentra el proceso con lsof o fuser -vm y detenlo, y luego desmonta.

¿Qué revisa findmnt --verify que mount -a no revisa?

Analiza cada línea de fstab e informa de problemas como directorios de punto de montaje inexistentes, tipos desconocidos o UUID que no se pueden resolver, sin montar nada, incluidas las entradas ya montadas.

¿Por qué ejecutar systemctl daemon-reload después de editar /etc/fstab?

systemd genera unidades de montaje a partir de fstab; la recarga hace que las regenere para que use tus nuevas entradas.
