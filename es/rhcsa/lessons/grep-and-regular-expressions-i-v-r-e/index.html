grep y expresiones regulares: ^, $, ., *, [ ], -i, -v, -r, -E

grep imprime las líneas de su entrada que coinciden con un patrón. En el RHCSA lo usas constantemente: para encontrar un ajuste en un archivo de configuración, para extraer líneas de un log o para cumplir una tarea como 'guarda cada línea de /usr/share/dict/words que contenga la cadena ich en /root/lines'. El patrón es una expresión regular (regex), un pequeño lenguaje para describir texto.

Los caracteres básicos de las regex son pocos. ^ ancla la coincidencia al inicio de una línea y $ al final, así que ^root coincide con las líneas que empiezan con root y bash$ con las líneas que terminan en bash. Un punto . coincide con cualquier carácter individual. Un asterisco * significa 'cero o más del elemento anterior', así que a* coincide con nada, a, aa, etc., y .* coincide con cualquier secuencia de caracteres. Los corchetes enumeran un conjunto de caracteres permitidos: [0-9] es un dígito, [aeiou] una vocal y [^0-9] (con un acento circunflejo dentro de los corchetes) cualquier carácter que no sea un dígito.

grep '^root' /etc/passwd            # líneas que empiezan con root
grep -v '^#' /etc/ssh/sshd_config   # ocultar líneas de comentario
grep -v '^$' file                   # ocultar líneas vacías
grep -i 'error' /var/log/messages   # sin distinguir mayúsculas
grep -r 'PermitRootLogin' /etc/ssh  # buscar en un árbol de directorios
grep -E '^(root|student):' /etc/passwd

Cada una de las opciones de este tema hace un trabajo claro. -i ignora mayúsculas y minúsculas. -v invierte la coincidencia e imprime las líneas que no coinciden, lo que, combinado con ^# y ^$, es la forma clásica de ver solo las líneas activas de un archivo de configuración. -r busca recursivamente en todos los archivos bajo un directorio y antepone el nombre del archivo a cada resultado. Otras útiles son -n para números de línea, -c para contar las líneas que coinciden y -l para listar solo los nombres de los archivos que coinciden.

grep simple usa expresiones regulares básicas, en las que +, ?, |, { } y ( ) son caracteres normales a menos que pongas una barra invertida delante. grep -E cambia a expresiones regulares extendidas, donde esos caracteres son especiales sin barras invertidas: + significa uno o más, ? cero o uno, | alternativa, {3} exactamente tres y los paréntesis agrupan. Así, grep -E 'cat|dog' encuentra cualquiera de las dos palabras, mientras que grep 'cat|dog' simple busca el texto literal cat|dog.

Pon siempre el patrón entre comillas simples. Caracteres como *, $ y [ ] también son especiales para el shell, y sin comillas Bash puede expandirlos en nombres de archivo o valores de variables antes de que grep los vea. Para coincidir con un punto literal, escápalo: grep '\.conf$'.

Términos clave

Regular expression (expresión regular)
Un lenguaje de patrones para describir texto, usado por grep, sed, vim y muchas otras herramientas.
Anchor (ancla)
^ coincide con el inicio de una línea y $ con el final; coinciden con posiciones, no con caracteres.
Character class (clase de caracteres)
Una expresión entre corchetes como [a-z] que coincide con un carácter del conjunto listado; [^...] la niega.
-v
Opción de grep que imprime las líneas que NO coinciden con el patrón.
-E
Opción de grep que habilita las expresiones regulares extendidas, haciendo especiales + ? | {} y ().
Ejemplo real

Para revisar solo los ajustes activos de /etc/ssh/sshd_config, ejecutas grep -v -e '^#' -e '^$' /etc/ssh/sshd_config. Las líneas de comentario y en blanco desaparecen y puedes confirmar rápidamente si PasswordAuthentication está configurado.

Consejo para el examen: En una regex, * no significa 'cualquier cosa' como en un glob del shell; significa 'cero o más del carácter anterior'. La regex para 'cualquier cosa' es .* y los patrones van entre comillas simples.

Comprueba lo que sabes

¿Qué comando imprime las líneas de /etc/passwd que terminan en nologin?

grep 'nologin$' /etc/passwd, porque $ ancla la coincidencia al final de la línea.

¿Por qué grep 'a|b' file podría no encontrar nada cuando hay líneas que contienen a o b?

En las regex básicas | es literal; usa grep -E 'a|b' (o escápalo como \|) para obtener la alternativa.

¿Qué hace grep -v '^$'?

Elimina las líneas vacías, porque ^$ coincide con una línea sin nada entre el inicio y el final, y -v invierte la coincidencia.
