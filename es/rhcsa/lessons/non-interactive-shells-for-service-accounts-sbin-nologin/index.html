Shells no interactivos para cuentas de servicio (/sbin/nologin)

No todas las cuentas son para personas. Servicios como servidores web, bases de datos y tareas de respaldo se ejecutan con sus propios usuarios para que comprometer un servicio no entregue todo el sistema. Esas cuentas deben poseer archivos y ejecutar procesos, pero nadie debería poder iniciar sesión con ellas. Darles un shell no interactivo es la forma estándar de garantizarlo.

El shell es el último campo de la línea de una cuenta en /etc/passwd, y es el programa que se inicia cuando el usuario inicia sesión. Ponlo en /sbin/nologin y cualquier inicio de sesión interactivo, ya sea en la consola, por SSH o con su -, inicia nologin en su lugar. Ese programa imprime un mensaje corto, por defecto This account is currently not available, y termina. En RHEL, /sbin es un enlace a /usr/sbin, así que /usr/sbin/nologin es el mismo archivo.

useradd -r -s /sbin/nologin -c 'Backup service' backupsvc
usermod -s /sbin/nologin sarah       # cuenta existente
getent passwd sarah
# sarah:x:1003:1003::/home/sarah:/sbin/nologin
su - sarah
# This account is currently not available.

Entiende los límites. nologin bloquea los shells, no todo. Un usuario con /sbin/nologin todavía puede autenticarse en servicios que no inician un shell, como algunas configuraciones de FTP o correo, y root todavía puede ejecutar comandos como ese usuario con sudo -u o runuser. El reenvío de puertos por SSH podría seguir siendo posible según la configuración del servidor. Si una cuenta no debe autenticarse en absoluto, bloquéala o haz que caduque también.

Una herramienta relacionada es /bin/false, que simplemente termina con fallo y no imprime nada. También bloquea los inicios de sesión interactivos, pero en RHEL se prefiere nologin porque explica por qué falló el inicio de sesión. Las tareas del examen que dicen que el usuario no debe tener un shell interactivo esperan /sbin/nologin.

La lista de shells de inicio de sesión válidos está en /etc/shells. Algunos servicios, como ciertos servidores FTP, rechazan a los usuarios cuyo shell no aparece ahí, lo que conviene saber si una cuenta de servicio no puede autenticarse de forma inesperada. Puedes comprobar el shell de cualquier usuario con getent passwd user o mirando el último campo.

Términos clave

Service account (cuenta de servicio)
Una cuenta que usa un programa y no una persona, normalmente creada con useradd -r.
/sbin/nologin
Un shell que rechaza educadamente el inicio de sesión interactivo; se usa para bloquear los inicios de sesión de cuentas de servicio.
Login shell (shell de inicio de sesión)
El programa que se inicia cuando un usuario inicia sesión, guardado en el último campo de /etc/passwd.
/etc/shells
La lista de shells de inicio de sesión válidos del sistema.
Ejemplo real

La tarea: crear el usuario sarah como miembro de sysadmins sin shell interactivo. Ejecutas useradd -G sysadmins -s /sbin/nologin sarah y estableces su contraseña. su - sarah imprime This account is currently not available, lo que confirma el requisito.

Consejo para el examen: Sin shell interactivo en el examen significa -s /sbin/nologin. Bloquea los inicios de sesión con shell pero no la autenticación en sí, así que combínalo con el bloqueo cuando una cuenta deba quedar completamente deshabilitada.

Comprueba lo que sabes

¿Dónde se guarda el shell de inicio de sesión de un usuario?

En el séptimo (último) campo de la línea del usuario en /etc/passwd.

¿Cómo le das a un usuario existente un shell no interactivo?

usermod -s /sbin/nologin username.

¿Impide /sbin/nologin que root ejecute un comando como ese usuario?

No; root todavía puede usar sudo -u o runuser, porque nologin solo bloquea los inicios de sesión con shell interactivo.
