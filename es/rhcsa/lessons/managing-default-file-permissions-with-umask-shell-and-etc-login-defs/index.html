Red Hat Certified System Administrator EX200 (RHEL 10)

Gestionar los permisos predeterminados de los archivos con umask (shell y /etc/login.defs, ~/.bashrc)

Cuando un programa crea un archivo o directorio, pide un modo inicial: 666 (rw-rw-rw-) para los archivos regulares y 777 (rwxrwxrwx) para los directorios. Luego la umask (máscara de creación de archivos del usuario) quita bits de esa petición. Cada proceso tiene su propia umask, heredada de su padre, así que el valor establecido en tu shell controla los permisos de todo lo que creas desde él.

La umask enumera los bits que se quitan. Con umask 022, se quita la escritura al grupo y a los otros: los archivos nuevos obtienen 644 (rw-r--r--) y los directorios nuevos 755. Con umask 002, solo los otros pierden la escritura: archivos 664, directorios 775. Con umask 077, el grupo y los otros lo pierden todo: archivos 600, directorios 700. Los archivos nunca obtienen ejecución por la umask, porque los programas no la piden para los archivos regulares.

umask            # 0022
umask -S         # u=rwx,g=rx,o=rx
umask 027
touch f; mkdir d
ls -ld f d       # -rw-r----- f   drwxr-x--- d

Establecer umask 027 en el prompt afecta solo a ese shell y a sus hijos, y desaparece al cerrar la sesión. Para que sea persistente para un usuario, añade la línea umask a ~/.bashrc (que leen los shells interactivos) o a ~/.bash_profile (que se lee al iniciar sesión). Los cambios surten efecto en los shells nuevos.

En RHEL los valores predeterminados de todo el sistema vienen de varios lugares. /etc/login.defs tiene un ajuste UMASK, usado por ejemplo al crear directorios personales y aplicado al iniciar sesión por PAM (Pluggable Authentication Modules). Los archivos de inicio del shell como /etc/profile y /etc/bashrc también pueden establecerla, y el lugar más limpio para anularla a nivel de todo el sitio es un script en /etc/profile.d/. Los resultados típicos son 0022 para root y 0002 para los usuarios normales, lo que encaja con los grupos privados de usuario de RHEL, porque el grupo de un usuario solo lo contiene a él.

# /etc/profile.d/umask.sh  (todos los usuarios)
umask 027

# ~/.bashrc  (un usuario)
umask 077

Dos cosas que recordar. La umask nunca concede permisos; solo los quita, así que no puede hacer ejecutable un archivo. Y se aplica solo en la creación; los archivos existentes conservan sus modos, así que usa chmod para corregirlos. Algunos servicios, como las unidades de systemd con UMask=, establecen sus propios valores independientemente de tu shell.

Términos clave

umask
Una máscara por proceso de bits de permiso que se quitan a los archivos y directorios nuevos.
Default creation mode (modo de creación predeterminado)
El modo que piden los programas antes de aplicar la máscara: 666 para archivos y 777 para directorios.
~/.bashrc
Un archivo de inicio del shell por usuario donde se puede establecer una umask persistente para ese usuario.
/etc/profile.d/
Un directorio de scripts del shell que se ejecutan al iniciar sesión para todos los usuarios; un lugar limpio para ajustes de todo el sitio como la umask.
Ejemplo real

Los archivos nuevos del usuario daniel deben poder leerse solo por él. Añades umask 077 a /home/daniel/.bashrc. Después de que vuelva a iniciar sesión, touch report.txt crea -rw------- y mkdir notes crea drwx------.

Consejo para el examen: Resta la umask a 666 para los archivos y a 777 para los directorios. Con umask 027, los archivos quedan en 640 y los directorios en 750.

Comprueba lo que sabes

Con umask 007, ¿qué modos obtienen los archivos y directorios nuevos?

Archivos 660 (rw-rw----) y directorios 770 (rwxrwx---).

¿Dónde establecerías una umask persistente para un solo usuario?

En el ~/.bashrc o ~/.bash_profile de ese usuario.

¿Puede la umask hacer ejecutables los archivos regulares nuevos?

No; solo quita bits, y los programas piden 666 para los archivos, así que la ejecución nunca se establece por defecto.
