Red Hat Certified System Administrator EX200 (RHEL 10)

Configurar el firewall con firewall-cmd: zonas, servicios, puertos, orígenes, tiempo de ejecución vs. permanente

La lección de redes trató cómo abrir servicios y puertos. El objetivo de seguridad va más allá: usar zonas y direcciones de origen para controlar quién puede conectarse, y ser preciso con la configuración en tiempo de ejecución y la permanente. La meta es el mínimo privilegio, es decir, permitir solo lo que un servicio necesita y solo desde las redes que lo necesitan.

firewalld asigna cada paquete entrante a una zona. Si la dirección de origen del paquete coincide con un origen vinculado a una zona, se aplica esa zona. Si no, se aplica la zona de la interfaz de entrada, y si la interfaz no tiene ninguna, la zona predeterminada. Las zonas predefinidas van desde drop (descartar todo en silencio) y block (rechazar todo), pasando por public e internal, hasta trusted (permitir todo). Cada una tiene sus propios servicios y puertos.

Vincular una red de origen a una zona te permite tratar a ciertos clientes de forma distinta. Por ejemplo, permite SSH solo desde una red de administración poniendo esa red en la zona internal con ssh permitido, y quitando ssh de public.

firewall-cmd --permanent --zone=internal --add-source=10.0.5.0/24
firewall-cmd --permanent --zone=internal --add-service=ssh
firewall-cmd --permanent --zone=public --remove-service=ssh
firewall-cmd --reload
firewall-cmd --get-active-zones
firewall-cmd --zone=internal --list-all

Otros comandos de zonas: --set-default-zone=name cambia la predeterminada de inmediato y de forma permanente, --change-interface=enp1s0 --zone=internal mueve una interfaz (para las interfaces gestionadas por NetworkManager, el ajuste duradero es connection.zone de la conexión) y --list-all-zones lo muestra todo. Los servicios y puertos se añaden por zona con --add-service y --add-port=port/proto, y se quitan con las opciones --remove- correspondientes; --query-service=http responde yes o no.

Tiempo de ejecución frente a permanente es el concepto que más se evalúa. Los cambios en tiempo de ejecución se aplican ahora y desaparecen al recargar o reiniciar. Los cambios permanentes se guardan pero no se aplican hasta recargar. Ambos pueden desincronizarse; firewall-cmd --list-all muestra el tiempo de ejecución y firewall-cmd --permanent --list-all muestra la configuración guardada. Una forma segura de experimentar en remoto es hacer cambios en tiempo de ejecución, probar y luego --runtime-to-permanent. Si te quedas sin acceso por un cambio en tiempo de ejecución, una recarga o un reinicio restaura las reglas guardadas.

Cuando un servicio debe seguir siendo accesible después de reiniciar, la configuración permanente debe incluirlo. Compara siempre la salida de tiempo de ejecución y la permanente antes de terminar una tarea.

Términos clave

Source binding (vinculación de origen)
Asignar una dirección o red de origen a una zona para que los paquetes que vienen de ella usen las reglas de esa zona.
Default zone (zona predeterminada)
La zona usada para las interfaces y el tráfico no asignados a ninguna otra zona; public a menos que se cambie.
Runtime configuration (configuración en tiempo de ejecución)
Las reglas de firewall vigentes en este momento, que se pierden al recargar o reiniciar si no se guardan.
--runtime-to-permanent
Guarda la configuración actual del firewall en tiempo de ejecución como configuración permanente.
Ejemplo real

Solo la red de administración 192.168.50.0/24 puede usar la consola web en TCP 9090. Añades esa red como origen a la zona internal con cockpit permitido y quitas cockpit de public, todo con --permanent; recargas y lo confirmas con --get-active-zones y --zone=internal --list-all.

Consejo para el examen: Las vinculaciones de origen tienen prioridad sobre las zonas de interfaz. Compara firewall-cmd --list-all con --permanent --list-all para asegurarte de que tus reglas en tiempo de ejecución y guardadas coinciden.

Comprueba lo que sabes

¿Cómo elige firewalld una zona para un paquete entrante?

Primero una vinculación de origen que coincida, luego la zona de la interfaz de entrada y después la zona predeterminada.

¿Cómo guardas reglas en tiempo de ejecución que funcionan sin volver a escribirlas?

firewall-cmd --runtime-to-permanent.

¿Qué comando muestra las reglas guardadas de una zona, en lugar de las que están en ejecución?

firewall-cmd --permanent --zone=name --list-all.
