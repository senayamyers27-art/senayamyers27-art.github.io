Red Hat Certified System Administrator EX200 (RHEL 10)

Instalar, actualizar y eliminar paquetes RPM con dnf (install, remove, update, reinstall, history undo)

dnf es el gestor de paquetes de RHEL. Su trabajo es instalar software desde los repositorios configurados resolviendo las dependencias: si un paquete necesita bibliotecas u otros paquetes, dnf los encuentra y los instala también, y cuando eliminas algo, elimina los paquetes que dependen de él. Casi todas las tareas de servicios del RHCSA empiezan instalando un paquete, así que estos comandos deben volverse algo natural.

dnf install package instala uno o más paquetes, mostrando un resumen de la transacción y pidiendo confirmación; -y responde que sí automáticamente. También puedes instalar un archivo RPM local con dnf install ./file.rpm, y dnf traerá de los repositorios cualquier dependencia que falte, por eso se prefiere a rpm -i para archivos locales. dnf remove package desinstala un paquete más todo lo que dependa de él; lee el resumen antes de confirmar para no eliminar más de lo que pretendías.

dnf update (también escrito dnf upgrade) instala versiones más nuevas de todos los paquetes instalados, o de los que nombres: dnf update openssh-server. dnf check-update lista las actualizaciones disponibles sin instalarlas. Los paquetes del kernel son especiales: dnf instala el kernel nuevo junto a los anteriores en lugar de reemplazarlo, para que puedas arrancar un kernel anterior si el nuevo tiene problemas, y se conserva un número limitado de kernels.

dnf reinstall package reinstala la misma versión. Es la solución rápida cuando se borraron o dañaron archivos que pertenecen a un paquete, por ejemplo un binario eliminado o un archivo de configuración predeterminado estropeado en un laboratorio.

dnf install -y httpd mod_ssl
dnf remove -y telnet
dnf update -y
dnf reinstall -y openssh-server
dnf history               # listar transacciones anteriores
dnf history info 7        # qué cambió la transacción 7
dnf history undo 7        # revertirla

Cada transacción de dnf queda registrada. dnf history las lista con un ID, la línea de comandos, la fecha y el número de paquetes cambiados. dnf history info ID muestra exactamente qué paquetes se instalaron, actualizaron o eliminaron. dnf history undo ID revierte esa transacción concreta: los paquetes que instaló se eliminan y los que eliminó se reinstalan, siempre que las versiones necesarias sigan disponibles en un repositorio. dnf history rollback ID va más allá y deshace todas las transacciones posteriores a la indicada.

Hábitos de seguridad útiles: usa dnf list installed name o rpm -q name para confirmar un resultado, y --assumeno para ver qué haría un comando sin hacerlo. La mayoría de las tareas del examen solo exigen que el software quede instalado y funcionando, lo que a menudo también significa habilitar e iniciar su servicio.

Términos clave

dnf install
Instala paquetes y sus dependencias desde los repositorios habilitados o desde archivos RPM locales.
dnf remove
Desinstala paquetes junto con los paquetes que dependen de ellos.
dnf update
Actualiza los paquetes instalados a las versiones más nuevas disponibles; también se llama dnf upgrade.
dnf reinstall
Reinstala la versión actual de un paquete, restaurando sus archivos.
dnf history undo
Revierte los cambios hechos por una transacción de dnf registrada concreta.
Ejemplo real

En un laboratorio eliminaste por accidente un grupo de paquetes que se llevó varias herramientas. dnf history muestra la eliminación como la transacción 12; dnf history info 12 confirma la lista y dnf history undo 12 reinstala todo lo que eliminó.

Consejo para el examen: Prefiere dnf install ./file.rpm a rpm -i file.rpm para paquetes locales: dnf resuelve las dependencias desde los repositorios y registra el cambio en el historial de dnf.

Comprueba lo que sabes

¿Cómo restauras archivos borrados de un paquete instalado?

dnf reinstall package.

¿Qué hace dnf history undo 5?

Revierte la transacción 5: elimina lo que instaló y reinstala lo que eliminó, si esas versiones están disponibles.

¿Por qué dnf conserva los kernels anteriores después de una actualización?

Los kernels nuevos se instalan junto a los anteriores para que puedas arrancar un kernel previo si el nuevo falla.
