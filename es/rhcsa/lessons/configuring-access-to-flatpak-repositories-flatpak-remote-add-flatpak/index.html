Red Hat Certified System Administrator EX200 (RHEL 10)

Configurar el acceso a repositorios Flatpak: flatpak remote-add, flatpak remotes

Flatpak es una segunda forma de distribuir software en RHEL, orientada principalmente a aplicaciones de escritorio. Una aplicación Flatpak se empaqueta junto con un runtime, un conjunto compartido de bibliotecas sobre el que se ejecuta, y se ejecuta en un sandbox (entorno aislado) que limita a qué puede acceder en el host. Como las aplicaciones traen su propio runtime, se pueden actualizar de forma independiente de los paquetes RPM del sistema operativo. Los objetivos actuales del EX200 incluyen configurar repositorios Flatpak y gestionar aplicaciones Flatpak.

Los repositorios Flatpak se llaman remotes. Un remote es una fuente con nombre de aplicaciones y runtimes, muy parecido a un repositorio de dnf, pero se configura con el comando flatpak en lugar de un archivo .repo. Los remotes se pueden añadir a nivel de sistema, disponibles para todos los usuarios y guardados en /var/lib/flatpak, que es lo predeterminado (requiere root o autorización de administrador), o por usuario con --user, guardados en ~/.local/share/flatpak. Asegúrate primero de que el propio paquete flatpak esté instalado (dnf install flatpak).

flatpak remote-add añade un remote. Le das un nombre y una ubicación, que normalmente es un archivo .flatpakrepo: un pequeño descriptor que contiene la URL del repositorio, el título y la clave GPG usada para verificar su contenido. --if-not-exists hace que el comando termine con éxito sin avisar si el remote ya existe, lo que es útil en scripts y al repetir una tarea.

flatpak remote-add --if-not-exists myremote /path/or/url/to/myremote.flatpakrepo
flatpak remotes                 # listar los remotes configurados
flatpak remotes --show-details  # incluir URLs y opciones
flatpak remote-ls myremote      # lo que ofrece el remote
flatpak remote-modify --disable myremote
flatpak remote-delete myremote

flatpak remotes lista los remotes configurados con su nombre y opciones como system o user; --show-details añade títulos y URLs. flatpak remote-ls NAME lista las aplicaciones y runtimes disponibles en un remote, que es el equivalente en Flatpak de comprobar que un repositorio funciona. remote-modify cambia los ajustes de un remote existente, por ejemplo deshabilitarlo, y remote-delete lo elimina.

Las firmas importan aquí igual que con RPM. Un archivo .flatpakrepo normalmente incluye la clave GPG, así que el contenido se verifica automáticamente. Si añades un remote directamente por URL sin clave, puede que tengas que proporcionarla con --gpg-import=keyfile; deshabilitar la verificación con --no-gpg-verify solo debe hacerse en un laboratorio controlado y solo si una tarea lo permite explícitamente. En el examen, usa exactamente el nombre y la ubicación del remote que especifica la tarea, ya que los evaluadores revisan el nombre con flatpak remotes.

Términos clave

Flatpak
Un sistema para distribuir aplicaciones aisladas en un sandbox que incluyen sus propios runtimes, independiente de los paquetes RPM.
Remote (repositorio remoto)
Un repositorio Flatpak con nombre desde el que se instalan aplicaciones y runtimes.
Runtime (entorno de ejecución)
Un conjunto compartido de bibliotecas y servicios sobre el que se ejecutan las aplicaciones Flatpak.
.flatpakrepo file (archivo .flatpakrepo)
Un descriptor que contiene la URL, el título y la clave GPG de un remote, usado con flatpak remote-add.
System vs user installation (instalación de sistema vs. de usuario)
Los remotes y apps de sistema se comparten entre todos los usuarios (/var/lib/flatpak); los de --user viven en el directorio personal del usuario.
Ejemplo real

Una tarea pide un remote Flatpak a nivel de sistema llamado examplerepo usando el archivo .flatpakrepo proporcionado en el servidor del aula. Como root ejecutas flatpak remote-add --if-not-exists examplerepo con esa ubicación; luego flatpak remotes muestra examplerepo con la opción system y flatpak remote-ls examplerepo lista sus aplicaciones.

Consejo para el examen: Revisa si la tarea quiere un remote a nivel de sistema (ejecutado como root, lo predeterminado) o uno por usuario (--user). El nombre del remote que elijas debe coincidir exactamente con la tarea.

Comprueba lo que sabes

¿Qué comando lista los remotes Flatpak configurados en un sistema?

flatpak remotes (añade --show-details para ver las URLs).

¿Qué hace --if-not-exists en flatpak remote-add?

Hace que el comando termine con éxito sin error cuando ya existe un remote con ese nombre.

¿Dónde se guardan los remotes y aplicaciones Flatpak a nivel de sistema?

En /var/lib/flatpak; los de cada usuario están en ~/.local/share/flatpak.
