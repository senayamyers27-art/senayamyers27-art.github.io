Establecer el target de arranque predeterminado (systemctl get-default, set-default)

Un target de systemd es un grupo con nombre de unidades que representa un estado del sistema. Sustituye a los antiguos runlevels numerados. Al arrancar, systemd inicia el target predeterminado y todo aquello de lo que depende. Los dos targets que establecerás con más frecuencia son multi-user.target, un sistema completo con red y servicios pero solo con consola de texto, y graphical.target, que añade un inicio de sesión gráfico encima de multi-user.

systemctl get-default imprime el predeterminado actual. systemctl set-default multi-user.target lo cambia. Por debajo, el predeterminado es un enlace simbólico, /etc/systemd/system/default.target, que apunta al target elegido, y set-default simplemente reemplaza ese enlace. El cambio se aplica en el siguiente arranque.

systemctl get-default
systemctl set-default multi-user.target
# Created symlink /etc/systemd/system/default.target -> .../multi-user.target
systemctl isolate multi-user.target   # cambiar ahora, sin reiniciar

Para cambiar el estado actual de inmediato, usa systemctl isolate target, que inicia las unidades de ese target y detiene todo lo que no necesita. Solo los targets marcados como aislables se pueden usar así. Cambiar de graphical a multi-user con isolate termina la sesión gráfica, así que hazlo desde una consola o una sesión SSH que no te importe perder.

Otros targets son importantes para la recuperación. rescue.target da un shell de root monousuario con los sistemas de archivos locales montados pero sin red; emergency.target da un shell todavía más mínimo con el sistema de archivos raíz en solo lectura. Puedes elegir uno para un solo arranque editando la línea del kernel en el menú de GRUB (presiona e) y añadiendo systemd.unit=rescue.target, y luego Ctrl+X para arrancar. Esto no cambia el predeterminado.

Los nombres antiguos de runlevel siguen existiendo como alias, como runlevel3.target para multi-user y runlevel5.target para graphical, y puedes verlos en documentación antigua. Usa los nombres reales de los targets en el examen. Después de establecer un predeterminado, verifícalo con get-default; los evaluadores suelen revisar exactamente esa salida.

Términos clave

Target
Una unidad de systemd que agrupa otras unidades para definir un estado del sistema, en sustitución de los runlevels.
multi-user.target
Un estado del sistema completo sin gráficos, con red y servicios; el predeterminado habitual en servidores.
graphical.target
multi-user.target más un gestor de inicio de sesión gráfico.
isolate
Un comando de systemctl que cambia el sistema en ejecución a un target, deteniendo las unidades que este no necesita.
Ejemplo real

Un servidor arranca en un inicio de sesión gráfico y desperdicia memoria. Ejecutas systemctl set-default multi-user.target, compruebas que get-default imprime multi-user.target y, opcionalmente, ejecutas systemctl isolate multi-user.target para cambiar ahora en lugar de esperar al siguiente reinicio.

Consejo para el examen: set-default cambia solo el siguiente arranque; isolate cambia solo el estado actual. Una tarea que dice que el sistema debe arrancar en una consola de texto necesita set-default.

Comprueba lo que sabes

¿Qué archivo cambia systemctl set-default?

Reemplaza el enlace simbólico /etc/systemd/system/default.target para que apunte al target elegido.

¿Cómo arrancas una vez en rescue.target sin cambiar el predeterminado?

Edita la línea del kernel en el menú de GRUB, añade systemd.unit=rescue.target y arranca con Ctrl+X.

¿Cuál es la diferencia entre multi-user.target y graphical.target?

graphical.target incluye todo lo de multi-user.target más un gestor de pantalla gráfico para iniciar sesión.
