Restaurar los contextos de archivo predeterminados (restorecon -Rv) y añadir reglas con semanage fcontext

SELinux mantiene una base de datos de la política con la etiqueta que debe tener cada ruta, escrita como expresiones regulares como /var/www(/.*)? asociadas a httpd_sys_content_t. La etiqueta real se guarda en cada archivo. Cuando ambas no coinciden, la solución es restablecer el archivo a lo que dice la política. Cuando la propia política no tiene ninguna regla para tu ruta personalizada, primero añades una.

restorecon devuelve los archivos a la etiqueta que espera la política. -R actúa recursivamente y -v imprime cada cambio, para que veas qué estaba mal. restorecon -Rv /var/www/html corrige los archivos movidos ahí desde directorios personales. Es seguro ejecutarlo repetidamente, ya que solo cambia las etiquetas que difieren de la política. restorecon -Rnv muestra lo que cambiaría sin cambiar nada.

restorecon -Rv /var/www/html
# Relabeled /var/www/html/page.html from ...admin_home_t:s0 to ...httpd_sys_content_t:s0

Las ubicaciones personalizadas necesitan una regla. Si sirves contenido web desde /web, la etiqueta predeterminada de la política para esa ruta es default_t, que httpd no puede leer, y restorecon simplemente volvería a poner default_t. Añade una regla con semanage fcontext -a -t type 'regex' y luego aplícala con restorecon. La expresión regular '/web(/.*)?' coincide con el directorio y todo lo que contiene; ponla entre comillas para que el shell no la expanda.

semanage fcontext -a -t httpd_sys_content_t '/web(/.*)?'
restorecon -Rv /web
ls -dZ /web
semanage fcontext -l -C        # listar las personalizaciones locales

semanage fcontext -l lista todas las reglas, y puedes filtrarlo con grep buscando una ruta existente parecida para encontrar el tipo correcto, por ejemplo semanage fcontext -l | grep '/var/www'. -d borra una regla local y -m modifica una. semanage viene del paquete policycoreutils-python-utils, que puede que tengas que instalar. Como la regla se guarda en la política, sobrevive a los reinicios y a los reetiquetados completos.

Compáralo con chcon, que cambia directamente la etiqueta de un archivo, por ejemplo chcon -t httpd_sys_content_t /web/index.html. Funciona de inmediato pero es temporal, en el sentido de que restorecon o un reetiquetado lo deshacen, ya que la política sigue diciendo otra cosa. En el examen, usa semanage fcontext más restorecon para todo lo que deba persistir.

Dos trucos relacionados: touch /.autorelabel y un reinicio reetiquetan todo el sistema de archivos, y restorecon es la solución correcta después de colocar claves SSH o archivos de configuración con mv.

Términos clave

restorecon
Restablece las etiquetas de SELinux de los archivos a los valores definidos en la política; -R actúa recursivamente y -v informa de los cambios.
semanage fcontext
Añade, modifica, borra o lista las reglas de la política que asocian patrones de ruta con tipos de archivo.
chcon
Cambia directamente la etiqueta de un archivo; el cambio se pierde con restorecon o un reetiquetado.
(/.*)?
El sufijo de expresión regular que, en las reglas de fcontext, coincide con un directorio y todo lo que hay debajo.
Ejemplo real

Apache debe servir contenido desde /srv/site. Ejecutas semanage fcontext -a -t httpd_sys_content_t '/srv/site(/.*)?' y luego restorecon -Rv /srv/site, que reetiqueta todos los archivos. Tras probar un reetiquetado completo con touch /.autorelabel y un reinicio, ls -Z sigue mostrando httpd_sys_content_t porque la regla está en la política.

Consejo para el examen: semanage fcontext solo registra la regla; no cambia ningún archivo. Síguelo siempre de restorecon -Rv sobre la ruta, y prefiere esta pareja a chcon para que el cambio persista.

Comprueba lo que sabes

Añadiste una regla con semanage fcontext pero ls -Z muestra la etiqueta anterior. ¿Qué olvidaste?

Ejecutar restorecon -Rv sobre la ruta para aplicar la regla a los archivos existentes.

¿Por qué chcon no es una solución persistente?

Solo cambia la etiqueta en el archivo; restorecon o un reetiquetado la restablecen a lo que dice la política.

¿Con qué coincide el patrón '/data(/.*)?'?

Con el propio directorio /data y todo lo que hay debajo.
