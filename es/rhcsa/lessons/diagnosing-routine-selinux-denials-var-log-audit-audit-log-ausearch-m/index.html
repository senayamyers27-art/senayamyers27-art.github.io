Red Hat Certified System Administrator EX200 (RHEL 10)

Diagnosticar denegaciones rutinarias de SELinux: /var/log/audit/audit.log, ausearch -m AVC, sealert

Cuando SELinux bloquea algo, la aplicación normalmente solo informa un error vago como permission denied o 403 Forbidden. La explicación real está en el log de auditoría. Resolver problemas de SELinux es una rutina: confirmar que SELinux está implicado, encontrar la denegación, entender qué etiqueta, puerto o booleano está mal y corregir esa cosa concreta.

Las denegaciones las registra el demonio de auditoría, auditd, en /var/log/audit/audit.log como mensajes AVC (access vector cache). Cada uno nombra el permiso denegado, como read, open o name_bind, el proceso con su contexto de origen (scontext), el destino con su contexto (tcontext) y la clase de objeto (tclass), como file, dir o tcp_socket.

type=AVC msg=audit(...): avc:  denied  { read } for  pid=2143
  comm="httpd" name="index.html" dev="vda1" ino=12345
  scontext=system_u:system_r:httpd_t:s0
  tcontext=unconfined_u:object_r:admin_home_t:s0 tclass=file

Léelo así: al proceso httpd, de tipo httpd_t, se le denegó la lectura de un archivo etiquetado como admin_home_t. Los servidores web pueden leer httpd_sys_content_t, así que la etiqueta del archivo está mal, y restorecon o una regla de semanage fcontext lo corrige. Una denegación name_bind sobre un tcp_socket apunta a una etiqueta de puerto, y una denegación de una acción legítima pero opcional suele apuntar a un booleano.

ausearch busca en el log de auditoría sin tener que recorrerlo entero. ausearch -m AVC -ts recent muestra los mensajes AVC de los últimos diez minutos, -ts today los de hoy y -c httpd filtra por nombre de comando. Añade -i para interpretar los valores numéricos como nombres legibles.

sealert, del paquete setroubleshoot-server, va más allá. Cuando está instalado, el servicio setroubleshoot escribe un resumen de una línea en el journal, y sealert -l id imprime una explicación completa, incluidas las causas probables y los comandos sugeridos, como la línea exacta de semanage fcontext, semanage port o setsebool. sealert -a /var/log/audit/audit.log analiza todo el log. Busca en el journal con journalctl | grep sealert o busca el texto SELinux is preventing.

ausearch -m AVC -ts recent -i
journalctl -t setroubleshoot --since '10 min ago'
sealert -l 3e4f...   # id del mensaje del journal

Dos precauciones. Si no hay ningún AVC pero sospechas de SELinux, usa brevemente setenforce 0 y vuelve a intentarlo; si entonces funciona, SELinux está implicado, posiblemente mediante una regla que no registra nada (una regla dontaudit), y debes volver a enforcing de inmediato. Y lee con sentido crítico las sugerencias de sealert: su consejo de último recurso de construir un módulo personalizado con audit2allow casi nunca es correcto en las tareas del examen, donde la respuesta es una etiqueta, un tipo de puerto o un booleano correctos.

Términos clave

AVC denial (denegación AVC)
Un registro del log de auditoría de un acceso bloqueado por SELinux, que nombra el permiso, el contexto de origen, el contexto de destino y la clase.
auditd
El demonio de auditoría que escribe las denegaciones de SELinux y otros eventos en /var/log/audit/audit.log.
ausearch
Busca en el log de auditoría por tipo de mensaje, hora y comando; -m AVC selecciona las denegaciones de SELinux.
sealert
Una herramienta de setroubleshoot que explica las denegaciones en lenguaje sencillo y sugiere soluciones.
Ejemplo real

Apache devuelve 403 para un sitio nuevo en /srv/site. ausearch -m AVC -ts recent muestra que a httpd_t se le denegó la lectura de archivos con tcontext default_t. sealert sugiere semanage fcontext -a -t httpd_sys_content_t '/srv/site(/.*)?' seguido de restorecon. Lo aplicas, y el sitio carga con SELinux todavía en enforcing.

Consejo para el examen: Lee el tcontext de la denegación: un tipo de archivo equivocado significa restorecon o semanage fcontext, name_bind significa semanage port y un comportamiento opcional significa un booleano. Nunca dejes SELinux en permissive como solución.

Comprueba lo que sabes

¿Qué comando muestra las denegaciones de SELinux de los últimos minutos?

ausearch -m AVC -ts recent.

En un mensaje AVC, ¿qué representan scontext y tcontext?

scontext es el contexto del proceso que intenta el acceso; tcontext es el contexto del archivo, puerto u otro objeto de destino.

No aparece ningún AVC, pero cambiar a permissive hace que el problema desaparezca. ¿Qué podría explicarlo?

Una regla dontaudit está denegando el acceso en silencio, así que SELinux sigue siendo la causa aunque no se registre nada.
