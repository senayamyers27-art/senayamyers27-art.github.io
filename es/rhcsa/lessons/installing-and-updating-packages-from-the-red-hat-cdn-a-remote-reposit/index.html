Red Hat Certified System Administrator EX200 (RHEL 10)

Instalar y actualizar paquetes desde la CDN de Red Hat, un repositorio remoto o el sistema de archivos local

RHEL instala software como paquetes RPM (RPM Package Manager), gestionados con dnf. dnf lee repositorios, que son colecciones de paquetes más metadatos, resuelve las dependencias e instala todo lo necesario. Los repositorios pueden venir de la CDN (content delivery network) de Red Hat después del registro, de un servidor remoto que gestiona tu organización o de medios locales como el DVD de instalación.

Comandos de uso diario: dnf install httpd, dnf remove httpd, dnf update (o dnf upgrade) para todas las actualizaciones, dnf update kernel para un solo paquete, dnf search keyword, dnf info pkg, dnf provides /usr/sbin/semanage para encontrar qué paquete contiene un archivo y dnf list installed. dnf repolist muestra los repositorios habilitados y dnf repolist all también los deshabilitados. Los grupos instalan conjuntos relacionados: dnf group list y dnf group install 'Server'.

En un sistema RHEL registrado, los repositorios de la CDN, normalmente BaseOS y AppStream, los configura automáticamente subscription-manager en /etc/yum.repos.d/redhat.repo. BaseOS contiene el núcleo del sistema operativo y AppStream contiene aplicaciones, lenguajes y bases de datos.

Los sistemas del examen a menudo no tienen acceso a la CDN, y se te indica que uses un repositorio en una URL dada. Crea un archivo que termine en .repo en /etc/yum.repos.d/. Cada sección tiene un ID entre corchetes, un name, un baseurl, enabled=1 y ajustes de GPG (GNU Privacy Guard). Con gpgcheck=1 también das gpgkey= apuntando a la clave del proveedor; pon gpgcheck=0 solo si la tarea lo dice.

# /etc/yum.repos.d/local.repo
[BaseOS-local]
name=BaseOS from DVD
baseurl=file:///mnt/dvd/BaseOS
enabled=1
gpgcheck=0

[AppStream-local]
name=AppStream from DVD
baseurl=file:///mnt/dvd/AppStream
enabled=1
gpgcheck=0

Para un repositorio remoto, el baseurl simplemente usa la dirección web que te dieron en lugar de file:///. dnf config-manager --add-repo con esa dirección puede generarte un archivo básico; revísalo y edítalo después. Para el DVD, monta la ISO (mount -o loop rhel.iso /mnt/dvd) y añade una línea a fstab si debe sobrevivir al reinicio. Ejecuta dnf clean all y dnf repolist para confirmar que dnf ve los nuevos repositorios.

Un archivo de paquete individual que ya está en disco se instala con dnf install ./package.rpm, que aun así trae las dependencias de los repositorios habilitados. La herramienta de bajo nivel rpm consulta lo que está instalado: rpm -qa lista todo, rpm -qi pkg muestra detalles, rpm -ql pkg lista los archivos y rpm -qf /path nombra el paquete dueño. Evita rpm -i para instalar porque no resuelve las dependencias.

Términos clave

dnf
El gestor de paquetes de RHEL que instala, actualiza y elimina paquetes RPM y resuelve las dependencias desde los repositorios.
.repo file (archivo .repo)
Un archivo en /etc/yum.repos.d/ que define repositorios con un ID, name, baseurl y los ajustes enabled y gpgcheck.
BaseOS and AppStream
Los dos repositorios principales de RHEL: paquetes del núcleo del sistema operativo, y aplicaciones y entornos de ejecución.
GPG check (verificación GPG)
La verificación de la firma de un paquete contra una clave de confianza antes de instalarlo.
Ejemplo real

El examen te da dos direcciones de repositorio para BaseOS y AppStream. Creas /etc/yum.repos.d/exam.repo con dos secciones, cada una con un baseurl, enabled=1 y gpgcheck=0 según las instrucciones; luego dnf repolist lista ambas y dnf install -y httpd funciona.

Consejo para el examen: Un archivo .repo debe terminar en .repo y cada sección necesita un ID único entre corchetes y un baseurl. Un error de escritura ahí hace fallar todas las tareas de instalación posteriores, así que confírmalo con dnf repolist de inmediato.

Comprueba lo que sabes

¿Cómo encuentras qué paquete proporciona el comando semanage?

dnf provides semanage (o la ruta completa /usr/sbin/semanage).

¿Qué forma de baseurl apunta a un DVD montado localmente?

file:/// seguido de la ruta, como file:///mnt/dvd/BaseOS.

¿Por qué usar dnf install ./pkg.rpm en lugar de rpm -i pkg.rpm?

dnf resuelve e instala las dependencias desde los repositorios habilitados, mientras que rpm -i falla si faltan dependencias.
