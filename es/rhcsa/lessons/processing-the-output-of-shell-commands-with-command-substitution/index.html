Procesar la salida de comandos del shell con la sustitución de comandos $( )

La sustitución de comandos ejecuta un comando y coloca su salida en tu línea de comandos o en una variable. Así es como un script conoce datos del sistema, como el nombre del host, la fecha de hoy, el número de líneas de un archivo o la dirección IP de una interfaz, y luego los usa en mensajes, nombres de archivo o pruebas.

La sintaxis es $(command). El shell ejecuta el comando en un subshell, captura su salida estándar, elimina los saltos de línea finales y sustituye el resultado en su lugar. today=$(date +%F) guarda algo como 2026-09-25 en una variable, y echo "Kernel: $(uname -r)" inserta la salida directamente en un mensaje. La forma más antigua, que encierra el comando entre comillas invertidas (backquotes), hace lo mismo pero es más difícil de leer y de anidar, así que prefiere $( ).

#!/bin/bash
host=$(hostname -s)
users=$(who | wc -l)
rootuse=$(df --output=pcent / | tail -1 | tr -d ' %')
echo "$host has $users login(s); / is ${rootuse}% full"
if [ "$rootuse" -gt 90 ]; then
    echo "WARNING: root file system almost full" >&2
fi
tar -czf /backup/etc-$(date +%F).tar.gz /etc

A menudo debes recortar la salida de un comando hasta dejar exactamente el valor que necesitas, y una tubería dentro de la sustitución lo hace. cut selecciona campos (cut -d: -f1 /etc/passwd da los nombres de usuario), awk '{print $2}' imprime una columna separada por espacios en blanco, tr borra o traduce caracteres, head y tail eligen líneas y grep las filtra. Prueba primero la tubería en el prompt y solo después envuélvela en $( ).

Solo se captura stdout. Los mensajes de error siguen yendo a la terminal, así que añade 2>/dev/null dentro de los paréntesis si quieres silenciarlos. El código de salida del comando queda disponible después en $?, lo que te permite escribir out=$(some_cmd) || echo 'failed'.

Las comillas también importan aquí. Cuando uses una sustitución como argumento, ponla entre comillas dobles, "$(command)", para mantener su salida como una sola palabra; sin comillas, el resultado se divide por los espacios en blanco y se expanden los caracteres glob que contenga. La excepción es cuando quieres deliberadamente la división en palabras, como en for u in $(cut -d: -f1 /etc/passwd), que da una iteración del bucle por cada nombre de usuario.

Las sustituciones se anidan sin problema: echo "Config owned by $(rpm -qf $(which sshd))" encuentra el binario de sshd y luego el paquete que es su dueño.

Términos clave

Command substitution (sustitución de comandos)
$(command): se reemplaza a sí misma con la salida estándar del comando.
Backticks (comillas invertidas)
La forma antigua command de la sustitución de comandos; equivalente pero más difícil de anidar.
cut
Extrae campos o rangos de caracteres de cada línea, p. ej. cut -d: -f1.
awk '{print $N}'
Imprime el campo N, separado por espacios en blanco, de cada línea.
Subshell
Una copia hija del shell en la que se ejecuta el comando sustituido.
Ejemplo real

Una tarea pide un script que guarde la lista de usuarios con UID 1000 o superior en un archivo con el nombre del host. Calculas file=/root/users-$(hostname -s).txt y lo llenas con awk -F: '$3 >= 1000 {print $1}' /etc/passwd > "$file".

Consejo para el examen: $( ) captura solo stdout y elimina los saltos de línea finales. Ponlo entre comillas ("$(cmd)") a menos que quieras intencionalmente que la salida se divida en palabras separadas.

Comprueba lo que sabes

¿Cómo guardas la fecha actual como AAAA-MM-DD en una variable?

d=$(date +%F).

¿$(command) captura los mensajes de error?

No, solo la salida estándar; redirige 2>&1 dentro de los paréntesis para incluirlos.

¿Por qué preferir $( ) a las comillas invertidas?

Es más fácil de leer y se anida sin necesidad de escapar.
