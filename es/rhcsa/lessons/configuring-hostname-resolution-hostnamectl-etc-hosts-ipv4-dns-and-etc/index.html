Red Hat Certified System Administrator EX200 (RHEL 10)

Configurar la resolución de nombres de host: hostnamectl, /etc/hosts, ipv4.dns y /etc/resolv.conf

Este objetivo abarca dos trabajos relacionados: darle a la máquina su propio nombre y hacer que pueda convertir nombres en direcciones. Ambos son tareas rutinarias del examen, y un sistema que no puede resolver nombres hará fallar tareas posteriores como los montajes NFS, la sincronización de la hora y los repositorios.

El nombre de host estático se guarda en /etc/hostname y se establece con hostnamectl set-hostname server1.example.com, que actualiza el archivo y el sistema en ejecución a la vez, así que no hace falta reiniciar. Ejecuta hostnamectl o hostname para comprobarlo. Usa el nombre de dominio completo (FQDN, fully qualified domain name) cuando la tarea te dé uno.

La resolución de nombres usa las fuentes listadas en la línea hosts: de /etc/nsswitch.conf, normalmente primero files y luego dns. files significa /etc/hosts, una lista sencilla de direcciones seguidas de nombres y alias. Las entradas ahí surten efecto de inmediato y tienen prioridad sobre DNS para esos nombres, lo que resulta práctico en laboratorios e instalaciones pequeñas.

# /etc/hosts
127.0.0.1      localhost localhost.localdomain
192.168.10.20  server1.example.com server1
192.168.10.30  server2.example.com server2

Los servidores DNS (Domain Name System) se listan en /etc/resolv.conf como líneas nameserver, y search lista los dominios que se añaden a los nombres cortos. En RHEL, NetworkManager escribe este archivo a partir de las conexiones activas, así que las ediciones manuales se sobrescriben cuando se activa una conexión. Configura el DNS en la conexión.

nmcli con mod static1 ipv4.dns '192.168.10.1 192.168.10.2'
nmcli con mod static1 ipv4.dns-search example.com
nmcli con mod static1 ipv4.ignore-auto-dns yes   # con DHCP, usar solo estos
nmcli con up static1
cat /etc/resolv.conf

Con DHCP, el servidor normalmente también proporciona servidores DNS; ipv4.ignore-auto-dns yes hace que el perfil use solo los servidores que listaste. Usa +ipv4.dns para añadir un servidor a la lista existente. Después de cualquier cambio, prueba con getent hosts name, que usa el mismo orden de búsqueda que las aplicaciones, incluido /etc/hosts.

Términos clave

hostnamectl
La herramienta que muestra y establece el nombre de host del sistema, escribiendo el nombre estático en /etc/hostname.
/etc/hosts
Un archivo local de asociaciones de direcciones a nombres que por defecto se consulta antes que DNS.
/etc/resolv.conf
El archivo del resolvedor que lista los nameserver y los dominios de búsqueda, generado por NetworkManager en RHEL.
ipv4.dns
La propiedad de conexión de NetworkManager que contiene las direcciones de los servidores DNS de ese perfil.
Ejemplo real

Estableces el nombre de host con hostnamectl set-hostname servera.lab.example.com, luego añades el DNS 172.25.250.254 con nmcli con mod en la conexión activa y la reactivas. Ahora /etc/resolv.conf lista ese nameserver, y getent hosts classroom.lab.example.com devuelve una dirección.

Consejo para el examen: No arregles el DNS editando /etc/resolv.conf directamente en RHEL; NetworkManager lo reescribe. Establece ipv4.dns en la conexión y actívala de nuevo.

Comprueba lo que sabes

¿Qué comando establece el nombre de host de forma permanente sin reiniciar?

hostnamectl set-hostname name.

¿Qué archivo decide si /etc/hosts se revisa antes que DNS?

/etc/nsswitch.conf, en su línea hosts:.

¿Por qué desaparecen tus ediciones manuales de /etc/resolv.conf?

NetworkManager lo regenera a partir de los ajustes DNS de las conexiones; configura ipv4.dns con nmcli.
