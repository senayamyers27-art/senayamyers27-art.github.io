Campos de /etc/fstab: dispositivo, punto de montaje, tipo, opciones, dump, orden de fsck

/etc/fstab (file system table) lista los sistemas de archivos que se montan al arrancar. Cada línea que no es un comentario tiene seis campos separados por espacios o tabulaciones. Editarás este archivo en casi todas las tareas de almacenamiento del RHCSA, así que aprende los campos en orden hasta que puedas escribir una línea sin mirar.

# dispositivo             punto montaje tipo opciones          dump fsck
UUID=5b2e...c7            /data        xfs   defaults          0    0
LABEL=logs                /logs        ext4  defaults,noatime  0    2
/dev/vg1/lvapp            /app         xfs   defaults          0    0
UUID=3f1c...9a2e          none         swap  defaults          0    0
server1:/export/share     /mnt/share   nfs   defaults,_netdev  0    0

El campo 1 es el dispositivo: UUID=, LABEL=, la ruta de un volumen lógico como /dev/vg1/lvapp (estable porque los nombres de LVM persisten) o host:/path para NFS (Network File System). Evita los nombres en bruto como /dev/vdb1 para los discos. El campo 2 es el punto de montaje, un directorio absoluto existente, o none para swap. El campo 3 es el tipo: xfs, ext4, vfat, swap, nfs, etc.

El campo 4 contiene opciones separadas por comas y sin espacios. defaults significa rw, suid, dev, exec, auto, nouser y async. Extras útiles: ro (solo lectura), noexec, nosuid, noauto (no montar al arrancar), nofail (el arranque continúa si falta el dispositivo), _netdev (esperar a la red) y, para vfat, uid=, gid= y umask=.

El campo 5 es el indicador dump, usado por la antigua herramienta de respaldo dump; ponlo en 0. El campo 6 es el orden de fsck: 0 significa no revisar nunca al arrancar, 1 es para el sistema de archivos raíz y 2 para otros sistemas de archivos que se revisan después de la raíz. XFS no usa fsck al arrancar, así que las líneas XFS normalmente usan 0, igual que el swap y los sistemas de archivos de red. Los sistemas de archivos de datos ext4 suelen usar 2.

Flujo de trabajo: obtén el UUID con blkid o lsblk -f, crea el punto de montaje con mkdir -p, añade la línea, ejecuta systemctl daemon-reload y luego mount -a y findmnt --verify. Un truco para ir más rápido: blkid /dev/vdb1 >> /etc/fstab añade el UUID al final para que lo edites hasta darle forma en lugar de volver a escribirlo, pero limpia con cuidado el texto sobrante.

El orden importa en los montajes anidados: una línea para /data/archive debe ir después de la línea de /data. Los campos se separan por espacios en blanco, así que un espacio dentro de la lista de opciones rompe toda la línea.

Términos clave

/etc/fstab
El archivo que lista los sistemas de archivos y el swap que se montan o activan al arrancar, cada uno en una línea de seis campos.
defaults
El conjunto de opciones rw, suid, dev, exec, auto, nouser y async.
fsck order (orden de fsck)
El sexto campo de fstab: 0 omite la revisión, 1 es la raíz y 2 los demás sistemas de archivos revisados después de la raíz.
nofail
Una opción de fstab que permite que el arranque continúe si el dispositivo no está presente.
Ejemplo real

Necesitas que /dev/vgdata/lvweb (XFS) se monte en solo lectura en /srv/web al arrancar. Añades la línea /dev/vgdata/lvweb /srv/web xfs ro 0 0, ejecutas systemctl daemon-reload y mount -a, y findmnt /srv/web muestra la columna de opciones empezando por ro.

Consejo para el examen: Las preguntas del examen suelen pedir qué significan el quinto y el sexto campo. Dump es heredado y se pone en 0; el orden de fsck es 1 para la raíz, 2 para los demás y 0 para XFS, swap y los montajes de red.

¿Por qué las líneas XFS suelen terminar en 0 0?

El indicador dump no se usa, y fsck no revisa XFS al arrancar (se repara mediante su journal y xfs_repair), así que el orden de fsck es 0.

¿Qué hace noauto?

Impide que el sistema de archivos se monte al arrancar o con mount -a; solo se monta cuando se pide explícitamente.
