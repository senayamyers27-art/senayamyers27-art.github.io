Red Hat Certified System Administrator EX200 (RHEL 10)

Configurar clientes del servicio de hora con chronyd (/etc/chrony.conf, chronyc sources) y timedatectl

La hora exacta importa más de lo que parece. Los logs de distintos sistemas deben coincidir al resolver problemas, Kerberos y muchas comprobaciones de TLS (Transport Layer Security) fallan cuando los relojes se desfasan, y las tareas programadas se ejecutan en el momento equivocado. RHEL mantiene la hora con chrony, una implementación de NTP (Network Time Protocol). El demonio es chronyd, se configura en /etc/chrony.conf y se consulta con chronyc.

La configuración nombra las fuentes de hora. Una línea server nombra un servidor NTP; una línea pool nombra un nombre DNS (Domain Name System) que se resuelve en varios servidores. La opción iburst envía una ráfaga rápida de peticiones al arrancar para que el reloj se sincronice antes. Para apuntar un cliente a un servidor concreto, comenta la línea pool predeterminada y añade la tuya.

# /etc/chrony.conf
#pool 2.rhel.pool.ntp.org iburst
server classroom.example.com iburst
driftfile /var/lib/chrony/drift
makestep 1.0 3

Después de editar, reinicia el servicio con systemctl restart chronyd y asegúrate de que esté habilitado. Luego compruébalo con chronyc sources -v. La línea que empieza con ^* es la fuente seleccionada actualmente para sincronizar; ^+ marca candidatas aceptables y ^? significa que la fuente es inaccesible o todavía no se ha evaluado. chronyc tracking muestra el desfase actual y el estrato (stratum).

timedatectl es la herramienta general para los ajustes del reloj. timedatectl sin más muestra la hora local, UTC (Coordinated Universal Time), la zona horaria, si NTP está activo y si el reloj está sincronizado. timedatectl set-timezone Europe/Berlin establece la zona (lista los nombres con timedatectl list-timezones). timedatectl set-ntp true habilita la hora por red, lo que en RHEL inicia y habilita chronyd; set-ntp false lo detiene para que puedas poner la hora a mano con timedatectl set-time.

timedatectl set-timezone America/New_York
timedatectl set-ntp true
systemctl restart chronyd
chronyc sources -v
timedatectl        # System clock synchronized: yes

Si una fuente nunca llega a ^*, revisa la resolución de nombres del servidor, la accesibilidad de red y que el puerto UDP 123 no esté bloqueado en el camino. Un cliente no necesita abrir el firewall local para NTP, porque es él quien inicia las peticiones.

Términos clave

NTP
Network Time Protocol, usado para sincronizar relojes con servidores de hora por la red.
chronyd
El demonio NTP de RHEL, configurado en /etc/chrony.conf.
iburst
Una opción de servidor de chrony que envía varias peticiones rápidas al arrancar para sincronizar antes.
timedatectl
Una herramienta de systemd para ver y establecer la hora, la zona horaria y si la sincronización NTP está activada.
Ejemplo real

Una tarea te pide convertir el sistema en cliente de hora de classroom.example.com. Reemplazas la línea pool de /etc/chrony.conf por server classroom.example.com iburst, ejecutas systemctl enable chronyd y systemctl restart chronyd, y al cabo de un minuto chronyc sources muestra ^* classroom.example.com.

Consejo para el examen: En la salida de chronyc sources, el asterisco después del acento circunflejo marca la fuente con la que realmente estás sincronizado. Sin asterisco, la configuración todavía no funciona.

Comprueba lo que sabes

¿Qué línea añadirías a /etc/chrony.conf para usar ntp1.example.com?

server ntp1.example.com iburst, y luego reiniciar chronyd.

¿Qué hace timedatectl set-ntp true en RHEL?

Activa la sincronización de hora por red habilitando e iniciando chronyd.

En la salida de chronyc sources, ¿qué significa ^??

Que la fuente es inaccesible o todavía no se ha evaluado.
