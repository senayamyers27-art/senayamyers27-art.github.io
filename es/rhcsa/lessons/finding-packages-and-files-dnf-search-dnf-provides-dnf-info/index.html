Red Hat Certified System Administrator EX200 (RHEL 10)

Encontrar paquetes y archivos: dnf search, dnf provides, dnf info

Las tareas del examen rara vez te dicen el nombre exacto del paquete. Dicen 'instala la herramienta que proporciona el comando semanage' o 'asegúrate de que el sistema pueda servir páginas web'. Tres subcomandos de dnf cubren la distancia entre lo que necesitas y el paquete que lo ofrece.

dnf search keyword busca la palabra clave en los nombres y resúmenes de los paquetes de todos los repositorios habilitados. dnf search web server lista los paquetes cuyo nombre o resumen coincide, mostrando primero las coincidencias en el nombre. Si obtienes muy pocos resultados, dnf search --all keyword también busca en las descripciones y URLs. La búsqueda es mejor cuando sabes qué tipo de software quieres pero no su nombre.

dnf provides (también dnf whatprovides) responde a otra pregunta: ¿qué paquete contiene un archivo o comando concreto? Dale una ruta, un nombre de comando o un glob. dnf provides semanage indica policycoreutils-python-utils; dnf provides '*/bin/sealert' encuentra la herramienta de diagnóstico de SELinux. Pon los globs entre comillas para que el shell no los expanda primero. Es el más útil de los tres en el examen, porque muchas tareas nombran un comando en lugar de un paquete.

dnf search nfs
dnf provides semanage
dnf provides '*/bin/ifconfig'
dnf info httpd
dnf list --installed 'python3*'
dnf list --available 'php*'

dnf info package muestra los detalles de un paquete: nombre, versión, release, arquitectura, tamaño, el repositorio del que proviene, un resumen y una descripción. El campo Repository muestra @System (o algo similar) cuando el paquete ya está instalado. Úsalo para confirmar que tienes el paquete correcto antes de instalarlo, o para ver qué versión está disponible.

dnf list los complementa mostrando paquetes por patrón de nombre, divididos en secciones de instalados y disponibles, y acepta globs como 'kernel*'. Para archivos que pertenecen a paquetes ya instalados, rpm -qf /path es más rápido que dnf provides porque solo lee la base de datos local, mientras que dnf provides busca en los metadatos de los repositorios y por eso puede encontrar archivos en paquetes que todavía no has instalado.

Estas búsquedas dependen de que los repositorios funcionen. Si no devuelven nada, revisa primero dnf repolist: una configuración de repositorios vacía o rota es una causa más común que un paquete inexistente.

Términos clave

dnf search
Busca palabras clave en los nombres y resúmenes de los paquetes (o, con --all, también en las descripciones).
dnf provides
Encuentra qué paquete contiene un archivo, comando o glob de ruta dado; también se llama whatprovides.
dnf info
Muestra detalles de un paquete, como versión, repositorio, tamaño y descripción.
dnf list
Lista los paquetes instalados y disponibles que coinciden con un patrón de nombre.
@System
Etiqueta que dnf usa para indicar que un paquete está instalado localmente y no disponible desde un repositorio.
Ejemplo real

Una tarea te pide establecer una etiqueta de puerto de SELinux, pero no se encuentra semanage. dnf provides semanage muestra que policycoreutils-python-utils proporciona /usr/sbin/semanage, así que instalas ese paquete y continúas.

Consejo para el examen: Cuando una tarea nombra un comando y no un paquete, recurre a dnf provides command (pon entre comillas los globs como '*/bin/name'). Usa dnf search cuando solo sabes qué hace el software.

Comprueba lo que sabes

¿Qué comando te dice qué paquete instalaría /usr/bin/dig?

dnf provides /usr/bin/dig (o dnf provides dig).

¿Cómo puede dnf info mostrarte si un paquete ya está instalado?

Los paquetes instalados muestran el repositorio como @System o aparecen en 'Installed Packages'.

¿Por qué dnf search podría no devolver resultados para un paquete que sí existe?

Los repositorios pueden estar mal configurados o deshabilitados; revisa primero dnf repolist.
