Red Hat Certified System Administrator EX200 (RHEL 10)

Caducidad predeterminada en /etc/login.defs y valores predeterminados de cuentas en /etc/default/useradd y /etc/skel

Cuando useradd crea una cuenta, rellena todo lo que no especificaste a partir de tres lugares. Cambiar estos valores predeterminados es la forma de asegurar que toda cuenta futura cumpla la política sin tener que recordar las opciones cada vez. El punto clave, que se evalúa a menudo: estos archivos solo afectan a las cuentas creadas después, no a las existentes.

/etc/login.defs contiene ajustes de la suite shadow. Sus líneas de caducidad de contraseñas establecen los valores que se copian en /etc/shadow para los usuarios nuevos: PASS_MAX_DAYS, PASS_MIN_DAYS y PASS_WARN_AGE. También establece los rangos de UID y GID (ID de grupo) para las cuentas normales y de sistema (UID_MIN, UID_MAX, SYS_UID_MIN y los equivalentes de GID), si se crean directorios personales (CREATE_HOME), el UMASK predeterminado usado para los nuevos directorios personales y el método de hash de contraseñas (ENCRYPT_METHOD).

# /etc/login.defs (extracto)
PASS_MAX_DAYS   90
PASS_MIN_DAYS   1
PASS_WARN_AGE   14
UID_MIN         1000
CREATE_HOME     yes

/etc/default/useradd contiene los valores predeterminados propios de useradd: HOME (directorio base de los directorios personales, normalmente /home), SHELL (shell de inicio de sesión predeterminado), SKEL (el directorio esqueleto), INACTIVE y EXPIRE (periodo de inactividad y caducidad de la cuenta predeterminados) y GROUP. Puedes verlo con useradd -D y cambiar valores con, por ejemplo, useradd -D -s /bin/bash o editando el archivo directamente.

/etc/skel es el directorio esqueleto. Su contenido se copia en cada nuevo directorio personal, así que los archivos que pongas ahí, como un .bashrc estándar, un README o un directorio vacío, aparecen para cada usuario nuevo. RHEL lo incluye con .bash_logout, .bash_profile y .bashrc. Se incluyen los archivos ocultos, algo fácil de olvidar cuando miras con ls simple; usa ls -a /etc/skel.

useradd -D                     # mostrar los valores predeterminados de useradd
echo 'Welcome' > /etc/skel/README
useradd testuser
ls -a /home/testuser           # README está ahí
chage -l testuser              # muestra los valores de caducidad de login.defs

Para las cuentas existentes, aplica tú mismo la política con chage en cada usuario. Una tarea típica del examen dice: los usuarios nuevos deben tener contraseñas que caduquen a los 30 días. La respuesta es PASS_MAX_DAYS 30 en /etc/login.defs y, si también menciona a los usuarios existentes, chage -M 30 para ellos.

Términos clave

/etc/login.defs
Configuración para las cuentas nuevas: caducidad de contraseñas predeterminada, rangos de UID y GID, CREATE_HOME, UMASK y método de hash.
/etc/default/useradd
Valores predeterminados de useradd, como el directorio base personal, el shell predeterminado, el directorio esqueleto y la caducidad; se muestran con useradd -D.
/etc/skel
El directorio esqueleto cuyos archivos se copian en el directorio personal de cada usuario nuevo.
PASS_MAX_DAYS
El ajuste de login.defs para la edad máxima predeterminada de la contraseña aplicada a las cuentas nuevas.
Ejemplo real

La política dice que la contraseña de toda cuenta nueva debe caducar a los 20 días. Pones PASS_MAX_DAYS 20 en /etc/login.defs, creas el usuario kim y chage -l kim muestra un máximo de 20. El usuario lee, creado la semana pasada, sigue mostrando 99999 hasta que ejecutas chage -M 20 lee.

Consejo para el examen: login.defs y /etc/default/useradd solo cambian las cuentas creadas después. Si los usuarios existentes deben cumplir, ejecuta chage también sobre ellos.

Comprueba lo que sabes

¿Qué archivo establece la edad máxima predeterminada de la contraseña para los usuarios nuevos?

/etc/login.defs, mediante PASS_MAX_DAYS.

¿Cómo ves el shell predeterminado actual de useradd y el directorio base personal?

Ejecuta useradd -D, que imprime los valores de /etc/default/useradd.

Pones un archivo en /etc/skel. ¿Qué usuarios lo reciben?

Solo los usuarios cuyos directorios personales se crean a partir de ese momento; los directorios personales existentes no cambian.
