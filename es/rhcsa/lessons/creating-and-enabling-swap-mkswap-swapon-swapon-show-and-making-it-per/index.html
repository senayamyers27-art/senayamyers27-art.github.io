Red Hat Certified System Administrator EX200 (RHEL 10)

Crear y habilitar swap (mkswap, swapon, swapon --show) y hacerlo persistente

El swap es espacio en disco que el kernel usa como desbordamiento de la memoria. Cuando la RAM se llena, el kernel mueve al swap las páginas que no se han usado recientemente para que los programas activos puedan seguir ejecutándose. El swap es mucho más lento que la RAM, así que es una red de seguridad más que una mejora de rendimiento, pero muchas cargas de trabajo y el examen RHCSA esperan que lo añadas cuando se te pida. El swap puede estar en una partición, en un volumen lógico o en un archivo; las tareas del examen normalmente piden una partición o un volumen lógico de un tamaño dado.

El flujo de trabajo tiene tres pasos. Primero, crea el espacio: una partición (en fdisk establece el tipo en Linux swap, en parted usa mkpart con el tipo de sistema de archivos linux-swap, en gdisk usa el código de tipo 8200) o un volumen lógico con lvcreate. Segundo, escribe una firma de swap con mkswap, que también asigna un UUID (universally unique identifier). Tercero, actívalo con swapon. Revisa el resultado con swapon --show o free -h.

mkswap /dev/vdb2            # escribe la firma, imprime el UUID
swapon /dev/vdb2            # activar ahora
swapon --show               # listar las áreas de swap activas
free -h                     # la línea Swap: muestra el nuevo total

La activación con swapon no sobrevive a un reinicio. Para que el swap sea persistente, añade una línea a /etc/fstab. Para swap, el campo del punto de montaje es none (o swap), el tipo es swap y los campos dump y fsck son ambos 0. Usa el UUID de mkswap o blkid en lugar del nombre del dispositivo, porque los nombres como /dev/vdb pueden cambiar entre arranques.

UUID=3f1c...-9a2e  none  swap  defaults  0 0

Después de editar /etc/fstab, prueba la entrada sin reiniciar: ejecuta swapon -a, que activa todas las entradas de swap listadas en el archivo, y luego swapon --show otra vez. Si ya habías activado el dispositivo a mano, desactívalo primero con swapoff /dev/vdb2 para que swapon -a demuestre que la línea de fstab funciona. También puedes establecer una prioridad con la opción pri=; el kernel usa primero las áreas de swap de mayor prioridad.

Los errores comunes son olvidar el paso de mkswap (swapon falla entonces con una firma no válida), poner la ruta de un punto de montaje en el segundo campo o escribir mal el UUID. En el examen, un sistema que no arranca por una línea de fstab rota cuesta mucho más que la tarea de swap, así que prueba siempre con swapon -a y findmnt --verify antes de reiniciar.

Términos clave

Swap space (espacio swap)
Espacio en disco que usa el kernel para guardar páginas de memoria que no caben en la RAM.
mkswap
Escribe una firma de swap y un UUID en una partición, volumen lógico o archivo para que pueda usarse como swap.
swapon / swapoff
Activan o desactivan áreas de swap; swapon -a activa todas las entradas de swap de /etc/fstab.
UUID
Un identificador único universal guardado en un sistema de archivos o en una firma de swap, usado para referirse a un dispositivo de forma fiable en /etc/fstab.
Ejemplo real

Te piden añadir una partición swap de 512 MiB en /dev/vdb que esté activa después de reiniciar. Creas la partición 2 con parted como linux-swap, ejecutas mkswap /dev/vdb2, copias el UUID en /etc/fstab con none, swap, defaults, 0 0, luego ejecutas swapon -a y lo confirmas con swapon --show antes de reiniciar.

Consejo para el examen: La persistencia es lo que revisan los evaluadores. Un área de swap activada solo con swapon desaparece al reiniciar, así que la tarea falla a menos que exista la línea en /etc/fstab y swapon -a la active sin errores.

Comprueba lo que sabes

¿Qué tres comandos llevan una nueva partición a ser swap activo y verificado?

mkswap para escribir la firma, swapon para activarlo y swapon --show (o free -h) para verificarlo.

¿Qué va en los campos del punto de montaje y de fsck de una línea de swap en /etc/fstab?

El punto de montaje es none (o swap) y los campos dump y orden de fsck son ambos 0, ya que el swap nunca se monta ni se revisa.

¿Por qué usar el UUID en lugar de /dev/vdb2 en /etc/fstab?

Los nombres de dispositivo pueden cambiar entre arranques cuando se añaden discos o se detectan en otro orden, mientras que el UUID permanece con la firma de swap.
