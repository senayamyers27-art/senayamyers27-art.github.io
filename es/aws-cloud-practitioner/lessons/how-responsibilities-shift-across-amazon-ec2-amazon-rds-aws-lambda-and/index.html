AWS Certified Cloud Practitioner CLF-C02

Cómo cambian las responsabilidades entre Amazon EC2, Amazon RDS, AWS Lambda y Amazon S3

El modelo de responsabilidad compartida no es una línea fija. Cuanto más administra AWS por ti, más responsabilidad pasa a AWS. Comparar cuatro servicios comunes aclara ese cambio, y al examen le encanta preguntar 'quién hace qué' precisamente sobre estos.

Amazon EC2 es infraestructura como servicio (IaaS). AWS protege el host físico, la red y el hipervisor. Tú eres responsable de casi todo lo que está por encima: elegir y parchear el sistema operativo invitado, instalar y actualizar aplicaciones, configurar el firewall del host y los security groups, administrar los permisos y las claves de IAM, y proteger y respaldar tus datos. EC2 te da el mayor control y, por lo tanto, la mayor responsabilidad.

Amazon RDS es un servicio de base de datos administrado. AWS se hace cargo del sistema operativo del host de la base de datos, de instalar el motor de base de datos, de parchearlo (durante una ventana de mantenimiento que tú eliges), de ejecutar respaldos automatizados y de gestionar la conmutación por error Multi-AZ cuando la habilitas. Tú sigues administrando quién puede conectarse (security groups, usuarios de la base de datos e IAM), si el almacenamiento está cifrado, qué configuración de parámetros y qué retención de respaldos eliges, y los datos y las consultas en sí. No puedes iniciar sesión en el sistema operativo de una instancia RDS estándar, lo cual es una pista de que el sistema operativo es trabajo de AWS.

AWS Lambda es cómputo serverless. Subes el código de tu función y AWS lo ejecuta, así que AWS se encarga de los servidores, el sistema operativo, los parches del entorno de ejecución (en los runtimes administrados), el escalado y la disponibilidad. Tu responsabilidad se reduce al código de tu función y sus dependencias, al rol de ejecución de IAM y sus permisos, a la configuración que estableces y a los datos que maneja tu código.

Amazon S3 es un servicio de almacenamiento abstraído. AWS administra la infraestructura de almacenamiento, la durabilidad y la disponibilidad. Tú eres responsable de tus objetos, las políticas de bucket y el control de acceso, la configuración de S3 Block Public Access, las decisiones de cifrado y la configuración de versionado y de ciclo de vida. El patrón en los cuatro: AWS asume más a medida que pasas de EC2 a RDS y a Lambda y S3, pero los datos, las identidades y la configuración de acceso siempre quedan de tu lado.

Términos clave

Infrastructure as a service (IaaS, infraestructura como servicio)
Un modelo como EC2 en el que AWS proporciona infraestructura virtual y el cliente administra el sistema operativo y todo lo que está por encima.
Managed service (servicio administrado)
Un servicio como RDS en el que AWS opera el software subyacente, los parches y los respaldos en nombre del cliente.
Serverless (sin servidor)
Un modelo como Lambda en el que el cliente aporta el código y AWS ejecuta, escala y parchea el cómputo subyacente.
Execution role (rol de ejecución)
El rol de IAM que asume una función Lambda para acceder a otros servicios de AWS; sus permisos son responsabilidad del cliente.
Ejemplo real

Un equipo traslada su servidor MySQL autoadministrado en EC2 a Amazon RDS for MySQL. Ya no parchea el sistema operativo ni el motor de base de datos y ya no escribe scripts de respaldo, porque RDS lo hace. Sigue decidiendo quién puede llegar a la base de datos mediante security groups, activa el cifrado del almacenamiento y administra las cuentas de usuario de la base de datos.

Consejo para el examen: El sistema operativo es la señal clave. En EC2 lo parcheas tú; en RDS y Lambda lo parchea AWS. Pero en todos los servicios configuras el acceso y proteges tus datos.

Comprueba lo que sabes

En Amazon RDS, ¿quién aplica los parches del motor de base de datos?

AWS los aplica, durante la ventana de mantenimiento que elige el cliente.

En una función de AWS Lambda, ¿cuáles son las principales responsabilidades de seguridad del cliente?

El código de la función y sus dependencias, el rol de ejecución de IAM y sus permisos, la configuración, como las variables de entorno, y los datos que procesa.
