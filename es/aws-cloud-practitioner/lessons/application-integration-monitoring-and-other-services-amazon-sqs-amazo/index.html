AWS Certified Cloud Practitioner CLF-C02

Integración de aplicaciones, monitoreo y otros servicios: Amazon SQS, Amazon SNS, Amazon EventBridge, Amazon CloudWatch, AWS Systems Manager y AWS IoT Core

Las aplicaciones modernas se construyen con muchos componentes que deben comunicarse de forma confiable y ser monitoreados y administrados a escala. Si cada componente llama directamente al siguiente, una pieza lenta o que falla arrastra a todo lo que está antes; esto se llama acoplamiento fuerte. Los servicios de integración de aplicaciones reducen ese acoplamiento, y los servicios de administración permiten que un equipo pequeño vigile y opere grandes flotas. El examen evalúa si puedes elegir el servicio correcto para desacoplar, notificar, enrutar eventos, monitorear, administrar flotas y conectar dispositivos.

Amazon Simple Queue Service (Amazon SQS) es una cola de mensajes totalmente administrada. Un productor envía mensajes a una cola, y los consumidores sondean la cola, procesan los mensajes a su propio ritmo y eliminan cada uno una vez atendido. Mientras un consumidor trabaja en un mensaje, este queda oculto para los demás durante un tiempo de visibilidad (visibility timeout), y los mensajes que fallan repetidamente pueden moverse a una cola de mensajes fallidos (dead-letter queue) para investigarlos. La cola absorbe ráfagas de trabajo y desacopla los componentes, de modo que un consumidor lento o que falla no rompe al productor. Las colas estándar ofrecen un rendimiento muy alto con entrega de al menos una vez; las colas FIFO (primero en entrar, primero en salir) conservan el orden y procesan cada mensaje exactamente una vez.

Amazon Simple Notification Service (Amazon SNS) es un servicio de publicación/suscripción (pub/sub). Un publicador envía un mensaje a un tema (topic), y SNS lo envía de inmediato a cada suscriptor: colas de SQS, funciones de AWS Lambda, endpoints HTTPS, direcciones de correo electrónico, o notificaciones push móviles y mensajes de texto SMS. La diferencia clave es la dirección y la audiencia: SQS es una cola de la que los consumidores extraen mensajes, con un consumidor procesando cada mensaje; SNS envía cada mensaje a muchos suscriptores a la vez. Combinarlos, en un fan-out de SNS hacia varias colas de SQS, permite que cada sistema posterior procese el mismo evento de forma independiente.

Amazon EventBridge es un bus de eventos serverless. Recibe eventos de servicios de AWS, de tus propias aplicaciones y de socios de software como servicio (SaaS), y los enruta a destinos según reglas que coinciden con el contenido del evento, por ejemplo «cuando una instancia EC2 cambie a detenida, invoca esta función Lambda» o «cuando un hallazgo de GuardDuty tenga severidad alta, notifica al equipo de seguridad». EventBridge Scheduler ejecuta tareas según una programación. Amazon CloudWatch es el servicio central de monitoreo operativo: recopila métricas como el uso de CPU, almacena y busca registros en CloudWatch Logs, muestra paneles y genera alarmas que pueden notificar a un tema de SNS o activar Auto Scaling.

AWS Systems Manager es un conjunto de capacidades para administrar instancias EC2 y servidores locales a escala. Session Manager da acceso seguro a la shell a través de la consola o la CLI sin abrir puertos de entrada ni administrar claves SSH, y registra las sesiones para auditoría. Patch Manager automatiza la aplicación de parches del sistema operativo según una programación. Run Command ejecuta scripts en flotas completas, Inventory registra el software instalado y Parameter Store guarda valores de configuración y secretos. AWS IoT Core conecta de forma segura dispositivos de Internet de las cosas (IoT) a la nube, recibe sus mensajes, a menudo mediante el liviano protocolo MQTT, y los enruta con reglas a servicios como Lambda, Amazon DynamoDB o Kinesis.

Veamos un ejemplo práctico. Una tienda en línea publica un mensaje de «pedido realizado» en un tema de SNS. Se suscriben tres colas de SQS: una para pagos, una para el almacén y una para los recibos por correo, de modo que el servicio de cada equipo procesa los pedidos a su propia velocidad, y una caída del almacén simplemente hace que su cola crezca hasta que se recupere. EventBridge vigila los cambios de estado de EC2 y notifica a operaciones. Las alarmas de CloudWatch sobre las tasas de error avisan al ingeniero de guardia, Patch Manager de Systems Manager aplica parches a la flota cada domingo, y los ingenieros usan Session Manager en lugar de abrir el puerto 22. Los sensores inteligentes de los estantes del almacén informan los niveles de existencias a través de IoT Core.

Errores comunes: elegir SQS cuando un mensaje debe llegar a varios sistemas a la vez (eso es SNS, a menudo con colas detrás); elegir SNS cuando el trabajo debe almacenarse temporalmente y ser procesado de forma confiable por un trabajador (eso es SQS); confundir CloudWatch, que monitorea el rendimiento y las operaciones, con AWS CloudTrail, que registra la actividad de las API para auditoría; abrir SSH a internet cuando Session Manager lo evitaría; y pensar que EventBridge es solo un programador de tareas en lugar de un enrutador de eventos basado en reglas.

En el examen, las palabras clave deciden. «Desacoplar», «almacenar temporalmente» o «cola» significa SQS, y «procesar en orden, exactamente una vez» significa una cola FIFO de SQS. «Notificar a varios suscriptores», «pub/sub», «fan-out» o «enviar una alerta por SMS o correo» significa SNS. «Reaccionar a eventos con reglas» o «enrutar eventos de aplicaciones SaaS» significa EventBridge. «Métricas, registros, alarmas, paneles» significa CloudWatch. «Aplicar parches a una flota», «ejecutar comandos en muchas instancias» o «conectarse a instancias sin claves SSH ni puertos abiertos» significa Systems Manager. «Conectar sensores y dispositivos» significa IoT Core.

Términos clave

Amazon SQS
Cola de mensajes totalmente administrada que desacopla productores y consumidores, donde los consumidores extraen los mensajes.
Amazon SNS
Servicio pub/sub que envía cada mensaje publicado en un tema a todos sus suscriptores.
Fan-out
Patrón en el que un mensaje de SNS se entrega a varias colas de SQS u otros suscriptores para procesarlo en paralelo.
Amazon EventBridge
Bus de eventos serverless que enruta eventos a destinos según reglas de coincidencia.
Amazon CloudWatch
Servicio de AWS para métricas, registros, paneles y alarmas.
AWS Systems Manager
Conjunto de herramientas para administrar, parchar y acceder a servidores EC2 y locales a escala.
Session Manager
Capacidad de Systems Manager que proporciona acceso auditado a la shell sin puertos de entrada ni claves SSH.
AWS IoT Core
Servicio administrado que conecta de forma segura dispositivos IoT y enruta sus mensajes a servicios de AWS.
Ejemplo real

Un servicio de impresión de fotos llamaba directamente a su sistema de impresión desde la capa web, así que cuando las impresoras estaban lentas, los clientes veían errores al pagar. El equipo colocó una cola de SQS entre ambos: ahora el sitio web deja un mensaje en la cola y responde al instante, y los trabajadores de impresión toman los trabajos tan rápido como pueden. Durante la temporada alta de fiestas la cola crece durante algunas horas, pero no se pierde ningún pedido y los clientes nunca lo notan.

Consejo para el examen: SQS se basa en extracción (pull) y cada mensaje lo procesa un solo consumidor; SNS se basa en envío (push) y entrega cada mensaje a todos los suscriptores. Un evento que debe llegar a varios sistemas significa SNS, a menudo con colas de SQS detrás.

Comprueba lo que sabes

Una capa web debe entregar trabajo a un back-end más lento sin perder solicitudes durante los picos. ¿Qué servicio?

Amazon SQS, que almacena los mensajes para que el back-end los procese a su propio ritmo.

Un evento de pedido debe llegar simultáneamente a los sistemas de facturación, envíos y correo electrónico. ¿Qué patrón?

Fan-out de SNS: publicar en un tema de SNS al que cada sistema está suscrito, a menudo mediante su propia cola de SQS.

¿Cómo pueden los administradores acceder a instancias EC2 sin abrir puertos SSH ni administrar claves?

Con AWS Systems Manager Session Manager.

¿Qué servicio activaría una función Lambda cada vez que se detiene una instancia EC2?

Amazon EventBridge, mediante una regla que coincida con el evento de cambio de estado de la instancia.
