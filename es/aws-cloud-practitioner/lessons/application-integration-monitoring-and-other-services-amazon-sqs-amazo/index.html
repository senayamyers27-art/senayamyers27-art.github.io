AWS Certified Cloud Practitioner CLF-C02

Integración de aplicaciones, monitoreo y otros servicios: Amazon SQS, Amazon SNS, Amazon EventBridge, Amazon CloudWatch, AWS Systems Manager y AWS IoT Core

Las aplicaciones modernas se construyen a partir de muchos componentes que deben comunicarse de forma fiable y ser monitoreados y administrados a escala. Estos servicios unen las piezas y las mantienen funcionando.

Amazon Simple Queue Service (Amazon SQS) es una cola de mensajes totalmente administrada. Un productor envía mensajes a una cola, y los consumidores sondean (poll) la cola y procesan los mensajes a su propio ritmo, eliminando cada uno una vez atendido. La cola amortigua las ráfagas de trabajo y desacopla los componentes para que un consumidor lento o caído no afecte al productor. Las colas estándar ofrecen un rendimiento muy alto; las colas FIFO preservan el orden y procesan cada mensaje exactamente una vez.

Amazon Simple Notification Service (Amazon SNS) es un servicio de mensajería de publicación/suscripción (pub/sub). Un publicador envía un mensaje a un tema (topic), y SNS lo envía de inmediato a cada suscriptor: colas SQS, funciones Lambda, endpoints HTTPS, direcciones de correo electrónico o notificaciones push móviles y SMS. La diferencia clave: SQS es una cola de la que los consumidores extraen mensajes, con un consumidor procesando cada mensaje; SNS envía cada mensaje a muchos suscriptores a la vez. Combinarlos (fan-out de SNS hacia varias colas SQS) es un patrón común.

Amazon EventBridge es un bus de eventos serverless. Recibe eventos de los servicios de AWS, de tus propias aplicaciones y de socios SaaS, y los dirige a destinos según reglas que coinciden con el contenido del evento, por ejemplo 'cuando una instancia EC2 cambie a detenida, invocar esta función Lambda'. EventBridge Scheduler ejecuta tareas según una programación.

Amazon CloudWatch, que viste en el dominio de seguridad, también es el servicio central de monitoreo operativo: métricas, registros, paneles y alarmas. AWS Systems Manager es un conjunto de capacidades para administrar instancias EC2 y servidores locales a escala: Session Manager para acceso seguro por shell sin abrir puertos de entrada ni administrar claves SSH, Patch Manager para automatizar los parches del sistema operativo, Run Command para ejecutar scripts en flotas completas, Inventory y Parameter Store para la configuración. AWS IoT Core conecta de forma segura miles de millones de dispositivos de Internet de las cosas (IoT) a la nube, recibiendo sus mensajes (a menudo mediante el protocolo MQTT) y dirigiéndolos a otros servicios de AWS.

Pistas del examen: 'desacoplar' o 'amortiguar' significa SQS; 'notificar a varios suscriptores' o 'fan-out' significa SNS; 'reaccionar a eventos con reglas' significa EventBridge; 'parchear una flota' o 'conectarse a instancias sin claves SSH' significa Systems Manager; 'conectar sensores y dispositivos' significa IoT Core.

Términos clave

Amazon SQS
Una cola de mensajes administrada que desacopla productores y consumidores, los cuales sondean la cola para obtener mensajes.
Amazon SNS
Un servicio pub/sub administrado que envía mensajes desde temas a muchos suscriptores.
Amazon EventBridge
Un bus de eventos serverless que dirige eventos a destinos según reglas de coincidencia.
AWS Systems Manager
Un conjunto de herramientas para ver, parchear, configurar y acceder a EC2 y a servidores locales a escala.
AWS IoT Core
Un servicio administrado que conecta de forma segura dispositivos IoT a AWS y dirige sus mensajes.
Ejemplo real

Cuando un cliente hace un pedido, la aplicación web publica en un tema de SNS. El tema hace fan-out hacia una cola SQS para el servicio de facturación y otra para el servicio de envíos, y cada uno procesa a su propio ritmo. EventBridge dispara una función Lambda cada vez que una instancia se detiene inesperadamente, y Systems Manager Patch Manager parchea todos los servidores de pedidos cada domingo.

Consejo para el examen: SQS se basa en extracción (pull) y cada mensaje lo procesa un consumidor; SNS se basa en envío (push) y entrega cada mensaje a todos los suscriptores. Si un escenario necesita que un evento llegue a varios sistemas a la vez, elige SNS (a menudo con colas SQS detrás).

Comprueba lo que sabes

¿Qué servicio permite a los administradores abrir un shell en instancias EC2 sin abrir el puerto 22 ni administrar claves SSH?

AWS Systems Manager Session Manager.

Un único evento de pedido debe entregarse a tres servicios distintos al mismo tiempo. ¿Qué servicio encaja de forma natural?

Amazon SNS, publicando en un tema al que se suscriben esos servicios (o sus colas SQS).
