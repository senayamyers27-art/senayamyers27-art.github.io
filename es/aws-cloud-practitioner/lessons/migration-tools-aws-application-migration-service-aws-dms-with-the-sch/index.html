AWS Certified Cloud Practitioner CLF-C02

Herramientas de migración: AWS Application Migration Service, AWS DMS con la Schema Conversion Tool y AWS DataSync

Una vez que decidiste cómo se trasladará cada aplicación (las 7 R), necesitas herramientas para trasladarla realmente. AWS ofrece servicios dedicados para las tres cosas que llevan la mayoría de las migraciones: servidores completos, bases de datos y archivos. El examen espera que elijas el servicio correcto a partir de una breve descripción de lo que se está trasladando, así que la habilidad más importante aquí es relacionar la carga con el servicio.

AWS Application Migration Service (a menudo abreviado como AWS MGN) es el principal servicio de AWS para hacer rehost (lift and shift). Instalas un agente de replicación en cada servidor de origen, que puede ser físico, virtual o estar funcionando en otra nube. El servicio replica continuamente los discos de los servidores a nivel de bloque hacia un área de preparación (staging) de bajo costo en tu cuenta de AWS, de modo que el origen sigue funcionando con normalidad. En cualquier momento puedes lanzar instancias de prueba a partir de los datos replicados sin interrumpir el origen. Cuando las pruebas son exitosas, realizas el corte (cutover): la replicación se pone al día, detienes la aplicación en el origen y los servidores se lanzan como instancias de Amazon Elastic Compute Cloud (Amazon EC2). La replicación continua mantiene corta esa ventana de corte, a menudo de minutos.

AWS Database Migration Service (AWS DMS) migra bases de datos a AWS. Creas una instancia de replicación, defines los puntos de enlace (endpoints) de origen y de destino, y ejecutas una tarea de migración que realiza una carga completa y luego puede seguir aplicando los cambios en curso, lo que se conoce como captura de datos de cambios (change data capture, CDC), hasta que cambias las aplicaciones al destino. La base de datos de origen sigue totalmente operativa durante la migración, lo que minimiza el tiempo de inactividad. DMS admite migraciones homogéneas, en las que el origen y el destino usan el mismo motor (por ejemplo, de Oracle a Oracle en Amazon RDS), y migraciones heterogéneas, en las que son distintos (por ejemplo, de Oracle a Amazon Aurora PostgreSQL).

En las migraciones heterogéneas, el esquema, es decir, las tablas, vistas, procedimientos almacenados, funciones y otros objetos de código, primero debe convertirse al dialecto del motor de destino. Ese es el trabajo de la AWS Schema Conversion Tool (AWS SCT), una aplicación descargable que además genera un informe de evaluación de lo que se convierte automáticamente y lo que requiere trabajo manual. DMS ahora también ofrece conversión de esquemas integrada en la consola. La división del trabajo es sencilla: SCT (o DMS Schema Conversion) convierte la estructura y DMS traslada los datos.

AWS DataSync es un servicio de transferencia de datos en línea para archivos y objetos. Despliegas un agente de DataSync cerca de tu almacenamiento local, creas ubicaciones para el origen (como un recurso compartido Network File System (NFS) o Server Message Block (SMB)) y para el destino (como Amazon S3, Amazon Elastic File System (Amazon EFS) o Amazon FSx), y luego creas y ejecutas una tarea. DataSync se encarga de la programación, el cifrado en tránsito, la verificación de la integridad de los datos y las transferencias incrementales, así que sirve tanto para migraciones únicas como para la sincronización recurrente de grandes conjuntos de archivos. También puede copiar entre servicios de almacenamiento de AWS. Para conjuntos de datos demasiado grandes como para enviarlos por la red a tiempo, AWS ofrece dispositivos de transferencia fuera de línea de la AWS Snow Family, como AWS Snowball Edge, que cargas localmente y envías de vuelta a AWS.

Veamos un ejemplo práctico. Una empresa está dejando su centro de datos. Sus 120 servidores de aplicaciones Windows y Linux se replican con Application Migration Service y se cortan en oleadas a lo largo de varios fines de semana. Su base de datos Microsoft SQL Server local pasa a Amazon RDS for SQL Server con DMS, una migración homogénea que no requiere conversión de esquema. Una base de datos de informes Oracle separada se está trasladando a Aurora PostgreSQL, así que el equipo primero ejecuta SCT para convertir el esquema y revisar el informe de evaluación, y luego usa DMS con replicación continua. Por último, 40 terabytes de documentos escaneados en un recurso compartido SMB se copian a Amazon S3 con DataSync, que se ejecuta todas las noches hasta el corte final.

Errores comunes: elegir DMS para trasladar archivos o DataSync para trasladar una base de datos en funcionamiento; olvidar SCT cuando los motores son distintos; pensar que DMS requiere dejar la base de datos de origen fuera de línea durante toda la migración (sigue en línea, y CDC mantiene sincronizado el destino); y elegir AWS Server Migration Service u otros nombres antiguos, cuando AWS ahora orienta a los clientes hacia Application Migration Service para el rehost. Recuerda también que AWS Migration Hub ofrece un único lugar para dar seguimiento al avance de las migraciones en estas herramientas, y que AWS Application Discovery Service recopila datos sobre los servidores locales para ayudar a planificarlas.

Las preguntas del examen suelen nombrar la carga y una restricción. 'Hacer lift and shift de servidores con un tiempo de inactividad mínimo' o 'replicar servidores físicos o virtuales a EC2' es AWS Application Migration Service. 'Migrar una base de datos mientras sigue operativa' es AWS DMS. 'Los motores de base de datos de origen y destino son distintos' o 'convertir procedimientos almacenados' agrega la AWS Schema Conversion Tool. 'Trasladar o sincronizar recursos compartidos de archivos a Amazon S3, EFS o FSx a través de la red' es AWS DataSync. 'Petabytes con ancho de banda limitado' apunta a un dispositivo de la Snow Family fuera de línea.

Términos clave

AWS Application Migration Service (AWS MGN)
Principal servicio de rehost de AWS, que replica continuamente los servidores de origen y los lanza como instancias EC2 en el corte.
Corte (cutover)
El cambio final del sistema de origen al sistema migrado en AWS.
AWS Database Migration Service (AWS DMS)
Servicio que migra datos entre bases de datos mientras el origen sigue operativo.
Captura de datos de cambios (change data capture, CDC)
Replicación continua de los cambios en curso desde la base de datos de origen al destino después de la carga inicial.
AWS Schema Conversion Tool (AWS SCT)
Herramienta que convierte el esquema y los objetos de código de una base de datos de un motor a otro en migraciones heterogéneas.
Migración heterogénea (heterogeneous migration)
Migración de bases de datos entre motores distintos, como de Oracle a Aurora PostgreSQL.
AWS DataSync
Servicio en línea que traslada y sincroniza archivos y objetos entre el almacenamiento local y los servicios de almacenamiento de AWS.
Ejemplo real

Un laboratorio de investigación traslada sus servidores de análisis a EC2 con Application Migration Service, lanzando copias de prueba semanas antes del corte para comprobar que las licencias de software y las rutas de red funcionan. Su base de datos MySQL pasa a Amazon Aurora MySQL con DMS usando replicación continua, así que el corte implica solo unos minutos de inactividad. Años de datos de instrumentos en un recurso compartido NFS se copian a Amazon S3 con una tarea nocturna de DataSync hasta que el laboratorio hace el cambio.

Consejo para el examen: Los servidores van con Application Migration Service, las bases de datos con DMS (más SCT cuando los motores son distintos) y los recursos compartidos de archivos con DataSync. DMS traslada los datos; SCT convierte el esquema.

Comprueba lo que sabes

¿Qué servicio es la principal herramienta de AWS para migrar servidores con lift and shift?

AWS Application Migration Service, que replica los servidores continuamente y los lanza como instancias EC2 en el corte.

Una empresa migra de Oracle a Aurora PostgreSQL. ¿Qué dos herramientas necesita?

La AWS Schema Conversion Tool (o DMS Schema Conversion) para convertir el esquema, y AWS DMS para trasladar los datos.

¿La base de datos de origen tiene que estar fuera de línea durante una migración con DMS?

No. Sigue operativa, y la captura de datos de cambios mantiene sincronizado el destino hasta el corte.

¿Qué servicio debería copiar según una programación un recurso compartido SMB local a Amazon S3?

AWS DataSync, que transfiere y sincroniza archivos a través de la red.
