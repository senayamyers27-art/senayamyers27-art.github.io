AWS Certified Cloud Practitioner CLF-C02

Modelos de implementación (nube, híbrido y local) y aprovisionamiento único frente a repetible

Un modelo de implementación (deployment model) describe dónde se ejecutan tus aplicaciones. AWS suele hablar de tres, y el examen te pide identificar cuál describe un escenario y por qué una organización podría elegirlo.

En una implementación en la nube (cloud deployment), a veces llamada nativa de la nube o all-in, todas las partes de la aplicación se ejecutan en la nube. Puede ser una aplicación construida en la nube desde el principio o una que se migró por completo. Puede usar infraestructura de bajo nivel, como instancias EC2, o servicios administrados y serverless de más alto nivel, como Lambda y DynamoDB. Una empresa sin centro de datos propio que ejecuta todo en AWS está usando el modelo de nube.

Una implementación híbrida (hybrid deployment) conecta recursos basados en la nube con infraestructura que permanece en las instalaciones propias. Las organizaciones eligen el modelo híbrido cuando algunos sistemas todavía no pueden moverse, por regulaciones, necesidades de latencia, dependencia de hardware local o un plan de migración gradual, pero aun así quieren los beneficios de la nube para otras cargas de trabajo. Por ejemplo, una empresa puede mantener su sistema ERP heredado en su propio centro de datos mientras ejecuta en AWS nuevas aplicaciones web orientadas a clientes, conectadas mediante AWS Site-to-Site VPN o AWS Direct Connect. Servicios como AWS Outposts y AWS Storage Gateway están diseñados para configuraciones híbridas.

Una implementación local (on-premises), a veces llamada nube privada, ejecuta los recursos en el propio centro de datos de la organización, usando virtualización y herramientas de gestión de recursos para obtener algo de la agilidad de la nube. No ofrece la escala ni la economía de pago por uso de la nube pública, pero algunas organizaciones la usan por requisitos estrictos de control.

El aprovisionamiento (provisioning) es cómo creas los recursos, y puede ser único o repetible. El aprovisionamiento único, como hacer clic en la consola para lanzar una instancia de prueba, está bien para experimentos y para aprender. El aprovisionamiento repetible usa código o plantillas, como CloudFormation o la CLI en scripts, para que la misma configuración se pueda volver a crear de forma coherente en otro entorno, cuenta o Región. Los entornos de producción deben aprovisionarse de forma repetible, porque los pasos manuales son fáciles de olvidar, difíciles de auditar y casi imposibles de reproducir con exactitud después de un desastre.

Términos clave

Cloud deployment (implementación en la nube)
Un modelo en el que todas las partes de una aplicación se ejecutan en la nube.
Hybrid deployment (implementación híbrida)
Un modelo que conecta recursos en la nube con infraestructura que permanece en las instalaciones propias.
On-premises deployment (implementación local)
Un modelo en el que los recursos se ejecutan en el propio centro de datos de la organización, a veces llamado nube privada.
Repeatable provisioning (aprovisionamiento repetible)
Crear recursos a partir de plantillas o scripts para que la misma configuración se pueda reproducir de forma coherente.
Ejemplo real

Un hospital mantiene su archivo de imágenes médicas en sus instalaciones porque los escáneres y las regulaciones locales lo exigen, pero ejecuta su sitio web de citas para pacientes en AWS y conecta ambos mediante una Site-to-Site VPN. Esa es una implementación híbrida. La infraestructura del sitio web está definida en una plantilla de CloudFormation para poder reconstruirla en otra Región si hace falta.

Consejo para el examen: Cualquier escenario en el que algunos recursos permanecen en el centro de datos de la empresa y otros se ejecutan en AWS, conectados entre sí, es híbrido. No te dejes engañar por opciones como 'multi-Región'; eso sigue siendo una implementación totalmente en la nube.

Comprueba lo que sabes

Una empresa ejecuta sus aplicaciones nuevas en AWS pero mantiene su mainframe en sus instalaciones, con ambos conectados. ¿Qué modelo de implementación es este?

Híbrido.

¿Por qué se prefiere el aprovisionamiento repetible para producción?

Porque crea entornos coherentes y auditables que se pueden reproducir con exactitud, evitando errores manuales y acelerando la recuperación.
