AWS Certified Cloud Practitioner CLF-C02

Datos de facturación detallados: la consola Billing and Cost Management, los Cost and Usage Reports y las exportaciones de datos, y las etiquetas de asignación de costos

Los gráficos de resumen responden muchas preguntas, pero las organizaciones grandes necesitan datos de facturación detallados, línea por línea, para asignar costos a los equipos, alimentar sus propias herramientas de informes y conciliar facturas. Este tema cubre dónde reside la información de facturación, cómo obtener los datos más granulares y cómo las etiquetas convierten una larga lista de cargos en algo que un equipo de finanzas puede entender. El examen se centra en elegir la fuente correcta de datos de facturación y en el paso de activación de las etiquetas de asignación de costos.

La consola AWS Billing and Cost Management es el lugar central para las tareas de facturación. Allí ves las facturas actuales y pasadas, los cargos del mes en curso por servicio y Región, administras los métodos de pago, la configuración de impuestos y los contactos de facturación, abres Cost Explorer y Budgets, ves el uso del Free Tier y defines preferencias de facturación como las alertas. El acceso se controla con IAM, así que puedes permitir que un usuario de finanzas vea las facturas sin darle acceso a la infraestructura. En AWS Organizations, la cuenta de administración ve la factura consolidada de todas las cuentas miembro. El servicio AWS Billing Conductor puede producir vistas de facturación personalizadas, por ejemplo para revendedores.

Para obtener los datos más detallados, los AWS Cost and Usage Reports (CUR) entregan datos de facturación completos, hasta el nivel de ID de recurso individual, uso por hora o por día, precios y descuentos, como archivos en un bucket de Amazon S3 que tú eliges. AWS ha evolucionado esto hacia Data Exports, que te permite crear exportaciones de datos de costo y uso, incluido el formato CUR 2.0, hacia S3. Desde allí puedes consultar los datos con Amazon Athena, cargarlos en Amazon Redshift o visualizarlos con Amazon QuickSight o herramientas de terceros. Si una pregunta pide los datos de facturación más granulares para un análisis personalizado, la respuesta es el Cost and Usage Report o las exportaciones de datos, no Cost Explorer.

Las etiquetas de asignación de costos dan sentido a esos datos. Una etiqueta (tag) es un rótulo de clave-valor, como Project=Checkout o CostCenter=1234, asociado a los recursos. Hay etiquetas definidas por el usuario, que creas tú, y etiquetas generadas por AWS, como aws:createdBy. Una etiqueta se convierte en etiqueta de asignación de costos solo después de que la activas en la consola de Billing and Cost Management, y tras la activación aparece como columna en los informes de costos y como filtro y dimensión de agrupación en Cost Explorer y Budgets. Por defecto, las etiquetas se aplican a los datos de costos desde la activación en adelante; AWS permite una solicitud de relleno retroactivo (backfill) por un periodo limitado de meses anteriores, pero no debes contar con que las etiquetas aparezcan de forma retroactiva.

Una estrategia de etiquetado consistente es lo que hace que esto funcione. Un esquema típico etiqueta cada recurso con CostCenter, Environment (por ejemplo production o dev) y Owner. Define un conjunto pequeño de claves obligatorias, su ortografía exacta y los valores permitidos, hazlas cumplir con políticas de etiquetas (tag policies) en AWS Organizations, y usa reglas de AWS Config o infraestructura como código para detectar recursos sin etiquetar. Así, finanzas puede ver exactamente cuánto cuesta cada equipo, proyecto o entorno, una práctica llamada showback (informar los costos a los equipos) o chargeback (cobrar realmente a los equipos). AWS Cost Categories puede agrupar los costos en categorías comprensibles para el negocio usando etiquetas y cuentas.

Veamos un ejemplo práctico. Una empresa pregunta por qué sus informes de facturación no muestran costos para la etiqueta Project, aunque los ingenieros etiquetan todo. El administrador de facturación descubre que la etiqueta nunca se activó como etiqueta de asignación de costos, la activa, y los siguientes informes ya la incluyen. Finanzas quiere detalle a nivel de recurso para una revisión trimestral, así que el administrador crea una exportación de datos en formato CUR 2.0 hacia S3 y da a los analistas acceso a Athena para consultarla. Mientras tanto, las variaciones de ortografía como project y Project se corrigen con una política de etiquetas.

Errores comunes: esperar que las etiquetas aparezcan en los informes de facturación sin activarlas; confundir Cost Explorer (resúmenes y gráficos) con el CUR o las exportaciones de datos (las partidas más detalladas); claves de etiquetas inconsistentes que dividen los costos entre varias ortografías; y suponer que las cuentas miembro de una organización pagan por separado. Otra trampa es etiquetar solo algunos recursos: los elementos sin etiquetar, como los NAT gateways compartidos o la transferencia de datos, terminan en una categoría sin asignar, así que decide cómo se repartirán los costos compartidos.

En el examen, «los datos de facturación más detallados» o «partidas para análisis personalizado» significa Cost and Usage Reports o exportaciones de datos; «ver facturas o actualizar el método de pago» significa la consola Billing and Cost Management; «seguir los costos por departamento o proyecto» significa etiquetas de asignación de costos; y «faltan los costos etiquetados en los informes» significa que las etiquetas no se activaron.

Términos clave

Consola Billing and Cost Management
Consola central para facturas, pagos, preferencias de facturación y herramientas de costos.
Cost and Usage Report (CUR)
Los datos de facturación más detallados de AWS, entregados como archivos en S3, hasta el nivel de recurso individual.
Data Exports
Función de AWS para exportar datos de costo y uso, incluido CUR 2.0, a Amazon S3.
Etiqueta (tag)
Rótulo de clave-valor asociado a un recurso de AWS para organización, automatización o seguimiento de costos.
Etiqueta de asignación de costos
Etiqueta activada en la consola de facturación para que aparezca en los informes de costos y pueda filtrar y agrupar los costos.
Showback y chargeback
Informar los costos de la nube a los equipos que los generaron (showback) o cobrárselos internamente (chargeback).
Política de etiquetas (tag policy)
Política de AWS Organizations que estandariza las claves y los valores de las etiquetas entre cuentas.
Ejemplo real

El área central de TI de una universidad paga una sola factura de AWS para decenas de grupos de investigación. Exige que cada recurso lleve las etiquetas Grant y PI, activa ambas como etiquetas de asignación de costos y hace cumplir la ortografía con una política de etiquetas. Cada mes, una consulta de Athena sobre la exportación de datos del Cost and Usage Report produce un estado de costos por subvención, que la oficina de finanzas usa para cobrar a cada subvención de investigación exactamente lo que usó.

Consejo para el examen: Las etiquetas no aparecen en los informes de facturación hasta que se activan como etiquetas de asignación de costos en la consola de facturación. Para los datos de facturación más granulares, elige Cost and Usage Reports o exportaciones de datos, no Cost Explorer.

Comprueba lo que sabes

Los ingenieros etiquetan los recursos con Department, pero la etiqueta no aparece en Cost Explorer. ¿Por qué?

La etiqueta no se ha activado como etiqueta de asignación de costos en la consola de Billing and Cost Management.

¿Qué fuente de datos de facturación proporciona partidas a nivel de recurso para un análisis personalizado?

Los AWS Cost and Usage Reports, que ahora se entregan mediante Data Exports a Amazon S3.

¿Dónde descargaría un usuario de finanzas una factura o actualizaría el método de pago?

En la consola AWS Billing and Cost Management.

¿Cómo puede una organización asegurarse de que los equipos usen las mismas claves y valores de etiquetas?

Usando políticas de etiquetas en AWS Organizations, respaldadas por verificaciones como reglas de AWS Config o infraestructura como código.
