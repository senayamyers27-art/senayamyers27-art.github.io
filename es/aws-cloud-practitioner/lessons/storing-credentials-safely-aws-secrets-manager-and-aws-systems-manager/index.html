AWS Certified Cloud Practitioner CLF-C02

Guardar credenciales de forma segura: AWS Secrets Manager y AWS Systems Manager Parameter Store

Las aplicaciones necesitan secretos: contraseñas de bases de datos, claves de API de servicios de terceros, tokens y certificados. El peor lugar para guardarlos es el código fuente o los archivos de configuración en texto plano de un servidor, donde terminan copiados en repositorios de código, copias de seguridad, imágenes de contenedores y registros, y son difíciles de cambiar una vez que se filtran. AWS ofrece dos servicios para almacenar esos valores de forma centralizada y recuperarlos en tiempo de ejecución, con el acceso controlado por AWS Identity and Access Management (IAM): AWS Secrets Manager y AWS Systems Manager Parameter Store.

AWS Secrets Manager está diseñado específicamente para secretos. Almacenas un secreto, como un nombre de usuario y una contraseña de base de datos en formato JSON, y tu aplicación lo recupera con una llamada a la API cuando lo necesita, por ejemplo aws secretsmanager get-secret-value --secret-id prod/orders/db. El acceso se controla con políticas de IAM y políticas de recursos sobre el secreto, los secretos se cifran con AWS Key Management Service (AWS KMS) y cada recuperación queda registrada en AWS CloudTrail. Los secretos pueden replicarse a otras Regiones para aplicaciones multirregión. Secrets Manager se cobra por secreto al mes y por llamada a la API.

Su función más destacada es la rotación automática. Secrets Manager puede cambiar una contraseña según una programación que tú defines y actualizar la base de datos al mismo tiempo, de modo que la contraseña anterior deja de funcionar y las aplicaciones obtienen la nueva en su siguiente llamada. Tiene soporte integrado de rotación para Amazon RDS, Amazon Aurora, Amazon Redshift y Amazon DocumentDB, y usa funciones de rotación de AWS Lambda para otros tipos de secretos, como las claves de API de terceros. Algunos servicios de AWS, incluido Amazon RDS, también pueden crear y administrar por ti la contraseña del usuario maestro en Secrets Manager.

AWS Systems Manager Parameter Store es una capacidad de AWS Systems Manager que almacena datos de configuración y secretos como parámetros en una jerarquía, como /prod/app/db-host. Los parámetros pueden ser String, StringList o SecureString; los valores SecureString se cifran con KMS. Los recuperas con una llamada como aws ssm get-parameter --name /prod/app/db-password --with-decryption, o puedes obtener de una vez una rama completa de la jerarquía. Los parámetros estándar no tienen cargo adicional, mientras que los parámetros avanzados, que permiten valores más grandes y políticas de parámetros, sí se cobran. Parameter Store no ofrece rotación automática integrada como lo hace Secrets Manager.

Elegir entre ambos es una pregunta frecuente del examen. Si el requisito es la rotación automática de credenciales de bases de datos, elige Secrets Manager. Si el requisito es almacenar de forma centralizada valores de configuración, como indicadores de funcionalidades (feature flags), puntos de enlace o secretos simples, a bajo costo o sin costo, Parameter Store es una buena opción. Ambos sacan los secretos del código, ambos pueden usar cifrado de KMS, ambos registran el acceso mediante CloudTrail y ambos dependen de IAM para controlar quién puede leer cada valor. Uses el que uses, concede al rol de IAM de la aplicación permiso para leer solo los secretos o parámetros específicos que necesita, lo que es el mínimo privilegio aplicado a los secretos.

Veamos un ejemplo práctico. Un servicio de pedidos tiene la contraseña de su base de datos en un archivo de configuración subido a Git. Después de que el repositorio se hace público por accidente, el equipo rota la contraseña, la guarda en Secrets Manager con rotación automática cada 30 días y cambia la aplicación para que llame a GetSecretValue al iniciar, con una caché de corta duración. El nombre del host de la base de datos, la configuración de tiempos de espera y los indicadores de funcionalidades van a Parameter Store bajo /prod/orders/. El rol de IAM del servicio solo tiene permitido leer ese secreto y esa ruta de parámetros.

Errores comunes: guardar secretos como variables de entorno en texto plano o en el código 'solo por ahora'; elegir Parameter Store cuando la pregunta exige explícitamente la rotación automática; pensar que Secrets Manager es gratuito (se cobra por secreto y por llamada a la API); pensar que estos servicios reemplazan a IAM (dependen de él); y conceder a una aplicación secretsmanager:GetSecretValue sobre todos los secretos en lugar del único que necesita. Otra trampa es confundir estos servicios con AWS KMS: KMS administra claves de cifrado, mientras que Secrets Manager y Parameter Store almacenan los valores secretos que esas claves protegen. Por último, recuerda que la rotación solo sirve si las aplicaciones obtienen el valor actual en lugar de guardarlo en caché para siempre.

La redacción del examen suele ser decisiva. 'Rotar' o 'rotación' de credenciales de bases de datos es una señal fuerte de AWS Secrets Manager. 'Almacenar datos de configuración y secretos sin cargo adicional' o 'parámetros jerárquicos' apunta a Parameter Store. 'Eliminar credenciales codificadas en el código de la aplicación' puede ser cualquiera de los dos, así que busca la pista de la rotación o del costo. 'Administrar claves de cifrado' es KMS, no un almacén de secretos.

Términos clave

Secreto (secret)
Valor sensible, como una contraseña, una clave de API o un token, que debe protegerse contra su divulgación.
AWS Secrets Manager
Servicio que almacena, recupera y rota automáticamente secretos como las credenciales de bases de datos.
Rotación de secretos (secret rotation)
Cambiar una credencial según una programación y actualizar tanto el almacén como el sistema de destino.
AWS Systems Manager Parameter Store
Capacidad de Systems Manager que almacena datos de configuración y secretos como parámetros jerárquicos.
SecureString
Tipo de parámetro de Parameter Store cuyo valor se cifra con AWS KMS.
Credenciales codificadas (hard-coded credentials)
Secretos escritos directamente en el código fuente o en archivos de configuración, una práctica que debe evitarse.
Ejemplo real

Una auditoría de seguridad de una empresa de medios encuentra contraseñas de bases de datos en texto plano en decenas de imágenes de contenedores. La empresa traslada cada credencial de base de datos a Secrets Manager con rotación automática cada 30 días, guarda la configuración no sensible, como los puntos de enlace de API, en Parameter Store, y da al rol de IAM de cada servicio acceso solo a su propio secreto. Reconstruir una imagen ya no copia ninguna contraseña, y una contraseña antigua filtrada deja de funcionar en un mes como máximo.

Consejo para el examen: 'Rotar' o 'rotación' apunta a AWS Secrets Manager. 'Almacenar datos de configuración o secretos simples sin cargo adicional' apunta a Parameter Store. KMS administra claves, no valores secretos.

Comprueba lo que sabes

Una empresa necesita que las contraseñas de sus bases de datos se roten automáticamente cada 30 días. ¿Qué servicio se usa?

AWS Secrets Manager, que tiene rotación integrada para bases de datos como Amazon RDS.

¿Qué servicio puede almacenar valores de configuración en una jerarquía, con parámetros estándar sin cargo adicional?

AWS Systems Manager Parameter Store.

¿Cómo se protege un parámetro SecureString?

Su valor se cifra con una clave de AWS KMS, y el acceso se controla con IAM.

¿Por qué no deben codificarse los secretos en el código fuente de la aplicación?

Porque terminan copiados en repositorios, imágenes y copias de seguridad donde pueden filtrarse, y son difíciles de rotar una vez expuestos.
