AWS Certified Cloud Practitioner CLF-C02

Guardar credenciales de forma segura: AWS Secrets Manager y AWS Systems Manager Parameter Store

Las aplicaciones necesitan secretos: contraseñas de bases de datos, claves de API de servicios de terceros, tokens. El peor lugar para guardarlos es el código fuente o archivos de configuración en texto plano en un servidor, donde terminan copiados en repositorios, respaldos y registros. AWS ofrece dos servicios para almacenar esos valores de forma centralizada y recuperarlos en tiempo de ejecución con acceso controlado por IAM.

AWS Secrets Manager está diseñado específicamente para secretos. Almacenas un secreto, como el usuario y la contraseña de una base de datos, y tu aplicación lo recupera con una llamada de API cuando lo necesita. El acceso se controla con IAM y políticas de recursos, los secretos se cifran con AWS KMS y cada recuperación queda registrada en CloudTrail. Su función más destacada es la rotación automática: Secrets Manager puede cambiar una contraseña según un calendario y actualizar la base de datos al mismo tiempo, con soporte integrado para Amazon RDS, Amazon Aurora, Amazon Redshift y Amazon DocumentDB, y funciones Lambda para otros tipos de secretos. Los secretos también se pueden replicar a otras Regiones. Secrets Manager se cobra por secreto al mes y por llamada de API.

AWS Systems Manager Parameter Store es una capacidad de AWS Systems Manager que almacena datos de configuración y secretos como parámetros en una jerarquía, como /prod/app/db-host. Los parámetros pueden ser String, StringList o SecureString; los valores SecureString se cifran con KMS. Los parámetros estándar no tienen costo adicional, lo que hace que Parameter Store sea atractivo para valores de configuración y secretos simples. No ofrece rotación automática integrada como Secrets Manager.

Elegir entre ellos es una pregunta frecuente en el examen. Si el requisito es la rotación automática de credenciales de bases de datos, elige Secrets Manager. Si el requisito es almacenar valores de configuración o secretos simples de forma centralizada a bajo costo o sin costo, Parameter Store encaja bien. Ambos sacan los secretos del código, ambos usan cifrado con KMS y ambos dependen de IAM para controlar quién puede leer cada valor.

Uses el que uses, concede al rol de IAM de la aplicación permiso para leer solo los secretos o parámetros específicos que necesita, que es el mínimo privilegio aplicado a los secretos.

Términos clave

AWS Secrets Manager
Un servicio para almacenar, recuperar y rotar automáticamente secretos como credenciales de bases de datos y claves de API.
Parameter Store
Una capacidad de AWS Systems Manager para almacenar datos de configuración y secretos como parámetros jerárquicos.
SecureString
Un tipo de parámetro de Parameter Store cuyo valor se cifra con AWS KMS.
Secret rotation (rotación de secretos)
Cambiar periódicamente una credencial y actualizar todo lo que la usa, algo que Secrets Manager puede automatizar.
Ejemplo real

Un equipo de desarrollo encuentra una contraseña de la base de datos de producción confirmada (commit) en su repositorio Git. Cambia la contraseña, la guarda en Secrets Manager con rotación automática cada 30 días y actualiza la aplicación para que obtenga la credencial al iniciarse usando su rol de IAM. La configuración que no es secreta, como los indicadores de funciones (feature flags), va a Parameter Store como parámetros String simples.

Consejo para el examen: La palabra 'rotar' o 'rotación' en una pregunta es una señal fuerte de AWS Secrets Manager. 'Almacenar datos de configuración sin costo adicional' apunta a Parameter Store.

Comprueba lo que sabes

¿Qué servicio puede rotar automáticamente las credenciales de bases de datos de Amazon RDS?

AWS Secrets Manager.

¿Cómo se protegen los parámetros SecureString en Parameter Store?

Se cifran con AWS KMS, y el acceso se controla mediante IAM.
