AWS Certified Cloud Practitioner CLF-C02

Formas de usar AWS: AWS Management Console, AWS CLI, SDK, API e infraestructura como código con AWS CloudFormation

Todo lo que haces en AWS, ya sea crear un bucket, lanzar un servidor o leer una factura, es en última instancia una llamada a una interfaz de programación de aplicaciones (API) de un servicio de AWS. Cada solicitud se autentica con tus credenciales, se verifica contra tus permisos y normalmente queda registrada en AWS CloudTrail. Las distintas formas de usar AWS son simplemente distintas interfaces para esas mismas API. El examen te pide relacionar cada interfaz con el tipo de trabajo para el que sirve: explorar, automatizar con scripts, escribir aplicaciones o construir infraestructura repetible.

La AWS Management Console es la interfaz web. Inicias sesión desde un navegador, eliges una Región en el menú superior y usas asistentes y paneles. Es ideal para aprender, explorar un servicio nuevo, tareas puntuales y monitoreo visual, y la AWS Console Mobile Application te permite revisar recursos y alarmas desde cualquier lugar. La consola es fácil pero no es repetible: si debes construir el mismo entorno diez veces, hacerlo con clics diez veces es lento, propenso a errores y difícil de auditar. El inicio de sesión en la consola debe hacerse con un usuario de IAM Identity Center o un usuario de IAM con autenticación multifactor (MFA), nunca con el usuario raíz para el trabajo diario, y cada clic sigue convirtiéndose en una llamada a la API registrada en CloudTrail.

La AWS Command Line Interface (AWS CLI) te permite controlar los servicios escribiendo comandos en una terminal, lo que hace que las tareas se puedan automatizar con scripts. La configuras con aws configure (o, mejor aún, con inicio de sesión único mediante aws configure sso) y luego ejecutas comandos como aws s3 ls o aws ec2 describe-instances --region eu-west-1. AWS CloudShell es una shell en el navegador que se abre desde la consola, ya autenticada con tu identidad de la consola y con la CLI instalada, así que no necesitas configuración local ni claves almacenadas. La CLI muestra los resultados como JSON, texto o tablas, y la opción --query filtra la salida, lo que facilita pasar los resultados a otros scripts. El siguiente ejemplo crea un bucket, sube un archivo y lista el contenido.

aws s3 mb s3://example-lesson-bucket-12345
aws s3 cp report.csv s3://example-lesson-bucket-12345/
aws s3 ls s3://example-lesson-bucket-12345/

Los kits de desarrollo de software (SDK) permiten que el código de una aplicación llame a los servicios de AWS en lenguajes como Python (Boto3), JavaScript, Java, Go y .NET. El SDK firma cada solicitud, gestiona los reintentos y convierte las respuestas en objetos nativos, de modo que una app para compartir fotos puede subir archivos a S3 con una sola llamada a una función. Podrías llamar directamente a las API HTTPS, pero los SDK y la CLI son mucho más cómodos. La infraestructura como código (IaC) va más allá: con AWS CloudFormation describes recursos como una nube privada virtual (VPC), subredes, instancias y una base de datos en una plantilla JSON o YAML, y CloudFormation los crea juntos como una pila (stack), en el orden correcto, y puede actualizar o eliminar toda la pila de forma consistente. Las plantillas se pueden versionar y revisar como código. El AWS Cloud Development Kit (CDK) te permite escribir la misma infraestructura en un lenguaje de programación y genera CloudFormation por ti.

Veamos un ejemplo práctico. Un equipo construye su primer entorno de pruebas con clics en la consola, lo cual está bien para aprender. Cuando necesita entornos idénticos de desarrollo, pruebas y producción en dos Regiones, escribe una plantilla de CloudFormation y la implementa con aws cloudformation deploy --template-file app.yaml --stack-name shop-dev. Un ingeniero de operaciones usa la CLI en un script nocturno para copiar registros a S3, y la propia aplicación web usa el SDK de Python para guardar los archivos que suben los clientes. Cada herramienta se usa donde mejor encaja.

Errores comunes: creer que la consola y la CLI acceden a funciones distintas (llaman a las mismas API, aunque una función recién lanzada puede aparecer primero en una de ellas); pensar que CloudFormation es solo para empresas grandes; olvidar que eliminar una pila elimina los recursos que creó; guardar claves de acceso de largo plazo en laptops cuando bastaría con CloudShell o credenciales temporales; y confundir CloudFormation, que aprovisiona infraestructura, con AWS Elastic Beanstalk, que implementa una aplicación sobre infraestructura que administra por ti. Otra trampa es suponer que la CLI hace las cosas repetibles por sí sola; solo lo hacen los scripts o las plantillas guardados en control de versiones.

En el examen, «explorar un servicio» o «tarea puntual mediante una interfaz gráfica» apunta a la Management Console. «Automatizar tareas con scripts» o «terminal» apunta a la AWS CLI, y «sin instalar nada en la laptop» sugiere CloudShell. «Llamar a AWS desde el código de la aplicación» apunta a un SDK. «Implementar la misma infraestructura de forma repetida y consistente», «entre cuentas o Regiones», «plantillas» o «infraestructura como código» apuntan a AWS CloudFormation, y el CDK es la respuesta cuando los desarrolladores quieren un lenguaje de programación conocido.

Términos clave

AWS Management Console
Interfaz gráfica basada en navegador para administrar los servicios de AWS.
AWS CLI
Herramienta de línea de comandos para llamar a las API de los servicios de AWS desde una terminal o un script.
AWS CloudShell
Shell en el navegador, ya autenticada y con la AWS CLI instalada, que se abre desde la consola.
SDK
Kit de desarrollo de software: bibliotecas específicas de cada lenguaje que permiten que el código de una aplicación llame a las API de AWS.
Infraestructura como código (IaC)
Definir y aprovisionar infraestructura mediante plantillas o código legibles por máquina en lugar de pasos manuales.
AWS CloudFormation
Servicio de AWS que crea, actualiza y elimina recursos como una pila a partir de una plantilla JSON o YAML.
AWS CDK
El Cloud Development Kit, que define infraestructura en un lenguaje de programación y sintetiza plantillas de CloudFormation.
Ejemplo real

Una empresa de software incorpora un cliente nuevo cada semana, y cada cliente recibe un entorno aislado con una VPC, un balanceador de carga, una base de datos y monitoreo. Construir cada uno a mano en la consola tomaba un día y producía pequeñas diferencias que causaban caídas del servicio. El equipo plasmó el diseño en una plantilla de CloudFormation guardada en Git, y ahora un pipeline crea cada entorno como una pila en menos de una hora, idéntico cada vez, y lo elimina limpiamente cuando un cliente se va.

Consejo para el examen: Implementación repetible y consistente entre cuentas o Regiones, o «infraestructura como código», significa CloudFormation. La CLI automatiza tareas con scripts y los SDK son para el código de las aplicaciones; ninguno de los dos es la respuesta de IaC.

Comprueba lo que sabes

La aplicación de un desarrollador debe subir archivos a S3 desde código Python. ¿Qué método de acceso encaja?

Un AWS SDK (Boto3 para Python), que permite que el código de la aplicación llame a las API de AWS con la firma y los reintentos ya resueltos.

¿Qué servicio te permite definir una VPC, instancias y una base de datos en un archivo YAML y crearlos juntos?

AWS CloudFormation, que aprovisiona los recursos como una pila a partir de la plantilla.

¿Cómo puede un administrador ejecutar comandos de la CLI sin instalar ni configurar nada localmente?

Usando AWS CloudShell, una shell en el navegador ya autenticada y con la CLI instalada.

¿Por qué la consola es una mala opción para construir entornos de producción idénticos en tres Regiones?

Los clics manuales no son repetibles ni auditables, por lo que los entornos se desvían entre sí; un enfoque basado en plantillas como CloudFormation es consistente.
