AWS Certified Cloud Practitioner CLF-C02

Protección de red: security groups frente a network ACLs, AWS WAF, AWS Shield Standard y Advanced, AWS Firewall Manager

AWS te ofrece varias capas de protección de red, cada una trabajando en un nivel distinto: la interfaz de red, la subred, la solicitud web y la organización completa. Usarlas juntas se llama defensa en profundidad (defense in depth). El examen evalúa tanto las diferencias entre ellas como cuál usar ante una amenaza determinada, así que aprende cada una según dónde se ubica y lo que puede y no puede hacer.

Los security groups (grupos de seguridad) son firewalls virtuales para recursos como las instancias de Amazon EC2, más precisamente para sus interfaces de red elásticas. Solo admiten reglas de permiso; todo lo que no está permitido se deniega. Tienen estado (stateful): si se permite una solicitud entrante, la respuesta se permite automáticamente de salida, y viceversa. Todas las reglas se evalúan en conjunto, y una regla puede hacer referencia a otro security group, por ejemplo para permitir que el grupo de la base de datos acepte tráfico solo del grupo de los servidores web. Un comando típico es aws ec2 authorize-security-group-ingress --group-id <sg-id> --protocol tcp --port 443 --cidr 0.0.0.0/0 para permitir HTTPS desde cualquier lugar.

Las listas de control de acceso a la red (network ACLs) protegen subredes completas en una Amazon Virtual Private Cloud (Amazon VPC). Admiten reglas de permiso y de denegación, se evalúan en orden según el número de regla y gana la primera coincidencia, y no tienen estado (stateless): el tráfico de retorno debe permitirse explícitamente con una regla separada, lo que por lo general significa permitir el rango de puertos efímeros para las respuestas. La network ACL predeterminada permite todo el tráfico de entrada y de salida. Un diseño típico usa security groups para la mayor parte del control y network ACLs como respaldo general a nivel de subred, por ejemplo para bloquear un rango de direcciones específico que te está atacando.

AWS WAF es un firewall de aplicaciones web. Inspecciona las solicitudes HTTP y HTTPS en la capa 7 para recursos como las distribuciones de Amazon CloudFront, los Application Load Balancers y las API de Amazon API Gateway. Creas una lista de control de acceso web (web ACL) con reglas, o usas grupos de reglas administrados de AWS y de vendedores de AWS Marketplace, para bloquear ataques comunes como la inyección SQL y el cross-site scripting, filtrar por dirección IP o por país, y limitar la tasa de los clientes que envían demasiadas solicitudes. Los security groups y las network ACLs no pueden ver el interior de las solicitudes HTTP; WAF sí.

AWS Shield protege contra ataques de denegación de servicio distribuida (DDoS). Shield Standard está habilitado automáticamente para todos los clientes de AWS sin costo adicional y defiende contra los ataques más comunes de las capas de red y de transporte. Shield Advanced es una suscripción de pago que agrega detección y mitigación mejoradas para recursos como EC2, Elastic Load Balancing, CloudFront, Amazon Route 53 y AWS Global Accelerator, acceso al AWS Shield Response Team (SRT) durante los ataques, informes detallados de ataques, AWS WAF incluido para los recursos protegidos y protección de costos frente a los cargos de escalado causados por un ataque DDoS. AWS Firewall Manager configura y administra de forma centralizada las reglas de firewall en todas las cuentas de AWS Organizations: defines las políticas una vez, como un conjunto de reglas de WAF, la protección de Shield Advanced o los security groups obligatorios, y Firewall Manager las aplica automáticamente a las cuentas y recursos existentes y nuevos.

Veamos un ejemplo práctico. Una tienda en línea tiene tres problemas: un rango de IP que sondea todos los servidores, bots que intentan inyección SQL a través del cuadro de búsqueda y una gran inundación de tráfico antes de una venta. El equipo agrega una regla de denegación para el rango que sondea en la network ACL de las subredes públicas (los security groups no pueden denegar), adjunta a su Application Load Balancer una web ACL de AWS WAF con un grupo de reglas administrado contra la inyección SQL y una regla basada en tasa, y se suscribe a Shield Advanced para el balanceador de carga y la distribución de CloudFront para obtener ayuda del SRT y protección de costos. Luego Firewall Manager distribuye la misma política de WAF a las otras 15 cuentas de la empresa.

Errores comunes: intentar bloquear una dirección IP específica con un security group (no tiene reglas de denegación); olvidar que las network ACLs no tienen estado, de modo que permitir el puerto 443 de entrada sin permitir el tráfico de retorno de salida rompe las conexiones; esperar que WAF detenga las inundaciones de la capa de red (eso es Shield); pensar que Shield Standard debe comprarse o habilitarse (es automático y gratuito); y confundir Firewall Manager, que administra reglas entre cuentas, con un firewall que inspecciona el tráfico por sí mismo. AWS Network Firewall, un firewall administrado aparte para el tráfico de la VPC, también puede aparecer como distractor.

La redacción del examen se relaciona de forma directa. 'Con estado', 'solo reglas de permiso' o 'a nivel de instancia' significa security group. 'Sin estado', 'reglas de permiso y de denegación', 'a nivel de subred' o 'bloquear un rango de IP' significa network ACL. 'Inyección SQL', 'cross-site scripting', 'encabezados HTTP' o 'limitar la tasa de solicitudes web' significa AWS WAF. 'Protección DDoS sin costo adicional' es Shield Standard; 'equipo de respuesta DDoS disponible 24/7' o 'protección de costos' es Shield Advanced. 'Administrar de forma centralizada las reglas de firewall en las cuentas de AWS Organizations' es AWS Firewall Manager.

Términos clave

Security group (grupo de seguridad)
Firewall virtual con estado y solo de permisos, adjunto a las interfaces de red de recursos como las instancias EC2.
Network ACL
Firewall sin estado a nivel de subred con reglas numeradas de permiso y denegación que se evalúan en orden.
Con estado (stateful)
Permitir automáticamente el tráfico de retorno de una conexión permitida.
AWS WAF
Firewall de aplicaciones web que filtra las solicitudes HTTP y HTTPS dirigidas a CloudFront, balanceadores de carga y API.
Denegación de servicio distribuida (DDoS)
Ataque que inunda un objetivo con tráfico desde muchas fuentes para dejarlo sin disponibilidad.
AWS Shield
Protección contra DDoS, con Standard incluido para todos los clientes y Advanced como nivel de pago con acceso a un equipo de respuesta.
AWS Firewall Manager
Servicio que aplica de forma centralizada políticas de WAF, Shield Advanced y security groups en las cuentas de AWS Organizations.
Ejemplo real

El sitio de una empresa de venta de boletos se vuelve lento cada vez que sale a la venta un evento popular porque los bots bombardean la página de pago. La empresa adjunta a su distribución de CloudFront una web ACL de AWS WAF con una regla basada en tasa y reglas de control de bots, mantiene en sus instancias security groups que solo permiten tráfico del balanceador de carga, y se suscribe a Shield Advanced para que el Shield Response Team pueda ayudar durante los ataques grandes y queden cubiertos los costos de escalado inesperados.

Consejo para el examen: Con estado y solo de permisos significa security group; sin estado con permisos y denegaciones significa network ACL. Para bloquear una dirección IP a nivel de red necesitas una network ACL (o WAF para las solicitudes web), porque los security groups no pueden denegar.

Comprueba lo que sabes

¿Cuál tiene estado: un security group o una network ACL?

Un security group; el tráfico de retorno se permite automáticamente. Las network ACLs no tienen estado.

¿Cómo bloquearías un rango de IP malicioso específico para que no llegue a una subred?

Agregando una regla de denegación para ese rango en la network ACL de la subred, porque los security groups no tienen reglas de denegación.

¿Qué servicio protege una aplicación web contra la inyección SQL y el cross-site scripting?

AWS WAF, adjunto a CloudFront, a un Application Load Balancer o a API Gateway.

¿Qué agrega Shield Advanced frente a Shield Standard?

Detección y mitigación mejoradas, acceso al Shield Response Team, informes detallados de ataques y protección de costos frente al escalado causado por ataques DDoS.
