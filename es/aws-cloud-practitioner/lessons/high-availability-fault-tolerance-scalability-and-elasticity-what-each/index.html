Alta disponibilidad, tolerancia a fallos, escalabilidad y elasticidad: qué significa cada término y cómo lo ofrece AWS

Estos cuatro términos suenan parecidos, y el examen los usa deliberadamente como distractores entre sí. Aprender definiciones precisas y la función de AWS detrás de cada uno te dará puntos fáciles.

Alta disponibilidad (high availability) significa que un sistema permanece activo y utilizable la mayor parte del tiempo, con un tiempo de inactividad mínimo, incluso cuando fallan componentes individuales. Normalmente tolera una breve interrupción mientras el tráfico se traslada a recursos sanos. En AWS la logras ejecutando recursos en más de una Availability Zone (AZ, zona de disponibilidad), que son grupos separados de centros de datos dentro de una Región, y colocando un Elastic Load Balancer delante de ellos para que el tráfico solo vaya a destinos sanos. Una base de datos como Amazon RDS con despliegue Multi-AZ mantiene una instancia en espera en otra AZ y conmuta a ella automáticamente.

La tolerancia a fallos (fault tolerance) es una idea más estricta: el sistema sigue funcionando sin interrupción y sin pérdida de datos cuando falla un componente, porque los componentes redundantes ya están haciendo el trabajo. Piensa en un avión con varios motores. La tolerancia a fallos suele costar más porque pagas por capacidad totalmente redundante todo el tiempo. Muchos servicios administrados de AWS están construidos así internamente; por ejemplo, Amazon S3 almacena los objetos de forma redundante en varias AZ de una Región.

La escalabilidad (scalability) es la capacidad de un sistema de manejar más carga agregando recursos. Puedes escalar verticalmente (scale up) pasando a una instancia más grande con más CPU y memoria, u horizontalmente (scale out) agregando más instancias. En la nube se prefiere generalmente el escalado horizontal porque no existe el techo de una sola máquina y además mejora la disponibilidad. La elasticidad es escalabilidad que ocurre automáticamente en ambas direcciones, creciendo y reduciéndose con la demanda, de modo que pagas solo lo que la carga actual necesita. Amazon EC2 Auto Scaling, AWS Lambda y la capacidad bajo demanda de Amazon DynamoDB son ejemplos de servicios elásticos.

Un resumen útil: la alta disponibilidad trata de minimizar el tiempo de inactividad, la tolerancia a fallos trata de cero interrupciones, la escalabilidad trata de la capacidad de crecer y la elasticidad trata de crecer y reducirse automáticamente para ajustarse a la demanda.

Términos clave

High availability (alta disponibilidad)
Diseñar un sistema para que siga accesible con un tiempo de inactividad mínimo, normalmente ejecutándolo en varias Availability Zones.
Fault tolerance (tolerancia a fallos)
La capacidad de un sistema de seguir funcionando sin interrupción cuando fallan uno o más componentes.
Vertical scaling (escalado vertical)
Aumentar el tamaño de un solo recurso, por ejemplo pasar a un tipo de instancia con más CPU o memoria.
Horizontal scaling (escalado horizontal)
Agregar o quitar recursos del mismo tipo, como más instancias EC2 detrás de un balanceador de carga.
Elasticity (elasticidad)
Escalado automático hacia fuera y hacia dentro para que la capacidad siga de cerca a la demanda.
Ejemplo real

Una tienda en línea ejecuta su capa web en instancias EC2 en dos Availability Zones detrás de un Application Load Balancer, con un grupo de Auto Scaling que agrega instancias cuando el uso de CPU es alto y las quita durante la noche. Si una AZ tiene un problema, el balanceador de carga envía el tráfico a la otra AZ (alta disponibilidad), y el tamaño de la flota sigue a la demanda (elasticidad).

Consejo para el examen: Si una pregunta enfatiza 'ningún tiempo de inactividad' o 'sigue funcionando sin interrupción', la respuesta es tolerancia a fallos. Si enfatiza 'agrega y quita capacidad automáticamente según la demanda', la respuesta es elasticidad, no solo escalabilidad.

Comprueba lo que sabes

¿Cuál es el cambio de diseño más simple en AWS para que una aplicación web de una sola instancia sea altamente disponible?

Ejecutar instancias en al menos dos Availability Zones detrás de un Elastic Load Balancer, idealmente administradas por un grupo de Auto Scaling.

¿Cuál es la diferencia entre escalar hacia arriba (scale up) y escalar hacia fuera (scale out)?

Escalar hacia arriba (vertical) hace más grande un recurso; escalar hacia fuera (horizontal) agrega más recursos. Escalar hacia fuera evita el límite de una sola máquina y mejora la disponibilidad.
