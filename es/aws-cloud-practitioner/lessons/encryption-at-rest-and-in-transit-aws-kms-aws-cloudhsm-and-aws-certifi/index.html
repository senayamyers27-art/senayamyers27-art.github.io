AWS Certified Cloud Practitioner CLF-C02

Cifrado en reposo y en tránsito: AWS KMS, AWS CloudHSM y AWS Certificate Manager

El cifrado protege los datos para que solo alguien con la clave correcta pueda leerlos. Lo necesitas en dos lugares. El cifrado en reposo (encryption at rest) protege los datos almacenados, como los objetos en Amazon Simple Storage Service (Amazon S3), los volúmenes en Amazon Elastic Block Store (Amazon EBS) o las filas de una base de datos. El cifrado en tránsito (encryption in transit) protege los datos que se mueven por una red, normalmente con Transport Layer Security (TLS), que es lo que usa HTTPS. El examen Cloud Practitioner te pide elegir entre tres servicios que apoyan esto: AWS Key Management Service, AWS CloudHSM y AWS Certificate Manager.

AWS Key Management Service (AWS KMS) es el servicio administrado para crear y controlar claves de cifrado. La mayoría de los servicios de AWS que almacenan datos se integran con KMS, así que cifrar un volumen EBS o un bucket de S3 suele ser una sola opción de configuración. Las claves de KMS nunca salen del servicio sin cifrar; están protegidas por módulos de seguridad de hardware que opera AWS y que están validados según la norma FIPS 140. Controlas quién puede usar cada clave mediante políticas de claves (key policies) y políticas de IAM, y cada uso de una clave queda registrado en AWS CloudTrail, lo que te da un registro de auditoría de quién descifró qué.

KMS tiene tres tipos de claves que conviene conocer. Las claves propiedad de AWS (AWS owned keys) las usan los servicios de AWS internamente y son invisibles para ti. Las claves administradas por AWS (AWS managed keys) las crea un servicio en tu cuenta, con alias como aws/s3 o aws/ebs, y AWS administra su rotación. Las claves administradas por el cliente (customer managed keys) son claves que tú creas y controlas, incluidas su política de clave, su rotación automática y su eliminación programada; por ejemplo aws kms create-key --description "payroll data". Elige claves administradas por el cliente cuando necesites controlar el acceso a la clave misma, separar funciones o auditar su uso en detalle.

AWS CloudHSM proporciona módulos de seguridad de hardware (hardware security modules, HSM) dedicados en la nube de AWS. Un HSM es un dispositivo resistente a manipulaciones que almacena claves y realiza operaciones criptográficas. Con CloudHSM, los HSM de tu clúster son de un solo inquilino (single-tenant) y tú administras las claves y los usuarios del HSM; AWS administra el hardware pero no puede acceder a tus claves. Las organizaciones eligen CloudHSM cuando una regulación o un contrato exige hardware dedicado bajo su control exclusivo, o cuando una aplicación necesita interfaces estándar como PKCS#11, Java Cryptography Extension (JCE) o Microsoft CryptoAPI. KMS es más sencillo y está integrado con más servicios; CloudHSM da más control pero implica más trabajo operativo.

AWS Certificate Manager (ACM) aprovisiona, administra y despliega certificados TLS para el cifrado en tránsito. Solicitas un certificado público para un dominio, por ejemplo con aws acm request-certificate --domain-name www.example.com --validation-method DNS, demuestras que controlas el dominio mediante validación por DNS o por correo electrónico, y adjuntas el certificado a servicios integrados como Elastic Load Balancing, Amazon CloudFront o Amazon API Gateway. Los certificados públicos de ACM para estos servicios integrados se proporcionan sin cargo adicional, y ACM los renueva automáticamente, lo que elimina la clásica caída causada por una fecha de vencimiento olvidada.

Veamos un ejemplo práctico. Una empresa emergente de salud debe cifrar los expedientes de pacientes en reposo y en tránsito y mostrar a los auditores quién accedió a las claves. Crea una clave de KMS administrada por el cliente con una política de clave que solo permite usarla al rol de la aplicación, habilita la rotación automática y configura su bucket de S3 y su base de datos RDS para usar esa clave. CloudTrail registra cada llamada de descifrado. Solicita un certificado de ACM para su dominio y lo adjunta a su Application Load Balancer, para que los navegadores se conecten por HTTPS. Un banco socio con un requisito contractual de HSM dedicados usa CloudHSM en su lugar.

Errores comunes: pensar que ACM cifra los datos en reposo (proporciona certificados para los datos en tránsito); pensar que las claves de KMS pueden exportarse en texto plano (no se puede); elegir CloudHSM cuando la pregunta solo pide un cifrado fácil e integrado (la respuesta es KMS); y suponer que el cifrado predeterminado elimina todas tus obligaciones. Muchos servicios ahora cifran de forma predeterminada, por ejemplo los objetos nuevos en S3 se cifran automáticamente, pero decidir qué más cifrar, qué claves usar y quién puede usarlas sigue siendo responsabilidad del cliente según el modelo de responsabilidad compartida.

Las preguntas del examen dependen de palabras clave. 'Crear y administrar claves de cifrado integradas con los servicios de AWS' o 'auditar el uso de claves con CloudTrail' es KMS. 'HSM dedicado de un solo inquilino', 'hardware validado por FIPS bajo el control exclusivo del cliente' o 'AWS no debe tener acceso a las claves' es CloudHSM. 'Certificados SSL/TLS', 'HTTPS para un balanceador de carga' o 'renovación automática de certificados' es ACM. 'Proteger los datos almacenados en disco' significa en reposo; 'proteger los datos que se mueven entre el cliente y el servidor' significa en tránsito.

Términos clave

Cifrado en reposo (encryption at rest)
Cifrar los datos almacenados, como objetos de S3, volúmenes EBS y almacenamiento de bases de datos.
Cifrado en tránsito (encryption in transit)
Cifrar los datos mientras se mueven por una red, normalmente con TLS.
AWS Key Management Service (AWS KMS)
Servicio administrado para crear y controlar claves de cifrado, integrado con la mayoría de los servicios de AWS.
Clave administrada por el cliente (customer managed key)
Clave de KMS que creas y controlas, incluidas su política de clave, su rotación y su eliminación.
Módulo de seguridad de hardware (hardware security module, HSM)
Dispositivo resistente a manipulaciones que almacena claves y realiza operaciones criptográficas.
AWS CloudHSM
Servicio que proporciona HSM dedicados de un solo inquilino cuyas claves administra exclusivamente el cliente.
AWS Certificate Manager (ACM)
Servicio que aprovisiona, despliega y renueva automáticamente certificados TLS para los servicios de AWS.
Ejemplo real

El certificado de una tienda en línea venció en un fin de semana festivo y dejó el sitio fuera de línea durante horas. Después de pasarse a AWS, emite sus certificados mediante ACM y los adjunta a su balanceador de carga y a su distribución de CloudFront, y ACM los renueva automáticamente. Los datos de pedidos en S3 y Amazon RDS se cifran con una clave de KMS administrada por el cliente, y el equipo de seguridad revisa cada mes los registros de CloudTrail sobre el uso de claves.

Consejo para el examen: 'Claves administradas integradas con los servicios de AWS' es KMS; 'HSM dedicado de un solo inquilino' o 'control exclusivo del hardware' es CloudHSM; 'certificados SSL/TLS' es ACM. ACM es para los datos en tránsito, no en reposo.

Comprueba lo que sabes

¿Cuál es la diferencia entre el cifrado en reposo y en tránsito?

En reposo protege los datos almacenados, como discos y objetos; en tránsito protege los datos que se mueven por una red, normalmente con TLS.

Una regulación exige HSM de un solo inquilino bajo el control exclusivo de la empresa. ¿Qué servicio se usa?

AWS CloudHSM.

¿Qué servicio emite y renueva automáticamente certificados TLS para un balanceador de carga?

AWS Certificate Manager (ACM).

¿Cómo puedes ver quién usó una clave de KMS para descifrar datos?

Cada uso de una clave de KMS se registra en AWS CloudTrail, así que revisas los eventos de CloudTrail de esa clave.
