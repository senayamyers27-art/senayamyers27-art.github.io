AWS Certified Cloud Practitioner CLF-C02

Estrategias de licenciamiento (traer tu propia licencia frente a licencia incluida) y ajuste de tamaño para reducir el desperdicio

Las licencias de software pueden ser una parte importante de una factura de la nube, sobre todo en el caso de sistemas operativos y bases de datos comerciales, y el desperdicio causado por recursos sobredimensionados puede ser aún mayor. Esta lección cubre los dos grandes modelos de licenciamiento que ofrece AWS, el caso especial de las licencias ligadas a hardware físico y el ajuste de tamaño (rightsizing), el proceso continuo de hacer coincidir los recursos con lo que una carga de trabajo realmente necesita. El examen espera que sepas cuándo tiene sentido cada modelo de licenciamiento y qué herramientas recomiendan cambios de tamaño.

Con licencia incluida (license included), el costo de la licencia de software está incorporado en el precio por hora del recurso de AWS. Por ejemplo, puedes lanzar una instancia de Amazon Elastic Compute Cloud (Amazon EC2) a partir de una Amazon Machine Image (AMI) de Windows Server, o crear una base de datos de Amazon RDS for SQL Server, y la licencia forma parte de lo que le pagas a AWS. No tienes que comprar, controlar ni regularizar (true-up) licencias por tu cuenta, y dejas de pagar la licencia en cuanto dejas de usar el recurso. Este modelo es sencillo y se adapta a cargas de trabajo variables, de corta duración o nuevas para las que no tienes licencias existentes.

Con traer tu propia licencia (bring your own license, BYOL), usas licencias que ya posees y le pagas a AWS solo por la infraestructura. Esto puede ahorrar dinero si tu organización ya invirtió en licencias, por ejemplo mediante un acuerdo empresarial con el proveedor del software. Sin embargo, algunas licencias se cuentan por socket físico o por núcleo físico, o exigen que el software se ejecute en hardware dedicado a ti. Por eso AWS ofrece los Amazon EC2 Dedicated Hosts: servidores físicos totalmente dedicados a tu uso, con visibilidad de sockets y núcleos para que puedas cumplir esos términos de licencia. Revisa siempre los términos de licencia del proveedor antes de llevar una licencia a la nube. AWS License Manager ayuda a controlar el uso de licencias y a hacer cumplir los límites entre cuentas para que no excedas por accidente lo que posees. También existen opciones con licencia incluida para software que de otro modo podrías traer, así que compara ambos precios a lo largo de la vida esperada de la carga de trabajo antes de decidir.

El ajuste de tamaño (rightsizing) es el proceso de hacer coincidir los tipos y tamaños de instancia con la carga de trabajo real para no pagar por capacidad que no usas. Los equipos que vienen de instalaciones propias a menudo eligen tamaños de instancia que replican el hardware anterior, que por lo general estaba sobredimensionado para la demanda pico. Al observar datos reales de utilización, como el uso de CPU, memoria y red recopilado por Amazon CloudWatch, puedes pasar a un tamaño más pequeño o a otra familia de instancias. AWS Compute Optimizer analiza el uso y recomienda mejores tipos de instancia, configuraciones de grupos de Auto Scaling, volúmenes de Amazon EBS y tamaños de memoria de Lambda, y Cost Explorer ofrece recomendaciones de ajuste de tamaño para EC2.

# Ask Compute Optimizer for EC2 recommendations
aws compute-optimizer get-ec2-instance-recommendations

# Ask Cost Explorer for rightsizing recommendations
aws ce get-rightsizing-recommendation --service AmazonEC2

Veamos un ejemplo práctico. Una empresa migra veinte bases de datos SQL Server. Ya posee licencias de SQL Server cubiertas por un acuerdo que permite usarlas en hardware dedicado, así que para sus bases de datos de producción grandes y estables usa BYOL en Dedicated Hosts y controla el uso en License Manager. Para un puñado de bases de datos de proyectos pequeñas y de corta duración usa Amazon RDS con licencia incluida, para poder crearlas y eliminarlas libremente. Después de tres meses, Compute Optimizer muestra que la mayoría de los servidores de aplicaciones promedian menos del 15 por ciento de CPU, así que el equipo los pasa a tamaños más pequeños y a una generación de instancias más nueva.

Errores comunes: suponer que toda licencia puede llevarse a la nube (deciden los términos del proveedor, no AWS); confundir los Dedicated Hosts, que te dan un servidor físico completo con visibilidad de sockets y núcleos, con las Dedicated Instances, que se ejecutan en hardware de un solo inquilino pero sin esa visibilidad ni control sobre la ubicación; tratar el ajuste de tamaño como una tarea única durante la migración, cuando las cargas de trabajo y las generaciones de instancias siguen cambiando; y ajustar el tamaño solo según la CPU cuando la verdadera limitación es la memoria. Otras formas de reducir el desperdicio incluyen detener los recursos que no son de producción fuera del horario laboral y eliminar los volúmenes EBS no adjuntos y las instantáneas (snapshots) antiguas.

La redacción del examen suele ser directa. 'Licencias existentes ligadas a sockets o núcleos físicos' o 'software que debe ejecutarse en servidores físicos dedicados' apunta a Dedicated Hosts con BYOL. 'Evitar administrar licencias' o 'pagar la licencia por hora' apunta a instancias con licencia incluida. 'Controlar el uso de licencias y hacer cumplir límites' es AWS License Manager. 'Las instancias están infrautilizadas de forma constante' o 'recomendar tipos de instancia óptimos según el uso' es ajuste de tamaño con AWS Compute Optimizer o Cost Explorer.

Términos clave

Licencia incluida (license included)
Modelo en el que el costo de la licencia de software está incorporado en el precio del recurso de AWS.
Traer tu propia licencia (bring your own license, BYOL)
Usar en AWS licencias que ya posees y pagarle a AWS solo por la infraestructura.
Amazon EC2 Dedicated Host
Servidor físico dedicado a un solo cliente, con visibilidad de sockets y núcleos para cumplir con las licencias.
AWS License Manager
Servicio que controla el uso de licencias de software y hace cumplir las reglas de licenciamiento entre cuentas.
Ajuste de tamaño (rightsizing)
Hacer coincidir los tipos y tamaños de instancia con las necesidades reales de la carga de trabajo para eliminar capacidad pagada pero sin usar.
AWS Compute Optimizer
Servicio que analiza la utilización y recomienda recursos de cómputo de mejor tamaño.
Ejemplo real

Una firma de ingeniería trasladó sus servidores de licencias CAD a AWS y supuso que podía reutilizar sus licencias perpetuas en cualquier lugar. Los términos del proveedor exigían hardware físico dedicado contado por núcleos, así que la firma colocó esos servidores en un EC2 Dedicated Host y registró las reglas en License Manager. Para sus servidores de archivos Windows de uso general eligió instancias con licencia incluida, y luego usó los datos de Compute Optimizer para reducirlas dos tamaños después de un mes de monitoreo.

Consejo para el examen: Las licencias ligadas a sockets o núcleos físicos apuntan a Dedicated Hosts con BYOL; evitar la administración de licencias apunta a licencia incluida. Las recomendaciones de ajuste de tamaño provienen de Compute Optimizer y Cost Explorer.

Comprueba lo que sabes

¿Cuándo suele ser mejor opción la licencia incluida?

Cuando no tienes licencias existentes o la carga de trabajo es de corta duración o variable, porque pagas solo mientras el recurso está en funcionamiento y no tienes nada que controlar.

¿Por qué una empresa podría necesitar un EC2 Dedicated Host para BYOL?

Porque algunas licencias se cuentan por socket o núcleo físico o exigen hardware dedicado, y los Dedicated Hosts ofrecen esa visibilidad y ese control.

¿Qué servicio recomienda tipos de instancia más pequeños o distintos según la utilización real?

AWS Compute Optimizer (Cost Explorer también ofrece recomendaciones de ajuste de tamaño para EC2).

¿Por qué el ajuste de tamaño es un proceso continuo?

Porque las cargas de trabajo cambian y aparecen nuevas generaciones de instancias, así que el mejor tamaño y tipo cambian con el tiempo.
