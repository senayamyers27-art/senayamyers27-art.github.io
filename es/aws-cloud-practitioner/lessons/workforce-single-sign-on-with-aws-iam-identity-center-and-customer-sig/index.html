AWS Certified Cloud Practitioner CLF-C02

Inicio de sesión único para empleados con AWS IAM Identity Center e inicio de sesión de clientes con Amazon Cognito

Hay dos grupos muy distintos de personas que necesitan iniciar sesión en lo que construyes en AWS. Tu fuerza laboral (workforce), es decir, empleados y contratistas, necesita acceder a las cuentas de AWS y a las aplicaciones de negocio. Tus clientes, los usuarios finales de tus aplicaciones web y móviles, necesitan registrarse e iniciar sesión en esas aplicaciones. AWS tiene un servicio distinto para cada caso.

AWS IAM Identity Center (el sucesor de AWS Single Sign-On) es la forma recomendada de dar a tu fuerza laboral acceso a AWS. Se conecta a una fuente de identidad: su propio directorio integrado, Microsoft Active Directory o un proveedor de identidad externo como Microsoft Entra ID u Okta. Los usuarios inician sesión una sola vez en un portal de acceso de AWS y ven todas las cuentas y roles de AWS que tienen permitido usar, además de las aplicaciones de negocio integradas. El acceso se define con conjuntos de permisos (permission sets), que son colecciones de políticas que Identity Center convierte en roles de IAM en cada cuenta asignada. Los usuarios obtienen credenciales temporales, así que no hay contraseñas ni claves de usuarios de IAM de larga duración que administrar. Funciona especialmente bien con AWS Organizations, donde asignas acceso a muchas cuentas desde un solo lugar.

Amazon Cognito proporciona registro, inicio de sesión y control de acceso para tus propias aplicaciones web y móviles, y escala a cantidades muy grandes de usuarios. Un grupo de usuarios de Cognito (user pool) es un directorio de usuarios: gestiona el registro, el inicio de sesión, el restablecimiento de contraseñas, MFA y el inicio de sesión social o empresarial (por ejemplo, mediante Google, Apple, Facebook o un proveedor de identidad SAML), y devuelve tokens en los que confía tu aplicación. Un grupo de identidades de Cognito (identity pool) intercambia esos tokens por credenciales temporales de AWS, de modo que una aplicación móvil puede, por ejemplo, subir una foto directamente a S3 con permisos limitados.

La distinción clave en el examen es quién inicia sesión. 'Los empleados necesitan inicio de sesión único en varias cuentas de AWS' es IAM Identity Center. 'Los clientes de nuestra aplicación móvil necesitan crear cuentas e iniciar sesión con su identidad de redes sociales' es Amazon Cognito. Ninguno de los dos reemplaza a IAM; ambos dependen en última instancia de roles y políticas de IAM para otorgar permisos de AWS.

También puedes ver el término federación (federation), que significa confiar en identidades administradas por un proveedor de identidad externo en lugar de crear usuarios de AWS por separado. Ambos servicios admiten la federación, para públicos diferentes.

Términos clave

AWS IAM Identity Center
El servicio de inicio de sesión único para la fuerza laboral en varias cuentas de AWS y aplicaciones de negocio.
Permission set (conjunto de permisos)
Una plantilla de políticas en IAM Identity Center que define qué puede hacer un usuario en una cuenta de AWS asignada.
Amazon Cognito
Un servicio que agrega registro, inicio de sesión y control de acceso de usuarios a aplicaciones web y móviles.
User pool (grupo de usuarios)
Un directorio de usuarios de Cognito que gestiona el registro, el inicio de sesión y los tokens de los usuarios de una aplicación.
Federation (federación)
Confiar en identidades de un proveedor de identidad externo en lugar de crear usuarios separados en AWS.
Ejemplo real

Una empresa con 30 cuentas de AWS conecta IAM Identity Center a su directorio corporativo, de modo que los ingenieros inician sesión una vez y eligen la cuenta y el conjunto de permisos que necesitan. Por separado, su aplicación de fidelización de clientes usa un user pool de Cognito para que los compradores se registren con una dirección de correo o inicien sesión con su cuenta de Apple o Google.

Consejo para el examen: Fuerza laboral hacia cuentas de AWS es igual a IAM Identity Center; usuarios finales de una aplicación es igual a Cognito. Si la pregunta menciona 'millones de usuarios de una aplicación móvil' o 'proveedores de identidad sociales', elige Cognito.

Comprueba lo que sabes

Los empleados necesitan un solo inicio de sesión para acceder a varias cuentas de AWS de una organización. ¿Qué servicio debes usar?

AWS IAM Identity Center.

Un juego móvil necesita que los jugadores se registren e inicien sesión con sus cuentas de Google. ¿Qué servicio encaja?

Amazon Cognito (un user pool con un proveedor de identidad social).
