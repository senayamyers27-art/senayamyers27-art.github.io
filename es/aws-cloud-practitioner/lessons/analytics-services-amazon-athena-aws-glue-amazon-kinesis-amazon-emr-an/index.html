AWS Certified Cloud Practitioner CLF-C02

Servicios de análisis: Amazon Athena, AWS Glue, Amazon Kinesis, Amazon EMR y Amazon OpenSearch Service

Las empresas recopilan enormes volúmenes de datos, desde clics en sitios web hasta lecturas de sensores y registros de aplicaciones, y quieren convertirlos en conocimiento. Los servicios de análisis de AWS cubren cuatro trabajos: consultar los datos donde ya están, prepararlos y catalogarlos, procesarlos en tiempo real o en grandes lotes, y buscarlos y visualizarlos. Cada servicio tiene un nicho claro, y el examen evalúa si puedes elegir el correcto a partir de la descripción del trabajo.

Amazon Athena es un servicio de consultas interactivo y serverless que analiza datos directamente en Amazon S3 usando el lenguaje de consulta estructurado (SQL) estándar. No hay servidores ni clústeres que administrar ni datos que cargar: defines una tabla sobre archivos como CSV, JSON o Parquet y ejecutas una consulta como SELECT status, COUNT(*) FROM weblogs GROUP BY status;. Pagas según la cantidad de datos que escanea cada consulta, así que almacenar los datos en formatos comprimidos y columnares como Parquet y particionarlos por fecha reduce tanto el costo como el tiempo. Athena es ideal para el análisis ad hoc de registros y data lakes.

AWS Glue es un servicio de integración de datos serverless para extraer, transformar y cargar (ETL). Los rastreadores (crawlers) de Glue examinan las fuentes de datos, infieren su estructura y registran los esquemas como tablas en el AWS Glue Data Catalog, un repositorio central de metadatos que pueden usar Athena, Amazon EMR y Amazon Redshift. Luego, los trabajos (jobs) de Glue limpian, transforman y mueven datos entre almacenes, por ejemplo convirtiendo archivos CSV sin procesar en Parquet particionado para consultarlos de forma eficiente. AWS Glue DataBrew ofrece preparación visual de datos sin código.

Amazon Kinesis maneja datos en streaming en tiempo real. Amazon Kinesis Data Streams captura y almacena flujos de registros, como clickstreams, registros de aplicaciones o telemetría de Internet de las cosas (IoT), para que varias aplicaciones consumidoras puedan procesarlos en segundos. Amazon Data Firehose (antes Kinesis Data Firehose) es la opción más sencilla: carga datos en streaming en destinos como S3, Redshift o Amazon OpenSearch Service sin código, y opcionalmente los agrupa en lotes y los comprime. Kinesis Video Streams ingiere video de cámaras conectadas.

Amazon EMR es una plataforma administrada de big data para ejecutar frameworks de código abierto como Apache Spark, Apache Hadoop, Hive y Presto en clústeres escalables, o en un modo serverless, para procesamiento a gran escala como análisis de registros, preparación de datos para ML y simulaciones financieras. Elígelo cuando un equipo ya usa estos frameworks o necesita un control detallado sobre el procesamiento de big data. Amazon OpenSearch Service es un servicio administrado para OpenSearch (y el Elasticsearch heredado), usado para búsqueda de texto completo, análisis de registros y paneles operativos. Amazon QuickSight ofrece paneles y visualizaciones de inteligencia de negocios (BI), y Amazon Managed Streaming for Apache Kafka (Amazon MSK) ejecuta Kafka para los equipos que lo prefieren sobre Kinesis.

Veamos un ejemplo práctico. Un sitio de noticias quiere entender el comportamiento de sus lectores. Los eventos de visitas a páginas llegan en streaming a Kinesis Data Streams, y un consumidor actualiza una lista de «tendencias ahora» en segundos. Data Firehose también entrega los mismos eventos a S3 cada pocos minutos. Un rastreador de Glue cataloga los archivos y un trabajo nocturno de Glue los convierte a Parquet. Los analistas ejecutan consultas ad hoc en Athena, como «¿qué artículos terminaron de leer los lectores móviles?», mientras que un equipo de ingeniería de datos usa EMR con Spark para construir modelos de intereses de los lectores. Los editores revisan paneles de QuickSight, y el cuadro de búsqueda del sitio funciona con OpenSearch Service.

Errores comunes: confundir Athena y Redshift (ambos ejecutan SQL, pero Athena consulta archivos en S3 bajo demanda, mientras que Redshift es un almacén de datos al que cargas los datos para analítica intensiva y repetida); pensar que Glue consulta datos (cataloga y transforma; Athena consulta); elegir EMR cuando bastaría una entrega sin código con Firehose o una simple consulta en Athena; y tratar Kinesis como procesamiento por lotes cuando su propósito es el tiempo real. Otra trampa es usar OpenSearch Service como almacén de datos; destaca en búsqueda y análisis de registros más que en informes relacionales complejos.

Las palabras clave del examen se relacionan de forma clara. «Consultas SQL sobre datos en S3 sin servidores» o «pago por consulta» significa Athena. «ETL», «catálogo de datos», «rastreador» o «descubrir el esquema» significa Glue. «Streaming en tiempo real», «clickstream» o «ingerir datos en segundos» significa Kinesis, con Data Firehose para «cargar datos en streaming en S3 o Redshift sin código». «Hadoop», «Spark» o «clústeres de big data» significa EMR. «Búsqueda de texto completo» o «paneles de análisis de registros» significa OpenSearch Service. «Paneles de inteligencia de negocios» significa QuickSight. «Almacén de datos» significa Redshift.

Términos clave

Amazon Athena
Servicio serverless para consultar datos en S3 con SQL estándar, facturado según los datos escaneados.
AWS Glue
Servicio de integración de datos serverless para ETL, con rastreadores y un Data Catalog central.
ETL
Extraer, transformar y cargar: mover datos desde las fuentes, darles nueva forma y cargarlos en un almacén de destino.
AWS Glue Data Catalog
Repositorio central de metadatos con definiciones de tablas que usan Athena, EMR y Redshift.
Amazon Kinesis Data Streams
Servicio para capturar y procesar registros de datos en streaming en tiempo real.
Amazon Data Firehose
Servicio que carga datos en streaming en destinos como S3 y Redshift sin código personalizado.
Amazon EMR
Plataforma administrada para frameworks de big data como Apache Spark y Hadoop.
Amazon OpenSearch Service
Servicio administrado para búsqueda, análisis de registros y paneles operativos.
Ejemplo real

Un equipo de seguridad conserva meses de VPC Flow Logs y registros de CloudTrail en S3. En lugar de construir una base de datos, ejecuta un rastreador de Glue para crear tablas y usa Athena para responder preguntas como «¿qué direcciones IP fueron rechazadas con más frecuencia la semana pasada?», pagando solo por los datos que escanea cada consulta. Después de convertir los registros a Parquet con un trabajo de Glue, las mismas consultas escanean muchos menos datos y cuestan mucho menos.

Consejo para el examen: Athena y Redshift ejecutan SQL. Athena consulta archivos en S3 bajo demanda sin nada que cargar; Redshift es un almacén de datos al que cargas los datos para analítica intensiva y repetida.

Comprueba lo que sabes

Un equipo quiere ejecutar consultas SQL ocasionales sobre archivos de registro en S3 sin administrar ningún servidor. ¿Qué servicio?

Amazon Athena.

¿Qué servicio descubre el esquema de los datos en S3 y lo guarda en un catálogo central?

AWS Glue, mediante rastreadores y el Glue Data Catalog.

Un sitio web debe procesar eventos de clickstream en segundos. ¿Qué familia de servicios encaja?

Amazon Kinesis (Kinesis Data Streams para el procesamiento en tiempo real).

Un equipo de datos ya usa Apache Spark y Hadoop. ¿Qué servicio administrado le permite ejecutarlos en AWS?

Amazon EMR.
