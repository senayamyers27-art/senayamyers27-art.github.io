AWS Certified Cloud Practitioner CLF-C02

Registro y monitoreo para la seguridad: AWS CloudTrail, Amazon CloudWatch y las verificaciones de seguridad de AWS Trusted Advisor

No puedes proteger lo que no puedes ver. Tres servicios te dan visibilidad de lo que ocurre en tu cuenta de AWS, y el examen espera que sepas qué registra cada uno.

AWS CloudTrail registra la actividad de API en tu cuenta: quién hizo qué, cuándo, desde dónde y sobre qué recurso. Toda acción en AWS, ya sea desde la consola, la CLI, un SDK u otro servicio, es una llamada de API, así que CloudTrail responde preguntas como '¿quién eliminó este bucket de S3?' o '¿quién cambió este security group?'. El Event history de CloudTrail muestra sin costo los últimos 90 días de eventos de administración en una Región. Para una retención más larga, análisis y eventos de datos (como lecturas individuales de objetos de S3), creas un trail (registro de seguimiento) que entrega los registros a un bucket de S3, opcionalmente con validación de integridad de los archivos de registro para poder demostrar que no se alteraron. Un organization trail puede registrar todas las cuentas de AWS Organizations.

Amazon CloudWatch monitorea el rendimiento y el estado de tus recursos y aplicaciones. Recopila métricas (como el uso de CPU de EC2), almacena y permite buscar registros en CloudWatch Logs, y te deja configurar alarmas que te notifican mediante Amazon SNS o ejecutan una acción automática cuando una métrica cruza un umbral. Para la seguridad, puedes enviar los registros de CloudTrail a CloudWatch Logs y crear filtros de métricas y alarmas para eventos como inicios de sesión del usuario raíz o inicios de sesión fallidos repetidos en la consola. En resumen: CloudTrail te dice quién hizo algo; CloudWatch te dice cómo están funcionando las cosas y te alerta.

AWS Trusted Advisor inspecciona tu cuenta y da recomendaciones en categorías que incluyen seguridad, optimización de costos, rendimiento, tolerancia a fallos, límites de servicio (cuotas) y excelencia operativa. Las verificaciones de seguridad incluyen buckets de S3 con permisos de acceso abiertos, security groups que permiten acceso sin restricciones a puertos específicos, si MFA está habilitado en el usuario raíz y claves de acceso expuestas. Un conjunto básico de verificaciones está disponible para todos los clientes, mientras que el conjunto completo requiere un plan de soporte Business o superior.

Una configuración madura los combina: CloudTrail para auditoría, CloudWatch para alertas, Trusted Advisor para verificaciones de buenas prácticas y GuardDuty para analizar los registros de CloudTrail y de red en busca de amenazas.

Términos clave

AWS CloudTrail
Un servicio que registra las llamadas de API y la actividad de la cuenta para auditoría, gobernanza e investigación.
Trail (registro de seguimiento)
Una configuración de CloudTrail que entrega los registros de eventos a un bucket de S3 para su retención a largo plazo.
Amazon CloudWatch
Un servicio de monitoreo para métricas, registros y alarmas sobre recursos y aplicaciones de AWS.
CloudWatch alarm (alarma de CloudWatch)
Una regla que vigila una métrica y dispara notificaciones o acciones cuando se cruza un umbral.
AWS Trusted Advisor
Un servicio que verifica una cuenta frente a buenas prácticas de seguridad, costos, rendimiento, resiliencia y cuotas.
Ejemplo real

Un security group de producción de repente permite SSH desde cualquier lugar. Una verificación de Trusted Advisor señala el acceso sin restricciones, CloudTrail muestra qué rol de IAM hizo el cambio y desde qué dirección IP, y el equipo agrega una alarma de CloudWatch sobre un filtro de métricas para recibir una alerta la próxima vez que se modifique un security group.

Consejo para el examen: '¿Quién hizo este cambio?' o 'auditar llamadas de API' es CloudTrail. 'Uso de CPU', 'configurar una alarma' o 'recopilar registros de la aplicación' es CloudWatch. Confundirlos es uno de los errores más comunes en Cloud Practitioner.

Comprueba lo que sabes

¿Qué servicio mostraría qué usuario terminó ayer una instancia EC2?

AWS CloudTrail.

¿Cómo recibirías una notificación cuando el uso de CPU de una instancia se mantiene por encima del 80 por ciento?

Creando una alarma de Amazon CloudWatch sobre la métrica CPUUtilization que notifique a un tema (topic) de SNS.
