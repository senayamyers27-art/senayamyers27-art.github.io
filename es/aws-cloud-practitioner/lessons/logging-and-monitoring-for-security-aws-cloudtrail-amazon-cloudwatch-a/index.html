AWS Certified Cloud Practitioner CLF-C02

Registro y monitoreo para la seguridad: AWS CloudTrail, Amazon CloudWatch y las verificaciones de seguridad de AWS Trusted Advisor

No puedes proteger lo que no puedes ver. Tres servicios te dan visibilidad de lo que ocurre en tu cuenta de AWS, cada uno desde un ángulo distinto: AWS CloudTrail registra quién hizo qué, Amazon CloudWatch mide el rendimiento de los recursos y genera alarmas, y AWS Trusted Advisor revisa tu cuenta según las buenas prácticas. El examen espera que sepas qué registra cada uno, y con frecuencia los pone uno junto al otro como opciones.

AWS CloudTrail registra la actividad de la API en tu cuenta: quién hizo qué, cuándo, desde qué dirección IP y sobre qué recurso. Cada acción en AWS, ya sea mediante la consola, la interfaz de línea de comandos (CLI), un kit de desarrollo de software (SDK) u otro servicio de AWS, es una llamada a la API, así que CloudTrail responde preguntas como '¿quién eliminó este bucket de S3?' o '¿quién cambió este security group?'. El Event history de CloudTrail muestra sin cargo los últimos 90 días de eventos de administración en una Región; puedes buscar en él desde la consola en CloudTrail > Event history o con aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=DeleteBucket.

Para una retención más larga y más detalle, creas un registro de seguimiento (trail) que entrega los archivos de registro a un bucket de S3 que tú eliges. Los trails pueden incluir eventos de datos, como las lecturas individuales de objetos de S3 o las invocaciones de Lambda, que no se registran de forma predeterminada por su volumen. Habilita la validación de integridad de los archivos de registro para poder demostrar que los registros no se alteraron, y restringe el acceso al bucket de registros. Un trail de organización registra todas las cuentas de AWS Organizations en un solo lugar, y CloudTrail Lake te permite almacenar y consultar eventos con SQL.

Amazon CloudWatch monitorea el rendimiento y el estado de tus recursos y aplicaciones. Recopila métricas, como el uso de CPU de EC2 o el número de solicitudes de un balanceador de carga, almacena y permite buscar registros en CloudWatch Logs, y te permite crear paneles y configurar alarmas que te notifican mediante Amazon Simple Notification Service (Amazon SNS) o toman una acción automática, como escalar o recuperar una instancia, cuando una métrica cruza un umbral. Para la seguridad, puedes enviar los registros de CloudTrail a CloudWatch Logs y crear filtros de métricas y alarmas para eventos como los inicios de sesión del usuario raíz, los cambios en las políticas de IAM o los intentos fallidos repetidos de inicio de sesión en la consola. En resumen: CloudTrail te dice quién hizo algo; CloudWatch te dice cómo está funcionando todo y te alerta.

AWS Trusted Advisor inspecciona tu cuenta y ofrece recomendaciones en categorías que incluyen optimización de costos, rendimiento, seguridad, tolerancia a fallos, límites de servicio (cuotas de servicio) y excelencia operativa. Las verificaciones de seguridad incluyen los buckets de S3 con permisos de acceso abiertos, los security groups que permiten acceso sin restricciones a puertos específicos, si la MFA está habilitada en el usuario raíz, el uso de IAM y las claves de acceso expuestas. Todos los clientes obtienen un conjunto básico de verificaciones de seguridad y las verificaciones de cuotas de servicio, mientras que el conjunto completo de verificaciones, además del acceso programático mediante la AWS Support API, requiere un plan de soporte Business, Enterprise On-Ramp o Enterprise.

Veamos un ejemplo práctico. El lunes por la mañana un security group de producción permite SSH desde todo internet. La verificación semanal de Trusted Advisor ya lo había marcado como acceso sin restricciones. El equipo busca AuthorizeSecurityGroupIngress en el Event history de CloudTrail y descubre que el rol de un contratista agregó la regla el viernes por la noche desde una dirección IP desconocida. Quitan la regla y luego crean un filtro de métricas de CloudWatch sobre el grupo de registros de CloudTrail para los cambios en security groups, con una alarma que envía un correo al equipo de seguridad mediante SNS. GuardDuty, que analiza los mismos registros de CloudTrail y de red en busca de amenazas, confirma que no hay más actividad sospechosa.

Errores comunes: elegir CloudWatch para averiguar quién hizo un cambio (eso es CloudTrail); elegir CloudTrail para monitorear el uso de CPU o configurar una alarma por umbral (eso es CloudWatch); suponer que CloudTrail conserva los eventos para siempre sin un trail (el Event history cubre 90 días de eventos de administración); suponer que los eventos de datos, como las lecturas de objetos de S3, se registran de forma predeterminada; y pensar que Trusted Advisor corrige los problemas por ti. Recomienda; tú actúas. Evita también confundir Trusted Advisor con AWS Config, que registra el historial de configuración y evalúa tus propias reglas.

La redacción del examen suele delatar la respuesta. '¿Quién hizo este cambio?', 'auditar llamadas a la API' o 'dar seguimiento a la actividad de los usuarios' es CloudTrail. 'Uso de CPU', 'configurar una alarma', 'recopilar registros de aplicaciones' o 'panel de métricas' es CloudWatch. 'Recomendaciones para reducir costos, mejorar la seguridad y verificar los límites de servicio' o 'identificar security groups con acceso sin restricciones' es Trusted Advisor. 'Conjunto completo de verificaciones de Trusted Advisor' implica soporte Business o superior. Confundir CloudTrail con CloudWatch es uno de los errores más comunes en Cloud Practitioner, así que ve más despacio en esas preguntas.

Términos clave

AWS CloudTrail
Servicio que registra las llamadas a la API y la actividad de la cuenta, mostrando quién hizo qué, cuándo y desde dónde.
Event history
Vista de la consola de CloudTrail con los últimos 90 días de eventos de administración en una Región, disponible sin cargo.
Trail (registro de seguimiento)
Configuración de CloudTrail que entrega archivos de registro a un bucket de S3 para su retención y análisis a largo plazo.
Amazon CloudWatch
Servicio de monitoreo de métricas, registros, paneles y alarmas.
Alarma de CloudWatch (CloudWatch alarm)
Vigilancia sobre una métrica que notifica o toma una acción cuando se cruza un umbral.
Filtro de métricas (metric filter)
Patrón de CloudWatch Logs que convierte los eventos de registro coincidentes en una métrica sobre la que puedes crear alarmas.
AWS Trusted Advisor
Servicio que revisa tu cuenta según buenas prácticas de costos, rendimiento, seguridad, tolerancia a fallos, límites de servicio y excelencia operativa.
Ejemplo real

La base de datos de una empresa de comercio electrónico se eliminó durante un fin de semana y nadie sabía cómo. Su trail de organización mostró que la llamada DeleteDBInstance provino del rol de un desarrollador durante una prueba de automatización que salió mal. Luego la empresa agregó la protección contra eliminación, creó una alarma de CloudWatch sobre los eventos de CloudTrail de eliminación de bases de datos y revisó las verificaciones de seguridad de Trusted Advisor, que además revelaron dos security groups abiertos a internet.

Consejo para el examen: '¿Quién hizo este cambio?' o 'auditar llamadas a la API' es CloudTrail. 'Uso de CPU', 'configurar una alarma' o 'recopilar registros de aplicaciones' es CloudWatch. 'Recomendaciones de buenas prácticas, incluidos security groups abiertos y MFA en el usuario raíz' es Trusted Advisor.

Comprueba lo que sabes

¿Qué servicio te dice qué identidad de IAM eliminó un bucket de S3?

AWS CloudTrail, que registra las llamadas a la API con la identidad de quien llama, la hora y la IP de origen.

¿Cómo puedes recibir una alerta cuando el usuario raíz inicia sesión?

Enviando los registros de CloudTrail a CloudWatch Logs, creando un filtro de métricas para los eventos de inicio de sesión raíz y configurando una alarma de CloudWatch que notifique mediante SNS (una regla de EventBridge también sirve).

¿Cuánto tiempo hacia atrás cubre el Event history de CloudTrail sin crear un trail?

90 días de eventos de administración en la Región.

¿Qué se necesita para obtener el conjunto completo de verificaciones de Trusted Advisor?

Un plan de soporte Business, Enterprise On-Ramp o Enterprise; los demás clientes obtienen las verificaciones básicas de seguridad y de cuotas de servicio.
