AWS Certified Cloud Practitioner CLF-C02

Estrategias de migración (las 7 R): rehost, replatform, refactor, repurchase, retire, retain y relocate

Cuando una organización traslada sus aplicaciones a AWS, rara vez las trata a todas igual. Algunas se mueven tal como están, otras se mejoran en el camino y otras se apagan. AWS describe siete estrategias de migración comunes, conocidas como las 7 R. Durante la planificación de la migración, a cada aplicación del portafolio se le asigna una de ellas según su valor para el negocio, su complejidad técnica, su licenciamiento y el tiempo disponible. El examen te presenta un escenario y te pregunta qué estrategia describe.

Rehost, a menudo llamado lift and shift (levantar y trasladar), mueve una aplicación a AWS sin cambiarla, por ejemplo copiando un servidor tal cual a Amazon Elastic Compute Cloud (Amazon EC2). Es rápido, permite migrar grandes cantidades de servidores con rapidez y a menudo puede automatizarse con AWS Application Migration Service. Puedes optimizar después, una vez que los servidores estén funcionando en la nube. Replatform, a veces llamado lift, tinker and shift (levantar, ajustar y trasladar), hace algunas optimizaciones para la nube sin cambiar la arquitectura central. El ejemplo clásico es trasladar una base de datos autoadministrada a Amazon Relational Database Service (Amazon RDS) para que AWS se encargue de los parches y las copias de seguridad.

Refactor, también llamado re-architect (rediseñar la arquitectura), replantea cómo está construida la aplicación, normalmente usando funciones nativas de la nube como funciones sin servidor, contenedores, colas administradas o bases de datos diseñadas para un propósito específico. Es la que requiere más tiempo y esfuerzo, pero puede aportar el mayor beneficio en escalabilidad, agilidad y costo, y suele estar impulsada por una necesidad de negocio fuerte que la arquitectura actual no puede satisfacer. Repurchase, a veces llamado drop and shop (dejar y comprar), significa pasar a un producto diferente, por lo general reemplazando una aplicación alojada por la propia empresa con una oferta de software como servicio (SaaS), como abandonar un sistema de gestión de relaciones con clientes (CRM) en las instalaciones propias por uno SaaS.

Retire significa dar de baja las aplicaciones que ya no son útiles; el descubrimiento del portafolio suele encontrar una cantidad sorprendente de servidores que nadie usa, y apagarlos ahorra dinero de inmediato. Retain, a veces llamado revisit (volver a revisar), significa mantener una aplicación donde está por ahora, tal vez porque se actualizó recientemente, depende de hardware o licencias que no pueden trasladarse, tiene restricciones de cumplimiento o simplemente todavía no vale la pena migrarla. Relocate significa trasladar infraestructura a la nube sin comprar hardware nuevo, reescribir aplicaciones ni cambiar las operaciones, por ejemplo mover cargas de trabajo basadas en VMware vSphere a VMware Cloud on AWS.

Las diferencias clave tienen que ver con cuánto cambia la aplicación. Rehost no cambia nada de la aplicación. Relocate traslada una plataforma de virtualización completa junto con ella, también sin cambiar las aplicaciones. Replatform cambia uno o dos componentes, como el alojamiento de la base de datos o el sistema operativo, mientras la arquitectura permanece igual. Refactor cambia la arquitectura misma. Repurchase reemplaza la aplicación por un producto diferente. Retire y retain no migran la aplicación en absoluto. El esfuerzo y el beneficio potencial suelen aumentar desde rehost hacia refactor. Por eso muchas organizaciones primero hacen rehost para cumplir un plazo y luego hacen replatform o refactor de las aplicaciones más valiosas una vez que están funcionando en AWS, un enfoque que a veces se describe como migrar primero y modernizar después.

Veamos un ejemplo práctico. Una empresa evalúa 300 servidores. Cuarenta resultan no usarse y se apagan (retire). Sus sistemas de correo electrónico y de RR. HH. se reemplazan por productos SaaS (repurchase). Un sistema de facturación en mainframe se queda en el centro de datos hasta que otro proyecto lo reemplace (retain). Doscientos servidores de aplicaciones se copian a EC2 con Application Migration Service para cumplir el plazo de salida del centro de datos (rehost). La base de datos principal de clientes pasa a Amazon RDS (replatform). El sistema de pedidos, que tiene problemas en los picos, se reconstruye con contenedores, AWS Lambda y Amazon DynamoDB (refactor).

Errores comunes: llamar refactor a un traslado a RDS cuando la aplicación en sí no cambia (es replatform); llamar rehost a un cambio a SaaS; confundir retain (mantenerla por ahora) con retire (apagarla); y confundir relocate con rehost. Relocate traslada a nivel del hipervisor, conservando la misma plataforma de virtualización y las mismas operaciones, mientras que rehost traslada servidores individuales a EC2. Ten en cuenta además que el material antiguo de AWS describía seis R; relocate es la séptima y está en el examen actual.

Las preguntas del examen dependen de frases clave. 'Sin cambios de código, lo más rápido posible' o 'lift and shift' es rehost. 'Optimizaciones menores, como pasar a una base de datos administrada' es replatform. 'Reconstruir usando servicios nativos de la nube' o 'dividir un monolito en microservicios' es refactor. 'Cambiar a un producto SaaS' es repurchase. 'Dar de baja' o 'apagarla' es retire. 'Mantenerla en las instalaciones propias por ahora' es retain. 'Trasladar cargas de trabajo de VMware sin cambiar las operaciones' es relocate.

Términos clave

Rehost (lift and shift)
Trasladar una aplicación a AWS sin cambios, normalmente a Amazon EC2.
Replatform (lift, tinker and shift)
Trasladar con algunas optimizaciones para la nube, como una base de datos administrada, manteniendo la arquitectura central.
Refactor (re-architect)
Rediseñar una aplicación para usar funciones nativas de la nube, como la computación sin servidor o los contenedores.
Repurchase (drop and shop)
Reemplazar una aplicación por un producto diferente, por lo general una oferta SaaS.
Retire
Dar de baja una aplicación que ya no se necesita.
Retain (revisit)
Mantener una aplicación en su entorno actual por ahora.
Relocate
Trasladar infraestructura, como cargas de trabajo basadas en VMware, a la nube sin cambiar las aplicaciones ni las operaciones.
Ejemplo real

Una empresa de logística debe dejar su centro de datos arrendado en nueve meses. Hace rehost de la mayoría de sus servidores de aplicaciones a EC2 para cumplir el plazo, hace replatform de sus bases de datos PostgreSQL a Amazon RDS, retira una docena de servidores de informes que no se usan y mantiene en sus instalaciones un sistema de control de almacén que depende de hardware local (retain). Un año después, con el plazo ya cumplido, hace refactor de su servicio de rastreo convirtiéndolo en funciones sin servidor para manejar los picos de las fiestas.

Consejo para el examen: Trasladar una base de datos a Amazon RDS sin rediseñar la aplicación es replatform; reescribir un monolito como microservicios o funciones sin servidor es refactor. Retain conserva una aplicación; retire la elimina.

Comprueba lo que sabes

Una aplicación se traslada a EC2 sin cambios de código para cumplir un plazo. ¿Qué estrategia es?

Rehost, también llamado lift and shift.

Una empresa reemplaza su CRM en instalaciones propias por un producto SaaS. ¿Qué estrategia es?

Repurchase, pasar a un producto diferente.

¿Qué distingue a replatform de refactor?

Replatform hace algunas optimizaciones, como una base de datos administrada, sin cambiar la arquitectura; refactor rediseña la aplicación usando funciones nativas de la nube.

¿Qué estrategia traslada cargas de trabajo basadas en VMware a AWS sin cambiar las aplicaciones ni las operaciones?

Relocate, por ejemplo a VMware Cloud on AWS.
