AWS Certified Cloud Practitioner CLF-C02

Estrategias de migración (las 7 R): rehost, replatform, refactor, repurchase, retire, retain y relocate

Cuando una organización traslada sus aplicaciones a AWS, rara vez las trata todas de la misma manera. AWS describe siete estrategias de migración comunes, conocidas como las 7 R. Durante la planificación de la migración, a cada aplicación del portafolio se le asigna una de ellas según su valor para el negocio, su complejidad y el tiempo disponible.

Rehost (realojar), a menudo llamado lift and shift, traslada una aplicación a AWS sin modificarla, por ejemplo copiando un servidor tal cual a Amazon EC2. Es rápido y permite migrar grandes cantidades de servidores en poco tiempo, y puedes optimizar después, una vez que estén funcionando en la nube. Replatform (cambiar de plataforma), a veces llamado lift, tinker and shift, aplica algunas optimizaciones para la nube sin cambiar la arquitectura central; el ejemplo clásico es mover una base de datos autoadministrada a Amazon RDS para que AWS se encargue de los parches y los respaldos.

Refactor (refactorizar), también llamado re-architect, replantea cómo está construida la aplicación, normalmente usando funciones nativas de la nube como funciones serverless, contenedores o bases de datos administradas. Requiere el mayor esfuerzo, pero puede aportar el mayor beneficio en escalabilidad, agilidad y costo. Repurchase (recomprar) significa pasar a un producto diferente, normalmente reemplazando una aplicación autoalojada por una oferta de software como servicio (SaaS), como abandonar un sistema local de gestión de relaciones con clientes (CRM) por uno SaaS.

Retire (retirar) significa dar de baja aplicaciones que ya no se necesitan; las revisiones de portafolio suelen encontrar una cantidad sorprendente de ellas. Retain (retener), o revisit (revisar más adelante), significa mantener una aplicación donde está por ahora, quizá porque se actualizó recientemente, depende de hardware que no se puede mover o todavía no vale la pena migrarla. Relocate (reubicar) significa mover infraestructura a la nube sin comprar hardware nuevo, reescribir aplicaciones ni cambiar las operaciones, por ejemplo trasladar cargas de trabajo basadas en VMware a un entorno VMware que se ejecuta en AWS.

En el examen, identifica las frases clave: 'sin cambios de código, lo más rápido posible' es rehost; 'optimizaciones menores, como una base de datos administrada' es replatform; 'reconstruir usando servicios nativos de la nube' es refactor; 'cambiar a un producto SaaS' es repurchase; 'apagarla' es retire; 'mantenerla en las instalaciones propias por ahora' es retain.

Términos clave

Rehost (realojar)
Lift and shift: trasladar una aplicación a la nube sin modificarla.
Replatform (cambiar de plataforma)
Aplicar algunas optimizaciones para la nube, como una base de datos administrada, sin cambiar la arquitectura central de la aplicación.
Refactor (refactorizar)
Rediseñar la arquitectura de una aplicación para usar funciones nativas de la nube; el mayor esfuerzo y a menudo el mayor beneficio.
Repurchase (recomprar)
Reemplazar una aplicación por un producto diferente, normalmente una oferta SaaS.
Retain (retener)
Mantener una aplicación en su entorno actual por ahora y revisar la decisión más adelante.
Ejemplo real

Un minorista revisa 200 aplicaciones. Hace rehost de 120 servidores web estándar a EC2 para cumplir el plazo del contrato de arrendamiento de su centro de datos, hace replatform de su base de datos de productos a Amazon RDS, hace repurchase de su sistema interno de correo electrónico como producto SaaS, retira 25 herramientas de informes que nadie usa y retiene un mainframe que revisará el año próximo.

Consejo para el examen: Replatform frente a refactor es la trampa clásica. Mover una base de datos a RDS sin rediseñar la aplicación es replatform; reescribir un monolito como microservicios o funciones serverless es refactor.

Comprueba lo que sabes

Una empresa debe dejar su centro de datos en tres meses y quiere mover cientos de servidores sin modificarlos. ¿Qué estrategia encaja mejor?

Rehost (lift and shift), porque es la más rápida y no requiere cambios en las aplicaciones.

Reemplazar una aplicación local de recursos humanos por un producto SaaS, ¿qué estrategia de migración es?

Repurchase (recomprar).
