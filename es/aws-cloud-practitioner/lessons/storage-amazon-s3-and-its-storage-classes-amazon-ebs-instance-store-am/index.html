AWS Certified Cloud Practitioner CLF-C02

Almacenamiento: Amazon S3 y sus clases de almacenamiento, Amazon EBS, instance store, Amazon EFS, Amazon FSx, AWS Storage Gateway y AWS Backup

AWS ofrece tres tipos de almacenamiento: de objetos, de bloques y de archivos. El almacenamiento de objetos guarda archivos completos con metadatos y se accede a ellos por HTTPS mediante una clave; el almacenamiento de bloques presenta volúmenes sin formato que un sistema operativo formatea, como un disco duro; el almacenamiento de archivos presenta un sistema de archivos compartido que muchas máquinas montan mediante un protocolo de red. Elegir correctamente depende de cómo se accede a los datos, cuántas máquinas los necesitan y cuánto tiempo deben durar, y el examen te pide con frecuencia hacer esa correspondencia.

Amazon Simple Storage Service (Amazon S3) es almacenamiento de objetos. Guardas objetos en buckets y accedes a ellos por clave, por ejemplo con aws s3 cp backup.zip s3://my-bucket/2025/. Escala prácticamente sin límite y está diseñado para una durabilidad del 99,999999999 por ciento (once nueves) al almacenar los datos de forma redundante en varias AZ. Es adecuado para copias de seguridad, data lakes, contenido estático de sitios web y medios. Las clases de almacenamiento equilibran precio y patrones de acceso: S3 Standard para datos de acceso frecuente; S3 Intelligent-Tiering, que mueve objetos entre niveles de acceso automáticamente cuando los patrones son desconocidos; S3 Standard-Infrequent Access (Standard-IA) para datos que se leen poco pero se necesitan rápido; S3 One Zone-IA, más barata pero almacenada en una sola AZ; y las clases de archivo S3 Glacier Instant Retrieval, S3 Glacier Flexible Retrieval (de minutos a horas) y S3 Glacier Deep Archive, la clase de menor costo, con recuperación en horas. Las reglas de ciclo de vida mueven o hacen expirar objetos automáticamente a medida que envejecen, y el control de versiones protege contra sobrescrituras accidentales.

Amazon Elastic Block Store (Amazon EBS) ofrece volúmenes de almacenamiento de bloques que se conectan a instancias EC2 como discos duros virtuales, usados para volúmenes de arranque y bases de datos. Un volumen reside en una AZ y persiste independientemente de la instancia, así que los datos sobreviven a una detención, y sobreviven a la terminación si el volumen está configurado para no eliminarse. Puedes tomar instantáneas (snapshots) de un punto en el tiempo, que AWS almacena de forma duradera y que pueden copiarse entre Regiones. El instance store es almacenamiento de bloques temporal conectado físicamente al host. Es muy rápido, pero sus datos se pierden cuando la instancia se detiene, hiberna o termina, así que úsalo solo para cachés, búferes y datos temporales.

Amazon Elastic File System (Amazon EFS) es un sistema de archivos administrado y elástico que usa el protocolo Network File System (NFS) y que muchas instancias Linux, contenedores y funciones Lambda pueden montar a la vez, en varias AZ, creciendo y reduciéndose automáticamente. Amazon FSx ofrece sistemas de archivos de terceros totalmente administrados: FSx for Windows File Server (protocolo Server Message Block, o SMB, con integración con Active Directory), FSx for Lustre (computación de alto rendimiento), FSx for NetApp ONTAP y FSx for OpenZFS.

AWS Storage Gateway es un servicio de almacenamiento híbrido que da a las aplicaciones locales acceso al almacenamiento en la nube: S3 File Gateway presenta S3 como un recurso compartido de archivos, Volume Gateway presenta volúmenes de bloques respaldados en AWS, y Tape Gateway reemplaza las cintas de respaldo físicas con cintas virtuales almacenadas en AWS. AWS Backup administra y automatiza de forma centralizada las copias de seguridad de servicios como EBS, RDS, DynamoDB, EFS, FSx y S3, mediante planes de respaldo que definen programaciones, retención y copias a otras Regiones o cuentas. Ayuda a demostrar a los auditores que las copias de seguridad siguen la política.

Veamos un ejemplo práctico. Una agencia de diseño ejecuta servidores de renderizado Linux que necesitan todos los mismos archivos de proyecto, así que monta EFS en cada servidor. El volumen de arranque de cada servidor es EBS, y el espacio temporal de renderizado usa instance store rápido porque puede recrearse. Los videos terminados van a S3 Standard, y una regla de ciclo de vida los mueve a Glacier Flexible Retrieval después de 90 días y a Glacier Deep Archive después de un año. La antigua biblioteca de cintas de la oficina se reemplaza con Tape Gateway, y AWS Backup toma copias diarias de EBS y EFS con una retención de 35 días.

Errores comunes: guardar datos importantes en instance store; esperar que un volumen EBS se conecte a una instancia en otra AZ (en su lugar, restaura allí una instantánea); elegir EFS para recursos compartidos de archivos de Windows (usa FSx for Windows File Server); suponer que One Zone-IA sobrevive a la pérdida de una AZ; y elegir Glacier Deep Archive para datos que se necesitan en minutos. Otra trampa es pensar que S3 es un sistema de archivos que montas como EFS; es almacenamiento de objetos al que se accede mediante una API, aunque algunas herramientas puedan hacer que parezca una carpeta.

En el examen, relaciona los patrones de acceso. «Almacenamiento de archivos compartido para muchas instancias Linux» es EFS; «recursos compartidos de archivos de Windows» o «SMB con Active Directory» es FSx for Windows File Server; «sistema de archivos para computación de alto rendimiento» es FSx for Lustre. «Disco de arranque o de base de datos para una instancia» es EBS. «Almacenamiento local temporal y más rápido» es instance store. «Almacenamiento de objetos ilimitado», «sitio web estático» o «data lake» es S3. «Archivo de largo plazo de menor costo, con recuperación en horas» es Glacier Deep Archive; «patrones de acceso desconocidos» es Intelligent-Tiering. «Acceso local al almacenamiento en la nube» o «cintas virtuales» es Storage Gateway, y «administrar de forma centralizada las copias de seguridad de varios servicios» es AWS Backup.

Términos clave

Amazon S3
Almacenamiento de objetos que guarda los datos como objetos en buckets, diseñado para una durabilidad de once nueves.
Clases de almacenamiento de S3
Niveles de precio para objetos de S3 según la frecuencia de acceso y las necesidades de recuperación, desde Standard hasta Glacier Deep Archive.
Regla de ciclo de vida
Política de S3 que transfiere objetos a clases más baratas o los elimina a medida que envejecen.
Amazon EBS
Volúmenes persistentes de almacenamiento de bloques que se conectan a instancias EC2 dentro de una Availability Zone.
Instance store
Almacenamiento de bloques temporal en el host cuyos datos se pierden cuando la instancia se detiene o termina.
Amazon EFS
Sistema de archivos NFS administrado y elástico que muchos clientes Linux pueden montar a la vez en varias AZ.
Amazon FSx
Sistemas de archivos de terceros totalmente administrados, como Windows File Server y Lustre.
AWS Storage Gateway
Servicio híbrido que da a las aplicaciones locales acceso al almacenamiento de AWS como archivos, volúmenes o cintas virtuales.
Ejemplo real

Un hospital debe conservar imágenes médicas durante muchos años, pero rara vez las vuelve a abrir después del primer mes. Almacena las imágenes nuevas en S3 Standard, y una regla de ciclo de vida las mueve a S3 Glacier Instant Retrieval después de 30 días, porque ocasionalmente un médico necesita un estudio antiguo en milisegundos. Los registros que superan el mínimo legal de uso activo pasan a Glacier Deep Archive, y AWS Backup protege los volúmenes EBS de los servidores de imágenes.

Consejo para el examen: El almacenamiento de archivos compartido para Linux es EFS; los recursos compartidos de archivos de Windows son FSx for Windows File Server; el disco de una sola instancia es EBS. Nunca guardes en instance store datos que deban sobrevivir a una detención.

Comprueba lo que sabes

Varias instancias EC2 Linux en distintas AZ necesitan leer y escribir los mismos archivos. ¿Qué servicio encaja?

Amazon EFS, un sistema de archivos NFS compartido que se puede montar en varias AZ.

¿Qué pasa con los datos del instance store cuando se detiene la instancia?

Se pierden, porque el instance store es almacenamiento temporal ligado al host físico.

¿Qué clase de almacenamiento de S3 es adecuada para datos con patrones de acceso impredecibles?

S3 Intelligent-Tiering, que mueve los objetos entre niveles automáticamente.

Una empresa quiere reemplazar sus cintas de respaldo físicas con almacenamiento en la nube sin dejar de usar su software de respaldo. ¿Qué debe usar?

AWS Storage Gateway en modo Tape Gateway, que presenta cintas virtuales almacenadas en AWS.
