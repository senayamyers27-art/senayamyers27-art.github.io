AWS Certified Cloud Practitioner CLF-C02

Almacenamiento: Amazon S3 y sus clases de almacenamiento, Amazon EBS, instance store, Amazon EFS, Amazon FSx, AWS Storage Gateway y AWS Backup

AWS ofrece tres tipos de almacenamiento: de objetos, de bloques y de archivos. Elegir correctamente depende de cómo se accede a los datos.

Amazon Simple Storage Service (Amazon S3) es almacenamiento de objetos. Guardas objetos (archivos más metadatos) en buckets y accedes a ellos por HTTPS mediante una clave. Escala prácticamente sin límite, está diseñado para una durabilidad del 99.999999999 por ciento (once nueves) al almacenar los datos de forma redundante en varias AZ, y se adapta a respaldos, data lakes, contenido de sitios web estáticos y medios. Las clases de almacenamiento equilibran el precio frente a los patrones de acceso: S3 Standard para datos de acceso frecuente; S3 Intelligent-Tiering, que mueve objetos entre niveles automáticamente cuando los patrones de acceso son desconocidos; S3 Standard-Infrequent Access (Standard-IA) para datos que se leen rara vez pero se necesitan rápido; S3 One Zone-IA, que es más barata pero guarda los datos en una sola AZ; y las clases de archivo S3 Glacier Instant Retrieval, S3 Glacier Flexible Retrieval y S3 Glacier Deep Archive, la clase de menor costo, cuya recuperación tarda horas. Las reglas de ciclo de vida (lifecycle rules) pueden mover objetos entre clases automáticamente a medida que envejecen.

Amazon Elastic Block Store (Amazon EBS) proporciona volúmenes de almacenamiento en bloques que se conectan a instancias EC2, como discos duros virtuales. Un volumen reside en una AZ y persiste de forma independiente de la instancia, así que los datos sobreviven a una detención o terminación si se conserva el volumen. Puedes tomar instantáneas (snapshots), que se almacenan en S3 y pueden copiarse entre Regiones. El instance store es almacenamiento en bloques temporal conectado físicamente al host; es muy rápido, pero sus datos se pierden cuando la instancia se detiene, hiberna o termina, así que úsalo solo para cachés, búferes y datos temporales.

Amazon Elastic File System (Amazon EFS) es un sistema de archivos administrado y elástico que usa el protocolo NFS y que muchas instancias Linux, contenedores y funciones Lambda pueden montar a la vez, en varias AZ. Amazon FSx proporciona sistemas de archivos de terceros totalmente administrados: FSx for Windows File Server (SMB, integración con Active Directory), FSx for Lustre (computación de alto rendimiento), FSx for NetApp ONTAP y FSx for OpenZFS.

AWS Storage Gateway es un servicio de almacenamiento híbrido que da a las aplicaciones locales acceso al almacenamiento en la nube, con tipos como S3 File Gateway, Volume Gateway y Tape Gateway (que reemplaza las cintas de respaldo físicas por cintas virtuales almacenadas en AWS). AWS Backup administra y automatiza de forma centralizada los respaldos de servicios como EBS, RDS, DynamoDB, EFS y S3, con planes de respaldo y políticas de retención.

Términos clave

Amazon S3
Almacenamiento de objetos con escala prácticamente ilimitada y muy alta durabilidad, organizado en buckets.
S3 Glacier Deep Archive
La clase de almacenamiento de S3 de menor costo, para archivos a largo plazo cuya recuperación puede tardar horas.
Amazon EBS
Volúmenes de almacenamiento en bloques persistentes para instancias EC2, limitados a una sola Availability Zone.
Instance store
Almacenamiento en bloques temporal en el host físico cuyos datos se pierden cuando la instancia se detiene o termina.
Amazon EFS
Un sistema de archivos NFS administrado que muchos clientes Linux pueden montar simultáneamente en varias AZ.
AWS Storage Gateway
Un servicio híbrido que conecta aplicaciones locales con el almacenamiento en la nube de AWS.
Ejemplo real

Un despacho de abogados guarda los documentos de sus casos en S3 Standard, con una regla de ciclo de vida que mueve los archivos a S3 Glacier Deep Archive después de dos años. Sus servidores de gestión documental usan volúmenes EBS, los usuarios de Windows comparten archivos en FSx for Windows File Server, la antigua biblioteca de cintas se reemplaza por Tape Gateway y AWS Backup aplica un plan de respaldo diario a todo ello.

Consejo para el examen: El almacenamiento de archivos compartido para muchas instancias Linux es EFS; para Windows es FSx for Windows File Server. El disco de arranque o de base de datos de una sola instancia es EBS. Los datos que deben sobrevivir a la detención de la instancia nunca deben depender del instance store.

Comprueba lo que sabes

¿Qué clase de almacenamiento de S3 es la opción más barata para datos que se conservan durante años y rara vez, o nunca, se recuperan?

S3 Glacier Deep Archive.

¿Qué ocurre con los datos de un volumen de instance store cuando se detiene la instancia EC2?

Se pierden; el instance store es temporal. Usa EBS para los datos que deben persistir.
