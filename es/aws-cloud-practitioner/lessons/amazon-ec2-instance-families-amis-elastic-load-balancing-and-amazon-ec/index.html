AWS Certified Cloud Practitioner CLF-C02

Familias de instancias de Amazon EC2, AMI, Elastic Load Balancing y Amazon EC2 Auto Scaling

Amazon Elastic Compute Cloud (Amazon EC2) ofrece servidores virtuales redimensionables llamados instancias. Eliges el sistema operativo, el tamaño y la configuración, y obtienes control total, incluido el acceso de administrador o root. Según el modelo de responsabilidad compartida, ese control significa que eres responsable de aplicar parches y proteger el sistema operativo invitado, configurar los grupos de seguridad y administrar el software que instales. EC2 es infraestructura como servicio (IaaS): AWS opera el hardware y la virtualización, y tú operas todo lo que está por encima.

Los tipos de instancia se agrupan en familias optimizadas para distintas cargas de trabajo. Las instancias de uso general equilibran cómputo, memoria y redes, y sirven para servidores web y repositorios de código. Las instancias optimizadas para cómputo tienen procesadores de alto rendimiento para procesamiento por lotes, servidores de juegos, transcodificación de medios y modelado científico. Las instancias optimizadas para memoria sirven para bases de datos en memoria y analítica de big data en tiempo real. Las instancias de computación acelerada usan aceleradores de hardware como unidades de procesamiento gráfico (GPU) para aprendizaje automático, gráficos y otros trabajos en paralelo. Las instancias optimizadas para almacenamiento ofrecen un rendimiento de almacenamiento local alto y de baja latencia para almacenes de datos y grandes bases de datos transaccionales. Un nombre de tipo como m7g.large codifica la letra de la familia, la generación, atributos opcionales y el tamaño.

Una Amazon Machine Image (AMI) es la plantilla que se usa para lanzar una instancia. Contiene el sistema operativo, el software preinstalado y la configuración. Puedes usar AMI proporcionadas por AWS, suscribirte a AMI en AWS Marketplace o crear las tuyas a partir de una instancia configurada, para que cada servidor nuevo arranque idéntico, un componente básico para la automatización y Auto Scaling. Las AMI son regionales, pero puedes copiarlas a otras Regiones.

Elastic Load Balancing (ELB) distribuye automáticamente el tráfico entrante entre destinos, como instancias EC2 en varias Availability Zones, y envía tráfico solo a los destinos que pasan las comprobaciones de estado. El Application Load Balancer (ALB) funciona en la capa 7 para HTTP y HTTPS y puede enrutar por ruta de URL o nombre de host, por ejemplo enviando /api/* a un grupo e /images/* a otro. El Network Load Balancer (NLB) funciona en la capa 4 para TCP y UDP, maneja un rendimiento muy alto con baja latencia y admite direcciones IP estáticas. El Gateway Load Balancer (GWLB) implementa y escala appliances virtuales de terceros, como firewalls.

Amazon EC2 Auto Scaling agrega o quita instancias automáticamente en un grupo de Auto Scaling para ajustarse a la demanda. Defines una capacidad mínima, máxima y deseada, lo apuntas a una plantilla de lanzamiento (launch template) que indica la AMI y el tipo de instancia, y agregas políticas de escalado como el seguimiento de objetivos (target tracking) para mantener el uso promedio de CPU cerca del 50 por ciento, o el escalado programado para periodos de alta demanda conocidos. Auto Scaling también reemplaza las instancias que fallan las comprobaciones de estado. Juntos, ELB y Auto Scaling te dan una capa web elástica y altamente disponible: la capacidad crece en los picos, se reduce cuando está inactiva para que dejes de pagar por ella y se repara sola.

Veamos un ejemplo práctico. Un vendedor de boletos en línea tiene semanas tranquilas y picos repentinos cuando salen a la venta los conciertos. Construye una AMI base (golden AMI) con su aplicación, crea una plantilla de lanzamiento con instancias de uso general y define un grupo de Auto Scaling en tres AZ con un mínimo de dos instancias y un máximo de veinte. Un ALB enruta /checkout y /search a grupos de destino separados. Cuando abren las ventas, la CPU sube, el seguimiento de objetivos agrega instancias y el ALB reparte el tráfico entre ellas. Durante la noche el grupo vuelve a reducirse a dos, y una instancia que falla se reemplaza automáticamente.

Errores comunes: olvidar que en EC2 el cliente aplica los parches al sistema operativo invitado; elegir una familia por su nombre en lugar de por la carga de trabajo (las bases de datos en memoria necesitan instancias optimizadas para memoria, no para cómputo); suponer que un balanceador de carga por sí solo agrega capacidad (Auto Scaling agrega instancias; ELB reparte el tráfico); elegir el NLB cuando se necesita enrutamiento HTTP basado en rutas; y ejecutar todo en una sola AZ, lo que anula el propósito del balanceo de carga. Otra trampa es pensar que Auto Scaling solo escala hacia afuera; también escala hacia adentro para ahorrar dinero.

En el examen, relaciona las palabras clave. «Base de datos en memoria» o «grandes conjuntos de datos en memoria» significa optimizada para memoria. «Procesamiento por lotes», «computación de alto rendimiento» o «servidores de juegos» significa optimizada para cómputo. «Entrenamiento de aprendizaje automático» o «gráficos» significa computación acelerada. «Lectura y escritura secuencial alta en almacenamiento local» significa optimizada para almacenamiento. «Plantilla para lanzar instancias idénticas» es una AMI. «Distribuir el tráfico entre instancias en buen estado» es ELB, con ALB para «enrutamiento HTTP por ruta o host» y NLB para «rendimiento extremo» o «IP estática». «Agregar o quitar instancias automáticamente según la demanda» es EC2 Auto Scaling.

Términos clave

Amazon EC2
Servicio de AWS que ofrece servidores virtuales redimensionables llamados instancias.
Familia de instancias
Grupo de tipos de instancia optimizados para un tipo de carga de trabajo, como cómputo, memoria o almacenamiento.
AMI
Amazon Machine Image: la plantilla con sistema operativo, software y configuración que se usa para lanzar una instancia.
Elastic Load Balancing (ELB)
Servicio que distribuye el tráfico entre destinos en buen estado en varias Availability Zones.
Application Load Balancer (ALB)
Balanceador de carga de capa 7 para HTTP y HTTPS que puede enrutar por ruta o nombre de host.
Network Load Balancer (NLB)
Balanceador de carga de capa 4 para TCP y UDP con rendimiento muy alto y soporte para IP estáticas.
EC2 Auto Scaling
Servicio que agrega o quita instancias EC2 automáticamente para ajustarse a la demanda y reemplaza las que no están en buen estado.
Plantilla de lanzamiento (launch template)
Configuración guardada que indica la AMI, el tipo de instancia y los ajustes que Auto Scaling usa para lanzar instancias.
Ejemplo real

El sitio de inscripciones de una universidad funciona con dos instancias la mayor parte del año, pero colapsa el primer día de inscripción. El equipo de TI crea una AMI del servidor configurado, un grupo de Auto Scaling en dos AZ con escalado programado a doce instancias la mañana de la inscripción más seguimiento de objetivos sobre la CPU, y un Application Load Balancer al frente. Ahora el día de inscripción transcurre sin problemas y el grupo se reduce automáticamente después.

Consejo para el examen: Relaciona la carga de trabajo con la familia: las bases de datos en memoria van en instancias optimizadas para memoria, los lotes o HPC en optimizadas para cómputo, y el entrenamiento de ML o los gráficos en computación acelerada. El enrutamiento HTTP basado en rutas significa un Application Load Balancer.

Comprueba lo que sabes

¿Qué familia de instancias EC2 es adecuada para una gran base de datos en memoria?

La optimizada para memoria, porque ofrece una proporción alta de memoria respecto al cómputo.

¿Cuál es la diferencia entre Elastic Load Balancing y EC2 Auto Scaling?

ELB distribuye el tráfico entre destinos en buen estado; Auto Scaling cambia la cantidad de instancias para ajustarse a la demanda.

¿Qué balanceador de carga puede enviar las solicitudes de /api a un conjunto de servidores y las de /images a otro?

El Application Load Balancer, que enruta en la capa 7 por ruta o host.

¿Qué proporciona una AMI?

Una plantilla con el sistema operativo, el software y la configuración que se usa para lanzar instancias idénticas.
