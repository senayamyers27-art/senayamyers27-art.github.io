Familias de instancias de Amazon EC2, AMI, Elastic Load Balancing y Amazon EC2 Auto Scaling

Amazon Elastic Compute Cloud (Amazon EC2) proporciona servidores virtuales redimensionables, llamados instancias. Eliges el sistema operativo, el tamaño y la configuración, y tienes control total, incluido el acceso de administrador o root, lo que también significa que eres responsable de parchear y proteger el sistema operativo invitado.

Los tipos de instancia se agrupan en familias optimizadas para distintas cargas de trabajo. Las instancias de uso general (general purpose) equilibran cómputo, memoria y red, y sirven para servidores web y repositorios de código. Las instancias optimizadas para cómputo (compute optimized) tienen procesadores de alto rendimiento para trabajo limitado por el cómputo, como el procesamiento por lotes, los servidores de juegos y el modelado científico. Las instancias optimizadas para memoria (memory optimized) son para cargas de trabajo que procesan grandes conjuntos de datos en memoria, como las bases de datos en memoria y el análisis de big data en tiempo real. Las instancias de computación acelerada (accelerated computing) usan aceleradores de hardware como GPU para aprendizaje automático, gráficos y otras cargas de trabajo paralelas. Las instancias optimizadas para almacenamiento (storage optimized) ofrecen un rendimiento de almacenamiento local alto y de baja latencia para cargas de trabajo como almacenes de datos (data warehousing) y grandes bases de datos transaccionales. La letra al inicio del nombre del tipo, y un tamaño como large o xlarge, te indican la familia y el tamaño.

Una Amazon Machine Image (AMI) es una plantilla para lanzar instancias. Incluye el sistema operativo y cualquier software y configuración preinstalados. Puedes usar AMI proporcionadas por AWS, comprarlas en AWS Marketplace o crear las tuyas a partir de una instancia configurada para que cada servidor nuevo arranque idéntico, un componente útil para la automatización.

Elastic Load Balancing (ELB) distribuye automáticamente el tráfico entrante entre varios destinos, como instancias EC2 en varias Availability Zones, y lo dirige solo a destinos sanos usando comprobaciones de estado. El Application Load Balancer trabaja en la capa 7 (HTTP y HTTPS) y puede enrutar según la ruta de la URL o el nombre de host. El Network Load Balancer trabaja en la capa 4 (TCP y UDP) para un rendimiento extremo y direcciones IP estáticas. El Gateway Load Balancer se usa para desplegar appliances virtuales de terceros, como firewalls.

Amazon EC2 Auto Scaling agrega o quita automáticamente instancias de un grupo de Auto Scaling para ajustarse a la demanda. Estableces una capacidad mínima, máxima y deseada, y políticas de escalado como 'mantener el uso promedio de CPU en 50 por ciento'. También reemplaza las instancias en mal estado. Juntos, ELB y Auto Scaling te dan una capa web altamente disponible y elástica.

Términos clave

Amazon EC2
Un servicio que proporciona servidores virtuales redimensionables (instancias) en la nube.
Instance family (familia de instancias)
Un grupo de tipos de instancia EC2 optimizados para un perfil de carga de trabajo, como los optimizados para cómputo o para memoria.
Amazon Machine Image (AMI)
Una plantilla que contiene el sistema operativo y el software usados para lanzar instancias EC2.
Elastic Load Balancing
Un servicio que distribuye el tráfico entrante entre destinos sanos en varias AZ.
Auto Scaling group (grupo de Auto Scaling)
Un conjunto de instancias EC2 que Auto Scaling amplía, reduce y repara según las políticas.
Ejemplo real

Un sitio de noticias crea una AMI personalizada que contiene su aplicación web, lanza instancias a partir de ella en un grupo de Auto Scaling distribuido en tres AZ con un mínimo de dos instancias y coloca delante un Application Load Balancer. Cuando surge una gran noticia, Auto Scaling agrega instancias; cuando un servidor falla una comprobación de estado, se reemplaza automáticamente.

Consejo para el examen: Relaciona la carga de trabajo con la familia: bases de datos en memoria apuntan a optimizadas para memoria, procesamiento por lotes o computación de alto rendimiento a optimizadas para cómputo, entrenamiento de aprendizaje automático o gráficos a computación acelerada. Para enrutamiento HTTP basado en rutas, elige un Application Load Balancer.

Comprueba lo que sabes

¿Qué familia de instancias EC2 es la mejor para una caché grande en memoria?

Optimizada para memoria (memory optimized).

¿Qué dos servicios juntos hacen que una capa web sea a la vez altamente disponible y elástica?

Elastic Load Balancing, para repartir el tráfico entre AZ, y EC2 Auto Scaling, para agregar, quitar y reemplazar instancias.
