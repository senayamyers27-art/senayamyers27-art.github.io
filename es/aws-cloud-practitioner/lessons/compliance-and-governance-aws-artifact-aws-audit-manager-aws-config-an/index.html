AWS Certified Cloud Practitioner CLF-C02

Cumplimiento y gobernanza: AWS Artifact, AWS Audit Manager, AWS Config y dónde encontrar información de cumplimiento

Las organizaciones reguladas deben demostrar que sus sistemas cumplen normas como el Payment Card Industry Data Security Standard (PCI DSS) para pagos con tarjeta, la Health Insurance Portability and Accountability Act (HIPAA) para datos de salud en Estados Unidos, o ISO/IEC 27001 para la gestión de la seguridad de la información. En la nube, el cumplimiento se comparte igual que la seguridad: AWS demuestra que su infraestructura cumple estas normas, y tú demuestras que tus propias cargas de trabajo las cumplen. Varios servicios de AWS ayudan con cada lado, y el examen evalúa cuál se ajusta a cada necesidad.

AWS Artifact es el portal de autoservicio de la AWS Management Console para los documentos de cumplimiento propios de AWS, disponible sin costo. Tiene dos partes. Artifact Reports te da acceso bajo demanda a los informes de seguridad y cumplimiento de AWS elaborados por auditores externos, como los informes System and Organization Controls (SOC), las certificaciones de cumplimiento de PCI DSS y las certificaciones ISO, que puedes entregar a tus propios auditores como evidencia de que el lado de AWS está cubierto. Artifact Agreements te permite revisar, aceptar y administrar acuerdos con AWS, como el Business Associate Addendum (BAA) que se necesita cuando manejas información de salud protegida bajo HIPAA, para una cuenta o para todas las cuentas de una organización.

AWS Audit Manager te ayuda a auditar tu propio uso de AWS. Eliges un marco (framework), ya sea uno prediseñado asociado a una norma o regulación, o uno personalizado, y creas una evaluación. Luego Audit Manager recopila continuamente evidencia de tus cuentas, como instantáneas de configuración, actividad de AWS CloudTrail, resultados de las reglas de AWS Config y verificaciones de AWS Security Hub, y la organiza por control. Cuando llega la auditoría, generas un informe de evaluación en lugar de pasar semanas reuniendo capturas de pantalla y hojas de cálculo. Algunos controles, como una política de capacitación documentada, no pueden recopilarse automáticamente, así que puedes subir evidencia manual junto con los elementos automatizados y delegar la revisión de controles individuales a sus responsables. Audit Manager te ayuda a prepararte; no te certifica como conforme.

AWS Config registra la configuración de tus recursos de AWS y cómo cambia a lo largo del tiempo. Puedes ver cómo era un security group el martes pasado y, combinándolo con CloudTrail, quién lo cambió. Las reglas de Config evalúan los recursos frente a la configuración deseada, por ejemplo 's3-bucket-public-read-prohibited' o 'encrypted-volumes', y marcan los recursos no conformes; los paquetes de conformidad (conformance packs) agrupan muchas reglas en un solo conjunto desplegable. Config también puede activar una corrección automática mediante Systems Manager Automation. Desde la CLI, aws configservice describe-compliance-by-config-rule muestra qué reglas se cumplen y cuáles no.

Para información general, las páginas de AWS Compliance Programs enumeran las normas en las que participa AWS, y las páginas de Services in Scope muestran qué servicios de AWS están cubiertos por cada programa, lo cual importa porque no todos los servicios están dentro del alcance de todas las normas. El AWS Customer Compliance Center, los documentos técnicos y las guías de inicio rápido explican cómo cumplir los requisitos. Para la gobernanza a escala, AWS Organizations con las políticas de control de servicios (service control policies, SCP) y AWS Control Tower con sus controles preventivos y de detección ayudan a mantener muchas cuentas dentro de las reglas.

Veamos un ejemplo práctico. Un grupo de clínicas está trasladando un portal de pacientes a AWS. Su responsable de cumplimiento acepta el BAA en AWS Artifact Agreements y descarga el informe SOC 2 más reciente desde Artifact Reports para los auditores. Los ingenieros consultan la página de Services in Scope para confirmar que cada servicio que planean usar es apto para HIPAA. Despliegan un paquete de conformidad de AWS Config que marca los volúmenes sin cifrar y los buckets públicos, y configuran una evaluación de Audit Manager para que la evidencia se recopile de forma continua para la auditoría anual.

Errores comunes: pensar que AWS Artifact revisa tus propios recursos (solo contiene los documentos y acuerdos de AWS); pensar que AWS Config es un servicio de detección de amenazas (evalúa configuraciones, mientras que Amazon GuardDuty detecta amenazas); suponer que, como AWS está certificado en una norma, tu carga de trabajo cumple automáticamente (tú todavía debes configurar correctamente tu parte); y confundir Config, que registra y evalúa la configuración de los recursos, con CloudTrail, que registra las llamadas a la API. Config te dice cómo es el recurso; CloudTrail te dice quién llamó a qué API.

La redacción del examen suele ser una pista clara. 'Descargar los informes SOC o PCI de AWS' o 'aceptar un BAA' es AWS Artifact. 'Recopilar evidencia continuamente para una auditoría' o 'asociar el uso de AWS con un marco de cumplimiento' es AWS Audit Manager. 'Dar seguimiento a los cambios de configuración a lo largo del tiempo', 'evaluar recursos según reglas' o '¿este recurso cumple con nuestra política?' es AWS Config. '¿Qué servicios están cubiertos por un programa de cumplimiento?' es la información de AWS Services in Scope.

Términos clave

AWS Artifact
Portal de autoservicio para los informes de auditoría de terceros de AWS y acuerdos como el BAA.
Business Associate Addendum (BAA)
Acuerdo exigido por HIPAA antes de manejar información de salud protegida en AWS, que se acepta mediante Artifact Agreements.
AWS Audit Manager
Servicio que recopila continuamente evidencia de tu uso de AWS y la asocia con marcos de cumplimiento.
AWS Config
Servicio que registra la configuración de los recursos a lo largo del tiempo y la evalúa según reglas.
Regla de Config (Config rule)
Verificación que marca los recursos como conformes o no conformes con una configuración deseada.
Paquete de conformidad (conformance pack)
Colección desplegable de reglas de AWS Config y acciones de corrección.
Services in Scope
Información de AWS que enumera qué servicios están cubiertos por cada programa de cumplimiento.
Ejemplo real

Un procesador de pagos en línea que se prepara para su evaluación PCI DSS descarga desde Artifact la certificación PCI de AWS para cubrir la capa de infraestructura. Ejecuta una evaluación de Audit Manager con un marco PCI que ha estado recopilando evidencia todo el año, y sus reglas de AWS Config muestran dos security groups que permitían acceso entrante sin restricciones. El historial de Config muestra cuándo cambiaron, CloudTrail muestra quién los cambió, y el equipo los corrige antes de que llegue el evaluador.

Consejo para el examen: Artifact contiene los informes de cumplimiento y los acuerdos de AWS; no evalúa tus recursos. Para comprobar si tus propios recursos cumplen un estándar de configuración, usa AWS Config; para reunir evidencia de auditoría, usa Audit Manager.

Comprueba lo que sabes

¿Dónde descargas los informes SOC de AWS para entregarlos a tus auditores?

En AWS Artifact, en Artifact Reports.

Una empresa debe marcar cualquier volumen EBS que no esté cifrado. ¿Qué servicio usa?

AWS Config, con una regla que evalúa si los volúmenes están cifrados.

¿Qué hace AWS Audit Manager?

Recopila continuamente evidencia de tus cuentas de AWS y la organiza según un marco de cumplimiento para preparar auditorías.

¿Que AWS tenga una certificación PCI DSS hace que tu aplicación cumpla con PCI?

No. Cubre la infraestructura de AWS; tú todavía debes configurar y operar tu propia carga de trabajo para cumplir la norma.
