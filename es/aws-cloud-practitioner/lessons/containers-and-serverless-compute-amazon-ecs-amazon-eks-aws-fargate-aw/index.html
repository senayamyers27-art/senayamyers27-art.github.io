AWS Certified Cloud Practitioner CLF-C02

Contenedores y cómputo serverless: Amazon ECS, Amazon EKS, AWS Fargate, AWS Lambda y AWS Elastic Beanstalk

EC2 no es la única forma de ejecutar código en AWS. Los contenedores y los servicios serverless eliminan más parte de la administración de servidores, y el examen verifica que sepas elegir entre ellos.

Un contenedor empaqueta una aplicación con sus dependencias para que se ejecute igual en todas partes. Para ejecutar muchos contenedores necesitas un orquestador. Amazon Elastic Container Service (Amazon ECS) es el servicio de orquestación de contenedores propio de AWS, totalmente administrado, fácil de usar y profundamente integrado con AWS. Amazon Elastic Kubernetes Service (Amazon EKS) ejecuta Kubernetes, el popular orquestador de código abierto, con AWS administrando el plano de control de Kubernetes; elígelo cuando ya usas Kubernetes o quieres portabilidad entre entornos. Las imágenes de contenedor suelen almacenarse en Amazon Elastic Container Registry (Amazon ECR).

Tanto ECS como EKS necesitan capacidad de cómputo para ejecutar los contenedores. Puedes aportar instancias EC2 que administras tú, o usar AWS Fargate, un motor de cómputo serverless para contenedores. Con Fargate no aprovisionas ni parcheas servidores; defines la CPU y la memoria que necesita cada tarea o pod y pagas esos recursos mientras se ejecuta. La distinción: ECS y EKS son orquestadores; Fargate es un lugar donde sus contenedores se ejecutan sin administrar servidores.

AWS Lambda ejecuta código sin aprovisionar servidores en absoluto, en respuesta a eventos como un objeto subido a S3, un mensaje en una cola SQS, una solicitud HTTP a través de Amazon API Gateway o una programación horaria. Lambda escala automáticamente con la cantidad de eventos, y pagas por solicitud y por el tiempo de cómputo que usa tu código, sin cargos cuando está inactivo. Es ideal para tareas cortas impulsadas por eventos; una sola invocación puede durar como máximo 15 minutos, así que los procesos de larga duración van en otro lugar.

AWS Elastic Beanstalk es una plataforma como servicio (PaaS) para aplicaciones web. Subes tu código, por ejemplo una aplicación Java, .NET, Python, Node.js o Docker, y Beanstalk se encarga automáticamente del aprovisionamiento de capacidad, el balanceo de carga, Auto Scaling y el monitoreo del estado, usando EC2 y otros servicios por debajo. Conservas acceso total a esos recursos, pero no necesitas ensamblarlos tú mismo. Se adapta a desarrolladores que quieren desplegar rápido sin aprender cada servicio de infraestructura.

Términos clave

Amazon ECS
El servicio de orquestación de contenedores de AWS, totalmente administrado.
Amazon EKS
Un servicio administrado para ejecutar Kubernetes en AWS.
AWS Fargate
Un motor de cómputo serverless que ejecuta contenedores para ECS y EKS sin administrar servidores.
AWS Lambda
Un servicio de cómputo serverless impulsado por eventos que ejecuta código y cobra por solicitud y por tiempo de cómputo.
AWS Elastic Beanstalk
Una PaaS que despliega y administra aplicaciones web, encargándose del aprovisionamiento, el balanceo de carga y el escalado.
Ejemplo real

Una empresa tiene tres cargas de trabajo. Sus microservicios ya se ejecutan en Kubernetes, así que los traslada a Amazon EKS con Fargate para no administrar nodos. Las miniaturas de imágenes las genera una función Lambda cada vez que llega un archivo a S3. Una pequeña aplicación web interna escrita en Python se despliega con Elastic Beanstalk para que el desarrollador no tenga que configurar a mano balanceadores de carga ni escalado.

Consejo para el examen: 'Kubernetes' en la pregunta significa EKS. 'Ejecutar contenedores sin administrar servidores' significa Fargate. 'Ejecutar código en respuesta a eventos, sin servidores, pagando solo cuando se ejecuta' significa Lambda. 'Subir código y que AWS se encargue del despliegue, el escalado y el balanceo de carga' significa Elastic Beanstalk.

Comprueba lo que sabes

¿Cuál es la diferencia entre Amazon ECS y AWS Fargate?

ECS orquesta contenedores; Fargate es una opción de cómputo serverless que ejecuta esos contenedores sin que administres instancias EC2.

¿Por qué Lambda no es una buena opción para un trabajo que se ejecuta de forma continua durante dos horas?

Una sola invocación de Lambda tiene una duración máxima de 15 minutos; el trabajo de larga duración va en EC2, contenedores o un servicio de procesamiento por lotes.
