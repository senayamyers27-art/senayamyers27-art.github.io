AWS Certified Cloud Practitioner CLF-C02

Contenedores y cómputo serverless: Amazon ECS, Amazon EKS, AWS Fargate, AWS Lambda y AWS Elastic Beanstalk

Amazon EC2 no es la única forma de ejecutar código en AWS. Los contenedores y los servicios serverless te quitan progresivamente más trabajo de administración de servidores, lo que traslada una mayor parte del modelo de responsabilidad compartida hacia AWS. El examen verifica que puedas elegir entre Amazon Elastic Container Service (Amazon ECS), Amazon Elastic Kubernetes Service (Amazon EKS), AWS Fargate, AWS Lambda y AWS Elastic Beanstalk a partir de una breve descripción de lo que quiere un equipo.

Un contenedor empaqueta una aplicación con sus bibliotecas y dependencias para que se ejecute de la misma manera en una laptop, un servidor de pruebas o en producción. Los contenedores arrancan en segundos y comparten el kernel del sistema operativo del host, por lo que son más livianos que las máquinas virtuales. Ejecutar muchos contenedores en muchos hosts requiere un orquestador que ubique los contenedores, reinicie los que fallen, los escale y los conecte a los balanceadores de carga. Las imágenes de contenedor normalmente se almacenan en Amazon Elastic Container Registry (Amazon ECR), un registro de imágenes administrado.

Amazon ECS es el servicio de orquestación de contenedores totalmente administrado propio de AWS. Es fácil de adoptar y está profundamente integrado con funciones de AWS como los roles de IAM, los balanceadores de carga y Amazon CloudWatch; describes los contenedores en una definición de tarea (task definition) y los ejecutas como tareas o como servicios de larga duración. Amazon EKS ejecuta Kubernetes, el popular orquestador de código abierto, con AWS administrando el plano de control de Kubernetes. Elige EKS cuando un equipo ya usa Kubernetes, quiere sus herramientas o necesita portabilidad hacia otros entornos; elige ECS cuando quieras la opción nativa de AWS más sencilla.

Tanto ECS como EKS necesitan capacidad de cómputo para ejecutar contenedores. Puedes aportar instancias EC2 que administras y parchas tú, o usar AWS Fargate, un motor de cómputo serverless para contenedores. Con Fargate no aprovisionas, escalas ni parchas servidores; declaras la CPU y la memoria que necesita cada tarea o pod y pagas por esos recursos mientras se ejecuta. La distinción clave: ECS y EKS son orquestadores que deciden qué se ejecuta y dónde, mientras que Fargate es un lugar donde sus contenedores se ejecutan sin que administres servidores.

AWS Lambda ejecuta código sin aprovisionar ningún servidor, en respuesta a eventos como un objeto subido a Amazon S3, un mensaje que llega a una cola de Amazon SQS, una solicitud HTTP a través de Amazon API Gateway o una programación de Amazon EventBridge. Subes una función, eliges el tamaño de memoria y Lambda ejecuta tantas copias como requieran los eventos. Pagas por solicitud y por el tiempo de cómputo medido en pequeños incrementos, sin cargos cuando la función está inactiva. Lambda es adecuado para tareas cortas impulsadas por eventos; una sola invocación puede durar como máximo 15 minutos, así que los procesos de larga duración corresponden a contenedores o EC2. AWS Elastic Beanstalk es una plataforma como servicio (PaaS) para aplicaciones web: subes código, como una aplicación Java, .NET, Python, Node.js o Docker, y Beanstalk aprovisiona y administra por ti las instancias EC2, un balanceador de carga, Auto Scaling y el monitoreo de estado, y deja esos recursos visibles y ajustables.

Veamos un ejemplo práctico. Una empresa de medios tiene cuatro necesidades. Su equipo de plataforma ya ejecuta Kubernetes en sus instalaciones y quiere las mismas herramientas en AWS, así que usa EKS. Un nuevo equipo de microservicios quiere contenedores sin parchar servidores, así que ejecuta servicios de ECS en Fargate. Cuando un usuario sube una foto a S3, una función Lambda crea miniaturas en uno o dos segundos. Un pequeño equipo de marketing con una aplicación web en Node.js y sin experiencia en infraestructura la implementa con Elastic Beanstalk, que construye el balanceador de carga y el escalado por ellos.

Errores comunes: pensar que Fargate es una alternativa a ECS o EKS (es un tipo de lanzamiento u opción de cómputo que ellos usan); elegir Lambda para un trabajo que dura horas; suponer que serverless significa que no hay servidores (AWS los administra por ti); confundir Elastic Beanstalk con AWS CloudFormation (Beanstalk implementa una aplicación en un entorno que construye; CloudFormation aprovisiona cualquier recurso que defina tu plantilla); y suponer que ECR ejecuta contenedores cuando solo almacena imágenes. Recuerda también que con Lambda y Fargate sigues siendo responsable de tu código, sus permisos y sus datos.

En el examen, sigue las palabras clave. «Kubernetes» significa EKS. «Ejecutar contenedores Docker con un orquestador sencillo nativo de AWS» significa ECS. «Ejecutar contenedores sin administrar servidores ni clústeres de instancias» significa Fargate. «Ejecutar código en respuesta a eventos, sin servidores, pagando solo cuando se ejecuta» significa Lambda. «Subir código y que AWS se encargue de la capacidad, el balanceo de carga, el escalado y el monitoreo» significa Elastic Beanstalk. «Almacenar imágenes de contenedor» significa ECR. Si una opción describe un proceso de larga duración de varias horas, descarta Lambda.

Términos clave

Contenedor
Paquete de una aplicación y sus dependencias que se ejecuta de forma consistente en distintos entornos y comparte el kernel del sistema operativo del host.
Amazon ECS
Servicio de orquestación de contenedores totalmente administrado propio de AWS.
Amazon EKS
Servicio administrado para ejecutar Kubernetes en AWS, con AWS operando el plano de control.
AWS Fargate
Motor de cómputo serverless que ejecuta contenedores de ECS o EKS sin que administres servidores.
AWS Lambda
Servicio serverless que ejecuta código en respuesta a eventos y cobra por solicitud y tiempo de cómputo.
AWS Elastic Beanstalk
Plataforma como servicio que implementa y administra aplicaciones web, y se encarga de la capacidad, el balanceo de carga y el escalado.
Amazon ECR
Registro administrado para almacenar y compartir imágenes de contenedor.
Ejemplo real

Una aseguradora recibe formularios de reclamos escaneados durante todo el día. Cada carga a un bucket de S3 activa una función Lambda que valida el archivo y coloca un mensaje en una cola. Un servicio de procesamiento de reclamos, empaquetado como contenedores y ejecutado por ECS en Fargate, lee la cola y procesa cada reclamo. Nadie en el equipo parcha servidores, la función Lambda no cuesta nada durante la noche cuando no llegan reclamos, y las tareas de Fargate escalan según la longitud de la cola.

Consejo para el examen: «Kubernetes» significa EKS; «contenedores sin administrar servidores» significa Fargate; «código impulsado por eventos, pagando solo cuando se ejecuta» significa Lambda; «sube el código y AWS se encarga del resto» significa Elastic Beanstalk.

Comprueba lo que sabes

Un equipo usa Kubernetes en sus instalaciones y quiere un equivalente administrado en AWS. ¿Qué servicio encaja?

Amazon EKS, que ejecuta Kubernetes con un plano de control administrado por AWS.

¿Cuál es la relación entre ECS y Fargate?

ECS orquesta contenedores; Fargate es una opción de cómputo serverless donde esos contenedores se ejecutan sin que administres instancias EC2.

¿Por qué Lambda no es adecuado para un trabajo de codificación de video que dura tres horas?

Una invocación de Lambda puede durar como máximo 15 minutos, así que los trabajos largos corresponden a contenedores o EC2.

Un desarrollador quiere implementar una aplicación web en Python sin configurar balanceadores de carga ni escalado. ¿Qué servicio?

AWS Elastic Beanstalk, que aprovisiona y administra esa infraestructura automáticamente.
