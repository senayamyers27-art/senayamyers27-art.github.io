AWS Certified Cloud Practitioner CLF-C02

Redes: Amazon VPC, subredes, internet gateway y NAT gateway, Route 53, CloudFront, Site-to-Site VPN y Direct Connect

Amazon Virtual Private Cloud (Amazon VPC) te permite lanzar recursos de AWS en una red virtual lógicamente aislada que tú defines. Eliges su rango de direcciones IP, creas subredes, configuras tablas de enrutamiento y controlas el tráfico con security groups y network ACLs. Cada Región te da una VPC predeterminada para empezar, pero los diseños de producción suelen usar VPC personalizadas.

Una subred (subnet) es un rango de direcciones IP dentro de una VPC, y cada subred reside en una sola Availability Zone. Una subred pública tiene una ruta hacia un internet gateway, de modo que los recursos que contiene con direcciones IP públicas pueden ser alcanzados desde internet y alcanzarlo; los balanceadores de carga y los hosts bastión suelen estar aquí. Una subred privada no tiene una ruta directa hacia internet; las bases de datos y los servidores de aplicaciones suelen estar aquí. Un internet gateway es el componente de la VPC que permite la comunicación entre la VPC e internet. Un NAT gateway, ubicado en una subred pública, permite que las instancias de subredes privadas inicien conexiones salientes hacia internet, por ejemplo para descargar actualizaciones de software, mientras impide que desde internet se inicien conexiones hacia ellas.

Amazon Route 53 es el servicio de Domain Name System (DNS) de AWS, altamente disponible. Traduce nombres como www.example.com en direcciones IP, te permite registrar nombres de dominio, realiza comprobaciones de estado y ofrece políticas de enrutamiento como simple, ponderado (weighted), basado en latencia, conmutación por error (failover) y geolocalización. Amazon CloudFront es una red de entrega de contenido (CDN) que almacena en caché contenido estático y dinámico en ubicaciones de borde de todo el mundo, reduciendo la latencia para los usuarios y la carga sobre tu origen, e integrándose con AWS WAF y Shield para su protección.

Dos servicios conectan redes locales con AWS. AWS Site-to-Site VPN crea túneles IPsec cifrados entre tu red local y tu VPC a través de internet público. Es rápido de configurar y relativamente económico, pero el rendimiento depende de las condiciones de internet. AWS Direct Connect proporciona una conexión de red privada y dedicada desde tus instalaciones o desde una instalación de colocation hasta AWS que no atraviesa internet público, ofreciendo un rendimiento más constante y posiblemente menores costos de transferencia de datos para grandes volúmenes, pero tarda más en aprovisionarse. Algunas organizaciones usan una VPN como respaldo de Direct Connect.

Atajos para el examen: 'red aislada' es VPC; 'las instancias privadas necesitan internet saliente' es NAT gateway; 'DNS' o 'registro de dominios' es Route 53; 'almacenar contenido en caché globalmente' es CloudFront; 'cifrado por internet, configuración rápida' es VPN; 'conexión privada dedicada, rendimiento constante' es Direct Connect.

Términos clave

Amazon VPC
Una red virtual lógicamente aislada en AWS donde defines rangos de IP, subredes y enrutamiento.
Internet gateway
Un componente de la VPC que permite la comunicación entre los recursos de las subredes públicas e internet.
NAT gateway
Un servicio administrado que permite que las instancias de subredes privadas establezcan conexiones salientes a internet sin aceptar conexiones entrantes.
Amazon Route 53
Un servicio escalable de DNS y registro de dominios con comprobaciones de estado y políticas de enrutamiento.
AWS Direct Connect
Una conexión de red privada y dedicada entre la infraestructura local y AWS.
Ejemplo real

La VPC de una empresa tiene subredes públicas en dos AZ para un Application Load Balancer y los NAT gateways, y subredes privadas para sus servidores de aplicaciones y su base de datos RDS. Route 53 dirige shop.example.com a una distribución de CloudFront situada delante del balanceador de carga. La oficina central se conecta a la VPC mediante Direct Connect, con una Site-to-Site VPN como respaldo.

Consejo para el examen: Un internet gateway permite acceso a internet en ambos sentidos para las subredes públicas; un NAT gateway permite acceso solo saliente para las subredes privadas. La VPN va cifrada por internet; Direct Connect es una línea privada dedicada.

Comprueba lo que sabes

Las instancias de una subred privada necesitan descargar parches de internet, pero no deben ser alcanzables desde él. ¿Qué agregas?

Un NAT gateway en una subred pública, con una ruta desde la subred privada hacia él.

¿Qué opción de conexión no atraviesa internet público?

AWS Direct Connect.
