AWS Certified Cloud Practitioner CLF-C02

Redes: Amazon VPC, subredes, internet gateway y NAT gateway, Route 53, CloudFront, Site-to-Site VPN y Direct Connect

Las redes en AWS empiezan con Amazon Virtual Private Cloud (Amazon VPC), que te permite lanzar recursos en una red virtual aislada lógicamente que tú defines. Eliges su rango de direcciones IP en notación de enrutamiento entre dominios sin clases (CIDR), como 10.0.0.0/16, creas subredes, configuras tablas de rutas y controlas el tráfico con grupos de seguridad (con estado, a nivel de instancia) y listas de control de acceso de red (network ACL, sin estado, a nivel de subred). Cada Región te da una VPC predeterminada para empezar, pero los diseños de producción suelen usar VPC personalizadas.

Una subred es un rango de direcciones IP dentro de una VPC, y cada subred reside en exactamente una Availability Zone. Lo que hace que una subred sea pública o privada es su tabla de rutas. Una subred pública tiene una ruta como 0.0.0.0/0 -> igw-... hacia un internet gateway, de modo que los recursos que contiene con direcciones IP públicas pueden llegar a internet y ser alcanzados desde internet; los balanceadores de carga suelen estar aquí. Una subred privada no tiene esa ruta; los servidores de aplicaciones y las bases de datos suelen estar aquí. Un internet gateway es el componente de la VPC, escalado horizontalmente, que permite la comunicación bidireccional con internet. Un NAT gateway (traducción de direcciones de red), ubicado en una subred pública, permite que las instancias de subredes privadas inicien conexiones salientes, por ejemplo para descargar parches, mientras impide que internet inicie conexiones hacia ellas.

Amazon Route 53 es el servicio de sistema de nombres de dominio (DNS) altamente disponible de AWS. Traduce nombres como www.example.com a direcciones IP, te permite registrar nombres de dominio, realiza comprobaciones de estado y ofrece políticas de enrutamiento como simple, ponderada (divide el tráfico por porcentaje), basada en latencia (envía a los usuarios a la Región más rápida), de conmutación por error (cambia a un sitio en espera cuando fallan las comprobaciones de estado) y de geolocalización (enruta según la ubicación del usuario). Amazon CloudFront es una red de entrega de contenido (CDN) que almacena en caché contenido estático y dinámico en ubicaciones de borde de todo el mundo, lo que reduce la latencia para los espectadores y la carga sobre tu origen, y se integra con AWS WAF y AWS Shield para la protección.

Dos servicios conectan redes locales con AWS. AWS Site-to-Site VPN (red privada virtual) crea túneles cifrados de Internet Protocol Security (IPsec) entre tu red local y tu VPC a través de internet público. Se configura rápido y es relativamente económica, pero su rendimiento varía según las condiciones de internet. AWS Direct Connect proporciona una conexión privada dedicada desde tus instalaciones o una instalación de colocación hasta AWS que no atraviesa internet público, con ancho de banda y latencia más consistentes y costos de transferencia de datos potencialmente menores para grandes volúmenes, pero tarda más en aprovisionarse. Muchas organizaciones usan una VPN como respaldo de Direct Connect. Para usuarios remotos individuales, AWS Client VPN ofrece acceso VPN desde laptops.

Veamos un ejemplo práctico. Una empresa construye una VPC con subredes públicas y privadas en dos AZ. Un Application Load Balancer está en las subredes públicas, y los servidores web y una base de datos RDS en las subredes privadas. Los servidores web descargan actualizaciones a través de un NAT gateway, pero no pueden ser alcanzados directamente desde internet. Route 53 aloja el dominio de la empresa con un registro de conmutación por error que apunta a un sitio de respaldo, y CloudFront almacena imágenes en caché cerca de los clientes. La oficina central se conecta mediante Direct Connect para las transferencias de datos de nómina, con una Site-to-Site VPN como respaldo.

Errores comunes: colocar un NAT gateway en una subred privada (pertenece a una subred pública); pensar que un NAT gateway permite conexiones entrantes desde internet; suponer que una subred puede abarcar varias AZ; creer que Direct Connect está cifrado por defecto solo porque es privado (puedes agregar cifrado, por ejemplo una VPN sobre él o MACsec donde sea compatible); y confundir Route 53, que responde consultas DNS y enruta a los usuarios, con CloudFront, que almacena en caché y entrega contenido. Otra trampa es tratar los grupos de seguridad y las network ACL como lo mismo: los grupos de seguridad tienen estado y solo admiten reglas de permitir, mientras que las network ACL no tienen estado y admiten reglas de permitir y denegar.

Atajos para el examen: «red aislada lógicamente» es VPC. «Las instancias privadas solo necesitan acceso saliente a internet» es un NAT gateway, y «permitir tráfico de internet hacia una subred pública» es un internet gateway. «DNS», «registro de dominios» o «enrutar a los usuarios al endpoint más sano o más cercano» es Route 53. «Almacenar contenido en caché a nivel global» o «reducir la latencia del contenido estático» es CloudFront. «Conexión cifrada a través de internet, rápida de configurar» es Site-to-Site VPN. «Conexión privada dedicada con rendimiento consistente» es Direct Connect. «Firewall sin estado a nivel de subred» es una network ACL, y «firewall con estado a nivel de instancia» es un grupo de seguridad.

Términos clave

Amazon VPC
Red virtual aislada lógicamente en AWS cuyos rangos de IP, subredes y enrutamiento controlas tú.
Subred
Rango de direcciones IP dentro de una VPC, ubicado en una sola Availability Zone.
Internet gateway
Componente de la VPC que permite la comunicación bidireccional entre los recursos de subredes públicas e internet.
NAT gateway
Servicio administrado en una subred pública que permite a las instancias de subredes privadas hacer conexiones a internet solo salientes.
Amazon Route 53
Servicio DNS de AWS que ofrece registro de dominios, comprobaciones de estado y políticas de enrutamiento.
Amazon CloudFront
Red de entrega de contenido de AWS que almacena contenido en caché en ubicaciones de borde cercanas a los espectadores.
AWS Site-to-Site VPN
Túneles IPsec cifrados entre una red local y una VPC a través de internet.
AWS Direct Connect
Conexión de red privada dedicada entre las instalaciones locales y AWS que evita internet público.
Ejemplo real

Los servidores de base de datos de un minorista, ubicados en una subred privada, necesitan parches de seguridad mensuales desde internet, pero nunca deben aceptar conexiones entrantes. El equipo de redes agrega un NAT gateway en una subred pública y una ruta 0.0.0.0/0 desde la tabla de rutas privada hacia él. Los parches se descargan correctamente, y un escaneo de puertos desde el exterior no encuentra nada accesible. Los clientes llegan a la tienda a través de Route 53 y CloudFront, y el almacén se conecta mediante una Site-to-Site VPN.

Consejo para el examen: Un internet gateway permite acceso bidireccional a internet para las subredes públicas; un NAT gateway permite acceso solo saliente para las subredes privadas. La VPN funciona cifrada sobre internet; Direct Connect es una línea privada dedicada.

Comprueba lo que sabes

¿Qué hace que una subred sea pública?

Que su tabla de rutas tenga una ruta hacia un internet gateway.

Las instancias de una subred privada deben descargar actualizaciones pero no aceptar conexiones entrantes desde internet. ¿Qué agregas?

Un NAT gateway en una subred pública, con una ruta hacia él desde la tabla de rutas de la subred privada.

Una empresa necesita conectividad a AWS consistente y de gran ancho de banda que no atraviese internet. ¿Qué servicio?

AWS Direct Connect.

¿Qué servicio enruta a los usuarios hacia la Región con menor latencia mediante DNS?

Amazon Route 53 con una política de enrutamiento basada en latencia.
