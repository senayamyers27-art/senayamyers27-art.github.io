AWS Certified Cloud Practitioner CLF-C02

Bases de datos: Amazon RDS y Aurora, Amazon DynamoDB, Amazon ElastiCache, Amazon Redshift y otras bases de datos de propósito específico

AWS te anima a elegir una base de datos de propósito específico para cada trabajo en lugar de forzar todo tipo de datos en un solo motor. Puedes ejecutar cualquier base de datos por tu cuenta en Amazon EC2, pero entonces tú la instalas, la parchas, la respaldas y la replicas. Los servicios de bases de datos administradas asumen ese trabajo pesado indiferenciado, así que, según el modelo de responsabilidad compartida, AWS se encarga del software de base de datos y de la infraestructura, mientras que tú sigues siendo responsable de tus datos, el diseño del esquema, el control de acceso y configuraciones como el cifrado.

Amazon Relational Database Service (Amazon RDS) ejecuta bases de datos relacionales, que almacenan datos en tablas con esquemas definidos, usan el lenguaje de consulta estructurado (SQL) y admiten joins y transacciones. RDS admite motores como MySQL, PostgreSQL, MariaDB, Oracle y Microsoft SQL Server, y se encarga del aprovisionamiento, los parches y las copias de seguridad automatizadas con restauración a un punto en el tiempo. Una implementación Multi-AZ mantiene una réplica en espera (standby) en otra Availability Zone y realiza la conmutación por error automáticamente, lo cual sirve para la disponibilidad. Las réplicas de lectura (read replicas) copian los datos de forma asíncrona para poder atender tráfico de lectura, lo cual sirve para el rendimiento. Amazon Aurora es el motor relacional propio de AWS, compatible con MySQL y PostgreSQL, diseñado para mayor rendimiento y disponibilidad, con almacenamiento replicado automáticamente en varias AZ; Aurora Serverless ajusta la capacidad automáticamente.

Amazon DynamoDB es una base de datos NoSQL de clave-valor y documentos, totalmente administrada y serverless. Ofrece un rendimiento consistente de milisegundos de un solo dígito prácticamente a cualquier escala sin servidores que administrar, y es adecuada para aplicaciones con patrones de acceso simples y de alto volumen, como carritos de compras, tablas de clasificación de juegos, perfiles de usuario y datos de sesión. Eliges capacidad bajo demanda (on-demand), que escala automáticamente y cobra por solicitud, o capacidad aprovisionada con escalado automático opcional. DynamoDB Accelerator (DAX) agrega una caché en memoria, y las tablas globales (global tables) replican los datos entre Regiones.

Amazon ElastiCache ofrece cachés en memoria administradas compatibles con Valkey, Redis OSS y Memcached. Colocar una caché delante de una base de datos mantiene en memoria los datos que se leen con frecuencia, lo que reduce los tiempos de respuesta a menos de un milisegundo y disminuye la carga sobre la base de datos. Amazon Redshift es un almacén de datos (data warehouse) para analítica: ejecuta consultas SQL complejas sobre cantidades muy grandes de datos estructurados para informes e inteligencia de negocios, usando almacenamiento columnar y procesamiento en paralelo. Sirve para el procesamiento analítico en línea (OLAP), no para el procesamiento de transacciones en línea (OLTP) del día a día de una aplicación.

Otras bases de datos de propósito específico cubren nichos concretos. Amazon Neptune es una base de datos de grafos para datos muy conectados, como redes sociales, motores de recomendación y detección de fraude. Amazon DocumentDB (compatible con MongoDB) almacena documentos similares a JSON. Amazon Keyspaces es compatible con Apache Cassandra. Amazon Timestream maneja datos de series temporales, como lecturas de sensores de Internet de las cosas (IoT). Amazon MemoryDB es una base de datos en memoria duradera para cuando necesitas la velocidad de la memoria como almacén principal. Para mover bases de datos existentes a estos servicios, AWS Database Migration Service (AWS DMS) migra los datos con un tiempo de inactividad mínimo, y la AWS Schema Conversion Tool ayuda cuando cambias de motor.

Veamos un ejemplo práctico. Una tienda en línea guarda pedidos, pagos e inventario en Aurora PostgreSQL porque necesita transacciones entre tablas relacionadas, y la ejecuta en varias AZ. Sus carritos de compras y datos de sesión van a DynamoDB, que escala sin esfuerzo durante las ofertas. Las páginas de productos se almacenan en caché en ElastiCache para no consultar la base de datos en cada visita. Cada noche, los datos de pedidos se cargan en Redshift, donde los analistas ejecutan informes grandes sin ralentizar la tienda en vivo, y un grafo de Neptune impulsa las recomendaciones de «los clientes que compraron esto también compraron».

Errores comunes: confundir Multi-AZ (una réplica en espera para la conmutación por error) con las réplicas de lectura (copias adicionales para escalar las lecturas); elegir Redshift para las transacciones de una aplicación o RDS para analítica a escala de petabytes; describir DynamoDB como relacional; pensar que ElastiCache es una base de datos principal que conserva los datos de forma duradera (es una caché); y olvidar que en RDS no puedes iniciar sesión en el sistema operativo subyacente, mientras que ejecutar una base de datos en EC2 da control total pero también responsabilidad total. Otra trampa es suponer que administrado significa que AWS configura los permisos de tus usuarios y tus opciones de cifrado; eso sigue siendo tuyo.

En el examen, relaciona las palabras clave con los servicios. «Relacional», «SQL», «joins» o «transacciones» significa RDS o Aurora, con Aurora como favorita para «compatible con MySQL o PostgreSQL con mayor rendimiento». «NoSQL», «clave-valor», «base de datos serverless» o «latencia de milisegundos a cualquier escala» significa DynamoDB. «Caché» o «en memoria para reducir la carga de la base de datos» significa ElastiCache. «Almacén de datos», «inteligencia de negocios» o «analítica sobre petabytes» significa Redshift. «Grafo» o «relaciones entre entidades» significa Neptune, «MongoDB» significa DocumentDB y «series temporales» significa Timestream. «Alta disponibilidad para RDS» significa Multi-AZ.

Términos clave

Amazon RDS
Servicio administrado para motores de bases de datos relacionales como MySQL, PostgreSQL, MariaDB, Oracle y SQL Server.
Amazon Aurora
Motor relacional de AWS compatible con MySQL y PostgreSQL, con almacenamiento replicado en varias AZ.
Implementación Multi-AZ
Configuración de RDS con una réplica en espera síncrona en otra AZ para la conmutación por error automática.
Réplica de lectura (read replica)
Copia de una base de datos actualizada de forma asíncrona que se usa para descargar el tráfico de lectura.
Amazon DynamoDB
Base de datos NoSQL serverless de clave-valor y documentos con rendimiento consistente de milisegundos de un solo dígito.
Amazon ElastiCache
Caché en memoria administrada compatible con Valkey, Redis OSS y Memcached.
Amazon Redshift
Almacén de datos administrado para analítica SQL sobre grandes volúmenes de datos estructurados.
Amazon Neptune
Base de datos de grafos administrada para datos muy conectados.
Ejemplo real

Un juego móvil almacena los perfiles de los jugadores y las tablas de clasificación en DynamoDB, que maneja millones de lecturas por minuto en el lanzamiento sin planificación de capacidad. La facturación y el historial de compras residen en RDS para MySQL con Multi-AZ, porque necesitan transacciones y deben sobrevivir a la falla de una AZ. Los analistas del estudio cargan semanalmente los eventos de juego en Redshift para estudiar en qué niveles abandonan los jugadores, y ElastiCache guarda la lista diaria de los 100 mejores para que cargue al instante.

Consejo para el examen: Multi-AZ es para disponibilidad (conmutación por error automática); las réplicas de lectura son para el rendimiento de lectura. Redshift es analítica (OLAP), no transacciones; DynamoDB es NoSQL, no relacional.

Comprueba lo que sabes

Una empresa necesita una base de datos relacional pero no quiere parcharla ni respaldarla manualmente. ¿Qué servicio?

Amazon RDS (o Aurora), que administra los parches, las copias de seguridad y la conmutación por error.

¿Qué servicio es adecuado para un almacén de clave-valor serverless con rendimiento de milisegundos de un solo dígito a cualquier escala?

Amazon DynamoDB.

¿Qué proporciona una implementación Multi-AZ de RDS?

Una réplica en espera en otra Availability Zone con conmutación por error automática, lo que mejora la disponibilidad y no el rendimiento de lectura.

Los analistas necesitan ejecutar informes SQL complejos sobre años de datos de ventas. ¿Qué servicio encaja mejor?

Amazon Redshift, el almacén de datos creado para analítica a gran escala.
