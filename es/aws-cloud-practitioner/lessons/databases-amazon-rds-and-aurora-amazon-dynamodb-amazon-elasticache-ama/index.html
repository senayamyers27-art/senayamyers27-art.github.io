AWS Certified Cloud Practitioner CLF-C02

Bases de datos: Amazon RDS y Aurora, Amazon DynamoDB, Amazon ElastiCache, Amazon Redshift y otras bases de datos de propósito específico

AWS te anima a elegir una base de datos de propósito específico (purpose-built) para cada trabajo en lugar de forzar todo en un solo motor. También puedes ejecutar cualquier base de datos por tu cuenta en EC2, pero entonces administras la instalación, los parches, los respaldos y la replicación; los servicios de bases de datos administrados asumen ese trabajo.

Amazon Relational Database Service (Amazon RDS) ejecuta bases de datos relacionales, que almacenan datos en tablas con SQL y admiten consultas complejas y transacciones. RDS admite motores como MySQL, PostgreSQL, MariaDB, Oracle y Microsoft SQL Server, y se encarga del aprovisionamiento, los parches, los respaldos automatizados y, con despliegues Multi-AZ, la conmutación automática por error a una instancia en espera en otra AZ. Las réplicas de lectura (read replicas) pueden descargar el tráfico de lectura. Amazon Aurora es el motor relacional propio de AWS, compatible con MySQL y PostgreSQL, diseñado para mayor rendimiento y disponibilidad, con el almacenamiento replicado automáticamente en varias AZ.

Amazon DynamoDB es una base de datos NoSQL de clave-valor y de documentos, totalmente administrada y serverless. Ofrece un rendimiento constante de milisegundos de un solo dígito prácticamente a cualquier escala, sin servidores que administrar, y se adapta a aplicaciones con patrones de acceso simples y de gran volumen, como carritos de compra, tablas de clasificación de juegos y datos de sesión. Eliges capacidad bajo demanda (on-demand) o aprovisionada.

Amazon ElastiCache proporciona cachés en memoria administradas compatibles con Redis OSS, Valkey y Memcached. Colocar una caché delante de una base de datos guarda en memoria los datos que se leen con frecuencia, reduciendo los tiempos de respuesta a microsegundos y la carga sobre la base de datos. Amazon Redshift es un almacén de datos (data warehouse) para análisis: ejecuta consultas SQL complejas sobre cantidades muy grandes de datos estructurados para informes e inteligencia de negocio, usando almacenamiento columnar. Es para análisis (OLAP), no para las transacciones cotidianas de una aplicación (OLTP).

Otras bases de datos de propósito específico incluyen Amazon Neptune (base de datos de grafos para datos muy conectados, como redes sociales y detección de fraude), Amazon DocumentDB (base de datos de documentos compatible con MongoDB), Amazon Keyspaces (compatible con Apache Cassandra), Amazon Timestream (datos de series temporales, como lecturas de sensores IoT) y Amazon MemoryDB (una base de datos en memoria duradera). Para trasladar bases de datos existentes a estos servicios, recuerda AWS DMS de la lección de migración.

Términos clave

Amazon RDS
Un servicio administrado de bases de datos relacionales que admite motores como MySQL, PostgreSQL, Oracle y SQL Server.
Amazon Aurora
Una base de datos relacional construida por AWS, compatible con MySQL y PostgreSQL, con almacenamiento replicado en varias AZ.
Amazon DynamoDB
Una base de datos NoSQL serverless de clave-valor y de documentos con baja latencia constante a cualquier escala.
Amazon ElastiCache
Un servicio administrado de caché en memoria que reduce la carga de la base de datos y los tiempos de respuesta.
Amazon Redshift
Un almacén de datos administrado para análisis SQL a gran escala.
Ejemplo real

Un marketplace en línea guarda los pedidos en Aurora PostgreSQL por su integridad transaccional, mantiene las sesiones y los carritos de los usuarios en DynamoDB, almacena en caché las páginas de productos populares en ElastiCache, carga cada noche los datos de ventas en Redshift para los paneles de la dirección y usa Neptune para detectar redes de cuentas fraudulentas relacionadas.

Consejo para el examen: Relaciona las palabras clave con los servicios: 'relacional' o 'SQL' con transacciones significa RDS o Aurora; 'NoSQL', 'clave-valor' o 'base de datos serverless' significa DynamoDB; 'caché' o 'en memoria' significa ElastiCache; 'almacén de datos' o 'análisis sobre petabytes' significa Redshift; 'grafo' o 'relaciones' significa Neptune.

Comprueba lo que sabes

¿Qué servicio de base de datos elegirías para un almacén de clave-valor serverless con latencia de milisegundos a escala masiva?

Amazon DynamoDB.

Un equipo quiere reducir la carga de lectura sobre su base de datos RDS para los datos de acceso frecuente. ¿Qué servicio ayuda?

Amazon ElastiCache como caché en memoria (las réplicas de lectura de RDS son otra opción para escalar las lecturas).
