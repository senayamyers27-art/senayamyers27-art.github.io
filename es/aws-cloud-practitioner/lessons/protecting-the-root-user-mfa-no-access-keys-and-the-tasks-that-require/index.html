AWS Certified Cloud Practitioner CLF-C02

Proteger el usuario raíz: MFA, sin claves de acceso y las tareas que requieren las credenciales raíz

Cuando creas una cuenta de AWS, inicias sesión con la dirección de correo electrónico y la contraseña que usaste para registrarte. Esa identidad es el usuario raíz (root user), y tiene acceso completo y sin restricciones a todos los recursos y configuraciones de la cuenta, incluida la facturación y la posibilidad de cerrar la cuenta. Las políticas de permisos no pueden limitar al usuario raíz de una cuenta independiente. Como es tan poderoso, protegerlo es una de las primeras cosas que AWS te pide hacer, y las preguntas sobre él aparecen con regularidad en el examen Cloud Practitioner.

Habilita la autenticación multifactor (MFA) en el usuario raíz de inmediato. La MFA exige un segundo factor además de la contraseña, como una clave de acceso (passkey) o una llave de seguridad FIDO, una aplicación autenticadora virtual que genera códigos basados en el tiempo, o un token de hardware, de modo que una contraseña robada no basta por sí sola. En la consola lo haces desde el menú de la cuenta en Security credentials > Multi-factor authentication (MFA) > Assign MFA device. Usa una contraseña fuerte y única, y mantén segura la propia bandeja del correo electrónico raíz, ya que allí llegan los restablecimientos de contraseña. Registrar más de un dispositivo MFA te da un respaldo si pierdes uno.

No crees claves de acceso para el usuario raíz. Las claves de acceso (access keys) son credenciales de largo plazo, un ID de clave de acceso y una clave de acceso secreta, que se usan para el acceso programático mediante la interfaz de línea de comandos de AWS (CLI) o los kits de desarrollo de software (SDK). Las claves de acceso raíz le darían control total de la cuenta a un script, o a cualquiera que las encontrara en un repositorio de código. Si existen claves de acceso raíz, elimínalas. Puedes comprobarlo rápidamente con aws iam get-account-summary, que informa AccountMFAEnabled y AccountAccessKeysPresent para el usuario raíz; quieres 1 y 0, respectivamente.

Para el trabajo diario, incluido el trabajo administrativo, no uses el usuario raíz en absoluto. Crea acceso administrativo mediante AWS IAM Identity Center o roles de IAM con solo los permisos necesarios, e inicia sesión con ellos. Guarda bajo llave las credenciales raíz y monitorea su uso: una alarma de Amazon CloudWatch o una regla de Amazon EventBridge sobre los eventos de inicio de sesión raíz registrados por AWS CloudTrail te avisa de inmediato si alguien las usa. En AWS Organizations, los administradores también pueden administrar de forma centralizada el acceso raíz de las cuentas miembro, eliminando las credenciales raíz de esas cuentas y realizando de forma centralizada las pocas tareas raíz privilegiadas cuando hace falta.

Un pequeño conjunto de tareas solo puede realizarlo el usuario raíz. Algunos ejemplos son cambiar la configuración de la cuenta, como el nombre de la cuenta, la dirección de correo electrónico raíz y la contraseña raíz; cerrar la cuenta de AWS; restaurar los permisos de IAM cuando el único administrador de IAM quedó bloqueado por accidente; ver ciertas facturas de impuestos; registrarse como vendedor en el Reserved Instance Marketplace; habilitar MFA delete en un bucket de S3; y editar o eliminar una política de bucket de S3 que deniega el acceso a todas las entidades principales, incluidos los administradores de la cuenta. AWS publica la lista completa, y ha cambiado con el tiempo, así que aprende el patrón: las acciones de propiedad y recuperación a nivel de cuenta requieren el usuario raíz.

Veamos un ejemplo práctico. El fundador de una pequeña empresa creó la cuenta de AWS hace años y todavía inicia sesión como raíz todos los días, y hay una clave de acceso raíz guardada en un script de despliegue. Una revisión de seguridad señala ambas cosas. El fundador habilita MFA con dos llaves de seguridad, elimina la clave de acceso raíz y reemplaza las credenciales del script por un rol de IAM, crea un conjunto de permisos de administrador en IAM Identity Center para el trabajo diario y configura una alarma sobre los inicios de sesión raíz. La contraseña raíz y las llaves MFA se guardan en una caja fuerte y se usan solo cuando surge una tarea exclusiva del usuario raíz.

Errores comunes: creer que las políticas de IAM pueden restringir al usuario raíz en una cuenta independiente (no pueden, aunque las políticas de control de servicios de AWS Organizations sí pueden restringir las cuentas miembro); pensar que necesitas el usuario raíz para crear usuarios de IAM, lanzar instancias o ver la facturación (los usuarios y roles de IAM con los permisos adecuados pueden hacerlo); compartir las credenciales raíz dentro de un equipo; y conservar claves de acceso raíz 'para emergencias'. Una emergencia que realmente requiere el usuario raíz se atiende iniciando sesión en la consola con la contraseña y la MFA, no con claves.

Las preguntas del examen suelen pedir cómo proteger el usuario raíz o qué tarea lo requiere. 'Buena práctica para el usuario raíz' es habilitar MFA, no crear claves de acceso y usarlo solo para las tareas que lo requieren. '¿Qué tarea requiere las credenciales del usuario raíz?' tiene respuestas como cambiar el correo electrónico raíz o el nombre de la cuenta, cerrar la cuenta o restaurar permisos de IAM bloqueados. Los distractores como 'crear un usuario de IAM', 'lanzar una instancia EC2' o 'ver Cost Explorer' no requieren el usuario raíz.

Términos clave

Usuario raíz (root user)
Identidad creada junto con una nueva cuenta de AWS que tiene acceso sin restricciones a todos los recursos y configuraciones.
Autenticación multifactor (MFA)
Exigir un segundo factor, como una llave de seguridad o un código de una aplicación autenticadora, además de una contraseña.
Claves de acceso (access keys)
Credenciales de largo plazo formadas por un ID de clave de acceso y una clave de acceso secreta, para el acceso programático.
Tarea exclusiva del usuario raíz (root-only task)
Acción a nivel de cuenta, como cerrar la cuenta o cambiar el correo electrónico raíz, que solo puede realizar el usuario raíz.
Acceso raíz centralizado (centralized root access)
Capacidad de AWS Organizations que permite a los administradores eliminar y administrar de forma centralizada las credenciales raíz de las cuentas miembro.
AWS CloudTrail
Servicio que registra la actividad de la API en una cuenta, incluidos los inicios de sesión del usuario raíz.
Ejemplo real

Una organización sin fines de lucro descubre que su factura de AWS se triplicó de la noche a la mañana porque una antigua clave de acceso raíz se había subido a un repositorio de código público y se usó para lanzar instancias. Después de contener el incidente con AWS Support, elimina todas las claves de acceso raíz, habilita MFA en el usuario raíz, pasa al personal a IAM Identity Center con conjuntos de permisos de mínimo privilegio y agrega una alerta ante cualquier inicio de sesión raíz. Ahora las credenciales raíz solo se usan para las poco frecuentes tareas a nivel de cuenta.

Consejo para el examen: Protege el usuario raíz con MFA, elimina cualquier clave de acceso raíz y úsalo solo para las tareas exclusivas del usuario raíz. Cambiar el correo electrónico raíz o el nombre de la cuenta, cerrar la cuenta y restaurar permisos de IAM bloqueados requieren el usuario raíz; crear usuarios de IAM o lanzar instancias no.

Comprueba lo que sabes

¿Qué dos acciones recomienda AWS primero para proteger el usuario raíz?

Habilitar MFA en el usuario raíz y asegurarse de que no tenga claves de acceso (eliminar las que existan).

¿Cuál de estas tareas requiere el usuario raíz: cerrar la cuenta, crear un usuario de IAM o ver Cost Explorer?

Cerrar la cuenta; las otras dos pueden hacerlas identidades de IAM con los permisos adecuados.

¿Por qué el usuario raíz nunca debería tener claves de acceso?

Porque son credenciales de largo plazo con acceso sin restricciones, así que si se filtran le dan a un atacante el control total de la cuenta.

¿Qué deberían usar los administradores para el trabajo administrativo diario en lugar del usuario raíz?

Acceso administrativo mediante IAM Identity Center o roles de IAM con solo los permisos que necesitan.
