AWS Certified Cloud Practitioner CLF-C02

Proteger el usuario raíz: MFA, sin claves de acceso y las tareas que requieren las credenciales raíz

Cuando creas una cuenta de AWS, inicias sesión con la dirección de correo electrónico y la contraseña que usaste para registrarte. Esa identidad es el usuario raíz (root user), y tiene acceso completo y sin restricciones a todos los recursos y configuraciones de la cuenta, incluida la facturación y la posibilidad de cerrar la cuenta. Como es tan poderoso, protegerlo es una de las primeras cosas que AWS te pide hacer.

Habilita la autenticación multifactor (MFA) en el usuario raíz de inmediato. MFA exige un segundo factor, como una aplicación autenticadora, una llave de seguridad física o una passkey, además de la contraseña, de modo que una contraseña robada no basta por sí sola. Usa una contraseña fuerte y única, y mantén segura la propia cuenta de correo del usuario raíz, ya que los restablecimientos de contraseña llegan allí.

No crees claves de acceso (access keys) para el usuario raíz. Las claves de acceso son credenciales de largo plazo para el acceso programático mediante la CLI o los SDK; unas claves de acceso raíz darían control total de la cuenta a un script o a cualquiera que las encontrara. Si existen claves de acceso raíz, elimínalas. Para el trabajo diario, incluido el trabajo administrativo, usa usuarios de IAM Identity Center o roles de IAM con solo los permisos necesarios, y guarda bajo llave las credenciales raíz.

Un pequeño conjunto de tareas solo puede realizarlo el usuario raíz. Algunos ejemplos son cambiar la configuración de la cuenta, como el nombre de la cuenta, la dirección de correo raíz y la contraseña raíz; cerrar la cuenta de AWS; restaurar los permisos cuando el único administrador de IAM quedó bloqueado por accidente; ver ciertas facturas de impuestos; registrarse como vendedor en el Reserved Instance Marketplace; habilitar MFA delete en un bucket de S3; y editar o eliminar una política de bucket de S3 que deniega a todas las entidades principales (principals). AWS publica la lista completa, y ha cambiado con el tiempo, así que aprende el patrón: las acciones de propiedad y recuperación a nivel de cuenta necesitan el usuario raíz.

En AWS Organizations, los administradores también pueden gestionar de forma centralizada el acceso raíz de las cuentas miembro, reduciendo la cantidad de credenciales raíz que existen. Sea cual sea la configuración, el principio es el mismo: el usuario raíz es para tareas poco frecuentes a nivel de cuenta, no para el uso diario.

Términos clave

Root user (usuario raíz)
La identidad creada junto con una cuenta de AWS, que tiene acceso completo a todos los recursos y configuraciones.
Multi-factor authentication (MFA, autenticación multifactor)
Exigir un segundo factor, como un código de autenticador o una llave de seguridad, además de una contraseña.
Access keys (claves de acceso)
Credenciales de largo plazo (access key ID y secret access key) que se usan para el acceso programático a AWS.
Least privilege (mínimo privilegio)
Otorgar solo los permisos necesarios para realizar una tarea; por eso el trabajo diario no debe usar el usuario raíz.
Ejemplo real

La fundadora de una nueva startup se registra en AWS, habilita de inmediato MFA en el usuario raíz con una llave de seguridad física, no tiene que eliminar nada porque nunca se crearon claves de acceso raíz, y luego configura IAM Identity Center con un conjunto de permisos (permission set) de administrador para el trabajo diario. Las credenciales raíz solo se vuelven a usar cuando la empresa necesita cambiar el correo de contacto de la cuenta.

Consejo para el examen: Espera preguntas sobre qué tarea requiere el usuario raíz. Cambiar el correo raíz o el nombre de la cuenta, cerrar la cuenta y restaurar permisos de IAM bloqueados son respuestas clásicas; lanzar instancias, crear usuarios de IAM o ver Cost Explorer no necesitan el usuario raíz.

Comprueba lo que sabes

¿Cuáles son los dos pasos más importantes para proteger el usuario raíz?

Habilitar MFA y no crear claves de acceso raíz (o eliminar las que existan), y luego usar otras identidades para el trabajo diario.
