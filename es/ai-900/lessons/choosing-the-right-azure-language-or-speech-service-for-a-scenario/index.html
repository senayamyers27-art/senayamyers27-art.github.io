Elegir el servicio de lenguaje o de voz de Azure adecuado para un escenario

Las preguntas del dominio 4 suelen describir una necesidad y preguntar qué servicio o función de Azure usar. Igual que con la visión, el método confiable es identificar la entrada (texto o audio) y la salida que busca el escenario, y luego relacionarlas. Esta lección integra el dominio como una guía de decisión.

Si la entrada es texto y la salida es información sobre ese texto, usa Azure AI Language. Elige la función según la salida: qué idioma (detección de idioma), positivo o negativo (análisis de sentimiento), sentimiento sobre aspectos específicos (minería de opiniones), temas principales (extracción de frases clave), personas, lugares, fechas y otras categorías (reconocimiento de entidades con nombre), a qué entidad del mundo real se refiere (vinculación de entidades), datos personales encontrados y enmascarados (detección de PII), una versión más corta (resumen) o tus propias categorías (clasificación de texto personalizada).

Si la entrada es una solicitud de un usuario y la salida es una acción, usa conversational language understanding para obtener la intención y las entidades. Si la salida es una respuesta a partir de contenido de FAQ existente, usa question answering. Si la salida necesita ser texto redactado libremente, como una respuesta detallada y personalizada, un modelo de IA generativa puede ser la mejor opción.

Si la entrada o la salida es audio, usa Azure AI Speech: speech to text para transcripciones y subtítulos, text to speech para salida hablada y speech translation para audio hablado en otro idioma. Si la entrada es texto o documentos que necesitan estar en otro idioma, usa Azure AI Translator: traducción de texto, o traducción de documentos para conservar el formato.

Las soluciones reales encadenan servicios. Un bot de voz multilingüe podría usar speech to text, Translator, CLU o question answering, y luego text to speech. Un pipeline de analítica de llamadas podría usar speech to text por lotes, detección de PII para ocultar números de tarjeta, análisis de sentimiento y resumen.

Cuidado con los distractores que suenan plausibles pero hacen otro trabajo: la extracción de frases clave no evalúa el tono; el análisis de sentimiento no traduce; Translator no maneja audio en vivo (speech translation sí); question answering no extrae entidades para una acción.

Términos clave

Azure AI Language
Servicio para analizar y entender texto, que incluye CLU y question answering.
Azure AI Speech
Servicio para speech to text, text to speech y speech translation.
Azure AI Translator
Servicio para traducir texto y documentos entre idiomas.
Service chaining (encadenamiento de servicios)
Combinar varios servicios de IA en secuencia para que la salida de uno sea la entrada del siguiente.
Ejemplo real

El centro de contacto de una aerolínea transcribe llamadas con speech to text, oculta números de tarjeta con detección de PII, puntúa el sentimiento y resume cada llamada con Azure AI Language, traduce los resúmenes para los equipos regionales con Translator y opera un bot en su sitio web con question answering para las preguntas frecuentes sobre equipaje.

Consejo para el examen: Análisis de texto: Language. Audio: Speech. Otro idioma: Translator, salvo que la entrada sea hablada; entonces, speech translation. Acción a partir de un comando: CLU. Respuesta a partir de FAQ: question answering.

Comprueba lo que sabes

Una empresa quiere convertir a texto las llamadas habladas de los clientes y luego revisar si tienen sentimiento negativo. ¿Qué servicios?

Speech to text de Azure AI Speech y luego análisis de sentimiento de Azure AI Language.

Un sitio web debe traducir sus páginas de ayuda HTML conservando su diseño. ¿Qué capacidad?

Document translation de Azure AI Translator.
