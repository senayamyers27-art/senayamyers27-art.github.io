Grounding y generación aumentada por recuperación (RAG) con tus propios datos

Un modelo de lenguaje grande solo sabe lo que estaba en sus datos de entrenamiento. Nunca ha visto las políticas de tu empresa, tu catálogo de productos ni los anuncios de la semana pasada, y puede inventar con total seguridad una respuesta cuando se le pregunta. El grounding (fundamentación) resuelve esto dándole al modelo información relevante y confiable en el prompt e indicándole que base su respuesta en esa información.

La generación aumentada por recuperación (retrieval augmented generation, RAG) es el patrón estándar para hacer grounding a escala. Primero, tu contenido (documentos, páginas web, registros de bases de datos) se divide en fragmentos (chunks) y se indexa, normalmente en un servicio de búsqueda como Azure AI Search. Cada fragmento se convierte típicamente en un vector de embedding con un modelo de embeddings, para que pueda encontrarse por su significado, a menudo combinado con búsqueda por palabras clave (búsqueda híbrida, hybrid search).

Cuando un usuario hace una pregunta, la app recupera los fragmentos más relevantes del índice. Luego aumenta el prompt: agrega esos fragmentos al mensaje de sistema o de usuario con una instrucción como 'Responde usando solo las fuentes de abajo y cítalas. Si la respuesta no está ahí, di que no lo sabes.' Por último, el modelo genera una respuesta fundamentada en el contenido recuperado. La app puede mostrar las fuentes como citas para que los usuarios las verifiquen.

RAG tiene ventajas importantes. Las respuestas reflejan información actual y privada sin volver a entrenar el modelo; actualizar el índice actualiza las respuestas. Reduce las respuestas inventadas (salidas sin fundamento) y agrega transparencia mediante las citas. Puede respetar los permisos si el paso de recuperación solo devuelve documentos que el usuario tiene permitido ver. Además, suele ser más barato y rápido de configurar que el fine-tuning.

El fine-tuning es diferente: continúa el entrenamiento de un modelo con tus ejemplos para cambiar su comportamiento o estilo. Es útil para enseñar un formato o tono consistente, pero no es la mejor forma de darle a un modelo hechos que cambian, porque el conocimiento queda fijo en el momento del entrenamiento. Para datos factuales que cambian con frecuencia, elige RAG.

En Microsoft Foundry puedes agregar tus propios datos a una solución de chat, conectar un índice de Azure AI Search y probar respuestas fundamentadas en el chat playground. Luego, las evaluaciones pueden medir el groundedness (fundamentación): si las respuestas realmente están respaldadas por las fuentes recuperadas.

Términos clave

Grounding (fundamentación)
Proporcionar información relevante y confiable en el prompt para que el modelo base su respuesta en ella.
Retrieval augmented generation (RAG, generación aumentada por recuperación)
Un patrón que recupera contenido relevante de tus datos y lo agrega al prompt antes de que el modelo genere una respuesta.
Vector index (índice vectorial)
Un índice de búsqueda que almacena embeddings para que el contenido pueda recuperarse por similitud semántica.
Fine-tuning (ajuste fino)
Entrenar más un modelo preentrenado con tus propios ejemplos para cambiar su comportamiento o estilo.
Ejemplo real

Un chatbot de recursos humanos indexa el manual del empleado en Azure AI Search. Cuando un empleado pregunta '¿Cuántos días de licencia parental me corresponden?', la app recupera la sección de la política de licencias, la agrega al prompt y el modelo responde con una cita a esa sección. Cuando recursos humanos actualiza la política, volver a indexar actualiza las respuestas ese mismo día.

Consejo para el examen: El modelo debe responder a partir de tus datos actuales o privados sin volver a entrenar: RAG. El modelo debe adoptar un estilo o formato de forma consistente: el fine-tuning puede ayudar. RAG primero recupera y luego genera.

Comprueba lo que sabes

¿Cuáles son los tres pasos de RAG al momento de la pregunta?

Recuperar contenido relevante del índice, aumentar el prompt con él y generar una respuesta fundamentada.

¿Por qué normalmente se prefiere RAG sobre el fine-tuning para hechos que cambian con frecuencia?

Actualizar el índice cambia las respuestas de inmediato, mientras que el conocimiento de un modelo con fine-tuning queda fijo hasta que vuelves a entrenar.
