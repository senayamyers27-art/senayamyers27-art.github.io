Crear y usar recursos de Azure AI services: recursos multiservicio vs de un solo servicio, endpoints, claves y el nivel gratuito F0

Antes de que tu app pueda llamar a cualquier servicio de Azure AI, necesitas un recurso para ese servicio en tu suscripción de Azure. El recurso te da un endpoint al cual llamar, credenciales para autenticarte y un lugar para la facturación. AI-900 evalúa las decisiones que tomas al crear uno.

Un recurso multiservicio (multi-service resource), llamado Azure AI services en el portal, da acceso a varios servicios de IA, como Vision, Language, Speech, Translator y Document Intelligence, mediante un solo recurso con un solo conjunto de claves y facturación consolidada. Es adecuado para desarrolladores que usan varios servicios y quieren administrarlos juntos. Los modelos de Azure OpenAI y otros modelos de IA generativa también se pueden usar a través de recursos de Foundry, que se cubren en el dominio 5.

Un recurso de un solo servicio (single-service resource) da acceso a un único servicio, como Azure AI Vision o Azure AI Language. Elígelo cuando solo uses ese servicio, quieras llevar sus costos por separado, necesites un límite de acceso separado o quieras el nivel gratuito. La mayoría de los recursos de un solo servicio ofrecen un nivel de precios gratuito F0 con transacciones limitadas por mes, suficiente para aprender y para prototipos; los niveles estándar (como S0) se pagan por uso. El recurso multiservicio no tiene nivel gratuito.

Cada recurso tiene un endpoint, una URL a la que tu app envía solicitudes, y dos claves. Los clientes se autentican enviando una clave en un encabezado de la solicitud o, de preferencia en producción, usando Microsoft Entra ID para que no haya ninguna clave almacenada en el código. Hay dos claves para que puedas regenerar una mientras las apps usan la otra, y luego cambiar, sin tiempo de inactividad. Las claves deben guardarse en un almacén seguro como Azure Key Vault, nunca en el código fuente.

También eliges una región, que afecta la latencia, la residencia de los datos y qué funciones están disponibles, y un grupo de recursos (resource group) para la administración. Después de crear el recurso, puedes probarlo sin código en el portal de Foundry o en el studio del servicio (como Vision Studio o Language Studio), y luego usar la REST API o los SDK desde tu aplicación.

Cuando termines un laboratorio, elimina el recurso o su grupo de recursos para que nada siga generando cargos, y prefiere F0 cuando el servicio lo ofrezca.

Términos clave

Multi-service resource (recurso multiservicio)
Un recurso de Azure AI services que da un endpoint y un conjunto de claves para varios servicios de IA con una sola factura.
Single-service resource (recurso de un solo servicio)
Un recurso para un solo servicio de IA, como Azure AI Vision, a menudo con un nivel gratuito F0.
Endpoint
La URL a la que llama una aplicación para usar el servicio de IA.
Resource key (clave del recurso)
Un valor secreto que se envía con las solicitudes para autenticarse en un servicio de IA; cada recurso tiene dos.
Ejemplo real

Una estudiante que prepara una demostración para su clase crea un recurso de un solo servicio de Azure AI Vision en el nivel F0, guarda el endpoint y la clave en variables de entorno y prueba la función de captions. En cambio, la app de producción de su empleador usa un recurso multiservicio de Azure AI services para Vision, Language y Translator, con autenticación de Microsoft Entra ID y una sola factura consolidada.

Consejo para el examen: Una clave y un endpoint para muchos servicios, una sola factura: multiservicio. Nivel gratuito F0 o facturación separada para un servicio: un solo servicio. Una app necesita el endpoint más una clave (o Entra ID) para llamarlo.

Comprueba lo que sabes

¿Por qué cada recurso de Azure AI services tiene dos claves?

Para poder rotar las claves sin tiempo de inactividad: las apps cambian a la segunda clave mientras se regenera la primera.

¿Qué tipo de recurso deberías elegir para experimentar con Azure AI Language sin costo?

Un recurso de Language de un solo servicio en el nivel gratuito F0, donde esté disponible.
