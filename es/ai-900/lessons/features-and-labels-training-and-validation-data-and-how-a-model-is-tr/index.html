Características y etiquetas, datos de entrenamiento y validación, y cómo se entrena un modelo y luego se usa para inferencia

El machine learning empieza con datos, normalmente organizados como una tabla. Cada fila es una observación (una casa, un paciente, una transacción) y cada columna es un valor que la describe. Entender para qué sirve cada columna es la base de todos los demás temas de ML en AI-900.

Las características (features) son las columnas de entrada que usa el modelo para hacer una predicción. En un modelo de precios de casas, las características podrían ser la superficie, el número de habitaciones, la antigüedad y la distancia a la estación. La etiqueta (label) es la columna que quieres predecir, en este caso el precio de venta. Matemáticamente, un modelo es una función y = f(x), donde x es el conjunto de valores de las características e y es la etiqueta predicha. El entrenamiento es el proceso de encontrar una función que relacione bien x con y.

Cuando los datos de entrenamiento incluyen etiquetas conocidas, el enfoque se llama aprendizaje supervisado (supervised learning): el algoritmo está supervisado por las respuestas correctas. La regresión y la clasificación son supervisadas. Cuando los datos no tienen etiquetas, como en el clustering, es aprendizaje no supervisado (unsupervised learning): el algoritmo encuentra la estructura por sí solo.

Nunca evalúas un modelo solo con los datos de los que aprendió, porque un modelo puede memorizar sus ejemplos de entrenamiento y aun así fallar con ejemplos nuevos. En cambio, divides los datos. La mayoría de las filas (a menudo alrededor del 70 al 80 por ciento) forman el conjunto de entrenamiento del que aprende el algoritmo. El resto se reserva como conjunto de validación (o de prueba). Después del entrenamiento, usas el modelo para predecir las etiquetas de las filas de validación y comparas las predicciones con las etiquetas reales para calcular métricas.

El sobreajuste (overfitting) ocurre cuando un modelo se ajusta demasiado a los datos de entrenamiento, incluido su ruido, y rinde mucho peor con los datos de validación. El subajuste (underfitting) ocurre cuando un modelo es demasiado simple para captar el patrón y rinde mal en ambos. El objetivo es un modelo que generalice: que rinda bien con datos que no ha visto.

El entrenamiento es iterativo. Los científicos de datos prueban distintos algoritmos, ajustan parámetros llamados hiperparámetros (hyperparameters), diseñan mejores características y vuelven a entrenar hasta que las métricas de validación son lo bastante buenas. Luego se implementa el modelo elegido, y las aplicaciones le envían nuevos valores de características para obtener predicciones. Ese uso del modelo es la inferencia (inferencing). En el momento de la inferencia no hay etiqueta; predecirla es precisamente el objetivo.

Términos clave

Feature (característica)
Un valor de entrada que usa el modelo para hacer una predicción, como la edad o la superficie.
Label (etiqueta)
El valor que un modelo supervisado se entrena para predecir, como un precio o un resultado sí/no.
Validation data (datos de validación)
Datos reservados del entrenamiento que se usan para medir qué tan bien rinde el modelo con ejemplos no vistos.
Overfitting (sobreajuste)
Cuando un modelo aprende demasiado de cerca los datos de entrenamiento y rinde mal con datos nuevos.
Ejemplo real

Una empresa de bicicletas compartidas tiene dos años de registros diarios: temperatura, lluvia, día de la semana, indicador de feriado y número de alquileres. Entrena con el 80 por ciento de los días, compara las predicciones con el otro 20 por ciento y luego implementa el modelo para que el pronóstico del clima de mañana produzca una estimación de alquileres para planificar el personal.

Consejo para el examen: Si la pregunta plantea cuál columna es la etiqueta, elige el valor que se está prediciendo. Una gran diferencia entre el rendimiento en entrenamiento y en validación significa overfitting.

Comprueba lo que sabes

En un conjunto de datos para predecir si un correo es spam, ¿cuál es la etiqueta?

La columna de spam o no spam, porque eso es lo que predice el modelo; las palabras y el remitente del correo son características.

¿Por qué los datos de validación deben mantenerse separados de los de entrenamiento?

Para poder medir cómo rinde el modelo con datos que no ha visto, lo que revela el overfitting.
