CompTIA Security+ SY0-701

TPM, HSM, enclave seguro y sistema de gestión de claves

La criptografía solo es tan fuerte como la protección de sus claves. Si una clave privada está en un archivo simple en el disco, el malware o un ladrón pueden copiarla. Security+ cubre varias herramientas de hardware y software diseñadas para generar, almacenar y usar claves manteniéndolas fuera de alcance.

Un Trusted Platform Module (TPM) es un chip, o su equivalente en firmware, integrado en la placa base de una computadora. Puede generar y almacenar claves de forma segura, y en general esas claves no se pueden exportar. Un TPM apoya el arranque seguro y medido (secure and measured boot) registrando los hashes de los componentes de arranque en registros especiales; si el firmware o el bootloader fueron manipulados, las mediciones cambian. Las herramientas de cifrado de disco completo como BitLocker usan el TPM para liberar la clave del disco solo cuando las mediciones de arranque coinciden, así que mover la unidad a otra computadora o alterar el bootloader impide el desbloqueo automático. Un TPM también admite la atestación remota (remote attestation), en la que un dispositivo demuestra su estado de arranque ante un servidor de gestión. Un TPM está ligado a un solo dispositivo.

Un módulo de seguridad de hardware (hardware security module, HSM) es un dispositivo dedicado y resistente a manipulaciones (un appliance, una tarjeta de expansión o un servicio en la nube) creado para generar, almacenar y usar claves a gran volumen. Las autoridades de certificación, los bancos y los procesadores de pagos usan HSM para proteger sus claves más sensibles, como las claves de firma de una CA. Los HSM realizan las operaciones criptográficas internamente para que las claves nunca salgan en texto plano, a menudo aceleran el procesamiento criptográfico y están diseñados para detectar manipulación física y borrar las claves si son atacados. La distinción sencilla: el TPM es por dispositivo y viene integrado; el HSM es de escala empresarial y da servicio a muchos sistemas.

Un enclave seguro (secure enclave) es un área aislada y protegida de un procesador que ejecuta código y maneja datos de forma separada del sistema operativo principal. Incluso si el sistema operativo está comprometido, la memoria del enclave sigue protegida. Los teléfonos y las computadoras usan enclaves seguros para almacenar datos biométricos y claves de pago, y los enclaves son una de las principales formas de proteger los datos en uso, mientras se están procesando.

Un sistema de gestión de claves (key management system, KMS) es el servicio centralizado que gestiona el ciclo de vida de las claves en toda una organización: genera claves, las almacena (a menudo respaldado por un HSM), controla quién y qué puede usarlas, las rota según un calendario, registra todo uso de las claves y las revoca o destruye cuando es necesario. Los proveedores de nube ofrecen servicios KMS que te permiten cifrar almacenamiento y bases de datos con claves que tú controlas. El KMS aporta política y auditoría al uso de las claves, mientras que el HSM proporciona el almacenamiento reforzado que está debajo.

Cuando tengas que elegir entre ellos en una pregunta, busca pistas: 'laptop', 'integridad del arranque' o 'BitLocker' apuntan al TPM; 'autoridad de certificación', 'alto volumen' o 'appliance resistente a manipulaciones' apuntan al HSM; 'área aislada del procesador' o 'datos en uso' apuntan al enclave seguro; 'rotación y auditoría centralizadas de claves' apuntan a un KMS.

Términos clave

Trusted Platform Module, TPM
Un chip en la placa base de un dispositivo que almacena claves de forma segura y admite el arranque seguro y medido.
Hardware security module, HSM (módulo de seguridad de hardware)
Un dispositivo dedicado y resistente a manipulaciones que genera, almacena y usa claves criptográficas de forma segura a escala empresarial.
Secure enclave (enclave seguro)
Un área aislada del procesador que protege el código y los datos frente al sistema operativo principal, incluso mientras están en uso.
Key management system, KMS (sistema de gestión de claves)
Un servicio centralizado para gestionar todo el ciclo de vida, el acceso y la auditoría de las claves criptográficas.
Ejemplo real

La CA interna de una empresa guarda su clave de firma en un HSM, las laptops de los empleados guardan las claves de BitLocker en sus TPM, los teléfonos que se usan para la MFA protegen las plantillas biométricas en un enclave seguro, y el equipo de nube usa el KMS del proveedor para rotar cada año las claves de cifrado de la base de datos.

Consejo para el examen: TPM = un dispositivo, integrado, integridad del arranque. HSM = appliance empresarial dedicado para muchas claves. No los confundas en el examen.

Comprueba lo que sabes

¿Qué tecnología protegería la clave de firma raíz de una autoridad de certificación?

Un módulo de seguridad de hardware (HSM).

¿Cómo ayuda un TPM a detectar un bootloader manipulado?

Mide los componentes de arranque en sus registros; si las mediciones cambian, el TPM no libera las claves y la atestación falla.

¿Qué aporta un KMS además del almacenamiento seguro de claves?

La gestión centralizada del ciclo de vida: control de acceso, rotación, auditoría y revocación de las claves.
