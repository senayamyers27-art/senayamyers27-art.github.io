CompTIA Security+ SY0-701

Ataques criptográficos: downgrade, colisión y cumpleaños

Los algoritmos criptográficos fuertes rara vez se rompen de frente. En su lugar, los atacantes buscan formas de rodearlos: obligar a los sistemas a usar opciones más débiles, explotar debilidades en funciones hash más antiguas o aprovechar las matemáticas de la probabilidad. Security+ nombra tres ataques criptográficos que debes reconocer: los ataques de degradación (downgrade), de colisión y de cumpleaños. Entenderlos explica por qué se retiran los protocolos y algoritmos antiguos, y por qué la configuración importa tanto como la elección del algoritmo.

Un ataque de degradación (downgrade attack) engaña a dos partes para que negocien una versión de protocolo o un cifrado más débil que el que ambas admiten en realidad. Muchos protocolos, incluido TLS, comienzan con una negociación en la que el cliente y el servidor acuerdan la mejor versión y el mejor cifrado que ambos admiten. Un atacante en la ruta (on-path) que pueda interferir en esa negociación puede hacer que cada lado crea que el otro solo admite una opción antigua y vulnerable, como una versión obsoleta de SSL o TLS o un cifrado de grado de exportación. Una vez degradada la conexión, el atacante puede explotar las fallas conocidas del protocolo más débil. El SSL stripping es un ataque relacionado que reescribe los enlaces HTTPS a HTTP simple para que el usuario nunca obtenga una conexión cifrada.

Las defensas contra la degradación son principalmente de configuración. Deshabilita las versiones antiguas de protocolo (SSL 2.0, SSL 3.0, TLS 1.0 y 1.1) y los conjuntos de cifrado débiles en servidores y clientes, para que no haya nada débil a lo que retroceder. TLS 1.3 incluye protección integrada contra la degradación y elimina muchas opciones heredadas. Para los sitios web, HTTP Strict Transport Security (HSTS) indica a los navegadores que usen siempre HTTPS, lo que derrota el SSL stripping, y las listas de precarga de HSTS protegen incluso la primera visita. Analizar con regularidad la configuración TLS de tus servidores muestra si todavía hay opciones débiles habilitadas.

Una colisión ocurre cuando dos entradas distintas producen el mismo hash. Un buen hash criptográfico debería hacer inviable encontrar colisiones. Cuando los investigadores demuestran formas prácticas de crear colisiones, como ha ocurrido con MD5 y SHA-1, ya no se puede confiar en el algoritmo para fines de seguridad. El peligro es la falsificación: si un atacante puede crear un documento inofensivo y uno malicioso con el mismo hash, una firma sobre la versión inofensiva también es válida para la maliciosa, porque las firmas se calculan sobre el hash. Hay ataques reales que usaron colisiones de MD5 para falsificar certificados. La defensa es usar algoritmos resistentes a colisiones, como SHA-256, SHA-384 o SHA-3, y dejar de aceptar MD5 y SHA-1 para las firmas.

El ataque de cumpleaños (birthday attack) se basa en la paradoja del cumpleaños: en una sala con solo 23 personas, hay cerca de un 50 por ciento de probabilidad de que dos compartan cumpleaños, muchas menos personas de las que la mayoría espera. La misma matemática se aplica a los hashes. Encontrar dos entradas cualesquiera que colisionen requiere aproximadamente la raíz cuadrada del número de valores hash posibles, no el número completo. Para un hash de n bits, eso es cerca de 2 elevado a n/2 intentos. Así, un hash de 128 bits como MD5 ofrece solo unos 64 bits de resistencia a colisiones, lo que está al alcance de la computación moderna. La defensa es simplemente usar salidas de hash más largas: SHA-256 ofrece unos 128 bits de resistencia a colisiones, algo muy por encima de cualquier ataque práctico.

Veamos una verificación de hardening. Un equipo de seguridad analiza sus servidores web públicos y encuentra uno que todavía acepta TLS 1.0 con un conjunto de cifrado antiguo por 'compatibilidad'. Confirman con los logs que ningún cliente real lo usa, lo deshabilitan, habilitan solo TLS 1.2 y 1.3 y activan HSTS. Una herramienta como el siguiente comando muestra qué protocolo negociará un servidor:

openssl s_client -connect www.example.com:443 -tls1_1
# a handshake failure here is the desired result once old versions are disabled

Errores comunes: pensar que un algoritmo fuerte te protege si los débiles siguen habilitados (los ataques de degradación apuntan a la opción más débil que se ofrece); tratar una colisión como si fuera lo mismo que revertir un hash (una colisión encuentra dos entradas con hashes iguales, no recupera la entrada original); creer que el ataque de cumpleaños consiste en adivinar el cumpleaños de las personas; y suponer que el ataque requiere el trabajo completo de 2^n. Palabras clave del examen: 'obligado a usar un protocolo más antiguo y débil', 'negociación' y 'retroceso (fallback)' apuntan a una degradación. 'Dos archivos distintos con el mismo hash' es una colisión. 'Probabilidad', 'raíz cuadrada' y 'un hash más corto es más vulnerable' apuntan a un ataque de cumpleaños. Las soluciones son deshabilitar los protocolos heredados y usar HSTS contra la degradación, y usar funciones hash modernas y más largas contra los ataques de colisión y de cumpleaños.

Términos clave

Ataque de degradación (downgrade attack)
Obligar a las partes a negociar una versión de protocolo o un cifrado más débil que el que ambas admiten.
SSL stripping
Reescribir conexiones o enlaces HTTPS a HTTP simple para que el tráfico no esté cifrado.
Colisión (collision)
Dos entradas distintas que producen el mismo valor hash.
Ataque de cumpleaños (birthday attack)
Aprovechar la probabilidad para encontrar colisiones de hash en aproximadamente la raíz cuadrada de los valores hash posibles.
Resistencia a colisiones (collision resistance)
La propiedad de que sea inviable encontrar dos entradas con el mismo hash.
HSTS
HTTP Strict Transport Security, un encabezado que indica a los navegadores que usen solo HTTPS para un sitio.
Ejemplo real

Un auditor descubre que un proceso interno de firma de código todavía usa SHA-1. Como se han demostrado colisiones prácticas de SHA-1, un atacante podría en principio preparar un archivo benigno y uno malicioso con el mismo hash, lograr que se firme el benigno y reutilizar la firma. El equipo migra la firma a SHA-256, vuelve a firmar las versiones actuales y configura los endpoints para rechazar las firmas SHA-1.

Consejo para el examen: Los ataques de degradación explotan cualquier opción débil que siga habilitada, así que la solución es deshabilitarla. Los ataques de cumpleaños reducen a la mitad la fuerza efectiva de un hash contra colisiones, así que la solución es un hash moderno y más largo.

Comprueba lo que sabes

¿Por qué deshabilitar las versiones antiguas de TLS protege contra los ataques de degradación?

Si las versiones débiles no se admiten, no hay nada más débil a lo que un atacante pueda forzar la conexión.

¿Qué hace que una colisión sea peligrosa para las firmas digitales?

Las firmas se calculan sobre el hash, así que si dos documentos comparten un hash, la firma de uno es válida para el otro.

¿Aproximadamente cuánto trabajo necesita un ataque de cumpleaños contra un hash de 128 bits?

Unos 2 elevado a 64 intentos, la raíz cuadrada del número de valores posibles.

¿Encontrar una colisión es lo mismo que revertir un hash a su entrada original?

No; una colisión encuentra dos entradas que comparten un hash, mientras que revertirlo (un ataque de preimagen) encuentra una entrada para un hash dado.
