OWASP Top 10: control de acceso roto, inyección, configuración incorrecta, fallas de integridad y SSRF

El Open Worldwide Application Security Project (OWASP) es una comunidad sin fines de lucro que publica guías gratuitas sobre seguridad de aplicaciones web. Su documento más conocido, el OWASP Top 10, clasifica las categorías de riesgo más críticas de las aplicaciones web y se actualiza cada pocos años. Security+ no te exige memorizar la clasificación, pero debes reconocer las categorías principales y lo que defiende contra cada una.

El control de acceso roto (broken access control) significa que los usuarios pueden actuar fuera de sus permisos previstos. Algunos ejemplos son cambiar un ID en una URL para ver el pedido de otro cliente (una referencia directa a objetos insegura, insecure direct object reference), llegar a páginas de administración adivinando su ruta, o elevar privilegios modificando una solicitud. Se mantiene constantemente entre los riesgos más graves. La solución es aplicar la autorización en el servidor para cada solicitud, denegar por defecto y nunca depender de ocultar enlaces ni de verificaciones hechas solo en el navegador.

La inyección (injection) ocurre cuando una entrada no confiable se envía a un intérprete como parte de un comando o una consulta, de modo que la entrada cambia el significado del comando. La inyección SQL, la inyección de comandos del sistema operativo y la inyección LDAP son ejemplos. Las defensas centrales son las consultas parametrizadas (prepared statements), la validación de entradas en el servidor y el uso de APIs seguras en lugar de construir comandos concatenando cadenas. En las listas recientes de OWASP, el cross-site scripting también se agrupa bajo inyección.

La configuración de seguridad incorrecta (security misconfiguration) abarca ajustes inseguros: cuentas predeterminadas que se dejan habilitadas, funciones innecesarias instaladas, mensajes de error detallados que revelan stack traces, encabezados de seguridad faltantes, listado de directorios activado o almacenamiento en la nube abierto al público. Las defensas son configuraciones base reforzadas, verificaciones automatizadas de la configuración y eliminar todo lo que no se necesite.

Las fallas de integridad de software y datos (software and data integrity failures) ocurren cuando se confía en código o datos sin verificarlos. Algunos ejemplos son aplicaciones que descargan actualizaciones o plugins sin verificar las firmas, pipelines de compilación inseguros que permiten a los atacantes insertar código y la deserialización de datos no confiables. La firma de código, la verificación de hashes, la protección del pipeline de CI/CD y el uso de repositorios de confianza atienden esta categoría.

El server-side request forgery (SSRF) engaña a un servidor para que haga solicitudes en nombre del atacante. Si una aplicación obtiene una URL proporcionada por el usuario, por ejemplo para mostrar la vista previa de una imagen, un atacante podría indicar una dirección interna para que el servidor obtenga datos de sistemas internos o de un servicio de metadatos de la nube que el atacante no puede alcanzar directamente. Las defensas incluyen validar los destinos y usar listas de permitidos, bloquear las solicitudes a rangos de direcciones internas y segmentar la red para que el servidor web no pueda llegar a servicios internos sensibles.

Otras categorías de la lista de 2021 incluyen fallas criptográficas, diseño inseguro, componentes vulnerables y desactualizados, fallas de identificación y autenticación, y fallas de registro y monitoreo de seguridad. Los nombres y las agrupaciones de las categorías cambian entre ediciones (la edición de 2025, por ejemplo, integra SSRF dentro de broken access control), así que aprende los conceptos y no la lista exacta. Un firewall de aplicaciones web puede ayudar a detectar algunos ataques, pero complementa la programación segura, no la reemplaza.

Términos clave

OWASP Top 10
Una lista actualizada periódicamente de las categorías de riesgo de seguridad más críticas de las aplicaciones web.
Broken access control (control de acceso roto)
Fallas que permiten a los usuarios actuar fuera de sus permisos previstos, como ver los datos de otros usuarios.
Injection (inyección)
Enviar una entrada no confiable a un intérprete para que se ejecute como parte de un comando o una consulta.
Server-side request forgery, SSRF (falsificación de solicitudes del lado del servidor)
Un ataque que hace que un servidor envíe solicitudes a destinos no previstos, a menudo sistemas internos.
Integrity failure (falla de integridad)
Confiar en código, actualizaciones o datos sin verificar que sean auténticos y no hayan sido alterados.
Ejemplo real

Un cliente se da cuenta de que al cambiar order=1001 por order=1002 en la URL de una tienda ve el pedido de otra persona. Los desarrolladores corrigen este control de acceso roto verificando en el servidor que el usuario que inició sesión sea el dueño de cada pedido antes de devolverlo.

Consejo para el examen: Cambiar un ID para ver los datos de otra persona es control de acceso roto. Un servidor que obtiene una URL interna elegida por el atacante es SSRF. Confiar en actualizaciones sin firma es una falla de integridad.

Comprueba lo que sabes

¿Cuál es la defensa principal contra las fallas de inyección?

Las consultas parametrizadas o las APIs seguras, combinadas con la validación de entradas del lado del servidor.

¿Por qué el SSRF es peligroso en los entornos de nube?

Se puede engañar al servidor para que llegue a servicios internos, como los metadatos de la instancia, que contienen credenciales o datos sensibles inalcanzables desde internet.

Da un ejemplo de configuración de seguridad incorrecta.

Cuentas de administrador predeterminadas que se dejan habilitadas, mensajes de error detallados, listado de directorios o almacenamiento en la nube legible públicamente.
