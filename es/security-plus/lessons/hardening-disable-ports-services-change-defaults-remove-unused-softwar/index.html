CompTIA Security+ SY0-701

Hardening: deshabilitar puertos y servicios, cambiar valores predeterminados y eliminar software sin uso

El hardening (endurecimiento) significa reducir la superficie de ataque de un sistema y configurarlo de forma segura antes y durante todo su uso. De fábrica, muchos sistemas operativos, dispositivos de red y aplicaciones están configurados para una instalación fácil y no para la seguridad: hay servicios adicionales en ejecución, existen cuentas predeterminadas y hay funciones cómodas pero riesgosas habilitadas. El hardening revierte eso.

Deshabilitar los puertos y servicios innecesarios es el primer paso. Cada servicio en escucha es un punto de entrada potencial y algo más que parchear. Si un servidor solo necesita servir páginas web, no debería ejecutar también compartición de archivos, escritorio remoto, un servidor FTP o una interfaz de administración antigua. Puedes listar los puertos en escucha con comandos como ss -tulpn en Linux o netstat -ano en Windows, o escanear el host desde otra máquina que controles, y luego detener y deshabilitar todo lo que no se requiera. Los firewalls basados en host agregan una segunda capa al bloquear los puertos que no deberían ser alcanzables. En los switches, deshabilita los puertos físicos sin uso para que nadie pueda simplemente conectar un dispositivo no autorizado.

Cambiar los valores predeterminados es lo siguiente. Los nombres de usuario y contraseñas predeterminados de routers, cámaras, impresoras, bases de datos y consolas de administración están documentados públicamente, y los ataques automatizados los prueban constantemente; algunas botnets de IoT se construyeron casi por completo de esta manera. Cambia las contraseñas predeterminadas por otras fuertes y únicas, renombra o deshabilita las cuentas de administrador predeterminadas cuando sea posible, y cambia otros valores predeterminados riesgosos, como las community strings de SNMP, la configuración predeterminada de la red Wi-Fi y las páginas web de ejemplo. Algunas regulaciones ahora desalientan que los dispositivos se vendan con contraseñas predeterminadas universales, pero siempre debes verificarlo.

Eliminar el software sin uso reduce la cantidad de código que puede contener vulnerabilidades. El software de prueba preinstalado (bloatware), los runtimes antiguos, los plugins de navegador sin uso, las aplicaciones de ejemplo y las herramientas de desarrollo en los servidores de producción deben desinstalarse. El software que no está instalado no necesita parches y no se puede explotar.

El hardening suele guiarse por líneas base seguras (secure baselines): configuraciones documentadas y probadas para cada tipo de sistema. Las organizaciones las construyen a partir de las guías de los fabricantes y de referencias de la industria, como los CIS Benchmarks del Center for Internet Security o las guías gubernamentales de implementación técnica de seguridad. Luego, las líneas base se despliegan de forma consistente con herramientas como Group Policy, la gestión de configuración o la infraestructura como código, y los sistemas se revisan periódicamente para detectar desviaciones (drift) respecto de la línea base. Otros pasos de hardening incluyen habilitar firewalls de host y protección de endpoints, aplicar cifrado, exigir autenticación fuerte, configurar el registro de eventos y aplicar parches.

El hardening se aplica en todas partes: estaciones de trabajo, servidores, dispositivos móviles, equipos de red, recursos en la nube, dispositivos embebidos e IoT, y sistemas industriales. El objetivo y el método son los mismos cada vez: saber qué debe hacer el sistema, permitir solo eso y eliminar o bloquear todo lo demás.

Términos clave

Hardening (endurecimiento)
Reducir la superficie de ataque de un sistema y aplicar configuraciones seguras.
Secure baseline (línea base segura)
Una configuración segura documentada y aprobada que se usa como estándar para un tipo de sistema.
Default credentials (credenciales predeterminadas)
Nombres de usuario y contraseñas de fábrica que son de conocimiento público y deben cambiarse.
Configuration drift (desviación de configuración)
La desviación gradual de la configuración de un sistema respecto de su línea base aprobada.
CIS Benchmarks
Guías de configuración segura basadas en consenso para muchos sistemas operativos, aplicaciones y dispositivos.
Ejemplo real

Antes de desplegar un nuevo servidor web, una administradora aplica la línea base de la organización: deshabilita los servicios de FTP e impresión que no se usan, cierra todos los puertos excepto el 443 y un puerto SSH restringido, elimina las aplicaciones web de ejemplo, cambia la cuenta de administrador predeterminada y habilita el envío de logs al SIEM.

Consejo para el examen: Si la pregunta trata de reducir la superficie de ataque, la respuesta suele ser el hardening: deshabilitar los servicios y puertos innecesarios, cambiar las credenciales predeterminadas y eliminar el software sin uso.

Comprueba lo que sabes

¿Por qué se deben deshabilitar los servicios sin uso aunque estén parcheados?

Cada servicio en ejecución es un punto de entrada adicional que puede tener vulnerabilidades futuras o estar mal configurado; eliminarlo reduce la superficie de ataque.

¿Qué hace que las credenciales predeterminadas sean tan peligrosas?

Están documentadas públicamente, así que los atacantes y las herramientas automatizadas pueden probarlas contra cualquier dispositivo expuesto.

¿Para qué se usa una línea base segura?

Define la configuración segura aprobada para un tipo de sistema, para que los sistemas se construyan de forma consistente y se puedan revisar en busca de desviaciones.
