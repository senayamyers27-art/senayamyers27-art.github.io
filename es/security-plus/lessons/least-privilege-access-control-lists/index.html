Privilegio mínimo y listas de control de acceso

El principio de privilegio mínimo (least privilege) dice que cada usuario, proceso y sistema debe tener solo el acceso mínimo necesario para hacer su trabajo, y solo durante el tiempo que lo necesite. Es una de las ideas más importantes en seguridad porque limita el daño causado por errores, malware y cuentas comprometidas. Si la cuenta de una recepcionista es víctima de phishing, el privilegio mínimo significa que el atacante obtiene el acceso de una recepcionista, no el de un administrador del dominio.

Aplicar el privilegio mínimo se ve así en la práctica. Los usuarios hacen su trabajo diario con cuentas estándar y usan una cuenta administrativa separada solo cuando es necesario. Las cuentas de servicio reciben solo los permisos que el servicio requiere. El acceso se otorga según el rol, en lugar de copiarse del de un colega. El acceso temporal, como el del proyecto de un contratista, vence automáticamente. Las herramientas de acceso just-in-time y de gestión de acceso privilegiado (PAM) otorgan derechos elevados solo por un tiempo limitado y registran su uso. Las revisiones de acceso periódicas eliminan los permisos que se han acumulado con el tiempo, un problema llamado privilege creep (acumulación de privilegios), que es común cuando las personas cambian de rol y conservan sus accesos anteriores.

Una lista de control de acceso (access control list, ACL) es una de las herramientas principales para aplicar el privilegio mínimo. Una ACL es una lista ordenada de reglas asociada a un recurso que especifica a quién o a qué se le permite o se le niega el acceso y qué puede hacer. Hay dos tipos comunes. Las ACL del sistema de archivos y de objetos, como los permisos NTFS en una carpeta de Windows, enumeran usuarios o grupos con permisos como lectura, escritura, modificación o control total. Las ACL de red en routers, switches y firewalls enumeran reglas que permiten o niegan el tráfico según la dirección IP de origen y destino, el protocolo y el puerto.

Las ACL de red se procesan de arriba hacia abajo, y gana la primera regla que coincide. Por eso, las reglas específicas van arriba de las generales. La mayoría de las ACL terminan con un implicit deny (denegación implícita): cualquier tráfico que no coincida con un permiso explícito se descarta. Ese comportamiento apoya el privilegio mínimo, porque solo pasa lo que permites deliberadamente. Una regla típica podría decir, en lenguaje sencillo, 'permitir TCP desde la subred de administración hacia la subred de servidores en el puerto 22', sin nada más para SSH, de modo que cualquier otro origen queda denegado.

Las ACL bien gestionadas asignan permisos a grupos en lugar de a usuarios individuales, lo que facilita los cambios y las revisiones. Deben documentarse, revisarse como parte de la gestión de cambios y probarse, porque una regla demasiado amplia como 'permit any any' anula su propósito sin que nadie lo note.

El privilegio mínimo también se aplica a las aplicaciones y los sistemas: la cuenta de base de datos de una aplicación web no debe ser administradora de la base de datos, y un contenedor no debe ejecutarse como root. Cuando el examen pregunte por el principio que limita el impacto de una cuenta comprometida, la respuesta es el privilegio mínimo.

Términos clave

Least privilege (privilegio mínimo)
Otorgar solo el acceso mínimo necesario para realizar una tarea, durante el tiempo mínimo.
Access control list, ACL (lista de control de acceso)
Una lista ordenada de reglas en un recurso o dispositivo de red que permite o niega el acceso.
Implicit deny (denegación implícita)
La regla predeterminada al final de una ACL que bloquea todo lo que no se haya permitido de forma explícita.
Privilege creep (acumulación de privilegios)
La acumulación gradual de permisos innecesarios a medida que los usuarios cambian de rol.
Privileged access management, PAM (gestión de acceso privilegiado)
Herramientas y procesos que controlan, limitan en el tiempo y monitorean el uso de cuentas con privilegios elevados.
Ejemplo real

Durante una revisión trimestral de accesos, un gerente ve que una empleada que pasó de nómina a marketing hace dos años todavía tiene acceso de escritura al recurso compartido de nómina. Se elimina ese acceso, lo que reduce la acumulación de privilegios y el riesgo si su cuenta llegara a verse comprometida.

Consejo para el examen: Las ACL de red se leen de arriba hacia abajo, gana la primera coincidencia y terminan con un implicit deny. Coloca las reglas específicas antes que las generales.

Comprueba lo que sabes

¿Qué pasa con el tráfico que no coincide con ninguna regla en una ACL de red típica?

Se descarta por el implicit deny al final de la lista.

¿Por qué los administradores deben usar cuentas separadas para las tareas administrativas?

Así las actividades diarias, como el correo y la navegación, se ejecutan sin derechos elevados, lo que limita el daño si esa cuenta se ve comprometida.

¿Qué control detecta y corrige la acumulación de privilegios?

Las revisiones de acceso periódicas (recertificación), que eliminan los permisos que ya no se necesitan.
