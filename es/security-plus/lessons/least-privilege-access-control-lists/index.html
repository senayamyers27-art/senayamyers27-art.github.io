CompTIA Security+ SY0-701

Privilegio mínimo y listas de control de acceso

El principio de privilegio mínimo establece que cada usuario, proceso y sistema debe tener solo el acceso que necesita para hacer su trabajo, y nada más, y solo durante el tiempo que lo necesite. Importa porque el acceso excesivo convierte incidentes pequeños en grandes: si un usuario víctima de phishing es administrador local, el malware se ejecuta como administrador; si la cuenta de base de datos de una aplicación web puede eliminar tablas, una falla de inyección SQL puede destruir datos. El privilegio mínimo no detiene todos los ataques, pero limita el radio de impacto de los que tienen éxito.

El privilegio mínimo se aplica en todas partes. Los usuarios reciben cuentas estándar para el trabajo diario y cuentas privilegiadas separadas para la administración, que usan solo cuando es necesario. Las cuentas de servicio reciben solo los permisos que usa su aplicación. Las aplicaciones se ejecutan como usuarios con pocos privilegios en lugar de root o SYSTEM. Los roles en la nube otorgan acciones específicas sobre recursos específicos en lugar de políticas amplias de administrador. Otros principios relacionados lo respaldan: la necesidad de saber (need to know; acceso a información específica solo cuando se requiere para una tarea), la separación de funciones (ninguna persona controla por sí sola todo un proceso sensible) y el acceso justo a tiempo (just-in-time; privilegios otorgados temporalmente cuando se solicitan y retirados de forma automática).

Las listas de control de acceso (ACL) son una de las principales herramientas para implementar el privilegio mínimo. Una ACL es una lista ordenada de reglas asociada a un recurso que indica a quién o a qué se le permite o se le niega cada tipo de acceso. Las ACL del sistema de archivos, como los permisos NTFS en Windows o las ACL POSIX en Linux, enumeran usuarios y grupos con derechos como lectura, escritura, modificación y ejecución. Las ACL de red en routers, switches y subredes en la nube enumeran reglas de permitir y denegar basadas en direcciones de origen y destino, protocolos y puertos. El concepto es el mismo: reglas explícitas asociadas a un recurso que se evalúan cuando se intenta el acceso. Las plataformas en la nube agregan sus propias versiones, como las ACL de red en las subredes y los grupos de seguridad en las instancias, y las políticas de identidad que enumeran qué acciones puede realizar un rol sobre qué recursos.

Las ACL de red normalmente se procesan de arriba hacia abajo, y gana la primera regla que coincide. La mayoría termina con una denegación implícita: todo lo que no se permite explícitamente se bloquea. Eso hace que el orden de las reglas sea crítico. Un permiso amplio colocado por encima de una denegación específica significa que nunca se llega a la denegación. En los sistemas de archivos, Windows evalúa la combinación de permisos de todos los grupos de un usuario, y una denegación explícita normalmente prevalece sobre un permiso. Gestionar el acceso mediante grupos en lugar de usuarios individuales mantiene las ACL legibles y hace que los cambios sean más seguros. Cuando se incorpora un nuevo analista, lo agregas al grupo 'Finance-Read' en lugar de editar decenas de entradas individuales de ACL, y cuando se va, una sola eliminación le quita todo ese acceso de una vez.

Este es un ejemplo práctico de una ACL de red que protege una subred de base de datos. El objetivo es permitir que solo los servidores de aplicaciones lleguen a la base de datos en su puerto, permitir que el servidor de monitoreo la verifique y bloquear todo lo demás, registrando los intentos:

access-list DB-IN permit tcp 10.20.5.0 0.0.0.255 host 10.30.1.10 eq 1433
access-list DB-IN permit icmp host 10.99.0.5 host 10.30.1.10
access-list DB-IN deny   ip any any log
```

El privilegio mínimo se deteriora con el tiempo por la acumulación de privilegios (privilege creep): las personas cambian de rol, conservan los permisos antiguos y obtienen otros nuevos, hasta que un empleado con muchos años en la empresa puede llegar a casi todo. Las revisiones periódicas de acceso (recertificación), en las que los gerentes confirman que el acceso de cada persona sigue siendo necesario, son el control que contrarresta esa acumulación. El aprovisionamiento automatizado vinculado a roles y el desaprovisionamiento oportuno cuando las personas se van mantienen los permisos alineados con los puestos. Monitorear el uso de cuentas privilegiadas y alertar sobre nuevos miembros en los grupos de administradores ayuda a detectar el mal uso. Las herramientas de gestión de acceso privilegiado (PAM) van más allá: guardan las credenciales de administrador en una bóveda, las entregan solo para tareas aprobadas y graban las sesiones.

Errores comunes: otorgar acceso amplio 'temporalmente' y nunca retirarlo; confundir las ACL con los firewalls en general (un firewall usa reglas similares a una ACL, pero también puede rastrear el estado de las conexiones e inspeccionar aplicaciones); colocar las reglas en el orden equivocado; olvidar la denegación implícita; y pensar que el privilegio mínimo solo se aplica a las personas, cuando las cuentas de servicio y las aplicaciones suelen ser las que tienen más privilegios de sobra. Palabras clave del examen: 'solo los permisos necesarios para el trabajo' es privilegio mínimo; 'el empleado conservó el acceso de un rol anterior' es acumulación de privilegios, que se corrige con revisiones de acceso; 'orden de las reglas', 'entradas de permitir y denegar' y 'denegación implícita' apuntan a las ACL; 'ninguna persona puede completar el proceso sola' es separación de funciones.

Términos clave

Privilegio mínimo (least privilege)
Otorgar solo el acceso mínimo necesario para realizar una tarea y solo durante el tiempo necesario.
Lista de control de acceso (ACL)
Una lista ordenada de reglas en un recurso que especifica a qué sujetos se les permite o niega cada acceso.
Denegación implícita (implicit deny)
La regla predeterminada que bloquea todo lo que no se permite explícitamente.
Acumulación de privilegios (privilege creep)
La acumulación gradual de accesos innecesarios a medida que los usuarios cambian de rol.
Revisión de acceso (access review)
Una verificación periódica en la que los responsables confirman que el acceso de cada usuario sigue siendo necesario.
Necesidad de saber (need to know)
Restringir el acceso a la información a quienes la requieren para una tarea específica.
Separación de funciones (separation of duties)
Dividir un proceso sensible entre varias personas para que nadie pueda completarlo solo.
Ejemplo real

Una revisión de acceso en un hospital descubre que una enfermera que pasó a un puesto de facturación hace tres años todavía tiene acceso completo a los expedientes clínicos, además de nuevos permisos de facturación y una antigua membresía en un grupo de administradores de servidores de un proyecto. Su gerente elimina los derechos clínicos y de administración y conserva solo el acceso de facturación. Después, la organización automatiza el aprovisionamiento basado en roles para que un cambio de rol provoque la eliminación del acceso del rol anterior.

Consejo para el examen: Las ACL se procesan de arriba hacia abajo, gana la primera coincidencia y hay una denegación implícita al final. Si se coloca una denegación específica después de un permiso amplio, la denegación nunca surte efecto.

Comprueba lo que sabes

¿Cómo reduce el privilegio mínimo el impacto de un ataque de phishing exitoso?

El malware se ejecuta con los derechos limitados de la víctima, así que no puede instalar controladores, cambiar la configuración del sistema ni llegar a datos a los que el usuario no tiene acceso.

La ACL de un router permite todo el tráfico de 10.0.0.0/8 en la línea 1 y niega el host 10.1.1.5 en la línea 2. ¿Se bloquea 10.1.1.5?

No; se aplica la primera regla que coincide (el permiso amplio), así que nunca se llega a la denegación.

¿Qué control aborda mejor la acumulación de privilegios?

Las revisiones periódicas de acceso (recertificación), respaldadas por el aprovisionamiento y desaprovisionamiento basados en roles.

¿Por qué los administradores deberían usar cuentas separadas para el trabajo administrativo?

Para que las actividades cotidianas, como el correo y la navegación, se ejecuten sin derechos de administrador, lo que limita el daño si esas actividades llevan a un compromiso.
