CompTIA Security+ SY0-701

Niveles de cifrado: disco completo, partición, archivo, base de datos y registro

Los datos en reposo se pueden cifrar a distintos niveles, desde la unidad completa hasta un solo campo de una base de datos. Cada nivel protege contra amenazas diferentes, y elegir el correcto es un escenario frecuente en el examen. La pregunta guía es: ¿de quién o de qué necesitas proteger los datos, y cuándo se descifran?

El cifrado de disco completo (full disk encryption, FDE) cifra todo un dispositivo de almacenamiento, incluidos el sistema operativo, el espacio de intercambio (swap) y los archivos temporales. BitLocker en Windows y FileVault en macOS son ejemplos, y algunas unidades lo hacen por hardware como unidades autocifradas (self-encrypting drives, SEDs). El FDE protege contra la pérdida física: si roban una laptop apagada, el ladrón solo ve texto cifrado. La limitación es que, una vez que el sistema arranca y se desbloquea, los datos se descifran de forma transparente para cualquiera que use la máquina, incluido el malware que se ejecuta como el usuario que inició sesión. El FDE a menudo usa un Trusted Platform Module (TPM) para proteger la clave.

El cifrado de partición o de volumen cifra solo una partición o volumen específico, por ejemplo un volumen de datos en un servidor mientras el volumen del sistema queda sin cifrar. Es útil cuando solo una parte del almacenamiento contiene datos sensibles o cuando distintos volúmenes necesitan claves diferentes.

El cifrado a nivel de archivo cifra archivos o carpetas individuales, como con Encrypting File System (EFS) de Windows o al cifrar un solo archivo comprimido con contraseña. La protección puede viajar con el archivo y puede vincularse a usuarios específicos, de modo que otro usuario que haya iniciado sesión en la misma computadora aun así no pueda abrirlo. Es más granular, pero más difícil de gestionar a gran escala, y los usuarios pueden olvidarse de usarlo.

Los enfoques a nivel de volumen y de archivo no protegen los datos dentro de una base de datos en ejecución, porque el motor de la base de datos descifra el almacenamiento para trabajar con él. El cifrado de base de datos atiende eso. El cifrado transparente de base de datos (transparent database encryption) cifra los archivos de la base de datos en disco sin cambiar las aplicaciones. El cifrado a nivel de registro o de columna (a nivel de campo) va más allá y cifra filas o columnas específicas, como números de tarjeta de crédito o números de identificación nacional, de modo que incluso los administradores de bases de datos o un atacante que ejecute consultas vean texto cifrado, a menos que tengan la clave correcta.

Recuerda también los otros estados de los datos. Los datos en tránsito se protegen con protocolos como TLS e IPsec, y los datos en uso (en memoria mientras se procesan) son los más difíciles de proteger, con tecnologías como los enclaves seguros. El cifrado de transporte y el cifrado de datos en reposo se complementan; uno no reemplaza al otro.

Como regla práctica: laptop robada, piensa en cifrado de disco completo. Campos sensibles en una aplicación, piensa en cifrado de registro o de columna. Archivos compartidos específicos, piensa en cifrado a nivel de archivo.

Términos clave

Full disk encryption, FDE (cifrado de disco completo)
Cifrado de todo un dispositivo de almacenamiento, que protege los datos si el dispositivo se pierde o es robado mientras está apagado.
Self-encrypting drive, SED (unidad autocifrada)
Una unidad que realiza el cifrado en su propio hardware.
File-level encryption (cifrado a nivel de archivo)
Cifrado aplicado a archivos o carpetas individuales, a menudo vinculado a usuarios específicos.
Transparent database encryption (cifrado transparente de base de datos)
Cifrado de los archivos de la base de datos en reposo sin cambios en las aplicaciones que la usan.
Record-level encryption (cifrado a nivel de registro)
Cifrado de filas o campos individuales en una base de datos para que ciertos datos sensibles sigan protegidos incluso frente a usuarios autorizados de la base de datos.
Ejemplo real

Una clínica cifra las laptops del personal con BitLocker por si las roban, y su base de datos de pacientes cifra la columna del número de seguro social, de modo que los reportes que ejecuta el personal de soporte muestran texto cifrado en ese campo, pero siguen listando nombres y citas.

Consejo para el examen: El FDE protege un dispositivo perdido y apagado, pero no un sistema encendido con sesión iniciada. Si personal interno o los DBA no deben leer un campo, elige cifrado de registro o de columna.

Comprueba lo que sabes

El principal riesgo de una empresa es que se pierdan laptops en taxis. ¿Qué nivel de cifrado es el más adecuado?

El cifrado de disco completo, que protege todos los datos del dispositivo cuando está apagado.

¿Por qué el cifrado de disco completo no impide que el malware lea archivos en una laptop con sesión iniciada?

Una vez que el disco se desbloquea al arrancar, los datos se descifran de forma transparente para cualquier proceso que se ejecute en el sistema.

¿Qué nivel protege una columna de tarjetas de crédito frente a los administradores de bases de datos?

El cifrado a nivel de registro, columna o campo dentro de la base de datos.
