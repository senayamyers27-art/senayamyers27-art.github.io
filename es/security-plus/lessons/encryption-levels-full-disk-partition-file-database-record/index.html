CompTIA Security+ SY0-701

Niveles de cifrado: disco completo, partición, archivo, base de datos y registro

El cifrado puede aplicarse con distintos niveles de granularidad, desde una unidad completa hasta un solo campo de una base de datos. Elegir el nivel correcto importa porque cada uno protege contra amenazas distintas y tiene costos diferentes en rendimiento y administración. La pregunta clave es: ¿cuándo se descifran los datos y quién puede verlos una vez descifrados? Un control que protege una laptop robada puede no hacer nada contra un atacante que inicia sesión como un usuario válido. SY0-701 enumera el cifrado de disco completo, de partición, de volumen, de archivo, de base de datos y de registro, además del cifrado de transporte para los datos en movimiento.

El cifrado de disco completo (FDE) cifra todo lo que hay en una unidad, incluidos el sistema operativo, el espacio de intercambio (swap) y los archivos temporales. Algunos ejemplos son BitLocker en Windows y FileVault en macOS, normalmente vinculados a un módulo de plataforma segura (TPM) que libera la clave solo si el proceso de arranque no ha sido manipulado. Las unidades de autocifrado (SED) hacen lo mismo en el hardware de la unidad, a menudo siguiendo el estándar Opal. El FDE es excelente para dispositivos perdidos o robados: sin la clave, el disco es ilegible. Su limitación es que, una vez que el sistema arranca y un usuario inicia sesión, los datos se descifran de forma transparente para cualquiera que use la máquina, incluido el malware que se ejecuta como ese usuario.

El cifrado de partición y de volumen protege una partición o un volumen lógico específico en lugar del disco completo, por ejemplo un volumen de datos separado en un servidor. El cifrado a nivel de volumen también es común en el almacenamiento en la nube, donde el proveedor cifra un volumen de almacenamiento en bloques. El cifrado a nivel de archivo protege archivos o carpetas individuales, como el Encrypting File System (EFS) de Windows o cifrar un archivo con una herramienta antes de enviarlo por correo. El cifrado de archivos se mantiene unido al archivo aunque se copie a otro lugar (según la herramienta), y puede vincularse a usuarios específicos, así que protege contra otros usuarios de la misma máquina.

El cifrado de bases de datos protege los datos dentro de una base de datos. El cifrado transparente de datos (TDE) cifra los archivos de la base de datos en disco, lo que protege contra alguien que robe los archivos o los respaldos, pero el motor de la base de datos descifra los datos para cualquier consulta autorizada. El cifrado a nivel de registro o de columna (a nivel de campo) va más allá y cifra campos sensibles específicos, como los números de tarjetas de crédito o los números de identificación nacional, a veces con claves que tiene la aplicación en lugar de la base de datos. Así, incluso un administrador de base de datos que revise las tablas solo ve texto cifrado.

Un ejemplo práctico muestra por qué ayudan las capas. Una empresa de salud tiene los expedientes de los pacientes en un servidor. BitLocker en el servidor protege los discos si se roba el hardware o si se devuelve una unidad para reparación. El TDE protege los archivos y los respaldos de la base de datos si se copian fuera del servidor. El cifrado a nivel de columna en los campos de diagnóstico y número de identificación protege contra un administrador o un atacante con acceso SQL que intente leer los valores más sensibles. Y TLS protege los datos mientras viajan a los navegadores de los médicos. Cada capa cubre un hueco que las demás dejan.

Las compensaciones siguen un patrón. El cifrado más amplio (disco completo) es sencillo de desplegar e invisible para los usuarios, pero solo protege los datos cuando el dispositivo está apagado o bloqueado. El cifrado más específico (de registro o de campo) protege contra más internos y cuentas comprometidas, pero es más complejo: las aplicaciones deben modificarse, buscar e indexar campos cifrados es más difícil y la gestión de claves se vuelve crítica. La gestión de claves atraviesa todos los niveles; si la clave se almacena junto a los datos sin protección, el cifrado aporta poco.

Errores comunes: creer que el FDE protege los datos contra el malware o contra un atacante remoto en un sistema encendido y con sesión iniciada (no lo hace); suponer que el TDE detiene a un DBA malicioso (la base de datos descifra para las consultas autorizadas, así que no lo detiene); y olvidar que los datos copiados de un disco cifrado a una unidad USB o a un correo ya no están protegidos, a menos que también se cifren a nivel de archivo. Recuerda también que el cifrado en reposo no hace nada por los datos en tránsito; sigues necesitando TLS o una VPN.

Enfoque del examen: 'laptop perdida o robada' apunta al cifrado de disco completo. 'Proteger un solo archivo sensible que se comparte por correo' apunta al cifrado de archivos. 'Proteger los archivos y respaldos de la base de datos' apunta al cifrado a nivel de base de datos (transparente). 'Proteger los números de tarjeta incluso de los administradores' o 'cifrar solo campos específicos' apunta al cifrado a nivel de registro, columna o campo. Identifica quién es el atacante y qué acceso tiene, y luego elige el nivel más específico que todavía proteja contra él.

Términos clave

Cifrado de disco completo (FDE)
Cifrar toda una unidad, incluido el sistema operativo, para que los datos sean ilegibles sin la clave cuando el dispositivo está apagado.
Unidad de autocifrado (SED)
Una unidad que realiza el cifrado de disco completo en su propio hardware.
Cifrado de volumen
Cifrar una partición o un volumen lógico específico en lugar del disco completo.
Cifrado a nivel de archivo
Cifrar archivos o carpetas individuales, a menudo vinculados a usuarios específicos.
Cifrado transparente de datos (TDE)
Cifrado de los archivos de datos y de logs de una base de datos en reposo, que se descifran automáticamente para las consultas autorizadas.
Cifrado a nivel de registro
Cifrar registros o campos individuales, como los números de tarjeta, dentro de una base de datos.
Ejemplo real

Un procesador de pagos ya usa cifrado de disco completo en todos sus servidores, pero una auditoría descubre que los administradores de bases de datos pueden leer los números de tarjeta completos. La empresa agrega cifrado a nivel de columna al campo del número de tarjeta, con claves guardadas en un módulo de seguridad de hardware que solo la aplicación de pagos puede usar. Los administradores todavía pueden mantener la base de datos, pero las consultas que ejecutan devuelven texto cifrado para esa columna.

Consejo para el examen: Relaciona el nivel con la amenaza: dispositivo robado significa disco completo; compartir un solo archivo significa nivel de archivo; un interno o una cuenta de base de datos comprometida que lee campos sensibles significa nivel de registro o de columna.

Comprueba lo que sabes

Una laptop con cifrado de disco completo se infecta con malware mientras el usuario tiene la sesión iniciada. ¿El FDE protege los archivos contra el malware?

No; una vez que el sistema arranca y se desbloquea, los archivos se descifran de forma transparente para cualquier proceso que se ejecute como el usuario.

¿Por qué una empresa podría elegir el cifrado a nivel de campo en lugar del cifrado transparente de la base de datos para los números de tarjetas de crédito?

El cifrado a nivel de campo mantiene ilegibles los números de tarjeta incluso para los administradores y los atacantes con acceso a la base de datos, mientras que el TDE descifra para cualquier consulta autorizada.

¿Cuál es una desventaja práctica del cifrado a nivel de registro?

Agrega complejidad: las aplicaciones deben manejar las claves, y buscar o indexar campos cifrados es más difícil.

Un usuario copia un archivo de una laptop cifrada a una memoria USB. ¿La copia sigue protegida por el FDE?

No; el FDE solo protege los datos en ese disco. La copia necesita cifrado a nivel de archivo o cifrado de la unidad USB.
