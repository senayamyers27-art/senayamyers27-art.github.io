CompTIA Security+ SY0-701

Puertos clave: 22, 25, 53, 80, 443, 389, 636 y 3389

Un número de puerto identifica qué servicio de un host debe recibir el tráfico de red. La dirección IP lleva los datos a la máquina correcta; el puerto los lleva al programa correcto. Los puertos bien conocidos (del 0 al 1023) están asignados a servicios estándar, y Security+ espera que reconozcas los importantes de inmediato. Los puertos importan para la seguridad porque cada puerto abierto es un posible punto de entrada: las reglas de firewall, los resultados de escaneos, las entradas de logs y las tareas de endurecimiento se escriben en términos de puertos, así que leerlos con soltura es una habilidad práctica además de una habilidad para el examen.

La lista central de esta lección. El puerto 22 (TCP) es SSH, y también SFTP y SCP, para administración remota y transferencia de archivos seguras. El puerto 25 (TCP) es SMTP, el Protocolo Simple de Transferencia de Correo, que se usa entre servidores de correo para entregar los mensajes. El puerto 53 es DNS, que usa UDP para la mayoría de las consultas y TCP para las transferencias de zona y las respuestas grandes. El puerto 80 (TCP) es HTTP, tráfico web sin cifrar. El puerto 443 (TCP) es HTTPS, tráfico web dentro de TLS; el más reciente HTTP/3 también usa UDP 443. El puerto 389 es LDAP para consultas de directorio. El puerto 636 es LDAPS, LDAP sobre TLS. El puerto 3389 (TCP) es el Protocolo de Escritorio Remoto (RDP), que se usa para el acceso remoto gráfico a sistemas Windows. Una forma rápida de organizarlos: 22, 443 y 636 son las opciones cifradas; 80 y 389 son sus contrapartes en texto claro; 25 y 53 son servicios de infraestructura de los que depende toda red; y 3389 es un objetivo de acceso remoto de alto valor.

Vale la pena conocer algunos más porque aparecen en los escenarios: 20 y 21 FTP, 23 Telnet, 67 y 68 DHCP, 88 Kerberos, 110 POP3 y 995 POP3S, 143 IMAP y 993 IMAPS, 123 NTP, 161 y 162 SNMP, 445 SMB (uso compartido de archivos de Windows), 514 syslog, 587 envío SMTP desde clientes de correo (normalmente con STARTTLS), 1812 y 1813 RADIUS, 3306 MySQL y 1433 Microsoft SQL Server. No necesitas memorizar todos los puertos que existen, pero sí debes conocer los inseguros y sus contrapartes seguras.

Así es como aparecen los puertos en la práctica. Un escaneo de un servidor podría producir una salida como esta, y cada puerto abierto plantea una pregunta: ¿debería ser accesible y desde dónde?

PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
443/tcp  open  https
3389/tcp open  ms-wbt-server

En el propio host, netstat -ano en Windows o ss -tulpn en Linux enumeran los puertos en escucha y el proceso detrás de cada uno, lo que te ayuda a encontrar el programa responsable de un puerto abierto inesperado. El razonamiento de seguridad sobre los puertos sigue algunas reglas. Cierra o bloquea todo lo que el host no necesite, lo cual es parte del endurecimiento. Prefiere la versión segura (443 en lugar de 80, 636 en lugar de 389, 22 en lugar de 23). Nunca expongas directamente a internet puertos de administración como 22, 3389, 445 o los puertos de bases de datos; colócalos detrás de una VPN, un jump server o un acceso zero trust, y restringe las direcciones de origen. RDP en el 3389 expuesto a internet es uno de los puntos de entrada de ransomware más comunes, mediante la adivinación de contraseñas y el relleno de credenciales (credential stuffing). El tráfico saliente inesperado también importa: una estación de trabajo que envía SMTP por el puerto 25 directamente a internet podría estar infectada con malware que envía spam, por eso muchas redes bloquean el 25 saliente excepto desde los servidores de correo.

Errores comunes: suponer que un servicio siempre se ejecuta en su puerto estándar (los administradores pueden mover los servicios, y los atacantes encapsulan tráfico por el 443 o el 53 para pasar desapercibidos, así que los firewalls que solo miran puertos pueden ser engañados); creer que mover RDP a un puerto no estándar lo asegura (eso es oscuridad, no un control); confundir el 389 con el 636; y olvidar que DNS usa tanto UDP como TCP en el 53. Recuerda también que un puerto abierto en un escaneo no significa que el servicio sea vulnerable, solo que es accesible.

Las preguntas del examen a menudo presentan una línea de log o una regla de firewall y preguntan qué está ocurriendo, o preguntan qué puerto abrir o bloquear. 'Permitir búsquedas de directorio seguras' es el 636. 'Bloquear el escritorio remoto desde internet' es el 3389. 'De servidor de correo a servidor de correo' es el 25. 'Shell remoto cifrado' es el 22. 'Transferencia de zona' es TCP 53. Volúmenes inusualmente grandes de tráfico DNS en el 53 hacia un único dominio externo pueden indicar tunelización DNS (DNS tunneling), una pista de detección que combina puertos con comportamiento.

Términos clave

Puerto (port)
Un número que identifica un servicio o aplicación específico en un host.
Puerto 22
SSH, SFTP y SCP para acceso remoto y transferencia de archivos cifrados.
Puerto 25
SMTP, que se usa para entregar el correo entre servidores de correo.
Puerto 53
DNS, que usa UDP para la mayoría de las consultas y TCP para las transferencias de zona y las respuestas grandes.
Puertos 389 y 636
LDAP (texto claro o StartTLS) y LDAPS (LDAP sobre TLS), respectivamente.
Puerto 3389
Protocolo de Escritorio Remoto (RDP) para el acceso remoto gráfico a sistemas Windows.
Puerto 443
HTTPS, tráfico web protegido con TLS.
Ejemplo real

Una revisión del firewall encuentra una regla que permite que cualquier dirección de internet llegue al TCP 3389 de un servidor de finanzas, creada hace años para un proveedor. Los logs de autenticación muestran miles de inicios de sesión fallidos desde todo el mundo cada día. El equipo elimina la regla, exige que el proveedor se conecte a través de la VPN y de un jump server con MFA, y agrega una alerta para cualquier regla futura que exponga el 3389, el 22 o el 445 a internet.

Consejo para el examen: Conoce los pares seguro-inseguro por puerto: 22 vs 23, 443 vs 80, 636 vs 389, 993 vs 143, 995 vs 110. Si una pregunta pide qué puerto permitir para el acceso seguro al directorio, la respuesta es 636, no 389.

Comprueba lo que sabes

Una estación de trabajo envía grandes cantidades de tráfico saliente por TCP 25 hacia muchas IP externas. ¿Qué sugiere eso?

Que podría estar infectada con malware que envía spam, ya que las estaciones de trabajo normales envían el correo a través del servidor de correo de la empresa, no directamente por el puerto 25.

¿Por qué es peligroso exponer el puerto 3389 a internet?

Expone RDP a la adivinación de contraseñas y al relleno de credenciales, un punto de entrada común del ransomware; debe estar detrás de una VPN, un jump server o un control similar.

¿Qué puerto ofrece LDAP sobre TLS?

El 636.

¿Bloquear un puerto garantiza que no se pueda llegar a un servicio a través del firewall?

No; los servicios pueden moverse a otros puertos o encapsularse a través de puertos permitidos como el 443, así que también se necesita inspección con reconocimiento de aplicaciones.
