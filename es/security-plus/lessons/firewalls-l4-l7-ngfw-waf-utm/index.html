CompTIA Security+ SY0-701

Firewalls (L4/L7, NGFW), WAF y UTM

Un firewall (cortafuegos) aplica reglas sobre qué tráfico de red puede pasar entre zonas, por ejemplo entre internet y tu red interna. Las reglas se procesan en orden, normalmente de arriba hacia abajo, y gana la primera coincidencia. Un conjunto de reglas bien construido termina con una denegación implícita o explícita: todo lo que no esté permitido específicamente se bloquea. Ese enfoque de denegación predeterminada es una idea central del examen.

Los firewalls se diferencian por la profundidad con la que examinan el tráfico, lo que se corresponde con las capas del modelo OSI. Un firewall de capa 4 (capa de transporte) toma decisiones según las direcciones IP de origen y destino, los números de puerto y el protocolo (TCP o UDP). Un filtro de paquetes stateless (sin estado) juzga cada paquete por separado; un firewall stateful (con estado) rastrea las conexiones, así que sabe que una respuesta pertenece a una sesión que inició tu usuario y puede descartar paquetes no solicitados. El filtrado de capa 4 es rápido, pero no puede saber qué aplicación va dentro de un puerto permitido. Cualquier cosa puede viajar por el puerto 443.

Un firewall de capa 7 (capa de aplicación) entiende el protocolo de la aplicación en sí. Puede distinguir la navegación web de la compartición de archivos tunelizada por el mismo puerto, y permitir o bloquear según la aplicación, el usuario o el contenido. Un firewall de nueva generación (next-generation firewall, NGFW) combina el filtrado stateful con el reconocimiento de aplicaciones, a menudo prevención de intrusiones integrada, la identidad del usuario y, si se configura, el descifrado del tráfico TLS para inspeccionarlo.

Un firewall de aplicaciones web (web application firewall, WAF) es especializado: se ubica frente a las aplicaciones web e inspecciona las solicitudes HTTP en busca de ataques como la inyección SQL y el cross-site scripting. Un firewall normal protege redes; un WAF protege un sitio web o una API. A menudo es la forma más rápida de proteger una aplicación con una falla conocida mientras los desarrolladores corrigen el código.

La gestión unificada de amenazas (unified threat management, UTM) es un appliance todo en uno que combina firewall, prevención de intrusiones, antivirus, filtrado de contenido, VPN y a veces filtrado de spam. Es adecuado para organizaciones pequeñas y medianas que quieren una sola caja que gestionar. Las contrapartidas son un único punto de falla y posibles límites de rendimiento cuando todas las funciones están activas.

Un conjunto de reglas de ejemplo en un laboratorio podría verse así, evaluado de arriba hacia abajo:

1  ALLOW  TCP  any       -> 10.0.5.10  443   (servidor web público)
2  ALLOW  TCP  10.0.1.0/24 -> 10.0.5.20  22   (administradores al jump host)
3  DENY   IP   any       -> any        any   (denegación predeterminada)

Términos clave

Stateful firewall (firewall con estado)
Un firewall que rastrea el estado de las conexiones y permite el tráfico de retorno de las sesiones establecidas.
NGFW
Next-generation firewall: combina el filtrado stateful con el reconocimiento de aplicaciones, la identidad del usuario y a menudo un IPS.
WAF
Web application firewall: inspecciona el tráfico HTTP para bloquear ataques web como la inyección SQL y el XSS.
UTM
Unified threat management: un solo appliance que agrupa firewall, IPS, antivirus, filtrado y VPN.
Implicit deny (denegación implícita)
La regla según la cual el tráfico que no está permitido explícitamente se bloquea.
Ejemplo real

Una tienda en línea descubre que su página de búsqueda es vulnerable a la inyección SQL. La corrección del código tomará dos semanas. El equipo de seguridad habilita reglas del WAF que bloquean los patrones de inyección en esa página, lo que protege a los clientes mientras los desarrolladores corrigen el código.

Consejo para el examen: Proteger una aplicación web contra inyección o XSS significa WAF. Controlar por puerto e IP significa capa 4. Identificar aplicaciones sin importar el puerto significa capa 7 o NGFW.

Comprueba lo que sabes

¿Por qué un firewall de capa 4 no puede detener una aplicación maliciosa que usa el puerto 443?

Solo ve direcciones, puertos y protocolo, no el contenido de la aplicación, así que cualquier tráfico en un puerto permitido pasa.

¿Por qué importa el orden de las reglas en un firewall?

Las reglas se procesan de arriba hacia abajo y se aplica la primera coincidencia, así que un permiso amplio colocado arriba de una denegación específica la anula.

¿Cuándo es adecuado un appliance UTM?

Para organizaciones más pequeñas que quieren gestionar muchas funciones de seguridad en un solo dispositivo, aceptando las contrapartidas de único punto de falla y de rendimiento.
