CompTIA Security+ SY0-701

Riesgos de la virtualización: VM escape y VM sprawl

La virtualización permite que un servidor físico ejecute muchas máquinas virtuales (VM). Una capa delgada de software llamada hipervisor divide el hardware y mantiene separada cada VM. Un hipervisor Tipo 1 (bare-metal) se ejecuta directamente sobre el hardware y es típico en centros de datos y nubes. Un hipervisor Tipo 2 (hosted) se ejecuta como una aplicación sobre un sistema operativo normal, como el software de virtualización de escritorio en una laptop. La virtualización ahorra dinero y facilita copiar y restaurar sistemas, pero introduce riesgos que debes reconocer.

El VM escape (escape de VM) es el más grave. Ocurre cuando un atacante que controla una VM invitada explota una falla en el hipervisor o en el hardware virtual para salir y ejecutar código en el host, o llegar a otras VM en él. Como un solo host puede ejecutar cargas de trabajo de muchos departamentos o, en una nube, de muchos clientes, un escape anula el aislamiento del que depende todo lo demás. Las defensas son mantener parcheados los hipervisores, deshabilitar los dispositivos virtuales y las funciones compartidas innecesarias (como el portapapeles y las carpetas compartidas entre host e invitado) y separar en hosts distintos las cargas de trabajo de sensibilidad muy diferente.

La reutilización de recursos (resource reuse) es una preocupación relacionada. Cuando se elimina una VM, su memoria y su espacio en disco se reasignan a otras VM. Si ese espacio no se limpia correctamente, podrían quedar expuestos restos de los datos anteriores. Los hipervisores y los proveedores de nube están diseñados para evitarlo, pero es una categoría de riesgo reconocida.

El VM sprawl (proliferación de VM) es un problema operativo que se convierte en uno de seguridad. Como crear una VM toma minutos, las organizaciones acumulan VM de las que nadie lleva registro: máquinas de prueba, copias antiguas y proyectos olvidados. Las VM no gestionadas no se parchean ni se monitorean, pueden contener datos sensibles y pueden convertirse en un punto de entrada fácil. La solución es la gobernanza: un inventario de cada VM con un dueño, procesos de aprobación para crearlas, revisiones periódicas y vencimiento automático para las temporales.

Los snapshots, que capturan el estado de una VM en un momento dado, son útiles para revertir rápidamente, pero también pueden contener configuraciones antiguas sin parches o datos sensibles, así que necesitan las mismas reglas de protección y retención que los respaldos.

En el examen, relaciona los síntomas con los términos: salir de un invitado hacia el host es VM escape; demasiadas VM no gestionadas es sprawl; datos sobrantes de un inquilino anterior es resource reuse.

Términos clave

Hypervisor (hipervisor)
Software que crea y ejecuta máquinas virtuales y las aísla entre sí.
VM escape (escape de VM)
Un ataque en el que código dentro de una VM invitada rompe el aislamiento para llegar al hipervisor, al host o a otras VM.
VM sprawl (proliferación de VM)
El crecimiento descontrolado de máquinas virtuales que no se registran, no se parchean ni se monitorean.
Type 1 hypervisor (hipervisor Tipo 1)
Un hipervisor bare-metal que se ejecuta directamente sobre el hardware sin un sistema operativo anfitrión.
Snapshot
Una copia guardada del estado de una VM en un momento dado, que se usa para revertir.
Ejemplo real

Durante una auditoría, un hospital encuentra 40 VM sin dueño registrado. Varias ejecutan un sistema operativo desactualizado y una contiene una copia de una base de datos de pacientes de un proyecto terminado. El equipo construye un inventario, asigna dueños, elimina lo que no se necesita y exige fechas de vencimiento en todas las VM de prueba nuevas.

Consejo para el examen: El VM escape se trata de una falla del aislamiento en el hipervisor; el sprawl se trata de la pérdida de control y de inventario. Parchear el hipervisor atiende el escape; la gestión de activos atiende el sprawl.

Comprueba lo que sabes

¿Qué hace que el VM escape sea especialmente peligroso en una nube pública?

El host puede ejecutar VM de muchos clientes, así que salir de un invitado podría exponer las cargas de trabajo y los datos de otros inquilinos.

¿Qué control atiende mejor el VM sprawl?

La gestión de activos y la gobernanza: un inventario con dueños, aprobación para las VM nuevas, revisiones periódicas y la baja de las que no se usan.
