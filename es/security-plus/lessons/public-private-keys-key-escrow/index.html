CompTIA Security+ SY0-701

Claves públicas y privadas, y key escrow (custodia de claves)

La criptografía de clave pública depende de pares de claves. Cada par tiene una clave pública, que puede compartirse libremente, y una clave privada, que debe permanecer en secreto con su dueño. Ambas están relacionadas matemáticamente de modo que lo que hace una clave solo puede deshacerlo la otra, y aun así en la práctica no es posible deducir la clave privada a partir de la pública. Gestionar bien estas claves, incluido cómo se crean, almacenan, comparten, respaldan, rotan y destruyen, es tan importante como los propios algoritmos. La mayoría de las fallas criptográficas del mundo real se deben a una mala gestión de claves, no a matemáticas rotas.

El par tiene dos usos principales y es esencial acertar la dirección. Para la confidencialidad, el emisor cifra con la clave pública del destinatario, y solo la clave privada del destinatario puede descifrar. Para la autenticación, la integridad y el no repudio, el dueño firma con su propia clave privada, y cualquiera puede verificar la firma con la clave pública del dueño. Un recurso sencillo para recordarlo: para guardar algo en secreto para Bob, usa la clave pública de Bob; para demostrar que algo vino de Alice, Alice usa su clave privada.

Las claves públicas se distribuyen dentro de certificados digitales, que vinculan una clave pública con una identidad (una persona, un servidor o un dispositivo) y están firmados por una autoridad de certificación (CA). Ese vínculo importa: sin él, un atacante podría entregarte su propia clave pública haciéndose pasar por tu banco. El conjunto de CA, certificados, políticas y procesos que hace que esto funcione se llama infraestructura de clave pública (PKI), y se trata en la siguiente lección.

El ciclo de vida de las claves incluye varios pasos. La generación debe usar una fuente fuerte de números aleatorios y, para las claves de alto valor, ocurrir dentro de hardware seguro, como un módulo de seguridad de hardware (HSM) o un TPM. El almacenamiento debe proteger la clave privada con un control de acceso fuerte e, idealmente, hacerla no exportable. La distribución solo involucra claves públicas. La rotación reemplaza las claves de forma periódica o después de una sospecha de compromiso. La revocación les indica a los demás que ya no deben confiar en una clave, y la destrucción elimina de forma segura las claves antiguas cuando ya no se necesitan. Las claves a menudo se clasifican por uso; tener claves separadas para firmar y para cifrar es una buena práctica común.

La custodia de claves (key escrow) significa que una copia de una clave privada o secreta la guarda un tercero de confianza o un sistema interno seguro, para poder recuperarla si es necesario. Las organizaciones usan la custodia cuando perder una clave significaría perder datos: si se pierde la clave de cifrado de un empleado o el empleado se va, la empresa todavía puede descifrar los archivos del negocio. Las claves de recuperación de BitLocker almacenadas en un servicio de directorio o en un sistema de gestión de dispositivos son un ejemplo común del mundo real. La custodia también se discute en el contexto del acceso legal por parte de las autoridades.

Recorre un caso práctico. Una empresa emite a cada empleado un certificado de cifrado de correo. Al generarse, la clave privada de cifrado se archiva en el sistema de recuperación de claves de la empresa, protegida de manera que la recuperación requiere dos administradores autorizados (control dual). Una empleada se va de forma repentina y el área legal necesita leer mensajes cifrados en su buzón. Dos administradores siguen el procedimiento documentado, recuperan la clave y la recuperación queda registrada. Sin embargo, su clave de firma nunca se puso en custodia, porque hacerlo permitiría que otra persona creara firmas en su nombre y destruiría el no repudio.

Errores comunes: cifrar con tu propia clave privada para mantener algo confidencial (eso crea una firma, que cualquiera puede verificar, así que no oculta nada); compartir la clave privada con un colega para 'ayudar'; suponer que la custodia no tiene riesgos (el almacén de custodia se vuelve un objetivo de alto valor y necesita protección fuerte, separación de funciones y auditoría); y poner en custodia las claves de firma. La custodia es adecuada para las claves de cifrado, donde importa recuperar los datos, no para las claves de firma, donde importa el control exclusivo.

Enfoque del examen: las preguntas piden qué clave se usa para una tarea. 'Enviar un mensaje confidencial a Bob' es la clave pública de Bob. 'Descifrar un mensaje que te enviaron' es tu clave privada. 'Firmar un documento' es la clave privada de quien firma, y 'verificar una firma' es la clave pública de quien firma. 'Recuperar datos cifrados después de que un empleado se va o pierde una clave' apunta a la custodia de claves o a la recuperación de claves. 'Proteger el proceso de custodia contra un solo administrador deshonesto' apunta al control M de N o al control dual.

Términos clave

Clave pública (public key)
La mitad compartible de un par de claves, que se usa para cifrar datos para el dueño o verificar sus firmas.
Clave privada (private key)
La mitad secreta de un par de claves, que se usa para descifrar los datos enviados al dueño o para crear firmas digitales.
Par de claves (key pair)
Una clave pública y una privada vinculadas matemáticamente que se usan en la criptografía asimétrica.
Custodia de claves (key escrow)
Guardar una copia de una clave con una parte o un sistema de confianza para poder recuperarla cuando se necesite.
Rotación de claves (key rotation)
Reemplazar las claves de forma periódica o después de una sospecha de compromiso para limitar la exposición.
Control dual (dual control)
Exigir que dos o más personas autorizadas realicen una acción sensible, como recuperar una clave en custodia.
Infraestructura de clave pública (PKI)
Las CA, los certificados, las políticas y los procesos que se usan para gestionar las claves públicas y confiar en ellas.
Ejemplo real

La unidad protegida con BitLocker de una laptop no se desbloquea después de reemplazar la tarjeta madre, porque el TPM ya no coincide. La mesa de ayuda recupera la clave de recuperación de 48 dígitos que se puso en custodia automáticamente en el sistema de gestión de dispositivos de la empresa cuando se cifró la unidad. El usuario vuelve a trabajar en minutos, y la recuperación queda registrada para auditoría.

Consejo para el examen: Cifra con la clave pública del destinatario; firma con tu propia clave privada. Pon en custodia las claves de cifrado para recuperarlas, pero nunca las claves de firma, porque eso socavaría el no repudio.

Comprueba lo que sabes

Alice quiere enviarle a Bob un archivo confidencial. ¿Qué clave usa para cifrarlo?

La clave pública de Bob, para que solo la clave privada de Bob pueda descifrarlo.

¿Por qué una empresa no debería poner en custodia las claves de firma de sus empleados?

Si otra persona puede usar la clave de firma, el empleado podría negar haber firmado, lo que socava el no repudio.

¿Cuál es el principal riesgo de la custodia de claves?

El sistema de custodia se vuelve un objetivo valioso; si se compromete, quedan expuestas muchas claves y muchos datos cifrados.

Un empleado se va y es necesario leer sus archivos cifrados. ¿Qué lo hace posible?

La custodia o la recuperación de claves, en la que se almacenó de antemano y de forma segura una copia de la clave de cifrado.
