CompTIA Security+ SY0-701

Capas OSI y dónde ocurren los ataques

El modelo Open Systems Interconnection (OSI) divide la comunicación de red en siete capas. Conocer las capas te ayuda a describir dónde trabaja un dispositivo, dónde ocurre un ataque y qué control lo defiende. Una ayuda de memoria común en inglés, de abajo hacia arriba, es 'Please Do Not Throw Sausage Pizza Away': Physical (física), Data link (enlace de datos), Network (red), Transport (transporte), Session (sesión), Presentation (presentación), Application (aplicación).

La capa 1, física, son los cables, las señales de radio y los conectores que transportan bits. Los ataques en esta capa incluyen cortar cables, intervenir líneas (wiretapping), interferir señales inalámbricas (jamming) y conectar dispositivos no autorizados en tomas de red abiertas. Las defensas son físicas: cuartos de cableado con llave, puertos sin uso deshabilitados y blindaje. La capa 2, enlace de datos, mueve tramas dentro de una red local usando direcciones MAC; los switches trabajan aquí. Los ataques de capa 2 incluyen MAC flooding (saturar la tabla de direcciones de un switch para que inunde el tráfico), MAC spoofing, ARP poisoning y VLAN hopping. La seguridad de puertos (port security), el control de acceso a la red 802.1X y la inspección dinámica de ARP (dynamic ARP inspection) ayudan.

La capa 3, red, enruta paquetes entre redes usando direcciones IP; los routers y muchos firewalls operan aquí. El IP spoofing, la manipulación de rutas y las inundaciones basadas en ICMP están en esta capa, junto con IPsec como protección de capa 3. La capa 4, transporte, maneja la entrega de extremo a extremo con TCP (orientado a conexión y confiable) y UDP (sin conexión y rápido), y es donde viven los números de puerto. Los SYN floods, que agotan un servidor dejando muchas conexiones TCP semiabiertas, y el escaneo de puertos son actividades de capa 4. Los firewalls stateful rastrean las conexiones de capa 4.

La capa 5, sesión, gestiona las sesiones entre aplicaciones, y el secuestro de sesión (session hijacking) se asocia con ella. La capa 6, presentación, se encarga del formato de los datos, la codificación de caracteres, la compresión y el cifrado; TLS suele describirse en relación con las capas 5 y 6. La capa 7, aplicación, es donde los usuarios y las aplicaciones interactúan con la red: HTTP, DNS, SMTP, etcétera. Muchos ataques modernos ocurren aquí, incluidos la inyección SQL, el cross-site scripting, los enlaces de phishing y los ataques DDoS de capa de aplicación que envían solicitudes costosas pero de apariencia legítima. Los firewalls de aplicaciones web (WAF) y los firewalls de nueva generación inspeccionan la capa 7.

El examen a menudo usa los números de capa como abreviatura. 'Un firewall de capa 4' filtra por direcciones IP, protocolos y puertos. 'Un firewall de capa 7' puede entender la aplicación, por ejemplo bloquear un patrón específico de solicitud web o una aplicación particular sin importar el puerto. Un 'ataque de capa 2' se queda dentro de un dominio de broadcast, por eso la segmentación con VLAN y el enrutamiento limitan su alcance.

También verás el modelo TCP/IP, más sencillo, que fusiona las tres capas superiores de OSI en una sola capa de aplicación y las dos inferiores en una capa de enlace. Las preguntas de Security+ usan sobre todo los números de OSI, así que vale la pena memorizar las siete con un dispositivo y un ataque de ejemplo para cada una.

Términos clave

OSI model (modelo OSI)
Un modelo de referencia de siete capas que describe cómo se divide la comunicación de red en funciones.
Layer 2, Data link (capa 2, enlace de datos)
La capa que mueve tramas usando direcciones MAC dentro de una red local; los switches operan aquí.
Layer 4, Transport (capa 4, transporte)
La capa que maneja la entrega de extremo a extremo con TCP y UDP y usa números de puerto.
Layer 7, Application (capa 7, aplicación)
La capa donde operan las aplicaciones y protocolos como HTTP y DNS; los WAF inspeccionan el tráfico aquí.
SYN flood
Un ataque de denegación de servicio que envía muchas solicitudes de conexión TCP sin completar el handshake.
Ejemplo real

El firewall tradicional de una tienda en línea permite el puerto 443, pero no puede ver que las solicitudes entrantes contienen intentos de inyección SQL. El equipo agrega un firewall de aplicaciones web que inspecciona el contenido HTTP en la capa 7 y bloquea las solicitudes maliciosas mientras permite el tráfico normal.

Consejo para el examen: Asocia los ataques con las capas: MAC flooding y ARP poisoning son de capa 2, IP spoofing es de capa 3, los SYN floods y los escaneos de puertos son de capa 4, la inyección SQL y el XSS son de capa 7.

Comprueba lo que sabes

¿En qué capa OSI reenvía el tráfico un switch usando direcciones MAC?

En la capa 2, la capa de enlace de datos.

¿De qué capa es un ataque SYN flood?

De la capa 4, la capa de transporte, porque abusa del handshake de TCP.

¿Por qué un firewall de capa 7 puede bloquear algo que un firewall de capa 4 no puede?

Inspecciona el contenido de la aplicación, como las solicitudes HTTP, en lugar de solo direcciones, protocolos y puertos.
