CompTIA Security+ SY0-701

Nube: IaaS, PaaS, SaaS y responsabilidad compartida

La computación en la nube significa rentar recursos de cómputo a un proveedor en lugar de comprarlos y operarlos tú mismo. El proveedor es dueño de los centros de datos, del hardware y de una parte cada vez mayor del stack de software, y tú pagas por lo que usas. En materia de seguridad, la pregunta clave siempre es la misma: ¿quién es responsable de proteger cada capa? La respuesta depende del modelo de servicio que elijas, y el examen espera que lo conozcas capa por capa.

Infrastructure as a Service (IaaS) te da máquinas virtuales, redes virtuales y almacenamiento. El proveedor protege las instalaciones físicas, el hardware y el hipervisor. Tú eres responsable de todo lo que construyes encima: el sistema operativo invitado y sus parches, las aplicaciones instaladas, las reglas de firewall (a menudo llamadas grupos de seguridad o security groups), las identidades y los datos en sí. IaaS te da el mayor control y, por lo tanto, la mayor responsabilidad.

Platform as a Service (PaaS) te da un entorno de ejecución gestionado, como una plataforma de hosting de aplicaciones o una base de datos gestionada. Ahora el proveedor también parchea el sistema operativo y el software de la plataforma. Tú sigues siendo dueño del código de tu aplicación, de su configuración, de las cuentas que pueden acceder a ella y de tus datos. Software as a Service (SaaS) es una aplicación terminada en la que inicias sesión, como el correo web o un sistema de gestión de relaciones con clientes (CRM). El proveedor opera casi todo; tú sigues siendo responsable de quién tiene cuentas, cómo se autentican, cómo se configuran la compartición y otras opciones, y qué datos colocas en ella.

El modelo de responsabilidad compartida (shared responsibility model) es la división por escrito de estas tareas. Un resumen útil: el proveedor es responsable de la seguridad de la nube, y el cliente es responsable de la seguridad en la nube. En todos los modelos, el cliente siempre conserva la responsabilidad sobre los datos, las identidades y las decisiones de acceso. Por eso muchas brechas reales en la nube provienen de errores del cliente, como un bucket de almacenamiento abierto al público, roles de administrador demasiado amplios o la falta de autenticación multifactor (MFA), y no de que hayan hackeado al proveedor.

También verás los modelos de implementación. Una nube pública la comparten muchos clientes (multitenencia) con separación lógica. Una nube privada está dedicada a una sola organización. Una nube comunitaria la comparten organizaciones con necesidades comunes, y una nube híbrida combina recursos locales o privados con la nube pública. Herramientas como un cloud access security broker (CASB) se ubican entre los usuarios y los servicios en la nube para dar visibilidad y aplicar políticas, por ejemplo bloquear la carga de archivos sensibles a aplicaciones SaaS no aprobadas.

En un laboratorio o en una consola verás el lado del cliente de esta división: crear usuarios y roles de gestión de identidades y accesos (IAM), configurar reglas de grupos de seguridad, habilitar el cifrado en el almacenamiento y activar el registro de eventos. Todo eso es tu responsabilidad, sin importar el modelo.

Términos clave

IaaS
Infrastructure as a Service: máquinas virtuales, redes y almacenamiento rentados; el cliente gestiona el sistema operativo y lo que está encima.
PaaS
Platform as a Service: un entorno de ejecución o una base de datos gestionados; el cliente gestiona el código, la configuración, el acceso y los datos.
SaaS
Software as a Service: una aplicación completa alojada; el cliente gestiona las cuentas, la configuración y los datos.
Shared responsibility model (modelo de responsabilidad compartida)
La división de las tareas de seguridad entre el proveedor de nube y el cliente, que cambia según el modelo de servicio.
CASB
Cloud access security broker: un punto de control que da visibilidad y aplica políticas sobre el uso de servicios en la nube.
Ejemplo real

Una empresa traslada sus recursos compartidos de archivos a un servicio de almacenamiento en la nube pública. Un ingeniero que prueba un sitio web hace que un bucket de almacenamiento sea legible públicamente y olvida revertirlo. Meses después, un investigador encuentra registros de clientes expuestos. La infraestructura del proveedor funcionó correctamente; la brecha vino de una configuración del lado del cliente, que el modelo de responsabilidad compartida asigna claramente a la empresa.

Consejo para el examen: Si una pregunta pide quién parchea el sistema operativo invitado en IaaS, la respuesta es el cliente. En todos los modelos, el cliente es responsable de los datos y el acceso, así que las preguntas sobre configuraciones incorrectas apuntan al cliente.

Comprueba lo que sabes

En un despliegue PaaS, ¿quién es responsable de parchear el sistema operativo subyacente?

El proveedor de nube. En PaaS, el proveedor gestiona el sistema operativo y el entorno de ejecución; el cliente gestiona el código de la aplicación, la configuración, el acceso y los datos.

¿Qué responsabilidad conserva el cliente por igual en IaaS, PaaS y SaaS?

Proteger sus datos y gestionar las identidades y el acceso, incluido quién tiene cuentas y qué permisos tiene.

¿Qué herramienta le daría a una organización visibilidad sobre qué aplicaciones SaaS usan los empleados y bloquearía cargas riesgosas?

Un cloud access security broker (CASB), que se ubica entre los usuarios y los servicios en la nube para monitorear y aplicar políticas.
