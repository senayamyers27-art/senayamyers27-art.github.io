Firmas digitales

Una firma digital prueba quién creó un dato y que no ha cambiado desde entonces. Proporciona tres de los objetivos de seguridad que has visto hasta ahora: integridad, autenticación del origen y no repudio. No proporciona confidencialidad; cualquiera puede leer un documento firmado a menos que también esté cifrado.

La firma funciona combinando hashing con criptografía asimétrica. Primero, el remitente calcula el hash del mensaje y obtiene un resumen (digest) corto. Segundo, el remitente usa su clave privada para firmar ese resumen. La firma resultante se envía junto con el mensaje. Calcular primero el hash es importante porque las operaciones asimétricas son lentas, y firmar un resumen de tamaño fijo es mucho más eficiente que firmar un archivo grande.

La verificación es el proceso inverso. El destinatario calcula su propio hash del mensaje que recibió. Luego usa la clave pública del remitente para verificar la firma, lo que confirma que la firma se creó sobre un resumen determinado con la clave privada correspondiente. Si los resúmenes coinciden, quedan probadas dos cosas: el mensaje no ha sido alterado (integridad) y lo firmó quien posee esa clave privada (autenticidad). Como solo el dueño debería tener la clave privada, no puede negar de forma creíble haberlo firmado (no repudio). Si cambiara aunque sea un bit del mensaje, los hashes no coincidirían y la verificación fallaría.

¿Cómo sabe el destinatario que la clave pública realmente pertenece al remitente? Ahí entran los certificados. La clave pública del remitente normalmente se entrega en un certificado emitido por una CA de confianza, así que verificar una firma a menudo incluye validar la cadena de certificados y revisar la revocación.

Las firmas digitales están en todas partes. La firma de código (code signing) permite que los sistemas operativos verifiquen que el software proviene del editor indicado y que no fue manipulado después de firmarse, y muchos sistemas advierten o bloquean cuando el código no está firmado. Los estándares de seguridad de correo como S/MIME firman los mensajes. DNSSEC firma los registros DNS para que los resolvers puedan detectar respuestas falsificadas. El firmware firmado y el secure boot verifican que el código de bajo nivel provenga del fabricante. Las plataformas de firma de documentos usan firmas para los contratos.

Compara las firmas digitales con herramientas relacionadas. Un hash simple da integridad, pero cualquiera puede recalcular el hash de un archivo modificado, así que no prueba quién lo creó. Un HMAC usa una clave secreta compartida, así que prueba que el mensaje vino de alguien que tiene la clave, pero como ambos lados la comparten, no puede proporcionar no repudio. Solo una firma ligada a la clave privada de una sola persona lo logra.

Términos clave

Digital signature (firma digital)
Un valor creado con una clave privada sobre el hash de unos datos, que prueba la integridad, el origen y el no repudio.
Code signing (firma de código)
Firmar digitalmente el software para que los usuarios y los sistemas operativos puedan verificar su editor y que no fue alterado.
Message digest (resumen del mensaje)
El hash de longitud fija de un mensaje, que es lo que se firma en lugar del mensaje completo.
Verification (verificación)
Usar la clave pública del firmante y un hash recalculado para confirmar que una firma es válida.
Ejemplo real

Antes de instalar un driver, Windows revisa su firma de código. El fabricante calculó el hash del driver y firmó ese hash con su clave privada. Windows recalcula el hash, verifica la firma con la clave pública del fabricante que viene en su certificado y rechazaría el driver si un atacante lo hubiera modificado.

Consejo para el examen: Se firma con la clave privada del remitente y se verifica con la clave pública del remitente. Las firmas dan integridad, autenticación y no repudio, pero no confidencialidad.

Comprueba lo que sabes

¿Qué clave usa el destinatario para verificar una firma digital?

La clave pública del remitente.

¿Por qué un HMAC no puede proporcionar no repudio?

Ambas partes comparten la misma clave secreta, así que cualquiera de las dos pudo haber generado el HMAC.

¿Qué pasa con la verificación si un archivo firmado cambia en un byte?

El hash recalculado ya no coincide con el resumen firmado, así que la verificación falla.
