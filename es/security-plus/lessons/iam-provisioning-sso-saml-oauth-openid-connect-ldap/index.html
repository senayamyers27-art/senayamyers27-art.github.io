CompTIA Security+ SY0-701

IAM: aprovisionamiento, SSO, SAML, OAuth, OpenID Connect y LDAP

La gestión de identidades y accesos (identity and access management, IAM) abarca cómo se crean las cuentas, cómo las personas demuestran quiénes son, a qué pueden acceder y cómo se retira el acceso. Hacerlo bien previene una enorme proporción de brechas, porque el acceso robado o excesivo está involucrado en muchísimas de ellas.

El aprovisionamiento (provisioning) es crear cuentas y otorgar acceso cuando alguien entra a la organización o cambia de rol; el desaprovisionamiento (deprovisioning) es retirarlo cuando se va. Lo ideal es que ambos se automaticen desde el sistema de recursos humanos, para que el acceso se otorgue según el rol y se retire de inmediato. Las cuentas huérfanas que quedan después de que alguien se va son un riesgo clásico. Las revisiones de acceso periódicas (recertificación) confirman que las personas todavía necesitan lo que tienen, lo que combate la acumulación de permisos. La verificación de identidad (identity proofing) comprueba que una persona es quien dice ser antes de emitirle una cuenta.

El inicio de sesión único (single sign-on, SSO) permite que un usuario se autentique una sola vez con un proveedor de identidad (identity provider, IdP) y luego acceda a muchas aplicaciones, llamadas proveedores de servicios o partes que confían (relying parties), sin volver a iniciar sesión. Menos contraseñas significa menos contraseñas débiles o reutilizadas, y los equipos de seguridad pueden exigir MFA y deshabilitar el acceso desde un solo lugar. El riesgo es la concentración: el IdP se convierte en un objetivo de alto valor. La federación extiende la confianza entre organizaciones, de modo que los usuarios de un socio pueden usar los inicios de sesión de su propia empresa para llegar a tu aplicación.

Security Assertion Markup Language (SAML) es un estándar basado en XML para intercambiar datos de autenticación y autorización entre un IdP y un proveedor de servicios. Después de que inicias sesión, el IdP envía una aserción firmada digitalmente que indica quién eres, y la aplicación confía en ella. SAML es común en el SSO web empresarial. Open Authorization (OAuth) se trata de autorización, no de autenticación: permite que un usuario otorgue a una aplicación acceso limitado a sus recursos en otro servicio sin compartir su contraseña, usando tokens de acceso con alcances (scopes) definidos, como permitir que una aplicación de agenda lea tu calendario. OpenID Connect (OIDC) agrega una capa de autenticación sobre OAuth y proporciona un token de identidad para que las aplicaciones puedan verificar quién es el usuario. Se usa mucho en los inicios de sesión de consumidores y aplicaciones móviles.

Lightweight Directory Access Protocol (LDAP) se usa para consultar y modificar servicios de directorio, que almacenan usuarios, grupos y otros objetos en una jerarquía. Normalmente funciona en el puerto 389; LDAPS (LDAP sobre TLS) usa el puerto 636 y debe preferirse para que las credenciales no se envíen en texto claro. Active Directory es un directorio muy utilizado que admite LDAP.

Los modelos de control de acceso se relacionan con esto: el control de acceso basado en roles asigna permisos según el puesto de trabajo, el basado en atributos usa atributos como el departamento y la ubicación, y el privilegio mínimo debe guiar a todos ellos.

Términos clave

Provisioning (aprovisionamiento)
Crear cuentas y otorgar acceso según el rol de un usuario.
SSO
Single sign-on: una sola autenticación da acceso a varias aplicaciones.
SAML
Un estándar basado en XML para intercambiar aserciones de autenticación firmadas entre un proveedor de identidad y un proveedor de servicios.
OAuth
Un marco de autorización que otorga a las aplicaciones un acceso limitado basado en tokens sin compartir contraseñas.
OpenID Connect
Una capa de identidad sobre OAuth que proporciona la autenticación del usuario.
LDAP
Un protocolo para consultar y gestionar servicios de directorio; LDAPS lo protege con TLS.
Ejemplo real

Cuando se contrata a una nueva analista, el sistema de RR. HH. dispara el aprovisionamiento automático: una cuenta de directorio, la membresía en el grupo del rol de analista y el acceso SSO a través del IdP de la empresa al correo, al SIEM y al sistema de tickets mediante SAML. Cuando ella se va, deshabilitar su única cuenta de directorio le retira el acceso a todos ellos a la vez.

Consejo para el examen: OAuth es autorización (a qué puede acceder una aplicación); OIDC agrega autenticación (quién eres); SAML son aserciones basadas en XML, comunes en el SSO empresarial. LDAPS en el 636 es la forma segura de LDAP.

Comprueba lo que sabes

¿Qué estándar permite que una aplicación acceda a tus fotos en otro servicio sin conocer tu contraseña?

OAuth, que emite tokens de acceso con alcance limitado para la autorización.

¿Qué le agrega OpenID Connect a OAuth?

Una capa de autenticación con un token de identidad, para que la aplicación pueda verificar quién es el usuario.

¿Qué riesgo reduce el desaprovisionamiento automatizado?

Las cuentas huérfanas que siguen activas después de que una persona se va y podrían usarse indebidamente.
