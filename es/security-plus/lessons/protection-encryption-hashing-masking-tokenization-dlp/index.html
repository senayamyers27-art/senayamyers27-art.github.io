CompTIA Security+ SY0-701

Protección: cifrado, hashing, enmascaramiento, tokenización y DLP

Varias técnicas protegen los datos, y las preguntas del examen a menudo dependen de elegir la correcta. La clave es preguntarse si hay que recuperar el valor original, quién debe hacerlo y si los datos deben conservar su formato.

El cifrado transforma los datos en texto cifrado usando un algoritmo y una clave; cualquiera que tenga la clave correcta puede revertirlo. Es la opción correcta cuando las personas o los sistemas autorizados necesitan recuperar los datos originales, como en los documentos almacenados o el tráfico de red. Su seguridad depende de proteger las claves, así que la gestión de claves importa tanto como el algoritmo.

El hashing pasa los datos por una función unidireccional que produce un resumen (digest) de longitud fija. No puedes recuperar el original a partir del hash, y hasta un cambio mínimo en la entrada produce un resumen muy distinto. El hashing se usa para verificaciones de integridad (comparar el hash de un archivo con un valor conocido y correcto) y para almacenar contraseñas, donde el sistema calcula el hash de lo que escribe el usuario y compara los hashes. A las contraseñas se les debe aplicar una salt, es decir, agregar un valor aleatorio único antes del hashing, para que contraseñas idénticas no produzcan hashes idénticos y las tablas precalculadas no sirvan.

El enmascaramiento (masking) oculta parte de los datos y los deja utilizables para mostrarse, como mostrar solo los últimos cuatro dígitos de un número de tarjeta en un recibo. El enmascaramiento estático crea una copia alterada de forma permanente, a menudo para entornos de prueba; el enmascaramiento dinámico oculta los valores al momento según quién los esté viendo. La tokenización reemplaza un valor sensible con un token aleatorio que no tiene ninguna relación matemática con el original. La asociación se guarda en una bóveda de tokens segura. Los sistemas de pago usan la tokenización para que los comercios almacenen tokens en lugar de números de tarjeta reales, lo que reduce lo que un atacante podría robar.

Otras técnicas de los objetivos incluyen la ofuscación (hacer que los datos o el código sean más difíciles de entender), la segmentación (mantener los datos sensibles en sistemas separados), las restricciones de permisos y las restricciones geográficas.

La prevención de pérdida de datos (data loss prevention, DLP) es diferente: es un sistema de detección y aplicación de políticas, no una transformación. La DLP identifica los datos sensibles mediante patrones, palabras clave, huellas (fingerprints) o etiquetas de clasificación, y luego monitorea endpoints, redes, correo y servicios en la nube para bloquear, advertir o registrar cuando esos datos salen por canales no aprobados. La DLP de endpoint puede impedir la copia a memorias USB; la DLP de red inspecciona el tráfico saliente; la DLP en la nube vigila las aplicaciones SaaS.

Términos clave

Hashing
Una función unidireccional que produce un resumen de longitud fija y se usa para verificaciones de integridad y para almacenar contraseñas.
Salt (sal)
Un valor aleatorio que se agrega a una contraseña antes del hashing para que contraseñas idénticas produzcan hashes distintos.
Tokenization (tokenización)
Reemplazar datos sensibles con un token no sensible asociado al original en una bóveda segura.
Data masking (enmascaramiento de datos)
Ocultar parte o la totalidad de un valor manteniéndolo utilizable para mostrarse o para pruebas.
DLP
Data loss prevention: herramientas que detectan y bloquean el movimiento no autorizado de datos sensibles.
Ejemplo real

El proveedor de pagos de una tienda en línea devuelve un token en lugar del número de tarjeta del cliente. La tienda guarda solo el token para las compras repetidas, enmascara la tarjeta en las páginas de pedidos para mostrar los últimos cuatro dígitos, calcula el hash de las contraseñas de los clientes con una salt y usa DLP para bloquear los correos que contienen patrones de números de tarjeta.

Consejo para el examen: Necesitas recuperar el original con una clave: cifrado. Nunca necesitas recuperarlo: hashing. Conservar el formato pero quitar el valor real de los sistemas: tokenización. Ocultar una parte en pantalla: enmascaramiento.

Comprueba lo que sabes

¿Por qué se usa hashing, y no cifrado, para almacenar contraseñas?

El sistema nunca necesita recuperar la contraseña; solo compara hashes, y una función unidireccional significa que una base de datos robada no revela directamente las contraseñas.

¿En qué se diferencia la tokenización del cifrado?

Un token no tiene relación matemática con el original y solo puede asociarse de vuelta mediante una bóveda segura, mientras que el texto cifrado se puede descifrar con la clave.

Un empleado intenta copiar un archivo con registros de clientes a una memoria USB y es bloqueado. ¿Qué control lo hizo?

La prevención de pérdida de datos (DLP) de endpoint.
