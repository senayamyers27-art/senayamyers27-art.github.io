Listas de aplicaciones permitidas (allow listing)

El allow listing de aplicaciones (término antiguo: whitelisting) es un control que permite ejecutar en un sistema solo las aplicaciones aprobadas. Todo lo demás se bloquea de forma predeterminada. Es lo opuesto a una lista de denegados (deny list o blacklist), que permite todo excepto el software malicioso conocido. Security+ considera el allow listing una mitigación fuerte porque detiene el malware desconocido, incluidas las variantes nuevas que las firmas del antivirus nunca han visto.

La diferencia de filosofía importa. Una deny list debe conocer una amenaza para bloquearla, así que siempre va detrás de los atacantes. Una allow list no necesita saber cuál es la amenaza; si el software no está en la lista aprobada, no se ejecuta. Esto encaja con la idea de implicit deny de las listas de control de acceso y con el principio de privilegio mínimo aplicado al software.

Las reglas de una allow list pueden identificar las aplicaciones de varias maneras. Una regla de hash permite un archivo solo si su hash criptográfico coincide con un valor aprobado, lo cual es muy preciso pero debe actualizarse cada vez que se actualiza el programa. Una regla de editor o de certificado (publisher rule) permite el software firmado con el certificado de firma de código de un proveedor de confianza, y sobrevive a las actualizaciones de ese proveedor. Una regla de ruta permite los programas que se ejecutan desde carpetas específicas, como Program Files, lo cual es fácil de gestionar pero más débil si los usuarios o el malware pueden escribir archivos en esas carpetas. Muchas organizaciones combinan estos enfoques.

En Windows, herramientas como AppLocker y Windows Defender Application Control implementan el allow listing, normalmente desplegado mediante Group Policy o la gestión de dispositivos. En otras plataformas, las suites de protección de endpoints y la gestión de dispositivos móviles ofrecen controles similares. Un buen despliegue comienza en modo de auditoría (audit mode), en el que la herramienta registra lo que habría bloqueado sin bloquearlo realmente, para que puedas construir una lista precisa antes de aplicarla.

El principal desafío es operativo. Las organizaciones con muchas aplicaciones distintas y actualizaciones frecuentes deben mantener la lista, y una lista mal mantenida frustra a los usuarios y genera tickets en la mesa de ayuda. El allow listing es más fácil en sistemas de propósito fijo, como servidores, quioscos, terminales de punto de venta y estaciones de trabajo de control industrial, donde el conjunto de software rara vez cambia. También es valioso contra los ataques sin archivos y basados en scripts cuando la política cubre scripts e intérpretes como PowerShell.

Las deny lists siguen teniendo su lugar, por ejemplo para bloquear aplicaciones no deseadas específicas o dominios maliciosos conocidos, y son más fáciles de mantener. En el examen, si el objetivo es impedir que malware desconocido o de día cero se ejecute en un sistema estable, elige el allow listing de aplicaciones.

Términos clave

Application allow listing (lista de aplicaciones permitidas)
Permitir que se ejecuten solo las aplicaciones aprobadas explícitamente y bloquear todo lo demás.
Deny list (lista de denegados)
Bloquear elementos maliciosos conocidos especificados y permitir todo lo demás.
Hash rule (regla de hash)
Una regla de allow list que identifica un archivo aprobado por su hash criptográfico.
Publisher rule (regla de editor)
Una regla de allow list que permite el software firmado con el certificado de un proveedor de confianza.
Audit mode (modo de auditoría)
Un modo en el que una política de control de aplicaciones registra lo que bloquearía sin aplicarlo.
Ejemplo real

Las terminales de punto de venta de un minorista solo necesitan el software de cobro y algunas herramientas del sistema. El equipo habilita el allow listing de aplicaciones usando reglas de editor. Cuando más tarde se copia en una terminal una muestra de malware llegada por phishing, simplemente no se inicia porque no está en la lista.

Consejo para el examen: El allow listing bloquea las amenazas desconocidas de forma predeterminada; el deny listing solo bloquea lo que ya conoce. El allow listing funciona mejor en sistemas cuyo software rara vez cambia.

Comprueba lo que sabes

¿Por qué el allow listing es efectivo contra el malware de día cero?

Todo lo que no esté aprobado explícitamente se bloquea, así que el malware nuevo se detiene aunque no exista una firma.

¿Cuál es la desventaja de las reglas de allow list basadas en hash?

Cada actualización del software cambia el hash, así que la lista debe actualizarse cada vez.

¿Por qué iniciar un despliegue de allow listing en modo de auditoría?

Para ver qué se bloquearía y construir una lista precisa antes de que la aplicación de la política afecte a los usuarios.
