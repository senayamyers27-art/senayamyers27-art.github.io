CompTIA Security+ SY0-701

Hashing, salting y key stretching

Una función hash toma una entrada de cualquier tamaño y produce una salida de longitud fija llamada hash o digest (resumen). Los buenos hashes criptográficos son unidireccionales (no puedes recuperar la entrada a partir del hash), deterministas (la misma entrada siempre da el mismo hash) y sensibles al cambio (modificar un solo bit de la entrada cambia la salida por completo). También deben ser resistentes a colisiones, es decir, que no sea práctico encontrar dos entradas distintas con el mismo hash. El hashing no es cifrado: no hay clave ni nada que descifrar.

Los hashes se usan principalmente para la integridad. Si descargas un archivo y calculas su hash SHA-256, puedes compararlo con el valor que publica el proveedor; si coinciden, el archivo no fue alterado. Los algoritmos comunes incluyen la familia SHA-2 (SHA-256, SHA-512) y SHA-3. MD5 y SHA-1 son más antiguos y tienen debilidades conocidas de colisión, así que no se debe confiar en ellos para fines de seguridad. En Linux puedes ejecutar sha256sum file.iso, y en Windows Get-FileHash file.iso en PowerShell.

Los hashes también son la forma en que los sistemas almacenan contraseñas. En lugar de guardar la contraseña, el sistema guarda su hash y, al iniciar sesión, calcula el hash de lo que escribes y lo compara. Si roban la base de datos, los atacantes no obtienen directamente las contraseñas en texto plano. Sin embargo, los hashes simples siguen siendo vulnerables. Como el hashing es determinista, dos usuarios con la misma contraseña tienen el mismo hash, y los atacantes pueden usar rainbow tables precalculadas, listas enormes de hashes de contraseñas comunes, para encontrarlas al instante.

El salting defiende contra esto. Una salt (sal) es un valor aleatorio, único para cada contraseña, que se combina con la contraseña antes de calcular el hash y se almacena junto al hash. Ahora las contraseñas idénticas producen hashes distintos, y las rainbow tables precalculadas se vuelven inútiles porque el atacante necesitaría una tabla para cada salt posible. La salt no es secreta; su función es garantizar la unicidad.

El key stretching (estiramiento de claves) hace que cada intento sea más lento. En lugar de calcular el hash una vez, el sistema ejecuta el hash (o un algoritmo especial) miles de veces o usa deliberadamente mucha memoria. Un inicio de sesión legítimo apenas nota el retraso, pero un atacante que prueba miles de millones de intentos se ve enormemente frenado. Los algoritmos comunes de key stretching son PBKDF2, bcrypt, scrypt y Argon2. Están diseñados para contraseñas, a diferencia de los hashes rápidos de propósito general como SHA-256.

Términos relacionados: un HMAC (hash-based message authentication code) combina un hash con una clave secreta para que el receptor pueda verificar tanto la integridad como que el remitente conocía la clave. Un pepper es un valor secreto que se agrega a todas las contraseñas y se guarda separado de la base de datos, lo que añade protección si solo roban la base de datos.

Términos clave

Hash
Un resumen unidireccional de longitud fija de los datos que se usa para verificar la integridad.
Salt (sal)
Un valor aleatorio por contraseña que se agrega antes del hashing para que las contraseñas idénticas produzcan hashes distintos y las rainbow tables fallen.
Key stretching (estiramiento de claves)
Procesar una contraseña de forma repetida o costosa (PBKDF2, bcrypt, scrypt, Argon2) para frenar los intentos de fuerza bruta.
Rainbow table
Una tabla de búsqueda precalculada con los hashes de muchas contraseñas posibles.
Collision (colisión)
Cuando dos entradas distintas producen la misma salida de hash.
Ejemplo real

Dos empleados eligen 'Summer2026'. Como el sistema agrega una salt única a cada una antes de calcular el hash con bcrypt, sus hashes almacenados se ven completamente distintos. Cuando más tarde se filtra la base de datos, los atacantes no pueden usar una rainbow table y deben adivinar cada hash lentamente, uno por uno.

Consejo para el examen: El salting derrota a las rainbow tables; el key stretching frena la fuerza bruta. El hashing da integridad, nunca confidencialidad, porque no es reversible.

Comprueba lo que sabes

¿Por qué una salt derrota a las rainbow tables?

Cada contraseña se combina con un valor aleatorio único, así que los hashes precalculados de contraseñas comunes ya no coinciden con los hashes almacenados.

Menciona dos algoritmos de key stretching.

Cualquiera dos de PBKDF2, bcrypt, scrypt o Argon2.

¿Qué objetivo de la tríada CIA apoya el calcular el hash de un archivo descargado?

La integridad, al confirmar que el archivo no fue alterado.
