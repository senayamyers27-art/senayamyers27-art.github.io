Formato IPv6: ocho hextetos, compresión de ceros a la izquierda y ::, longitud de prefijo (normalmente /64)

IPv6 se creó porque el espacio de direcciones de 32 bits de IPv4 se agotó. Una dirección IPv6 tiene 128 bits, lo que da una cantidad prácticamente ilimitada de direcciones y elimina la necesidad de NAT para ahorrar direcciones. Los 128 bits se escriben como ocho grupos de cuatro dígitos hexadecimales separados por dos puntos. Cada grupo tiene 16 bits y a menudo se le llama hextet (hexteto, o quartet). Un ejemplo completo: 2001:0db8:0000:0000:0000:ff00:0042:8329. El hexadecimal usa los dígitos del 0 al 9 y las letras de la a a la f, y las letras no distinguen mayúsculas de minúsculas, aunque lo estándar es usar minúsculas.

Dos reglas acortan las direcciones. Primero, los ceros a la izquierda de cualquier hexteto se pueden quitar: 0db8 se convierte en db8, 0042 en 42 y 0000 en 0. Los ceros a la derecha no se pueden quitar, porque 'db80' y 'db8' son valores distintos. Segundo, una secuencia de hextetos consecutivos formados solo por ceros se puede reemplazar por dos puntos dobles (::). Aplicando ambas reglas al ejemplo se obtiene 2001:db8::ff00:42:8329. Los dos puntos dobles solo pueden aparecer una vez en una dirección; si aparecieran dos veces, no se podría saber cuántos hextetos de ceros representa cada uno. Cuando hay dos secuencias de ceros separadas, la práctica estándar es comprimir la más larga (o la primera si son iguales).

Para expandir una dirección comprimida, cuenta los hextetos que se muestran y rellena el :: con suficientes grupos 0000 hasta llegar a ocho. En fe80::1 se muestran dos hextetos, así que :: representa seis hextetos de ceros: fe80:0000:0000:0000:0000:0000:0000:0001. El loopback ::1 se expande a siete hextetos de ceros seguidos de 0001, y :: solo significa la dirección no especificada, formada completamente por ceros.

Igual que CIDR en IPv4, IPv6 usa una longitud de prefijo después de una barra para indicar cuántos bits son la parte de red. IPv6 no usa máscaras de subred con puntos. El tamaño de subred estándar para una LAN es /64: los primeros 64 bits son el prefijo de red (prefijo de enrutamiento más el ID de subred) y los últimos 64 bits son el interface ID (identificador de interfaz) que identifica al host. Funciones como SLAAC dependen de las subredes /64. Una organización podría recibir un /48 de su proveedor y luego crear muchas subredes /64 a partir de él usando los 16 bits entre /48 y /64 como ID de subred.

Verás direcciones IPv6 en ipconfig en Windows (con un índice de zona %número después de las direcciones link-local, que identifica la interfaz), en ip -6 addr en Linux y en show ipv6 interface brief en dispositivos Cisco.

Términos clave

Hextet (hexteto)
Un grupo de 16 bits de una dirección IPv6, escrito como cuatro dígitos hexadecimales.
Double colon (::, dos puntos dobles)
Notación que reemplaza una secuencia de hextetos consecutivos formados solo por ceros; solo se puede usar una vez por dirección.
Prefix length (longitud de prefijo)
El número de bits de red de una dirección IPv6, escrito después de una barra; las subredes LAN normalmente son /64.
Interface ID (identificador de interfaz)
La porción de host de una dirección IPv6, normalmente los últimos 64 bits.
Ejemplo real

Un diagrama de red indica que un servidor es 2001:db8:acad:10::25/64. Expandida, es 2001:0db8:acad:0010:0000:0000:0000:0025. Los primeros cuatro hextetos, 2001:db8:acad:10, son el prefijo /64 que comparten todos los hosts de esa subred.

Consejo para el examen: Una dirección con dos veces los dos puntos dobles siempre es inválida. Y de un hexteto solo se pueden quitar los ceros a la izquierda, nunca los de la derecha.

Comprueba lo que sabes

Comprime 2001:0db8:0000:0000:0000:0000:0000:0001 lo más posible.

2001:db8::1.

¿Por qué :: solo puede aparecer una vez en una dirección?

Si apareciera dos veces, no habría forma de saber cuántos hextetos de ceros representa cada ::.

¿Cuántos bits tiene el interface ID en una subred IPv6 típica /64?

64 bits.
