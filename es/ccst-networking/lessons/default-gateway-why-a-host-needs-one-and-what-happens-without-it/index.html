Default gateway: por qué un host lo necesita y qué pasa sin él

Un host solo puede hablar directamente con los dispositivos de su propia subred. Para cualquier otra cosa, incluido cualquier destino en internet, debe enviar el tráfico a un router de su subred que sepa cómo llegar a otras redes. La dirección de ese router, configurada en el host, es el default gateway (puerta de enlace predeterminada). En una red doméstica, el default gateway es el router de casa, a menudo 192.168.0.1 o 192.168.1.1; en una oficina, normalmente es la interfaz de un router o de un switch de Capa 3 para esa VLAN.

Cada vez que un host envía un paquete, decide si el destino es local o remoto comparando la dirección IP de destino con su propia dirección y máscara de subred. Si el destino está en la misma subred, el host usa ARP para encontrar la dirección MAC del destino y envía la trama directamente. Si está en una subred distinta, el host usa ARP para encontrar la dirección MAC del default gateway y envía la trama al gateway, mientras que el paquete IP de adentro sigue dirigido al destino final. Luego el router lo reenvía.

El default gateway normalmente lo suministra DHCP junto con la dirección IP, la máscara y los servidores DNS, o se configura manualmente en los dispositivos con direcciones estáticas. En Windows, ipconfig lo muestra como Default Gateway; en Linux, ip route lo muestra como default via; en los switches Cisco configurados para administración, el comando ip default-gateway lo establece para que el switch pueda administrarse desde otras subredes.

Si el default gateway falta o es incorrecto, los síntomas son muy característicos: el host puede llegar a otros dispositivos de su propia subred (una impresora o una PC de al lado), pero a nada en otras subredes ni en internet. El ping a una dirección remota falla, mientras que el ping a un vecino local funciona. Las causas típicas son una configuración estática mal escrita, una dirección de gateway fuera de la subred del host, la interfaz del router caída o un servidor DHCP que está entregando la opción equivocada. Otra causa es que el propio router gateway no tenga ruta o conexión a internet, lo que desde el lado del usuario se ve parecido.

Una secuencia de prueba estándar es revisar ipconfig para ver si hay gateway, hacer ping al gateway y luego hacer ping a una dirección IP remota. Si el gateway no responde (y se sabe que permite ping), el problema está entre el host y el router: el cableado, la VLAN o la interfaz del router. Si el gateway responde pero las direcciones remotas no, el problema está más allá del router. Ten en cuenta que la resolución de nombres es un paso aparte; con un gateway correcto pero un DNS incorrecto aún puedes llegar a direcciones IP remotas, pero no a nombres.

Términos clave

Default gateway (puerta de enlace predeterminada)
La dirección del router a la que un host envía el tráfico cuando el destino no está en su propia subred.
Local destination (destino local)
Una dirección en la propia subred del host, a la que se llega directamente con ARP y una trama dirigida a ese dispositivo.
Remote destination (destino remoto)
Una dirección en una subred distinta, a la que se llega enviando la trama al default gateway.
ip default-gateway
Comando de Cisco que establece el gateway que usa un switch de Capa 2 para su propio tráfico de administración.
Ejemplo real

Una PC con una dirección configurada manualmente puede imprimir en una impresora de su subred, pero no puede abrir ningún sitio web. ipconfig muestra que el campo del default gateway está vacío. Después de agregar el gateway correcto, 10.20.30.1, la PC llega a internet.

Consejo para el examen: Síntoma clásico: los dispositivos locales funcionan, las redes remotas e internet no. Piensa en un default gateway faltante o incorrecto. Además, el gateway debe estar en la misma subred que el host.

Comprueba lo que sabes

¿Qué pasa cuando un host sin default gateway intenta llegar a un servidor en otra subred?

No tiene a dónde enviar el paquete, así que la comunicación con las redes remotas falla mientras que la comunicación local sigue funcionando.

Cuando un host envía un paquete a una red remota, ¿qué dirección MAC va en el campo de destino de la trama?

La dirección MAC del default gateway.
