TCP frente a UDP: orientado a conexión frente a sin conexión, el three-way handshake y cuándo se usa cada uno

TCP (Transmission Control Protocol) y UDP (User Datagram Protocol) son los dos protocolos principales de la capa de Transporte. Ambos usan números de puerto para que un host sepa a qué aplicación pertenece un segmento, pero hacen promesas muy distintas sobre la entrega.

TCP es orientado a conexión y confiable. Antes de enviar datos, los dos hosts establecen una conexión con un three-way handshake (saludo de tres vías). El cliente envía un segmento con la bandera SYN (synchronize) y un número de secuencia inicial. El servidor responde con SYN-ACK, confirmando el número del cliente y enviando el suyo. El cliente termina con ACK. Después de eso, TCP numera cada byte que envía, el receptor confirma lo que llegó y todo lo que no se confirme a tiempo se retransmite. TCP también reordena los datos que llegan fuera de secuencia y usa control de flujo (la ventana, window) para que un emisor rápido no sature a un receptor lento. Al terminar, los hosts cierran la conexión con segmentos FIN y ACK, o de forma abrupta con RST (reset).

UDP es sin conexión (connectionless) y de mejor esfuerzo (best-effort). No hay handshake, ni confirmaciones, ni retransmisión, ni ordenamiento. El encabezado UDP mide solo 8 bytes, frente a al menos 20 bytes de TCP, así que UDP es ligero y rápido. Si una aplicación necesita confiabilidad sobre UDP, la propia aplicación debe construirla.

Elige según lo que valora la aplicación. TCP conviene para todo lo que requiere que cada byte llegue correctamente: navegación web (HTTP y HTTPS), correo (SMTP, IMAP, POP3), transferencia de archivos (FTP, SFTP) e inicio de sesión remoto (SSH, Telnet). UDP conviene para tráfico en tiempo real y de solicitud/respuesta simple, donde la velocidad importa más que la entrega perfecta, o donde un mensaje perdido simplemente se vuelve a enviar: llamadas de voz y video, transmisiones en vivo y juegos, consultas DNS, DHCP, TFTP, NTP y SNMP. Un paquete de voz que llega tarde no sirve, así que retransmitirlo solo agregaría retardo. DNS usa UDP para las consultas normales, pero cambia a TCP para respuestas grandes y transferencias de zona.

En Wireshark puedes observar un handshake: filtra con tcp.flags.syn == 1 y verás pares SYN y SYN-ACK al inicio de cada conexión. En una computadora, netstat -an en Windows o ss -tuna en Linux lista las conexiones con estados TCP como LISTEN, ESTABLISHED y TIME_WAIT; las entradas UDP no tienen estado de conexión (Windows deja la columna State en blanco y ss muestra UNCONN) porque no hay conexión.

Términos clave

TCP
Transmission Control Protocol: entrega orientada a conexión, confiable y ordenada, con confirmaciones y retransmisión.
UDP
User Datagram Protocol: entrega sin conexión y de mejor esfuerzo, con sobrecarga mínima y sin retransmisión.
Three-way handshake (saludo de tres vías)
El intercambio SYN, SYN-ACK, ACK que TCP usa para abrir una conexión.
Flow control (control de flujo)
El mecanismo de ventana de TCP que limita cuántos datos transmite un emisor antes de recibir confirmación.
Ejemplo real

Durante una videoconferencia la imagen se pixela brevemente cuando el Wi-Fi pierde algunos paquetes, pero la llamada continúa; eso es UDP transportando medios sin retransmisión. Mientras tanto, un archivo que subes en el chat llega intacto porque viaja por TCP, que reenvía cualquier pieza faltante.

Consejo para el examen: El orden importa: SYN, SYN-ACK, ACK. Y si una pregunta enfatiza 'confiable, ordenado, con confirmación', elige TCP; si dice 'baja sobrecarga, tiempo real, sin handshake', elige UDP.

Comprueba lo que sabes

¿Cuáles son los tres segmentos del handshake de TCP, en orden?

SYN del cliente, SYN-ACK del servidor y ACK del cliente.

¿Por qué las llamadas de voz normalmente usan UDP en lugar de TCP?

Retransmitir paquetes de voz atrasados agregaría retardo y llegarían demasiado tarde para ser útiles, así que la baja sobrecarga y la velocidad importan más que la confiabilidad.

Nombra dos protocolos comunes que usan UDP.

Por ejemplo, las consultas DNS, DHCP, TFTP y NTP.
