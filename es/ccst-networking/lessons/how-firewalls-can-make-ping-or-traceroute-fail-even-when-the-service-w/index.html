Cómo los firewalls pueden hacer que ping o traceroute fallen aunque el servicio funcione

Ping y traceroute son excelentes primeras pruebas, pero dependen de ICMP y, en el caso de traceroute, de que los routers respondan con mensajes ICMP Time Exceeded. Los firewalls, incluidos los firewalls de host en computadoras y servidores, a menudo bloquean parte o todo el ICMP. Cuando eso pasa, la herramienta de diagnóstico falla mientras que el servicio real, como un sitio web en TCP 443, funciona perfectamente. Necesitas reconocerlo para no perseguir un problema que no existe.

¿Por qué bloquear ICMP? Algunos administradores lo hacen para que los hosts sean más difíciles de descubrir con escaneos de red, para reducir la superficie de ataque o porque las políticas del firewall están escritas para permitir solo los servicios específicos necesarios y simplemente ICMP no está en la lista. Por ejemplo, Windows Defender Firewall bloquea por defecto las solicitudes ICMP echo entrantes en muchos perfiles de red, así que hacer ping a otra PC con Windows a menudo falla aunque esté en línea y compartiendo archivos. Muchos sitios web públicos y servidores en la nube también descartan el ping. Bloquear todo ICMP no es lo ideal, porque algunos mensajes ICMP son importantes para el funcionamiento correcto de la red (IPv6 en particular depende de ICMPv6), pero es común.

Traceroute tiene más formas de fallar. Los routers pueden estar configurados para no enviar mensajes Time Exceeded, o para limitar su frecuencia (rate-limit), lo que produce asteriscos en algunos saltos aunque el tráfico pase por ellos sin problema. Los firewalls pueden bloquear el tipo de sonda: el tracert de Windows usa ICMP Echo, mientras que el traceroute de Linux y macOS usa por defecto sondas UDP hacia puertos altos, y un firewall podría permitir uno pero no el otro. Así que un trace que termina en asteriscos antes del destino no prueba que el destino sea inalcanzable para la aplicación.

El enfoque correcto es probar el servicio real. Para un sitio web, ábrelo en un navegador o usa una herramienta que se conecte al puerto TCP. En Windows, Test-NetConnection server.example.com -Port 443 informa si la conexión TCP tuvo éxito. En Linux y macOS, nc -zv server.example.com 443 (netcat) o curl -I hacia la dirección web hacen el mismo trabajo. Si la prueba de puerto tiene éxito, el servicio es alcanzable sin importar lo que diga ping. Algunas versiones de traceroute también pueden usar sondas TCP hacia el puerto de un servicio, que los firewalls tienen más probabilidades de permitir.

Lo contrario también es cierto: un ping exitoso no prueba que un servicio funcione. El host puede estar activo mientras el servicio web está detenido o su puerto bloqueado. Pregunta siempre qué necesita realmente el usuario y pruébalo directamente. Al reportar, di específicamente qué probaste, por ejemplo: 'El ICMP hacia el servidor agota el tiempo de espera, pero TCP 443 se conecta correctamente, así que el servicio web es alcanzable y probablemente el ICMP está filtrado.'

Términos clave

ICMP filtering (filtrado de ICMP)
Una política de firewall que bloquea parte o todos los mensajes ICMP, lo que hace que ping o traceroute fallen.
Host-based firewall (firewall basado en host)
Software de firewall que se ejecuta en una computadora y controla su tráfico entrante y saliente.
Port test (prueba de puerto)
Verificar si una conexión TCP a un puerto específico tiene éxito, por ejemplo con Test-NetConnection o nc.
Rate limiting (limitación de frecuencia)
Restringir cuántas respuestas ICMP envía un router, lo que puede hacer que algunos saltos de traceroute muestren asteriscos.
Ejemplo real

Un técnico reporta que el sitio web de la empresa está caído porque el ping hacia él agota el tiempo de espera. Ejecutas Test-NetConnection www.example.com -Port 443 y reporta TcpTestSucceeded: True, y la página carga en un navegador. El firewall del servidor web simplemente descarta el ICMP; el servicio está bien.

Consejo para el examen: Un ping fallido no prueba que un host o servicio esté caído, y un ping exitoso no prueba que el servicio funcione. Prueba el puerto real que usa la aplicación.

Comprueba lo que sabes

¿Por qué podría fallar el ping a una PC con Windows aunque esté en línea?

Windows Defender Firewall a menudo bloquea por defecto las solicitudes ICMP echo entrantes.

¿Cómo puedes confirmar que un servidor web es alcanzable si no responde al ping?

Probando directamente el puerto del servicio, por ejemplo con Test-NetConnection -Port 443, nc -zv, curl o un navegador.
