Cómo filtran el tráfico los firewalls: reglas permit y deny, puertos y protocolos, implicit deny

Un firewall (cortafuegos) es un dispositivo o software que controla qué tráfico puede pasar entre redes o entrar y salir de un host, según una política de seguridad. Se ubica en los límites, como entre la red interna e internet, entre zonas internas o en la propia computadora, e inspecciona cada paquete o conexión comparándolo con una lista ordenada de reglas.

Cada regla (en los routers Cisco, a menudo una entrada de control de acceso dentro de una ACL, access control list o lista de control de acceso) identifica el tráfico usando criterios como la dirección IP o red de origen, la dirección IP o red de destino, el protocolo (TCP, UDP, ICMP) y el puerto de origen o destino, y especifica una acción: permit (permitir) o deny (bloquear, a veces llamado drop o reject). Por ejemplo, una regla podría permitir TCP desde cualquier origen hacia el servidor web 203.0.113.10 en el puerto 443, y denegar TCP desde internet hacia cualquier host interno en el puerto 3389 (RDP). Las reglas también pueden aplicarse a una dirección, entrante o saliente, en una interfaz o zona determinada.

Las reglas se procesan de arriba hacia abajo, y la primera regla que coincide decide la acción; las reglas posteriores no se revisan. Por eso el orden importa. Un 'deny any' amplio colocado encima de un permit específico bloqueará el tráfico permitido, y un permit amplio encima de un deny específico hace inútil el deny. La buena práctica es poner las reglas específicas antes que las generales.

Si ninguna regla coincide, se aplica el implicit deny (denegación implícita): al final de cada lista de acceso y de la mayoría de las políticas de firewall hay una regla invisible de 'denegar todo'. Todo lo que no esté permitido explícitamente se bloquea. Esto respalda el principio de mínimo privilegio (least privilege), que permite solo lo necesario. También explica un error común: agregar una ACL con solo sentencias deny bloquea todo el tráfico, porque nunca se permite nada. Muchos administradores agregan al final un deny explícito con registro (logging) para dejar constancia de lo que se está bloqueando.

Los puertos y protocolos son la forma en que los firewalls reconocen los servicios, así que conocer los números de puerto comunes te ayuda a leer las reglas: permitir DNS significa UDP (y TCP) 53, web significa TCP 80 y 443, SSH significa TCP 22. Algunos firewalls van más allá con el reconocimiento de aplicaciones (application awareness), identificando las aplicaciones sin importar el puerto.

Que una conexión bloqueada se descarte en silencio o se rechace cambia lo que ve el usuario: el tráfico descartado normalmente provoca un tiempo de espera agotado, mientras que un rechazo devuelve un TCP reset o un mensaje ICMP, así que la falla aparece rápidamente. Al solucionar problemas, los logs del firewall que muestran las conexiones denegadas, con origen, destino y puerto, son una de las pistas más útiles.

Términos clave

Firewall (cortafuegos)
Un dispositivo o software que permite o deniega el tráfico según una política de seguridad.
ACL
Access control list (lista de control de acceso): una lista ordenada de sentencias permit y deny usada para filtrar tráfico.
Implicit deny (denegación implícita)
La regla invisible al final de una política que bloquea todo el tráfico que no esté permitido explícitamente.
First match (primera coincidencia)
Procesamiento de reglas en el que la primera regla que coincide con un paquete determina la acción.
Least privilege (mínimo privilegio)
Permitir solo el acceso necesario y denegar todo lo demás.
Ejemplo real

Un administrador agrega una regla de firewall que permite HTTPS hacia un nuevo servidor web, pero la coloca debajo de una regla existente que deniega todo el tráfico hacia la subred de ese servidor. Los usuarios no pueden conectarse. Mover la regla permit por encima de la regla deny lo resuelve, porque el firewall se detiene en la primera coincidencia.

Consejo para el examen: Las reglas se leen de arriba hacia abajo y gana la primera coincidencia. Todo lo que no esté permitido lo bloquea el implicit deny del final.

Comprueba lo que sabes

¿Qué pasa con el tráfico que no coincide con ninguna regla de una política de firewall?

Lo bloquea el implicit deny al final de la política.

¿Por qué importa el orden de las reglas?

Las reglas se procesan de arriba hacia abajo y decide la primera coincidencia, así que una regla general encima de una específica puede anularla.
