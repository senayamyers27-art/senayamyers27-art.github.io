NAT y PAT: cómo un router doméstico comparte una sola dirección pública

NAT (Network Address Translation, traducción de direcciones de red) es una función de un router o firewall que reescribe las direcciones IP de los paquetes a medida que pasan entre una red interna (inside) y una red externa (outside). Su trabajo principal es permitir que los dispositivos con direcciones privadas se comuniquen en internet usando direcciones públicas. En la terminología de NAT, la inside local address es la dirección privada del host y la inside global address es la dirección pública a la que se traduce.

Hay varias formas. El NAT estático (static NAT) asocia de forma permanente una dirección privada con una dirección pública, lo cual es útil cuando un servidor interno debe ser accesible desde afuera. El NAT dinámico (dynamic NAT) asocia direcciones privadas con direcciones públicas de un pool (grupo), por orden de llegada; si el pool se agota, los hosts adicionales no pueden conectarse. PAT (Port Address Translation), también llamado NAT overload (sobrecarga de NAT), asocia muchas direcciones privadas con una sola dirección pública traduciendo también los números de puerto. PAT es lo que hace casi cualquier router doméstico o de oficina pequeña.

Así funciona PAT. Tu laptop en 192.168.1.20 abre una conexión web desde el puerto de origen 51000 hacia un servidor en el puerto 443. El router reemplaza la dirección de origen por su dirección pública WAN, por ejemplo 203.0.113.5, y puede cambiar el puerto de origen por un valor único, por ejemplo 62001. Registra la asociación en su tabla de traducción: 192.168.1.20:51000 corresponde a 203.0.113.5:62001. Cuando la respuesta regresa a 203.0.113.5:62001, el router consulta la tabla, reescribe el destino de vuelta a 192.168.1.20:51000 y lo reenvía a la laptop. Como cada conversación recibe un puerto único, miles de conexiones internas pueden compartir una sola dirección pública.

Un efecto secundario es que las conexiones entrantes no solicitadas no tienen ninguna entrada que coincida, así que el router las descarta. Por eso alojar un servidor de juegos o una cámara en casa requiere port forwarding (reenvío de puertos), una regla estática que le indica al router que envíe el tráfico entrante en cierto puerto a un host interno específico. El port forwarding expone deliberadamente ese dispositivo, así que debe usarse con cuidado. NAT oculta el direccionamiento interno, pero no es un control de seguridad por sí mismo; sigue siendo necesaria una política de firewall.

En los routers Cisco verás interfaces marcadas con ip nat inside e ip nat outside, y show ip nat translations lista las asociaciones activas. En un router doméstico, la tabla NAT normalmente está oculta, pero la página de port forwarding es donde creas las reglas de entrada.

Términos clave

NAT
Network Address Translation: reescribir las direcciones IP a medida que los paquetes cruzan un router, normalmente de privada a pública.
PAT
Port Address Translation (NAT overload): muchos hosts internos comparten una sola dirección pública, distinguidos por números de puerto.
Static NAT (NAT estático)
Una asociación fija uno a uno entre una dirección privada y una pública.
Port forwarding (reenvío de puertos)
Una regla estática que envía el tráfico entrante de un puerto público específico a un host interno elegido.
Translation table (tabla de traducción)
La lista del router con las asociaciones activas entre direcciones/puertos internos y direcciones/puertos externos.
Ejemplo real

Una familia tiene un teléfono, dos laptops, un televisor y una consola de videojuegos en línea al mismo tiempo con una sola dirección pública de su proveedor. La tabla PAT del router rastrea cada conexión por puerto, así que las respuestas de los servicios de streaming y de los sitios web siempre regresan al dispositivo correcto.

Consejo para el examen: 'Muchos a uno usando puertos' es PAT (NAT overload). 'Uno a uno, permanente' es NAT estático. 'Muchos a muchos desde un pool' es NAT dinámico.

Comprueba lo que sabes

¿Cómo sabe un router con PAT a qué dispositivo interno pertenece una respuesta?

Busca el puerto de destino de la respuesta en su tabla de traducción, que asocia cada puerto externo con una dirección y un puerto internos.

¿Por qué un servidor web interno necesita NAT estático o port forwarding para ser accesible desde internet?

Sin una asociación preconfigurada, las conexiones entrantes no tienen entrada de traducción y el router las descarta.
