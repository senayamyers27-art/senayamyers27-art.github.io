ping, tracert/traceroute, ipconfig/ifconfig/ip y nslookup: cómo ejecutarlos y leer sus resultados

Estas cuatro familias de herramientas responden las preguntas más comunes del soporte de redes: cuál es mi configuración, puedo llegar al destino, qué ruta toma el tráfico y se resuelve el nombre. Saber ejecutar cada una y leer su salida es esencial para el examen y para el trabajo diario.

ipconfig (Windows), ifconfig (macOS y Linux antiguo) e ip addr (Linux moderno) muestran tu configuración. Verifica que el adaptador esté conectado, que la dirección IPv4 sea válida para tu red (no 169.254.x.x), que la máscara de subred coincida con la red, que haya un default gateway y, con ipconfig /all, que aparezcan los servidores DNS y el servidor DHCP. Muchos problemas se resuelven simplemente leyendo esta salida con cuidado.

ping <target> prueba la alcanzabilidad con ICMP Echo. El éxito muestra respuestas con tiempos de ida y vuelta en milisegundos; el resumen muestra la pérdida de paquetes. 'Request timed out' significa que no hubo respuesta; 'Destination host unreachable' significa que un router o tu propia PC no pudo entregarlo; una pérdida intermitente sugiere un enlace inestable o congestión. Algunas opciones útiles son ping -t en Windows (continuo hasta Ctrl+C) y ping -c 5 en Linux y macOS (enviar cinco). Haz ping hacia afuera por pasos: loopback, tu propia IP, el gateway, una IP remota, un nombre remoto.

tracert (Windows) y traceroute (Linux y macOS) muestran cada salto de router a lo largo de la ruta. Envían paquetes con valores de TTL crecientes; cada router que reduce el TTL a cero devuelve un mensaje ICMP Time Exceeded, que revela su dirección y su tiempo. Cada línea muestra un número de salto, tres tiempos de ida y vuelta y la dirección o el nombre del router. Un asterisco (*) significa que no hubo respuesta dentro del tiempo de espera para esa sonda. Unos cuantos asteriscos en medio, con saltos posteriores que sí responden, es normal, porque algunos routers no responden; un trace que se detiene en cierto salto y muestra solo asteriscos a partir de ahí señala dónde se está perdiendo o bloqueando el tráfico. El tracert de Windows usa ICMP, mientras que el traceroute tradicional de Linux usa sondas UDP por defecto.

nslookup <name> consulta el DNS. Primero muestra qué servidor DNS respondió y luego las direcciones resueltas. 'Non-authoritative answer' (respuesta no autoritativa) es normal y significa que la respuesta vino de un servidor que no es autoritativo para el dominio, normalmente tu resolvedor DNS recursivo, a menudo desde su caché, y no directamente del servidor autoritativo del dominio. Errores como 'can't find ... Non-existent domain' (NXDOMAIN) significan que el nombre no existe o está mal escrito, y un tiempo de espera agotado significa que no se pudo llegar al servidor DNS. Puedes consultar un servidor específico con nslookup example.com 8.8.8.8 para comparar resultados; si eso funciona mientras que el servidor por defecto falla, el problema es el servidor DNS configurado.

En conjunto: si el ping a 8.8.8.8 funciona pero el ping a un nombre falla, concéntrate en el DNS con nslookup. Si el ping al gateway falla, concéntrate en la conexión local. Si el ping a IP remotas falla más allá del gateway, ejecuta tracert para ver dónde se detiene.

Términos clave

ping
Una herramienta que envía ICMP Echo Requests para probar la alcanzabilidad y medir el tiempo de ida y vuelta.
tracert / traceroute
Herramientas que listan cada salto de router hacia un destino usando valores de TTL crecientes.
nslookup
Una herramienta que consulta servidores DNS para resolver nombres a direcciones.
Non-authoritative answer (respuesta no autoritativa)
Una respuesta DNS de un servidor que no es autoritativo para el dominio, como un resolvedor recursivo o su caché.
Ejemplo real

Un usuario no puede abrir el portal de la empresa por nombre. ipconfig /all muestra direcciones correctas, el ping a la IP del portal funciona, pero nslookup portal.example.com agota el tiempo de espera. nslookup portal.example.com 10.0.0.53, usando el servidor DNS secundario, funciona, así que reportas que el servidor DNS primario no está respondiendo.

Consejo para el examen: La IP funciona pero el nombre no: problema de DNS, usa nslookup. Un traceroute que muestra asteriscos a partir de un salto sugiere dónde se descarta el tráfico, pero los asteriscos sueltos con respuestas posteriores a menudo son inofensivos.

Comprueba lo que sabes

¿Cómo descubre traceroute cada router a lo largo de una ruta?

Envía sondas con valores de TTL crecientes; cada router que descarta una sonda cuando el TTL llega a cero responde con ICMP Time Exceeded, lo que revela su dirección.

¿Qué significa 'Non-authoritative answer' en nslookup?

Que la respuesta vino de un servidor DNS que no es autoritativo para el dominio (normalmente tu resolvedor, a menudo desde su caché) y no directamente del servidor autoritativo del dominio; es normal.
