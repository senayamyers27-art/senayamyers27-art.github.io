Hunting en Sentinel: consultas de hunting, hunts, marcadores (bookmarks), livestream, notebooks con MSTICPy

La búsqueda proactiva de amenazas (threat hunting) supone que los atacantes podrían ya estar dentro sin ser detectados, y los busca. Sentinel ofrece un conjunto de herramientas que apoyan cada paso: encontrar ideas, ejecutar consultas, guardar evidencia, vigilar actividad nueva y hacer análisis avanzados.

La página Hunting lista las consultas de hunting. Muchas vienen de las soluciones de Content hub y están mapeadas a tácticas y técnicas de MITRE ATT&CK; también puedes escribir las tuyas. Cada consulta muestra cuántos resultados devuelve y si ese número cambió recientemente. Puedes ejecutar todas las consultas a la vez, ordenarlas por número de resultados o por cambio, y filtrarlas por táctica o fuente de datos. Una consulta que de repente devuelve resultados que antes no devolvía merece una revisión. Las consultas de hunting no crean alertas por sí solas.

Los hunts son una forma de organizar un proyecto de hunting de principio a fin. Creas un hunt con una hipótesis (por ejemplo, 'un atacante está usando una herramienta de administración remota para persistencia'), agregas consultas relevantes, haces seguimiento del estado y los hallazgos, y colaboras con tus colegas. Cuando el hunt termina, registras el resultado y puedes crear reglas de análisis o incidentes a partir de lo que encontraste.

Los marcadores (bookmarks) guardan filas interesantes del resultado de una consulta con notas, etiquetas y entidades mapeadas. Conservan la evidencia aunque la consulta o los datos subyacentes cambien. Los marcadores aparecen en el gráfico de investigación y pueden agregarse a un incidente existente o usarse para crear un incidente nuevo. Así es como un hallazgo de hunting entra en el proceso de incidentes. Los marcadores se almacenan en la tabla HuntingBookmark.

Livestream te permite ejecutar una consulta de hunting de forma continua contra los datos nuevos que llegan y recibir una notificación cuando aparecen resultados, sin crear una regla de análisis completa. Es ideal para vigilar un indicador específico durante una investigación activa, como una IP sospechosa que reaparece. Si una sesión de livestream resulta valiosa, puedes convertir la consulta en una regla de análisis.

Los notebooks te dan todo el poder de Python. Sentinel se integra con Jupyter notebooks que se ejecutan en Azure Machine Learning, y con notebooks sobre el data lake de Sentinel. MSTICPy (Microsoft Threat Intelligence Center Python security tools) es una biblioteca de código abierto creada para esto. Tiene proveedores de consultas para datos de Sentinel y Defender, enriquecimiento como búsquedas de inteligencia de amenazas y geolocalización de IP, decodificación de datos (por ejemplo base64) y visualizaciones como líneas de tiempo, árboles de procesos y mapas. Los notebooks son ideales para aprendizaje automático, análisis complejos y playbooks de investigación repetibles que combinan datos de muchas fuentes. Recuerda que el cómputo usado para ejecutar notebooks se factura por separado.

El flujo general: elige una hipótesis, ejecuta consultas de hunting o escribe KQL nuevo, marca la evidencia con bookmarks, usa livestream para vigilar si aparece más, profundiza en un notebook si hace falta y luego convierte los hallazgos en incidentes y nuevas detecciones.

Términos clave

Hunting query (consulta de hunting)
Una consulta KQL guardada para la búsqueda proactiva, a menudo mapeada a MITRE ATT&CK, que no crea alertas.
Bookmark (marcador)
Resultados de consulta guardados con notas, etiquetas y entidades que pueden agregarse a un incidente o crear uno.
Livestream
Una sesión que ejecuta una consulta de hunting de forma continua sobre datos nuevos y te notifica las coincidencias.
MSTICPy
Una biblioteca de Python de código abierto para investigaciones de seguridad en notebooks, con consultas de datos, enriquecimiento y visualización.
Ejemplo real

Durante un hunt de volcado de credenciales, una analista ejecuta las consultas de hunting relevantes, encuentra tres filas sospechosas y las guarda como bookmarks con el host y la cuenta mapeados. Crea un incidente a partir de los bookmarks, inicia un livestream sobre el hash del proceso sospechoso y usa un notebook con MSTICPy para construir un árbol de procesos y buscar el hash en la inteligencia de amenazas.

Consejo para el examen: Guardar evidencia de un hunt: bookmark. Vigilar nuevas coincidencias sin escribir una regla: livestream. Python, aprendizaje automático o enriquecimiento complejo: notebook con MSTICPy.

Comprueba lo que sabes

¿Cómo se convierte un hallazgo de hunting en un incidente?

Guarda los resultados como bookmark y luego crea un incidente nuevo a partir del bookmark o agrégalo a uno existente.

¿Las consultas de hunting generan alertas de forma programada?

No. Se ejecutan manualmente; para alertar de forma programada creas una regla de análisis.

¿Para qué se usa MSTICPy?

Para consultar datos de seguridad, enriquecerlos con inteligencia de amenazas y geolocalización, y visualizarlos en notebooks.
