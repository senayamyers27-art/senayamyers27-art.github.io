Esquema de advanced hunting: DeviceProcessEvents, DeviceNetworkEvents, DeviceLogonEvents, EmailEvents, EmailUrlInfo, IdentityLogonEvents, CloudAppEvents, AlertInfo y AlertEvidence

Advanced hunting en el portal de Defender expone los datos de Defender XDR como tablas agrupadas por fuente. Saber qué tabla contiene qué tipo de evento, y cómo se vinculan las tablas, es la diferencia entre una búsqueda rápida y una frustrante. La referencia del esquema en el portal lista todas las columnas; aquí están las tablas en las que se enfoca el SC-200.

Las tablas de dispositivos vienen de Defender for Endpoint. DeviceProcessEvents registra la creación de procesos: FileName, FolderPath, ProcessCommandLine, el hash SHA256, la cuenta y el proceso padre mediante las columnas InitiatingProcess, como InitiatingProcessFileName. Es donde buscas PowerShell codificado, binarios living-off-the-land o aplicaciones de Office que inician shells. DeviceNetworkEvents registra conexiones de red: RemoteIP, RemotePort, RemoteUrl, el ActionType (por ejemplo, conexión exitosa o fallida) y el proceso que la inició. DeviceLogonEvents registra los inicios de sesión en dispositivos, con AccountName, LogonType (como interactive, network o remote interactive) y ActionType que muestra éxito o fallo. Otras tablas de dispositivos cubren archivos, registro, imágenes cargadas y eventos generales.

Las tablas de correo vienen de Defender for Office 365. EmailEvents tiene una fila por cada entrega de mensaje, que incluye SenderFromAddress, RecipientEmailAddress, Subject, DeliveryAction, DeliveryLocation y ThreatTypes. EmailUrlInfo lista las URL encontradas en los mensajes, y EmailAttachmentInfo lista los adjuntos. Todas comparten NetworkMessageId, la clave con la que haces join para conectar un mensaje con sus URL o archivos. UrlClickEvents registra los clics de Safe Links, y EmailPostDeliveryEvents registra acciones posteriores a la entrega, como ZAP.

IdentityLogonEvents registra la actividad de autenticación vista por Defender for Identity en Active Directory y por Microsoft Entra ID, con el protocolo (por ejemplo, Kerberos o NTLM), la cuenta, el dispositivo y el motivo del fallo. Es ideal para buscar password spraying contra cuentas locales o el uso de protocolos heredados. Las tablas de identidad también incluyen IdentityQueryEvents e IdentityDirectoryEvents. CloudAppEvents viene de Defender for Cloud Apps y registra la actividad en aplicaciones en la nube como Exchange Online, SharePoint y Teams: ActionType, Application, la cuenta, la dirección IP y una columna RawEventData en JSON, que analizas para obtener detalles como los parámetros de reglas de bandeja de entrada.

AlertInfo tiene una fila por cada alerta de cualquier producto de Defender (y de Sentinel cuando está incorporado): AlertId, Title, Severity, Category, ServiceSource y DetectionSource. AlertEvidence tiene una fila por cada entidad adjunta a una alerta: EntityType, EvidenceRole y columnas de entidad como DeviceId, AccountName, FileName o RemoteIP. Únelas por AlertId para hacer preguntas como 'qué dispositivos aparecieron en alertas de severidad alta esta semana'.

EmailEvents
| where Timestamp > ago(7d) and ThreatTypes has "Phish"
| join kind=inner EmailUrlInfo on NetworkMessageId
| project Timestamp, RecipientEmailAddress, Subject, Url

Recuerda que la columna de tiempo en estas tablas es Timestamp, y que advanced hunting conserva aproximadamente 30 días de datos de Defender. Para un historial más largo, los datos deben estar en Sentinel.

Términos clave

DeviceProcessEvents
La tabla de eventos de creación de procesos, que incluye líneas de comandos y detalles del proceso padre.
NetworkMessageId
El identificador de correo que vincula EmailEvents con EmailUrlInfo, EmailAttachmentInfo y tablas relacionadas.
IdentityLogonEvents
Eventos de autenticación de Defender for Identity (AD local) y de Microsoft Entra ID.
AlertEvidence
Una fila por cada entidad adjunta a una alerta, unida a AlertInfo por AlertId.
Ejemplo real

Después de un incidente de phishing, un analista une EmailEvents con EmailUrlInfo por NetworkMessageId para listar a cada destinatario de la URL maliciosa, luego une UrlClickEvents para ver quién hizo clic y después consulta DeviceProcessEvents en los dispositivos de esos usuarios para buscar procesos iniciados por el navegador en la hora siguiente. Un dispositivo muestra la ejecución de un script descargado.

Consejo para el examen: Relaciona la redacción de la pregunta con las tablas: proceso y línea de comandos significa DeviceProcessEvents; conexión o IP remota significa DeviceNetworkEvents; inicios de sesión Kerberos o NTLM locales significa IdentityLogonEvents; reglas de buzón en Exchange Online normalmente significa CloudAppEvents.

Comprueba lo que sabes

¿Qué columna une EmailEvents con EmailUrlInfo?

NetworkMessageId.

¿Dónde buscarías el proceso padre de un inicio sospechoso de PowerShell?

En DeviceProcessEvents, usando las columnas InitiatingProcess, como InitiatingProcessFileName.

¿Cómo listas las entidades de las alertas de severidad alta?

Une AlertInfo (filtrada por Severity) con AlertEvidence por AlertId.
