Alertas de seguridad de Defender for Cloud: detalles de la alerta, la pestaña Take action, desencadenar automatización

Cuando un plan de cargas de trabajo de Defender for Cloud detecta una amenaza, como la ejecución de un proceso sospechoso en una VM, el acceso anónimo a una cuenta de almacenamiento, un intento de inyección SQL o una operación sospechosa de Resource Manager, genera una alerta de seguridad. Las alertas aparecen en la página Security alerts de Defender for Cloud y, gracias a la integración con Defender XDR, en la cola de incidentes del portal de Defender. También pueden llegar a Sentinel mediante su conector de Defender for Cloud.

Cada alerta tiene una severidad (high, medium, low o informational), un estado (active, in progress, resolved o dismissed), el recurso afectado, las tácticas de MITRE ATT&CK, la hora y una descripción. La pestaña de detalles de la alerta explica qué se detectó y muestra las entidades relacionadas: el host, la cuenta, la línea de comandos del proceso, la dirección IP, el archivo o el blob de almacenamiento. Cuando las alertas están vinculadas, Defender for Cloud puede agruparlas como un incidente de seguridad.

La pestaña Take action es la parte favorita del examen. Está dividida en secciones. Inspect resource context abre los registros y la actividad del recurso alrededor de la hora de la alerta. Mitigate the threat da pasos de remediación manual para esta alerta específica. Prevent future attacks lista recomendaciones de seguridad para el recurso que reducirían la probabilidad de que se repita, como habilitar la protección de endpoints o restringir el acceso de red. Trigger automated response te permite ejecutar una Logic App sobre esta alerta en este momento. Suppress similar alerts crea una regla de supresión para alertas que son esperadas en tu entorno, con condiciones y una fecha de vencimiento.

Para automatizar a escala, Defender for Cloud tiene la automatización de flujos de trabajo (workflow automation). Creas una workflow automation que ejecuta una Logic App cuando una alerta, una recomendación o un cambio de cumplimiento normativo cumple condiciones que defines, como la severidad o el nombre de la alerta. Los usos típicos son abrir un ticket, enviar un correo al propietario de un recurso o aislar una VM. La Logic App necesita un desencadenador del conector de Defender for Cloud (para alertas o recomendaciones). Como alternativa, exportas las alertas de forma continua (continuous export) a Event Hubs o a un espacio de trabajo de Log Analytics y actúas sobre ellas desde ahí, o dejas que la automatización de Sentinel las maneje.

Las reglas de supresión de alertas en Defender for Cloud funcionan como el ajuste de alertas en Defender XDR: ocultan o descartan automáticamente las alertas que cumplen condiciones, y deben ser limitadas y con tiempo definido. Descartar (dismiss) una alerta solo cambia su estado; no corrige el problema de fondo.

Un buen flujo de trabajo: lee los detalles de la alerta, inspecciona el contexto del recurso, sigue los pasos de mitigación, aplica las recomendaciones de prevención y cambia el estado a resolved con notas. Si la alerta fue una prueba autorizada, suprime de forma limitada en lugar de deshabilitar el plan.

Términos clave

Take action tab (pestaña Take action)
La pestaña de la alerta con secciones para inspeccionar el contexto, mitigar, prevenir que se repita, desencadenar automatización y suprimir alertas similares.
Workflow automation (automatización de flujos de trabajo)
Una función de Defender for Cloud que ejecuta automáticamente una Logic App cuando las alertas o recomendaciones cumplen condiciones.
Suppression rule (regla de supresión)
Una regla que oculta o descarta alertas esperadas que cumplen condiciones, con un vencimiento opcional.
Continuous export (exportación continua)
Transmitir las alertas y recomendaciones de Defender for Cloud a Event Hubs o a un espacio de trabajo de Log Analytics.
Ejemplo real

Defender for Storage alerta sobre el acceso a una cuenta de almacenamiento desde un nodo de salida de Tor. La analista abre Take action, inspecciona los registros de almacenamiento alrededor de esa hora, sigue la mitigación para regenerar las claves de la cuenta y, en Prevent future attacks, aplica la recomendación de deshabilitar el acceso desde la red pública. Luego crea una workflow automation que envía un correo a los propietarios del almacenamiento por todas las alertas de almacenamiento de severidad alta.

Consejo para el examen: Ejecutar una Logic App sobre una alerta ahora: Trigger automated response en la pestaña Take action. Ejecutarla automáticamente cada vez: workflow automation. Detener alertas esperadas: regla de supresión.

Comprueba lo que sabes

¿Qué sección de Take action lista recomendaciones para evitar que la alerta se repita?

Prevent future attacks.

¿Cómo ejecutas automáticamente una Logic App para cada alerta de severidad alta de Defender for Cloud?

Crea una workflow automation con una condición de severidad que desencadene la Logic App.

¿Descartar una alerta remedia la amenaza?

No. Solo cambia el estado; todavía debes mitigar y corregir el problema de fondo.
