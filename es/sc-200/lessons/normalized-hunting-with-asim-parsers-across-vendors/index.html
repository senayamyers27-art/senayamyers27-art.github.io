Hunting normalizado con parsers de ASIM entre proveedores

La mayoría de las organizaciones tienen varios firewalls, proxies, servidores DNS y sistemas de identidad de distintos proveedores. Cada uno registra el mismo tipo de evento con nombres de tabla, nombres de columna y valores diferentes. Un firewall llama a la dirección de origen SrcIP, otro src_ip, y un tercero la pone dentro de un mensaje Syslog. Escribir cada detección y cada búsqueda una vez por proveedor no escala.

El Advanced Security Information Model (ASIM) resuelve esto normalizando los datos en el momento de la consulta. ASIM define esquemas para tipos de eventos comunes, incluidos network session, DNS, web session, authentication, process event, file event, registry event, audit event, user management y DHCP. Cada esquema tiene nombres de columna y formatos de valores estándar, por ejemplo SrcIpAddr, DstIpAddr, DstPortNumber y EventResult con valores como Success o Failure.

Los parsers son funciones KQL que leen datos específicos de un proveedor y producen filas en el esquema de ASIM. Hay parsers específicos de la fuente (source-specific), uno por producto, y parsers unificadores (unifying) que llaman a todos los parsers específicos de un esquema y combinan los resultados con union. Cuando consultas el parser unificador _Im_NetworkSession, obtienes las sesiones de red de todas las fuentes compatibles en un solo resultado normalizado, sin saber de qué tablas vinieron. Las fuentes nuevas se agregan añadiendo su parser; las consultas construidas sobre el parser unificador las incorporan automáticamente.

Hay dos variantes de parser unificador. Los parsers de filtrado, cuyo nombre lleva el prefijo _Im_, aceptan parámetros como starttime, endtime y filtros específicos del esquema, como prefijos de direcciones IP de origen o nombres de dominio. Los filtros se aplican dentro de cada parser de fuente, así que se procesan menos datos y las consultas se ejecutan más rápido. Los parsers sin parámetros, con el prefijo _ASim_, devuelven todo y son útiles para explorar. Los parsers integrados se implementan con Sentinel y empiezan con un guion bajo; existen versiones implementadas en el espacio de trabajo, sin el guion bajo, para personalizarlas.

_Im_NetworkSession(starttime = ago(1d), endtime = now())
| where DstPortNumber == 3389 and EventResult == "Success"
| summarize Sessions = count() by SrcIpAddr, DstIpAddr

Esta única consulta encuentra sesiones de Remote Desktop Protocol en todas las fuentes de firewall y de red normalizadas. La misma idea se aplica a las detecciones: muchas plantillas de reglas de análisis de Sentinel están construidas sobre ASIM para que funcionen entre proveedores. La contrapartida es que el análisis en tiempo de consulta cuesta algo de rendimiento y dependes de que existan parsers para tus productos. Para un uso intensivo, también es posible la normalización en tiempo de ingesta en tablas de ASIM.

Cuando hagas hunting entre proveedores, recurre primero al parser unificador de ASIM del esquema, pasa los filtros como parámetros y baja a una tabla sin procesar del proveedor solo cuando necesites un campo que ASIM no mapea.

Términos clave

ASIM
El Advanced Security Information Model, que normaliza eventos de distintas fuentes en esquemas comunes.
Unifying parser (parser unificador)
Una función de ASIM que combina todos los parsers específicos de la fuente de un esquema en un solo resultado normalizado.
Filtering parser (parser de filtrado)
Un parser _Im_ que acepta parámetros como filtros de tiempo y de IP para mejorar el rendimiento.
Source-specific parser (parser específico de la fuente)
Una función de ASIM que normaliza los datos de un producto en un esquema.
Ejemplo real

Una empresa usa dos marcas distintas de firewall después de una fusión. En lugar de mantener dos versiones de cada búsqueda, el SOC reescribe sus búsquedas de movimiento lateral para usar _Im_NetworkSession con filtros de tiempo. Cuando se agrega un tercer firewall y se instala su parser de ASIM, las búsquedas existentes lo cubren sin cambios.

Consejo para el examen: Una sola consulta entre muchos proveedores para el mismo tipo de evento significa ASIM. Usa los parsers de filtrado _Im_ con parámetros para mejorar el rendimiento; los parsers _ASim_ no aceptan parámetros.

Comprueba lo que sabes

¿Cuál es el beneficio de consultar _Im_NetworkSession en lugar de la tabla de cada firewall?

Una sola consulta normalizada cubre todas las fuentes compatibles, y las fuentes nuevas se incluyen automáticamente.

¿Por qué pasar starttime y endtime a un parser de filtrado?

Los filtros se aplican dentro de cada parser de fuente, lo que reduce los datos procesados y acelera la consulta.

Nombra tres esquemas de ASIM.

Ejemplos: network session, DNS, authentication, process event, web session, file event.
