Microsoft Certified: Security Operations Analyst Associate SC-200

Conectores de datos y soluciones de Content hub; Windows Security Events y CEF/Syslog mediante Azure Monitor Agent y reglas de recopilación de datos (DCR); la Logs Ingestion API para fuentes personalizadas

Un SIEM es tan bueno como los datos que recibe. En Sentinel, los conectores de datos (data connectors) traen registros de servicios de Microsoft, otras nubes, firewalls, servidores y aplicaciones de software como servicio a las tablas del espacio de trabajo. Los conectores se entregan mediante Content hub, un catálogo de soluciones. Una solución es un paquete que puede incluir conectores, reglas de análisis, workbooks, consultas de hunting, parsers y playbooks para un producto o escenario. Instalas la solución, luego abres la página de su conector y sigues los pasos de configuración.

Las fuentes propias de Microsoft, como Microsoft Entra ID, Microsoft 365 y Defender XDR, normalmente se conectan con unos pocos clics porque son de servicio a servicio. Los servidores necesitan un agente. Azure Monitor Agent (AMA) es el agente actual para Windows y Linux; reemplazó al antiguo agente de Log Analytics. AMA se controla mediante reglas de recopilación de datos (DCR), que definen tres cosas: las fuentes de datos a recopilar, una transformación KQL opcional aplicada en el momento de la ingesta, y el espacio de trabajo y la tabla de destino. Las máquinas fuera de Azure se conectan mediante Azure Arc para poder implementarles AMA.

Para servidores Windows, el conector Windows Security Events via AMA escribe en la tabla SecurityEvent. Eliges un conjunto de eventos: All, Common, Minimal, o Custom usando consultas XPath para recopilar ID de eventos específicos, por ejemplo 4624 (inicio de sesión exitoso), 4625 (inicio de sesión fallido) y 4688 (creación de proceso). Elegir un conjunto limitado es la forma más eficaz de controlar el costo. Windows Forwarded Events es un conector relacionado para eventos recopilados mediante Windows Event Forwarding.

Muchos dispositivos de red envían registros como Syslog o Common Event Format (CEF), un formato estructurado transportado sobre Syslog. Normalmente no pueden ejecutar un agente, así que construyes un reenviador de registros Linux (log forwarder): una máquina Linux con rsyslog o syslog-ng más AMA. Los dispositivos envían al reenviador, y las DCR le indican a AMA qué facilidades (facilities) y severidades recopilar. Syslog va a la tabla Syslog; CEF va a la tabla CommonSecurityLog. Los conectores CEF via AMA y Syslog via AMA te guían para crear estas DCR.

Para fuentes personalizadas, como una aplicación interna o un producto sin conector, usa la Logs Ingestion API. Creas una tabla personalizada (su nombre termina en _CL), una DCR que describe la forma de los datos entrantes y cualquier transformación, y un registro de aplicación de Microsoft Entra o una identidad administrada. La identidad recibe el rol Monitoring Metrics Publisher en la DCR, y tu código o herramienta envía JSON al endpoint de ingesta de la DCR. Algunas configuraciones también usan un data collection endpoint (DCE). Microsoft también ofrece un codeless connector framework para crear conectores que consultan APIs sin escribir código.

Siempre verifica que los datos lleguen: ejecuta una consulta como SecurityEvent | take 10 o revisa el estado del conector y la hora de la última recepción de la tabla.

Términos clave

Content hub
El catálogo de soluciones de Sentinel que empaqueta conectores, reglas, workbooks, parsers y playbooks.
Azure Monitor Agent (AMA)
El agente actual para Windows y Linux que recopila datos según las reglas de recopilación de datos.
Data collection rule, DCR (regla de recopilación de datos)
Una configuración que define las fuentes, una transformación opcional en tiempo de ingesta y la tabla de destino.
Logs Ingestion API
Una API REST para enviar datos personalizados a una tabla del espacio de trabajo mediante una DCR.
Ejemplo real

Los firewalls de un fabricante solo pueden enviar CEF sobre Syslog. El SOC implementa una pequeña VM Linux con rsyslog y AMA, instala la solución de Content hub del proveedor, crea una DCR para el conector CEF via AMA y apunta los firewalls a la VM. En minutos, CommonSecurityLog se llena y las reglas de análisis de la solución empiezan a ejecutarse.

Consejo para el examen: Relaciona formatos con tablas: eventos de Windows con SecurityEvent, Syslog con Syslog, CEF con CommonSecurityLog, datos personalizados por API con una tabla _CL. El filtrado y la transformación ocurren en la DCR.

Comprueba lo que sabes

¿Qué tabla recibe los registros CEF recopilados por AMA?

CommonSecurityLog.

¿Cómo recopilas solo los ID de evento 4624, 4625 y 4688 de servidores Windows?

Usa el conector Windows Security Events via AMA con un conjunto de eventos XPath personalizado en la DCR.

¿Qué necesita una aplicación para enviar datos mediante la Logs Ingestion API?

Una tabla personalizada, una DCR que describa los datos y una identidad de Entra con el rol Monitoring Metrics Publisher en la DCR.
