Defender for Cloud: CSPM fundamental vs. planes de protección de cargas de trabajo de pago (Servers, Storage, Databases), conexión de cuentas de AWS y GCP, integración de Defender for Endpoint para servidores

Microsoft Defender for Cloud protege recursos en la nube en Azure, Amazon Web Services (AWS), Google Cloud Platform (GCP) y servidores locales (on-premises). Hace dos trabajos distintos, y el examen espera que los distingas. La administración de la postura de seguridad en la nube (CSPM) busca debilidades en cómo están configurados los recursos. La protección de cargas de trabajo en la nube (los planes Defender) detecta amenazas activas contra cargas de trabajo en ejecución y genera alertas de seguridad.

El CSPM fundamental (Foundational CSPM) está activado de forma predeterminada sin costo adicional. Te da una puntuación de seguridad (secure score), recomendaciones de seguridad basadas en el Microsoft cloud security benchmark, inventario de recursos y vistas de cumplimiento normativo para algunos estándares. El plan de pago Defender CSPM agrega funciones de postura más profundas, como el análisis de rutas de ataque (attack path analysis), el cloud security explorer, el escaneo sin agente y las reglas de gobernanza. Ninguno de los dos planes de CSPM produce alertas de amenazas sobre un atacante en una máquina virtual; ese es el trabajo de la protección de cargas de trabajo.

La protección de cargas de trabajo se habilita por plan y por suscripción (o cuenta de AWS o proyecto de GCP). Defender for Servers protege máquinas Windows y Linux, y viene en Plan 1 y Plan 2; el Plan 2 agrega más funciones, como el escaneo de vulnerabilidades sin agente, la supervisión de integridad de archivos (file integrity monitoring) y el acceso a VM just-in-time. Defender for Storage detecta amenazas contra cuentas de almacenamiento, como patrones de acceso inusuales y cargas de malware, con escaneo opcional de malware de blobs nuevos. Los planes de bases de datos cubren Azure SQL, servidores SQL en máquinas, bases de datos relacionales de código abierto y Azure Cosmos DB, y alertan sobre cosas como intentos de inyección SQL e inicios de sesión por fuerza bruta. También hay planes para contenedores, App Service, Key Vault, Resource Manager y APIs.

Para proteger AWS y GCP, agregas un entorno en Environment settings de Defender for Cloud. Para AWS, creas un conector e implementas la plantilla de CloudFormation proporcionada, que crea los roles que Defender for Cloud necesita para leer la cuenta. Para GCP, ejecutas un script proporcionado, normalmente en Cloud Shell, para crear las cuentas de servicio y los permisos. Luego eliges qué planes activar para ese conector, como Defender CSPM y Defender for Servers. Los servidores fuera de Azure pueden conectarse mediante Azure Arc para que se les puedan implementar extensiones de Azure.

Defender for Servers incluye una licencia de Defender for Endpoint e integra ambos productos automáticamente. Cuando la integración está activada, Defender for Cloud implementa el sensor de Defender for Endpoint en las máquinas compatibles, las incorpora a tu tenant de Defender for Endpoint y muestra las alertas de Defender for Endpoint en Defender for Cloud. Las mismas máquinas aparecen en el inventario de dispositivos del portal de Defender, así que tus analistas de endpoints y tu equipo de nube ven un solo conjunto de detecciones.

Una forma sencilla de recordarlo: la postura te dice dónde están las puertas sin llave, y la protección de cargas de trabajo te dice que alguien está entrando por una. La secure score y las recomendaciones vienen del CSPM. Alertas como 'suspicious process executed' en una VM vienen de un plan Defender de pago.

Términos clave

Foundational CSPM (CSPM fundamental)
El nivel gratuito de Defender for Cloud que ofrece secure score, recomendaciones e inventario de recursos.
Cloud workload protection (protección de cargas de trabajo en la nube)
Los planes Defender de pago (Servers, Storage, Databases y otros) que detectan amenazas y generan alertas de seguridad.
Multicloud connector (conector multinube)
La conexión de Defender for Cloud a una cuenta de AWS o a un proyecto de GCP, creada con una plantilla de CloudFormation o un script de GCP.
Defender for Endpoint integration (integración con Defender for Endpoint)
La función de Defender for Servers que implementa y licencia el sensor de Defender for Endpoint en los servidores protegidos.
Ejemplo real

Un minorista ejecuta servidores web en VM de Azure y en AWS EC2. La secure score muestra recomendaciones para ambos, pero no aparece ninguna alerta cuando se ejecuta una detección de prueba en EC2. El equipo se da cuenta de que solo tiene CSPM fundamental en el conector de AWS, así que habilita Defender for Servers en él; entonces se implementa el sensor de Defender for Endpoint y empiezan a llegar alertas.

Consejo para el examen: Si una opción dice que el CSPM fundamental producirá alertas de amenazas, es incorrecta. Las alertas de amenazas necesitan un plan Defender de cargas de trabajo; el attack path analysis necesita Defender CSPM.

Comprueba lo que sabes

¿Qué nivel da la secure score sin costo adicional?

El CSPM fundamental, que está habilitado de forma predeterminada.

¿Cómo conectas una cuenta de AWS a Defender for Cloud?

Crea un conector de AWS en Environment settings e implementa la plantilla de CloudFormation que genera; luego elige los planes que quieres habilitar.

¿Qué hace la integración de Defender for Endpoint en Defender for Servers?

Implementa e incorpora el sensor de Defender for Endpoint en los servidores compatibles y lleva sus detecciones de EDR a Defender for Cloud y al portal de Defender.
