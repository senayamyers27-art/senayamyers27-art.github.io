Microsoft Certified: Security Operations Analyst Associate SC-200

Automatización: reglas de automatización vs. playbooks de Logic Apps, desencadenadores, tareas de incidentes; watchlists, workbooks, UEBA y conectores de inteligencia de amenazas

Sentinel tiene dos capas de automatización. Las reglas de automatización (automation rules) son reglas ligeras e integradas que se ejecutan cuando se crean o actualizan incidentes o alertas. Pueden cambiar el estado, la severidad o el propietario, agregar etiquetas, agregar tareas de incidentes y ejecutar playbooks. Las reglas tienen un número de orden, una fecha de vencimiento opcional y condiciones como el nombre de la regla de análisis, la severidad, una etiqueta o una entidad. Son ideales para el triaje: asignar todos los incidentes de phishing al equipo de correo, subir la severidad cuando está involucrada una cuenta VIP o cerrar automáticamente incidentes conocidos como benignos.

Los playbooks son flujos de trabajo de Azure Logic Apps. Se encargan de todo lo que requiere sistemas externos o lógica de varios pasos: enriquecer una dirección IP con un servicio de reputación, publicar en Microsoft Teams, abrir un ticket, deshabilitar a un usuario mediante Microsoft Graph o pedir la aprobación de un analista. Los playbooks usan el desencadenador (trigger) de Microsoft Sentinel, que viene en tres tipos: de incidente, de alerta y de entidad. Los playbooks con desencadenador de incidente pueden ejecutarse desde reglas de automatización y son el tipo recomendado. Los playbooks con desencadenador de alerta también pueden ejecutarse desde reglas de automatización que se disparan cuando se crea una alerta (las configuraciones antiguas los adjuntaban directamente a las reglas de análisis). Los playbooks con desencadenador de entidad se ejecutan manualmente desde una entidad. Los playbooks se autentican en Sentinel y otros servicios, idealmente con una identidad administrada. Recuerda que Sentinel necesita el rol Automation Contributor en el grupo de recursos del playbook.

Las tareas de incidentes (incident tasks) son listas de verificación dentro de un incidente, como 'Restablecer la contraseña' o 'Revisar las reglas de la bandeja de entrada'. Las agregan las reglas de automatización o los playbooks, para que todos los analistas sigan los mismos pasos para un tipo de incidente dado, y se registra su cumplimiento.

Las watchlists son listas de referencia que cargas, normalmente como archivos CSV: usuarios VIP, hosts de administración conocidos, empleados dados de baja o rangos de IP aprobados. Cada una tiene un alias y una columna de clave de búsqueda (search key). En KQL, _GetWatchlist('VIPUsers') devuelve la lista, con la que haces join o filtras en reglas y búsquedas. Las watchlists ayudan tanto a subir la prioridad (alertar cuando está involucrado un VIP) como a reducir el ruido (excluir escáneres conocidos).

Los workbooks son paneles interactivos construidos sobre los workbooks de Azure Monitor. Muchos vienen con las soluciones de Content hub, y puedes crear los tuyos con gráficos, cuadrículas y parámetros basados en KQL. Son para visualización y reportes, no para generar alertas.

El análisis del comportamiento de usuarios y entidades (UEBA) construye líneas base del comportamiento normal de usuarios, hosts y otras entidades a partir de fuentes como los registros de inicio de sesión, los registros de auditoría y los eventos de seguridad de Windows. Escribe en tablas como BehaviorAnalytics, IdentityInfo y UserPeerAnalytics, y enriquece las páginas de entidad con información como 'primera vez que este usuario accedió a este recurso'. Habilitas UEBA en la configuración de Sentinel y eliges sus fuentes de datos.

Los conectores de inteligencia de amenazas traen indicadores de compromiso al espacio de trabajo. Algunos ejemplos son el conector Threat Intelligence TAXII para fuentes STIX/TAXII, el conector de API de carga (upload API) para plataformas de inteligencia de amenazas y el conector Microsoft Defender Threat Intelligence. Luego los indicadores se usan en las reglas de análisis de coincidencia de inteligencia de amenazas (threat intelligence matching) y en el hunting.

Términos clave

Automation rule (regla de automatización)
Una regla integrada de Sentinel que actúa sobre incidentes o alertas cuando se crean o actualizan, incluida la ejecución de playbooks.
Playbook
Un flujo de trabajo de Azure Logic Apps desencadenado por un incidente, una alerta o una entidad de Sentinel para enriquecimiento o respuesta.
Watchlist (lista de seguimiento)
Una lista de referencia, consultada con _GetWatchlist(), que se usa para enriquecer o filtrar reglas y búsquedas.
UEBA
User and entity behavior analytics (análisis del comportamiento de usuarios y entidades), que establece líneas base de la actividad normal y destaca anomalías en las páginas de entidad.
Ejemplo real

Un SOC crea una regla de automatización que se dispara con los incidentes de sus reglas de phishing: los asigna al equipo de correo, agrega tres tareas de incidente y ejecuta un playbook que consulta la reputación de cada URL y publica un resumen en un canal de Teams. Una watchlist de ejecutivos sube la severidad a High siempre que uno de ellos sea una entidad mapeada.

Consejo para el examen: Elige una regla de automatización para cambios dentro de Sentinel (propietario, estado, severidad, etiquetas, tareas). Elige un playbook cuando el escenario mencione un sistema externo, una API de enriquecimiento, correo, Teams o tickets. A menudo es la regla de automatización la que ejecuta el playbook.

Comprueba lo que sabes

¿Qué tipo de desencadenador de playbook se recomienda para que el playbook pueda ejecutarse desde reglas de automatización?

El desencadenador de incidente de Microsoft Sentinel.

¿Cómo usas una watchlist llamada VIPUsers en una consulta?

Llama a _GetWatchlist('VIPUsers') y haz join o filtra por su columna de clave de búsqueda.

¿Qué agrega habilitar UEBA a las investigaciones?

Líneas base de comportamiento, información sobre anomalías en las páginas de entidad y tablas como BehaviorAnalytics e IdentityInfo.
