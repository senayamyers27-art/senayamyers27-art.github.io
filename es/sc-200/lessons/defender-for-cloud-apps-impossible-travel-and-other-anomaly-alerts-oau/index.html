Defender for Cloud Apps: alertas de viaje imposible y otras anomalías, riesgo de aplicaciones OAuth y revocación del consentimiento de aplicaciones

Microsoft Defender for Cloud Apps es el agente de seguridad de acceso a la nube (CASB) de Microsoft. Se conecta mediante APIs a servicios en la nube como Microsoft 365 y otras aplicaciones de software como servicio, descubre la TI en la sombra (shadow IT) a partir de registros de red y aplica directivas a la actividad de los usuarios. Para el SOC, sus resultados más importantes son las alertas de detección de anomalías y la visibilidad de las aplicaciones OAuth.

Las directivas de detección de anomalías vienen integradas y activadas de forma predeterminada. Aprenden el comportamiento normal de cada usuario durante un período inicial de aprendizaje y luego alertan sobre desviaciones. El viaje imposible (impossible travel) se dispara cuando el mismo usuario inicia sesión desde dos ubicaciones tan alejadas que nadie podría viajar entre ellas en el tiempo transcurrido, lo que sugiere una credencial robada usada desde otro país. Tiene fuentes conocidas de falsos positivos, como las VPN y los proxies corporativos, así que la directiva puede ajustarse y los rangos de IP conocidos pueden etiquetarse como corporativos. Otras alertas de anomalías incluyen actividad desde un país poco frecuente, actividad desde direcciones IP anónimas, actividad desde direcciones IP sospechosas, descarga masiva, eliminación masiva, actividad de ransomware (muchas cargas de archivos con extensiones inusuales), uso compartido de archivos inusual y reglas sospechosas de manipulación de la bandeja de entrada, como reenviar correo a una dirección externa o mover mensajes a carpetas ocultas.

Estas alertas alimentan los incidentes de Defender XDR. Investigar significa revisar el registro de actividad del usuario, los detalles del inicio de sesión, la reputación de la dirección IP y lo que pasó después de la anomalía: nuevas reglas de bandeja de entrada, descargas, enlaces compartidos o consentimientos de aplicaciones. Las opciones de respuesta incluyen suspender al usuario, exigir que vuelva a iniciar sesión y confirmar al usuario como comprometido en ID Protection.

OAuth es el protocolo que permite que una aplicación acceda a datos en nombre de un usuario después de que el usuario (o un administrador) otorga su consentimiento. Los atacantes lo aprovechan con el phishing de consentimiento (consent phishing): envían un enlace que le pide al usuario otorgar a una aplicación maliciosa permisos como leer el correo. No se roba ninguna contraseña, así que restablecer contraseñas no elimina el acceso. Defender for Cloud Apps, con app governance, muestra las aplicaciones OAuth con su nivel de permisos, su editor (publisher), cuántos usuarios dieron su consentimiento y su uso en la comunidad. Las aplicaciones con privilegios altos, editores no verificados y pocos usuarios son sospechosas.

Para responder, puedes prohibir (ban) la aplicación en Defender for Cloud Apps, lo que revoca sus permisos e impide consentimientos futuros, o revocar el consentimiento y eliminar la entidad de servicio (service principal) o la aplicación empresarial en Microsoft Entra ID. Revisa también a qué accedió la aplicación usando los registros de auditoría. Para evitar que se repita, restringe el consentimiento de usuarios en Entra ID para que los usuarios solo puedan dar su consentimiento a aplicaciones de editores verificados con permisos de bajo riesgo, y usa el flujo de consentimiento de administrador (admin consent workflow) para todo lo demás.

Las directivas que creas tú, como las directivas de actividad y las directivas de aplicaciones OAuth, complementan las detecciones de anomalías integradas.

Términos clave

Impossible travel (viaje imposible)
Una alerta de anomalía para inicios de sesión desde ubicaciones distantes en un tiempo que hace imposible el viaje físico.
OAuth app consent (consentimiento de aplicación OAuth)
El permiso que un usuario o administrador otorga a una aplicación para acceder a datos en su nombre.
Consent phishing (phishing de consentimiento)
Engañar a los usuarios para que otorguen permisos OAuth a una aplicación maliciosa, eludiendo los controles de contraseña.
Ban app (prohibir la aplicación)
Una acción de Defender for Cloud Apps que revoca los permisos de una aplicación OAuth y bloquea nuevos consentimientos.
Ejemplo real

Defender for Cloud Apps muestra que 12 usuarios dieron su consentimiento a una aplicación no verificada que solicita acceso completo al buzón, y uno de ellos tiene una regla sospechosa de reenvío en la bandeja de entrada. El analista prohíbe la aplicación, elimina la aplicación empresarial en Entra ID, borra la regla de reenvío y cambia la configuración de consentimiento de usuarios del tenant para permitir solo editores verificados.

Consejo para el examen: Restablecer una contraseña no elimina una concesión OAuth maliciosa. La respuesta es revocar el consentimiento o prohibir la aplicación, y luego restringir el consentimiento de usuarios.

Comprueba lo que sabes

¿Cuál es una causa común de falsos positivos en el viaje imposible?

Las VPN o los proxies corporativos que hacen que los inicios de sesión parezcan venir de ubicaciones distantes.

¿Por qué un restablecimiento de contraseña no detiene una aplicación OAuth maliciosa?

La aplicación tiene sus propios tokens otorgados por consentimiento, que siguen siendo válidos hasta que se revoque el consentimiento.

¿Cómo puedes reducir el phishing de consentimiento en el futuro?

Restringe el consentimiento de usuarios a editores verificados y permisos de bajo riesgo, y exige el consentimiento de administrador para lo demás.
