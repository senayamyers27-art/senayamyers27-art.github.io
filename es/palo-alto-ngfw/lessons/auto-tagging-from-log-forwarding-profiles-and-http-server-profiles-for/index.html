Auto-tagging desde log forwarding profiles y HTTP server profiles para webhooks y sistemas de tickets

El auto-tagging cierra el ciclo entre la detección y la aplicación de políticas. Cuando el firewall registra un evento importante, como una amenaza crítica desde un host interno, puede etiquetar la dirección IP del host. Luego, un dynamic address group que coincide con la etiqueta coloca al host en una regla de cuarentena, todo en cuestión de segundos y sin commit.

El etiquetado se configura en un log forwarding profile (Objects > Log Forwarding). Cada entrada de la match list tiene un tipo de log y un filtro, por ejemplo el threat log con severidad critical. En Built-in Actions agregas una acción de tipo Tagging: eliges el objetivo (dirección de origen, dirección de destino y, para algunos tipos de log, el usuario o la dirección XFF), la acción (agregar o quitar etiqueta), dónde se registra la etiqueta (el User-ID local, Panorama o un dispositivo remoto mediante un HTTP server profile), la etiqueta en sí y un timeout opcional tras el cual la etiqueta vence. Después adjuntas el log forwarding profile a las reglas de seguridad que deben dispararlo.

El lado de la aplicación es una política normal. Crea un DAG con una expresión de coincidencia sobre la etiqueta, como 'quarantine', y coloca una regla cerca de la parte superior de la rulebase que deniegue o restrinja el tráfico desde ese DAG, quizás permitiendo solo el acceso a los servidores de remediación. Como la membresía del DAG se actualiza dinámicamente, los hosts etiquetados quedan restringidos de inmediato. Un timeout permite que los hosts regresen automáticamente; sin él, un administrador quita la etiqueta después de la limpieza. Etiquetar usuarios en dynamic user groups funciona igual cuando la identidad del usuario importa más que la IP.

Los HTTP server profiles extienden esto a otros sistemas. En Device > Server Profiles > HTTP defines uno o más servidores (dirección, protocolo, puerto, método) y, por tipo de log, un formato de URI, encabezados, parámetros y una plantilla de carga útil construida con campos del log. Existen formatos de carga útil predefinidos para algunos servicios comunes, y puedes escribir tu propio JSON. Cuando un log forwarding profile envía un log coincidente al perfil HTTP, el firewall llama al webhook. Eso puede abrir un ticket en una herramienta de gestión de servicios de TI, publicar en un canal de chat o disparar un playbook de orquestación que investigue más a fondo. Usa HTTPS y encabezados de autenticación para que el lado receptor pueda confiar en la solicitud.

Al combinarlo todo, una sola amenaza crítica puede etiquetar al host para ponerlo en cuarentena, abrir un ticket de incidente y notificar al analista de guardia. Este es el tipo de integración que el examen espera que sepas diseñar. Recuerda las piezas: log forwarding profile con un filtro, acción integrada de tagging, DAG en una regla de seguridad y HTTP server profile para la notificación externa. Revisa los IP-Tag logs para confirmar que las etiquetas se registraron y se quitaron como se esperaba.

Ten cuidado con los filtros. Etiquetar con eventos de baja severidad o propensos a falsos positivos puede poner en cuarentena máquinas sanas, así que empieza solo con alertas y ajusta a medida que ganes confianza.

Términos clave

Auto-tagging (etiquetado automático)
Una acción integrada del reenvío de logs que agrega o quita etiquetas en IP o usuarios cuando se genera un log coincidente.
Built-in action (acción integrada)
Una acción dentro de una entrada de un log forwarding profile, como el etiquetado, que se ejecuta cuando un log coincide.
Webhook
Una solicitud HTTP enviada a otro sistema cuando ocurre un evento, usada aquí mediante un HTTP server profile.
IP-Tag log
El log que registra las etiquetas asignadas a direcciones IP y las que se les quitan.
Ejemplo real

Una laptop dispara una firma de spyware crítica. El log forwarding profile etiqueta su IP como 'quarantine' con un timeout de 24 horas y envía el threat log a un HTTP server profile que abre un ticket. Una regla en la parte superior le niega al DAG Quarantine todo excepto el servidor de remediación, así que la laptop queda aislada incluso antes de que un analista la revise.

Consejo para el examen: La cadena es: filtro del log forwarding profile, luego la acción de tagging, luego el DAG que coincide con la etiqueta y luego una regla de seguridad que usa el DAG. Los HTTP server profiles envían logs a webhooks para tickets y chat.

Comprueba lo que sabes

¿Dónde configuras que se agregue una etiqueta cuando se registra una amenaza crítica?

En una entrada de un log forwarding profile filtrada por severidad, usando una acción integrada de tagging, adjunto a las reglas de seguridad.

¿Cómo queda bloqueada una IP etiquetada?

Un dynamic address group que coincide con la etiqueta se usa en una regla de denegación o restricción, y la IP se une al grupo automáticamente.

¿Qué define el formato de la carga útil enviada a un webhook de tickets?

El formato de carga útil por tipo de log y los encabezados del HTTP server profile.
