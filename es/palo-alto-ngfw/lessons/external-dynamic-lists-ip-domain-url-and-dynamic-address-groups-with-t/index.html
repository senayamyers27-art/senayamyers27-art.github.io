External dynamic lists (IP, dominio, URL) y dynamic address groups con etiquetas

La política estática es lenta para cambiar: cada nueva dirección maliciosa o cada servidor nuevo implica una edición y un commit. Las external dynamic lists y los dynamic address groups permiten que la política se adapte automáticamente, y ambos son fundamentales para la automatización en PAN-OS.

Una external dynamic list (EDL) es un archivo de texto alojado en un servidor web, con una entrada por línea, que el firewall descarga según una programación. La creas en Objects > External Dynamic Lists con un tipo, una URL de origen, un certificate profile opcional para la validación HTTPS, credenciales si son necesarias y un intervalo de verificación (cada cinco minutos, cada hora, diario, semanal o mensual). Los cambios en el archivo surten efecto en la siguiente actualización sin necesidad de commit. Puedes forzar una actualización desde la CLI con request system external-list refresh y ver las entradas con request system external-list show.

El tipo decide dónde se puede usar la lista. Una lista IP Address contiene direcciones, rangos y subredes, y se usa como origen o destino en reglas de seguridad, NAT, PBF y descifrado. Una lista Domain se usa en los perfiles anti-spyware, dentro de las DNS policies, para que el firewall pueda alertar, bloquear o aplicar sinkhole a las consultas DNS de los dominios listados. Una lista URL se usa como categoría de URL personalizada en los perfiles de URL filtering o como coincidencia de categoría de URL en las reglas de seguridad y descifrado. Palo Alto también proporciona listas IP predefinidas, como las direcciones IP maliciosas conocidas y los proveedores de bulletproof hosting, mantenidas mediante las suscripciones de contenido de amenazas, y listas URL predefinidas. Cada plataforma tiene límites de capacidad de entradas, que varían según el modelo.

Un dynamic address group (DAG) es un address group cuya membresía se define mediante una expresión de coincidencia sobre etiquetas (tags), como 'web' and 'prod', en lugar de una lista fija. Cualquier dirección IP registrada con etiquetas coincidentes se vuelve miembro automáticamente. Las etiquetas pueden provenir de objetos de dirección, de la XML API (llamadas register y unregister desde scripts o herramientas de orquestación), de fuentes de información de VM que leen metadatos de la nube o del hipervisor, del auto-tagging en el reenvío de logs, y de Panorama o de los User-ID agents. Las actualizaciones de membresía ocurren en tiempo de ejecución sin commit, y por eso los DAG se usan para cuarentenas y para cargas de trabajo en la nube que aparecen y desaparecen.

Los dynamic user groups son el equivalente para usuarios: grupos cuyos miembros son usuarios que llevan ciertas etiquetas, útiles para poner en cuarentena una cuenta comprometida en lugar de una IP.

Usa EDL cuando la fuente de verdad es una lista mantenida en otro lugar, como un feed de amenazas o un inventario interno de TI. Usa DAG cuando la membresía proviene de eventos o metadatos. Considera siempre qué pasa si el servidor de la lista no está disponible (el firewall conserva la última lista obtenida con éxito) y protege el origen de la lista, porque quien lo controla controla tu política.

Términos clave

External dynamic list (EDL, lista dinámica externa)
Una lista de IP, dominios o URL alojada en la web que el firewall obtiene periódicamente y usa en la política sin commit.
Dynamic address group (DAG, grupo de direcciones dinámico)
Un address group cuyos miembros son direcciones IP registradas con etiquetas que coinciden con su filtro.
DNS sinkhole
Una acción anti-spyware que responde las consultas de dominios maliciosos con una dirección controlada para poder encontrar los hosts infectados.
Dynamic user group (grupo de usuarios dinámico)
Un grupo cuya membresía son usuarios con etiquetas coincidentes, usado para la cuarentena basada en usuarios.
Ejemplo real

Una plataforma de inteligencia de amenazas publica una lista de dominios de comando y control. La agregas como una EDL de tipo Domain, haces referencia a ella en la DNS policy del perfil anti-spyware con la acción sinkhole, y luego buscas en el Traffic log los hosts internos que consultan la dirección del sinkhole para encontrar las máquinas infectadas.

Consejo para el examen: Las listas IP van en las reglas, las listas de dominios van en las DNS policies de anti-spyware, las listas URL van en URL filtering o en las categorías de URL de las reglas. Los cambios en EDL y DAG surten efecto sin commit.

Comprueba lo que sabes

¿Dónde se usa una EDL de tipo Domain?

En las DNS policies de un perfil anti-spyware, para las acciones alert, block o sinkhole.

¿Cómo se convierte una IP en miembro de un dynamic address group?

Se registra con etiquetas que coinciden con la expresión de coincidencia del grupo, por ejemplo mediante la API, el monitoreo de VM o el auto-tagging.

¿Actualizar el archivo EDL en el servidor web requiere un commit en el firewall?

No, el firewall toma los cambios en su siguiente actualización programada.
