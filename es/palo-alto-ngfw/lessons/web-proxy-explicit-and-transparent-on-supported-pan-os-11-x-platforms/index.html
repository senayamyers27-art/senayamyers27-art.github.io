Web proxy (explícito y transparente) en plataformas compatibles con PAN-OS 11.x

Muchas organizaciones han usado durante mucho tiempo web proxies separados, de modo que los navegadores envían las solicitudes web a un proxy que las inspecciona y las reenvía. PAN-OS 11.x agregó una función de web proxy en las plataformas compatibles para que el propio firewall pueda cumplir ese rol, ayudando a los clientes a consolidar o migrar desde appliances de proxy heredados. La compatibilidad depende del modelo de hardware o de VM y de la versión de PAN-OS, así que revisa la información de compatibilidad antes de planificar.

Un proxy explícito es uno que los clientes conocen. Los navegadores o sistemas operativos se configuran, manualmente o con un archivo de configuración automática de proxy (PAC), para enviar las solicitudes web a la dirección IP y al puerto de escucha del proxy. El cliente se conecta al proxy y le pide, usando HTTP CONNECT para HTTPS, que llegue al destino. Como el cliente habla con el proxy a sabiendas, el proxy puede exigirle autenticación, normalmente con Kerberos para las máquinas del dominio o con SAML a través de un proveedor de identidad. El proxy explícito es útil cuando quieres que cada solicitud web se atribuya a un usuario, y cuando el firewall no está de otro modo en el camino del tráfico web.

Un proxy transparente intercepta el tráfico web sin configuración en el cliente. El firewall está en el camino del tráfico, y el tráfico destinado a puertos web se redirige hacia la función de proxy. Los usuarios no saben que existe un proxy, lo que evita distribuir archivos PAC, pero depende de que el tráfico se enrute a través del firewall y de otros métodos, como User-ID, para identificar a los usuarios.

La configuración se hace en la configuración del web proxy (en Network > Proxy en las versiones compatibles). Espera tener que proporcionar una interfaz loopback para el proxy, un objeto DNS proxy que el proxy usa para la resolución de nombres, el puerto de escucha para el modo explícito, el método de autenticación y las zonas para el tráfico del proxy. La política de seguridad sigue aplicándose: las reglas deben permitir el tráfico que pasa por el proxy, y el filtrado de URL y los perfiles de amenazas hacen su trabajo normal. Para inspeccionar el contenido HTTPS en lugar de solo ver el dominio en la solicitud CONNECT, sigues necesitando descifrado.

¿Cómo se relaciona esto con el firewall normal? Un firewall de nueva generación regular inspecciona el tráfico en línea sin actuar como extremo de proxy; la función de web proxy es un modo adicional de manejar el tráfico web que conserva los flujos de trabajo que dependen de un proxy, como los archivos PAC y la autenticación en el proxy, en torno a los cuales se construyeron algunas aplicaciones y políticas. Elige explícito cuando los clientes deban dirigirse al proxy y autenticarse ahí; elige transparente cuando no puedas modificar la configuración de los clientes.

Al diagnosticar problemas, verifica si los clientes realmente usan el archivo PAC (explícito), si funciona la resolución DNS a través del DNS proxy y si la autenticación tuvo éxito; luego revisa los logs de Traffic y URL Filtering de las sesiones que pasan por el proxy.

Términos clave

Explicit proxy (proxy explícito)
Un proxy que los clientes están configurados para usar, directamente o mediante un archivo PAC, enviando las solicitudes a su IP y puerto.
Transparent proxy (proxy transparente)
Un proxy que intercepta el tráfico web en el camino sin ninguna configuración en el cliente.
PAC file (archivo PAC)
Un script de configuración automática de proxy que indica a los navegadores qué proxy usar para cada destino.
HTTP CONNECT
El método que usa un cliente de proxy explícito para pedirle al proxy que abra un túnel hacia un destino HTTPS.
Ejemplo real

Una empresa está retirando un appliance de proxy antiguo al que los navegadores llegan mediante un archivo PAC con autenticación Kerberos. En un firewall compatible con PAN-OS 11.x, el equipo configura un web proxy explícito con Kerberos, actualiza el archivo PAC para que apunte a la dirección del proxy del firewall y mantiene funcionando el filtrado de URL basado en usuarios sin cambiar la configuración de los navegadores.

Consejo para el examen: Explícito significa que los clientes están configurados (archivo PAC o ajustes) y se les puede exigir autenticación; transparente significa sin cambios en los clientes. La función depende de la plataforma y la versión, y la inspección del contenido HTTPS sigue necesitando descifrado.

Comprueba lo que sabes

¿Qué distingue a un proxy explícito de uno transparente?

Los clientes están configurados para enviar solicitudes a un proxy explícito; un proxy transparente intercepta el tráfico sin configuración en el cliente.

¿Qué modo de proxy admite de forma natural pedir a los usuarios que se autentiquen ante el proxy?

El proxy explícito, comúnmente con Kerberos o SAML.

¿Usar el web proxy elimina la necesidad de descifrado para inspeccionar el contenido HTTPS?

No. Sin descifrado, el firewall solo ve el dominio solicitado, no el contenido cifrado.
