XML API de PAN-OS (keygen, config, op, commit) y REST API; admin role profiles solo para API

Todo lo que haces en la interfaz web es, en última instancia, una llamada a la API, y PAN-OS expone dos API para la automatización. La XML API es la más antigua y completa, y cubre la configuración, los comandos operativos, los commits, los logs, los reportes, User-ID y la transferencia de archivos. La REST API ofrece acceso basado en JSON a políticas, objetos y configuración de red y del dispositivo. Ambas funcionan sobre HTTPS en la interfaz de administración (o en una interfaz de datos con administración habilitada).

La XML API se organiza por tipo de solicitud en el parámetro type de las solicitudes al endpoint /api/. Primero obtienes una API key con type=keygen, proporcionando un nombre de usuario y una contraseña (preferiblemente en el cuerpo de un POST en lugar de en la URL). Luego la clave se envía en las solicitudes posteriores, idealmente en el encabezado X-PAN-KEY. Usar una cuenta de servicio dedicada significa que la clave solo tiene los derechos de esa cuenta.

Las solicitudes de configuración usan type=config con un action y un xpath que apunta a un nodo del árbol de configuración. Las acciones comunes son get (leer la configuración candidate), show (leer la configuración running), set (agregar o combinar), edit (reemplazar), delete, rename, clone y move. Las solicitudes operativas usan type=op con un parámetro cmd que contiene el comando de CLI expresado en XML, como la forma XML de show system info. Un truco práctico es ejecutar debug cli on en la CLI, que imprime el equivalente XML de los comandos que escribes. Los commits usan type=commit, opcionalmente parciales, y devuelven un job ID que consultas periódicamente con una solicitud op para verificar si terminó. Otros tipos incluyen log, report, export, import, user-id y version.

La REST API usa URL de recursos con una versión en la ruta, como /restapi/v11.0/Objects/Addresses, con parámetros de ubicación (por ejemplo vsys y name) y los métodos HTTP estándar: GET para leer, POST para crear, PUT para editar y DELETE para eliminar. Es fácil para los desarrolladores que conocen JSON, pero no lo cubre todo; operaciones como el commit se hacen mediante la XML API. Usa la documentación integrada en el API browser del firewall, accesible desde la dirección de administración, para explorar ambas.

La seguridad en el uso de la API proviene de un admin role profile solo para API. Crea un admin role profile con todas las áreas de la Web UI deshabilitadas, la Command Line configurada en none y solo los tipos de XML API y los recursos de REST API que necesita el script habilitados. Para un exportador de logs de solo lectura, habilita solo XML API Log. Para un actualizador de objetos de dirección, habilita los permisos de configuración y commit y nada más. Asigna ese perfil a una cuenta de administrador dedicada, genera la clave y guárdala en un gestor de secretos. También puedes definir un tiempo de vida de las API keys en la configuración del dispositivo para que las claves venzan, y usar Expire All API Keys para revocar las claves existentes; generar una clave nueva no invalida por sí mismo las anteriores.

Prueba siempre la automatización contra un firewall de laboratorio, maneja los errores en las respuestas XML (status='error') y recuerda que los cambios de configuración quedan en la candidate hasta que se hace commit.

Términos clave

keygen
El tipo de solicitud de la XML API que devuelve una API key para un nombre de usuario y una contraseña.
XPath
La sintaxis de rutas que usa la XML API para direccionar un nodo del árbol de configuración.
type=op
El tipo de solicitud de la XML API para ejecutar comandos operativos (no de configuración) expresados en XML.
API-only role (rol solo para API)
Un admin role profile con la interfaz web y la CLI deshabilitadas y solo los permisos de API necesarios habilitados.
Ejemplo real

La herramienta de orquestación de un equipo de seguridad debe agregar las IP de atacantes a un address group. Creas un rol de administrador con la interfaz web y la CLI desactivadas y solo la configuración y el commit de la XML API habilitados, generas una clave para esa cuenta, y la herramienta usa type=config action=set con un xpath hacia el objeto de dirección, luego type=commit, consultando periódicamente el job ID.

Consejo para el examen: Conoce los tipos de solicitud XML: keygen, config (con acciones como get, show, set, edit, delete), op y commit. REST usa URL versionadas y JSON; el commit es una función de la XML API. Las cuentas solo para API se crean con admin role profiles, no con dynamic roles.

Comprueba lo que sabes

¿Cuál es la diferencia entre set y edit en la XML API?

set agrega o combina en el xpath, mientras que edit reemplaza el nodo del xpath con el elemento proporcionado.

¿Cómo puedes encontrar el XML de un comando operativo de CLI?

Ejecuta debug cli on en la CLI y luego el comando; se imprime el equivalente XML.

¿Cómo te aseguras de que una API key filtrada no pueda cambiar la configuración?

Generándola para una cuenta cuyo admin role profile solo permita los tipos de API de solo lectura necesarios.
