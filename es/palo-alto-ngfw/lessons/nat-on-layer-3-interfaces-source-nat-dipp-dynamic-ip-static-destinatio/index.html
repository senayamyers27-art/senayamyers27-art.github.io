NAT en interfaces Layer 3: source NAT (DIPP, dynamic IP, static), destination NAT, U-turn NAT, IP pre-NAT vs zona post-NAT en las reglas de seguridad

Network Address Translation (NAT) reescribe direcciones a medida que el tráfico atraviesa el firewall. PAN-OS maneja NAT en su propia rulebase (Policies > NAT), separada de las reglas de seguridad, y la evalúa de arriba hacia abajo, ganando la primera coincidencia. Para usar NAT necesitas interfaces Layer 3 (virtual wire también admite algo de NAT, pero el examen se enfoca en Layer 3).

Source NAT cambia la dirección de origen, normalmente para que los hosts privados puedan llegar a Internet. Dynamic IP and Port (DIPP) es la opción de todos los días: muchos hosts internos comparten una dirección pública (a menudo la dirección de la interfaz de salida), y el firewall los distingue traduciendo los puertos de origen. Dynamic IP traduce cada host uno a uno a la siguiente dirección libre de un pool sin cambiar los puertos; cuando el pool se agota, las sesiones nuevas fallan a menos que configures un respaldo (fallback) a DIPP. Static IP traduce una dirección fija a otra dirección fija, y la opción Bi-directional también crea la traducción entrante correspondiente.

Destination NAT cambia la dirección de destino, normalmente para publicar un servidor interno. Una regla que coincide con la IP pública del servidor la traduce a la dirección privada, opcionalmente con traducción de puertos (443 público a 8443 privado). La traducción de destino también puede apuntar a un FQDN o distribuirse entre varias direcciones.

El concepto más evaluado es cómo se alinean las zonas y las direcciones. Cuando llega un paquete, el firewall determina la zona de origen a partir de la interfaz de ingreso, luego hace una búsqueda de ruta sobre el destino original (pre-NAT) para encontrar la zona de destino, y compara la política NAT con esos valores. Después se verifica la política de seguridad usando las direcciones IP pre-NAT y la zona post-NAT. Para un servidor web entrante: la regla NAT va de Untrust a Untrust (la IP pública se enruta hacia la interfaz Untrust), con destino la IP pública, traducida a 10.1.1.10. La regla de seguridad va de Untrust a DMZ (zona post-NAT), con destino la IP pública (dirección pre-NAT).

U-turn NAT resuelve el caso de usuarios internos que llegan a un servidor interno por su IP pública. Con solo una traducción de destino, y con el servidor en la misma subred que los usuarios, la solicitud va al firewall, se traduce hacia el servidor, y el servidor responde directamente al usuario, saltándose el firewall y rompiendo la sesión. La solución es una regla NAT de Trust a Untrust (la búsqueda de ruta de la IP pública apunta a Untrust), con destino la IP pública, traducida al servidor, más una traducción de origen a la interfaz del firewall para que las respuestas regresen a través del firewall. Un split DNS que entregue la dirección privada a los clientes internos suele ser una alternativa más limpia.

Verifica con las columnas de NAT del Traffic log, o desde la CLI con test nat-policy-match y test security-policy-match, y con show running nat-policy.

Términos clave

DIPP
Dynamic IP and Port source NAT: muchos hosts comparten una o pocas direcciones con traducción de puertos de origen.
Dynamic IP NAT
Source NAT que asigna cada host uno a uno a una dirección libre del pool sin traducción de puertos; el pool puede agotarse.
U-turn NAT (NAT en U)
NAT que permite a los clientes internos llegar a un servidor interno por su IP pública, traduciendo destino y origen para que el tráfico regrese a través del firewall.
Post-NAT zone (zona post-NAT)
La zona donde realmente reside el destino traducido, usada como zona de destino en las reglas de seguridad.
Ejemplo real

Un servidor web en 10.10.10.5 en la DMZ se publica como 203.0.113.10. La regla NAT coincide de Untrust a Untrust, destino 203.0.113.10, traducido a 10.10.10.5. La regla de seguridad permite de Untrust a DMZ, destino 203.0.113.10, aplicaciones web-browsing y ssl. Si se escribiera con 10.10.10.5 como destino, la regla de seguridad nunca coincidiría.

Consejo para el examen: Las reglas de seguridad usan direcciones pre-NAT y zona post-NAT. Las reglas NAT usan direcciones pre-NAT y la zona que se obtiene al enrutar el destino pre-NAT. Casi todas las preguntas de NAT del examen giran en torno a esto.

Comprueba lo que sabes

¿Qué tipo de source NAT puede quedarse sin direcciones?

Dynamic IP, porque asigna los hosts uno a uno a direcciones del pool sin traducción de puertos.

En la regla de seguridad para un destination NAT entrante, ¿qué dirección y zona de destino usas?

La dirección pública (pre-NAT) y la zona DMZ (post-NAT).

¿Por qué U-turn NAT también traduce el origen?

Para que el servidor responda al firewall en lugar de directamente al cliente interno, manteniendo la sesión simétrica.
