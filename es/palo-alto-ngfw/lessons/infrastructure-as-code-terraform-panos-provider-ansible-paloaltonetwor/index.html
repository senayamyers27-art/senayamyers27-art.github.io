Infraestructura como código: Terraform panos provider, colección Ansible paloaltonetworks.panos, SDK pan-os-python

Infraestructura como código (IaC, infrastructure as code) significa describir la configuración del firewall en archivos de texto guardados en control de versiones y luego dejar que una herramienta la aplique. Los beneficios son la repetibilidad, la revisión de los cambios por pares, la facilidad para regresar a una versión conocida y la consistencia entre muchos firewalls. Las tres herramientas de este tema se comunican por debajo con la XML API de PAN-OS, así que todo lo visto en la lección de la API (claves, roles solo para API, configuración candidate versus running) sigue aplicando.

Terraform, de HashiCorp, es declarativo: escribes el estado final deseado en archivos HCL y Terraform determina qué crear, cambiar o eliminar. El provider panos de Palo Alto Networks proporciona recursos para objetos, políticas, configuración de red y más, para firewalls y Panorama. Terraform registra lo que administra en un archivo de estado (state file), y terraform plan muestra los cambios antes de que terraform apply los realice. Terraform es excelente para construir configuración, por ejemplo para crear un conjunto de objetos de dirección y reglas junto con despliegues de VM-Series en la nube. El commit se maneja por separado de los cambios de recursos, y la forma depende de la versión del provider, así que revisa su documentación; una configuración enviada no está activa hasta que se hace commit. Protege el archivo de estado, porque puede contener valores sensibles.

Ansible, de Red Hat, usa playbooks YAML de tareas que se ejecutan en orden. La colección paloaltonetworks.panos, instalada desde Ansible Galaxy, proporciona módulos para objetos de dirección, reglas de seguridad, NAT, interfaces, commits y comandos operativos. Cada módulo recibe un diccionario provider con la dirección del firewall y las credenciales o la API key. Los módulos están diseñados para ser idempotentes: ejecutar un playbook dos veces no debería cambiar nada la segunda vez. Ansible es muy adecuado para flujos de trabajo procedimentales, como incorporar un firewall, ejecutar una secuencia de actualización o recopilar información.

- name: Ensure web server object exists
  paloaltonetworks.panos.panos_address_object:
    provider: '{{ provider }}'
    name: web-srv
    value: 10.1.1.10
    description: DMZ web server

- name: Commit
  paloaltonetworks.panos.panos_commit_firewall:
    provider: '{{ provider }}'

pan-os-python es el SDK de Python de Palo Alto (se importa como panos). Modela la configuración como un árbol de objetos: un objeto Firewall o Panorama en la cima, con hijos como objetos de dirección, rulebases y reglas. Construyes o actualizas objetos en Python y luego llamas a métodos como create(), apply(), delete() y commit(). Es la opción más flexible cuando necesitas lógica personalizada, y es lo que usa internamente la colección de Ansible.

from panos.firewall import Firewall
from panos.objects import AddressObject

fw = Firewall('192.0.2.10', api_key=API_KEY)
obj = AddressObject('web-srv', '10.1.1.10')
fw.add(obj)
obj.create()   # va a la configuración candidate
fw.commit()    # la convierte en running

Cómo elegir entre ellas: Terraform para construcciones declarativas basadas en estado, especialmente junto con infraestructura en la nube; Ansible para flujos de trabajo ordenados y equipos que ya lo usan; pan-os-python para scripts e integraciones personalizados. Elijas lo que elijas, usa una cuenta dedicada solo para API y mantén los secretos fuera del código.

Términos clave

Declarative (declarativo)
Describir el estado final deseado y dejar que la herramienta calcule los cambios, como hace Terraform.
Idempotent (idempotente)
Producir el mismo resultado sin importar cuántas veces se ejecute una operación, un objetivo de diseño de los módulos de Ansible.
Terraform state (estado de Terraform)
El archivo donde Terraform registra los recursos que administra y sus valores actuales.
pan-os-python
El SDK de Python de Palo Alto que modela la configuración de firewalls y Panorama como un árbol de objetos.
Ejemplo real

Un equipo de nube despliega firewalls VM-Series con Terraform. Agregan el provider panos al mismo repositorio para que los objetos de dirección y las reglas de seguridad de cada aplicación nueva se definan junto a su infraestructura, se revisen en un pull request, se planifiquen, se apliquen y luego se confirmen con commit a través de su pipeline.

Consejo para el examen: Terraform es declarativo y basado en estado, Ansible ejecuta tareas ordenadas e idempotentes, y pan-os-python es el SDK de Python sobre el que se construye la colección de Ansible. Todos cambian la configuración candidate, así que sigue siendo necesario un commit.
