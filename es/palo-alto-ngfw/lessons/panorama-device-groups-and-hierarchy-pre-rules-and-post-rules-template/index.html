Panorama: device groups y jerarquía, pre-rules y post-rules, templates, template stacks, template variables y overrides

Panorama es la plataforma de administración centralizada de Palo Alto para muchos firewalls. Divide la configuración en dos familias: device groups para las políticas y los objetos, y templates para la configuración de red y del dispositivo. Tener esto claro es esencial para el examen.

Un device group contiene firewalls que comparten política, como todos los firewalls de sucursal. Contiene reglas de seguridad, NAT, descifrado y otras, además de objetos de dirección, de servicio y de perfil. Los device groups forman una jerarquía bajo la ubicación Shared: Shared en la cima, luego los device groups padre y después los hijos, con varios niveles de profundidad. Los objetos y las reglas definidos más arriba son heredados por los grupos inferiores, así que puedes definir una sola vez las reglas para toda la empresa y más abajo las reglas específicas de cada región. Un hijo puede sobrescribir el valor de un objeto heredado cuando está permitido.

Las reglas de Panorama se colocan antes o después de las reglas locales propias del firewall. Las pre-rules se evalúan primero y no pueden sobrescribirse localmente; son ideales para bloqueos a nivel de toda la empresa. Las post-rules vienen después de las reglas locales y justo encima de las reglas predeterminadas; son adecuadas para reglas de registro generales o de limpieza. El orden completo de evaluación en un firewall administrado es: pre-rules de Shared, pre-rules de los device groups ancestros, pre-rules del device group del firewall, reglas locales del firewall, post-rules del device group, post-rules de los ancestros, post-rules de Shared y, por último, las reglas predeterminadas intrazone e interzone. Los administradores locales pueden ver las reglas de Panorama, pero no editarlas.

Los templates configuran las pestañas Network y Device: interfaces, zonas, routers, VPN, HA, server profiles, configuración de logs, etc. Un template stack combina varios templates, por ejemplo un template global para DNS y NTP, un template regional para los servidores syslog y un template específico del modelo para las interfaces. Los templates de un stack tienen un orden, y cuando dos templates configuran el mismo parámetro, gana el que está más arriba en el stack. Asignas los firewalls al stack, no directamente a templates individuales. El propio stack también puede contener configuración que sobrescribe a sus templates miembros.

Las template variables hacen que los templates compartidos funcionen para muchos firewalls cuyos valores difieren. Escribes una variable como $mgmt-dns o $branch-lan-ip en el template, y luego le das a cada firewall su propio valor en la configuración de variables por dispositivo del template stack. Así, un template puede servir a cien sucursales, cada una con sus propias direcciones IP.

Los overrides permiten desviaciones locales. Un administrador del firewall puede sobrescribir localmente un valor enviado por un template, lo que se muestra con un ícono de override, a menos que Panorama se haya configurado para impedirlo. Los valores locales sobrescritos prevalecen sobre el template hasta que alguien revierte el override. El exceso de overrides hace que la flota sea inconsistente, así que usa variables donde los valores difieren legítimamente.

Términos clave

Device group (grupo de dispositivos)
Un contenedor de Panorama de firewalls que comparten políticas y objetos, organizado en una jerarquía bajo Shared.
Pre-rules / post-rules
Reglas de Panorama que se evalúan antes o después de las reglas locales de un firewall.
Template stack (pila de templates)
Una combinación ordenada de templates asignada a firewalls; los templates más altos ganan cuando hay conflicto de parámetros.
Template variable (variable de template)
Un marcador como $dns-primary en un template cuyo valor se define por firewall.
Ejemplo real

Una cadena minorista tiene 300 tiendas con diseños idénticos pero subredes diferentes. El ingeniero construye un template de tienda con variables para la IP de la LAN y el gateway, lo apila bajo un template global para DNS, NTP y registro, y coloca pre-rules en Shared que bloquean categorías de alto riesgo. Cada tienda recibe sus propios valores de variables y la misma política.

Consejo para el examen: Device groups = políticas y objetos; templates = pestañas Network y Device. Las pre-rules van antes de las reglas locales y no pueden sobrescribirse localmente. En un stack, gana el template más alto.

Comprueba lo que sabes

¿Dónde configurarías las interfaces y zonas de 50 firewalls en Panorama?

En un template, asignado a los firewalls a través de un template stack.

¿Dónde queda una regla local del firewall respecto de las reglas de Panorama?

Después de todas las pre-rules y antes de todas las post-rules.

¿Cómo usas un solo template para muchos firewalls con IP diferentes?

Usa template variables y define los valores de cada firewall en el template stack.
