IPsec sitio a sitio: IKE gateway, perfiles criptográficos IKE e IPsec, interfaces tunnel, proxy IDs, tunnel monitoring

Los firewalls de Palo Alto construyen VPN sitio a sitio basadas en rutas. En lugar de una política que diga 'cifra el tráfico de A a B', creas una interfaz tunnel y enrutas las redes remotas hacia ella. Todo lo que se enruta hacia el túnel se cifra con IPsec. Esto mantiene la lógica de la VPN en el enrutamiento, donde las rutas estáticas o los protocolos dinámicos pueden dirigir el tráfico.

Los bloques de construcción se configuran en orden. Primero, una interfaz tunnel (Network > Interfaces > Tunnel, por ejemplo tunnel.10) asignada a un virtual o logical router y a una zona de seguridad; una dirección IP en ella es opcional, pero es necesaria para el tunnel monitoring o el enrutamiento dinámico a través del túnel. Segundo, un IKE crypto profile para la fase 1: grupo Diffie-Hellman (DH), algoritmo de cifrado, algoritmo de autenticación (hash) y tiempo de vida de la clave. Tercero, un IPsec crypto profile para la fase 2: ESP (o AH), cifrado, autenticación, grupo DH para perfect forward secrecy (PFS) y tiempo de vida. Ambos peers deben coincidir en estos valores.

Luego viene el IKE gateway (Network > Network Profiles > IKE Gateways). Define la versión de IKE (IKEv1, IKEv2 o IKEv2 preferred), la interfaz e IP locales, la dirección del peer (IP estática, FQDN o dinámica), la autenticación por pre-shared key o certificado, la identificación local y del peer, el IKE crypto profile y opciones como NAT traversal y dead peer detection. Por último, el objeto IPsec tunnel (Network > IPsec Tunnels) une la interfaz tunnel, el IKE gateway y el IPsec crypto profile.

Los proxy IDs definen qué subredes locales y remotas cubre la asociación de seguridad de la fase 2. Un túnel de PAN-OS a PAN-OS no los necesita, porque ambos lados usan 0.0.0.0/0 de forma predeterminada. Pero cuando el peer es un dispositivo basado en políticas, debes ingresar proxy IDs que reflejen exactamente las redes locales y remotas configuradas en el peer, uno por cada par de subredes. Una discrepancia es la causa clásica de que la fase 1 se establezca mientras la fase 2 falla.

El tunnel monitoring envía pings a través del túnel hacia una IP de destino del otro lado, con origen en la IP de la interfaz tunnel. Un perfil de monitoreo elige qué sucede ante una falla: Wait Recover mantiene el túnel y espera, mientras que Fail Over permite que el enrutamiento o PBF muevan el tráfico a un camino de respaldo. Dead peer detection funciona a nivel de IKE; el tunnel monitoring demuestra que el tráfico realmente pasa.

No olvides la política y el enrutamiento. Necesitas una ruta para las subredes remotas que apunte a la interfaz tunnel y reglas de seguridad entre la zona interna y la zona de la VPN. Diagnostica con los indicadores de estado de la página IPsec Tunnels, el System log (mensajes de IKE) y comandos de CLI como show vpn ike-sa, show vpn ipsec-sa y test vpn ike-sa gateway <name>.

Términos clave

IKE gateway
El objeto que define el peer de la VPN, la interfaz local, la versión de IKE, la autenticación y el IKE crypto profile para la fase 1.
IPsec crypto profile (perfil criptográfico IPsec)
Configuración de la fase 2: ESP o AH, cifrado, autenticación, grupo DH para PFS y tiempo de vida.
Proxy ID
Un par de subredes local/remota que define una SA de fase 2, requerido cuando el peer usa una VPN basada en políticas.
Tunnel monitoring (monitoreo del túnel)
Pings a través del túnel hacia una IP remota que detectan un camino de datos roto y disparan wait-recover o fail-over.
Ejemplo real

Conectas un firewall PAN-OS al dispositivo VPN basado en políticas de un socio que protege 172.16.5.0/24 y 172.16.6.0/24. La fase 1 se establece, pero solo funciona una subred. El System log muestra una discrepancia en la propuesta de la fase 2. Al agregar dos proxy IDs, uno por cada subred remota emparejada con tu red local 10.1.0.0/16, ambas SA se levantan.

Consejo para el examen: Fase 1 arriba pero fase 2 abajo con un peer basado en políticas casi siempre significa proxy IDs. Recuerda que la interfaz tunnel necesita una zona y un router, y que el tráfico sigue necesitando reglas de seguridad y una ruta.

Comprueba lo que sabes

¿Qué objeto une la interfaz tunnel, el IKE gateway y el IPsec crypto profile?

La configuración de IPsec tunnel en Network > IPsec Tunnels.

¿Cuándo se requieren proxy IDs?

Cuando el peer es un dispositivo VPN basado en políticas; deben reflejar los pares de subredes locales y remotas del peer.

¿Qué requiere el tunnel monitoring en la interfaz tunnel?

Una dirección IP, que se usa como origen de los pings de monitoreo.
