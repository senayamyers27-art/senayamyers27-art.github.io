Sistemas virtuales: creación de vsys, interfaces/zonas/routers por vsys, shared gateway, tráfico entre vsys mediante zonas external

Los sistemas virtuales (vsys) dividen un firewall físico en varios firewalls lógicos, cada uno con sus propias interfaces, zonas, políticas, objetos y administradores. Los proveedores de servicios los usan para sus clientes (tenants), y las empresas los usan para separar unidades de negocio que necesitan políticas independientes. Todo firewall ejecuta vsys1 aunque nunca lo veas.

Para crear más, primero habilitas Multi Virtual System Capability en Device > Setup > Management; habilitarlo requiere un commit. Cuántos vsys puedes ejecutar depende de la plataforma, y muchas plataformas necesitan una licencia de sistemas virtuales para los vsys adicionales más allá de los incluidos. Es posible que los modelos más pequeños no admitan multi-vsys en absoluto. Después de eso, Device > Virtual Systems te permite agregar vsys2, vsys3, etc., definir límites de recursos como sesiones y reglas, y elegir qué interfaces, VLAN, virtual wires y routers puede usar el vsys.

Cada interfaz pertenece exactamente a un vsys, y cada zona pertenece a un vsys. Los virtual routers son más flexibles: un vsys puede tener su propio VR para una separación de enrutamiento completa, o varios vsys pueden compartir un VR. Los objetos y las políticas pueden definirse por vsys o en la ubicación Shared para que todos los reutilicen. Los administradores pueden restringirse a un vsys usando los roles de administrador de sistema virtual.

Un shared gateway es un sistema virtual especial que varios vsys usan para llegar a una red común, normalmente Internet, a través de las mismas interfaces. En lugar de darle a cada cliente su propia interfaz pública, el shared gateway es dueño de la interfaz externa. Los shared gateways tienen zonas, NAT y PBF, pero no tienen política de seguridad propia; la seguridad se aplica en cada vsys cliente. El tráfico entre un vsys y un shared gateway no necesita una zona external: el shared gateway aparece como una opción de zona para el vsys.

El tráfico entre dos vsys usa zonas external. En vsys1 creas una zona external que apunta a vsys2, y en vsys2 una zona external que apunta a vsys1. Una sesión desde la zona Trust de vsys1 hacia la zona DMZ de vsys2 se evalúa dos veces: vsys1 necesita una regla de Trust hacia su zona external, y vsys2 necesita una regla desde su zona external hacia DMZ. El enrutamiento también debe enviar el tráfico al otro vsys, ya sea mediante un VR compartido o una ruta cuyo siguiente salto sea el otro VR. Como cada vsys inspecciona la sesión, los logs aparecen en ambos.

Piensa en los vsys como firewalls separados conectados por un cable interno: cada lado necesita sus propias zonas, rutas y reglas de seguridad. Al diagnosticar multi-vsys, verifica siempre qué vsys estás viendo en el selector de vsys de la interfaz web y en comandos de CLI como set system setting target-vsys.

Términos clave

Virtual system (vsys, sistema virtual)
Un firewall lógico dentro de un firewall físico con sus propias interfaces, zonas, políticas y administradores.
Shared gateway (gateway compartido)
Un sistema virtual que permite a varios vsys compartir interfaces externas; admite NAT y PBF pero no tiene política de seguridad.
External zone (zona externa)
Un tipo de zona que apunta a otro vsys, usado para pasar tráfico entre sistemas virtuales.
Multi Virtual System Capability
La configuración del dispositivo que habilita la creación de vsys adicionales, sujeta al soporte de la plataforma y al licenciamiento.
Ejemplo real

Una universidad ejecuta vsys1 para la administración y vsys2 para las residencias estudiantiles. Ambos llegan a Internet a través de un shared gateway que es dueño de ethernet1/1 y realiza source NAT. Cuando la aplicación de registro académico en vsys1 debe llegar a un portal en vsys2, los administradores crean zonas external en ambos vsys y reglas correspondientes en ambos lados, y la sesión aparece en los logs de los dos vsys.

Consejo para el examen: El tráfico entre vsys necesita una zona external y una regla de seguridad en cada vsys. Los shared gateways hacen NAT y enrutamiento pero no tienen política de seguridad. Una interfaz y una zona siempre pertenecen exactamente a un vsys.

Comprueba lo que sabes

¿Cuántas reglas de seguridad necesita el tráfico de vsys1 a vsys2?

Dos: una en vsys1 hacia su zona external y otra en vsys2 desde su zona external.

¿Dónde se aplica la política de seguridad para el tráfico que usa un shared gateway?

En el vsys cliente, porque los shared gateways no tienen política de seguridad.

¿Qué debes habilitar antes de crear vsys2?

Multi Virtual System Capability en la configuración de administración del dispositivo, en una plataforma compatible y con licencia.
