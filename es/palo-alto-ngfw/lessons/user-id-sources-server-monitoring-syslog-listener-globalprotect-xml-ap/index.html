Fuentes de User-ID (server monitoring, syslog listener, GlobalProtect, XML API), group mapping y Cloud Identity Engine

User-ID asocia direcciones IP con nombres de usuario para que las políticas y los logs puedan referirse a personas y grupos en lugar de direcciones. El firewall no adivina: aprende las asociaciones de las fuentes que configuras. Luego aplica las reglas solo en las zonas donde User Identification está habilitado.

El server monitoring es la fuente más común. El User-ID agent integrado en PAN-OS del firewall, o el User-ID agent basado en Windows instalado en un servidor, lee los logs de eventos de seguridad de los controladores de dominio de Microsoft Active Directory, donde los eventos de inicio de sesión exitoso registran qué usuario inició sesión desde qué IP. También puede monitorear servidores Exchange y Novell eDirectory. La cuenta utilizada necesita derechos para leer los logs de eventos, como la membresía en el grupo Event Log Readers, y no debe ser un administrador del dominio. El agente de Windows es útil a gran escala porque descarga del firewall el trabajo de recolección.

Un syslog listener recopila asociaciones de sistemas que ya autentican usuarios, como controladores inalámbricos, sistemas de control de acceso a la red (NAC), concentradores VPN o proxies. Defines syslog parse profiles con expresiones regulares o identificadores de campo que extraen el nombre de usuario y la dirección IP de los mensajes de inicio y cierre de sesión, y luego agregas los servidores emisores a la lista de servidores monitoreados. El listener se habilita en una interfaz mediante un perfil de administración de interfaz (User-ID Syslog Listener-UDP o -SSL).

GlobalProtect es la fuente más confiable para usuarios remotos y en movimiento: el usuario se autentica ante el gateway, así que el firewall sabe exactamente quién tiene la IP del túnel. Los gateways internos extienden esto a los usuarios de la LAN. La XML API permite que cualquier script o sistema de terceros envíe eventos de inicio y cierre de sesión, y etiquetas, al firewall; así es como las aplicaciones personalizadas, las plataformas en la nube y las herramientas de orquestación alimentan a User-ID. Otras fuentes incluyen el Authentication Portal, los terminal server agents para hosts multiusuario (que asocian por rango de puertos porque muchos usuarios comparten una IP) y el client probing, que Palo Alto desaconseja.

Conocer el nombre de usuario es solo la mitad del trabajo; las políticas suelen escribirse para grupos. El group mapping (Device > User Identification > Group Mapping Settings) usa un server profile LDAP para leer la membresía de grupos desde el directorio, con una lista de inclusión de grupos para limitar cuáles se obtienen y un intervalo de actualización. Verifícalo con show user group list y show user ip-user-mapping all.

El Cloud Identity Engine (CIE) es un servicio en la nube que realiza la sincronización de directorios y la autenticación para los productos de Palo Alto. Lee usuarios y grupos desde Active Directory local (mediante un agente), Microsoft Entra ID, Okta y otros proveedores de identidad, y los firewalls lo consultan para obtener la información de grupos en lugar de que cada uno ejecute el group mapping por LDAP. Su Cloud Authentication Service también puede actuar como método de autenticación para funciones como GlobalProtect y Authentication Portal usando proveedores de identidad SAML. Es especialmente útil para directorios en la nube que no tienen interfaz LDAP.

Términos clave

Server monitoring (monitoreo de servidores)
Recolección de User-ID de eventos de inicio de sesión desde controladores de dominio, Exchange o eDirectory mediante el User-ID agent integrado o el de Windows.
Syslog parse profile (perfil de análisis de syslog)
Reglas de regex o de campos que extraen el nombre de usuario y la dirección IP de mensajes syslog de terceros.
Group mapping (asociación de grupos)
Obtener la membresía de grupos del directorio, normalmente vía LDAP, para que las políticas puedan hacer referencia a grupos.
Cloud Identity Engine
Un servicio en la nube de Palo Alto que sincroniza usuarios y grupos desde directorios e IdP y ofrece autenticación en la nube.
Ejemplo real

El personal se conecta a través de un controlador Wi-Fi usando 802.1X, pero esos inicios de sesión no pasan por los controladores de dominio, así que muchas IP aparecen como unknown. Configuras el controlador para enviar syslog de autenticación al firewall, escribes un syslog parse profile que extrae el usuario y la IP, y ahora los usuarios de Wi-Fi aparecen en los logs y coinciden con las reglas basadas en grupos.

Consejo para el examen: Server monitoring lee los logs de seguridad de los DC; los syslog listeners analizan mensajes de terceros; GlobalProtect es lo mejor para usuarios remotos; la XML API es para scripts. El group mapping necesita LDAP o el Cloud Identity Engine.

Comprueba lo que sabes

¿Qué fuente de User-ID conviene para un sistema NAC que registra las autenticaciones de usuarios?

Un syslog listener con un syslog parse profile para los mensajes de ese sistema.

¿Por qué usar el Cloud Identity Engine en una organización que solo usa Microsoft Entra ID?

Sincroniza los usuarios y grupos del directorio en la nube para las políticas sin necesitar una conexión LDAP a un directorio local.

¿Cómo maneja User-ID un terminal server con muchos usuarios en una sola IP?

Un terminal server agent asocia los usuarios a rangos de puertos de origen en lugar de a la IP compartida.
