Actualizaciones de software y contenido: rutas de actualización de PAN-OS e imágenes base, orden de actualización en HA, programación y umbrales de dynamic updates

Un firewall ejecuta dos tipos de código que se actualizan con calendarios distintos. El software PAN-OS es el sistema operativo, publicado como feature releases (como 10.2, 11.0, 11.1) con maintenance releases dentro de cada una (como 11.1.x). Las actualizaciones de contenido son firmas y datos: Applications and Threats (App-IDs y firmas de vulnerabilidades y spyware), Antivirus, WildFire, archivos de datos de GlobalProtect y otros. Se actualizan con frecuencia y sin reinicio.

Las rutas de actualización de PAN-OS tienen reglas. Para instalar una maintenance release de una nueva feature release, primero debes descargar la imagen base (base image) de esa feature release (la versión .0), aunque nunca la instales; el firewall necesita tenerla presente para instalar, por ejemplo, una maintenance release posterior de 11.1. Tradicionalmente también actualizas pasando por cada feature release en secuencia, en lugar de saltarte una. Las versiones más recientes permiten omitir algunas versiones en ciertos casos, así que siempre lee la ruta de actualización en las notas de la versión. Cada versión de PAN-OS también requiere una versión mínima de contenido, así que instala el contenido actual de Applications and Threats antes de actualizar el software.

Una actualización segura de un solo firewall se ve así: lee las notas de la versión y los problemas conocidos, guarda y exporta un snapshot de configuración con nombre y el device state, actualiza el contenido, descarga las imágenes base y de destino, instala, reinicia y verifica. Si administras el firewall con Panorama, actualiza Panorama primero; Panorama debe ejecutar la misma versión o una posterior que los firewalls que administra.

Los pares HA se actualizan un peer a la vez para que el tráfico siga fluyendo. Un orden típico en active/passive: deshabilita preemption si está habilitada, actualiza el peer pasivo y reinícialo, confirma que esté sano y sincronizado, suspende el peer activo para que el peer actualizado tome el control, actualiza el antiguo peer activo, luego regrésalo al estado funcional y restablece preemption. Durante esta ventana los peers ejecutan brevemente versiones diferentes, algo que HA tolera para la actualización.

Las dynamic updates se programan en Device > Dynamic Updates. Cada tipo tiene una programación (por ejemplo, cada 30 minutos para WildFire, diaria o cada hora para otros) y una acción: solo descargar, o descargar e instalar. El parámetro threshold (umbral) retrasa la instalación de una nueva versión de contenido hasta que haya estado disponible durante un número determinado de horas, dándole a Palo Alto tiempo para retirar una versión problemática antes de que tu firewall la instale. Para redes de misión crítica, usar un threshold es una buena práctica común. Las actualizaciones de Applications and Threats también te permiten revisar los App-IDs nuevos y elegir deshabilitarlos hasta que hayas verificado cómo afectan a la política.

Todo esto puede administrarse de forma centralizada: Panorama puede enviar software y contenido a los firewalls y actuar como servidor de actualizaciones. Verifica el resultado con show system info y en la página de dynamic updates.

Términos clave

Base image (imagen base)
La imagen .0 de una feature release, que debe descargarse antes de instalar una maintenance release de esa feature release.
Maintenance release (versión de mantenimiento)
Una versión de corrección de errores dentro de una feature release de PAN-OS, como una compilación 11.1.x posterior.
Threshold (umbral)
Un parámetro de dynamic updates que espera un número determinado de horas después de la publicación antes de instalar contenido nuevo.
Applications and Threats
El paquete de contenido que contiene las definiciones de App-ID y las firmas de vulnerabilidades y spyware.
Ejemplo real

Debes llevar un par HA de 10.2 a una maintenance release posterior de 11.1. Primero actualizas Panorama, instalas el contenido más reciente en ambos firewalls y luego revisas en las notas de la versión la ruta compatible. Descargas cada imagen base necesaria, actualizas el peer pasivo, haces failover, actualizas el otro peer y confirmas que las sesiones se mantuvieron sincronizadas durante todo el proceso.

Consejo para el examen: Primero la imagen base, el contenido antes que el software, Panorama antes que los firewalls, el peer pasivo antes que el activo. Los thresholds retrasan la instalación de contenido para reducir el riesgo de una versión defectuosa.

Comprueba lo que sabes

¿Por qué debes descargar una imagen base que no vas a ejecutar?

PAN-OS requiere que la imagen base de la feature release esté presente antes de instalar una maintenance release de esa feature release.

En un par active/passive, ¿qué peer actualizas primero?

El peer pasivo; luego haces failover y actualizas el antiguo peer activo.

¿Qué hace el threshold de dynamic updates?

Retrasa la instalación de una nueva versión de contenido hasta que lleve publicada el número de horas configurado.
