Palo Alto Networks Certified Next-Generation Firewall Engineer NGFW-Engineer

Plano de administración: permitted IPs, service routes, configuración candidate vs running, commits, partial commits, config locks y named snapshots

Los firewalls de Palo Alto separan el plano de administración (management plane), que ejecuta la interfaz web, la CLI, el registro y la configuración, del plano de datos (data plane), que procesa el tráfico. Proteger y operar el plano de administración con cuidado es higiene básica y un área favorita del examen.

Empieza por el acceso. La interfaz MGT dedicada (Device > Setup > Interfaces > Management) tiene su propia IP y configuración sobre qué servicios permite (HTTPS, SSH, ping, SNMP, User-ID, etc.) y una lista de Permitted IP Addresses. Solo las direcciones o subredes de la lista pueden llegar a esos servicios. La buena práctica es mantener la administración en una red aislada, deshabilitar HTTP y Telnet, restringir las permitted IPs a los jump hosts de los administradores y nunca exponer la administración a Internet. Las interfaces de datos con perfiles de administración de interfaz tienen sus propias listas de IP permitidas.

Los service routes, vistos antes, deciden qué interfaz usa el plano de administración para llegar a servicios externos como DNS, NTP, actualizaciones, syslog y servidores de autenticación. Si la red de MGT no puede llegar a ellos, configura un service route en una interfaz de datos.

El firewall mantiene dos configuraciones. La configuración candidate es la que editas en la interfaz web o en el modo configure de la CLI; los cambios ahí todavía no hacen nada. La configuración running es la que el firewall realmente está aplicando. Un commit valida la candidate y la convierte en running. Antes de hacer commit puedes usar Preview Changes para ver las diferencias, Validate para buscar errores sin aplicar nada y Change Summary para ver quién cambió qué. Un partial commit aplica solo algunos cambios, por ejemplo solo los cambios hechos por administradores específicos, lo que evita que un administrador haga commit por accidente del trabajo inconcluso de otro. En la CLI, comandos como commit partial admin <name> hacen lo mismo.

Los locks (bloqueos) coordinan a varios administradores. Un config lock impide que otros administradores cambien la configuración candidate; un commit lock impide que otros hagan commit. Los locks pueden establecerse manualmente desde el ícono de candado, y los superusers pueden quitar los locks de otros administradores. Adquirir automáticamente un commit lock al empezar a editar es una opción configurable.

Los named configuration snapshots te protegen de los errores. En Device > Setup > Operations puedes usar Save named configuration snapshot (escribe la candidate en un archivo con nombre), Load named configuration snapshot (reemplaza la candidate con él), Revert to running configuration (descarta los cambios sin commit), Load configuration version (regresa a una versión anterior ya aplicada con commit) y Export o Import para sacar o traer archivos del equipo. Cargar un snapshot solo cambia la candidate; nada surte efecto hasta que haces commit. Exportar un snapshot y el device state antes de una actualización es una práctica estándar.

Términos clave

Candidate configuration (configuración candidata)
La copia editable de la configuración que solo surte efecto después de un commit.
Running configuration (configuración en ejecución)
La configuración que el firewall está aplicando actualmente.
Partial commit (commit parcial)
Un commit de solo los cambios seleccionados, como los hechos por administradores específicos.
Config lock (bloqueo de configuración)
Un bloqueo que impide que otros administradores cambien la configuración candidate.
Named snapshot (snapshot con nombre)
Una copia guardada y con nombre de la configuración que luego puede cargarse en la candidate.
Ejemplo real

Dos administradores editan el mismo firewall. Priya terminó un cambio de NAT, mientras que las reglas de seguridad a medio construir de Sam siguen en la candidate. Priya usa Commit con el alcance limitado a sus propios cambios, así que su regla NAT entra en producción y el trabajo de Sam queda pendiente hasta que él esté listo.

Consejo para el examen: Cargar o revertir un snapshot solo cambia la candidate; aún necesitas hacer commit. Las permitted IPs de la interfaz MGT son el control principal sobre quién puede llegar a la administración.

Comprueba lo que sabes

Cargaste un named snapshot, pero el comportamiento del firewall no cambió. ¿Por qué?

Cargar un snapshot solo reemplaza la configuración candidate; debes hacer commit para que pase a running.

¿Cómo descartas todos los cambios sin commit?

Con Revert to running configuration.

¿Qué parámetro limita qué hosts pueden llegar a la interfaz web de la interfaz MGT?

La lista de Permitted IP Addresses en la configuración de la interfaz de administración.
