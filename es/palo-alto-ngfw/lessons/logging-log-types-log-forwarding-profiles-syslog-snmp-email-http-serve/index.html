Palo Alto Networks Certified Next-Generation Firewall Engineer NGFW-Engineer

Registro (logging): tipos de log, log forwarding profiles, server profiles de syslog/SNMP/email/HTTP, Device > Log Settings, Strata Logging Service

Los logs son la forma de demostrar lo que hizo el firewall y de alimentar a un equipo de operaciones de seguridad. PAN-OS escribe muchos tipos de log, visibles en Monitor > Logs. Los que más usarás son Traffic (un registro de cada sesión, de forma predeterminada al final de la sesión), Threat (detecciones de vulnerabilidades, spyware, virus, inundaciones y escaneos), URL Filtering, WildFire Submissions, Data Filtering, HIP Match, GlobalProtect, User-ID, IP-Tag, Decryption, Tunnel Inspection, Authentication, Configuration, System y Alarms. La vista Unified log combina varios tipos en una sola búsqueda.

El registro de tráfico se controla por regla de seguridad. En la pestaña Actions de una regla, Log at Session End está activado de forma predeterminada y Log at Session Start está desactivado; habilita el registro al inicio solo para diagnosticar problemas, porque agrega volumen. El tráfico denegado solo se registra si la regla de denegación tiene el registro habilitado, por eso la gente sobrescribe interzone-default.

Para enviar los logs a otro lugar, primero defines server profiles en Device > Server Profiles. Un perfil syslog enumera los servidores, el transporte (UDP, TCP o SSL), el puerto, el formato (BSD o IETF) y la facility, y te permite personalizar el formato del mensaje por tipo de log, lo cual importa para el análisis en el SIEM. Un perfil SNMP trap envía traps a los sistemas de monitoreo de red. Un perfil de email envía mensajes a través de un gateway SMTP. Un perfil HTTP envía logs a servicios web, con URI, encabezados y carga útil personalizados por tipo de log, y así es como te integras con herramientas de tickets y de chat.

Un log forwarding profile (Objects > Log Forwarding) decide a dónde van los logs generados por las políticas. Cada entrada elige un tipo de log (traffic, threat, URL, WildFire, data, tunnel, authentication, decryption), un filtro opcional (por ejemplo, severidad critical o high) y destinos: Panorama o registro en la nube, syslog, SNMP, email o HTTP. Las entradas también pueden ejecutar acciones integradas como el etiquetado. Adjuntas el perfil a las reglas de seguridad en la pestaña Actions. Un perfil llamado default se aplica automáticamente a las reglas nuevas.

Los logs que no se generan por las políticas (System, Configuration, User-ID, HIP Match, GlobalProtect, IP-Tag y similares) se reenvían en cambio desde Device > Log Settings, con el mismo tipo de filtros y destinos.

Strata Logging Service, antes Cortex Data Lake, es el almacenamiento de logs en la nube de Palo Alto. Los firewalls le reenvían los logs directamente o a través de Panorama, lo que brinda retención centralizada y permite que aplicaciones en la nube como Strata Cloud Manager y los productos Cortex analicen los datos. Requiere una licencia y el certificado de dispositivo del firewall. Panorama con Log Collectors es la alternativa local (on-premises). Verifica la recepción de logs con show logging-status.

Términos clave

Log forwarding profile (perfil de reenvío de logs)
Un objeto adjunto a las reglas de seguridad que envía los logs de política coincidentes a Panorama, registro en la nube, syslog, SNMP, email o HTTP.
Device > Log Settings
Donde se reenvían los logs System, Configuration, User-ID, HIP Match y otros logs que no son de política.
HTTP server profile (perfil de servidor HTTP)
Un server profile que envía logs a servicios web con URI, encabezados y carga útil personalizables.
Strata Logging Service
El servicio de almacenamiento de logs en la nube de Palo Alto (antes Cortex Data Lake) que usan las aplicaciones de administración y análisis en la nube.
Ejemplo real

El SOC quiere cada amenaza crítica en su SIEM en cuestión de segundos, y también todos los cambios de configuración. Creas un perfil de servidor syslog sobre TCP y un log forwarding profile con una entrada threat filtrada por severidad critical, lo adjuntas a las reglas de Internet y, en Device > Log Settings, reenvías los logs de Configuration al mismo perfil syslog.

Consejo para el examen: Los logs Traffic, Threat, URL, WildFire y Data se reenvían con un log forwarding profile en las reglas de seguridad; los logs System y Configuration usan Device > Log Settings. Los logs de Traffic se generan de forma predeterminada solo al final de la sesión.

Comprueba lo que sabes

¿Dónde configuras el reenvío de los logs de Configuration a syslog?

En Device > Log Settings, usando un perfil de servidor syslog.

¿Por qué el tráfico bloqueado podría no aparecer en el Traffic log?

La regla de denegación que coincide, a menudo interzone-default, no tiene el registro habilitado.

¿Qué les sucede a las reglas de seguridad nuevas si un log forwarding profile se llama default?

Se les adjunta automáticamente.
