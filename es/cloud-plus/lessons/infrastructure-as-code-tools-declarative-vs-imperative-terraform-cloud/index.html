Herramientas de infraestructura como código: declarativa frente a imperativa, Terraform, CloudFormation, ARM/Bicep

Las herramientas de infraestructura como código difieren principalmente en dos aspectos: si son declarativas o imperativas, y si están atadas a un solo proveedor.

Un enfoque declarativo describe el estado final deseado: debería haber una red virtual con estas dos subredes y una VM de este tamaño. La herramienta compara ese estado deseado con lo que existe y hace los cambios que sean necesarios, creando, actualizando o borrando recursos. Ejecutarla de nuevo sin cambios no hace nada. Un enfoque imperativo lista los pasos a realizar: crea la red, luego crea la subred, luego lanza la VM. Los scripts que usan comandos de CLI o SDK son imperativos; son flexibles pero debes manejar el caso en que los recursos ya existen, y ejecutar un script dos veces puede crear duplicados. La mayoría de las herramientas de IaC son declarativas, aunque a menudo se dirigen mediante scripts imperativos en una canalización.

Terraform, de HashiCorp, es una herramienta declarativa ampliamente usada que funciona con muchos proveedores (AWS, Azure, Google Cloud, Kubernetes, servicios DNS y muchos más) mediante complementos llamados proveedores (providers). Escribes la configuración en HCL (HashiCorp Configuration Language), ejecutas terraform init para descargar los proveedores, terraform plan para previsualizar los cambios y terraform apply para hacerlos. Terraform mantiene un archivo de estado que asigna la configuración a los recursos reales, normalmente almacenado de forma remota con bloqueo. Los módulos reutilizables empaquetan patrones comunes. OpenTofu es una bifurcación de código abierto con el mismo flujo de trabajo.

AWS CloudFormation es el servicio declarativo nativo de AWS. Las plantillas en JSON o YAML definen recursos, y CloudFormation las despliega como una pila (stack), rastreando el estado por sí mismo. Los conjuntos de cambios (change sets) previsualizan los cambios, las actualizaciones fallidas se revierten automáticamente y la detección de desviación informa de los cambios manuales. Las plantillas de Azure Resource Manager (ARM) son el formato JSON nativo de Azure; Bicep es un lenguaje más legible que se compila a plantillas ARM, y los despliegues los gestiona Azure mismo, así que no hay un archivo de estado separado del que ocuparse. Google Cloud tiene sus propias opciones nativas y también usa comúnmente Terraform.

Elige herramientas nativas del proveedor para una integración profunda y sin archivo de estado que gestionar; elige una herramienta multiproveedor como Terraform para la multinube y para gestionar otros servicios, como DNS o monitorización, en el mismo flujo de trabajo.

Términos clave

Declarative (declarativa)
Describir el estado final deseado y dejar que la herramienta determine cómo alcanzarlo.
Imperative (imperativa)
Especificar la secuencia exacta de comandos a ejecutar.
Terraform
Una herramienta de IaC declarativa multiproveedor que usa HCL, proveedores, módulos y un archivo de estado.
CloudFormation
El servicio de IaC nativo de AWS que despliega plantillas JSON o YAML como pilas.
Bicep
Un lenguaje específico de dominio para los despliegues de Azure que se compila a plantillas ARM.
Ejemplo real

Una empresa que ejecuta cargas de trabajo en AWS y Azure estandariza en Terraform para que un equipo, un lenguaje y una canalización puedan gestionar redes en ambas nubes más su proveedor de DNS externo. Su subsidiaria exclusiva de Azure sigue usando Bicep porque no necesita archivo de estado y se integra directamente con los despliegues de Azure.

Consejo para el examen: Terraform es multiproveedor y usa un archivo de estado; CloudFormation es solo de AWS; ARM y Bicep son solo de Azure. Declarativa describe qué; imperativa describe cómo. IaC multinube en una sola herramienta apunta a Terraform.

Comprueba lo que sabes

¿Qué hace terraform plan?

Compara la configuración con el estado y la infraestructura real y muestra los cambios que haría apply, sin hacerlos.

¿Por qué es seguro ejecutar una plantilla declarativa dos veces?

Describe el estado final, así que si los recursos ya coinciden, la herramienta no hace cambios en lugar de crear duplicados.
