Modelos de despliegue: pública, privada, híbrida, comunitaria y multinube

Un modelo de despliegue describe quién posee y usa la infraestructura de la nube, a diferencia del modelo de servicio, que describe qué capas administras. El mismo servicio IaaS podría entregarse desde una nube pública o desde una nube privada en tu propio centro de datos.

Una nube pública la opera un proveedor y la comparten muchos clientes (inquilinos) no relacionados entre sí a través de internet. Obtienes aprovisionamiento de autoservicio rápido, una escala enorme y facturación de pago por uso, sin hardware que comprar. Una nube privada atiende a una sola organización. Puede estar en las instalaciones o alojada por un tercero, pero aun así ofrece características de nube: autoservicio, recursos agrupados, elasticidad y uso medido. Simplemente poseer servidores virtualizados no es una nube privada a menos que los usuarios puedan aprovisionar recursos bajo demanda. Las nubes privadas convienen para un control estricto, hardware especial o datos que la política exige mantener en una instalación concreta, a costa del gasto de capital y de una escala limitada.

Una nube híbrida conecta una nube privada o un entorno local con una nube pública para que las cargas de trabajo y los datos puedan moverse o trabajar en conjunto, normalmente sobre una VPN o un enlace dedicado con identidad compartida. Los motivos comunes son mantener una base de datos sensible en las instalaciones mientras las capas web se ejecutan en la nube pública, o el cloud bursting (desbordamiento a la nube), en el que la demanda adicional se derrama hacia la nube pública durante los picos. Una nube comunitaria la comparten varias organizaciones con requisitos comunes, como agencias gubernamentales o instituciones de investigación que deben cumplir las mismas reglas de conformidad, y el costo se reparte entre ellas.

Multinube (multicloud) significa usar servicios de dos o más proveedores de nube pública. Es distinto de la híbrida: la híbrida trata de mezclar privada y pública, la multinube trata de mezclar proveedores. Las organizaciones eligen la multinube para evitar la dependencia de un proveedor (vendor lock-in), para usar el mejor servicio de cada proveedor, o para satisfacer necesidades de resiliencia o regulatorias. Los costos son más habilidades que mantener, modelos distintos de identidad y de red, informes de costos más difíciles y cargos por salida de datos cuando estos se mueven entre proveedores.

Términos clave

Public cloud (nube pública)
Infraestructura de nube propiedad de un proveedor y compartida por muchos inquilinos, consumida bajo demanda por internet.
Private cloud (nube privada)
Infraestructura de nube dedicada a una organización, en las instalaciones o alojada, que aun así ofrece autoservicio y elasticidad.
Hybrid cloud (nube híbrida)
Una combinación de infraestructura privada o local y nube pública, conectadas para que las cargas de trabajo puedan interoperar.
Community cloud (nube comunitaria)
Infraestructura de nube compartida por varias organizaciones con misión, seguridad o conformidad comunes.
Multicloud (multinube)
Usar servicios de más de un proveedor de nube pública.
Cloud bursting
Enviar la demanda de desbordamiento desde un entorno privado a una nube pública cuando se agota la capacidad local.
Ejemplo real

Un hospital mantiene su sistema de historiales de pacientes en una nube privada local por razones regulatorias, ejecuta su sitio web público de citas en una nube pública y enlaza ambos con una VPN de sitio a sitio. Eso es una nube híbrida. Cuando más adelante añade el servicio de analítica de un segundo proveedor, también se vuelve multinube.

Consejo para el examen: No confundas híbrida con multinube. Híbrida significa privada más pública; multinube significa dos o más proveedores públicos. Un diseño puede ser ambas cosas al mismo tiempo.

Comprueba lo que sabes

Varias agencias estatales comparten una infraestructura construida para cumplir las mismas reglas de conformidad. ¿Qué modelo de despliegue es este?

Una nube comunitaria, porque la comparten organizaciones con requisitos comunes.

¿Cuál es la razón principal que dan las organizaciones para adoptar la multinube?

Evitar la dependencia de un proveedor, junto con usar el mejor servicio de cada proveedor y añadir resiliencia frente a la caída de un proveedor.
