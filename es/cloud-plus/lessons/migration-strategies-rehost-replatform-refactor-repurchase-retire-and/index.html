Estrategias de migración: rehospedar, replataformar, refactorizar, recomprar, retirar y retener

Cuando una organización mueve aplicaciones a la nube, cada aplicación recibe una estrategia de migración. La lista común, a menudo llamada las 6 R, es parte del vocabulario de Cloud+. Algunos marcos añaden una séptima, reubicar (relocate), para mover entornos virtualizados enteros a una versión alojada en la nube de la misma plataforma de hipervisor.

Rehospedar (rehost), o traslado directo (lift and shift), mueve una aplicación tal como está, normalmente copiando VMs a instancias de nube con una herramienta de migración. Es la forma más rápida y de menor riesgo de dejar un centro de datos, pero no aprovecha las funcionalidades de la nube, así que los ahorros son limitados hasta que la aplicación se optimice más tarde. Replataformar (replatform), a veces llamado levantar, ajustar y trasladar (lift, tinker and shift), hace unos pocos cambios puntuales para obtener beneficios de la nube sin cambiar la arquitectura central: por ejemplo, mover una base de datos autogestionada a un servicio de base de datos gestionado, o ejecutar la aplicación en una plataforma gestionada en lugar de una VM.

Refactorizar (refactor), o rearquitecturar, rediseña la aplicación para que sea nativa de la nube, quizá dividiendo un monolito en microservicios, usando funciones sin servidor o colas gestionadas. Entrega la mayor escalabilidad y agilidad pero requiere el mayor tiempo, dinero y habilidad, así que se reserva para aplicaciones donde el valor de negocio lo justifica. Recomprar (repurchase), o descartar y comprar (drop and shop), reemplaza la aplicación con un producto distinto, normalmente SaaS: pasar de un servidor de correo o CRM autoalojado a una oferta SaaS.

Retirar (retire) significa apagar la aplicación porque nadie la necesita; el descubrimiento a menudo encuentra un número sorprendente de sistemas sin uso. Retener (retain), o revisar (revisit), significa dejar la aplicación donde está por ahora, quizá porque se actualizó hace poco, depende de hardware que no puede moverse, enfrenta restricciones de conformidad o simplemente no vale la pena moverla aún.

En la práctica una cartera mezcla estrategias. Un patrón común es rehospedar muchos sistemas rápido para cumplir una fecha límite de salida del centro de datos, y luego replataformar o refactorizar los más importantes una vez que están funcionando en la nube.

Términos clave

Rehost (rehospedar)
Traslado directo (lift and shift): mover una aplicación a la nube sin cambiarla.
Replatform (replataformar)
Mover con pequeñas optimizaciones, como cambiar a una base de datos gestionada, sin cambiar la arquitectura central.
Refactor (refactorizar)
Rearquitecturar una aplicación para usar servicios y patrones nativos de la nube.
Repurchase (recomprar)
Reemplazar una aplicación con un producto distinto, a menudo SaaS.
Retire / retain (retirar / retener)
Desmantelar una aplicación que ya no se necesita, o dejarla deliberadamente donde está por ahora.
Ejemplo real

Ante un contrato de arrendamiento de centro de datos que termina en seis meses, una empresa rehospeda 120 VMs, replataforma su base de datos de pedidos a un servicio de base de datos gestionado, recompra su sistema de tickets como SaaS, retira 15 servidores que nadie usa y retiene una aplicación de mainframe que revisará el próximo año.

Consejo para el examen: Busca las palabras clave: sin cambios de código y más rápido significa rehospedar; un servicio gestionado con cambios mínimos significa replataformar; reescribir para nativo de la nube o microservicios significa refactorizar; cambiar a SaaS significa recomprar.

Comprueba lo que sabes

Un equipo mueve su servidor MySQL autogestionado a un servicio de base de datos gestionado pero deja el código de la aplicación sin cambios. ¿Qué estrategia es esa?

Replataformar: una optimización puntual sin rearquitecturar la aplicación.

¿Qué estrategia da el mayor beneficio nativo de la nube pero cuesta el mayor esfuerzo?

Refactorizar (rearquitecturar).
