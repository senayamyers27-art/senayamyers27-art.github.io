Tipos de almacenamiento en la nube: bloque, archivo y objeto; niveles de almacenamiento y rendimiento (IOPS, rendimiento)

Los proveedores de nube ofrecen tres tipos principales de almacenamiento, y elegir el equivocado es una trampa clásica del examen. El almacenamiento en bloque presenta un volumen en bruto, como un disco duro virtual, que conectas a una VM (algunos servicios permiten conexión múltiple en casos especiales). El sistema operativo lo formatea con un sistema de archivos. Da baja latencia y se usa para discos de arranque y bases de datos. El almacenamiento de archivos proporciona un sistema de archivos compartido sobre un protocolo de red como NFS o SMB, de modo que muchos servidores pueden montar a la vez el mismo árbol de directorios. Conviene para contenido compartido, directorios personales y aplicaciones de traslado directo (lift-and-shift) que esperan un recurso compartido de red.

El almacenamiento de objetos guarda datos como objetos en buckets o contenedores. Cada objeto tiene una clave (su nombre), los datos y metadatos, y se alcanza a través de API HTTP(S) en lugar de montarse como un disco. El almacenamiento de objetos escala casi sin límite y es muy duradero, lo que lo convierte en la opción habitual para copias de seguridad, registros, medios, contenido de sitios web estáticos y lagos de datos. No puedes editar parte de un objeto en su lugar; reemplazas el objeto completo.

Dentro de un servicio de almacenamiento eliges niveles (tiers). Los niveles caliente o estándar cuestan más por almacenar pero poco por leer, para datos usados con frecuencia. Los niveles frío o de acceso poco frecuente son más baratos por almacenar pero cobran más por recuperación y pueden tener una duración mínima de almacenamiento. Los niveles de archivo son los más baratos por almacenar pero pueden tardar de minutos a horas en recuperar. Las políticas de ciclo de vida mueven los objetos entre niveles automáticamente según su antigüedad. Para el almacenamiento en bloque, los niveles tienen que ver con el medio: volúmenes respaldados por SSD para E/S aleatoria y volúmenes respaldados por HDD para grandes lecturas secuenciales, con algunos tipos de volumen que te dejan aprovisionar el rendimiento por separado.

Importan dos medidas de rendimiento. Las IOPS (operaciones de entrada/salida por segundo) cuentan cuántas lecturas y escrituras puede realizar un volumen; importan para bases de datos y otras operaciones pequeñas y aleatorias. El rendimiento (throughput) es cuánto dato se mueve por segundo, normalmente en MB/s; importa para grandes trabajos secuenciales como el procesamiento de registros, las copias de seguridad y el video. La latencia es el tiempo que tarda cada operación. Un volumen puede tener alto rendimiento pero bajas IOPS, o al revés, así que ajusta la métrica a la carga de trabajo.

Términos clave

Block storage (almacenamiento en bloque)
Volúmenes en bruto conectados a una instancia y formateados con un sistema de archivos; baja latencia, usados para discos de arranque y bases de datos.
File storage (almacenamiento de archivos)
Un sistema de archivos compartido montado en red (NFS o SMB) que muchos clientes pueden usar a la vez.
Object storage (almacenamiento de objetos)
Almacenamiento de objetos con claves y metadatos en buckets, accedido mediante API HTTP; muy duradero y escalable.
IOPS
Operaciones de entrada/salida por segundo: la tasa de operaciones individuales de lectura y escritura que un dispositivo de almacenamiento puede manejar.
Throughput (rendimiento)
La cantidad de datos transferidos por segundo, normalmente medida en MB/s.
Ejemplo real

Un equipo ejecuta una base de datos transaccional en un volumen en bloque SSD dimensionado para sus necesidades de IOPS, guarda las imágenes subidas en almacenamiento de objetos con una regla de ciclo de vida que las mueve a un nivel frío tras 90 días, y da a sus servidores web un sistema de archivos compartido para una carpeta de contenido heredada que todos leen.

Consejo para el examen: Las bases de datos y los discos de arranque apuntan al almacenamiento en bloque; un recurso compartido montado por muchos servidores apunta al almacenamiento de archivos; las copias de seguridad, los registros y el contenido estático a escala apuntan al almacenamiento de objetos. Muchas operaciones pequeñas y aleatorias significan IOPS; las grandes transferencias secuenciales significan rendimiento.

Comprueba lo que sabes

Varios servidores web Linux deben leer y escribir en el mismo directorio. ¿Qué tipo de almacenamiento encaja?

Almacenamiento de archivos, como un recurso compartido NFS, porque puede ser montado por muchos servidores a la vez.

Un trabajo de copia de seguridad mueve archivos grandes de forma secuencial y va lento. ¿Qué métrica deberías mirar primero?

El rendimiento, porque las grandes transferencias secuenciales están limitadas por MB/s en lugar de por operaciones por segundo.
