Conectividad híbrida: VPN de sitio a sitio, interconexiones dedicadas, emparejamiento y concentradores de tránsito

Una vez que tienes redes en la nube, necesitas conectarlas a tus oficinas y centros de datos y entre sí. Cloud+ evalúa qué método de conexión encaja con una necesidad dada de ancho de banda, latencia, costo y tiempo de configuración.

Una VPN de sitio a sitio construye un túnel IPsec cifrado sobre el internet público entre tu dispositivo VPN local y una puerta de enlace VPN en la nube. Es rápida de configurar y barata, y cifra el tráfico, pero el rendimiento depende de internet: el ancho de banda es limitado y la latencia varía. La mayoría de los proveedores te permite crear dos túneles para redundancia y usar BGP (Border Gateway Protocol) para intercambiar rutas de forma dinámica. Una VPN de cliente o de punto a sitio, en cambio, conecta usuarios individuales en lugar de redes enteras.

Una interconexión dedicada es una conexión física privada entre tu red y el proveedor, realizada en una instalación de colocación o a través de un socio (AWS Direct Connect, Azure ExpressRoute y Google Cloud Interconnect son ejemplos). El tráfico no cruza el internet público, así que obtienes latencia consistente, mayor ancho de banda y a menudo cargos de transferencia de datos más bajos. Tarda semanas en pedirse y cuesta más. Tales enlaces no están necesariamente cifrados de forma predeterminada, así que algunas organizaciones ejecutan una VPN sobre la interconexión o usan cifrado a nivel de enlace donde se ofrezca. Un diseño común es una interconexión dedicada como primaria con una VPN de sitio a sitio como respaldo.

Dentro de la nube, el emparejamiento (peering) de VPC o VNet conecta dos redes virtuales de forma privada para que los recursos puedan hablar usando direcciones IP privadas. El emparejamiento requiere rangos CIDR que no se solapen y normalmente no es transitivo: si A se empareja con B y B se empareja con C, A no puede alcanzar a C a través de B. Con muchas redes, una malla completa de emparejamientos se vuelve inmanejable. Un concentrador de tránsito (transit hub, como una puerta de enlace de tránsito, una VNet concentradora o una WAN virtual) resuelve esto con un diseño de concentrador y radios (hub-and-spoke): cada VPC y conexión local se conecta al concentrador, que enruta entre ellas según sus tablas de rutas.

Términos clave

Site-to-site VPN (VPN de sitio a sitio)
Un túnel IPsec cifrado sobre internet que conecta toda una red local a una red en la nube.
Dedicated interconnect (interconexión dedicada)
Un enlace físico privado entre la red de un cliente y un proveedor de nube que evita el internet público.
VPC peering (emparejamiento de VPC)
Una conexión privada entre dos redes virtuales que les permite comunicarse con direcciones IP privadas; normalmente no transitiva.
Transit hub (concentrador de tránsito)
Un servicio de enrutador central que conecta muchas redes virtuales y enlaces locales en una topología de concentrador y radios.
BGP
Border Gateway Protocol, usado para intercambiar rutas dinámicamente sobre enlaces VPN e interconexiones.
Ejemplo real

Un minorista necesita que su plataforma de analítica en la nube extraiga grandes conjuntos de datos cada noche desde su centro de datos con un rendimiento predecible. Pide una interconexión dedicada para la conectividad primaria, mantiene una VPN de sitio a sitio como ruta de conmutación por error, y conecta ambas más sus doce VPC a un concentrador de tránsito en lugar de mantener docenas de emparejamientos.

Consejo para el examen: Lo necesitas hoy y barato: VPN de sitio a sitio. Necesitas latencia consistente y alto ancho de banda que evite internet: interconexión dedicada. Muchas VPC que necesitan hablar entre sí: un concentrador de tránsito, porque el emparejamiento no es transitivo.

Comprueba lo que sabes

La VPC A está emparejada con la VPC B, y B está emparejada con C. ¿Puede A alcanzar a C a través de B?

No. El emparejamiento no es transitivo; necesitas un emparejamiento directo A-C o un concentrador de tránsito.

¿Por qué una empresa podría seguir ejecutando una VPN cuando tiene una interconexión dedicada?

Como ruta de respaldo si la interconexión falla, o para cifrar el tráfico que el enlace privado no cifra de forma predeterminada.
