Controles de seguridad de red: grupos de seguridad frente a ACL de red, WAF, protección DDoS y puntos de conexión privados

Las redes de la nube ofrecen varias capas de filtrado, y las preguntas del examen a menudo giran en torno a las diferencias entre ellas.

Un grupo de seguridad (security group) es un cortafuegos virtual adjunto a una instancia o interfaz de red. Es con estado (stateful): si se permite una conexión entrante, el tráfico de retorno se permite automáticamente, y viceversa. En AWS, los grupos de seguridad admiten solo reglas de permitir; cualquier cosa no permitida se deniega. Pueden referenciar otros grupos de seguridad como orígenes, por ejemplo permitir que el grupo de la base de datos acepte el puerto 5432 solo desde el grupo de los servidores de aplicación, lo que sigue funcionando a medida que las instancias van y vienen. Los grupos de seguridad de red (NSG) de Azure también son con estado pero admiten reglas de permitir y denegar con prioridades, y pueden aplicarse a subredes o interfaces.

Una ACL de red (NACL), en términos de AWS, se aplica a toda una subred. Es sin estado (stateless): el tráfico de retorno debe permitirse explícitamente, lo que normalmente significa permitir los puertos efímeros (1024-65535) para las respuestas. Admite reglas de permitir y denegar y las procesa en orden numérico, deteniéndose en la primera coincidencia. Las NACL son útiles como límite grueso de subred, por ejemplo para bloquear rápido un rango de direcciones malicioso conocido, mientras que los grupos de seguridad proporcionan control fino a nivel de instancia. Una regla de tráfico de retorno olvidada en una NACL es un escenario clásico de resolución de problemas.

Un cortafuegos de aplicaciones web (WAF) inspecciona las solicitudes HTTP y HTTPS en la capa 7, delante de un balanceador de carga, una puerta de enlace de API o una CDN. Bloquea ataques web comunes como la inyección SQL y el cross-site scripting usando conjuntos de reglas gestionados, y puede aplicar limitación de tasa y reglas geográficas o de IP. Los cortafuegos de red no pueden ver estos ataques porque solo miran direcciones y puertos. La protección DDoS absorbe y filtra las inundaciones de tráfico destinadas a saturar un servicio. La protección básica contra inundaciones de la capa de red la incluyen los grandes proveedores; los niveles avanzados añaden protección de la capa de aplicación, monitorización y soporte de respuesta. Las CDN y el autoescalado también ayudan a absorber la carga.

Los puntos de conexión privados (o enlaces privados) dan a un servicio gestionado, como el almacenamiento de objetos o una base de datos, una dirección IP privada dentro de tu red virtual, de modo que el tráfico nunca cruza el internet público, y puedes entonces deshabilitar el punto de conexión público del servicio. Los puntos de conexión de puerta de enlace o de servicio son una opción relacionada que mantiene el tráfico en la red del proveedor.

Términos clave

Security group (grupo de seguridad)
Un cortafuegos virtual con estado aplicado a instancias o interfaces.
Network ACL (ACL de red)
Una lista de reglas de permitir y denegar sin estado y ordenada, aplicada en el límite de la subred.
Stateful filtering (filtrado con estado)
Rastrear las conexiones para que el tráfico de retorno de una conexión permitida se permita automáticamente.
WAF
Cortafuegos de aplicaciones web: un filtro de capa 7 que bloquea ataques como la inyección SQL y el cross-site scripting.
Private endpoint (punto de conexión privado)
Una dirección IP privada en tu red virtual que se conecta a un servicio gestionado sin usar el internet público.
Ejemplo real

La base de datos de una aplicación acepta conexiones solo desde el grupo de seguridad de la capa de aplicación en el puerto 5432. Un WAF delante del balanceador de carga bloquea los intentos de inyección SQL, la cuenta de almacenamiento que contiene los archivos de clientes se alcanza a través de un punto de conexión privado con el acceso público deshabilitado, y una NACL de subred bloquea un rango de direcciones visto en un ataque.

Consejo para el examen: Con estado y por instancia: grupo de seguridad. Sin estado, ordenada, por subred y capaz de denegar: NACL. Inyección SQL o cross-site scripting: WAF, no un cortafuegos de red. Mantener el tráfico a un servicio gestionado fuera de internet: punto de conexión privado.
