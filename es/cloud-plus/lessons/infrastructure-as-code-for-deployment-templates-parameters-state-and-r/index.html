Infraestructura como código para el despliegue: plantillas, parámetros, estado y entornos repetibles

La infraestructura como código (IaC) significa describir tus recursos de nube en archivos que una herramienta lee para crearlos y actualizarlos, en lugar de hacer clic en una consola. Esos archivos viven en control de versiones, se revisan como el código de aplicación y pueden ejecutarse una y otra vez para producir el mismo resultado.

Una plantilla es el archivo que describe los recursos: redes, subredes, VMs, bases de datos, reglas de seguridad y cómo se relacionan. La mayoría de las herramientas de despliegue son declarativas: declaras el resultado final deseado, y la herramienta averigua qué llamadas de API hacer. Las plantillas se escriben en formatos como JSON, YAML o un lenguaje específico de la herramienta. En lugar de codificar valores de forma fija, las plantillas usan parámetros (también llamados variables o entradas) como el nombre del entorno, el tamaño de la instancia o el rango CIDR. La misma plantilla despliega entonces desarrollo, prueba y producción pasando distintos valores de parámetro, lo que mantiene los entornos consistentes permitiendo diferencias sensatas, como instancias más pequeñas en desarrollo. Las salidas (outputs) exponen valores como la dirección de un balanceador de carga para que otras plantillas o canalizaciones las usen.

El estado (state) es cómo la herramienta recuerda lo que ha creado. Las herramientas nativas del proveedor rastrean los despliegues como pilas (stacks) o despliegues dentro de la nube. Herramientas como Terraform mantienen un archivo de estado que asigna los recursos de tu código a los ID de recursos reales. Cuando ejecutas un plan, la herramienta compara la configuración deseada con el estado y la realidad, y muestra lo que creará, cambiará o destruirá antes de aplicar. Almacena el estado compartido de forma remota con bloqueo, para que dos personas no puedan aplicar a la vez, y protégelo, porque puede contener valores sensibles.

La desviación (drift) ocurre cuando alguien cambia un recurso a mano de modo que ya no coincide con el código. La detección de desviación la encuentra; la solución es actualizar el código o volver a aplicarlo, no seguir haciendo cambios en la consola. Los beneficios de la IaC son la repetibilidad, la velocidad, la revisión por pares, un rastro de auditoría a través del historial de versiones y la recreación fácil de un entorno para la recuperación ante desastres.

Términos clave

Infrastructure as code (infraestructura como código)
Definir y gestionar la infraestructura mediante archivos legibles por máquina bajo control de versiones.
Template (plantilla)
Un archivo que describe los recursos a desplegar y su configuración.
Parameter (parámetro)
Un valor de entrada que permite a una plantilla desplegar distintos entornos o tamaños.
State (estado)
El registro que una herramienta de IaC mantiene de los recursos que gestiona y sus identificadores reales.
Drift (desviación)
Diferencias entre los recursos desplegados y la configuración definida en el código, normalmente por cambios manuales.
Ejemplo real

Un equipo usa una plantilla con un parámetro de entorno para construir redes idénticas de dev, test y prod. Tras un cambio manual nocturno en un grupo de seguridad en prod, la comprobación semanal de desviación lo señala; el ingeniero añade la regla a la plantilla, la somete a revisión y la vuelve a aplicar, de modo que el cambio queda documentado y es repetible.

Consejo para el examen: Si los entornos difieren inesperadamente o un cambio manual sigue desapareciendo, piensa en desviación e IaC. Los parámetros hacen reutilizable una plantilla; el estado permite a la herramienta saber qué ya existe. Nunca codifiques secretos de forma fija en las plantillas.

Comprueba lo que sabes

¿Cómo puede una sola plantilla crear tanto un entorno de prueba pequeño como uno de producción grande?

Usando parámetros para valores como el tamaño de la instancia, los recuentos y los nombres, pasando distintos valores para cada entorno.

¿Qué problema resuelve el bloqueo de estado?

Impide que dos personas o canalizaciones apliquen cambios al mismo estado al mismo tiempo y lo corrompan.
