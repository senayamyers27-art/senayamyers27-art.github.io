Virtualización y cómputo: hipervisores, familias de instancias, hosts dedicados y multiinquilinato

El cómputo en la nube se construye sobre la virtualización: software que permite que un servidor físico ejecute muchas máquinas virtuales aisladas. El hipervisor es la capa que reparte la CPU, la memoria, el almacenamiento y la red del host entre los invitados y los mantiene separados.

Hay dos tipos de hipervisor. Un hipervisor tipo 1, o bare-metal, se ejecuta directamente sobre el hardware sin un sistema operativo de propósito general por debajo. Ejemplos son VMware ESXi, Microsoft Hyper-V, Xen y KVM, y los proveedores de nube usan hipervisores tipo 1 porque son eficientes y tienen una superficie de ataque pequeña. Un hipervisor tipo 2, o alojado, se ejecuta como una aplicación sobre un sistema operativo normal, como VirtualBox o VMware Workstation en un portátil. El tipo 2 es cómodo para pruebas pero añade sobrecarga.

Los proveedores agrupan los tamaños de sus VM en familias de instancias, a veces llamadas series de máquinas o tamaños de VM. Las familias de propósito general equilibran CPU y memoria. Las familias optimizadas para cómputo dan más CPU por gigabyte de memoria, para procesamiento por lotes o servidores web bajo mucha carga. Las familias optimizadas para memoria convienen a bases de datos en memoria y cachés. Las familias optimizadas para almacenamiento ofrecen discos locales rápidos para cargas de trabajo de alta IOPS, y las familias aceleradas añaden GPU para aprendizaje automático o gráficos. Dentro de una familia eliges un tamaño, y algunas familias usan créditos de CPU ampliables (burstable): bien para cargas de trabajo con picos y ligeras, pero malas para carga sostenida.

De forma predeterminada, las VM de la nube se ejecutan en hardware compartido junto a las VM de otros clientes, lo que es multiinquilinato. El hipervisor aísla a los inquilinos, pero algunos clientes necesitan más. Una instancia dedicada se ejecuta en hardware usado solo por un cliente, mientras que un host dedicado te da todo un servidor físico que puedes ver y en el que puedes colocar VMs. Los hosts dedicados ayudan con licencias de software que se cuentan por socket o núcleo físico, y con reglas de conformidad que exigen aislamiento físico. Cuestan más y tú asumes la planificación de capacidad de ese host.

Un concepto más es la sobresuscripción (oversubscription): asignar más CPU virtuales o memoria a los invitados de la que el host tiene físicamente, bajo la suposición de que no todos los invitados alcanzan su pico a la vez. Aumenta la densidad pero puede causar contención, que en la nube puedes notar como un vecino ruidoso (noisy neighbor) que ralentiza tu VM.

Términos clave

Type 1 hypervisor (hipervisor tipo 1)
Un hipervisor bare-metal que se ejecuta directamente sobre el hardware; usado por los proveedores de nube.
Type 2 hypervisor (hipervisor tipo 2)
Un hipervisor alojado que se ejecuta como una aplicación sobre un sistema operativo de propósito general.
Instance family (familia de instancias)
Un grupo de tamaños de VM ajustados a un perfil de carga de trabajo, como propósito general, optimizado para cómputo, memoria o almacenamiento, o GPU.
Dedicated host (host dedicado)
Un servidor físico reservado para un cliente, que da visibilidad de sockets y núcleos para licenciamiento y aislamiento.
Multitenancy (multiinquilinato)
Muchos clientes compartiendo la misma infraestructura física mientras están lógicamente aislados entre sí.
Ejemplo real

Una empresa que migra una base de datos cuya licencia se cuenta por núcleo físico elige un host dedicado para poder demostrar en cuántos núcleos se ejecuta el software, mientras que su capa web sin estado permanece en instancias normales compartidas de propósito general.

Consejo para el examen: El licenciamiento atado a sockets o núcleos físicos, o un requisito de aislamiento físico, apunta a hosts dedicados. Una caché ávida de memoria apunta a una familia optimizada para memoria, no simplemente a una VM de propósito general más grande.

Comprueba lo que sabes

¿Qué tipo de hipervisor usan las nubes públicas y por qué?

Tipo 1 (bare-metal), porque se ejecuta directamente sobre el hardware con menos sobrecarga y una superficie de ataque menor.

Una carga de trabajo de analítica en memoria se queda sin RAM una y otra vez mientras la CPU está mayormente ociosa. ¿Qué deberías cambiar?

Moverla a una familia de instancias optimizada para memoria, que da más memoria por vCPU.
