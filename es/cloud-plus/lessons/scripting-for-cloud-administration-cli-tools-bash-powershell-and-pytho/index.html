CompTIA Cloud+ CV0-004

Scripting para la administración de la nube: herramientas de CLI, Bash, PowerShell y Python

Los scripts llenan los huecos entre las consolas y la infraestructura como código completa: cambios masivos, informes, trabajos de limpieza programados, pegamento entre sistemas e investigaciones rápidas. Cloud+ espera que leas scripts simples y reconozcas la herramienta correcta para una tarea, no que seas un desarrollador de software.

Cada proveedor ofrece una interfaz de línea de comandos: la AWS CLI (aws), la Azure CLI (az) y la Google Cloud CLI (gcloud), más los módulos de Azure PowerShell. Las CLI se autentican con un perfil configurado, una sesión de inicio de sesión único o la identidad de carga de trabajo de la máquina en la que se ejecutan, y pueden dar salida JSON para su procesamiento posterior. La mayoría admite opciones de consulta o filtro para devolver solo los campos que necesitas, lo que es útil en los scripts. Por ejemplo, aws ec2 describe-instances --filters Name=instance-state-name,Values=stopped lista las instancias detenidas. Los shells de nube en el navegador te dan una CLI autenticada sin instalación local.

Bash es el shell predeterminado en la mayoría de los sistemas Linux. Es ideal para encadenar comandos con tuberías (pipes), bucles sobre listas de recursos y automatización rápida en servidores Linux y en trabajos de CI. Herramientas como jq analizan la salida JSON, grep filtra líneas y curl llama a las API. Empieza los scripts con set -euo pipefail para que se detengan ante los errores en lugar de continuar a ciegas.

PowerShell es orientado a objetos: los comandos, llamados cmdlets, con nombres en forma Verbo-Sustantivo como Get-AzVM, pasan objetos estructurados en lugar de texto por la tubería, así que puedes filtrar y seleccionar propiedades sin analizar cadenas. Es nativo de la administración de Windows y también se ejecuta en Linux y macOS, lo que lo hace común para la automatización de Azure y Microsoft 365.

Python es un lenguaje de propósito general con SDK oficiales de la nube, como boto3 para AWS y las bibliotecas cliente de Azure y Google Cloud. Es la mejor elección cuando la lógica se vuelve compleja: manejo de errores, reintentos, procesamiento de datos, llamar a varias API o escribir funciones sin servidor.

Sea cual sea el lenguaje, escribe scripts de forma segura: nunca codifiques credenciales de forma fija, usa identidades de carga de trabajo o perfiles, añade una opción de ejecución en seco (dry run) antes de las acciones destructivas, registra lo que hizo el script, maneja la paginación y los límites de tasa, almacena los scripts en Git y pruébalos en no producción primero.

Términos clave

CLI
Interfaz de línea de comandos, como aws, az o gcloud, para gestionar los recursos de la nube desde un terminal o script.
Bash
Un shell y lenguaje de scripting de Unix usado en Linux para la automatización de comandos.
PowerShell
Un shell y lenguaje de scripting basado en objetos cuyos cmdlets usan nombres Verbo-Sustantivo.
SDK
Kit de desarrollo de software: una biblioteca para llamar a las API de la nube desde un lenguaje de programación como Python.
Dry run (ejecución en seco)
Ejecutar un script o comando en un modo que muestra lo que haría sin hacer cambios.
Ejemplo real

Un administrador escribe un script de Python usando el SDK del proveedor que encuentra los volúmenes desvinculados de más de 30 días en cada región, escribe un informe y los borra solo cuando se ejecuta con una bandera --confirm. Se ejecuta cada semana como una función sin servidor programada usando un rol que puede listar y borrar volúmenes y nada más.

Consejo para el examen: Bash pasa texto; PowerShell pasa objetos; Python conviene para la lógica compleja y el trabajo con SDK. Cualquier respuesta de script que codifique claves de acceso de forma fija es incorrecta; usa perfiles, SSO o identidades de carga de trabajo.

Comprueba lo que sabes

¿Qué hace set -euo pipefail al inicio de un script de Bash?

Hace que el script salga ante los errores, ante el uso de variables no definidas y cuando cualquier comando de una tubería falla, en lugar de continuar en silencio.

¿Por qué se dice que PowerShell es orientado a objetos?

Los cmdlets pasan objetos estructurados con propiedades por la tubería, en lugar de texto plano que debe analizarse.
