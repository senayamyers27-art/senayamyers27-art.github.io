Microservicios, arquitectura dirigida por eventos, colas de mensajes y puertas de enlace de API

Una aplicación monolítica se construye y se implementa como una sola unidad: un cambio en cualquier funcionalidad implica reconstruir y volver a implementar todo, y una funcionalidad muy demandada te obliga a escalar todo. Una arquitectura de microservicios divide la aplicación en servicios pequeños e independientes, cada uno dueño de una capacidad de negocio y de sus propios datos, comunicándose por la red mediante API. Los equipos pueden implementar, escalar y elegir tecnología para cada servicio por separado, y la falla de un servicio no tiene por qué tumbar a los demás.

Los microservicios traen sus propios problemas: muchas llamadas de red, resolución de problemas más difícil entre servicios y la necesidad de buena monitorización y trazado. Suelen ejecutarse en contenedores e implementarse mediante canalizaciones automatizadas, porque hacerlo a mano no escala.

La arquitectura dirigida por eventos reduce el acoplamiento estrecho entre servicios. En lugar de que el servicio A llame al servicio B directamente y espere, A publica un evento como OrderPlaced (pedido realizado), y cualquier servicio interesado reacciona a él. Dos bloques de construcción lo sostienen. Una cola de mensajes retiene los mensajes hasta que un consumidor los procesa; normalmente cada mensaje lo maneja un consumidor, y la cola absorbe los picos para que un backend lento no se vea desbordado. Si el procesamiento falla repetidamente, una cola de mensajes fallidos (dead-letter queue) conserva el mensaje malo para investigarlo. Un tema de publicación/suscripción (pub/sub) entrega una copia de cada mensaje a cada suscriptor, de modo que un solo evento puede disparar correo, facturación y analítica a la vez. El resultado es un acoplamiento débil y un procesamiento asíncrono: el emisor no necesita que el receptor esté en línea en ese momento.

Una puerta de enlace de API (API gateway) es la única puerta de entrada para las solicitudes de los clientes a tus servicios. Enruta cada solicitud al servicio backend correcto y centraliza tareas transversales: autenticación y autorización, terminación TLS, limitación de tasa y regulación (throttling), validación de solicitudes, caché y métricas de uso. Los clientes obtienen un único punto de conexión estable aunque los servicios detrás cambien.

Términos clave

Microservice (microservicio)
Un servicio pequeño e implementable de forma independiente, dueño de una capacidad de negocio y que se comunica mediante API.
Message queue (cola de mensajes)
Un búfer que almacena mensajes hasta que un consumidor los procesa, desacoplando a los emisores de los receptores.
Pub/sub
Un patrón de mensajería en el que un mensaje publicado se entrega a cada suscriptor de un tema.
Dead-letter queue (cola de mensajes fallidos)
Una cola que retiene los mensajes que no pudieron procesarse tras un número fijado de intentos.
API gateway (puerta de enlace de API)
Un punto de entrada gestionado que enruta las solicitudes de API a servicios backend y maneja autenticación, regulación y monitorización.
Ejemplo real

Durante una venta navideña, el servicio de pedidos de una tienda en línea escribe cada pedido en una cola de mensajes en lugar de llamar directamente al lento sistema del almacén. Los pedidos se aceptan al instante, la cola crece durante el pico y los trabajadores del almacén la vacían a su propio ritmo sin perder ningún pedido.

Consejo para el examen: Cola significa un consumidor por mensaje y almacenamiento en búfer; pub/sub significa distribución (fan-out) a muchos suscriptores. Una puerta de enlace de API es la respuesta cuando una pregunta menciona un único punto de entrada, limitación de tasa o autenticación delante de muchas API.

Comprueba lo que sabes

¿Cómo ayuda una cola de mensajes cuando un servicio backend es más lento que el frontend?

Almacena los mensajes en búfer, de modo que el frontend puede seguir aceptando trabajo mientras el backend lo procesa a su propio ritmo, desacoplando a ambos.

Nombra tres funciones que una puerta de enlace de API suele proporcionar.

Enrutamiento de solicitudes, autenticación o autorización, y limitación de tasa (también terminación TLS, caché y métricas).
