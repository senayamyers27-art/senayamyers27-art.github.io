Aprovisionamiento de cómputo: elegir tamaño y tipo de instancia, imágenes y plantillas, imágenes doradas

Aprovisionar cómputo significa crear las máquinas virtuales en las que se ejecuta una carga de trabajo, con el tamaño correcto, el software correcto y un proceso repetible.

Empieza por las necesidades de la carga de trabajo, medidas en lugar de adivinadas: CPU, memoria, rendimiento de almacenamiento, ancho de banda de red y cualquier hardware especial como GPU. Elige una familia de instancias que se ajuste al perfil (propósito general, optimizada para cómputo, para memoria, para almacenamiento o acelerada) y luego un tamaño dentro de ella. Comprueba el sistema operativo y la arquitectura del procesador, ya que algunas familias usan procesadores basados en ARM y tu software debe admitirlos. Considera instancias ampliables (burstable) para cargas ligeras y con picos, y elige opciones de almacenamiento y red, como la red mejorada (enhanced networking), que la familia admita. Tras el lanzamiento, monitoriza la utilización y dimensiona correctamente.

Toda VM parte de una imagen: una plantilla que contiene el sistema operativo y, opcionalmente, software y ajustes instalados. Los proveedores publican imágenes base para sistemas operativos comunes, y los mercados (marketplaces) ofrecen imágenes de proveedores, a veces con tarifas de licencia incluidas. Las plantillas de lanzamiento o plantillas de instancia van más allá: almacenan la imagen más el tipo de instancia, la red, los grupos de seguridad, el almacenamiento, el rol de identidad y el script de arranque, de modo que los grupos de autoescalado y los administradores lanzan instancias idénticas cada vez.

Una imagen dorada (golden image) es la imagen aprobada y reforzada de tu organización. Tomas una imagen base, aplicas parches, refuerzo de seguridad como los ajustes del CIS Benchmark, agentes de monitorización y seguridad y configuración estándar, y luego la capturas como una imagen nueva. Las instancias lanzadas desde ella son consistentes y seguras desde el primer arranque, y arrancan más rápido que las instancias que instalan todo en el arranque. Las imágenes doradas deben versionarse y reconstruirse con regularidad, normalmente mediante una canalización automatizada de imágenes, porque una imagen antigua pronto se convierte en una imagen sin parchear.

Hay un equilibrio entre hornear (baking) y arrancar con bootstrap. Hornear pone tanto como sea posible en la imagen, para lanzamientos rápidos y consistentes. El bootstrapping mantiene la imagen pequeña y usa scripts de arranque (por ejemplo datos de usuario de cloud-init) o gestión de configuración para instalar y configurar en el lanzamiento, lo que es más flexible pero más lento y puede fallar en el arranque. Muchos equipos hornean el SO y los agentes y arrancan con bootstrap los ajustes de la aplicación.

Términos clave

Image (imagen)
Una plantilla que contiene un sistema operativo y software opcional, usada para lanzar máquinas virtuales.
Golden image (imagen dorada)
Una imagen aprobada por la organización, parcheada y reforzada, usada como punto de partida estándar para nuevas instancias.
Launch template (plantilla de lanzamiento)
Un conjunto guardado de ajustes de instancia, incluyendo imagen, tamaño, red y script de arranque, usado para lanzamientos consistentes.
User data / cloud-init
Un script de arranque o configuración pasado a una instancia y ejecutado en el primer arranque.
Burstable instance (instancia ampliable)
Un tipo de instancia que acumula créditos de CPU durante periodos ociosos y los gasta para superar su línea base.
Ejemplo real

Un equipo de seguridad mantiene una imagen dorada mensual de Linux construida por una canalización que aplica parches, refuerzo CIS y el agente de monitorización. Los grupos de autoescalado referencian una plantilla de lanzamiento que apunta a la última versión de imagen aprobada, así que cada nuevo servidor web está parcheado y conforme en el momento en que arranca.

Consejo para el examen: Si las nuevas instancias se desvían en la configuración o arrancan sin parchear, la solución es una imagen dorada mantenida al día por una compilación automatizada, usada a través de plantillas de lanzamiento. Recuerda que las imágenes doradas envejecen: deben reconstruirse, no solo crearse una vez.

Comprueba lo que sabes

¿Cuál es la ventaja de hornear el software en una imagen en lugar de instalarlo en el arranque?

Las instancias se lanzan más rápido y de forma más consistente, con menos posibilidades de que una instalación en el arranque falle.

¿Qué almacena una plantilla de lanzamiento además de la imagen?

El tipo de instancia, los ajustes de red y subred, los grupos de seguridad, el almacenamiento, el rol de identidad y los scripts de arranque.
