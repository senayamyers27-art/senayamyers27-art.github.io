CompTIA Cloud+ CV0-004

API, webhooks y formatos de datos (JSON, YAML) para la automatización de la nube

Todo en la nube es, en última instancia, una llamada de API. La consola, la CLI, los SDK y las herramientas de IaC son todos clientes de las mismas API del proveedor, así que entender las API ayuda a automatizar y resolver problemas.

La mayoría de las API de la nube son API de estilo REST sobre HTTPS. Un cliente envía una solicitud con un método, una URL (punto de conexión) que identifica el recurso, cabeceras y a menudo un cuerpo. Los métodos se corresponden con acciones: GET lee, POST crea o dispara una acción, PUT reemplaza, PATCH actualiza parte de un recurso y DELETE lo elimina. Las solicitudes deben autenticarse, normalmente con una solicitud firmada usando credenciales temporales o un token portador (bearer) de OAuth 2.0 en la cabecera Authorization. Las respuestas llevan códigos de estado: 200 OK y 201 Created para el éxito; 400 Bad Request para entrada inválida; 401 Unauthorized cuando falta la autenticación o es inválida; 403 Forbidden cuando estás autenticado pero no permitido; 404 Not Found; 429 Too Many Requests cuando se te limita la tasa; y códigos 5xx para errores del lado del servidor, que normalmente vale la pena reintentar con retroceso exponencial.

Un webhook invierte la dirección. En lugar de que tu script pregunte repetidamente a un servicio si algo ha ocurrido (sondeo o polling), el servicio envía un POST HTTP a una URL que registraste cuando ocurre un evento: se empuja una confirmación, termina una compilación, se dispara una alerta. Los webhooks disparan canalizaciones, notificaciones de chat y funciones de automatización. Protege los receptores de webhooks verificando una firma de secreto compartido en cada solicitud y usando HTTPS.

JSON (JavaScript Object Notation) es el formato habitual para los cuerpos de las API: objetos entre llaves con claves entre comillas, arreglos entre corchetes, cadenas entre comillas dobles, más números, true, false y null. No permite comentarios ni comas finales. YAML es un superconjunto de JSON diseñado para que las personas lo escriban, usado para los manifiestos de Kubernetes, las canalizaciones de CI, los playbooks de Ansible y las plantillas de CloudFormation. Usa la indentación con espacios (nunca tabuladores) para la estructura, guiones para los elementos de lista y pares key: value, y admite comentarios con #.

service:
  name: web
  ports:
    - 80
    - 443
  public: true
```

Los mismos datos en JSON son `{"service": {"name": "web", "ports": [80, 443], "public": true}}`. Una indentación incorrecta en YAML cambia la estructura, lo que es una causa común de despliegues fallidos.

Términos clave

REST API
Una interfaz basada en HTTP donde los recursos se direccionan por URL y se manipulan con métodos como GET, POST, PUT y DELETE.
Webhook
Una devolución de llamada HTTP que un servicio envía a una URL registrada cuando ocurre un evento.
JSON
Un formato de datos de texto ligero de objetos, arreglos, cadenas, números, booleanos y null.
YAML
Un formato de datos amigable para las personas que usa la indentación para la estructura, común en los archivos de configuración.
Exponential backoff (retroceso exponencial)
Reintentar una solicitud fallida tras esperas progresivamente más largas para evitar sobrecargar un servicio.
Ejemplo real

Un equipo registra un webhook en su servicio de alojamiento de Git que hace POST al sistema de CI cada vez que cambia main. La canalización llama entonces a la API de la nube para implementar. Cuando el script de despliegue empieza a recibir respuestas 429 durante un lanzamiento grande, el ingeniero añade retroceso exponencial y los errores se detienen.

Consejo para el examen: 401 significa que la autenticación falló (¿quién eres?); 403 significa autenticado pero no permitido; 429 significa limitación de tasa, así que retrocede y reintenta. Los webhooks te empujan eventos; el sondeo pregunta repetidamente. YAML usa espacios para la indentación, nunca tabuladores.

Comprueba lo que sabes

La llamada de API de un script devuelve 403. ¿Es el problema las credenciales o los permisos?

Los permisos: el llamador estaba autenticado pero no está autorizado para esa acción o recurso.

¿Cuál es la ventaja de un webhook sobre el sondeo?

El servicio te notifica de inmediato cuando ocurre un evento, en lugar de que tu código pregunte repetidamente y malgaste solicitudes.
