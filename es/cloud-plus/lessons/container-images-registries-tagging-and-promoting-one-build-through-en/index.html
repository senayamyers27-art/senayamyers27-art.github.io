Imágenes de contenedor, registros, etiquetado y promoción de una compilación a través de los entornos

Una imagen de contenedor es un paquete de solo lectura que contiene una aplicación, su entorno de ejecución, bibliotecas y valores de configuración predeterminados, construido en capas a partir de un Dockerfile o un archivo de compilación similar. Cada instrucción, como copiar archivos o instalar paquetes, crea una capa; las capas se almacenan en caché y se comparten entre imágenes, lo que acelera las compilaciones y ahorra almacenamiento.

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER 1000
CMD ["python", "app.py"]

Las buenas imágenes parten de una imagen base pequeña y de confianza, instalan solo lo necesario, se ejecutan como un usuario no root y no contienen secretos. Las compilaciones multietapa (multi-stage) compilan el código en una etapa y copian solo el resultado en una imagen final mínima. Las imágenes más pequeñas se descargan más rápido y tienen menos vulnerabilidades.

Las imágenes se almacenan en un registro: un registro público como Docker Hub, o un registro privado como los registros de contenedores que ofrece cada proveedor de nube. Dentro de un registro, un repositorio contiene las versiones de una imagen. Los registros privados se integran con IAM, así que los nodos y las canalizaciones se autentican con identidades de carga de trabajo, y muchos escanean las imágenes al empujar. Coloca los registros cerca de los clústeres que extraen de ellos, y usa la replicación para los despliegues multirregión.

Cada versión de imagen se referencia con una etiqueta, como web:1.4.2, o con un digest, un hash SHA-256 de su contenido (web@sha256:...). Las etiquetas son punteros mutables a menos que el registro imponga la inmutabilidad, así que latest o incluso 1.4.2 pueden moverse a una imagen distinta. Eso hace que los despliegues sean impredecibles, por lo que producción debería usar etiquetas de versión específicas con la inmutabilidad de etiquetas habilitada, o digests. Una convención común es etiquetar tanto con la versión semántica como con el hash de la confirmación de Git.

La promoción significa mover la misma imagen a través de los entornos. La CI compila la imagen una vez, la etiqueta y la empuja. El entorno de prueba implementa esa imagen exacta; cuando pasa, la canalización la promociona a preproducción y luego a producción, quizá añadiendo una etiqueta de entorno o copiándola a un registro de producción, pero nunca reconstruyéndola. Reconstruir podría extraer una imagen base o dependencia más nueva y producir algo que nunca se probó. La firma de imágenes y las políticas de admisión pueden asegurar que los clústeres ejecuten solo imágenes que fueron construidas por tu canalización y pasaron sus escaneos.

Términos clave

Container image (imagen de contenedor)
Un paquete en capas, de solo lectura, de una aplicación y sus dependencias, usado para ejecutar contenedores.
Registry (registro)
Un servicio que almacena y distribuye imágenes de contenedor.
Image tag (etiqueta de imagen)
Una etiqueta legible por humanos, como una versión, que apunta a una imagen específica.
Image digest (digest de imagen)
Un hash de contenido que identifica una imagen de forma única e inmutable.
Image promotion (promoción de imagen)
Implementar la misma imagen construida a través de entornos sucesivos sin reconstruirla.
Ejemplo real

Una canalización compila orders:2.7.0 una vez, la escanea y la empuja al registro con la inmutabilidad de etiquetas habilitada. Prueba y preproducción implementan esa etiqueta, y tras la aprobación producción implementa el mismo digest. Cuando aparece un error, revertir significa volver a implementar orders:2.6.3, que todavía está en el registro.

Consejo para el examen: Evita latest en producción; usa etiquetas de versión inmutables o digests. Compila una vez y promociona la misma imagen; reconstruir por entorno rompe la garantía de que lo que probaste es lo que ejecutas.

Comprueba lo que sabes

¿Por qué implementar la etiqueta latest es arriesgado en producción?

Es un puntero móvil, así que distintos nodos o despliegues pueden extraer distintas imágenes, y no puedes estar seguro de qué versión se está ejecutando ni revertir de forma fiable.

¿Qué identifica una imagen de forma única e inmutable?

Su digest, un hash SHA-256 del contenido de la imagen.
