Azure Container Instances (grupos de contenedores, directivas de reinicio) y Azure Container Apps (revisiones, entrada y reglas de escalado)

Azure ofrece varias formas de ejecutar contenedores sin administrar máquinas virtuales. Dos entran en el alcance de este examen: Azure Container Instances (ACI), para ejecutar contenedores de forma rápida y sencilla, y Azure Container Apps, para ejecutar microservicios y aplicaciones web con escalado automático, revisiones y entrada (ingress) administrada. Ninguno requiere que operes tú mismo un clúster de Kubernetes. La habilidad evaluada es elegir el servicio correcto y configurar sus opciones clave: grupos de contenedores y directivas de reinicio para ACI, y revisiones, entrada y reglas de escalado para Container Apps. ACI inicia un contenedor en segundos y factura por segundo la vCPU y la memoria que usa. La unidad de implementación es un grupo de contenedores (container group): uno o más contenedores programados en el mismo host que comparten un ciclo de vida, una red local (se comunican entre sí por localhost), una dirección IP pública opcional con una etiqueta de nombre DNS y volúmenes montados, como un recurso compartido de Azure Files. Es similar a un pod de Kubernetes. Los grupos de varios contenedores se admiten para contenedores Linux y suelen implementarse desde un archivo YAML o una plantilla de Azure Resource Manager (ARM), por ejemplo un contenedor de aplicación más un sidecar de registro.
