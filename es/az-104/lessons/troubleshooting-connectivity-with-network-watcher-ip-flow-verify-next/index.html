Solución de problemas de conectividad con Network Watcher: IP flow verify, próximo salto, connection troubleshoot y rutas efectivas

Cuando una VM no puede llegar a algo, la causa suele ser una de tres: una regla de un grupo de seguridad de red bloquea el tráfico, una ruta lo envía a un lugar inesperado, o el propio destino no está escuchando o es inalcanzable. Azure Network Watcher proporciona herramientas que prueban cada posibilidad desde el punto de vista de la plataforma Azure. Network Watcher se habilita automáticamente por región cuando creas una VNet, y sus herramientas están en el portal en Network Watcher o en las hojas Help y Connect troubleshoot de una VM.

IP flow verify comprueba si un paquete específico se permitiría o se denegaría hacia o desde una VM. Especificas la VM y la NIC, la dirección (entrante o saliente), el protocolo (TCP o UDP), la IP y el puerto locales, y la IP y el puerto remotos. El resultado es Access allowed o Access denied, más el nombre de la regla de NSG que tomó la decisión, como DenyAllInBound o una regla personalizada. Es la forma más rápida de confirmar o descartar un problema de NSG.

Next hop (próximo salto) te indica a dónde enviaría Azure un paquete desde una VM hacia una IP de destino. Devuelve el tipo de próximo salto, como Internet, VirtualNetwork, VirtualAppliance, VirtualNetworkGateway o None, la dirección IP del próximo salto si la hay, y el ID de la tabla de rutas que contiene la ruta definida por el usuario coincidente. Si el tráfico hacia internet va inesperadamente a un firewall, o a None, next hop lo muestra de inmediato.

Las rutas efectivas (effective routes), que se encuentran en la interfaz de red de una VM (Help > Effective routes), enumeran todas las rutas que se aplican a la NIC: rutas del sistema, rutas de tablas de rutas (UDR), rutas aprendidas por BGP de las puertas de enlace y rutas de emparejamiento, con su origen, estado y próximo salto. Mientras next hop responde '¿a dónde va este paquete?', las rutas efectivas muestran toda la tabla de enrutamiento para que puedas detectar una UDR demasiado amplia o una ruta de emparejamiento que falta. Effective security rules es la vista equivalente para las reglas de NSG combinadas.

Connection troubleshoot prueba una conexión real desde un origen, como una VM, una instancia de un conjunto de escalado o un Application Gateway, hacia una VM, FQDN, URI o dirección IP de destino en un puerto. Informa si la conexión tuvo éxito, la latencia, los saltos a lo largo de la ruta y los problemas que encontró, como un NSG que deniega el tráfico, una ruta hacia None o que el puerto de destino no responde. Para las VM depende de la extensión de VM Network Watcher agent, que el portal puede instalar.

Un orden práctico cuando una VM no puede conectarse: ejecuta connection troubleshoot para obtener un veredicto general; si apunta a una regla, usa IP flow verify para identificar la regla de NSG; si apunta al enrutamiento, usa next hop y las rutas efectivas. Si la vista de Azure indica que el tráfico está permitido y bien enrutado, revisa dentro de la VM (firewall, servicio detenido) o en el destino. La captura de paquetes y los registros de flujo de NSG (o registros de flujo de VNet) ayudan con los problemas intermitentes.

Términos clave

IP flow verify
Una herramienta de Network Watcher que indica si un paquete específico se permite o se deniega y qué regla de NSG lo decidió.
Next hop (próximo salto)
Una herramienta de Network Watcher que muestra el tipo de próximo salto, la IP y la tabla de rutas para el tráfico de una VM hacia un destino.
Effective routes (rutas efectivas)
El conjunto completo de rutas del sistema, definidas por el usuario, BGP y de emparejamiento aplicadas a una interfaz de red.
Connection troubleshoot
Una herramienta de Network Watcher que prueba una conexión de extremo a extremo e informa sobre la accesibilidad, la latencia, los saltos y los problemas.
Ejemplo real

Una VM no puede llegar a la API de un socio en 203.0.113.10 en el puerto 443. Connection troubleshoot informa que la conexión es inalcanzable. Next hop desde la VM hacia esa dirección devuelve VirtualAppliance 10.0.1.4 desde la tabla de rutas rt-spokes, lo que muestra que el tráfico va al firewall, donde el administrador encuentra que falta una regla de permitir para la dirección del socio.

Consejo para el examen: ¿Bloqueado por un NSG? IP flow verify nombra la regla. ¿Ruta incorrecta? Next hop muestra el próximo salto y la tabla de rutas; las rutas efectivas muestran la tabla completa. ¿Prueba de extremo a extremo con latencia y saltos? Connection troubleshoot.

Comprueba lo que sabes

¿Qué herramienta te indica la regla de NSG exacta que deniega RDP hacia una VM?

IP flow verify.

¿Qué herramienta muestra que una ruta definida por el usuario está enviando el tráfico hacia internet a una aplicación virtual?

Next hop (las rutas efectivas de la NIC también muestran la ruta).

¿Qué necesita connection troubleshoot en una VM de origen?

La extensión de VM Network Watcher agent.
