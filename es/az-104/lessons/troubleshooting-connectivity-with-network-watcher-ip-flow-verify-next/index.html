Solución de problemas de conectividad con Network Watcher: IP flow verify, próximo salto, connection troubleshoot y rutas efectivas

Cuando una máquina virtual (VM) no puede llegar a algo, la causa suele ser una de tres: una regla de grupo de seguridad de red (NSG) bloquea el tráfico, una ruta lo envía a un lugar inesperado, o el propio destino no está escuchando o no es accesible. Azure Network Watcher proporciona herramientas que prueban cada posibilidad desde el punto de vista de la plataforma Azure, sin iniciar sesión en la VM. Network Watcher se habilita automáticamente por región cuando creas una red virtual, y sus herramientas están en el portal, en Network Watcher o en las hojas Help y Connection troubleshoot de una VM.

IP flow verify comprueba si un paquete específico se permitiría o se denegaría hacia o desde una VM. Especificas la VM y la NIC, la dirección (entrante o saliente), el protocolo (TCP o UDP), la IP y el puerto locales, y la IP y el puerto remotos. El resultado es Access allowed o Access denied, más el nombre de la regla de NSG que tomó la decisión, como DenyAllInBound o una regla personalizada. Es la forma más rápida de demostrar o descartar un problema de NSG. El equivalente en la CLI es az network watcher test-ip-flow --vm vm-web --direction Inbound --protocol TCP --local 10.1.0.4:443 --remote 203.0.113.10:50000.

Próximo salto (next hop) te indica a dónde enviaría Azure un paquete desde una VM hacia una IP de destino. Devuelve el tipo de próximo salto, como Internet, VirtualNetwork, VirtualAppliance, VirtualNetworkGateway o None, la dirección IP del próximo salto si la hay y el ID de la tabla de rutas que contiene la ruta definida por el usuario (UDR) que coincide. Si el tráfico hacia internet va inesperadamente a un firewall, o a None, el próximo salto lo muestra de inmediato: az network watcher show-next-hop --vm vm-web --source-ip 10.1.0.4 --dest-ip 10.20.0.5.

Las rutas efectivas (effective routes), que se encuentran en la interfaz de red de una VM en Help > Effective routes, enumeran todas las rutas que se aplican a la NIC: rutas del sistema, rutas de tablas de rutas, rutas aprendidas por BGP (Border Gateway Protocol) desde las puertas de enlace y rutas de emparejamiento, con su origen, estado y próximo salto. Mientras que el próximo salto responde '¿a dónde va este paquete?', las rutas efectivas muestran toda la tabla de enrutamiento para que puedas detectar una UDR demasiado amplia o una ruta de emparejamiento que falta. Las reglas de seguridad efectivas son la vista equivalente para las reglas de NSG combinadas de la subred y de la NIC.

Connection troubleshoot prueba una conexión real desde un origen, como una VM, una instancia de un conjunto de escalado o un Application Gateway, hacia una VM, un FQDN (nombre de dominio completo), un URI o una dirección IP de destino en un puerto. Informa si la conexión tuvo éxito, la latencia, los saltos a lo largo de la ruta y los problemas que encontró, como un NSG que deniega el tráfico, una ruta hacia None o que el puerto de destino no responde. Para las VM depende de la extensión de VM del agente de Network Watcher, que el portal puede instalar por ti. Un orden práctico cuando una VM no puede conectarse: ejecuta connection troubleshoot para obtener un veredicto general; si apunta a una regla, usa IP flow verify para identificar la regla de NSG; si apunta al enrutamiento, usa el próximo salto y las rutas efectivas. Si la vista de Azure dice que el tráfico está permitido y enrutado correctamente, busca dentro de la VM (firewall del sistema operativo, servicio que no se está ejecutando) o en el destino. La captura de paquetes y los registros de flujo ayudan con los problemas intermitentes.

Veamos un ejemplo práctico. Después de que el equipo de redes agrega una tabla de rutas a la subred de aplicación, vm-app1 ya no puede llegar a una API en 10.30.0.8 en una VNet emparejada. Connection troubleshoot informa que el destino es inaccesible. IP flow verify saliente en TCP 443 dice Access allowed por AllowVnetOutBound, así que el NSG no es el problema. El próximo salto hacia 10.30.0.8 devuelve VirtualAppliance 10.0.1.4 y el ID de la tabla de rutas nueva. Las rutas efectivas muestran una ruta definida por el usuario para 10.30.0.0/16 con próximo salto VirtualAppliance; como tiene el mismo prefijo que la ruta de emparejamiento, la UDR gana, y el firewall no tiene ninguna regla que permita este tráfico. Agregar una regla en el firewall restablece la conectividad, y connection troubleshoot ahora informa Reachable con la latencia.

Errores comunes: usar IP flow verify para diagnosticar un problema de enrutamiento (solo evalúa reglas de NSG); esperar que el próximo salto te informe sobre los NSG; olvidar que IP flow verify necesita que la VM esté en ejecución; probar la entrada cuando la pregunta trata sobre la salida; omitir la extensión del agente de Network Watcher para connection troubleshoot; y suponer que, porque Azure permite el tráfico, el firewall del sistema operativo invitado también lo permite.

Las preguntas del examen asocian síntomas con herramientas. 'Determinar qué regla de NSG bloquea el tráfico' significa IP flow verify. 'Determinar a dónde se envía el tráfico' o 'identificar la tabla de rutas que afecta al tráfico' significa próximo salto. 'Ver todas las rutas aplicadas a una NIC' significa rutas efectivas. 'Probar la conectividad de extremo a extremo con latencia y saltos' significa connection troubleshoot. 'Capturar paquetes para analizarlos' significa captura de paquetes, y 'registrar todos los flujos de tráfico' significa registros de flujo.

Términos clave

Network Watcher
Servicio regional de Azure con herramientas de diagnóstico y supervisión para los recursos de red virtual.
IP flow verify
Herramienta que prueba si un paquete específico se permite o se deniega hacia o desde una VM e identifica la regla de NSG responsable.
Próximo salto (next hop)
Herramienta que muestra a dónde enviará Azure un paquete desde una VM, incluidos el tipo de próximo salto, la IP y la tabla de rutas.
Rutas efectivas (effective routes)
La lista completa de rutas del sistema, definidas por el usuario, BGP y de emparejamiento aplicadas a una interfaz de red.
Connection troubleshoot
Herramienta que prueba una conexión real desde un origen hacia un destino e informa accesibilidad, latencia, saltos y problemas.
Agente de Network Watcher (Network Watcher agent)
Extensión de VM necesaria para connection troubleshoot, la captura de paquetes y Connection Monitor desde VM de Azure.
Ejemplo real

Los usuarios informan que una VM web dejó de responder en el puerto 443 después de un cambio de seguridad. IP flow verify, ejecutado como entrante para TCP 443 desde una dirección de internet, devuelve Access denied por una regla personalizada llamada Deny-All-Web con prioridad 150, que un colega agregó por encima de la regla Allow existente con prioridad 200. Cambiar la prioridad de la regla Allow a 140 soluciona el problema, y ahora IP flow verify informa Access allowed.

Consejo para el examen: ¿Bloqueado por un NSG? IP flow verify identifica la regla. ¿Ruta incorrecta? El próximo salto muestra el próximo salto y la tabla de rutas, y las rutas efectivas muestran la tabla completa. ¿Prueba de extremo a extremo con latencia y saltos? Connection troubleshoot.

Comprueba lo que sabes

¿Qué herramienta te indica la regla de NSG exacta que deniega un paquete?

IP flow verify, que devuelve Access allowed o Access denied y el nombre de la regla que decidió.

El tráfico de internet de una VM pasa inesperadamente por un firewall. ¿Qué herramienta muestra por qué?

El próximo salto, que muestra el tipo de próximo salto (VirtualAppliance), su dirección IP y la tabla de rutas que contiene la ruta coincidente.

¿Cuál es la diferencia entre el próximo salto y las rutas efectivas?

El próximo salto evalúa un destino; las rutas efectivas enumeran todas las rutas aplicadas a la NIC con su origen y estado.

¿Qué requiere connection troubleshoot en una VM de Azure de origen?

La extensión de VM del agente de Network Watcher, que el portal puede instalar automáticamente.
