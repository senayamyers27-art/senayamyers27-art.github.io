Network Watcher y Connection Monitor

Azure Network Watcher es el servicio regional que proporciona herramientas de supervisión, diagnóstico y registro para los recursos de las redes virtuales de Azure, como máquinas virtuales (VM), puertas de enlace VPN y puertas de enlace de aplicaciones. Se habilita automáticamente en cada región cuando creas o actualizas una red virtual allí, y aparece en el portal como un recurso llamado NetworkWatcher_<region> en un grupo de recursos llamado NetworkWatcherRG. Supervisa la ruta de red y la configuración, no la aplicación que se ejecuta en tus VM.

Sus herramientas se agrupan en tres categorías. Supervisión: Topology, que dibuja los recursos de una red y cómo se conectan, y Connection Monitor, para comprobaciones continuas. Herramientas de diagnóstico de red, usadas para investigaciones puntuales: IP flow verify, diagnóstico de NSG (grupo de seguridad de red), próximo salto, reglas de seguridad efectivas, connection troubleshoot, captura de paquetes (captura el tráfico hacia y desde una VM en un archivo para analizarlo) y VPN troubleshoot (diagnostica una puerta de enlace o una conexión VPN). Tráfico: los registros de flujo (flow logs), que registran el tráfico IP que pasa por los NSG o las redes virtuales, y el análisis de tráfico (traffic analytics), que procesa los registros de flujo en un área de trabajo de Log Analytics para mostrar patrones de tráfico, los mayores emisores (top talkers) y flujos inusuales. Los registros de flujo de red virtual son los sucesores de los antiguos registros de flujo de NSG, que se están retirando.

Connection Monitor proporciona supervisión continua de extremo a extremo de la conectividad entre puntos de conexión. Mientras que connection troubleshoot responde '¿puedo conectarme ahora mismo?', Connection Monitor responde '¿esta conexión estuvo en buen estado toda la semana y qué tan rápida fue?'. Es la herramienta para seguir la latencia y la pérdida de paquetes entre los niveles de una aplicación, entre Azure y la red local, o desde Azure hacia un punto de conexión externo, como la API de un socio.

Construyes un monitor de conexión a partir de grupos de prueba (test groups). Cada grupo de prueba tiene orígenes, como VM o conjuntos de escalado de Azure con la extensión del agente de Network Watcher, o máquinas locales y habilitadas para Arc con Azure Monitor Agent; destinos, como VM de Azure, direcciones IP, URL o nombres de dominio completos (FQDN); y configuraciones de prueba. Una configuración de prueba define el protocolo (TCP, HTTP o ICMP), el puerto, la frecuencia de prueba y los umbrales de éxito, por ejemplo 'comprobaciones fallidas por debajo del 5 por ciento y tiempo de ida y vuelta por debajo de 100 milisegundos'. Connection Monitor ejecuta las pruebas de forma continua y almacena los resultados en un área de trabajo de Log Analytics.

Los resultados aparecen en el panel de Connection Monitor, con el estado de cada par de origen y destino, gráficos del tiempo de ida y vuelta y de las comprobaciones fallidas, y una topología salto a salto que muestra en qué punto de la ruta ocurre un problema, como una pérdida en un firewall o una latencia alta en un salto de un proveedor de internet. Connection Monitor emite métricas, así que puedes crear reglas de alerta de métricas sobre ellas, por ejemplo alertar cuando ChecksFailedPercent supera un umbral, y enrutar las alertas mediante grupos de acciones.

Veamos un ejemplo práctico. Una tienda en línea en Azure llama a la API de pagos de un socio y a una base de datos local a través de una VPN de sitio a sitio. Los clientes informan ocasionalmente pagos lentos por la noche. El equipo de redes crea un monitor de conexión con dos grupos de prueba: las VM web hacia la URL de la API del socio en HTTPS 443, y las VM web hacia la IP de la base de datos local en TCP 1433, cada uno probado cada 30 segundos con un umbral de 150 milisegundos de tiempo de ida y vuelta. Agregan una alerta de métricas sobre las comprobaciones fallidas. Dos días después, el panel muestra que la latencia hacia la base de datos sube cada noche en un salto dentro de la ruta VPN; ejecutar VPN troubleshoot en la puerta de enlace revela un túnel que se renegocia repetidamente, lo que el proveedor corrige.

Errores comunes: usar connection troubleshoot cuando la pregunta pide supervisión continua con historial; olvidar la extensión del agente de Network Watcher en los orígenes que son VM de Azure; esperar que Connection Monitor explique qué regla de NSG bloqueó el tráfico (eso es IP flow verify); eliminar el grupo de recursos NetworkWatcherRG y luego preguntarse por qué las herramientas dejan de funcionar en una región; y esperar que los registros de flujo muestren el contenido de los paquetes, cuando registran metadatos del flujo como direcciones, puertos y decisiones de permiso o denegación.

Las preguntas del examen asocian necesidades con herramientas. Un '¿por qué no puede conectarse esta VM?' puntual apunta a IP flow verify, al próximo salto o a connection troubleshoot. 'Supervisar continuamente la latencia y la pérdida de paquetes' o 'alertar cuando la conectividad con un punto de conexión se degrade' apunta a Connection Monitor. 'Analizar quién se comunicó con quién' o 'identificar los mayores emisores' apunta a los registros de flujo con análisis de tráfico. 'El túnel de sitio a sitio está caído' apunta a VPN troubleshoot. 'Capturar tráfico para analizarlo con Wireshark' apunta a la captura de paquetes, y 'visualizar los recursos y sus conexiones' apunta a Topology.

Términos clave

Network Watcher
Servicio regional que ofrece herramientas de supervisión, diagnóstico y registro de tráfico para las redes de Azure.
Connection Monitor
Función de Network Watcher que prueba de forma continua la conectividad, la latencia y la pérdida de paquetes entre puntos de conexión.
Grupo de prueba (test group)
Unidad de Connection Monitor que combina orígenes, destinos y configuraciones de prueba.
Configuración de prueba (test configuration)
El protocolo, el puerto, la frecuencia y los umbrales de éxito que se usan en las comprobaciones de Connection Monitor.
Registros de flujo (flow logs)
Registros de los flujos de tráfico IP a través de NSG o redes virtuales, almacenados en una cuenta de almacenamiento.
Análisis de tráfico (traffic analytics)
Función que procesa los registros de flujo en Log Analytics para mostrar patrones de tráfico y los mayores emisores.
VPN troubleshoot
Herramienta de diagnóstico que comprueba el estado de una puerta de enlace o una conexión VPN e informa los problemas.
Ejemplo real

Un banco debe demostrar que su nivel web en Azure puede llegar en todo momento a un servicio local de detección de fraude en menos de 50 milisegundos. El equipo de redes configura Connection Monitor con un grupo de prueba desde las VM web hacia la IP del servicio en TCP 8443, un umbral de 50 milisegundos y una alerta de métricas que avisa al ingeniero de redes de guardia mediante un grupo de acciones cada vez que el umbral se supera durante cinco minutos.

Consejo para el examen: Connection Monitor sirve para la supervisión continua con historial y alertas; connection troubleshoot es una prueba puntual. Los orígenes que son VM de Azure necesitan la extensión del agente de Network Watcher, y los resultados se almacenan en un área de trabajo de Log Analytics.

Comprueba lo que sabes

¿Qué herramienta mide de forma continua la latencia y la pérdida de paquetes desde VM de Azure hacia un servidor local y conserva el historial?

Connection Monitor de Network Watcher.

¿Qué debe estar instalado en una VM de Azure usada como origen de Connection Monitor?

La extensión de VM del agente de Network Watcher.

¿Qué función de Network Watcher ayuda a identificar los mayores emisores de una red durante la última semana?

Los registros de flujo analizados con el análisis de tráfico en un área de trabajo de Log Analytics.

Una conexión VPN de sitio a sitio se cae continuamente. ¿Qué herramienta de Network Watcher la diagnostica?

VPN troubleshoot, que comprueba el estado de la puerta de enlace y de la conexión y devuelve registros detallados.
