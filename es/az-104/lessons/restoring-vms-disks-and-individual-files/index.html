Restaurar VM, discos y archivos individuales

Una copia de seguridad solo vale tanto como tu capacidad de restaurarla. Azure Backup ofrece varios tipos de restauración para las máquinas virtuales (VM) de Azure, y cada uno se ajusta a una situación diferente. Inicias una restauración desde el elemento de copia de seguridad del almacén o desde la hoja Backup de la VM, eliges un punto de recuperación (coherente frente a bloqueos, coherente con el sistema de archivos o coherente con la aplicación, y los más recientes suelen estar disponibles como instantáneas de restauración instantánea, que son las más rápidas) y luego eliges un tipo de restauración. Saber qué tipo de restauración corresponde a un escenario es exactamente lo que evalúa el examen.

Create new virtual machine crea una VM nueva a partir del punto de recuperación en la red virtual y la subred que elijas, con un nombre nuevo. Es la forma más rápida de recuperar una máquina funcional con una configuración básica, pero ofrece una personalización limitada. Restore disks crea discos administrados a partir del punto de recuperación en un grupo de recursos de destino, usando una cuenta de almacenamiento provisional (staging), y además genera una plantilla que puedes personalizar para crear la VM. Úsalo cuando necesites una configuración que la restauración rápida no puede manejar, como un tamaño específico, un conjunto de disponibilidad o extensiones, o cuando solo quieras los discos, por ejemplo para conectar uno a otra VM y copiar datos desde él.

Replace existing restaura los discos sobre los de la VM existente y conserva la configuración de la VM, como su nombre, su interfaz de red y su configuración de IP. La VM todavía debe existir, y Azure toma una instantánea de los discos actuales antes de reemplazarlos para que puedas volver atrás. Es la opción natural cuando una VM está intacta pero sus datos están dañados, por ejemplo después de una actualización fallida. La restauración entre regiones realiza las mismas operaciones en la región secundaria emparejada, para almacenes configurados con almacenamiento con redundancia geográfica y restauración entre regiones. Restaurar una VM a un momento anterior a una infección de ransomware también es la razón por la que importan la eliminación temporal y la inmutabilidad.

A menudo no necesitas la VM completa, solo algunos archivos. File Recovery te permite montar un punto de recuperación como unidades locales: selecciona File Recovery, elige el punto de recuperación y descarga un script (un ejecutable para Windows, un script de Python para Linux). Al ejecutarlo en una máquina, la VM original u otra con un sistema operativo compatible, se conectan los discos del punto de recuperación como volúmenes mediante iSCSI (Internet Small Computer Systems Interface). Los exploras, copias los archivos que necesitas y luego seleccionas Unmount disks en el portal. La conexión se mantiene solo durante un tiempo limitado, y el script requiere acceso saliente a los puntos de conexión de Azure.

Otros orígenes de datos se restauran de forma diferente. Azure Disk Backup en un almacén de Backup restaura una instantánea como un disco administrado nuevo, que luego conectas a una VM; nunca sobrescribe el disco original. Las copias de seguridad de Azure Files pueden restaurar el recurso compartido completo o archivos y carpetas individuales, en la ubicación original (sobrescribiendo u omitiendo los conflictos) o en un recurso compartido alternativo. SQL Server en una VM se puede restaurar a un momento específico usando las copias de seguridad de registros, ya sea sobrescribiendo la base de datos o como una base de datos nueva. Desde la línea de comandos, az backup recoverypoint list muestra los puntos de recuperación disponibles de un elemento, y az backup job list --operation Restore te permite seguir un trabajo de restauración hasta que termine.

Veamos un ejemplo práctico. Llegan tres solicitudes diferentes el mismo día. Un usuario eliminó una carpeta de hojas de cálculo en el servidor de archivos vm-fs1 el martes pasado: usas File Recovery con el punto de recuperación del martes, ejecutas el script en vm-fs1, copias la carpeta de vuelta y desmontas. Un parche dañó el sistema operativo de vm-app2, pero su nombre, su IP y sus reglas de firewall deben mantenerse iguales: usas Replace existing con el punto de recuperación anterior al parche. Un auditor quiere una copia de vm-db3 tal como estaba a fin de mes, en una red aislada y con un tamaño mayor: usas Restore disks y luego implementas la plantilla generada con el tamaño y la red cambiados.

Errores comunes: restaurar una VM completa cuando solo se necesitan unos pocos archivos; elegir Create new cuando la identidad y la IP de la VM deben mantenerse iguales; esperar que Replace existing funcione después de que se eliminó la VM; olvidar desmontar los discos de File Recovery; y esperar que la restauración de un disco desde un almacén de Backup sobrescriba el disco original.

En las preguntas del examen, 'unos pocos archivos' o 'una sola carpeta' significa File Recovery; 'la VM todavía existe pero los datos están mal, conservar la configuración' significa Replace existing; 'configuración personalizada' o 'solo los discos' significa Restore disks; 'la forma más rápida de obtener una VM nueva que funcione' significa Create new; 'restaurar en la región emparejada' significa restauración entre regiones.

Términos clave

Punto de recuperación (recovery point)
Copia de los datos protegidos en un momento dado a partir de la cual puedes restaurar.
Create new virtual machine
Tipo de restauración que crea rápidamente una VM nueva a partir de un punto de recuperación con una configuración básica.
Restore disks
Tipo de restauración que crea discos administrados y una plantilla personalizable en lugar de una VM terminada.
Replace existing
Tipo de restauración que sobrescribe los discos de una VM existente y conserva su configuración.
File Recovery
Función que monta un punto de recuperación como unidades mediante un script descargado para poder copiar archivos individuales.
iSCSI
Internet Small Computer Systems Interface, el protocolo que usa File Recovery para conectar los discos del punto de recuperación como volúmenes.
Ejemplo real

Una asistente legal sobrescribe por accidente una plantilla de contrato en una VM de servidor de archivos Windows. La administradora abre la hoja Backup de la VM, selecciona File Recovery, elige el punto de recuperación de la noche anterior, descarga el script ejecutable y lo ejecuta en el servidor de archivos. Aparece una letra de unidad nueva con el volumen anterior, copia la plantilla de vuelta a su carpeta y luego desmonta los discos desde el portal. Toda la tarea lleva quince minutos y la VM nunca se desconecta.

Consejo para el examen: Unos pocos archivos significa el script de File Recovery. La VM existe pero los datos están mal significa Replace existing. Configuración personalizada de la VM o solo los discos significa Restore disks. Una VM nueva rápida significa Create new, y las copias de seguridad de discos en un almacén de Backup se restauran como discos nuevos.

Comprueba lo que sabes

Un usuario necesita tres archivos de la copia de seguridad de la semana pasada de una VM. ¿Qué opción de restauración deberías usar?

File Recovery, que monta el punto de recuperación como unidades mediante un script para que puedas copiar solo esos archivos.

Los datos de una VM están dañados, pero su nombre y su configuración de red deben mantenerse iguales. ¿Qué tipo de restauración corresponde?

Replace existing, que restaura los discos sobre la VM existente y conserva su configuración.

¿Cuándo elegirías Restore disks en lugar de Create new virtual machine?

Cuando necesitas una configuración personalizada, como un tamaño específico o un conjunto de disponibilidad, o solo quieres los discos para conectarlos en otro lugar.

¿Cómo se restaura un disco administrado protegido por Azure Disk Backup?

Como un disco administrado nuevo creado a partir de la instantánea, que luego conectas a una VM; el disco original no se sobrescribe.
