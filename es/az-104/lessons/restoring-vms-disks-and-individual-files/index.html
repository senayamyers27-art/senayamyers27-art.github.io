Restaurar VM, discos y archivos individuales

Una copia de seguridad solo vale lo que vale tu capacidad de restaurarla. Azure Backup ofrece varios tipos de restauración para las VM de Azure, y cada uno se ajusta a una situación distinta. Inicias una restauración desde el elemento de copia de seguridad del almacén o desde la hoja Backup de la VM, eliges un punto de recuperación (coherente ante bloqueos, coherente con el sistema de archivos o coherente con la aplicación, y los más recientes suelen estar disponibles como instantáneas de instant restore) y luego eliges un tipo de restauración.

Create new virtual machine crea una VM nueva a partir del punto de recuperación en la región, la red virtual y la subred que elijas, con un nombre nuevo. Es la forma más rápida de recuperar una máquina funcional con una configuración básica. Como ofrece una personalización limitada, no es adecuada para todas las configuraciones.

Restore disks crea discos administrados a partir del punto de recuperación en un grupo de recursos de destino, usando una cuenta de almacenamiento provisional (staging), y también genera una plantilla que puedes personalizar para crear la VM. Úsala cuando necesites cambiar configuraciones que la restauración rápida no puede manejar, como un tamaño específico, un conjunto de disponibilidad o extensiones, o cuando solo quieras los discos, por ejemplo para conectar uno a otra VM y copiar datos de él.

Replace existing restaura los discos sobre los de la VM existente, conservando la configuración de la VM, como su nombre y su configuración de red. La VM debe seguir existiendo, y Azure toma una instantánea de los discos actuales antes de reemplazarlos para que puedas volver atrás. Es la opción natural cuando una VM está intacta pero sus datos están dañados, por ejemplo después de una actualización fallida.

La restauración entre regiones realiza las mismas operaciones en la región secundaria emparejada, para almacenes configurados con almacenamiento con redundancia geográfica y restauración entre regiones. Restaurar una VM también es la forma de recuperarse a un momento anterior a una infección de ransomware, y por eso importan la eliminación temporal y la inmutabilidad.

A menudo no necesitas toda la VM, solo algunos archivos. File recovery (recuperación de archivos) te permite montar un punto de recuperación como unidades locales: seleccionas File Recovery, eliges el punto de recuperación y descargas un script (un ejecutable para Windows, un script de Python para Linux). Al ejecutarlo en una máquina, la VM original u otra con un SO compatible, conecta los discos del punto de recuperación como volúmenes mediante iSCSI (Internet Small Computer Systems Interface). Los exploras, copias los archivos que necesitas y luego desmontas los discos desde el portal. La conexión solo se mantiene durante un tiempo limitado, y debes desmontar al terminar.

Otros orígenes de datos se restauran de otra manera. Azure Disk Backup en un almacén de Backup restaura una instantánea como un disco administrado nuevo, que conectas a una VM. Las copias de seguridad de Azure Files pueden restaurar todo el recurso compartido o archivos y carpetas individuales, en la ubicación original (sobrescribiendo u omitiendo los conflictos) o en un recurso compartido alternativo. SQL Server en una VM se puede restaurar a un momento dado usando copias de seguridad de registros.

Términos clave

Create new virtual machine
Un tipo de restauración que crea una VM nueva a partir de un punto de recuperación con una configuración básica.
Restore disks
Un tipo de restauración que crea discos administrados y una plantilla, lo que permite una VM personalizada o la recuperación de datos.
Replace existing
Un tipo de restauración que reemplaza los discos de una VM existente después de tomar una instantánea de sus discos actuales.
File recovery (recuperación de archivos)
Montar los discos de un punto de recuperación en una máquina con un script descargado para copiar archivos individuales.
Ejemplo real

Un usuario elimina una carpeta de informes en una VM de servidor de archivos, y por otro lado una actualización daña una VM de aplicación. Para el servidor de archivos, el administrador usa File Recovery, ejecuta el script en la VM, copia la carpeta desde el volumen de recuperación montado y desmonta. Para la VM de aplicación, usa Replace existing con el punto de recuperación de anoche, conservando el nombre, la IP y la configuración de la VM.

Consejo para el examen: ¿Necesitas algunos archivos? Script de File Recovery. ¿La VM existe pero los datos están mal? Replace existing. ¿Necesitas una configuración de VM personalizada o solo los discos? Restore disks. ¿Una VM nueva rápida? Create new. Las copias de seguridad de discos en un almacén de Backup se restauran como discos nuevos.

Comprueba lo que sabes

El SO de una VM está dañado, pero quieres conservar el mismo recurso de VM y su configuración de red. ¿Qué tipo de restauración usas?

Replace existing.

Necesitas restaurar una VM en un conjunto de disponibilidad con un tamaño específico. ¿Qué tipo de restauración te da ese control?

Restore disks, y luego crear la VM a partir de los discos o de la plantilla generada.

¿Cómo recuperas un solo archivo eliminado de una copia de seguridad de una VM de Azure?

Usa File Recovery: descarga y ejecuta el script para montar el punto de recuperación como unidades, copia el archivo y luego desmonta.
