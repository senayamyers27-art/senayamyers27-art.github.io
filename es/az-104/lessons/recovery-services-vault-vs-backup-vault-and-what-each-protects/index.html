Almacén de Recovery Services vs. almacén de Backup y qué protege cada uno

Azure Backup protege los datos tomando copias de seguridad según una programación y almacenándolas en un almacén (vault), una entidad de almacenamiento administrada por Azure que contiene los puntos de recuperación y las directivas de copia de seguridad. Nunca administras tú mismo las cuentas de almacenamiento subyacentes. Azure tiene dos tipos de almacén, y cada uno admite un conjunto diferente de cargas de trabajo. Elegir el almacén correcto para un origen de datos es una pregunta clásica del examen, porque no puedes, por ejemplo, hacer copia de seguridad de una máquina virtual (VM) de Azure en un almacén de Backup, ni de discos administrados como elementos independientes en un almacén de Recovery Services.

Un almacén de Recovery Services (Recovery Services vault) es el tipo de almacén original. Protege: VM de Azure (Windows y Linux, la VM completa con todos sus discos); bases de datos de SQL Server y SAP HANA que se ejecutan dentro de VM de Azure; recursos compartidos de Azure Files; archivos, carpetas y estado del sistema locales mediante el agente MARS (Microsoft Azure Recovery Services); y cargas de trabajo locales mediante Microsoft Azure Backup Server (MABS) o System Center Data Protection Manager (DPM). Un almacén de Recovery Services también es donde se configura la replicación de Azure Site Recovery, así que el mismo tipo de almacén sirve tanto para copias de seguridad como para recuperación ante desastres.

Un almacén de Backup (Backup vault) es el tipo de almacén más reciente, usado por los orígenes de datos más nuevos. Protege discos administrados de Azure (Azure Disk Backup, mediante instantáneas incrementales), Azure Blobs (copia de seguridad operativa y almacenada), Azure Database for PostgreSQL y clústeres de Azure Kubernetes Service (AKS), entre otros. Si una pregunta plantea dónde hacer copia de seguridad de discos administrados individuales con una programación frecuente, o de datos de blobs frente a eliminaciones accidentales, la respuesta es un almacén de Backup. Crear cada tipo desde la línea de comandos muestra la diferencia de proveedores de recursos:

az backup vault create --resource-group rg-bcdr --name rsv-prod-weu --location westeurope
az dataprotection backup-vault create --resource-group rg-bcdr --vault-name bv-prod-weu \
  --location westeurope --type SystemAssigned \
  --storage-settings "[{type:'LocallyRedundant',datastore-type:'VaultStore'}]"

Algunas reglas se aplican a ambos. El almacén debería estar en la misma región que los recursos que protege, y para la copia de seguridad de VM de Azure debe estarlo. Eliges la redundancia del almacenamiento de copias de seguridad del almacén (localmente redundante, con redundancia de zona o con redundancia geográfica) y deberías configurarla antes de proteger el primer elemento, porque no se puede cambiar después de proteger elementos. El almacenamiento con redundancia geográfica es necesario si quieres la restauración entre regiones. Ambos tipos de almacén admiten eliminación temporal, inmutabilidad y roles de control de acceso basado en roles (RBAC) como Backup Contributor, Backup Operator y Backup Reader. Administras todo desde un solo lugar: el Business Continuity Center del portal (el sucesor de Backup center) ofrece una vista única de los elementos protegidos, los trabajos, las directivas y los almacenes de ambos tipos, entre suscripciones y regiones. También puedes configurar la copia de seguridad directamente desde un recurso, por ejemplo en la hoja Backup de una VM, donde eliges o creas un almacén y una directiva.

Veamos un ejemplo práctico. Una empresa en West Europe necesita proteger: veinte VM de Azure, una base de datos de SQL Server que se ejecuta en una de ellas, un recurso compartido de Azure Files, las carpetas Documentos de una flota de portátiles, un conjunto de discos administrados que usa un conjunto de escalado y una cuenta de almacenamiento con contratos. La administradora crea un almacén de Recovery Services en West Europe para las VM, la base de datos SQL (como carga de trabajo de SQL en VM de Azure), el recurso compartido de archivos y las copias de seguridad del agente MARS. Crea un almacén de Backup en West Europe para los discos administrados y la copia de seguridad de blobs. Ambos almacenes se configuran con almacenamiento con redundancia geográfica antes de proteger el primer elemento, porque los auditores exigen la restauración entre regiones.

Errores comunes: elegir un almacén de Backup para VM de Azure; crear el almacén en una región diferente a la de las VM y luego descubrir que las VM no aparecen; intentar cambiar la redundancia del almacenamiento después de proteger elementos; confundir Azure Site Recovery (replicación para recuperación ante desastres) con Azure Backup (copias a un momento dado), aunque ambos usan un almacén de Recovery Services; y suponer que un origen de datos nuevo usa el tipo de almacén antiguo sin comprobarlo.

La redacción del examen delata la respuesta. 'VM de Azure', 'SQL Server en una VM de Azure', 'Azure Files', 'agente MARS', 'archivos y carpetas locales' o 'Site Recovery' significa un almacén de Recovery Services. 'Discos administrados', 'blobs', 'Azure Database for PostgreSQL' o 'AKS' significa un almacén de Backup. 'El almacén en otra región no ve la VM' significa que el almacén debe estar en la región de la VM. 'Se debe restaurar en la región emparejada' significa almacenamiento con redundancia geográfica configurado antes de la protección. Una regla mnemotécnica sencilla: almacén de Recovery Services para servidores y lo que se ejecuta en ellos; almacén de Backup para los orígenes de datos de PaaS y almacenamiento más nuevos.

Términos clave

Azure Backup
El servicio de Azure que toma copias de seguridad programadas y basadas en directivas y almacena los puntos de recuperación en un almacén.
Almacén de Recovery Services (Recovery Services vault)
El tipo de almacén para VM de Azure, SQL y SAP HANA en VM, Azure Files, MARS, MABS y Azure Site Recovery.
Almacén de Backup (Backup vault)
El tipo de almacén más reciente para orígenes de datos como discos administrados, blobs, Azure Database for PostgreSQL y AKS.
Agente MARS (MARS agent)
El agente Microsoft Azure Recovery Services que hace copia de seguridad de archivos, carpetas y estado del sistema de equipos Windows.
Redundancia del almacenamiento de copias de seguridad (backup storage redundancy)
La configuración LRS, ZRS o GRS del almacén, que debe elegirse antes de proteger el primer elemento.
Business Continuity Center
El centro del portal que administra la copia de seguridad y la recuperación ante desastres entre tipos de almacén, suscripciones y regiones.
Ejemplo real

Al equipo de nube de un hospital se le pide proteger con copias de seguridad frecuentes un clúster de AKS nuevo y los discos administrados de sus servidores de imágenes médicas, además de las copias de seguridad de VM que ya tiene. Descubre que el almacén de Recovery Services que ya usa no puede contener estos orígenes de datos, así que crea un almacén de Backup en la misma región con la redundancia de almacenamiento adecuada, configura allí la copia de seguridad de AKS y Azure Disk Backup, y ve ambos almacenes juntos en el Business Continuity Center.

Consejo para el examen: Las VM de Azure, Azure Files, SQL en VM, MARS y Site Recovery usan un almacén de Recovery Services. Los discos administrados, los blobs, PostgreSQL y AKS usan un almacén de Backup. Configura la redundancia del almacenamiento antes de proteger el primer elemento.

Comprueba lo que sabes

¿Qué tipo de almacén necesitas para hacer copia de seguridad de una VM de Azure que ejecuta SQL Server, incluida la propia base de datos?

Un almacén de Recovery Services, que admite tanto la copia de seguridad de VM de Azure como la de SQL Server en VM de Azure.

¿Dónde configuras Azure Disk Backup para discos administrados individuales?

En un almacén de Backup.

¿Por qué una VM podría no aparecer cuando intentas agregarla a un almacén de Recovery Services?

El almacén está en una región diferente; para la copia de seguridad de VM de Azure, el almacén debe estar en la misma región que la VM.

¿Cuándo deberías configurar la redundancia del almacenamiento de un almacén como redundancia geográfica?

Antes de proteger cualquier elemento, porque no se puede cambiar después de proteger elementos, y es necesaria para la restauración entre regiones.
