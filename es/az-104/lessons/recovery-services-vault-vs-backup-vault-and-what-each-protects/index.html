Almacén de Recovery Services vs. almacén de Backup y qué protege cada uno

Azure Backup protege los datos realizando copias de seguridad según una programación y almacenándolas en un almacén (vault), una entidad de almacenamiento administrada por Azure que contiene los puntos de recuperación y las directivas de copia de seguridad. Azure tiene dos tipos de almacén, y cada uno admite un conjunto distinto de cargas de trabajo. Elegir el almacén correcto para un origen de datos es una pregunta clásica del examen, porque no puedes, por ejemplo, hacer una copia de seguridad de una VM de Azure en un almacén de Backup.

Un almacén de Recovery Services (Recovery Services vault) es el tipo de almacén original. Protege: máquinas virtuales de Azure (Windows y Linux, la VM completa, incluidos todos los discos); bases de datos de SQL Server y SAP HANA que se ejecutan dentro de VM de Azure; recursos compartidos de Azure Files; archivos, carpetas y estado del sistema locales mediante el agente MARS (Microsoft Azure Recovery Services); y cargas de trabajo locales mediante Microsoft Azure Backup Server (MABS) o System Center Data Protection Manager. Un almacén de Recovery Services también es donde se configura la replicación de Azure Site Recovery, así que el mismo tipo de almacén sirve tanto para copias de seguridad como para recuperación ante desastres.

Un almacén de Backup (Backup vault) es el tipo de almacén más reciente, usado por los orígenes de datos más nuevos. Protege, entre otros, discos administrados de Azure (Azure Disk Backup, con instantáneas incrementales), Azure Blobs (copia de seguridad operativa y copia de seguridad en almacén), Azure Database for PostgreSQL y clústeres de Azure Kubernetes Service. Si una pregunta plantea dónde hacer copias de seguridad programadas de discos administrados individuales o de datos de blobs, la respuesta es un almacén de Backup.

Algunas reglas se aplican a ambos. El almacén debe estar en la misma región que los recursos que protege (para la copia de seguridad de VM de Azure es obligatorio). Eliges la redundancia del almacenamiento de copias de seguridad del almacén, con redundancia local, de zona o geográfica, y debes definirla antes de proteger el primer elemento, porque no se puede cambiar una vez que hay elementos protegidos. El almacenamiento con redundancia geográfica es necesario si quieres la restauración entre regiones. Ambos tipos de almacén admiten eliminación temporal (soft delete), inmutabilidad y roles de RBAC como Backup Contributor, Backup Operator y Backup Reader.

Lo administras todo desde un solo lugar: el Business Continuity Center del portal (el sucesor de Backup center) ofrece una vista única de los elementos protegidos, trabajos, directivas y almacenes de ambos tipos, entre suscripciones y regiones. También puedes configurar la copia de seguridad directamente desde un recurso, por ejemplo en la hoja Backup de una VM, donde eliges o creas un almacén y una directiva.

Una regla mnemotécnica sencilla: almacén de Recovery Services para 'los servidores y lo que se ejecuta en ellos', es decir, VM, bases de datos en VM, recursos compartidos de archivos, máquinas locales y Site Recovery; almacén de Backup para 'los orígenes de datos PaaS y de almacenamiento más nuevos', como discos, blobs, PostgreSQL y AKS. Cuando Microsoft agregue un origen de datos nuevo, comprueba qué tipo de almacén usa en lugar de suponerlo.

Términos clave

Recovery Services vault (almacén de Recovery Services)
Un almacén que protege VM de Azure, SQL y SAP HANA en VM, Azure Files y datos locales mediante MARS o MABS, y que hospeda Site Recovery.
Backup vault (almacén de Backup)
Un tipo de almacén más reciente que protege orígenes de datos como discos administrados, blobs, Azure Database for PostgreSQL y AKS.
MARS agent (agente MARS)
El agente Microsoft Azure Recovery Services que hace copias de seguridad de archivos, carpetas y estado del sistema de máquinas Windows en un almacén de Recovery Services.
Backup storage redundancy (redundancia del almacenamiento de copias de seguridad)
La configuración LRS, ZRS o GRS del almacenamiento de un almacén, que debe elegirse antes de proteger elementos.
Ejemplo real

Un administrador debe proteger tres cosas: VM de producción, un conjunto de discos administrados conectados a una aplicación en clúster y un contenedor de blobs con contratos. Crea un almacén de Recovery Services con redundancia geográfica para las VM, y un almacén de Backup en la misma región para Azure Disk Backup de los discos administrados y la copia de seguridad en almacén del contenedor de blobs, y lo supervisa todo desde el Business Continuity Center.

Consejo para el examen: VM de Azure, Azure Files, SQL en VM, MARS y Site Recovery = almacén de Recovery Services. Discos administrados, blobs, PostgreSQL y AKS = almacén de Backup. Define la redundancia del almacenamiento antes de proteger el primer elemento.

Comprueba lo que sabes

¿Qué tipo de almacén necesitas para hacer una copia de seguridad de una VM de Azure?

Un almacén de Recovery Services, en la misma región que la VM.

¿Qué tipo de almacén admite Azure Disk Backup de discos administrados individuales?

Un almacén de Backup.

Quieres hacer una copia de seguridad de archivos de un servidor Windows local directamente en Azure. ¿Qué usas?

El agente MARS en el servidor, haciendo la copia de seguridad en un almacén de Recovery Services.
