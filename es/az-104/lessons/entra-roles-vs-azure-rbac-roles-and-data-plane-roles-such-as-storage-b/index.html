Microsoft Certified: Azure Administrator Associate AZ-104

Roles de Entra vs. roles de Azure RBAC, y roles del plano de datos como Storage Blob Data Reader

Azure tiene dos sistemas de roles separados, y las preguntas del examen a menudo evalúan si sabes cuál aplica. Los roles de Microsoft Entra controlan lo que alguien puede hacer en el propio directorio: crear usuarios, restablecer contraseñas, administrar grupos, registrar aplicaciones y configurar opciones del tenant. Algunos ejemplos son Global Administrator, User Administrator, Groups Administrator, Helpdesk Administrator y Application Administrator. Su ámbito es todo el tenant o una unidad administrativa, y los asignas en Microsoft Entra ID > Roles and administrators.

Los roles de Azure RBAC controlan lo que alguien puede hacer con los recursos de Azure: máquinas virtuales, cuentas de almacenamiento, redes. Sus ámbitos son grupos de administración, suscripciones, grupos de recursos y recursos, y los asignas en la hoja Access control (IAM) de un recurso. Los dos sistemas son independientes. Un Global Administrator no tiene automáticamente ningún acceso a las suscripciones, y un Owner de suscripción no puede crear usuarios en Entra ID a menos que también tenga un rol de Entra adecuado.

Existe un puente. Un Global Administrator puede activar 'Access management for Azure resources' en las propiedades del tenant. Eso le da el rol User Access Administrator en el ámbito raíz (/), por encima de todos los grupos de administración y suscripciones, para que pueda concederse a sí mismo o a otros acceso a cualquier suscripción. Esto está pensado para recuperación, por ejemplo cuando el único propietario de la suscripción se fue, y debe desactivarse de nuevo después.

Azure RBAC a su vez se divide en dos planos. El plano de control (plano de administración) es la API de Azure Resource Manager: crear una cuenta de almacenamiento, cambiar su firewall, leer sus propiedades. El plano de datos son los datos dentro del recurso: blobs, mensajes de cola, entidades de tabla, secretos de Key Vault. Owner, Contributor y Reader son roles del plano de control. No contienen DataActions, así que por sí solos no conceden la lectura de un blob mediante autorización de Microsoft Entra.

Los roles del plano de datos llenan ese vacío. Storage Blob Data Reader permite a una entidad leer y enumerar blobs; Storage Blob Data Contributor agrega escritura y eliminación; Storage Blob Data Owner además permite establecer ACL (listas de control de acceso) en Data Lake Storage. Hay roles equivalentes para colas (Storage Queue Data Contributor), tablas y Azure Files sobre REST, y para Key Vault (Key Vault Secrets User, Key Vault Administrator). Asígnalos en el ámbito de la cuenta de almacenamiento o del contenedor para aplicar privilegios mínimos.

Una sorpresa común: un Contributor aun así puede leer blobs en el portal. Eso se debe a que Contributor tiene la acción del plano de control listKeys, de modo que el portal puede obtener la clave de la cuenta de almacenamiento y usar autorización con Shared Key. Si deshabilitas el acceso con clave compartida en la cuenta, o cambias el método de autenticación del portal a 'Microsoft Entra user account', solo funcionan los roles del plano de datos. Un Reader, que no puede enumerar las claves, ve la cuenta pero recibe un error al abrir un contenedor a menos que también tenga un rol de datos.

Términos clave

Microsoft Entra role (rol de Microsoft Entra)
Un rol de directorio, como User Administrator, que controla la administración de objetos de Entra y la configuración del tenant.
Control plane (plano de control)
Operaciones de administración sobre recursos de Azure mediante Azure Resource Manager, regidas por Actions en los roles de RBAC.
Data plane (plano de datos)
Operaciones sobre los datos dentro de un recurso, como leer blobs, regidas por DataActions en los roles de RBAC.
Storage Blob Data Reader
Un rol integrado del plano de datos que permite leer y enumerar contenedores de blobs y blobs usando autorización de Entra.
Ejemplo real

Una aplicación de análisis se ejecuta con una identidad administrada y necesita leer archivos de un contenedor. El administrador asigna Storage Blob Data Reader solo en ese contenedor. Darle Reader en la cuenta de almacenamiento no funcionaría, porque Reader no tiene acciones de datos y no puede enumerar las claves, y Contributor le daría mucho más poder del que necesita.

Consejo para el examen: Las tareas de directorio (usuarios, grupos, contraseñas) apuntan a roles de Entra; las tareas de recursos apuntan a Azure RBAC. Si la pregunta trata de leer el contenido de blobs con Entra ID, busca un rol 'Storage Blob Data', no Reader ni Contributor.

Comprueba lo que sabes

Un usuario es Owner de una suscripción. ¿Puede restablecer la contraseña de otro usuario en Entra ID?

No por ese rol. Owner es un rol de Azure RBAC; restablecer contraseñas requiere un rol de Entra como Helpdesk Administrator o User Administrator.

Un usuario con Reader en una cuenta de almacenamiento recibe un error de autorización al abrir un contenedor en el portal. ¿Qué rol lo soluciona con privilegios mínimos?

Storage Blob Data Reader en el ámbito del contenedor o de la cuenta, que concede acceso de lectura en el plano de datos.

¿Cómo puede un Global Administrator recuperar el acceso a una suscripción cuyo único Owner se fue?

Habilitando 'Access management for Azure resources' para recibir User Access Administrator en el ámbito raíz, conceder el rol necesario y luego desactivarlo.
