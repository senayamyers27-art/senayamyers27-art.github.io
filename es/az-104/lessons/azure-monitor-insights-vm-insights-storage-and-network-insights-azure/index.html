Insights de Azure Monitor: VM insights, insights de almacenamiento y de red, Azure Monitor Agent y reglas de recopilación de datos

Los insights son experiencias de supervisión seleccionadas de Azure Monitor para un tipo concreto de recurso. Combinan métricas, registros y libros (workbooks) en vistas listas para usar, así que no tienes que diseñar tú mismo los gráficos y las consultas. Los encuentras en Monitor > Insights, y muchos también aparecen en la hoja Insights del propio recurso. Para el examen necesitas saber qué muestran VM insights, los insights de almacenamiento y los insights de red, y cómo llegan los datos del sistema invitado a Azure Monitor mediante Azure Monitor Agent y las reglas de recopilación de datos.

VM insights supervisa el rendimiento y el estado de las máquinas virtuales (VM) y los conjuntos de escalado, tanto de VM de Azure como de servidores conectados mediante Azure Arc. La vista Performance muestra gráficos de CPU, memoria, disco y red de todas las máquinas supervisadas y ayuda a encontrar las más ocupadas o más limitadas. La vista Map, que además necesita el Dependency agent, muestra los procesos de cada VM y sus conexiones de red con otras máquinas y servicios, algo útil para descubrir dependencias antes de una migración. VM insights almacena sus datos en un área de trabajo de Log Analytics, principalmente en la tabla InsightsMetrics, y lo habilitas desde la hoja Insights de la VM, que instala el agente y crea una regla de recopilación de datos por ti.

Los insights de almacenamiento (storage insights) ofrecen una vista unificada de la capacidad, las transacciones, la disponibilidad y la latencia de tus cuentas de almacenamiento, a partir de las métricas de plataforma, así que funcionan sin configuración adicional. Detectan rápidamente una cuenta con errores crecientes o un crecimiento inesperado. Los insights de red (network insights) muestran el estado y las métricas de los recursos de red, como equilibradores de carga, puertas de enlace e IP públicas, con una vista de topología, y enlazan con herramientas de Network Watcher como Connection Monitor.

Los datos a nivel del sistema invitado dentro de una VM, como los registros de eventos de Windows, el syslog de Linux y los contadores de rendimiento del sistema operativo, los recopila Azure Monitor Agent (AMA). AMA se instala como extensión de VM (y en servidores habilitados para Arc), se autentica con una identidad administrada y reemplazó al antiguo agente de Log Analytics, que ya se retiró. A diferencia del agente antiguo, AMA no decide por sí mismo qué recopilar ni a dónde enviarlo; eso se define en las reglas de recopilación de datos.

Una regla de recopilación de datos (DCR) es un recurso de Azure que describe qué datos recopilar, cómo transformarlos y a dónde enviarlos. Para las VM, una DCR podría recopilar los contadores '% Processor Time' y 'Available MBytes' cada 60 segundos más los eventos de advertencia y error de los registros System y Application, y enviarlos a un área de trabajo de Log Analytics (los contadores de rendimiento también pueden ir a Azure Monitor Metrics). Asocias la DCR con las VM mediante asociaciones de reglas de recopilación de datos. Una VM puede tener varias DCR y una DCR puede aplicarse a muchas VM, así que podrías tener una DCR base para todos los servidores y una DCR adicional para los servidores SQL. Las transformaciones escritas en KQL (Kusto Query Language) pueden filtrar o modificar los datos antes de almacenarlos, lo que reduce el costo de ingesta. Para implementar a escala, usa iniciativas de Azure Policy que instalen AMA y asocien DCR automáticamente en cada VM nueva. Si faltan datos, revisa los tres eslabones de la cadena: la extensión del agente está instalada y en buen estado, la VM está asociada con la DCR y el área de trabajo de destino de la DCR es la correcta. Una comprobación rápida en KQL es Heartbeat | where Computer == "vm-sql01" | take 5; los latidos demuestran que el agente se comunica con el área de trabajo.

Veamos un ejemplo práctico. Un equipo que migra veinte servidores quiere saber cuáles se comunican entre sí, además de los errores del registro System de Windows de todos ellos. Habilita VM insights con la opción Map, que instala AMA y el Dependency agent y crea una DCR; la vista Map revela que un antiguo servidor de informes todavía se conecta a la base de datos, así que se une a la oleada de migración. Luego crea una segunda DCR que recopila los eventos de error del registro System, la asocia con los veinte servidores mediante una asignación de directiva y agrega una transformación KQL que descarta un ID de evento informativo muy ruidoso para contener los costos.

Errores comunes: instalar AMA y esperar datos sin asociar una DCR; esperar la vista Map sin el Dependency agent; suponer que los insights de almacenamiento necesitan un agente; confundir las métricas de plataforma (a nivel de host, automáticas) con contadores del sistema invitado como el uso de memoria (necesitan AMA y una DCR); y seguir planificando en torno al agente de Log Analytics retirado.

En las preguntas del examen, 'recopilar registros de eventos de Windows o syslog de las VM' significa AMA más una DCR; 'ver las dependencias entre servidores' significa la vista Map de VM insights con el Dependency agent; 'una sola vista de todas las cuentas de almacenamiento' significa insights de almacenamiento; 'filtrar datos antes de la ingesta' significa una transformación de DCR; 'aplicar automáticamente a todas las VM nuevas' significa Azure Policy.

Términos clave

Insights
Experiencias seleccionadas de Azure Monitor que combinan métricas, registros y libros para un tipo de recurso.
VM insights
Insight que muestra gráficos de rendimiento de las VM y, con el Dependency agent, un mapa de procesos y conexiones.
Azure Monitor Agent (AMA)
El agente actual que recopila registros y datos de rendimiento del sistema operativo invitado de VM y servidores habilitados para Arc.
Regla de recopilación de datos (data collection rule, DCR)
Recurso de Azure que define qué datos recopilar, cómo transformarlos y a dónde enviarlos.
Asociación de regla de recopilación de datos (data collection rule association)
El vínculo entre una DCR y una VM u otro recurso que hace que el agente aplique esa regla.
Dependency agent
Agente necesario para que la vista Map de VM insights descubra procesos y conexiones de red.
Transformación (transformation)
Instrucción KQL en una DCR que filtra o modifica los datos entrantes antes de almacenarlos.
Ejemplo real

Una empresa de hospedaje recibe quejas por presión de memoria, pero el Explorador de métricas no muestra ninguna métrica de memoria para sus VM, porque el uso de memoria es un contador del sistema operativo invitado. El administrador crea una regla de recopilación de datos que reúne Available MBytes y % Committed Bytes In Use cada minuto, la asocia con todos los servidores web mediante una asignación de Azure Policy y usa la vista Performance de VM insights para encontrar tres servidores que están constantemente cerca de su límite de memoria.

Consejo para el examen: Azure Monitor Agent no recopila nada hasta que se asocia una regla de recopilación de datos con la máquina. La vista Map de VM insights necesita el Dependency agent, y los insights de almacenamiento usan métricas de plataforma sin ningún agente.

Comprueba lo que sabes

Instalaste Azure Monitor Agent en una VM, pero no llega ningún evento al área de trabajo. ¿Qué es lo que más probablemente falta?

Una regla de recopilación de datos asociada con la VM que defina los eventos y el área de trabajo de destino.

¿Qué componente adicional requiere la vista Map de VM insights?

El Dependency agent, además de Azure Monitor Agent.

¿Puede una regla de recopilación de datos aplicarse a muchas VM?

Sí. Una DCR se puede asociar con muchas máquinas, y una máquina puede tener varias DCR.

¿Cómo puedes reducir el costo de ingesta descartando eventos innecesarios antes de que se almacenen?

Agrega a la regla de recopilación de datos una transformación KQL que filtre esos eventos.
