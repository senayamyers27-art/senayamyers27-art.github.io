Insights de Azure Monitor: VM insights, insights de almacenamiento y de red, Azure Monitor Agent y reglas de recopilación de datos

Los insights son experiencias de supervisión seleccionadas en Azure Monitor para un tipo concreto de recurso. Combinan métricas, registros y libros (workbooks) en paneles listos para usar, para que no tengas que diseñar gráficos y consultas tú mismo. Los encuentras en Monitor > Insights, y muchos también aparecen en la hoja Insights del propio recurso.

VM insights supervisa el rendimiento y el estado de las máquinas virtuales y los conjuntos de escalado, tanto de VM de Azure como de servidores conectados mediante Azure Arc. La vista Performance muestra gráficos de CPU, memoria, disco y red de todas las máquinas supervisadas, y ayuda a encontrar las más ocupadas o más limitadas. La vista Map, que además necesita el Dependency agent, muestra los procesos de cada VM y sus conexiones de red con otras máquinas y servicios, lo que es útil para descubrir dependencias antes de una migración. VM insights almacena sus datos en un área de trabajo de Log Analytics, principalmente en la tabla InsightsMetrics, y lo habilitas desde la hoja Insights de la VM, que instala el agente y crea una regla de recopilación de datos por ti.

Storage insights ofrece una vista unificada de la capacidad, las transacciones, la disponibilidad y la latencia de tus cuentas de almacenamiento, a partir de las métricas de plataforma, así que funciona sin configuración adicional. Permite detectar rápidamente una cuenta con errores en aumento o un crecimiento inesperado. Network insights muestra el estado y las métricas de los recursos de red, como equilibradores de carga, puertas de enlace e IP públicas, con una vista de topología, y enlaza con herramientas de Network Watcher como Connection Monitor.

Los datos a nivel de invitado de dentro de una VM, como los registros de eventos de Windows, el syslog de Linux y los contadores de rendimiento del SO, los recopila el Azure Monitor Agent (AMA). AMA se instala como una extensión de VM (y en servidores habilitados para Arc), usa una identidad administrada y reemplazó al antiguo agente de Log Analytics, que ya se retiró. A diferencia del agente anterior, AMA no decide por sí mismo qué recopilar ni a dónde enviarlo; eso se define en las reglas de recopilación de datos.

Una regla de recopilación de datos (DCR) es un recurso de Azure que describe qué datos recopilar, cómo transformarlos y a dónde enviarlos. Para las VM, una DCR podría recopilar los contadores '% Processor Time' y 'Available MBytes' cada 60 segundos, además de los eventos de advertencia y error de los registros System y Application, y enviarlos a un área de trabajo de Log Analytics (los contadores de rendimiento también pueden ir a Azure Monitor Metrics). Asocias la DCR con las VM mediante asociaciones de reglas de recopilación de datos. Una VM puede tener varias DCR, y una DCR puede aplicarse a muchas VM, así que podrías tener una DCR base para todos los servidores y una DCR adicional para los servidores SQL. Las transformaciones escritas en KQL pueden filtrar o modificar los datos antes de almacenarlos, lo que reduce el costo.

Para implementar a escala, usa iniciativas de Azure Policy que instalen AMA y asocien las DCR automáticamente. Si faltan datos, revisa los tres eslabones de la cadena: la extensión del agente está instalada y en buen estado, la VM está asociada con la DCR, y el área de trabajo de destino de la DCR es la correcta.

Términos clave

VM insights
Una experiencia de Azure Monitor que muestra el rendimiento de las VM y, con el Dependency agent, mapas de procesos y conexiones.
Azure Monitor Agent (AMA)
El agente actual que recopila datos del SO invitado de las VM de Azure y de los servidores habilitados para Arc, configurado mediante reglas de recopilación de datos.
Data collection rule (DCR) (regla de recopilación de datos)
Un recurso que define qué datos recopilar, las transformaciones opcionales y los destinos.
DCR association (asociación de DCR)
El vínculo entre una regla de recopilación de datos y una máquina o recurso que indica al agente que aplique la regla.
Ejemplo real

Un administrador debe recopilar los errores de System y Application de Windows de 200 servidores en un área de trabajo. Crea una DCR con esos orígenes de registros de eventos y el área de trabajo como destino, y asigna una iniciativa de directivas integrada que instala el Azure Monitor Agent y asocia la DCR con cada VM Windows de la suscripción, incluidas las futuras.

Consejo para el examen: AMA no recopila nada hasta que se asocia una regla de recopilación de datos con la máquina. La vista Map de VM insights necesita el Dependency agent. Storage insights usa métricas de plataforma y no necesita agente.

Comprueba lo que sabes

El Azure Monitor Agent está instalado en una VM, pero no llegan registros de eventos al área de trabajo. ¿Qué es probable que falte?

Una regla de recopilación de datos que defina los registros de eventos y el área de trabajo, asociada con la VM.

¿Qué característica de VM insights muestra las conexiones entre procesos y otros servidores, y qué agente adicional necesita?

La característica Map, que necesita el Dependency agent.

¿Dónde configuras qué contadores de rendimiento envía una VM y con qué frecuencia?

En una regla de recopilación de datos.
