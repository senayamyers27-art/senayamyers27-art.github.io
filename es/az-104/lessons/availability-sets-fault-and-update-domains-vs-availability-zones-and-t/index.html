Conjuntos de disponibilidad (dominios de error y de actualización) vs. zonas de disponibilidad y sus SLA

Una sola VM tarde o temprano sufrirá una interrupción, por un fallo de hardware, una actualización del host o un problema en el centro de datos. Azure te da dos formas de repartir varias VM para que un solo evento no pueda derribarlas todas: los conjuntos de disponibilidad (availability sets) dentro de un centro de datos, y las zonas de disponibilidad (availability zones) entre centros de datos. Cada una viene con un acuerdo de nivel de servicio (SLA) distinto, es decir, el tiempo de actividad que Microsoft garantiza para la conectividad de las VM.

Un conjunto de disponibilidad es un agrupamiento lógico de VM que Azure reparte entre dominios de error (fault domains) y dominios de actualización (update domains). Un dominio de error es un grupo de hardware que comparte una fuente de alimentación y un conmutador de red, similar a un rack; si falla, solo caen las VM de ese dominio de error. Las regiones admiten hasta tres dominios de error para los conjuntos de disponibilidad (dos en algunas regiones). Un dominio de actualización es un grupo de hosts que Azure puede reiniciar al mismo tiempo durante el mantenimiento planificado de la plataforma; solo se reinicia un dominio de actualización a la vez, y puedes configurar hasta 20, con 5 como valor predeterminado. Las VM del conjunto se asignan a los dominios por turnos (round robin), así que con dos servidores web quedan en dominios de error y de actualización diferentes.

Una zona de disponibilidad es una ubicación físicamente separada dentro de una región, con alimentación, refrigeración y redes independientes; las regiones que admiten zonas tienen al menos tres. Al crear una VM puedes fijarla a la zona 1, 2 o 3 (una implementación zonal). Colocar VM en dos o más zonas protege contra el fallo de un centro de datos completo, cosa que un conjunto de disponibilidad no puede hacer. Algunos servicios, como el almacenamiento con redundancia de zona, los equilibradores de carga Standard y las IP públicas Standard, pueden ser redundantes entre zonas, abarcando todas las zonas automáticamente.

Los SLA publicados para VM se corresponden directamente con estas opciones: 99.99 por ciento de conectividad para dos o más VM implementadas en dos o más zonas de disponibilidad de la misma región; 99.95 por ciento para dos o más VM en el mismo conjunto de disponibilidad; y 99.9 por ciento para una sola VM cuando todos sus discos son Premium SSD, Premium SSD v2 o Ultra Disk (menor con discos standard). Los niveles más altos de protección requieren al menos dos instancias, y por eso siempre se combinan con un equilibrador de carga que envía el tráfico solo a las VM en buen estado.

Reglas clave para los escenarios del examen. Una VM solo se puede agregar a un conjunto de disponibilidad al crearla; para pasar una VM existente a un conjunto debes volver a crearla (conservando sus discos). Una VM no puede estar a la vez en un conjunto de disponibilidad y en una zona de disponibilidad. Los conjuntos de disponibilidad son gratuitos; solo pagas por las VM. Las zonas solo están disponibles en algunas regiones y para algunos tamaños, así que un requisito de sobrevivir al fallo de un centro de datos descarta las regiones sin zonas. Para grupos grandes y elásticos, los Virtual Machine Scale Sets con orquestación Flexible pueden repartir las instancias entre zonas y dominios de error por ti.

Términos clave

Fault domain (dominio de error)
Un grupo de hardware que comparte alimentación y red y que puede fallar en conjunto, como un rack.
Update domain (dominio de actualización)
Un grupo de hosts que pueden reiniciarse juntos durante el mantenimiento planificado; solo se actualiza uno a la vez.
Availability set (conjunto de disponibilidad)
Un agrupamiento que reparte las VM entre dominios de error y de actualización dentro de un centro de datos.
Availability zone (zona de disponibilidad)
Una ubicación de centro de datos físicamente separada dentro de una región, con alimentación, refrigeración y redes independientes.
SLA
Service level agreement (acuerdo de nivel de servicio): el porcentaje de tiempo de actividad que Microsoft garantiza para una configuración.
Ejemplo real

Una tienda en línea ejecuta dos VM web detrás de un equilibrador de carga. El negocio pide protección contra una interrupción completa de un centro de datos en la región. Un conjunto de disponibilidad solo protegería contra fallos de rack y de mantenimiento, así que el administrador vuelve a implementar las VM en las zonas 1 y 2 detrás de un equilibrador de carga Standard con redundancia de zona, llevando el diseño al SLA de 99.99 por ciento.

Consejo para el examen: Fallo de centro de datos = zonas de disponibilidad (99.99 por ciento); protección de rack o mantenimiento = conjunto de disponibilidad (99.95 por ciento); una sola VM con discos premium = 99.9 por ciento. Los conjuntos de disponibilidad solo se eligen al crear la VM.

Comprueba lo que sabes

¿Cuál es la diferencia entre un dominio de error y un dominio de actualización?

Un dominio de error es hardware compartido que puede fallar en conjunto (no planificado); un dominio de actualización es un grupo que se reinicia junto durante el mantenimiento planificado.

¿Puedes agregar una VM existente en ejecución a un conjunto de disponibilidad?

No. El conjunto debe elegirse al crearla, así que tendrías que volver a crear la VM, por ejemplo a partir de sus discos existentes.

¿Qué SLA se aplica a dos VM en zonas de disponibilidad diferentes?

99.99 por ciento de conectividad de VM.
