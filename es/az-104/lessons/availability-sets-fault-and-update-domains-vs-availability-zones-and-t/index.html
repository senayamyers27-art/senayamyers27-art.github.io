Conjuntos de disponibilidad (dominios de error y de actualización) vs. zonas de disponibilidad y sus SLA

Una sola máquina virtual (VM) acabará sufriendo una interrupción, por un error de hardware, una actualización del host o un problema en el centro de datos. Azure te da dos formas de repartir varias VM para que un solo evento no las derribe a todas: los conjuntos de disponibilidad dentro de un centro de datos y las zonas de disponibilidad entre centros de datos de una región. Cada uno tiene un acuerdo de nivel de servicio (SLA) distinto, el porcentaje de tiempo de actividad que Microsoft garantiza para la conectividad de las VM, y el examen espera que relaciones un requisito con la opción y el SLA correctos.

Un conjunto de disponibilidad es una agrupación lógica de VM que Azure reparte entre dominios de error y dominios de actualización. Un dominio de error es un grupo de hardware que comparte una fuente de alimentación y un conmutador de red, similar a un bastidor (rack); si falla, solo caen las VM de ese dominio de error. Las regiones admiten hasta tres dominios de error para los conjuntos de disponibilidad (dos en algunas regiones). Un dominio de actualización es un grupo de hosts que Azure puede reiniciar al mismo tiempo durante el mantenimiento planeado de la plataforma; solo se reinicia un dominio de actualización a la vez, y puedes configurar hasta 20, con 5 como valor predeterminado. Las VM del conjunto se asignan a los dominios por turnos (round robin), así que con dos servidores web quedan en dominios de error y de actualización distintos. Creas uno con az vm availability-set create --resource-group rg-web --name avset-web --platform-fault-domain-count 2 --platform-update-domain-count 5 y luego haces referencia a él al crear cada VM.

Una zona de disponibilidad es una ubicación físicamente separada dentro de una región, con alimentación, refrigeración y red independientes; las regiones que admiten zonas tienen al menos tres. Al crear una VM puedes fijarla en la zona 1, 2 o 3 (una implementación zonal), por ejemplo con az vm create ... --zone 1. Colocar VM en dos o más zonas protege frente al error de todo un centro de datos, algo que un conjunto de disponibilidad no puede hacer. Algunos servicios, como el almacenamiento con redundancia de zona, los equilibradores de carga Standard y las direcciones IP públicas Standard, pueden tener redundancia de zona y abarcar todas las zonas automáticamente, lo que combina de forma natural con las VM zonales.

Los SLA publicados de las VM se corresponden directamente con estas opciones: 99,99 por ciento de conectividad para dos o más VM implementadas en dos o más zonas de disponibilidad de la misma región; 99,95 por ciento para dos o más VM en el mismo conjunto de disponibilidad; y 99,9 por ciento para una sola VM cuando todos sus discos son Premium SSD, Premium SSD v2 o Ultra Disk, con compromisos menores para VM únicas con discos estándar. Los niveles más altos requieren al menos dos instancias, y por eso siempre los combinas con un equilibrador de carga que envía tráfico solo a las VM en buen estado. El SLA cubre la plataforma; tu aplicación todavía debe tolerar que desaparezca una instancia.

Reglas clave para los escenarios del examen. Una VM solo se puede agregar a un conjunto de disponibilidad al crearla; para mover una VM existente a un conjunto debes volver a crearla, normalmente conservando sus discos de sistema operativo y de datos. Una VM no puede estar a la vez en un conjunto de disponibilidad y en una zona de disponibilidad. Los conjuntos de disponibilidad son gratuitos; solo pagas por las VM. Las zonas solo están disponibles en algunas regiones y para algunos tamaños, así que el requisito de sobrevivir al error de un centro de datos descarta las regiones sin zonas. Para grupos grandes y elásticos, Virtual Machine Scale Sets con orquestación flexible puede repartir las instancias entre zonas o dominios de error por ti y agregar escalado automático.

Veamos un ejemplo práctico. Una tienda en línea ejecuta dos VM web detrás de un equilibrador de carga en un único conjunto de disponibilidad. Ahora la empresa pide protección frente a una interrupción completa de un centro de datos en la región. Un conjunto de disponibilidad solo protege frente a errores de bastidor y mantenimiento planeado dentro de un centro de datos, así que no puede cumplir el requisito. Vuelves a implementar las VM a partir de sus discos existentes en las zonas 1 y 2, las colocas detrás de un equilibrador de carga Standard con redundancia de zona y una IP pública Standard, y confirmas que los sondeos de estado marcan ambas como en buen estado. El diseño ahora cumple los requisitos del SLA del 99,99 por ciento.

Errores comunes: confundir los dominios de error (errores de hardware no planeados) con los dominios de actualización (mantenimiento planeado); esperar que un conjunto de disponibilidad sobreviva a la interrupción de un centro de datos; intentar agregar una VM en ejecución a un conjunto de disponibilidad; combinar un conjunto de disponibilidad y una zona en una VM; implementar una sola VM en una zona y esperar el 99,99 por ciento; y olvidar el equilibrador de carga, sin el cual la segunda VM no ayuda a los usuarios.

Redacción típica del examen: 'sobrevivir al error de un centro de datos' o 'el SLA más alto' apunta a zonas de disponibilidad y al 99,99 por ciento. 'Proteger frente a errores de bastidor y mantenimiento planeado' apunta a un conjunto de disponibilidad y al 99,95 por ciento. 'Una sola VM, discos premium' apunta al 99,9 por ciento. 'Reinicio planeado del host' apunta a los dominios de actualización, y 'error de alimentación o de conmutador' a los dominios de error. 'Agregar una VM existente a un conjunto' significa volver a crearla. 'Región sin zonas' significa que las zonas no son una opción.

Términos clave

Dominio de error (fault domain)
Un grupo de hardware que comparte alimentación y red y que puede fallar a la vez, como un bastidor.
Dominio de actualización (update domain)
Un grupo de hosts que se pueden reiniciar juntos durante el mantenimiento planeado; solo se actualiza uno a la vez.
Conjunto de disponibilidad (availability set)
Una agrupación que reparte las VM entre dominios de error y de actualización dentro de un centro de datos.
Zona de disponibilidad (availability zone)
Una ubicación de centro de datos físicamente separada dentro de una región, con alimentación, refrigeración y red independientes.
Con redundancia de zona (zone-redundant)
Una configuración de servicio que abarca automáticamente todas las zonas de una región, como el front-end de un equilibrador de carga Standard.
SLA
Acuerdo de nivel de servicio: el porcentaje de tiempo de actividad que Microsoft garantiza para una configuración.
Ejemplo real

Una tienda en línea ejecuta dos VM web detrás de un equilibrador de carga. La empresa pide protección frente a una interrupción completa de un centro de datos en la región. Un conjunto de disponibilidad solo protegería frente a errores de bastidor y de mantenimiento, así que el administrador vuelve a implementar las VM en las zonas 1 y 2 detrás de un equilibrador de carga Standard con redundancia de zona, lo que lleva el diseño al SLA del 99,99 por ciento.

Consejo para el examen: Error de un centro de datos = zonas de disponibilidad (99,99 por ciento); protección frente a bastidor o mantenimiento = conjunto de disponibilidad (99,95 por ciento); una sola VM con discos premium = 99,9 por ciento. Los conjuntos de disponibilidad solo se eligen al crear la VM.

Comprueba lo que sabes

¿Cuál es la diferencia entre un dominio de error y un dominio de actualización?

Un dominio de error es hardware compartido que puede fallar a la vez (no planeado); un dominio de actualización es un grupo que se reinicia junto durante el mantenimiento planeado.

¿Puedes agregar una VM existente en ejecución a un conjunto de disponibilidad?

No. El conjunto debe elegirse al crearla, así que tendrías que volver a crear la VM, por ejemplo a partir de sus discos existentes.

¿Qué SLA se aplica a dos VM en zonas de disponibilidad distintas?

99,99 por ciento de conectividad de VM.

¿Puede una VM estar en un conjunto de disponibilidad y en una zona de disponibilidad al mismo tiempo?

No. Eliges uno u otro; para protección a nivel de centro de datos, usa zonas.
