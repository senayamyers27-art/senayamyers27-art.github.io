Niveles de Azure Container Registry y administración de imágenes

Una imagen de contenedor empaqueta una aplicación con todo lo que necesita para ejecutarse. Azure Container Registry (ACR) es un registro privado para almacenar esas imágenes y artefactos relacionados, como gráficos de Helm, cerca de donde los ejecutas: Azure Container Instances, Container Apps, App Service o Azure Kubernetes Service. Es el equivalente en Azure de un Docker Hub privado.

ACR se ofrece en tres niveles de servicio, y todos ofrecen la misma API principal. Basic es el punto de entrada para desarrollo y aprendizaje, con el menor almacenamiento incluido y el menor rendimiento. Standard aumenta el almacenamiento y el rendimiento para la mayoría de las cargas de producción. Premium agrega las características empresariales: replicación geográfica (geo-replication, un registro replicado en varias regiones para que las descargas sean locales y sobrevivan a una interrupción regional), puntos de conexión privados mediante Private Link y reglas de firewall de red, redundancia de zona, claves administradas por el cliente para el cifrado, mayor rendimiento, registros conectados y directivas de retención para manifiestos sin etiqueta. Si un escenario menciona replicación geográfica o puntos de conexión privados para un registro, la respuesta es Premium. Puedes cambiar de nivel más adelante.

Cada registro tiene un nombre de servidor de inicio de sesión como contosoacr.azurecr.io, y las imágenes se referencian como loginserver/repository:tag. Un flujo de trabajo manual típico con la CLI de Docker:

az acr login --name contosoacr
docker tag webapp:1.0 contosoacr.azurecr.io/shop/webapp:1.0
docker push contosoacr.azurecr.io/shop/webapp:1.0
az acr repository list --name contosoacr --output table

Ni siquiera necesitas Docker localmente: ACR Tasks puede compilar una imagen en Azure a partir de un Dockerfile con az acr build --registry contosoacr --image shop/webapp:1.1 ., y las tareas pueden recompilar automáticamente cuando hay commits en el código fuente o cuando se actualiza una imagen base, lo que ayuda a mantener las imágenes con las revisiones al día. az acr import copia imágenes desde otro registro, como uno público, sin descargarlas a tu equipo.

Opciones de autenticación: inicio de sesión individual con Entra mediante az acr login; entidades de servicio e identidades administradas con roles de RBAC como AcrPull (solo descarga) y AcrPush (descarga y carga); tokens con ámbito de repositorio para acceso limitado; y el usuario administrador (admin user), un único nombre de usuario y contraseña compartidos que está deshabilitado de forma predeterminada y debe seguir así, salvo para pruebas rápidas. Para un servicio que descarga imágenes, da a su identidad administrada el rol AcrPull en el registro.

La administración de imágenes mantiene el registro ordenado y económico. Las etiquetas como latest se pueden mover, así que las implementaciones de producción deben usar etiquetas de versión específicas o resúmenes (digests) de imagen. Los manifiestos sin etiqueta se acumulan cuando se sobrescriben las etiquetas; puedes eliminarlos con az acr repository delete o con az acr run y el comando purge de forma programada, y los registros Premium pueden aplicar una directiva de retención para manifiestos sin etiqueta. También puedes bloquear una imagen o etiqueta para evitar su eliminación o sobrescritura.

Términos clave

Azure Container Registry
Un registro privado administrado para imágenes de contenedor y artefactos relacionados.
Geo-replication (replicación geográfica)
Una característica de ACR Premium que replica un registro en varias regiones para descargas locales y resiliencia.
AcrPull
Un rol integrado que permite descargar imágenes de un registro, normalmente asignado a una identidad administrada.
ACR Tasks
Una característica del registro que compila y actualiza imágenes de contenedor en Azure, activada manualmente, por commits o por actualizaciones de la imagen base.
Ejemplo real

Una empresa ejecuta contenedores en West Europe y Southeast Asia y debe mantener el registro accesible solo desde sus redes virtuales. Actualiza su registro a Premium, agrega una réplica geográfica en Southeast Asia, crea puntos de conexión privados en ambas regiones y deshabilita el acceso público. Las Container Apps de cada región descargan las imágenes mediante sus identidades administradas, que tienen el rol AcrPull.

Consejo para el examen: La replicación geográfica, los puntos de conexión privados y las claves administradas por el cliente apuntan al nivel Premium. Usa AcrPull para identidades que solo descargan imágenes y mantén deshabilitado el usuario administrador.

Comprueba lo que sabes

¿Qué nivel de ACR necesitas para replicar un registro en varias regiones?

Premium.

Una aplicación de App Service debe descargar imágenes de ACR con privilegios mínimos. ¿Qué configuras?

Una identidad administrada para la aplicación con el rol AcrPull en el registro.

¿Cómo puedes compilar una imagen a partir de un Dockerfile sin tener Docker instalado en tu estación de trabajo?

Usa ACR Tasks, por ejemplo az acr build, que compila la imagen en Azure y la carga en el registro.
