Niveles de Azure Container Registry y administración de imágenes

Una imagen de contenedor empaqueta una aplicación con todo lo que necesita para ejecutarse: código, entorno de ejecución, bibliotecas y configuración. Azure Container Registry (ACR) es un registro privado y administrado para almacenar esas imágenes y artefactos relacionados, como gráficos de Helm, cerca de donde las ejecutas: Azure Container Instances, Azure Container Apps, App Service o Azure Kubernetes Service (AKS). Piensa en él como un Docker Hub privado dentro de tu suscripción, protegido por Microsoft Entra ID y el control de acceso basado en roles de Azure (RBAC), para que solo las personas y los servicios que elijas puedan extraer (pull) o insertar (push) imágenes. Cada registro tiene un nombre de servidor de inicio de sesión (login server) como contosoacr.azurecr.io, y las imágenes se referencian como loginserver/repository:tag. Un repositorio agrupa las versiones de una imagen y una etiqueta (tag) identifica una versión. Detrás de cada etiqueta hay un manifiesto identificado por un resumen (digest) inmutable como sha256:.... ACR se ofrece en tres niveles de servicio que comparten la misma API principal. Basic es el punto de entrada para desarrollo y aprendizaje, con el menor almacenamiento incluido y el menor rendimiento. Standard aumenta el almacenamiento y el rendimiento para la mayoría de las cargas de trabajo de producción. Premium agrega las funciones empresariales: replicación geográfica (geo-replication; un registro replicado en varias regiones para que las extracciones sean locales y sobrevivan a una interrupción regional), puntos de conexión privados mediante Azure Private Link y reglas de firewall de red, redundancia de zonas de disponibilidad, claves administradas por el cliente para el cifrado, el mayor rendimiento, registros conectados y una directiva de retención para manifiestos sin etiqueta. Puedes cambiar de nivel más adelante sin volver a crear el registro. Las cantidades exactas de almacenamiento varían según el nivel y cambian con el tiempo, así que aprende qué funciones requieren Premium en lugar de memorizar cifras.

az acr create --resource-group rg-app --name contosoacr --sku Standard
az acr login --name contosoacr
docker tag webapp:1.0 contosoacr.azurecr.io/shop/webapp:1.0
docker push contosoacr.azurecr.io/shop/webapp:1.0
az acr repository list --name contosoacr --output table
az acr repository show-tags --name contosoacr --repository shop/webapp

Ni siquiera necesitas Docker en tu equipo. ACR Tasks compila una imagen en Azure a partir de un Dockerfile con az acr build --registry contosoacr --image shop/webapp:1.1 ., y las tareas pueden volver a compilar automáticamente cuando hay confirmaciones (commits) de código fuente o cuando se actualiza una imagen base, lo que mantiene las imágenes con parches al día. az acr import copia imágenes de otro registro, como uno público, directamente y sin descargarlas a tu equipo. Opciones de autenticación: inicio de sesión individual de Entra con az acr login; entidades de servicio e identidades administradas con roles RBAC como AcrPull (solo extraer) y AcrPush (extraer e insertar); tokens con ámbito de repositorio para acceso limitado; y el usuario administrador (admin user), un único nombre de usuario y contraseña compartidos que está deshabilitado de forma predeterminada y debería seguir así, salvo para pruebas rápidas. Para un servicio que extrae imágenes, asigna a su identidad administrada el rol AcrPull en el registro.

La administración de imágenes mantiene el registro ordenado, seguro y económico. Las etiquetas como latest se pueden mover a otra imagen, así que las implementaciones de producción deberían usar etiquetas de versión específicas o resúmenes (digests) de imagen. Cuando insertas una imagen nueva con una etiqueta existente, el manifiesto anterior queda sin etiqueta pero sigue consumiendo almacenamiento. Puedes eliminar imágenes antiguas con az acr repository delete, programar una limpieza con az acr run y el comando purge (por ejemplo, para quitar imágenes de más de 30 días) y, en Premium, habilitar una directiva de retención que elimina los manifiestos sin etiqueta después de un número definido de días. También puedes bloquear una imagen o etiqueta con az acr repository update --write-enabled false para que no se pueda sobrescribir ni eliminar.

Veamos un ejemplo práctico. Una empresa ejecuta su API en Container Apps en West Europe y East US, y el área de seguridad exige que el registro no sea accesible desde internet. Esa combinación, dos regiones que extraen localmente más acceso privado, requiere Premium. El equipo habilita la replicación geográfica en ambas regiones, crea un punto de conexión privado en cada red virtual central (hub) y deshabilita el acceso de red público. Las Container Apps usan una identidad administrada asignada por el usuario con AcrPull. Una tarea nocturna de acr purge elimina las imágenes de más de 60 días, excepto las etiquetadas como versiones publicadas.

Errores comunes: habilitar el usuario administrador y pegar su contraseña en las canalizaciones en lugar de usar una identidad administrada; dar a una identidad AcrPush o Contributor cuando solo necesita extraer; implementar latest en producción y perder la noción de qué código se está ejecutando; suponer que Basic o Standard pueden usar puntos de conexión privados o replicación geográfica; y olvidar que los manifiestos sin etiqueta siguen costando almacenamiento.

La redacción del examen sigue patrones claros: 'replicar en varias regiones', 'punto de conexión privado' o 'clave administrada por el cliente' significa Premium; 'privilegio mínimo para un servicio que implementa contenedores' significa AcrPull en una identidad administrada; 'compilar sin tener Docker instalado' significa ACR Tasks con az acr build; 'copiar desde Docker Hub' significa az acr import; 'impedir que una imagen se sobrescriba' significa bloquearla.

Términos clave

Azure Container Registry (ACR)
Registro privado administrado para imágenes de contenedor y artefactos relacionados, protegido con Entra ID y RBAC.
Servidor de inicio de sesión (login server)
El nombre completo del registro, como contosoacr.azurecr.io, que se usa como prefijo de los nombres de imagen.
Replicación geográfica (geo-replication)
Función de Premium que replica un registro en varias regiones para extracciones locales y resiliencia regional.
AcrPull
Rol integrado que permite a una identidad extraer imágenes de un registro, pero no insertarlas.
ACR Tasks
Función del registro que compila, prueba y aplica parches a imágenes en Azure, desencadenada manualmente, por confirmaciones o por actualizaciones de la imagen base.
Resumen de imagen (image digest)
Hash de contenido inmutable que identifica exactamente un manifiesto de imagen, a diferencia de una etiqueta, que se puede mover.
Usuario administrador (admin user)
Un único nombre de usuario y contraseña compartidos de un registro, deshabilitado de forma predeterminada y no recomendado para producción.
Ejemplo real

Un equipo de desarrollo inserta cada día una imagen nueva con la etiqueta latest, y la factura de almacenamiento del registro crece poco a poco. Un administrador encuentra cientos de manifiestos sin etiqueta que dejaron las etiquetas sobrescritas. Programa una tarea de ACR que ejecuta el comando purge cada semana para eliminar los manifiestos sin etiqueta y las imágenes de más de 90 días, cambia la canalización de versiones a etiquetas de versión como 2.4.1 y concede a la identidad administrada de la canalización el rol AcrPush, mientras que la Container App de producción recibe solo AcrPull.

Consejo para el examen: La replicación geográfica, los puntos de conexión privados, la redundancia de zona y las claves administradas por el cliente apuntan al nivel Premium. Un servicio que solo extrae imágenes necesita AcrPull en su identidad administrada; mantén deshabilitado el usuario administrador compartido.

Comprueba lo que sabes

Un registro debe ser accesible solo mediante un punto de conexión privado. ¿Qué nivel se requiere?

Premium, porque los puntos de conexión privados y las reglas de firewall de red de ACR son funciones de Premium.

¿Cuál es la forma de privilegio mínimo para permitir que una aplicación de App Service extraiga imágenes de ACR?

Habilitar una identidad administrada en la aplicación y asignarle el rol AcrPull en el registro.

¿Cómo puedes compilar una imagen a partir de un Dockerfile cuando Docker no está instalado en tu equipo?

Usa ACR Tasks, por ejemplo az acr build, que compila la imagen en Azure y la inserta en el registro.

¿Por qué las implementaciones de producción deberían evitar la etiqueta latest?

Las etiquetas se pueden mover a otras imágenes, así que latest puede cambiar de forma inesperada; las etiquetas de versión o los resúmenes identifican exactamente qué imagen se ejecuta.
