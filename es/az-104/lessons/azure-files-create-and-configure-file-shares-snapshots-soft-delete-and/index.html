Azure Files: crear y configurar recursos compartidos de archivos, instantáneas, eliminación temporal y consideraciones sobre el puerto SMB 445

Azure Files proporciona recursos compartidos de archivos totalmente administrados en la nube que los clientes montan como una unidad de red, usando SMB (Server Message Block) o, en los recursos compartidos premium, NFS (Network File System). Windows, Linux y macOS pueden conectarse, y los recursos compartidos pueden reemplazar o ampliar los servidores de archivos locales. Azure File Sync puede almacenar en caché un recurso compartido en servidores Windows Server locales para un acceso rápido en sucursales.

Creas un recurso compartido de archivos dentro de una cuenta de almacenamiento. Una cuenta standard general-purpose v2 aloja recursos compartidos standard en almacenamiento de disco duro, con niveles como transaction optimized, hot y cool que equilibran el costo de almacenamiento frente al costo de transacciones. Una cuenta premium FileStorage aloja recursos compartidos premium en almacenamiento de estado sólido para baja latencia y alto IOPS (operaciones de entrada/salida por segundo), y es la única opción para recursos compartidos NFS. Cada recurso compartido tiene una cuota de tamaño o un tamaño aprovisionado, que en los recursos compartidos premium también determina el rendimiento. En el portal: storage account > File shares > + File share; con la CLI, az storage share-rm create.

Para montar un recurso compartido en Windows, el botón Connect del portal genera un script que básicamente ejecuta net use Z: \\<account>.file.core.windows.net\<share> con credenciales, ya sea la clave de la cuenta de almacenamiento o, mejor aún, autenticación basada en identidad. En Linux montas con el tipo de sistema de archivos cifs. La ruta UNC del recurso compartido siempre usa el punto de conexión file de la cuenta.

SMB usa el puerto TCP 445. Los clientes fuera de Azure se conectan a través de internet, y muchos proveedores de servicios de internet y redes corporativas bloquean el puerto 445 saliente debido a antiguos gusanos de SMB. Si un montaje falla desde una oficina, prueba con PowerShell: Test-NetConnection -ComputerName <account>.file.core.windows.net -Port 445. Si TcpTestSucceeded es false, las opciones son abrir el puerto en el firewall, conectarse mediante una VPN de sitio a sitio, una VPN de punto a sitio o ExpressRoute (normalmente con un punto de conexión privado), o usar Azure File Sync para que los usuarios se comuniquen con un servidor local. Las conexiones desde fuera de la región de Azure requieren SMB 3.x con cifrado, así que los clientes SMB antiguos no pueden conectarse a través de internet.

Las instantáneas de recursos compartidos (share snapshots) capturan una copia de solo lectura de todo un recurso compartido de archivos en un momento dado. Son incrementales, así que solo los cambios desde la instantánea anterior ocupan espacio. Los usuarios de Windows pueden abrir Versiones anteriores (Previous Versions) en una carpeta del recurso compartido montado para restaurar archivos por su cuenta. Azure Backup para Azure Files usa internamente las instantáneas de recursos compartidos y agrega programación y retención.

La eliminación temporal (soft delete) para recursos compartidos de archivos conserva un recurso compartido eliminado, incluidas sus instantáneas, durante un periodo de retención que defines, para que puedas recuperarlo desde la lista File shares con 'Show deleted shares'. Está habilitada de forma predeterminada en las cuentas de almacenamiento nuevas. La eliminación temporal funciona a nivel de recurso compartido; para recuperar un archivo individual usas instantáneas o copias de seguridad.

Términos clave

Azure file share (recurso compartido de Azure Files)
Un recurso compartido SMB o NFS administrado, alojado en una cuenta de almacenamiento, que los clientes montan como una unidad de red.
Share snapshot (instantánea de recurso compartido)
Una copia incremental de solo lectura de todo un recurso compartido de archivos en un momento dado.
File share soft delete (eliminación temporal de recursos compartidos)
Una configuración que conserva los recursos compartidos eliminados durante un periodo para poder recuperarlos.
Port 445 (puerto 445)
El puerto TCP que usa SMB, a menudo bloqueado por ISP y firewalls, lo que impide montar recursos compartidos de Azure Files desde fuera.
Ejemplo real

El personal de una sucursal no puede asignar un nuevo recurso compartido de Azure Files, aunque funciona desde una VM de Azure. El administrador ejecuta Test-NetConnection hacia el punto de conexión del recurso compartido en el puerto 445 desde la oficina y ve que falla porque el ISP bloquea el puerto. La solución es enrutar el acceso por la VPN de sitio a sitio existente hacia un punto de conexión privado de la cuenta de almacenamiento.

Consejo para el examen: Si un recurso compartido se monta desde VM de Azure pero no desde el entorno local, sospecha primero del puerto 445 bloqueado. La eliminación temporal protege recursos compartidos completos; las instantáneas o Azure Backup restauran archivos individuales. NFS requiere una cuenta premium.

Comprueba lo que sabes

¿Qué comando de PowerShell comprueba si un cliente puede llegar a un recurso compartido de Azure Files mediante SMB?

Test-NetConnection -ComputerName <account>.file.core.windows.net -Port 445.

Un usuario elimina un archivo de un recurso compartido. ¿Qué característica le permite restaurarlo por su cuenta en Windows?

Las instantáneas de recursos compartidos, mediante la pestaña Versiones anteriores (Azure Backup también usa instantáneas para esto).

¿Qué tipo de cuenta necesitas para un recurso compartido de archivos NFS?

Una cuenta premium FileStorage.
