Azure Files: crear y configurar recursos compartidos de archivos, instantáneas, eliminación temporal y consideraciones sobre el puerto SMB 445

Azure Files proporciona recursos compartidos de archivos totalmente administrados en la nube que los clientes montan como una unidad de red, usando SMB (Server Message Block) o, en los recursos compartidos premium, NFS (Network File System). Pueden conectarse clientes Windows, Linux y macOS, y los recursos compartidos pueden reemplazar o ampliar los servidores de archivos locales sin que tengas que administrar hardware de servidor ni sistema operativo. Azure File Sync puede almacenar en caché un recurso compartido en servidores Windows Server locales para ofrecer acceso rápido en las sucursales, con el recurso compartido en la nube como copia central.

Creas un recurso compartido de archivos dentro de una cuenta de almacenamiento. Una cuenta estándar de uso general v2 aloja recursos compartidos estándar en almacenamiento de disco duro, con niveles como optimizado para transacciones, hot y cool, que equilibran el costo de almacenamiento con el de transacciones. Una cuenta FileStorage premium aloja recursos compartidos premium en almacenamiento de estado sólido para ofrecer baja latencia y muchas IOPS (operaciones de entrada/salida por segundo), y es la única opción para los recursos compartidos NFS. Cada recurso compartido tiene una cuota o un tamaño aprovisionado, que en los recursos compartidos premium también determina el rendimiento. En el portal ve a la cuenta de almacenamiento > Almacenamiento de datos > Recursos compartidos de archivos > + Recurso compartido de archivos; con la CLI ejecuta az storage share-rm create --resource-group rg-files --storage-account stfiles01 --name finance --quota 1024.

Para montar un recurso compartido en Windows, el botón Conectar del portal genera un script que básicamente ejecuta net use Z: \\<account>.file.core.windows.net\<share> con credenciales, ya sea la clave de la cuenta de almacenamiento o, mejor, la autenticación basada en identidad. En Linux lo montas con el tipo de sistema de archivos cifs, por ejemplo sudo mount -t cifs //<account>.file.core.windows.net/finance /mnt/finance -o vers=3.1.1,credentials=/etc/smbcredentials/<account>.cred,serverino. La ruta UNC (convención de nomenclatura universal) del recurso compartido siempre usa el punto de conexión de archivos de la cuenta.

SMB usa el puerto TCP 445. Los clientes fuera de Azure se conectan a través de internet, y muchos proveedores de servicios de internet y redes corporativas bloquean el puerto 445 saliente por culpa de antiguos gusanos de SMB. Si un montaje falla desde una oficina, pruébalo con PowerShell: Test-NetConnection -ComputerName <account>.file.core.windows.net -Port 445. Si TcpTestSucceeded es False, las opciones son abrir el puerto en el firewall, conectarse mediante una VPN de sitio a sitio, una VPN de punto a sitio o ExpressRoute (normalmente con un punto de conexión privado), o usar Azure File Sync para que los usuarios se comuniquen con un servidor local por la red de la oficina. Las conexiones desde fuera de la región de Azure requieren SMB 3.x con cifrado, así que los clientes antiguos con SMB 2.1 no pueden conectarse a través de internet.

Las instantáneas de recursos compartidos capturan una copia de solo lectura de todo un recurso compartido de archivos en un momento dado. Son incrementales, así que solo los cambios desde la instantánea anterior ocupan espacio. Los usuarios de Windows pueden abrir Versiones anteriores en una carpeta del recurso compartido montado para restaurar archivos por sí mismos, y los administradores pueden examinar las instantáneas en el portal. Azure Backup para Azure Files usa internamente las instantáneas de recursos compartidos y agrega programación, retención y una interfaz de restauración. La eliminación temporal de recursos compartidos de archivos conserva un recurso compartido eliminado, incluidas sus instantáneas, durante un período de retención que defines, para que puedas recuperarlo desde la lista Recursos compartidos de archivos con Mostrar recursos compartidos eliminados. Está habilitada de forma predeterminada en las cuentas de almacenamiento nuevas. La eliminación temporal funciona a nivel de recurso compartido; para recuperar un archivo individual usas instantáneas o copias de seguridad.

Veamos un ejemplo práctico. El personal de una sucursal no puede asignar un nuevo recurso compartido de archivos de Azure, aunque se monta bien desde una VM de Azure en la misma región. Ejecutas Test-NetConnection hacia el punto de conexión del recurso compartido en el puerto 445 desde la oficina y ves que falla porque el proveedor de internet bloquea el puerto. En lugar de recurrir al proveedor, creas un punto de conexión privado para el subrecurso file en la red virtual central, configuras el DNS para que el nombre de la cuenta se resuelva a la IP privada y enrutas el acceso por la VPN de sitio a sitio existente. El recurso compartido se monta, y configuras Azure Backup para tomar instantáneas diarias de modo que los usuarios puedan restaurar sus propios archivos desde Versiones anteriores.

Errores comunes: intentar crear un recurso compartido NFS en una cuenta estándar; culpar a los permisos cuando el problema real es el puerto 445 bloqueado; esperar que la eliminación temporal del recurso compartido restaure un solo archivo eliminado; suponer que las instantáneas son copias completas que duplican el costo; montar con la clave de la cuenta de almacenamiento para los usuarios habituales cuando está disponible el acceso basado en identidad; y conectarse desde un cliente SMB antiguo que no admite cifrado.

Redacción típica del examen: 'se monta desde una VM de Azure pero no desde el entorno local' apunta al puerto 445 bloqueado. '¿Qué comando prueba la conectividad?' apunta a Test-NetConnection en el puerto 445. 'El usuario restaura una versión anterior de un archivo' apunta a las instantáneas de recursos compartidos. 'Recuperar un recurso compartido eliminado' apunta a la eliminación temporal de recursos compartidos. 'NFS' o 'baja latencia y muchas IOPS' apunta a una cuenta FileStorage premium. 'Almacenar archivos en caché localmente en las sucursales' apunta a Azure File Sync.

Términos clave

Recurso compartido de archivos de Azure (Azure file share)
Un recurso compartido SMB o NFS administrado, alojado en una cuenta de almacenamiento, que los clientes montan como una unidad de red.
Cuenta FileStorage
El tipo de cuenta de almacenamiento premium para recursos compartidos de archivos en SSD, obligatorio para los recursos compartidos NFS.
Instantánea de recurso compartido (share snapshot)
Una copia incremental y de solo lectura de todo un recurso compartido de archivos en un momento dado.
Eliminación temporal de recursos compartidos de archivos
Una configuración que conserva los recursos compartidos eliminados durante un período para poder recuperarlos.
Puerto 445
El puerto TCP que usa SMB, a menudo bloqueado por proveedores de internet y firewalls, lo que impide montar recursos compartidos de Azure desde fuera.
Azure File Sync
Un servicio que almacena en caché un recurso compartido de archivos de Azure en servidores Windows Server locales para ofrecer acceso rápido.
Ejemplo real

El personal de una sucursal no puede asignar un nuevo recurso compartido de archivos de Azure, aunque funciona desde una VM de Azure. El administrador ejecuta Test-NetConnection hacia el punto de conexión del recurso compartido en el puerto 445 desde la oficina y ve que falla porque el proveedor de internet bloquea el puerto. La solución es enrutar el acceso por la VPN de sitio a sitio existente hacia un punto de conexión privado de la cuenta de almacenamiento, con un DNS que resuelva el nombre de la cuenta a la IP privada.

Consejo para el examen: Si un recurso compartido se monta desde VM de Azure pero no desde el entorno local, sospecha primero del puerto 445 bloqueado. La eliminación temporal protege recursos compartidos completos; las instantáneas o Azure Backup restauran archivos individuales. NFS requiere una cuenta premium.

Comprueba lo que sabes

¿Qué comando de PowerShell comprueba si un cliente puede llegar a un recurso compartido de archivos de Azure por SMB?

Test-NetConnection -ComputerName <account>.file.core.windows.net -Port 445.

Un usuario elimina un archivo de un recurso compartido. ¿Qué función le permite restaurarlo por sí mismo en Windows?

Las instantáneas de recursos compartidos, a través de la pestaña Versiones anteriores (Azure Backup también usa instantáneas para esto).

¿Qué tipo de cuenta necesitas para un recurso compartido de archivos NFS?

Una cuenta FileStorage premium.

Un administrador elimina por error todo un recurso compartido de archivos. ¿Cómo lo recuperas?

Si la eliminación temporal de recursos compartidos está habilitada, muestra los recursos compartidos eliminados en la lista Recursos compartidos de archivos y recupéralo dentro del período de retención.
