Microsoft Certified: Azure Administrator Associate AZ-104

Propiedades de usuarios y grupos, licencias (incluida la asignación de licencias basada en grupos), usuarios externos (invitados B2B) y restablecimiento de contraseña de autoservicio

Un objeto de usuario en Microsoft Entra ID contiene más que un nombre y una contraseña. Propiedades como el puesto, el departamento, el gerente, la ubicación de la oficina y la ubicación de uso (usage location) las usan las reglas de grupos dinámicos, la libreta de direcciones y las licencias. Las editas en la página Properties del usuario, de forma masiva con Microsoft Graph PowerShell o, para usuarios sincronizados, en Active Directory local. Los grupos también tienen propiedades: nombre, descripción, propietarios (que pueden administrar la pertenencia sin ser administradores), tipo de pertenencia, y si al grupo se le pueden asignar roles de Entra, una opción que solo puedes elegir al crearlo.

Las licencias de productos como Microsoft 365 o Entra ID P1 y P2 se asignan por usuario. Antes de poder asignar una licencia, el usuario debe tener establecida una ubicación de uso, porque algunos servicios no están disponibles en todos los países; sin ella la asignación falla. Puedes asignar una licencia directamente en la página Licenses del usuario, pero a gran escala eso se vuelve difícil de controlar.

La asignación de licencias basada en grupos (group-based licensing) resuelve eso: asignas la licencia a un grupo y cada miembro la recibe, con la opción de desactivar planes de servicio individuales dentro del producto. Cuando un usuario se une al grupo obtiene la licencia; cuando sale, se le quita. Combínala con un grupo dinámico y las licencias siguen automáticamente los datos de Recursos Humanos. La asignación de licencias basada en grupos requiere Entra ID P1 o un producto que lo incluya. Si la asignación falla, por ejemplo porque no hay suficientes licencias o falta la ubicación de uso, el grupo muestra a los usuarios en estado de error para que puedas corregirlos.

La colaboración externa usa Microsoft Entra B2B. Invitas a un socio por su dirección de correo (Users > New user > Invite external user), y se crea un objeto de usuario invitado en tu tenant con el tipo de usuario Guest. El socio inicia sesión con su propia identidad de su organización de origen, una cuenta Microsoft o un código de acceso de un solo uso, así que nunca administras su contraseña. Una vez que acepta la invitación, puedes poner a los invitados en grupos y darles roles de RBAC como a cualquier otro usuario. La configuración de colaboración externa controla quién puede invitar a invitados y cuánto pueden ver los invitados de tu directorio, y puedes permitir o bloquear dominios de socios específicos.

El restablecimiento de contraseña de autoservicio (SSPR) permite a los usuarios restablecer una contraseña olvidada sin llamar a la mesa de ayuda. Lo habilitas en Password reset para None (ninguno), Selected (un grupo) o All (todos los usuarios), eliges qué métodos de autenticación se permiten (por ejemplo la aplicación Microsoft Authenticator, teléfono móvil, correo electrónico o preguntas de seguridad) y defines cuántos métodos se requieren para restablecer: uno o dos. Los usuarios deben registrar sus métodos antes de poder usar SSPR, y puedes exigir el registro al iniciar sesión. Para usuarios sincronizados desde el entorno local, se necesita la escritura diferida de contraseñas (password writeback) mediante Microsoft Entra Connect o Cloud Sync para que la nueva contraseña se escriba de vuelta en Active Directory. Las cuentas de administrador siempre usan una directiva integrada más estricta que requiere dos métodos y no permite preguntas de seguridad.

Términos clave

Usage location (ubicación de uso)
La propiedad de país de un usuario que debe establecerse antes de poder asignarle una licencia.
Group-based licensing (licencias basadas en grupos)
Asignar una licencia a un grupo para que todos los miembros la hereden y la pierdan al salir del grupo.
B2B guest user (usuario invitado B2B)
Una identidad externa invitada a tu tenant con tipo de usuario Guest, que inicia sesión con credenciales de su propia organización o cuenta.
Self-service password reset (SSPR) (restablecimiento de contraseña de autoservicio)
Una característica que permite a los usuarios registrados restablecer su propia contraseña usando métodos de autenticación verificados.
Password writeback (escritura diferida de contraseñas)
Una característica de sincronización que escribe de vuelta en Active Directory local las contraseñas restablecidas en la nube.
Ejemplo real

Una firma de ingeniería agrega un grupo dinámico para todos los usuarios del departamento Engineering y le asigna la licencia de Microsoft 365. Cuando se crea la cuenta de un nuevo ingeniero con ubicación de uso Canadá y departamento Engineering, la licencia llega automáticamente. Un contratista de una firma asociada es invitado como invitado B2B y agregado a un grupo del proyecto, e inicia sesión con la cuenta de su propia empresa.

Consejo para el examen: Si falla la asignación de una licencia, revisa primero la ubicación de uso. En preguntas sobre SSPR, recuerda que las opciones de alcance son None, Selected (un solo grupo) y All, y que los usuarios locales necesitan password writeback.

Comprueba lo que sabes

La asignación de una licencia a un usuario nuevo falla con un error. El tenant tiene licencias disponibles. ¿Cuál es la causa más probable?

La ubicación de uso del usuario no está establecida; es obligatoria antes de poder asignar una licencia.

¿Cómo se autentica un invitado B2B en tu tenant?

Con su propia identidad de su organización de origen, una cuenta Microsoft o un código de acceso de un solo uso; tu tenant no almacena su contraseña.

Habilitas SSPR para usuarios sincronizados, pero las contraseñas restablecidas no funcionan en el entorno local. ¿Qué falta?

Password writeback mediante Microsoft Entra Connect o Cloud Sync, que escribe la nueva contraseña de vuelta en Active Directory.
