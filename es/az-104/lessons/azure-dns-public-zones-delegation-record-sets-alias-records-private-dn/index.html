Azure DNS: zonas públicas, delegación, conjuntos de registros, registros de alias; zonas DNS privadas con registro automático

Azure DNS hospeda zonas DNS (Domain Name System) en la red global de servidores de nombres de Microsoft, así que administras tus registros con las mismas herramientas, RBAC y plantillas que el resto de Azure. No registra nombres de dominio por ti; compras un dominio a un registrador y luego hospedas su zona en Azure DNS. Hay dos tipos de zonas: las zonas públicas responden consultas desde internet, y las zonas privadas responden solo para las redes virtuales que vinculas a ellas.

Crear una zona pública como contoso.com le da un registro SOA (start of authority) y un conjunto de registros NS que enumera cuatro servidores de nombres de Azure asignados a esa zona, con nombres bajo azure-dns.com, azure-dns.net, azure-dns.org y azure-dns.info. La zona no hace nada hasta que delegas el dominio: en tu registrador, reemplaza las entradas de servidores de nombres del dominio por esos cuatro servidores de nombres de Azure. Una vez que el cambio se propaga, los resolvedores de internet consultan a Azure DNS por tus registros. Puedes comprobarlo con nslookup -type=NS contoso.com.

Delegar un subdominio funciona de la misma manera dentro del DNS. Para hospedar dev.contoso.com como su propia zona, quizá administrada por otro equipo, crea la zona secundaria y luego, en la zona primaria contoso.com, agrega un conjunto de registros NS llamado dev que contenga los servidores de nombres de la zona secundaria.

Los registros se organizan en conjuntos de registros (record sets): todos los registros con el mismo nombre y tipo forman un conjunto, con un único TTL (time to live) que indica cuánto tiempo pueden los resolvedores almacenar en caché la respuesta. Por ejemplo, el conjunto de registros A www puede contener varias direcciones IP. Los tipos admitidos incluyen A, AAAA, CNAME, MX, NS, PTR, SOA, SRV, TXT y CAA. Un conjunto de registros CNAME solo puede contener un registro, y no puedes crear un CNAME en el ápice de la zona (el propio contoso.com), lo cual es una regla del estándar DNS.

Los registros de alias (alias records) resuelven dos problemas. Un conjunto de registros de alias de tipo A, AAAA o CNAME apunta a un recurso de Azure en lugar de a un valor fijo: una dirección IP pública, un perfil de Traffic Manager, un punto de conexión de Azure Front Door o de CDN, u otro conjunto de registros de la misma zona. Cuando la IP del recurso cambia, el alias se actualiza automáticamente, así que nunca quedan registros colgantes que apunten a una dirección antigua. Y como un alias A puede estar en el ápice, puedes apuntar contoso.com a un perfil de Traffic Manager o a Front Door, cosa que un CNAME no puede hacer.

Una zona DNS privada, como corp.contoso.com, solo funciona dentro de Azure. La vinculas a VNet mediante vínculos de red virtual (virtual network links); las VM de las VNet vinculadas pueden resolver sus registros mediante el DNS proporcionado por Azure. Al crear un vínculo puedes habilitar el registro automático (auto-registration), y entonces Azure crea y quita automáticamente registros A para las VM de esa VNet a medida que se crean, cambian de IP o se eliminan. Una VNet puede estar vinculada a muchas zonas privadas para resolución, pero solo una de ellas puede tener el registro automático habilitado para esa VNet. Las zonas privadas también son lo que hace que los puntos de conexión privados se resuelvan a sus IP privadas.

Términos clave

DNS zone (zona DNS)
Un contenedor de los registros DNS de un dominio, hospedado por Azure DNS como público o privado.
Delegation (delegación)
Apuntar un dominio o subdominio a los servidores de nombres que hospedan su zona, usando registros NS en el registrador o en la zona primaria.
Record set (conjunto de registros)
Todos los registros DNS con el mismo nombre y tipo en una zona, que comparten un TTL.
Alias record (registro de alias)
Un conjunto de registros A, AAAA o CNAME que hace referencia a un recurso de Azure y se actualiza automáticamente cuando este cambia.
Auto-registration (registro automático)
Una opción del vínculo de una zona DNS privada que mantiene automáticamente registros A para las VM de la VNet vinculada.
Ejemplo real

Una empresa traslada contoso.com a Azure DNS. El administrador crea la zona pública, copia los cuatro servidores de nombres de Azure asignados en la configuración del registrador y agrega un registro de alias A en el ápice que apunta a la IP pública de un Application Gateway. Para los nombres internos, una zona privada corp.contoso.com se vincula a la VNet concentradora con registro automático para que cada VM nueva obtenga un registro automáticamente.

Consejo para el examen: Una zona no hace nada hasta que los registros NS del registrador apuntan a los servidores de nombres de Azure. Usa un registro de alias para el ápice de la zona y para seguir recursos de Azure. Solo una zona privada con registro automático por VNet.

Comprueba lo que sabes

Creaste una zona pública en Azure DNS, pero los usuarios de internet siguen obteniendo los registros antiguos. ¿Qué paso falta?

La delegación: actualizar los servidores de nombres del dominio en el registrador con los cuatro servidores de nombres de Azure DNS.

¿Cómo puedes apuntar contoso.com (el ápice) a un punto de conexión de Azure Front Door?

Crea un registro de alias A en el ápice que haga referencia al recurso de Front Door; no se permite un CNAME en el ápice.

¿Cómo obtienen las VM registros DNS en una zona privada sin trabajo manual?

Vinculando la zona a su VNet con el registro automático habilitado.
