Replicación de objetos y movimiento de datos con AzCopy y Azure Storage Explorer

Mover datos hacia, desde y entre cuentas de almacenamiento es una tarea rutinaria. Azure ofrece una opción automática basada en directivas (la replicación de objetos) y herramientas que ejecutas tú mismo: AzCopy en la línea de comandos y Azure Storage Explorer como aplicación de escritorio.

La replicación de objetos (object replication) copia de forma asíncrona blobs en bloques desde un contenedor de una cuenta de almacenamiento de origen a un contenedor de una cuenta de destino, que puede estar en otra región o incluso en otra suscripción. Los usos típicos son mantener una copia cerca de los usuarios en otra región, alimentar una cuenta de análisis separada o reducir la latencia de lectura. Configuras una directiva de replicación con una o más reglas, cada una emparejando un contenedor de origen con un contenedor de destino, opcionalmente filtradas por prefijo del nombre del blob y una hora mínima de creación para que solo se copien los blobs nuevos.

La replicación de objetos tiene requisitos previos que se evalúan con frecuencia: el control de versiones de blobs (blob versioning) debe estar habilitado en las cuentas de origen y de destino, y la fuente de cambios (change feed) debe estar habilitada en la cuenta de origen. Solo funciona con blobs en bloques, y el contenedor de destino pasa a ser en la práctica de solo lectura para los datos replicados mientras exista la directiva. No reemplaza la redundancia geográfica: es por contenedor, asíncrona, y tú eliges qué replicar, mientras que GRS replica toda la cuenta a la región emparejada y no puedes elegir la región de destino ni qué se replica.

AzCopy es una herramienta gratuita de línea de comandos para copiar datos hacia y desde Blob Storage y Azure Files. Te autenticas con azcopy login (Microsoft Entra ID, que requiere un rol del plano de datos como Storage Blob Data Contributor) o anexando un token SAS a la URL. Comandos comunes:

# <container-url> = la URL completa del contenedor en el punto de conexión blob de la cuenta
azcopy login
azcopy copy "C:\data\*" "<container-url>" --recursive
azcopy sync "C:\data" "<container-url>" --recursive
azcopy copy "<source-container-url>?<SAS>" "<destination-container-url>?<SAS>" --recursive

azcopy copy copia todo lo que le indiques; azcopy sync compara el origen y el destino y copia solo los archivos nuevos o modificados, y opcionalmente elimina los archivos sobrantes en el destino con --delete-destination. Las copias de cuenta a cuenta se ejecutan de servidor a servidor, así que los datos no pasan por tu equipo. AzCopy es la herramienta preferida para transferencias automatizadas por script, grandes o repetibles.

Azure Storage Explorer es una aplicación gráfica gratuita para Windows, macOS y Linux. Te conectas con tu cuenta de Entra, una clave de cuenta, una cadena de conexión o una URL de SAS, y luego exploras contenedores, recursos compartidos de archivos, colas y tablas, subes y descargas archivos, administras niveles de acceso, creas tokens SAS y estableces directivas de acceso. Internamente usa AzCopy para las transferencias. Es adecuada para tareas puntuales y para quienes prefieren una GUI (interfaz gráfica de usuario). Para transferencias sin conexión muy grandes, cuando la red es demasiado lenta, la alternativa son los dispositivos Azure Data Box.

Términos clave

Object replication (replicación de objetos)
Copia asíncrona y basada en directivas de blobs en bloques desde un contenedor de origen a un contenedor de destino en otra cuenta.
Change feed (fuente de cambios)
Un registro ordenado de los cambios en los blobs de una cuenta, requerido en la cuenta de origen para la replicación de objetos.
AzCopy
Una herramienta de línea de comandos para copiar y sincronizar datos con Blob Storage y Azure Files.
Azure Storage Explorer
Una GUI de escritorio gratuita para explorar y administrar cuentas de almacenamiento que usa AzCopy para las transferencias.
Ejemplo real

Una empresa de medios produce videos en West Europe, pero tiene muchos espectadores en East US. El administrador habilita el control de versiones en dos cuentas y la fuente de cambios en la de origen, y luego crea una directiva de replicación de objetos desde el contenedor 'published' de origen hacia un contenedor en East US. Por otro lado, un editor usa Storage Explorer para subir algunos archivos, mientras una tarea programada cada noche ejecuta azcopy sync para enviar la carpeta de salida del servidor de renderizado.

Consejo para el examen: La replicación de objetos necesita control de versiones en ambas cuentas y fuente de cambios en la de origen, y solo maneja blobs en bloques. Usa azcopy sync para actualizaciones incrementales y azcopy copy para copias completas.

Comprueba lo que sabes

La configuración de la replicación de objetos falla. ¿Qué características deben estar habilitadas en las cuentas de origen y de destino?

El control de versiones de blobs en ambas, y la fuente de cambios en la de origen.

¿Qué comando de AzCopy copia solo los archivos nuevos o modificados desde una carpeta local a un contenedor?

azcopy sync, ejecutado con --recursive para incluir subcarpetas.

Un comando de AzCopy autenticado con azcopy login falla con un error de permisos, aunque el usuario es Contributor. ¿Por qué?

La autenticación de Entra para datos de blobs necesita un rol del plano de datos como Storage Blob Data Contributor; Contributor es un rol del plano de control.
