Administración de costos: análisis de costos, presupuestos y alertas de presupuesto, recomendaciones de costos de Azure Advisor y reservas

Azure se factura por consumo, así que los costos pueden crecer en silencio: una VM de prueba olvidada, un disco no conectado o una dirección IP pública que quedó después de un laboratorio siguen generando cargos. Microsoft Cost Management, disponible en el portal sin cargo adicional para los recursos de Azure, te da las herramientas para ver adónde va el dinero, recibir avisos antes de gastar de más y encontrar ahorros. Se espera que un administrador lo configure y actúe en consecuencia, no que solo lea la factura a fin de mes.

El análisis de costos es la vista de informes (Cost Management > Análisis de costos). Eliges un ámbito (grupo de administración, suscripción o grupo de recursos), un intervalo de fechas y una vista, como costos acumulados, costos diarios o costo por servicio. Luego agrupas y filtras por grupo de recursos, nombre del servicio, ubicación, medidor o etiqueta. Agrupar por etiqueta es la forma de hacer contracargos (chargeback) o informes de costos (showback) a los departamentos, y por eso el etiquetado importa. La vista acumulada también muestra el costo previsto para el resto del período, y puedes guardar vistas, anclarlas a paneles o programar exportaciones de los datos de costos a una cuenta de almacenamiento para analizarlos con otras herramientas. Los datos de costos se actualizan varias veces al día, no en tiempo real, así que no esperes que ya aparezca un recurso creado hace un minuto.

Un presupuesto establece un umbral de gasto para un ámbito durante un período de restablecimiento (mensual, trimestral o anual). Le agregas condiciones de alerta como porcentajes del presupuesto, basadas en el costo real o en el costo previsto, por ejemplo 50 por ciento real, 90 por ciento real y 100 por ciento previsto. Cuando se cumple una condición, Azure envía un correo a los destinatarios indicados y puede desencadenar un grupo de acciones, que puede ejecutar un runbook de Azure Automation, una aplicación lógica o una función, por ejemplo para apagar las VM de desarrollo. Los presupuestos nunca detienen los recursos ni el gasto por sí solos; solo notifican, y cualquier detención la debe hacer la automatización que conectes. Una alerta de costo previsto es útil porque te avisa antes de gastar de más, no después.

Azure Advisor analiza tu configuración y tu uso y ofrece recomendaciones en cinco categorías: Costo, Seguridad, Confiabilidad, Excelencia operativa y Rendimiento. Las recomendaciones de costo incluyen apagar o cambiar el tamaño de máquinas virtuales infrautilizadas, eliminar discos administrados no conectados y direcciones IP públicas inactivas, y comprar reservas o planes de ahorro para cargas de trabajo estables. Cada recomendación muestra su ahorro estimado; puedes aplicarla, posponerla o descartarla, y puedes ajustar el umbral de CPU que Advisor usa para considerar que una VM está infrautilizada.

Las reservas de Azure ofrecen un descuento a cambio de comprometerte con un tipo de recurso específico, como una familia de tamaños de VM en una región, durante uno o tres años. La reserva es un descuento de facturación que se aplica automáticamente a los recursos en ejecución que coinciden; no crea ni inicia una VM ni garantiza capacidad para ella. Defines el ámbito de una reserva en un solo grupo de recursos, una sola suscripción, un grupo de administración o de forma compartida en todo el contexto de facturación, para que se beneficie cualquier uso que coincida. Los planes de ahorro de Azure para proceso comprometen un gasto por hora entre servicios y regiones, a cambio de algo menos de descuento y más flexibilidad. Otras palancas son Ventaja híbrida de Azure (Azure Hybrid Benefit, que usa licencias existentes de Windows Server o SQL Server con Software Assurance), las VM de acceso puntual (Spot) para trabajos interrumpibles, las programaciones de apagado automático en VM de desarrollo y el ajuste de tamaño.

Veamos un ejemplo práctico. Un equipo de desarrollo supera una y otra vez el gasto previsto. Creas un presupuesto mensual en el grupo de recursos del equipo con alertas por correo al 80 por ciento real y al 100 por ciento previsto, y vinculas la alerta de costo previsto a un grupo de acciones que ejecuta un runbook que detiene las VM etiquetadas Environment = Dev. En la categoría Costo de Advisor encuentras tres discos no conectados y una VM con un uso de CPU promedio bajo, así que el equipo elimina los discos y cambia el tamaño de la VM. Para las VM de la base de datos de producción, que funcionan todo el tiempo con el mismo tamaño, compras una reserva con ámbito en la suscripción de producción.

Errores comunes: suponer que un presupuesto limita el gasto; esperar que una reserva implemente o mantenga una VM; comprar una reserva para cargas de trabajo que cambian de tamaño o se apagan con frecuencia, donde encaja mejor un plan de ahorro o nada; olvidar que los datos de costos llegan con retraso; y depender de etiquetas de grupos de recursos que nunca se copiaron a los recursos, lo que deja gasto sin etiquetar en el análisis de costos.

Redacción típica del examen: 'notificar cuando el gasto llegue a' apunta a un presupuesto con condiciones de alerta. 'Detener automáticamente los recursos cuando se alcance el presupuesto' apunta a un presupuesto más un grupo de acciones que ejecuta automatización. 'Identificar VM infrautilizadas' o 'recomendaciones para reducir costos' apunta a Azure Advisor. 'Carga de trabajo estable que se ejecuta continuamente durante años' apunta a una reserva. 'Desglosar los costos por departamento' apunta a etiquetas y análisis de costos agrupado por etiqueta. 'Reutilizar licencias locales de Windows' apunta a Ventaja híbrida de Azure.

Términos clave

Análisis de costos (cost analysis)
La vista de Cost Management para explorar costos reales y previstos por ámbito, agrupados y filtrados por dimensiones como la etiqueta.
Presupuesto (budget)
Un umbral de gasto para un ámbito y un período con condiciones de alerta; notifica pero no detiene el gasto.
Grupo de acciones (action group)
Un conjunto reutilizable de acciones de notificación y automatización que los presupuestos y las alertas pueden desencadenar.
Azure Advisor
Un servicio que analiza tus recursos y ofrece recomendaciones de Costo, Seguridad, Confiabilidad, Excelencia operativa y Rendimiento.
Reserva (reservation)
Un compromiso de uno o tres años con un tipo de recurso a cambio de un descuento de facturación sobre el uso que coincida.
Plan de ahorro para proceso (savings plan)
Un compromiso de gasto por hora en proceso que descuenta el uso entre servicios y regiones.
Ventaja híbrida de Azure (Azure Hybrid Benefit)
Una ventaja de licencias que permite usar en Azure licencias existentes de Windows Server o SQL Server con Software Assurance.
Ejemplo real

Un equipo de desarrollo supera una y otra vez su presupuesto. El administrador crea un presupuesto mensual en el grupo de recursos del equipo con alertas por correo al 80 por ciento real y al 100 por ciento previsto, y vincula un grupo de acciones a un runbook que detiene las VM de desarrollo etiquetadas. Advisor también señala tres discos inactivos y una VM con poco uso de CPU, que el equipo elimina y redimensiona, y el análisis de costos del mes siguiente muestra el ahorro.

Consejo para el examen: Los presupuestos alertan; no imponen límites. Si una pregunta plantea cómo detener automáticamente los recursos cuando el gasto alcanza un umbral, la respuesta es un presupuesto con un grupo de acciones que ejecuta automatización. Las reservas son descuentos de facturación, no capacidad.

Comprueba lo que sabes

Un presupuesto llega al 100 por ciento. ¿Se detienen los recursos?

No. Los presupuestos solo envían alertas o desencadenan grupos de acciones; detener recursos requiere automatización conectada al grupo de acciones.

¿Dónde encuentras una recomendación para cambiar el tamaño de una VM infrautilizada?

En Azure Advisor, categoría Costo (también se muestra en Cost Management).

¿Cómo muestras los costos por departamento en el análisis de costos?

Etiqueta los recursos con una etiqueta de departamento y agrupa el análisis de costos por esa etiqueta.

¿Comprar una reserva de VM crea una máquina virtual?

No. Una reserva es un descuento de facturación que se aplica automáticamente a las VM en ejecución que coinciden; las VM las sigues implementando tú.
