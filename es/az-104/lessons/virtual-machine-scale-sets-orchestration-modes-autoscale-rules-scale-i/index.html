Virtual Machine Scale Sets: modos de orquestación, reglas de escalado automático y reducción horizontal

Un Virtual Machine Scale Set (VMSS, conjunto de escalado de máquinas virtuales) administra un grupo de VM con equilibrio de carga como un solo recurso. En lugar de crear cada VM a mano, describes el modelo una vez (imagen, tamaño, red, extensiones) e indicas al conjunto de escalado cuántas instancias ejecutar. Puede agregar y quitar instancias automáticamente según la demanda, repartirlas entre zonas de disponibilidad y dominios de error, e implementar actualizaciones. Los conjuntos de escalado son la respuesta estándar para niveles sin estado como front-ends web y trabajadores por lotes.

Los conjuntos de escalado tienen dos modos de orquestación, que se eligen al crearlos. La orquestación Uniform usa instancias idénticas creadas a partir de un modelo; las administras principalmente mediante las API del conjunto de escalado, lo que es adecuado para cargas grandes sin estado. La orquestación Flexible, el modo recomendado para implementaciones nuevas, administra VM estándar de Azure que también puedes administrar individualmente con los comandos normales de VM. Te permite mezclar tamaños de VM y capacidad Spot y normal, reparte las instancias entre dominios de error y zonas para alta disponibilidad, e incluso puede incorporar VM agregadas manualmente. Si una pregunta del examen requiere mezclar tamaños o tratar las instancias como VM normales, la respuesta es Flexible.

El escalado automático (autoscale) se configura en la hoja Scaling del conjunto de escalado, usando el escalado automático de Azure Monitor. Estableces un número mínimo, máximo y predeterminado de instancias, y luego agregas reglas. Una regla de escalado horizontal (scale-out) podría decir: cuando el porcentaje promedio de CPU entre instancias sea mayor que 70 por ciento durante 10 minutos, aumentar el recuento en 2. Una regla de reducción horizontal (scale-in) es el reflejo: cuando la CPU promedio esté por debajo del 30 por ciento durante 10 minutos, disminuir el recuento en 1. Cada regla tiene un periodo de enfriamiento (cool down) durante el cual no ocurre más escalado, para que la métrica se estabilice. Crea siempre reglas de reducción junto con las reglas de escalado horizontal; de lo contrario, el conjunto crece y nunca se reduce. Los perfiles basados en programación cambian los límites en horarios definidos, por ejemplo un mínimo más alto en horario laboral, y el escalado automático predictivo puede escalar por adelantado ante patrones de carga recurrentes.

El escalado automático usa el mínimo como piso aunque las reglas indiquen otra cosa, y el recuento predeterminado se usa cuando las métricas no están disponibles. Las reglas pueden usar métricas del host como CPU, red y disco, o métricas del invitado y de Application Insights.

Al reducir horizontalmente, la directiva de reducción (scale-in policy) decide qué instancias se quitan. La directiva Default primero equilibra las instancias entre zonas de disponibilidad y dominios de error, y luego elimina la instancia con el ID de instancia más alto. NewestVM quita primero las instancias creadas más recientemente, y OldestVM quita las más antiguas, ambas manteniendo el equilibrio entre zonas. La protección de instancias (instance protection) te permite marcar una VM como 'protect from scale-in' para que el escalado automático nunca la quite, o 'protect from scale set actions' para que también quede excluida de las actualizaciones y otras operaciones del conjunto de escalado.

La directiva de actualización (upgrade policy) controla cómo llegan los cambios del modelo a las instancias existentes: Manual (tú actualizas las instancias), Automatic (todas las instancias se actualizan sin orden garantizado, con posible tiempo de inactividad) o Rolling (por lotes, con comprobaciones de estado entre ellos). Combina un conjunto de escalado con un equilibrador de carga o Application Gateway y un sondeo de estado o la extensión Application Health para que el tráfico solo llegue a las instancias en buen estado.

Términos clave

Virtual Machine Scale Set (conjunto de escalado de máquinas virtuales)
Un recurso que implementa y administra un grupo de VM con equilibrio de carga a partir de un modelo común, con escalado automático.
Flexible orchestration (orquestación Flexible)
El modo de conjunto de escalado recomendado que administra VM estándar, permite tamaños mixtos y reparte las instancias entre dominios de error y zonas.
Autoscale rule (regla de escalado automático)
Una condición sobre una métrica, en una ventana de tiempo, que agrega o quita instancias por un número o un porcentaje.
Scale-in policy (directiva de reducción horizontal)
La regla (Default, NewestVM u OldestVM) que decide qué instancias se eliminan al reducir horizontalmente.
Instance protection (protección de instancias)
Una configuración que excluye una instancia específica de la reducción horizontal o de todas las acciones del conjunto de escalado.
Ejemplo real

Un sitio de venta de boletos recibe mucho tráfico cuando abren las ventas. El administrador crea un conjunto de escalado Flexible en tres zonas con un mínimo de 2 y un máximo de 20 instancias, una regla para agregar 3 instancias cuando la CPU promedio supera el 70 por ciento durante 5 minutos, una regla para quitar 1 cuando baja del 25 por ciento durante 15 minutos, y un perfil de programación que eleva el mínimo a 8 los días de venta.

Consejo para el examen: Combina siempre las reglas de escalado horizontal con reglas de reducción. La directiva de reducción Default equilibra zonas y dominios de error y luego quita el ID de instancia más alto; usa la protección de instancias para conservar una VM específica. Los tamaños de VM mixtos requieren orquestación Flexible.

Comprueba lo que sabes

Un conjunto de escalado escala horizontalmente bajo carga, pero nunca vuelve a reducirse. ¿Cuál es la causa probable?

No hay una regla de reducción (o su umbral nunca se cumple); el escalado automático necesita una regla explícita para disminuir el recuento.

¿Qué instancia se quita primero con la directiva de reducción Default en un conjunto de una sola zona con dominios de error equilibrados?

La instancia con el ID de instancia más alto, después de equilibrar entre dominios de error.

¿Cómo impides que el escalado automático quite una VM que contiene datos de depuración?

Habilita la protección de instancias 'protect from scale-in' en esa instancia.
