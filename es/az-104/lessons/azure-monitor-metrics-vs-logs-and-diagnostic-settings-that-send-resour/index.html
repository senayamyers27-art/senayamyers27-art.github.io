Métricas vs. registros en Azure Monitor, y configuraciones de diagnóstico que envían registros de recursos a un área de trabajo de Log Analytics

Azure Monitor es el servicio de la plataforma que recopila, almacena y analiza la telemetría de los recursos de Azure, los sistemas operativos y las aplicaciones. Casi todo lo que hace se basa en dos tipos de datos: métricas y registros (logs). Saber cuál es cuál, y qué se recopila automáticamente, responde una gran parte de las preguntas sobre supervisión.

Las métricas son valores numéricos muestreados a intervalos regulares y almacenados como una serie temporal, como Percentage CPU de una VM, Transactions de una cuenta de almacenamiento o Data Path Availability de un equilibrador de carga. Las métricas de plataforma se recopilan automáticamente para los recursos de Azure sin ninguna configuración, son ligeras y casi en tiempo real, lo que las hace ideales para gráficos y alertas rápidas. Las exploras en Metrics explorer, eligiendo un recurso, una métrica, una agregación (promedio, mínimo, máximo, suma, recuento) y, opcionalmente, dividiéndolas por una dimensión. Las métricas de plataforma se conservan durante un periodo limitado (93 días); envíalas a un área de trabajo si necesitas una retención más larga o quieres consultarlas junto con otros datos.

Los registros son entradas de eventos u observaciones con muchas propiedades, como un inicio de sesión, una solicitud HTTP, un evento de Windows o una lectura de un contador de rendimiento con el nombre de su equipo. Se almacenan en un área de trabajo de Log Analytics (Log Analytics workspace), donde los consultas con KQL (Kusto Query Language), correlacionas datos de muchos orígenes y los conservas durante un periodo de retención configurable. Los registros son más completos, pero tardan un poco más en llegar que las métricas.

Tres orígenes de registros importan a nivel de Azure. El registro de actividad (activity log) registra los eventos del plano de control de una suscripción: quién creó, cambió o eliminó qué recurso y cuándo, además de los eventos de estado del servicio. Se recopila automáticamente y se conserva 90 días en el portal. Los registros de recursos (resource logs) registran lo que sucede dentro de un recurso, como las solicitudes de acceso a Key Vault, las operaciones de lectura y escritura de almacenamiento o los eventos de NSG. No se recopilan en absoluto hasta que creas una configuración de diagnóstico. Los registros del SO invitado y los contadores de rendimiento de dentro de las VM necesitan el Azure Monitor Agent, que se trata por separado.

Una configuración de diagnóstico (diagnostic setting) se define por recurso (Monitoring > Diagnostic settings). Eliges las categorías de registros o grupos de categorías (como allLogs o audit) y opcionalmente AllMetrics, y luego uno o más destinos: un área de trabajo de Log Analytics para consultas y alertas, una cuenta de almacenamiento para archivado económico a largo plazo, un event hub para transmitir a un sistema SIEM (administración de información y eventos de seguridad) de terceros, o una solución de un socio. El registro de actividad también tiene configuraciones de diagnóstico a nivel de suscripción, para que pueda enviarse a un área de trabajo con una retención más larga y consultas entre suscripciones.

Como cada recurso necesita su propia configuración de diagnóstico, las organizaciones usan Azure Policy con el efecto DeployIfNotExists, como las definiciones integradas que configuran las opciones de diagnóstico hacia un área de trabajo de Log Analytics, para crearlas automáticamente en cada recurso nuevo.

Términos clave

Metrics (métricas)
Datos numéricos de series temporales muestreados a intervalos regulares, recopilados automáticamente para los recursos de Azure.
Logs (registros)
Entradas de eventos y observaciones con muchas propiedades, almacenadas en un área de trabajo de Log Analytics y consultadas con KQL.
Activity log (registro de actividad)
El registro a nivel de suscripción de las operaciones del plano de control y los eventos de estado del servicio.
Resource logs (registros de recursos)
Registros de las operaciones dentro de un recurso, recopilados solo cuando se configura una configuración de diagnóstico.
Diagnostic setting (configuración de diagnóstico)
Una configuración por recurso que envía los registros y métricas seleccionados a un área de trabajo, una cuenta de almacenamiento, un event hub o un socio.
Ejemplo real

Seguridad quiere que cada acceso a Key Vault quede registrado y se pueda buscar durante un año. El administrador crea un área de trabajo de Log Analytics con retención de un año y asigna una directiva DeployIfNotExists que agrega una configuración de diagnóstico que envía la categoría audit de cada Key Vault a esa área de trabajo, y luego ejecuta una tarea de corrección para los almacenes existentes.

Consejo para el examen: Las métricas y el registro de actividad son automáticos; los registros de recursos requieren una configuración de diagnóstico. Elige el destino según el propósito: área de trabajo para consultar y alertar, cuenta de almacenamiento para archivar a bajo costo, event hub para transmitir a herramientas externas.

Comprueba lo que sabes

Las operaciones de lectura de una cuenta de almacenamiento no aparecen en Log Analytics. ¿Qué debes configurar?

Una configuración de diagnóstico en el servicio blob de la cuenta de almacenamiento que envíe sus registros al área de trabajo.

¿Qué es mejor para una alerta que debe activarse en menos de un minuto ante un uso alto de CPU: métricas o registros?

Métricas, que son casi en tiempo real y ligeras.

¿Dónde averiguas quién eliminó una red virtual la semana pasada?

En el registro de actividad, que registra las operaciones del plano de control con el autor de la llamada.
