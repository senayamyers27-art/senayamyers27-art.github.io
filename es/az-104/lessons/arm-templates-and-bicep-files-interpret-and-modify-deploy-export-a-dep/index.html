Plantillas ARM y archivos Bicep: interpretar y modificar, implementar, exportar una implementación como plantilla y convertir ARM JSON a Bicep

La infraestructura como código significa describir los recursos de Azure en archivos y dejar que Azure Resource Manager (ARM) los cree, en lugar de hacer clic en el portal. Los archivos son repetibles, revisables y quedan bajo control de versiones. Los formatos nativos de Azure son las plantillas ARM, escritas en JSON, y Bicep, un lenguaje más sencillo que se compila a ARM JSON. El examen espera que sepas leer ambos, cambiar un valor e implementar.

Una plantilla ARM tiene una estructura fija: $schema y contentVersion, luego parameters (valores que se proporcionan en el momento de la implementación, como el nombre de una VM), variables (valores calculados dentro de la plantilla), resources (lo que se va a implementar, cada uno con type, apiVersion, name, location y properties) y outputs (valores que se devuelven después de la implementación). Las expresiones entre corchetes llaman a funciones de plantilla, por ejemplo [resourceGroup().location] o [parameters('storageName')]. dependsOn indica el orden entre recursos.

Bicep expresa lo mismo con menos sintaxis. Esta es una cuenta de almacenamiento con un parámetro y una salida:

param storageName string
param location string = resourceGroup().location

resource sa 'Microsoft.Storage/storageAccounts@2023-01-01' = {
  name: storageName
  location: location
  sku: { name: 'Standard_LRS' }
  kind: 'StorageV2'
}

output blobEndpoint string = sa.properties.primaryEndpoints.blob

Léela de arriba hacia abajo: param declara entradas (con un valor predeterminado opcional), resource declara un recurso con un nombre simbólico (sa), un tipo y una versión de API, y output devuelve un valor. Bicep resuelve las dependencias automáticamente cuando un recurso hace referencia al nombre simbólico de otro. Para cambiar la redundancia, editarías Standard_LRS a Standard_GRS. Las piezas reutilizables van en módulos (module net './network.bicep' = { ... }). Los valores de los parámetros pueden venir de un archivo de parámetros (.json o .bicepparam) para que la misma plantilla implemente desarrollo y producción con valores diferentes.

Puedes obtener una plantilla a partir de recursos existentes. En el portal, un grupo de recursos o un recurso tiene Export template en Automation, que genera una plantilla de los recursos actuales; una implementación anterior en la lista Deployments del grupo de recursos también ofrece su plantilla original. Las plantillas exportadas son un punto de partida: a menudo tienen valores fijos en el código, incluyen propiedades de solo lectura y pueden no admitir todos los tipos de recurso, así que las parametrizas y las limpias antes de reutilizarlas.

La conversión entre formatos se hace con la CLI de Bicep, incluida en la Azure CLI. az bicep decompile --file main.json convierte una plantilla ARM JSON en un archivo Bicep en la medida de lo posible, que luego revisas para corregir las advertencias. az bicep build --file main.bicep compila Bicep a ARM JSON. Rara vez necesitas compilar manualmente, porque az deployment group create y New-AzResourceGroupDeployment aceptan archivos .bicep directamente. La página Deploy a custom template del portal acepta ARM JSON y te permite editarlo antes de implementarlo.

Términos clave

ARM template (plantilla ARM)
Un archivo JSON que declara recursos, parámetros, variables y salidas de Azure para que Azure Resource Manager los implemente.
Bicep
Un lenguaje específico de dominio para Azure que se compila a ARM JSON, con una sintaxis más sencilla y dependencias automáticas.
Parameter (parámetro)
Un valor que se proporciona en el momento de la implementación para que una plantilla se pueda reutilizar con distintas entradas.
Decompile (descompilar)
Convertir una plantilla ARM JSON a Bicep con az bicep decompile.
Ejemplo real

Un administrador creó a mano en el portal un entorno de aplicación web que funciona y quiere recrearlo para un equipo de pruebas. Usa Export template en el grupo de recursos, descompila el JSON a Bicep, reemplaza los nombres fijos por parámetros y lo implementa en un grupo de recursos nuevo con un archivo de parámetros de prueba.

Consejo para el examen: Ten claro de dónde vienen los valores: los parámetros se proporcionan en la implementación, las variables se calculan en la plantilla y las salidas se devuelven después. az bicep decompile convierte JSON a Bicep; az bicep build hace lo contrario.

Comprueba lo que sabes

¿Qué sección de la plantilla editarías para que el tamaño de la VM se pueda elegir en el momento de la implementación?

Agrega un parámetro para el tamaño en la sección parameters (param en Bicep) y haz referencia a él en el recurso de la VM.

¿Cómo conviertes una plantilla ARM JSON existente a Bicep?

Ejecuta az bicep decompile --file template.json y revisa el resultado.

¿Dónde puedes obtener una plantilla de recursos que se crearon manualmente en el portal?

Con Export template en el grupo de recursos o el recurso (en Automation), y luego la limpias y la parametrizas.
