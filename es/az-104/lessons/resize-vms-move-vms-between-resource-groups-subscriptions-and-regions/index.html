Cambiar el tamaño de VM, mover VM entre grupos de recursos, suscripciones y regiones, y administrar discos

Las cargas de trabajo cambian después de la implementación, así que los administradores suelen cambiar el tamaño de las máquinas virtuales (VM), trasladarlas y ajustar sus discos. Algunas de estas operaciones se realizan mientras la VM está en ejecución, otras necesitan un reinicio, otras necesitan que la VM esté desasignada, y cada tipo de movimiento usa una herramienta distinta. Saber cuál es cuál es lo que evalúa el examen, porque elegir mal implica un tiempo de inactividad innecesario o una operación que simplemente falla.

Para cambiar el tamaño, abre la hoja Tamaño de la VM, o ejecuta az vm resize --resource-group rg-app --name vm-report --size Standard_E8s_v5, o en PowerShell cambia $vm.HardwareProfile.VmSize y ejecuta Update-AzVM. Cambiar el tamaño de una VM en ejecución la reinicia. La lista de tamaños que se muestra depende del clúster de hardware que aloja la VM en ese momento. Si el tamaño que quieres no aparece, primero detén (desasigna) la VM; entonces se puede elegir cualquier tamaño disponible en la región, y Azure coloca la VM en hardware adecuado cuando se inicia. Cambiar el tamaño puede modificar el número de discos de datos e interfaces de red (NIC) que admite la VM, así que revisa esos límites al pasar a un tamaño más pequeño, y recuerda que el contenido del disco temporal se pierde si la VM se traslada a hardware nuevo.

Mover una VM a otro grupo de recursos o suscripción usa la operación normal de movimiento de recursos (Mover en el portal, o az resource move). Mueve la VM junto con sus recursos dependientes, como sus discos, interfaces de red y direcciones IP públicas. La VM no cambia de región y el movimiento no la detiene, pero su identificador de recurso cambia. Ambas suscripciones deben estar en el mismo inquilino de Microsoft Entra, el destino debe tener registrados los proveedores de recursos necesarios, y algunas configuraciones, como las VM creadas a partir de ciertos planes de Marketplace, tienen restricciones adicionales.

Mover una VM a otra región no es una operación de movimiento; es un traslado que crea una copia en la región de destino. Azure Resource Mover organiza el traslado de VM y recursos relacionados, como redes virtuales, grupos de seguridad de red (NSG) y equilibradores de carga, entre regiones: agregas los recursos, comprueba las dependencias, y tú preparas, inicias el movimiento y luego lo confirmas o lo descartas. Azure Site Recovery también puede replicar una VM a otra región y conmutarla por error de forma permanente. En cualquier caso, espera direcciones IP nuevas y algo de tiempo de inactividad en el cambio, y limpia después los recursos de origen.

Administración de discos: puedes conectar discos de datos nuevos o existentes en la hoja Discos de la VM mientras está en ejecución (az vm disk attach --vm-name vm-report --resource-group rg-app --name data02 --new --size-gb 256), y luego inicializarlos y formatearlos en el sistema operativo (Administración de discos en Windows, o particionar, formatear y montar en Linux). Puedes aumentar el tamaño de un disco pero nunca reducirlo; según el tipo de disco y la configuración, una ampliación puede requerir que la VM esté desasignada, y después amplías la partición dentro del sistema operativo. Cambiar el tipo de un disco, por ejemplo de Standard SSD a Premium SSD, se hace con la VM desasignada o el disco desconectado, y los discos Premium necesitan un tamaño de VM que admita almacenamiento Premium. Las instantáneas de disco capturan una copia completa o incremental de un disco administrado, útil antes de cambios arriesgados o para crear un disco nuevo. Desconectar un disco de datos lo conserva como recurso independiente, y eliminar una VM no elimina necesariamente sus discos, así que busca discos huérfanos sin conectar, que siguen costando dinero.

Veamos un ejemplo práctico. Una VM de informes necesita más memoria para los trabajos de cierre de mes. El tamaño de la serie E que quieres no aparece en la lista de cambio de tamaño, así que durante una ventana de mantenimiento desasignas la VM, seleccionas el tamaño nuevo y la vuelves a iniciar. Antes de convertir su disco de datos de Standard SSD a Premium SSD, tomas una instantánea incremental y luego cambias el tipo de disco mientras la VM sigue desasignada. Más adelante, la empresa traslada sus operaciones a otra región, así que usas Azure Resource Mover para trasladar la VM junto con su red virtual y su NSG, confirmas el movimiento, actualizas el DNS a la nueva dirección IP y eliminas los recursos de origen.

Errores comunes: esperar que un movimiento entre grupos de recursos o suscripciones cambie la región de una VM; mover una VM sin sus discos ni sus NIC; intentar reducir un disco administrado; olvidar ampliar la partición en el sistema operativo después de agrandar un disco; cambiar el tamaño de una VM en ejecución en horario laboral sin darse cuenta de que se reinicia; y dejar discos sin conectar después de eliminar VM.

Redacción típica del examen: 'el tamaño deseado no está en la lista' apunta a desasignar primero la VM. 'Mover a otra suscripción' apunta a un movimiento de recursos con los recursos dependientes, en el mismo inquilino. 'Mover a otra región' apunta a Azure Resource Mover o Site Recovery. 'Reducir el tamaño del disco' no es posible; copia los datos a un disco nuevo y más pequeño. 'Cambiar el disco de Standard a Premium' apunta a desasignar y comprobar que el tamaño admita almacenamiento Premium. 'Costos de almacenamiento inesperados después de eliminar VM' apunta a discos huérfanos.

Términos clave

Desasignar (deallocate)
Detener una VM para que libere su hardware de host y deje de facturar el proceso, lo que permite colocarla en otro hardware.
Cambiar el tamaño (resize)
Cambiar el tamaño de una VM, lo que reinicia la VM y puede requerir desasignarla si el tamaño no está disponible en el clúster actual.
Movimiento de recursos (resource move)
Mover una VM y sus recursos dependientes a otro grupo de recursos o suscripción sin cambiar su región.
Azure Resource Mover
Un servicio que mueve VM y recursos relacionados entre regiones de Azure con comprobación de dependencias y pasos de confirmación.
Instantánea de disco (disk snapshot)
Una copia de un disco administrado en un momento dado, que puede ser incremental.
Disco sin conectar (unattached disk)
Un disco administrado que no está conectado a ninguna VM y que sigue generando costo de almacenamiento.
Ejemplo real

Una VM de informes necesita más memoria para los trabajos de cierre de mes. El tamaño de la serie E deseado no está en la lista, así que el administrador desasigna la VM durante una ventana de mantenimiento, selecciona el tamaño nuevo y la vuelve a iniciar. Más adelante, la empresa quiere la VM en otra región, así que el administrador usa Azure Resource Mover para trasladarla junto con su red virtual y su grupo de seguridad de red.

Consejo para el examen: Si falta un tamaño en la lista de cambio de tamaño, desasigna primero la VM. Mover entre grupos de recursos o suscripciones nunca cambia la región de una VM; usa Resource Mover o Site Recovery para cambiar de región. Los discos pueden crecer, no reducirse.

Comprueba lo que sabes

Quieres cambiar el tamaño de una VM, pero el tamaño no está disponible en la lista. ¿Qué debes hacer?

Detener (desasignar) la VM y luego elegir entre todos los tamaños disponibles en la región.

¿Qué servicio mueve una VM y sus recursos de red a otra región de Azure?

Azure Resource Mover (también se puede usar Azure Site Recovery).

¿Puedes reducir un disco de datos administrado de 256 GiB a 128 GiB?

No. Los discos administrados se pueden ampliar pero no reducir; tendrías que copiar los datos a un disco nuevo y más pequeño.

Amplías un disco de datos de 128 GiB a 256 GiB, pero el sistema operativo sigue mostrando 128 GiB. ¿Qué falta?

Ampliar la partición o el sistema de archivos dentro del sistema operativo, algo que Azure no hace por ti.
