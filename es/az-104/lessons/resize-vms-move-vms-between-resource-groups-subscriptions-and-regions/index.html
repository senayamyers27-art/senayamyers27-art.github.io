Microsoft Certified: Azure Administrator Associate AZ-104

Cambiar el tamaño de VM, mover VM entre grupos de recursos, suscripciones y regiones, y administrar discos

Las cargas de trabajo cambian después de la implementación, así que los administradores a menudo cambian el tamaño de las VM, las trasladan y ajustan sus discos. Saber cuáles de estas tareas necesitan un reinicio o una desasignación, y qué herramientas manejan cada tipo de movimiento, es lo que evalúa el examen.

Para cambiar el tamaño, abre la hoja Size de la VM, o ejecuta az vm resize --size Standard_D4s_v5 o Update-AzVM después de cambiar el tamaño en el objeto de la VM. Cambiar el tamaño de una VM en ejecución la reinicia. La lista de tamaños que se muestra depende del clúster de hardware que aloja la VM en ese momento. Si el tamaño que quieres no aparece, primero detén (desasigna) la VM; entonces puedes elegir cualquier tamaño disponible en la región, y Azure coloca la VM en el hardware adecuado cuando se inicia. Cambiar el tamaño puede modificar el número de discos de datos y NIC que admite la VM, así que revisa esos límites al pasar a un tamaño más pequeño.

Mover una VM a otro grupo de recursos u otra suscripción usa la operación normal de movimiento de recursos. Mueve la VM junto con sus recursos dependientes, como sus discos, interfaces de red y direcciones IP públicas, porque deben terminar en ubicaciones compatibles. La VM no cambia de región y el movimiento no la detiene, pero su ID de recurso cambia. Ambas suscripciones deben estar en el mismo tenant de Microsoft Entra, y algunas configuraciones, como VM con ciertos planes de marketplace o recursos reservados, tienen restricciones adicionales.

Mover una VM a otra región no es una operación de movimiento; es una reubicación que crea una copia en la región de destino. Azure Resource Mover orquesta el traslado de VM y recursos relacionados, como redes virtuales, NSG y equilibradores de carga, entre regiones, comprobando las dependencias y permitiéndote preparar, mover y luego confirmar (commit) o descartar. Azure Site Recovery también puede replicar una VM a otra región y conmutarla por error de forma permanente. En ambos casos, debes esperar direcciones IP nuevas y algo de tiempo de inactividad en el momento del cambio.

Administración de discos: puedes conectar discos de datos nuevos o existentes en la hoja Disks de la VM mientras está en ejecución, y luego inicializarlos y formatearlos en el SO (Administración de discos en Windows, o particionar y montar en Linux). Puedes aumentar el tamaño de un disco, pero nunca reducirlo; según el tipo de disco y la configuración, una ampliación puede requerir que la VM esté desasignada, y después de ampliarlo extiendes la partición dentro del SO. Cambiar el tipo de un disco, como de Standard SSD a Premium SSD, normalmente se hace con la VM desasignada o con el disco desconectado. El tamaño de la VM debe admitir almacenamiento Premium (tamaños con una 's' en el nombre) para usar discos Premium.

Las instantáneas de disco (disk snapshots) capturan una copia completa o incremental de un disco administrado en un momento dado, útil antes de cambios riesgosos o para crear un disco nuevo. Desconectar un disco de datos conserva el disco y sus datos como un recurso independiente, y eliminar la VM no necesariamente elimina sus discos, así que busca discos huérfanos no conectados, que siguen costando dinero.

Términos clave

Deallocate (desasignar)
Detener una VM para que libere su hardware de host y deje de facturar el proceso, lo que permite colocarla en otro hardware.
Azure Resource Mover
Un servicio que mueve VM y recursos relacionados entre regiones de Azure con comprobaciones de dependencias y pasos de confirmación.
Disk snapshot (instantánea de disco)
Una copia de un disco administrado en un momento dado, que puede ser incremental.
Unattached disk (disco no conectado)
Un disco administrado que no está conectado a ninguna VM y que sigue generando costos de almacenamiento.
Ejemplo real

Una VM de informes necesita más memoria para los trabajos de cierre de mes. El tamaño deseado de la serie E no aparece en la lista, así que el administrador desasigna la VM durante una ventana de mantenimiento, selecciona el nuevo tamaño y la vuelve a iniciar. Más adelante, el negocio quiere la VM en otra región, así que el administrador usa Azure Resource Mover para moverla junto con su red virtual y su grupo de seguridad de red.

Consejo para el examen: Si un tamaño no aparece en la lista de cambio de tamaño, desasigna primero la VM. Mover entre grupos de recursos o suscripciones nunca cambia la región de una VM; usa Resource Mover o Site Recovery para cambiar de región. Los discos pueden crecer, no reducirse.

Comprueba lo que sabes

Quieres cambiar el tamaño de una VM, pero el tamaño no está disponible en la lista. ¿Qué deberías hacer?

Detener (desasignar) la VM y luego elegir entre todos los tamaños disponibles en la región.

¿Qué servicio mueve una VM y sus recursos de red a otra región de Azure?

Azure Resource Mover (también se puede usar Azure Site Recovery).

¿Puedes reducir un disco de datos administrado de 256 GiB a 128 GiB?

No. Los discos administrados se pueden ampliar, pero no reducir; tendrías que copiar los datos a un disco nuevo más pequeño.
