Puntos de conexión de servicio vs. puntos de conexión privados, y zonas DNS privadas para Private Link

Muchos servicios de la plataforma Azure, como Azure Storage, Azure SQL Database y Key Vault, se alcanzan de forma predeterminada mediante puntos de conexión públicos en internet. Dos características permiten que los recursos de una VNet lleguen a ellos de forma más segura: los puntos de conexión de servicio (service endpoints) y los puntos de conexión privados (private endpoints). Suenan parecidos pero funcionan de forma muy diferente, y elegir entre ellos es un escenario frecuente del examen.

Un punto de conexión de servicio es una configuración de una subred, como Microsoft.Storage o Microsoft.Sql. Una vez habilitado, el tráfico desde esa subred hacia el servicio viaja por la red troncal de Azure y lleva la identidad de la subred. El firewall del servicio puede entonces permitir esa subred específica (una regla de red virtual) y denegar todo lo demás. El servicio sigue usando su dirección IP pública, y la VM sigue conectándose al nombre público. Los puntos de conexión de servicio son gratuitos, rápidos de configurar, solo funcionan para el tráfico que se origina en subredes de Azure (no desde el entorno local por VPN) y permiten el acceso a todas las instancias de ese tipo de servicio, a menos que agregues una directiva de punto de conexión de servicio (service endpoint policy, disponible para Storage) que limite a qué cuentas se puede llegar.

Un punto de conexión privado es una interfaz de red colocada en tu subred con una dirección IP privada, conectada mediante Azure Private Link a un recurso específico, como el servicio blob de una cuenta de almacenamiento o un servidor SQL. Los clientes se conectan a esa IP privada. Como es una dirección real en tu VNet, es accesible desde VNet emparejadas y desde el entorno local mediante VPN o ExpressRoute, y luego puedes deshabilitar por completo el acceso de red público en el recurso. Como se asigna a una sola instancia de recurso, también ayuda a evitar la exfiltración de datos hacia otras cuentas. Los puntos de conexión privados se facturan por hora y por gigabyte procesado.

Los puntos de conexión privados solo funcionan si los clientes resuelven el nombre normal del servicio a la IP privada. Cuando creas un punto de conexión privado, el nombre DNS público, como contoso.blob.core.windows.net, obtiene un CNAME hacia un nombre privatelink, como contoso.privatelink.blob.core.windows.net. Creas una zona DNS privada de Azure con ese nombre privatelink, la vinculas a tus VNet y agregas un registro A para la IP privada. El portal hace esto por ti cuando eliges 'Integrate with private DNS zone', asociando un grupo de zonas DNS al punto de conexión para que los registros se mantengan automáticamente. Ejemplos: privatelink.blob.core.windows.net para blobs, privatelink.file.core.windows.net para archivos, privatelink.database.windows.net para Azure SQL, privatelink.vaultcore.azure.net para Key Vault.

En una red hub-and-spoke, mantén las zonas privatelink en un solo lugar y vincúlalas a cada VNet que necesite resolución. Los servidores DNS locales deben reenviar las consultas de esas zonas hacia Azure, normalmente a un punto de conexión de entrada de Azure DNS Private Resolver, porque las máquinas locales no pueden consultar directamente Azure DNS en 168.63.129.16. Un síntoma clásico de DNS roto: nslookup devuelve una IP pública en lugar de la privada, y la conexión se rechaza porque el acceso público está deshabilitado.

Regla práctica: punto de conexión de servicio para una forma sencilla y gratuita de restringir un servicio a subredes de Azure; punto de conexión privado cuando necesitas una IP privada, acceso desde el entorno local, un ámbito por recurso o el acceso público deshabilitado.

Términos clave

Service endpoint (punto de conexión de servicio)
Una configuración de subred que envía el tráfico a un servicio de Azure por la red troncal con la identidad de la subred, mientras el servicio conserva su IP pública.
Private endpoint (punto de conexión privado)
Una NIC con una IP privada en tu VNet que se conecta a un recurso específico mediante Private Link.
Private DNS zone (zona DNS privada)
Una zona de Azure DNS que solo se puede resolver desde las VNet vinculadas, usada para asignar nombres privatelink a IP privadas.
Service endpoint policy (directiva de punto de conexión de servicio)
Una directiva que restringe el tráfico del punto de conexión de servicio a cuentas específicas de Azure Storage.
Ejemplo real

Una base de datos SQL debe ser accesible solo desde una subred de aplicaciones en Azure y desde un servidor de informes local por VPN, con el acceso público deshabilitado. Un punto de conexión de servicio no puede atender al servidor local, así que el administrador crea un punto de conexión privado, lo integra con la zona privatelink.database.windows.net vinculada a la VNet y configura el DNS local para reenviar esa zona a un punto de conexión de entrada de DNS Private Resolver.

Consejo para el examen: Acceso desde el entorno local, deshabilitar el acceso público o limitar el ámbito a una sola instancia de recurso significa punto de conexión privado. Si falla una conexión por punto de conexión privado, revisa primero el DNS: el nombre debe resolverse a la IP privada mediante una zona privatelink.

Comprueba lo que sabes

¿Qué opción da a una base de datos de Azure SQL una dirección IP privada en tu VNet?

Un punto de conexión privado.

Después de crear un punto de conexión privado, el nslookup de una VM sigue devolviendo una IP pública. ¿Qué falta?

Una zona DNS privada (como privatelink.database.windows.net) vinculada a la VNet de la VM con un registro A para el punto de conexión.

¿Cuál es gratuito y se configura en una subred: el punto de conexión de servicio o el punto de conexión privado?

El punto de conexión de servicio.
