Microsoft Certified: Azure Administrator Associate AZ-104

Usuarios y grupos de Microsoft Entra: creación, creación masiva, grupos de seguridad vs. de Microsoft 365, pertenencia asignada vs. dinámica

Microsoft Entra ID (antes Azure Active Directory) es el servicio de identidad detrás de cada suscripción de Azure. Cada persona que inicia sesión en Azure portal, y cada grupo que usas para conceder acceso, vive en un tenant (inquilino) de Entra. Como administrador de Azure pasarás mucho tiempo creando usuarios y grupos, porque un buen diseño de grupos es lo que mantiene el acceso manejable: concedes permisos a los grupos y luego agregas y quitas personas de los grupos a medida que cambian sus funciones.

Puedes crear un usuario en el portal (Microsoft Entra ID > Users > New user), con la Azure CLI (az ad user create), con Microsoft Graph PowerShell (New-MgUser) o invitando a un usuario externo. Un usuario en la nube necesita un nombre para mostrar, un user principal name (UPN) como ana@contoso.com cuyo sufijo de dominio sea un dominio verificado en el tenant, y una contraseña inicial. Los usuarios sincronizados desde Active Directory local con Microsoft Entra Connect se administran en el entorno local, así que la mayoría de sus propiedades se cambian allí, no en el portal.

Para muchos usuarios a la vez, usa Bulk operations > Bulk create en la página Users. Descargas una plantilla CSV, completas una fila por usuario (nombre, UPN, contraseña inicial y propiedades opcionales), la subes, y el portal ejecuta el trabajo y te permite descargar un archivo de resultados que muestra qué filas tuvieron éxito o fallaron. La misma área ofrece invitación masiva (bulk invite) para invitados y eliminación masiva (bulk delete). Los grupos también tienen importación masiva y eliminación masiva de miembros desde un CSV.

Entra ID tiene dos tipos de grupo. Un grupo de seguridad (security group) se usa para conceder acceso a recursos: asignaciones de roles de Azure RBAC, asignaciones de aplicaciones, licencias y directivas. Sus miembros pueden ser usuarios, dispositivos, entidades de servicio (service principals) y otros grupos (anidamiento). Un grupo de Microsoft 365 es un grupo de colaboración: incluye un buzón compartido, un calendario, un sitio de SharePoint y puede respaldar un equipo de Microsoft Teams. Sus miembros solo pueden ser usuarios, no puede contener otros grupos y siempre tiene su propia dirección de correo electrónico. Si la pregunta trata de conceder permisos de Azure a un conjunto de administradores, la respuesta es un grupo de seguridad.

Cada grupo también tiene un tipo de pertenencia. Assigned (asignada) significa que un administrador o el propietario del grupo agrega y quita miembros a mano. Dynamic user (usuario dinámico) significa que Entra ID evalúa una regla contra los atributos del usuario y mantiene la pertenencia actualizada automáticamente, por ejemplo (user.department -eq "Sales") -and (user.country -eq "US"). Dynamic device (dispositivo dinámico) hace lo mismo con atributos de dispositivo como device.deviceOSType, y solo está disponible para grupos de seguridad. No puedes agregar ni quitar miembros de un grupo dinámico a mano; en su lugar cambias la regla o los atributos del usuario.

La pertenencia dinámica requiere una licencia de Microsoft Entra ID P1 (o un producto que la incluya) para los usuarios que son miembros de grupos dinámicos. Puedes cambiar un grupo entre asignado y dinámico, pero al cambiar a dinámico se reemplazan los miembros existentes por quienes coincidan con la regla. El procesamiento de reglas no es instantáneo, así que un nuevo empleado puede tardar un tiempo en aparecer en el grupo.

Términos clave

User principal name (UPN) (nombre principal de usuario)
El nombre de inicio de sesión de un usuario de Entra en formato de dirección de correo, cuyo sufijo debe ser un dominio verificado del tenant.
Security group (grupo de seguridad)
Un grupo de Entra que se usa para conceder acceso a recursos; puede contener usuarios, dispositivos, entidades de servicio y otros grupos.
Microsoft 365 group (grupo de Microsoft 365)
Un grupo de colaboración con buzón compartido, calendario, sitio de SharePoint y equipo de Teams opcional; sus miembros solo pueden ser usuarios.
Dynamic membership (pertenencia dinámica)
Pertenencia a un grupo calculada automáticamente a partir de una regla sobre atributos de usuario o dispositivo, en lugar de mantenerse a mano.
Ejemplo real

Una empresa contrata a 40 agentes de soporte temporales. El administrador completa la plantilla CSV de creación masiva para crear las cuentas en una sola carga, establece el departamento de cada usuario en 'Support' y se apoya en un grupo de usuarios dinámico con la regla (user.department -eq "Support") que ya tiene el rol Reader en el grupo de recursos de soporte, de modo que los nuevos agentes obtienen acceso sin ningún paso adicional.

Consejo para el examen: Fíjate en el tipo de miembro. Los dispositivos solo pueden ir en grupos de seguridad, las reglas de dispositivo dinámico solo funcionan en grupos de seguridad y los grupos de Microsoft 365 no pueden contener grupos anidados. Los grupos dinámicos además requieren licencias de Entra ID P1.

Comprueba lo que sabes

Necesitas un grupo que contenga automáticamente todos los dispositivos Windows del tenant. ¿Qué tipo de grupo y qué tipo de pertenencia eliges?

Un grupo de seguridad con pertenencia de dispositivo dinámico. Los grupos de Microsoft 365 no pueden contener dispositivos, y las reglas de dispositivo dinámico solo se admiten en grupos de seguridad.

Un grupo tiene pertenencia de usuario dinámico y un gerente te pide agregar a mano a una persona más. ¿Qué pasa?

No puedes agregar miembros a mano a un grupo dinámico. Cambia los atributos del usuario para que coincida con la regla, cambia la regla o usa un grupo asignado aparte.

¿Cuál es el método más rápido en el portal para crear 200 usuarios en la nube?

Bulk create en la página Users: descarga la plantilla CSV, completa una fila por usuario, súbela y revisa el archivo de resultados.
