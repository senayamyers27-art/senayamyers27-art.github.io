Emparejamiento de redes virtuales: no transitivo, tránsito de puerta de enlace y uso de puertas de enlace remotas, emparejamiento global

El emparejamiento de redes virtuales (VNet peering) conecta dos VNet para que sus recursos se comuniquen usando direcciones IP privadas, como si fueran una sola red. El tráfico viaja por la red troncal de Microsoft, nunca por internet pública, con baja latencia y sin ninguna puerta de enlace en el camino. Emparejar VNet de la misma región es emparejamiento regional; emparejar VNet de regiones diferentes es emparejamiento global (global peering), que funciona de la misma manera. Las VNet pueden estar en suscripciones diferentes, e incluso en tenants de Microsoft Entra diferentes con los permisos adecuados.

Un emparejamiento en realidad son dos vínculos, uno desde cada lado. En el portal, crear un emparejamiento en una VNet puede crear ambos vínculos a la vez; con la CLI o PowerShell creas ambos tú mismo (az network vnet peering create en cada lado). El estado del emparejamiento muestra Initiated cuando solo existe un lado y Connected cuando existen ambos. Las VNet no deben tener espacios de direcciones superpuestos. El tráfico de emparejamiento se cobra por los datos de entrada y salida, con tarifas más altas para el emparejamiento global.

El emparejamiento es no transitivo. Si la VNet A está emparejada con la VNet B, y B está emparejada con C, A no puede llegar a C a través de B. Este es el dato más evaluado sobre el emparejamiento. En un diseño de hub-and-spoke (concentrador y radios), en el que los radios solo se emparejan con un concentrador central, los radios no pueden comunicarse entre sí de forma predeterminada. Para permitir el tráfico entre radios, puedes emparejar los radios directamente o enrutar el tráfico a través de una aplicación virtual de red o Azure Firewall en el concentrador usando rutas definidas por el usuario, con 'Allow forwarded traffic' habilitado en los emparejamientos. Azure Virtual Network Manager y Azure Virtual WAN también pueden crear topologías conectadas por ti.

Cada vínculo de emparejamiento tiene configuraciones. Allow access to the remote VNet (activada de forma predeterminada) permite la comunicación. Allow forwarded traffic acepta tráfico que no se originó en la VNet emparejada, como el tráfico enrutado a través de una aplicación virtual. Allow gateway transit, establecida en el lado del concentrador, permite que las VNet emparejadas usen la puerta de enlace de VPN o ExpressRoute del concentrador. Use remote gateways, establecida en el lado del radio, indica al radio que use la puerta de enlace del par en lugar de la suya.

El tránsito de puerta de enlace (gateway transit) es la forma en que una red hub-and-spoke comparte una sola puerta de enlace de VPN. El concentrador tiene la puerta de enlace y habilita Allow gateway transit; cada radio habilita Use remote gateways. Así los radios pueden llegar al entorno local a través de la puerta de enlace del concentrador, y el entorno local aprende las rutas hacia los radios. Un radio que ya tiene su propia puerta de enlace no puede usar puertas de enlace remotas, y una VNet solo puede usar puertas de enlace remotas de un emparejamiento. El tránsito de puerta de enlace funciona tanto con el emparejamiento global como con el regional.

Solucionar problemas de emparejamiento normalmente se reduce a tres comprobaciones: ¿ambos vínculos están en Connected?, ¿se superponen los espacios de direcciones?, y ¿los grupos de seguridad de red o las tablas de rutas bloquean el tráfico? Las rutas efectivas de Network Watcher en la NIC de una VM muestran si existe una ruta 'VNet peering' hacia el espacio de direcciones remoto.

Términos clave

VNet peering (emparejamiento de VNet)
Una conexión privada por la red troncal entre dos VNet que permite a los recursos comunicarse por IP privada.
Global peering (emparejamiento global)
Emparejamiento entre VNet de diferentes regiones de Azure.
Non-transitive (no transitivo)
La propiedad por la que el emparejamiento conecta solo las dos VNet involucradas, no las VNet emparejadas con cualquiera de ellas.
Gateway transit (tránsito de puerta de enlace)
Una opción de emparejamiento que permite a las VNet emparejadas usar la puerta de enlace de VPN o ExpressRoute de la VNet concentradora, combinada con Use remote gateways en el radio.
Ejemplo real

Una empresa tiene una VNet concentradora con una puerta de enlace de VPN hacia su sede central y tres VNet radio para aplicaciones. Los emparejamientos del concentrador permiten el tránsito de puerta de enlace y cada radio usa puertas de enlace remotas, así que todos los radios llegan a la sede central a través de una sola puerta de enlace. Cuando Spoke1 necesita llegar a Spoke2, el administrador agrega rutas definidas por el usuario que pasan por Azure Firewall en el concentrador, porque el emparejamiento no es transitivo.

Consejo para el examen: El emparejamiento es no transitivo: A-B y B-C no dan A-C. Allow gateway transit va en la VNet que tiene la puerta de enlace; Use remote gateways va en la VNet que la toma prestada. Los espacios de direcciones no deben superponerse.

Comprueba lo que sabes

Spoke1 y Spoke2 están emparejadas cada una con Hub. ¿Puede una VM de Spoke1 llegar a una VM de Spoke2?

No de forma predeterminada, porque el emparejamiento es no transitivo; empareja los radios o enruta a través de una aplicación virtual en el concentrador.

¿Qué configuración habilitas en un radio para que use la puerta de enlace de VPN del concentrador?

Use remote gateways (con Allow gateway transit habilitado en el lado del concentrador).

Un emparejamiento muestra el estado Initiated. ¿Qué significa?

Solo se ha creado un lado del emparejamiento; crea el vínculo desde la otra VNet.
