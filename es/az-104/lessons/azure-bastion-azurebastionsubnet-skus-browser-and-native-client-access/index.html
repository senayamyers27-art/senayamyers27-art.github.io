Azure Bastion: AzureBastionSubnet, SKU y acceso por explorador y cliente nativo

Abrir RDP (Remote Desktop Protocol, puerto 3389) o SSH (Secure Shell, puerto 22) a internet expone las VM a escaneos constantes y a ataques de adivinación de contraseñas. Azure Bastion es un servicio administrado que te permite conectarte a tus VM por RDP y SSH sin darles direcciones IP públicas. Te conectas a Bastion mediante TLS en el puerto 443, desde Azure portal o un cliente nativo, y Bastion abre la sesión RDP o SSH hacia la IP privada de la VM dentro de la VNet.

Una implementación dedicada de Bastion reside en su propia subred, que debe llamarse exactamente AzureBastionSubnet y ser al menos /26. El host de Bastion recibe una dirección IP pública Standard. Lo implementas en una VNet, a menudo un concentrador, y con la SKU Basic y superiores puede llegar a las VM de esa VNet y de las VNet emparejadas, así que un solo Bastion puede servir a toda una red hub-and-spoke. Las VM de destino no necesitan IP pública ni agente. Los NSG de las subredes de las VM deben permitir RDP o SSH desde el intervalo de direcciones de la subred de Bastion, y si colocas un NSG en AzureBastionSubnet, debe permitir el tráfico entrante y saliente específico que Bastion necesita.

Bastion viene en varias SKU, y las características aumentan con cada una. Developer es una opción gratuita y de menor costo para desarrollo y pruebas que usa infraestructura compartida, admite una conexión a la vez hacia VM de la misma VNet y no necesita AzureBastionSubnet; solo está disponible en algunas regiones. Basic es una implementación dedicada con RDP y SSH desde el portal y una capacidad fija. Standard agrega escalado del host (eliges el número de instancias para más sesiones simultáneas), compatibilidad con cliente nativo, conexión basada en IP (conectarse a una IP privada, incluidas máquinas locales accesibles desde la VNet), vínculos compartibles, puertos personalizados y transferencia de archivos. Premium agrega características como la grabación de sesiones y la implementación solo privada sin IP pública. Puedes actualizar una SKU, por ejemplo de Basic a Standard, pero no bajarla.

El acceso por explorador es el más sencillo: abre la VM en el portal, elige Connect > Bastion, introduce las credenciales (un nombre de usuario y contraseña, una clave privada SSH o una clave almacenada en Key Vault), y la sesión se abre en una pestaña del explorador. Copiar y pegar texto funciona; la transferencia de archivos no funciona en el explorador.

El acceso con cliente nativo (Standard y Premium) te permite usar tu cliente local de Escritorio remoto o tu cliente SSH, que admite características como la transferencia de archivos y varios monitores. Inicias sesión con la Azure CLI y ejecutas comandos como az network bastion rdp --name bas-hub --resource-group rg-hub --target-resource-id <vm-id> o az network bastion ssh ... --auth-type AAD. Primero debe habilitarse la compatibilidad con cliente nativo en la configuración de Bastion.

Para el examen, recuerda el nombre y el tamaño mínimo de la subred, que las VM no necesitan IP públicas y qué características requieren Standard o superior: cliente nativo, escalado, vínculos compartibles y conexión basada en IP.

Términos clave

Azure Bastion
Un servicio administrado que proporciona acceso RDP y SSH a las VM mediante TLS sin exponer los puertos ni las IP públicas de las VM.
AzureBastionSubnet
La subred dedicada, de al menos /26, que requiere una implementación de Bastion.
Native client support (compatibilidad con cliente nativo)
Una característica de Bastion Standard o Premium que te permite conectarte con tu cliente RDP o SSH local mediante la Azure CLI.
Host scaling (escalado del host)
Agregar instancias de Bastion en la SKU Standard o Premium para admitir más sesiones simultáneas.
Ejemplo real

Los auditores señalan VM con RDP abierto a internet. El administrador quita las IP públicas de las VM, implementa Azure Bastion Standard en una AzureBastionSubnet /26 de la VNet concentradora, habilita la compatibilidad con cliente nativo y actualiza los NSG de los radios para permitir 3389 y 22 solo desde el intervalo de la subred de Bastion. Ahora los administradores se conectan con az network bastion rdp desde sus laptops.

Consejo para el examen: La subred debe llamarse AzureBastionSubnet y ser /26 o más grande. El cliente nativo, el escalado del host, los vínculos compartibles y la conexión basada en IP necesitan Standard o superior. Las VM no necesitan IP pública.

Comprueba lo que sabes

¿Qué nombre y tamaño mínimo de subred requiere una implementación dedicada de Bastion?

AzureBastionSubnet, al menos /26.

Un administrador quiere usar su cliente RDP local con varios monitores a través de Bastion. ¿Qué SKU y configuración necesita?

Standard o Premium, con la compatibilidad con cliente nativo habilitada.

¿Las VM de destino necesitan una dirección IP pública para que se pueda llegar a ellas mediante Bastion?

No. Bastion se conecta a sus direcciones IP privadas dentro de la VNet.
