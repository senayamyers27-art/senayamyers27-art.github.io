Microsoft Certified: Azure Administrator Associate AZ-104

Crear máquinas virtuales: imágenes, tamaños, discos de SO y de datos, tipos de disco (de Standard HDD a Ultra), encryption at host y Azure Disk Encryption

Azure Virtual Machines te dan control total de un sistema operativo en la nube, lo que también significa que eres responsable de aplicarle revisiones, configurarlo y protegerlo. Crear una implica una serie de decisiones en la página Create a virtual machine: suscripción y grupo de recursos, nombre, región y opciones de disponibilidad, tipo de seguridad, imagen, tamaño, cuenta de administrador, puertos de entrada, discos, redes y configuración de administración.

La imagen es la plantilla del disco del SO. Las imágenes de Azure Marketplace incluyen Windows Server, Windows cliente (para algunos usos) y distribuciones de Linux como Ubuntu, Red Hat Enterprise Linux y SUSE. También puedes crear tus propias imágenes generalizadas y compartirlas mediante una Azure Compute Gallery para que los equipos implementen una compilación estándar y reforzada. La imagen también define la generación (Gen 1 o Gen 2), y Gen 2 es necesaria para características como Trusted Launch.

El tamaño define las vCPU, la memoria, el almacenamiento temporal, el número máximo de discos de datos y el ancho de banda de red. Los tamaños se agrupan por propósito: serie B con capacidad de ráfaga (burstable) para cargas ligeras, serie D de uso general, serie E optimizada para memoria, serie F optimizada para proceso, serie L optimizada para almacenamiento y serie N con GPU (unidades de procesamiento gráfico). No todos los tamaños están disponibles en todas las regiones o zonas, y tu suscripción tiene cuotas de vCPU por región y familia.

Cada VM tiene un disco del SO, y la mayoría de los tamaños también incluyen un disco temporal (la unidad D: en Windows) que reside en el host y se pierde cuando la VM se desasigna o se mueve, así que úsalo solo para datos transitorios como archivos de paginación. Los datos persistentes de las aplicaciones van en discos de datos, que son discos administrados que conectas y luego inicializas dentro del SO. Tipos de discos administrados, del más barato al más rápido: Standard HDD para copias de seguridad y datos no críticos; Standard SSD para servidores web y producción ligera; Premium SSD para producción y cargas sensibles al rendimiento; Premium SSD v2 y Ultra Disk, en los que defines la capacidad, las IOPS y el rendimiento de forma independiente, para las bases de datos más exigentes. Premium SSD v2 y Ultra Disk solo pueden ser discos de datos, no discos del SO, y tienen restricciones de región y zona.

Los discos administrados siempre se cifran en reposo mediante cifrado del lado del servidor con claves administradas por la plataforma, y puedes cambiar a claves administradas por el cliente mediante un disk encryption set vinculado a Key Vault. Encryption at host va más allá: los datos del disco temporal y de las cachés de los discos del SO y de datos se cifran en el host de la VM antes de fluir al almacenamiento, así que los datos quedan cifrados de extremo a extremo. Debe registrarse como característica para la suscripción y habilitarse por VM.

Azure Disk Encryption (ADE) cifra dentro del SO invitado usando BitLocker en Windows o DM-Crypt en Linux, con las claves almacenadas en Azure Key Vault. Era la forma tradicional de cumplir requisitos de 'cifrado a nivel del SO'. Microsoft anunció el retiro de ADE y recomienda encryption at host para las implementaciones nuevas, y ambos no se pueden combinar en una misma VM. Espera preguntas del examen que los contrasten: ADE funciona dentro del SO con un almacén de claves que debe estar habilitado para el cifrado de discos; encryption at host funciona a nivel de plataforma sin ningún agente en la VM.

Términos clave

VM size (tamaño de VM)
La combinación de vCPU, memoria, almacenamiento temporal y límites de disco y de red de una VM.
Temporary disk (disco temporal)
Almacenamiento local no persistente en el host de la VM que se pierde cuando la VM se desasigna o se mueve.
Ultra Disk
El tipo de disco administrado de mayor rendimiento, con IOPS y rendimiento ajustables de forma independiente, utilizable solo como disco de datos.
Encryption at host (cifrado en el host)
Una característica de la plataforma que cifra el disco temporal y las cachés de disco en el host, proporcionando cifrado de extremo a extremo.
Azure Disk Encryption
Cifrado de volúmenes dentro del invitado usando BitLocker o DM-Crypt con claves en Azure Key Vault.
Ejemplo real

Un equipo implementa una VM con SQL Server. Elige un tamaño de la serie E optimizado para memoria, un disco del SO Premium SSD, discos de datos Premium SSD v2 para datos y registros con IOPS ajustadas a la carga de trabajo, mantiene tempdb en el disco temporal local y habilita encryption at host con una clave administrada por el cliente en un disk encryption set para satisfacer al equipo de seguridad.

Consejo para el examen: Ultra Disk y Premium SSD v2 no pueden ser discos del SO. El disco temporal pierde los datos al desasignar. Encryption at host es a nivel de plataforma y no necesita agente; ADE es dentro del invitado con Key Vault y se está retirando.

Comprueba lo que sabes

¿Qué tipos de disco se pueden usar como disco del SO de una VM?

Standard HDD, Standard SSD y Premium SSD; Premium SSD v2 y Ultra Disk son solo para discos de datos.

La aplicación de una VM escribió archivos en la unidad D: y desaparecieron después de detener y desasignar la VM. ¿Por qué?

La unidad D: en las VM Windows de Azure es el disco temporal, que no es persistente.

¿Qué opción cifra el disco temporal y las cachés de una VM sin instalar nada en el SO invitado?

Encryption at host.
