Microsoft Certified: Azure Administrator Associate AZ-104

Crear máquinas virtuales: imágenes, tamaños, discos de SO y de datos, tipos de disco (de Standard HDD a Ultra), encryption at host y Azure Disk Encryption

Azure Virtual Machines te da control total de un sistema operativo en la nube, lo que también significa que eres responsable de aplicarle revisiones, configurarlo y protegerlo. Crear una implica una serie de decisiones en la página Crear una máquina virtual: suscripción y grupo de recursos, nombre, región y opciones de disponibilidad, tipo de seguridad (Estándar o Inicio seguro, Trusted Launch), imagen, tamaño, cuenta de administrador (contraseña o clave SSH), puertos de entrada, discos, redes y opciones de administración. Cada decisión afecta al costo, al rendimiento o a la resiliencia, y varias no se pueden cambiar después sin volver a implementar.

La imagen es la plantilla del disco del sistema operativo. Las imágenes de Azure Marketplace incluyen Windows Server, Windows cliente para algunos usos y distribuciones de Linux como Ubuntu, Red Hat Enterprise Linux y SUSE. También puedes crear tus propias imágenes generalizadas y compartirlas mediante Azure Compute Gallery para que los equipos implementen una compilación estándar y reforzada. La imagen también define la generación de la VM (Gen 1 o Gen 2), y Gen 2 es necesaria para funciones como Inicio seguro con Arranque seguro y un TPM (módulo de plataforma segura) virtual. Desde la CLI: az vm create --resource-group rg-app --name vm-web01 --image Ubuntu2204 --size Standard_D2s_v5 --admin-username azureuser --generate-ssh-keys.

El tamaño define las CPU virtuales (vCPU), la memoria, el almacenamiento temporal, el número máximo de discos de datos y el ancho de banda de red. Los tamaños se agrupan por propósito: la serie B con capacidad de ráfaga para cargas ligeras, la serie D de uso general, la serie E optimizada para memoria, la serie F optimizada para proceso, la serie L optimizada para almacenamiento y la serie N con GPU (unidades de procesamiento gráfico). Una 's' en el nombre del tamaño significa que admite almacenamiento Premium. No todos los tamaños están disponibles en todas las regiones o zonas, y tu suscripción tiene cuotas de vCPU por región y familia, así que una implementación puede fallar con un error de cuota hasta que solicites un aumento.

Toda VM tiene un disco de sistema operativo, y la mayoría de los tamaños también incluyen un disco temporal (la unidad D: en Windows, a menudo /dev/sdb o /mnt en Linux) que reside en el host y se pierde cuando la VM se desasigna, se redimensiona a un hardware nuevo o se mueve, así que úsalo solo para datos transitorios como los archivos de paginación. Los datos persistentes de las aplicaciones van en discos de datos, que son discos administrados que conectas y luego inicializas dentro del sistema operativo. Los tipos de discos administrados, del más barato al más rápido: Standard HDD para copias de seguridad y datos no críticos; Standard SSD para servidores web y producción ligera; Premium SSD para producción y cargas sensibles al rendimiento; Premium SSD v2 y Ultra Disk, en los que defines la capacidad, las IOPS (operaciones de entrada/salida por segundo) y el rendimiento de forma independiente para las bases de datos más exigentes. Premium SSD v2 y Ultra Disk solo pueden ser discos de datos, no discos del sistema operativo, y tienen restricciones de región y de zona.

Los discos administrados siempre se cifran en reposo mediante cifrado del lado del servidor (SSE) con claves administradas por la plataforma, y puedes cambiar a claves administradas por el cliente mediante un conjunto de cifrado de disco vinculado a Azure Key Vault. Encryption at host (cifrado en el host) va más allá: los datos del disco temporal y las memorias caché de los discos del sistema operativo y de datos se cifran en el host de la VM antes de fluir al almacenamiento, de modo que los datos quedan cifrados de extremo a extremo. La característica EncryptionAtHost debe registrarse en la suscripción (az feature register --namespace Microsoft.Compute --name EncryptionAtHost) y luego habilitarse en cada VM. Azure Disk Encryption (ADE) cifra dentro del sistema operativo invitado usando BitLocker en Windows o DM-Crypt en Linux, con las claves almacenadas en un Key Vault habilitado para el cifrado de discos. Microsoft anunció la retirada de ADE y recomienda encryption at host para las implementaciones nuevas, y ambas no se pueden combinar en una misma VM.

Veamos un ejemplo práctico. Un equipo implementa una VM con SQL Server. Elige un tamaño de la serie E optimizado para memoria con 's' para que admita almacenamiento Premium, un disco de sistema operativo Premium SSD y discos de datos Premium SSD v2 para datos y registros, con IOPS y rendimiento ajustados a la carga de trabajo. La base de datos tempdb va en el disco temporal local porque se vuelve a crear en cada inicio. El equipo de seguridad exige que nada, incluidas las memorias caché y el disco temporal, se almacene sin cifrar, así que el administrador registra la característica, habilita encryption at host y usa un conjunto de cifrado de disco con una clave administrada por el cliente.

Errores comunes: elegir Ultra Disk o Premium SSD v2 para el disco del sistema operativo; guardar archivos importantes en el disco temporal; seleccionar un tamaño sin 's' y luego no poder conectar discos Premium; suponer que el cifrado del lado del servidor cubre el disco temporal y las memorias caché (eso es encryption at host); intentar habilitar ADE y encryption at host en una misma VM; y olvidar revisar la cuota regional de vCPU antes de una implementación grande.

Redacción típica del examen: 'menor costo, acceso poco frecuente, no crítico' apunta a Standard HDD. 'Producción, latencia baja y constante' apunta a Premium SSD. 'Ajustar IOPS y rendimiento de forma independiente para una base de datos exigente' apunta a Premium SSD v2 o Ultra Disk, solo como discos de datos. 'Datos perdidos después de la desasignación' apunta al disco temporal. 'Cifrar el disco temporal y las memorias caché sin un agente en el invitado' apunta a encryption at host. 'BitLocker o DM-Crypt con Key Vault' apunta a Azure Disk Encryption.

Términos clave

Tamaño de VM (VM size)
La combinación de vCPU, memoria, almacenamiento temporal y límites de discos y red de una VM.
Azure Compute Gallery
Un servicio para almacenar y compartir imágenes de VM personalizadas entre suscripciones y regiones.
Disco temporal (temporary disk)
Almacenamiento local no persistente en el host de la VM que se pierde cuando la VM se desasigna o se mueve.
Ultra Disk
El tipo de disco administrado de mayor rendimiento, con IOPS y rendimiento ajustables de forma independiente, que solo se puede usar como disco de datos.
Conjunto de cifrado de disco (disk encryption set)
Un recurso que vincula los discos administrados con una clave administrada por el cliente en Key Vault para el cifrado del lado del servidor.
Encryption at host
Una función de la plataforma que cifra el disco temporal y las memorias caché de los discos en el host, proporcionando cifrado de extremo a extremo.
Azure Disk Encryption
Cifrado de volúmenes dentro del invitado con BitLocker o DM-Crypt y claves en Azure Key Vault.
Ejemplo real

Un equipo implementa una VM con SQL Server. Elige un tamaño de la serie E optimizado para memoria, un disco de sistema operativo Premium SSD y discos de datos Premium SSD v2 para datos y registros con IOPS ajustadas a la carga de trabajo, mantiene tempdb en el disco temporal local y habilita encryption at host con una clave administrada por el cliente en un conjunto de cifrado de disco para cumplir los requisitos del equipo de seguridad.

Consejo para el examen: Ultra Disk y Premium SSD v2 no pueden ser discos del sistema operativo. El disco temporal pierde los datos al desasignar la VM. Encryption at host funciona a nivel de plataforma y no necesita agente; ADE funciona dentro del invitado con Key Vault y se está retirando.

Comprueba lo que sabes

¿Qué tipos de disco se pueden usar como disco del sistema operativo de una VM?

Standard HDD, Standard SSD y Premium SSD; Premium SSD v2 y Ultra Disk son solo para discos de datos.

La aplicación de una VM escribió archivos en la unidad D: y desaparecieron después de detener y desasignar la VM. ¿Por qué?

La unidad D: en las VM Windows de Azure es el disco temporal, que no es persistente.

¿Qué opción cifra el disco temporal y las memorias caché de una VM sin instalar nada en el sistema operativo invitado?

Encryption at host.

No puedes conectar un disco de datos Premium SSD a una VM. ¿Qué debes revisar primero?

Si el tamaño de la VM admite almacenamiento Premium, lo que suele indicarse con una 's' en el nombre del tamaño.
