Firewalls de almacenamiento y reglas de red virtual, servicios de Microsoft de confianza y puntos de conexión privados para almacenamiento

De forma predeterminada, una cuenta de almacenamiento nueva acepta conexiones desde cualquier red y depende de la autorización (claves, SAS o Entra ID) para mantener seguros los datos. El firewall de almacenamiento agrega una capa de red: incluso una solicitud con una clave válida se rechaza si no proviene de una red permitida. Configúralo en la hoja Networking de la cuenta, donde el acceso de red público puede habilitarse desde todas las redes, habilitarse desde redes virtuales y direcciones IP seleccionadas, o deshabilitarse.

Cuando eliges redes seleccionadas, la cuenta deniega todo excepto lo que indiques. Las reglas de red IP permiten direcciones IP públicas específicas o intervalos en notación CIDR, como la dirección de internet de tu oficina. Solo funcionan con direcciones públicas; no puedes usarlas para intervalos de direcciones privadas dentro de una red virtual. Las reglas de red virtual permiten subredes específicas. Para agregar una subred, debe tener habilitado un punto de conexión de servicio (service endpoint) para Microsoft.Storage, que el portal puede activar por ti. Con un punto de conexión de servicio, el tráfico de la subred viaja al almacenamiento por la red troncal de Azure y lleva la identidad de la subred, así que el firewall puede reconocerlo, pero la cuenta de almacenamiento conserva su dirección IP pública.

Bloquear todo el tráfico público puede romper servicios de Azure que necesitan llegar a tu cuenta, como Azure Backup, los registros de diagnóstico de Azure Monitor, Azure Event Grid o Azure Site Recovery. La excepción 'Allow Azure services on the trusted services list to access this storage account' deja pasar a esos servicios propios de Microsoft específicos, usando autenticación sólida. También existen las reglas de instancia de recurso (resource instance rules), que permiten que un recurso concreto, como un área de trabajo específica de Azure Synapse, llegue a la cuenta mediante su identidad administrada.

Un punto de conexión privado (private endpoint) es la opción más sólida. Crea una interfaz de red en una de tus subredes con una dirección IP privada de esa subred, conectada mediante Azure Private Link a un subrecurso de la cuenta de almacenamiento, como blob, file, queue, table, web o dfs. Los clientes de la red virtual, de redes emparejadas o de redes locales conectadas por VPN o ExpressRoute llegan a la cuenta a través de esa IP privada. Luego puedes establecer el acceso de red público en Disabled para que la cuenta no tenga ninguna exposición a internet. Necesitas un punto de conexión privado por cada subrecurso que uses.

Los puntos de conexión privados dependen del DNS. El nombre de la cuenta debe resolverse en la IP privada para los clientes que deban usar el punto de conexión. El portal ofrece integrarlo con una zona DNS privada como privatelink.blob.core.windows.net, vinculada a tu red virtual, para que name.blob.core.windows.net se resuelva mediante un CNAME a la dirección privada. Los clientes locales necesitan reenvío de DNS hacia Azure para obtener la misma respuesta.

Resumen para el examen: reglas IP para direcciones públicas conocidas; reglas de red virtual más puntos de conexión de servicio para subredes que llegan al punto de conexión público por la red troncal; puntos de conexión privados cuando los datos deben permanecer en direcciones privadas o se debe deshabilitar el acceso público; y la excepción de servicios de confianza para los servicios de la plataforma Azure.

Términos clave

Storage firewall (firewall de almacenamiento)
Reglas de red en una cuenta de almacenamiento que solo permiten conectarse a los intervalos de IP públicas, subredes y excepciones indicados.
Service endpoint (punto de conexión de servicio)
Una configuración de subred que enruta el tráfico hacia un servicio por la red troncal de Azure e identifica la subred para que las reglas de red virtual puedan permitirla.
Trusted Microsoft services (servicios de Microsoft de confianza)
Una excepción del firewall que permite que servicios específicos de la plataforma Azure accedan a la cuenta incluso cuando el acceso público está restringido.
Private endpoint (punto de conexión privado)
Una interfaz de red con una IP privada en tu subred que se conecta a un subrecurso de almacenamiento específico mediante Private Link.
Ejemplo real

La cuenta de almacenamiento de un equipo de finanzas no debe ser accesible desde internet, pero las VM de la red virtual Hub y la oficina local conectada por VPN necesitan leer blobs. El administrador crea un punto de conexión privado para el subrecurso blob en una subred de Hub, lo integra con la zona DNS privada privatelink.blob.core.windows.net, configura el reenvío de DNS local y establece el acceso de red público en Disabled. Se habilita la excepción de servicios de confianza para que Azure Backup siga funcionando.

Consejo para el examen: Los puntos de conexión de servicio conservan el punto de conexión público y solo funcionan desde subredes de Azure; los puntos de conexión privados dan una IP privada utilizable desde redes emparejadas y locales. Las reglas IP no pueden contener direcciones privadas. Los puntos de conexión privados necesitan un DNS correcto.

Comprueba lo que sabes

Agregas una subred a un firewall de almacenamiento, pero el portal indica que se requiere un punto de conexión de servicio. ¿Cuál?

Microsoft.Storage en esa subred.

Después de restringir una cuenta de almacenamiento a redes seleccionadas, Azure Backup ya no puede escribir en ella. ¿Qué deberías habilitar?

La excepción que permite a los servicios de Microsoft de confianza acceder a la cuenta de almacenamiento.

Usuarios locales conectados por VPN deben llegar a una cuenta de almacenamiento usando una dirección IP privada. ¿Punto de conexión de servicio o punto de conexión privado?

Un punto de conexión privado; los puntos de conexión de servicio solo se aplican al tráfico desde subredes de Azure y siguen usando el punto de conexión público.
