Microsoft Certified: Azure Administrator Associate AZ-104

Firewalls de almacenamiento y reglas de red virtual, servicios de Microsoft de confianza y puntos de conexión privados para almacenamiento

De forma predeterminada, una cuenta de almacenamiento nueva acepta conexiones desde cualquier red y depende de la autorización (claves, firmas de acceso compartido o Microsoft Entra ID) para mantener los datos seguros. El firewall de almacenamiento agrega una capa de red: incluso una solicitud con una clave válida se rechaza si no proviene de una red permitida. Lo configuras en la hoja Redes de la cuenta, donde el acceso a la red pública puede estar habilitado desde todas las redes, habilitado desde redes virtuales y direcciones IP seleccionadas, o deshabilitado. La defensa en profundidad consiste en usar ambas capas: autorización sólida y redes restringidas.

Cuando eliges redes seleccionadas, la cuenta deniega todo excepto lo que indicas. Las reglas de red IP permiten direcciones IP públicas específicas o intervalos en notación CIDR (enrutamiento entre dominios sin clases), como la dirección de internet de tu oficina 203.0.113.0/24. Solo funcionan con direcciones públicas; no puedes usarlas para intervalos de direcciones privadas dentro de una red virtual. Las reglas de red virtual permiten subredes específicas. Para poder agregar una subred, esta debe tener habilitado un punto de conexión de servicio para Microsoft.Storage, que el portal puede activar por ti, o puedes ejecutar az network vnet subnet update --vnet-name vnet-hub --name snet-app --resource-group rg-net --service-endpoints Microsoft.Storage y luego az storage account network-rule add --account-name stfin --vnet-name vnet-hub --subnet snet-app. Con un punto de conexión de servicio, el tráfico de la subred viaja al almacenamiento por la red troncal de Azure y lleva la identidad de la subred, de modo que el firewall puede reconocerlo, pero la cuenta de almacenamiento conserva su dirección IP pública y el cliente sigue conectándose al punto de conexión público.

Bloquear el tráfico público puede romper servicios de Azure que necesitan llegar a tu cuenta, como Azure Backup, los registros de diagnóstico de Azure Monitor, Azure Event Grid o Azure Site Recovery. La excepción 'Permitir que los servicios de Azure de la lista de servicios de confianza accedan a esta cuenta de almacenamiento' deja pasar a esos servicios propios de Microsoft concretos, usando autenticación sólida. Las reglas de instancia de recurso van más allá y permiten que un recurso particular, como un área de trabajo específica de Azure Synapse, llegue a la cuenta mediante su identidad administrada, lo que es más estricto que confiar en todo un servicio.

Un punto de conexión privado es la opción más sólida. Crea una interfaz de red en una de tus subredes con una dirección IP privada de esa subred, conectada mediante Azure Private Link a un subrecurso de la cuenta de almacenamiento: blob, file, queue, table, web o dfs. Los clientes de la red virtual, de redes emparejadas o de redes locales conectadas por VPN (red privada virtual) o ExpressRoute llegan a la cuenta a través de esa IP privada. Luego puedes establecer el acceso a la red pública en Deshabilitado para que la cuenta no tenga ninguna exposición a internet. Necesitas un punto de conexión privado por cada subrecurso que uses, así que una aplicación que usa blobs y archivos necesita dos.

Los puntos de conexión privados dependen del DNS (sistema de nombres de dominio). El nombre de la cuenta debe resolverse a la IP privada para los clientes que deben usar el punto de conexión. El portal ofrece integrarlo con una zona DNS privada como privatelink.blob.core.windows.net, vinculada a tu red virtual, para que name.blob.core.windows.net se resuelva mediante un registro CNAME a la dirección privada. Los clientes locales necesitan reenvío de DNS hacia Azure, por ejemplo mediante Azure DNS Private Resolver, para obtener la misma respuesta; si no, resuelven la IP pública y quedan bloqueados. Ejecutar nslookup name.blob.core.windows.net desde un cliente muestra rápidamente qué dirección obtiene.

Veamos un ejemplo práctico. La cuenta de almacenamiento de un equipo de finanzas no debe ser accesible desde internet, pero las VM de la red virtual Hub y los usuarios de la oficina local conectados por VPN necesitan leer blobs. Creas un punto de conexión privado para el subrecurso blob en una subred de Hub, lo integras con la zona DNS privada privatelink.blob.core.windows.net, configuras el reenvío de DNS local y estableces el acceso a la red pública en Deshabilitado. Habilitas la excepción de servicios de confianza para que Azure Backup siga funcionando. Un nslookup desde la oficina ahora devuelve la dirección privada, y una prueba desde una conexión a internet doméstica se rechaza.

Errores comunes: intentar agregar un intervalo de IP privadas a las reglas IP; agregar una regla de subred sin habilitar el punto de conexión de servicio Microsoft.Storage; esperar que los puntos de conexión de servicio ayuden a los clientes locales; crear un punto de conexión privado para blob y esperar que los recursos compartidos de archivos funcionen a través de él; olvidar el DNS, de modo que los clientes siguen resolviendo la dirección pública; y restringir el firewall sin la excepción de servicios de confianza, lo que rompe en silencio las copias de seguridad o los registros.

Redacción típica del examen: 'permitir la IP pública de la oficina' apunta a una regla de red IP. 'Permitir una subred' o 'tráfico por la red troncal de Azure conservando el punto de conexión público' apunta a un punto de conexión de servicio y una regla de red virtual. 'Dirección IP privada', 'sin acceso público', 'entorno local por VPN o ExpressRoute' o 'red emparejada' apunta a un punto de conexión privado. 'Azure Backup o los registros de diagnóstico dejaron de funcionar después de restringir el acceso' apunta a la excepción de servicios de Microsoft de confianza. 'El nombre sigue resolviéndose a una dirección pública' apunta a la configuración de la zona DNS privada.

Términos clave

Firewall de almacenamiento
Reglas de red en una cuenta de almacenamiento que solo permiten conectarse a los intervalos de IP públicas, subredes y excepciones indicados.
Regla de red IP (IP network rule)
Una regla de firewall que permite una dirección IP pública o un intervalo CIDR; no se permiten intervalos privados.
Punto de conexión de servicio (service endpoint)
Una configuración de subred que enruta el tráfico hacia un servicio por la red troncal de Azure e identifica la subred para que las reglas de red virtual puedan permitirla.
Servicios de Microsoft de confianza
Una excepción de firewall que permite a determinados servicios de la plataforma Azure acceder a la cuenta aunque el acceso público esté restringido.
Punto de conexión privado (private endpoint)
Una interfaz de red con una IP privada en tu subred que se conecta a un subrecurso de almacenamiento específico mediante Private Link.
Zona DNS privada (private DNS zone)
Una zona DNS como privatelink.blob.core.windows.net que resuelve el nombre de la cuenta a la IP del punto de conexión privado dentro de las redes vinculadas.
Ejemplo real

La cuenta de almacenamiento de un equipo de finanzas no debe ser accesible desde internet, pero las VM de la red virtual Hub y la oficina local conectada por VPN necesitan leer blobs. El administrador crea un punto de conexión privado para el subrecurso blob en una subred de Hub, lo integra con la zona DNS privada privatelink.blob.core.windows.net, configura el reenvío de DNS local y establece el acceso a la red pública en Deshabilitado. La excepción de servicios de confianza se habilita para que Azure Backup siga funcionando.

Consejo para el examen: Los puntos de conexión de servicio conservan el punto de conexión público y solo funcionan desde subredes de Azure; los puntos de conexión privados dan una IP privada utilizable desde redes emparejadas y locales. Las reglas IP no pueden contener direcciones privadas, y los puntos de conexión privados necesitan un DNS correcto.

Comprueba lo que sabes

Agregas una subred a un firewall de almacenamiento, pero el portal indica que se requiere un punto de conexión de servicio. ¿Cuál?

Microsoft.Storage en esa subred.

Después de restringir una cuenta de almacenamiento a redes seleccionadas, Azure Backup ya no puede escribir en ella. ¿Qué debes habilitar?

La excepción que permite a los servicios de Microsoft de confianza acceder a la cuenta de almacenamiento.

Usuarios locales conectados por VPN deben llegar a una cuenta de almacenamiento con una dirección IP privada. ¿Punto de conexión de servicio o punto de conexión privado?

Un punto de conexión privado; los puntos de conexión de servicio solo se aplican al tráfico desde subredes de Azure y siguen usando el punto de conexión público.

Existe un punto de conexión privado para blob, pero una VM sigue conectándose a la IP pública. ¿Cuál es la causa probable?

El DNS: falta la zona DNS privada o no está vinculada a la red virtual de la VM, así que el nombre se resuelve a la dirección pública.
