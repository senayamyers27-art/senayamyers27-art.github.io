Direcciones IP públicas: SKU Standard, asignación estática y zonas

Una dirección IP pública es un recurso de Azure independiente que asocias a algo que debe ser accesible desde internet, o aparecer en internet: la interfaz de red de una máquina virtual, un equilibrador de carga público, una puerta de enlace VPN, Application Gateway, Azure Bastion, Azure Firewall o una puerta de enlace NAT. Como es un recurso propio, puedes conservar la dirección cuando eliminas o reemplazas el recurso al que estaba asociada, lo que importa cuando socios, registros DNS o listas de permitidos de firewalls dependen de esa dirección exacta.

Las IP públicas vienen en SKU (stock-keeping units). Standard es el SKU que debes usar: Microsoft retiró el SKU Basic anterior, así que los diseños nuevos, y las respuestas del examen, deben asumir Standard. Las IP públicas Standard tienen tres propiedades importantes. Primero, siempre usan asignación estática: la dirección se asigna al crear el recurso y no cambia hasta que lo eliminas. Segundo, son seguras de forma predeterminada: el tráfico entrante se bloquea a menos que un grupo de seguridad de red (NSG) lo permita explícitamente. Tercero, admiten zonas de disponibilidad. Una IP pública Standard debe combinarse con un equilibrador de carga de SKU Standard, porque los SKU del equilibrador de carga y de su IP pública deben coincidir. La asignación estática frente a la dinámica es un tema clásico del examen. Con el antiguo SKU Basic, una dirección dinámica se asignaba cuando el recurso se iniciaba y podía cambiar cuando una VM se detenía y desasignaba. Una dirección estática nunca cambia, que es lo que necesitas para registros A de DNS, listas de permitidos de firewalls y algunos certificados. Las direcciones Standard siempre son estáticas, así que si una pregunta dice que una dirección cambia después de desasignar, la solución es una IP pública Standard estática.

La configuración de zona se elige al crear la IP y no se puede cambiar después. Una IP con redundancia de zona (zone-redundant) se sirve desde todas las zonas de la región y sobrevive al fallo de cualquier zona individual; es la opción habitual en regiones con zonas. Una IP zonal está fijada a una zona (1, 2 o 3) y falla si esa zona falla, lo que conviene para una VM colocada deliberadamente en esa zona. Sin zona (No zone) es la opción para regiones sin zonas de disponibilidad. Haz que la IP coincida con tu diseño: un front-end de equilibrador de carga con redundancia de zona debe usar una IP pública con redundancia de zona.

az network public-ip create --resource-group rg-web --name pip-lb-web \
  --sku Standard --allocation-method Static --zone 1 2 3 \
  --dns-name contoso-shop

Otras propiedades que verás en el portal: versión de IP (IPv4 o IPv6), nivel (Regional, o Global para un equilibrador de carga entre regiones), una etiqueta de nombre DNS opcional que crea un nombre como contoso-shop.westeurope.cloudapp.azure.com, preferencia de enrutamiento (red de Microsoft o internet) y tiempo de espera de inactividad. Un prefijo de IP pública (public IP prefix) reserva un bloque contiguo de direcciones públicas estáticas, útil cuando los socios deben agregar a su lista de permitidos un rango predecible. Para el acceso saliente a internet desde VM privadas, el enfoque recomendado es una puerta de enlace NAT con una IP pública Standard o un prefijo, en lugar de dar a cada VM su propia IP pública. Menos IP públicas significan una superficie de ataque más pequeña; los administradores deberían llegar a las VM mediante Azure Bastion o VPN en lugar de RDP o SSH públicos.

Veamos un ejemplo práctico. Un proveedor de pagos debe agregar tu dirección saliente a su lista de permitidos, y tu sitio web necesita una dirección fija que sobreviva al fallo de una zona. Para la entrada, creas una IP pública Standard con redundancia de zona para el front-end del equilibrador de carga y agregas una regla de NSG que permite TCP 443 desde internet hacia la subred web, ya que las IP Standard bloquean el tráfico entrante de forma predeterminada. Para la salida, asocias una puerta de enlace NAT con un prefijo de IP pública a la subred de la aplicación y envías el prefijo al proveedor de pagos. Ninguna de las VM tiene su propia IP pública.

Errores comunes: esperar que una IP pública Standard nueva acepte tráfico sin una regla de NSG; intentar cambiar una IP zonal a redundancia de zona después de crearla; combinar una IP Standard con un equilibrador de carga Basic; dar a cada VM una IP pública para el acceso saliente; y eliminar una VM junto con su IP pública cuando había que conservar la dirección.

Palabras clave del examen: 'la dirección nunca debe cambiar' significa Standard estática; 'sobrevivir al fallo de una zona' significa redundancia de zona; 'no llega tráfico entrante a una IP pública nueva' significa agregar una regla de permiso en el NSG; 'rango contiguo predecible' significa un prefijo de IP pública; 'solo saliente, sin exposición entrante' significa una puerta de enlace NAT.

Términos clave

Dirección IP pública (public IP address)
Recurso de Azure independiente que da a un recurso asociado una dirección enrutable en internet.
SKU Standard
El SKU actual de IP pública: siempre estático, seguro de forma predeterminada y compatible con zonas.
Asignación estática (static allocation)
Dirección asignada al crearse que no cambia hasta que se elimina el recurso de IP pública.
Con redundancia de zona (zone-redundant)
IP pública servida desde todas las zonas de disponibilidad de una región, de modo que sobrevive al fallo de una sola zona.
Zonal
IP pública fijada a una zona de disponibilidad, que falla si esa zona falla.
Prefijo de IP pública (public IP prefix)
Bloque contiguo reservado de direcciones IP públicas estáticas.
Puerta de enlace NAT (NAT gateway)
Servicio administrado que proporciona conectividad saliente a internet para una subred mediante IP públicas o prefijos compartidos.
Ejemplo real

Una empresa ejecuta una puerta de enlace VPN y un equilibrador de carga web en una región con zonas de disponibilidad. Durante una revisión de diseño, la arquitecta verifica que ambos usen IP públicas Standard con redundancia de zona, para que la pérdida de una zona de centro de datos no cambie ni elimine las direcciones de las que dependen las sucursales y los clientes. También confirma que el NSG de la subred web permita explícitamente TCP 443, porque las IP públicas Standard bloquean el tráfico entrante hasta que una regla lo permite.

Consejo para el examen: Las IP públicas Standard siempre son estáticas, compatibles con zonas y cerradas al tráfico entrante hasta que un NSG lo permite. La elección de zona queda fija al crearlas, y los SKU del equilibrador de carga y de la IP pública deben coincidir.

Comprueba lo que sabes

Una IP pública Standard nueva está asociada a una VM, pero nadie puede llegar al servidor web. ¿Cuál es la causa probable?

Las IP públicas Standard son seguras de forma predeterminada, así que una regla de NSG debe permitir explícitamente el puerto de entrada, como TCP 443.

¿Puedes cambiar más adelante una IP pública zonal a redundancia de zona?

No. La configuración de zona se elige al crearla y no se puede cambiar; debes crear una IP pública nueva.

¿Qué método de asignación usan las IP públicas Standard?

Solo estático; la dirección se mantiene igual hasta que se elimina el recurso.

Unas VM privadas necesitan acceso saliente a internet a través de un conjunto pequeño y fijo de direcciones. ¿Qué se recomienda?

Una puerta de enlace NAT en su subred con una IP pública Standard o un prefijo de IP pública.
