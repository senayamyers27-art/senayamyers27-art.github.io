Direcciones IP públicas: SKU Standard, asignación estática y zonas

Una dirección IP pública es un recurso de Azure independiente que asocias con algo que debe ser accesible desde internet, o aparecer ante internet: la interfaz de red de una VM, un equilibrador de carga público, una puerta de enlace de VPN, Application Gateway, Azure Bastion, Azure Firewall o una NAT gateway. Como es un recurso propio, puedes conservar la dirección cuando eliminas o reemplazas el recurso al que estaba asociada.

Las IP públicas vienen en SKU (stock-keeping units). Standard es la SKU que debes usar. Microsoft retiró la SKU Basic anterior, así que los diseños nuevos, y las respuestas del examen, deben suponer Standard. Las IP públicas Standard tienen tres propiedades importantes. Primero, siempre usan asignación estática: la dirección se asigna al crear el recurso y no cambia hasta que lo eliminas. Segundo, son seguras de forma predeterminada: el tráfico entrante se bloquea a menos que un grupo de seguridad de red lo permita explícitamente. Tercero, admiten zonas de disponibilidad. Una IP pública Standard debe combinarse con equilibradores de carga de SKU Standard, y las SKU de un equilibrador de carga y de su IP pública deben coincidir.

La asignación estática frente a la dinámica es un tema clásico del examen. Con la antigua SKU Basic, una dirección dinámica se asignaba cuando el recurso se iniciaba y podía cambiar cuando una VM se detenía y desasignaba. Una dirección estática nunca cambia, que es lo que necesitas para registros DNS, listas de permitidos de firewalls y certificados TLS. Las direcciones Standard siempre son estáticas.

La configuración de zona se elige al crear la IP y no se puede cambiar después. Una IP con redundancia de zona (zone-redundant) se sirve desde todas las zonas de la región y sobrevive al fallo de cualquier zona individual; es la opción predeterminada en regiones con zonas. Una IP zonal está fijada a una zona (1, 2 o 3) y falla si esa zona falla, lo que es adecuado para una VM zonal. Sin zona (no zone) es la opción para regiones sin zonas. Haz coincidir la IP con tu diseño: el front-end de un equilibrador de carga con redundancia de zona debe usar una IP pública con redundancia de zona.

Otras propiedades que verás en el portal: versión de IP (IPv4 o IPv6), nivel (Regional, o Global para un equilibrador de carga entre regiones), una etiqueta de nombre DNS opcional que crea un nombre como myapp.westeurope.cloudapp.azure.com, preferencia de enrutamiento (red de Microsoft o internet) y tiempo de espera de inactividad. Un prefijo de IP pública (public IP prefix) reserva un bloque contiguo de direcciones públicas estáticas, útil cuando los socios deben incluir en su lista de permitidos un intervalo predecible.

Para acceso a internet solo de salida desde VM privadas, una NAT gateway con una IP pública Standard o un prefijo es el enfoque recomendado, en lugar de dar a cada VM su propia IP pública. Menos IP públicas significan una superficie de ataque más pequeña; los administradores deben llegar a las VM mediante Azure Bastion o VPN en lugar de RDP o SSH públicos.

Términos clave

Standard SKU public IP (IP pública de SKU Standard)
La SKU actual de IP pública: siempre estática, cerrada al tráfico entrante de forma predeterminada y compatible con zonas.
Static allocation (asignación estática)
Una asignación de IP que no cambia durante toda la vida del recurso de IP pública.
Zone-redundant IP (IP con redundancia de zona)
Una IP pública que se sirve desde todas las zonas de disponibilidad de una región y sobrevive al fallo de una sola zona.
Public IP prefix (prefijo de IP pública)
Un intervalo contiguo reservado de direcciones IP públicas estáticas.
Ejemplo real

El firewall de un socio solo acepta tráfico desde una dirección fija. El administrador crea una IP pública Standard con redundancia de zona, la asocia a una NAT gateway en la subred de la aplicación y le da esa dirección al socio. Como las IP Standard son estáticas, los reinicios de VM y los eventos de escalado nunca cambian la dirección de origen que ve el socio.

Consejo para el examen: Las IP públicas Standard siempre son estáticas, compatibles con zonas y cerradas al tráfico entrante hasta que un NSG lo permita. La elección de zona se fija al crearlas. Las SKU del equilibrador de carga y de la IP pública deben coincidir.

Comprueba lo que sabes

Asocias una IP pública Standard a una VM, pero no puedes conectarte por RDP. ¿Cuál es la causa probable?

Las IP públicas Standard son seguras de forma predeterminada; un NSG debe permitir el tráfico RDP entrante (mejor aún, usa Bastion).

¿Puedes cambiar una IP pública zonal a una con redundancia de zona?

No. La configuración de zona se establece al crearla; crea una IP pública nueva con redundancia de zona.

¿Qué configuración de IP pública garantiza que la dirección nunca cambie cuando la VM se desasigna?

La asignación estática, que las IP públicas de SKU Standard siempre usan.
