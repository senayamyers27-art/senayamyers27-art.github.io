Microsoft Certified: Azure Administrator Associate AZ-104

App Service: certificados TLS, nombres DNS personalizados, copias de seguridad, redes (integración con VNet, puntos de conexión privados) y ranuras de implementación

Toda aplicación de App Service recibe un nombre de host predeterminado, <app-name>.azurewebsites.net, con HTTPS ya funcionando mediante un certificado de Microsoft. Las aplicaciones de producción suelen necesitar más: un dominio personalizado, su propio certificado TLS (Transport Layer Security), copias de seguridad, redes privadas y una forma segura de publicar actualizaciones. Estas opciones están en las hojas de la aplicación en el portal (Custom domains, Certificates, Backups, Networking y Deployment slots), y el examen espera que sepas qué hace cada una y a qué dirección del tráfico afecta.

Para agregar un dominio personalizado, ve a Custom domains > Add custom domain. App Service te pide demostrar la propiedad con un registro TXT llamado asuid.<subdomain> (o asuid para la raíz) que contiene el ID de verificación de dominio de la aplicación, y asignar el nombre: un registro CNAME que apunta www a <app-name>.azurewebsites.net o, para un dominio raíz (ápice) como contoso.com, un registro A que apunta a la dirección IP de entrada de la aplicación, porque un CNAME no puede estar en el ápice. Después de la validación, el nombre se agrega a la aplicación. Los dominios personalizados no están disponibles en el nivel Free. Para usar HTTPS en el nombre personalizado, enlaza un certificado. Las opciones incluyen un certificado administrado de App Service gratuito (renovado automáticamente, pero no para nombres comodín), un App Service certificate comprado mediante Azure, un certificado importado desde Azure Key Vault o un archivo de certificado privado cargado (.pfx). Los enlaces suelen ser SNI SSL (Server Name Indication), que permite que muchos certificados compartan una dirección IP; IP-based SSL proporciona una dirección dedicada. Activa HTTPS Only para que las solicitudes HTTP se redirijan a HTTPS y define la versión mínima de TLS para rechazar clientes obsoletos.

Las copias de seguridad copian el contenido y la configuración de la aplicación y, opcionalmente, una base de datos conectada. La plataforma toma copias de seguridad automáticas en los niveles Basic y superiores; las copias de seguridad personalizadas, a partir de Standard, te permiten definir tu propia programación y retención y enviarlas a una cuenta de almacenamiento que elijas. Puedes restaurar en la misma aplicación, en otra aplicación o en una ranura de implementación. Las copias de seguridad no reemplazan al control de código fuente, pero ayudan a recuperarse de un cambio incorrecto o de la eliminación accidental de contenido.

Las redes tienen dos direcciones, y el examen verifica que no las confundas. Entrante: un punto de conexión privado (private endpoint) da a la aplicación una dirección IP privada en tu red virtual (VNet), para que los clientes la alcancen de forma privada, y luego puedes deshabilitar el acceso de red público; las restricciones de acceso (access restrictions) proporcionan reglas de permiso y denegación basadas en IP o en puntos de conexión de servicio sobre el punto de conexión público. Saliente: la integración con VNet (VNet integration) permite que la aplicación llame a recursos dentro de una VNet, como una base de datos en una IP privada, a través de una subred dedicada delegada a Microsoft.Web/serverFarms. La integración con VNet no hace que la aplicación sea accesible de forma privada, y un punto de conexión privado no permite que la aplicación llegue al interior de la red. Muchos diseños seguros usan ambos.

Las ranuras de implementación (deployment slots; Standard y superiores) son aplicaciones activas con sus propios nombres de host, como <app-name>-staging.azurewebsites.net. Implementas en staging, pruebas y precalientas, y luego la intercambias con producción con az webapp deployment slot swap --slot staging --target-slot production; el enrutamiento cambia sin tiempo de inactividad, y volver a intercambiar es una reversión instantánea. La configuración de la aplicación y las cadenas de conexión se mueven con el código durante un intercambio, a menos que estén marcadas como configuración de ranura de implementación (sticky), lo que las mantiene en la ranura. También puedes enrutar un porcentaje del tráfico de producción a una ranura y habilitar el intercambio automático después de la implementación.

Veamos un ejemplo práctico. Un bufete de abogados mueve su portal de clientes a App Service Standard. Agrega portal.contoso.com con un CNAME y un registro TXT asuid.portal, enlaza un certificado administrado gratuito con SNI SSL y habilita HTTPS Only con TLS 1.2 como mínimo. El portal lee una base de datos SQL que solo tiene un punto de conexión privado, así que el equipo habilita la integración con VNet en una subred delegada. Una ranura de staging contiene una cadena de conexión sticky que apunta a una base de datos de prueba. Cada versión va a staging, se prueba y luego se intercambia; cuando una versión falla, vuelven a intercambiar en menos de un minuto.

Errores comunes: usar un CNAME para el dominio ápice; olvidar el registro TXT asuid; esperar que la integración con VNet oculte la aplicación de internet; olvidar marcar como configuración de ranura la cadena de conexión de la base de datos de staging, de modo que producción apunta a datos de prueba después de un intercambio; y esperar que un certificado administrado cubra un nombre comodín.

Palabras clave del examen: 'la aplicación debe llegar a una base de datos privada' significa integración con VNet; 'accesible solo desde la red corporativa' significa un punto de conexión privado; 'publicación sin tiempo de inactividad con reversión instantánea' significa ranuras e intercambio; 'la configuración debe quedarse en la ranura' significa configuración de ranura de implementación; 'dominio raíz' significa un registro A.

Términos clave

Dominio personalizado (custom domain)
Tu propio nombre DNS asignado a una aplicación de App Service con un registro CNAME o A más un registro TXT de verificación asuid.
Certificado administrado de App Service (App Service managed certificate)
Certificado TLS gratuito y renovado automáticamente para dominios personalizados que no son comodín en una aplicación.
SNI SSL
Enlace TLS que usa Server Name Indication para que muchos certificados puedan compartir una dirección IP.
Integración con VNet (VNet integration)
Función saliente que permite a una aplicación llegar a recursos de una red virtual a través de una subred delegada.
Punto de conexión privado (private endpoint)
Función entrante que da a la aplicación una IP privada en una VNet para que los clientes la alcancen de forma privada.
Ranura de implementación (deployment slot)
Instancia activa independiente de una aplicación, como staging, que se puede intercambiar con producción.
Configuración de ranura de implementación (deployment slot setting)
Configuración de aplicación o cadena de conexión marcada como sticky para que se quede en su ranura durante un intercambio.
Ejemplo real

Una tienda en línea implementa cada versión en una ranura de staging que usa una cadena de conexión sticky para una pasarela de pago de prueba. Cuando pasan las pruebas de humo, el equipo intercambia staging con producción; el código se mueve, pero la ranura de producción conserva la configuración de su pasarela de pago real. Cuando aparece un error una hora después, vuelven a intercambiar para restaurar la versión anterior al instante y luego investigan la compilación defectuosa en la ranura de staging sin afectar a los clientes.

Consejo para el examen: La integración con VNet es solo saliente; un punto de conexión privado es solo entrante. Los intercambios de ranuras mueven la configuración a menos que esté marcada como configuración de ranura de implementación. Un dominio ápice usa un registro A, un subdominio normalmente un CNAME, y ambos necesitan un registro TXT asuid.

Comprueba lo que sabes

Una aplicación de App Service debe conectarse a una base de datos SQL que solo tiene una dirección IP privada. ¿Qué función se necesita?

La integración con VNet, que da a la aplicación acceso saliente a la red virtual a través de una subred delegada.

¿Qué registros DNS creas para asignar contoso.com (el ápice) a una aplicación de App Service?

Un registro A que apunta a la dirección IP de la aplicación y un registro TXT llamado asuid que contiene el ID de verificación de dominio.

Después de un intercambio, producción está usando la base de datos de staging. ¿Qué se pasó por alto?

La cadena de conexión no estaba marcada como configuración de ranura de implementación, así que se movió con el código durante el intercambio.

¿Cuál es el nivel mínimo para las ranuras de implementación?

Standard; los planes Free, Shared y Basic no admiten ranuras de implementación.
