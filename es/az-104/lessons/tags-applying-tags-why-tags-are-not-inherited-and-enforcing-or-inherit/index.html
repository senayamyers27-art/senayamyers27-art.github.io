Etiquetas: cómo aplicarlas, por qué no se heredan y cómo exigirlas o heredarlas con directivas

Las etiquetas (tags) son pares de nombre y valor, como CostCenter = 1234 o Environment = Production, que asocias a suscripciones, grupos de recursos y recursos. No cambian cómo funciona un recurso. En cambio, agregan metadatos de negocio con los que puedes filtrar, generar informes y automatizar: quién es el dueño del recurso, qué proyecto lo paga, si se puede apagar de noche. El análisis de costos puede agrupar el gasto por etiqueta, que suele ser la razón principal por la que las organizaciones las adoptan.

Aplicas etiquetas en la hoja Tags de un recurso, al crearlo en el portal, en plantillas ARM o Bicep con la propiedad tags, o desde la línea de comandos con az tag update --operation merge o Update-AzTag -Operation Merge. Fíjate en la operación: Merge agrega o actualiza las etiquetas que indicas, mientras que Replace quita todas las etiquetas existentes y deja solo el nuevo conjunto. Los nombres de las etiquetas no distinguen mayúsculas de minúsculas, y cada recurso tiene un límite de cuántas etiquetas puede llevar. No todos los tipos de recurso admiten etiquetas, y algunos solo las aceptan mediante ciertas herramientas.

Para editar etiquetas necesitas acceso de escritura al recurso, que Contributor proporciona. El rol integrado Tag Contributor permite a alguien administrar etiquetas en los recursos sin darle acceso a los recursos en sí, lo que resulta adecuado para un equipo de finanzas o de gobernanza.

El dato clave para el examen: las etiquetas no se heredan. Si etiquetas un grupo de recursos con CostCenter = 1234, las VM, discos y NIC que contiene no reciben esa etiqueta. Lo mismo ocurre con las suscripciones. La gente suele sorprenderse cuando el análisis de costos agrupado por etiqueta muestra la mayor parte del gasto como 'untagged' (sin etiquetar), aunque todos los grupos de recursos están etiquetados. (Cost Management tiene su propia configuración de herencia de etiquetas que copia las etiquetas en los registros de uso para los informes, pero no etiqueta los recursos en sí).

Azure Policy cierra esa brecha. Entre las definiciones integradas están 'Require a tag on resources' y 'Require a tag and its value on resource groups', que usan el efecto Deny para que las implementaciones sin etiquetas fallen. 'Add or replace a tag on resources' e 'Inherit a tag from the resource group if missing' usan el efecto Modify, así que Azure agrega la etiqueta automáticamente a medida que se crean o actualizan recursos. Para los recursos que ya existen, ejecuta una tarea de corrección sobre la asignación Modify, y los etiquetará de forma masiva usando la identidad administrada de la asignación.

Un buen patrón combina ambas cosas: exige una etiqueta CostCenter en los grupos de recursos con Deny, asigna 'Inherit a tag from the resource group if missing' para la misma etiqueta en la suscripción o el grupo de administración y luego corrige una vez los recursos existentes. A partir de entonces, cada recurso nuevo recibe la etiqueta sin que los desarrolladores tengan que acordarse.

Términos clave

Tag (etiqueta)
Un par de nombre y valor de metadatos asociado a una suscripción, grupo de recursos o recurso.
Merge vs Replace
Operaciones de actualización de etiquetas: Merge agrega o cambia las etiquetas indicadas; Replace sobrescribe todo el conjunto de etiquetas.
Tag Contributor
Un rol integrado que permite administrar etiquetas en las entidades sin conceder acceso a las entidades en sí.
Inherit a tag from the resource group
Una directiva Modify integrada que copia una etiqueta del grupo de recursos principal en los recursos que no la tienen.
Ejemplo real

Finanzas informa que el 70 por ciento del gasto del mes pasado está sin etiquetar, aunque todos los grupos de recursos tienen una etiqueta CostCenter. El administrador asigna la directiva integrada 'Inherit a tag from the resource group if missing' para CostCenter en la suscripción, crea una tarea de corrección para etiquetar los recursos existentes, y el análisis de costos del mes siguiente agrupado por CostCenter casi no muestra gasto sin etiquetar.

Consejo para el examen: Las etiquetas nunca se heredan automáticamente. Si una pregunta plantea cómo pueden los recursos obtener las etiquetas de su grupo de recursos, la respuesta es una Azure Policy con el efecto Modify (más una corrección para los recursos existentes), no un bloqueo ni RBAC.

Comprueba lo que sabes

Etiquetas un grupo de recursos con Environment = Test. ¿Una cuenta de almacenamiento creada después en él tiene esa etiqueta?

No. Las etiquetas no se heredan; necesitas una directiva Modify como 'Inherit a tag from the resource group if missing' para copiarla.

¿Qué efecto de directiva impide que los usuarios creen recursos sin una etiqueta obligatoria?

Deny, como lo usa la definición integrada 'Require a tag on resources'.

¿Qué pasa si actualizas las etiquetas con la operación Replace y solo especificas Owner = Ana?

Se quitan todas las etiquetas existentes y el recurso queda solo con la etiqueta Owner.
