Etiquetas: cómo aplicarlas, por qué no se heredan y cómo exigirlas o heredarlas con directivas

Las etiquetas son pares de nombre y valor, como CostCenter = 1234 o Environment = Production, que adjuntas a suscripciones, grupos de recursos y recursos. No cambian el funcionamiento de un recurso. En cambio, agregan metadatos de negocio por los que puedes filtrar, generar informes y automatizar: quién es el propietario del recurso, qué proyecto lo paga, si se puede apagar por la noche. El análisis de costos de Microsoft Cost Management puede agrupar el gasto por etiqueta, que suele ser el motivo principal por el que las organizaciones adoptan un estándar de etiquetado. La automatización también puede usarlas, por ejemplo un runbook que detiene cada noche todas las VM etiquetadas AutoShutdown = Yes. Un estándar de etiquetado solo funciona si se hace cumplir, y ahí entra Azure Policy, como verás más adelante en esta lección.

Aplicas etiquetas en la hoja Etiquetas de un recurso, al crearlo en el portal, en plantillas de Azure Resource Manager (ARM) o Bicep con la propiedad tags, o desde la línea de comandos. Presta atención a la operación: Merge agrega o actualiza las etiquetas que indicas, Replace quita todas las etiquetas existentes y deja solo el nuevo conjunto, y Delete quita las etiquetas indicadas.

az tag update --resource-id <id> --operation Merge --tags CostCenter=1234 Owner=ana
az tag update --resource-id <id> --operation Replace --tags Owner=ana
# PowerShell equivalent
Update-AzTag -ResourceId <id> -Tag @{CostCenter='1234'} -Operation Merge

Los nombres de etiqueta no distinguen mayúsculas de minúsculas en la mayoría de las operaciones, pero los valores sí. Cada recurso tiene un límite de etiquetas que puede llevar, y no todos los tipos de recurso admiten etiquetas. Para editar etiquetas necesitas acceso de escritura al recurso, que proporciona Contributor. El rol integrado Tag Contributor permite a alguien administrar las etiquetas de los recursos sin darle acceso a los recursos en sí, lo que conviene a un equipo de finanzas o de gobernanza. El dato clave para el examen es que las etiquetas no se heredan. Si etiquetas un grupo de recursos con CostCenter = 1234, las VM, los discos y las interfaces de red que contiene no reciben esa etiqueta, y lo mismo ocurre con las suscripciones. Cost Management tiene su propia opción de herencia de etiquetas que aplica las etiquetas de la suscripción y del grupo de recursos a los registros de uso para los informes, pero no etiqueta los recursos en sí.

Azure Policy cierra esa brecha. Entre las definiciones integradas están 'Require a tag on resources' y 'Require a tag and its value on resource groups', que usan el efecto Deny para que fallen las implementaciones sin etiqueta. 'Add or replace a tag on resources' e 'Inherit a tag from the resource group if missing' usan el efecto Modify, así que Azure agrega la etiqueta automáticamente a medida que se crean o actualizan recursos. Para los recursos que ya existen, ejecuta una tarea de corrección sobre la asignación Modify, que los etiqueta de forma masiva usando la identidad administrada de la asignación. Un buen patrón combina ambas: exigir una etiqueta CostCenter en los grupos de recursos con Deny, asignar 'Inherit a tag from the resource group if missing' para la misma etiqueta en la suscripción o el grupo de administración y luego corregir una vez los recursos existentes.

Veamos un ejemplo práctico. Finanzas informa que el 70 por ciento del gasto del mes pasado no tiene etiqueta, aunque todos los grupos de recursos tienen una etiqueta CostCenter. Explicas que las etiquetas no se heredan, luego asignas 'Inherit a tag from the resource group if missing' para CostCenter en la suscripción y creas una tarea de corrección que etiqueta los recursos existentes. También asignas 'Require a tag on resource groups' con Deny para que no se puedan crear grupos nuevos sin CostCenter. El análisis de costos del mes siguiente agrupado por CostCenter casi no muestra gasto sin etiquetar, y los desarrolladores nunca tuvieron que cambiar sus plantillas.

Errores comunes: suponer que la etiqueta de un grupo de recursos pasa a sus recursos; usar Replace cuando querías Merge y borrar las etiquetas existentes; elegir Deny cuando el requisito es agregar etiquetas automáticamente; olvidar la corrección de los recursos existentes; y darle Contributor a un equipo de finanzas solo para que edite etiquetas, cuando Tag Contributor es la opción de privilegio mínimo. Recuerda también que las etiquetas son texto sin cifrar visible para cualquiera con acceso de lectura, así que nunca guardes secretos en ellas.

Redacción típica del examen: 'los recursos no muestran las etiquetas del grupo de recursos' apunta a la falta de herencia. 'Aplicar automáticamente la etiqueta del grupo de recursos' apunta a la directiva Modify 'Inherit a tag from the resource group if missing'. 'Impedir recursos sin etiqueta' apunta a Deny con 'Require a tag'. 'Aplicar a los recursos existentes' apunta a una tarea de corrección. 'Administrar solo etiquetas' apunta a Tag Contributor. 'Informar los costos por departamento' apunta a etiquetas más análisis de costos agrupado por etiqueta.

Términos clave

Etiqueta (tag)
Un par de nombre y valor de metadatos adjunto a una suscripción, un grupo de recursos o un recurso.
Merge vs. Replace
Operaciones de actualización de etiquetas: Merge agrega o cambia las etiquetas indicadas, Replace sobrescribe todo el conjunto de etiquetas.
Tag Contributor
Un rol integrado que permite administrar etiquetas en entidades sin conceder acceso a las entidades en sí.
Require a tag on resources
Una directiva integrada con Deny que impide crear o actualizar recursos que no tengan una etiqueta especificada.
Inherit a tag from the resource group
Una directiva integrada con Modify que copia una etiqueta del grupo de recursos principal a los recursos que no la tienen.
Herencia de etiquetas de Cost Management
Una opción de facturación que aplica las etiquetas principales a los registros de uso para los informes, sin cambiar los recursos.
Ejemplo real

Finanzas informa que el 70 por ciento del gasto del mes pasado no tiene etiqueta, aunque todos los grupos de recursos tienen una etiqueta CostCenter. El administrador asigna la directiva integrada 'Inherit a tag from the resource group if missing' para CostCenter en la suscripción, crea una tarea de corrección para etiquetar los recursos existentes, y el análisis de costos del mes siguiente agrupado por CostCenter casi no muestra gasto sin etiquetar.

Consejo para el examen: Las etiquetas nunca se heredan automáticamente. Si una pregunta plantea cómo pueden los recursos obtener las etiquetas de su grupo de recursos, la respuesta es una directiva de Azure Policy con el efecto Modify (más una corrección para los recursos existentes), no un bloqueo ni RBAC.

Comprueba lo que sabes

Etiquetas un grupo de recursos con Environment = Test. ¿Una cuenta de almacenamiento creada después en él tiene esa etiqueta?

No. Las etiquetas no se heredan; necesitas una directiva Modify como 'Inherit a tag from the resource group if missing' para copiarla.

¿Qué efecto de directiva impide a los usuarios crear recursos sin una etiqueta obligatoria?

Deny, como el que usa la definición integrada 'Require a tag on resources'.

¿Qué pasa si actualizas las etiquetas con la operación Replace y solo especificas Owner = Ana?

Se quitan todas las etiquetas existentes y el recurso queda solo con la etiqueta Owner.

Un analista de finanzas debe editar las etiquetas de todos los recursos pero no cambiar los recursos. ¿Qué rol asignas?

Tag Contributor, que concede la administración de etiquetas sin acceso a los recursos en sí.
