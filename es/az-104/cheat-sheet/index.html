Dominio 1: Manage Azure identities and governance (24%)

Consejos para el examen

  • Fíjate en el tipo de miembro. Los dispositivos solo pueden ir en grupos de seguridad, las reglas de dispositivo dinámico solo funcionan en grupos de seguridad y los grupos de Microsoft 365 no pueden contener grupos anidados. Los grupos dinámicos además requieren licencias de Entra ID P1.
  • Si falla la asignación de una licencia, revisa primero la ubicación de uso. En preguntas sobre SSPR, recuerda que las opciones de alcance son None, Selected (un solo grupo) y All, y que los usuarios locales necesitan password writeback.
  • Contributor no puede asignar roles y User Access Administrator no puede crear recursos; solo Owner puede hacer ambas cosas. Los permisos se suman entre todas las asignaciones, y NotActions no es una denegación.
  • Las tareas de directorio (usuarios, grupos, contraseñas) apuntan a roles de Entra; las tareas de recursos apuntan a Azure RBAC. Si la pregunta trata de leer el contenido de blobs con Entra ID, busca un rol 'Storage Blob Data', no Reader ni Contributor.
  • Deny y Audit no cambian los recursos existentes. Si una pregunta plantea cómo corregir recursos que ya existen, la respuesta implica una directiva Modify o DeployIfNotExists y una tarea de corrección, con una identidad administrada.
  • Solo Owner y User Access Administrator (entre los roles integrados) pueden quitar bloqueos. ReadOnly puede romper operaciones normales como enumerar claves de almacenamiento o iniciar VM, y los bloqueos nunca protegen los datos dentro de un recurso.
  • Las etiquetas nunca se heredan automáticamente. Si una pregunta plantea cómo pueden los recursos obtener las etiquetas de su grupo de recursos, la respuesta es una Azure Policy con el efecto Modify (más una corrección para los recursos existentes), no un bloqueo ni RBAC.
  • Mover recursos nunca cambia su región ni conserva las asignaciones de roles a nivel de recurso. Ambas suscripciones deben estar en el mismo tenant de Entra, y los recursos dependientes deben moverse juntos.
  • Las asignaciones fluyen hacia abajo, nunca hacia arriba ni hacia los lados. Para aplicar una regla a muchas suscripciones con el menor esfuerzo, asígnala en su grupo de administración común. Una suscripción confía en un tenant, y cada suscripción tiene un grupo de administración primario.
  • Los presupuestos alertan; no hacen cumplir. Si una pregunta plantea cómo detener recursos automáticamente cuando el gasto alcanza un umbral, la respuesta es un presupuesto con un grupo de acciones que ejecuta automatización. Las reservas son descuentos de facturación, no capacidad.

Términos clave

User principal name (UPN) (nombre principal de usuario)
El nombre de inicio de sesión de un usuario de Entra en formato de dirección de correo, cuyo sufijo debe ser un dominio verificado del tenant.
Security group (grupo de seguridad)
Un grupo de Entra que se usa para conceder acceso a recursos; puede contener usuarios, dispositivos, entidades de servicio y otros grupos.
Microsoft 365 group (grupo de Microsoft 365)
Un grupo de colaboración con buzón compartido, calendario, sitio de SharePoint y equipo de Teams opcional; sus miembros solo pueden ser usuarios.
Dynamic membership (pertenencia dinámica)
Pertenencia a un grupo calculada automáticamente a partir de una regla sobre atributos de usuario o dispositivo, en lugar de mantenerse a mano.
Usage location (ubicación de uso)
La propiedad de país de un usuario que debe establecerse antes de poder asignarle una licencia.
Group-based licensing (licencias basadas en grupos)
Asignar una licencia a un grupo para que todos los miembros la hereden y la pierdan al salir del grupo.
B2B guest user (usuario invitado B2B)
Una identidad externa invitada a tu tenant con tipo de usuario Guest, que inicia sesión con credenciales de su propia organización o cuenta.
Self-service password reset (SSPR) (restablecimiento de contraseña de autoservicio)
Una característica que permite a los usuarios registrados restablecer su propia contraseña usando métodos de autenticación verificados.
Password writeback (escritura diferida de contraseñas)
Una característica de sincronización que escribe de vuelta en Active Directory local las contraseñas restablecidas en la nube.
Role assignment (asignación de rol)
La vinculación de una entidad de seguridad con una definición de rol en un ámbito específico.
Scope (ámbito)
El nivel en el que se aplica el acceso: grupo de administración, suscripción, grupo de recursos o recurso; los niveles inferiores lo heredan.
NotActions
Operaciones eliminadas de la lista Actions de una definición de rol; no es una denegación y otro rol puede volver a concederlas.
User Access Administrator
Un rol integrado que puede administrar asignaciones de roles pero no puede administrar los recursos en sí.
Microsoft Entra role (rol de Microsoft Entra)
Un rol de directorio, como User Administrator, que controla la administración de objetos de Entra y la configuración del tenant.
Control plane (plano de control)
Operaciones de administración sobre recursos de Azure mediante Azure Resource Manager, regidas por Actions en los roles de RBAC.
Data plane (plano de datos)
Operaciones sobre los datos dentro de un recurso, como leer blobs, regidas por DataActions en los roles de RBAC.
Storage Blob Data Reader
Un rol integrado del plano de datos que permite leer y enumerar contenedores de blobs y blobs usando autorización de Entra.
Policy definition (definición de directiva)
Una regla JSON con una condición y un efecto que describe una configuración de recurso permitida o requerida.
Initiative (iniciativa)
Una definición de conjunto de directivas que agrupa varias definiciones para asignarlas y controlarlas juntas.
Exclusion (exclusión)
Un ámbito secundario indicado en una asignación que la asignación no evalúa.
DeployIfNotExists
Un efecto que implementa un recurso relacionado cuando falta, usando una identidad administrada para la asignación.
Remediation task (tarea de corrección)
Un trabajo que pone en cumplimiento los recursos existentes no conformes para directivas Modify y DeployIfNotExists.
CanNotDelete lock (bloqueo CanNotDelete)
Un bloqueo que permite leer y modificar un recurso, pero impide eliminarlo.
ReadOnly lock (bloqueo ReadOnly)
Un bloqueo que permite leer un recurso, pero impide tanto las actualizaciones como la eliminación.
Lock inheritance (herencia de bloqueos)
La regla por la cual un bloqueo en una suscripción o grupo de recursos se aplica a todos los recursos que están debajo, incluidos los creados después.
Tag (etiqueta)
Un par de nombre y valor de metadatos asociado a una suscripción, grupo de recursos o recurso.
Merge vs Replace
Operaciones de actualización de etiquetas: Merge agrega o cambia las etiquetas indicadas; Replace sobrescribe todo el conjunto de etiquetas.
Tag Contributor
Un rol integrado que permite administrar etiquetas en las entidades sin conceder acceso a las entidades en sí.
Inherit a tag from the resource group
Una directiva Modify integrada que copia una etiqueta del grupo de recursos principal en los recursos que no la tienen.
Resource group (grupo de recursos)
Un contenedor lógico para recursos de Azure que comparten un ciclo de vida; cada recurso pertenece exactamente a uno.
Resource group location (ubicación del grupo de recursos)
La región donde se almacenan los metadatos del grupo; no restringe dónde se implementan sus recursos.
Move validation (validación del movimiento)
Una comprobación que Azure ejecuta antes de un movimiento para confirmar que los tipos de recurso, las dependencias y el destino son compatibles.
Resource ID (ID de recurso)
La ruta completa de un recurso, incluidos la suscripción y el grupo de recursos, que cambia cuando el recurso se mueve.
Management group (grupo de administración)
Un contenedor por encima de las suscripciones que se usa para aplicar directivas y RBAC a muchas suscripciones a la vez.
Tenant Root Group
El único grupo de administración de nivel superior de cada tenant, del que descienden todos los grupos de administración y suscripciones.
Subscription (suscripción)
Un límite de facturación, cuota y administración para recursos de Azure que confía en un tenant de Entra.
Inheritance (herencia)
El flujo de las asignaciones de RBAC y de directivas desde un ámbito primario hacia todos los ámbitos secundarios.
Cost analysis (análisis de costos)
La vista de Cost Management para explorar los costos reales y previstos por ámbito, agrupados y filtrados por dimensiones como la etiqueta.
Budget (presupuesto)
Un umbral de gasto para un ámbito y un periodo con condiciones de alerta; notifica, pero no detiene el gasto.
Action group (grupo de acciones)
Un conjunto reutilizable de acciones de notificación y automatización que los presupuestos y las alertas pueden activar.
Reservation (reserva)
Un compromiso de uno o tres años con un tipo de recurso a cambio de un descuento de facturación sobre el uso que coincide.

Dominio 2: Implement and manage storage (19%)

Consejos para el examen

  • Relaciona los requisitos con las opciones: fallo de centro de datos = ZRS como mínimo; fallo de región = GRS o GZRS; debe leer durante una interrupción regional = RA-GRS o RA-GZRS. Las cuentas Premium no ofrecen redundancia geográfica.
  • Los puntos de conexión de servicio conservan el punto de conexión público y solo funcionan desde subredes de Azure; los puntos de conexión privados dan una IP privada utilizable desde redes emparejadas y locales. Las reglas IP no pueden contener direcciones privadas. Los puntos de conexión privados necesitan un DNS correcto.
  • Para revocar una SAS sin afectar a otros, usa una directiva de acceso almacenada. Las SAS de cuenta no pueden usarla, así que revocarlas implica regenerar la clave con la que se firmaron. La SAS de delegación de usuario es solo para blobs y no usa claves de cuenta.
  • Dos capas: primero RBAC a nivel de recurso compartido, luego NTFS, y gana la más estricta. Solo se puede habilitar un origen de identidad por cuenta de almacenamiento. Elevated Contributor es el rol de recurso compartido que permite cambiar las ACL NTFS.
  • El cifrado de infraestructura solo se puede establecer al crear la cuenta. CMK necesita una identidad administrada y un almacén de claves con soft delete y purge protection. El cifrado en reposo no se puede deshabilitar.
  • La replicación de objetos necesita control de versiones en ambas cuentas y fuente de cambios en la de origen, y solo maneja blobs en bloques. Usa azcopy sync para actualizaciones incrementales y azcopy copy para copias completas.
  • Archive está fuera de línea y primero debe rehidratarse; la prioridad Standard puede tardar hasta 15 horas. Las duraciones mínimas son 30 días para Cool, 90 para Cold y 180 para Archive. Archive no puede ser el nivel predeterminado de la cuenta.
  • Las reglas de ciclo de vida actúan según la antigüedad desde la modificación, la creación o el último acceso; las reglas de último acceso necesitan el seguimiento de acceso habilitado. Los cambios pueden tardar hasta 24 horas en aplicarse, y las versiones e instantáneas necesitan sus propias acciones.
  • La eliminación temporal protege contra eliminaciones; el control de versiones protege contra sobrescrituras; las instantáneas son manuales. La replicación de objetos y la restauración a un momento dado necesitan control de versiones y fuente de cambios. Ninguna de estas características protege la propia cuenta de almacenamiento.
  • Si un recurso compartido se monta desde VM de Azure pero no desde el entorno local, sospecha primero del puerto 445 bloqueado. La eliminación temporal protege recursos compartidos completos; las instantáneas o Azure Backup restauran archivos individuales. NFS requiere una cuenta premium.

Términos clave

LRS
Almacenamiento con redundancia local: tres copias síncronas en un centro de datos de la región primaria.
ZRS
Almacenamiento con redundancia de zona: tres copias síncronas en tres zonas de disponibilidad de la región primaria.
GRS / GZRS
Opciones con redundancia geográfica que replican de forma asíncrona a la región secundaria emparejada, usando LRS o ZRS en la primaria, respectivamente.
RA-GRS / RA-GZRS
Opciones con redundancia geográfica y acceso de lectura que permiten leer desde el punto de conexión secundario en cualquier momento.
Last Sync Time (hora de la última sincronización)
Una propiedad que muestra hasta qué momento se han replicado los datos en la región secundaria.
Storage firewall (firewall de almacenamiento)
Reglas de red en una cuenta de almacenamiento que solo permiten conectarse a los intervalos de IP públicas, subredes y excepciones indicados.
Service endpoint (punto de conexión de servicio)
Una configuración de subred que enruta el tráfico hacia un servicio por la red troncal de Azure e identifica la subred para que las reglas de red virtual puedan permitirla.
Trusted Microsoft services (servicios de Microsoft de confianza)
Una excepción del firewall que permite que servicios específicos de la plataforma Azure accedan a la cuenta incluso cuando el acceso público está restringido.
Private endpoint (punto de conexión privado)
Una interfaz de red con una IP privada en tu subred que se conecta a un subrecurso de almacenamiento específico mediante Private Link.
Account key (clave de cuenta)
Uno de los dos secretos que dan acceso total a los datos de una cuenta de almacenamiento y que se usan para firmar SAS de cuenta y de servicio.
Service SAS (SAS de servicio)
Una SAS firmada con una clave de cuenta que concede acceso a recursos de un solo servicio de almacenamiento.
User delegation SAS (SAS de delegación de usuario)
Una SAS de blob firmada con una clave obtenida mediante credenciales de Microsoft Entra, limitada por los permisos de esa identidad.
Stored access policy (directiva de acceso almacenada)
Un conjunto con nombre de restricciones de SAS en un contenedor, recurso compartido, cola o tabla que te permite revocar los tokens SAS de servicio vinculados.
AD DS authentication (autenticación con AD DS)
Autenticación de Azure Files en la que la cuenta de almacenamiento está unida al Active Directory local y los usuarios presentan tickets Kerberos de AD.
Microsoft Entra Kerberos
Una opción de Azure Files en la que Entra ID emite tickets Kerberos para identidades híbridas, de modo que los clientes no necesitan línea de visión a un controlador de dominio.
Share-level permission (permiso a nivel de recurso compartido)
Un rol de Azure RBAC, como Storage File Data SMB Share Contributor, que controla el acceso a todo un recurso compartido de archivos.
NTFS permissions (permisos NTFS)
Listas de control de acceso de Windows en directorios y archivos del recurso compartido que proporcionan acceso detallado.
Storage Service Encryption
Cifrado AES-256 automático y siempre activo de los datos en reposo en Azure Storage.
Customer-managed key (CMK) (clave administrada por el cliente)
Una clave que controlas en Key Vault o Managed HSM y que protege las claves de cifrado de datos de una cuenta de almacenamiento.
Infrastructure encryption (cifrado de infraestructura)
Una segunda capa opcional de cifrado a nivel de infraestructura que debe habilitarse al crear la cuenta.
Encryption scope (ámbito de cifrado)
Una configuración de clave con nombre dentro de una cuenta de almacenamiento que se puede aplicar a contenedores o a blobs individuales.
Object replication (replicación de objetos)
Copia asíncrona y basada en directivas de blobs en bloques desde un contenedor de origen a un contenedor de destino en otra cuenta.
Change feed (fuente de cambios)
Un registro ordenado de los cambios en los blobs de una cuenta, requerido en la cuenta de origen para la replicación de objetos.
AzCopy
Una herramienta de línea de comandos para copiar y sincronizar datos con Blob Storage y Azure Files.
Azure Storage Explorer
Una GUI de escritorio gratuita para explorar y administrar cuentas de almacenamiento que usa AzCopy para las transferencias.
Access tier (nivel de acceso)
La configuración Hot, Cool, Cold o Archive de un blob en bloques que determina los costos de almacenamiento y de acceso.
Archive tier (nivel Archive)
Un nivel fuera de línea para datos de acceso poco frecuente; los blobs deben rehidratarse antes de poder leerse.
Rehydration (rehidratación)
Devolver un blob archivado a un nivel en línea, cambiando su nivel o copiándolo, con prioridad Standard o High.
Early deletion charge (cargo por eliminación anticipada)
Una tarifa por quitar o cambiar de nivel un blob antes de que termine el periodo mínimo de retención del nivel.
Lifecycle management policy (directiva de administración del ciclo de vida)
Un conjunto de reglas JSON en una cuenta de almacenamiento que cambian de nivel o eliminan blobs automáticamente según condiciones.
prefixMatch
Un filtro de regla que limita una regla a los blobs cuyo nombre empieza con un nombre de contenedor y una ruta opcional.
daysAfterModificationGreaterThan
Una condición que activa una acción cuando un blob lleva sin modificarse más días que el número indicado.
Last access time tracking (seguimiento de la hora del último acceso)
Una configuración de la cuenta que registra las lecturas de blobs para que las reglas puedan actuar según los días desde el último acceso.
Blob soft delete (eliminación temporal de blobs)
Una configuración que conserva los blobs e instantáneas eliminados durante un número de días definido para poder recuperarlos.
Container soft delete (eliminación temporal de contenedores)
Una configuración que conserva los contenedores eliminados y su contenido durante un número de días definido.
Blob versioning (control de versiones de blobs)
Conservación automática del estado anterior de un blob cada vez que se modifica o se elimina.
Snapshot (instantánea)
Una copia de solo lectura de un blob en un momento dado, creada manualmente.
Azure file share (recurso compartido de Azure Files)
Un recurso compartido SMB o NFS administrado, alojado en una cuenta de almacenamiento, que los clientes montan como una unidad de red.
Share snapshot (instantánea de recurso compartido)
Una copia incremental de solo lectura de todo un recurso compartido de archivos en un momento dado.
File share soft delete (eliminación temporal de recursos compartidos)
Una configuración que conserva los recursos compartidos eliminados durante un periodo para poder recuperarlos.
Port 445 (puerto 445)
El puerto TCP que usa SMB, a menudo bloqueado por ISP y firewalls, lo que impide montar recursos compartidos de Azure Files desde fuera.

Dominio 3: Deploy and manage Azure compute resources (24%)

Consejos para el examen

  • Ten claro de dónde vienen los valores: los parámetros se proporcionan en la implementación, las variables se calculan en la plantilla y las salidas se devuelven después. az bicep decompile convierte JSON a Bicep; az bicep build hace lo contrario.
  • Incremental es el predeterminado y nunca elimina; completo elimina todo lo que esté en el grupo de recursos pero no en la plantilla. Ejecuta siempre what-if antes de una implementación en modo completo.
  • Ultra Disk y Premium SSD v2 no pueden ser discos del SO. El disco temporal pierde los datos al desasignar. Encryption at host es a nivel de plataforma y no necesita agente; ADE es dentro del invitado con Key Vault y se está retirando.
  • Si un tamaño no aparece en la lista de cambio de tamaño, desasigna primero la VM. Mover entre grupos de recursos o suscripciones nunca cambia la región de una VM; usa Resource Mover o Site Recovery para cambiar de región. Los discos pueden crecer, no reducirse.
  • Fallo de centro de datos = zonas de disponibilidad (99.99 por ciento); protección de rack o mantenimiento = conjunto de disponibilidad (99.95 por ciento); una sola VM con discos premium = 99.9 por ciento. Los conjuntos de disponibilidad solo se eligen al crear la VM.
  • Combina siempre las reglas de escalado horizontal con reglas de reducción. La directiva de reducción Default equilibra zonas y dominios de error y luego quita el ID de instancia más alto; usa la protección de instancias para conservar una VM específica. Los tamaños de VM mixtos requieren orquestación Flexible.
  • La replicación geográfica, los puntos de conexión privados y las claves administradas por el cliente apuntan al nivel Premium. Usa AcrPull para identidades que solo descargan imágenes y mantén deshabilitado el usuario administrador.
  • Los trabajos por lotes en ACI deben usar Never u OnFailure, no el valor predeterminado Always. En Container Apps, dividir el tráfico requiere el modo de varias revisiones, y un número mínimo de réplicas de cero permite escalar a cero.
  • Escala verticalmente para obtener más potencia o características; escala horizontalmente para tener más instancias. El escalado automático basado en reglas necesita Standard o superior, y las ranuras de implementación también empiezan en Standard. Todas las aplicaciones de un plan se comparten y escalan juntas.
  • La integración con VNet es solo saliente; un punto de conexión privado es solo entrante. Los intercambios de ranuras mueven la configuración a menos que esté marcada como deployment slot setting. Los dominios raíz usan un registro A; los subdominios normalmente un CNAME, ambos con un registro TXT asuid para la verificación.

Términos clave

ARM template (plantilla ARM)
Un archivo JSON que declara recursos, parámetros, variables y salidas de Azure para que Azure Resource Manager los implemente.
Bicep
Un lenguaje específico de dominio para Azure que se compila a ARM JSON, con una sintaxis más sencilla y dependencias automáticas.
Parameter (parámetro)
Un valor que se proporciona en el momento de la implementación para que una plantilla se pueda reutilizar con distintas entradas.
Decompile (descompilar)
Convertir una plantilla ARM JSON a Bicep con az bicep decompile.
Incremental mode (modo incremental)
El modo de implementación predeterminado que crea o actualiza los recursos de la plantilla y deja intactos los demás recursos del grupo.
Complete mode (modo completo)
Un modo de implementación que además elimina los recursos del grupo de recursos que no están declarados en la plantilla.
What-if
Una operación de vista previa que muestra lo que una implementación crearía, cambiaría o eliminaría sin hacer cambios.
Idempotent (idempotente)
Que produce el mismo resultado sin importar cuántas veces se ejecute, que es como se comportan las implementaciones de plantillas.
VM size (tamaño de VM)
La combinación de vCPU, memoria, almacenamiento temporal y límites de disco y de red de una VM.
Temporary disk (disco temporal)
Almacenamiento local no persistente en el host de la VM que se pierde cuando la VM se desasigna o se mueve.
Ultra Disk
El tipo de disco administrado de mayor rendimiento, con IOPS y rendimiento ajustables de forma independiente, utilizable solo como disco de datos.
Encryption at host (cifrado en el host)
Una característica de la plataforma que cifra el disco temporal y las cachés de disco en el host, proporcionando cifrado de extremo a extremo.
Azure Disk Encryption
Cifrado de volúmenes dentro del invitado usando BitLocker o DM-Crypt con claves en Azure Key Vault.
Deallocate (desasignar)
Detener una VM para que libere su hardware de host y deje de facturar el proceso, lo que permite colocarla en otro hardware.
Azure Resource Mover
Un servicio que mueve VM y recursos relacionados entre regiones de Azure con comprobaciones de dependencias y pasos de confirmación.
Disk snapshot (instantánea de disco)
Una copia de un disco administrado en un momento dado, que puede ser incremental.
Unattached disk (disco no conectado)
Un disco administrado que no está conectado a ninguna VM y que sigue generando costos de almacenamiento.
Fault domain (dominio de error)
Un grupo de hardware que comparte alimentación y red y que puede fallar en conjunto, como un rack.
Update domain (dominio de actualización)
Un grupo de hosts que pueden reiniciarse juntos durante el mantenimiento planificado; solo se actualiza uno a la vez.
Availability set (conjunto de disponibilidad)
Un agrupamiento que reparte las VM entre dominios de error y de actualización dentro de un centro de datos.
Availability zone (zona de disponibilidad)
Una ubicación de centro de datos físicamente separada dentro de una región, con alimentación, refrigeración y redes independientes.
SLA
Service level agreement (acuerdo de nivel de servicio): el porcentaje de tiempo de actividad que Microsoft garantiza para una configuración.
Virtual Machine Scale Set (conjunto de escalado de máquinas virtuales)
Un recurso que implementa y administra un grupo de VM con equilibrio de carga a partir de un modelo común, con escalado automático.
Flexible orchestration (orquestación Flexible)
El modo de conjunto de escalado recomendado que administra VM estándar, permite tamaños mixtos y reparte las instancias entre dominios de error y zonas.
Autoscale rule (regla de escalado automático)
Una condición sobre una métrica, en una ventana de tiempo, que agrega o quita instancias por un número o un porcentaje.
Scale-in policy (directiva de reducción horizontal)
La regla (Default, NewestVM u OldestVM) que decide qué instancias se eliminan al reducir horizontalmente.
Instance protection (protección de instancias)
Una configuración que excluye una instancia específica de la reducción horizontal o de todas las acciones del conjunto de escalado.
Azure Container Registry
Un registro privado administrado para imágenes de contenedor y artefactos relacionados.
Geo-replication (replicación geográfica)
Una característica de ACR Premium que replica un registro en varias regiones para descargas locales y resiliencia.
AcrPull
Un rol integrado que permite descargar imágenes de un registro, normalmente asignado a una identidad administrada.
ACR Tasks
Una característica del registro que compila y actualiza imágenes de contenedor en Azure, activada manualmente, por commits o por actualizaciones de la imagen base.
Container group (grupo de contenedores)
Una implementación de ACI de uno o más contenedores que comparten host, ciclo de vida, red y volúmenes.
Restart policy (directiva de reinicio)
La configuración de ACI Always, OnFailure o Never que decide si los contenedores se reinician después de terminar.
Revision (revisión)
Una instantánea inmutable de una versión de Container Apps, creada cuando cambian configuraciones con ámbito de revisión.
Ingress (entrada)
La configuración de Container Apps que expone una aplicación de forma interna o externa mediante HTTP o TCP.
Scale rule (regla de escalado)
Una regla de Container Apps basada en orígenes de eventos HTTP, TCP o KEDA que define el número de réplicas.
App Service plan (plan de App Service)
El conjunto de recursos de proceso (región, SO, nivel, tamaño, número de instancias) sobre el que se ejecutan una o más aplicaciones de App Service.
Scale up (escalar verticalmente)
Pasar a un nivel superior o a un tamaño de instancia más grande para obtener más recursos y características por instancia.
Scale out (escalar horizontalmente)
Aumentar el número de instancias que ejecutan las aplicaciones de un plan.
Autoscale (escalado automático)
Ajuste automático del número de instancias, basado en reglas o en programación, disponible en Standard y niveles superiores.
Custom domain verification (verificación de dominio personalizado)
Demostrar a App Service la propiedad del dominio con un registro TXT asuid antes de asignar un registro CNAME o A.
App Service managed certificate (certificado administrado de App Service)
Un certificado TLS gratuito y renovado automáticamente para un dominio personalizado sin comodín en una aplicación.
VNet integration (integración con VNet)
Una característica saliente que permite que una aplicación llegue a recursos dentro de una red virtual a través de una subred delegada.
Private endpoint (App Service) (punto de conexión privado)
Una característica entrante que da a la aplicación una IP privada en una red virtual para que los clientes lleguen a ella de forma privada.
Deployment slot setting (configuración de ranura de implementación)
Una configuración de aplicación o cadena de conexión fija (sticky) que permanece con su ranura durante un intercambio.

Dominio 4: Implement and manage virtual networking (19%)

Consejos para el examen

  • Direcciones utilizables = total menos 5. La primera dirección utilizable es .4. Los espacios de direcciones superpuestos impiden el emparejamiento y las conexiones VPN, y los servicios especiales necesitan subredes con nombres especiales.
  • El emparejamiento es no transitivo: A-B y B-C no dan A-C. Allow gateway transit va en la VNet que tiene la puerta de enlace; Use remote gateways va en la VNet que la toma prestada. Los espacios de direcciones no deben superponerse.
  • Las IP públicas Standard siempre son estáticas, compatibles con zonas y cerradas al tráfico entrante hasta que un NSG lo permita. La elección de zona se fija al crearlas. Las SKU del equilibrador de carga y de la IP pública deben coincidir.
  • Las tablas de rutas se asocian con subredes, no con NIC. Gana el prefijo más largo; en caso de empate, UDR gana sobre BGP, que gana sobre las rutas del sistema. Virtual appliance necesita una IP de próximo salto y reenvío IP en la NIC de la NVA. None descarta el tráfico.
  • Gana el número de prioridad más bajo y el procesamiento se detiene en la primera coincidencia. Entrante: NSG de subred y luego NSG de NIC; saliente: NIC y luego subred; ambos deben permitir. La regla predeterminada DenyAllInBound bloquea el tráfico de internet a menos que agregues un Allow.
  • La subred debe llamarse AzureBastionSubnet y ser /26 o más grande. El cliente nativo, el escalado del host, los vínculos compartibles y la conexión basada en IP necesitan Standard o superior. Las VM no necesitan IP pública.
  • Acceso desde el entorno local, deshabilitar el acceso público o limitar el ámbito a una sola instancia de recurso significa punto de conexión privado. Si falla una conexión por punto de conexión privado, revisa primero el DNS: el nombre debe resolverse a la IP privada mediante una zona privatelink.
  • Una zona no hace nada hasta que los registros NS del registrador apuntan a los servidores de nombres de Azure. Usa un registro de alias para el ápice de la zona y para seguir recursos de Azure. Solo una zona privada con registro automático por VNet.
  • Los equilibradores de carga Standard bloquean el tráfico entrante hasta que un NSG lo permite. Las reglas de equilibrio de carga reparten el tráfico; las reglas NAT de entrada asignan un puerto a una VM. Las necesidades de capa 7 (rutas URL, WAF) apuntan a Application Gateway, no a Load Balancer.
  • ¿Bloqueado por un NSG? IP flow verify nombra la regla. ¿Ruta incorrecta? Next hop muestra el próximo salto y la tabla de rutas; las rutas efectivas muestran la tabla completa. ¿Prueba de extremo a extremo con latencia y saltos? Connection troubleshoot.

Términos clave

Virtual network (VNet) (red virtual)
Una red privada y aislada en una región de Azure en la que los recursos obtienen direcciones IP privadas.
Address space (espacio de direcciones)
El intervalo o los intervalos CIDR asignados a una VNet, que no deben superponerse con las redes a las que quieras conectarte.
Subnet (subred)
Un intervalo dentro del espacio de direcciones de una VNet donde se colocan los recursos y donde se aplican los NSG y las tablas de rutas.
Reserved addresses (direcciones reservadas)
Las cinco direcciones que Azure reserva en cada subred: red, puerta de enlace predeterminada, dos para Azure DNS y difusión.
VNet peering (emparejamiento de VNet)
Una conexión privada por la red troncal entre dos VNet que permite a los recursos comunicarse por IP privada.
Global peering (emparejamiento global)
Emparejamiento entre VNet de diferentes regiones de Azure.
Non-transitive (no transitivo)
La propiedad por la que el emparejamiento conecta solo las dos VNet involucradas, no las VNet emparejadas con cualquiera de ellas.
Gateway transit (tránsito de puerta de enlace)
Una opción de emparejamiento que permite a las VNet emparejadas usar la puerta de enlace de VPN o ExpressRoute de la VNet concentradora, combinada con Use remote gateways en el radio.
Standard SKU public IP (IP pública de SKU Standard)
La SKU actual de IP pública: siempre estática, cerrada al tráfico entrante de forma predeterminada y compatible con zonas.
Static allocation (asignación estática)
Una asignación de IP que no cambia durante toda la vida del recurso de IP pública.
Zone-redundant IP (IP con redundancia de zona)
Una IP pública que se sirve desde todas las zonas de disponibilidad de una región y sobrevive al fallo de una sola zona.
Public IP prefix (prefijo de IP pública)
Un intervalo contiguo reservado de direcciones IP públicas estáticas.
System route (ruta del sistema)
Una ruta predeterminada que Azure crea automáticamente para cada subred, como el intervalo de la VNet y 0.0.0.0/0 hacia internet.
Route table (tabla de rutas)
Un recurso que contiene rutas definidas por el usuario y que se asocia con subredes para controlar el tráfico saliente.
Virtual appliance next hop (próximo salto de aplicación virtual)
Un próximo salto de ruta que reenvía el tráfico a la IP privada de una aplicación virtual de red, como un firewall.
Forced tunneling (tunelización forzada)
Enrutar todo el tráfico con destino a internet de vuelta al entorno local a través de una conexión VPN o ExpressRoute.
IP forwarding (reenvío IP)
Una configuración de NIC que permite a una VM reenviar tráfico que no va dirigido a ella, necesaria para las NVA.
Network security group (NSG) (grupo de seguridad de red)
Un conjunto con estado de reglas de permitir y denegar con prioridad que filtra el tráfico de subredes y NIC.
Priority (prioridad)
Un número de 100 a 4096; los números más bajos se evalúan primero y el procesamiento se detiene en la primera coincidencia.
Service tag (etiqueta de servicio)
Un grupo con nombre de prefijos IP para un servicio o ámbito de Azure, como Internet o Storage, mantenido por Microsoft.
Application security group (ASG) (grupo de seguridad de aplicaciones)
Un grupo con nombre de NIC que se puede usar como origen o destino en las reglas de NSG.
Effective security rules (reglas de seguridad efectivas)
Las reglas combinadas de todos los NSG aplicados a una NIC, tal como se aplican realmente.
Azure Bastion
Un servicio administrado que proporciona acceso RDP y SSH a las VM mediante TLS sin exponer los puertos ni las IP públicas de las VM.
AzureBastionSubnet
La subred dedicada, de al menos /26, que requiere una implementación de Bastion.
Native client support (compatibilidad con cliente nativo)
Una característica de Bastion Standard o Premium que te permite conectarte con tu cliente RDP o SSH local mediante la Azure CLI.
Host scaling (escalado del host)
Agregar instancias de Bastion en la SKU Standard o Premium para admitir más sesiones simultáneas.
Service endpoint (punto de conexión de servicio)
Una configuración de subred que envía el tráfico a un servicio de Azure por la red troncal con la identidad de la subred, mientras el servicio conserva su IP pública.
Private endpoint (punto de conexión privado)
Una NIC con una IP privada en tu VNet que se conecta a un recurso específico mediante Private Link.
Private DNS zone (zona DNS privada)
Una zona de Azure DNS que solo se puede resolver desde las VNet vinculadas, usada para asignar nombres privatelink a IP privadas.
Service endpoint policy (directiva de punto de conexión de servicio)
Una directiva que restringe el tráfico del punto de conexión de servicio a cuentas específicas de Azure Storage.
DNS zone (zona DNS)
Un contenedor de los registros DNS de un dominio, hospedado por Azure DNS como público o privado.
Delegation (delegación)
Apuntar un dominio o subdominio a los servidores de nombres que hospedan su zona, usando registros NS en el registrador o en la zona primaria.
Record set (conjunto de registros)
Todos los registros DNS con el mismo nombre y tipo en una zona, que comparten un TTL.
Alias record (registro de alias)
Un conjunto de registros A, AAAA o CNAME que hace referencia a un recurso de Azure y se actualiza automáticamente cuando este cambia.
Auto-registration (registro automático)
Una opción del vínculo de una zona DNS privada que mantiene automáticamente registros A para las VM de la VNet vinculada.
Public load balancer (equilibrador de carga público)
Un equilibrador de carga con una IP de front-end pública que distribuye el tráfico de internet hacia las VM de back-end.
Internal load balancer (equilibrador de carga interno)
Un equilibrador de carga con una IP de front-end privada que distribuye el tráfico dentro de una VNet o de redes conectadas.
Health probe (sondeo de estado)
Una comprobación periódica TCP, HTTP o HTTPS que saca de la rotación las instancias de back-end en mal estado.
Load-balancing rule (regla de equilibrio de carga)
Una asignación de una IP y un puerto de front-end a un grupo y un puerto de back-end, con un sondeo y una configuración de persistencia de sesión.
Inbound NAT rule (regla NAT de entrada)
Una regla que reenvía un puerto de front-end específico hacia una VM y un puerto de back-end específicos.
IP flow verify
Una herramienta de Network Watcher que indica si un paquete específico se permite o se deniega y qué regla de NSG lo decidió.
Next hop (próximo salto)
Una herramienta de Network Watcher que muestra el tipo de próximo salto, la IP y la tabla de rutas para el tráfico de una VM hacia un destino.
Effective routes (rutas efectivas)
El conjunto completo de rutas del sistema, definidas por el usuario, BGP y de emparejamiento aplicadas a una interfaz de red.
Connection troubleshoot
Una herramienta de Network Watcher que prueba una conexión de extremo a extremo e informa sobre la accesibilidad, la latencia, los saltos y los problemas.

Dominio 5: Monitor and maintain Azure resources (14%)

Consejos para el examen

  • Las métricas y el registro de actividad son automáticos; los registros de recursos requieren una configuración de diagnóstico. Elige el destino según el propósito: área de trabajo para consultar y alertar, cuenta de almacenamiento para archivar a bajo costo, event hub para transmitir a herramientas externas.
  • Relaciona la pregunta con el operador: filtrar = where, agregar por grupo = summarize ... by, elegir columnas = project, gráfico = render. Los filtros de tiempo usan ago(), y las series temporales usan bin().
  • Umbrales de rendimiento = alerta de métricas; condición en KQL = alerta de búsqueda de registros; 'alguien eliminó', estado del servicio o estado de los recursos = alerta del registro de actividad. Para silenciar las notificaciones durante el mantenimiento sin deshabilitar las reglas, usa una regla de procesamiento de alertas.
  • AMA no recopila nada hasta que se asocia una regla de recopilación de datos con la máquina. La vista Map de VM insights necesita el Dependency agent. Storage insights usa métricas de plataforma y no necesita agente.
  • Connection Monitor es para supervisión continua con historial y alertas; connection troubleshoot es una prueba puntual. Los orígenes que son VM de Azure necesitan la extensión Network Watcher agent, y los resultados se almacenan en Log Analytics.
  • VM de Azure, Azure Files, SQL en VM, MARS y Site Recovery = almacén de Recovery Services. Discos administrados, blobs, PostgreSQL y AKS = almacén de Backup. Define la redundancia del almacenamiento antes de proteger el primer elemento.
  • Más de una copia de seguridad al día, VM con Trusted Launch o discos Premium SSD v2/Ultra necesitan la directiva mejorada. La restauración entre regiones requiere GRS más la configuración CRR. Las copias de seguridad en eliminación temporal se conservan 14 días de forma predeterminada.
  • ¿Necesitas algunos archivos? Script de File Recovery. ¿La VM existe pero los datos están mal? Replace existing. ¿Necesitas una configuración de VM personalizada o solo los discos? Restore disks. ¿Una VM nueva rápida? Create new. Las copias de seguridad de discos en un almacén de Backup se restauran como discos nuevos.
  • La conmutación por error de prueba usa una red aislada y no afecta a la replicación; límpiala siempre. Después de la conmutación por error, confirmas y luego vuelves a proteger antes de la conmutación por recuperación. El almacén debe estar en una región diferente de la de las VM de origen.
  • Los informes de copia de seguridad necesitan configuraciones de diagnóstico en los almacenes que envíen datos a un área de trabajo de Log Analytics; sin área de trabajo, no hay informes. Las alertas integradas de copia de seguridad no notifican a nadie hasta que conectas un grupo de acciones, normalmente mediante una regla de procesamiento de alertas.

Términos clave

Metrics (métricas)
Datos numéricos de series temporales muestreados a intervalos regulares, recopilados automáticamente para los recursos de Azure.
Logs (registros)
Entradas de eventos y observaciones con muchas propiedades, almacenadas en un área de trabajo de Log Analytics y consultadas con KQL.
Activity log (registro de actividad)
El registro a nivel de suscripción de las operaciones del plano de control y los eventos de estado del servicio.
Resource logs (registros de recursos)
Registros de las operaciones dentro de un recurso, recopilados solo cuando se configura una configuración de diagnóstico.
Diagnostic setting (configuración de diagnóstico)
Una configuración por recurso que envía los registros y métricas seleccionados a un área de trabajo, una cuenta de almacenamiento, un event hub o un socio.
KQL
Kusto Query Language, el lenguaje de consulta de solo lectura basado en canalizaciones que se usa en Log Analytics y Azure Monitor.
where
Un operador que filtra filas según una condición.
summarize
Un operador que agrega filas con funciones como count() o avg(), agrupadas por columnas.
project
Un operador que selecciona, cambia el nombre o reordena las columnas de salida.
bin()
Una función que redondea valores, normalmente marcas de tiempo, en intervalos de tamaño fijo para series temporales.
Metric alert (alerta de métricas)
Una regla de alerta que evalúa una métrica frente a un umbral estático o dinámico con una frecuencia regular.
Log search alert (alerta de búsqueda de registros)
Una regla de alerta que ejecuta una consulta KQL según una programación y se activa cuando los resultados cumplen una condición.
Activity log alert (alerta del registro de actividad)
Una regla de alerta que se activa con eventos administrativos, de estado del servicio o de estado de los recursos en el registro de actividad.
Action group (grupo de acciones)
Un conjunto reutilizable de notificaciones y acciones automatizadas que activan las alertas.
Alert processing rule (regla de procesamiento de alertas)
Una regla que suprime o agrega grupos de acciones a las alertas activadas que coinciden con un ámbito y filtros, opcionalmente según una programación.
VM insights
Una experiencia de Azure Monitor que muestra el rendimiento de las VM y, con el Dependency agent, mapas de procesos y conexiones.
Azure Monitor Agent (AMA)
El agente actual que recopila datos del SO invitado de las VM de Azure y de los servidores habilitados para Arc, configurado mediante reglas de recopilación de datos.
Data collection rule (DCR) (regla de recopilación de datos)
Un recurso que define qué datos recopilar, las transformaciones opcionales y los destinos.
DCR association (asociación de DCR)
El vínculo entre una regla de recopilación de datos y una máquina o recurso que indica al agente que aplique la regla.
Network Watcher
Un servicio regional de Azure que proporciona herramientas de supervisión, diagnóstico y registro de red para los recursos de las VNet.
Connection Monitor
Una característica de Network Watcher que prueba continuamente la conectividad y la latencia entre orígenes y destinos.
Test group (grupo de prueba)
Un componente de Connection Monitor que combina orígenes, destinos y configuraciones de prueba.
Flow logs (registros de flujo)
Registros del tráfico IP que pasa por los NSG o las redes virtuales, usados para auditoría y traffic analytics.
Packet capture (captura de paquetes)
Una herramienta de Network Watcher que registra los paquetes hacia y desde una VM para un análisis detallado.
Recovery Services vault (almacén de Recovery Services)
Un almacén que protege VM de Azure, SQL y SAP HANA en VM, Azure Files y datos locales mediante MARS o MABS, y que hospeda Site Recovery.
Backup vault (almacén de Backup)
Un tipo de almacén más reciente que protege orígenes de datos como discos administrados, blobs, Azure Database for PostgreSQL y AKS.
MARS agent (agente MARS)
El agente Microsoft Azure Recovery Services que hace copias de seguridad de archivos, carpetas y estado del sistema de máquinas Windows en un almacén de Recovery Services.
Backup storage redundancy (redundancia del almacenamiento de copias de seguridad)
La configuración LRS, ZRS o GRS del almacenamiento de un almacén, que debe elegirse antes de proteger elementos.
Backup policy (directiva de copia de seguridad)
Una programación y un conjunto de reglas de retención que se aplican a los elementos protegidos de un almacén.
Enhanced policy (directiva mejorada)
Un tipo de directiva de copia de seguridad de VM que admite varias copias de seguridad al día y es obligatorio para algunos tipos de VM, como Trusted Launch.
On-demand backup (copia de seguridad a petición)
Una copia de seguridad puntual fuera de la programación, conservada hasta la fecha que elijas.
Soft delete (eliminación temporal)
Conservación de los datos de copia de seguridad eliminados, 14 días de forma predeterminada, para que se puedan recuperar.
Cross-region restore (restauración entre regiones)
Restaurar a partir de datos de copia de seguridad replicados en la región secundaria emparejada, disponible en almacenes GRS con la característica habilitada.
Create new virtual machine
Un tipo de restauración que crea una VM nueva a partir de un punto de recuperación con una configuración básica.
Restore disks
Un tipo de restauración que crea discos administrados y una plantilla, lo que permite una VM personalizada o la recuperación de datos.
Replace existing
Un tipo de restauración que reemplaza los discos de una VM existente después de tomar una instantánea de sus discos actuales.
File recovery (recuperación de archivos)
Montar los discos de un punto de recuperación en una máquina con un script descargado para copiar archivos individuales.
Azure Site Recovery
Un servicio de recuperación ante desastres que replica continuamente las VM a una ubicación secundaria y orquesta la conmutación por error.
Test failover (conmutación por error de prueba)
Un simulacro de conmutación por error que crea VM en una red aislada sin afectar a la replicación ni a producción.
Commit (confirmar)
El paso que finaliza una conmutación por error y descarta los demás puntos de recuperación.
Re-protect (volver a proteger)
Invertir la replicación después de una conmutación por error para que las VM en ejecución se repliquen de vuelta a la región original.
Recovery plan (plan de recuperación)
Un agrupamiento ordenado de VM, con scripts opcionales, que se conmutan por error juntas.
Backup reports (informes de copia de seguridad)
Informes basados en libros de Azure Monitor sobre elementos de copia de seguridad, trabajos, uso, directivas y optimización, alimentados desde Log Analytics.
Resource-specific tables (tablas específicas de recursos)
Tablas dedicadas de Log Analytics, como AddonAzureBackupJobs, que usan las configuraciones de diagnóstico y los informes de copia de seguridad.
Built-in backup alerts (alertas integradas de copia de seguridad)
Alertas de Azure Monitor generadas automáticamente para fallos de trabajos de copia de seguridad y operaciones de seguridad críticas.
Business Continuity Center
La experiencia del portal para administrar y supervisar la copia de seguridad y la recuperación ante desastres entre almacenes, suscripciones y regiones.
