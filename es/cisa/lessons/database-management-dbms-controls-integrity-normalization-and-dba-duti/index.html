Gestión de bases de datos: controles del DBMS, integridad, normalización y funciones del DBA

Las bases de datos guardan los datos más valiosos de la organización, así que merecen atención especial de auditoría. Un sistema de gestión de bases de datos (DBMS) almacena los datos y controla el acceso a ellos, aplica reglas de integridad, gestiona el uso concurrente y apoya el respaldo y la recuperación.

Las bases de datos relacionales organizan los datos en tablas de filas y columnas vinculadas por claves. Una clave primaria identifica de forma única cada fila; una clave foránea apunta a una clave primaria en otra tabla. La integridad referencial asegura que una clave foránea siempre apunte a un registro real, por ejemplo que no haya pedidos de un cliente inexistente. La integridad de entidad asegura que cada fila tenga una clave primaria única y no nula. La normalización organiza las tablas para guardar cada hecho una sola vez, lo que reduce la redundancia y las anomalías de actualización; la desnormalización agrega redundancia a propósito para mejorar el rendimiento y debe controlarse para que las copias sigan siendo consistentes. Las transacciones siguen las propiedades ACID (atomicidad, consistencia, aislamiento y durabilidad) para que las actualizaciones sean de todo o nada y sobrevivan a las fallas.

El administrador de base de datos (DBA) tiene un acceso muy amplio: define estructuras, gestiona el rendimiento, los respaldos y la recuperación, y a menudo otorga accesos. Como los privilegios del DBA pueden evadir los controles de la aplicación, los controles compensatorios son esenciales: limitar el número de DBA, usar cuentas nominales individuales, registrar la actividad del DBA en un almacén que no pueda modificar, revisar esos registros de forma independiente y aplicar gestión de cambios a los cambios de esquema. Los cambios directos a datos de producción fuera de la aplicación deben ser raros, aprobados y registrados.

Otros controles incluyen el acceso mediante vistas o roles que muestran a los usuarios solo los datos que necesitan, el cifrado de campos sensibles, el monitoreo de actividad de la base de datos y respaldos probados que incluyan los registros de transacciones para recuperar a un punto en el tiempo.

Términos clave

Integridad referencial
Una regla que asegura que los valores de una clave foránea siempre coincidan con una clave primaria existente en la tabla relacionada.
Normalización
Estructurar una base de datos para que cada hecho se guarde una sola vez, reduciendo la redundancia y la inconsistencia.
ACID
Propiedades de las transacciones confiables: atomicidad, consistencia, aislamiento y durabilidad.
Monitoreo de actividad de la base de datos
Herramientas que registran y analizan el acceso y los cambios en la base de datos, sobre todo de usuarios privilegiados.
Ejemplo real

Una auditora descubre que tres DBA comparten una sola cuenta de administrador y que los registros de la base de datos se guardan donde los DBA pueden borrarlos. Recomienda cuentas nominales, enviar los registros al sistema del equipo de seguridad y una revisión mensual de los cambios directos a datos por alguien ajeno al equipo de DBA.

Consejo para el examen: Los DBA pueden evadir los controles de la aplicación. Las mejores respuestas implican registrar la actividad del DBA en un lugar protegido y que alguien independiente la revise.

Comprueba lo que sabes

¿Qué evita la integridad referencial?

Registros que apuntan a registros relacionados inexistentes, como pedidos de un cliente que no existe.

¿Por qué una cuenta de DBA compartida es un problema?

Las acciones no pueden atribuirse a una persona, lo que destruye la rendición de cuentas.
