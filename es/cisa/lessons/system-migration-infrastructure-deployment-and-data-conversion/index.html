Migración de sistemas, despliegue de infraestructura y conversión de datos

Pasar a un sistema nuevo normalmente implica mover datos y a menudo también infraestructura, por ejemplo de servidores locales a la nube. Las migraciones fallan cuando los datos se pierden, se alteran o se mapean mal, o cuando el nuevo entorno no se configura de forma segura.

La conversión de datos sigue una secuencia planificada: identificar los datos de origen y sus dueños, depurarlos, mapear los campos del formato anterior al nuevo, definir reglas de conversión, ejecutar conversiones de prueba, conciliar resultados, corregir excepciones y hacer la conversión final. La conciliación es el control clave. Los conteos de registros, los totales de control de montos y los totales hash de campos clave se comparan entre origen y destino, y se revisan en detalle muestras de registros. El dueño de los datos aprueba que los datos convertidos estén completos y sean exactos. Los datos y el sistema anteriores deben conservarse, en modo de solo lectura, hasta verificar el nuevo sistema y cumplir los requisitos de retención.

Los controles durante la conversión incluyen restringir quién puede ejecutar los programas de conversión, registrar todas las correcciones manuales, mantener una pista de auditoría de las ejecuciones y proteger los datos sensibles en tránsito y en las áreas intermedias. Los desarrolladores no deben cambiar directamente datos de producción para corregir errores.

El despliegue de infraestructura necesita sus propios controles: estándares de construcción aprobados y configuraciones endurecidas, infraestructura como código revisada igual que el código de aplicaciones, segmentación de red, respaldo y monitoreo configurados antes de salir a producción y capacidad dimensionada para la carga esperada. En migraciones a la nube, la organización debe entender el modelo de responsabilidad compartida y configurar correctamente identidades, cifrado y registros. El auditor revisa los planes de conversión y la evidencia de conciliación, las aprobaciones y la configuración de seguridad del nuevo entorno.

Términos clave

Conversión de datos
Transformar y mover datos del formato de un sistema anterior al de un sistema nuevo.
Mapeo de datos
Definir cómo corresponde cada campo del sistema de origen con los campos del sistema de destino.
Total de control
La suma de un campo numérico, como montos, usada para confirmar que todos los datos se procesaron o transfirieron.
Infraestructura como código
Definir y desplegar infraestructura mediante archivos de configuración con control de versiones en lugar de configurarla a mano.
Ejemplo real

Una cooperativa de crédito migra 200,000 cuentas de socios. Los conteos de registros coinciden, pero la suma de saldos difiere en $1,240. La investigación encuentra que las cuentas con saldo negativo se mapearon mal; se corrige el mapeo, se repite y concilia la prueba, y la directora de finanzas da su aprobación.

Consejo para el examen: La conciliación con conteos de registros, totales de control y totales hash, aprobada por el dueño de los datos, es el control clave de la conversión. Conserva los datos anteriores hasta verificar la conversión.

Comprueba lo que sabes

¿Quién debe aprobar los datos convertidos?

El dueño de los datos en el negocio, después de revisar los resultados de la conciliación.

¿Por qué conservar los datos anteriores después de la conversión?

Para poder verificar, corregir o revertir, y para cumplir los requisitos de retención.
