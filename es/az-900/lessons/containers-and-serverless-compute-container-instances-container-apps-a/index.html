Contenedores y cómputo serverless: Container Instances, Container Apps, AKS, Azure Functions y App Service

Un contenedor empaqueta una aplicación junto con todo lo que necesita para ejecutarse, como bibliotecas, runtime y configuración, pero comparte el kernel del sistema operativo del host en lugar de incluir un sistema operativo completo. Por eso los contenedores son más pequeños y arrancan más rápido que las máquinas virtuales (VM), y la misma imagen de contenedor se ejecuta igual en una laptop y en Azure. Docker es el formato y motor de contenedores más conocido, y las imágenes suelen almacenarse en un registro como Azure Container Registry. Mientras que una VM virtualiza el hardware, un contenedor virtualiza el sistema operativo. Azure ofrece varias formas de ejecutar contenedores, desde la más sencilla hasta la más controlable, además de opciones serverless y de alojamiento web, y el examen Microsoft Azure Fundamentals (AZ-900) te pide elegir la adecuada para un escenario.

Azure Container Instances (ACI) es la forma más rápida y sencilla de ejecutar un contenedor en Azure. Le das una imagen y la ejecuta, sin VM ni orquestación que administrar, y se te factura mientras el contenedor se ejecuta. Es adecuado para aplicaciones sencillas, automatización de tareas, trabajos de compilación y trabajo por lotes de corta duración. No ofrece el escalado avanzado, el descubrimiento de servicios ni las actualizaciones graduales de un orquestador.

az container create --resource-group rg-demo --name hello --image mcr.microsoft.com/azuredocs/aci-helloworld --ports 80 --ip-address Public

Azure Container Apps es una plataforma serverless para ejecutar aplicaciones en contenedores y microservicios. Se basa en Kubernetes pero te lo oculta, y agrega funciones como el escalado automático según el tráfico HTTP o los eventos (incluido el escalado a cero), la división del tráfico entre revisiones y el ingreso HTTPS administrado. Es un buen punto intermedio cuando quieres más que contenedores individuales pero no quieres operar Kubernetes. Azure Kubernetes Service (AKS) es un servicio de Kubernetes administrado. Kubernetes es un orquestador de código abierto que implementa, escala y repara grandes cantidades de contenedores en un clúster de máquinas. En AKS, Azure administra el plano de control de Kubernetes, y tú administras los nodos de trabajo, sus actualizaciones y tus cargas de trabajo. AKS da el mayor control y es adecuado para aplicaciones complejas de microservicios y equipos que ya conocen Kubernetes.

Azure Functions es cómputo serverless basado en eventos. Escribes una función pequeña, eliges un desencadenador, como una solicitud HTTP, un mensaje en una cola, un nuevo blob en el almacenamiento o un temporizador, y Azure la ejecuta cuando ocurre el evento. En el alojamiento basado en consumo escala automáticamente y pagas solo por las ejecuciones y los recursos que usan; otros planes mantienen instancias precalentadas para arranques más rápidos o se ejecutan en capacidad dedicada. Las funciones suelen ser sin estado, pero Durable Functions agrega estado para flujos de trabajo más largos. Azure App Service es una oferta de plataforma como servicio (PaaS) para alojar aplicaciones web, API REST y back ends móviles en muchos lenguajes, en Windows o Linux, y también puede ejecutar contenedores. Incluye balanceo de carga integrado, autoscale, ranuras de implementación (deployment slots) para probar una versión antes de intercambiarla a producción, dominios personalizados e integración con el control de código fuente. Elige App Service para aplicaciones web de larga ejecución, y Functions para fragmentos cortos de código que reaccionan a eventos.

Considera un ejemplo práctico. Una empresa de medios tiene cuatro necesidades. Un script nocturno que convierte archivos, empaquetado como contenedor, se ejecuta durante veinte minutos y se detiene: Azure Container Instances. Su sitio web público, creado en Node.js por un equipo pequeño que no quiere administrar servidores: App Service. Un nuevo conjunto de microservicios en contenedores que deben escalar a cero por la noche, pero el equipo no tiene expertos en Kubernetes: Container Apps. Un paso de redimensionamiento que debe ejecutarse cada vez que se sube una foto al almacenamiento y no costar nada cuando está inactivo: Azure Functions con un desencadenador de blob. Más adelante, un equipo de plataforma independiente con amplia experiencia en Kubernetes traslada una malla de servicios grande y compleja a AKS porque necesita control sobre los grupos de nodos y la red.

Errores comunes: pensar que los contenedores incluyen un sistema operativo completo como las VM; elegir AKS para un solo contenedor sencillo, lo que agrega complejidad innecesaria; suponer que AKS significa que Microsoft administra todo (tú sigues administrando los grupos de nodos y las cargas de trabajo); y elegir Functions para un sitio web siempre encendido. Otra trampa es olvidar que App Service también puede ejecutar contenedores, así que 'contenedor' en una pregunta no significa automáticamente ACI o AKS.

Las preguntas del examen usan palabras clave. 'Ejecutar un solo contenedor rápidamente sin orquestación' es Azure Container Instances. 'Orquestar muchos contenedores', 'Kubernetes' o 'control total sobre el clúster' es AKS. 'Contenedores serverless' o 'microservicios sin administrar Kubernetes' es Azure Container Apps. 'Ejecutar código cuando ocurre un evento, facturado por ejecución' es Azure Functions. 'Alojar una aplicación web o API sin administrar servidores', 'ranuras de implementación' es App Service. 'Ligero, arranca rápido, comparte el kernel del host' describe los contenedores en comparación con las VM.

Términos clave

Contenedor (container)
Un paquete ligero de una aplicación y sus dependencias que comparte el kernel del sistema operativo del host.
Azure Container Instances (ACI)
La forma más sencilla de ejecutar un solo contenedor en Azure, sin VM ni orquestador que administrar.
Azure Container Apps
Una plataforma serverless para aplicaciones en contenedores y microservicios que oculta Kubernetes y puede escalar a cero.
Azure Kubernetes Service (AKS)
Un servicio de Kubernetes administrado en el que Azure opera el plano de control y tú administras los nodos y las cargas de trabajo.
Orquestación (orchestration)
Implementación, escalado, red y reparación automatizados de muchos contenedores en un clúster.
Azure Functions
Cómputo serverless basado en eventos que ejecuta código con desencadenadores y factura por ejecución en los planes de consumo.
Ranura de implementación (deployment slot)
Una instancia de preproducción separada de una aplicación de App Service que se puede intercambiar a producción.
Ejemplo real

Una empresa de logística empaqueta su optimizador de rutas como un contenedor. El equipo de datos ejecuta experimentos puntuales en Azure Container Instances; el sistema de producción, formado por una docena de microservicios administrados por un equipo de plataforma experimentado, se ejecuta en AKS. El sitio web de rastreo para clientes se ejecuta en App Service con una ranura de preproducción, y una Azure Function disparada por mensajes de cola envía las notificaciones de entrega, con un costo casi nulo cuando no se mueven paquetes.

Consejo para el examen: Un solo contenedor, lo más sencillo: ACI. Microservicios sin administrar Kubernetes: Container Apps. Orquestar muchos contenedores con control total: AKS. Código ante eventos facturado por ejecución: Functions. Alojamiento de aplicaciones web sin administrar servidores: App Service.

Comprueba lo que sabes

¿Por qué los contenedores arrancan más rápido que las VM?

Comparten el kernel del sistema operativo del host en lugar de iniciar un sistema operativo completo, así que son más pequeños y ligeros.

¿Qué servicio deberías usar para ejecutar un solo contenedor rápidamente sin administrar servidores ni un orquestador?

Azure Container Instances, la opción de contenedores más sencilla de Azure.

En AKS, ¿qué administra Azure y qué administras tú?

Azure administra el plano de control de Kubernetes; tú administras los nodos de trabajo y tus cargas de trabajo.

Una función debe ejecutarse cada vez que se sube un archivo al almacenamiento. ¿Qué servicio encaja?

Azure Functions con un desencadenador de blob, que ejecuta el código con cada carga y factura por ejecución en un plan de consumo.
