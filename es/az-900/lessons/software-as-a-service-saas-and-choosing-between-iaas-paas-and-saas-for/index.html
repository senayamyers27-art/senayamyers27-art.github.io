Software como servicio (SaaS) y cómo elegir entre IaaS, PaaS y SaaS para un escenario

El software como servicio (SaaS) es una aplicación completa que el proveedor opera y entrega a través de internet, normalmente por una cuota de suscripción por usuario. Ejemplos conocidos son Microsoft 365 para el correo y las aplicaciones de oficina, Microsoft Teams, Dynamics 365 para la gestión de relaciones con clientes (CRM) y los procesos de negocio, y muchos productos de terceros que se usan desde un navegador. Usas el software a través de un navegador web o una aplicación cliente; no implementas servidores, no escribes la aplicación ni administras su plataforma.

SaaS es el tipo de servicio con la menor responsabilidad para el cliente. El proveedor administra la infraestructura, el sistema operativo, el runtime y la propia aplicación, incluidas las actualizaciones y las nuevas funciones. Tú sigues administrando lo que nunca deja de ser del cliente: tus datos, los dispositivos que se conectan y las cuentas e identidades de los usuarios. Eso incluye configurar opciones como quién puede compartir archivos fuera de la organización, cuánto tiempo se conservan los datos y si se exige autenticación multifactor. Muchas pérdidas de datos en SaaS no provienen del proveedor sino de la configuración del cliente, como una biblioteca de documentos compartida con 'cualquier persona que tenga el vínculo'.

El beneficio de SaaS es la rapidez y la sencillez: puedes empezar a usar una aplicación madura casi de inmediato, con precios por usuario predecibles, actualizaciones automáticas y sin mantenimiento. La contrapartida es el menor control. Puedes configurar la aplicación dentro de las opciones que ofrece, pero no puedes cambiar cómo está construida, elegir su sistema operativo ni decidir exactamente cuándo llegan las actualizaciones más allá de lo que el proveedor permite.

Elegir entre los tres tipos es un escenario común en el examen. Trabaja con dos preguntas: cuánto control necesita el escenario y quién debe hacer el trabajo operativo. Si necesitas control total del sistema operativo, debes instalar software personalizado o heredado, o debes mover servidores existentes tal como están, elige infraestructura como servicio (IaaS). Si los desarrolladores quieren crear e implementar su propia aplicación sin administrar servidores ni aplicar parches, elige plataforma como servicio (PaaS). Si el negocio simplemente necesita una aplicación terminada, como correo, un CRM o uso compartido de archivos, y no tiene razón para crear la suya, elige SaaS.

Ayuda alinear los tres por responsabilidad. En IaaS administras el sistema operativo, el runtime, las aplicaciones y los datos, y Microsoft administra las capas físicas. En PaaS administras las aplicaciones y los datos, y Microsoft también opera el sistema operativo y el runtime. En SaaS administras tus datos, dispositivos, cuentas y configuraciones, y Microsoft opera todo lo demás. Al pasar de IaaS a SaaS, la flexibilidad disminuye, y también la cantidad de trabajo y las habilidades especializadas que necesitas en tu propio equipo. Ninguno es el mejor en general; cada uno se ajusta a una necesidad distinta.

Considera un ejemplo práctico. Una empresa recibe tres solicitudes el mismo día. Primero, el equipo de ventas quiere un sistema CRM el mes siguiente; construir uno tomaría un año, así que la respuesta es un producto SaaS como Dynamics 365. Segundo, los desarrolladores quieren lanzar un nuevo portal de clientes escrito en .NET y no quieren aplicar parches a servidores, así que la respuesta es PaaS en App Service con Azure SQL Database. Tercero, el equipo de finanzas usa un paquete contable de hace 15 años que necesita una versión concreta de Windows Server y un emulador de llave de hardware instalado como administrador, y el datacenter va a cerrar; la respuesta es IaaS, realojándolo en VM de Azure. La misma empresa ahora usa los tres tipos, cada uno con una división distinta de la responsabilidad compartida.

Errores comunes: pensar que SaaS significa que el cliente no tiene deberes de seguridad; elegir IaaS 'para ir a lo seguro' cuando una opción PaaS o SaaS satisface la necesidad con mucho menos trabajo; y suponer que la elección es de todo o nada. Las organizaciones a menudo usan los tres a la vez, y los equipos de seguridad necesitan saber qué tipo usa cada carga de trabajo, porque la división de responsabilidades es distinta en cada uno. Una última trampa es confundir el tipo de servicio con el modelo de implementación: SaaS, PaaS e IaaS describen lo que alquilas, mientras que público, privado e híbrido describen dónde se ejecuta y quién lo comparte.

Las preguntas del examen suelen describir una necesidad y enumerar servicios. 'Aplicación lista para usar', 'suscripción por usuario', 'sin desarrollo ni administración de infraestructura' apunta a SaaS. 'Los desarrolladores implementan su propio código sin administrar servidores' apunta a PaaS. 'Control total del sistema operativo', 'software personalizado' o 'lift-and-shift' apunta a IaaS. Una pregunta sobre qué modelo requiere la mayor administración por parte del cliente espera IaaS, y la menor espera SaaS. Los datos y las identidades son del cliente en los tres.

Términos clave

Software como servicio (SaaS)
Una aplicación completa operada por el proveedor y usada a través de internet, normalmente por suscripción.
Microsoft 365
La suite SaaS de Microsoft de correo, aplicaciones de oficina, almacenamiento de archivos y herramientas de colaboración.
Gestión de relaciones con clientes (CRM)
Software para gestionar las interacciones con los clientes y los prospectos de venta.
Licenciamiento por usuario (per-user licensing)
Un modelo de precios en el que pagas una cuota recurrente por cada persona que usa la aplicación.
Tipo de servicio (service type)
La categoría de servicio en la nube, IaaS, PaaS o SaaS, que determina cómo se comparte la responsabilidad.
Responsabilidad de configuración (configuration responsibility)
El deber del cliente de configurar de forma segura las opciones de una aplicación SaaS, como las reglas de uso compartido y de inicio de sesión.
Ejemplo real

Un despacho de abogados necesita correo, calendarios y colaboración en documentos para 80 personas y no tiene desarrolladores de TI. Se suscribe a Microsoft 365, paga por usuario cada mes y es productivo en pocos días. Microsoft opera y actualiza el servicio. El contratista de TI del despacho sigue configurando la autenticación multifactor, bloquea el uso compartido externo de las carpetas de clientes y elimina las cuentas cuando el personal se va, porque las cuentas, los dispositivos y los datos siguen siendo responsabilidad del despacho en SaaS.

Consejo para el examen: Relaciona el escenario con el control necesario: control total del sistema operativo o lift-and-shift es IaaS, crear tu propia aplicación sin administrar servidores es PaaS, una aplicación lista para usar es SaaS. Los datos, los dispositivos y las identidades son del cliente en los tres.

Comprueba lo que sabes

Una empresa quiere correo para su personal sin implementar ni mantener nada. ¿Qué tipo de servicio encaja?

SaaS, como Microsoft 365, porque el proveedor opera toda la aplicación.

¿Qué tipo de servicio requiere la mayor administración por parte del cliente?

IaaS, porque el cliente administra el sistema operativo, el runtime, las aplicaciones y los datos.

En SaaS, ¿quién es responsable de decidir si los archivos pueden compartirse fuera de la organización?

El cliente, porque la configuración de la aplicación y la protección de sus datos y cuentas siguen siendo del cliente.

Los desarrolladores quieren implementar una API web personalizada sin aplicar parches a servidores. ¿Qué tipo de servicio encaja?

PaaS, por ejemplo Azure App Service, porque ejecuta su código mientras Microsoft administra el sistema operativo y el runtime.
