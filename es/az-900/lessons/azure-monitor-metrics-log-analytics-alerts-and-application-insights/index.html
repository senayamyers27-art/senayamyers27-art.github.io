Azure Monitor: métricas, Log Analytics, alertas y Application Insights

Azure Monitor es la plataforma para recopilar, analizar y actuar sobre los datos de monitoreo de tus recursos de Azure, tus máquinas on-premises y otras nubes. Reúne datos de las aplicaciones, los sistemas operativos, los recursos de Azure, las suscripciones y el tenant, para que puedas entender el rendimiento de tus sistemas, detectar problemas a tiempo y responder automáticamente. Es la herramienta que usas para vigilar tus propias cargas de trabajo, a diferencia de Service Health, que informa los problemas del propio Azure. Azure Monitor trabaja con dos tipos principales de datos. Las métricas son valores numéricos recopilados a intervalos regulares, como el porcentaje de CPU, la memoria disponible o las solicitudes por segundo. Son ligeras, casi en tiempo real e ideales para gráficas y alertas rápidas; muchos recursos de Azure envían métricas de plataforma automáticamente sin configuración, y las ves en Metrics explorer. Los registros (logs) son registros de eventos y datos con propiedades detalladas, como trazas de aplicaciones, contadores de rendimiento, eventos de seguridad o entradas del registro de actividad que muestran quién cambió qué en tu suscripción. Los registros se almacenan en un área de trabajo de Log Analytics, y los datos del interior del sistema operativo de una VM se recopilan instalando el Azure Monitor Agent y definiendo reglas de recopilación de datos. La mayoría de los recursos también pueden enviar sus registros de recursos detallados a un área de trabajo agregando una configuración de diagnóstico.

Log Analytics es la herramienta del portal de Azure para escribir y ejecutar consultas de registros sobre esos datos usando Kusto Query Language (KQL). Una consulta empieza con el nombre de una tabla y encadena los resultados mediante operadores que filtran, resumen y ordenan. Por ejemplo, una consulta puede contar los inicios de sesión fallidos por hora, encontrar qué VM tuvieron más errores o mostrar cuándo reportó cada máquina por última vez. Las consultas se pueden guardar, anclar a paneles, usar en workbooks (informes interactivos) o usar como base para alertas. Una consulta sencilla que muestra cuándo envió cada computadora conectada su último latido (heartbeat) se ve así:

Heartbeat
| where TimeGenerated > ago(1h)
| summarize LastSeen = max(TimeGenerated) by Computer

Las alertas de Azure Monitor te notifican de forma proactiva cuando algo en tus datos de monitoreo requiere atención. Una regla de alerta define el ámbito (qué recursos), la condición (un umbral de métrica como CPU por encima de 80% durante diez minutos, el resultado de una consulta de registros o un evento del registro de actividad como la eliminación de un recurso) y la gravedad. Cuando se dispara, ejecuta un grupo de acciones, que puede enviar correos, SMS o notificaciones push, llamar a un webhook, abrir un ticket de administración de servicios de TI o iniciar automatización como una Azure Function, una Logic App o un runbook. Los grupos de acciones son compartidos, así que el mismo grupo también lo usan las alertas de Service Health y de Cost Management.

Application Insights es una función de Azure Monitor para el monitoreo del rendimiento de aplicaciones (APM). Supervisa aplicaciones web en producción, ya se ejecuten en Azure, on-premises o en otra nube, una vez que agregas su SDK o habilitas la instrumentación automática. Da seguimiento a las tasas de solicitudes, los tiempos de respuesta y las tasas de error, las llamadas a dependencias como bases de datos y API, las excepciones con su seguimiento de pila, las vistas de página y las sesiones de usuario, y dibuja un mapa de la aplicación que muestra cómo se conectan los componentes. También puede ejecutar pruebas de disponibilidad que comprueban tu sitio a intervalos regulares desde ubicaciones de todo el mundo. Ayuda a los desarrolladores a encontrar la causa de las páginas lentas o de los errores en su código, algo que las métricas de infraestructura por sí solas no revelarían.

Considera un ejemplo práctico. La página de pago de una tienda en línea se vuelve lenta todas las tardes. Las métricas muestran que la CPU del servidor web está bien, así que el problema no es de capacidad. Application Insights revela que todas las solicitudes lentas llaman a una misma dependencia de API de pagos que tarda varios segundos en responder. El equipo agrega una alerta de métrica sobre el tiempo de respuesta y una alerta de registros con una consulta KQL sobre los pagos fallidos, ambas enviadas a un grupo de acciones que avisa al ingeniero de guardia.

Errores comunes: confundir las métricas (números muestreados en el tiempo) con los registros (registros detallados que se consultan con KQL); pensar que Azure Monitor solo vigila recursos de Azure (también puede supervisar máquinas on-premises y de otras nubes, por ejemplo mediante Azure Arc); usar Service Health para solucionar los errores de tu propia aplicación (eso es Azure Monitor y Application Insights); y olvidar que una regla de alerta necesita un grupo de acciones para notificar a alguien o ejecutar automatización.

Las preguntas del examen relacionan palabras clave con funciones. 'Valores numéricos recopilados a intervalos regulares' o 'casi en tiempo real' apunta a las métricas. 'Consultar registros', 'KQL' o 'área de trabajo' apunta a Log Analytics. 'Notificar cuando la CPU supere un umbral' apunta a las alertas, y 'enviar SMS, correo o disparar automatización' apunta a los grupos de acciones. 'Supervisar el rendimiento, las excepciones o las dependencias de una aplicación web' o 'APM' apunta a Application Insights. 'Quién eliminó un recurso' apunta al registro de actividad.

Términos clave

Azure Monitor
La plataforma para recopilar, analizar y actuar sobre la telemetría de Azure, on-premises y otras nubes.
Métricas (metrics)
Valores numéricos muestreados a intervalos regulares, ideales para gráficas y alertas rápidas.
Registros (logs)
Registros detallados de eventos con propiedades enriquecidas, almacenados en un área de trabajo de Log Analytics.
Log Analytics
La herramienta del portal para consultar datos de registros con Kusto Query Language (KQL).
Regla de alerta (alert rule)
Una definición del ámbito, la condición y la gravedad que dispara una alerta.
Grupo de acciones (action group)
Un conjunto reutilizable de notificaciones y acciones automatizadas que se ejecuta cuando se dispara una alerta.
Application Insights
Una función de Azure Monitor para el monitoreo del rendimiento de aplicaciones web en producción.
Registro de actividad (activity log)
Un registro a nivel de suscripción de las operaciones de administración, que muestra quién hizo qué y cuándo.
Ejemplo real

Las VM de una empresa de logística a veces se quedan sin espacio en disco durante la noche, lo que hace fallar un trabajo nocturno. El equipo instala el Azure Monitor Agent, envía los contadores de rendimiento a un área de trabajo de Log Analytics y crea una alerta de registros con una consulta KQL que se dispara cuando el espacio libre en disco baja de 10%. El grupo de acciones de la alerta envía un correo al equipo de operaciones e inicia un runbook que borra los archivos temporales, así que ahora el trabajo termina de forma confiable.

Consejo para el examen: Las métricas son números a lo largo del tiempo; los registros son datos detallados que se consultan con KQL en Log Analytics. Application Insights supervisa aplicaciones (solicitudes, excepciones, dependencias), no solo la infraestructura. Las alertas usan grupos de acciones para notificar o automatizar.

Comprueba lo que sabes

¿Qué tipo de datos de Azure Monitor es adecuado para una alerta casi en tiempo real sobre el porcentaje de CPU?

Las métricas, que son valores numéricos ligeros recopilados a intervalos regulares.

¿Qué lenguaje usas para consultar datos en Log Analytics?

Kusto Query Language (KQL).

Un desarrollador necesita ver qué dependencia hace lentas las solicitudes de una aplicación web. ¿Qué función ayuda?

Application Insights, que da seguimiento a las solicitudes, las dependencias y las excepciones.

¿Qué hace un grupo de acciones?

Define a quién se notifica y qué automatización se ejecuta, como correo, SMS, webhook o una Logic App, cuando se dispara una alerta.
