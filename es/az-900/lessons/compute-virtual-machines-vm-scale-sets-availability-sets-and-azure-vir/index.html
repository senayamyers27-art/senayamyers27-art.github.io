Microsoft Certified: Azure Fundamentals AZ-900

Cómputo: máquinas virtuales, VM scale sets, availability sets y Azure Virtual Desktop

Las máquinas virtuales (VM) de Azure son la opción de cómputo de infraestructura como servicio (IaaS). Una VM es una computadora virtualizada que ejecuta Windows o Linux sobre el hardware de Microsoft. Eliges una imagen (el sistema operativo, a veces con software preinstalado), un tamaño (el número de CPU virtuales y la cantidad de memoria), los discos y la red. Tienes control total del sistema operativo, así que las VM son adecuadas para migraciones lift-and-shift, software personalizado y pruebas y desarrollo. También te encargas de los parches y la configuración. Una VM en ejecución se factura por cómputo aunque esté inactiva; detenerla y desasignarla libera el hardware y detiene los cargos de cómputo, aunque sus discos se siguen facturando. El examen Microsoft Azure Fundamentals (AZ-900) espera que conozcas las VM y tres servicios relacionados: los scale sets, los availability sets y Azure Virtual Desktop.

Los virtual machine scale sets te permiten crear y administrar un grupo de VM idénticas con balanceo de carga. En lugar de construir cada VM a mano, defines la configuración una vez y el scale set crea las instancias. Los scale sets admiten autoscale, agregando VM cuando la demanda crece y quitándolas cuando baja, y pueden distribuir las instancias entre zonas de disponibilidad. Las actualizaciones se pueden implementar en las instancias por lotes. Se usan para cargas de trabajo grandes y sin estado, como front ends web, procesamiento por lotes y trabajos de cómputo intensivo. Crear uno es un solo comando:

az vmss create --resource-group rg-web --name web-vmss --image Ubuntu2204 --instance-count 3 --zones 1 2 3 --admin-username azureuser --generate-ssh-keys

Los availability sets (conjuntos de disponibilidad) son una forma más antigua de mantener disponible un grupo de VM dentro de un solo datacenter. Colocas dos o más VM que hacen el mismo trabajo en un availability set, y Azure las distribuye entre dominios de error y dominios de actualización. Un dominio de error es un grupo de hardware que comparte una fuente de energía y un conmutador de red, como un rack, así que una falla de hardware afecta solo a las VM de ese dominio de error. Un dominio de actualización es un grupo de VM que Azure puede reiniciar al mismo tiempo durante un mantenimiento planeado, de modo que no todas tus VM se reinician juntas. Los availability sets no cuestan nada adicional; pagas solo las VM. Protegen contra fallas de rack y de mantenimiento; las zonas de disponibilidad protegen contra una falla mayor, la pérdida de un datacenter completo, y para los diseños nuevos en general se prefieren las zonas cuando la región las admite.

Azure Virtual Desktop es un servicio de virtualización de escritorios y aplicaciones. Los usuarios se conectan desde casi cualquier dispositivo, Windows, macOS, iOS, Android o un navegador web, a un escritorio completo de Windows o a aplicaciones individuales que se ejecutan en Azure. Como el escritorio se ejecuta en la nube, los datos de la empresa no tienen que almacenarse en el dispositivo del usuario, y el acceso puede protegerse con Microsoft Entra ID y autenticación multifactor. Azure Virtual Desktop admite ediciones multisesión de Windows, en las que varios usuarios comparten una VM, lo que reduce el costo en comparación con una VM por persona. Se adapta a trabajadores remotos e híbridos, contratistas, centros de atención telefónica y personal que necesita un escritorio seguro desde dispositivos personales.

Considera un ejemplo práctico. Un minorista necesita cuatro cosas. Su servidor de informes de punto de venta ejecuta software personalizado de Windows, así que va en una VM estándar. Su tienda en línea tiene picos diarios pronunciados, así que el nivel web se ejecuta en un scale set en tres zonas con autoscale. Un par de servidores de aplicaciones heredados deben permanecer en un solo datacenter por razones de licenciamiento, así que comparten un availability set, lo que garantiza que una falla de rack o un reinicio por mantenimiento nunca tire ambos. Por último, el personal de temporada contratado para las fiestas usa sus propias laptops, así que el minorista les da Azure Virtual Desktop, y cuando termina un contrato, se retira su acceso sin que quede ningún dato de la empresa en la laptop.

Errores comunes: pensar que un scale set y un availability set son lo mismo; suponer que los availability sets protegen contra una interrupción de datacenter; creer que apagar una VM desde el sistema operativo detiene la facturación de cómputo (solo desasignarla lo hace); y tratar Azure Virtual Desktop como una forma de alojar servidores web en lugar de escritorios de usuario. Otra trampa es olvidar que los scale sets necesitan una aplicación que pueda ejecutarse como muchas copias idénticas.

La redacción del examen apunta a la respuesta correcta. 'Grupo de VM idénticas que escala automáticamente' es un VM scale set. 'Proteger las VM de una falla de rack o de hardware y del mantenimiento planeado dentro de un datacenter' es un availability set, usando dominios de error y de actualización. 'Proteger contra la falla de un datacenter' son las zonas de disponibilidad. 'Dar a los usuarios un escritorio Windows seguro desde cualquier dispositivo' o 'Windows multisesión' es Azure Virtual Desktop. 'Control total del sistema operativo' es una VM.

Términos clave

Máquina virtual (VM)
Un recurso de cómputo IaaS que ejecuta un sistema operativo Windows o Linux completo que tú administras.
Virtual machine scale set
Un conjunto de VM idénticas con balanceo de carga que puede escalar automáticamente y abarcar zonas.
Availability set (conjunto de disponibilidad)
Una agrupación de VM distribuidas entre dominios de error y de actualización para sobrevivir a fallas de hardware y mantenimiento en un datacenter.
Dominio de error (fault domain)
Un grupo de hardware que comparte energía y red, de modo que una sola falla de hardware afecta solo a ese grupo.
Dominio de actualización (update domain)
Un grupo de VM que pueden reiniciarse juntas durante un mantenimiento planeado.
Azure Virtual Desktop
Un servicio que entrega escritorios y aplicaciones de Windows que se ejecutan en Azure a usuarios en casi cualquier dispositivo.
Multisesión (multi-session)
Una edición de Windows que permite que varios usuarios compartan una VM en Azure Virtual Desktop.
Ejemplo real

Una firma contable contrata a 40 empleados temporales para la temporada de impuestos que trabajan desde sus propias laptops. En lugar de comprar y proteger 40 laptops de la empresa, implementa Azure Virtual Desktop con un grupo de hosts de Windows multisesión. El personal inicia sesión con autenticación multifactor y obtiene un escritorio completo con el software contable de la firma, mientras los archivos de los clientes permanecen en Azure y nunca llegan a los dispositivos personales. Después de la temporada, la firma retira su acceso y reduce el grupo de hosts.

Consejo para el examen: Los scale sets tratan de muchas VM idénticas y del autoscale; los availability sets distribuyen las VM entre dominios de error y de actualización dentro de un datacenter; las zonas protegen contra la pérdida de un datacenter; Azure Virtual Desktop entrega escritorios a los usuarios.

Comprueba lo que sabes

¿Cuál es la diferencia entre un dominio de error y un dominio de actualización?

Un dominio de error agrupa hardware que comparte energía y red, y protege contra fallas de hardware; un dominio de actualización agrupa VM que se reinician juntas durante el mantenimiento planeado.

¿Qué servicio usarías para ejecutar muchas VM web idénticas que escalan automáticamente?

Un virtual machine scale set, que crea instancias idénticas con balanceo de carga y admite autoscale.

¿Una VM detenida (no desasignada) sigue generando cargos de cómputo?

Sí, la facturación de cómputo se detiene solo cuando la VM se desasigna; los discos se facturan en ambos casos.

¿Por qué Azure Virtual Desktop es una buena opción para contratistas que usan dispositivos personales?

El escritorio y los datos permanecen en Azure, así que no se almacena nada sensible en el dispositivo, y el acceso se puede retirar de forma centralizada.
