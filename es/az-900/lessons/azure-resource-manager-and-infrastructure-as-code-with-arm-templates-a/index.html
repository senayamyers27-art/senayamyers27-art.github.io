Azure Resource Manager e infraestructura como código con plantillas ARM y Bicep

Azure Resource Manager (ARM) es el servicio de implementación y administración de Azure. Toda solicitud para crear, actualizar o eliminar un recurso, ya venga del portal, de Azure CLI, de Azure PowerShell, de las API REST o de un kit de desarrollo de software (SDK), pasa por Resource Manager. Autentica a quien llama con Microsoft Entra ID, comprueba la autorización con el control de acceso basado en roles (RBAC), evalúa Azure Policy y los bloqueos y luego envía la solicitud al servicio de Azure correspondiente, llamado proveedor de recursos, como Microsoft.Compute para las VM. Como todas las herramientas pasan por la misma capa, obtienes resultados consistentes y funciones consistentes como RBAC, etiquetas, bloqueos y directivas sin importar qué herramienta uses.

Resource Manager aporta varios beneficios. Puedes administrar tu infraestructura mediante plantillas declarativas en lugar de scripts. Puedes implementar, administrar y supervisar todos los recursos de una solución como un grupo, normalmente un grupo de recursos, en lugar de uno por uno. Puedes volver a implementar de forma consistente a lo largo del ciclo de desarrollo, desde desarrollo hasta pruebas y producción. Resource Manager maneja las dependencias, de modo que los recursos se crean en el orden correcto, como una red virtual antes de la VM que la usa, e implementa en paralelo los recursos independientes. También puedes aplicar etiquetas y control de acceso una sola vez a todo un grupo y ver el costo combinado. La infraestructura como código (IaC) significa describir la infraestructura que necesitas en archivos de código y luego usar esos archivos para crearla. En lugar de hacer clic en el portal, guardas las definiciones en un control de código fuente como Git, revisas los cambios como cualquier otro código e implementas el mismo entorno repetidamente con una canalización (pipeline). IaC reduce el error humano, documenta exactamente lo que existe y evita la desviación de configuración (configuration drift), en la que entornos que deberían ser idénticos se vuelven distintos poco a poco.

Las plantillas de Azure Resource Manager (plantillas ARM) son archivos JSON que definen los recursos que se implementarán. Son declarativas: indicas lo que quieres que exista, no los pasos para crearlo, y Resource Manager determina cómo llegar allí. Las implementaciones son idempotentes, lo que significa que puedes implementar la misma plantilla muchas veces y obtener el mismo resultado; los recursos que ya coinciden no se tocan. Las plantillas tienen secciones para parámetros (valores que se proporcionan al implementar, como el nombre del entorno), variables, recursos y salidas, de modo que una plantilla puede servir a muchos entornos, y las soluciones más grandes se pueden dividir en plantillas vinculadas o anidadas. Implementas con un comando como az deployment group create --resource-group rg-demo --template-file main.json.

Bicep es un lenguaje específico de dominio de Microsoft para implementar recursos de Azure de forma declarativa. Usa una sintaxis más sencilla y concisa que JSON, tiene mejor comprobación de tipos y soporte en los editores, y admite módulos para reutilizar código. Un archivo Bicep se transpila a una plantilla ARM JSON estándar antes de la implementación, así que puede hacer todo lo que hacen las plantillas ARM, y los nuevos tipos de recursos y versiones de API de Azure están disponibles en Bicep de inmediato. Lo implementas con el mismo comando, apuntando --template-file a main.bicep. Por ejemplo, una cuenta de almacenamiento puede declararse en pocas líneas:

resource sa 'Microsoft.Storage/storageAccounts@2023-01-01' = {
  name: 'stdemo${uniqueString(resourceGroup().id)}'
  location: resourceGroup().location
  sku: { name: 'Standard_LRS' }
  kind: 'StorageV2'
}

Considera un ejemplo práctico. Una empresa de software necesita entornos de desarrollo, pruebas y producción idénticos, cada uno con una red virtual, una aplicación web de App Service, una base de datos SQL y una cuenta de almacenamiento. En lugar de construir cada uno a mano, el equipo escribe un archivo Bicep con un parámetro para el nombre del entorno y los tamaños de SKU, lo guarda en Git y lo implementa desde una canalización. Cuando producción necesita un contenedor de almacenamiento adicional, el cambio se revisa en una pull request y se vuelve a implementar; como las implementaciones son idempotentes, solo se crea el nuevo contenedor. Una regla de firewall que faltaba en pruebas se corrige volviendo a implementar el archivo.

Errores comunes: pensar que el portal omite Resource Manager (no lo hace); confundir las plantillas declarativas con los scripts imperativos que enumeran pasos; creer que Bicep implementa mediante un motor diferente (se compila a ARM JSON); y suponer que volver a implementar una plantilla duplica los recursos (la idempotencia lo evita).

Las preguntas del examen usan algunas frases recurrentes. 'Servicio de implementación y administración de Azure' o 'capa de administración consistente' apunta a Azure Resource Manager. 'Implementar el mismo entorno de forma repetida y consistente' o 'definir la infraestructura en código' apunta a la infraestructura como código. 'Archivo JSON que define recursos de forma declarativa' apunta a una plantilla ARM. 'Sintaxis más sencilla que se compila a plantillas ARM' apunta a Bicep. 'Describir el estado final deseado, no los pasos' significa declarativo, y 'el mismo resultado cada vez que implementas' significa idempotente.

Términos clave

Azure Resource Manager (ARM)
La capa de implementación y administración que procesa cada solicitud para crear, cambiar o eliminar recursos de Azure.
Proveedor de recursos (resource provider)
Un servicio de Azure, como Microsoft.Compute, que ofrece un tipo de recurso a través de Resource Manager.
Infraestructura como código (IaC)
Definir e implementar la infraestructura a partir de archivos de código guardados en un control de código fuente.
Plantilla ARM (ARM template)
Un archivo JSON que define de forma declarativa los recursos de Azure que se implementarán.
Bicep
Un lenguaje conciso de Microsoft para implementaciones declarativas en Azure que se transpila a ARM JSON.
Declarativo (declarative)
Describir el estado final deseado y dejar que la plataforma determine los pasos.
Idempotente (idempotent)
Que produce el mismo resultado sin importar cuántas veces se ejecute una implementación.
Desviación de configuración (configuration drift)
Entornos que deberían coincidir y que se vuelven distintos poco a poco por cambios manuales.
Ejemplo real

Después de una prueba de recuperación ante desastres, una empresa descubre que reconstruir a mano su región secundaria tomó dos días y que se omitieron varias configuraciones. El equipo reescribe el entorno como módulos Bicep guardados en Git. En la siguiente prueba, una sola ejecución de la canalización implementa el entorno completo en la región secundaria en menos de una hora, idéntico a producción, y los archivos sirven además como documentación precisa de lo que existe.

Consejo para el examen: Todas las herramientas, incluido el portal, pasan por Azure Resource Manager. Las plantillas ARM son JSON y declarativas; Bicep es un lenguaje más sencillo que se compila a ARM JSON. Declarativo significa que describes el estado final; idempotente significa que volver a implementar da el mismo resultado.

Comprueba lo que sabes

¿Qué servicio procesa una solicitud de creación de VM hecha en el portal de Azure?

Azure Resource Manager, que maneja cada solicitud de creación, actualización y eliminación sin importar la herramienta.

¿Qué significa que las implementaciones de plantillas ARM sean idempotentes?

Que implementar la misma plantilla repetidamente produce el mismo resultado sin duplicar recursos.

¿Cómo se relaciona Bicep con las plantillas ARM?

Bicep es un lenguaje más sencillo que se transpila a plantillas ARM JSON antes de la implementación.

¿Cuál es el principal beneficio de la infraestructura como código?

Implementaciones consistentes, repetibles y revisables que reducen el error humano y la desviación de configuración.
