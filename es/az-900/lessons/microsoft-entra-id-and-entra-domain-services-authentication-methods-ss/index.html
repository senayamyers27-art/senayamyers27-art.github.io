Microsoft Certified: Azure Fundamentals AZ-900

Microsoft Entra ID y Entra Domain Services; métodos de autenticación: SSO, MFA y sin contraseña

Microsoft Entra ID, antes llamado Azure Active Directory (Azure AD), es el servicio de administración de identidades y acceso (IAM) de Microsoft basado en la nube. Almacena usuarios, grupos y aplicaciones, y gestiona el inicio de sesión en Azure, Microsoft 365 y miles de otras aplicaciones de software como servicio (SaaS). Cada organización obtiene su propio tenant de Entra, una instancia dedicada del directorio, y cada suscripción de Azure confía exactamente en un tenant para sus identidades. Entra ID proporciona autenticación, inicio de sesión único, administración de aplicaciones, registro de dispositivos y funciones de protección de identidades como la detección de inicios de sesión riesgosos. Como la identidad es el plano de control de la nube, a menudo se le llama el nuevo perímetro de seguridad.

Muchas organizaciones también ejecutan Active Directory Domain Services (AD DS) on-premises. Microsoft Entra Connect (o el más ligero Entra Cloud Sync) sincroniza usuarios y grupos del AD on-premises con Entra ID, de modo que las personas usan una sola identidad para ambos. Esto se llama identidad híbrida. Sin embargo, Entra ID no es simplemente AD DS en la nube: usa protocolos web como OAuth 2.0, OpenID Connect y Security Assertion Markup Language (SAML), y no ofrece Kerberos, NTLM, Lightweight Directory Access Protocol (LDAP), unidades organizativas ni Group Policy como lo hace un controlador de dominio.

Microsoft Entra Domain Services cubre ese hueco. Proporciona un dominio administrado con unión al dominio, Group Policy, LDAP y autenticación Kerberos o NTLM, sin que tengas que implementar, aplicar parches ni supervisar controladores de dominio; Microsoft opera dos controladores de dominio por ti. Permite que las aplicaciones antiguas que dependen de esos protocolos pasen a VM de Azure sin cambios. El dominio administrado se sincroniza en una sola dirección desde Entra ID, así que los usuarios inician sesión con las mismas credenciales, pero los cambios hechos en el dominio administrado no regresan. Lo creas en el portal buscando Microsoft Entra Domain Services y eligiendo un nombre de dominio y una red virtual.

La autenticación es demostrar quién eres; la autorización, que se ve más adelante con el control de acceso basado en roles, es decidir qué puedes hacer. Entra ID ofrece varias formas de hacer la autenticación más fuerte y más sencilla a la vez. El inicio de sesión único (SSO) permite que un usuario inicie sesión una vez y luego abra muchas aplicaciones sin volver a iniciar sesión. Significa menos contraseñas que recordar, menos reutilización de contraseñas, menos restablecimientos en la mesa de ayuda y un solo lugar para desactivar el acceso cuando alguien deja la empresa.

La autenticación multifactor (MFA) exige dos o más tipos de evidencia: algo que sabes (una contraseña o un PIN), algo que tienes (un teléfono o una llave de hardware) y algo que eres (una huella digital o el rostro). Así, una contraseña robada por sí sola no basta para iniciar sesión. La autenticación multifactor de Microsoft Entra puede usar una notificación push o un código en la aplicación Microsoft Authenticator, un token de hardware, o un mensaje de texto o una llamada de voz, aunque las opciones basadas en el teléfono son más débiles. Los valores predeterminados de seguridad (security defaults), disponibles gratis en todos los tenants, activan con un solo interruptor el registro de MFA y protecciones básicas. La autenticación sin contraseña (passwordless) va más allá y elimina la contraseña por completo, combinando algo que tienes con algo que eres o sabes. Las opciones incluyen Windows Hello for Business (biometría o un PIN ligado a un dispositivo), el inicio de sesión sin contraseña con la aplicación Microsoft Authenticator y las llaves de seguridad FIDO2 o passkeys. Los métodos sin contraseña son más cómodos y resisten el phishing mucho mejor, porque no hay contraseña que robar ni que escribir en una página falsa.

Considera un ejemplo práctico. Un fabricante sincroniza su AD on-premises con Entra ID mediante Entra Connect para que el personal use una sola cuenta para Microsoft 365 y las aplicaciones on-premises. Habilita SSO para que los empleados lleguen al portal de recursos humanos, al sistema de gastos y al portal de Azure después de un solo inicio de sesión. Exige MFA mediante la aplicación Authenticator y da a los ingenieros llaves FIDO2 para iniciar sesión sin contraseña. Una antigua aplicación de inventario que necesita LDAP y unión al dominio se traslada a una VM de Azure unida a un dominio administrado de Entra Domain Services, para que nadie tenga que mantener controladores de dominio en Azure.

Errores comunes: pensar que Entra ID admite Kerberos y Group Policy directamente (eso es Entra Domain Services o AD DS); confundir Entra Connect, que sincroniza identidades, con Entra Domain Services, que proporciona un dominio administrado; tratar SSO como un factor de seguridad (trata de comodidad y control central, no de una prueba adicional); y describir una contraseña más una pregunta de seguridad como MFA (ambas son algo que sabes, así que sigue siendo un solo factor).

La redacción del examen suele ser directa. 'Servicio de administración de identidades y acceso basado en la nube' es Entra ID. 'Unión al dominio, LDAP, Kerberos o Group Policy sin administrar controladores de dominio' es Entra Domain Services. 'Iniciar sesión una vez para acceder a muchas aplicaciones' es SSO. 'Exigir una segunda forma de verificación' es MFA. 'Eliminar las contraseñas' o 'resistente al phishing' apunta a métodos sin contraseña como Windows Hello for Business o las llaves FIDO2. 'Sincronizar usuarios on-premises con la nube' es Entra Connect.

Términos clave

Microsoft Entra ID
El servicio de identidades y administración de acceso en la nube de Microsoft, antes Azure Active Directory.
Tenant (inquilino)
Una instancia dedicada de Entra ID que representa a una organización.
Microsoft Entra Domain Services
Un dominio administrado que ofrece unión al dominio, Group Policy, LDAP y Kerberos sin administrar controladores de dominio.
Microsoft Entra Connect
Una herramienta que sincroniza identidades de Active Directory on-premises con Entra ID para la identidad híbrida.
Inicio de sesión único (SSO)
Iniciar sesión una vez para acceder a muchas aplicaciones sin volver a escribir las credenciales.
Autenticación multifactor (MFA)
Exigir dos o más tipos distintos de evidencia (lo que sabes, lo que tienes, lo que eres) para iniciar sesión.
Autenticación sin contraseña (passwordless)
Iniciar sesión sin contraseña, usando una credencial ligada a un dispositivo más biometría o un PIN.
Llave de seguridad FIDO2 (FIDO2 security key)
Una llave de hardware o passkey que usa criptografía de clave pública para un inicio de sesión resistente al phishing.
Ejemplo real

Un distrito escolar tiene miles de estudiantes y empleados que olvidaban constantemente sus contraseñas en una docena de aplicaciones educativas. Conecta esas aplicaciones a Entra ID para el inicio de sesión único, de modo que un solo inicio de sesión abre todo, y exige MFA con la aplicación Authenticator al personal que puede ver los expedientes de los estudiantes. Los restablecimientos de contraseña en la mesa de ayuda bajan mucho, y cuando un docente se va, desactivar una sola cuenta de Entra retira de una vez el acceso a todas las aplicaciones conectadas.

Consejo para el examen: Entra ID es el servicio de identidad en la nube que usa protocolos modernos. Entra Domain Services es para aplicaciones heredadas que necesitan unión al dominio, LDAP o Kerberos sin administrar controladores de dominio. MFA agrega un factor; sin contraseña elimina la contraseña; SSO reduce el número de inicios de sesión.

Comprueba lo que sabes

Una aplicación heredada necesita LDAP y Kerberos en Azure, y el equipo no quiere administrar controladores de dominio. ¿Qué deberían usar?

Microsoft Entra Domain Services, que proporciona un dominio administrado con esos protocolos.

Un usuario inicia sesión con una contraseña y luego aprueba un aviso en la aplicación Authenticator. ¿Qué es esto?

Autenticación multifactor: algo que sabes más algo que tienes.

¿Por qué la autenticación sin contraseña es más resistente al phishing que una contraseña?

No hay contraseña que robar ni que escribir en un sitio falso; el inicio de sesión depende de una credencial ligada a un dispositivo más biometría o un PIN.

¿Qué herramienta sincroniza los usuarios de Active Directory on-premises con Entra ID?

Microsoft Entra Connect (o Entra Cloud Sync), que crea una identidad híbrida.
