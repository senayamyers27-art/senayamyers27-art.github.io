Mover datos y migrar: AzCopy, Storage Explorer, Azure File Sync, Azure Migrate y Azure Data Box

Llevar datos y cargas de trabajo a Azure suele ser el primer proyecto real que una organización ejecuta en la nube. Azure ofrece distintas herramientas según cuántos datos haya, con qué frecuencia se mueven, si quieres una línea de comandos o una herramienta gráfica y si estás moviendo archivos o servidores completos. El examen te da un escenario breve y espera que elijas la herramienta adecuada, así que ayuda conocer la pista que apunta a cada una. AzCopy es una utilidad de línea de comandos para copiar blobs o archivos hacia o desde una cuenta de almacenamiento, y entre cuentas de almacenamiento. Se ejecuta en Windows, macOS y Linux, se puede automatizar con scripts para trabajos repetidos y se autentica con Microsoft Entra ID o con una firma de acceso compartido (SAS), una URL firmada que concede acceso limitado. azcopy copy realiza copias, mientras que azcopy sync sincroniza en una sola dirección, haciendo que el destino coincida con el origen. No mantiene dos ubicaciones en sincronización bidireccional continua. Por ejemplo:

azcopy login
azcopy copy "./logs" "<container URL>/logs" --recursive
azcopy sync "./reports" "<container URL>/reports"

Azure Storage Explorer es una aplicación de escritorio gratuita para Windows, macOS y Linux con una interfaz gráfica para administrar cuentas de almacenamiento. Puedes explorar contenedores y recursos compartidos, subir y descargar archivos, administrar directivas de acceso y cambiar propiedades haciendo clic en lugar de escribir comandos. Internamente usa AzCopy para las transferencias, así que obtienes la misma velocidad con una interfaz más amigable. Es adecuada para administradores y desarrolladores que mueven datos de vez en cuando o quieren inspeccionar el contenido de una cuenta.

Azure File Sync centraliza los recursos compartidos de archivos de una organización en Azure Files, conservando la flexibilidad y el rendimiento de un servidor de archivos Windows on-premises. Instalas el agente de File Sync en un Windows Server, lo registras en un Storage Sync Service en Azure y vinculas las carpetas locales a un recurso compartido de Azure Files. A partir de entonces, los cambios se sincronizan de forma continua y en ambas direcciones, y varios servidores, como los de las sucursales, pueden sincronizarse con el mismo recurso compartido. Con la organización en niveles en la nube (cloud tiering), los archivos de uso frecuente permanecen en caché en el servidor local mientras que los que se usan poco viven solo en Azure y se recuperan bajo demanda. Azure Migrate es otra cosa: es un centro para mover cargas de trabajo completas. Te ayuda a descubrir y evaluar servidores, bases de datos, aplicaciones web y escritorios virtuales on-premises, informa su preparación y el costo estimado en Azure, y luego los migra, con herramientas integradas de Microsoft y de socios como Azure Database Migration Service.

Azure Data Box es un servicio de transferencia física para grandes cantidades de datos cuando subirlos por la red tomaría demasiado tiempo, costaría demasiado o no es posible. Pides un dispositivo en el portal, Microsoft te envía un equipo de almacenamiento resistente y cifrado, copias tus datos en él localmente y lo devuelves, y Microsoft sube los datos a tu cuenta de almacenamiento. Hay varios productos Data Box para distintos volúmenes, desde discos hasta equipos grandes. Data Box también puede exportar datos fuera de Azure, por ejemplo para la recuperación ante desastres o para cumplir una regulación. Después de la carga, los discos del dispositivo se borran de forma segura conforme a los estándares de sanitización de medios. Es adecuado para migraciones masivas únicas y para sitios con conectividad limitada o nula.

Considera un ejemplo práctico. Un despacho de abogados tiene cinco sucursales, cada una con su propio servidor de archivos Windows, además de un archivo en la oficina central de varios cientos de terabytes y veinte VM on-premises. Quiere una copia central de los recursos compartidos de las sucursales manteniendo un acceso local rápido, así que usa Azure File Sync con cloud tiering. Subir el archivo por el enlace de internet de la oficina tomaría meses, así que pide Azure Data Box. Para las VM ejecuta Azure Migrate para evaluar su preparación y costo y luego migrarlas. Un desarrollador que necesita subir artefactos de compilación cada noche escribe un script de AzCopy, y la gerente de la oficina usa Storage Explorer para revisar lo que se subió.

Errores comunes: elegir AzCopy cuando el escenario necesita una sincronización bidireccional continua con un servidor on-premises (eso es File Sync); pensar que Storage Explorer es un motor de transferencia independiente (usa AzCopy); elegir Azure Migrate para un simple traslado masivo de datos sin servidores involucrados; y olvidar que existe Data Box cuando la red es el cuello de botella.

La redacción del examen delata la herramienta: 'línea de comandos' o 'script' apunta a AzCopy; 'interfaz gráfica' o 'aplicación de escritorio' apunta a Storage Explorer; 'mantener una caché local de archivos en un servidor de archivos Windows' o 'cloud tiering' apunta a Azure File Sync; 'descubrir, evaluar y migrar servidores' apunta a Azure Migrate; 'terabytes de datos con ancho de banda limitado' o 'transferencia sin conexión' apunta a Azure Data Box.

Términos clave

AzCopy
Una herramienta de línea de comandos para copiar datos hacia, desde y entre cuentas de almacenamiento de Azure, con sincronización unidireccional.
Azure Storage Explorer
Una aplicación de escritorio gráfica y gratuita para administrar cuentas de almacenamiento que usa AzCopy para las transferencias.
Azure File Sync
Un servicio que sincroniza servidores de archivos Windows con Azure Files y puede llevar los archivos poco usados a la nube.
Organización en niveles en la nube (cloud tiering)
Una función de File Sync que mantiene localmente los archivos de uso frecuente y guarda solo en Azure los que se usan poco.
Azure Migrate
Un centro para descubrir, evaluar y migrar servidores, bases de datos y aplicaciones on-premises a Azure.
Azure Data Box
Un servicio de dispositivos físicos para mover grandes volúmenes de datos hacia o desde Azure sin conexión.
Firma de acceso compartido (SAS)
Un token firmado que se agrega a una URL de almacenamiento y concede acceso limitado y con tiempo definido.
Ejemplo real

Un laboratorio de investigación tiene varios cientos de terabytes de datos de secuenciación genómica en arreglos locales y solo una conexión a internet modesta. Subirlos tomaría meses, así que pide Azure Data Box, copia los datos localmente y devuelve el dispositivo para que se carguen en Blob storage. A partir de entonces, los nuevos resultados diarios son pequeños, así que un trabajo programado de AzCopy sube cada noche la salida del día al mismo contenedor.

Consejo para el examen: Línea de comandos automatizable: AzCopy. Herramienta gráfica: Storage Explorer. Mantener servidores de archivos Windows on-premises sincronizados con la nube: Azure File Sync. Evaluar y migrar servidores: Azure Migrate. Demasiados datos para la red: Data Box.

Comprueba lo que sabes

Una organización quiere que los servidores de archivos de sus sucursales mantengan una caché local mientras la copia maestra vive en Azure. ¿Qué servicio encaja?

Azure File Sync, que sincroniza servidores de archivos Windows con Azure Files y admite cloud tiering.

¿Qué herramienta elegirías para evaluar si las VM on-premises están listas para Azure y estimar su costo?

Azure Migrate, el centro de descubrimiento, evaluación y migración.

¿azcopy sync mantiene dos ubicaciones sincronizadas en ambas direcciones?

No. Hace que el destino coincida con el origen en una sola dirección.

Una empresa debe mover un conjunto de datos muy grande desde un sitio con mala conectividad. ¿Qué servicio encaja?

Azure Data Box, que envía un dispositivo físico para que los datos se transfieran sin conexión.
