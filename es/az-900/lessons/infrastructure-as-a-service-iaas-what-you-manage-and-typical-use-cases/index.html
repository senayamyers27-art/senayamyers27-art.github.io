Infraestructura como servicio (IaaS): qué administras y casos de uso típicos como lift-and-shift

La infraestructura como servicio (IaaS) es el tipo de servicio en la nube que te da más control. El proveedor suministra los componentes físicos, el datacenter, los servidores físicos, el hardware de almacenamiento y la red física, y tú alquilas versiones virtuales de ellos. El servicio IaaS más conocido de Azure son las máquinas virtuales (VM), junto con las redes virtuales, los discos administrados y los balanceadores de carga. IaaS es lo más parecido en la nube a operar tu propia sala de servidores, sin ser dueño de la sala.

Según el modelo de responsabilidad compartida, IaaS te deja la mayor cantidad de trabajo entre los tipos de servicio en la nube. Microsoft mantiene el hardware funcionando, protege el datacenter físico y administra el hipervisor. Tú eliges y administras el sistema operativo, aplicas sus actualizaciones, instalas y configuras el middleware y los runtimes, implementas las aplicaciones, configuras los controles de red como las reglas de los grupos de seguridad de red, configuras las copias de seguridad y proteges tus datos e identidades. Puedes instalar casi cualquier software que quieras, igual que en tu propio servidor, y puedes iniciar sesión con Remote Desktop Protocol (RDP) o Secure Shell (SSH) como administrador. Crear una VM IaaS muestra de qué eres responsable: eliges la imagen, el tamaño, los discos, la red y las credenciales.

az group create --name rg-iaas --location eastus
az vm create --resource-group rg-iaas --name app01 --image Win2022Datacenter --size Standard_D2s_v5 --admin-username azureuser
az vm open-port --resource-group rg-iaas --name app01 --port 3389

Todo lo que viene después de ese comando, desde las actualizaciones de Windows hasta el antivirus y la instalación de la aplicación, depende de ti. Abrir el puerto 3389 a internet, como en la última línea, es exactamente el tipo de decisión sobre controles de red que sigue siendo del cliente, y una implementación real lo restringiría a direcciones conocidas o usaría Azure Bastion, que ofrece acceso RDP y SSH desde el navegador sin exponer el puerto en absoluto. Ayuda comparar IaaS con el siguiente tipo de servicio. En PaaS no podrías elegir la imagen de Windows Server, iniciar sesión como administrador ni instalar un controlador personalizado, pero tampoco aplicarías parches a nada por debajo de tu aplicación. IaaS cambia comodidad por control, y esa es la distinción que le importa al examen. IaaS también se factura según el consumo: pagas la VM mientras está asignada, sus discos mientras existen y los datos salientes, así que apagar y desasignar las VM que no se usan forma parte de operar bien IaaS.

El escenario IaaS más común es la migración lift-and-shift, también llamada rehosting (realojamiento). Una organización toma servidores existentes de su datacenter y los recrea como VM de Azure con cambios mínimos. Esto es rápido, porque no hace falta rediseñar la aplicación, y permite a la empresa cerrar un datacenter o evitar reemplazar hardware envejecido. Más adelante puede modernizar partes de la aplicación para que usen servicios PaaS. Otros usos típicos de IaaS incluyen las pruebas y el desarrollo, donde los equipos crean y eliminan entornos rápidamente; las aplicaciones que necesitan una versión específica del sistema operativo, una configuración o software heredado que ningún servicio PaaS admite; las cargas de trabajo que necesitan control a nivel de administrador; y la computación de alto rendimiento, donde quieres un control fino sobre el hardware virtual.

Considera un ejemplo práctico. Una empresa de logística ejecuta una aplicación de planificación de rutas en Windows Server con un componente de terceros que debe instalarse con derechos de administrador y una configuración específica del registro. El arrendamiento de su datacenter termina en seis meses. Reescribir la aplicación para PaaS tomaría un año, así que el equipo usa Azure Migrate para evaluar los servidores y realojarlos como VM de Azure. El cambio toma un fin de semana. Después, el equipo programa los parches del sistema operativo con Azure Update Manager, configura Azure Backup y endurece las reglas de los grupos de seguridad de red, porque esas siguen siendo sus responsabilidades en IaaS.

Errores comunes: suponer que Microsoft aplica parches al sistema operativo invitado de una VM IaaS; elegir IaaS para una nueva aplicación web que no tiene necesidades especiales de sistema operativo, cuando PaaS eliminaría la mayor parte del trabajo operativo; y olvidar que una VM en ejecución se factura aunque esté inactiva. Otro es tratar el lift-and-shift como el estado final; a menudo es el primer paso antes de modernizar.

La redacción del examen delata la respuesta: 'máximo control', 'control total del sistema operativo', 'instalar software personalizado', 'aplicación heredada' o 'migrar servidores sin cambios de código' apunta a IaaS, normalmente Azure Virtual Machines. 'Los desarrolladores solo quieren implementar código' se aleja de IaaS y apunta a PaaS. Una pregunta sobre quién es responsable del servidor físico que aloja una VM espera la respuesta Microsoft, mientras que una que pregunta quién instala las actualizaciones de seguridad dentro de la VM espera al cliente.

Términos clave

Infraestructura como servicio (IaaS)
Un tipo de servicio en el que alquilas cómputo, almacenamiento y redes virtuales y administras el sistema operativo y todo lo que está por encima.
Máquina virtual (VM)
Una computadora basada en software que ejecuta un sistema operativo sobre hardware físico compartido.
Lift-and-shift (rehost)
Mover servidores existentes a VM en la nube con pocos o ningún cambio en la aplicación.
Imagen (image)
Una plantilla que contiene un sistema operativo, y a veces software, usada para crear una VM.
Tamaño de VM (VM size)
La combinación de CPU virtuales, memoria y otra capacidad asignada a una VM.
Azure Migrate
Un servicio que descubre y evalúa servidores on-premises y ayuda a moverlos a Azure.
Ejemplo real

Una firma de ingeniería tiene un antiguo sistema de gestión documental que solo funciona en una versión específica de Windows Server con un controlador personalizado. Su hardware está fallando. La firma crea VM de Azure equivalentes, copia los servidores con Azure Migrate y cambia a los usuarios en un fin de semana. Los administradores de la firma siguen aplicando parches a Windows, ejecutando el antivirus y administrando las copias de seguridad en las VM, porque en IaaS esas tareas siguen siendo suyas.

Consejo para el examen: Si un escenario enfatiza el máximo control, una configuración de sistema operativo personalizada o heredada, o mover servidores sin cambiarlos, la respuesta es IaaS. En IaaS, aplicar parches al sistema operativo invitado siempre es trabajo del cliente.

Comprueba lo que sabes

¿Quién administra el sistema operativo de una VM de Azure?

El cliente, porque IaaS deja el sistema operativo y todo lo que está por encima al cliente.

¿Qué es la migración lift-and-shift y qué tipo de servicio usa?

Mover servidores existentes a la nube con cambios mínimos, lo que usa máquinas virtuales IaaS.

¿Por qué un equipo podría elegir PaaS en lugar de IaaS para una nueva aplicación web?

PaaS elimina los parches del sistema operativo y la administración de servidores, así que el equipo puede concentrarse en el código y gastar menos en operaciones.

Menciona dos responsabilidades del cliente que se mantienen en IaaS.

Dos cualesquiera de: aplicar parches al sistema operativo invitado, instalar y actualizar aplicaciones, configurar reglas de seguridad de red, las copias de seguridad y proteger los datos y las identidades.
