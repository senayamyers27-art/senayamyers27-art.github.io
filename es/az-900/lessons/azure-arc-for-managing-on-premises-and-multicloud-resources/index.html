Azure Arc para administrar recursos on-premises y multicloud

La mayoría de las organizaciones no ejecutan todo en Azure. Tienen servidores en sus propios datacenters, en sucursales y en ubicaciones perimetrales (edge) como fábricas o tiendas, y a veces cargas de trabajo en otras nubes públicas. Administrar cada entorno con herramientas separadas hace difícil aplicar una seguridad, un cumplimiento y un monitoreo consistentes, y deja huecos que nadie nota. Azure Arc extiende la administración y la gobernanza de Azure a los recursos que están fuera de Azure, para que puedas usar las mismas herramientas y reglas en todas partes.

Azure Arc funciona proyectando los recursos que no son de Azure en Azure Resource Manager. Para un servidor, instalas el agente ligero Azure Connected Machine, normalmente generando un script de incorporación en el portal en Azure Arc, luego Machines, luego Add; para un clúster de Kubernetes, lo conectas con un comando como az connectedk8s connect --name my-cluster --resource-group rg-arc. Entonces el recurso aparece en el portal de Azure como un recurso de Azure con su propio ID de recurso, ubicado en una suscripción y un grupo de recursos como cualquier otro. La carga de trabajo en sí sigue ejecutándose exactamente donde está; Arc no la migra, no la copia ni cambia dónde viven sus datos.

Una vez que un recurso está habilitado para Arc, puedes administrarlo con las herramientas conocidas de Azure. Puedes organizarlo con grupos de recursos y etiquetas, controlar quién puede administrarlo con el control de acceso basado en roles de Azure (RBAC), aplicar y auditar Azure Policy (incluidas las configuraciones de invitado dentro del sistema operativo), supervisarlo con Azure Monitor, protegerlo con Microsoft Defender for Cloud y mantenerlo actualizado con Azure Update Manager. Esto te da un panel único (single pane of glass) para los entornos on-premises, perimetrales y multicloud, con un solo inventario y un solo conjunto de informes de cumplimiento.

Azure Arc puede administrar varios tipos de recursos. Los servidores habilitados para Arc abarcan servidores Windows y Linux físicos y virtuales que se ejecutan fuera de Azure, ya sea en tu datacenter o en otra nube. Kubernetes habilitado para Arc abarca clústeres de Kubernetes alojados en cualquier lugar, y te permite implementarles configuraciones desde repositorios Git. SQL Server habilitado para Arc extiende la administración de Azure a las instancias de SQL Server fuera de Azure, y los servicios de datos habilitados para Arc te permiten ejecutar algunos servicios de datos de Azure, como Azure SQL Managed Instance, en tu propia infraestructura. Arc también puede conectar plataformas de virtualización como VMware vSphere y System Center Virtual Machine Manager (SCVMM) para que sus VM se puedan administrar e incluso crear desde Azure.

Arc encaja de forma natural con los modelos de nube de las lecciones anteriores: es la respuesta de Microsoft para administrar de forma consistente los entornos híbridos y multicloud. Es importante separarlo de los servicios que mueven cargas de trabajo. Azure Migrate mueve servidores a Azure; Azure Arc los deja donde están y los administra. Azure Arc también se diferencia de los productos Azure Stack, que llevan la infraestructura y los servicios de Azure a ejecutarse en hardware en tu propia ubicación, mientras que Arc lleva el plano de administración de Azure a la infraestructura que ya tienes.

Considera un ejemplo práctico. Una cadena minorista tiene doscientos servidores Linux en sus tiendas, un conjunto de servidores Windows en su propio datacenter y un clúster de Kubernetes en otro proveedor de nube. Los auditores quieren pruebas de que todos los servidores tienen una configuración de seguridad específica y los parches al día. El equipo incorpora los servidores con el agente Connected Machine y conecta el clúster con Kubernetes habilitado para Arc. Luego asigna una iniciativa de Azure Policy al grupo de recursos que contiene los recursos de Arc, ve el cumplimiento en un solo panel, habilita Defender for Cloud en todos ellos y programa las actualizaciones con Azure Update Manager. Ninguna de las cargas de trabajo se movió.

Errores comunes: pensar que Azure Arc migra servidores a Azure (eso es Azure Migrate); creer que los recursos de Arc deben ejecutarse en hardware de Azure (se ejecutan en cualquier lugar, incluidas otras nubes); suponer que Arc solo funciona con Windows (admite servidores Windows y Linux y Kubernetes); y confundir Arc con una VPN o una conexión de red (Arc trata de administración y gobernanza; el agente necesita conectividad saliente hacia Azure, no un enlace de red site-to-site).

Las preguntas del examen suelen incluir una pista de ubicación. 'Administrar servidores on-premises desde el portal de Azure', 'aplicar Azure Policy a servidores en otra nube', 'panel único para entornos híbridos y multicloud' o 'gobernar clústeres de Kubernetes que se ejecutan en cualquier lugar' apunta a Azure Arc. Si el escenario dice 'mover', 'migrar' o 'evaluar para la migración', la respuesta es en cambio Azure Migrate. Si dice 'ejecutar servicios de Azure en hardware de nuestro propio datacenter', piensa en Azure Stack o en los servicios de datos habilitados para Arc según la redacción.

Términos clave

Azure Arc
Un servicio que extiende la administración y la gobernanza de Azure a los recursos que se ejecutan fuera de Azure.
Servidores habilitados para Arc (Arc-enabled servers)
Máquinas Windows o Linux fuera de Azure que se proyectan en Azure Resource Manager para administrarlas.
Agente Connected Machine (Connected Machine agent)
El agente ligero que se instala en un servidor para conectarlo a Azure Arc.
Kubernetes habilitado para Arc (Arc-enabled Kubernetes)
Clústeres de Kubernetes que se ejecutan en cualquier lugar y están conectados a Azure para su administración y configuración.
Nube híbrida (hybrid cloud)
Un entorno que combina infraestructura on-premises con servicios de nube pública.
Multicloud
Usar servicios de más de un proveedor de nube pública.
Panel único (single pane of glass)
Una sola consola y un solo conjunto de herramientas para administrar recursos en muchos entornos.
Ejemplo real

Un banco debe mantener algunos servidores on-premises por razones regulatorias, pero quiere la misma línea base de seguridad que en sus VM de Azure. Incorpora esos servidores a Azure Arc, asigna la misma iniciativa de Azure Policy que usa para las VM de Azure y habilita Defender for Cloud. El equipo de seguridad ahora ve los servidores on-premises y los de Azure lado a lado en un solo informe de cumplimiento, mientras que los servidores nunca salen del datacenter del banco.

Consejo para el examen: Arc administra los recursos donde están; no los mueve. Si el escenario dice 'aplicar Azure Policy a servidores on-premises o de otra nube' o 'administrar entornos híbridos y multicloud desde un solo lugar', la respuesta es Azure Arc. Mover cargas de trabajo a Azure es Azure Migrate.

Comprueba lo que sabes

Una empresa quiere usar Azure Policy en servidores que se ejecutan en otra nube pública. ¿Qué servicio lo permite?

Azure Arc, que proyecta esos servidores en Azure Resource Manager para que se pueda aplicar Azure Policy.

¿Incorporar un servidor a Azure Arc lo migra a Azure?

No. El servidor sigue ejecutándose donde está; Arc solo agrega la administración y la gobernanza de Azure.

¿Qué debe instalarse en un servidor on-premises para conectarlo a Azure Arc?

El agente Azure Connected Machine.

Menciona dos servicios de Azure que puedes usar en un servidor habilitado para Arc.

Dos cualesquiera de Azure Policy, RBAC, etiquetas, Azure Monitor, Microsoft Defender for Cloud y Azure Update Manager.
