Microsoft Certified: Azure Fundamentals AZ-900

Beneficios de seguridad, gobernanza y administración de la nube (administración de la nube frente a en la nube)

Pasar a la nube puede fortalecer la seguridad y la gobernanza, no solo reducir costos. Microsoft invierte mucho en la seguridad física de sus datacenters, en proteger su red contra ataques como las inundaciones de denegación de servicio distribuida (DDoS) a gran escala y en mantener actualizada la plataforma subyacente. Según el tipo de servicio, también puedes delegar a Microsoft la aplicación de parches del sistema operativo, lo que elimina una fuente común de vulnerabilidades. Tú sigues decidiendo quién tiene acceso y cómo se protegen tus datos, como indica el modelo de responsabilidad compartida. El examen Microsoft Azure Fundamentals (AZ-900) agrupa estos beneficios como seguridad, gobernanza y administración. En cuanto a la seguridad, la nube te permite elegir cuánto administrar. Con IaaS conservas el máximo control y puedes instalar cualquier software de seguridad que quieras; con PaaS y SaaS, Microsoft se encarga de más parches y mantenimiento por ti. Azure también ofrece servicios integrados que de otro modo tendrías que comprar y operar, como Azure DDoS Protection, Microsoft Defender for Cloud para la postura de seguridad y la protección contra amenazas, y Azure Key Vault para almacenar secretos y claves.

Gobernanza significa establecer reglas y asegurarse de que los recursos las sigan, por ejemplo permitir recursos solo en regiones aprobadas, exigir ciertas etiquetas o limitar los tamaños de VM. En Azure puedes implementar plantillas que ya cumplen los estándares corporativos, auditar y aplicar reglas con Azure Policy, evitar eliminaciones accidentales con bloqueos de recursos y ver informes de cumplimiento de todas las suscripciones. Como estos controles se aplican de forma centralizada y se heredan hacia abajo en la jerarquía, es más fácil mantener consistentes cientos de recursos de lo que sería con revisiones manuales de servidores físicos. Microsoft también publica informes de auditoría y certificaciones de sus servicios a través del Service Trust Portal, para que puedas ver qué estándares cumple la plataforma.

La administración se divide en dos ideas que el examen nombra directamente. La administración de la nube (management of the cloud) significa administrar tus recursos de nube: escalarlos automáticamente, implementarlos desde plantillas, supervisar su estado y reemplazar automáticamente los recursos que fallan, y recibir alertas basadas en métricas configuradas para conocer los problemas en tiempo real. Trata de lo que la nube te permite hacer con tus recursos. On-premises, agregar un servidor a una granja web significaba pedir hardware y configurarlo a mano; en Azure, un scale set agrega una instancia idéntica desde una plantilla en minutos, y Azure Monitor puede generar una alerta o disparar una acción cuando una métrica como la CPU o el tiempo de respuesta cruza un umbral que tú defines.

La administración en la nube (management in the cloud) significa las formas en que interactúas con tu entorno y lo administras: mediante el portal web de Azure, una interfaz de línea de comandos (CLI) como Azure CLI o Azure PowerShell, interfaces de programación de aplicaciones (API) y Azure Cloud Shell en el navegador. Trata de las herramientas e interfaces que usas para llegar a tus recursos. Por ejemplo, las tres opciones siguientes crean el mismo grupo de recursos:

# Azure CLI
az group create --name rg-demo --location westeurope
# Azure PowerShell
New-AzResourceGroup -Name rg-demo -Location westeurope
# Portal: Resource groups > Create > name and region > Review + create

Considera un ejemplo práctico. Una auditoría de una empresa encontró servidores en países no aprobados y decenas de recursos sin etiquetas de los que nadie podía dar cuenta. Después de pasar a Azure, asigna una directiva en la parte superior de su jerarquía que permite solo dos regiones europeas y exige una etiqueta costCenter, y agrega un bloqueo contra eliminación a las bases de datos de producción. Los administradores construyen los entornos a partir de plantillas aprobadas, y el autoscale junto con las alertas de monitoreo mantienen en buen estado el nivel web. Los ingenieros usan el portal para revisiones puntuales y scripts de Azure CLI para las tareas repetibles. La siguiente auditoría muestra todos los recursos en cumplimiento, con informes generados desde Azure Policy en lugar de hojas de cálculo.

Errores comunes: suponer que Microsoft se vuelve responsable de tu control de acceso en la nube; confundir la gobernanza (reglas y cumplimiento) con las herramientas de seguridad; y clasificar ejemplos en la categoría de 'administración' equivocada. Otra trampa es pensar que la gobernanza solo restringe a las personas; las directivas bien elegidas también aceleran a los equipos, porque las plantillas aprobadas eliminan las conjeturas.

Las preguntas del examen suelen enumerar ejemplos y preguntar a qué categoría pertenecen. El autoscale, las plantillas, el monitoreo, las alertas y la autorreparación son administración de la nube. El portal, Azure CLI, Azure PowerShell, Cloud Shell y las API son administración en la nube. 'Garantizar que los recursos solo se creen en regiones aprobadas' es gobernanza, normalmente mediante Azure Policy. 'Microsoft aplica los parches del sistema operativo por ti' es un beneficio de seguridad de PaaS y SaaS.

Términos clave

Gobernanza (governance)
Establecer reglas sobre cómo se pueden crear y usar los recursos, y comprobar que las cumplan.
Azure Policy
Un servicio que evalúa los recursos contra reglas y puede auditar o bloquear los que no cumplen.
Bloqueo de recursos (resource lock)
Una configuración que impide que un recurso se elimine o modifique por accidente.
Administración de la nube (management of the cloud)
Administrar los propios recursos de nube, por ejemplo con autoscale, plantillas, monitoreo y alertas.
Administración en la nube (management in the cloud)
Las herramientas que se usan para llegar al entorno y administrarlo, como el portal, la CLI, PowerShell y las API.
Denegación de servicio distribuida (DDoS)
Un ataque que inunda un servicio con tráfico desde muchas fuentes para dejarlo no disponible.
Azure Cloud Shell
Un shell basado en el navegador con Azure CLI y Azure PowerShell ya instalados y con la sesión iniciada.
Ejemplo real

Un grupo hospitalario que adopta Azure se preocupa por la consistencia entre decenas de equipos. Usa Azure Policy para exigir configuraciones de cifrado y regiones aprobadas, bloquea sus bases de datos de producción contra eliminación y construye los nuevos entornos solo a partir de plantillas aprobadas. Los administradores gestionan los recursos mediante el portal y scripts de Azure CLI, mientras el autoscale y las alertas vigilan el portal de pacientes. Los auditores revisan los informes de cumplimiento publicados por Microsoft para la plataforma y el panel de cumplimiento de directivas del propio hospital.

Consejo para el examen: Una función que actúa sobre los recursos (autoscale, plantillas, monitoreo, alertas) es administración de la nube. Una forma de acceder a Azure (portal, CLI, PowerShell, Cloud Shell, API) es administración en la nube.

Comprueba lo que sabes

¿Usar Azure CLI para implementar una VM es un ejemplo de administración de la nube o de administración en la nube?

Administración en la nube, porque la CLI es una herramienta para interactuar con el entorno y administrarlo.

¿Configurar autoscale para una aplicación web es administración de la nube o en la nube?

Administración de la nube, porque es una capacidad que actúa sobre los propios recursos.

¿Qué servicio de Azure aplica reglas como regiones permitidas o etiquetas obligatorias?

Azure Policy, que audita o deniega los recursos que no cumplen.
