Conectividad híbrida: VPN Gateway (site-to-site, point-to-site) frente a ExpressRoute

Muchas organizaciones necesitan que sus redes on-premises y sus redes virtuales (VNet) de Azure funcionen como una sola, por ejemplo para que los usuarios de la oficina puedan llegar a una aplicación que se ejecuta en VM de Azure, o para que los servidores de Azure puedan consultar una base de datos que sigue en el datacenter. Azure ofrece dos opciones principales de conectividad híbrida, VPN Gateway y ExpressRoute, y el examen Microsoft Azure Fundamentals (AZ-900) espera que sepas cuándo elegir cada una. Una red privada virtual (VPN) crea un túnel cifrado entre dos redes a través de una red no confiable, normalmente internet público. Azure VPN Gateway es un tipo de puerta de enlace de red virtual implementada en una subred dedicada de tu VNet, que debe llamarse GatewaySubnet. Usa Internet Protocol Security (IPsec) e Internet Key Exchange (IKE) para cifrar el tráfico entre la VNet y otras ubicaciones a través de internet. Las puertas de enlace pueden estar basadas en directivas, usando reglas estáticas, o basadas en rutas, usando tablas de enrutamiento; la basada en rutas es la opción más flexible y común.

az network vnet subnet create --resource-group rg-net --vnet-name vnet-hub --name GatewaySubnet --address-prefixes 10.1.255.0/27
az network vnet-gateway create --resource-group rg-net --name vpngw --vnet vnet-hub --gateway-type Vpn --vpn-type RouteBased --sku VpnGw1 --public-ip-addresses vpngw-pip

VPN Gateway admite varios tipos de conexión. Site-to-site (S2S, de sitio a sitio) conecta una red on-premises completa a Azure mediante un dispositivo VPN en la oficina, de modo que cada máquina de la oficina puede llegar a la VNet. Point-to-site (P2S, de punto a sitio) conecta una computadora individual, como la laptop de un trabajador remoto, a la VNet usando software cliente VPN, sin necesidad de un dispositivo VPN en la oficina. VNet-to-VNet conecta dos VNet de Azure mediante puertas de enlace. Para una mayor disponibilidad puedes ejecutar las puertas de enlace en modo activo-en espera, el predeterminado, en el que una instancia en espera toma el control si la activa falla, o en modo activo-activo, en el que ambas instancias transportan túneles. Algunas organizaciones también usan ExpressRoute con una VPN site-to-site como ruta de conmutación por error.

Azure ExpressRoute extiende tu red on-premises a la nube de Microsoft mediante una conexión privada proporcionada por un socio de conectividad. El tráfico no viaja por internet público. Esto ofrece más confiabilidad, mayores velocidades, latencia constante y un aislamiento más fuerte que las conexiones basadas en internet, lo que es adecuado para grandes transferencias de datos, cargas de trabajo críticas y organizaciones con necesidades de cumplimiento estrictas. Las conexiones pueden hacerse en una instalación de coubicación, mediante un enlace Ethernet punto a punto, mediante una red any-to-any de un proveedor o con ExpressRoute Direct directamente a la red de Microsoft. ExpressRoute puede llegar a los servicios de Azure y a otros servicios de nube de Microsoft como Microsoft 365, y ExpressRoute Global Reach puede unir sitios on-premises entre sí a través de la red troncal de Microsoft. Ten en cuenta que privado no significa automáticamente cifrado; las organizaciones con requisitos de cifrado pueden agregar cifrado sobre ExpressRoute, por ejemplo con MACsec o un túnel IPsec.

La contrapartida es el costo y la configuración. VPN Gateway se configura más rápido y es más barato, pero el rendimiento depende de internet. ExpressRoute requiere trabajar con un proveedor y cuesta más, pero ofrece un rendimiento predecible. Para un solo usuario remoto, point-to-site es la opción correcta; para conectar una oficina completa a bajo costo, site-to-site; para una conexión grande, crítica y de alto ancho de banda que debe evitar internet, ExpressRoute.

Considera un ejemplo práctico. Un banco ejecuta sistemas de trading en su propio datacenter y traslada el análisis a Azure. Cada noche copia varios terabytes de datos de mercado a Azure, y los reguladores exigen que ese tráfico no atraviese internet público. Contrata un circuito ExpressRoute a través de un socio de conectividad y agrega una VPN site-to-site como ruta de respaldo. Sus cincuenta sucursales son pequeñas y se conectan a Azure con VPN site-to-site, y sus administradores de TI que trabajan desde casa usan VPN point-to-site desde sus laptops.

Errores comunes: pensar que el tráfico VPN no está cifrado (está cifrado, pero atraviesa internet); pensar que el tráfico de ExpressRoute está cifrado de manera predeterminada (es privado, no cifrado automáticamente); y elegir site-to-site para un solo usuario remoto. Otras trampas son olvidar que la puerta de enlace necesita su propia subred llamada GatewaySubnet, y suponer que ExpressRoute es solo para Azure, cuando también puede llegar a otros servicios de nube de Microsoft. Recuerda también que una puerta de enlace VPN tarda en implementarse y se factura mientras existe, así que en los laboratorios debes eliminarla al terminar.

Las preguntas del examen usan palabras clave claras. 'No debe atravesar internet público', 'conexión privada dedicada', 'latencia predecible' o 'proveedor de conectividad' es ExpressRoute. 'Túnel cifrado a través de internet' es VPN Gateway. 'Una laptop' o 'trabajador remoto individual' es point-to-site. 'Conectar toda la oficina' o 'dispositivo VPN on-premises' es site-to-site. 'Conectar dos VNet de Azure mediante puertas de enlace' es VNet-to-VNet, aunque el peering suele ser la opción más sencilla para eso.

Términos clave

Red privada virtual (VPN)
Un túnel cifrado que conecta redes o dispositivos a través de una red no confiable como internet.
Azure VPN Gateway
Una puerta de enlace de red virtual que envía tráfico cifrado entre una VNet y otras ubicaciones a través de internet.
VPN site-to-site (S2S)
Una VPN que conecta una red on-premises completa a Azure mediante un dispositivo VPN.
VPN point-to-site (P2S)
Una VPN que conecta una computadora individual a una VNet de Azure usando software cliente.
Azure ExpressRoute
Una conexión privada desde on-premises a la nube de Microsoft a través de un socio de conectividad que no usa internet público.
GatewaySubnet
La subred dedicada, con ese nombre exacto, donde se implementa la puerta de enlace de una VNet.
ExpressRoute Global Reach
Una función que une sitios on-premises entre sí a través de sus circuitos ExpressRoute.
Ejemplo real

Un fabricante con una oficina central y un puñado de ingenieros remotos necesita acceder a un sistema ERP en VM de Azure. Crea una puerta de enlace VPN, conecta el firewall de la oficina central con una VPN site-to-site y da a los ingenieros perfiles de VPN point-to-site en sus laptops. Dos años después, cuando traslada a diario archivos de diseño grandes a Azure y necesita una latencia estable, agrega un circuito ExpressRoute y conserva la VPN site-to-site como ruta de conmutación por error.

Consejo para el examen: Si el tráfico no debe atravesar internet público, la respuesta es ExpressRoute. El tráfico de VPN Gateway está cifrado pero viaja por internet. Una laptop significa point-to-site; una oficina completa significa site-to-site.

Comprueba lo que sabes

Una empresa exige que su tráfico híbrido nunca atraviese internet público. ¿Qué opción encaja?

ExpressRoute, que usa una conexión privada a través de un socio de conectividad.

Un solo empleado necesita llegar a una VNet de Azure desde su casa. ¿Qué tipo de conexión VPN encaja?

Point-to-site, que conecta una computadora usando software cliente VPN.

¿El tráfico de ExpressRoute está cifrado de manera predeterminada?

No, es privado pero no está cifrado automáticamente; puedes agregar cifrado como MACsec o IPsec si se requiere.

Menciona una ventaja de VPN Gateway frente a ExpressRoute.

Se configura más rápido y es más barato, porque usa la conexión a internet existente en lugar de un circuito de un proveedor.
