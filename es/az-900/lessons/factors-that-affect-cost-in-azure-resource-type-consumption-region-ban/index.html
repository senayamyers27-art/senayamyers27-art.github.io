Microsoft Certified: Azure Fundamentals AZ-900

Factores que afectan el costo en Azure: tipo de recurso, consumo, región, ancho de banda, reservas y Azure Hybrid Benefit

Azure factura la mayoría de los servicios por consumo, así que la factura es la suma de muchos medidores pequeños y no una cuota fija. Entender qué impulsa esos medidores es lo que te permite estimar el costo antes de implementar y controlarlo después. El examen espera que menciones los principales factores de costo y expliques cómo cada uno sube o baja lo que pagas, y que reconozcas las opciones de compra que reducen el costo de las cargas de trabajo estables.

El tipo de recurso es el primer factor. Cada servicio tiene sus propios medidores de precios: una VM se factura por tamaño y por el tiempo que se ejecuta, más sus discos y cualquier software con licencia; una cuenta de almacenamiento se factura por la cantidad de datos almacenados, su redundancia y nivel de acceso, y el número de operaciones de lectura y escritura; una función serverless se factura por ejecuciones y recursos usados. La configuración dentro de un recurso también importa. Un tamaño de VM más grande, los discos SSD premium o el almacenamiento con redundancia geográfica cuestan más que sus alternativas más pequeñas o sencillas, así que ajustar el tamaño adecuado (right-sizing) es uno de los ahorros más efectivos.

El consumo es la cantidad que realmente usas. El pago por uso cobra por lo que usas, sin compromiso, lo que es adecuado para cargas de trabajo variables o de corta duración. Para las cargas de trabajo predecibles puedes comprometerte por adelantado. Azure Reservations te compromete con un tipo de recurso específico, como un tamaño de VM en una región, por un plazo de uno o tres años a cambio de un descuento significativo. Los planes de ahorro de Azure para cómputo (savings plans) te comprometen con un gasto fijo por hora en los servicios de cómputo elegibles, lo que da más flexibilidad entre tamaños y regiones. Las máquinas virtuales Spot usan la capacidad sobrante de Azure a un precio mucho menor pero pueden ser desalojadas cuando Azure necesita recuperar esa capacidad, así que son adecuadas para trabajos por lotes interrumpibles, no para servidores web de producción. Desasignar una VM detiene los cargos de cómputo, aunque sigues pagando sus discos.

La región importa porque el mismo servicio puede costar distinto en distintas regiones, debido a la energía, el terreno, los impuestos y la demanda locales. Elegir una región más barata puede reducir el costo, siempre que se sigan cumpliendo los requisitos de latencia, residencia de datos y cumplimiento. El ancho de banda, o tráfico de red, a menudo se pasa por alto. Los datos que entran a Azure (ingress) generalmente son gratuitos. Los datos que salen de Azure (egress), como los archivos que descargan los usuarios, se facturan, y en muchos casos también los datos que se mueven entre regiones o entre zonas de disponibilidad. El precio depende de la cantidad transferida y de las zonas de facturación geográficas.

Azure Hybrid Benefit te permite usar en Azure las licencias on-premises existentes que tienen Software Assurance activo o suscripciones que califican, para Windows Server y SQL Server. Así pagas una tarifa menor por la VM o la base de datos porque se elimina la parte de licencia del precio. También se aplica a algunas suscripciones de Linux, como Red Hat y SUSE. Lo activas al crear una VM seleccionando la opción de licenciamiento, o más tarde en la configuración de la VM. Otros factores incluyen los productos comprados en Azure Marketplace, donde los proveedores externos agregan sus propios cargos, y la limpieza básica: eliminar discos olvidados, direcciones IP públicas y entornos de prueba.

Considera un ejemplo práctico. Una empresa ejecuta una base de datos de clientes en una VM las 24 horas, un trabajo nocturno de renderizado que puede reiniciarse si se interrumpe y un entorno de pruebas que se usa solo en horario de oficina. Ya posee licencias de Windows Server con Software Assurance. La VM de base de datos recibe una reserva de tres años y Azure Hybrid Benefit, lo que reduce tanto el costo de cómputo como el de licencia. El trabajo de renderizado pasa a VM Spot. El entorno de pruebas se programa para apagarse y desasignarse cada tarde. El equipo también coloca la base de datos en la misma región que la aplicación web para evitar los cargos por transferencia entre regiones.

Errores comunes: suponer que una VM detenida no cuesta nada (debes desasignarla, y los discos se siguen facturando); pensar que todo el tráfico de red se cobra (el entrante generalmente es gratuito); tratar Reservations y Hybrid Benefit como lo mismo (uno es un compromiso de tiempo, el otro reutiliza licencias que ya posees, y se pueden combinar); ejecutar producción en VM Spot; y elegir una región solo por precio ignorando las reglas de residencia de datos o la latencia para los usuarios.

Las preguntas del examen usan palabras clave claras. 'Comprometerse por uno o tres años a cambio de un descuento' apunta a Reservations. 'Reutilizar licencias existentes de Windows Server o SQL Server con Software Assurance' apunta a Azure Hybrid Benefit. 'Carga de trabajo interrumpible al precio más bajo' apunta a VM Spot. 'Datos subidos a Azure' generalmente son gratuitos, mientras que 'datos descargados por los usuarios' generan cargos de egress. 'El mismo servicio, distinto precio' apunta a la región. 'Tamaño más grande o nivel premium' apunta al tipo de recurso.

Términos clave

Pago por uso (pay-as-you-go)
Pagar solo por los recursos que consumes, sin compromiso inicial.
Azure Reservations
Un compromiso de uno o tres años con un recurso específico a cambio de una tarifa con descuento.
Plan de ahorro de Azure para cómputo (Azure savings plan for compute)
Un compromiso con un gasto fijo por hora en los servicios de cómputo elegibles a cambio de precios más bajos.
Máquina virtual Spot (Spot virtual machine)
Una VM que usa capacidad sobrante a bajo precio y que puede ser desalojada cuando Azure necesita esa capacidad.
Ingress y egress
Datos que entran a Azure (generalmente gratuitos) y datos que salen de Azure (facturados).
Azure Hybrid Benefit
Usar licencias existentes de Windows Server, SQL Server o algunas de Linux en Azure para reducir el costo.
Desasignar (deallocate)
Detener una VM de modo que se liberen sus recursos de cómputo y se detenga la facturación de cómputo.
Ejemplo real

La factura de Azure de una plataforma de video sube inesperadamente. La investigación muestra que la mayor parte del aumento es egress, porque un video popular se descarga millones de veces directamente desde Blob storage. Las cargas no cuestan nada, pero cada descarga agrega cargos de ancho de banda saliente. El equipo sirve el video mediante una red de entrega de contenido con caché y revisa sus precios, y ajusta el tamaño de varias VM sobredimensionadas que funcionaron con poca CPU todo el mes.

Consejo para el examen: La transferencia de datos entrante generalmente es gratuita; la saliente se factura. Reservations premia un compromiso a largo plazo; Hybrid Benefit reutiliza licencias que ya posees. El mismo servicio puede costar distinto en distintas regiones, y una VM detenida debe desasignarse para detener los cargos de cómputo.

Comprueba lo que sabes

Una empresa tiene licencias de Windows Server con Software Assurance. ¿Cómo puede reducir los costos de VM en Azure?

Aplicando Azure Hybrid Benefit para que se elimine la parte de licencia del precio de la VM.

¿Qué opción de compra es adecuada para una VM que debe ejecutarse continuamente durante los próximos tres años?

Una Azure Reservation, que da un descuento por un compromiso de uno o tres años.

¿Subir datos a Azure normalmente se factura?

No. El ingress generalmente es gratuito; el egress (datos que salen de Azure) se factura.

¿Por qué las VM Spot no son adecuadas para un servidor web de producción?

Pueden ser desalojadas con poco aviso cuando Azure necesita recuperar la capacidad.
