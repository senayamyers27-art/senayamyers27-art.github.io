Microsoft Certified: Azure Fundamentals AZ-900

Servicios de Azure Storage (Blob, Files, Queue, Table, Disks), tipos de cuenta de almacenamiento y niveles de acceso (Hot, Cool, Cold, Archive)

Azure Storage es la plataforma de almacenamiento en la nube de Microsoft para casi cualquier tipo de dato que produce una aplicación: documentos, imágenes, copias de seguridad, mensajes, registros estructurados y los discos duros virtuales que están detrás de las máquinas virtuales (VM). Es durable (siempre se mantienen varias copias), de alta disponibilidad, segura de manera predeterminada (los datos se cifran en reposo automáticamente) y enormemente escalable, y pagas solo por la capacidad y las operaciones que usas. La mayoría de los servicios de almacenamiento viven dentro de una cuenta de almacenamiento, que le da a tus datos un espacio de nombres único accesible por HTTP o HTTPS. Como el nombre de la cuenta forma parte de las direcciones de los endpoints públicos, como mystorage.blob.core.windows.net, debe ser único en todo Azure, tener entre 3 y 24 caracteres y usar solo letras minúsculas y números.

Azure Storage ofrece varios servicios de datos, y el examen espera que relaciones cada uno con una necesidad. Blob storage guarda datos no estructurados como imágenes, video, copias de seguridad y archivos de registro, organizados en contenedores; es almacenamiento de objetos optimizado para cantidades de datos muy grandes, y cada blob tiene su propia URL. Azure Files proporciona recursos compartidos de archivos totalmente administrados que montas con el protocolo Server Message Block (SMB), y en los recursos compartidos premium con Network File System (NFS), igual que una unidad de red asignada, lo que es adecuado para el lift-and-shift de aplicaciones que ya usan recursos compartidos de archivos. Queue storage guarda grandes cantidades de mensajes pequeños para que las partes de una aplicación puedan comunicarse de forma asíncrona: un front end web deja un mensaje de pedido en una cola y un proceso en segundo plano lo procesa después. Table storage almacena datos clave-valor estructurados y no relacionales (NoSQL) con un esquema flexible. Azure Disks son volúmenes a nivel de bloque conectados a las VM de Azure, ofrecidos como discos administrados para que Azure se encargue del almacenamiento subyacente por ti.

El tipo de cuenta de almacenamiento decide qué servicios, niveles de rendimiento y opciones de redundancia puedes usar. Standard general-purpose v2 es el tipo recomendado para la mayoría de los escenarios; admite blobs (incluido Azure Data Lake Storage), archivos, colas y tablas y se ejecuta en hardware estándar basado en discos duros. Los tipos de cuenta Premium usan unidades de estado sólido (SSD) para una latencia baja y constante y son especializados: premium block blobs para altas tasas de transacciones u objetos pequeños, premium file shares para cargas de trabajo de archivos empresariales y premium page blobs para escenarios de page blobs. Puedes crear una cuenta en el portal en Storage accounts, luego Create, o con un comando como az storage account create --name stdemo01 --resource-group rg-demo --sku Standard_LRS --kind StorageV2.

Los datos de blob pueden almacenarse en niveles de acceso que equilibran el costo de almacenamiento frente al costo de acceso. El nivel Hot es para datos a los que se accede con frecuencia; tiene el costo de almacenamiento más alto y el costo de acceso más bajo. El nivel Cool es para datos a los que se accede con poca frecuencia y que se conservan al menos 30 días. El nivel Cold es para datos a los que se accede rara vez y que se conservan al menos 90 días. El nivel Archive es para datos a los que casi nunca se accede y que se conservan al menos 180 días, con el costo de almacenamiento más bajo y el costo de recuperación más alto. Mover o eliminar datos de un nivel más frío antes de su periodo mínimo genera un cargo por eliminación anticipada, así que los niveles solo ahorran dinero si los datos realmente se quedan donde están.

Archive es diferente en un aspecto importante: está fuera de línea. No puedes leer directamente un blob archivado; primero debes rehidratarlo cambiando su nivel a un nivel en línea (Hot, Cool o Cold) o copiándolo a uno, y eso puede tardar horas. La cuenta de almacenamiento tiene un nivel de acceso predeterminado que heredan los nuevos blobs, mientras que Archive solo se puede establecer en blobs individuales. Las reglas de administración del ciclo de vida pueden mover los blobs entre niveles automáticamente a medida que envejecen, por ejemplo moviendo los archivos de registro a Cool después de 30 días, a Archive después de 180 días y eliminándolos después de varios años.

Considera un ejemplo práctico. Una clínica almacena fotos subidas por los pacientes que los médicos consultan a menudo el primer mes y luego rara vez. La regulación exige una retención de siete años. Pones las fotos en Blob storage en una cuenta general-purpose v2 con el nivel predeterminado Hot y agregas una regla de ciclo de vida: mover los blobs a Cool después de 30 días sin acceso y a Archive después de un año. La aplicación de citas usa Queue storage para pasar los recordatorios de citas a un proceso en segundo plano, y una herramienta de informes heredada que espera una unidad asignada lee desde un recurso compartido de Azure Files. Cada necesidad corresponde a un servicio distinto en la misma cuenta.

Errores comunes: elegir Archive para datos que podrías necesitar en minutos (primero necesita rehidratación); pensar que la cuenta puede tener Archive como nivel predeterminado (no puede); confundir Table storage con una base de datos relacional (Table storage no tiene joins ni esquema fijo); confundir Azure Files, que es un recurso compartido que muchas máquinas pueden montar, con Azure Disks, que es un volumen conectado a una VM; y suponer que las cuentas Premium admiten todos los servicios y opciones de redundancia (son especializadas).

Las preguntas del examen suelen basarse en escenarios. 'Datos no estructurados como imágenes o video' apunta a Blob storage. 'Reemplazar un recurso compartido de un servidor de archivos on-premises' o 'montar mediante SMB' apunta a Azure Files. 'Desacoplar componentes de una aplicación con mensajes' apunta a Queue storage. 'Datos clave-valor NoSQL' apunta a Table storage. 'Acceso poco frecuente, puede esperar horas, el almacenamiento más barato' apunta a Archive, mientras que 'acceso poco frecuente pero debe estar disponible de inmediato' apunta a Cool o Cold. 'Tipo de cuenta recomendado para la mayoría de los escenarios' es Standard general-purpose v2.

Términos clave

Cuenta de almacenamiento (storage account)
Un contenedor para los servicios de datos de Azure Storage que proporciona un espacio de nombres y endpoints únicos a nivel global.
Blob storage
Almacenamiento de objetos para grandes cantidades de datos no estructurados, organizados en contenedores.
Azure Files
Recursos compartidos de archivos en la nube totalmente administrados que pueden montarse mediante SMB o NFS.
Queue storage
Un servicio para almacenar mensajes de modo que los componentes de una aplicación puedan comunicarse de forma asíncrona.
Table storage
Un almacén NoSQL para datos clave-valor estructurados y sin esquema.
Nivel de acceso (access tier)
Una configuración Hot, Cool, Cold o Archive en los datos de blob que equilibra el costo de almacenamiento frente al costo de acceso.
Rehidratación (rehydration)
Cambiar un blob archivado a un nivel en línea para poder leerlo, lo que puede tardar horas.
Administración del ciclo de vida (lifecycle management)
Reglas que mueven blobs entre niveles o los eliminan automáticamente según su antigüedad o acceso.
Ejemplo real

Una empresa de medios guarda los proyectos de video terminados en Blob storage. Los proyectos activos permanecen en el nivel Hot para una edición rápida. Una regla de administración del ciclo de vida mueve los proyectos sin tocar durante 90 días a Cold y, después de un año, a Archive, lo que reduce mucho el costo de almacenamiento. Cuando un cliente pide un proyecto antiguo, un ingeniero lo rehidrata a Hot y planifica que esté disponible más tarde ese mismo día y no de inmediato.

Consejo para el examen: Archive está fuera de línea y necesita una rehidratación que puede tardar horas, y solo se puede establecer por blob. Los periodos mínimos de retención son Cool 30 días, Cold 90 días y Archive 180 días. Queue es para mensajes, Table es para datos clave-valor NoSQL, Files es para recursos compartidos SMB/NFS.

Comprueba lo que sabes

Una aplicación necesita leer un blob en segundos, pero se accede a él solo unas pocas veces al año. ¿Es adecuado Archive?

No. Archive está fuera de línea y debe rehidratarse, lo que puede tardar horas; Cool o Cold lo mantienen en línea a un costo menor que Hot.

¿Qué servicio de almacenamiento permite que muchos servidores monten el mismo recurso compartido mediante SMB?

Azure Files, que proporciona recursos compartidos de archivos totalmente administrados que se montan como una unidad de red.

¿Qué tipo de cuenta de almacenamiento recomienda Microsoft para la mayoría de los escenarios?

Standard general-purpose v2, que admite blobs, archivos, colas y tablas.

¿Qué ocurre si eliminas un blob del nivel Cool después de diez días?

Pagas un cargo por eliminación anticipada, porque Cool tiene un periodo mínimo de retención de 30 días.
