Redes virtuales, subredes, peering, Azure DNS y endpoints públicos frente a privados

Una red virtual de Azure (VNet) es tu propia red privada en Azure. Permite que los recursos de Azure, como las VM, se comuniquen entre sí, con internet y con tus redes on-premises. Cuando creas una VNet le asignas un espacio de direcciones en rangos de IP privados, como 10.1.0.0/16, escrito en notación Classless Inter-Domain Routing (CIDR), y vive en una región y una suscripción. Las VNet proporcionan aislamiento: los recursos de una VNet no pueden llegar a los recursos de otra hasta que las conectes. Divides una VNet en subredes, rangos de direcciones más pequeños como 10.1.1.0/24, para organizar y proteger los recursos. Por ejemplo, podrías poner los servidores web en una subred y los servidores de bases de datos en otra. Los recursos de distintas subredes de la misma VNet pueden comunicarse entre sí de manera predeterminada. Filtras el tráfico con grupos de seguridad de red (NSG), que contienen reglas priorizadas de permitir y denegar basadas en origen, destino, puerto y protocolo, y pueden asociarse a una subred o a una interfaz de red.

az network vnet create --resource-group rg-net --name vnet-hub --address-prefixes 10.1.0.0/16 --subnet-name web --subnet-prefixes 10.1.1.0/24
az network vnet subnet create --resource-group rg-net --vnet-name vnet-hub --name db --address-prefixes 10.1.2.0/24
az network vnet peering create --resource-group rg-net --name hub-to-spoke --vnet-name vnet-hub --remote-vnet vnet-spoke --allow-vnet-access

El emparejamiento de redes virtuales (VNet peering) une dos VNet para que los recursos de cada una puedan comunicarse usando direcciones IP privadas, como si estuvieran en una sola red. El peering puede conectar VNet de la misma región o de regiones distintas (peering global), y el tráfico entre VNet emparejadas viaja por la red troncal de Microsoft, no por internet público. Los espacios de direcciones de las VNet emparejadas no deben superponerse, y el peering debe configurarse en ambas direcciones para que el tráfico fluya en ambos sentidos. El peering no es transitivo de manera predeterminada: si A está emparejada con B y B con C, A no puede llegar a C sin su propio enlace o un dispositivo de enrutamiento.

Azure DNS aloja zonas del Domain Name System (DNS) en la red global de Microsoft. DNS traduce nombres como www.example.com a direcciones IP. Con Azure DNS administras tus registros con las mismas credenciales, permisos RBAC, herramientas y facturación que tus otros recursos de Azure, por ejemplo con az network dns record-set a add-record. Azure DNS aloja tus registros, pero el nombre de dominio en sí lo sigues comprando a un registrador y lo apuntas a los servidores de nombres de Azure. Las zonas DNS privadas proporcionan resolución de nombres dentro de tus VNet, para que las VM puedan encontrarse por nombre sin exponer esos nombres públicamente.

Se puede llegar a los recursos a través de endpoints públicos o privados. Un endpoint público es una dirección accesible desde internet, como una dirección IP pública en una VM o la dirección pública predeterminada de una cuenta de almacenamiento. Un endpoint privado es una interfaz de red con una dirección IP privada de tu VNet que se conecta de forma privada a un servicio PaaS de Azure, como una cuenta de almacenamiento o una base de datos SQL, mediante Azure Private Link. El tráfico hacia un endpoint privado permanece en la red de Microsoft, y luego puedes desactivar por completo el acceso de red pública al servicio, lo que reduce su exposición.

Considera un ejemplo práctico. Una empresa ejecuta un nivel web y un nivel de base de datos en una VNet, 10.1.0.0/16, con subredes separadas y un NSG que permite solo a la subred web llegar al puerto 1433 de la subred de base de datos. La VNet de un segundo equipo, 10.2.0.0/16, aloja herramientas compartidas, así que las dos VNet están emparejadas. El nombre del sitio web público se aloja en Azure DNS. Su cuenta de almacenamiento guarda documentos de clientes, así que el equipo crea un endpoint privado en la subred de base de datos y desactiva el acceso público; los servidores web llegan a la cuenta de almacenamiento mediante una IP privada, y las solicitudes desde internet se rechazan.

Errores comunes: emparejar VNet con espacios de direcciones superpuestos; suponer que el peering es transitivo; creer que Azure DNS vende nombres de dominio; y pensar que un endpoint privado cifra los datos, cuando su propósito es el acceso de red privado. Otra trampa es dejar abierto el endpoint público de un servicio después de agregar un endpoint privado; la exposición solo se elimina cuando se desactiva el acceso de red pública.

Las preguntas del examen usan pistas reconocibles. 'Conectar dos VNet para que se comuniquen de forma privada' es peering, y 'en regiones distintas' es peering global. 'Filtrar el tráfico por puerto e IP' es un grupo de seguridad de red. 'Alojar registros DNS con credenciales y facturación de Azure' es Azure DNS. 'Acceder a un servicio PaaS mediante una IP privada desde tu VNet' o 'eliminar la exposición a internet público' es un endpoint privado. 'Segmentar recursos dentro de una VNet' son las subredes.

Términos clave

Red virtual (VNet)
Una red privada aislada en Azure, en una región y una suscripción, con su propio espacio de direcciones.
Subred (subnet)
Un rango de direcciones dentro de una VNet que se usa para agrupar y proteger recursos.
Grupo de seguridad de red (NSG)
Un conjunto de reglas de permitir y denegar que filtra el tráfico hacia subredes o interfaces de red.
VNet peering (emparejamiento de redes virtuales)
Una conexión privada entre dos VNet a través de la red troncal de Microsoft; el peering global une VNet de regiones distintas.
Azure DNS
Un servicio que aloja zonas y registros DNS en la infraestructura de Azure; no registra nombres de dominio.
Endpoint privado (private endpoint)
Una interfaz de red con una IP privada en tu VNet que se conecta de forma privada a un servicio PaaS de Azure.
Endpoint público (public endpoint)
Una dirección accesible desde internet, como una IP pública o la URL pública predeterminada de un servicio.
Ejemplo real

Una startup de salud almacena archivos de pacientes en Azure Storage. Una auditoría señala que la cuenta de almacenamiento es accesible desde internet. El equipo crea un endpoint privado en la VNet de su aplicación, actualiza el DNS privado para que el nombre del almacenamiento se resuelva a la IP privada y desactiva el acceso de red pública. La aplicación sigue funcionando a través de la dirección privada, mientras que los intentos de conexión desde internet ahora fallan.

Consejo para el examen: El peering conecta VNet y requiere espacios de direcciones que no se superpongan; no es transitivo. Un endpoint privado le da a un servicio PaaS una IP privada en tu VNet. Azure DNS aloja registros pero no vende nombres de dominio.

Comprueba lo que sabes

¿Qué requisito deben cumplir dos VNet antes de poder emparejarse?

Sus espacios de direcciones no deben superponerse.

¿El tráfico entre VNet emparejadas atraviesa internet público?

No, viaja de forma privada por la red troncal de Microsoft.

¿Puedes comprar un nombre de dominio mediante Azure DNS?

No, Azure DNS aloja la zona y los registros; el dominio se compra a un registrador y se delega a los servidores de nombres de Azure.

¿Cuál es el beneficio de seguridad de un endpoint privado para una cuenta de almacenamiento?

Se llega al servicio mediante una IP privada en tu VNet, así que puedes desactivar el acceso público y eliminar la exposición a internet.
