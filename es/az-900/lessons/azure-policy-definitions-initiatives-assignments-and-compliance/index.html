Azure Policy: definiciones, iniciativas, asignaciones y cumplimiento

Azure Policy es un servicio que te ayuda a aplicar los estándares de la organización y evaluar el cumplimiento a escala. Mientras que el control de acceso basado en roles (RBAC) controla quién puede hacer algo, Azure Policy controla qué se puede crear y cómo deben configurarse los recursos, sin importar quién lo haga, incluso un Owner. Por ejemplo, una directiva puede permitir recursos solo en ciertas regiones para cumplir las reglas de residencia de datos, exigir una etiqueta en cada grupo de recursos, permitir solo tamaños de VM específicos para controlar el costo o exigir que las cuentas de almacenamiento acepten solo tráfico HTTPS. Es una de las herramientas de gobernanza centrales del examen, junto con los grupos de administración, los bloqueos y las etiquetas.

Una definición de directiva describe una regla: una condición que evaluar y un efecto que aplicar cuando un recurso coincide. Las definiciones se escriben en JSON con un bloque if y un bloque then, y Azure proporciona cientos de definiciones integradas, como 'Allowed locations' y 'Require a tag on resources'. Los efectos comunes incluyen Deny, que bloquea una solicitud de creación o actualización que infringe la regla; Audit, que permite la solicitud pero marca el recurso como no conforme; Append y Modify, que agregan o cambian propiedades como las etiquetas; AuditIfNotExists y DeployIfNotExists, que comprueban o implementan un recurso o una configuración relacionados que faltan; y Disabled, que desactiva la regla. Una regla simplificada se ve así:

"if": { "not": { "field": "location", "in": "[parameters('allowedLocations')]" } },
"then": { "effect": "deny" }

Una iniciativa, también llamada conjunto de directivas (policy set), agrupa varias definiciones de directivas relacionadas para que puedas administrarlas y asignarlas como una sola unidad hacia un mismo objetivo. Por ejemplo, una iniciativa para un benchmark de seguridad podría contener decenas de definiciones que cubren el cifrado, el registro y las reglas de red, y existen iniciativas integradas para estándares regulatorios. Microsoft Defender for Cloud usa una iniciativa integrada, el Microsoft cloud security benchmark, para impulsar sus recomendaciones. Una definición o iniciativa no hace nada hasta que creas una asignación, que la aplica a un ámbito: un grupo de administración, una suscripción o un grupo de recursos. Las asignaciones se heredan en todos los ámbitos secundarios, así que asignar una directiva en un grupo de administración cubre cada suscripción, grupo de recursos y recurso que está debajo. Puedes excluir ámbitos secundarios específicos, y estableces los valores de los parámetros, como la lista de regiones permitidas, al momento de la asignación. En el portal abres Policy, eliges Definitions, seleccionas una y eliges Assign; desde la CLI puedes ejecutar az policy assignment create.

Azure Policy evalúa los recursos cuando se crean o actualizan, cuando cambia una asignación y periódicamente para los recursos existentes. La página Compliance muestra el porcentaje de recursos conformes y enumera cada recurso no conforme con el motivo. Para las directivas que usan Modify o DeployIfNotExists, puedes crear tareas de corrección (remediation tasks) que arreglan los recursos no conformes existentes, por ejemplo agregando una etiqueta faltante a cientos de recursos a la vez. Los recursos existentes no se eliminan ni se bloquean cuando asignas una directiva Deny; se informan como no conformes, y el Deny se aplica a las futuras creaciones y actualizaciones.

Considera un ejemplo práctico. Una empresa europea debe mantener todos sus datos en dos regiones europeas y quiere que cada recurso esté etiquetado con un centro de costos. Creas una iniciativa que contiene 'Allowed locations' con Deny, configurada con las dos regiones, y 'Require a tag on resources' con Deny para la etiqueta CostCenter. Asignas la iniciativa al grupo de administración superior de la empresa. Luego un desarrollador intenta crear una VM en una región de Estados Unidos y la solicitud falla con un error de directiva. La vista de cumplimiento muestra algunos recursos antiguos sin la etiqueta, así que agregas una directiva de herencia de etiquetas con Modify y ejecutas una tarea de corrección.

Errores comunes: confundir Policy con RBAC (un Owner puede seguir siendo bloqueado por una directiva Deny); esperar que una nueva directiva Deny elimine los recursos no conformes existentes (los informa); olvidar que una definición no tiene efecto hasta que se asigna; y confundir Policy con los bloqueos de recursos, que protegen recursos específicos contra la eliminación o el cambio en lugar de aplicar reglas de configuración.

Redacción del examen: 'garantizar que los recursos se creen solo en ciertas regiones', 'aplicar estándares', 'permitir solo ciertos tamaños de VM' o 'informar los recursos no conformes' apunta a Azure Policy. 'Agrupar varias directivas' apunta a una iniciativa. 'Aplicar una directiva a un ámbito' apunta a una asignación. 'Bloquear' es el efecto Deny; 'permitir pero señalar' es Audit.

Términos clave

Azure Policy
Un servicio que aplica reglas a las configuraciones de los recursos e informa el cumplimiento en los distintos ámbitos.
Definición de directiva (policy definition)
Una regla en JSON que describe una condición y el efecto que se aplica cuando un recurso coincide.
Efecto (effect)
La acción que realiza una directiva, como Deny, Audit, Modify o DeployIfNotExists.
Iniciativa (policy set)
Un grupo de definiciones de directivas relacionadas que se administran y asignan como una sola unidad.
Asignación (assignment)
La aplicación de una definición o iniciativa a un ámbito, con parámetros y exclusiones opcionales.
Estado de cumplimiento (compliance state)
Si un recurso cumple las directivas asignadas, lo que se muestra en la página Compliance.
Tarea de corrección (remediation task)
Un trabajo que pone en cumplimiento los recursos no conformes existentes usando Modify o DeployIfNotExists.
Ejemplo real

Una empresa minorista descubrió que su personal creaba VM costosas con GPU para experimentos. El equipo de nube asigna a la suscripción la directiva integrada 'Allowed virtual machine size SKUs' con una lista de tamaños aprobados. A partir de entonces, cualquier intento de implementar un tamaño con GPU se deniega con un mensaje de directiva claro, mientras que las VM existentes se muestran como no conformes para que el equipo pueda revisarlas y redimensionarlas.

Consejo para el examen: Policy trata de lo que está permitido (configuración); RBAC trata de quién puede actuar. Una iniciativa agrupa definiciones; una asignación las aplica a un ámbito. Deny bloquea los cambios no conformes; Audit solo los informa. Las directivas se aplican incluso a los Owner.

Comprueba lo que sabes

Una empresa quiere impedir que alguien cree recursos fuera de dos regiones aprobadas. ¿Qué debe usar?

Azure Policy con la definición Allowed locations y el efecto Deny, asignada en un ámbito adecuado.

¿Qué es una iniciativa en Azure Policy?

Un grupo de definiciones de directivas relacionadas que se administran y asignan juntas hacia un mismo objetivo.

Se asigna una directiva Deny para una etiqueta obligatoria. ¿Qué les ocurre a los recursos existentes sin la etiqueta?

Se informan como no conformes pero no se eliminan; el Deny se aplica a las nuevas creaciones y actualizaciones.

Un usuario tiene el rol Owner. ¿Puede Azure Policy bloquear de todos modos su implementación?

Sí. Policy evalúa la configuración del recurso sin importar el rol del usuario.
