CompTIA Network+ N10-009

Conceptos de nube: NFV, VPC, grupos de seguridad, gateways de nube, modelos de implementación y de servicio (IaaS, PaaS, SaaS)

La computación en la nube significa usar recursos informáticos, como servidores, almacenamiento y redes, que administra un proveedor y que consumes bajo demanda a través de una red. El proveedor agrupa recursos para muchos clientes, te permite escalar hacia arriba y hacia abajo rápidamente y normalmente cobra por uso. Network+ se centra en cómo funcionan las redes en ese mundo: cómo se construyen las redes virtuales, cómo entra y sale el tráfico, cómo se filtra y el vocabulario de los modelos de servicio y de implementación. Estas ideas importan porque la mayoría de las organizaciones hoy combinan sistemas locales (on-premises) y en la nube, y el ingeniero de redes tiene que conectarlos de forma segura.

La virtualización de funciones de red (NFV) reemplaza los dispositivos de hardware dedicados, como routers, firewalls y balanceadores de carga, con versiones de software que se ejecutan en servidores estándar o en la nube. En lugar de enviar un firewall físico a un sitio y esperar a que lo instalen en el rack, levantas un firewall virtual en minutos. NFV es lo que hace posibles las redes en la nube, porque un proveedor no puede instalar un firewall físico para cada cliente. No la confundas con las redes definidas por software (SDN): NFV virtualiza los dispositivos en sí, mientras que SDN separa el plano de control del plano de datos para que la red se pueda administrar de forma centralizada. A menudo se usan juntas.

Una nube privada virtual (VPC) es tu propia red aislada lógicamente dentro de una nube pública. Tú eliges su rango de direcciones IP privadas (por ejemplo 10.20.0.0/16) y lo divides en subredes, normalmente subredes públicas para los recursos expuestos a internet y subredes privadas para bases de datos y servidores internos. Lo que hace 'pública' a una subred es simplemente su tabla de rutas: tiene una ruta hacia un gateway de internet. Controlas todo el enrutamiento con tablas de rutas, igual que lo harías en un router físico.

Los gateways de nube conectan la VPC con el mundo exterior. Un gateway de internet permite que entre y salga tráfico para los recursos que tienen direcciones públicas. Un gateway NAT permite que los recursos de las subredes privadas inicien conexiones salientes, como descargar parches, mientras bloquea las entrantes no solicitadas. Para conectar una VPC con tu centro de datos se usa un gateway VPN (un túnel IPsec de sitio a sitio por internet) o un circuito privado dedicado que ofrece el proveedor, el cual da un rendimiento más constante. En un diseño típico, la subred pública 10.20.1.0/24 tiene una ruta predeterminada (0.0.0.0/0) hacia el gateway de internet, la subred privada 10.20.2.0/24 tiene su ruta predeterminada apuntando al gateway NAT, y ambas tienen una ruta hacia el rango de la oficina central 192.168.0.0/16 que apunta al gateway VPN.

La seguridad en una VPC funciona por capas. Un grupo de seguridad (security group) es un firewall virtual con estado asociado a una instancia o interfaz de red individual: enumeras lo que se permite entrar y salir, y el tráfico de retorno se permite automáticamente. Los grupos de seguridad normalmente solo tienen reglas de permiso, y todo lo demás se deniega implícitamente. Una lista de control de acceso a la red (NACL), en los proveedores que la ofrecen, se aplica a toda una subred y normalmente no tiene estado, así que debes permitir ambas direcciones de forma explícita, incluidos los puertos efímeros de retorno; las NACL pueden tener reglas de permiso y de denegación, que se procesan en orden. Recuerda: grupo de seguridad significa nivel de instancia y con estado; NACL significa nivel de subred y sin estado.

Los modelos de servicio describen cuánto administra el proveedor por ti. En Infraestructura como Servicio (IaaS) rentas máquinas virtuales, almacenamiento y redes; tú administras el sistema operativo, los parches, las aplicaciones y los datos. En Plataforma como Servicio (PaaS) el proveedor también opera el sistema operativo y el entorno de ejecución, y tú implementas tu código o el esquema de tu base de datos. En Software como Servicio (SaaS) simplemente usas una aplicación terminada, como el correo web o un sistema de gestión de relaciones con clientes. Este es el modelo de responsabilidad compartida: cuanto más te alejas de IaaS hacia SaaS, más responsabilidad tiene el proveedor, aunque tú siempre sigues siendo responsable de tus datos, tus cuentas de usuario y la forma en que configuras el acceso.

Los modelos de implementación describen para quién es la nube. Una nube pública es infraestructura compartida que se ofrece a cualquiera. Una nube privada está dedicada a una sola organización, en sus instalaciones o alojada. Una nube híbrida combina la pública y la privada y mueve cargas de trabajo entre ellas, por ejemplo expandiéndose a la nube pública en horas pico. Una nube comunitaria la comparten organizaciones con necesidades comunes, como agencias gubernamentales u hospitales sujetos a las mismas regulaciones. Las redes en la nube también traen términos como elasticidad (agregar o quitar recursos automáticamente a medida que cambia la demanda), escalabilidad (la capacidad de crecer) y multiinquilino o multitenencia (muchos clientes que comparten el mismo hardware físico, aislados lógicamente). Un error común es suponer que el proveedor protege todo en la nube; los grupos de seguridad y el almacenamiento mal configurados están entre las causas más frecuentes de brechas en la nube.

Las preguntas del examen normalmente describen una necesidad y preguntan por el modelo o el componente. 'No quiere administrar servidores ni el sistema operativo' significa PaaS o SaaS; 'control total del sistema operativo' significa IaaS; 'solo usar la aplicación' significa SaaS. 'La subred privada necesita actualizaciones pero no debe ser accesible' significa gateway NAT. 'Reglas con estado a nivel de instancia' significa grupo de seguridad. 'Reemplazar dispositivos de hardware con software' significa NFV. 'Compartida por varias organizaciones con necesidades comunes de cumplimiento' significa nube comunitaria.

Términos clave

NFV (virtualización de funciones de red)
Ejecutar funciones de red como el enrutamiento y el firewall como software en lugar de hardware dedicado.
VPC (nube privada virtual)
Una red aislada lógicamente y definida por el cliente dentro de un proveedor de nube pública.
Grupo de seguridad (security group)
Un firewall virtual con estado que se aplica a instancias o interfaces en la nube y permite el tráfico entrante y saliente especificado.
Gateway de internet (internet gateway)
Un componente de la VPC que permite que los recursos con direcciones públicas envíen y reciban tráfico de internet.
Gateway NAT (NAT gateway)
Un gateway de nube que permite que los recursos de subredes privadas hagan conexiones salientes a internet sin aceptar tráfico entrante no solicitado.
Modelo de responsabilidad compartida (shared responsibility model)
La división de las tareas de seguridad entre el proveedor de nube y el cliente, que se desplaza hacia el proveedor de IaaS a PaaS y a SaaS.
Nube híbrida (hybrid cloud)
Una implementación que combina recursos de nube pública y privada y mueve o conecta cargas de trabajo entre ellas.
Ejemplo real

Una startup construye una VPC con una subred pública para sus servidores web y una subred privada para su base de datos. El grupo de seguridad de los servidores web permite HTTPS desde cualquier lugar, mientras que el grupo de seguridad de la base de datos solo permite el puerto de la base de datos, y solo desde el grupo de seguridad de los servidores web. La base de datos instala parches a través de un gateway NAT, pero no es accesible desde internet. Cuando más adelante la empresa necesita que el sistema contable de su oficina lea los datos de ventas, agrega un gateway VPN de sitio a sitio para que la red de la oficina y la VPC se comuniquen de forma privada.

Consejo para el examen: Asocia los modelos según quién administra el sistema operativo: en IaaS lo haces tú, en PaaS y SaaS lo hace el proveedor. SaaS es una aplicación terminada. El gateway de internet permite tráfico entrante y saliente; el gateway NAT solo permite el saliente.

Comprueba lo que sabes

Un desarrollador quiere implementar código sin aplicar parches a servidores, pero seguir escribiendo y controlando la aplicación. ¿Qué modelo de servicio encaja y por qué no SaaS?

PaaS, porque el proveedor administra la infraestructura, el sistema operativo y el entorno de ejecución mientras el desarrollador aporta el código; SaaS sería una aplicación terminada que el desarrollador no puede modificar.

Un grupo de seguridad permite TCP 443 entrante. ¿Necesita también una regla saliente para que las respuestas lleguen a los clientes? ¿Y una NACL?

El grupo de seguridad no, porque tiene estado y permite el tráfico de retorno automáticamente; una NACL sin estado necesitaría una regla saliente que permita los puertos efímeros.

Un servidor en una subred con ruta hacia un gateway NAT no es accesible desde internet, incluso después de agregar una regla para IP pública. ¿Por qué?

Porque la subred enruta a través de un gateway NAT, que solo permite conexiones iniciadas hacia afuera; el acceso público entrante necesita una ruta hacia un gateway de internet.

¿En qué se diferencia NFV de SDN?

NFV convierte los dispositivos de red en instancias de software; SDN separa el plano de control del plano de datos para que un controlador central programe la red. Resuelven problemas distintos y a menudo se combinan.
