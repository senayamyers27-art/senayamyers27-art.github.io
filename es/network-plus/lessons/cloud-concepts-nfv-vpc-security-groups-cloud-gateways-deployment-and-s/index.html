CompTIA Network+ N10-009

Conceptos de nube: NFV, VPC, grupos de seguridad, gateways de nube, modelos de implementación y de servicio (IaaS, PaaS, SaaS)

La computación en la nube significa usar recursos de cómputo, como servidores, almacenamiento y redes, que opera un proveedor y que tú consumes bajo demanda a través de una red. El proveedor agrupa recursos para muchos clientes, te permite escalar hacia arriba y hacia abajo rápidamente y normalmente cobra según el uso. Network+ se enfoca en cómo funcionan las redes en ese mundo y en el vocabulario de los modelos de servicio y de implementación.

La virtualización de funciones de red (NFV, network functions virtualization) reemplaza dispositivos de hardware dedicados, como routers, firewalls y balanceadores de carga, por versiones de software que se ejecutan en servidores estándar o en la nube. En lugar de enviar una caja de firewall a un sitio, levantas un firewall virtual. NFV es lo que hace posible las redes en la nube, porque un proveedor no puede instalar un firewall físico en el rack para cada cliente.

Una nube privada virtual (VPC, virtual private cloud) es tu propia red lógicamente aislada dentro de una nube pública. Tú eliges su rango de direcciones IP y lo divides en subredes, normalmente subredes públicas para los recursos expuestos a internet y subredes privadas para bases de datos y servidores internos. Controlas el enrutamiento con tablas de rutas. Para llegar a internet, una VPC usa un internet gateway, que permite el tráfico de entrada y salida para los recursos con direcciones públicas. Los recursos en subredes privadas salen a través de un NAT gateway, que permite conexiones salientes pero bloquea las entrantes no solicitadas. Para conectar una VPC con tu centro de datos se usa un VPN gateway o un enlace privado dedicado. En conjunto, estos son los gateways de nube que menciona el examen.

La seguridad en una VPC funciona por capas. Un grupo de seguridad (security group) es un firewall virtual con estado asociado a una instancia o interfaz individual: enumeras lo que se permite entrar y salir, y el tráfico de retorno se permite automáticamente. Una lista de control de acceso de red (NACL), en los proveedores que la ofrecen, se aplica a toda una subred y normalmente es sin estado, por lo que debes permitir ambas direcciones de forma explícita. Recuerda: security group = a nivel de instancia y con estado.

Los modelos de servicio describen cuánto administra el proveedor por ti. En Infraestructura como Servicio (IaaS) alquilas máquinas virtuales, almacenamiento y redes; tú administras el sistema operativo y todo lo que está encima. En Plataforma como Servicio (PaaS) el proveedor también ejecuta el sistema operativo y el entorno de ejecución, y tú despliegas tu código o base de datos. En Software como Servicio (SaaS) simplemente usas una aplicación terminada, como el correo web o un CRM. Este es el modelo de responsabilidad compartida: cuanto más te alejas de IaaS hacia SaaS, más responsabilidad tiene el proveedor, aunque tú siempre sigues siendo responsable de tus datos y del acceso de los usuarios.

Los modelos de implementación describen para quién es la nube. Una nube pública es infraestructura compartida que se ofrece a cualquiera. Una nube privada está dedicada a una sola organización, en sus instalaciones (on premises) o alojada por terceros. Una nube híbrida combina la pública y la privada y mueve cargas de trabajo entre ellas. Una nube comunitaria la comparten organizaciones con necesidades comunes, como agencias gubernamentales. Las redes en la nube también traen términos como elasticidad (agregar o quitar recursos automáticamente según la demanda) y multitenencia o multitenancy (muchos clientes que comparten el mismo hardware físico, aislados de forma lógica).

Términos clave

NFV
Network functions virtualization (virtualización de funciones de red): ejecutar funciones de red como el enrutamiento y el firewall como software en lugar de hardware dedicado.
VPC
Virtual private cloud (nube privada virtual): una red lógicamente aislada y definida por el cliente dentro de un proveedor de nube pública.
Security group (grupo de seguridad)
Un firewall virtual con estado aplicado a instancias o interfaces en la nube que permite el tráfico entrante y saliente especificado.
NAT gateway
Un gateway de nube que permite a los recursos de subredes privadas hacer conexiones salientes a internet sin aceptar tráfico entrante no solicitado.
IaaS
Infrastructure as a Service (Infraestructura como Servicio): el cliente alquila cómputo, almacenamiento y red virtuales y administra el sistema operativo y lo que está encima.
Ejemplo real

Una startup crea una VPC con una subred pública para sus servidores web y una subred privada para su base de datos. El grupo de seguridad de los servidores web permite HTTPS desde cualquier lugar; el grupo de seguridad de la base de datos permite solo el puerto de la base de datos desde el grupo de los servidores web. La base de datos instala parches a través de un NAT gateway, pero no se puede acceder a ella desde internet.

Consejo para el examen: Asocia los modelos según quién administra el sistema operativo: en IaaS lo haces tú; en PaaS y SaaS lo hace el proveedor. SaaS es una aplicación terminada. El internet gateway permite entrada y salida; el NAT gateway permite solo salida.

Comprueba lo que sabes

Un desarrollador quiere desplegar código sin administrar servidores ni el sistema operativo. ¿Qué modelo de servicio le conviene?

PaaS, donde el proveedor administra la infraestructura, el sistema operativo y el entorno de ejecución.

¿Los grupos de seguridad son con estado o sin estado?

Con estado (stateful): el tráfico de retorno de las conexiones permitidas se permite automáticamente.

¿Qué componente de nube permite que los servidores de una subred privada descarguen actualizaciones sin ser accesibles desde internet?

Un NAT gateway.
