CompTIA Network+ N10-009

Seguridad de switches: port security, DHCP snooping, dynamic ARP inspection, BPDU guard

Los switches de acceso son donde se conectan los usuarios y los dispositivos, así que son el lugar natural para detener los ataques de capa 2 antes de que se propaguen. Los protocolos de capa 2, como ARP y DHCP, fueron diseñados para entornos de confianza y creen todo lo que escuchan, algo que los atacantes explotan. Cuatro funciones trabajan juntas para cerrar estas brechas, y Network+ espera que sepas cuál detiene cada ataque, cómo dependen unas de otras y cómo se ve su comportamiento ante violaciones cuando estás resolviendo problemas.

El port security limita qué direcciones MAC, y cuántas, pueden usar un puerto de switch. Puedes fijar una cantidad máxima de direcciones (por ejemplo una para una PC, o dos para un teléfono con una PC conectada detrás), definir de forma estática las MAC permitidas o usar el aprendizaje sticky, en el que el switch aprende las primeras direcciones MAC que ve y las guarda en la configuración en ejecución. Cuando ocurre una violación, el puerto toma una acción: protect (descarta en silencio las tramas infractoras), restrict (las descarta, registra la violación y la contabiliza) o shutdown (pone el puerto en estado err-disabled, el valor predeterminado habitual). El port security vence la inundación de MAC e impide que los usuarios conecten switches no autorizados o intercambien dispositivos. Las direcciones MAC pueden falsificarse, así que el port security es un control básico, no una autenticación fuerte; 802.1X es más fuerte.

El DHCP snooping protege contra los servidores DHCP no autorizados. Marcas como confiables los puertos que llevan a los servidores DHCP o relays legítimos, normalmente los enlaces ascendentes; todos los demás puertos son no confiables. El switch descarta los mensajes de servidor DHCP (ofertas y confirmaciones) que llegan por puertos no confiables, así que un servidor no autorizado conectado a un puerto de usuario no puede entregar direcciones. El DHCP snooping también puede limitar la tasa de solicitudes DHCP en los puertos no confiables para resistir los ataques de agotamiento. Como beneficio adicional, construye una tabla de vinculaciones (binding table) que registra qué dirección MAC recibió qué dirección IP, en qué puerto y VLAN, y por cuánto tiempo.

Dynamic ARP inspection (DAI, inspección dinámica de ARP) usa esa tabla de vinculaciones de DHCP snooping para detener el envenenamiento de ARP. En los puertos no confiables, el switch compara cada mensaje ARP con la tabla; si un host reclama una asociación IP-MAC que no se le asignó, por ejemplo haciéndose pasar por la puerta de enlace predeterminada, el switch descarta el paquete y lo registra. Los dispositivos con direcciones estáticas no tienen vinculación DHCP, así que necesitan entradas estáticas o ACL de ARP, o su tráfico ARP legítimo será descartado. Una función relacionada, IP source guard, usa la misma tabla para bloquear paquetes con direcciones IP de origen falsificadas. La dependencia importa: habilita DHCP snooping primero, o DAI no tendrá contra qué comparar.

BPDU guard protege el spanning tree. Los puertos de acceso conectados a dispositivos finales se configuran como puertos de borde con PortFast para que se activen de inmediato. Los dispositivos finales nunca envían BPDU, así que si llega una a ese puerto, alguien conectó un switch o algo se está comportando mal. BPDU guard pone el puerto en err-disabled al instante, lo que evita bucles e impide que un atacante intente convertirse en el root bridge. Root guard es una función relacionada para puertos que pueden conectarse a switches pero que nunca deben llevar hacia la raíz. Esta es una configuración de capa de acceso que combina las cuatro funciones:

ip dhcp snooping
ip dhcp snooping vlan 10,20
ip arp inspection vlan 10,20
interface g1/0/48
 description Uplink to distribution
 ip dhcp snooping trust
 ip arp inspection trust
interface range g1/0/1 - 24
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
 switchport port-security violation restrict
 switchport port-security mac-address sticky
 spanning-tree portfast
 spanning-tree bpduguard enable

Un puerto en err-disabled permanece apagado hasta que un administrador lo vuelve a habilitar (con shutdown y luego no shutdown) o lo hace un temporizador de recuperación automática, así que a menudo encontrarás este estado al resolver problemas: show interfaces status muestra el puerto como err-disabled, y el registro indica la función que lo provocó, como una violación de port security o un evento de BPDU guard. Encuentra y elimina siempre la causa antes de volver a habilitarlo. Errores comunes: olvidar marcar como confiable el enlace ascendente, de modo que se descartan las ofertas DHCP legítimas y todos los clientes reciben una dirección APIPA; habilitar DAI sin DHCP snooping; fijar el máximo de port security en uno en puertos con teléfonos IP y PC; y habilitar BPDU guard en puertos que se conectan legítimamente a otros switches.

Las preguntas del examen asocian ataques con funciones. 'Miles de direcciones MAC en un puerto' o 'el switch inunda como un hub' significan port security. 'Clientes que reciben un rango de IP o una puerta de enlace incorrectos' significa DHCP snooping. 'MAC de la puerta de enlace falsificada' u 'on-path mediante ARP' significan dynamic ARP inspection. 'Un usuario conectó un switch pequeño', 'puerto en err-disabled después de conectar un dispositivo' o 'switch no autorizado que intenta convertirse en raíz' significan BPDU guard (o root guard). '¿De qué función depende DAI?' es DHCP snooping.

Términos clave

Port security
Una función del switch que limita y controla las direcciones MAC permitidas en un puerto.
MAC sticky (sticky MAC)
Una opción de port security en la que el switch aprende y guarda de forma dinámica las direcciones MAC permitidas.
Modo de violación (violation mode)
La acción que toma el port security ante una violación: protect, restrict o shutdown.
DHCP snooping
Una función del switch que permite los mensajes de servidor DHCP solo en puertos confiables y construye una tabla de vinculaciones.
Dynamic ARP inspection
Una función del switch que valida los paquetes ARP contra vinculaciones confiables para evitar el envenenamiento de ARP.
BPDU guard
Una función que pone en err-disabled un puerto de borde si recibe una BPDU.
Err-disabled
Un estado del puerto en el que el switch lo apagó debido a un error o una violación detectados.
Ejemplo real

Un pasante conecta un switch pequeño debajo de su escritorio para agregar una segunda PC. El puerto de acceso tiene BPDU guard habilitado, y el switch pequeño envía BPDU, así que el puerto pasa de inmediato a err-disabled y ambas PC pierden la conectividad. La mesa de ayuda ve el mensaje de registro que nombra a BPDU guard, retira el switch, vuelve a habilitar el puerto y explica la política. La semana siguiente, los registros de DAI del mismo piso muestran respuestas ARP descartadas de una laptop que afirmaba ser la puerta de enlace, y el equipo de seguridad encuentra y limpia el malware que tenía antes de que se interceptara cualquier tráfico.

Consejo para el examen: Ataque y defensa: inundación de MAC -> port security; DHCP no autorizado -> DHCP snooping; envenenamiento de ARP -> dynamic ARP inspection (que depende de DHCP snooping); switch no autorizado o bucle en un puerto de borde -> BPDU guard.

Comprueba lo que sabes

Después de habilitar DHCP snooping en un switch de acceso, todos los clientes reciben una dirección 169.254. ¿Qué se omitió probablemente?

No se marcó como confiable el enlace ascendente hacia el servidor DHCP o el relay, así que el switch descartó las ofertas DHCP legítimas.

Un escritorio tiene un teléfono IP con una PC conectada a él, y el puerto pasa a err-disabled cada vez que ambos están encendidos. El port security está configurado con máximo 1. ¿Qué debe cambiar?

Subir el máximo a 2 (o más si hace falta) para que se permitan las direcciones MAC tanto del teléfono como de la PC.

DAI está habilitado y de repente un servidor con IP estática no puede comunicarse. ¿Por qué?

No tiene vinculación en DHCP snooping, así que DAI descarta sus mensajes ARP; agrega una vinculación estática o una ACL de ARP para él, o marca el puerto como confiable si corresponde.

¿Qué modo de violación elegirías si quieres bloquear los dispositivos no autorizados pero mantener funcionando el dispositivo legítimo y registrar el evento?

Restrict, que descarta las tramas de las MAC no autorizadas y registra la violación sin apagar todo el puerto.
