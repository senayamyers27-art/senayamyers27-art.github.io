CompTIA Network+ N10-009

Monitoreo: versiones de SNMP, traps, MIB, datos de flujo, captura de paquetes, líneas base, agregación de registros y syslog, integración por API

El monitoreo te dice cómo se está comportando la red antes de que los usuarios llamen. Combina varias fuentes de datos, cada una con un nivel de detalle distinto: estadísticas de los dispositivos mediante SNMP, resúmenes de conversaciones mediante datos de flujo, paquetes completos mediante captura, y eventos mediante registros (logs). Saber cuál usar para cada pregunta es una habilidad central de Network+.

SNMP (Simple Network Management Protocol) permite que una estación de administración de red (NMS, el manager) lea estadísticas de los agentes en los dispositivos. El manager consulta (polling) a los agentes en UDP 161 con solicitudes get, y puede cambiar configuraciones con solicitudes set; los agentes envían traps no solicitadas (o informs con confirmación) al manager en UDP 162 cuando ocurren eventos, como la caída de una interfaz. Los datos que expone un agente se describen en una MIB (Management Information Base), una base de datos jerárquica de variables, cada una identificada por un OID (object identifier), como el contador de bytes recibidos en una interfaz. Las versiones importan para la seguridad. SNMPv1 y v2c se autentican con una community string enviada en texto claro (los valores predeterminados como 'public' y 'private' deben cambiarse); v2c agregó la recuperación masiva (bulk) y los contadores de 64 bits. SNMPv3 agrega autenticación real basada en usuarios y cifrado, con los niveles de seguridad noAuthNoPriv, authNoPriv y authPriv. Usa SNMPv3 siempre que sea posible.

Los datos de flujo (flow data) resumen las conversaciones en lugar de su contenido. NetFlow, IPFIX y sFlow exportan a un colector registros que contienen las direcciones y puertos de origen y destino, el protocolo, los conteos de bytes y paquetes y marcas de tiempo. Los datos de flujo responden '¿quién está hablando con quién y cuánto?', lo que los hace ideales para encontrar a los mayores generadores de tráfico (top talkers), planificar la capacidad y detectar tráfico inusual como la exfiltración de datos, con mucho menos almacenamiento que las capturas completas.

La captura de paquetes registra los paquetes completos, incluidas las cargas útiles, usando herramientas como Wireshark o tcpdump. Ofrece el mayor detalle para diagnosticar problemas de protocolos, pero produce enormes volúmenes de datos y puede capturar información sensible. Para capturar tráfico que no está destinado a tu equipo en una red conmutada, usa la duplicación de puertos (port mirroring, un puerto SPAN) o un tap de red.

Una línea base registra el comportamiento normal, como la utilización típica, las tasas de error, la CPU y la latencia en distintos momentos, para que las alertas se activen ante desviaciones significativas y las anomalías resalten.

Los registros (logs) anotan eventos. Syslog es la forma estándar en que los dispositivos de red envían mensajes de registro a un colector central, en UDP 514 por defecto. Cada mensaje tiene una facility (el tipo de origen) y un nivel de severidad del 0 al 7: 0 Emergency, 1 Alert, 2 Critical, 3 Error, 4 Warning, 5 Notice, 6 Informational, 7 Debug; los números más bajos son más graves. La agregación de registros reúne los registros de muchas fuentes en un solo lugar, los normaliza y los conserva para las búsquedas y los requisitos de retención. Un sistema SIEM (security information and event management) va más allá, correlacionando eventos entre fuentes y alertando sobre incidentes de seguridad. Una hora precisa obtenida por NTP en cada dispositivo es esencial para correlacionar los registros.

El monitoreo moderno usa cada vez más las API. Los dispositivos y controladores exponen API REST, y la telemetría en streaming envía los datos en lugar de esperar a que se consulten. La integración por API permite que las plataformas de monitoreo, los sistemas de tickets y las herramientas de automatización compartan datos, por ejemplo abriendo automáticamente un ticket cuando se dispara una alerta.

Términos clave

MIB
Management Information Base: el conjunto estructurado de variables que expone un agente SNMP, cada una identificada por un OID.
SNMP trap
Un mensaje no solicitado de un agente SNMP al manager, enviado en UDP 162, que informa un evento.
NetFlow
Una tecnología de exportación de flujos que resume las conversaciones de tráfico para su análisis sin capturar las cargas útiles.
Syslog severity (severidad de syslog)
Un nivel de 0 (Emergency) a 7 (Debug) que indica qué tan grave es un mensaje de registro.
SIEM
Security information and event management: un sistema que agrega y correlaciona registros para detectar eventos de seguridad.
Ejemplo real

Los usuarios dicen que la WAN está lenta todas las tardes. Las gráficas de SNMP muestran el enlace al 95 por ciento de utilización desde las 2 p. m., muy por encima de la línea base. Los datos de NetFlow muestran un host que envía grandes volúmenes a un proveedor de almacenamiento en la nube, que resulta ser un trabajo de respaldo mal configurado. No fue necesaria ninguna captura de paquetes.

Consejo para el examen: SNMPv3 es la única versión con cifrado y autenticación de usuarios. Las consultas usan UDP 161 y las traps UDP 162. Los datos de flujo responden quién habló con quién y cuánto; la captura de paquetes muestra el contenido completo. La severidad 0 de syslog es la más grave.

Comprueba lo que sabes

¿Qué versión de SNMP ofrece autenticación y cifrado?

SNMPv3.

¿Cuál es la diferencia entre los datos de flujo y una captura de paquetes?

Los datos de flujo resumen las conversaciones (direcciones, puertos, conteos de bytes); una captura de paquetes registra el contenido completo de los paquetes.

¿Qué nivel de syslog es más grave, el 2 o el 6?

El nivel 2 (Critical); los números más bajos son más graves, y el 6 es Informational.
