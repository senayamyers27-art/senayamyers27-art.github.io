CompTIA Network+ N10-009

Reglas de seguridad: ACL, denegación implícita, filtrado de URL y de contenido, zonas y subredes filtradas

Las reglas de seguridad deciden qué tráfico se permite entre las partes de una red. Aparecen como listas de control de acceso en routers y switches, como políticas en los firewalls y como filtros en los proxies web. Escribirlas correctamente, y entender cómo se procesan, es esencial tanto para el examen como para la vida real.

Una lista de control de acceso (ACL, access control list) es una lista ordenada de sentencias permit y deny. Cada regla coincide con criterios como la dirección IP de origen y destino, el protocolo y los números de puerto. En los dispositivos estilo Cisco, una ACL estándar filtra solo por la dirección de origen, mientras que una ACL extendida coincide con el origen, el destino, el protocolo y los puertos; una pauta común es colocar las ACL extendidas cerca del origen y las ACL estándar cerca del destino. Las ACL se aplican a una interfaz en una dirección, de entrada o de salida, y solo se aplica una ACL por interfaz, por dirección y por protocolo.

El orden importa muchísimo. El dispositivo lee las reglas de arriba hacia abajo y actúa en la primera coincidencia; las reglas posteriores no se revisan. Por eso las reglas específicas deben ir antes que las generales. Si pones 'permit any' primero, nada de lo que venga después importa. Al final de cada ACL hay una denegación implícita (implicit deny) invisible: todo el tráfico que no coincide con ninguna regla se descarta. Eso hace que los firewalls denieguen por defecto por diseño, lo cual es seguro, pero también significa que si creas una ACL que contiene solo sentencias deny, bloqueas todo, porque el tráfico permitido nunca recibe un permit explícito. Muchos administradores agregan al final un 'deny any' explícito con registro para poder ver lo que se está descartando. Los firewalls con estado rastrean las sesiones, así que normalmente escribes reglas solo para la dirección que inicia la conexión.

El filtrado a nivel de contenido va más allá de las direcciones y los puertos. El filtrado de URL permite o bloquea el acceso web según la dirección del sitio o su categoría, como apuestas, malware o redes sociales, normalmente en un proxy, un firewall de nueva generación o un secure web gateway. El filtrado de contenido inspecciona lo que realmente se transfiere, bloqueando tipos de archivo, malware o datos que coinciden con patrones sensibles. Como la mayor parte del tráfico web está cifrado, la inspección profunda a menudo requiere la inspección TLS, que descifra y vuelve a cifrar el tráfico usando un certificado interno de confianza, lo que plantea consideraciones de privacidad que deben estar cubiertas por una política.

Los firewalls organizan las interfaces en zonas de seguridad con distintos niveles de confianza, como inside (confiable), outside (internet no confiable) y una o más zonas intermedias. Las políticas controlan el tráfico entre zonas. Una subred filtrada (screened subnet), antes llamada DMZ (zona desmilitarizada), es una zona para los servidores que deben ser accesibles desde internet, como los servidores web públicos, de retransmisión de correo o DNS. Los usuarios de internet solo pueden llegar a esos servicios específicos de la subred filtrada, y los servidores que están allí tienen un acceso muy limitado a la red interna. Si un servidor público es comprometido, el atacante sigue separado de los sistemas internos. Una subred filtrada puede construirse con un firewall de tres interfaces o con dos firewalls en serie.

Mantén los conjuntos de reglas documentados, revisados y depurados con regularidad, porque las reglas viejas sin uso se acumulan y crean aberturas inesperadas.

Términos clave

ACL
Access control list (lista de control de acceso): un conjunto ordenado de reglas permit y deny que se usa para filtrar el tráfico.
Implicit deny (denegación implícita)
La regla final invisible de una ACL o política de firewall que descarta todo el tráfico no permitido explícitamente.
Screened subnet (subred filtrada)
Una zona de red, antes llamada DMZ, que aloja los servicios expuestos a internet separados de la red interna.
URL filtering (filtrado de URL)
Permitir o bloquear el acceso web según la dirección del sitio o su categoría.
Security zone (zona de seguridad)
Un grupo de interfaces o redes con un nivel de confianza común, que se usa para definir la política del firewall.
Ejemplo real

Un administrador agrega una ACL para bloquear un host problemático: 'deny host 10.1.1.50'. De inmediato, toda la subred pierde el acceso, porque la denegación implícita bloquea todo lo demás. Agregar 'permit ip any any' después de la línea deny restablece el acceso para todos excepto 10.1.1.50.

Consejo para el examen: Las ACL se procesan de arriba hacia abajo, gana la primera coincidencia y toda lista termina con una denegación implícita. Una lista que contiene solo sentencias deny bloquea todo. Los servidores públicos van en la subred filtrada (DMZ), no en la red interna.

Comprueba lo que sabes

¿Por qué las reglas específicas de una ACL deben colocarse por encima de las generales?

Porque el procesamiento se detiene en la primera coincidencia, así que una regla general colocada arriba coincidiría primero y la regla específica nunca se usaría.

¿Qué pasa con el tráfico que no coincide con ninguna regla de una ACL?

La denegación implícita lo descarta.

¿Dónde debe colocar una empresa su servidor web público?

En una subred filtrada (DMZ), separada de la red interna mediante reglas de firewall.
