CompTIA Network+ N10-009

Gestión de cambios y gestión de la configuración: líneas base, configuraciones doradas, respaldos

Muchas interrupciones no las causa una falla de hardware sino los cambios: un comando mal escrito, una actualización sin probar, una regla agregada a toda prisa. La gestión de cambios y la gestión de la configuración son los procesos que mantienen los cambios controlados y las configuraciones conocidas y recuperables.

La gestión de cambios (change management) es el proceso formal para proponer, aprobar, implementar y revisar cambios. Un flujo típico: alguien presenta una solicitud de cambio que describe qué cambiará, por qué, el riesgo y el impacto, los pasos de implementación, un plan de pruebas y un plan de reversión (rollback o backout). Un comité asesor de cambios (CAB, change advisory board) o un aprobador lo revisa. Los cambios aprobados se programan en una ventana de mantenimiento, normalmente en horarios de poco uso, y se notifica a los usuarios afectados. Después de la implementación, el cambio se verifica, se actualiza la documentación y se cierra el cambio. Los cambios de emergencia también necesitan aprobación y documentación, solo que más rápido. Los cambios estándar, de bajo riesgo y repetibles, pueden estar aprobados de antemano. El objetivo no es la burocracia, sino menos sorpresas y un registro de lo que cambió cuando algo se rompe.

La gestión de la configuración (configuration management) consiste en conocer y controlar la configuración de cada dispositivo. Una línea base (baseline) es un estado de referencia documentado y aprobado. Una línea base de configuración registra cómo debería estar configurado un dispositivo; una línea base de rendimiento registra el comportamiento normal, como el ancho de banda típico, el uso de CPU y la latencia, para que puedas reconocer cuándo algo es anormal. Una configuración dorada (golden config) es una plantilla estándar aprobada para un tipo o rol de dispositivo, como todos los switches de acceso, que incluye el hardening de seguridad y la configuración de registros, NTP, SNMP y AAA. Los dispositivos nuevos se construyen a partir de ella y los existentes se comparan con ella.

La deriva de configuración (configuration drift) ocurre cuando los dispositivos se alejan poco a poco de la línea base por arreglos puntuales y cambios no documentados. Las herramientas de monitoreo de configuración obtienen regularmente las configuraciones de los dispositivos, las comparan con la configuración dorada o con la versión anterior y alertan sobre las diferencias, de modo que se detectan los cambios no autorizados o accidentales. La infraestructura como código y la automatización reducen la deriva al aplicar la misma plantilla en todas partes.

Los respaldos hacen posible la recuperación. Respalda las configuraciones de los dispositivos de forma automática y regular, y después de cada cambio; guárdalas fuera del dispositivo, idealmente en un control de versiones para que puedas ver exactamente qué cambió y revertirlo. En muchos dispositivos de red, la configuración en ejecución (running configuration, en RAM) se pierde al reiniciar a menos que se guarde en la configuración de inicio (startup configuration, en NVRAM o flash), por ejemplo con copy running-config startup-config. Olvidar este paso es un error clásico que convierte un cambio exitoso en una interrupción después del siguiente ciclo de encendido. Respalda también las imágenes de firmware, las licencias y los certificados, y prueba las restauraciones periódicamente, porque un respaldo sin probar es solo una esperanza.

En conjunto, estas prácticas significan que cuando algo se rompe puedes responder rápidamente tres preguntas: qué cambió, cómo debería verse y cómo vuelvo a un estado conocido y funcional.

Términos clave

Change advisory board (comité asesor de cambios)
Un grupo que revisa, evalúa y aprueba los cambios propuestos.
Rollback plan (plan de reversión)
Los pasos documentados para devolver un sistema a su estado anterior si un cambio falla.
Golden configuration (configuración dorada)
Una plantilla de configuración estándar aprobada que se usa para construir y auditar los dispositivos de un rol determinado.
Baseline (línea base)
Una referencia documentada de la configuración o el rendimiento normal que se usa para comparar.
Running configuration (configuración en ejecución)
La configuración activa en la memoria de un dispositivo, que debe guardarse para que se conserve tras un reinicio.
Ejemplo real

Un ingeniero agrega una nueva VLAN a un switch de núcleo durante una ventana de mantenimiento aprobada, verifica la conectividad y guarda la running config en la startup. El respaldo nocturno de configuraciones registra el cambio en el control de versiones. Una semana después, el monitoreo señala que un switch de acceso ya no coincide con la configuración dorada: alguien habilitó Telnet. El equipo lo revierte y abre un incidente.

Consejo para el examen: Todo cambio necesita una solicitud aprobada, una ventana de mantenimiento y un plan de reversión. Línea base de configuración = cómo debería estar configurado; línea base de rendimiento = cómo se comporta normalmente. Guarda la running config o perderás los cambios al reiniciar.

Comprueba lo que sabes

¿Cuál es el propósito de un plan de reversión en una solicitud de cambio?

Restaurar rápidamente el estado funcional anterior si el cambio falla.

¿Qué es la deriva de configuración y cómo se detecta?

La divergencia gradual respecto a la configuración aprobada; se detecta comparando las configuraciones actuales con una línea base o una configuración dorada.

Un switch perdió un cambio reciente de VLAN después de un corte de energía. ¿Qué se omitió probablemente?

Guardar la configuración en ejecución en la configuración de inicio.
