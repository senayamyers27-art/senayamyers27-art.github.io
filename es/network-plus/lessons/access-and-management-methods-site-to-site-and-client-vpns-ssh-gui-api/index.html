CompTIA Network+ N10-009

Métodos de acceso y administración: VPN de sitio a sitio y de cliente, SSH, GUI, API, consola, jump box, en banda vs fuera de banda

Los administradores necesitan formas seguras de llegar a las redes y administrar los dispositivos, y necesitan una vía de entrada incluso cuando la propia red está rota. Network+ espera que conozcas las opciones y las ventajas y desventajas de seguridad de cada una.

Las redes privadas virtuales ofrecen acceso seguro a través de redes no confiables. Una VPN de sitio a sitio (site-to-site) conecta redes completas, como una sucursal con la sede central, mediante un túnel permanente entre dos gateways, normalmente firewalls o routers que usan IPsec; los usuarios no instalan nada. Una VPN de cliente a sitio (client-to-site o de acceso remoto) conecta un dispositivo individual a la red corporativa. Puede usar un cliente completo con IPsec o TLS, o una VPN sin cliente (clientless) a través de un portal en el navegador web que expone aplicaciones específicas por HTTPS. Las VPN de acceso remoto pueden ser de túnel completo o de túnel dividido, como se vio antes.

Para la administración de dispositivos, SSH (Secure Shell, TCP 22) es el estándar para el acceso por línea de comandos: cifra la sesión y admite autenticación basada en claves. Telnet debe deshabilitarse porque envía todo, incluidas las contraseñas, en texto claro. Muchos dispositivos también ofrecen una interfaz gráfica de usuario (GUI) a través de un navegador web; debe accederse solo por HTTPS, nunca por HTTP. Las API, normalmente API REST que usan JSON sobre HTTPS, permiten que las herramientas de automatización y los scripts configuren y consulten los dispositivos de forma programática, lo que escala mucho mejor que el trabajo manual por CLI y es la base de la infraestructura como código; el acceso por API debe usar tokens o claves con mínimo privilegio.

El puerto de consola ofrece acceso directo y local a la CLI de un dispositivo mediante una conexión serial, usando un cable rollover (de consola) o un cable de consola USB y un programa de terminal. Funciona incluso cuando el dispositivo no tiene configuración IP, por eso se usa para la configuración inicial y la recuperación. Protege el acceso por consola físicamente y con contraseñas.

Un jump box (servidor de salto o bastion host) es un sistema reforzado al que los administradores deben conectarse primero antes de llegar a las interfaces de administración. En lugar de permitir SSH a cada dispositivo desde cada laptop, lo permites solo desde el jump box, que está estrictamente controlado, usa MFA y registra las sesiones. Esto reduce la superficie de ataque y crea un registro de auditoría.

La administración en banda (in-band) usa la misma red que lleva el tráfico de los usuarios, por ejemplo SSH a la dirección IP de un switch en una VLAN de producción (idealmente una VLAN de administración dedicada). Es cómoda, pero si la red falla pierdes el acceso de administración justo cuando más lo necesitas. La administración fuera de banda (OOB, out-of-band) usa un camino separado que no depende de la red de producción, como una red de administración dedicada, un servidor de consolas conectado a los puertos de consola de los dispositivos o un módem celular para los sitios remotos. OOB te permite arreglar un router cuya mala configuración cortó su propio acceso en banda. Los sitios críticos suelen tener ambos.

Términos clave

Site-to-site VPN (VPN de sitio a sitio)
Una VPN que conecta de forma permanente dos redes a través de sus gateways.
Jump box
Un host intermediario reforzado que los administradores deben usar para acceder a las interfaces de administración de otros sistemas.
Out-of-band management (administración fuera de banda)
Administrar los dispositivos a través de un camino separado e independiente de la red de producción, como un servidor de consolas.
Console port (puerto de consola)
Un puerto serial de administración local que ofrece acceso a la CLI sin necesidad de conectividad de red.
Clientless VPN (VPN sin cliente)
Acceso remoto a través de un navegador web sobre TLS sin un cliente VPN dedicado.
Ejemplo real

Una ingeniera aplica una ACL que por accidente bloquea SSH hacia el router de una sucursal remota y se queda sin acceso. Como la sucursal tiene un servidor de consolas accesible a través de un módem LTE, se conecta fuera de banda, corrige la ACL mediante el puerto de consola del router y la sucursal vuelve a estar en línea en minutos.

Consejo para el examen: Si la pregunta dice que la red está caída pero aun así necesitas administrar el dispositivo, la respuesta es la administración fuera de banda (servidor de consolas, red separada, celular). Reemplaza Telnet por SSH y HTTP por HTTPS. Un jump box centraliza y audita el acceso administrativo.

Comprueba lo que sabes

¿Cuál es la ventaja clave de la administración fuera de banda?

Ofrece acceso incluso cuando la red de producción está caída o mal configurada.

¿Qué tipo de VPN conecta la red de una sucursal con la sede central sin software en los equipos de los usuarios?

Una VPN de sitio a sitio.

¿Por qué usar un jump box?

Limita el acceso de administración a un solo host reforzado y monitoreado, lo que reduce la superficie de ataque y proporciona un registro de auditoría.
