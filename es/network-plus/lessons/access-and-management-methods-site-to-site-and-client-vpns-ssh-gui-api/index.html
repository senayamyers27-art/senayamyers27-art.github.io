CompTIA Network+ N10-009

Métodos de acceso y administración: VPN de sitio a sitio y de cliente, SSH, GUI, API, consola, jump box, en banda vs fuera de banda

Los administradores necesitan formas seguras de llegar a las redes y administrar los dispositivos, y necesitan una vía de entrada incluso cuando la propia red está caída. Cada método de administración es también una posible vía de ataque, porque quien controla la interfaz de administración controla el dispositivo. Network+ espera que conozcas las opciones, cuándo usar cada una y sus compensaciones de seguridad: qué métodos cifran, cuáles escalan y cuáles siguen funcionando durante una interrupción.

Las redes privadas virtuales ofrecen acceso seguro a través de redes no confiables. Una VPN de sitio a sitio (site-to-site) conecta redes completas, como una sucursal con la oficina central o una oficina con una VPC en la nube, mediante un túnel permanente entre dos gateways, normalmente firewalls o routers que usan IPsec; los usuarios no instalan nada y a menudo ni saben que existe. Una VPN de cliente a sitio (de acceso remoto) conecta un dispositivo individual con la red corporativa. Puede usar un cliente completo con IPsec o TLS, o una VPN sin cliente (clientless) a través de un portal en el navegador web que expone aplicaciones específicas por HTTPS. Las VPN de acceso remoto pueden ser de túnel completo (todo el tráfico pasa por la VPN) o de túnel dividido (solo el tráfico corporativo), lo que compensa la capacidad de inspección frente al ancho de banda. El acceso remoto debe exigir MFA.

Para la administración de dispositivos, SSH (Secure Shell, TCP 22) es el estándar para el acceso por línea de comandos: cifra toda la sesión y admite autenticación basada en claves, que es más fuerte que las contraseñas. Telnet (TCP 23) debe deshabilitarse porque envía todo, incluidas las contraseñas, en texto claro. Muchos dispositivos ofrecen también una interfaz gráfica de usuario (GUI) a través de un navegador web; se debe acceder a ella solo por HTTPS, nunca por HTTP, e idealmente con un certificado emitido por una CA. Un hardening típico de las líneas de administración se ve así:

R1(config)# ip domain-name corp.example
R1(config)# crypto key generate rsa modulus 2048
R1(config)# ip ssh version 2
R1(config)# line vty 0 4
R1(config-line)# transport input ssh
R1(config-line)# access-class MGMT-ONLY in
R1(config-line)# login local

Las API, normalmente API REST que intercambian JSON por HTTPS, permiten que las herramientas de automatización y los scripts configuren y consulten dispositivos de forma programática, lo cual escala mucho mejor que el trabajo manual en la CLI a lo largo de cientos de dispositivos y es la base de la infraestructura como código. El acceso por API debe usar tokens o claves con mínimo privilegio, almacenados de forma segura y no dentro de los scripts. El puerto de consola proporciona acceso directo y local a la CLI de un dispositivo mediante una conexión serial, usando un cable rollover (de consola) o un cable de consola USB y un programa de terminal. Funciona incluso cuando el dispositivo no tiene configuración IP, por eso se usa para la configuración inicial, la recuperación de contraseñas y la recuperación ante desastres. Protege el acceso por consola físicamente, con contraseñas y con tiempos de espera por inactividad.

Un jump box (servidor de salto o bastion host) es un sistema endurecido al que los administradores deben conectarse primero antes de llegar a las interfaces de administración. En lugar de permitir SSH a cada dispositivo desde cualquier laptop, lo permites solo desde la dirección del jump box (la ACL del ejemplo anterior hace exactamente eso). El jump box está estrictamente controlado, actualizado, exige MFA y registra o graba las sesiones. Esto reduce la superficie de ataque a un solo host bien protegido y crea un registro de auditoría de quién hizo qué. En entornos de nube, la misma idea aparece como un bastion host en una subred pública que da acceso a servidores en subredes privadas.

La administración en banda (in-band) usa la misma red que transporta el tráfico de los usuarios, por ejemplo SSH a la dirección IP de un switch, idealmente en una VLAN de administración dedicada. Es cómoda y económica, pero si la red falla, o si un cambio corta tu propio acceso, pierdes la administración justo cuando más la necesitas. La administración fuera de banda (OOB, out-of-band) usa una ruta separada que no depende de la red de producción, como una red de administración dedicada, un servidor de consolas (servidor de terminales) conectado a los puertos de consola de muchos dispositivos, o un módem celular en un sitio remoto. OOB te permite reparar un router cuya mala configuración cortó su propio acceso en banda. Los sitios críticos suelen tener ambas. Errores comunes: dejar Telnet o HTTP habilitados junto a SSH y HTTPS, permitir la administración desde cualquier dirección, tratar una VLAN de administración como fuera de banda (sigue pasando por los switches de producción) y olvidar que los puertos de consola necesitan protección física.

Palabras clave del examen: 'la red está caída pero debes llegar al dispositivo' o 'te bloqueaste a ti mismo con una ACL' significa administración fuera de banda; 'configuración inicial de un switch nuevo sin IP' significa consola; 'automatizar la configuración de muchos dispositivos' significa API; 'punto de entrada único y controlado para los administradores' significa jump box; 'conectar redes de sucursales de forma permanente' significa VPN de sitio a sitio; 'acceder a aplicaciones web desde un navegador sin cliente' significa VPN sin cliente; 'CLI cifrada' significa SSH.

Términos clave

VPN de sitio a sitio (site-to-site VPN)
Una VPN que conecta de forma permanente dos redes a través de sus gateways.
VPN sin cliente (clientless VPN)
Acceso remoto a través de un navegador web mediante TLS, sin un cliente VPN dedicado.
SSH
Secure Shell: acceso remoto cifrado por línea de comandos en TCP 22, que reemplaza a Telnet.
API
Interfaz de programación de aplicaciones: una forma programática, a menudo REST sobre HTTPS, para que las herramientas configuren y consulten dispositivos.
Puerto de consola (console port)
Un puerto serial local de administración que da acceso a la CLI sin necesidad de conectividad de red.
Jump box
Un host intermediario endurecido que los administradores deben usar para acceder a las interfaces de administración de otros sistemas.
Administración fuera de banda (out-of-band management)
Administrar dispositivos mediante una ruta separada e independiente de la red de producción, como un servidor de consolas.
Ejemplo real

Una ingeniera aplica una ACL que por accidente bloquea el SSH hacia el router de una sucursal remota, y queda fuera de la administración en banda. Como la sucursal tiene un servidor de consolas accesible mediante un módem LTE, se conecta fuera de banda, inicia sesión por el puerto de consola del router y corrige la ACL, y la sucursal vuelve a estar en línea en pocos minutos. La revisión posterior al cambio agrega un paso que exige programar una reversión automática cuando se modifiquen ACL de administración de forma remota. También confirma que la administración rutinaria debe pasar por el jump box, que graba cada sesión.

Consejo para el examen: Si la pregunta dice que la red está caída pero aun así necesitas administrar el dispositivo, la respuesta es la administración fuera de banda (servidor de consolas, red separada, celular). Reemplaza Telnet por SSH y HTTP por HTTPS. Un jump box centraliza y audita el acceso de los administradores.

Comprueba lo que sabes

El tráfico de administración usa una VLAN de administración dedicada en los switches de producción. ¿Es eso administración fuera de banda? ¿Por qué?

No. Sigue siendo en banda, porque depende de los mismos switches y enlaces que la producción; si estos fallan, el acceso de administración también falla.

Llega un switch nuevo con la configuración en blanco. ¿Qué método de acceso debes usar primero y por qué?

El puerto de consola, porque el switch todavía no tiene dirección IP ni credenciales configuradas para el acceso por SSH, GUI o API.

Seguridad quiere reducir la cantidad de hosts que pueden hacer SSH a los dispositivos de red y conservar un registro de las sesiones de administración. ¿Qué diseño cumple ambos objetivos?

Un jump box: restringe las ACL de administración de los dispositivos a su dirección, exige MFA en él y registra o graba las sesiones que maneja.

Un equipo debe cambiar la configuración de NTP en 400 switches de forma coherente. ¿Qué método de administración es el más adecuado?

Una API o una herramienta de automatización que use las API de los dispositivos, que aplica el cambio de forma programática y coherente en lugar de iniciar sesión en cada switch.
