CompTIA Network+ N10-009

NAT y PAT, redundancia del primer salto (FHRP/VRRP/HSRP), subinterfaces

La traducción de direcciones de red (NAT) reescribe las direcciones IP a medida que los paquetes pasan por un router o firewall. Su tarea principal es permitir que los hosts con direcciones privadas del RFC 1918 lleguen a internet usando direcciones públicas, lo que ahorra el escaso espacio IPv4 y oculta el direccionamiento interno. El router mantiene una tabla de traducción para que el tráfico de retorno se asocie con el host interno correcto. NAT se configura en el dispositivo situado en el límite entre la red interna (privada) y la externa (pública), normalmente el router o firewall de borde.

Existen varias formas. La NAT estática asocia de forma permanente una dirección privada con una dirección pública, y se usa cuando un servidor interno debe ser accesible desde afuera. La NAT dinámica asocia direcciones privadas con direcciones públicas tomadas de un grupo (pool) por orden de llegada; cuando el grupo se agota, los nuevos hosts no pueden conectarse. La traducción de direcciones de puerto (PAT), también llamada NAT overload, asocia muchas direcciones privadas con una sola dirección pública traduciendo también el puerto de origen, de modo que cada conexión interna recibe un par único de dirección pública y puerto. PAT es lo que hace cualquier router doméstico y la mayoría de los bordes corporativos. El reenvío de puertos (port forwarding) es una regla estática que envía el tráfico entrante de un puerto público determinado a un host interno, por ejemplo TCP 443 público hacia un servidor web interno.

Este es PAT paso a paso. La PC A (10.0.0.5) abre una conexión desde el puerto de origen 51000 hacia un servidor web. El router reescribe el origen con su dirección pública 203.0.113.10 y, si es necesario, un nuevo puerto como el 40001, y registra la asociación. La PC B (10.0.0.6) también usa el puerto de origen 51000; el router le asigna 203.0.113.10:40002. Cuando llegan respuestas para el puerto 40001, el router consulta la tabla y las envía a 10.0.0.5:51000. Términos del router que puedes ver: inside local es la dirección privada del host interno, inside global es la dirección pública a la que se traduce y outside global es la dirección real del host de internet.

R1# show ip nat translations
Pro  Inside global        Inside local      Outside global
tcp  203.0.113.10:40001   10.0.0.5:51000    198.51.100.7:443
tcp  203.0.113.10:40002   10.0.0.6:51000    198.51.100.7:443
tcp  203.0.113.20:443     10.0.0.50:443     ---

La última línea de arriba es una asociación estática para un servidor web interno. NAT rompe el direccionamiento verdaderamente de extremo a extremo, lo que complica algunos protocolos como IPsec (de ahí NAT traversal en UDP 4500) y SIP, y no es un control de seguridad por sí mismo, aunque como efecto secundario bloquea las conexiones entrantes no solicitadas. Ahora considera la puerta de enlace predeterminada. Cada host tiene configurada una sola puerta de enlace predeterminada, y si ese router falla, los hosts pierden el acceso más allá de su subred aunque exista un segundo router. Un protocolo de redundancia del primer salto (FHRP) resuelve esto permitiendo que dos o más routers compartan una dirección IP virtual y una dirección MAC virtual. Los hosts usan la IP virtual como puerta de enlace; un router está activo y responde a ARP por ella, y si falla, un router en espera toma la dirección virtual en cuestión de segundos, sin reconfigurar ningún host.

HSRP (Hot Standby Router Protocol) es propietario de Cisco, con roles activo y en espera (standby). VRRP (Virtual Router Redundancy Protocol) es el estándar abierto, con roles maestro y de respaldo, e incluso puede usar la dirección de una interfaz real del router como IP virtual. Ambos eligen el router activo según una prioridad configurable (gana la más alta), intercambian mensajes hello para detectar fallas y admiten la preferencia (preemption), que permite que un router de mayor prioridad recupere el rol cuando se restablece. Sin preferencia, el respaldo conserva el rol incluso después de que regresa el original. GLBP es otra opción de Cisco que además balancea la carga entre routers. El seguimiento de interfaces (interface tracking) puede reducir la prioridad de un router si su enlace ascendente falla, de modo que un router con el enlace WAN caído cede el rol de puerta de enlace a su par.

Una subinterfaz es una interfaz lógica creada sobre una interfaz física, como GigabitEthernet0/0.10. El uso clásico es el router on a stick: un solo puerto del router se conecta a un troncal del switch, y cada subinterfaz se etiqueta con un ID de VLAN usando encapsulamiento 802.1Q y recibe una dirección IP para actuar como puerta de enlace de esa VLAN. Así el router enruta entre VLAN por un solo cable, por ejemplo interface g0/0.10, encapsulation dot1Q 10, ip address 192.168.10.1 255.255.255.0. Es económico y simple, aunque el enlace único puede convertirse en un cuello de botella, por lo que las redes más grandes usan switches de capa 3 con SVI. Errores comunes: olvidar que el lado del switch debe ser troncal, poner un número de VLAN que no coincide en el encapsulamiento y dar a los hosts como puerta de enlace la dirección física de un router en lugar de la IP virtual del FHRP.

Palabras clave del examen: 'muchos usuarios, una IP pública' significa PAT; 'el servidor debe ser accesible desde internet en una dirección fija' significa NAT estática o reenvío de puertos; 'grupo agotado' significa NAT dinámica. 'Redundancia de la puerta de enlace', 'IP virtual' y 'los hosts no cambian su configuración' significan FHRP, donde 'estándar abierto' apunta a VRRP y 'propietario de Cisco' a HSRP. 'Enrutamiento entre VLAN con una sola interfaz de router' significa router on a stick con subinterfaces.

Términos clave

PAT (traducción de direcciones de puerto)
Asocia muchas direcciones privadas con una sola dirección pública usando puertos de origen únicos.
NAT estática (static NAT)
Una asociación fija uno a uno entre una dirección IP privada y una pública.
Reenvío de puertos (port forwarding)
Una regla estática que envía el tráfico entrante de un puerto público específico a un host y puerto internos elegidos.
Inside global
La dirección pública que representa a un host interno después de la traducción.
FHRP (protocolo de redundancia del primer salto)
Permite que varios routers compartan una IP virtual de puerta de enlace para que los hosts mantengan la conectividad si uno falla.
VRRP
Virtual Router Redundancy Protocol: el FHRP de estándar abierto, con routers maestro y de respaldo.
Subinterfaz (subinterface)
Una interfaz lógica sobre un puerto físico, comúnmente etiquetada con una VLAN para el enrutamiento router on a stick.
Ejemplo real

Una oficina tiene dos routers configurados con VRRP que comparten la puerta de enlace virtual 192.168.1.1, y cada PC usa esa dirección como puerta de enlace predeterminada. El principal tiene prioridad 120 y la preferencia habilitada; el secundario tiene prioridad 100. Cuando el principal se queda sin energía, el secundario toma la IP virtual en cuestión de segundos y los usuarios siguen navegando, mientras PAT en ambos routers traduce el tráfico de todos a la dirección pública de la oficina. Cuando el principal regresa, la preferencia le permite recuperar automáticamente el rol de maestro.

Consejo para el examen: PAT = muchos a uno usando puertos. NAT estática = uno a uno, usada para servidores accesibles desde afuera. HSRP es solo de Cisco; VRRP es el estándar abierto. Router on a stick usa subinterfaces con etiquetas 802.1Q.

Comprueba lo que sabes

Una empresa tiene 300 empleados pero solo 5 IP públicas configuradas como grupo de NAT dinámica, y en horas de mucho uso algunos usuarios no pueden llegar a internet al azar. ¿Por qué y qué lo soluciona?

La NAT dinámica le da a cada host activo una dirección pública completa, así que el grupo de 5 se agota; configurar PAT (overload) permite que todos los hosts compartan direcciones usando puertos únicos.

Dos routers ejecutan HSRP, pero después de que el router activo que falló vuelve, el de espera sigue reenviando el tráfico. ¿Por qué?

La preferencia (preemption) no está habilitada, así que el router recuperado, con mayor prioridad, no recupera el rol activo.

Los usuarios de la VLAN 20 no pueden llegar a otras VLAN en un diseño router on a stick, pero la VLAN 10 funciona. Menciona dos causas probables.

La subinterfaz del router para la VLAN 20 tiene el número de VLAN dot1Q o la IP incorrectos, o la VLAN 20 no está permitida en el troncal del switch hacia el router.

¿Por qué los hosts usan la IP virtual en lugar de la dirección propia de cualquiera de los routers cuando hay un FHRP configurado?

La IP virtual se mueve al router que esté activo, así que los hosts conservan la misma puerta de enlace durante una conmutación por error; una dirección física desaparecería junto con su router.
