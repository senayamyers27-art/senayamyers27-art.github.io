CompTIA Network+ N10-009

DNS: tipos de registros (A, AAAA, CNAME, MX, TXT, NS, PTR, SOA), zonas, recursivo vs autoritativo, DNSSEC, DoH/DoT, archivo hosts

El Domain Name System (DNS) traduce los nombres que las personas recuerdan, como www.example.com, a las direcciones IP que usan las computadoras. Casi toda conexión empieza con una consulta DNS, así que cuando DNS falla, los usuarios dicen 'se cayó internet' aunque la red esté bien. DNS usa el puerto 53, UDP para la mayoría de las consultas y TCP para las transferencias de zona y las respuestas grandes.

Los datos de DNS viven en registros de recursos (resource records). Un registro A asocia un nombre a una dirección IPv4; un registro AAAA asocia un nombre a una dirección IPv6. Un registro CNAME (canonical name) es un alias que hace que un nombre apunte a otro nombre, como www apuntando al nombre de un balanceador de carga. Un registro MX (mail exchanger) enumera los servidores de correo de un dominio, con valores de preferencia en los que los números más bajos se intentan primero. Un registro TXT contiene texto arbitrario, muy usado para la seguridad del correo (políticas SPF, DKIM y DMARC) y para demostrar la propiedad de un dominio ante servicios en la nube. Un registro NS (name server) nombra los servidores autoritativos de una zona. Un registro PTR (pointer) hace la búsqueda inversa, asociando una dirección IP de vuelta a un nombre, y se guarda en zonas especiales como in-addr.arpa para IPv4. El registro SOA (start of authority) está en la parte superior de cada zona y contiene el servidor primario, el contacto del administrador, un número de serie y temporizadores que controlan cómo se actualizan los servidores secundarios. Los registros también llevan un TTL que les indica a los resolvedores cuánto tiempo guardarlos en caché.

Una zona es la parte del espacio de nombres DNS de la que es responsable un servidor determinado. Una zona de búsqueda directa (forward lookup zone) resuelve nombres a direcciones; una zona de búsqueda inversa (reverse lookup zone) resuelve direcciones a nombres. Un servidor primario tiene la copia editable de la zona; los servidores secundarios tienen copias de solo lectura obtenidas mediante transferencias de zona (AXFR para una transferencia completa, IXFR para una incremental), que deben restringirse a los servidores autorizados porque revelan la zona completa.

Dos tipos de servidores cumplen roles distintos. Un servidor autoritativo tiene los registros reales de una zona y da respuestas definitivas sobre ella. Un resolvedor recursivo, como el servidor DNS de tu ISP o de tu empresa, hace el trabajo pesado por los clientes: pregunta a un servidor raíz, que lo remite al servidor del dominio de nivel superior (por ejemplo, .com), que lo remite al servidor autoritativo del dominio, que da la respuesta. El resolvedor guarda los resultados en caché para acelerar las consultas posteriores. Tu PC hace una consulta recursiva a su resolvedor; el resolvedor hace consultas iterativas a los otros servidores.

El DNS clásico no está autenticado ni cifrado, lo que permite el envenenamiento de caché (respuestas falsificadas) y el espionaje. DNSSEC (DNS Security Extensions) agrega firmas digitales a los registros, para que los resolvedores puedan verificar que las respuestas son auténticas y no fueron alteradas; ofrece integridad y autenticidad, pero no confidencialidad. Para la privacidad, DNS over TLS (DoT) cifra DNS en TCP 853, y DNS over HTTPS (DoH) envía DNS dentro de HTTPS en TCP 443, lo que hace que se mezcle con el tráfico web. Las organizaciones a veces bloquean o controlan DoH para que no se evada su propio filtrado de DNS.

Por último, el archivo hosts local (/etc/hosts en Linux y macOS, C:\Windows\System32\drivers\etc\hosts en Windows) asocia nombres con direcciones de forma estática y se consulta antes que DNS por defecto. Es útil para pruebas, pero el malware también puede abusar de él para redirigir sitios, así que una entrada inesperada allí es una señal de alerta. Usa nslookup o dig para probar DNS directamente.

Términos clave

CNAME
Un registro DNS que convierte un nombre en alias de otro nombre.
PTR record (registro PTR)
Un registro DNS que se usa para las búsquedas inversas, asociando una dirección IP con un nombre de host.
Authoritative server (servidor autoritativo)
Un servidor DNS que tiene los registros oficiales de una zona.
Recursive resolver (resolvedor recursivo)
Un servidor DNS que realiza la búsqueda completa en nombre de un cliente y guarda los resultados en caché.
DNSSEC
Extensiones que firman digitalmente los registros DNS para que los resolvedores puedan verificar su autenticidad e integridad.
Ejemplo real

Algunos destinatarios marcan como spam el correo de una empresa. dig example.com TXT muestra que no hay registro SPF, y dig example.com MX confirma los servidores de correo. El administrador agrega un registro TXT con una política SPF que enumera los servidores de correo legítimos, y la entregabilidad mejora.

Consejo para el examen: A = IPv4, AAAA = IPv6, PTR = inversa, MX = correo, NS = servidores de nombres, SOA = autoridad de la zona y número de serie, TXT = SPF/DKIM/verificación, CNAME = alias. DNSSEC da integridad, no cifrado; DoH y DoT dan cifrado.

Comprueba lo que sabes

¿Qué tipo de registro crearías para que 10.1.1.20 se resuelva de vuelta a server1.example.com?

Un registro PTR en la zona de búsqueda inversa.

¿Contra qué protege DNSSEC y qué no ofrece?

Protege contra respuestas DNS falsificadas o alteradas (como el envenenamiento de caché) usando firmas; no cifra las consultas.

¿Qué puerto usa DNS over TLS?

TCP 853.
