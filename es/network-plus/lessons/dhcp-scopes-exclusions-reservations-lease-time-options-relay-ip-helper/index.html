CompTIA Network+ N10-009

DHCP: ámbitos, exclusiones, reservas, tiempo de concesión, opciones, relay/IP helper; SLAAC para IPv6

El Dynamic Host Configuration Protocol (DHCP) les da automáticamente a los hosts su configuración IP: una dirección, máscara de subred, puerta de enlace predeterminada, servidores DNS y más. Sin él, cada dispositivo necesitaría configuración manual, lo cual es lento y favorece las direcciones duplicadas. Los servidores DHCP escuchan en UDP 67 y los clientes usan UDP 68.

Un cliente obtiene una dirección mediante el intercambio DORA. Discover: el cliente, que todavía no tiene dirección, envía un broadcast buscando un servidor. Offer: un servidor responde ofreciendo una dirección. Request: el cliente envía un broadcast indicando que acepta esa oferta (lo que también les dice a los demás servidores que sus ofertas fueron rechazadas). Acknowledge: el servidor confirma y comienza la concesión (lease). Si ningún servidor responde, un cliente Windows recurre a una dirección APIPA 169.254.x.x.

Un ámbito (scope) es el rango de direcciones que un servidor puede entregar para una subred, como de 192.168.10.100 a 192.168.10.200, junto con su configuración. Las exclusiones son direcciones dentro del rango del ámbito que el servidor nunca debe entregar, normalmente porque están asignadas de forma estática a impresoras, servidores o la puerta de enlace. Las reservas asocian una dirección específica a un cliente específico, identificado por su dirección MAC, de modo que ese dispositivo siempre obtenga la misma IP y siga administrándose de forma centralizada mediante DHCP; esto es adecuado para impresoras y puntos de acceso. Un servidor puede alojar muchos ámbitos, uno por subred o VLAN.

Las direcciones se conceden en arrendamiento, no se entregan de forma permanente. El tiempo de concesión (lease time) fija cuánto tiempo puede usar el cliente la dirección. Al 50 por ciento de la concesión (el temporizador T1) el cliente intenta renovar con su servidor; al 87.5 por ciento (T2) lo intenta con cualquier servidor; si la concesión vence, debe dejar de usar la dirección. Las concesiones cortas son adecuadas para redes de invitados concurridas con muchos dispositivos de paso, para que las direcciones se reciclen rápido; las concesiones largas son adecuadas para oficinas cableadas estables y reducen el tráfico DHCP.

Las opciones de DHCP llevan configuración adicional. Algunas comunes son la opción 3 (router, la puerta de enlace predeterminada), la opción 6 (servidores DNS), la opción 15 (nombre de dominio), la opción 42 (servidores NTP) y la opción 66 (servidor TFTP, que usan los teléfonos IP para arrancar). Las opciones pueden configurarse por ámbito o para todo el servidor.

Como los mensajes Discover son broadcasts, no atraviesan los routers. Con un servidor DHCP central que atiende muchas VLAN, configuras un agente de retransmisión DHCP (DHCP relay agent) en la interfaz de router o SVI de cada VLAN; en los dispositivos Cisco es el comando ip helper-address. El relay recibe el broadcast, lo reenvía como unicast al servidor DHCP e incluye la dirección de la interfaz, lo que le indica al servidor qué ámbito usar. Una dirección helper que falta o está mal es una razón común por la que una VLAN recibe direcciones APIPA mientras las demás funcionan.

IPv6 puede usar DHCPv6, pero también ofrece SLAAC (stateless address autoconfiguration). Los routers envían anuncios de router (router advertisements) con el prefijo de red; los hosts construyen sus propias direcciones a partir de ese prefijo y un ID de interfaz. Unas banderas en el anuncio de router les indican a los hosts si deben usar solo SLAAC, DHCPv6 sin estado para opciones adicionales como los servidores DNS, o DHCPv6 con estado también para las direcciones. Los servidores DNS también pueden entregarse en el propio anuncio de router (RDNSS).

Términos clave

DORA
Discover, Offer, Request, Acknowledge: el proceso de concesión DHCP de cuatro mensajes.
Scope (ámbito)
El conjunto de direcciones y configuraciones que un servidor DHCP entrega para una subred.
Reservation (reserva)
Una entrada DHCP que siempre asigna una dirección IP específica a una dirección MAC específica.
Exclusion (exclusión)
Una dirección o rango dentro de un ámbito que el servidor DHCP no asignará.
DHCP relay
Una función de router o switch (IP helper) que reenvía los broadcasts DHCP a un servidor en otra subred.
Ejemplo real

Después de crear una nueva VLAN 40 para un laboratorio, cada PC en ella obtiene una dirección 169.254, mientras las demás VLAN funcionan. El servidor DHCP tiene un ámbito para 10.40.0.0/24, así que el técnico revisa la SVI de la VLAN 40 y descubre que no hay ip helper-address. Agregar el helper apuntando al servidor DHCP lo soluciona.

Consejo para el examen: Exclusión = nunca entregar esta dirección; reserva = siempre dar esta dirección a esta MAC. Si solo los clientes de una subred remota obtienen direcciones APIPA, sospecha del relay (IP helper).

Comprueba lo que sabes

¿Cuáles son los cuatro mensajes de DHCP en orden?

Discover, Offer, Request, Acknowledge (DORA).

¿Por qué se necesita un relay DHCP para un servidor centralizado?

Porque DHCP Discover es un broadcast y los routers no reenvían broadcasts; el relay lo reenvía como unicast al servidor.

¿Qué opción de DHCP proporciona la puerta de enlace predeterminada?

La opción 3 (router).
