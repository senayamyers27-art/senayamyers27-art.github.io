CompTIA Network+ N10-009

Puertos y protocolos comunes: FTP, SSH, Telnet, SMTP, DNS, DHCP, HTTP/S, NTP, SNMP, LDAP/S, SMB, Syslog, SQL, RDP, SIP

Las aplicaciones se localizan entre sí en un host mediante números de puerto, valores de 16 bits (0 a 65535) que van en el encabezado TCP o UDP. Los puertos bien conocidos (0 a 1023) están asignados a servicios comunes, los puertos registrados (1024 a 49151) a otras aplicaciones, y los puertos dinámicos o efímeros (49152 a 65535) los toman prestados los clientes. Un servidor escucha en un puerto conocido y un cliente se conecta a él desde un puerto de origen alto y aleatorio. El examen espera que reconozcas el puerto y el transporte de cada protocolo común y si es seguro o no. Las reglas de firewall, las capturas de paquetes, los resultados de escaneos y la resolución de problemas dependen de este conocimiento, así que vale la pena memorizarlo bien.

Transferencia de archivos y acceso remoto: FTP (File Transfer Protocol) usa TCP 21 para control y TCP 20 para datos en modo activo; envía las credenciales en texto claro. SFTP (SSH File Transfer Protocol) funciona dentro de SSH en TCP 22, y FTPS es FTP protegido con TLS (a menudo TCP 990 en modo implícito). SSH (Secure Shell) en TCP 22 da acceso cifrado por línea de comandos y reemplaza a Telnet en TCP 23, que no está cifrado. TFTP (Trivial FTP) usa UDP 69, no tiene autenticación y se usa para firmware de dispositivos, respaldos de configuración y arranque por red. RDP (Remote Desktop Protocol) usa TCP 3389 (y UDP 3389 para mejorar el rendimiento) para el acceso remoto gráfico a Windows.

Correo y web: SMTP (Simple Mail Transfer Protocol) envía correo entre servidores en TCP 25. Los objetivos de N10-009 indican SMTP seguro (SMTPS) en TCP 587, el puerto de envío (submission) que usan los clientes con STARTTLS; en el mundo real también verás el 465 usado para SMTP sobre TLS implícito. HTTP usa TCP 80 y HTTPS, que es HTTP sobre TLS, usa TCP 443. Los protocolos de recuperación de correo son contexto útil: POP3 es 110 (995 seguro) e IMAP es 143 (993 seguro).

Servicios de infraestructura: DNS (Domain Name System) usa el puerto 53, UDP para la mayoría de las consultas y TCP para las transferencias de zona y las respuestas grandes. DHCP (Dynamic Host Configuration Protocol) usa UDP 67 en el servidor y UDP 68 en el cliente. NTP (Network Time Protocol) usa UDP 123. SNMP (Simple Network Management Protocol) usa UDP 161 cuando un administrador (manager) sondea un dispositivo y UDP 162 para los traps que un dispositivo envía al administrador. Syslog envía mensajes de registro a un colector en UDP 514 (también existen variantes con TCP y TLS). LDAP (Lightweight Directory Access Protocol) consulta directorios como Active Directory en el puerto 389, y LDAPS (LDAP sobre TLS) usa TCP 636.

Uso compartido de archivos, bases de datos y voz: SMB (Server Message Block), que se usa para compartir archivos e impresoras en Windows, funciona directamente sobre TCP 445. Microsoft SQL Server escucha en TCP 1433 de forma predeterminada; otras bases de datos usan sus propios puertos, como 3306 para MySQL, 5432 para PostgreSQL y 1521 para Oracle. SIP (Session Initiation Protocol) establece, modifica y termina llamadas de voz y video en el puerto 5060 (UDP o TCP), y en el 5061 cuando está protegido con TLS. El audio real viaja por separado, normalmente como RTP (Real-time Transport Protocol) en un rango de puertos UDP altos, por lo que una llamada puede sonar pero no tener audio si solo se permite SIP a través de un firewall.

Una forma práctica de estudiar es observar una máquina real. Ejecuta netstat -an en Windows o ss -tuln en Linux y asocia cada puerto en escucha con un servicio. En la salida de abajo, el host ejecuta SSH, un servidor web, SMB y SQL Server, y tiene una sesión HTTPS establecida con un sitio remoto desde un puerto efímero.

C:\> netstat -an | findstr "LISTENING ESTABLISHED"
  TCP  0.0.0.0:22          0.0.0.0:0          LISTENING
  TCP  0.0.0.0:443         0.0.0.0:0          LISTENING
  TCP  0.0.0.0:445         0.0.0.0:0          LISTENING
  TCP  0.0.0.0:1433        0.0.0.0:0          LISTENING
  TCP  10.0.0.15:51544     203.0.113.10:443   ESTABLISHED

Agrupa los protocolos inseguros con sus reemplazos seguros, porque las preguntas de seguridad a menudo preguntan cuál usar: Telnet por SSH, HTTP por HTTPS, FTP por SFTP o FTPS, LDAP por LDAPS, SNMPv1/v2c por SNMPv3, SIP por SIP sobre TLS (5061). Entre los errores comunes están pensar que SFTP usa el puerto 21 o el 990 (usa el 22, porque forma parte de SSH), confundir TFTP (UDP 69) con FTP (TCP 20/21), suponer que DNS es solo UDP y olvidar que los traps SNMP van al administrador en el 162, mientras que el sondeo va al dispositivo en el 161. En el examen, los puertos aparecen en preguntas de reglas de firewall ('qué puerto se debe abrir para...'), en salidas de escaneo o de netstat ('qué servicio se está ejecutando') y en preguntas de seguridad ('qué protocolo debería reemplazar a...'). Palabras clave como 'texto claro', 'sin cifrar' o 'heredado' normalmente apuntan a Telnet, FTP, HTTP o SNMPv1. Lee con atención si la pregunta pide el puerto del servidor o el del cliente, y si dice TCP o UDP.

Términos clave

Puertos bien conocidos (well-known ports)
Los números de puerto 0 a 1023, asignados a servicios comunes como HTTP (80) y SSH (22).
Puerto efímero (ephemeral port)
Un puerto de origen temporal y alto que elige un cliente para una conexión saliente.
SFTP
SSH File Transfer Protocol: transferencia cifrada de archivos que funciona dentro de una sesión SSH en TCP 22.
Trap SNMP
Una alerta no solicitada que envía un dispositivo administrado al administrador SNMP en UDP 162.
LDAPS
LDAP protegido con TLS, en TCP 636.
SMB
Server Message Block: el protocolo de Windows para compartir archivos e impresoras, que funciona sobre TCP 445.
SIP
Session Initiation Protocol: establece y termina llamadas VoIP y de video en el 5060, o en el 5061 con TLS.
Ejemplo real

A una administradora de firewall le piden que permita a la mesa de ayuda administrar los switches de forma segura y recopilar sus registros. Ella permite TCP 22 (SSH) desde la subred de la mesa de ayuda hacia la VLAN de administración de los switches y bloquea por completo TCP 23 (Telnet). Luego permite UDP 514 desde los switches hacia el servidor syslog y UDP 162 desde los switches hacia el servidor de monitoreo para los traps SNMP, además de UDP 161 desde el servidor de monitoreo hacia los switches para el sondeo. Una semana después, un escaneo muestra TCP 21 abierto en un servidor de archivos, así que reemplaza el servicio FTP con SFTP en TCP 22.

Consejo para el examen: Cuidado con los pares que es fácil intercambiar: SNMP 161 (sondeo) vs 162 (traps), DHCP 67 (servidor) vs 68 (cliente), LDAP 389 vs LDAPS 636, SSH 22 vs Telnet 23, FTP 20/21 vs TFTP UDP 69.

Comprueba lo que sabes

Un nuevo sistema VoIP puede hacer llamadas y los teléfonos suenan, pero ninguna de las partes escucha audio. SIP en el 5060 está permitido en el firewall. ¿Qué es probable que falte?

Los puertos de medios RTP; SIP solo gestiona la señalización de la llamada, mientras que el audio viaja por separado como RTP en un rango de puertos UDP que el firewall también debe permitir.

Un escaneo muestra TCP 22, 445 y 3389 abiertos en un servidor. ¿Qué servicios son y cuál da acceso remoto gráfico?

SSH (22), uso compartido de archivos SMB (445) y RDP (3389); RDP proporciona el escritorio remoto gráfico.

Las consultas DNS funcionan, pero un servidor DNS secundario no puede copiar la zona desde el primario. El firewall solo permite UDP 53. ¿Por qué falla?

Las transferencias de zona usan TCP 53, así que el firewall también debe permitir TCP 53 entre los servidores.

Un auditor señala que las búsquedas en el directorio envían credenciales en texto claro por el puerto 389. ¿Qué debería reemplazarlo y en qué puerto?

LDAPS en TCP 636, que envuelve LDAP en cifrado TLS.
