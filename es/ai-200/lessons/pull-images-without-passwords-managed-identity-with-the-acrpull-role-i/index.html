Descargar imágenes sin contraseñas: identidad administrada con el rol AcrPull en lugar del usuario administrador

Todo servicio que ejecuta tu contenedor tiene que autenticarse en tu registro privado antes de poder descargar la imagen. Hay varias formas de hacerlo, y el examen espera que elijas la que no usa secretos almacenados.

El usuario administrador (admin user) es una única cuenta por registro con un nombre de usuario (el nombre del registro) y dos contraseñas. Está deshabilitado de forma predeterminada. Cuando se habilita, tiene derechos completos de push y pull, lo comparten todos los que conocen la contraseña, y no se puede limitar a un solo repositorio ni rastrear hasta una app concreta. Microsoft lo plantea solo para pruebas rápidas. Si ves una solución que habilita el usuario administrador y guarda su contraseña en una configuración de la app, es la respuesta incorrecta cuando existe una opción más segura.

El enfoque recomendado usa una identidad administrada (managed identity), una identidad en Microsoft Entra ID que Azure crea y administra para un recurso, con credenciales que nunca ves. Habilitas una identidad asignada por el sistema o asignada por el usuario en el recurso que descarga, y luego le asignas a esa identidad el rol AcrPull en el registro. AcrPull es un rol de Azure RBAC (control de acceso basado en roles) que permite leer imágenes y nada más. AcrPush agrega la capacidad de subir imágenes, para los agentes de compilación.

# 1. identidad y rol
az identity create -g rg -n app-pull-id
ACR_ID=$(az acr show -n myregistry --query id -o tsv)
PRINCIPAL=$(az identity show -g rg -n app-pull-id --query principalId -o tsv)
az role assignment create --assignee $PRINCIPAL --role AcrPull --scope $ACR_ID

# 2. indicarle a Container Apps que la use para este registro
az containerapp registry set -n orders -g rg \
  --server myregistry.azurecr.io --identity <identity-resource-id>

Cada servicio de cómputo lo configura de forma un poco distinta. En Container Apps configuras el registro con --identity (el ID de recurso de una identidad asignada por el usuario, o system). En App Service estableces la propiedad del sitio acrUseManagedIdentityCreds en true (y acrUserManagedIdentityID para una identidad asignada por el usuario). En AKS, az aks update --attach-acr myregistry otorga AcrPull a la identidad kubelet del clúster por ti.

Por qué a menudo se prefiere la identidad asignada por el usuario para descargar imágenes: una identidad asignada por el sistema no existe hasta que se crea la app, así que en una app completamente nueva hay un problema del huevo y la gallina en el que la primera revisión intenta descargar antes de que exista la asignación de rol. Una identidad asignada por el usuario se puede crear y recibir AcrPull primero, y luego adjuntarse a la app al crearla. Ten en cuenta también que las asignaciones de roles pueden tardar unos minutos en propagarse, así que un fallo de descarga inmediatamente después de la asignación puede resolverse solo.

Existen otras opciones, como entidades de servicio (service principals) con un secreto de cliente o tokens con alcance de repositorio, pero implican secretos que debes guardar y rotar. Con una identidad administrada más AcrPull, no hay nada que se pueda filtrar y el acceso es de mínimo privilegio.

Términos clave

Admin user (usuario administrador)
Una cuenta para todo el registro con contraseñas compartidas y derechos completos de push/pull; está deshabilitada de forma predeterminada y solo está pensada para pruebas.
AcrPull
Un rol integrado de Azure RBAC que concede permiso para descargar imágenes de un registro y nada más.
AcrPush
Un rol integrado que permite tanto subir como descargar imágenes, adecuado para pipelines de compilación.
Managed identity (identidad administrada)
Una identidad de Microsoft Entra para un recurso de Azure cuyas credenciales Azure administra y rota automáticamente.
Ejemplo real

Una Container App no pudo iniciarse por un error de descarga de imagen después de que un ingeniero deshabilitó el usuario administrador del registro. La solución fue crear una identidad administrada asignada por el usuario, otorgarle AcrPull en el registro, adjuntarla a la app y ejecutar az containerapp registry set con esa identidad. La app descargó la imagen correctamente y no quedó ninguna contraseña del registro en ninguna parte de su configuración.

Consejo para el examen: Cuando te pregunten por la forma más segura o de mínimo privilegio para que una app descargue imágenes, responde identidad administrada más AcrPull; descarta las opciones que habilitan el usuario administrador o guardan una contraseña.

Comprueba lo que sabes

¿Qué rol debe recibir la identidad de una Container App para descargar imágenes, y en qué alcance?

AcrPull en el registro de contenedores (o en un alcance más limitado), porque concede acceso de solo lectura a las imágenes.

¿Por qué una identidad asignada por el usuario puede ser más sencilla que una asignada por el sistema para la primera descarga de imagen de una app nueva?

Existe antes que la app, así que se le puede otorgar AcrPull por adelantado; una identidad asignada por el sistema solo existe después de crear la app.
