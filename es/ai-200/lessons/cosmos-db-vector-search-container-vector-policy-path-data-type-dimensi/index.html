Búsqueda vectorial en Cosmos DB: directiva vectorial del contenedor (ruta, tipo de datos, dimensiones, función de distancia), índices vectoriales (flat, quantizedFlat, diskANN) y VectorDistance()

Los modelos de embeddings convierten texto o imágenes en vectores: arreglos largos de números en los que los significados similares quedan cerca unos de otros. La búsqueda vectorial encuentra los elementos cuyos vectores están más cerca de un vector de consulta. Cosmos DB for NoSQL puede almacenar embeddings dentro de los mismos elementos JSON que tus datos operativos y buscar en ellos, así que una app de RAG (retrieval-augmented generation, generación aumentada por recuperación) no necesita una base de datos vectorial aparte. Primero hay que habilitar la función en la cuenta (la capacidad de búsqueda vectorial para NoSQL).

La búsqueda vectorial necesita dos piezas de configuración en el contenedor. La primera es la directiva vectorial del contenedor (vector embedding policy), que describe cada propiedad de embedding: su path (por ejemplo /embedding), su dataType (como float32, o tipos más pequeños como int8 y uint8), su número de dimensions (que debe coincidir con la longitud de salida de tu modelo de embeddings) y su distanceFunction: cosine, dotproduct o euclidean. Usa la función de distancia para la que se diseñó tu modelo de embeddings; cosine es la opción predeterminada habitual para embeddings de texto. La directiva vectorial se define al crear el contenedor, así que planifícala desde el principio.

La segunda pieza es un índice vectorial en la directiva de indexación del contenedor, listado bajo vectorIndexes con la misma ruta y un tipo. Hay tres tipos. flat hace una búsqueda exacta por fuerza bruta sobre vectores con precisión completa; da un recall perfecto, pero solo admite un número limitado de dimensiones y se encarece a medida que crecen los datos, así que encaja con conjuntos de datos pequeños. quantizedFlat comprime los vectores (cuantización) y los sigue recorriendo, sacrificando un poco de precisión a cambio de menor costo y admitiendo más dimensiones. diskANN construye un índice de vecinos más cercanos aproximados basado en grafos, desarrollado por Microsoft Research, que ofrece baja latencia y bajo costo a gran escala con un recall alto pero no perfecto. Como regla general: necesidades pequeñas o exactas, flat; tamaño moderado, quantizedFlat; gran escala, diskANN.

"vectorEmbeddingPolicy": { "vectorEmbeddings": [
  { "path": "/embedding", "dataType": "float32", "dimensions": 1536, "distanceFunction": "cosine" } ] },
"indexingPolicy": {
  "includedPaths": [ { "path": "/*" } ],
  "excludedPaths": [ { "path": "/embedding/*" } ],
  "vectorIndexes": [ { "path": "/embedding", "type": "diskANN" } ] }

Observa que la ruta del embedding se excluye del índice de rango normal. Indexar cientos de números por elemento como propiedades normales encarecería cada escritura y no aporta nada; de eso se encarga el índice vectorial.

Consultas con la función del sistema VectorDistance(), que devuelve una puntuación de similitud entre el vector de un elemento y el vector de consulta. Combínala con TOP y ORDER BY para obtener los k elementos más cercanos, y agrega filtros WHERE normales para los metadatos.

results = container.query_items(
    query="SELECT TOP 5 c.id, c.text, VectorDistance(c.embedding, @q) AS score "
          "FROM c WHERE c.category = @cat ORDER BY VectorDistance(c.embedding, @q)",
    parameters=[{"name": "@q", "value": query_vector}, {"name": "@cat", "value": "manuals"}],
    enable_cross_partition_query=True)

Usa siempre TOP en las consultas vectoriales para que el motor no devuelva todos los elementos. Con cosine y dot product, una puntuación más alta significa más similitud; el ORDER BY sobre VectorDistance devuelve primero los elementos más similares.

Términos clave

Vector embedding policy (directiva de embeddings vectoriales)
Configuración del contenedor que define la ruta, el tipo de datos, el número de dimensiones y la función de distancia de cada vector.
flat index (índice flat)
Un índice vectorial exacto por fuerza bruta con recall perfecto, adecuado para conjuntos de datos pequeños y dimensiones limitadas.
quantizedFlat index (índice quantizedFlat)
Un índice vectorial que comprime los vectores y los recorre, reduciendo el costo con una pequeña pérdida de precisión.
diskANN index (índice diskANN)
Un índice de vecinos más cercanos aproximados basado en grafos, diseñado para baja latencia a gran escala.
VectorDistance()
La función de consulta de Cosmos DB que devuelve la puntuación de similitud entre dos vectores.
Ejemplo real

Un chatbot de soporte guarda fragmentos de manuales de productos en Cosmos DB con un embedding float32 de 1536 dimensiones, distancia cosine y un índice diskANN, y excluye /embedding/* de la indexación de rango. Para cada pregunta genera el embedding del texto y ejecuta SELECT TOP 5 con VectorDistance y un filtro WHERE por línea de producto, y luego le pasa los cinco fragmentos al modelo.

Consejo para el examen: Las dimensiones de la directiva vectorial deben coincidir con la salida del modelo de embeddings; elige flat para búsquedas exactas pequeñas, quantizedFlat para tamaño medio y diskANN para gran escala, y excluye la ruta del vector del índice normal.

Comprueba lo que sabes

¿Qué cuatro propiedades describen un vector en la directiva vectorial del contenedor?

La ruta, el tipo de datos, el número de dimensiones y la función de distancia (cosine, dotproduct o euclidean).

¿Por qué incluir TOP en una consulta con VectorDistance?

Para limitar el resultado a los k elementos más cercanos; sin él, la consulta puntuaría y devolvería muchos más elementos y costaría más RU.
