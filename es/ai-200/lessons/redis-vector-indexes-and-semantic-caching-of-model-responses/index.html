Índices vectoriales de Redis y caché semántica de las respuestas del modelo

Redis no es solo una caché de clave-valor. Con el módulo search (RediSearch, parte de Redis Stack y disponible como módulo en Azure Managed Redis), Redis puede indexar campos dentro de hashes o documentos JSON, incluidos campos vectoriales, y ejecutar consultas de K vecinos más cercanos (K-nearest-neighbor) en memoria. En Azure Managed Redis eliges los módulos al crear la caché, así que planifica el uso de search desde el principio.

Creas un índice con FT.CREATE, indicando el prefijo de claves que se va a indexar, la estructura de datos (HASH o JSON) y un esquema. Un campo vectorial declara su algoritmo (FLAT para búsqueda exacta, HNSW para aproximada), el tipo de elemento (como FLOAT32), el número de dimensiones y la métrica de distancia (COSINE, L2 o IP). Toda clave escrita con ese prefijo se indexa automáticamente.

FT.CREATE idx:cache ON HASH PREFIX 1 semcache: SCHEMA
  prompt TEXT
  model TAG
  embedding VECTOR HNSW 6 TYPE FLOAT32 DIM 1536 DISTANCE_METRIC COSINE

FT.SEARCH idx:cache "(@model:{gpt-small})=>[KNN 3 @embedding $vec AS score]"
  PARAMS 2 vec <binary float32 bytes> SORTBY score DIALECT 2

La sintaxis de la consulta KNN combina un prefiltro (aquí, un filtro TAG sobre model) con una búsqueda vectorial, y el parámetro $vec lleva el vector de consulta como bytes sin procesar, que en Python generas con astype(np.float32).tobytes() de NumPy. DIALECT 2 es obligatorio para esta sintaxis vectorial parametrizada. Los resultados vuelven con la puntuación de distancia; con COSINE, una distancia menor significa más similitud.

La caché semántica aplica esto a las llamadas al modelo. Una caché normal solo acierta con exactamente la misma clave, pero los usuarios hacen la misma pregunta de muchas formas: "¿Cómo restablezco mi contraseña?" y "Olvidé mi contraseña, ¿qué hago?". Una caché semántica genera el embedding de cada prompt entrante, busca en el índice de la caché el prompt anterior más cercano y, si la distancia está por debajo de un umbral, devuelve la respuesta almacenada sin llamar al modelo. Cuando hay un fallo, la app llama al modelo y luego almacena el prompt, su embedding y la respuesta con un TTL.

El beneficio es menor latencia y menor costo del modelo para el tráfico repetitivo, como preguntas frecuentes y bots de soporte. Los riesgos requieren diseño. El umbral de similitud es un equilibrio: si es demasiado laxo, los usuarios reciben respuestas a otra pregunta; si es demasiado estricto, la caché casi nunca acierta. Delimita las entradas con filtros, como la versión del modelo, el idioma, el inquilino o el usuario, para que la respuesta en caché de un inquilino nunca llegue a otro, y no almacenes en caché respuestas que contengan datos personales o que dependan del contexto propio del usuario. Usa TTL para que las respuestas basadas en hechos cambiantes expiren, e invalida las entradas cuando cambien los documentos subyacentes.

La caché semántica complementa a RAG en lugar de reemplazarlo: RAG fundamenta las respuestas en tus datos, y la caché semántica evita repetir todo el recorrido de recuperación y generación para preguntas que en la práctica ya se respondieron.

Términos clave

FT.CREATE
El comando de búsqueda de Redis que define un índice sobre claves de hash o JSON, incluidos los campos vectoriales.
KNN query (consulta KNN)
Una consulta de búsqueda de Redis que devuelve los K vectores más cercanos a un vector de consulta proporcionado.
Semantic cache (caché semántica)
Una caché que devuelve respuestas del modelo almacenadas para prompts cuyos embeddings son lo bastante similares al prompt nuevo.
Similarity threshold (umbral de similitud)
La distancia máxima a la que un prompt en caché se considera una coincidencia en una caché semántica.
Ejemplo real

Un bot de soporte recibe a diario miles de preguntas sobre contraseñas con palabras ligeramente distintas. El equipo agrega una caché semántica en Redis: se genera el embedding de cada prompt y se busca con KNN 1, filtrando por idioma y versión del modelo, y se devuelven de inmediato las respuestas en caché con una distancia coseno por debajo de un umbral ajustado. Las llamadas al modelo para las preguntas comunes bajaron drásticamente, y las entradas expiran después de un día para que los cambios de política se reflejen.

Consejo para el examen: La caché semántica coincide por significado, no por texto exacto, así que el equilibrio que evalúa el examen es el umbral de similitud; delimita siempre las entradas de caché (inquilino, modelo, idioma) y asígnales un TTL.

Comprueba lo que sabes

Además del algoritmo (FLAT o HNSW), ¿qué tres configuraciones necesita un campo VECTOR de Redis?

El tipo de elemento, el número de dimensiones y la métrica de distancia, por ejemplo TYPE FLOAT32 DIM 1536 DISTANCE_METRIC COSINE.

¿Qué pasa si el umbral de similitud de una caché semántica es demasiado laxo?

Preguntas distintas se tratan como si fueran la misma, así que los usuarios reciben respuestas en caché que no corresponden a lo que preguntaron.
