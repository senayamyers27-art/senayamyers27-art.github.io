Change feed: change feed processor con un contenedor de leases, trigger de Cosmos DB en Azure Functions, modo latest version vs all versions and deletes

El change feed (fuente de cambios) es un registro persistente y ordenado de los cambios en los elementos de un contenedor de Cosmos DB. En lugar de sondear con consultas, tu código lee lo que cambió desde la última vez que miró. Es la columna vertebral de los patrones controlados por eventos: actualizar un índice de búsqueda o vectorial cuando cambian los documentos, generar embeddings para elementos nuevos, mantener sincronizada una caché o una vista materializada, o desencadenar flujos de trabajo. Los cambios están ordenados dentro de cada valor de clave de partición, pero no entre particiones.

El change feed tiene dos modos. El modo latest version (el predeterminado) entrega la versión más reciente de cada elemento creado o actualizado. Si un elemento cambia varias veces entre lecturas, puede que solo veas su estado más reciente, y las eliminaciones no aparecen en absoluto. La solución habitual es una eliminación lógica (soft delete): establecer una marca como deleted: true (que es una actualización que el feed sí ve) y dejar que un TTL (tiempo de vida) elimine el elemento más tarde. El modo all versions and deletes registra cada cambio, incluidas las versiones intermedias y las eliminaciones, con metadatos sobre la operación. Requiere que la cuenta use copia de seguridad continua, y solo puedes leer los cambios que estén dentro de la ventana de retención de la copia de seguridad continua.

El change feed processor es una función de biblioteca (en los SDK de .NET y Java, y reutilizada conceptualmente por Azure Functions) que hace que consumir el feed sea confiable a escala. Tiene cuatro partes: el contenedor supervisado cuyos cambios lees; un contenedor de leases (concesiones) que almacena los puntos de control (hasta dónde se ha procesado cada partición) y coordina la propiedad; las instancias de cómputo, cada una con un nombre de instancia único; y el delegado, tu código controlador que procesa cada lote. Cuando agregas instancias, los leases se reequilibran para repartir el trabajo; si una instancia falla, otra toma sus leases y continúa desde el último punto de control. El procesamiento es al menos una vez (at least once), así que haz que los controladores sean idempotentes.

Para los desarrolladores de Python, la forma más común de consumir el change feed es el trigger de Cosmos DB de Azure Functions, que ejecuta un change feed processor por ti. Proporcionas la conexión, la base de datos, el contenedor supervisado y el contenedor de leases; la función recibe una lista de documentos modificados.

Términos clave

Change feed (fuente de cambios)
Un registro ordenado y persistente de las creaciones y actualizaciones (y, en un modo, las eliminaciones) de un contenedor de Cosmos DB.
Lease container (contenedor de leases)
Un contenedor que almacena los puntos de control del change feed y la propiedad de las particiones para los processors y los triggers de Functions.
Latest version mode (modo latest version)
El modo predeterminado del change feed, que devuelve el estado más reciente de los elementos modificados y no incluye eliminaciones.
All versions and deletes mode (modo all versions and deletes)
Un modo del change feed que registra cada cambio, incluidas las eliminaciones, y requiere copia de seguridad continua.
Ejemplo real

Una base de conocimiento debe mantener sus vectores al día. Una función de Python con un trigger de Cosmos DB escucha el contenedor chunks y, para cada fragmento nuevo o editado, llama al modelo de embeddings y hace upsert del vector. Los artículos eliminados no desaparecían de la búsqueda, así que el equipo cambió la eliminación para que estableciera deleted: true con un TTL, algo que el feed en modo latest version entrega como una actualización.

Consejo para el examen: Las eliminaciones son invisibles en el modo latest version; responde con soft delete más TTL, o con el modo all versions and deletes (que necesita copia de seguridad continua). Dos funciones sobre un mismo contenedor necesitan prefijos de lease o contenedores separados.

Comprueba lo que sabes

¿Qué se almacena en el contenedor de leases?

Puntos de control y registros de propiedad que indican hasta dónde se ha procesado cada rango de particiones y qué instancia lo hizo.

¿Cómo puedes capturar las eliminaciones si debes seguir en el modo latest version?

Usa una marca de eliminación lógica que el feed ve como una actualización, y elimina el elemento más tarde con TTL.
