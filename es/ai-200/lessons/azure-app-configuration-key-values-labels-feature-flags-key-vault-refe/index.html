Azure App Configuration: pares clave-valor, etiquetas, marcas de características, referencias de Key Vault, actualización con clave centinela e instantáneas

Azure App Configuration es un servicio administrado para centralizar la configuración de las aplicaciones y las marcas de características (feature flags). En lugar de que cada app y cada entorno lleven sus propias copias de la configuración, las apps la cargan al iniciar desde un único almacén y pueden actualizarla en tiempo de ejecución sin volver a implementar. Complementa a Key Vault: App Configuration contiene la configuración común, mientras que los secretos se quedan en Key Vault.

El elemento básico es un par clave-valor (key-value). Las claves son cadenas, a menudo jerárquicas con un separador como : o /, por ejemplo Orders:MaxBatchSize. Las etiquetas (labels) agregan otra dimensión: la misma clave puede tener varios valores distinguidos por etiqueta, como Dev, Test y Prod, o números de versión. Una app selecciona las claves que necesita con un filtro de claves y elige un filtro de etiquetas para su entorno; para recurrir a los valores sin etiqueta, carga primero las claves sin etiqueta y luego la etiqueta del entorno, para que los valores etiquetados los reemplacen. Los valores pueden tener un tipo de contenido, como JSON.

Las marcas de características son pares clave-valor especiales (almacenados bajo el prefijo .appconfig.featureflag/) que activan o desactivan características en tiempo de ejecución. Una marca puede estar simplemente habilitada o deshabilitada, o usar filtros como un despliegue por porcentaje, una ventana de tiempo o la segmentación de usuarios y grupos específicos. Las bibliotecas de administración de características evalúan las marcas en tu código, lo que te permite publicar código oculto, habilitarlo gradualmente y apagarlo al instante si algo sale mal.

App Configuration puede contener referencias de Key Vault: un par clave-valor cuyo contenido lo marca como puntero al URI de un secreto de Key Vault. App Configuration nunca lee el secreto en sí. El proveedor del cliente lo resuelve llamando a Key Vault con la credencial de la app, así que la identidad de la app necesita tanto App Configuration Data Reader como Key Vault Secrets User. Esto ofrece un solo lugar para descubrir la configuración mientras los secretos siguen protegidos.

from azure.appconfiguration.provider import load, SettingSelector, WatchKey
cred = DefaultAzureCredential()
config = load(endpoint=APPCONFIG_ENDPOINT, credential=cred,
    selects=[SettingSelector(key_filter="Orders:*", label_filter="Prod")],
    keyvault_credential=cred,
    refresh_on=[WatchKey("Orders:Sentinel")], refresh_interval=60,
    feature_flag_enabled=True)
batch = config["Orders:MaxBatchSize"]
config.refresh()   # llámalo periódicamente, p. ej. en cada solicitud; solo recarga si cambió la centinela

Actualizar muchas claves de forma individual es ineficiente y puede cargar un conjunto actualizado a medias. El patrón de clave centinela (sentinel key) resuelve esto: vigilas una sola clave, como Orders:Sentinel. Cuando terminas de actualizar un grupo de configuraciones, cambias el valor de la centinela al final. El proveedor revisa la centinela después del intervalo de actualización y solo cuando cambia vuelve a cargar juntas todas las configuraciones seleccionadas. Tu código llama a refresh() con regularidad; es económico hasta que pasa el intervalo. La actualización también puede basarse en eventos de Event Grid de App Configuration para recibir cambios por push.

Las instantáneas (snapshots) son copias inmutables, con nombre y de un momento dado, de un conjunto de pares clave-valor elegidos con filtros. Una vez creada, una instantánea nunca cambia, así que una app que carga una instantánea obtiene exactamente la misma configuración cada vez, lo que resulta útil para implementaciones seguras y reversiones: implementa la versión 12 con la instantánea release-12 y vuelve a la instantánea anterior si hace falta. Otras características que debes conocer: restauración de revisiones a un momento dado, importación y exportación, réplicas geográficas para la resiliencia y varios niveles de precios (entre ellos Free y Standard) con distintas cuotas y características. Por seguridad, prefiere la autenticación de Microsoft Entra con App Configuration Data Reader en lugar de las claves de acceso.

Términos clave

Label (etiqueta)
Un valor que distingue versiones de la misma clave, que se usa comúnmente para entornos como Dev y Prod.
Feature flag (marca de característica)
Un par clave-valor que activa o desactiva una característica en tiempo de ejecución, opcionalmente con filtros como porcentaje o segmentación.
Sentinel key (clave centinela)
Una sola clave vigilada cuyo cambio indica a la app que vuelva a cargar toda su configuración a la vez.
Snapshot (instantánea)
Una copia inmutable y con nombre de pares clave-valor seleccionados que siempre devuelve la misma configuración.
Ejemplo real

Un equipo ejecuta un mismo conjunto de container apps en tres entornos. Guardan toda la configuración en App Configuration con las etiquetas Dev, Test y Prod, mantienen las contraseñas como referencias de Key Vault y publican un nuevo flujo de pago detrás de una marca de característica con un despliegue del 10 por ciento. Cuando cambian un lote de configuraciones de limitación, actualizan la clave centinela al final, y todas las apps cargan los valores nuevos en menos de un minuto sin reiniciarse.

Consejo para el examen: Valores específicos por entorno significan etiquetas; activar o desactivar en tiempo de ejecución significa marcas de características; recargar todo de forma coherente significa clave centinela; una configuración que nunca cambia para una versión significa instantáneas. Los secretos se quedan en Key Vault, referenciados desde App Configuration.

Comprueba lo que sabes

¿Por qué actualizar la clave centinela al final cuando cambias varias configuraciones?

La app vuelve a cargar todas las configuraciones solo cuando cambia la centinela, así que obtiene el conjunto completo y coherente en lugar de una actualización parcial.

¿Qué permisos necesita una app para resolver una referencia de Key Vault almacenada en App Configuration?

Acceso de lectura a App Configuration (App Configuration Data Reader) y al secreto en Key Vault (Key Vault Secrets User).
