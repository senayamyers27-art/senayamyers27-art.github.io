Etiquetas vs digests, etiquetas estables vs únicas, y limpieza de imágenes antiguas con `az acr repository` y tareas de purge

Cada imagen en un registro tiene dos tipos de nombre. Una etiqueta (tag) es un rótulo mutable y fácil de leer, como orders-api:1.4 u orders-api:latest. Un digest es un hash SHA-256 del manifiesto de la imagen, escrito como orders-api@sha256:..., y es inmutable: el mismo digest siempre se refiere exactamente a los mismos bytes. Una etiqueta es un puntero que se puede mover a una imagen nueva; un digest nunca puede cambiar.

La guía de Microsoft distingue entre etiquetas estables y etiquetas únicas. Una etiqueta estable, como 1.4 o latest, está pensada para moverse: cuando publicas un parche, la etiqueta 1.4 se vuelve a apuntar a la imagen nueva. Las etiquetas estables sirven para imágenes base cuyos consumidores quieren seguir las actualizaciones. Una etiqueta única se asigna una vez y nunca se reutiliza, por ejemplo un ID de compilación, un hash de commit de Git o una marca de fecha y hora. Las etiquetas únicas sirven para los despliegues, porque un despliegue que hace referencia a orders-api:20260914.3 descargará la misma imagen en cada nodo y en cada escalado horizontal, incluso semanas después.

¿Por qué importa esto? Si despliegas con una etiqueta estable, un nodo nuevo o una réplica nueva pueden descargar una imagen más reciente que las que ya se están ejecutando, y terminas con versiones mezcladas y sin un registro claro de lo que se publicó. Desplegar con una etiqueta única o con un digest te da despliegues repetibles y reversiones (rollbacks) sencillas: vuelve a apuntar a la etiqueta única anterior. También puedes bloquear una imagen o una etiqueta contra cambios con az acr repository update --write-enabled false.

Las etiquetas únicas se acumulan y el almacenamiento cuesta dinero, así que necesitas limpiar. Los comandos az acr repository inspeccionan y eliminan contenido: show-tags enumera las etiquetas (agrega --orderby time_desc para ordenar), show-manifests enumera los digests incluidos los que no tienen etiqueta, untag quita una etiqueta pero conserva el manifiesto, y delete --image repo:tag o delete --image repo@digest elimina el manifiesto y todas las etiquetas que apuntan a él. Cuando una etiqueta estable se mueve, el manifiesto anterior queda sin etiqueta (colgante o dangling) pero sigue usando almacenamiento.

az acr repository show-tags --name myregistry --repository orders-api --orderby time_desc --output table
az acr repository delete --name myregistry --image orders-api:20260101.1 --yes

# Limpieza programada: elimina etiquetas de más de 30 días y manifiestos sin etiqueta, conserva las 10 más recientes
az acr task create --registry myregistry --name nightly-purge \
  --cmd "acr purge --filter 'orders-api:.*' --ago 30d --keep 10 --untagged" \
  --schedule "0 2 * * *" --context /dev/null

El comando acr purge se ejecuta dentro de ACR Tasks. --filter recibe un repositorio y una expresión regular para las etiquetas, --ago define el umbral de antigüedad, --untagged también elimina los manifiestos colgantes y --keep conserva las etiquetas más recientes. Pruébalo primero con --dry-run, que enumera lo que se eliminaría. Programar purge con una tarea activada por temporizador te da una retención sin intervención manual; los registros Premium también pueden usar una directiva de retención para manifiestos sin etiqueta.

Términos clave

Tag (etiqueta)
Un rótulo mutable y legible que apunta a un manifiesto de imagen y se puede mover a una imagen más reciente.
Digest
Un identificador SHA-256 inmutable de un manifiesto de imagen que siempre se refiere exactamente al mismo contenido.
Unique tag (etiqueta única)
Una etiqueta que se usa una sola vez y nunca se reasigna, como un ID de compilación o un hash de commit; se recomienda para despliegues.
Untagged manifest (manifiesto sin etiqueta)
Una imagen cuyas etiquetas se movieron o se quitaron todas; sigue consumiendo almacenamiento hasta que se elimina.
acr purge
Un comando de ACR Tasks que elimina etiquetas y manifiestos sin etiqueta según un filtro y una antigüedad; suele ejecutarse de forma programada.
Ejemplo real

Después de un trimestre intenso, el registro de un equipo tenía miles de etiquetas con ID de compilación y su factura de almacenamiento había crecido sin parar. Crearon una tarea de ACR activada por temporizador que ejecuta acr purge cada noche con --ago 30d --keep 10 --untagged, después de revisar primero la salida de un --dry-run. Los despliegues siguieron usando etiquetas únicas, así que producción nunca se vio afectada, y las imágenes antiguas desaparecieron automáticamente.

Consejo para el examen: Para una pregunta sobre asegurar que cada réplica ejecute exactamente la misma imagen, elige una etiqueta única o un digest, nunca latest; para la limpieza automática de imágenes antiguas, elige acr purge en una tarea de ACR programada.

Comprueba lo que sabes

¿Por qué latest es una mala opción en un manifiesto de despliegue de producción?

Es una etiqueta estable que se mueve, así que las réplicas nuevas pueden descargar una imagen distinta de las que están en ejecución y las reversiones no quedan claras; las etiquetas únicas o los digests son repetibles.

¿Qué le pasa a una imagen cuando su única etiqueta se mueve a una compilación más reciente?

Se convierte en un manifiesto sin etiqueta que sigue usando almacenamiento hasta que se elimina, por ejemplo con acr purge --untagged.
