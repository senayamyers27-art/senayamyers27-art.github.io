Azure Database for PostgreSQL flexible server: incluir en la lista de permitidos y habilitar la extensión vector (pgvector)

Azure Database for PostgreSQL flexible server es el servicio administrado de PostgreSQL de Azure. Azure se encarga de las actualizaciones, las copias de seguridad, la alta disponibilidad y el escalado del proceso y el almacenamiento, y tú obtienes un PostgreSQL estándar que funciona con psycopg, SQLAlchemy y cualquier otra herramienta de PostgreSQL. Muchas apps de IA ya tienen datos relacionales en PostgreSQL, y pgvector les permite agregar búsqueda vectorial a esa misma base de datos.

pgvector es una extensión de código abierto de PostgreSQL que agrega un tipo de datos vector, operadores de distancia e índices de vecinos más cercanos aproximados. En un servidor que administras tú mismo, la instalas y ejecutas CREATE EXTENSION vector;. En un flexible server administrado hay un paso adicional, y es justo lo que evalúa el examen: las extensiones deben estar en la lista de permitidos (allow-listed) antes de poder crearse.

El primer paso es la lista de permitidos. Flexible server tiene un parámetro de servidor llamado azure.extensions que enumera las extensiones que los usuarios pueden crear. Agregas VECTOR en el portal (Server parameters) o con la CLI. Si te saltas este paso, CREATE EXTENSION vector falla con un error que indica que la extensión no está en la lista de permitidos. Algunas extensiones también necesitan shared_preload_libraries y un reinicio, pero pgvector no.

az postgres flexible-server parameter set -g rg --server-name pg-ai \
  --name azure.extensions --value VECTOR
# conserva las entradas existentes: usa una lista separada por comas, por ejemplo VECTOR,PG_TRGM

El segundo paso es crear la extensión en cada base de datos que la vaya a usar. Las extensiones son por base de datos, no por servidor. Conéctate a la base de datos de destino con un rol que tenga permiso (el administrador del servidor o un miembro del rol azure_pg_admin) y ejecuta la instrucción. Ten en cuenta que el nombre SQL de la extensión es vector, aunque el proyecto se llame pgvector.

CREATE EXTENSION IF NOT EXISTS vector;
SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';

Para la conectividad, elige entre acceso público con reglas de firewall y acceso privado mediante integración con VNet o un private endpoint. Para la autenticación, flexible server admite Microsoft Entra ID, así que la identidad administrada de tu app puede obtener un token de acceso con DefaultAzureCredential y usarlo como contraseña en lugar de almacenar una. Dimensiona el proceso para cargas vectoriales: los índices de vecinos más cercanos aproximados, especialmente HNSW (Hierarchical Navigable Small World), rinden mejor cuando caben en memoria, y su construcción se beneficia de un maintenance_work_mem más alto.

Una extensión relacionada, azure_ai, permite que SQL llame a los servicios de Azure AI (por ejemplo, para crear embeddings dentro de la base de datos). Sigue la misma regla de lista de permitidos, lo que hace que valga la pena recordar el patrón: agrega la extensión a azure.extensions y luego ejecuta CREATE EXTENSION en cada base de datos.

Términos clave

Flexible server (servidor flexible)
La opción de implementación de Azure Database for PostgreSQL que ofrece PostgreSQL administrado con proceso, alta disponibilidad y redes configurables.
azure.extensions
El parámetro de servidor que define la lista de extensiones permitidas que se pueden crear en un flexible server.
pgvector
Una extensión de código abierto de PostgreSQL, creada como vector, que agrega un tipo vector, operadores de distancia e índices ANN.
azure_pg_admin
Un rol de flexible server cuyos miembros pueden realizar acciones administrativas, como crear extensiones permitidas.
Ejemplo real

Un desarrollador ejecuta CREATE EXTENSION vector en un flexible server nuevo y recibe un error que indica que la extensión no está en la lista de permitidos. Agrega VECTOR al parámetro de servidor azure.extensions, se vuelve a conectar a la base de datos de la app y ejecuta la instrucción de nuevo, y esta vez funciona. Más tarde, un colega descubre que falta el tipo en una segunda base de datos y aprende que las extensiones deben crearse en cada base de datos.

Consejo para el examen: Dos pasos en orden: agrega VECTOR al parámetro de servidor azure.extensions y luego ejecuta CREATE EXTENSION vector en cada base de datos; el nombre SQL de la extensión es vector, no pgvector.

Comprueba lo que sabes

¿Por qué falla CREATE EXTENSION vector en un flexible server nuevo?

La extensión no está en la lista de permitidos; primero agrega VECTOR al parámetro de servidor azure.extensions.

¿Una extensión se crea una vez por servidor o una vez por base de datos?

Una vez por base de datos; cada base de datos que use vectores necesita su propio CREATE EXTENSION.
