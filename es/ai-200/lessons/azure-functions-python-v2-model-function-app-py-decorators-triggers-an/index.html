Modelo v2 de Python de Azure Functions: function_app.py, decoradores, triggers y enlaces de entrada/salida

Azure Functions ejecuta pequeños fragmentos de código en respuesta a eventos sin que tengas que administrar servidores. Cada función tiene exactamente un trigger (desencadenador), el evento que la inicia (una solicitud HTTP, un temporizador, un mensaje de cola), y opcionalmente enlaces (bindings), que la conectan de forma declarativa con otros servicios para entrada y salida. Los enlaces eliminan código repetitivo: en lugar de escribir código del SDK para leer un blob o enviar un mensaje de cola, declaras el enlace y usas un parámetro.

El modelo de programación v2 de Python define las funciones en código con decoradores, en lugar de un archivo function.json separado por función como en el modelo v1 anterior. Un proyecto v2 tiene un archivo function_app.py en su raíz que crea un objeto FunctionApp, y cada función es una función de Python decorada con un trigger y los enlaces que necesite. Los archivos de apoyo son host.json (configuración del runtime), local.settings.json (configuración local de la app) y requirements.txt (que debe incluir azure-functions).

import azure.functions as func
import json, logging

app = func.FunctionApp(http_auth_level=func.AuthLevel.FUNCTION)

@app.route(route="orders", methods=["POST"])
@app.queue_output(arg_name="outmsg", queue_name="new-orders", connection="AzureWebJobsStorage")
def create_order(req: func.HttpRequest, outmsg: func.Out[str]) -> func.HttpResponse:
    order = req.get_json()
    outmsg.set(json.dumps(order))
    return func.HttpResponse("accepted", status_code=202)

@app.blob_trigger(arg_name="blob", path="uploads/{name}", connection="DocsStorage")
@app.blob_output(arg_name="out", path="processed/{name}.txt", connection="DocsStorage")
def extract(blob: func.InputStream, out: func.Out[str]):
    logging.info("Processing %s", blob.name)
    out.set(blob.read().decode("utf-8", errors="ignore"))

Repasémoslo. @app.route crea un trigger HTTP; req es un func.HttpRequest, y el valor devuelto es la respuesta HTTP. @app.queue_output agrega un enlace de salida; el arg_name debe coincidir con un parámetro de tipo func.Out[...], y llamar a .set() escribe el mensaje cuando la función termina. El ejemplo del blob muestra un trigger con un patrón de ruta, donde {name} es una expresión de enlace capturada del blob que activó la función y reutilizada en la ruta de salida. Los enlaces de entrada, como @app.blob_input o @app.cosmos_db_input, cargan datos antes de que se ejecute tu código.

El argumento connection no es una cadena de conexión. Es el nombre de una configuración de la app (o un prefijo para un grupo de configuraciones) que contiene los detalles de conexión, lo que te permite cambiar a conexiones basadas en identidad sin modificar el código. AzureWebJobsStorage es la cuenta de almacenamiento que usa el propio host de Functions.

Las apps grandes pueden repartir las funciones en varios archivos con blueprints: crea func.Blueprint() en un módulo, decora funciones sobre él y regístralo en function_app.py con app.register_functions(bp). Algunos triggers, como el de Service Bus, también pueden enlazarse a tipos del SDK para un acceso más completo. Las funciones solo aparecen si el archivo se importa sin errores, así que un error de importación en function_app.py hace que no se encuentre ninguna función; revisa los registros de inicio cuando eso ocurra.

Términos clave

Trigger (desencadenador)
El evento que inicia una función; cada función tiene exactamente uno.
Binding (enlace)
Una conexión declarativa con otro servicio que proporciona datos de entrada o escribe la salida sin código del SDK.
function_app.py
El archivo de entrada de una function app de Python v2 que crea FunctionApp y define las funciones decoradas.
func.Out
El tipo de parámetro de un enlace de salida; llamar a set() proporciona el valor que se va a escribir.
Blueprint
Una característica del modelo v2 para definir funciones en módulos separados y registrarlas en la app.
Ejemplo real

Un desarrollador quiere un punto de conexión HTTP que acepte pedidos y los ponga en cola para procesarlos después. En function_app.py agrega @app.route para POST /orders y @app.queue_output enlazado a la cola new-orders. El cuerpo de la función tiene tres líneas: leer el JSON, establecer la salida y devolver 202. No se necesita código del SDK de almacenamiento, y una segunda función activada por la cola procesa los pedidos.

Consejo para el examen: En el modelo v2, los decoradores de function_app.py reemplazan a function.json; el parámetro connection nombra una configuración de la app, no una cadena de conexión literal, y cada función tiene un trigger pero cualquier número de enlaces.

Comprueba lo que sabes

¿Cuántos triggers puede tener una sola función?

Exactamente uno, aunque puede tener varios enlaces de entrada y de salida.

¿Qué contiene el argumento connection en un decorador de enlace?

El nombre de una configuración de la app (o un prefijo de configuración) que contiene la información de conexión, no la cadena de conexión en sí.
