Triggers comunes: HTTP (niveles de autorización), timer (NCRONTAB de seis campos), Service Bus, Cosmos DB, Blob y Event Grid

El trigger HTTP convierte una función en un punto de conexión web en una ruta bajo /api/ de forma predeterminada. Su nivel de autorización controla si se requiere una clave. ANONYMOUS no necesita clave. FUNCTION requiere una clave específica de la función o una clave de host, que se pasa en el encabezado x-functions-key o en el parámetro de consulta code. ADMIN requiere la clave maestra. Las claves no son autenticación de usuarios; para usuarios reales, coloca delante App Service Authentication (Easy Auth), API Management o tu propia validación de tokens. En local, las claves no se exigen.

El trigger de temporizador (timer) se ejecuta según una programación escrita en NCRONTAB, un formato cron de seis campos: {second} {minute} {hour} {day} {month} {day-of-week}. El campo adicional de segundos al principio es la principal diferencia con el cron de Unix de cinco campos, y es el detalle favorito del examen. 0 */5 * * * * se ejecuta cada cinco minutos; 0 30 9 * * 1-5 se ejecuta a las 9:30 los días laborables. Las horas están en UTC de forma predeterminada. Una función de temporizador puede definir run_on_startup (evítalo en producción, ya que los reinicios provocan ejecuciones adicionales) y usa un bloqueo singleton para que solo una instancia ejecute cada ocurrencia.

@app.timer_trigger(schedule="0 0 2 * * *", arg_name="timer", run_on_startup=False)
def nightly(timer: func.TimerRequest):
    if timer.past_due:
        logging.warning("Running late")

@app.service_bus_queue_trigger(arg_name="msg", queue_name="orders", connection="ServiceBusConn")
def handle_order(msg: func.ServiceBusMessage):
    logging.info(msg.get_body().decode())

@app.event_grid_trigger(arg_name="event")
def on_event(event: func.EventGridEvent):
    logging.info("%s %s", event.event_type, event.subject)

El trigger de Service Bus (service_bus_queue_trigger, o service_bus_topic_trigger con un nombre de suscripción) recibe los mensajes en modo peek-lock. Si la función tiene éxito, el runtime completa el mensaje; si lanza una excepción, el mensaje se abandona y se reintenta hasta que el max delivery count lo envía a la cola de mensajes fallidos. El runtime renueva los bloqueos durante las ejecuciones largas, y host.json controla la simultaneidad.

El trigger de Cosmos DB se ejecuta sobre el change feed del contenedor, como se vio antes. Necesita un contenedor de leases, entrega lotes de documentos modificados y no ve las eliminaciones en el modo latest version.

El trigger de Blob se activa cuando se agrega o actualiza un blob en una ruta de contenedor. La implementación clásica sondea (polling) el contenedor y puede tardar en detectar blobs nuevos en planes de tipo consumo y con contenedores grandes. El enfoque recomendado para baja latencia y confiabilidad es el trigger de blob basado en Event Grid (source="EventGrid" en el decorador v2, respaldado por una suscripción de Event Grid), y el plan Flex Consumption solo admite esta forma basada en eventos. Los recibos de blob (blob receipts) almacenados en la cuenta de almacenamiento del host evitan procesar el mismo blob dos veces.

El trigger de Event Grid recibe los eventos que envía una suscripción de Event Grid cuyo destino es la función. El runtime gestiona automáticamente el protocolo de validación del webhook, y puedes filtrar a nivel de la suscripción para que la función solo se ejecute con los eventos relevantes. Elígelo para reaccionar a eventos de recursos de Azure o a eventos de temas personalizados.

Al elegir: solicitud/respuesta significa HTTP; programación significa timer; mensajes de negocio confiables significan Service Bus; cambios en la base de datos significan Cosmos DB; archivos nuevos significan Blob (preferiblemente con origen Event Grid); y eventos de recursos de Azure significan Event Grid.

Términos clave

Authorization level (nivel de autorización)
Configuración del trigger HTTP (anonymous, function o admin) que decide qué clave, si la hay, debe proporcionar quien llama.
NCRONTAB
El formato cron de seis campos que usan los triggers de temporizador, que empieza con un campo de segundos.
Past due (atrasado)
Un indicador del temporizador que señala que la ejecución programada ocurrió más tarde de lo previsto, por ejemplo después de una interrupción.
Event Grid-based blob trigger (trigger de blob basado en Event Grid)
Un trigger de blob que usa notificaciones de Event Grid en lugar de sondeo para lograr menor latencia.
Ejemplo real

Una limpieza nocturna que debía ejecutarse una vez a las 2:00 se ejecutaba sesenta veces cada noche porque un desarrollador escribió * 0 2 * * *, donde el * del campo inicial de segundos significa cada segundo del minuto 2:00. Reescribirla como 0 0 2 * * * corrigió la programación. El mismo equipo cambió un trigger de blob lento basado en sondeo al origen Event Grid, y el procesamiento empezó a los pocos segundos de cada subida.

Consejo para el examen: Las programaciones del timer tienen seis campos, con los segundos primero (0 */5 * * * * es cada cinco minutos). La autorización FUNCTION necesita una clave en x-functions-key o en code; no es autenticación de usuarios.

Comprueba lo que sabes

Escribe una expresión NCRONTAB para todos los días a las 06:15 UTC.

0 15 6 * * *, con los campos segundo, minuto, hora, día, mes y día de la semana.

¿Qué le pasa a un mensaje de un trigger de Service Bus cuando la función lanza una excepción?

El mensaje se abandona y se reintenta; después de superar el max delivery count se mueve a la cola de mensajes fallidos.
