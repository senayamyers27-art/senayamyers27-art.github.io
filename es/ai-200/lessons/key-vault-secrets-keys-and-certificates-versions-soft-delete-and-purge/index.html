Key Vault: secretos, claves y certificados, versiones, eliminación temporal y protección contra purga, RBAC vs directivas de acceso

Azure Key Vault es un servicio administrado para almacenar y controlar el acceso a material confidencial, de modo que nunca tenga que estar en el código, en archivos de configuración ni en imágenes de contenedor. Un almacén (vault) contiene tres tipos de objetos, y saber cuál es cuál responde muchas preguntas.

Los secretos son valores pequeños y arbitrarios que almacenas y vuelves a leer: contraseñas, cadenas de conexión, claves de API. La app recupera el valor en sí. Las claves (keys) son claves criptográficas (RSA o de curva elíptica) que se usan para operaciones como cifrar, descifrar, firmar, verificar, encapsular (wrap) y desencapsular (unwrap). Key Vault realiza la operación, y el material de la clave privada no está pensado para salir del almacén; el nivel Premium protege las claves con HSM (módulos de seguridad de hardware), y Managed HSM es un servicio de un solo inquilino separado para requisitos más estrictos. Los certificados son certificados X.509 que Key Vault puede crear, importar, renovar automáticamente con entidades de certificación integradas y cuya expiración puede controlar; cada certificado tiene una clave y un secreto asociados en segundo plano.

Cada objeto tiene versiones. Cuando defines un valor nuevo para el secreto db-password, Key Vault crea una versión nueva con su propio identificador y conserva las anteriores. Una solicitud sin versión devuelve la versión actual (la más reciente); una solicitud con un ID de versión devuelve exactamente esa. Las versiones hacen que la rotación sea segura y permiten revertir cambios. Los objetos también pueden tener atributos como una fecha de activación, una fecha de expiración, un indicador de habilitado, etiquetas y un tipo de contenido.

secrets = SecretClient(vault_url=VAULT_URL, credential=DefaultAzureCredential())
secrets.set_secret("db-password", new_value, expires_on=expiry)
current = secrets.get_secret("db-password")
for p in secrets.list_properties_of_secret_versions("db-password"):
    print(p.version, p.created_on, p.enabled)

La eliminación temporal (soft delete) protege contra la eliminación accidental o malintencionada, y ahora siempre está habilitada en los almacenes. Un almacén u objeto eliminado pasa a un estado de eliminado durante un periodo de retención que eliges entre 7 y 90 días (90 de forma predeterminada), durante el cual se puede recuperar. Durante ese tiempo su nombre queda reservado, así que crear un secreto nuevo con el mismo nombre falla hasta que recuperes o purgues el anterior. Purgar lo elimina de forma permanente antes de que termine la retención. La protección contra purga (purge protection), cuando está habilitada, bloquea por completo la purga hasta que vence el periodo de retención, incluso para los administradores. La protección contra purga no se puede desactivar una vez habilitada, y a menudo la exigen los servicios que usan claves de Key Vault para el cifrado, como las claves administradas por el cliente.

Key Vault tiene dos modelos de autorización para el plano de datos. Las directivas de acceso del almacén (vault access policies) son el modelo anterior: una lista por almacén de entidades con permisos como Get y List para secretos, claves y certificados. No se pueden limitar a un solo secreto, y cualquiera con Contributor sobre el almacén puede editar las directivas y concederse acceso. Azure RBAC es el modelo recomendado: los roles del plano de datos, como Key Vault Secrets User, se asignan mediante asignaciones de roles de Azure, se pueden limitar a un secreto, clave o certificado individual, y se gobiernan y auditan como el resto del acceso en Azure. Un almacén usa un modelo u otro, según su configuración de modelo de permisos.

En la operación diaria, envía los registros de diagnóstico de Key Vault a Log Analytics para auditar quién leyó qué, restringe el acceso de red con firewalls o private endpoints, y guarda los secretos en caché en tu app en lugar de leerlos en cada solicitud, ya que las solicitudes al almacén se limitan cuando la frecuencia es alta.

Términos clave

Secret (secreto)
Un valor confidencial pequeño, como una contraseña o una cadena de conexión, que una app lee de Key Vault.
Key (clave)
Una clave criptográfica almacenada en Key Vault que realiza operaciones dentro del almacén sin exponer el material privado.
Soft delete (eliminación temporal)
La retención de almacenes y objetos eliminados durante 7 a 90 días para que se puedan recuperar.
Purge protection (protección contra purga)
Una configuración que impide la eliminación permanente hasta que termina el periodo de retención; no se puede deshabilitar una vez activada.
Access policy (directiva de acceso)
El modelo de autorización heredado de Key Vault que concede permisos por almacén, a diferencia de Azure RBAC.
Ejemplo real

Un script eliminó un secreto llamado api-key, y una nueva implementación que intentó volver a crearlo falló con un conflicto. Como la eliminación temporal reserva el nombre, el ingeniero recuperó el secreto eliminado, lo que restauró todas sus versiones. Luego el equipo habilitó la protección contra purga para que nadie pudiera destruir secretos de forma permanente antes de que terminara el periodo de retención, y cambió el almacén al modelo de permisos RBAC.

Consejo para el examen: Los secretos son valores que lees, las claves hacen criptografía dentro del almacén y los certificados son X.509 con administración del ciclo de vida. La protección contra purga no se puede deshabilitar una vez habilitada; RBAC permite un ámbito por secreto, las directivas de acceso no.
