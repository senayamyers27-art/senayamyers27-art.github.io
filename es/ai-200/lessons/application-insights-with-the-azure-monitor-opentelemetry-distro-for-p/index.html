Application Insights con la Azure Monitor OpenTelemetry Distro para Python: cadenas de conexión, trazas, spans y métricas personalizadas

Application Insights es la característica de supervisión del rendimiento de aplicaciones de Azure Monitor. Recopila solicitudes, dependencias (llamadas salientes), excepciones, registros y métricas de tu app y los almacena en un área de trabajo de Log Analytics, donde puedes buscarlos, graficarlos y crear alertas sobre ellos. Para Python, la forma recomendada por Microsoft de enviar esta telemetría es la Azure Monitor OpenTelemetry Distro, el paquete azure-monitor-opentelemetry.

OpenTelemetry es el estándar abierto y neutral respecto al proveedor para la telemetría: una API que usan tu código y las bibliotecas para producir trazas, métricas y registros, más SDK y exportadores que los envían a algún destino. La distro incluye el SDK de OpenTelemetry, el exportador de Azure Monitor y la instrumentación de bibliotecas populares como Flask, Django, FastAPI, requests, urllib y psycopg2, y lo configura todo con una sola llamada.

from azure.monitor.opentelemetry import configure_azure_monitor
configure_azure_monitor()   # lee APPLICATIONINSIGHTS_CONNECTION_STRING

from opentelemetry import trace, metrics
tracer = trace.get_tracer(__name__)
meter = metrics.get_meter(__name__)
tokens = meter.create_counter("llm_tokens", unit="tokens")

def answer(question):
    with tracer.start_as_current_span("rag.answer") as span:
        span.set_attribute("rag.top_k", 5)
        result = call_model(question)
        tokens.add(result.usage, {"model": "chat-small"})
        return result

La app encuentra su recurso de Application Insights mediante una cadena de conexión, que contiene la clave de instrumentación y el punto de conexión de ingesta de tu región. Defínela en la variable de entorno APPLICATIONINSIGHTS_CONNECTION_STRING (el enfoque habitual en App Service, Functions y Container Apps) o pasa connection_string= a configure_azure_monitor. Las cadenas de conexión reemplazan la configuración anterior basada solo en la clave de instrumentación. La cadena de conexión identifica adónde enviar los datos, pero no es un secreto fuerte para leerlos; para un control más estricto, puedes exigir la autenticación de Microsoft Entra para la ingesta. Llama a configure_azure_monitor() temprano, antes de importar o crear la app del framework web, para que las instrumentaciones puedan engancharse.

En OpenTelemetry, una traza (trace) es el recorrido completo de una operación, como una solicitud de usuario, y está formada por spans. Cada span es una unidad de trabajo con tiempo medido, que tiene un nombre, una hora de inicio y de fin, atributos (detalles clave-valor), un estado y un span padre. Application Insights asigna los spans según su tipo: los spans de servidor entrantes se convierten en entradas de la tabla requests, los spans de cliente salientes (llamadas HTTP, consultas a bases de datos, llamadas a modelos) se convierten en dependencies y los spans internos que creas también aparecen como dependencias. Las excepciones registradas en los spans llegan a exceptions, y la salida de logging de Python que recopila la distro llega a traces, un detalle de nomenclatura confuso pero importante: en Application Insights, la tabla traces contiene mensajes de registro.

Las métricas personalizadas usan la API de métricas de OpenTelemetry: contadores (valores que solo aumentan, como los tokens usados), histogramas (distribuciones, como la latencia o el número de fragmentos) y medidores (gauges). Los atributos de cada medición se convierten en dimensiones. Aparecen en la tabla customMetrics y en el explorador de métricas, donde puedes graficarlas y crear alertas. Prefiere las métricas para números de gran volumen que agregas, y los atributos de span o los registros para los detalles de cada operación.

Términos clave

Azure Monitor OpenTelemetry Distro
El paquete azure-monitor-opentelemetry que configura OpenTelemetry para enviar la telemetría de Python a Application Insights.
Connection string (cadena de conexión)
La configuración que indica adónde va la telemetría, incluida la clave de instrumentación y el punto de conexión de ingesta.
Span
Una unidad de trabajo con tiempo medido dentro de una traza, con atributos, estado y un span padre.
Custom metric (métrica personalizada)
Una medición definida por la aplicación, como un contador o un histograma, almacenada en la tabla customMetrics.
Ejemplo real

Una API de RAG solo mostraba solicitudes lentas en Application Insights, sin ningún detalle. El desarrollador llamó a configure_azure_monitor al iniciar, envolvió la recuperación y las llamadas al modelo en spans con atributos para top_k y el nombre del modelo, y agregó un contador de tokens. La vista de extremo a extremo ahora muestra que la mayor parte de la latencia es la llamada al modelo, y un gráfico de tokens por modelo alimenta una alerta de costos.

Consejo para el examen: Define APPLICATIONINSIGHTS_CONNECTION_STRING y llama a configure_azure_monitor temprano. Recuerda la correspondencia: los spans de servidor van a requests, los spans de cliente a dependencies, la salida de logging a traces y las mediciones del meter a customMetrics.

Comprueba lo que sabes

¿Qué tabla de Application Insights contiene los mensajes de logging de Python que envía la distro?

La tabla traces, pese a su nombre; los spans van a requests y dependencies.

¿Qué proporciona una cadena de conexión que una clave de instrumentación sola no proporciona?

El punto de conexión de ingesta y otras configuraciones junto con la clave, para que la telemetría llegue al punto de conexión regional correcto.
