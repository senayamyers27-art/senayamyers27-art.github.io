Selección y configuración del router ID de OSPF (sentencias network vs comandos de interfaz, interfaces pasivas)

Todo router OSPF (Open Shortest Path First) necesita un router ID (RID), un valor de 32 bits escrito como una dirección IPv4 que lo identifica en la base de datos de estado de enlace (LSDB), en las tablas de vecinos y en las elecciones de DR (router designado). No tiene que ser una dirección alcanzable, pero debe ser única dentro del dominio OSPF. Saber cómo se elige el RID, y las dos formas de habilitar OSPF en las interfaces, te permite leer y escribir casi cualquier configuración OSPF del CCNA.

IOS elige el router ID en este orden. Primero, un router-id configurado manualmente bajo el proceso OSPF. Si no hay ninguno, la dirección IPv4 más alta de cualquier interfaz loopback activa. Si no hay loopbacks, la dirección IPv4 más alta de cualquier interfaz física activa. 'Más alta' se refiere a la dirección numérica, no al número de interfaz. Se prefieren las loopbacks porque nunca se caen a menos que se apaguen deliberadamente, lo que mantiene estable el RID. La buena práctica es configurarlo de forma explícita: router ospf 1 y luego router-id 1.1.1.1. El RID se elige cuando arranca el proceso y no cambia por sí solo. Si lo cambias, IOS indica que tendrá efecto después de un reinicio o de clear ip ospf process. Los router IDs duplicados causan fallas de adyacencia y mensajes en el registro, así que una configuración copiada que repite un RID es un error común en los laboratorios.

Hay dos formas de habilitar OSPF en las interfaces. La forma tradicional usa sentencias network bajo el proceso: network 10.1.1.0 0.0.0.255 area 0. La dirección y la wildcard forman un patrón: cualquier interfaz cuya dirección IP coincida ejecuta OSPF en esa área, y se anuncia su subred conectada. La wildcard es una máscara inversa, en la que los bits en 0 deben coincidir y los bits en 1 se ignoran. Puedes ser amplio (network 10.0.0.0 0.255.255.255 area 0) o preciso, y coincidir exactamente con una interfaz con network 10.1.1.1 0.0.0.0 area 0. La sentencia network no decide qué prefijo se anuncia; lo deciden la dirección y la máscara propias de la interfaz. La forma más nueva es habilitar OSPF directamente en la interfaz: interface g0/1 y luego ip ospf 1 area 0. Es explícita y fácil de leer, y tiene prioridad sobre una sentencia network para esa interfaz. Ambos métodos producen el mismo resultado, y el examen espera que sepas leer cualquiera de los dos.

router ospf 1
 router-id 1.1.1.1
 network 192.168.10.0 0.0.0.255 area 0
 passive-interface g0/2
!
interface g0/1
 ip ospf 1 area 0

Una interfaz pasiva es aquella en la que OSPF sigue anunciando la subred conectada pero no envía hellos, así que no se forman vecinos. Úsala en las interfaces LAN que dan a los usuarios, donde no hay routers: evita hellos innecesarios e impide que un dispositivo no autorizado forme una adyacencia e inyecte rutas. Configura passive-interface g0/2, o haz pasivas todas las interfaces con passive-interface default y vuelve a habilitar las que necesitan vecinos con no passive-interface g0/0. Las interfaces loopback se anuncian de forma predeterminada como rutas de host /32; ip ospf network point-to-point en la loopback hace que se anuncie su máscara configurada. Verifica con show ip protocols, que muestra el RID, las sentencias network, las interfaces pasivas y los orígenes de enrutamiento, y con show ip ospf interface brief, que lista las interfaces OSPF con su área, costo y estado.

Veamos un ejemplo práctico. R2 tiene la loopback 0 en 2.2.2.2 y las interfaces 10.0.12.2 y 192.168.20.1, sin comando router-id, así que su RID es 2.2.2.2, tomado de la loopback, aunque 192.168.20.1 sea numéricamente mayor. La ingeniera agrega router-id 22.22.22.22, ve el mensaje de que tendrá efecto después de un reinicio o de un clear, y ejecuta clear ip ospf process en una ventana de mantenimiento. Habilita OSPF con network 10.0.12.0 0.0.0.3 area 0 y con ip ospf 1 area 0 en g0/2, y luego hace pasiva la g0/2 para que las PC de los usuarios en 192.168.20.0/24 nunca reciban hellos mientras la subred se sigue anunciando a R1.

Errores comunes: esperar que un router-id nuevo se aplique de inmediato; elegir una dirección física cuando existe una loopback; escribir una máscara de subred donde va una wildcard; pensar que una sentencia network define la longitud del prefijo anunciado; hacer pasivo un enlace que da a un router y luego preguntarse por qué desapareció el vecino; y olvidar que las interfaces pasivas se siguen anunciando.

Palabras clave del examen: 'no hay router-id configurado' significa revisar primero las loopbacks; 'detener los hellos en una LAN de usuarios pero seguir anunciándola' significa passive-interface; 'habilitar OSPF en una interfaz sin sentencia network' significa ip ospf <process> area <area>; y 'no se forman vecinos, RID duplicado en el registro' significa corregir el router ID.

Términos clave

Router ID
Un identificador OSPF único de 32 bits elegido, en este orden, a partir de router-id, la IP de loopback más alta o la IP más alta de una interfaz activa.
Sentencia network (network statement)
Un comando del proceso OSPF que usa una dirección y una wildcard para seleccionar qué interfaces ejecutan OSPF en un área.
ip ospf area
Comando de interfaz (ip ospf <process> area <area>) que habilita OSPF directamente en una interfaz.
Interfaz pasiva (passive interface)
Una interfaz cuya subred anuncia OSPF pero en la que no envía hellos ni forma vecinos.
Máscara wildcard (wildcard mask)
Una máscara inversa en la que los bits en 0 deben coincidir y los bits en 1 se ignoran.
clear ip ospf process
Comando que reinicia OSPF para que un router ID modificado tenga efecto, lo que interrumpe brevemente las adyacencias.
Ejemplo real

Un equipo de laboratorio copia la configuración de R3 para armar R4 y olvida cambiar router-id 3.3.3.3. Los dos routers nunca forman una adyacencia estable y el registro informa un router ID duplicado. Cambiar R4 a router-id 4.4.4.4 y ejecutar clear ip ospf process lleva al vecino a FULL, y show ip protocols confirma el nuevo ID.

Consejo para el examen: Orden de selección del RID: router-id manual, luego la loopback más alta y luego la interfaz física más alta. 'Más alta' se refiere a la dirección numérica, no al número de interfaz.

Comprueba lo que sabes

Un router no tiene comando router-id, tiene las loopbacks 10.1.1.1 y 10.9.9.9, y G0/0 en 192.168.1.1. ¿Cuál es su RID?

10.9.9.9, la dirección de loopback más alta; las loopbacks se prefieren a las interfaces físicas aunque una dirección física sea mayor.

¿En qué interfaces habilita OSPF network 172.16.0.0 0.0.255.255 area 0?

En cualquier interfaz con una dirección entre 172.16.0.0 y 172.16.255.255.

¿Qué hace passive-interface con la subred conectada de esa interfaz?

La subred se sigue anunciando en OSPF, pero no se envían hellos ni se forman vecinos en esa interfaz.

Cambias el router-id en un router OSPF que está funcionando. ¿Cuándo tiene efecto?

Después de un reinicio o de clear ip ospf process, porque el RID solo se elige cuando arranca el proceso OSPF.
