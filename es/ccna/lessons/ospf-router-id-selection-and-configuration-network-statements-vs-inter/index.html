Selección y configuración del router ID de OSPF (sentencias network vs comandos de interfaz, interfaces pasivas)

Todo router OSPF necesita un router ID (RID), un valor de 32 bits escrito como una dirección IPv4, que lo identifica en la LSDB, en las tablas de vecinos y en las elecciones de DR. No tiene que ser una dirección alcanzable, pero debe ser único dentro del dominio OSPF.

IOS elige el router ID en este orden. Primero, un router-id configurado manualmente bajo el proceso OSPF. Si no lo hay, la dirección IPv4 más alta de cualquier interfaz loopback activa. Si no hay loopbacks, la dirección IPv4 más alta de cualquier interfaz física activa. Se prefieren las loopbacks porque nunca se caen a menos que se apaguen deliberadamente, lo que mantiene estable el RID. La buena práctica es definirlo explícitamente: router ospf 1 y luego router-id 1.1.1.1.

El RID se elige cuando arranca el proceso OSPF y no cambia por sí solo. Si cambias el router ID configurado, IOS te avisa que tendrá efecto después de un reinicio (reload) o de un clear ip ospf process. Los router ID duplicados provocan fallas de adyacencia y mensajes de log, así que una configuración copiada que repite un RID es un error común de laboratorio.

Hay dos formas de habilitar OSPF en las interfaces. La forma tradicional usa sentencias network bajo el proceso: network 10.1.1.0 0.0.0.255 area 0. La dirección y la wildcard mask forman un patrón: cualquier interfaz cuya dirección IP coincida con el patrón ejecuta OSPF en esa área, y se anuncia su subred conectada. La wildcard es una máscara inversa, donde los bits en 0 deben coincidir y los bits en 1 se ignoran. Puedes ser amplio (network 10.0.0.0 0.255.255.255 area 0) o preciso, haciendo coincidir exactamente una interfaz con network 10.1.1.1 0.0.0.0 area 0. La sentencia network no decide qué prefijo se anuncia; eso lo deciden la dirección y la máscara de la propia interfaz.

La forma más nueva es habilitar OSPF directamente en la interfaz: interface g0/1 y luego ip ospf 1 area 0. Es explícita y fácil de leer, y tiene prioridad sobre cualquier sentencia network para esa interfaz. Ambos métodos producen el mismo resultado, y el examen espera que sepas leer cualquiera de los dos.

router ospf 1
 router-id 1.1.1.1
 network 192.168.10.0 0.0.0.255 area 0
 passive-interface g0/2
!
interface g0/1
 ip ospf 1 area 0

Una interfaz pasiva es aquella en la que OSPF anuncia la subred conectada pero no envía hellos, así que no se forman vecinos. Úsala en las interfaces LAN que dan hacia los usuarios, donde no hay routers: evita hellos innecesarios e impide que un dispositivo no autorizado forme una adyacencia e inyecte rutas. Configura passive-interface g0/2, o haz pasivas todas las interfaces con passive-interface default y luego vuelve a habilitar las que necesitan vecinos con no passive-interface g0/0. Las interfaces loopback se anuncian como rutas de host /32 de forma predeterminada; ip ospf network point-to-point en la loopback hace que se anuncie su máscara configurada.

Verifica con show ip protocols, que muestra el RID, las sentencias network, las interfaces pasivas y los orígenes de información de enrutamiento, y con show ip ospf interface brief, que lista las interfaces que ejecutan OSPF, su área, su costo y su estado.

Términos clave

Router ID
Un identificador OSPF único de 32 bits elegido de router-id, la IP de loopback más alta o la IP de interfaz activa más alta, en ese orden.
Network statement (sentencia network)
Un comando del proceso OSPF que usa una dirección y una wildcard para seleccionar qué interfaces ejecutan OSPF en un área.
ip ospf area
Comando de interfaz (ip ospf <process> area <area>) que habilita OSPF directamente en una interfaz.
Passive interface (interfaz pasiva)
Una interfaz cuya subred anuncia OSPF pero en la que no envía hellos ni forma vecinos.
Wildcard mask
Una máscara inversa en la que los bits en 0 deben coincidir y los bits en 1 se ignoran.
Ejemplo real

R2 tiene la loopback 0 en 2.2.2.2 y las interfaces 10.0.12.2 y 192.168.20.1. Sin comando router-id, su RID es 2.2.2.2, tomado de la loopback. El ingeniero agrega router-id 22.22.22.22, ve el mensaje de que tendrá efecto después de un reload o un clear, ejecuta clear ip ospf process y hace pasiva la LAN de usuarios para que las PC nunca reciban hellos.

Consejo para el examen: Orden de selección del RID: router-id manual, luego la loopback más alta, luego la interfaz física más alta. 'Más alta' se refiere a la dirección numérica, no al número de interfaz.

Comprueba lo que sabes

Un router no tiene comando router-id, tiene las loopbacks 10.1.1.1 y 10.9.9.9, y G0/0 en 192.168.1.1. ¿Cuál es su RID?

10.9.9.9, la dirección de loopback más alta; las loopbacks tienen preferencia sobre las interfaces físicas aunque una dirección física sea más alta.

¿En qué interfaces habilita OSPF network 172.16.0.0 0.0.255.255 area 0?

En cualquier interfaz con una dirección de 172.16.0.0 a 172.16.255.255.

¿Qué hace passive-interface con la subred conectada de esa interfaz?

La subred se sigue anunciando en OSPF, pero no se envían hellos ni se forman vecinos en esa interfaz.
