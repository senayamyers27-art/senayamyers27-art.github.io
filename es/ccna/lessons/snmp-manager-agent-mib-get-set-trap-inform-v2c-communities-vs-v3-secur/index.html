SNMP: manager, agente, MIB, get/set/trap/inform, comunidades v2c vs niveles de seguridad v3

Simple Network Management Protocol (SNMP) es el estándar de larga data para supervisar dispositivos de red. Permite que un sistema de monitoreo central lea valores como los contadores de interfaces, la carga de CPU y la temperatura, reciba alertas cuando algo ocurre y, cuando se permite, cambie configuraciones. Aunque la telemetría en streaming está creciendo, SNMP sigue estando en todas partes, y el CCNA evalúa sus componentes, tipos de mensajes y versiones.

Hay tres componentes. El SNMP manager es el software de la estación de administración de red (NMS) que recopila y muestra los datos. El SNMP agent (agente) es el software de cada dispositivo administrado que responde al manager y envía alertas. La MIB (management information base, base de información de administración) es la colección estructurada de variables que expone el agente, organizada como un árbol. Cada variable se identifica con un OID (object identifier, identificador de objeto), una cadena de números separados por puntos, como el de los octetos de entrada de una interfaz. Las MIB estándar cubren los datos comunes, y los fabricantes publican las suyas para valores específicos de sus dispositivos.

Los tipos de mensaje determinan quién habla y por qué. Get solicita el valor de uno o más OID; GetNext avanza al siguiente OID del árbol; GetBulk (añadido en v2c) obtiene muchos valores de forma eficiente. Set cambia un valor en el agente, por ejemplo para apagar una interfaz, por eso el acceso de escritura debe controlarse estrictamente. Un trap es una alerta no solicitada que el agente envía al manager, como 'link down', y no se confirma, así que puede perderse. Un inform es como un trap, pero el manager lo confirma, y el agente lo reenvía si no llega la confirmación, lo que lo hace más confiable. Los agentes escuchan en el puerto UDP 161; los managers reciben traps e informs en el puerto UDP 162.

SNMPv1 y v2c protegen el acceso solo con community strings (cadenas de comunidad), que actúan como contraseñas compartidas: normalmente una comunidad de solo lectura (RO) y una de lectura-escritura (RW). Se envían en texto claro, así que cualquiera que capture el tráfico puede leerlas, y las comunidades predeterminadas como 'public' y 'private' son una debilidad muy conocida. En IOS: snmp-server community N0tPublic RO 10 permite acceso de solo lectura desde los orígenes permitidos por la ACL 10, y snmp-server host 10.1.1.5 version 2c N0tPublic envía traps.

SNMPv3 añade seguridad real con usuarios y grupos, y tres niveles de seguridad. noAuthNoPriv autentica solo con un nombre de usuario y no cifra. authNoPriv autentica los mensajes con un hash como SHA, para que no puedan falsificarse ni alterarse, pero no cifra. authPriv añade cifrado como AES, para que el contenido sea confidencial. authPriv es el nivel recomendado.

snmp-server group NMS-GROUP v3 priv
snmp-server user nmsuser NMS-GROUP v3 auth sha AuthPass123 priv aes 128 PrivPass123
snmp-server host 10.1.1.5 version 3 priv nmsuser

Verifica con show snmp, show snmp user y show snmp group. La buena práctica de seguridad es usar SNMPv3 authPriv, evitar el acceso RW a menos que sea necesario, restringir con una ACL qué hosts pueden hacer consultas y nunca dejar configuradas las community strings predeterminadas.

Términos clave

SNMP manager / agent (manager / agente SNMP)
La estación de monitoreo que consulta y recibe alertas, y el software del dispositivo que responde y las envía.
MIB / OID
El árbol de variables administrables de un dispositivo, y el identificador numérico de cada variable.
Trap vs inform
Ambas son alertas iniciadas por el agente; un trap no se confirma, un inform se confirma y se retransmite si es necesario.
Community string (cadena de comunidad)
La contraseña compartida en texto claro que usan SNMPv1 y v2c para el acceso de solo lectura o de lectura-escritura.
authPriv
El nivel de seguridad de SNMPv3 con autenticación y cifrado.
Ejemplo real

Un sistema de monitoreo de red consulta cada switch cada cinco minutos con GetBulk para graficar la utilización de las interfaces. Cuando falla un enlace ascendente, el switch envía de inmediato un inform SNMPv3 al NMS en UDP 162; el NMS lo confirma y avisa al ingeniero de guardia. La antigua comunidad v2c 'public' encontrada durante una auditoría se elimina.

Consejo para el examen: Los traps no se confirman; los informs sí. Para los niveles de seguridad, recuerda el orden: noAuthNoPriv, authNoPriv, authPriv, y que solo authPriv cifra.

Comprueba lo que sabes

¿Qué mensaje SNMP permite que un agente alerte al manager y asegura la entrega con una confirmación?

Inform.

¿Cuál es la principal debilidad de seguridad de SNMPv2c?

Las community strings se envían en texto claro y no hay autenticación por usuario ni cifrado.

¿Qué nivel de seguridad de SNMPv3 proporciona autenticación pero no cifrado?

authNoPriv.
