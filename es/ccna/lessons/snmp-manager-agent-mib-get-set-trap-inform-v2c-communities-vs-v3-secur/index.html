SNMP: manager, agente, MIB, get/set/trap/inform, comunidades v2c vs niveles de seguridad v3

SNMP (Simple Network Management Protocol) es el estándar de larga data para monitorear dispositivos de red. Permite que un sistema de monitoreo central lea valores como los contadores de interfaz, la carga de CPU y la temperatura, reciba alertas cuando ocurre algo y, cuando está permitido, cambie la configuración. Aunque la telemetría en streaming crece, SNMP sigue presente casi en todas partes, y el CCNA evalúa sus componentes, tipos de mensaje, puertos y versiones.

Hay tres componentes. El SNMP manager es el software de la NMS (network management station) que recopila, guarda y muestra los datos. El agente SNMP es software en cada dispositivo administrado que responde al manager y envía alertas. La MIB (management information base) es el conjunto estructurado de variables que expone el agente, organizado como un árbol. Cada variable se identifica con un OID (object identifier), una cadena de números separados por puntos, como el del contador de octetos de entrada de una interfaz. Las MIB estándar cubren los datos comunes, y los fabricantes publican las suyas para los valores propios de cada dispositivo. Puedes recorrer la MIB de un dispositivo desde una estación de administración con una herramienta como snmpwalk, que emite solicitudes GetNext o GetBulk repetidas, para descubrir qué OID admite.

Los tipos de mensaje determinan quién habla y por qué. Get solicita el valor de uno o más OID; GetNext avanza al siguiente OID del árbol; GetBulk, agregado en v2c, obtiene muchos valores de forma eficiente. Set cambia un valor en el agente, por ejemplo para apagar una interfaz, y por eso el acceso de escritura debe controlarse estrictamente. Un trap es una alerta no solicitada que el agente envía al manager, como link down, y no se confirma, así que puede perderse. Un inform es como un trap, pero el manager lo confirma, y el agente lo reenvía si no llega la confirmación, lo que lo hace más confiable a cambio de un poco más de sobrecarga. Los agentes escuchan en el puerto UDP 161; los managers reciben traps e informs en el puerto UDP 162.

SNMPv1 y v2c protegen el acceso solo con community strings, que funcionan como contraseñas compartidas: normalmente una community de solo lectura (RO) y una de lectura y escritura (RW). Se envían en texto claro, así que cualquiera que capture el tráfico puede leerlas, y las communities predeterminadas como 'public' y 'private' son una debilidad muy conocida. En IOS, snmp-server community N0tPublic RO 10 permite el acceso de solo lectura desde los orígenes permitidos por la ACL 10, y snmp-server host 10.1.1.5 version 2c N0tPublic envía los traps al manager. Como solo la community string decide el acceso, cualquiera que conozca la string RW puede cambiar el dispositivo, así que trátala como una contraseña de administrador.

SNMPv3 agrega seguridad real con usuarios y grupos, y tres niveles de seguridad. noAuthNoPriv identifica al usuario solo por el nombre de usuario y no cifra. authNoPriv autentica los mensajes con un hash como SHA (Secure Hash Algorithm), para que no puedan falsificarse ni alterarse, pero no cifra. authPriv agrega cifrado, como AES (Advanced Encryption Standard), para que el contenido sea confidencial. authPriv es el nivel recomendado. En la configuración de abajo, el grupo exige priv, el usuario tiene una contraseña de autenticación y una de privacidad, y los traps se envían usando ese usuario.

snmp-server group NMS-GROUP v3 priv
snmp-server user nmsuser NMS-GROUP v3 auth sha AuthPass123 priv aes 128 PrivPass123
snmp-server host 10.1.1.5 version 3 priv nmsuser

Veamos un ejemplo resuelto. Una auditoría de seguridad de una oficina regional encuentra switches que responden consultas SNMP con la community 'public' desde cualquier dirección, además de una community RW que nadie usa. Un atacante en la VLAN de usuarios podría leer las tablas completas de interfaces y ARP, y con la string RW incluso podría cambiar la configuración. El ingeniero elimina ambas communities, crea un grupo y un usuario SNMPv3 en authPriv como arriba, aplica una ACL para que solo la NMS en 10.1.1.5 pueda consultar, y configura informs en lugar de traps para los eventos críticos, de modo que las alertas de link down no se pierdan si se descarta un paquete. La NMS se actualiza con las credenciales v3, y show snmp user y show snmp group confirman la configuración. Las gráficas siguen actualizándose, y una captura de paquetes ahora muestra cargas SNMP cifradas.

Errores comunes: invertir los puertos (los agentes en 161, los managers en 162); pensar que los traps se confirman; creer que las communities v2c están cifradas; suponer que authNoPriv oculta los datos; y dejar habilitado el acceso RW cuando solo se necesita monitoreo. Pistas del examen: 'alerta no solicitada y sin confirmación' significa trap; 'alerta confirmada' significa inform; 'cambiar un valor' significa Set; 'base de datos de variables' significa MIB; 'identificador numérico' significa OID; 'software en el dispositivo' significa agente; 'string compartida en texto claro' significa community (v1 o v2c); 'autenticación y cifrado' significa SNMPv3 authPriv; 'autenticación pero sin cifrado' significa authNoPriv.

Términos clave

SNMP manager
El software de la estación de administración de red que consulta a los agentes y recibe las alertas.
Agente SNMP (SNMP agent)
Software en un dispositivo administrado que responde a las solicitudes y envía traps o informs.
MIB
Management information base, el árbol de variables que expone un agente, cada una identificada por un OID.
Trap
Una alerta no solicitada y sin confirmación que el agente envía al manager por UDP 162.
Inform
Una alerta como un trap que el manager confirma, para que el agente pueda reenviarla.
Community string
Una contraseña compartida en texto claro que usan SNMPv1 y v2c para el acceso RO o RW.
authPriv
El nivel de seguridad de SNMPv3 que autentica y además cifra los mensajes.
Ejemplo real

Un proveedor de servicios administrados monitorea cientos de routers de clientes. Estandariza SNMPv3 authPriv con un usuario por cliente, restringe SNMP a las direcciones de sus colectores con ACL y usa informs para las fallas de fuente de alimentación y de enlace, de modo que las alertas se reintenten si la WAN descarta un paquete. Un script de cumplimiento encuentra y elimina las communities v2c antiguas que dejaron instaladores anteriores.

Consejo para el examen: Los traps no se confirman; los informs sí. Para los niveles de seguridad, recuerda el orden noAuthNoPriv, authNoPriv, authPriv, y que solo authPriv cifra. Los agentes escuchan en UDP 161 y los managers en UDP 162.

Comprueba lo que sabes

¿Cuál es la diferencia entre un trap y un inform?

Un trap no se confirma y puede perderse; un inform lo confirma el manager y se reenvía si no llega la confirmación.

¿Qué nivel de seguridad de SNMPv3 ofrece cifrado?

authPriv, que agrega privacidad (cifrado como AES) a la autenticación.

¿Por qué las community strings de SNMPv2c se consideran débiles?

Son contraseñas compartidas que se envían en texto claro, y las predeterminadas, como public y private, son ampliamente conocidas.

¿Qué puertos UDP usa SNMP?

Los agentes reciben solicitudes en el 161; los managers reciben traps e informs en el 162.
