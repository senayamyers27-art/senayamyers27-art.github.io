Cisco CCNA 200-301 v2.0

Solución de problemas de conectividad de clientes cableados e inalámbricos (verificar la configuración IP en Windows, macOS y Linux)

Muchos tickets de red empiezan con un solo usuario que no puede conectarse. Antes de revisar switches o routers, verifica lo que cree el propio cliente: su dirección IP, máscara, gateway predeterminado y servidores DNS, y si realmente está conectado en las Capas 1 y 2. El CCNA espera que conozcas los comandos de los tres sistemas operativos de escritorio más comunes y que sepas interpretar su salida.

En Windows, ipconfig muestra las direcciones IPv4 e IPv6, la máscara y el gateway predeterminado de cada adaptador. ipconfig /all añade la dirección MAC (física), si DHCP está habilitado, el servidor DHCP, los tiempos de concesión y los servidores DNS. ipconfig /release e ipconfig /renew liberan y solicitan una concesión DHCP, e ipconfig /flushdns borra la caché DNS local. netsh wlan show interfaces informa el SSID conectado, el BSSID, el canal y la calidad de la señal para Wi-Fi.

En macOS, ifconfig muestra las interfaces y direcciones (en0 suele ser el Wi-Fi en las laptops). ipconfig getifaddr en0 imprime solo la dirección, y networksetup -getinfo Wi-Fi muestra la dirección, la máscara y el router. netstat -rn muestra la tabla de enrutamiento, donde la ruta predeterminada revela el gateway. En Linux, la herramienta moderna es ip: ip addr (o ip a) lista las direcciones, ip route muestra el gateway predeterminado e ip link muestra el estado del enlace. Los sistemas más antiguos todavía tienen ifconfig y route -n. La configuración DNS está en /etc/resolv.conf o se puede consultar con resolvectl status en sistemas que usan systemd-resolved. Las tres plataformas admiten ping, nslookup y una herramienta de traceroute (tracert en Windows, traceroute en macOS y Linux).

Usa un enfoque estructurado. Primero revisa las capas física y de enlace de datos: ¿el cable está conectado y la luz de enlace encendida, o la laptop está asociada al SSID correcto con una señal razonable? Luego revisa la configuración IP: una dirección 169.254 apunta a una falla de DHCP; una dirección que parece correcta pero con la máscara o el gateway equivocados apunta a un error de configuración estática. Después, prueba la alcanzabilidad por pasos: haz ping al gateway, luego a una IP remota y luego a un nombre. Si una IP funciona pero un nombre no, el problema es el DNS.

Lo inalámbrico añade sus propios puntos de falla. El cliente puede estar en el SSID equivocado, tener guardada una contraseña incorrecta, fallar la autenticación 802.1X, estar demasiado lejos del AP, o estar en un canal saturado o con interferencia. Un cliente que está asociado pero tiene una dirección APIPA a menudo tiene una conexión inalámbrica correcta, pero la WLAN está asignada a una VLAN donde no se llega al DHCP. Compara también con un cliente que funcione en el mismo lugar: si los demás se conectan bien, céntrate en el cliente; si todos fallan, céntrate en la red.

Términos clave

ipconfig /all
Comando de Windows que muestra todos los detalles del adaptador, incluidos la MAC, el servidor DHCP, la concesión y los servidores DNS.
ip addr / ip route
Comandos de Linux que muestran las direcciones de las interfaces y la tabla de enrutamiento, incluido el gateway predeterminado.
ifconfig
Comando heredado de interfaces que todavía se usa en macOS y en Linux antiguo para mostrar direcciones y el estado de las interfaces.
RSSI
Received signal strength indicator (indicador de intensidad de la señal recibida), una medida de qué tan fuerte es la señal inalámbrica en el cliente.
Ejemplo real

Un usuario de una laptop Linux no puede navegar. ip a muestra 10.20.30.44/24 en wlan0 e ip route muestra una ruta default via 10.20.30.1. ping 10.20.30.1 y ping 8.8.8.8 funcionan, pero ping intranet.example.com falla con un error de resolución de nombres. /etc/resolv.conf indica un servidor DNS antiguo. Corregir la configuración DNS resuelve el problema.

Consejo para el examen: Debes saber a qué sistema operativo pertenece cada comando: ipconfig en Windows, ifconfig en macOS, ip addr en Linux. Las preguntas suelen mostrar una salida y preguntar de qué plataforma es o qué configuración está mal.

Comprueba lo que sabes

¿Qué comando de Windows muestra los servidores DNS y el servidor DHCP que usa un cliente?

ipconfig /all.

Un usuario puede hacer ping a un servidor remoto por IP pero no por nombre. ¿Qué configuración investigas?

El DNS: los servidores DNS configurados en el cliente y si pueden resolver el nombre.

En un host Linux moderno, ¿cómo muestras el gateway predeterminado?

Ejecuta ip route y busca la línea que empieza con 'default via'.
