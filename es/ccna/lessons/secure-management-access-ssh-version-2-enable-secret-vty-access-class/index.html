Cisco CCNA 200-301 v2.0

Acceso de administración seguro: SSH versión 2, enable secret, access-class en VTY, banners de inicio de sesión

Quien obtiene acceso administrativo a un router o switch controla la red. Asegurar el acceso de administración significa cifrar las sesiones remotas, proteger el modo privilegiado con una contraseña fuerte, restringir quién puede siquiera intentar iniciar sesión y mostrar una advertencia legal. Estos son algunos de los elementos que más se configuran en los laboratorios del CCNA.

Telnet envía todo, incluidas las contraseñas, en texto claro, así que cualquiera que capture el tráfico puede leerlo. SSH (Secure Shell) cifra la sesión y usa el puerto TCP 22. Para habilitar SSH en IOS, el dispositivo necesita un hostname distinto del predeterminado, un nombre de dominio y un par de claves RSA, porque el nombre de la clave se construye a partir del hostname y el dominio. SSH versión 2 es más seguro que la versión 1 y debe exigirse; IOS requiere un módulo RSA de al menos 768 bits para la versión 2, y 2048 bits es una elección sensata.

hostname R1
ip domain-name example.local
crypto key generate rsa modulus 2048
ip ssh version 2
username admin privilege 15 secret Str0ngPass
line vty 0 15
 login local
 transport input ssh
 access-class 10 in
 exec-timeout 10 0

transport input ssh permite solo SSH en las líneas VTY, bloqueando Telnet. login local usa la base de datos local de usuarios (o podrías usar AAA). Protege también la línea de consola con una contraseña o login local, y configura exec-timeout para que se cierren las sesiones inactivas.

El modo EXEC privilegiado se protege con enable secret, que almacena la contraseña como un hash robusto. El antiguo enable password la almacena en texto claro o, con service password-encryption, como un valor tipo 7, que se revierte fácilmente y solo evita que alguien lea la contraseña de la configuración por encima de tu hombro. Si ambos están configurados, enable secret tiene prioridad. Usa secret en cada contraseña donde esté disponible, incluido username ... secret. security passwords min-length y login block-for añaden protección contra contraseñas cortas e intentos de fuerza bruta.

access-class aplica una ACL estándar a las líneas VTY para controlar qué direcciones de origen pueden conectarse. Por ejemplo, access-list 10 permit 10.1.99.0 0.0.0.255 y luego access-class 10 in bajo las líneas VTY permite que solo la subred de administración abra sesiones SSH. Fíjate en la diferencia: access-class filtra en las líneas, mientras que ip access-group filtra en las interfaces.

Los banners de inicio de sesión muestran un aviso legal. banner motd # Authorized access only. Activity is monitored. # muestra un banner de mensaje del día antes del inicio de sesión; el carácter después de motd es un delimitador que marca el inicio y el final. Los banners deben advertir contra el uso no autorizado y nunca decir 'bienvenido'. Verifica SSH con show ip ssh y show ssh, y prueba con un cliente SSH desde una dirección permitida y desde una no permitida.

Términos clave

SSH version 2 (SSH versión 2)
Un protocolo de administración remota cifrado en el puerto TCP 22; la versión que debe exigirse en los dispositivos de red.
enable secret
Comando que protege el modo EXEC privilegiado con una contraseña en hash; tiene prioridad sobre enable password.
transport input ssh
Comando de línea VTY que permite solo conexiones SSH.
access-class
Comando de línea que aplica una ACL estándar para restringir qué direcciones de origen pueden usar las líneas VTY.
banner motd
Un banner de mensaje del día que se muestra antes del inicio de sesión, normalmente una advertencia legal.
Ejemplo real

Una auditoría descubre switches que permiten Telnet desde cualquier lugar. El equipo aplica una configuración estándar: hostname y dominio, crypto key generate rsa modulus 2048, ip ssh version 2, transport input ssh y access-class 10 in permitiendo solo 10.1.99.0/24, además de enable secret y un banner de advertencia. Un escaneo posterior muestra el puerto 23 cerrado y SSH accesible solo desde la subred de administración.

Consejo para el examen: SSH necesita un hostname, un nombre de dominio y claves RSA antes de funcionar. Si una pregunta dice que la generación de claves falló o que SSH no está habilitado, busca un hostname o un ip domain-name faltante.

Comprueba lo que sabes

¿Cuáles son los requisitos previos para generar claves RSA para SSH en IOS?

Un hostname que no sea el predeterminado y un nombre de dominio (ip domain-name); luego crypto key generate rsa con un módulo adecuado.

Si están configurados tanto enable password como enable secret, ¿cuál se usa?

enable secret, que además almacena la contraseña como un hash más robusto.

¿Cuál es la diferencia entre access-class e ip access-group?

access-class aplica una ACL a las líneas VTY para controlar las sesiones de administración; ip access-group aplica una ACL a una interfaz para filtrar el tráfico que pasa por ella.
