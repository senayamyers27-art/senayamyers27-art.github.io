Cisco CCNA 200-301 v2.0

Acceso de administración seguro: SSH versión 2, enable secret, access-class en VTY, banners de inicio de sesión

Quien obtiene acceso administrativo a un router o switch controla la red. Asegurar el acceso de administración significa cifrar las sesiones remotas, proteger el modo privilegiado con una contraseña fuerte, restringir quién puede siquiera intentar iniciar sesión y mostrar una advertencia legal. Estos son algunos de los elementos que más se configuran en los laboratorios de CCNA, y un paso faltante suele significar que SSH simplemente no funciona, sin mostrar error.

Telnet envía todo, incluidas las contraseñas, en texto claro por el puerto TCP 23, así que cualquiera que capture el tráfico puede leerlo. SSH (Secure Shell) cifra la sesión y usa el puerto TCP 22. Para habilitar SSH en IOS, el dispositivo necesita un hostname distinto del predeterminado Router o Switch, un nombre de dominio y un par de claves RSA (Rivest-Shamir-Adleman), porque el nombre de la clave se construye a partir del hostname y el dominio. SSH versión 2 es más seguro que la versión 1 y conviene exigirlo; IOS requiere un módulo RSA de al menos 768 bits para la versión 2, y 2048 bits es una elección sensata.

hostname R1
ip domain-name example.local
crypto key generate rsa modulus 2048
ip ssh version 2
username admin privilege 15 secret Str0ngPass
access-list 10 permit 10.1.99.0 0.0.0.255
line vty 0 15
 login local
 transport input ssh
 access-class 10 in
 exec-timeout 10 0

Recorre la configuración paso a paso. El hostname y el nombre de dominio permiten generar las claves; generar las claves habilita el servidor SSH. ip ssh version 2 rechaza a los clientes de la versión 1. El nombre de usuario le da un inicio de sesión a cada administrador. En las líneas VTY (virtual terminal), login local usa la base de datos de usuarios local (o podrías usar AAA), transport input ssh permite solo SSH y bloquea Telnet, y exec-timeout 10 0 cierra las sesiones que llevan diez minutos inactivas. Protege también la línea de consola con login local o una contraseña, porque el acceso físico sigue siendo acceso.

El modo EXEC privilegiado se protege con enable secret, que guarda la contraseña como un hash fuerte. El antiguo enable password la guarda en texto claro o, con service password-encryption, como un valor tipo 7, que se revierte fácilmente y solo evita que alguien lea la configuración por encima de tu hombro. Si ambos están configurados, enable secret tiene prioridad. Usa secret siempre que esté disponible, incluido username ... secret. security passwords min-length rechaza las contraseñas cortas, y login block-for 120 attempts 5 within 60 pausa los inicios de sesión después de fallas repetidas para frenar los intentos de fuerza bruta.

access-class aplica una ACL (access control list) estándar a las líneas VTY para controlar qué direcciones de origen pueden conectarse. En el ejemplo, la ACL 10 permite la subred de administración 10.1.99.0/24, y access-class 10 in en las líneas VTY significa que solo esa subred puede abrir sesiones SSH; todos los demás chocan con el deny implícito. Observa la diferencia: access-class filtra en las líneas, mientras que ip access-group filtra el tráfico que pasa por las interfaces. Los banners de inicio de sesión muestran un aviso legal. banner motd # Authorized access only. Activity is monitored. # muestra un banner de mensaje del día antes del inicio de sesión; el carácter que sigue a motd es un delimitador que marca el inicio y el final. Los banners deben advertir contra el uso no autorizado y nunca decir 'bienvenido'.

Veamos un ejemplo resuelto. Se instala un switch nuevo y una ingeniera escribe crypto key generate rsa, pero IOS lo rechaza con un mensaje que pide un nombre de dominio. Ella agrega ip domain-name corp.local, genera una clave de 2048 bits, configura ip ssh version 2 y restringe las líneas VTY como se mostró arriba. La prueba desde su PC de administración tiene éxito, y una prueba desde una VLAN de usuarios se rechaza, como se esperaba. show ip ssh confirma 'SSH Enabled - version 2.0', y show ssh lista su sesión activa. Luego, una revisión de seguridad señala el antiguo enable password, que ella reemplaza con enable secret.

Errores comunes: olvidar el nombre de dominio o dejar el hostname predeterminado; aplicar la restricción de VTY con ip access-group en lugar de access-class; dejar transport input all, con lo que Telnet sigue funcionando; configurar solo vty 0 4 en un dispositivo con líneas hasta la 15, lo que deja el resto abiertas; y confiar en que las contraseñas tipo 7 son seguras. Pistas del examen: 'falló la generación de claves crypto' apunta a un hostname o un nombre de dominio faltante; 'permitir que solo la subred de administración inicie sesión remotamente' es access-class en las líneas VTY; 'impedir Telnet' es transport input ssh; 'contraseña guardada como hash' es enable secret; 'advertencia legal antes del inicio de sesión' es un banner MOTD (message of the day).

Términos clave

SSH
Secure Shell, un protocolo de inicio de sesión remoto cifrado en el puerto TCP 22 que reemplaza a Telnet.
Par de claves RSA (RSA key pair)
Las claves pública y privada que genera el dispositivo para habilitar su servidor SSH.
enable secret
La contraseña del modo EXEC privilegiado guardada como un hash fuerte; tiene prioridad sobre enable password.
Contraseña tipo 7 (type 7 password)
La ofuscación débil y reversible que aplica service password-encryption.
access-class
Aplica una ACL estándar a las líneas VTY para controlar qué direcciones de origen pueden conectarse.
transport input ssh
Un comando de línea que permite solo sesiones SSH en las líneas VTY.
Banner MOTD (MOTD banner)
Un aviso de mensaje del día que se muestra antes del inicio de sesión y se usa para advertencias legales.
Ejemplo real

Durante una auditoría, una cadena minorista descubre que los routers de sus tiendas aceptan Telnet desde cualquier dirección y usan enable password. El equipo de red aplica una plantilla estándar: hostname y nombre de dominio, claves RSA de 2048 bits, SSH versión 2, transport input ssh, access-class para limitar los inicios de sesión a la subred de operaciones, enable secret, login block-for y un banner que indica que el acceso está restringido y monitoreado. Un escaneo posterior muestra el puerto TCP 23 cerrado y SSH respondiendo solo desde la red de administración.

Consejo para el examen: SSH necesita un hostname, un nombre de dominio y claves RSA antes de funcionar. Las líneas VTY se filtran con access-class, las interfaces con ip access-group, y enable secret le gana a enable password.

Comprueba lo que sabes

¿Qué tres cosas deben existir antes de que crypto key generate rsa pueda habilitar SSH?

Un hostname no predeterminado y un nombre de dominio IP, a partir de los cuales se construye el nombre de la clave, y luego la generación de claves en sí.

¿Cómo permites solo SSH, y no Telnet, en las líneas VTY?

Usa transport input ssh bajo line vty 0 15.

Si están configurados tanto enable password como enable secret, ¿cuál se usa?

enable secret, que además guarda la contraseña como un hash fuerte.

¿Qué comando restringe los inicios de sesión remotos a una subred de administración?

access-class <acl> in bajo las líneas VTY, con una ACL estándar que permita esa subred.
