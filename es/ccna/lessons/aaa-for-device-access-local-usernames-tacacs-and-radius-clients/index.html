Cisco CCNA 200-301 v2.0

AAA para el acceso a dispositivos: usuarios locales, clientes TACACS+ y RADIUS

AAA significa authentication, authorization and accounting (autenticación, autorización y registro). La autenticación pregunta quién eres, normalmente con un usuario y una contraseña. La autorización decide qué tienes permitido hacer, por ejemplo qué comandos o qué nivel de privilegio. El registro (accounting) guarda qué hiciste y cuándo, para auditoría y resolución de problemas. Aplicar AAA a routers y switches significa que los administradores inician sesión con cuentas individuales, no con una contraseña compartida, y que sus acciones pueden controlarse y registrarse.

El método más simple usa usuarios locales almacenados en cada dispositivo. username admin privilege 15 secret S3cureP@ss crea una cuenta cuya contraseña se almacena como un hash robusto. En las líneas VTY, login local hace que el dispositivo consulte esa base de datos local. Las cuentas locales están bien para unos pocos dispositivos, pero con decenas de dispositivos, agregar o quitar un usuario implica tocar cada uno, y no hay un registro central.

Los servidores AAA centrales resuelven eso. El dispositivo de red actúa como cliente AAA y envía cada inicio de sesión a un servidor, como Cisco ISE, que guarda las cuentas o las verifica contra un directorio. Hay dos protocolos. TACACS+ (Terminal Access Controller Access-Control System Plus) fue desarrollado por Cisco y usa el puerto TCP 49. Cifra todo el cuerpo del paquete y separa la autenticación, la autorización y el registro, lo que permite la autorización por comando. Eso lo convierte en la opción habitual para administrar dispositivos de red. RADIUS (Remote Authentication Dial-In User Service) es un estándar abierto que usa UDP, con los puertos 1812 para autenticación y 1813 para registro (las implementaciones más antiguas usan 1645 y 1646). Solo cifra la contraseña y combina la autenticación y la autorización en un solo intercambio. RADIUS es la opción habitual para el acceso a la red, como 802.1X para usuarios y Wi-Fi.

La configuración empieza con aaa new-model, que activa el marco AAA y cambia cómo funciona el inicio de sesión, así que configura primero una cuenta local de respaldo. Luego define el servidor y una lista de métodos (method list) que indica qué orígenes probar, y en qué orden.

aaa new-model
username admin privilege 15 secret S3cureP@ss
tacacs server ISE1
 address ipv4 10.1.1.50
 key MySharedKey
aaa authentication login default group tacacs+ local
aaa authorization exec default group tacacs+ local
aaa accounting commands 15 default start-stop group tacacs+

La lista de métodos group tacacs+ local significa: pregunta a los servidores TACACS+; si ninguno responde, recurre a la base de datos local. El respaldo ocurre solo cuando los servidores no son alcanzables, no cuando rechazan una contraseña; un rechazo es definitivo. La lista default se aplica a todas las líneas, a menos que se aplique una lista con nombre a una línea con login authentication <name>. RADIUS se configura de forma similar con radius server y group radius. Mantén siempre una cuenta local de respaldo para poder iniciar sesión si los servidores AAA se caen, y verifica con show aaa servers y probando inicios de sesión antes de cerrar tu sesión.

Términos clave

AAA
Authentication (quién eres), authorization (qué puedes hacer) y accounting (qué hiciste).
TACACS+
Protocolo AAA desarrollado por Cisco, en el puerto TCP 49, que cifra toda la carga útil y separa las tres funciones A.
RADIUS
Protocolo AAA de estándar abierto, en UDP 1812/1813, que cifra solo la contraseña y combina la autenticación y la autorización.
Method list (lista de métodos)
Una lista ordenada de orígenes de autenticación o autorización, como group tacacs+ y luego local.
aaa new-model
Comando global que habilita el marco AAA en un dispositivo IOS.
Ejemplo real

Una empresa con 150 switches usa TACACS+ para que los ingenieros inicien sesión con sus cuentas del directorio. Cuando un ingeniero se va, deshabilitar una sola cuenta del directorio elimina su acceso a todos los dispositivos, y los registros de accounting muestran qué comandos se ingresaron en cada switch. Durante una caída del servidor, la cuenta local de respaldo sigue funcionando porque la lista de métodos termina con local.

Consejo para el examen: TACACS+: TCP, cifrado de toda la carga útil, funciones AAA separadas, administración de dispositivos. RADIUS: UDP, cifrado solo de la contraseña, autenticación y autorización combinadas, acceso a la red. Las preguntas suelen pedirte que elijas según estos criterios.

Comprueba lo que sabes

¿Qué protocolo AAA cifra todo el cuerpo del paquete y admite autorización por comando?

TACACS+.

Con aaa authentication login default group radius local, ¿cuándo se usa la base de datos local?

Solo cuando ningún servidor RADIUS responde; si un servidor rechaza las credenciales, se niega el acceso.

¿Por qué configurar un usuario local antes de habilitar aaa new-model y una lista de métodos con servidor?

Para tener un inicio de sesión de respaldo que funcione si los servidores AAA no son alcanzables o están mal configurados, y así evitar quedarte bloqueado.
