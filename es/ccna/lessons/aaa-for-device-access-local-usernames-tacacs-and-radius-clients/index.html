Cisco CCNA 200-301 v2.0

AAA para el acceso a dispositivos: usuarios locales, clientes TACACS+ y RADIUS

AAA significa autenticación, autorización y contabilidad (authentication, authorization and accounting). La autenticación pregunta quién eres, normalmente con un nombre de usuario y una contraseña. La autorización decide qué tienes permitido hacer, como qué comandos puedes ejecutar o qué nivel de privilegio recibes. La contabilidad registra qué hiciste y cuándo, para auditoría y resolución de problemas. Aplicar AAA a routers y switches significa que los administradores inician sesión con cuentas individuales en lugar de una contraseña compartida, de modo que sus acciones se pueden controlar, registrar y rastrear hasta una persona, y el acceso de un empleado que se va se puede eliminar en un solo lugar.

El método más simple usa nombres de usuario locales almacenados en cada dispositivo. username admin privilege 15 secret S3cureP@ss crea una cuenta cuya contraseña se guarda como un hash fuerte. En las líneas VTY (virtual terminal), login local hace que el dispositivo consulte esa base de datos local. Las cuentas locales sirven para unos pocos dispositivos, pero con decenas de dispositivos, agregar o quitar un usuario significa tocar cada uno, las contraseñas se desincronizan y no hay un registro central de quién hizo qué.

Los servidores AAA centrales resuelven eso. El dispositivo de red actúa como cliente AAA y envía cada inicio de sesión a un servidor, como Cisco ISE (Identity Services Engine), que guarda las cuentas o las verifica contra un directorio. Hay dos protocolos. TACACS+ (Terminal Access Controller Access-Control System Plus) fue desarrollado por Cisco y usa el puerto TCP 49. Cifra todo el cuerpo del paquete y separa la autenticación, la autorización y la contabilidad, lo que permite la autorización por comando. Eso lo convierte en la opción habitual para administrar dispositivos de red. RADIUS (Remote Authentication Dial-In User Service) es un estándar abierto que usa UDP, con los puertos 1812 para autenticación y 1813 para contabilidad (las implementaciones antiguas usan 1645 y 1646). Cifra solo la contraseña y combina la autenticación y la autorización en un mismo intercambio. RADIUS es la opción habitual para el acceso a la red, como 802.1X para usuarios cableados y Wi-Fi.

La configuración empieza con aaa new-model, que activa el marco AAA y cambia de inmediato cómo funciona el inicio de sesión en las líneas, así que configura primero una cuenta local de respaldo. Luego define el servidor con su clave compartida y una lista de métodos que indica qué fuentes probar y en qué orden.

aaa new-model
username admin privilege 15 secret S3cureP@ss
tacacs server ISE1
 address ipv4 10.1.1.50
 key MySharedKey
aaa authentication login default group tacacs+ local
aaa authorization exec default group tacacs+ local
aaa accounting commands 15 default start-stop group tacacs+

La lista de métodos group tacacs+ local significa: consulta a los servidores TACACS+; si ninguno responde, recurre a la base de datos local. El respaldo ocurre solo cuando los servidores no son alcanzables o devuelven un error, no cuando rechazan una contraseña; un rechazo es definitivo. La lista default se aplica a todas las líneas, salvo que se aplique una lista con nombre a una línea con login authentication <name>. RADIUS se configura de la misma forma con radius server y group radius. Verifica con show aaa servers, que muestra el estado y los contadores de los servidores, y prueba siempre un nuevo inicio de sesión desde una segunda sesión antes de cerrar la actual.

Veamos un ejemplo resuelto. Un equipo de red de ocho personas administra 60 switches con una contraseña enable compartida. Un auditor pregunta quién cambió una VLAN el mes pasado y nadie puede responder. El equipo configura TACACS+ en todos los switches apuntando a dos nodos ISE, con local como respaldo y una cuenta local de emergencia guardada en una bóveda de contraseñas. Ahora cada ingeniero inicia sesión con una cuenta personal, el personal junior solo está autorizado para comandos show, y la contabilidad de comandos registra cada cambio de configuración con el nombre de usuario y la hora. Cuando en una ocasión los servidores ISE quedaron inalcanzables durante una caída de la WAN, la cuenta de emergencia siguió funcionando gracias al respaldo local.

Errores comunes: ingresar aaa new-model sin una cuenta local y quedarte sin acceso; esperar que se consulte la base de datos local después de que un servidor rechaza una contraseña; confundir qué protocolo cifra toda la carga útil; y elegir RADIUS cuando se requiere autorización por comando para los administradores. Las preguntas del examen suelen comparar los dos protocolos. Pistas como 'TCP 49', 'cifra toda la carga útil', 'separa la autorización', 'administración de dispositivos' o 'autorización de comandos' apuntan a TACACS+. 'UDP 1812/1813', 'estándar abierto', 'solo se cifra la contraseña', '802.1X' o 'acceso a la red para usuarios' apuntan a RADIUS. 'Registrar qué comandos ejecutó un administrador' es contabilidad, y 'qué nivel recibe un administrador' es autorización.

Términos clave

AAA
Autenticación, autorización y contabilidad (authentication, authorization and accounting): quién eres, qué puedes hacer y qué hiciste.
TACACS+
Protocolo AAA desarrollado por Cisco sobre TCP 49 que cifra toda la carga útil y separa las tres funciones de AAA.
RADIUS
Protocolo AAA de estándar abierto sobre UDP 1812 y 1813 que cifra solo la contraseña y combina la autenticación y la autorización.
Lista de métodos (method list)
Una lista ordenada de fuentes de autenticación, como group tacacs+ y luego local.
aaa new-model
El comando que habilita el marco AAA en un dispositivo Cisco IOS.
Respaldo local (local fallback)
Usar la base de datos de usuarios propia del dispositivo cuando no se puede llegar a los servidores AAA.
Contabilidad (accounting)
Registrar las sesiones y los comandos, con nombres de usuario y horas, para auditoría.
Ejemplo real

El equipo de red de una universidad pasa los inicios de sesión de los switches de contraseñas compartidas a TACACS+ en ISE. Cada ingeniero inicia sesión con una cuenta del directorio, los técnicos estudiantes reciben privilegio 1 con autorización solo para comandos show, y se registra cada comando de configuración. Por separado, el Wi-Fi usa RADIUS con 802.1X para que los estudiantes se autentiquen en la red con sus propias credenciales. Cuando aparece un cambio inesperado en una ACL, los registros de contabilidad muestran qué cuenta lo hizo y cuándo.

Consejo para el examen: TACACS+: TCP 49, cifrado de toda la carga útil, funciones AAA separadas, administración de dispositivos. RADIUS: UDP 1812/1813, cifrado solo de la contraseña, autenticación y autorización combinadas, acceso a la red. El respaldo local se aplica solo cuando los servidores no responden.

Comprueba lo que sabes

¿Qué protocolo AAA cifra todo el cuerpo del paquete y usa TCP?

TACACS+, en el puerto TCP 49, y por eso se prefiere para la administración de dispositivos.

Con aaa authentication login default group tacacs+ local, ¿qué ocurre si el servidor TACACS+ rechaza una contraseña?

El inicio de sesión falla; local se prueba solo si los servidores no responden, no después de un rechazo.

¿Por qué debes crear un usuario local antes de escribir aaa new-model?

AAA cambia el comportamiento del inicio de sesión de inmediato, y sin una cuenta local podrías quedarte sin acceso si los servidores no están disponibles.

¿Qué función de AAA registra los comandos que ingresó un administrador?

La contabilidad, por ejemplo con aaa accounting commands 15 default start-stop group tacacs+.
