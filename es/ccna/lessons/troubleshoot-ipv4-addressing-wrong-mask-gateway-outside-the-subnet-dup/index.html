Cisco CCNA 200-301 v2.0

Solución de problemas de direccionamiento IPv4: máscara incorrecta, gateway fuera de la subred, direcciones duplicadas, APIPA

Cuando un host no puede llegar a algo, su propia configuración IP es una de las primeras cosas que debes revisar. Hay cuatro problemas que aparecen una y otra vez: una máscara de subred incorrecta, un gateway predeterminado que no está en la subred del host, dos dispositivos usando la misma dirección, y un host que no obtuvo DHCP y se asignó a sí mismo una dirección APIPA. Cada uno tiene un patrón de síntomas reconocible.

Una máscara incorrecta cambia qué destinos considera locales el host. Si un host en 192.168.1.50 debería ser /24 pero está configurado como /16, cree que 192.168.5.10 está en su propia red y envía una solicitud ARP en lugar de reenviar al gateway. Nadie responde, así que ese tráfico falla, mientras que el tráfico hacia otros destinos puede seguir funcionando. Una máscara demasiado larga causa el problema contrario: el host trata a algunos vecinos que en realidad son locales como remotos y envía su tráfico al gateway, que puede o no devolverlo enrutado. La conectividad parcial, donde algunas direcciones funcionan y otras no, es una fuerte pista para revisar la máscara.

El gateway predeterminado debe ser una dirección dentro de la propia subred del host, porque el host llega al gateway haciendo ARP directamente hacia él. Si un host es 10.1.1.20/24 y su gateway es 10.1.2.1, el host puede hablar con los dispositivos locales pero con nada fuera de su subred. Lo mismo aplica a la inversa: la interfaz del router debe estar configurada con una dirección y una máscara que coincidan con las de los hosts. Compara ipconfig en la PC con show ip interface brief y show running-config interface en el router.

Las direcciones duplicadas causan problemas intermitentes. Dos dispositivos responden al ARP de la misma IP, así que los switches y otros hosts actualizan sus tablas una y otra vez y el tráfico va a un dispositivo y luego al otro. Windows normalmente avisa de un conflicto de direcciones, e IOS registra un mensaje de dirección duplicada cuando un dispositivo usa la propia dirección de interfaz del router. Usa show ip arp en el router o arp -a en un host para ver qué dirección MAC tiene actualmente esa IP, y luego rastrea esa MAC con show mac address-table hasta el puerto del switch. Los servidores DHCP ayudan a evitar conflictos, y excluir de los pools DHCP las direcciones asignadas estáticamente impide que el servidor las reparta.

APIPA (Automatic Private IP Addressing, direccionamiento IP privado automático) es lo que hacen Windows y muchos otros sistemas cuando están configurados para usar DHCP pero no reciben respuesta: se asignan a sí mismos una dirección de 169.254.0.0/16 sin gateway. Por lo tanto, una dirección APIPA te dice que el host nunca llegó a un servidor DHCP. La causa está en el camino hacia el DHCP: un cable desconectado, el puerto en la VLAN equivocada, la falta de ip helper-address en el router, o un servidor DHCP que se quedó sin direcciones. No es un problema que se arregle en el host.

Un buen hábito de resolución de problemas es hacer ping hacia afuera por pasos: la propia dirección del host, el gateway predeterminado, una dirección remota y luego un nombre. El punto donde los pasos empiezan a fallar te indica qué capa o configuración inspeccionar.

Términos clave

Default gateway (gateway predeterminado)
La dirección del router a la que un host envía el tráfico fuera de su subred; debe estar dentro de la propia subred del host.
APIPA
Automatic Private IP Addressing: una dirección autoasignada 169.254.x.x/16 que se usa cuando un cliente DHCP no recibe respuesta.
Duplicate address (dirección duplicada)
Dos dispositivos configurados con la misma IP, lo que hace que las entradas ARP cambien de uno a otro y provoca conectividad intermitente.
ARP
Address Resolution Protocol, que asocia una dirección IPv4 conocida con la dirección MAC en el segmento local.
Ejemplo real

Un usuario informa que el correo funciona pero la wiki interna no. ipconfig muestra 10.10.20.35 con máscara 255.0.0.0. La wiki está en 10.10.40.8, que la PC ahora considera local, así que hace ARP hacia ella y no obtiene respuesta. Al corregir la máscara a 255.255.255.0, ese tráfico se envía al gateway y la wiki carga.

Consejo para el examen: Una dirección 169.254.x.x nunca significa 'arregla la IP de la PC'; significa que el intercambio DHCP falló. Busca la respuesta relacionada con VLAN, cableado, el servidor DHCP o la helper address.

Comprueba lo que sabes

Una PC muestra 169.254.33.7 sin gateway predeterminado. ¿Qué te dice esto?

La PC es un cliente DHCP que no recibió ninguna oferta y se autoasignó una dirección APIPA; el problema está en llegar al servidor DHCP, por ejemplo la VLAN, el cableado, el relay o el agotamiento del pool.

Un host es 192.168.4.10/24 con gateway 192.168.5.1. ¿Qué funciona y qué falla?

Funciona la comunicación con otros hosts de 192.168.4.0/24; todo lo que está fuera de la subred falla porque el gateway no está en la subred del host y no se le puede hacer ARP.

¿Qué comandos ayudan a localizar el dispositivo que usa una dirección IP duplicada?

Usa show ip arp o arp -a para encontrar la dirección MAC de esa IP, y luego show mac address-table para encontrar el puerto del switch donde se aprendió esa MAC.
