Cisco CCNA 200-301 v2.0

Configuración de direcciones IPv6: estática, EUI-64, SLAAC y mensajes RA; solución de problemas de direccionamiento IPv6

Una vez que conoces los tipos de direcciones, necesitas saber cómo obtiene realmente una interfaz su dirección IPv6. Hay tres formas principales que evalúa el CCNA: configurarla de forma estática, dejar que el dispositivo construya el ID de interfaz con EUI-64 (identificador único extendido de 64 bits) o dejar que los hosts se configuren solos con SLAAC (autoconfiguración de direcciones sin estado) a partir de los router advertisements. DHCPv6 (Dynamic Host Configuration Protocol para IPv6), con estado o sin estado, es una cuarta opción que debes reconocer.

En un router Cisco, el enrutamiento IPv6 debe habilitarse globalmente con ipv6 unicast-routing. Sin ese comando el router no reenvía paquetes IPv6 entre interfaces ni envía router advertisements. Una dirección estática se configura en la interfaz con ipv6 address 2001:db8:acad:1::1/64. Agregar cualquier dirección global habilita automáticamente IPv6 en esa interfaz y crea una dirección link-local; también puedes configurar una fácil de recordar con ipv6 address fe80::1 link-local, o habilitar solo la link-local con ipv6 enable. A diferencia de IPv4, una interfaz puede tener varias direcciones IPv6 al mismo tiempo.

EUI-64 te permite configurar solo el prefijo y hacer que el dispositivo construya el ID de interfaz de 64 bits a partir de su dirección MAC: ipv6 address 2001:db8:acad:1::/64 eui-64. El proceso toma la MAC de 48 bits, la divide a la mitad, inserta FFFE en el medio e invierte el séptimo bit del primer byte (el bit universal/local). Para la MAC 0050.3e11.2233 las mitades son 0050.3e y 11.2233; al insertar FFFE queda 0050:3eff:fe11:2233; al invertir el séptimo bit, 00 cambia a 02, así que el ID de interfaz es 0250:3eff:fe11:2233, que se escribe 250:3eff:fe11:2233. Invertir significa alternar: un primer byte 02 se convertiría en 00.

SLAAC permite que los hosts se configuren solos sin servidor DHCP. Un router envía mensajes router advertisement (RA), que son mensajes ICMPv6 (Internet Control Message Protocol para IPv6), a ff02::1 de forma periódica, e inmediatamente en respuesta a un router solicitation (RS) que un host envía a ff02::2 al arrancar. El RA lleva el prefijo del enlace y su longitud, y proviene de la dirección link-local del router, que el host usa como gateway predeterminado. El host construye su propio ID de interfaz con EUI-64 o, lo que es más común en los sistemas operativos modernos, con un valor aleatorio por privacidad. Antes de usar cualquier dirección, el host ejecuta la detección de direcciones duplicadas (DAD) enviando un neighbor solicitation para ella; si nadie responde, la dirección es única.

Los flags del RA les dicen a los hosts qué más hacer. Con el flag M (configuración administrada de direcciones) activado, los hosts usan DHCPv6 con estado para obtener su dirección, de forma muy parecida a DHCPv4. Con el flag O (otra configuración) activado, los hosts usan SLAAC para la dirección pero obtienen información adicional, como los servidores DNS (Domain Name System), de DHCPv6 sin estado. Sin ninguno de los dos, los hosts dependen de SLAAC y de lo que traiga el propio RA. Ten en cuenta que el gateway predeterminado siempre viene del RA, nunca de DHCPv6. Una interfaz de router también puede usar SLAAC con ipv6 address autoconfig, o ser cliente DHCPv6 con ipv6 address dhcp.

Veamos un ejemplo práctico. Un laboratorio IPv6 nuevo tiene routers configurados con direcciones globales, pero las PC solo muestran direcciones fe80. show ipv6 interface brief en el router parece correcto, pero show running-config revela que nunca se ingresó ipv6 unicast-routing, así que el router no envía RA. Después de agregarlo, las PC reciben RA, construyen direcciones 2001:db8:acad:10:: con SLAAC e ipconfig muestra la dirección link-local del router como gateway. Además, en la salida de estilo show ipv6 interface de la interfaz de administración de un switch aparece una dirección marcada como DUPLICATE: alguien le había asignado de forma estática la dirección ::1 del router, y DAD lo detectó.

Errores comunes: olvidar ipv6 unicast-routing; usar en una LAN una longitud de prefijo distinta de /64, lo que rompe SLAAC; hacer solo uno de los dos pasos de EUI-64; escribir mal un prefijo de modo que el router y los hosts queden en subredes distintas; esperar que DHCPv6 entregue el gateway; y aplicar una ACL (lista de control de acceso) que bloquea ICMPv6, lo que rompe silenciosamente neighbor discovery. Verifica con show ipv6 interface brief, show ipv6 interface y, en los hosts, con ipconfig, ifconfig o ip -6 addr.

La redacción del examen sigue patrones. 'Solo una dirección link-local' significa que no llegó ningún RA, así que revisa ipv6 unicast-routing o que haya un router presente. 'Insertar FFFE e invertir el séptimo bit' es EUI-64. 'El host construye su propia dirección a partir del prefijo del router' es SLAAC. 'Flag M' significa DHCPv6 con estado; 'flag O' significa SLAAC más DHCPv6 sin estado para las opciones. 'El host pide a los routers que anuncien ahora' es un RS; 'comprueba que nadie más use la dirección' es DAD.

Términos clave

EUI-64
Un método para construir un ID de interfaz de 64 bits a partir de una MAC de 48 bits insertando FFFE e invirtiendo el séptimo bit.
SLAAC
Autoconfiguración de direcciones sin estado, en la que los hosts construyen su propia dirección a partir del prefijo de un router advertisement.
Router advertisement (RA)
Un mensaje ICMPv6 de un router que anuncia el prefijo, el gateway predeterminado y los flags de configuración.
Router solicitation (RS)
Un mensaje ICMPv6 que un host envía a ff02::2 para pedir a los routers que envíen un RA de inmediato.
Detección de direcciones duplicadas (DAD)
Una comprobación en la que un host envía un neighbor solicitation para su dirección tentativa y así asegura que nadie más la use.
DHCPv6 con estado (stateful DHCPv6)
Un modo de DHCPv6, señalado por el flag M del RA, en el que un servidor asigna y registra la dirección de cada host.
ipv6 unicast-routing
El comando global de IOS que habilita el reenvío IPv6 y los router advertisements.
Ejemplo real

La interfaz de un router de sucursal se configura con ipv6 address 2001:db8:77:5::/64 eui-64. Su MAC es 00a0.c912.3456, así que show ipv6 interface brief muestra 2001:DB8:77:5:2A0:C9FF:FE12:3456. Las PC detrás de él usan SLAAC a partir de los RA del router y, como el RA tiene activado el flag O, también consultan un servidor DHCPv6 sin estado para obtener las direcciones de los servidores DNS.

Consejo para el examen: En EUI-64 recuerda los dos pasos: insertar FFFE en el medio e invertir el séptimo bit. La mayoría de las opciones incorrectas hacen solo uno de los dos. Un host que solo tiene una dirección fe80 no está recibiendo RA.

Comprueba lo que sabes

¿Qué ID de interfaz produce EUI-64 a partir de la dirección MAC 00a0.c912.3456?

02a0:c9ff:fe12:3456. Divide la MAC, inserta FFFE e invierte el séptimo bit para que 00 se convierta en 02.

Un host solo tiene una dirección IPv6 link-local. ¿Cuál es la causa más probable?

No está recibiendo router advertisements, por ejemplo porque ipv6 unicast-routing no está habilitado en el router o porque no hay ningún router en ese enlace.

¿Qué les indica a los hosts un flag O activado en un RA?

Que construyan la dirección con SLAAC, pero que obtengan otros parámetros, como los servidores DNS, de DHCPv6 sin estado.

¿De dónde aprende un host IPv6 su gateway predeterminado, incluso cuando usa DHCPv6 con estado?

De los router advertisements; el gateway es la dirección link-local del router, y DHCPv6 no lo proporciona.
