Cisco CCNA 200-301 v2.0

Configuración de direcciones IPv6: estática, EUI-64, SLAAC y mensajes RA; solución de problemas de direccionamiento IPv6

Una vez que conoces los tipos de dirección, necesitas saber cómo obtiene realmente una interfaz su dirección IPv6. Hay tres formas principales: configurarla estáticamente, dejar que el dispositivo construya el ID de interfaz con EUI-64, o dejar que los hosts se configuren solos con SLAAC (stateless address autoconfiguration, autoconfiguración de direcciones sin estado) a partir de los anuncios de router. DHCPv6 es una cuarta opción que debes reconocer.

En un router Cisco, el enrutamiento IPv6 debe activarse globalmente con ipv6 unicast-routing. Sin él, el router no reenviará paquetes IPv6 ni enviará anuncios de router. Una dirección estática se configura con ipv6 address 2001:db8:acad:1::1/64 en la interfaz. Agregar ipv6 address habilita automáticamente IPv6 en la interfaz y crea una dirección link-local; también puedes definir una link-local fácil de recordar con ipv6 address fe80::1 link-local.

EUI-64 te permite configurar solo el prefijo y que el router construya el ID de interfaz de 64 bits a partir de su dirección MAC: ipv6 address 2001:db8:acad:1::/64 eui-64. El proceso toma la MAC de 48 bits, la divide a la mitad, inserta FFFE en el medio e invierte el séptimo bit del primer byte (el bit universal/local). Para la MAC 0050.3e11.2233, las mitades son 0050.3e y 11.2233; al insertar FFFE queda 0050:3eff:fe11:2233; al invertir el séptimo bit, 00 cambia a 02, lo que da el ID de interfaz 0250:3eff:fe11:2233, escrito como 250:3eff:fe11:2233.

SLAAC permite que los hosts se configuren solos sin servidor DHCP. Un router envía mensajes de anuncio de router (RA, router advertisement) a ff02::1 periódicamente, e inmediatamente como respuesta a una solicitud de router (RS, router solicitation) que un host envía a ff02::2 al arrancar. El RA lleva el prefijo del enlace y su longitud, y la dirección link-local del router, que el host usa como gateway predeterminado. El host construye su propio ID de interfaz, usando EUI-64 o, más comúnmente en los sistemas operativos modernos, un valor aleatorio por privacidad. Antes de usar cualquier dirección, el host ejecuta la detección de direcciones duplicadas (DAD) enviando una neighbor solicitation para esa dirección; si nadie responde, la dirección es única.

Los flags del RA indican a los hosts qué más hacer. Con el flag M (managed, administrado) activado, los hosts usan DHCPv6 con estado para obtener su dirección. Con el flag O (other, otro) activado, usan SLAAC para la dirección pero obtienen información adicional, como los servidores DNS, mediante DHCPv6 sin estado. Sin ninguno de los dos, dependen de SLAAC y de lo que el propio RA proporcione.

Al resolver problemas, verifica con show ipv6 interface brief y show ipv6 interface, y en los hosts con ipconfig o ip -6 addr. Las fallas comunes son: un host con solo una dirección link-local, lo que significa que no recibió ningún RA, a menudo porque falta ipv6 unicast-routing; una longitud de prefijo distinta de /64 en una LAN, lo que rompe SLAAC; prefijos mal escritos que ponen al router y a los hosts en subredes distintas; y una dirección duplicada marcada como DUPLICATE por DAD.

Términos clave

EUI-64
Un método para construir un ID de interfaz de 64 bits a partir de una MAC de 48 bits insertando FFFE e invirtiendo el séptimo bit.
SLAAC
Stateless address autoconfiguration, donde los hosts construyen su propia dirección a partir del prefijo de un anuncio de router.
Router advertisement, RA (anuncio de router)
Un mensaje ICMPv6 de un router que anuncia el prefijo, el gateway predeterminado y los flags de configuración.
Router solicitation, RS (solicitud de router)
Un mensaje ICMPv6 que un host envía a ff02::2 pidiendo a los routers que envíen un RA de inmediato.
Duplicate address detection, DAD (detección de direcciones duplicadas)
Una comprobación en la que un host envía una neighbor solicitation para su dirección tentativa para asegurarse de que nadie más la use.
Ejemplo real

Un nuevo laboratorio IPv6 tiene routers configurados con direcciones globales, pero las PC solo muestran direcciones fe80. Al revisar la configuración en ejecución se descubre que nunca se ingresó ipv6 unicast-routing, así que los routers no están enviando anuncios de router. Después de agregarlo, las PC reciben RA, construyen direcciones 2001:db8:acad:10:: con SLAAC y hacen ping al router.

Consejo para el examen: En EUI-64, recuerda los dos pasos: insertar FFFE en el medio e invertir el séptimo bit. La mayoría de las opciones incorrectas hacen solo uno de los dos.

Comprueba lo que sabes

¿Qué ID de interfaz produce EUI-64 a partir de la dirección MAC 00a0.c912.3456?

02a0:c9ff:fe12:3456. Divide la MAC, inserta FFFE e invierte el séptimo bit para que 00 se convierta en 02.

Un host solo tiene una dirección IPv6 link-local. ¿Cuál es la causa más probable?

No está recibiendo anuncios de router, por ejemplo porque ipv6 unicast-routing no está habilitado en el router o no hay ningún router en ese enlace.

¿Qué les indica a los hosts un flag O activado en un RA?

Que construyan la dirección con SLAAC pero obtengan otros parámetros, como los servidores DNS, mediante DHCPv6 sin estado.
