Solución de problemas de vecinos y rutas OSPF a partir de la salida de show ip ospf

Los problemas de OSPF se dividen en dos grupos: routers que no se convierten en vecinos, y vecinos que están activos pero con rutas faltantes o distintas de las esperadas. Unos pocos comandos show responden casi todas las preguntas, y el examen muestra con frecuencia su salida y pregunta la causa.

Empieza con show ip ospf neighbor. Los vecinos sanos muestran FULL, con /DR, /BDR, /DROTHER o /- para punto a punto, y 2WAY/DROTHER entre dos routers que no son DR también es sano en segmentos broadcast. Si un vecino que esperas falta por completo, los routers no están intercambiando hellos válidos: comprueba que OSPF esté habilitado en ambas interfaces, que ninguna sea pasiva, que coincidan el área, la subred y la máscara, los temporizadores hello y dead y la autenticación, y que los router ID sean distintos. Un vecino atascado en INIT significa que este router escucha al otro pero el otro no lo incluye en su respuesta, lo que sugiere tráfico en un solo sentido, como una ACL que bloquea OSPF en una dirección. EXSTART o EXCHANGE apunta a un desajuste de MTU.

Después, show ip ospf interface (o brief) muestra, para cada interfaz OSPF, el área, la IP y la máscara, el costo, el tipo de red, el estado (DR, BDR, DROTHER, P2P), el DR y el BDR, los temporizadores y el número de vecinos. Comparar esta salida desde ambos extremos es la forma más rápida de detectar desajustes de área, máscara, temporizadores o tipo de red. Si una interfaz que esperas no aparece en show ip ospf interface brief, OSPF no está habilitado ahí: corrige la wildcard de la sentencia network o agrega ip ospf 1 area 0.

show ip protocols muestra el router ID, las sentencias network con sus wildcards y áreas, las interfaces pasivas, el ancho de banda de referencia y los vecinos de los que el router aprende rutas. Un error de tipeo como network 10.1.1.0 0.0.0.255 area 1 en un router en lugar del área 0 aparece aquí. show ip ospf muestra el RID, el ancho de banda de referencia, las áreas y el número de ejecuciones de SPF.

Si los vecinos están en FULL pero falta una ruta, comprueba que el router remoto realmente anuncie la red: su interfaz debe estar activa e incluida en OSPF, aunque sea pasiva. Revisa show ip ospf database para ver si el LSA existe en tu LSDB. Si el LSA está presente pero la ruta no se instala, puede que se haya instalado en su lugar una ruta con mejor distancia administrativa, como una ruta estática, o que un desajuste de tipo de red impida que SPF use el enlace. Si la ruta está presente pero usa un camino inesperado, compara los costos con show ip ospf interface brief y comprueba la consistencia del ancho de banda de referencia.

R1# show ip ospf neighbor
Neighbor ID  Pri  State          Dead Time  Address     Interface
2.2.2.2        1  FULL/DR        00:00:35   10.0.12.2   Gi0/0
3.3.3.3        1  EXSTART/DROTHER 00:00:33  10.0.13.3   Gi0/1

En la salida anterior, R2 está sano y R3 está atascado en EXSTART, así que compararías la MTU de Gi0/1 de R1 y de la interfaz de R3 con show interfaces. Mantén tus comprobaciones en orden: estado del vecino, parámetros de la interfaz, configuración del proceso, base de datos y luego tabla de enrutamiento.

Términos clave

show ip ospf neighbor
Lista los vecinos OSPF con su router ID, prioridad, estado y rol, temporizador dead, dirección e interfaz.
show ip ospf interface
Muestra la configuración OSPF por interfaz, incluidos el área, el costo, el tipo de red, el DR/BDR y los temporizadores.
show ip protocols
Muestra el router ID, las sentencias network, las interfaces pasivas y los orígenes de enrutamiento de los protocolos en ejecución.
show ip ospf database
Muestra la base de datos de estado de enlace, los LSA que este router ha aprendido.
INIT state (estado INIT)
El router recibió un hello del vecino pero no ve su propio RID listado en él.
Ejemplo real

R4 no tiene ruta hacia 10.40.0.0/24 detrás de R5, aunque show ip ospf neighbor muestra a R5 en FULL. En R5, show ip ospf interface brief no lista G0/2, la interfaz LAN. show ip protocols muestra network 10.4.0.0 0.0.255.255 area 0, un error de tipeo que no cubre 10.40.0.1. Corregir la sentencia para cubrir 10.40.0.0 hace que la LAN aparezca en R4 como una ruta O.

Consejo para el examen: Ningún vecino significa desajuste de hello u OSPF no habilitado; INIT significa comunicación en un solo sentido; EXSTART/EXCHANGE significa MTU. Vecinos en FULL con una ruta faltante significa que la red no se está anunciando o que ganó una ruta con menor AD.

Comprueba lo que sabes

Un vecino está atascado en INIT. ¿Qué indica eso?

Este router recibe los hellos del vecino, pero el vecino no recibe los hellos de este router, lo que sugiere comunicación en un solo sentido, por ejemplo una ACL que filtra.

¿Qué comando revelaría un número de área mal escrito en una sentencia network?

show ip protocols (o show running-config section router ospf); show ip ospf interface también mostraría la interfaz en el área equivocada.

Los vecinos están en FULL pero falta una LAN remota. Menciona dos causas probables.

La interfaz LAN remota no tiene OSPF habilitado (no coincide con ninguna sentencia network ni comando ip ospf), o la interfaz LAN está caída.
