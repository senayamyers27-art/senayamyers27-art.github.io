Hipervisores (tipo 1 vs tipo 2), máquinas virtuales y contenedores

Los centros de datos modernos rara vez ejecutan un solo sistema operativo por servidor físico. En su lugar, un hipervisor permite que un host físico ejecute muchas máquinas virtuales (VM) aisladas, cada una creyendo que tiene su propia CPU, memoria, disco y tarjeta de red. Esto importa a los ingenieros de redes porque esas VM siguen necesitando VLAN, direcciones y seguridad, y gran parte de la conmutación ahora ocurre dentro del servidor, en un switch virtual.

Un hipervisor es la capa de software que crea y ejecuta VM y reparte el hardware físico entre ellas. Un hipervisor tipo 1, también llamado bare-metal, se instala directamente sobre el hardware del servidor sin ningún sistema operativo de propósito general debajo. Algunos ejemplos son VMware ESXi, Microsoft Hyper-V y KVM. El tipo 1 es el que encuentras en centros de datos y nubes porque es eficiente y estable. Un hipervisor tipo 2, también llamado hosted (alojado), se ejecuta como una aplicación sobre un sistema operativo normal como Windows o macOS. VirtualBox y VMware Workstation son ejemplos. El tipo 2 es práctico para laboratorios y equipos de escritorio, pero añade sobrecarga porque cada solicitud pasa por el sistema operativo anfitrión.

Cada VM contiene un sistema operativo invitado completo, con su propio kernel, bibliotecas y aplicaciones. Se conecta a la red mediante una NIC virtual (vNIC) que se enchufa a un switch virtual (vSwitch) dentro del hipervisor. El vSwitch conecta entre sí las VM del mismo host y sale a la red real a través de las NIC físicas del servidor. Esos enlaces ascendentes suelen ser troncales 802.1Q para que distintas VM puedan estar en distintas VLAN, y por eso un puerto de switch que da hacia un servidor se configura con frecuencia como troncal en lugar de puerto de acceso.

Los contenedores adoptan un enfoque más ligero. En lugar de virtualizar el hardware, un motor de contenedores como Docker comparte el kernel del sistema operativo del host y empaqueta solo la aplicación y sus bibliotecas. Los contenedores arrancan en segundos, usan mucha menos memoria y disco que las VM, y pueden ejecutarse muchos más en un solo host. La contrapartida es un aislamiento más débil: todos los contenedores de un host comparten un kernel, y un contenedor debe construirse para ese tipo de kernel (los contenedores Linux necesitan un kernel Linux). Las plataformas de orquestación como Kubernetes programan y conectan grandes cantidades de contenedores.

Para el examen, ten claras las capas. El hardware físico abajo; un hipervisor tipo 1 directamente sobre él, o un sistema operativo anfitrión con un hipervisor tipo 2 encima; VM, cada una con un sistema operativo invitado; o, en el caso de los contenedores, un único sistema operativo anfitrión con un motor de contenedores y paquetes de aplicaciones aislados. La virtualización también trae beneficios que le gustan al examen: mejor aprovechamiento del hardware, aprovisionamiento más rápido, snapshots (instantáneas) y mover VM en ejecución entre hosts para hacer mantenimiento.

Términos clave

Type 1 hypervisor (hipervisor tipo 1)
Un hipervisor bare-metal instalado directamente sobre el hardware del servidor, como ESXi, Hyper-V o KVM.
Type 2 hypervisor (hipervisor tipo 2)
Un hipervisor alojado que se ejecuta como aplicación sobre un sistema operativo de escritorio, como VirtualBox.
Virtual machine, VM (máquina virtual)
Una computadora definida por software, con su propio sistema operativo invitado, que se ejecuta sobre un hipervisor.
Container (contenedor)
Un paquete de aplicación aislado que comparte el kernel del sistema operativo del host en lugar de ejecutar su propio sistema operativo.
Virtual switch, vSwitch (switch virtual)
Software dentro de un hipervisor que conmuta el tráfico entre las NIC virtuales de las VM y las NIC físicas del host.
Ejemplo real

Una empresa reemplaza doce servidores físicos poco utilizados por dos hosts que ejecutan un hipervisor tipo 1. Las dos NIC físicas de cada host se conectan a un par de switches con troncales 802.1Q que transportan las VLAN 10, 20 y 30, y el vSwitch coloca la vNIC de cada VM en la VLAN correcta. Mientras tanto, una desarrolladora prueba la misma aplicación web localmente en contenedores en su laptop.

Consejo para el examen: Las palabras 'bare metal' significan tipo 1; 'se ejecuta sobre un sistema operativo existente' significa tipo 2. Si una pregunta destaca que se comparte el kernel del host y que el arranque es ligero, la respuesta son los contenedores, no las VM.

Comprueba lo que sabes

¿Qué tipo de hipervisor esperarías encontrar en un servidor de producción de un centro de datos, y por qué?

Tipo 1 (bare-metal), porque se ejecuta directamente sobre el hardware, con menos sobrecarga y menos capas que puedan fallar que un hipervisor alojado tipo 2.

¿Cuál es la diferencia arquitectónica clave entre una VM y un contenedor?

Una VM incluye su propio sistema operativo invitado completo y su kernel; un contenedor comparte el kernel del sistema operativo del host y empaqueta solo la aplicación y sus dependencias.

¿Por qué un puerto de switch conectado a un host de virtualización suele configurarse como troncal?

Porque las VM de ese host pertenecen a distintas VLAN, así que el enlace ascendente del vSwitch debe transportar tráfico etiquetado de varias VLAN.
