Redundancia del primer salto: IP virtual, prioridad y preferencia (preemption) en HSRP y VRRP

Normalmente, los hosts se configuran con un único gateway predeterminado. Si ese router falla, los hosts pierden toda la conectividad fuera de su subred aunque haya un segundo router en la misma subred, porque no tienen forma de cambiar de gateway por su cuenta. Los protocolos de redundancia del primer salto (FHRP) resuelven esto al permitir que dos o más routers compartan una dirección IP virtual y una dirección MAC (media access control) virtual que los hosts usan como gateway. Un router reenvía activamente; otro toma el control si el primero falla, y los hosts no notan nada porque la IP y la MAC del gateway que ya conocen siguen siendo las mismas.

HSRP (Hot Standby Router Protocol) es propietario de Cisco. Los routers de un grupo HSRP eligen un router activo, que responde a las solicitudes ARP (Address Resolution Protocol) para la IP virtual con la MAC virtual y reenvía el tráfico, y un router standby, que monitorea los hello del router activo y toma el control si dejan de llegar. Los demás routers del grupo escuchan. La MAC virtual se deriva del número de grupo: 0000.0c07.acXX para HSRPv1 y 0000.0c9f.fXXX para HSRPv2, donde las X son el número de grupo en hexadecimal. HSRPv2 admite más números de grupo, IPv6 y temporizadores en milisegundos, y las versiones deben coincidir dentro de un grupo.

La elección usa la prioridad, 100 de forma predeterminada, y gana la más alta; si las prioridades empatan, gana la dirección IP de interfaz más alta. La preferencia (preemption) está deshabilitada de forma predeterminada en HSRP. Eso significa que si un router con mayor prioridad arranca después de que otro se volvió activo, no toma el control hasta que falle el router activo. Para que el router que elegiste sea el activo siempre que esté sano, configura tanto una prioridad más alta como preempt. El seguimiento de objetos (object tracking) puede bajar la prioridad automáticamente cuando falla un enlace ascendente, de modo que el otro router, si tiene preemption, tome el control.

interface g0/1
 ip address 192.168.10.2 255.255.255.0
 standby version 2
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt

VRRP (Virtual Router Redundancy Protocol) es el equivalente de estándar abierto. Sus roles son master y backup en lugar de activo y standby. La prioridad también es 100 de forma predeterminada y gana la más alta, pero la preemption está habilitada de forma predeterminada. VRRP permite que la IP virtual sea la dirección real de la interfaz de uno de los routers; ese router es el propietario de la dirección (address owner) y recibe prioridad 255, así que siempre es master cuando está en funcionamiento. La MAC virtual de VRRP es 0000.5e00.01XX, donde XX es el número de grupo. GLBP (Gateway Load Balancing Protocol) es otro FHRP de Cisco que balancea la carga entregando MAC virtuales distintas a distintos hosts, pero el foco del CCNA son HSRP y VRRP. Ni HSRP ni VRRP balancean la carga dentro de un mismo grupo; para repartir la carga, ejecutas dos grupos con routers activos distintos y le das a cada mitad de los hosts un gateway diferente.

Veamos un ejemplo resuelto. R1 (192.168.10.2) y R2 (192.168.10.3) atienden la VLAN 10, y DHCP entrega 192.168.10.1 como gateway. R1 tiene prioridad 110 con preempt y R2 tiene el valor predeterminado de 100. R1 es el activo. Cuando R1 se reinicia, R2 deja de recibir hello, se vuelve activo al vencer el hold time y empieza a responder por la MAC virtual; el switch aprende la MAC en el puerto de R2 gracias al ARP gratuito (gratuitous ARP) de R2, y las sesiones de los usuarios continúan. Cuando R1 regresa, preempt le permite recuperar el rol activo. Sin preempt en R1, R2 seguiría activo hasta que fallara. show standby brief en R1 mostraría el grupo 10, prioridad 110, un indicador P, estado Active y a R2 como standby.

Errores comunes: apuntar los hosts a la dirección real de un router en lugar de la IP virtual, lo que elimina el beneficio; suponer que HSRP tiene preemption de forma predeterminada; usar números de grupo, IP virtuales o versiones distintas en los routers; e interpretar mal 'dos routers en Active', lo que suele significar que no se escuchan los hello entre sí por un problema de VLAN o de trunk entre ellos. Verifica HSRP con show standby brief (grupo, prioridad, indicador P, estado, routers activo y standby, IP virtual) y VRRP con show vrrp brief. Recuerda también que un FHRP protege solo al gateway en sí: si falla el enlace WAN del router activo pero su interfaz LAN sigue arriba, sigue atrayendo tráfico, a menos que uses object tracking para bajar su prioridad y el router standby esté configurado con preempt.

Las preguntas del examen suelen evaluar vocabulario y valores predeterminados. 'Propietario de Cisco, activo y standby' significa HSRP; 'estándar abierto, master y backup' significa VRRP; 'balancear carga con varias MAC virtuales en un grupo' significa GLBP. 'Un router con mayor prioridad regresó pero no tomó el control' apunta a la falta de preemption en HSRP. Una MAC como 0000.0c07.ac0a identifica el grupo 10 de HSRPv1, y 0000.5e00.0105 identifica el grupo 5 de VRRP. 'Prioridad 255' significa el propietario de la dirección en VRRP.

Términos clave

FHRP
First hop redundancy protocol: los routers comparten una IP y una MAC virtuales de gateway para que los hosts sigan funcionando si un router falla.
HSRP
Hot Standby Router Protocol, propietario de Cisco, con roles activo y standby y preemption deshabilitada de forma predeterminada.
VRRP
Virtual Router Redundancy Protocol, un estándar abierto con roles master y backup y preemption habilitada de forma predeterminada.
IP virtual (virtual IP)
La dirección de gateway compartida que se configura en los hosts.
Prioridad (priority)
El valor de elección, 100 de forma predeterminada, donde gana el más alto y los empates se resuelven por la IP de interfaz más alta.
Preferencia (preemption)
Permitir que un router con mayor prioridad tome el rol activo o master cuando entra en línea.
GLBP
Gateway Load Balancing Protocol, un FHRP de Cisco que reparte la carga respondiendo a ARP con MAC virtuales distintas.
Ejemplo real

Una clínica tiene dos routers en la VLAN del personal ejecutando HSRP con la IP virtual 10.20.0.1. Durante una actualización de firmware del router activo, el router standby toma el control en segundos y la aplicación de expedientes electrónicos sigue conectada. Después de la actualización, el primer router recupera el rol activo porque el ingeniero le configuró prioridad 110 y preempt, lo que mantiene el tráfico en el router con el mejor enlace WAN.

Consejo para el examen: HSRP: activo/standby, solo Cisco, preempt deshabilitado de forma predeterminada. VRRP: master/backup, estándar abierto, preempt habilitado de forma predeterminada. Ambos usan prioridad 100 de forma predeterminada y gana la más alta, y los hosts deben usar la IP virtual como gateway.

Comprueba lo que sabes

Un router HSRP con mayor prioridad se reinicia y no vuelve a ser activo. ¿Por qué?

La preemption de HSRP está deshabilitada de forma predeterminada, así que debe configurarse con standby <group> preempt.

¿Qué nombres de rol usa VRRP?

Master para el router que reenvía y backup para los demás.

¿Qué dirección deben usar los hosts como gateway predeterminado en un diseño con FHRP?

La IP virtual, para que el gateway siga siendo alcanzable sin importar qué router esté reenviando.

Dos routers HSRP muestran Active para el mismo grupo. ¿Cuál es la causa probable?

No se escuchan los hello entre sí, normalmente por un problema de VLAN, de trunk o de conectividad entre ellos.
