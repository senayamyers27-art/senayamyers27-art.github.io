Redundancia del primer salto: IP virtual, prioridad y preferencia (preemption) en HSRP y VRRP

Normalmente, los hosts se configuran con un solo gateway predeterminado. Si ese router falla, los hosts pierden toda la conectividad fuera de su subred aunque haya un segundo router en la misma subred, porque no tienen forma de cambiar de gateway por sí mismos. Los protocolos de redundancia del primer salto (FHRP) resuelven esto permitiendo que dos o más routers compartan una dirección IP virtual y una dirección MAC virtual que los hosts usan como gateway. Un router reenvía activamente; otro toma el control si el primero falla, y los hosts no notan nada.

HSRP (Hot Standby Router Protocol) es propietario de Cisco. Los routers de un grupo HSRP eligen un router activo (active), que responde al ARP de la IP virtual con la MAC virtual y reenvía el tráfico, y un router en espera (standby), que supervisa los hellos del router activo y toma el control si se detienen. Los demás routers del grupo escuchan. La MAC virtual se deriva del número de grupo: 0000.0c07.acXX para HSRPv1 y 0000.0c9f.fXXX para HSRPv2. HSRPv2 admite más números de grupo, IPv6 y temporizadores en milisegundos.

La elección usa la prioridad, 100 de forma predeterminada, y gana la más alta; si las prioridades empatan, gana la dirección IP de interfaz más alta. La preferencia (preemption) está deshabilitada de forma predeterminada en HSRP. Eso significa que, si un router con mayor prioridad arranca después de que otro se haya convertido en activo, no toma el control hasta que el router activo falle. Para que el router que elegiste sea siempre el activo cuando está sano, configura tanto una prioridad mayor como preempt. El seguimiento de objetos (object tracking) puede bajar la prioridad automáticamente cuando falla un enlace ascendente para que el otro router tome el control.

interface g0/1
 ip address 192.168.10.2 255.255.255.0
 standby version 2
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt

VRRP (Virtual Router Redundancy Protocol) es el equivalente de estándar abierto. Sus roles son master y backup en lugar de active y standby. La prioridad también es 100 de forma predeterminada y gana la más alta, pero la preferencia está habilitada de forma predeterminada. VRRP permite que la IP virtual sea la dirección real de la interfaz de uno de los routers; ese router es el propietario de la dirección (address owner) y recibe la prioridad 255. La MAC virtual de VRRP es 0000.5e00.01XX, donde XX es el número de grupo. GLBP (Gateway Load Balancing Protocol) es otro FHRP de Cisco que balancea la carga dando distintas MAC virtuales a distintos hosts, pero HSRP y VRRP son el foco del CCNA.

Los hosts deben usar la IP virtual como gateway predeterminado, no la dirección real de alguno de los routers, o pierden el beneficio. Verifica con show standby brief para HSRP, que lista el grupo, la prioridad, el flag de preempt (P), el estado (Active, Standby, Listen), los routers activo y en espera y la IP virtual, y con show vrrp brief para VRRP. Los grupos, las IP virtuales y las versiones deben coincidir en todos los routers de un grupo. Si dos routers afirman ser activos, comprueba que puedan escuchar los hellos del otro, lo que normalmente indica un problema de VLAN o de troncal entre ellos.

Términos clave

FHRP
First hop redundancy protocol: un protocolo que da a los hosts un gateway predeterminado virtual resiliente.
Virtual IP / virtual MAC (IP virtual / MAC virtual)
La dirección de gateway y la MAC compartidas por las que responde el router activo o master.
HSRP active / standby (activo / en espera)
El router que reenvía para la IP virtual, y el router listo para tomar el control si falla.
VRRP master / backup
Los equivalentes en VRRP de active y standby.
Preemption (preferencia)
Permitir que un router de mayor prioridad recupere el rol activo o master; desactivada de forma predeterminada en HSRP y activada en VRRP.
Ejemplo real

Dos switches de distribución atienden la VLAN 10 con la IP virtual HSRP 192.168.10.1. DSW1 tiene prioridad 110 con preempt; DSW2 tiene la predeterminada de 100. Cuando DSW1 se reinicia por una actualización, DSW2 se vuelve activo en segundos y las PC siguen funcionando. Cuando DSW1 regresa, la preferencia le permite recuperar el rol activo; sin preempt se quedaría en standby.

Consejo para el examen: HSRP: active/standby, solo Cisco, preempt desactivado de forma predeterminada. VRRP: master/backup, estándar abierto, preempt activado de forma predeterminada. Ambos usan prioridad 100 de forma predeterminada y gana la más alta.

Comprueba lo que sabes

¿Qué deben usar los hosts como gateway predeterminado cuando hay un FHRP configurado?

La dirección IP virtual compartida por el grupo, no la dirección de la interfaz física de un router.

El Router A (prioridad 120, sin preempt) arranca después de que el Router B (prioridad 100) se convirtió en activo de HSRP. ¿Qué ocurre?

El Router B sigue activo, porque la preferencia de HSRP está desactivada de forma predeterminada; A pasa a standby hasta que B falle o se configure preempt en A.

Menciona una diferencia entre HSRP y VRRP además de los nombres de los roles.

HSRP es propietario de Cisco con la preferencia desactivada de forma predeterminada; VRRP es un estándar abierto con la preferencia activada de forma predeterminada y puede usar la dirección real de la interfaz de un router como IP virtual.
