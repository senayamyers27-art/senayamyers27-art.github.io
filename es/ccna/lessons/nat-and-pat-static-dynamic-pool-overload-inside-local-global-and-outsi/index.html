NAT y PAT: estático, pool dinámico, overload; inside local/global y outside local/global

Network Address Translation (NAT, traducción de direcciones de red) reescribe las direcciones IP a medida que los paquetes pasan por un router, sobre todo para permitir que los hosts que usan direcciones privadas RFC 1918 lleguen a internet con direcciones públicas. Ahorra el escaso espacio IPv4 público y oculta el direccionamiento interno. El CCNA cubre tres formas y un conjunto de cuatro términos de direcciones que confunden a muchos estudiantes.

Los cuatro términos describen una dirección desde dos puntos de vista. Inside significa que el host está en tu red; outside significa que está en otro lugar. Local significa la dirección tal como se ve en la red interna; global significa tal como se ve desde afuera. Así, la dirección inside local es la dirección privada realmente configurada en tu PC, como 192.168.1.10. La dirección inside global es la dirección pública que representa a tu PC hacia afuera, como 203.0.113.5. La dirección outside global es la dirección real del host remoto, como un servidor web en 198.51.100.80. La dirección outside local es cómo se ve ese host remoto desde adentro; a menos que también traduzcas las direcciones externas, es igual a la outside global.

El NAT estático asocia una dirección inside local con una dirección inside global de forma permanente: ip nat inside source static 192.168.1.20 203.0.113.20. Se usa para servidores que deben ser alcanzables desde internet, porque la asociación existe antes de que empiece cualquier tráfico.

El NAT dinámico asocia los hosts internos con un pool de direcciones públicas por orden de llegada. Una ACL identifica qué direcciones internas se traducen, y un pool define el rango público. Cada host activo usa una dirección pública; si el pool se agota, los hosts nuevos no se pueden traducir.

access-list 1 permit 192.168.1.0 0.0.0.255
ip nat pool PUBLIC 203.0.113.10 203.0.113.14 netmask 255.255.255.248
ip nat inside source list 1 pool PUBLIC
! o PAT sobre la dirección de la interfaz externa:
ip nat inside source list 1 interface g0/0 overload
interface g0/1
 ip nat inside
interface g0/0
 ip nat outside

PAT (port address translation, traducción de direcciones de puerto), también llamado NAT overload, permite que muchos hosts internos compartan una sola dirección pública traduciendo también los números de puerto de origen. El router rastrea cada conexión por dirección y puerto, así que miles de sesiones pueden compartir una dirección. Agregar overload lo habilita, ya sea sobre la propia dirección de la interfaz o sobre un pool. PAT es lo que hacen casi todos los routers de hogar y de oficina.

Toda configuración NAT necesita las interfaces marcadas: ip nat inside en la interfaz que da hacia la LAN e ip nat outside en la interfaz que da hacia internet. Olvidar una de ellas, o una ACL que no coincide con los hosts internos, son las fallas más comunes. Verifica con show ip nat translations, que lista inside global, inside local, outside local y outside global para cada entrada (con puertos en el caso de PAT), y con show ip nat statistics, que muestra aciertos, fallos y el uso del pool. clear ip nat translation * elimina las entradas dinámicas.

Términos clave

Inside local
La dirección real, normalmente privada, de un host interno.
Inside global
La dirección pública que representa a un host interno hacia la red externa.
Outside global / outside local
La dirección real de un host remoto, y la dirección de ese host tal como se ve desde adentro (normalmente la misma).
Static NAT (NAT estático)
Una asociación permanente uno a uno de una dirección inside local con una inside global.
PAT (overload)
La traducción de muchas direcciones internas a una dirección pública, distinguidas por números de puerto.
Ejemplo real

Una oficina pequeña tiene una dirección pública en la G0/0 de su router. PAT con ip nat inside source list 1 interface g0/0 overload permite que 40 PC naveguen. La oficina también aloja un servidor de cámaras en 192.168.1.50 al que un proveedor debe llegar, así que el ISP proporciona una segunda dirección pública, 203.0.113.6, asociada con NAT estático a 192.168.1.50.

Consejo para el examen: Inside local es la dirección privada que configuraste en el host; inside global es su cara pública. Si recuerdas que 'inside/outside es dónde está el host, local/global es desde dónde miras', los cuatro términos salen solos.

Comprueba lo que sabes

Una PC 10.1.1.5 navega hacia 198.51.100.7 mediante PAT a 203.0.113.2. Indica las direcciones inside local, inside global y outside global.

Inside local 10.1.1.5, inside global 203.0.113.2, outside global 198.51.100.7.

¿Qué tipo de NAT deberías usar para un servidor web que debe aceptar conexiones desde internet?

NAT estático (o una asociación estática de puertos), para que la dirección pública del servidor siempre apunte a él.

NAT está configurado pero show ip nat translations sigue vacío. Menciona dos cosas que revisar.

Que ip nat inside e ip nat outside estén en las interfaces correctas, y que la ACL de la regla NAT coincida con las direcciones de los hosts internos.
