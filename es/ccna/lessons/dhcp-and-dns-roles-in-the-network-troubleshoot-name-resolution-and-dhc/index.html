Cisco CCNA 200-301 v2.0

Funciones de DHCP y DNS en la red; solución de problemas de resolución de nombres y de clientes DHCP

Dos servicios hacen que toda red sea utilizable sin que nadie lo note. DHCP (Dynamic Host Configuration Protocol) da automáticamente a los hosts su dirección IP, máscara, gateway predeterminado y las direcciones de los servidores DNS. DNS (Domain Name System, sistema de nombres de dominio) traduce los nombres que la gente recuerda, como www.example.com, a las direcciones IP que necesitan las computadoras. Cuando cualquiera de los dos falla, los usuarios informan que 'la red está caída', aunque el enrutamiento y la conmutación funcionen bien. Conocer la función de cada servicio te permite distinguir esas fallas.

DHCP funciona mediante el intercambio DORA: Discover, Offer, Request, Acknowledgment, usando los puertos UDP 67 (servidor) y 68 (cliente). Como Discover es un broadcast, se necesita un agente relay, configurado con ip helper-address en la interfaz del router que da hacia los clientes, cuando el servidor está en otra subred. La concesión es temporal, y los clientes la renuevan antes de que expire. Además de la dirección, las opciones DHCP entregan el gateway, los servidores DNS, el nombre de dominio y, para dispositivos como teléfonos IP y AP, cosas como las direcciones del controlador o del servidor TFTP.

DNS es una base de datos distribuida y jerárquica. Un cliente pregunta a su resolver DNS configurado, que responde desde la caché o consulta la jerarquía: los servidores raíz, luego los servidores de dominio de nivel superior como .com, y luego el servidor autoritativo del dominio. Los tipos de registro comunes son A (nombre a dirección IPv4), AAAA (nombre a dirección IPv6), CNAME (un alias de otro nombre), MX (servidor de correo de un dominio), NS (servidores de nombres de una zona) y PTR (dirección a nombre, para búsquedas inversas). Las consultas DNS normalmente usan el puerto UDP 53, con el puerto TCP 53 para respuestas grandes y transferencias de zona. Las respuestas se guardan en caché durante su TTL, por eso un registro modificado puede tardar en verse en todas partes.

En un router Cisco, ip name-server 10.1.1.53 define el servidor DNS que usa el router, e ip domain-lookup (activado de forma predeterminada) habilita las búsquedas. Una molestia conocida es que los comandos mal escritos en la CLI se tratan como nombres de host y el router intenta resolverlos; no ip domain-lookup lo evita en los laboratorios. ip host SERVER1 10.1.1.10 crea una asociación local estática.

Para resolver problemas de un cliente DHCP, revisa primero su configuración IP. Una dirección APIPA 169.254.x.x, o ninguna dirección, significa que DHCP falló. Luego revisa el camino: enlace activo, VLAN correcta, relay configurado con la dirección de servidor correcta en la interfaz correcta, un pool o ámbito para esa subred en el servidor, direcciones libres en el pool, y que DHCP snooping no esté descartando ofertas legítimas. ipconfig /release e ipconfig /renew en Windows, o dhclient en algunos sistemas Linux, reintentan el proceso; show ip dhcp binding y show ip dhcp pool en un servidor IOS muestran las concesiones y el agotamiento.

Para resolver problemas de DNS, separa la alcanzabilidad de la resolución de nombres. Si ping 10.1.1.10 funciona pero ping server1.example.com falla, el problema es el DNS. Comprueba qué servidor DNS usa el cliente con ipconfig /all, resolvectl status o /etc/resolv.conf, y luego prueba directamente con nslookup server1.example.com o dig. Las causas posibles son una dirección de servidor DNS incorrecta entregada por DHCP, un servidor DNS inalcanzable o bloqueado por una ACL en UDP 53, un registro faltante o incorrecto, o una caché desactualizada que ipconfig /flushdns borra.

Términos clave

DNS resolver
El servidor DNS al que consulta un cliente; responde desde la caché o busca el nombre a través de la jerarquía DNS.
A / AAAA record (registro A / AAAA)
Registros DNS que asocian un nombre con una dirección IPv4 o IPv6.
PTR record (registro PTR)
Un registro DNS inverso que asocia una dirección IP con un nombre.
nslookup
Una herramienta de línea de comandos que consulta directamente a los servidores DNS para probar la resolución de nombres.
DHCP lease (concesión DHCP)
El período durante el cual un cliente puede usar una dirección antes de renovarla con el servidor.
Ejemplo real

Después de un cambio de servidor DHCP, los usuarios pueden llegar a los sitios web por IP pero no por nombre. ipconfig /all muestra como servidor DNS 10.1.1.99, una dirección que ya no existe. El nuevo ámbito DHCP había copiado una opción DNS antigua. Corregir el servidor DNS del ámbito y pedir a los usuarios que ejecuten ipconfig /renew restablece la resolución de nombres.

Consejo para el examen: Si la IP funciona pero los nombres fallan, la respuesta es DNS. Si el cliente tiene una dirección 169.254, la respuesta es DHCP. Muchas preguntas de resolución de problemas se resuelven con esa sola distinción.

Comprueba lo que sabes

¿Qué tipo de registro DNS asocia un nombre con una dirección IPv6?

AAAA.

Un usuario puede hacer ping a 8.8.8.8 pero la navegación por nombre falla. ¿Qué deberías revisar primero?

La configuración de servidores DNS del cliente y si ese servidor es alcanzable y está resolviendo, por ejemplo con nslookup.

¿Por qué un cliente DHCP necesita un agente relay cuando el servidor está en otra subred?

DHCP Discover es un broadcast, y los routers no reenvían broadcasts; el relay lo reenvía como unicast hacia el servidor.
