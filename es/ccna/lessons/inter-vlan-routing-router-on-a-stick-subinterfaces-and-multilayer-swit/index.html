Enrutamiento entre VLAN: subinterfaces router-on-a-stick y SVI en switches multicapa

Cada VLAN es un dominio de broadcast y una subred IP separados, así que los hosts de VLAN distintas no pueden comunicarse directamente. Algo debe enrutar entre ellas, y ese router se convierte en el gateway predeterminado de cada VLAN. El CCNA cubre dos métodos: router-on-a-stick con subinterfaces, y las interfaces virtuales de switch (SVI) en un switch multicapa. Un tercer método, heredado, usa una interfaz física del router por VLAN, lo cual no escala.

Router-on-a-stick usa una sola interfaz física del router conectada a una troncal del switch. En el router creas una subinterfaz por VLAN, le indicas qué etiqueta 802.1Q maneja con encapsulation dot1Q y le asignas la dirección de gateway de esa VLAN. La interfaz física en sí no tiene dirección IP, pero debe estar activa (no shutdown).

interface g0/0
 no shutdown
interface g0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
interface g0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
interface g0/0.99
 encapsulation dot1Q 99 native
 ip address 192.168.99.1 255.255.255.0

El puerto del switch que da hacia el router debe ser una troncal que permita esas VLAN. El tráfico de la VLAN 10 hacia la VLAN 20 sube por la troncal etiquetado con 10, el router lo enruta y vuelve a bajar por la misma troncal etiquetado con 20. Su debilidad es que un solo enlace transporta todo el tráfico entre VLAN dos veces, así que puede convertirse en un cuello de botella, y el router es un punto único de falla. Es adecuado para sucursales pequeñas.

Un switch multicapa (de Capa 3) enruta en hardware usando SVI. Una SVI es una interfaz virtual para una VLAN: interface vlan 10 con ip address 192.168.10.1 255.255.255.0. Debes habilitar el enrutamiento con ip routing, que está desactivado de forma predeterminada en muchos switches. Una SVI está up/up solo si la VLAN existe y al menos un puerto de esa VLAN (un puerto de acceso o una troncal que la permita) está activo y reenviando, y la SVI no está apagada. Los switches multicapa también admiten puertos enrutados, con no switchport y una dirección IP, que se usan normalmente para enlaces ascendentes hacia routers u otros switches de Capa 3.

Las SVI son más rápidas y escalan mejor que router-on-a-stick porque el enrutamiento ocurre dentro del switch a velocidad de línea, sin cuello de botella en una troncal, y por eso las capas de distribución de los campus las usan. Al resolver problemas, verifica que el número de VLAN de la subinterfaz coincida con la VLAN del switch, que la troncal permita la VLAN, que la interfaz física del router no esté apagada, que ip routing esté habilitado en el switch y que los hosts usen el gateway correcto. show ip interface brief debería mostrar cada SVI o subinterfaz up/up, y show ip route debería listar la subred de cada VLAN como conectada (C) con una ruta local (L) para la dirección del gateway.

Términos clave

Router-on-a-stick
Enrutamiento entre VLAN a través de una sola interfaz del router usando subinterfaces 802.1Q sobre un enlace troncal.
Subinterface (subinterfaz)
Una división lógica de una interfaz física del router, como g0/0.10, cada una con su propia etiqueta de VLAN y dirección IP.
encapsulation dot1Q
Comando de subinterfaz que especifica qué etiqueta de VLAN 802.1Q maneja la subinterfaz.
SVI
Switch virtual interface: una interfaz de Capa 3 para una VLAN en un switch, usada como gateway de esa VLAN.
ip routing
Comando global que habilita el enrutamiento IPv4 en un switch multicapa.
Ejemplo real

Una sucursal tiene un router y un switch de acceso con las VLAN 10 y 20. El puerto g0/24 del switch es una troncal y el router usa g0/0.10 y g0/0.20 como gateways. Cuando la oficina central instala más adelante un switch Catalyst de Capa 3 en el núcleo, crea interface vlan 10 e interface vlan 20, habilita ip routing y dirige un enlace ascendente enrutado hacia el router WAN.

Consejo para el examen: Si una SVI aparece down/down, verifica que la VLAN exista y tenga al menos un puerto activo. Si el enrutamiento entre SVI falla con las SVI activas, busca un comando ip routing faltante.

Comprueba lo que sabes

¿Qué comando le indica a una subinterfaz del router el tráfico de qué VLAN debe aceptar?

encapsulation dot1Q <vlan-id>, opcionalmente con la palabra clave native para la VLAN nativa.

Menciona dos condiciones necesarias para que una SVI esté up/up.

La VLAN debe existir en la base de datos de VLAN, y al menos un puerto de esa VLAN (de acceso o una troncal que la permita) debe estar activo y reenviando; además, la SVI no debe estar apagada.

¿Por qué los campus más grandes prefieren las SVI a router-on-a-stick?

Las SVI enrutan en el hardware del switch sin enviar todo el tráfico entre VLAN por una sola troncal hacia un router externo, así que son más rápidas y evitan un cuello de botella.
