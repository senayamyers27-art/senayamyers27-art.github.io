OSPFv2 de área única: vecinos y adyacencias, redes punto a punto vs broadcast, elección de DR/BDR

OSPF (Open Shortest Path First) es un protocolo de enrutamiento de estado de enlace de estándar abierto, y OSPFv2 transporta rutas IPv4. En lugar de pasar tablas de enrutamiento completas entre vecinos, cada router OSPF describe sus propios enlaces en anuncios de estado de enlace (LSA), los inunda para que todos los routers del área tengan una base de datos de estado de enlace (LSDB) idéntica y ejecuta el algoritmo SPF (shortest path first) para calcular las mejores rutas. En un diseño de área única, todos los routers están en el área 0, el backbone. La métrica de OSPF es el costo, basado de forma predeterminada en el ancho de banda de la interfaz.

Los routers OSPF se descubren entre sí enviando paquetes hello a la dirección multicast 224.0.0.5 por cada interfaz con OSPF habilitado. En redes broadcast y punto a punto, el intervalo hello predeterminado es de 10 segundos y el intervalo dead, el tiempo que se espera antes de declarar caído a un vecino, es de 40 segundos. Para convertirse en vecinos, dos routers deben coincidir en varios parámetros del hello: ID de área, subred y máscara, temporizadores hello y dead, autenticación y flags de área stub, y deben tener router IDs distintos. Un desajuste en cualquiera de ellos impide que se forme la relación.

Una relación de vecindad avanza por varios estados: Down, Init (escuché tu hello), 2-Way (cada uno se ve listado en los hellos del otro), ExStart y Exchange (acuerdan quién dirige el intercambio e intercambian resúmenes de la base de datos), Loading (solicito los LSA que me faltan) y Full (bases de datos sincronizadas). Un router que está en Full con un vecino tiene una adyacencia con él. El tipo de red cambia lo que ocurre después. En un enlace punto a punto, como un enlace serial o un enlace Ethernet configurado con ip ospf network point-to-point, solo existen dos routers, así que simplemente se vuelven completamente adyacentes sin elección. En una red broadcast de acceso múltiple como Ethernet, que es el tipo predeterminado en las interfaces Ethernet, muchos routers pueden compartir el segmento, y si cada router se volviera completamente adyacente con todos los demás, la inundación escalaría mal. Por eso OSPF elige un router designado (DR) y un router designado de respaldo (BDR).

En un segmento broadcast, cada router forma una adyacencia completa solo con el DR y el BDR. Los routers que no son ni uno ni otro, llamados DROTHER, permanecen en el estado 2-Way entre sí, lo cual es normal. Los DROTHER envían las actualizaciones al DR y al BDR a 224.0.0.6, y el DR las vuelve a inundar a todos a 224.0.0.5. El BDR toma el control si el DR falla. La elección usa primero la prioridad OSPF de la interfaz: gana la más alta, con valor predeterminado 1 y rango de 0 a 255, y la prioridad 0 significa que nunca será DR ni BDR. Si las prioridades empatan, gana el router ID más alto, y el segundo mejor se convierte en BDR. La elección no es preferente (non-preemptive): un router nuevo con mayor prioridad no toma el control hasta que el DR falle o se reinicie el proceso OSPF. Configura la prioridad con ip ospf priority 100 en la interfaz.

Verifica con show ip ospf neighbor, que lista el router ID de cada vecino, su prioridad, su estado como FULL/DR, FULL/BDR, FULL/- (punto a punto) o 2WAY/DROTHER, el tiempo dead, la dirección y la interfaz. show ip ospf interface g0/0 muestra el tipo de red, el DR y el BDR, los temporizadores y el costo. Usar punto a punto en un enlace Ethernet entre exactamente dos routers es una decisión de diseño común: omite la elección, elimina la espera antes de que se forme la adyacencia y simplifica la LSDB.

Veamos un ejemplo práctico. Cuatro routers comparten una VLAN Ethernet. En R4, show ip ospf neighbor muestra a R1 como FULL/DR, a R2 como FULL/BDR y a R3 como 2WAY/DROTHER. Un ingeniero junior cree que R3 está fallando, pero esto es normal: los DROTHER solo establecen adyacencia completa con el DR y el BDR. El equipo quiere que R2 sea el DR, así que configura ip ospf priority 200 en R2 e ip ospf priority 0 en R3 y R4, y luego reinicia OSPF durante una ventana de mantenimiento; después, R2 es el DR y R1 el BDR. Entre R1 y R5, sobre un enlace punto a punto, el estado es FULL/- sin elección.

Errores comunes: tratar 2WAY/DROTHER como una falla; esperar que un router con mayor prioridad asuma el rol de DR de inmediato; comparar los router IDs antes que la prioridad; olvidar que la prioridad 0 excluye a un router de la elección; e ignorar los desajustes de temporizadores o de área cuando los vecinos nunca aparecen. Un vecino atascado en INIT, EXSTART o EXCHANGE es la verdadera señal de problema, a menudo un camino en un solo sentido o un desajuste de MTU (unidad máxima de transmisión) en las etapas ExStart y Exchange.

La redacción del examen es consistente. 'Tipo de red predeterminado en Ethernet' es broadcast, que elige un DR y un BDR. 'Sin elección' significa punto a punto. 'La prioridad más alta y luego el router ID más alto' decide el DR. 'Prioridad 0' significa que nunca será DR. 'Se une un router nuevo con mayor prioridad' significa que no hay cambio hasta un reinicio. '224.0.0.5' es todos los routers OSPF y '224.0.0.6' es el DR y el BDR. 'FULL' significa adyacencia; '2WAY entre DROTHER' es lo esperado.

Términos clave

Anuncio de estado de enlace (LSA)
Una unidad de datos de OSPF que describe los enlaces de un router y que se inunda para construir la base de datos de estado de enlace.
Adyacencia (adjacency)
Una relación de vecindad que alcanzó el estado Full con las bases de datos sincronizadas.
Intervalos hello y dead (hello and dead intervals)
Temporizadores de OSPF (10 y 40 segundos de forma predeterminada en enlaces broadcast y punto a punto) que deben coincidir entre vecinos.
DR / BDR
El router designado y el router designado de respaldo, elegidos en un segmento de acceso múltiple para reducir la inundación.
DROTHER
Un router en un segmento broadcast que no es ni DR ni BDR; permanece en 2-Way con los demás DROTHER.
Prioridad OSPF (OSPF priority)
Valor de interfaz (1 de forma predeterminada) que se usa primero en la elección de DR/BDR; 0 significa que nunca es elegible.
Ejemplo real

Dos routers de un centro de datos se conectan por un enlace Ethernet dedicado. Como el enlace solo tiene dos routers, el ingeniero configura ip ospf network point-to-point en ambos extremos. show ip ospf neighbor muestra FULL/- en lugar de FULL/DR, la adyacencia se forma más rápido después de un reinicio y la base de datos ya no necesita un LSA de red para ese segmento.

Consejo para el examen: 2WAY/DROTHER entre dos routers que no son DR es lo esperado. Un vecino atascado en INIT, EXSTART o EXCHANGE es la verdadera señal de un problema.

Comprueba lo que sabes

¿Cuál es el tipo de red OSPF predeterminado en Ethernet y qué provoca?

Broadcast, que desencadena una elección de DR y BDR en el segmento.

R1 tiene prioridad 1 y router ID 5.5.5.5; R2 tiene prioridad 10 y router ID 1.1.1.1. ¿Cuál se convierte en DR si ambos arrancan al mismo tiempo?

R2, porque la prioridad se compara antes que el router ID y 10 es mayor que 1.

Un router nuevo con prioridad 200 se une a un segmento que ya tiene un DR. ¿Toma el control?

No. La elección del DR no es preferente; solo se convierte en DR después de que fallen el DR y el BDR actuales o de que se reinicie OSPF.

Menciona tres parámetros del hello que deben coincidir para que dos routers OSPF se conviertan en vecinos.

Tres cualesquiera de: ID de área, subred y máscara, intervalo hello, intervalo dead, autenticación y flag de área stub.
