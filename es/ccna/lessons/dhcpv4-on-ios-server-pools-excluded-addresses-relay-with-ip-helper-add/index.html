DHCPv4 en IOS: pools del servidor, direcciones excluidas, relay con ip helper-address, solución de problemas de concesiones

DHCP (Dynamic Host Configuration Protocol) entrega direcciones IP y parámetros de forma automática para que no tengas que configurar cada host a mano. Un router Cisco o un switch multicapa con IOS puede actuar como servidor DHCP en sitios pequeños y, más comúnmente, como agente de relay que reenvía las solicitudes a un servidor central. También puede ser cliente DHCP. El CCNA espera que configures y verifiques los tres roles y que averigües por qué un cliente no obtuvo una concesión.

El intercambio tiene cuatro pasos, que se recuerdan como DORA. El cliente envía un Discover por broadcast. El servidor responde con un Offer que contiene una dirección propuesta. El cliente envía por broadcast un Request aceptando esa oferta; se envía por broadcast para que los demás servidores sepan que sus ofertas fueron rechazadas. El servidor confirma con un Acknowledgment. Los clientes usan el puerto UDP (User Datagram Protocol) 68 y los servidores el puerto UDP 67. Las concesiones vencen, así que un cliente intenta renovar con el mismo servidor a la mitad del tiempo de concesión y, si eso falla, intenta con cualquier servidor más adelante en la concesión.

Para configurar un servidor DHCP en IOS, primero excluye las direcciones que asignas de forma estática, como el gateway, los servidores y las impresoras, y luego crea un pool. Las exclusiones son comandos globales y se aplican a todos los pools. La sentencia network le indica al pool qué subred atiende, default-router entrega el gateway, dns-server los resolvedores y lease la duración en días (el valor predeterminado es un día). El orden importa en la práctica: ingresa las exclusiones antes de que los clientes empiecen a pedir direcciones, porque una concesión ya entregada no se retira solo porque la excluyas después. Recuerda también que el router que aloja el pool debe tener una interfaz en la subred indicada en la sentencia network, o una ruta de relay hacia ella, o ningún cliente llegará nunca a él.

ip dhcp excluded-address 192.168.10.1 192.168.10.10
ip dhcp pool LAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.1.53
 domain-name example.local
 lease 7

Como los mensajes Discover son broadcasts, no atraviesan routers. Cuando el servidor está en otra subred, configura un relay en la interfaz que da hacia los clientes: ip helper-address 10.1.1.20 en la interfaz g0/1, en una subinterfaz o en la SVI (interfaz virtual conmutada) de la VLAN. El router recibe el broadcast, escribe la dirección de su interfaz receptora en el campo giaddr (dirección IP del gateway) y envía la solicitud al servidor por unicast. El servidor usa giaddr para elegir el pool cuya red coincide, y por eso debe tener un pool para la subred de ese cliente. De forma predeterminada, ip helper-address también reenvía otros servicios de broadcast UDP, como DNS y TFTP. Un router se convierte en cliente DHCP con ip address dhcp, algo común en una interfaz que da a internet.

Veamos un ejemplo práctico. Se crea una VLAN 30 nueva y su SVI recibe 10.30.0.1/24, pero las PC de esa VLAN obtienen direcciones 169.254. El servidor DHCP central está en 10.1.1.20. Revisas show running-config interface vlan 30 y no encuentras ninguna dirección helper. Agregar ip helper-address 10.1.1.20 bajo interface vlan 30 hace que las solicitudes lleguen al servidor, pero los clientes siguen fallando porque el servidor no tiene un ámbito para 10.30.0.0/24; crearlo completa la solución. En un servidor IOS lo confirmarías con show ip dhcp binding, que lista cada dirección concedida y el identificador del cliente, y con show ip dhcp pool, que muestra la utilización.

Errores comunes: poner la dirección helper en la interfaz que da al servidor en lugar de la que da a los clientes; un helper que apunta al servidor equivocado; una sentencia network del pool que no coincide con la subred de los clientes; olvidar default-router, de modo que los clientes obtienen dirección pero no pueden salir de la subred; faltan exclusiones, así que el servidor concede la dirección del gateway; un pool que se quedó sin direcciones; y DHCP snooping descartando las respuestas del servidor que llegan por un puerto no confiable. show ip dhcp conflict lista las direcciones que el servidor encontró ya en uso, y debug ip dhcp server events muestra el intercambio en vivo en un laboratorio.

Las preguntas del examen usan una redacción reconocible. 'Los clientes de una subred remota obtienen direcciones 169.254' apunta a un ip helper-address ausente o incorrecto. 'Los clientes obtienen dirección pero no llegan a otras subredes' apunta a que falta default-router. 'Un cliente recibió la dirección del propio router' apunta a que faltan exclusiones. '¿Qué campo le indica al servidor la subred del cliente?' es giaddr. 'Orden de los mensajes DHCP' es Discover, Offer, Request, Acknowledgment, y 'el router obtiene su propia dirección del proveedor' es ip address dhcp.

Términos clave

DORA
El intercambio DHCP: Discover, Offer, Request, Acknowledgment.
ip dhcp excluded-address
Comando global de IOS que impide que el servidor DHCP conceda un rango de direcciones.
ip helper-address
Comando de interfaz que retransmite los broadcasts DHCP de los clientes como unicast hacia un servidor en otra subred.
giaddr
El campo de dirección IP del gateway que completa el agente de relay para que el servidor sepa en qué subred está el cliente.
Pool DHCP (DHCP pool)
Un bloque de configuración de IOS con nombre que define la subred, el gateway, los servidores DNS y la concesión para los clientes.
show ip dhcp binding
Comando que lista las direcciones que el servidor DHCP de IOS ha concedido y a qué clientes.
Ejemplo real

Una sucursal pequeña no tiene servidor, así que su router entrega las direcciones. El ingeniero excluye de 172.16.5.1 a 172.16.5.20 para el router, las impresoras y un NAS, crea el pool BRANCH con network 172.16.5.0 255.255.255.0, default-router 172.16.5.1 y los servidores DNS de la oficina central, y a la mañana siguiente revisa show ip dhcp binding y ve cuarenta laptops con concesiones de .21 en adelante.

Consejo para el examen: La dirección helper va en la interfaz que recibe los broadcasts de los clientes, no en la interfaz que da al servidor. Esta ubicación es una trampa común del examen.

Comprueba lo que sabes

¿Qué coloca el agente de relay en giaddr y por qué importa?

La dirección IP de la interfaz que recibió el broadcast del cliente; el servidor la usa para elegir el pool o ámbito que coincide con la subred del cliente.

Los clientes obtienen dirección pero no pueden llegar a nada fuera de su subred. ¿Qué comando del pool probablemente se olvidó?

default-router, que entrega el gateway predeterminado.

¿Por qué deberías excluir del pool la dirección de la interfaz del router?

Porque de lo contrario el servidor podría conceder esa dirección a un cliente y crear un conflicto de dirección duplicada con el gateway.

¿Qué puertos UDP usan los clientes y los servidores DHCP?

Los clientes usan el puerto UDP 68 y los servidores el puerto UDP 67.
