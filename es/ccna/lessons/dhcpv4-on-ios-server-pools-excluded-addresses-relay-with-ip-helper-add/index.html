DHCPv4 en IOS: pools del servidor, direcciones excluidas, relay con ip helper-address, solución de problemas de concesiones

DHCP (Dynamic Host Configuration Protocol, protocolo de configuración dinámica de host) reparte direcciones IP y parámetros automáticamente para que no tengas que configurar cada host a mano. Un router Cisco o un switch multicapa puede actuar como servidor DHCP en sitios pequeños y, más comúnmente, como relay (retransmisor) que reenvía las solicitudes a un servidor central. Necesitas conocer ambas configuraciones y cómo resolver sus problemas.

El intercambio DHCP tiene cuatro pasos, que se recuerdan como DORA. El cliente envía por broadcast un Discover. El servidor responde con un Offer que contiene una dirección propuesta. El cliente envía por broadcast un Request para aceptar esa oferta (por broadcast para que los demás servidores sepan que sus ofertas fueron rechazadas). El servidor confirma con un Acknowledgment. Los clientes usan el puerto UDP 68 y los servidores el puerto UDP 67. Las concesiones expiran, así que los clientes intentan renovar con el servidor a la mitad del tiempo de concesión.

Para configurar un servidor DHCP en IOS, primero excluye las direcciones que asignas estáticamente, como el gateway, los servidores y las impresoras, y luego crea un pool. Las exclusiones son comandos globales y se aplican a todos los pools.

ip dhcp excluded-address 192.168.10.1 192.168.10.10
ip dhcp pool LAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.1.53
 domain-name example.local
 lease 7

Como los mensajes Discover son broadcasts, no atraviesan routers. Cuando el servidor DHCP está en otra subred, configura un relay en la interfaz del router que da hacia los clientes: ip helper-address 10.1.1.20 en la interfaz g0/1 (o en la SVI de la VLAN). El router recibe el broadcast, completa el campo giaddr (gateway IP address) con la dirección de su interfaz y envía la solicitud por unicast al servidor. El servidor usa giaddr para elegir el pool cuya red coincide, por eso el servidor debe tener un pool para la subred de ese cliente. De forma predeterminada, ip helper-address también reenvía otros servicios de broadcast UDP, como DNS y TFTP.

Comandos útiles de verificación son show ip dhcp binding para ver las direcciones concedidas y los identificadores de cliente, show ip dhcp pool para ver la utilización, show ip dhcp conflict para las direcciones que el servidor encontró ya en uso, y debug ip dhcp server events. Un router también puede ser cliente DHCP en una interfaz con ip address dhcp, algo común en un enlace WAN hacia un proveedor de internet.

Fallas comunes: no hay helper address en la interfaz que da hacia los clientes, así que los clientes remotos obtienen APIPA; un helper que apunta al servidor equivocado; un pool cuya sentencia network no coincide con la subred de los clientes; olvidar default-router, así que los clientes obtienen dirección pero no pueden salir de la subred; faltan las exclusiones, así que el servidor reparte la dirección del gateway; el pool se queda sin direcciones; y DHCP snooping descarta las ofertas en un puerto no confiable.

Términos clave

DORA
El intercambio DHCP: Discover, Offer, Request, Acknowledgment.
ip dhcp excluded-address
Comando global de IOS que impide que el servidor DHCP conceda un rango de direcciones.
ip helper-address
Comando de interfaz que retransmite los broadcasts DHCP de los clientes como unicasts hacia un servidor en otra subred.
giaddr
El campo gateway IP address que completa un agente relay para que el servidor sepa en qué subred está el cliente.
show ip dhcp binding
Comando que lista las direcciones que el servidor DHCP de IOS ha concedido y a qué clientes.
Ejemplo real

Se crea una nueva VLAN 30 y su SVI recibe 10.30.0.1/24, pero las PC en ella reciben direcciones 169.254. El servidor DHCP central de Windows está en 10.1.1.20. Agregar ip helper-address 10.1.1.20 bajo interface vlan 30 y crear un ámbito 10.30.0.0/24 en el servidor lo resuelve, y la lista de concesiones del servidor para el nuevo ámbito confirma que los clientes están obteniendo direcciones.

Consejo para el examen: La helper address va en la interfaz que recibe los broadcasts de los clientes, no en la interfaz que da hacia el servidor. Esta ubicación es una trampa común del examen.

Comprueba lo que sabes

¿Qué pone el agente relay en giaddr, y por qué importa?

La dirección IP de la interfaz que recibió el broadcast del cliente; el servidor la usa para elegir el pool o ámbito que coincide con la subred del cliente.

Los clientes obtienen direcciones pero no pueden llegar a nada fuera de su subred. ¿Qué comando del pool probablemente se olvidó?

default-router, que proporciona el gateway predeterminado.

¿Por qué deberías excluir del pool la dirección de la interfaz del router?

Porque, si no, el servidor podría conceder esa dirección a un cliente y crear un conflicto de dirección duplicada con el gateway.
