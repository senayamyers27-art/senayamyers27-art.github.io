Control de acceso a la red: 802.1X, MAB y WebAuth

El control de acceso a la red decide quién y qué puede conectarse a un puerto de switch o a una red inalámbrica, y qué acceso recibe. Sin él, cualquiera que se conecte a una toma de pared se une a la red. La solución de Cisco usa Cisco ISE como servidor de políticas con tres métodos de autenticación en los switches: 802.1X, MAB y WebAuth.

IEEE 802.1X define el control de acceso basado en puertos con tres roles. El supplicant es el software del endpoint (integrado en Windows, macOS, Linux y los teléfonos). El authenticator es el switch o el controlador inalámbrico. El authentication server es un servidor RADIUS como ISE. El supplicant y el switch intercambian mensajes EAP (Extensible Authentication Protocol) sobre la LAN, llamados EAPOL (EAP over LAN). El switch los retransmite dentro de RADIUS hacia ISE. Hasta que la autenticación tiene éxito, el puerto permite solo tráfico EAPOL. Cuando ISE aprueba, devuelve un RADIUS Access-Accept con atributos de autorización como una VLAN, una ACL descargable o un SGT, y el switch los aplica. Los métodos EAP incluyen PEAP (Protected EAP, usuario y contraseña dentro de un túnel TLS), EAP-TLS (certificados en ambos lados, la opción común más fuerte) y EAP-FAST.

Muchos dispositivos, como impresoras, cámaras y dispositivos IoT antiguos, no tienen supplicant. MAB (MAC Authentication Bypass) se encarga de ellos: cuando el puerto no recibe respuesta EAPOL, el switch aprende la dirección MAC del dispositivo a partir de su primera trama y la envía a ISE como nombre de usuario en una solicitud RADIUS. ISE la verifica contra una lista de endpoints o datos de profiling y la autoriza. MAB es una autenticación débil porque las direcciones MAC son fáciles de suplantar, así que dales a los dispositivos MAB un acceso limitado, y usa el profiling de ISE para detectar un dispositivo que dice tener la MAC de una impresora pero se comporta como una laptop.

WebAuth (autenticación web) redirige el navegador del usuario a una página de inicio de sesión, y se usa principalmente para invitados y dispositivos sin supplicant. Local WebAuth sirve el portal desde el switch; Central WebAuth (CWA), más común, usa primero MAB, luego ISE devuelve una URL de redirección y una ACL para que el switch envíe el navegador al portal de invitados de ISE. Después del inicio de sesión, ISE emite un cambio de autorización (CoA) para volver a aplicar la sesión con acceso de invitado.

En el switch, habilitas AAA con RADIUS y dot1x system-auth-control, y configuras los puertos con authentication port-control auto, dot1x pae authenticator y mab. El orden y la prioridad deciden qué método se ejecuta primero; el enfoque común prueba 802.1X y luego recurre a MAB después de un tiempo de espera. Los modos de host controlan cuántos dispositivos permite un puerto: single-host, multi-host (el primer dispositivo se autentica por todos), multi-domain (un dispositivo de datos y un dispositivo de voz, típico de un teléfono IP con una PC detrás) y multi-auth (cada dispositivo se autentica por separado). IOS XE más reciente usa policy maps de Identity-Based Networking Services (IBNS) 2.0 para esta configuración.

Implementa con cuidado. El modo monitor (autenticación abierta) te permite ver qué fallaría sin bloquear a nadie; luego el modo de bajo impacto (low-impact) permite un tráfico limitado antes de la autenticación; el modo cerrado (closed) aplica la política de forma estricta. Verifica con show access-session interface Gi1/0/5 details.

Términos clave

Supplicant
El software cliente de 802.1X en el endpoint.
Authenticator
El switch o controlador inalámbrico que controla el puerto y retransmite EAP hacia el servidor RADIUS.
EAPOL
EAP over LAN: transporta los mensajes EAP entre el supplicant y el switch.
MAB
MAC Authentication Bypass: autentica a los dispositivos sin supplicant usando su dirección MAC.
Change of authorization (cambio de autorización)
Un mensaje RADIUS de ISE que le indica al switch que vuelva a autenticar o aplique una nueva política a una sesión activa.
Ejemplo real

Un puerto de una sala de conferencias está configurado para 802.1X con fallback a MAB y modo multi-domain. Un teléfono IP se autentica por MAB en el dominio de voz, la laptop de un empleado conectada detrás usa PEAP y queda en la VLAN corporativa, y la laptop de un visitante sin credenciales falla en 802.1X, recurre a MAB y es redirigida al portal de invitados de ISE mediante Central WebAuth.

Consejo para el examen: Conoce los tres roles de 802.1X: supplicant, authenticator y authentication server. EAPOL se ejecuta entre el endpoint y el switch; RADIUS se ejecuta entre el switch e ISE. MAB es para dispositivos sin supplicant y es débil porque las MAC pueden suplantarse.

Comprueba lo que sabes

¿Qué tráfico permite un puerto 802.1X antes de la autenticación?

Solo EAPOL (y, según el modo, un tráfico limitado definido por una ACL de preautenticación).

¿Qué modo de host admite un teléfono IP con una PC conectada detrás?

La autenticación multi-domain, que permite un dispositivo de voz y un dispositivo de datos.

¿Por qué se considera débil a MAB?

Las direcciones MAC pueden suplantarse fácilmente, así que los dispositivos MAB deben tener acceso restringido y verificarse con profiling.
