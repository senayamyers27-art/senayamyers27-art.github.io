Métodos de API REST y códigos de respuesta (200, 201, 204, 400, 401, 403, 404, 500)

REST (representational state transfer) es un estilo arquitectónico para API construidas sobre HTTP. Los recursos, como dispositivos, sitios o interfaces, se identifican por URL, y actúas sobre ellos con los métodos HTTP estándar. El servidor responde con un código de estado que te dice qué pasó. Las API REST no tienen estado (stateless): cada solicitud lleva todo lo que el servidor necesita, incluida la autenticación.

Los métodos principales corresponden a las operaciones CRUD (crear, leer, actualizar, eliminar). GET lee un recurso y no debería cambiar nada. POST crea un recurso nuevo, normalmente en una colección, o dispara una acción; el servidor a menudo asigna el identificador del recurso nuevo. PUT crea o reemplaza un recurso en una URL conocida con la representación completa que envías; los campos que omites pueden eliminarse. PATCH actualiza parcialmente un recurso, fusionando solo los campos que envías. DELETE elimina un recurso. GET, PUT y DELETE son idempotentes: repetir la misma solicitud tiene el mismo resultado que enviarla una vez. POST no es idempotente; enviarlo dos veces puede crear dos recursos.

Una solicitud consiste en el método, la URL (a menudo con parámetros de consulta después de un ?, como ?family=Switches), los encabezados y, para POST, PUT y PATCH, un cuerpo. Los encabezados importantes son Content-Type, que indica en qué formato está el cuerpo (por ejemplo application/json), Accept, que indica en qué formato quieres la respuesta, y los encabezados de autenticación como Authorization o X-Auth-Token.

Los códigos de estado vienen en clases. 2xx significa éxito: 200 OK es el éxito general con un cuerpo, típico de GET; 201 Created significa que se creó un recurso nuevo, típico de POST (a menudo con un encabezado Location que apunta a él); 202 Accepted significa que la solicitud se aceptó para procesamiento asíncrono, lo que Catalyst Center usa para las tareas; 204 No Content significa éxito sin cuerpo, típico de DELETE o de algunas llamadas PUT y PATCH. Los códigos 3xx son redirecciones.

Los códigos 4xx significan que el cliente hizo algo mal. 400 Bad Request significa que el servidor no pudo entender la solicitud, a menudo JSON mal formado o un campo obligatorio faltante. 401 Unauthorized significa que la autenticación falta, no es válida o expiró, así que obtén un token nuevo o corrige las credenciales. 403 Forbidden significa que el servidor sabe quién eres pero no tienes permitido hacer esto, un problema de permisos o de rol, y volver a autenticarte no ayudará. 404 Not Found significa que la URL o el recurso no existe, a menudo un error de escritura en la ruta o un identificador incorrecto. Otros códigos 4xx incluyen 405 Method Not Allowed y 409 Conflict. Los códigos 5xx significan que el servidor falló: 500 Internal Server Error es una falla genérica del lado del servidor, y 503 Service Unavailable significa que el servicio no puede atender la solicitud temporalmente. Con los errores 5xx la solicitud puede ser válida; el problema está en el servidor.

Un buen script verifica el código de estado antes de usar el cuerpo, maneja el 401 renovando el token y registra las respuestas 4xx y 5xx con el mensaje de error que devuelve la API.

Términos clave

CRUD
Create, read, update, delete (crear, leer, actualizar, eliminar): las operaciones básicas que corresponden a POST, GET, PUT o PATCH y DELETE.
Idempotent (idempotente)
Repetir la solicitud tiene el mismo efecto que enviarla una vez; se cumple para GET, PUT y DELETE.
201 Created
Código de éxito que indica que se creó un recurso nuevo.
401 frente a 403
401 significa no autenticado o token no válido; 403 significa autenticado pero sin permiso.
Content-Type
El encabezado que declara el formato del cuerpo de la solicitud o de la respuesta.
Ejemplo real

Un script que crea VLAN mediante la API de un controlador recibe 201 en la primera llamada y luego 401 una hora después. El token expiró, así que el script solicita un token nuevo y reintenta. Una llamada posterior para eliminar un sitio devuelve 403 porque la cuenta de servicio solo tiene el rol de observador, así que el equipo ajusta el rol en lugar de reintentar.

Consejo para el examen: 200 OK, 201 Created, 204 No Content; 400 solicitud mal formada, 401 problema de autenticación, 403 problema de permisos, 404 URL o recurso incorrecto, 500 falla del servidor. PUT reemplaza, PATCH fusiona.

Comprueba lo que sabes

Un POST que crea un nuevo registro de dispositivo tiene éxito. ¿Qué código de estado es el más apropiado?

201 Created.

¿Cuál es la diferencia práctica entre recibir 401 y 403?

401 significa que debes autenticarte o renovar tu token; 403 significa que estás autenticado pero te falta permiso, así que reintentar con la misma identidad no ayudará.

¿Qué método deberías usar para cambiar un campo de un recurso sin enviar el objeto completo?

PATCH.
