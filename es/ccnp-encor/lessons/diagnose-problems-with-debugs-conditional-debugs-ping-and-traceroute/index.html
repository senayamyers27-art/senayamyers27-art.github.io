Cisco CCNP Enterprise core exam (ENCOR) 350-401 v1.2

Diagnosticar problemas con debugs, debugs condicionales, ping y traceroute

La resolución de problemas en ENCOR combina pruebas simples de alcanzabilidad con una inspección detallada de los protocolos. La habilidad que se evalúa es elegir la herramienta correcta y usarla de forma segura en un dispositivo de producción.

Ping envía solicitudes ICMP echo y espera respuestas echo. En Cisco IOS, cada resultado tiene un carácter: '!' es una respuesta, '.' es un tiempo agotado, 'U' significa que se devolvió destination unreachable, 'Q' significa source quench, 'M' significa que el paquete no pudo fragmentarse y '?' es un tipo de paquete desconocido. El ping extendido (escribe ping solo, o usa palabras clave) te permite configurar la interfaz de origen, el tamaño del paquete, la cantidad de repeticiones y el bit don't-fragment. Usar como origen una interfaz LAN con ping 10.2.2.2 source Loopback0 prueba si existe la ruta de regreso para esa subred, algo que no prueba un ping predeterminado desde la interfaz de salida. Usar size 1500 df-bit es la forma de encontrar problemas de MTU en los túneles.

Traceroute muestra la ruta salto a salto. Cisco IOS envía sondas UDP con TTL creciente empezando en 1. Cada router que decrementa el TTL a 0 devuelve un mensaje ICMP time exceeded, identificándose; el destino devuelve port unreachable, lo que termina el trazado. tracert de Windows usa ICMP echo en su lugar. En la salida de IOS, '*' significa que no hubo respuesta dentro del tiempo límite, lo que puede significar un filtro o un router que limita la tasa de ICMP y no una falla real; un trazado que se detiene en un salto específico indica dónde buscar después. Tanto ping como traceroute aceptan vrf NAME cuando trabajas dentro de una VRF.

Los debugs muestran eventos en tiempo real de un proceso, como debug ip ospf adj o debug ip bgp updates. Son poderosos pero peligrosos: la salida de debug la procesa la CPU, y en un router ocupado un debug amplio como debug ip packet puede llevar la CPU al 100 por ciento y causar una caída. Buenas prácticas: prefiere primero los comandos show; envía la salida de debug al búfer de log en lugar de a la consola (no logging console, logging buffered 64000 debugging) y mírala con show logging; usa terminal monitor para verla en una sesión SSH; ten siempre claro cómo detenerlo (undebug all o u all); y limita el alcance del debug lo más posible. Habilita service timestamps debug datetime msec para que los eventos tengan marca de tiempo.

El debugging condicional restringe la salida a lo que te interesa. debug condition interface GigabitEthernet0/1 limita los debugs compatibles a esa interfaz; debug condition ip 10.1.1.10 los limita a un host. Muchos debugs también aceptan una ACL, como en debug ip packet 100 detail, que muestra solo los paquetes que coinciden con la ACL 100 (y ten en cuenta que debug ip packet solo muestra los paquetes conmutados por proceso, no los conmutados por CEF). Quita las condiciones con undebug condition all o no debug condition all.

Un método estructurado ayuda: define el problema, reúne información con comandos show, ping y traceroute, formula una hipótesis, pruébala (quizá con un debug acotado), corrige, verifica y documenta. Muchos escenarios de ENCOR siguen el modelo OSI de abajo hacia arriba, confirmando la capa física y de enlace de datos antes de revisar el enrutamiento.

Términos clave

Extended ping (ping extendido)
Un ping que te permite elegir el origen, el tamaño, la cantidad y el bit don't-fragment.
Traceroute
Una herramienta que incrementa el TTL en las sondas para listar cada salto de Capa 3 hacia un destino.
Conditional debug (debug condicional)
Debugging limitado a una interfaz, dirección u otra condición específica.
undebug all
Comando que desactiva todo el debugging de inmediato.
Ejemplo real

Los usuarios de una sucursal no pueden alcanzar un servidor, pero un ping desde la interfaz WAN del router de la sucursal tiene éxito. El ingeniero ejecuta ping 10.9.9.9 source Gi0/1 desde la interfaz LAN y falla, lo que revela que el router de la sede central no tiene una ruta de regreso a la LAN de la sucursal porque la nueva subred nunca se anunció.

Consejo para el examen: Prefiere siempre los comandos show, envía la salida de debug al búfer, acota los debugs con condiciones o ACL y conoce undebug all. En la salida de ping, '.' es un tiempo agotado y 'U' es un mensaje unreachable devuelto por un router.

Comprueba lo que sabes

¿Por qué usar una interfaz LAN como origen de un ping al probar la conectividad de una sucursal?

Prueba que el extremo remoto tiene una ruta de regreso a la subred LAN, algo que un ping con origen en la interfaz WAN no demuestra.

¿Cómo descubre cada salto el traceroute de IOS?

Envía sondas UDP con TTL creciente; cada router donde vence el TTL devuelve ICMP time exceeded, y el destino devuelve port unreachable.

¿Cómo puedes limitar la salida de debug a una interfaz?

Usa debug condition interface seguido del nombre de la interfaz antes de habilitar el debug.
