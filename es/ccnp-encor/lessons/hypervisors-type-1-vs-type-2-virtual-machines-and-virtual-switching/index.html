Hipervisores: tipo 1 frente a tipo 2, máquinas virtuales y conmutación virtual

La virtualización permite que un servidor físico ejecute muchos sistemas operativos aislados. El software que lo hace posible es el hipervisor, también llamado monitor de máquinas virtuales. Divide la CPU, la memoria, el almacenamiento y las interfaces de red del servidor entre las máquinas virtuales (VM), cada una de las cuales cree que tiene su propio hardware. Los ingenieros de redes necesitan este conocimiento porque muchas funciones de red, desde firewalls hasta controllers de SD-WAN y componentes de Catalyst Center, ahora se ejecutan como VM, y porque los servidores traen sus propios switches virtuales a la red.

Un hipervisor tipo 1, también llamado bare-metal o nativo, se ejecuta directamente sobre el hardware del servidor sin un sistema operativo de propósito general debajo. Ejemplos son VMware ESXi, Microsoft Hyper-V, KVM (la Kernel-based Virtual Machine integrada en Linux) y Xen. Como tiene acceso directo al hardware, es eficiente y es lo que usan los centros de datos en producción. Un hipervisor tipo 2, también llamado alojado (hosted), se ejecuta como una aplicación sobre un sistema operativo normal como Windows, macOS o Linux. Ejemplos son VMware Workstation, VMware Fusion y Oracle VirtualBox. Es práctico para laboratorios y equipos de escritorio, pero tiene más sobrecarga porque cada acceso al hardware pasa por el sistema operativo anfitrión.

Una máquina virtual consiste en hardware virtual (vCPU, memoria virtual, discos virtuales almacenados como archivos y NIC virtuales) más un sistema operativo invitado y sus aplicaciones. Cada VM está aislada de las demás, puede ejecutar un sistema operativo distinto y puede moverse, capturarse en snapshots o clonarse como un conjunto de archivos. Funciones como la migración en vivo (live migration) mueven una VM en ejecución entre hosts con una interrupción mínima, lo que requiere almacenamiento compartido o migración del almacenamiento y conectividad de red equivalente en ambos hosts.

Las VM deben comunicarse, así que el hipervisor incluye un switch virtual. Un switch virtual es un switch de Capa 2 por software dentro del host. La NIC virtual de cada VM se conecta a un puerto de él, y las NIC físicas del host actúan como uplinks hacia la red física. Los switches virtuales admiten el etiquetado de VLAN, así que el puerto de una VM puede colocarse en una VLAN, y el uplink hacia el switch físico es normalmente un trunk 802.1Q que transporta varias VLAN. El tráfico entre dos VM en el mismo host y la misma VLAN nunca toca la red física. Ejemplos incluyen VMware vSphere Standard Switch (configurado por host), vSphere Distributed Switch (administrado de forma centralizada en muchos hosts), el switch virtual de Hyper-V y Open vSwitch en Linux.

Para el ingeniero de redes, los puntos clave de diseño son configurar el puerto del switch físico que da hacia un hipervisor como trunk con las VLAN permitidas correctas, usar agregación de enlaces o el NIC teaming del hipervisor de forma consistente en ambos lados, y recordar que parte del tráfico es invisible para las herramientas de monitoreo físico porque se queda dentro del host.

Términos clave

Hypervisor (hipervisor)
Software que crea y ejecuta máquinas virtuales compartiendo el hardware físico entre ellas.
Type 1 hypervisor (hipervisor tipo 1)
Un hipervisor bare-metal que se ejecuta directamente sobre el hardware, como ESXi, Hyper-V o KVM.
Type 2 hypervisor (hipervisor tipo 2)
Un hipervisor alojado que se ejecuta como aplicación sobre un sistema operativo anfitrión, como VirtualBox o VMware Workstation.
Virtual switch (switch virtual)
Un switch de Capa 2 por software dentro del hipervisor que conecta las NIC virtuales entre sí y con los uplinks físicos.
Ejemplo real

Un host de centro de datos que ejecuta ESXi tiene dos NIC de 25 gigabits conectadas a dos switches leaf como trunks 802.1Q. Las VM web están en la VLAN 110 y las VM de base de datos en la VLAN 120 en el mismo distributed switch; el tráfico web a web se queda dentro del host, mientras que el tráfico web a base de datos sube por el trunk hacia el switch leaf para el enrutamiento y la inspección del firewall.

Consejo para el examen: El tipo 1 se ejecuta en bare metal (producción, centro de datos); el tipo 2 se ejecuta sobre un sistema operativo anfitrión (laboratorios, escritorios). El puerto físico que da hacia un hipervisor suele ser un trunk, no un puerto de acceso.

Comprueba lo que sabes

¿KVM es un hipervisor tipo 1 o tipo 2, y por qué?

Tipo 1, porque forma parte del kernel de Linux y ejecuta las VM con acceso directo al hardware en lugar de como una aplicación sobre un sistema operativo anfitrión separado.

¿Por qué el tráfico entre dos VM podría no aparecer en una sesión SPAN del switch físico?

Si ambas VM están en el mismo host y la misma VLAN, el switch virtual reenvía el tráfico internamente y este nunca llega al switch físico.
