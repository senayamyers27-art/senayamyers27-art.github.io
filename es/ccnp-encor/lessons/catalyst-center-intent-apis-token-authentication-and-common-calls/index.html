Intent APIs de Catalyst Center: autenticación con token y llamadas comunes

Catalyst Center expone una API REST northbound, llamada Intent API, que permite a scripts y otros sistemas hacer lo mismo que puedes hacer en la GUI: listar dispositivos, leer el estado de salud (health), consultar clientes, ejecutar comandos y aprovisionar. Se llama basada en intención porque describes lo que quieres, por ejemplo 'dame el health de todos los sitios', y Catalyst Center determina cómo obtenerlo de los dispositivos. La API está documentada dentro del producto, en su sección de plataforma, y en el sitio para desarrolladores de Cisco.

La autenticación usa un token. Primero envías una solicitud POST al endpoint de autenticación, /dna/system/api/v1/auth/token, usando autenticación HTTP Basic con un usuario y contraseña de Catalyst Center. La respuesta es un JSON que contiene un valor Token. En cada solicitud posterior, envías ese token en el encabezado X-Auth-Token. El token es válido por un tiempo limitado (Cisco documenta un valor predeterminado de aproximadamente una hora); después de eso, la API devuelve 401 y debes solicitar uno nuevo.

import os, requests
from requests.auth import HTTPBasicAuth
BASE = os.environ["CC_URL"]  # Dirección HTTPS de Catalyst Center
user, password = os.environ["CC_USER"], os.environ["CC_PASS"]
r = requests.post(BASE + "/dna/system/api/v1/auth/token",
                  auth=HTTPBasicAuth(user, password), verify="ca.pem")
token = r.json()["Token"]
headers = {"X-Auth-Token": token, "Content-Type": "application/json"}
devs = requests.get(BASE + "/dna/intent/api/v1/network-device",
                    headers=headers, verify="ca.pem").json()
for d in devs["response"]:
    print(d["hostname"], d["managementIpAddress"], d["softwareVersion"])

Las rutas de la Intent API empiezan con /dna/intent/api/v1/. Entre las llamadas comunes están network-device (el inventario, con parámetros de consulta para filtrar por hostname, familia o plataforma, y un ID de dispositivo que puedes usar en otras llamadas), site (la jerarquía de sitios), network-health y site-health (los puntajes de health de assurance), client-health y client-detail (experiencia de los clientes), los endpoints de topology (topología física y de Capa 2 o Capa 3) y los endpoints de interface. La mayoría de las respuestas envuelven los resultados en una clave response, así que primero lees json()["response"].

Algunas operaciones toman tiempo, como ejecutar comandos CLI con el command runner (network-device-poller/cli/read-request), el aprovisionamiento o el despliegue de plantillas. Estas son asíncronas: la API responde de inmediato (a menudo con 202 Accepted) y devuelve un taskId. Luego consultas periódicamente (polling) el endpoint de tareas, /dna/intent/api/v1/task/{taskId}, hasta que reporte que terminó, y lees el resultado, que puede apuntar a un ID de archivo con la salida del comando que obtienes desde el endpoint de archivos. Diseña tus scripts para esperar y consultar, en lugar de asumir que el trabajo terminó al instante.

Además de la Intent API, Catalyst Center ofrece notificaciones de eventos (webhooks) que envían los issues de assurance a sistemas externos, como herramientas ITSM, y APIs de integración. Por seguridad, usa una cuenta dedicada con el rol mínimo necesario, mantén las credenciales fuera del código y valida el certificado del servidor. Los endpoints exactos cambian entre versiones, así que revisa la documentación de la API para tu versión.

Términos clave

Intent API
La API REST northbound de Catalyst Center para consultar y configurar la red en términos de resultados deseados.
X-Auth-Token
El encabezado HTTP que lleva el token de Catalyst Center en cada solicitud a la API.
Token endpoint (endpoint de token)
POST /dna/system/api/v1/auth/token con autenticación Basic, que devuelve un token de duración limitada.
taskId
El identificador que devuelve una operación asíncrona; se consulta mediante la API de tareas para obtener su estado y resultado.
Ejemplo real

Cada mañana, un script se autentica en Catalyst Center, llama al endpoint site-health y publica en el canal de chat de operaciones cualquier sitio con un puntaje de health por debajo del objetivo. Cuando un sitio se ve mal, ejecuta un comando show en los switches de ese sitio mediante el command runner, consulta el taskId devuelto y adjunta la salida.

Consejo para el examen: Primero el token: POST a /dna/system/api/v1/auth/token con autenticación Basic y luego envía X-Auth-Token en cada llamada. Las acciones de larga duración devuelven un taskId que debes consultar, no el resultado final.

Comprueba lo que sabes

¿Qué encabezado lleva el token de Catalyst Center?

X-Auth-Token.

Una solicitud al command runner responde de inmediato con un taskId. ¿Qué haces después?

Consultar el endpoint de tareas con ese taskId hasta que termine y luego obtener el resultado, como el archivo de salida.
