Niveles de severidad de syslog y configuración del registro

Syslog es la forma estándar en que los dispositivos de red reportan eventos: interfaces que suben o bajan, vecinos que cambian de estado, cambios de configuración, violaciones de seguridad y problemas de hardware. Los mensajes pueden guardarse localmente o enviarse a un servidor syslog central, donde pueden buscarse, correlacionarse y conservarse para auditoría. ENCOR espera que conozcas los niveles de severidad por número y nombre y cómo configurar a dónde van los mensajes.

Cada mensaje tiene una severidad de 0 a 7, donde los números más bajos son más graves:

0 Emergencies    el sistema no se puede usar
1 Alerts         se necesita acción inmediata
2 Critical       condiciones críticas
3 Errors         condiciones de error
4 Warnings       condiciones de advertencia
5 Notifications  normal pero significativo
6 Informational  mensajes informativos
7 Debugging      mensajes de depuración

Una mnemotecnia común en inglés es 'Every Awesome Cisco Engineer Will Need Ice cream Daily'. Cuando configuras un nivel de registro, el dispositivo envía los mensajes de ese nivel y de todos los niveles más graves (número más bajo). Por ejemplo, logging trap warnings envía los niveles 0 a 4 al servidor syslog. Una interfaz que cambia de estado normalmente genera un mensaje de nivel 3 (LINK-3-UPDOWN) y los cambios del protocolo de línea son de nivel 5 (LINEPROTO-5-UPDOWN).

Un mensaje de Cisco se ve así: *Sep 25 10:15:02.123: %LINEPROTO-5-UPDOWN: Line protocol on Interface GigabitEthernet0/1, changed state to down. Las partes son una marca de tiempo, luego la facility (el componente, aquí LINEPROTO), el número de severidad, un mnemónico (UPDOWN) y la descripción. Se puede agregar un número de secuencia con service sequence-numbers.

Los mensajes pueden ir a varios destinos, cada uno con su propio nivel. La consola (logging console <level>) está activada por defecto en nivel debugging, lo que puede saturar una línea de consola lenta durante un evento, así que muchos ingenieros suben el nivel o la deshabilitan. El destino monitor (logging monitor <level>) envía los mensajes a las sesiones VTY que han ejecutado terminal monitor. El búfer (logging buffered <size> <level>) guarda los mensajes en RAM, se consulta con show logging y se pierde al reiniciar. El servidor syslog se configura con logging host 10.0.0.60 y su nivel con logging trap <level> (informational por defecto). Syslog hacia un servidor usa el puerto UDP 514 por defecto; algunas plataformas admiten transporte TCP o TLS para mayor confiabilidad y seguridad.

Buenas prácticas: haz que las marcas de tiempo sean útiles con service timestamps log datetime msec localtime show-timezone y sincroniza los relojes con NTP; de lo contrario, correlacionar eventos entre dispositivos es adivinar. Configura una dirección de origen consistente con logging source-interface Loopback0 para que el servidor vea una sola identidad por dispositivo. Envía los mensajes de nivel informational o notifications a un servidor central, conserva un búfer local para revisiones rápidas y evita enviar el nivel debugging al servidor en producción. logging facility establece la facility de syslog (como local7) que usa el servidor para clasificar los mensajes. Usa show logging para ver la configuración actual, los contadores por destino y el contenido del búfer.

Recuerda que syslog sobre UDP no tiene confirmación ni cifrado, así que para los registros importantes combínalo con notificaciones SNMP, transporte confiable donde se admita y protección de la red de gestión.

Términos clave

Syslog severity (severidad de syslog)
Una escala de 0 a 7 donde 0 es emergencies y 7 es debugging; más bajo es más grave.
logging trap
Establece el nivel máximo de severidad que se envía a los servidores syslog.
logging buffered
Guarda los mensajes de log en la RAM del dispositivo para verlos con show logging.
terminal monitor
Muestra los mensajes de log y de debug en la sesión SSH o Telnet actual.
Facility
El componente o categoría de un mensaje, como LINEPROTO u OSPF, o la facility de syslog como local7.
Ejemplo real

Un ingeniero que investiga caídas intermitentes configura logging trap notifications y logging host 10.0.0.60 en cada switch, con NTP y marcas de tiempo en milisegundos. El servidor syslog muestra entonces mensajes LINK-3-UPDOWN en el mismo uplink de distribución en varios switches dentro del mismo segundo, lo que apunta a un transceptor óptico que está fallando.

Consejo para el examen: Configurar un nivel incluye todos los números más bajos. logging trap 4 (warnings) envía del 0 al 4. El nivel 7 es debugging y el nivel 0 es emergencies. Syslog usa UDP 514 por defecto.

Comprueba lo que sabes

¿Qué niveles de severidad se envían con logging trap errors?

Los niveles 0 a 3: emergencies, alerts, critical y errors.

¿Por qué deberías configurar NTP cuando usas syslog?

Para que las marcas de tiempo de todos los dispositivos sean precisas y los eventos puedan correlacionarse.

Estás conectado por SSH y no ves mensajes de log. ¿Qué comando falta?

terminal monitor.
