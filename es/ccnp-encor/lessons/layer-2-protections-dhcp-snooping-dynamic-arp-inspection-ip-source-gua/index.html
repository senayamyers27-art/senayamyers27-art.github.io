Protecciones de Capa 2: DHCP snooping, dynamic ARP inspection, IP source guard

Los protocolos de Capa 2 como DHCP y ARP se diseñaron para redes confiables y no tienen autenticación. Un atacante en un puerto de acceso puede aprovecharlo: un servidor DHCP falso (rogue) puede anunciarse a sí mismo como gateway predeterminado para interceptar el tráfico, el ARP spoofing puede redirigir el tráfico a través del atacante (un ataque de intermediario) y el IP spoofing puede hacer que el tráfico de un atacante parezca venir de otro host. Los switches Cisco proporcionan tres funciones que se apoyan unas en otras para detener estos ataques.

DHCP snooping actúa como un firewall para DHCP. Marcas los puertos como confiables (trusted) o no confiables (untrusted). Los puertos confiables son los uplinks hacia los servidores DHCP legítimos; todos los demás son no confiables por defecto. En los puertos no confiables, el switch descarta los mensajes de servidor DHCP (offers y acknowledgments), así que un servidor falso en un puerto de usuario no puede responder a los clientes. También puede limitar la tasa de mensajes DHCP en los puertos no confiables para evitar ataques de agotamiento (starvation) que consumen el pool de direcciones. A medida que los clientes obtienen direcciones con éxito, el switch construye la tabla de enlaces (binding table) de DHCP snooping, registrando la dirección MAC, la dirección IP, la VLAN, el puerto y el tiempo de concesión de cada cliente. Esta tabla es en la que se apoyan las otras dos funciones.

ip dhcp snooping
ip dhcp snooping vlan 10,20
interface GigabitEthernet1/0/48
 ip dhcp snooping trust
interface range GigabitEthernet1/0/1 - 24
 ip dhcp snooping limit rate 15

Dynamic ARP inspection (DAI) valida los paquetes ARP en los puertos no confiables. Para cada solicitud o respuesta ARP, el switch verifica el par IP-MAC del emisor contra la binding table de DHCP snooping y descarta los paquetes que no coinciden, bloqueando el ARP spoofing y el envenenamiento ARP. Los dispositivos con direcciones estáticas, que no están en la binding table, necesitan ARP ACL para ser permitidos. Los uplinks entre switches normalmente se marcan como confiables con ip arp inspection trust. Habilita DAI por VLAN con ip arp inspection vlan 10,20. La validación opcional (ip arp inspection validate src-mac dst-mac ip) agrega verificaciones de que las direcciones en el cuerpo ARP coincidan con el encabezado Ethernet.

IP source guard (IPSG) filtra el tráfico IP ordinario en los puertos de acceso no confiables. Con ip verify source en una interfaz, el switch permite solo el tráfico cuya IP de origen (o tanto la IP como la MAC de origen, con ip verify source port-security) coincide con un enlace (binding) para ese puerto, tomado de la tabla de DHCP snooping o de enlaces estáticos. Todo lo demás se descarta, lo que impide que un host suplante otra dirección.

La cadena de dependencias es importante: DAI e IP source guard necesitan ambos la binding table de DHCP snooping, así que DHCP snooping debe habilitarse primero en las VLAN correspondientes. Un problema común en los laboratorios es que DHCP deja de funcionar después de habilitar snooping porque el uplink hacia el servidor no se marcó como confiable, o porque el switch inserta la opción 82 de DHCP y el servidor o el relay la rechaza (se corrige con no ip dhcp snooping information option donde corresponda). Verifica con show ip dhcp snooping, show ip dhcp snooping binding, show ip arp inspection y show ip verify source. Las violaciones se registran y, en las violaciones del límite de tasa, el puerto puede pasar a err-disabled.

Términos clave

DHCP snooping
Bloquea los mensajes de servidor DHCP en los puertos no confiables y construye una binding table de las concesiones legítimas.
Binding table (tabla de enlaces)
El registro de DHCP snooping de la MAC, la IP, la VLAN y el puerto de la concesión de cada cliente.
Dynamic ARP inspection
Descarta los paquetes ARP en los puertos no confiables cuyo mapeo de IP a MAC no coincide con la binding table.
IP source guard
Filtra el tráfico en los puertos de acceso para que solo se permitan los orígenes que coinciden con el enlace del puerto.
Trusted port (puerto confiable)
Un puerto, normalmente un uplink o un puerto de servidor, exento de las verificaciones de DHCP snooping y DAI.
Ejemplo real

Un usuario conecta un router doméstico en un puerto de la oficina y su servidor DHCP empieza a repartir direcciones 192.168.1.x. Con DHCP snooping habilitado, el switch descarta sus offers en el puerto no confiable. Más tarde, una herramienta en otra máquina envía respuestas ARP falsificadas reclamando la IP del gateway; DAI las descarta porque la MAC no coincide con la binding table, y un mensaje del log identifica el puerto.

Consejo para el examen: DHCP snooping va primero porque DAI e IP source guard usan su binding table. Marca como confiables los uplinks hacia los servidores DHCP y hacia otros switches, o DHCP y ARP dejarán de funcionar.

Comprueba lo que sabes

¿Qué le pasa a un DHCP offer recibido en un puerto no confiable con DHCP snooping habilitado?

El switch lo descarta, porque los mensajes de servidor solo se permiten en los puertos confiables.

¿Qué función detiene el envenenamiento ARP y contra qué verifica?

Dynamic ARP inspection, que valida los pares IP-MAC de ARP contra la binding table de DHCP snooping (o contra ARP ACL para los hosts estáticos).
