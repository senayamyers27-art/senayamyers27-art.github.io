AAA con TACACS+ y RADIUS, method lists y fallback

Las cuentas locales en cada dispositivo no escalan: agregar o quitar un administrador significa tocar cientos de dispositivos. AAA centraliza esto. Significa autenticación (authentication: quién eres), autorización (authorization: qué puedes hacer) y contabilidad (accounting: qué hiciste). Los dispositivos envían solicitudes AAA a un servidor central, como Cisco ISE, que verifica las credenciales contra un directorio y devuelve decisiones, mientras registra la actividad.

Dos protocolos transportan AAA. TACACS+ (Terminal Access Controller Access-Control System Plus) fue desarrollado por Cisco y ahora está documentado como un RFC informativo. Se ejecuta sobre el puerto TCP 49, cifra todo el cuerpo del paquete y separa la autenticación, la autorización y la contabilidad en intercambios distintos. Esa separación te permite autorizar cada comando individual que escribe un administrador y registrar cada comando, lo que hace de TACACS+ la opción preferida para la administración de dispositivos. RADIUS (Remote Authentication Dial-In User Service) es un estándar abierto que se ejecuta sobre UDP, comúnmente en los puertos 1812 para autenticación y 1813 para contabilidad (las implementaciones antiguas usaban 1645 y 1646). Cifra solo el campo de la contraseña, combina la autenticación y la autorización en una sola respuesta y tiene un amplio soporte para el acceso a la red, así que es el protocolo para 802.1X, VPN y el acceso inalámbrico de usuarios. Un resumen útil: TACACS+ para los administradores que inician sesión en los dispositivos, RADIUS para los usuarios y endpoints que acceden a la red.

La configuración de AAA empieza con aaa new-model, que habilita AAA y cambia de inmediato la forma en que se autentican las líneas, así que ten una cuenta local lista antes de escribirlo. Luego define los servidores y los grupos de servidores, y las method lists que dicen en qué orden probar las fuentes de autenticación:

aaa new-model
tacacs server ISE1
 address ipv4 10.0.0.20
 key <shared-key>
aaa group server tacacs+ ADMIN-TAC
 server name ISE1
!
aaa authentication login VTY-AUTH group ADMIN-TAC local
aaa authorization exec VTY-AUTH group ADMIN-TAC local
aaa authorization commands 15 VTY-AUTH group ADMIN-TAC local
aaa accounting commands 15 VTY-AUTH start-stop group ADMIN-TAC
!
line vty 0 15
 login authentication VTY-AUTH
 authorization exec VTY-AUTH
 authorization commands 15 VTY-AUTH
 accounting commands 15 VTY-AUTH

Una method list es una lista ordenada de métodos con nombre (o default). La lista default se aplica automáticamente a todas las líneas que no especifican una lista con nombre; una lista con nombre se aplica solo donde se hace referencia a ella. Los métodos se prueban de izquierda a derecha, pero el fallback ocurre solo ante un error, es decir, cuando no hay respuesta del servidor. Si el servidor TACACS+ es alcanzable y rechaza la contraseña, eso es una falla, y el dispositivo no prueba el siguiente método; el inicio de sesión se deniega. Así que en el ejemplo, local se usa solo cuando todos los servidores de ADMIN-TAC son inalcanzables. Los métodos finales comunes son local, enable y, peligrosamente, none, que permite el acceso sin autenticación.

Mantén seguro el acceso por consola: muchos diseños usan una lista con nombre para las líneas VTY y mantienen la consola en local o en una lista con fallback local, para que una falla de la red nunca te deje fuera. Configura una interfaz de origen para el tráfico AAA (ip tacacs source-interface Loopback0) para que el servidor reconozca al dispositivo. Verifica con show aaa servers, test aaa group ADMIN-TAC user pass legacy y debug aaa authentication en un laboratorio.

Términos clave

AAA
Authentication, authorization and accounting (autenticación, autorización y contabilidad): identificar a los usuarios, controlar sus acciones y registrar la actividad.
TACACS+
Protocolo AAA desarrollado por Cisco sobre TCP 49 que cifra todo el cuerpo y separa las tres A; el mejor para la administración de dispositivos.
RADIUS
Protocolo AAA de estándar abierto sobre UDP 1812/1813 que cifra solo la contraseña y combina la autenticación y la autorización; se usa para el acceso a la red.
Method list
Una lista ordenada de fuentes de autenticación o autorización, aplicada por nombre o como default.
Fallback (respaldo)
Pasar al siguiente método de una lista, lo que ocurre solo cuando un método devuelve un error, como la falta de respuesta del servidor.
Ejemplo real

Durante una caída de la WAN, el router de una sucursal no puede alcanzar los servidores TACACS+. Como su method list de VTY es group ADMIN-TAC local, el router recurre a la cuenta local de emergencia (break-glass) y el ingeniero aún puede iniciar sesión. Cuando los servidores vuelven a ser alcanzables, una colega que escribe mal su contraseña es rechazada directamente en lugar de recurrir a la base local.

Consejo para el examen: El fallback al siguiente método ocurre solo ante un error (sin respuesta), nunca ante una contraseña rechazada. TACACS+ equivale a TCP 49, cifrado de todo el cuerpo y autorización por comando; RADIUS equivale a UDP, cifrado solo de la contraseña y 802.1X.

Comprueba lo que sabes

El servidor TACACS+ rechaza la contraseña de un usuario. ¿El dispositivo probará después la base de datos local?

No; un rechazo es una falla, no un error, así que la method list se detiene y el acceso se deniega.

¿Por qué se prefiere TACACS+ para la administración de dispositivos?

Separa la autorización de la autenticación para que cada comando pueda autorizarse y contabilizarse individualmente, y cifra toda la carga útil.

¿Cuál es el riesgo de escribir aaa new-model sin preparación?

La autenticación de las líneas cambia de inmediato a los valores predeterminados de AAA, lo que puede dejarte fuera si no hay un usuario local ni una method list configurados.
