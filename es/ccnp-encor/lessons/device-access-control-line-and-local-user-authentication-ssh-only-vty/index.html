Cisco CCNP Enterprise core exam (ENCOR) 350-401 v1.2

Control de acceso a dispositivos: autenticación por línea y por usuario local, acceso VTY solo por SSH

Cada router y switch debe estar protegido contra el acceso administrativo no autorizado. ENCOR evalúa los bloques básicos en Cisco IOS: cómo autentican a los usuarios las líneas de consola y VTY, cómo se almacenan las contraseñas y cómo permitir solo SSH.

Los dispositivos Cisco tienen líneas: la línea de consola (line con 0) para el acceso serial directo y las líneas de terminal virtual (line vty 0 4, o 0 15 en muchas plataformas) para Telnet o SSH remoto. El método más simple es una contraseña de línea: password más login bajo la línea. Todos comparten una sola contraseña y no hay rendición de cuentas, así que solo es adecuado para laboratorios. Un mejor método son las cuentas de usuario locales: username admin privilege 15 secret <password> crea un usuario, y login local bajo la línea hace que el dispositivo pida usuario y contraseña y los verifique en la base de datos local. Cada administrador tiene su propia cuenta, y los logs pueden registrar quién hizo qué.

Protege el modo EXEC privilegiado con enable secret, que se almacena como hash, en lugar del antiguo enable password. Usa también la palabra clave secret para los nombres de usuario. IOS XE moderno admite tipos de hash fuertes como el tipo 8 (PBKDF2 con SHA-256) y el tipo 9 (scrypt), seleccionables con algorithm-type; el tipo 5 se basa en MD5 y es más antiguo, y el tipo 7, producido por service password-encryption para los comandos password simples, es una codificación débil y reversible que solo evita que alguien lea la contraseña por encima de tu hombro. Nunca confíes en el tipo 7.

Telnet envía todo, incluidas las contraseñas, en texto claro, así que SSH debe ser el único método de acceso remoto. Habilitar SSH requiere un hostname distinto al predeterminado, un nombre de dominio y un par de claves RSA, además de autenticación de usuarios:

hostname R1
ip domain name example.com
crypto key generate rsa modulus 2048
ip ssh version 2
username admin privilege 15 algorithm-type scrypt secret <password>
!
line vty 0 15
 login local
 transport input ssh
 exec-timeout 10 0
 access-class 10 in

transport input ssh bloquea Telnet en las líneas VTY. ip ssh version 2 deshabilita el SSHv1, más débil. exec-timeout cierra las sesiones inactivas. access-class 10 in aplica una ACL estándar que limita qué direcciones de origen pueden conectarse a las líneas VTY, típicamente solo la red de gestión. Considera también login block-for para frenar los intentos de adivinar contraseñas (bloqueando temporalmente los inicios de sesión después de fallas repetidas), security passwords min-length y deshabilitar los servicios sin uso, como el servidor HTTP si no se necesita.

Los niveles de privilegio van de 0 a 15. El nivel 1 es EXEC de usuario y el 15 es acceso privilegiado completo; a los niveles intermedios se les pueden asignar comandos específicos, aunque el acceso basado en roles mediante AAA suele ser más limpio. Para la consola, aplica también login local y un exec-timeout, ya que el acceso físico también es un riesgo. Verifica con show ip ssh, show ssh y show users. Las cuentas locales siguen siendo importantes incluso con AAA central, como respaldo cuando los servidores son inalcanzables.

Términos clave

VTY lines (líneas VTY)
Líneas de terminal virtual que se usan para las sesiones de gestión remota por Telnet o SSH.
login local
Comando de línea que autentica a los usuarios contra la base de datos local de nombres de usuario del dispositivo.
enable secret
La contraseña con hash que protege el modo EXEC privilegiado.
transport input ssh
Comando de línea que permite solo SSH para las sesiones remotas entrantes.
access-class
Aplica una ACL a las líneas VTY para restringir qué direcciones de origen pueden conectarse.
Ejemplo real

Una revisión de seguridad descubre switches alcanzables por Telnet desde la VLAN de usuarios con una contraseña de línea compartida. El equipo crea cuentas locales individuales con secrets scrypt, genera claves RSA de 2048 bits, configura transport input ssh, aplica access-class permitiendo solo la subred de gestión y agrega exec-timeout 10 0 a cada línea VTY y de consola.

Consejo para el examen: SSH necesita un hostname, un nombre de dominio y claves RSA. Usa access-class (no ip access-group) para filtrar el acceso VTY. Las contraseñas tipo 7 son reversibles; prefiere secret con hash tipo 8 o 9.

Comprueba lo que sabes

¿Qué cuatro cosas deben estar listas antes de que SSH funcione en IOS?

Un hostname no predeterminado, un nombre de dominio IP, un par de claves RSA y un método de autenticación de usuarios, como un nombre de usuario local con login local.

¿Qué comando limita el acceso VTY a la subred de gestión?

access-class con una ACL estándar aplicada en entrada bajo line vty.
