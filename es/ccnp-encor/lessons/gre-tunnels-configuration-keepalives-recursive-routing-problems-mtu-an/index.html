Túneles GRE: configuración, keepalives, problemas de enrutamiento recursivo, MTU y MSS

Generic Routing Encapsulation (GRE) es un protocolo de tunelización sencillo que envuelve un paquete dentro de otro. El paquete original, que puede ser IPv4, IPv6 o incluso tráfico multicast y de protocolos de enrutamiento, se convierte en la carga útil de un nuevo paquete IP con un encabezado GRE, usando el número de protocolo IP 47. GRE te permite construir un enlace virtual punto a punto a través de una red que no conoce tus direcciones, como internet, y ejecutar protocolos de enrutamiento sobre él. GRE no proporciona cifrado ni autenticación propios, por lo que a menudo se combina con IPsec.

Un túnel GRE básico necesita una interfaz de túnel en cada router con tres cosas: una dirección IP para el propio túnel (el overlay), un origen del túnel (tunnel source, una interfaz o dirección local en el underlay) y un destino del túnel (tunnel destination, la dirección del underlay del router remoto).

interface Tunnel0
 ip address 172.16.0.1 255.255.255.252
 tunnel source GigabitEthernet0/0
 tunnel destination 203.0.113.2
 ip mtu 1400
 ip tcp adjust-mss 1360

El modo de túnel predeterminado es tunnel mode gre ip. Una interfaz de túnel se levanta en cuanto el router tiene una ruta hacia el destino del túnel, aunque el extremo remoto esté caído o mal configurado. Los keepalives de GRE corrigen esto: keepalive 10 3 envía un keepalive cada 10 segundos y baja el protocolo de línea después de 3 respuestas perdidas. Ejecutar un protocolo de enrutamiento sobre el túnel también detecta la falla mediante sus propios hellos.

El enrutamiento recursivo es el problema clásico de GRE. El router debe alcanzar el destino del túnel a través del underlay. Si un protocolo de enrutamiento que se ejecuta sobre el túnel llega a aprender una mejor ruta hacia el destino del túnel a través del propio túnel, el router tendría que enviar los paquetes del túnel a través del túnel, lo cual es imposible. IOS lo detecta, registra un mensaje que dice que el túnel está deshabilitado temporalmente debido a enrutamiento recursivo, y el túnel oscila. Evítalo no anunciando nunca el underlay (las redes de origen y destino del túnel) en el protocolo de enrutamiento que se ejecuta sobre el túnel, por ejemplo usando protocolos o procesos separados, filtrando con distribute lists o usando rutas estáticas para el underlay.

GRE agrega sobrecarga: 20 bytes por el nuevo encabezado IP más 4 bytes del encabezado GRE, es decir, 24 bytes en total. En una ruta Ethernet estándar de 1500 bytes, un paquete original de tamaño completo ya no cabe y debe fragmentarse o descartarse. Configurar ip mtu en el túnel (comúnmente 1400 para dejar espacio para IPsec más adelante) hace que el router fragmente antes de encapsular o que avise a los emisores mediante ICMP. Como muchas redes bloquean ICMP, Path MTU Discovery puede fallar, así que también configuras ip tcp adjust-mss, que reescribe el tamaño máximo de segmento en los paquetes TCP SYN. El MSS es la MTU menos 40 bytes de encabezados IPv4 y TCP, así que una MTU de 1400 se combina con un MSS de 1360.

Verifica con show interfaces tunnel 0, show ip interface brief y haciendo ping a través del túnel con paquetes grandes y el bit don't-fragment, por ejemplo ping 172.16.0.2 size 1400 df-bit.

Términos clave

GRE
Generic Routing Encapsulation: un protocolo de tunelización (protocolo IP 47) que transporta un paquete dentro de otro sin cifrado.
Tunnel source y destination (origen y destino del túnel)
Las direcciones del underlay que usan los paquetes GRE entre los dos extremos del túnel.
Recursive routing (enrutamiento recursivo)
Una falla en la que la ruta hacia el destino del túnel apunta a través del propio túnel, lo que hace que el túnel se caiga.
MSS
Maximum segment size (tamaño máximo de segmento): la mayor carga útil TCP que aceptará un host, normalmente la MTU menos 40 bytes.
GRE keepalive
Sondas periódicas que bajan el protocolo de línea del túnel cuando el extremo remoto deja de responder.
Ejemplo real

Dos sucursales construyen un túnel GRE sobre internet y ejecutan EIGRP a través de él. Alguien agrega network 0.0.0.0 bajo EIGRP, lo que anuncia las interfaces públicas en EIGRP. Cada router aprende la dirección pública del otro a través del túnel, el log reporta enrutamiento recursivo y el túnel oscila hasta que la sentencia network se restringe a las subredes del túnel y de la LAN.

Consejo para el examen: Un túnel GRE está up/up siempre que el destino sea enrutable, aunque el extremo remoto esté muerto, a menos que se habiliten los keepalives. GRE agrega 24 bytes; configura ip mtu e ip tcp adjust-mss (MTU menos 40).

Comprueba lo que sabes

¿Qué causa el mensaje del log que indica que un túnel se deshabilitó temporalmente debido a enrutamiento recursivo?

La mejor ruta hacia el destino del túnel se aprendió a través del propio túnel, normalmente porque las direcciones del underlay se anunciaron en el protocolo de enrutamiento que se ejecuta sobre el túnel.

Si la ip mtu del túnel es 1400, ¿a qué valor debe configurarse ip tcp adjust-mss?

1360, que es 1400 menos 20 bytes de encabezado IP y 20 bytes de encabezado TCP.
