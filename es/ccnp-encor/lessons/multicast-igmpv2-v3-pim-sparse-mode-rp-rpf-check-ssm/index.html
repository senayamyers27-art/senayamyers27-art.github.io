Multicast: IGMPv2/v3, PIM sparse mode, RP, verificación RPF, SSM

Multicast envía un solo flujo a muchos receptores sin que la fuente envíe una copia separada a cada uno. Los receptores se unen a un grupo, identificado por una dirección clase D en 224.0.0.0/4, y la red replica los paquetes solo donde divergen las rutas hacia los receptores interesados. Los usos comunes son la distribución de video, los datos del mercado financiero y la instalación de imágenes de software. Multicast tiene dos mitades: los hosts que le dicen a su router local que quieren un grupo, y los routers que construyen árboles de distribución entre las fuentes y los receptores.

IGMP (Internet Group Management Protocol) se ejecuta entre los hosts y su router de primer salto. En IGMPv2, un host envía un membership report para unirse a un grupo, el router envía periódicamente consultas generales (general queries) para verificar si hay miembros, y un host envía un mensaje leave cuando termina, para que el router pueda dejar de reenviar rápidamente después de una consulta específica del grupo. Las uniones de IGMPv2 son (*,G): “cualquier fuente para el grupo G”. IGMPv3 agrega filtrado por fuente: un host puede pedir tráfico de una fuente específica hacia un grupo, (S,G), o excluir fuentes. IGMPv3 es obligatorio para Source-Specific Multicast. En los switches, IGMP snooping escucha estos mensajes para que el switch reenvíe multicast solo a los puertos con receptores interesados en lugar de inundar la VLAN.

Entre routers, PIM (Protocol Independent Multicast) construye los árboles. Es independiente porque usa la tabla de enrutamiento unicast que exista en lugar de su propio protocolo de topología. PIM sparse mode (PIM-SM) asume que los receptores son escasos y usa uniones explícitas: no se reenvía nada hasta que alguien lo pide. Depende de un rendezvous point (RP), un router donde se encuentran las fuentes y los receptores. Cuando un receptor se une, su router (el router de último salto) envía una unión PIM (*,G) salto a salto hacia el RP, construyendo un árbol compartido (RPT). Cuando una fuente empieza a enviar, su router de primer salto registra el tráfico con el RP encapsulándolo en mensajes PIM register unicast; el RP luego se une a un árbol hacia la fuente. Una vez que el tráfico fluye, el router de último salto normalmente cambia al árbol de ruta más corta (SPT), enviando una unión (S,G) directamente hacia la fuente para obtener una ruta más eficiente. El RP puede configurarse de forma estática con ip pim rp-address, o aprenderse dinámicamente con Auto-RP (Cisco) o BSR (bootstrap router, estándar). PIM dense mode, el enfoque antiguo de inundar y podar (flood-and-prune), rara vez se usa.

La verificación RPF (reverse path forwarding) evita los bucles. Cuando llega un paquete multicast, el router verifica si entró por la interfaz que el router usaría para alcanzar la fuente (o el RP, para el tráfico del árbol compartido) según la tabla de enrutamiento unicast. Si es así, lo reenvía; si no, descarta el paquete. Las fallas de RPF son una razón común por la que multicast no funciona, normalmente porque el enrutamiento unicast es asimétrico o porque PIM no está habilitado en la interfaz que prefiere el enrutamiento unicast.

SSM (Source-Specific Multicast) lo simplifica todo: los receptores usan IGMPv3 para especificar tanto la fuente como el grupo, y los routers construyen un árbol de ruta más corta (S,G) directamente hacia la fuente. No se necesita un RP, lo que elimina un punto único de falla y el proceso de registro. SSM usa el rango 232.0.0.0/8 por defecto y se habilita con ip pim ssm default.

Habilita el enrutamiento multicast con ip multicast-routing e ip pim sparse-mode en cada interfaz. Revisa con show ip mroute, show ip pim neighbor, show ip igmp groups y show ip rpf <source>.

Términos clave

IGMP
El protocolo que usan los hosts para unirse a grupos multicast y abandonarlos con su router local.
PIM sparse mode
Un protocolo de enrutamiento multicast que reenvía solo después de uniones explícitas, usando un RP para los árboles compartidos.
Rendezvous point (punto de encuentro)
El router donde las fuentes multicast se registran y los receptores se unen al árbol compartido (*,G).
RPF check (verificación RPF)
Reenviar un paquete multicast solo si llegó por la interfaz que se usa para alcanzar su fuente.
SSM
Source-Specific Multicast: los receptores solicitan (S,G) con IGMPv3, los árboles van directamente a la fuente, sin RP; rango 232.0.0.0/8.
Ejemplo real

Un flujo de video llega al RP pero no a un sitio remoto. show ip mroute en el router remoto muestra la interfaz de entrada de (S,G) como Null, y show ip rpf para la fuente apunta a una interfaz donde PIM no está habilitado. Habilitar ip pim sparse-mode en esa interfaz permite que pase la verificación RPF y el flujo llega.

Consejo para el examen: IGMP es de host a router; PIM es de router a router. (*,G) significa árbol compartido a través del RP; (S,G) significa árbol de fuente. SSM necesita IGMPv3 y ningún RP.

Comprueba lo que sabes

¿Por qué SSM no necesita un rendezvous point?

Los receptores especifican la fuente con IGMPv3, así que los routers pueden construir árboles (S,G) directamente hacia ella sin un punto de encuentro.

Un paquete multicast llega por una interfaz que no es la mejor ruta del router de regreso a la fuente. ¿Qué pasa?

Falla la verificación RPF y se descarta.

¿Qué hace IGMP snooping en un switch?

Escucha los mensajes IGMP para reenviar multicast solo a los puertos con receptores interesados en lugar de inundar la VLAN.
