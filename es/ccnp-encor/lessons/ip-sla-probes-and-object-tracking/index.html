Sondas IP SLA y object tracking

IP SLA (IP service level agreement) es una función de Cisco IOS que genera tráfico sintético para medir continuamente el desempeño de la red: alcanzabilidad, tiempo de ida y vuelta, jitter, pérdida de paquetes e incluso respuestas de aplicaciones como DNS o HTTP. Como el router sondea activamente, puedes detectar problemas antes que los usuarios y tomar decisiones de enrutamiento basadas en la salud real de la ruta y no solo en el estado del enlace.

Una operación IP SLA define qué enviar, a dónde y con qué frecuencia. La más común es icmp-echo, que hace ping a un objetivo. udp-jitter envía paquetes UDP y mide el retardo, el jitter y la pérdida en cada dirección, lo cual es ideal para la voz; necesita un IP SLA responder en el dispositivo Cisco remoto (ip sla responder) para agregar marcas de tiempo. Otros tipos incluyen tcp-connect, http, dns y udp-echo.

ip sla 10
 icmp-echo 203.0.113.1 source-interface GigabitEthernet0/0
 frequency 10
 threshold 500
 timeout 1000
ip sla schedule 10 life forever start-time now
!
track 1 ip sla 10 reachability
 delay down 10 up 30
!
ip route 0.0.0.0 0.0.0.0 203.0.113.1 track 1
ip route 0.0.0.0 0.0.0.0 198.51.100.1 10

Esta sonda hace ping al gateway del ISP principal cada 10 segundos. Una operación no hace nada hasta que se programa, lo cual es un error frecuente en los laboratorios. Los resultados aparecen en show ip sla statistics y la configuración en show ip sla configuration.

El object tracking conecta las mediciones con acciones. Un objeto track vigila algo y reporta up o down. Puede seguir la reachability de una operación IP SLA (up si la operación tiene éxito) o su state (up solo si el código de retorno es OK y, para algunas operaciones, dentro del umbral), el protocolo de línea de una interfaz (track 2 interface Gi0/1 line-protocol), o si una ruta está en la tabla de enrutamiento (track 3 ip route 10.0.0.0 255.0.0.0 reachability). Los tracks pueden combinarse con lógica booleana (track 10 list boolean and). El comando delay amortigua las oscilaciones esperando antes de cambiar de estado.

Los clientes del tracking incluyen las rutas estáticas (la ruta se elimina cuando el track está down, lo que permite que una ruta estática flotante con mayor distancia administrativa tome el control, como en el ejemplo anterior), HSRP y VRRP (reducen la prioridad cuando falla un uplink rastreado o un objetivo remoto, para que el otro router se vuelva activo), PBR (set ip next-hop verify-availability con un track) y los applets de EEM que reaccionan a los cambios de track.

La idea clave es que una interfaz puede seguir arriba mientras la ruta más allá de ella está rota. Un módem de banda ancha, por ejemplo, mantiene Ethernet arriba incluso cuando falla el ISP. Rastrear solo la interfaz no detectaría eso; rastrear una sonda IP SLA hacia un objetivo remoto sí lo detecta. Elige un objetivo que realmente represente la ruta, como el siguiente salto del ISP o una dirección remota conocida alcanzable solo a través de ese enlace, y usa como origen de la sonda la interfaz correcta. Revisa el tracking con show track.

Términos clave

IP SLA operation (operación IP SLA)
Una sonda sintética configurada, como icmp-echo o udp-jitter, que mide una ruta.
IP SLA responder
Una función de los dispositivos Cisco que responde y pone marcas de tiempo a sondas como udp-jitter para obtener mediciones precisas.
Track object (objeto track)
Un objeto cuyo estado up o down sigue a una IP SLA, una interfaz o una ruta y que usan otras funciones.
Floating static route (ruta estática flotante)
Una ruta estática de respaldo con mayor distancia administrativa que se usa solo cuando desaparece la principal.
Ejemplo real

El enlace del ISP principal del router de una sucursal sigue físicamente arriba durante una caída del proveedor, así que el tráfico termina en un agujero negro. Después de agregar una IP SLA icmp-echo hacia el gateway del ISP, un objeto track y una ruta predeterminada con tracking, el router elimina la ruta predeterminada principal a los pocos segundos de la caída y la estática flotante a través del respaldo LTE toma el control.

Consejo para el examen: Las operaciones IP SLA deben programarse con ip sla schedule o nunca se ejecutan. Rastrear una interfaz no detecta las fallas más allá del enlace; rastrear una IP SLA sí las detecta.

Comprueba lo que sabes

¿Por qué usar tracking con IP SLA en lugar de tracking de interfaz para un uplink a internet?

La interfaz puede seguir arriba mientras la ruta del proveedor está caída; una sonda IP SLA hacia un objetivo remoto detecta la falla de extremo a extremo.

¿Qué operación IP SLA mide el jitter para la voz y qué necesita en el extremo remoto?

udp-jitter, que necesita un IP SLA responder en el dispositivo Cisco remoto.

¿Cómo proporciona conmutación por falla una ruta estática con tracking?

Cuando el track pasa a down, la ruta con tracking se elimina de la tabla de enrutamiento y se activa una ruta estática flotante con mayor distancia administrativa.
