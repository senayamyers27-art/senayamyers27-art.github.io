NETCONF y RESTCONF para datos de configuración y operacionales

Extraer información de la salida de la CLI (screen-scraping) es frágil: una nueva versión de software cambia una columna y tu script se rompe. La programabilidad basada en modelos reemplaza eso con datos estructurados definidos por modelos YANG. NETCONF y RESTCONF son los dos protocolos que ENCOR espera que conozcas para leer y cambiar esos datos en los dispositivos Cisco IOS XE.

Ambos trabajan con dos tipos de datos. Los datos de configuración son lo que puedes establecer: interfaces, enrutamiento, VLAN. Los datos operacionales son el estado de solo lectura: contadores de interfaz, tablas de vecinos, CPU. Los modelos YANG describen ambos, y ambos protocolos codifican los datos de acuerdo con esos modelos.

NETCONF (Network Configuration Protocol, RFC 6241) se ejecuta sobre SSH en el puerto TCP 830. Codifica los mensajes en XML y usa llamadas a procedimientos remotos (RPC). Una sesión empieza con ambos lados intercambiando mensajes hello que listan sus capacidades (capabilities), incluidos los modelos YANG que admite el dispositivo. Las operaciones principales son get (datos de configuración y operacionales), get-config (configuración de un datastore especificado), edit-config (cambiar la configuración), copy-config, delete-config, lock y unlock (impedir que otros cambien un datastore mientras trabajas), y commit y discard-changes donde se admite un datastore candidate. NETCONF tiene el concepto de datastores: running (la configuración activa), startup y candidate (una copia de trabajo que validas y luego confirmas con commit). Los cambios pueden ser transaccionales: si alguna parte falla, todo el cambio puede rechazarse. En IOS XE, se habilita con netconf-yang, y se requiere un usuario con privilegio 15. La biblioteca ncclient de Python es el cliente habitual.

RESTCONF (RFC 8040) proporciona una interfaz HTTP tipo REST hacia los mismos datos YANG. Se ejecuta sobre HTTPS, codifica los datos en JSON o XML y mapea las operaciones a métodos HTTP: GET para leer, POST para crear, PUT para crear o reemplazar, PATCH para fusionar cambios y DELETE para eliminar. Los recursos se direccionan mediante URL construidas a partir de la ruta del modelo YANG, por ejemplo la ruta /restconf/data/ietf-interfaces:interfaces/interface=GigabitEthernet1 en la dirección HTTPS del dispositivo. Establece los encabezados Accept y Content-Type en application/yang-data+json para JSON. En IOS XE, se habilita con restconf más el servidor HTTPS (ip http secure-server) y la autenticación. RESTCONF es fácil de usar desde cualquier herramienta HTTP, como curl, Postman o requests de Python.

Cómo elegir entre ellos: NETCONF tiene funciones transaccionales más ricas (datastore candidate, bloqueo, confirmed commits, validación) y lo prefieren los sistemas de orquestación que cambian muchos dispositivos de forma confiable. RESTCONF es más sencillo, sin estado y familiar para los desarrolladores web, e ideal para lecturas rápidas y cambios individuales, pero no tiene bloqueo ni datastore candidate. Ambos usan los mismos modelos YANG, así que los datos se ven iguales sin importar qué protocolo uses.

Una tecnología relacionada es la telemetría basada en modelos (model-driven telemetry), en la que el dispositivo transmite datos operacionales modelados en YANG hacia un colector según un calendario o ante cambios, en lugar de ser sondeado.

Términos clave

NETCONF
Un protocolo de gestión de red basado en XML sobre SSH en el puerto 830 que usa operaciones RPC y datastores.
RESTCONF
Una interfaz HTTPS que usa GET, POST, PUT, PATCH y DELETE sobre datos modelados en YANG codificados en JSON o XML.
Datastore
Una copia de la configuración, como running, startup o candidate, sobre la que actúan las operaciones de NETCONF.
Capabilities exchange (intercambio de capacidades)
El intercambio de hello de NETCONF en el que cada lado lista las funciones y los modelos que admite.
edit-config
La operación de NETCONF que cambia la configuración en un datastore.
Ejemplo real

Un ingeniero escribe un script de Python con ncclient que se conecta a 200 switches en el puerto 830, bloquea cada datastore candidate, aplica un nuevo servidor NTP con edit-config, valida y confirma. Para un panel rápido, un segundo script usa solicitudes GET de RESTCONF con JSON para leer los contadores de interfaz del modelo ietf-interfaces.

Consejo para el examen: NETCONF: SSH, puerto 830, XML, operaciones RPC, datastores y bloqueo. RESTCONF: HTTPS, JSON o XML, verbos HTTP, sin datastore candidate ni bloqueo. Ambos se basan en modelos YANG.

Comprueba lo que sabes

¿Qué puerto y transporte usa NETCONF?

El puerto TCP 830 sobre SSH.

¿Qué método HTTP usarías en RESTCONF para fusionar un cambio en la configuración existente sin reemplazarla?

PATCH.

Menciona una capacidad que ofrece NETCONF y que le falta a RESTCONF.

El bloqueo del datastore o un datastore candidate con commit, lo que permite cambios transaccionales.
