Enrutamiento basado en políticas con route maps

El enrutamiento normal solo mira la dirección de destino. El enrutamiento basado en políticas (PBR) te permite anular esa decisión con base en otros criterios, como la dirección de origen, la aplicación o el tamaño del paquete. Podrías enviar el tráfico de invitados por un enlace de internet barato mientras el tráfico corporativo usa MPLS, o enrutar los respaldos de un servidor específico por una ruta dedicada.

PBR se construye con un route map. Un route map es una lista ordenada de sentencias, cada una con un número de secuencia, una acción (permit o deny) y cláusulas match y set opcionales. Las sentencias se evalúan en orden de secuencia; se aplica la primera sentencia cuyas cláusulas match se cumplen todas. En PBR, una sentencia permit que coincide significa “aplica las acciones set”; una sentencia deny que coincide significa “no enrutes este paquete por política; usa el enrutamiento normal basado en el destino”. Los paquetes que no coinciden con ninguna sentencia también se enrutan normalmente, porque el deny implícito al final de un route map, en PBR, simplemente significa reenvío normal en lugar de descarte.

Los criterios de coincidencia normalmente usan una ACL: match ip address 101 coincide con los paquetes permitidos por la ACL 101. También puedes coincidir por longitud del paquete con match length. La cláusula set elige qué hacer. set ip next-hop 192.0.2.1 envía el paquete a ese siguiente salto si está directamente conectado y es alcanzable. set ip default next-hop se usa solo si la tabla de enrutamiento no tiene una ruta explícita hacia el destino (aparte de la ruta predeterminada). set interface envía por una interfaz específica, lo mejor para enlaces punto a punto. También puedes establecer marcas, como set ip precedence o DSCP en algunas plataformas.

access-list 110 permit ip 10.10.50.0 0.0.0.255 any
!
route-map GUEST-OUT permit 10
 match ip address 110
 set ip next-hop 198.51.100.1
!
interface GigabitEthernet0/2
 ip policy route-map GUEST-OUT

La política se aplica en entrada en la interfaz por donde llega el tráfico con ip policy route-map NAME; actúa sobre los paquetes cuando entran, antes de la decisión de enrutamiento. El tráfico generado por el propio router no se ve afectado a menos que uses ip local policy route-map NAME de forma global.

Un riesgo clave es dejar el tráfico en un agujero negro (black-holing): si el siguiente salto configurado falla pero su interfaz sigue arriba, PBR puede seguir enviando tráfico hacia allá. Usa set ip next-hop verify-availability con object tracking (por ejemplo una sonda IP SLA) para que el router vuelva al enrutamiento normal, o a otro siguiente salto, cuando el objeto rastreado se caiga. PBR también se procesa en hardware en la mayoría de los switches Catalyst, usando TCAM, pero las políticas complejas pueden consumir recursos.

Verifica con show route-map (que muestra los contadores de coincidencias), show ip policy y debug ip policy en un laboratorio. Recuerda que las ACL usadas para PBR solo clasifican el tráfico; un deny en la ACL solo significa que ese paquete no coincide con esa sentencia.

Términos clave

Policy-based routing (enrutamiento basado en políticas)
Reenviar paquetes con base en criterios distintos al destino, definidos por un route map.
Route map
Una lista ordenada de sentencias permit o deny con cláusulas match y set.
set ip next-hop
Una acción de PBR que reenvía los paquetes que coinciden hacia un siguiente salto específico directamente conectado.
ip policy route-map
Comando de interfaz que aplica PBR a los paquetes que llegan por esa interfaz.
ip local policy
Aplica PBR al tráfico generado por el propio router.
Ejemplo real

Una sucursal quiere que el Wi-Fi de invitados (10.10.50.0/24) use el enlace de banda ancha mientras todo lo demás sigue a OSPF sobre MPLS. El ingeniero hace coincidir la subred de invitados en la ACL 110, establece el gateway de banda ancha como siguiente salto con verify-availability ligado a un track de IP SLA, y aplica el route map en entrada en la subinterfaz de invitados. Cuando falla la banda ancha, el tráfico de invitados vuelve al enrutamiento normal.

Consejo para el examen: PBR se aplica en entrada en la interfaz de ingreso y se evalúa antes de la tabla de enrutamiento. Un paquete que coincide con una sentencia deny o con ninguna sentencia se enruta normalmente, no se descarta.

Comprueba lo que sabes

¿Qué le pasa a un paquete que no coincide con ninguna sentencia de un route map de PBR?

Se reenvía usando la tabla de enrutamiento normal.

¿Cuál es la diferencia entre set ip next-hop y set ip default next-hop?

set ip next-hop anula la tabla de enrutamiento; set ip default next-hop se usa solo cuando no hay una ruta explícita para el destino.

¿En qué interfaz y en qué dirección se aplica PBR?

En entrada, en la interfaz por donde el tráfico entra al router.
