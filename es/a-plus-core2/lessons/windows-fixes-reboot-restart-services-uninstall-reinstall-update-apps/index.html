CompTIA A+ Core 2 220-1202

Soluciones en Windows: reiniciar, reiniciar servicios, desinstalar/reinstalar/actualizar apps, agregar recursos, verificar requisitos, sfc y DISM, reparar Windows, System Restore, reinstalar la imagen, revertir actualizaciones, reconstruir el perfil de usuario

Una vez que identificaste una causa probable, necesitas elegir una solución. La regla principal es probar la solución menos disruptiva que ataque la causa y pasar a opciones más drásticas solo si hace falta. Un reinicio le cuesta al usuario un minuto; reinstalar la imagen puede costarle un día. Antes de hacer cualquier cosa que pueda causar pérdida de datos, respalda los archivos del usuario y documenta cada paso en el ticket para que el siguiente técnico sepa qué se intentó.

Empieza por lo simple. Un reinicio libera la memoria, reinicia los servicios y completa las actualizaciones pendientes, y resuelve una cantidad sorprendente de problemas. Elige Restart en lugar de Shut down, porque con el inicio rápido (fast startup) habilitado, un apagado guarda la sesión del kernel en lugar de recargarla por completo. Si un servicio se detuvo, reinícialo en la consola Services (services.msc) o en la pestaña Services de Task Manager, revisa su tipo de inicio y sus dependencias, y lee el registro System para saber por qué falló. Si una aplicación se comporta mal, actualízala primero, ya que el fabricante puede haber corregido el error; luego prueba la opción Repair o Reset en Settings > Apps; después desinstálala y reinstálala para reemplazar los archivos y la configuración dañados. Algunos problemas en realidad son de capacidad o de compatibilidad. Si al sistema le falta capacidad, agrega recursos: más RAM para las advertencias de poca memoria, una unidad más grande o más rápida para un disco lleno, o un archivo de paginación más grande. Antes de culpar a Windows, verifica los requisitos: confirma que la versión de la aplicación, del controlador o del sistema operativo cumpla los requisitos indicados por el fabricante en cuanto a CPU, RAM, almacenamiento, edición del sistema operativo y arquitectura de 32 o 64 bits. Una app que necesita más de lo que ofrece el hardware nunca funcionará bien, por muchas veces que la reinstales.

Para los archivos del sistema dañados, usa las herramientas de reparación integradas desde un símbolo del sistema con privilegios elevados. sfc /scannow (System File Checker) analiza los archivos protegidos del sistema y reemplaza los dañados desde el almacén de componentes local. Si sfc informa que no pudo reparar todo, el propio almacén de componentes puede estar dañado, así que ejecuta DISM (Deployment Image Servicing and Management) para repararlo y luego vuelve a ejecutar sfc. Si Windows está muy dañado, repara Windows: usa Startup Repair desde el Entorno de recuperación de Windows (WinRE) para los problemas de arranque, o realiza una instalación de reparación en el mismo lugar (in-place repair install, ejecutar el programa de instalación sobre la instalación existente), que reinstala Windows conservando las apps y los archivos.

sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth
sfc /scannow

Cuando los problemas comenzaron después de un cambio, deshaz el cambio. System Restore regresa los archivos del sistema, los controladores, la configuración del registro y los programas instalados a un punto de restauración sin tocar los documentos personales. Revierte un controlador en Device Manager, y revierte las actualizaciones desinstalando una actualización de calidad reciente desde Settings > Windows Update > Update history > Uninstall updates, o regresando a la versión de características anterior dentro del periodo permitido; pausa las actualizaciones mientras esperas una corrección del fabricante. Para los problemas que afectan a un solo usuario, como una configuración que no se guarda, un perfil temporal o apps que fallan solo para esa persona, reconstruye el perfil de usuario: respalda los datos del usuario, inicia sesión como otro administrador, cambia el nombre o elimina la carpeta del perfil dañado y su entrada en la clave del registro ProfileList, pide al usuario que inicie sesión para crear un perfil nuevo y luego copia los datos de vuelta. Cuando el sistema está muy dañado, infectado al punto de no poder confiar en él, o repararlo tomaría más tiempo que reconstruirlo, reinstala la imagen estándar (reimage) o usa Reset this PC, que puede conservar o eliminar los archivos personales.

Veamos un ejemplo práctico. Después de una actualización mensual, una app de negocio falla al iniciar para todos los usuarios de un modelo de PC. Reliability Monitor muestra que los fallos comenzaron la mañana siguiente a la instalación de la actualización, y otros modelos sin la actualización funcionan bien. Desinstalas esa actualización específica desde Update history, pausas las actualizaciones en esos equipos, confirmas que la app funciona e informas el conflicto al fabricante. No reinstalaste la app ni la imagen, porque la evidencia apuntaba a la actualización.

Errores comunes: reinstalar la imagen primero porque es lo conocido, perdiendo tiempo y datos del usuario; ejecutar DISM sin volver a ejecutar sfc después; olvidar respaldar antes de reconstruir un perfil; usar System Restore esperando que recupere documentos eliminados, algo que no hace; y tratar el problema de un solo usuario como si fuera de todo el sistema.

Las preguntas del examen premian el orden y la correspondencia. “Solo un usuario afectado” apunta a reconstruir el perfil. “El problema comenzó después de una actualización” apunta a revertir la actualización. “sfc no puede reparar los archivos” apunta a DISM. “Deshacer cambios recientes de controladores y programas pero conservar los documentos” apunta a System Restore, y “no se puede eliminar el malware con confianza” apunta a reinstalar la imagen.

Términos clave

sfc /scannow
El comando System File Checker, que analiza y repara los archivos protegidos del sistema de Windows a partir del almacén de componentes.
DISM
Deployment Image Servicing and Management, que se usa con /RestoreHealth para reparar el almacén de componentes del que depende sfc.
System Restore
Una función que regresa los archivos del sistema, los controladores, el registro y los programas a un punto de restauración anterior sin cambiar los archivos personales.
Instalación de reparación en el mismo lugar (in-place repair install)
Ejecutar el programa de instalación de Windows sobre la instalación existente para reemplazar los archivos del sistema conservando las apps y los datos.
Reinstalar la imagen (reimage)
Borrar una computadora y reinstalar una imagen estándar del sistema operativo; es la solución más completa y más disruptiva.
Reconstruir un perfil de usuario
Reemplazar un perfil de usuario de Windows dañado por uno nuevo y copiar de vuelta los datos del usuario.
Revertir (roll back)
Regresar un controlador o una actualización a la versión anterior cuando la nueva causa problemas.
Ejemplo real

El menú Start y la búsqueda de una usuaria dejan de funcionar, pero solo en su cuenta; otro usuario de la misma PC no tiene ningún problema. El técnico respalda sus documentos y su escritorio, cambia el nombre de la carpeta de su perfil, elimina su entrada del registro en ProfileList, le pide que inicie sesión para generar un perfil nuevo y copia sus datos de vuelta. Todo funciona, y el ticket registra el perfil dañado como la causa.

Consejo para el examen: Elige la solución menos invasiva que corresponda a la causa: reiniciar antes de reinstalar, actualizar o reparar la app antes de reparar Windows, sfc luego DISM luego sfc, System Restore antes de reinstalar la imagen. Si solo un usuario tiene el problema, sospecha del perfil.

Comprueba lo que sabes

sfc /scannow informa que algunos archivos no se pudieron reparar. ¿Qué debes ejecutar a continuación?

DISM /Online /Cleanup-Image /RestoreHealth para reparar el almacén de componentes y luego volver a ejecutar sfc /scannow.

¿System Restore recupera un documento que el usuario eliminó ayer?

No. System Restore cambia los archivos del sistema, los controladores, el registro y los programas, no los archivos personales.

Una app falla para un usuario pero funciona para otros en la misma PC. ¿Cuál es la solución más probable?

Reconstruir el perfil de ese usuario, después de respaldar sus datos, porque el problema sigue al perfil.

¿Cuándo es correcto reinstalar la imagen?

Cuando el sistema está muy dañado o infectado al punto de no poder confiar en él, o cuando reconstruirlo es más rápido que seguir diagnosticando, después de respaldar los datos.
