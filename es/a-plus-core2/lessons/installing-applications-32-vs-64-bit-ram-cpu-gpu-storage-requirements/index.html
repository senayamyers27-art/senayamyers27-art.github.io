CompTIA A+ Core 2 220-1202

Instalación de aplicaciones: 32 vs. 64 bits, requisitos de RAM/CPU/GPU/almacenamiento, métodos de distribución (ISO, descarga, imagen) e impacto en el negocio

Instalar software parece sencillo, pero el trabajo de un técnico es asegurarse de que realmente funcionará, sea adecuado para el hardware, tenga licencia y no afecte al negocio. Antes de hacer clic en Install, verificas la compatibilidad y los requisitos, eliges un método de distribución confiable y piensas en quién más se verá afectado por el cambio. El examen presenta una instalación fallida o riesgosa y pregunta qué se debió haber verificado.

Empieza por la arquitectura. Una aplicación de 32 bits (x86) puede direccionar una cantidad limitada de memoria, unos 4 GB, mientras que una aplicación de 64 bits (x64) puede usar mucho más. Un sistema operativo Windows de 64 bits ejecuta tanto apps de 64 bits como la mayoría de las apps de 32 bits, usando una capa de compatibilidad y guardando los programas de 32 bits en la carpeta C:\Program Files (x86), mientras que los programas de 64 bits van en C:\Program Files. Un sistema operativo de 32 bits no puede ejecutar aplicaciones de 64 bits en absoluto, y en un sistema operativo de 64 bits se requieren controladores de 64 bits. Windows 11 solo está disponible en versiones de 64 bits. Los dispositivos basados en ARM usan un conjunto de instrucciones distinto, así que verifica que el software ofrezca una versión para ARM o que sea compatible mediante emulación.

A continuación, compara los requisitos del sistema publicados con el equipo. RAM (memoria de acceso aleatorio): una app que necesita más memoria de la que hay libre usará el archivo de paginación en disco y se volverá lenta. CPU: verifica la velocidad requerida, la cantidad de núcleos y cualquier función del conjunto de instrucciones que se exija. GPU (unidad de procesamiento gráfico): el software con uso intensivo de gráficos, como CAD, edición de video o juegos, puede necesitar una tarjeta gráfica dedicada, una cantidad mínima de memoria de video (VRAM) o compatibilidad con una API gráfica en particular. Almacenamiento: verifica el espacio libre para la instalación y sus datos, y si la app espera un SSD para tener un rendimiento aceptable. Revisa también las versiones de sistema operativo compatibles, los frameworks o entornos de ejecución necesarios, los tokens de hardware o periféricos externos, y si el usuario necesita derechos de administrador para instalar.

El software puede distribuirse de varias maneras. Las descargas desde el sitio web del fabricante o desde una tienda de apps son comunes para instalaciones individuales; usa siempre fuentes confiables y verifica el hash del archivo cuando el fabricante lo publique. Un archivo ISO es una imagen de disco que montas (con doble clic en Windows) o grabas, y se usa a menudo para suites grandes y medios de sistemas operativos. En las organizaciones, las aplicaciones con frecuencia se integran en una imagen estándar del sistema operativo o se distribuyen con herramientas de administración, de modo que cientos de equipos reciben la misma versión probada sin que los técnicos visiten cada escritorio. Los medios físicos, como las unidades USB, todavía se usan en algunos entornos, sobre todo donde las redes están aisladas.

Por último, considera el impacto en el negocio, que el examen divide en dispositivo, red, operación y negocio. En el dispositivo, una instalación nueva puede afectar el rendimiento o la estabilidad, entrar en conflicto con el software existente o cambiar las asociaciones de archivos. En la red, las descargas o actualizaciones grandes pueden consumir ancho de banda, y el software nuevo puede abrir puertos. En la operación, una instalación puede requerir un reinicio en horario laboral o causar tiempo de inactividad de un sistema crítico para el negocio. En el negocio, cada usuario necesita una licencia válida, hay que organizar el soporte y el software no aprobado puede romper el cumplimiento normativo. Por eso las organizaciones prueban el software primero, programan los despliegues, siguen la gestión de cambios y documentan qué versión está instalada en cada lugar.

Veamos un ejemplo práctico. Una firma de ingeniería quiere desplegar un nuevo paquete de modelado 3D en veinte estaciones de trabajo. Revisas los requisitos y descubres que necesita un sistema operativo de 64 bits, una GPU dedicada con una cantidad mínima de VRAM establecida y más RAM de la que tienen cinco de los equipos más antiguos. Esos cinco reciben primero mejoras o reemplazos. El fabricante entrega un ISO, así que pruebas la instalación en un equipo, la empaquetas para la herramienta de administración, programas la distribución fuera del horario laboral para no saturar la conexión de la oficina y confirmas que hay veinte licencias antes de que alguien la abra.

Errores comunes: suponer que un instalador de 64 bits funcionará en un sistema operativo de 32 bits; verificar solo la velocidad de la CPU e ignorar los requisitos de GPU o VRAM; descargar instaladores de sitios espejo no oficiales; instalar en horario laboral sin avisar cuando se requiere un reinicio; y olvidar las licencias, que son un impacto en el negocio aunque el software funcione perfectamente. Otra trampa es pensar que una app necesita un sistema operativo de 64 bits solo porque la computadora tiene un procesador de 64 bits; lo que importa es el sistema operativo instalado.

Las preguntas del examen dan pistas. 'El instalador no se ejecuta en una PC antigua' sugiere un sistema operativo de 32 bits con una app de 64 bits. 'La app es extremadamente lenta y el disco está ocupado constantemente' sugiere RAM insuficiente. 'El software de edición de video muestra errores o no inicia' apunta a los requisitos de GPU o VRAM. 'Desplegar la misma versión en cientos de equipos' apunta a una imagen o a una herramienta de administración. 'Verificar que la descarga no haya sido alterada' significa comparar su hash. 'Considerar licencias, tiempo de inactividad y ancho de banda' es impacto en el negocio.

Términos clave

32 bits (x86)
Una arquitectura cuyas aplicaciones pueden direccionar unos 4 GB de memoria; se ejecutan en sistemas de 32 bits y en la mayoría de los de 64 bits.
64 bits (x64)
Una arquitectura que puede direccionar mucha más memoria y requiere un sistema operativo de 64 bits.
Requisitos del sistema (system requirements)
El sistema operativo, CPU, RAM, GPU y almacenamiento mínimos y recomendados por el fabricante para ejecutar un software.
VRAM
Memoria de video de una tarjeta gráfica, que las aplicaciones con uso intensivo de gráficos exigen en cantidades mínimas.
Archivo ISO
Una imagen de disco que se usa para distribuir suites de software grandes o sistemas operativos.
Verificación de hash
Comparar el hash de un archivo descargado con el valor publicado por el fabricante para confirmar que no fue alterado.
Impacto en el negocio (business impact)
El efecto de una instalación en los dispositivos, la red, las operaciones y las licencias o el cumplimiento normativo.
Ejemplo real

Un voluntario de una organización benéfica descarga un programa de gestión de donantes en una PC antigua de la oficina, y el instalador falla de inmediato. El técnico revisa System Information y encuentra una edición de Windows de 32 bits, mientras que el programa solo existe en 64 bits. Como el hardware admite 64 bits, planifica una instalación limpia de un sistema operativo de 64 bits después de respaldar los datos, y luego instala el programa con éxito.

Consejo para el examen: Un sistema operativo de 64 bits ejecuta apps de 32 bits, pero uno de 32 bits no puede ejecutar apps de 64 bits. Si un instalador se niega a ejecutarse en un equipo antiguo, verifica si el sistema operativo es de 32 bits antes de culpar al software.

Comprueba lo que sabes

¿Dónde instala Windows de 64 bits los programas de 32 bits?

En C:\Program Files (x86), mientras que los programas de 64 bits van en C:\Program Files.

Un programa de gráficos inicia pero funciona muy mal en una laptop con gráficos integrados. ¿Qué requisito probablemente se pasó por alto?

El requisito de GPU o VRAM, que puede exigir una tarjeta gráfica dedicada.

¿Por qué debes verificar el hash de un instalador descargado?

Para confirmar que el archivo coincide con lo que publicó el fabricante y que no se dañó ni fue alterado.

Menciona dos impactos en el negocio que debes considerar antes de un despliegue grande.

Por ejemplo, las licencias para cada usuario, los reinicios o el tiempo de inactividad, el uso de ancho de banda de la red y la compatibilidad con el software existente.
