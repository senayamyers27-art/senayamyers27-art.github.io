CompTIA A+ Core 2 220-1202

Fundamentos de scripting: .bat, .ps1, .vbs, .sh, .js, .py; casos de uso (automatización, reinicios, asignación de unidades, instalaciones, respaldos, actualizaciones) y riesgos

Un script es un archivo de texto plano con comandos que un intérprete ejecuta en orden. A diferencia de un programa compilado, puedes abrir un script en un editor de texto, leerlo y modificarlo. Los scripts permiten a los técnicos automatizar tareas repetitivas, aplicar la misma configuración a muchos equipos y evitar errores manuales. El examen A+ no espera que escribas código complejo, pero sí que reconozcas los tipos de script comunes por su extensión, sepas para qué se usan, reconozcas los elementos básicos y comprendas los riesgos.

Conoce los tipos de script. .bat es un archivo por lotes (batch) de Windows que ejecuta el intérprete de Command Prompt (cmd.exe); usa comandos clásicos como net use, copy y robocopy. .ps1 es un script de PowerShell, el lenguaje de scripting moderno y mucho más potente de Windows, capaz de administrar casi todas las partes de Windows y muchos servicios en la nube; la política de ejecución (execution policy) de PowerShell controla si se pueden ejecutar scripts. .vbs es VBScript, un lenguaje de scripting más antiguo de Windows que ejecuta Windows Script Host; Microsoft lo declaró obsoleto, pero todavía aparece en scripts de inicio de sesión heredados y en malware. .sh es un script de shell para Linux y macOS, que ejecuta bash u otro shell, y normalmente empieza con una línea que indica su intérprete. .js es JavaScript, que se usa en los navegadores web y en servidores mediante Node.js, y que en Windows también puede ejecutar Windows Script Host. .py es Python, un lenguaje multiplataforma de propósito general popular para tareas de automatización y de datos.

Reconoce los elementos básicos. Las variables son espacios de almacenamiento con nombre para valores, como un nombre de usuario o una ruta de archivo. Los comentarios son notas que el intérprete ignora: REM o :: en los archivos por lotes, # en PowerShell, bash y Python, un apóstrofo en VBScript y // en JavaScript. Los bucles (loops) repiten acciones, por ejemplo una vez por cada computadora de una lista, y las instrucciones condicionales (if) ejecutan código solo cuando algo es verdadero, por ejemplo solo si existe una carpeta. Los tipos de datos incluyen cadenas (texto), enteros (números enteros) y valores booleanos (verdadero o falso). Los casos de uso comunes incluyen la automatización básica de tareas repetitivas; reiniciar equipos o servicios de forma programada; volver a asignar unidades de red al iniciar sesión; instalar aplicaciones de forma silenciosa en muchas computadoras; iniciar actualizaciones; ejecutar respaldos y copiar archivos con herramientas como robocopy o rsync; recopilar información, como el software instalado o el espacio en disco; y la administración remota de muchos dispositivos a la vez. Los scripts a menudo se implementan mediante Group Policy, una herramienta RMM (monitoreo y administración remotos, remote monitoring and management) o una tarea programada.

REM map-drives.bat: map shared drives at logon
net use S: \\fileserver\sales /persistent:yes
net use H: \\fileserver\home\%USERNAME%

Los scripts conllevan riesgos reales. Un script se ejecuta con los permisos de quien lo ejecuta, así que un error en un script ejecutado como administrador puede eliminar datos o configurar mal cientos de equipos a la vez. Prueba los scripts en un sandbox o en un solo equipo de prueba antes de implementarlos ampliamente. Los scripts descargados de internet pueden contener malware, y los atacantes suelen usar archivos de PowerShell, VBScript y JavaScript como adjuntos de correo o para ataques sin archivos (fileless), así que revisa los scripts antes de ejecutarlos, mantén las políticas de ejecución y los controles de aplicaciones, y firma digitalmente los scripts de confianza. La lista de riesgos del examen incluye introducir malware sin querer, cambiar configuraciones del sistema inadvertidamente y provocar fallos del navegador o del sistema por un mal manejo de los recursos, como un bucle que nunca termina y consume toda la memoria. Nunca escribas contraseñas directamente en los scripts; usa un almacén de credenciales seguro.

Veamos un ejemplo práctico. Cada empleado nuevo necesita que se le asignen las mismas cinco unidades de red. En lugar de asignarlas a mano en cada escritorio, escribes un breve script por lotes de inicio de sesión con comandos net use, agregas comentarios que explican cada línea y lo pruebas en un equipo de laboratorio con una cuenta de usuario estándar. Descubres que una ruta está mal, la corriges y luego asignas el script mediante Group Policy. Ahora todos los usuarios obtienen las mismas unidades automáticamente al iniciar sesión, y el script queda documentado en la base de conocimientos.

Errores comunes: ejecutar un script sin probar como administrador en todas las computadoras; descargar un script de un foro y ejecutarlo sin leerlo; guardar contraseñas en texto plano dentro de un script; y confundir los tipos de archivo, como pensar que .sh se ejecuta de forma nativa en Command Prompt de Windows.

Las preguntas del examen siguen patrones reconocibles. Relaciona las extensiones con las plataformas: .bat, .ps1 y .vbs son de Windows; .sh es de Linux y macOS; .py y .js son multiplataforma. “Asignar unidades al iniciar sesión” apunta a un script de inicio de sesión, “cambios inesperados en el sistema después de ejecutar un script” apunta a pruebas insuficientes, y “script recibido como adjunto de correo” apunta al riesgo de malware.

Términos clave

Script
Un archivo de texto plano con comandos que un intérprete ejecuta en orden.
Archivo por lotes (.bat)
Un script de Windows que ejecuta el intérprete de Command Prompt.
PowerShell (.ps1)
El potente lenguaje de scripting y shell de Microsoft para administrar Windows y otros sistemas.
Script de shell (.sh)
Un script para Linux o macOS que ejecuta bash u otro shell.
Variable
Un espacio de almacenamiento con nombre que guarda un valor que un script puede usar y cambiar.
Bucle (loop)
Una estructura que repite un conjunto de comandos, por ejemplo para cada elemento de una lista.
Política de ejecución (execution policy)
Una configuración de PowerShell que controla si se permite ejecutar scripts y cuáles.
Ejemplo real

Un técnico escribe un script de PowerShell para eliminar los archivos temporales de todas las PC del laboratorio y solo lo prueba en su propia laptop. En las PC del laboratorio, una variable queda vacía por una estructura de carpetas diferente, y el script empieza a eliminar el directorio equivocado hasta que alguien lo nota. Después de restaurar desde el respaldo, el equipo adopta la regla de que los scripts se revisan, se prueban en un equipo de muestra del laboratorio y se firman antes de implementarlos.

Consejo para el examen: Relaciona las extensiones con las plataformas: .bat, .ps1 y .vbs son de Windows; .sh es de Linux y macOS; .py y .js son multiplataforma. Los principales riesgos son introducir malware, cambiar configuraciones del sistema sin querer y provocar fallos por un mal manejo de los recursos, así que prueba antes de implementar.

Comprueba lo que sabes

¿Qué extensión de script esperarías para automatizar tareas en un servidor Linux?

.sh, un script de shell que ejecuta bash u otro shell.

Menciona tres usos comunes de los scripts en el soporte de TI.

Por ejemplo, asignar unidades de red, instalar aplicaciones, reiniciar servicios o equipos, ejecutar respaldos e iniciar actualizaciones.

¿Por qué se deben probar los scripts antes de implementarlos ampliamente?

Se ejecutan con los permisos del usuario y pueden cambiar configuraciones, eliminar datos o consumir recursos en muchos equipos a la vez.

¿Cómo escribes un comentario en un script de PowerShell o de Python?

Empieza la línea con el carácter #; el intérprete la ignora.
