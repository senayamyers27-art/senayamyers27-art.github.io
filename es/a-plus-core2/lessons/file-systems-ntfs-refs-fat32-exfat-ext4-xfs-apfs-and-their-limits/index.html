CompTIA A+ Core 2 220-1202

Sistemas de archivos: NTFS, ReFS, FAT32, exFAT, ext4, XFS, APFS y sus límites

Un sistema de archivos es el conjunto de reglas que usa un sistema operativo para organizar los datos en un dispositivo de almacenamiento: cómo se nombran los archivos, dónde se ubican sus partes en el disco, qué metadatos (fechas, propietarios, permisos) se guardan y cómo se lleva el control del espacio libre. Cuando formateas una unidad eliges un sistema de archivos, y esa elección determina qué sistemas operativos pueden leerla y escribir en ella, qué tan grandes pueden ser los archivos individuales y qué funciones de seguridad, como permisos y cifrado, están disponibles. Elegir el incorrecto está detrás de muchos tickets del tipo 'por qué no puedo copiar este archivo'.

NTFS (New Technology File System) es el estándar para las unidades de sistema de Windows. Admite permisos de archivos y carpetas, cifrado con EFS (Encrypting File System), compresión, cuotas de disco y registro en diario (journaling), que anota los cambios pendientes para que el volumen pueda recuperarse limpiamente después de una falla o un corte de energía. Sus límites de tamaño de archivo y de volumen son tan grandes que nunca importan en el trabajo normal. macOS puede leer NTFS pero no puede escribir en él de forma predeterminada, y la compatibilidad en Linux varía según la distribución, así que NTFS es una mala elección para una unidad que deba compartirse con una Mac.

ReFS (Resilient File System) es un sistema de archivos más reciente de Microsoft, diseñado para la integridad de los datos y para volúmenes muy grandes. Usa sumas de verificación (checksums) para detectar la corrupción y puede reparar automáticamente los datos dañados cuando se combina con el espejado de Storage Spaces. Está pensado para servidores, grupos de almacenamiento y almacenamiento de máquinas virtuales, y le faltan algunas funciones de NTFS, así que normalmente no instalas Windows sobre él. Piensa en ReFS como la opción para almacenamiento de datos resiliente, no para una unidad de arranque.

FAT32 (File Allocation Table, 32 bits) es antiguo, sencillo y legible por casi todo: Windows, macOS, Linux, cámaras, consolas de videojuegos y estéreos de auto. Su límite más conocido es un tamaño máximo de archivo de 4 GB (menos un byte), y las herramientas gráficas de formateo integradas en Windows tradicionalmente han ofrecido FAT32 solo para volúmenes de hasta 32 GB. No tiene permisos ni registro en diario. exFAT (Extended FAT) se creó para medios flash: elimina el límite de 4 GB por archivo, admite volúmenes muy grandes y las versiones modernas de Windows y macOS pueden leerlo y escribir en él, lo que lo convierte en la opción habitual para unidades USB grandes y tarjetas SD compartidas entre esos sistemas. Al igual que FAT32, no tiene permisos ni registro en diario.

Los demás sistemas operativos tienen sus propios valores predeterminados. En Linux, ext4 (cuarto sistema de archivos extendido) es el predeterminado habitual; tiene registro en diario y admite permisos de Linux y archivos grandes. XFS es un sistema de archivos con registro en diario de alto rendimiento, predeterminado en Red Hat Enterprise Linux y sus derivados, y es muy adecuado para archivos grandes y cargas de trabajo en paralelo. Windows no puede leer ninguno de los dos de forma nativa. APFS (Apple File System) es el predeterminado de macOS, iOS e iPadOS. Está optimizado para SSD y admite instantáneas (snapshots), espacio compartido entre volúmenes de un mismo contenedor y un cifrado integrado robusto. Las Mac más antiguas usaban HFS+ (Mac OS Extended). Windows no puede leer APFS sin herramientas de terceros.

Veamos un ejemplo práctico. Un editor de video intenta copiar un archivo de proyecto de 12 GB desde una PC con Windows a una unidad USB nueva de 128 GB y recibe el mensaje 'The file is too large for the destination file system', aunque la unidad está vacía. Revisas las propiedades de la unidad y ves FAT32. Como el editor también usa una Mac en casa, NTFS sería incómodo, ya que la Mac podría leerlo pero no escribir en él. Respaldas lo que haya en la unidad, la vuelves a formatear como exFAT y la copia funciona en ambas computadoras. Formatear borra la unidad, así que siempre copia los datos antes.

Errores comunes: pensar que 'archivo demasiado grande' significa que la unidad está llena (normalmente significa el límite por archivo de FAT32); elegir NTFS para una unidad en la que una Mac debe escribir; suponer que exFAT tiene permisos o registro en diario como NTFS; y esperar que Windows abra una unidad ext4 o APFS sin software adicional. Recuerda también que la cifra de 32 GB es un límite de las herramientas de formateo de Windows para FAT32, mientras que la cifra de 4 GB es un límite del propio sistema de archivos.

Las preguntas del examen emparejan el sistema de archivos con la tarea, así que aprende las parejas. Unidad de arranque de Windows o necesidad de permisos y EFS: NTFS. Unidad flash para archivos grandes compartida entre Windows y Mac: exFAT. Máxima compatibilidad con dispositivos antiguos y archivos pequeños: FAT32. Servidor Linux: ext4 o XFS. Mac o iPhone: APFS. Grupo de almacenamiento resiliente de Windows con verificación automática de integridad: ReFS. Palabras clave como 'journaling', 'permisos', 'checksums', 'snapshots' y '4 GB' apuntan directamente a la respuesta.

Términos clave

Sistema de archivos (file system)
La estructura que usa un sistema operativo para nombrar, almacenar, ubicar y proteger archivos en un volumen.
NTFS
El sistema de archivos predeterminado de Windows, con permisos, cifrado EFS, compresión, cuotas y registro en diario.
ReFS
El Resilient File System de Microsoft, que usa sumas de verificación y autorreparación para almacenamiento grande enfocado en la integridad.
FAT32
Un sistema de archivos heredado y muy compatible, con un tamaño máximo de archivo de 4 GB y sin permisos.
exFAT
Un sistema de archivos orientado a memorias flash, sin el límite de 4 GB por archivo de FAT32, que Windows y macOS pueden leer y escribir.
ext4 y XFS
Sistemas de archivos de Linux con registro en diario; ext4 es un predeterminado común y XFS es el predeterminado de Red Hat para alto rendimiento.
APFS
Apple File System, el predeterminado optimizado para SSD de macOS, iOS e iPadOS, con instantáneas y cifrado.
Registro en diario (journaling)
Anotar los cambios pendientes en un registro para que un sistema de archivos pueda recuperarse de forma consistente después de una falla.
Ejemplo real

La tarjeta de la cámara de una fotógrafa, formateada en FAT32, deja de grabar clips largos de video 4K siempre en el mismo punto. La cámara divide o detiene los archivos al llegar a 4 GB. Cambiar a una tarjeta formateada en exFAT, que la cámara admite, le permite grabar clips largos en un solo archivo que tanto su laptop con Windows como su Mac pueden abrir.

Consejo para el examen: 'Archivo demasiado grande' en una unidad con mucho espacio libre casi siempre significa FAT32 y su límite de 4 GB por archivo. Vuelve a formatear como exFAT para compartir entre Windows y Mac, o como NTFS si solo se usará con Windows.

Comprueba lo que sabes

¿Qué sistema de archivos debes elegir para una unidad USB que debe transportar archivos de 10 GB entre Windows y macOS?

exFAT, porque elimina el límite de 4 GB por archivo de FAT32 y ambos sistemas operativos pueden leerlo y escribir en él.

¿Qué sistema de archivos de Windows admite cifrado EFS y permisos NTFS en una unidad de arranque?

NTFS, el sistema de archivos estándar para la unidad de sistema de Windows.

¿Cuál es el sistema de archivos predeterminado en las Mac y los iPhone actuales?

APFS, el Apple File System, que está optimizado para SSD y admite instantáneas y cifrado.

¿Qué función ayuda a que un sistema de archivos se recupere limpiamente después de un corte de energía repentino?

El registro en diario (journaling), que anota los cambios pendientes para que el volumen pueda volver a un estado consistente.
