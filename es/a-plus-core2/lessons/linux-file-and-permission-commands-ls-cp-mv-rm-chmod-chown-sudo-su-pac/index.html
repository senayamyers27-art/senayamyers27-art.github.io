CompTIA A+ Core 2 220-1202

Linux: comandos de archivos y permisos (ls, cp, mv, rm, chmod, chown, sudo, su), gestores de paquetes (apt, dnf), ip, df, top, ps, grep, find, man, archivos clave (/etc/passwd, /etc/shadow, /etc/hosts, /etc/fstab, /etc/resolv.conf)

Linux se administra principalmente desde un shell como bash. Los comandos distinguen entre mayúsculas y minúsculas, las rutas usan barras normales y no hay letras de unidad: todo cuelga del directorio raíz /, y los demás discos se montan dentro de ese árbol. Si tienes dudas, lee la página del manual con man, como en man chmod, y presiona q para salir. El examen A+ espera que reconozcas los comandos principales, sepas leer una cadena de permisos y sepas qué hace cada archivo de configuración.

Trabajo con archivos: ls lista un directorio (ls -l muestra permisos, propietario, tamaño y fecha; ls -a incluye los archivos ocultos que empiezan con punto). cp copia (cp -r para directorios), mv mueve o cambia el nombre, y rm elimina (rm -r elimina un árbol de directorios). En el shell no hay Papelera de reciclaje, así que rm es permanente. pwd imprime el directorio actual y cd lo cambia. grep busca un patrón en un texto, como en grep error /var/log/syslog, y a menudo se combina con tuberías (pipes): ps aux | grep ssh. find busca en el sistema de archivos por nombre, tamaño o fecha, por ejemplo find /home -name '*.pdf'.

ls -l muestra los permisos como una cadena del tipo -rwxr-x---: el primer carácter es el tipo (- para un archivo, d para un directorio), y luego vienen tres grupos de lectura (r), escritura (w) y ejecución (x) para el propietario (user), el grupo y los demás (others). chmod los cambia, ya sea de forma simbólica (chmod g+w file) o en octal, donde r=4, w=2 y x=1 se suman, así que chmod 750 script.sh le da al propietario rwx (7), al grupo r-x (5) y a los demás nada (0). chown cambia la propiedad, por ejemplo chown alice:staff report.txt. Trabajar a diario como el superusuario root es riesgoso, así que los administradores usan sudo para ejecutar un solo comando con privilegios elevados (pide la contraseña del propio usuario, verifica que el usuario tenga permiso y registra la acción) y su para cambiar a otro usuario, root de forma predeterminada, lo que requiere la contraseña de esa cuenta.

El software se instala con un gestor de paquetes, que descarga desde repositorios confiables, verifica los paquetes y resuelve las dependencias. Debian y Ubuntu usan apt: sudo apt update actualiza la lista de paquetes y luego sudo apt upgrade o sudo apt install nginx. Red Hat, Fedora y distribuciones relacionadas usan dnf (el sucesor de yum): sudo dnf install nginx, sudo dnf upgrade. Información del sistema y de la red: ip addr (o ip a) muestra las interfaces y las direcciones, e ip route muestra la tabla de enrutamiento; reemplaza al antiguo ifconfig. df -h muestra el espacio libre de cada sistema de archivos montado en unidades legibles. top es una vista en vivo y actualizada de los procesos y del uso de CPU y memoria, y ps aux da una lista instantánea de todos los procesos. Por último, conoce estos archivos de configuración. /etc/passwd enumera las cuentas de usuario (nombre, identificador de usuario, directorio personal y shell de inicio de sesión) y cualquiera puede leerlo; a pesar de su nombre, ya no contiene contraseñas. /etc/shadow guarda las contraseñas en forma de hash y los datos de vencimiento de contraseñas, y solo root puede leerlo. /etc/hosts asocia nombres de host con direcciones IP de forma local y normalmente se consulta antes que DNS. /etc/fstab enumera los sistemas de archivos que se montan al arrancar y dónde. /etc/resolv.conf enumera los servidores DNS que usa el sistema.

ls -l /var/www
sudo chmod 644 index.html
sudo chown www-data:www-data index.html
sudo apt update && sudo apt install htop
df -h

Veamos un ejemplo práctico. Una página web en un servidor Ubuntu devuelve 'permission denied'. Ejecutas ls -l y ves que el archivo es -rw------- y pertenece a root, así que la cuenta del servidor web no puede leerlo. Ejecutas sudo chown www-data:www-data index.html y sudo chmod 644 index.html, lo que le da al propietario lectura y escritura y a todos los demás solo lectura. La página se carga.

Errores comunes: usar chmod 777 para 'arreglar' el acceso, lo que permite que cualquiera modifique el archivo; confundir su (cambiar de usuario, necesita la contraseña de la cuenta de destino) con sudo (un comando, tu propia contraseña); esperar apt en un sistema Red Hat; pensar que /etc/passwd contiene los hashes de las contraseñas; y ejecutar rm -r sin revisar la ruta.

Las preguntas del examen evalúan el reconocimiento. 'Mostrar el espacio libre en disco' es df. 'Vista en vivo de los procesos' es top; 'instantánea de los procesos' es ps. 'Buscar texto dentro de archivos' es grep; 'ubicar archivos por nombre' es find. 'Cambiar permisos' es chmod; 'cambiar propietario' es chown. 'Instalar software en Ubuntu' es apt; 'en Fedora o Red Hat' es dnf. '¿Dónde están los hashes de las contraseñas?' es /etc/shadow. '¿Qué servidores DNS?' es /etc/resolv.conf. 'Montar una unidad en cada arranque' es /etc/fstab. Los dígitos octales se decodifican así: 7 rwx, 6 rw-, 5 r-x y 4 r--.

Términos clave

chmod
Cambia los permisos de un archivo usando notación simbólica o números octales como 750.
chown
Cambia el propietario y el grupo de un archivo o directorio.
sudo
Ejecuta un solo comando con privilegios elevados usando la contraseña del propio usuario, con registro de la acción.
su
Cambia a otra cuenta de usuario, root de forma predeterminada, usando la contraseña de esa cuenta.
Gestor de paquetes (package manager)
Una herramienta como apt o dnf que instala y actualiza software desde repositorios y resuelve dependencias.
/etc/shadow
El archivo, legible solo por root, que guarda las contraseñas en forma de hash y la información de vencimiento de contraseñas.
/etc/fstab
El archivo que enumera los sistemas de archivos que se montan automáticamente al arrancar.
/etc/resolv.conf
El archivo que enumera los servidores DNS que usa un sistema Linux.
Ejemplo real

Una estación de trabajo Linux no puede resolver nombres internos, mientras que otros equipos sí. El técnico ejecuta ip addr para confirmar que tiene dirección, hace ping a la puerta de enlace con éxito y luego revisa /etc/resolv.conf, donde descubre que apunta a un servidor DNS dado de baja. Después de corregir la configuración de red para que se use el servidor DNS correcto, la resolución de nombres funciona.

Consejo para el examen: Los permisos en octal aparecen con frecuencia: 7 = rwx, 6 = rw-, 5 = r-x, 4 = r--. Recuerda también que /etc/passwd contiene las cuentas, pero /etc/shadow contiene los hashes de las contraseñas.

Comprueba lo que sabes

¿Qué permisos otorga chmod 640?

Lectura y escritura para el propietario, lectura para el grupo y ningún acceso para los demás.

¿Qué comando instala un paquete en Ubuntu?

sudo apt install seguido del nombre del paquete, normalmente después de sudo apt update.

¿Qué archivo guarda las contraseñas de usuario en forma de hash en Linux?

/etc/shadow, que solo root puede leer.

¿Cuál es la diferencia entre sudo y su?

sudo ejecuta un comando con privilegios elevados usando tu propia contraseña; su cambia a otra cuenta, root de forma predeterminada, usando la contraseña de esa cuenta.
