CompTIA A+ Core 2 220-1202

Acceso remoto: RDP, VPN, VNC, SSH, RMM, SPICE, WinRM, herramientas para compartir pantalla y transferir archivos, y sus consideraciones de seguridad

El acceso remoto permite a los técnicos dar soporte a los usuarios y administrar sistemas sin tener que trasladarse, y permite al personal trabajar desde cualquier lugar. Cada método tiene un propósito y un perfil de seguridad, y los atacantes apuntan con fuerza al acceso remoto, así que ambos aspectos son materia de examen.

RDP (Remote Desktop Protocol) ofrece una sesión de escritorio gráfica completa en un equipo Windows, de forma predeterminada por el puerto TCP 3389. El host debe tener una edición Pro o superior. Nunca expongas RDP directamente a internet; colócalo detrás de una VPN o un gateway, exige Network Level Authentication y MFA, y usa contraseñas robustas con bloqueo de cuentas, porque RDP expuesto es un punto de entrada común del ransomware. VNC (Virtual Network Computing) es un protocolo multiplataforma para compartir pantalla que muestra y controla la sesión de consola real; muchas implementaciones tienen un cifrado débil o inexistente, así que canalízalo por un túnel SSH o una VPN.

SSH (Secure Shell) proporciona una sesión de línea de comandos cifrada, normalmente por el puerto TCP 22, y es el estándar para administrar servidores Linux y dispositivos de red; reemplazó al inseguro Telnet. Usa autenticación basada en claves en lugar de contraseñas cuando sea posible y deshabilita el inicio de sesión directo como root. SSH también es la base de la transferencia segura de archivos con SFTP y SCP. SPICE (Simple Protocol for Independent Computing Environments) es un protocolo de visualización remota que se usa principalmente para acceder a las consolas de máquinas virtuales en algunas plataformas de virtualización. WinRM (Windows Remote Management) permite a los administradores ejecutar comandos y scripts de PowerShell en computadoras Windows remotas sin una sesión gráfica; restríngelo a los administradores y a las redes de administración.

Una VPN (red privada virtual) crea un túnel cifrado desde un dispositivo remoto hasta la red de la organización, para que los usuarios remotos puedan acceder a los recursos internos como si estuvieran en la oficina. La VPN no es en sí una herramienta de control remoto; proporciona la conexión segura sobre la cual funcionan otras herramientas. Las cuentas de VPN necesitan MFA y un desaprovisionamiento oportuno.

Las plataformas RMM (remote monitoring and management, monitoreo y administración remotos) las usan los departamentos de TI y los proveedores de servicios gestionados para monitorear muchos endpoints, desplegar parches y software, ejecutar scripts y tomar el control remoto desde una sola consola. Como un agente RMM tiene control administrativo de cada dispositivo administrado, una cuenta RMM comprometida es extremadamente peligrosa; protégela con MFA y mínimo privilegio. Las herramientas para compartir pantalla y de soporte remoto, incluidas las de uso compartido del escritorio, las videoconferencias y las apps de soporte remoto de terceros, permiten que un usuario invite a un técnico a ver o controlar su pantalla, idealmente con el consentimiento explícito del usuario en cada sesión. Las herramientas de transferencia de archivos, incluidas SFTP, el uso compartido de archivos en la nube y los servicios de transferencia gestionada, deben usar cifrado; evita el FTP sin cifrar.

Consideraciones de seguridad para todos los métodos: usa cifrado, MFA y autenticación robusta; permite solo herramientas aprobadas; restringe por IP o exige una VPN; mantén el software actualizado; registra las sesiones; y enseña a los usuarios que el personal legítimo de TI no los llamará sin aviso exigiendo acceso remoto. Los estafadores suelen convencer a sus víctimas de instalar herramientas de acceso remoto, así que una solicitud inesperada para instalar una es una señal de alerta.

Términos clave

RDP
Remote Desktop Protocol: el protocolo de sesión remota gráfica de Microsoft; puerto TCP predeterminado 3389.
SSH
Secure Shell: acceso remoto cifrado por línea de comandos; puerto TCP predeterminado 22.
VNC
Virtual Network Computing: protocolo multiplataforma para compartir pantalla que a menudo necesita un túnel cifrado.
RMM
Remote monitoring and management (monitoreo y administración remotos): plataformas para monitorear, aplicar parches y controlar muchos endpoints.
WinRM
Windows Remote Management: protocolo para ejecutar comandos de PowerShell en sistemas Windows remotos.
Ejemplo real

Una pequeña empresa permite RDP directamente desde internet a su servidor de oficina y ve miles de intentos fallidos de inicio de sesión en el registro Security. El técnico cierra el puerto en el firewall, configura una VPN con MFA para el personal remoto y permite RDP solo desde las direcciones de la VPN. Los intentos fallidos se detienen de inmediato.

Consejo para el examen: SSH (22) reemplazó a Telnet para el acceso seguro por línea de comandos; RDP (3389) es el acceso gráfico a Windows y nunca debe exponerse directamente a internet. Una VPN protege la conexión; por sí sola no es una herramienta de control remoto.

Comprueba lo que sabes

¿Qué protocolo usarías para administrar un servidor Linux por línea de comandos de forma cifrada?

SSH.

¿Cuál es la forma más segura de dar a los trabajadores remotos acceso RDP a las PC de la oficina?

Exigir una VPN (o un RD gateway) con MFA y permitir RDP solo a través de ella, nunca directamente desde internet.

¿Por qué es tan peligrosa una cuenta RMM comprometida?

La plataforma RMM tiene control administrativo de todos los dispositivos administrados, así que un atacante podría desplegar malware en todos ellos.
