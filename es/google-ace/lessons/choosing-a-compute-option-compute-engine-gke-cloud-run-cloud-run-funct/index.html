Elegir una opción de cómputo: Compute Engine, GKE, Cloud Run, Cloud Run functions y App Engine

Google Cloud ofrece un espectro de servicios de cómputo, desde control total hasta completamente administrado. Una gran parte de las preguntas del examen se reduce a elegir el correcto, así que aprende para qué sirve cada uno y qué tareas te quita de encima.

Compute Engine es infraestructura como servicio (IaaS): máquinas virtuales en las que eliges el tipo de máquina, la imagen del sistema operativo y los discos, y tú administras el sistema operativo. Elígelo para migraciones lift-and-shift, software que necesita un sistema operativo, un módulo del kernel o una licencia específicos, servidores con estado de larga duración, o cuando necesitas GPUs con control total. Los grupos de instancias administrados agregan escalado automático y autorreparación.

Google Kubernetes Engine (GKE) es Kubernetes administrado. Google ejecuta el plano de control; tú despliegas contenedores usando objetos de Kubernetes como Deployments y Services. Elígelo para microservicios en contenedores que necesitan funciones de Kubernetes, portabilidad, control detallado de la red y la programación, o muchos servicios sobre capacidad compartida. El modo Autopilot elimina la administración de nodos; el modo Standard te da control sobre los nodos.

Cloud Run es una plataforma serverless para contenedores. Le das una imagen de contenedor que escucha solicitudes HTTP (un service) o que se ejecuta hasta completarse (un job), y Google se encarga de los servidores, el escalado (incluso a cero) y los endpoints HTTPS. Pagas por los recursos usados mientras se atienden las solicitudes (o por el tiempo de instancia, según la configuración de facturación). Elígelo para apps web y APIs sin estado con tráfico variable cuando no necesitas Kubernetes. Cloud Run functions (antes Cloud Functions) te permite desplegar solo una función en un lenguaje compatible, activada por HTTP o por eventos como un archivo subido a Cloud Storage o un mensaje de Pub/Sub; se ejecutan sobre la infraestructura de Cloud Run.

App Engine es la plataforma como servicio (PaaS) original de Google para apps web. El entorno estándar ejecuta las apps en sandboxes específicos de cada lenguaje y puede escalar a cero; el entorno flexible ejecuta las apps en contenedores sobre VMs administradas. Cada proyecto puede tener una aplicación de App Engine, en una región elegida al crearla. Los proyectos nuevos generalmente se orientan hacia Cloud Run, pero App Engine sigue apareciendo en escenarios del examen, por ejemplo la división de tráfico entre versiones.

Una regla útil: cuanto menos quieras administrar, más te acercas a Cloud Run y a las funciones; cuanto más control o requisitos especiales de sistema operativo tengas, más te acercas a Compute Engine.

Términos clave

Compute Engine
Las máquinas virtuales IaaS de Google Cloud, en las que tú administras el sistema operativo.
GKE
Google Kubernetes Engine, un servicio de Kubernetes administrado para ejecutar contenedores.
Cloud Run
Una plataforma serverless que ejecuta contenedores sin estado y escala automáticamente, incluso a cero.
Cloud Run functions
Funciones activadas por eventos o por HTTP que se despliegan como código fuente, antes llamadas Cloud Functions.
Ejemplo real

Una empresa mueve a Compute Engine un servidor ERP heredado que necesita un agente con licencia, ejecuta sus 30 microservicios en GKE Autopilot, aloja en Cloud Run una API de marketing con tráfico en ráfagas y usa una Cloud Run function para generar miniaturas cada vez que llega una imagen a un bucket.

Consejo para el examen: Las palabras clave deciden: 'kernel', 'control del SO', 'licencia' significan Compute Engine; 'Kubernetes' o 'Helm' significan GKE; 'contenedor sin estado, escala a cero, sin infraestructura' significa Cloud Run; 'ejecutar código cuando se sube un archivo' significa Cloud Run functions.

Comprueba lo que sabes

¿Qué servicio encaja con un contenedor HTTP sin estado que no debe costar nada cuando está inactivo?

Cloud Run, porque escala a cero y no necesita servidores ni clústeres.

¿Cuántas aplicaciones de App Engine puede tener un proyecto?

Una, y su región no se puede cambiar después de crearla.
