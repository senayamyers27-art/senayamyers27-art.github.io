Snapshots, programaciones de snapshots, imágenes personalizadas y familias de imágenes

Compute Engine tiene varias formas de capturar discos y VMs, y cada una tiene un propósito distinto. Saber cuál usar es una tarea común en el examen.

Una snapshot es una copia de seguridad de un solo persistent disk o Hyperdisk en un momento dado. Las snapshots son incrementales: la primera contiene todos los datos, y las siguientes guardan solo los bloques que cambiaron, lo que las mantiene económicas. Se almacenan en ubicaciones respaldadas por Cloud Storage (multirregionales de forma predeterminada, o una región que elijas) y se pueden restaurar en un disco nuevo en cualquier zona, lo que también es una forma de mover un disco entre zonas o regiones. Crea una con gcloud compute snapshots create web-snap --source-disk=web-1 --source-disk-zone=us-central1-a. Para copias de seguridad consistentes a nivel de aplicación, vacía o pausa las escrituras primero; de lo contrario, una snapshot es consistente ante fallas (crash-consistent). Las instant snapshots y las archive snapshots son variantes para una reversión rápida dentro de la zona y para una retención a largo plazo más económica.

Una programación de snapshots (snapshot schedule) es una política de recursos que crea snapshots automáticamente, por ejemplo todos los días a las 02:00, y las elimina después de un período de retención, como 14 días. Creas la programación con gcloud compute resource-policies create snapshot-schedule y la adjuntas a los discos con gcloud compute disks add-resource-policies. Esta es la forma de respaldar VMs sin escribir scripts. Para copias de seguridad centralizadas y basadas en políticas, con informes sobre muchos recursos, Google también ofrece el servicio Backup and DR.

Una imagen personalizada (custom image) es una plantilla de disco de arranque. Creas una a partir de un disco, una snapshot u otra imagen, normalmente después de instalar y endurecer el software, y luego creas muchas VMs o plantillas de instancia a partir de ella. Las imágenes se pueden compartir con otros proyectos mediante IAM. Agrupar imágenes en una familia de imágenes permite que las plantillas de instancia hagan referencia a la familia, así las VMs nuevas usan automáticamente la imagen más reciente, y puedes marcar como obsoleta (deprecate) una imagen defectuosa para volver a la anterior.

Una machine image captura una VM completa: su configuración (tipo de máquina, metadatos, configuración de red) y todos sus discos. Es útil para clonar una VM entera o respaldarla junto con su configuración, mientras que una imagen contiene solo un disco.

Términos clave

Snapshot
Una copia de seguridad incremental de un disco en un momento dado que se puede restaurar en un disco nuevo.
Snapshot schedule (programación de snapshots)
Una política de recursos que crea y elimina snapshots de disco automáticamente según un calendario.
Custom image (imagen personalizada)
Una plantilla de disco de arranque creada a partir de tu propio disco, que se usa para crear VMs idénticas.
Machine image
Una captura de una VM completa, incluida su configuración y todos sus discos.
Ejemplo real

Un equipo de operaciones adjunta una programación de snapshots diaria con retención de 14 días a cada disco de producción. Cada mes crea una imagen personalizada con parches y endurecida en la familia web-base, y sus plantillas de instancia hacen referencia a la familia, así las VMs nuevas siempre arrancan desde la versión más reciente.

Consejo para el examen: Copia de seguridad de un disco: snapshot. Copias de seguridad automáticas sin scripts: snapshot schedule. Plantilla para muchas VMs idénticas: imagen personalizada en una familia de imágenes. VM completa con su configuración: machine image.

Comprueba lo que sabes

¿Por qué las snapshots sucesivas del mismo disco son más baratas que la primera?

Son incrementales y guardan solo los bloques que cambiaron desde la snapshot anterior.

¿Cómo puedes mover los datos de un disco a otra región?

Toma una snapshot y crea a partir de ella un disco nuevo en la región de destino.
