Acceso a Cloud Storage: acceso uniforme a nivel de bucket, prevención del acceso público y signed URLs

Cloud Storage tiene dos sistemas de control de acceso. IAM otorga roles en el proyecto o en un bucket (y, con las carpetas administradas, en prefijos), como Storage Object Viewer, Storage Object Creator o Storage Admin. Las listas de control de acceso (ACLs) son un sistema más antiguo y detallado que puede otorgar acceso a objetos individuales. Usar ambos hace difícil saber quién puede leer qué.

El acceso uniforme a nivel de bucket (uniform bucket-level access) deshabilita las ACLs en un bucket para que solo IAM (a nivel de bucket y de proyecto, más las carpetas administradas) controle el acceso. Se recomienda para casi todos los buckets y es obligatorio para algunas funciones, como las IAM Conditions en buckets y las carpetas administradas. Una vez habilitado, tienes un período limitado para desactivarlo antes de que se vuelva permanente. El acceso detallado (fine-grained) es el modo que conserva las ACLs, para casos especiales como compartir objetos individuales en apps heredadas.

Un bucket u objeto se vuelve público cuando se otorga acceso a allUsers (cualquier persona en internet) o a allAuthenticatedUsers (cualquier persona con una cuenta de Google). La prevención del acceso público (public access prevention) bloquea estos permisos. Puedes aplicarla en un bucket, o en proyectos, carpetas o toda la organización con la restricción de política de la organización storage.publicAccessPrevention. Con ella aplicada, ni siquiera un administrador puede hacer públicos los datos por error; alojar un sitio web público requiere entonces un bucket en un proyecto donde no esté aplicada, o una configuración con balanceador de carga y Cloud CDN diseñada para eso.

Las signed URLs dan acceso por tiempo limitado a un objeto específico a alguien que no tiene una identidad de Google, sin hacer público el bucket. La URL contiene una firma creada con las credenciales de una cuenta de servicio y una fecha de vencimiento, de hasta 7 días para las firmas V4. Cualquiera que tenga la URL puede realizar la acción especificada (por ejemplo GET para descargar o PUT para subir) hasta que venza. Crea una con gcloud storage sign-url gs://bucket/report.pdf --duration=1h --private-key-file=key.json o, mejor aún, con suplantación en lugar de un archivo de clave. Los signed policy documents hacen lo mismo para las subidas mediante formularios del navegador.

Otros controles incluyen las políticas de retención y las retenciones (holds), Requester Pays, los perímetros de VPC Service Controls alrededor del almacenamiento y CMEK para el cifrado. Los registros de auditoría Data Access registran quién leyó los objetos cuando están habilitados.

Términos clave

Uniform bucket-level access (acceso uniforme a nivel de bucket)
Una configuración del bucket que deshabilita las ACLs para que solo IAM controle el acceso.
Public access prevention (prevención del acceso público)
Una configuración o política de la organización que bloquea los permisos otorgados a allUsers y allAuthenticatedUsers.
Signed URL
Una URL que otorga acceso por tiempo limitado a un objeto sin requerir una identidad de Google.
allUsers
Un principal especial que significa cualquier persona en internet.
Ejemplo real

Un despacho de abogados necesita compartir un archivo de 2 GB con un cliente que no tiene cuenta de Google. El bucket tiene el acceso uniforme a nivel de bucket y la prevención del acceso público aplicados, así que el administrador genera una signed URL V4 válida por 24 horas. El cliente descarga el archivo, y el enlace deja de funcionar al día siguiente.

Consejo para el examen: Solo IAM, sin ACLs: acceso uniforme a nivel de bucket. Nunca público, ni siquiera por error: aplica la prevención del acceso público (política de la organización para todo). Acceso temporal para alguien sin cuenta: signed URL.

Comprueba lo que sabes

¿Cuál es la duración máxima de una signed URL V4?

7 días.

¿El acceso uniforme a nivel de bucket, por sí solo, impide que un bucket se haga público?

No. IAM todavía puede otorgar acceso a allUsers a menos que se aplique la prevención del acceso público.
