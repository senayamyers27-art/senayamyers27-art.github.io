Elegir un producto de datos: Cloud SQL, AlloyDB, Spanner, Firestore, Bigtable y BigQuery

Elegir el producto de datos correcto es una de las habilidades más evaluadas. Empieza preguntándote: ¿los datos son relacionales o no?, ¿son para transacciones (OLTP) o para analítica (OLAP)?, ¿qué tan grandes serán? y ¿necesitan abarcar varias regiones?

Cloud SQL es MySQL, PostgreSQL y SQL Server completamente administrados. Google se encarga de los parches, las copias de seguridad, la replicación y la conmutación por error, y te conectas con los drivers y herramientas habituales. Escala verticalmente (máquinas más grandes) y con réplicas de lectura, y es regional. Es la respuesta predeterminada para apps web y de negocio típicas que necesitan una base de datos relacional. AlloyDB for PostgreSQL es una base de datos compatible con PostgreSQL con mayor rendimiento para cargas transaccionales exigentes y cargas analíticas mixtas; elígela cuando una pregunta enfatice la compatibilidad con PostgreSQL con alto rendimiento.

Spanner es una base de datos relacional que escala horizontalmente, ofrece consistencia fuerte y admite configuraciones multirregionales con una disponibilidad muy alta. Elígela para sistemas transaccionales globales y de misión crítica, como plataformas de inventario, de trading o de videojuegos que superan la capacidad de una sola instancia de Cloud SQL.

Firestore es una base de datos NoSQL de documentos, serverless, para apps web, móviles y de servidor, con listeners en tiempo real, soporte sin conexión para clientes móviles y escalado automático. Bigtable es una base de datos NoSQL de columnas anchas para volúmenes enormes de datos con un throughput de lectura y escritura muy alto y baja latencia por clave de fila, como series temporales, telemetría de IoT, tecnología publicitaria y cotizaciones financieras. No es relacional y no admite joins de SQL entre tablas de la forma habitual. Memorystore ofrece Redis y Memcached administrados para caché.

BigQuery es el data warehouse serverless. Cargas o transmites datos y los consultas con SQL estándar a escala de petabytes, pagando por el almacenamiento y por las consultas (por bytes procesados bajo demanda, o por capacidad reservada). Es para analítica e informes, no para atender las transacciones de una app. También puede consultar algunos datos externos en su lugar de origen.

Cloud Storage guarda objetos no estructurados como imágenes, videos, copias de seguridad y archivos de data lake. A menudo forma parte de la respuesta junto con estas bases de datos.

Términos clave

Cloud SQL
MySQL, PostgreSQL y SQL Server administrados para cargas relacionales regionales.
Spanner
Una base de datos relacional con escalado horizontal y consistencia fuerte que puede abarcar varias regiones.
Bigtable
Una base de datos NoSQL de columnas anchas para cargas masivas de baja latencia basadas en claves, como series temporales.
BigQuery
Un data warehouse serverless para analítica con SQL a muy gran escala.
Ejemplo real

Una empresa de videojuegos guarda los perfiles de jugadores en Firestore para su app móvil, la telemetría de partidas en Bigtable para escrituras rápidas, una tienda global de artículos en Spanner para compras consistentes entre regiones, y exporta todo a BigQuery para la analítica diaria.

Consejo para el examen: Relacional y regional: Cloud SQL. Relacional y a escala global: Spanner. Series temporales o IoT a escala enorme: Bigtable. Documentos para móvil o web: Firestore. Analítica con SQL: BigQuery.

Comprueba lo que sabes

¿Qué producto encaja con una app regional que necesita una base de datos MySQL administrada?

Cloud SQL for MySQL.

¿Por qué BigQuery no es el almacén adecuado para el carrito de compras de una app?

Es un warehouse de analítica, optimizado para lecturas masivas, no para actualizaciones transaccionales de baja latencia.
