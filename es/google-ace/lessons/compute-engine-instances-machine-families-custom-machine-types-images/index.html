Instancias de Compute Engine: familias de máquinas, tipos de máquina personalizados, imágenes y Spot VMs

Crear una VM significa elegir una zona, un tipo de máquina, una imagen para el disco de arranque y la red. Desde la CLI, un ejemplo básico es gcloud compute instances create web-1 --zone=us-central1-a --machine-type=e2-medium --image-family=debian-12 --image-project=debian-cloud.

Los tipos de máquina se agrupan en familias. Las familias de uso general (como E2, N2, N2D, N4 y C3 en las generaciones actuales) equilibran CPU y memoria; E2 está optimizada para costos e incluye tipos de núcleo compartido como e2-micro y e2-small. Las familias optimizadas para cómputo (como C2 y H3) son para trabajo intensivo en CPU, como la computación de alto rendimiento. Las familias optimizadas para memoria (serie M) sirven para bases de datos en memoria muy grandes. Las familias optimizadas para aceleradores (series A y G) adjuntan GPUs para machine learning. Dentro de una familia, los tipos predefinidos vienen en formas como standard, highmem y highcpu. Los nombres exactos de las familias cambian a medida que salen nuevas generaciones, así que enfócate en las categorías.

Si ningún tipo predefinido encaja, crea un tipo de máquina personalizado (custom machine type) en las familias que lo admiten (como E2, N2 y N1) eligiendo vCPUs y memoria, por ejemplo --custom-cpu=6 --custom-memory=20GB. Pagas por lo que eliges, lo que evita desperdiciar dinero en el siguiente tamaño más grande. La memoria por vCPU debe mantenerse dentro de la proporción de la familia, a menos que habilites la memoria extendida.

Las imágenes proporcionan el disco de arranque. Las imágenes públicas de Google y de proveedores cubren Debian, Ubuntu, Rocky Linux, Windows Server y otros; Container-Optimized OS está diseñado para ejecutar contenedores. Las familias de imágenes (image families) siempre apuntan a la imagen más reciente de una serie, por eso los comandos suelen usar --image-family. También puedes crear imágenes personalizadas a partir de tus propios discos.

Las Spot VMs son capacidad sobrante con un descuento considerable. Google puede detenerlas (preemptarlas) en cualquier momento cuando necesita la capacidad, con un aviso de unos 30 segundos, y no hay garantía de disponibilidad. Son ideales para trabajos por lotes tolerantes a fallas, renderizado, ejecutores de CI y workers sin estado en grupos de instancias administrados, y poco adecuadas para bases de datos o cualquier cosa que no pueda interrumpirse. Las preemptible VMs son la versión anterior, limitada a 24 horas de ejecución. Para cargas de trabajo estables, los descuentos por compromiso de uso (committed use discounts) y los descuentos por uso sostenido (sustained use discounts) reducen en cambio el costo de las VMs normales.

Términos clave

Machine family (familia de máquinas)
Un grupo de tipos de máquina optimizados para una clase de carga de trabajo, como de uso general u optimizada para memoria.
Custom machine type (tipo de máquina personalizado)
Una forma de VM en la que eliges la cantidad de vCPUs y de memoria.
Image family (familia de imágenes)
Un nombre que siempre se resuelve en la imagen más nueva de una serie, como debian-12.
Spot VM
Una VM con descuento que Google puede preemptar en cualquier momento cuando necesita la capacidad.
Ejemplo real

Un estudio de animación renderiza fotogramas durante la noche en 200 Spot VMs dentro de un grupo de instancias administrado. Cuando algunas son preemptadas, el grupo las vuelve a crear y la cola de trabajos entrega los fotogramas sin terminar a otros workers, lo que reduce considerablemente la factura de renderizado en comparación con las VMs normales.

Consejo para el examen: 'Se puede interrumpir' más 'el menor costo' significa Spot VMs. 'Necesita una proporción inusual de CPU a memoria' significa un tipo de máquina personalizado. Las Spot VMs no son adecuadas para bases de datos.

Comprueba lo que sabes

¿Qué le pasa a una Spot VM cuando Google necesita recuperar la capacidad?

Es preemptada (detenida o eliminada, según su configuración) después de un breve período de aviso.

¿Por qué usar --image-family en lugar del nombre de una imagen específica?

La familia siempre se resuelve en la imagen más reciente no obsoleta, así obtienes los parches actuales.
