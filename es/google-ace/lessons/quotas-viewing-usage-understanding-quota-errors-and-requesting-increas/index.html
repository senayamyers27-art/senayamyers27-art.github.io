Cuotas: ver el uso, entender los errores de cuota y solicitar aumentos

Las cuotas te protegen tanto a ti como a Google Cloud de un uso inesperado. Limitan cuánto de un recurso puede usar un proyecto (cuotas de asignación, como la cantidad de CPUs en una región o la cantidad de direcciones IP estáticas) o con qué frecuencia puedes llamar a una API (cuotas de tasa, como solicitudes por minuto). Por separado, los límites del sistema (system limits) son valores fijos que no se pueden aumentar, como el tamaño máximo de un solo objeto o disco.

Muchas cuotas de Compute Engine son regionales. La cuota CPUS en us-central1 es independiente de la de europe-west1, y hay cuotas separadas para familias específicas, GPUs, capacidad Spot y preemptible, capacidad de persistent disk y direcciones IP en uso. Por eso un despliegue puede fallar en una región cuando tendría éxito en otra. Los proyectos nuevos y las cuentas de prueba gratuita empiezan con cuotas conservadoras.

Cuando una solicitud excedería una cuota, falla con un mensaje como Quota 'CPUS' exceeded. Limit: 24.0 in region us-central1. Los errores de cuota de tasa de una API normalmente devuelven HTTP 429 (Too Many Requests) o RESOURCE_EXHAUSTED. Lee el mensaje con atención; nombra la métrica y la región, lo que te dice exactamente qué cuota aumentar.

Para ver y administrar las cuotas, ve a IAM and admin > Quotas and system limits en la consola (o abre la pestaña Quotas de un servicio). Puedes filtrar por servicio, métrica y región y ver el uso actual frente a cada límite. Para aumentar una, selecciónala, elige Edit quota, ingresa el nuevo valor y una justificación, y envíala. Algunos aumentos se otorgan automáticamente en minutos; otros se revisan y pueden tardar más, así que planifica con anticipación los lanzamientos grandes. Necesitas un rol que incluya serviceusage.quotas.update, como Quota Administrator u Owner.

También puedes establecer cuotas más bajas tú mismo, por ejemplo limitar las solicitudes diarias de una API para controlar el costo, y puedes crear alertas de Cloud Monitoring sobre el uso de cuotas para recibir un aviso antes de llegar a un límite.

Términos clave

Allocation quota (cuota de asignación)
Un límite de cuánto de un recurso puede tener un proyecto, como las CPUs regionales.
Rate quota (cuota de tasa)
Un límite de cuántas solicitudes a una API se pueden hacer en un período.
System limit (límite del sistema)
Un máximo fijo que no se puede aumentar mediante una solicitud.
Quota increase request (solicitud de aumento de cuota)
Una solicitud hecha desde la página Quotas para aumentar un límite, a veces aprobada automáticamente.
Ejemplo real

Un equipo planea una prueba de carga con 200 VMs en us-east1. Una semana antes, revisan la página Quotas, ven un límite de CPUS demasiado bajo para su tipo de máquina y solicitan un aumento con una breve justificación. La solicitud se aprueba antes de la prueba, lo que evita una falla el día del lanzamiento.

Consejo para el examen: Los errores de cuota se corrigen solicitando un aumento para la métrica y región indicadas (o desplegando en otro lugar). Volver a habilitar APIs, cambiar IAM o mover carpetas no cambia las cuotas.

Comprueba lo que sabes

¿Las cuotas de CPU de Compute Engine son globales o regionales?

Mayormente regionales; cada región tiene su propia cuota de CPU.

¿Qué estado HTTP suele indicar que se excedió una cuota de tasa?

429 Too Many Requests (RESOURCE_EXHAUSTED).
