Presupuestos, alertas de presupuesto y exportación de datos de facturación a BigQuery

Cloud Billing te da varias formas de vigilar el gasto. Los informes (reports) en la consola muestran tendencias de costos por proyecto, servicio, SKU, etiqueta y período. Para un control proactivo creas presupuestos (budgets), y para un análisis profundo exportas los datos de facturación a BigQuery.

Un presupuesto se establece en una cuenta de facturación y puede abarcarla completa o solo proyectos, servicios o etiquetas seleccionados. Le asignas un monto, ya sea un número fijo o el gasto del mes anterior, y reglas de umbral como 50%, 90% y 100%. Los umbrales pueden basarse en el gasto real o en el gasto previsto (forecasted), para que te avisen antes de que un mes termine por encima del presupuesto. Cuando se cruza un umbral, los administradores y usuarios de facturación reciben alertas por correo, y también puedes enviar alertas a canales de notificación de Cloud Monitoring o publicarlas en un tema de Pub/Sub.

El dato más importante sobre los presupuestos: no limitan el gasto. Un presupuesto nunca detiene una VM ni deshabilita la facturación por sí solo. Si necesitas una acción automática, por ejemplo desactivar la facturación de un proyecto sandbox cuando alcance su límite, publicas las notificaciones del presupuesto en Pub/Sub y activas tu propio código, como una Cloud Run function, para realizar esa acción. Ten en cuenta también que los datos de facturación no son en tiempo real; puede haber un retraso de horas antes de que aparezca el uso.

La exportación de facturación a BigQuery escribe filas detalladas de datos de costos y uso en un dataset que eliges, de forma continua. Existen exportaciones de datos de costos de uso estándar, datos de costos de uso detallados (con detalle a nivel de recurso) y datos de precios. Una vez habilitada, puedes escribir SQL para desglosar el costo por proyecto, servicio, etiqueta o día y crear paneles en Looker Studio. La exportación solo incluye datos a partir del momento en que la habilitas, así que actívala pronto. Necesitas un rol como Billing Account Costs Manager o Administrator para configurarla, además de permisos sobre el dataset.

Las etiquetas (labels) hacen que estos informes sean útiles. Claves consistentes como env, team y app, aplicadas a los recursos, fluyen hacia los datos de facturación para que puedas responder '¿cuánto cuesta la app de checkout?' incluso en proyectos compartidos.

Términos clave

Budget (presupuesto)
Un monto y un conjunto de reglas de umbral que activan alertas a medida que crece el gasto real o previsto.
Threshold rule (regla de umbral)
Un porcentaje del presupuesto que envía una notificación cuando se cruza.
Billing export (exportación de facturación)
Un flujo continuo de datos detallados de Cloud Billing hacia un dataset de BigQuery.
Forecasted spend (gasto previsto)
La estimación de Google de cuál será el total del mes, sobre la que los presupuestos pueden alertar.
Ejemplo real

Una universidad le da a cada laboratorio de investigación un proyecto con un presupuesto de $200 que alerta al 50%, 90% y 100% del gasto previsto. Las alertas se publican en Pub/Sub, y una pequeña función le envía un correo al líder del laboratorio. Finanzas también exporta los datos de facturación a BigQuery y ejecuta una consulta mensual agrupada por la etiqueta del laboratorio.

Consejo para el examen: Si una pregunta espera que el gasto se detenga automáticamente, un presupuesto por sí solo es incorrecto; necesita notificaciones de Pub/Sub y código. Para analizar costos con SQL, la respuesta es la exportación de facturación a BigQuery, no los registros de auditoría.

Comprueba lo que sabes

¿Un presupuesto detiene los recursos cuando llega al 100%?

No. Envía alertas. Una acción automática requiere procesar las notificaciones de Pub/Sub con tu propio código.

¿Desde cuándo empieza a incluir datos la exportación de facturación?

Desde el momento en que la habilitas; no rellena todo el historial, así que habilítala pronto.
