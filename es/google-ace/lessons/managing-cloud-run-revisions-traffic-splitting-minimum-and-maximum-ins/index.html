Administrar Cloud Run: revisiones, división de tráfico, instancias mínimas y máximas

Cada despliegue en un servicio de Cloud Run crea una nueva revisión inmutable, con un nombre como web-00007-abc. Las revisiones conservan su imagen y su configuración, así que puedes mover el tráfico de vuelta a una anterior en cualquier momento. De forma predeterminada, una revisión nueva recibe el 100% del tráfico en cuanto está saludable.

La división de tráfico (traffic splitting) te permite lanzar gradualmente. Despliega la nueva revisión sin enviarle tráfico usando gcloud run deploy web --image=... --no-traffic --tag=green, lo que le da una URL con etiqueta (la etiqueta, tres guiones y el nombre de host del servicio) para hacer pruebas. Luego mueve el tráfico con gcloud run services update-traffic web --to-revisions=web-00007-abc=10,web-00006-def=90 para un canary del 10%, y después con --to-latest para enviar todo a la revisión más nueva. Revertir es simplemente mover el tráfico a la revisión anterior; no hace falta volver a construir nada.

El escalado es automático, pero tú controlas sus límites. Las instancias máximas (maximum instances) limitan cuántas instancias de contenedor se pueden ejecutar, lo que protege a los sistemas posteriores, como una base de datos con un pool de conexiones limitado, y limita el costo. Las instancias mínimas (minimum instances) mantienen cierta cantidad de instancias listas incluso sin tráfico, lo que reduce la latencia de arranque en frío (cold start, el retraso mientras una instancia nueva se inicia y se inicializa) a cambio de pagar por instancias inactivas. La concurrencia establece cuántas solicitudes atiende una instancia a la vez; el valor predeterminado es 80, y establecerla en 1 sirve para código que no es thread-safe, pero aumenta la cantidad de instancias necesarias.

Otras configuraciones que ajustarás incluyen la CPU y la memoria por instancia, el tiempo de espera de las solicitudes, las variables de entorno y los secretos, la cuenta de servicio con la que se ejecuta el servicio y el modo de facturación: con la facturación basada en solicitudes, la CPU se asigna solo durante las solicitudes, mientras que la facturación basada en instancias (CPU siempre asignada) sirve para trabajo en segundo plano entre solicitudes.

Para observar un servicio, la consola de Cloud Run muestra la cantidad de solicitudes, las latencias, la cantidad de instancias y los logs de cada revisión. gcloud run services describe web muestra la división de tráfico actual, y gcloud run revisions list muestra todas las revisiones.

Términos clave

Revision (revisión)
Una versión inmutable de un servicio de Cloud Run creada en cada despliegue.
Traffic split (división de tráfico)
Porcentajes de solicitudes enviados a distintas revisiones de un mismo servicio.
Minimum instances (instancias mínimas)
Una configuración que mantiene instancias listas para reducir los arranques en frío, facturadas aunque estén inactivas.
Cold start (arranque en frío)
El retraso que ocurre cuando Cloud Run inicia una nueva instancia de contenedor para atender una solicitud.
Ejemplo real

El equipo de la API de un banco despliega una revisión nueva con --no-traffic, ejecuta pruebas contra su URL con etiqueta y luego le envía el 5% del tráfico. Tras una hora de métricas de error limpias, pasa al 50% y luego al 100%. Mantiene las instancias mínimas en 2 para que los clientes nunca sufran un arranque en frío durante el horario laboral.

Consejo para el examen: El lanzamiento gradual en Cloud Run es la división de tráfico entre revisiones del mismo servicio. Una primera solicitud lenta se corrige con instancias mínimas; la protección de una base de datos se hace con instancias máximas.

Comprueba lo que sabes

¿Cómo reviertes un servicio de Cloud Run a la versión anterior?

Envía el 100% del tráfico a la revisión anterior con gcloud run services update-traffic (o desde la consola).

¿Cuál es la contrapartida de establecer las instancias mínimas por encima de cero?

Menos arranques en frío, pero pagas por esas instancias incluso cuando no hay tráfico.
