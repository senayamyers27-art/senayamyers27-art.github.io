Administración de usuarios y grupos con Cloud Identity o Google Workspace, y Google Cloud Directory Sync

Google Cloud no tiene su propio directorio de usuarios dentro de IAM. Las personas inician sesión con identidades de Google: cuentas administradas en Cloud Identity o Google Workspace para el dominio de tu empresa o, lo cual es menos ideal, cuentas de Google individuales como direcciones de Gmail. Cloud Identity es un producto de identidad como servicio; su edición gratuita te da usuarios y grupos administrados para tu dominio sin las apps de Workspace como Gmail. Workspace incluye las mismas funciones de identidad más las apps de productividad.

Los grupos se crean en la Admin console o en la sección Groups de la consola de Google Cloud y tienen una dirección de correo, como gcp-network-admins@example.com. IAM trata a un grupo como un principal, así que otorgar un rol a un grupo se lo da a cada miembro. Cuando alguien entra o sale de un equipo, cambias la membresía del grupo y todos los permisos de IAM relacionados se ajustan automáticamente. La práctica recomendada por Google es otorgar roles a grupos, no a usuarios individuales.

Muchas empresas ya administran a sus empleados en Microsoft Active Directory u otro directorio LDAP. Google Cloud Directory Sync (GCDS) es una herramienta gratuita que ejecutas en un servidor de tu propia red. Lee usuarios y grupos de Active Directory o LDAP y crea, actualiza y suspende las cuentas correspondientes en Cloud Identity o Workspace, en una sola dirección: de tu directorio hacia Google. No sincroniza contraseñas de forma predeterminada; para el inicio de sesión normalmente configuras inicio de sesión único (SSO) con SAML para que los usuarios se autentiquen contra tu proveedor de identidad existente, como Active Directory Federation Services o Microsoft Entra ID.

Las identidades para cargas de trabajo son diferentes. Las aplicaciones deben usar cuentas de servicio, no cuentas de usuario, y las cargas de trabajo externas deben usar Workload Identity Federation. Mezclar ambas cosas es un distractor común en el examen: las cuentas de servicio nunca son la respuesta para dar acceso a los empleados.

Mantén unas pocas cuentas de superadministrador en Cloud Identity, protégelas con una verificación en dos pasos sólida y no las uses para el trabajo diario, porque pueden administrar a todos los usuarios y otorgarse a sí mismas cualquier rol en la organización.

Términos clave

Cloud Identity
El producto de identidad como servicio de Google para administrar usuarios, grupos y dispositivos de un dominio, disponible en una edición gratuita.
Google Cloud Directory Sync
Una herramienta que sincroniza en una sola dirección usuarios y grupos de Active Directory o LDAP hacia Cloud Identity o Google Workspace.
SAML single sign-on (inicio de sesión único con SAML)
Federación que permite a los usuarios iniciar sesión en Google con las credenciales de su proveedor de identidad existente.
Google group (grupo de Google)
Una colección de identidades con su propia dirección de correo a la que se le pueden otorgar roles de IAM.
Ejemplo real

Un fabricante con 3,000 empleados en Active Directory ejecuta GCDS cada noche para que el grupo de AD de cada departamento aparezca como un grupo de Google. El SSO con su proveedor de identidad permite que el personal inicie sesión con su contraseña habitual, y los roles de IAM se otorgan solo a los grupos sincronizados, así que los cambios de RR. HH. en AD se reflejan automáticamente en el acceso a la nube.

Consejo para el examen: Usuarios existentes de AD más 'sin volver a crearlos' significa Google Cloud Directory Sync (a menudo con SSO de SAML). IAM no crea usuarios, y las cuentas de servicio son para cargas de trabajo, no para empleados.

Comprueba lo que sabes

¿En qué dirección copia los datos Google Cloud Directory Sync?

En una sola dirección, de Active Directory o LDAP hacia Cloud Identity o Google Workspace.

¿Por qué otorgar roles de IAM a grupos en lugar de a usuarios?

El acceso sigue a la membresía del grupo, así que las altas, cambios y bajas se gestionan en un solo lugar y las políticas de IAM se mantienen cortas.
