Suplantación de cuentas de servicio, credenciales de corta duración y cómo evitar las claves de cuentas de servicio

Una clave de cuenta de servicio (service account key) es un archivo de clave privada de larga duración (JSON) que cualquiera puede usar para autenticarse como la cuenta de servicio, desde cualquier lugar, hasta que la clave se elimine o se deshabilite. Las claves son una de las causas más comunes de brechas en la nube porque terminan copiadas en el código fuente, laptops, sistemas de CI y mensajes de chat. La guía de Google es evitar crear claves siempre que exista otra opción, y muchas organizaciones bloquean la creación de claves con la política de la organización iam.disableServiceAccountKeyCreation.

Para las cargas de trabajo que se ejecutan en Google Cloud, la alternativa es adjuntar una cuenta de servicio, como se vio antes, para que la plataforma proporcione tokens de corta duración. Para las personas que necesitan actuar como una cuenta de servicio, por ejemplo para probar sus permisos o ejecutar un script de automatización, la alternativa es la suplantación (impersonation).

La suplantación significa que un principal usa sus propias credenciales para obtener credenciales de corta duración de una cuenta de servicio. El principal necesita el rol Service Account Token Creator (roles/iam.serviceAccountTokenCreator) sobre esa cuenta de servicio. Con gcloud agregas --impersonate-service-account=deploy-sa@my-proj.iam.gserviceaccount.com a un comando, o lo estableces para toda una configuración con gcloud config set auth/impersonate_service_account deploy-sa@.... Terraform y las bibliotecas cliente también admiten la suplantación. Los tokens suelen vencer después de una hora, y los registros de auditoría registran tanto la cuenta de servicio como a la persona que la suplantó, lo que hace que la actividad sea rastreable.

La IAM Service Account Credentials API es la que emite estos tokens: tokens de acceso OAuth 2.0, tokens de ID de OpenID Connect para llamar a servicios como Cloud Run, y blobs o JWTs firmados. Las cadenas de suplantación (delegación) son posibles, pero deben usarse con moderación.

Si una clave tiene que existir, por ejemplo para un sistema de terceros que no admite nada más, adminístrala con cuidado: guárdala en un gestor de secretos, rótala con regularidad, establece un vencimiento usando la política de la organización de vencimiento de claves donde esté disponible, supervisa el uso de la clave y elimina las claves que no se usen. Si una clave se filtra, deshabilítala o elimínala de inmediato y revisa los registros de auditoría para ver para qué se usó. Quitar la clave de un repositorio no la invalida.

Términos clave

Service account key (clave de cuenta de servicio)
Una clave privada de larga duración que permite a quien la tenga autenticarse como la cuenta de servicio.
Impersonation (suplantación)
Usar tu propia identidad para obtener credenciales de corta duración de una cuenta de servicio.
Service Account Token Creator
El rol que permite generar credenciales de corta duración para una cuenta de servicio.
Short-lived credentials (credenciales de corta duración)
Tokens de acceso o de ID que vencen rápidamente, normalmente después de aproximadamente una hora.
Ejemplo real

Una desarrolladora solía guardar una clave de deploy-sa en su laptop. Su equipo elimina la clave, otorga a su grupo Service Account Token Creator sobre deploy-sa, y ahora ella ejecuta gcloud config set auth/impersonate_service_account deploy-sa@my-proj.iam.gserviceaccount.com. Los registros de auditoría muestran cada despliegue con su identidad y la de la cuenta de servicio.

Consejo para el examen: 'Sin crear una clave' más 'actuar como una cuenta de servicio' significa Token Creator y suplantación. Una clave filtrada debe deshabilitarse o eliminarse; borrar el commit no es suficiente.

Comprueba lo que sabes

¿Qué rol se requiere para suplantar una cuenta de servicio?

Service Account Token Creator sobre esa cuenta de servicio.

¿Qué debes hacer primero si una clave se sube a un repositorio público?

Deshabilitar o eliminar la clave, y luego revisar los registros de auditoría en busca de un uso indebido.
