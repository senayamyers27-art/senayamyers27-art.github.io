Infraestructura como código con Terraform y soluciones de Cloud Marketplace

La infraestructura como código (IaC) significa describir tu infraestructura en archivos que se guardan en control de versiones, se revisan como código y se aplican automáticamente. Te da entornos repetibles, revisión por pares de los cambios y un historial de quién cambió qué. Para Google Cloud, la herramienta más común es Terraform, una herramienta de código abierto de HashiCorp, usada con el proveedor (provider) de Google Cloud.

En Terraform escribes configuración declarativa en HashiCorp Configuration Language (HCL). Por ejemplo, un bloque de recurso google_compute_instance describe el nombre, la zona, el tipo de máquina y el disco de arranque de una VM. El flujo de trabajo es: terraform init descarga los proveedores y módulos; terraform plan compara tu configuración con el estado registrado y muestra qué se creará, cambiará o destruirá; terraform apply aplica los cambios; terraform destroy elimina todo lo que administra la configuración.

Terraform mantiene un archivo de estado (state) que relaciona la configuración con los recursos reales. Para equipos, guarda el estado de forma remota en un bucket de Cloud Storage (con Object Versioning activado) usando el backend gcs, para que todos compartan un solo estado y los cambios queden bloqueados mientras se ejecutan. No guardes el estado solo en una laptop, y trátalo como información sensible porque puede contener secretos.

Los módulos empaquetan configuración reutilizable, como una VPC estándar o una fábrica de proyectos. El Cloud Foundation Toolkit de Google publica módulos que siguen las mejores prácticas. Terraform viene preinstalado en Cloud Shell, y muchas páginas de la consola pueden mostrar el Terraform equivalente. Infrastructure Manager es un servicio de Google Cloud que ejecuta despliegues de Terraform por ti y guarda su estado. El antiguo Deployment Manager de Google, que usaba plantillas YAML, quedó obsoleto en favor de Infrastructure Manager, así que el trabajo nuevo debe usar Terraform o Infrastructure Manager. Config Connector es otra opción: te permite administrar recursos de Google Cloud como objetos de Kubernetes desde un clúster de GKE.

Cloud Marketplace ofrece soluciones prediseñadas de Google y sus socios, como stacks de WordPress, bases de datos, appliances de seguridad y herramientas para desarrolladores, que puedes desplegar con unos pocos clics. Algunas son gratuitas y otras se cobran a través de tu cuenta de Cloud Billing según los términos de licencia del proveedor. Marketplace es la respuesta cuando una pregunta pide la forma más rápida de desplegar un producto de terceros común.

Términos clave

Infrastructure as code (infraestructura como código)
Administrar la infraestructura mediante archivos de configuración declarativos y versionados.
terraform plan
Muestra los cambios que haría Terraform sin aplicarlos.
Terraform state (estado de Terraform)
Un archivo que registra qué recursos reales corresponden a la configuración.
Cloud Marketplace
Un catálogo de soluciones listas para desplegar de Google y sus socios.
Ejemplo real

Un equipo de plataforma mantiene su red, sus proyectos y sus clústeres de GKE en un repositorio git de módulos de Terraform. Cada pull request ejecuta terraform plan para que los revisores vean los cambios exactos, y al hacer merge se ejecuta terraform apply con el estado guardado en un bucket de Cloud Storage con versionado.

Consejo para el examen: 'Previsualizar los cambios antes de aplicarlos', 'con control de versiones', 'módulos reutilizables': todo apunta a Terraform. 'Desplegar rápidamente un producto de terceros común' apunta a Cloud Marketplace.

Comprueba lo que sabes

¿Dónde debe guardar un equipo el estado compartido de Terraform en Google Cloud?

En un bucket de Cloud Storage usando el backend gcs, idealmente con Object Versioning habilitado.

¿Qué hace terraform plan?

Muestra qué se crearía, cambiaría o destruiría, sin cambiar nada.
