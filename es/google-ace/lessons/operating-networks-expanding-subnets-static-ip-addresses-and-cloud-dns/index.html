Operar redes: ampliar subredes, direcciones IP estáticas y Cloud DNS

Las redes cambian a medida que crecen las cargas de trabajo, y el examen espera que sepas qué cambios se pueden hacer en el lugar.

Los rangos de subred se pueden ampliar pero no reducir. Si 10.10.0.0/24 se está quedando sin direcciones, gcloud compute networks subnets expand-ip-range app-subnet --region=us-central1 --prefix-length=22 lo amplía a 10.10.0.0/22 sin afectar a las VMs existentes, siempre que el rango más grande no se superponga con otras subredes o redes conectadas por peering. Cada subred reserva cuatro direcciones en su rango principal (la de red, la del gateway, la penúltima y la de broadcast), así que un /24 da 252 direcciones utilizables. También puedes agregar rangos secundarios, usados para IPs alias como los pods de GKE, y agregar subredes nuevas en cualquier región.

Las direcciones IP tienen dos tipos de duración. Las IPs externas efímeras se asignan cuando una VM se inicia y pueden cambiar después de que se detiene. Las IPs externas estáticas quedan reservadas para tu proyecto hasta que las liberes. Reserva una con gcloud compute addresses create web-ip --region=us-central1 (regional, para VMs y balanceadores de carga regionales) o --global (para balanceadores de carga globales), o promueve la IP efímera que ya tiene una VM para que nunca cambie. Las IPs internas también se pueden reservar como estáticas para que un servidor conserve la misma dirección privada. Las IPs externas estáticas reservadas que no están conectadas a nada se cobran, así que libera las que no uses.

Cloud DNS es un servicio de DNS autoritativo y administrado. Una zona pública sirve registros para un dominio en internet, como example.com; después de crearla, actualizas tu registrador para que use los servidores de nombres que asigna Cloud DNS. Una zona privada responde solo a las consultas de las redes VPC que autorizas, lo cual es útil para nombres internos como db.corp.internal. Administras registros como A, AAAA, CNAME, MX y TXT en la consola o con gcloud dns record-sets create. Las zonas de reenvío de DNS (forwarding zones) y las políticas de servidor conectan Cloud DNS con el DNS local en redes híbridas, y DNSSEC se puede habilitar en las zonas públicas.

Las VMs también obtienen nombres DNS internos automáticos con el formato VM_NAME.ZONE.c.PROJECT_ID.internal, para que otras VMs de la misma red puedan llegar a ellas por nombre sin administrar registros.

Términos clave

expand-ip-range
El subcomando de gcloud que amplía el rango principal de una subred en el lugar.
Static external IP (IP externa estática)
Una dirección pública reservada que se mantiene en tu proyecto hasta que la liberes.
Private DNS zone (zona DNS privada)
Una zona de Cloud DNS visible solo para las redes VPC autorizadas.
Internal DNS (DNS interno)
Nombres automáticos que permiten que las VMs de una red se comuniquen entre sí por nombre.
Ejemplo real

La subred de aplicaciones de una empresa SaaS se llena, así que la amplían de /24 a /22 en horario laboral sin tiempo de inactividad. Promueven a estática la IP efímera de su servidor SFTP para que las listas de permitidos de los clientes sigan funcionando, y crean una zona privada de Cloud DNS para que los servicios encuentren la base de datos en db.prod.internal.

Consejo para el examen: Las subredes crecen, nunca se reducen. Una IP pública que cambia se corrige reservando o promoviendo una dirección estática. Nombres solo internos: zona DNS privada.

Comprueba lo que sabes

¿Cuántas direcciones utilizables ofrece una subred /24 en Google Cloud?

252, porque se reservan cuatro direcciones en cada rango principal.

¿Las IPs externas estáticas reservadas cuestan dinero cuando no se usan?

Sí. Las direcciones reservadas que no están conectadas se cobran, así que libéralas.
