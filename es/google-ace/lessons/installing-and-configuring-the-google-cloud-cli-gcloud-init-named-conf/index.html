Instalación y configuración de Google Cloud CLI: gcloud init, configuraciones con nombre, proyecto, región y zona predeterminados

Google Cloud CLI es el conjunto de herramientas de línea de comandos para Google Cloud. Incluye gcloud para la mayoría de los servicios, gsutil (la herramienta anterior de Cloud Storage, ahora reemplazada en gran medida por gcloud storage) y bq para BigQuery, y puede instalar componentes adicionales como kubectl. Puedes instalarla en Linux, macOS o Windows, y viene preinstalada en Cloud Shell.

Después de instalarla, ejecuta gcloud init. Abre un navegador para autorizar tu cuenta de usuario, luego crea o actualiza una configuración y te pide elegir un proyecto predeterminado y, opcionalmente, una región y una zona predeterminadas. gcloud auth login autoriza una cuenta de usuario sin el resto de la configuración, y gcloud auth list muestra qué cuentas tienen credenciales y cuál está activa. Ten en cuenta que gcloud auth application-default login es diferente: crea Application Default Credentials que usan las bibliotecas cliente en tu código, no el propio gcloud.

Una configuración es un conjunto de propiedades con nombre. Las principales son core/account, core/project, compute/region y compute/zone. Las estableces con gcloud config set project my-proj o gcloud config set compute/zone us-central1-a, y las ves con gcloud config list. Si un comando necesita una zona y no hay ninguna establecida ni se pasa con --zone, gcloud te la pedirá o fallará.

Las configuraciones con nombre (named configurations) son la forma en que los profesionales evitan ejecutar comandos en el lugar equivocado. gcloud config configurations create prod crea y activa una nueva configuración; luego estableces su cuenta, proyecto y valores predeterminados. gcloud config configurations activate dev vuelve a cambiar, y gcloud config configurations list las muestra todas con la activa marcada. También puedes sobrescribir los valores para un solo comando con flags como --project y --configuration.

Mantén la CLI actualizada con gcloud components update (en instalaciones con gestor de paquetes, actualiza mediante el gestor de paquetes). Muchas funciones nuevas aparecen primero en los grupos de comandos gcloud beta o gcloud alpha, que necesitan tener sus componentes instalados.

Términos clave

gcloud init
Un comando interactivo que autoriza una cuenta y prepara una configuración con valores predeterminados.
Named configuration (configuración con nombre)
Un conjunto guardado de propiedades de gcloud, como cuenta, proyecto, región y zona, entre los que puedes alternar.
Application Default Credentials
Credenciales que las bibliotecas cliente encuentran automáticamente; se configuran localmente con gcloud auth application-default login.
gcloud config set
El comando para establecer una propiedad, como compute/zone, en la configuración activa.
Ejemplo real

Una ingeniera da soporte a dos clientes. Crea configuraciones llamadas acme y globex, cada una con su propia cuenta, proyecto y región. Antes de un cambio ejecuta gcloud config configurations activate acme, y el prompt de su shell muestra la configuración activa, así que nunca despliega en el cliente equivocado.

Consejo para el examen: Conoce la sintaxis exacta: gcloud config set compute/zone ZONE, gcloud config set project ID y gcloud config configurations activate NAME. Los distractores suelen inventar comandos como gcloud compute zones set.

Comprueba lo que sabes

¿Qué hace gcloud config configurations create?

Crea una nueva configuración con nombre y la activa, para que puedas establecer sus propiedades.

¿En qué se diferencia gcloud auth application-default login de gcloud auth login?

El primero crea credenciales para las bibliotecas cliente en tu código; el segundo autoriza a la propia CLI de gcloud.
