Redes VPC: modo automático vs. personalizado, subredes, reglas de firewall, Shared VPC y VPC Network Peering

Una red de Virtual Private Cloud (VPC) en Google Cloud es global: una VPC puede tener subredes en muchas regiones, y las VMs de distintas regiones de la misma VPC pueden comunicarse mediante IPs internas sin configuración adicional. Las subredes son regionales y cada una tiene un rango IPv4 principal, más rangos secundarios opcionales que se usan para cosas como las IPs de pods y servicios de GKE.

Al crear una VPC eliges un modo de subred. En el modo automático (auto mode), Google crea automáticamente una subred en cada región a partir del bloque 10.128.0.0/9, y agrega nuevas regiones a medida que se lanzan. La red default que suelen tener los proyectos nuevos es una VPC en modo automático con reglas de firewall permisivas. En el modo personalizado (custom mode), creas solo las subredes que quieres con los rangos que eliges. El modo personalizado se recomienda para producción porque evita superposiciones con las redes locales u otras redes que podrías conectar más adelante. Puedes convertir una red en modo automático a personalizado, pero no al revés.

Las reglas de firewall de VPC tienen estado (stateful) y se aplican a las instancias de VM. Cada regla tiene una dirección (ingress o egress), una acción (allow o deny), una prioridad de 0 a 65535 en la que ganan los números más bajos, protocolos y puertos, un rango de origen o destino, y destinos (targets): todas las instancias, las instancias con una network tag o las instancias que se ejecutan como una cuenta de servicio. Toda VPC tiene reglas implícitas que deniegan todo el tráfico de entrada y permiten todo el de salida. Por ejemplo: gcloud compute firewall-rules create allow-web --network=prod --direction=INGRESS --action=ALLOW --rules=tcp:80,tcp:443 --source-ranges=0.0.0.0/0 --target-tags=web. Las políticas de firewall jerárquicas a nivel de organización o carpeta y las políticas de firewall de red agregan control centralizado.

Shared VPC permite que un proyecto host sea dueño de una red VPC mientras los proyectos de servicio crean recursos en sus subredes. Un equipo central de redes administra las subredes, las rutas y los firewalls en el proyecto host, y los equipos de aplicaciones reciben Compute Network User en subredes específicas. Esta es la respuesta para el control centralizado de la red en muchos proyectos de una organización.

VPC Network Peering conecta dos redes VPC, en los mismos o en distintos proyectos u organizaciones, para que intercambien rutas internas de forma privada. Cada lado sigue administrándose por separado, los rangos de subred no deben superponerse y el peering no es transitivo: si A está conectada por peering con B, y B con C, A no puede llegar a C a través de B.

Términos clave

Custom mode VPC (VPC en modo personalizado)
Una VPC en la que tú mismo creas las subredes y eliges sus rangos.
Firewall rule priority (prioridad de regla de firewall)
Un número de 0 a 65535 en el que se aplica la regla coincidente con el número más bajo.
Shared VPC
Un modelo en el que los proyectos de servicio usan subredes de la VPC de un proyecto host administrado de forma centralizada.
VPC Network Peering
Una conexión privada y no transitiva entre dos redes VPC que intercambia las rutas de subred.
Ejemplo real

Una empresa crea una VPC en modo personalizado en un proyecto host de Shared VPC, con subredes en us-east1 y europe-west1 que no se superponen con los rangos de su centro de datos. Cinco equipos de aplicaciones conectan sus proyectos de servicio, y una regla de firewall permite tcp:443 solo hacia las VMs con la etiqueta web.

Consejo para el examen: Un equipo central administra la red de muchos proyectos: Shared VPC. Conectar dos VPCs administradas por separado: peering. El peering no es transitivo y los rangos no pueden superponerse. Ganan los números de prioridad más bajos.

Comprueba lo que sabes

¿Una red VPC es regional o global en Google Cloud?

Global. Sus subredes son regionales.

¿Qué reglas de firewall implícitas tiene toda VPC?

Denegar todo el tráfico de entrada y permitir todo el de salida, con la prioridad más baja.
