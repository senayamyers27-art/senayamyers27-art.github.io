Creación de proyectos: nombre, ID y número del proyecto, y habilitación de APIs

Antes de construir cualquier cosa necesitas un proyecto. Puedes crear uno en la consola (el selector de proyectos > New project) o desde la CLI con gcloud projects create PROJECT_ID --name="Display name" --folder=FOLDER_ID. Crear proyectos requiere el rol Project Creator en la organización o la carpeta, y el proyecto debe estar vinculado a una cuenta de facturación antes de que puedas usar la mayoría de los servicios de pago.

Cada proyecto tiene tres identificadores, y a las preguntas del examen les gusta evaluar la diferencia. El nombre del proyecto (project name) es una etiqueta amigable para mostrar; puedes cambiarlo en cualquier momento y no necesita ser único. El ID del proyecto (project ID) es una cadena única a nivel global de letras minúsculas, dígitos y guiones que eliges (o aceptas uno generado) al crear el proyecto. Nunca se puede cambiar, y es lo que usan gcloud, las APIs y muchos nombres de recursos. El número del proyecto (project number) lo asigna Google, también es permanente y aparece en lugares como la cuenta de servicio predeterminada de Compute Engine, PROJECT_NUMBER-compute@developer.gserviceaccount.com.

Los servicios de Google Cloud se exponen como APIs, y la mayoría están deshabilitadas en un proyecto nuevo. Si intentas usar un servicio cuya API está apagada, recibes un error que te dice que la API no se ha usado en el proyecto o está deshabilitada. La habilitas en la página APIs and services o con gcloud services enable compute.googleapis.com (o run.googleapis.com, container.googleapis.com, etc.). gcloud services list --enabled muestra lo que está activo. Habilitar una API no cuesta nada por sí solo; pagas por los recursos que luego creas.

Habilitar algunas APIs también crea cuentas de servicio administradas por Google, llamadas agentes de servicio (service agents), que permiten que el servicio actúe en tu proyecto, por ejemplo para adjuntar discos o descargar imágenes. No las borres ni les quites sus roles, o el servicio dejará de funcionar.

Cuando ya no necesites un proyecto, ciérralo con gcloud projects delete PROJECT_ID. Entra en un período de eliminación pendiente durante el cual un propietario puede restaurarlo; después de eso se elimina definitivamente y su ID no se puede reutilizar.

Términos clave

Project ID (ID del proyecto)
El identificador permanente y único a nivel global que eliges al crearlo y que usas en comandos y APIs.
Project number (número del proyecto)
Un identificador numérico permanente que asigna Google, usado en algunos nombres de cuentas de servicio.
Project name (nombre del proyecto)
Una etiqueta de visualización que se puede cambiar y que no necesita ser única.
Service agent (agente de servicio)
Una cuenta de servicio administrada por Google que un servicio de Google Cloud usa para actuar sobre los recursos de tu proyecto.
Ejemplo real

Una desarrolladora crea un proyecto con el ID shop-dev-4821 y el nombre Shop Dev. Cuando ejecuta gcloud run deploy, gcloud ofrece habilitar la API de Cloud Run. Más tarde el equipo cambia el nombre del proyecto a Shop Development en la consola; todos los scripts siguen funcionando porque hacen referencia al ID del proyecto, que no cambia.

Consejo para el examen: Si una pregunta dice que el equipo quiere cambiar un ID de proyecto, la respuesta es que no se puede; solo puede cambiar el nombre para mostrar. Un error de 'API not enabled' se corrige habilitando la API, no otorgando más roles de IAM.

Comprueba lo que sabes

¿Qué identificador del proyecto aparece en la dirección de correo de la cuenta de servicio predeterminada de Compute Engine?

El número del proyecto, como en PROJECT_NUMBER-compute@developer.gserviceaccount.com.

¿Cómo listas las APIs habilitadas en el proyecto actual?

Ejecuta gcloud services list --enabled, o revisa APIs and services en la consola.
