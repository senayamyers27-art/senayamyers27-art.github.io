Regiones, zonas y etiquetas: ubicar recursos y organizarlos para los informes de costos

La infraestructura de Google Cloud se divide en regiones y zonas. Una región es una ubicación geográfica específica, como us-central1 (Iowa), europe-west1 (Bélgica) o asia-northeast1 (Tokio). Cada región contiene varias zonas, como us-central1-a, us-central1-b y us-central1-c. Una zona es un área de despliegue aislada con su propia energía, refrigeración y red, así que una falla en una zona no debería afectar a las demás de la misma región.

Los recursos tienen un alcance que influye en cómo diseñas para la disponibilidad. Los recursos zonales, como una VM o un persistent disk zonal, viven en una sola zona. Los recursos regionales, como un grupo de instancias administrado regional, un persistent disk regional, un clúster regional de GKE o una instancia de Cloud SQL con alta disponibilidad, abarcan varias zonas de una región. Los recursos globales, como las redes VPC, las reglas de firewall, los balanceadores de carga globales y las imágenes, no están atados a una región. Cloud Storage agrega ubicaciones multirregionales y birregionales (multi-region y dual-region).

Al elegir una región, piensa en la latencia hacia los usuarios, la residencia de datos y el cumplimiento normativo, la disponibilidad de los productos y tipos de máquina que necesitas, y el precio, que varía según la región. Para la resiliencia, distribuye las cargas de trabajo en varias zonas; para la recuperación ante desastres, considera una segunda región.

Las etiquetas (labels) son pares clave-valor, como env=prod o team=payments, que adjuntas a recursos como VMs, discos, buckets y proyectos. Se usan para organizar, filtrar y, sobre todo, desglosar costos, porque las etiquetas aparecen en los informes de facturación y en la exportación de facturación a BigQuery. Las claves y los valores deben estar en minúsculas y seguir reglas simples de caracteres. Estableces las etiquetas en la consola o con comandos como gcloud compute instances update web-1 --update-labels=env=prod.

No confundas las etiquetas con las etiquetas de red (network tags). Las network tags son cadenas simples en las VMs que se usan para dirigir reglas de firewall y rutas. También existen las etiquetas de Resource Manager (resource manager tags), que se definen de forma central a nivel de organización o de proyecto y se pueden usar en condiciones de IAM y en políticas de la organización. Para los informes de costos por aplicación, la respuesta habitual son las labels.

Términos clave

Region (región)
Un área geográfica independiente, como us-central1, compuesta por zonas.
Zone (zona)
Un área de despliegue aislada dentro de una región, como us-central1-a.
Label (etiqueta)
Un par clave-valor en un recurso que se usa para organizar, filtrar y reportar costos.
Network tag (etiqueta de red)
Una cadena en una VM que se usa para aplicarle reglas de firewall y rutas.
Ejemplo real

Una empresa de medios ejecuta su API de video en instancias de tres zonas de europe-west4 para que la caída de una zona no la deje fuera de servicio. Cada recurso lleva las etiquetas app=video y env=prod, así que finanzas puede ver el costo mensual de la app en la exportación de facturación aunque comparta proyectos con otras apps.

Consejo para el examen: Una falla de zona implica distribuir en varias zonas de una región; una falla de región implica otra región. Para el costo por aplicación, elige labels, no network tags.

Comprueba lo que sabes

Nombra un recurso global, uno regional y uno zonal.

Global: una red VPC. Regional: una subred o un persistent disk regional. Zonal: una instancia de VM.

¿Para qué se usan las network tags?

Para dirigir reglas de firewall y rutas a VMs específicas.
