Cloud Audit Logs: registros Admin Activity, Data Access, System Event y Policy Denied

Los Cloud Audit Logs responden la pregunta 'quién hizo qué, dónde y cuándo' sobre los recursos de Google Cloud. Se escriben en Cloud Logging y cada entrada registra el principal (usuario o cuenta de servicio), el método llamado (como v1.compute.instances.delete), el recurso, la hora, la dirección IP de quien llamó y si la solicitud tuvo éxito. Son esenciales para las investigaciones de seguridad, el cumplimiento normativo y la solución de problemas.

Hay cuatro tipos. Los registros de auditoría Admin Activity registran las llamadas a la API que modifican la configuración o los metadatos: crear o eliminar una VM, cambiar una política de IAM, actualizar la configuración de un bucket. Siempre están habilitados, no se pueden desactivar y son gratuitos. Los registros de auditoría System Event registran las acciones realizadas por los sistemas de Google y no por los usuarios, como la migración en vivo de una VM o la autorreparación de un grupo de instancias administrado; también están siempre activos y son gratuitos.

Los registros de auditoría Data Access registran las llamadas a la API que leen la configuración o los metadatos (ADMIN_READ) y las llamadas que leen o escriben datos proporcionados por el usuario (DATA_READ y DATA_WRITE), como leer un objeto en Cloud Storage o consultar una tabla. Pueden ser muy voluminosos, por eso están deshabilitados de forma predeterminada en la mayoría de los servicios, y pagas por el volumen de logs que supere las asignaciones gratuitas. BigQuery es la excepción notable, donde los registros Data Access están habilitados de forma predeterminada. Los habilitas por servicio, para un proyecto, una carpeta o una organización, en la consola en IAM and admin > Audit logs, o en la sección auditConfigs de la política de IAM. Puedes eximir a principales específicos.

Los registros de auditoría Policy Denied se escriben cuando Google Cloud deniega el acceso debido a una política de seguridad, como un perímetro de VPC Service Controls. Se generan de forma predeterminada, y puedes excluirlos si es necesario.

Para ver los registros de auditoría necesitas el rol adecuado: Logs Viewer (roles/logging.viewer) puede ver los registros Admin Activity y System Event, mientras que los registros Data Access se consideran sensibles y requieren Private Logs Viewer (roles/logging.privateLogViewer). En Logs Explorer, filtra por logName que contenga cloudaudit.googleapis.com, o usa protoPayload.methodName y protoPayload.authenticationInfo.principalEmail.

Términos clave

Admin Activity audit logs
Registros siempre activos de las llamadas a la API que cambian la configuración o los metadatos de los recursos.
Data Access audit logs
Registros de lecturas de configuración y de lecturas o escrituras de datos de usuario, desactivados de forma predeterminada en la mayoría de los servicios.
System Event audit logs
Registros de acciones realizadas por los sistemas de Google, como la migración en vivo.
Private Logs Viewer
El rol necesario para ver los registros de auditoría Data Access.
Ejemplo real

Después de que desaparece una VM de producción, un ingeniero filtra los registros Admin Activity por un methodName que contenga instances.delete y encuentra el principal y la hora en menos de un minuto. Para cumplir con una nueva regulación, la empresa luego habilita los registros de auditoría DATA_READ para Cloud Storage solo en su proyecto de expedientes de pacientes, manteniendo bajo control el costo de los logs.

Consejo para el examen: Quién cambió o eliminó algo: Admin Activity (siempre activo). Quién leyó datos: Data Access, que primero hay que habilitar (excepto en BigQuery). Ver los registros Data Access requiere Private Logs Viewer.

Comprueba lo que sabes

¿Puedes deshabilitar los registros de auditoría Admin Activity?

No. Siempre se escriben y no se pueden desactivar.

¿Por qué los registros Data Access están deshabilitados de forma predeterminada en la mayoría de los servicios?

Pueden tener un volumen muy alto y agregar costo, así que los habilitas donde se necesiten.
