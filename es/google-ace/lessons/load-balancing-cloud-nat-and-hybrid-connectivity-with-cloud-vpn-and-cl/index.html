Balanceo de carga, Cloud NAT y conectividad híbrida con Cloud VPN y Cloud Interconnect

Cloud Load Balancing es una familia de balanceadores de carga administrados. Elige uno haciéndote tres preguntas: ¿el tráfico es HTTP(S) (capa 7) u otro TCP/UDP (capa 4)?, ¿viene de internet (externo) o del interior de tu red (interno)?, y ¿es global o regional?

Los Application Load Balancers son proxies de capa 7 para HTTP y HTTPS. El Application Load Balancer externo global da una sola dirección IP anycast en todo el mundo, enruta por host y ruta con URL maps, termina TLS con certificados administrados por Google o propios, y se integra con Cloud CDN y Cloud Armor. Los Application Load Balancers regionales externos e internos atienden el tráfico en una región. Los Network Load Balancers son de capa 4. Los Proxy Network Load Balancers terminan TCP (opcionalmente con descarga de TLS); los Network Load Balancers de paso (passthrough) reenvían paquetes sin actuar como proxy, así que los backends ven la IP original del cliente, y admiten TCP, UDP y otros protocolos. Los Network Load Balancers de paso internos distribuyen el tráfico dentro de una VPC.

Todos usan verificaciones de estado y servicios de backend que apuntan a grupos de instancias administrados, grupos de endpoints de red (network endpoint groups, para pods de GKE o servicios serverless como Cloud Run), o buckets para contenido estático.

Cloud NAT proporciona acceso saliente a internet para recursos sin direcciones IP externas, como VMs privadas y nodos de GKE, mientras bloquea las conexiones entrantes no solicitadas. Se configura por región en un Cloud Router y no usa una VM proxy. Private Google Access, una configuración de subred, permite que las VMs sin IPs externas lleguen a las APIs de Google, como Cloud Storage, sin NAT.

Para conectar redes locales (on-premises), Cloud VPN crea túneles IPsec a través de internet. HA VPN usa dos interfaces y, con dos túneles bien configurados, ofrece un SLA de disponibilidad del 99.99%; usa Cloud Router para intercambiar rutas dinámicamente con BGP. La VPN se configura rápido, pero está limitada por el rendimiento de internet. Cloud Interconnect proporciona conexiones privadas de alto ancho de banda: Dedicated Interconnect es un enlace físico directo con Google en una instalación de colocación, y Partner Interconnect pasa por un proveedor de servicios cuando no puedes llegar a una instalación de Google o necesitas menos ancho de banda. El tráfico de Interconnect no cruza el internet público, pero no está cifrado de forma predeterminada. El peering directo y el peering con operadores (direct y carrier peering) llegan a los servicios públicos de Google, como Workspace, no a tu VPC.

Términos clave

Application Load Balancer
Un balanceador de carga proxy de capa 7 para HTTP(S) con enrutamiento basado en URL.
Passthrough Network Load Balancer (Network Load Balancer de paso)
Un balanceador de carga de capa 4 que reenvía paquetes y conserva las direcciones IP de los clientes.
Cloud NAT
Traducción de direcciones de red administrada que da a los recursos privados acceso saliente a internet.
HA VPN
VPN IPsec de alta disponibilidad hacia Google Cloud que usa dos interfaces y BGP mediante Cloud Router.
Ejemplo real

Un minorista sirve su tienda en línea mediante un Application Load Balancer externo global con Cloud CDN, ejecuta VMs de backend sin IPs externas que descargan actualizaciones a través de Cloud NAT, y conecta sus almacenes mediante HA VPN mientras se aprovisiona un Partner Interconnect.

Consejo para el examen: HTTP(S) más global más enrutamiento por URL o CDN: Application Load Balancer externo global. VMs privadas que necesitan internet saliente: Cloud NAT. Rápido de configurar a través de internet: HA VPN. Privado y de alto ancho de banda: Interconnect.

Comprueba lo que sabes

¿Qué balanceadores de carga conservan la IP de origen del cliente hacia el backend?

Los Network Load Balancers de paso, porque no actúan como proxy de las conexiones.

¿Sobre qué hay que configurar Cloud NAT?

Sobre un Cloud Router en la región donde están los recursos privados.
