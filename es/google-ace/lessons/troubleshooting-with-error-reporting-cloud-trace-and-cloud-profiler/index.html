Solución de problemas con Error Reporting, Cloud Trace y Cloud Profiler

Además de las métricas y los logs, Google Cloud Observability incluye tres herramientas enfocadas en problemas de aplicaciones. Cada una responde una pregunta distinta, y las preguntas del examen suelen depender de relacionar la pregunta con la herramienta.

Error Reporting responde '¿qué errores está lanzando mi app y son nuevos?'. Analiza los logs de Cloud Run, Cloud Run functions, App Engine, GKE y Compute Engine (y los errores informados mediante su API o sus bibliotecas cliente), reconoce los stack traces y agrupa las excepciones similares con conteos, horas de primera y última aparición y stack traces de muestra. Puede notificarte cuando aparece un nuevo grupo de errores, y puedes marcar los errores como reconocidos o resueltos. En muchos servicios serverless funciona automáticamente sin cambios en el código, siempre que las excepciones se escriban en los logs.

Cloud Trace responde '¿en qué se va el tiempo de una solicitud?'. Es un sistema de rastreo distribuido: cada solicitud obtiene un trace compuesto por spans para cada paso, como el frontend, una llamada a otro servicio y una consulta a la base de datos, con sus tiempos. Muestra las distribuciones de latencia y te ayuda a encontrar el servicio lento en una cadena de microservicios. Muchos servicios de Google y balanceadores de carga producen datos de rastreo, y tú instrumentas tu propio código con OpenTelemetry para enviar spans.

Cloud Profiler responde '¿qué funciones de mi código usan más CPU o memoria?'. Toma muestras continuamente de las aplicaciones en ejecución en producción con poca sobrecarga y muestra flame graphs del tiempo de CPU, el uso del heap y otros recursos por función. Agregas el agente o la biblioteca de perfilado a tu aplicación. Úsalo para reducir el costo y la latencia optimizando las rutas de código más usadas.

Una investigación típica las combina: una política de alertas se dispara por latencia alta, Cloud Trace muestra que el tiempo se gasta en un servicio, Cloud Profiler muestra qué función está usando la CPU ahí, Logs Explorer muestra las entradas de log relacionadas y Error Reporting muestra si una nueva excepción comenzó con la última versión. Otras ayudas incluyen las recomendaciones de Active Assist, como ajustar el tamaño de las VMs inactivas, y las Connectivity Tests de Network Intelligence Center para problemas de rutas de red.

Términos clave

Error Reporting
Un servicio que agrupa y cuenta las excepciones de las aplicaciones a partir de los logs y alerta sobre las nuevas.
Cloud Trace
Un servicio de rastreo distribuido que muestra la latencia de las solicitudes desglosada en spans.
Cloud Profiler
Un perfilador continuo de baja sobrecarga que muestra el uso de CPU y memoria por función.
Span
Una operación cronometrada dentro de un trace, como una llamada a otro servicio.
Ejemplo real

La latencia del checkout aumenta después de una versión. Cloud Trace muestra que la mayor parte del tiempo está en el servicio de precios, Cloud Profiler revela que una función de análisis de JSON consume la mayor parte de su CPU, y Error Reporting muestra un nuevo grupo de excepciones de timeout que comenzó con la misma versión. El equipo revierte y corrige el analizador.

Consejo para el examen: Excepciones agrupadas: Error Reporting. Solicitudes lentas entre servicios: Cloud Trace. Puntos críticos de CPU o memoria a nivel de código: Cloud Profiler.

Comprueba lo que sabes

¿Qué herramienta muestra qué microservicio agrega más latencia a una solicitud?

Cloud Trace, mediante los spans de cada trace.

¿Error Reporting requiere cambios de código en Cloud Run?

Por lo general no; lee las excepciones con stack traces de los logs del servicio.
