Administrar VMs de Compute Engine: iniciar, detener, redimensionar, SSH con OS Login y reenvío TCP de IAP

La administración diaria de VMs se reduce principalmente a un puñado de comandos de gcloud. gcloud compute instances list muestra las VMs con sus zonas, estado e IPs. gcloud compute instances stop web-1 --zone=us-central1-a y start detienen e inician una VM; una VM detenida no genera cargos por vCPUs ni memoria, pero sigues pagando sus discos y cualquier IP estática reservada. suspend guarda el estado de la memoria en disco y resume la restaura. reset es un reinicio forzado, como desconectar el cable de corriente.

Para cambiar el tipo de máquina de una VM, primero debes detenerla: gcloud compute instances set-machine-type web-1 --machine-type=e2-standard-4, y luego volver a iniciarla. Los discos se pueden agrandar mientras la VM está en ejecución (gcloud compute disks resize), y después amplías el sistema de archivos dentro del sistema operativo. También puedes agregar etiquetas, metadatos como scripts de inicio y network tags sin volver a crear la VM. Mover una VM a otra zona o región generalmente implica crear una VM nueva a partir de una snapshot o de una machine image.

Para SSH, gcloud compute ssh web-1 se encarga de las claves por ti. Hay dos formas de autorizar las claves. Con las claves SSH basadas en metadatos, las claves públicas se guardan en los metadatos del proyecto o de la instancia, y cualquiera cuya clave esté ahí puede iniciar sesión hasta que alguien la quite. Con OS Login, las cuentas de Linux están vinculadas a identidades de Google: el acceso se controla con roles de IAM como Compute OS Login (usuario normal) o Compute OS Admin Login (sudo), puede exigir verificación en dos pasos, y quitar el rol a una persona o deshabilitar su cuenta elimina su acceso. Habilítalo con la clave de metadatos enable-oslogin=TRUE en el proyecto o la instancia. OS Login es lo recomendado para las organizaciones.

Muchas VMs no deberían tener direcciones IP externas. Para llegar a ellas sin un bastion host ni una VPN, usa el reenvío TCP de Identity-Aware Proxy (IAP TCP forwarding): gcloud compute ssh web-1 --tunnel-through-iap. IAP envuelve la conexión SSH en HTTPS y verifica el permiso de IAM del usuario (IAP-secured Tunnel User) antes de reenviar el tráfico. Tu firewall debe permitir el tráfico de entrada en tcp:22 (o 3389 para RDP) desde el rango de IAP, 35.235.240.0/20. La misma técnica funciona para RDP hacia VMs Windows.

Cuando el propio SSH está roto, la consola serie (serial console) te permite interactuar con el proceso de arranque y el prompt de inicio de sesión de la VM, si está habilitada. La salida del puerto serie (gcloud compute instances get-serial-port-output) muestra los logs de arranque y es seguro leerla sin habilitar el acceso interactivo.

Términos clave

OS Login
Una función que vincula las cuentas de Linux de las VMs a identidades de Google y controla el acceso SSH con roles de IAM.
IAP TCP forwarding (reenvío TCP de IAP)
Tunelizar SSH, RDP u otro tráfico TCP a través de Identity-Aware Proxy hacia VMs sin IPs externas.
35.235.240.0/20
El rango de origen que usa el reenvío TCP de IAP, que las reglas de firewall deben permitir.
Serial console (consola serie)
Acceso interactivo al puerto serie de una VM para solucionar problemas cuando el inicio de sesión normal falla.
Ejemplo real

Un equipo de seguridad quita todas las IPs externas de sus VMs, habilita OS Login a nivel de proyecto y otorga al grupo de operaciones Compute OS Admin Login e IAP-secured Tunnel User. Ahora los administradores se conectan con gcloud compute ssh --tunnel-through-iap, y cuando alguien deja la empresa su acceso termina en cuanto se deshabilita su cuenta.

Consejo para el examen: Sin IP externa y sin bastion: reenvío TCP de IAP con una regla de firewall para 35.235.240.0/20. Acceso vinculado a IAM y eliminado automáticamente: OS Login. Cambiar el tipo de máquina requiere detener la VM.

Comprueba lo que sabes

¿Qué debes hacer antes de cambiar el tipo de máquina de una VM?

Detener la VM, cambiar el tipo y luego volver a iniciarla.

¿Qué rol de IAM permite a un usuario conectarse mediante el reenvío TCP de IAP?

IAP-secured Tunnel User, junto con una regla de firewall que permita 35.235.240.0/20.
