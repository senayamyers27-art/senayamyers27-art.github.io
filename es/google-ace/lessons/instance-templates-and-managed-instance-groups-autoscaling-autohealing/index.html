Plantillas de instancia y grupos de instancias administrados: escalado automático, autorreparación y actualizaciones progresivas

Una plantilla de instancia (instance template) es una definición guardada de VM: tipo de máquina, imagen de arranque, discos, red, metadatos como un script de inicio, etiquetas y cuenta de servicio. Las plantillas son inmutables; para cambiar cualquier cosa creas una plantilla nueva. Creas una con gcloud compute instance-templates create web-v2 --machine-type=e2-medium --image-family=debian-12 --image-project=debian-cloud --tags=web --metadata-from-file=startup-script=start.sh.

Un grupo de instancias administrado (managed instance group, MIG) usa una plantilla para crear y mantener un conjunto de VMs idénticas. Un MIG zonal mantiene sus VMs en una zona; un MIG regional las distribuye en varias zonas de una región, lo que protege contra una falla de zona y se recomienda para producción. Los grupos de instancias no administrados (unmanaged instance groups), en cambio, son solo colecciones de VMs existentes, posiblemente diferentes, que administras tú mismo; pueden estar detrás de un balanceador de carga, pero no escalan automáticamente ni se autorreparan.

El escalado automático (autoscaling) agrega y quita VMs según una señal: la utilización promedio de CPU, la capacidad de servicio del balanceador de carga, una métrica de Cloud Monitoring o un calendario. Estableces el número mínimo y máximo de instancias y un objetivo, por ejemplo 60% de CPU. Un período de enfriamiento (inicialización) le indica al autoescalador que ignore los datos de las VMs nuevas mientras arrancan. Por ejemplo: gcloud compute instance-groups managed set-autoscaling web-mig --region=us-central1 --min-num-replicas=2 --max-num-replicas=10 --target-cpu-utilization=0.6.

La autorreparación (autohealing) usa una verificación de estado de la aplicación, como una solicitud HTTP a /healthz. Si una VM falla la verificación repetidamente, el MIG la vuelve a crear a partir de la plantilla. Configura un retraso inicial lo bastante largo para que la app arranque, o el grupo podría volver a crear VMs antes de que estén listas. Esto es distinto de las verificaciones de estado del balanceador de carga, que solo dejan de enviar tráfico a los backends no saludables.

Para cambiar el software o el tipo de máquina, crea una plantilla nueva e inicia una actualización. Una actualización progresiva (rolling update) reemplaza las VMs gradualmente, controlada por maxSurge (cuántas VMs adicionales se pueden crear) y maxUnavailable (cuántas pueden estar fuera de línea). También puedes hacer un canary estableciendo una segunda plantilla para un tamaño objetivo, como el 10% del grupo, y revertir actualizando a la plantilla anterior. Como las VMs de un MIG se pueden volver a crear en cualquier momento, mantenlas sin estado y guarda los datos en bases de datos o en Cloud Storage; los MIGs con estado (stateful MIGs) existen para casos especiales.

Términos clave

Instance template (plantilla de instancia)
Una definición inmutable de las propiedades de una VM que se usa para crear VMs en un grupo de instancias administrado.
Managed instance group (grupo de instancias administrado)
Un grupo de VMs idénticas creadas a partir de una plantilla que admite escalado automático, autorreparación y actualizaciones progresivas.
Autohealing (autorreparación)
Volver a crear las VMs que fallan una verificación de estado de la aplicación.
Rolling update (actualización progresiva)
Reemplazar gradualmente las VMs de un grupo por otras de una plantilla nueva, controlado por maxSurge y maxUnavailable.
Ejemplo real

Una tienda en línea ejecuta un MIG regional de 3 a 20 servidores web que escala automáticamente al 65% de CPU. Para aplicar parches al sistema operativo, el equipo crea una imagen nueva, crea la plantilla web-v8 e inicia una actualización progresiva con maxSurge 3 y maxUnavailable 0, así la capacidad nunca baja durante el cambio.

Consejo para el examen: No puedes editar una plantilla: plantilla nueva y luego actualización progresiva. La autorreparación necesita una verificación de estado. Los grupos no administrados no escalan automáticamente.

Comprueba lo que sabes

¿Cuál es la diferencia entre un MIG zonal y uno regional?

Un MIG zonal mantiene las VMs en una zona; un MIG regional las distribuye en varias zonas de una región para mayor disponibilidad.

¿Por qué configurar un retraso inicial en la autorreparación?

Para que el MIG no vuelva a crear VMs que todavía están arrancando y aún no han pasado la verificación de estado.
