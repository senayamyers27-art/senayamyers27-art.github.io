Dominio 1: System management (23%)

Consejos para el examen

  • Relaciona el síntoma con la etapa: si no aparece el menú de GRUB, apunta al firmware o al cargador de arranque; un error de 'cannot find root' apunta al initramfs o al argumento root=; y un arranque que se detiene en un shell de emergencia después de cargar el kernel suele apuntar a unidades de systemd o a /etc/fstab.
  • Recuerda que /proc y /sys no ocupan espacio en disco y se reconstruyen en cada arranque; las preguntas del examen sobre ver la CPU, la memoria o los parámetros del kernel suelen apuntar a /proc, mientras que los detalles de dispositivos y controladores apuntan a /sys.
  • Cuidado con la trampa de la persistencia: los cambios hechos con modprobe y sysctl -w desaparecen al reiniciar; la persistencia viene de /etc/modprobe.d o /etc/modules-load.d para los módulos y de /etc/sysctl.d para los parámetros del kernel.
  • Si una pregunta dice que el enlace debe funcionar entre particiones o hacia un directorio, la respuesta es un enlace simbólico; si dice que los datos deben seguir accesibles después de eliminar el nombre original, la respuesta es un enlace duro.
  • Si un escenario pregunta por qué un servidor se quedó en modo de emergencia después de que un disco se retiró o cambió de nombre, sospecha de una entrada de fstab por nombre de dispositivo sin nofail; la solución es usar UUID= y agregar nofail donde corresponda.
  • Si un LV se extendió pero df todavía muestra el tamaño anterior, el sistema de archivos no se redimensionó; la solución es resize2fs (ext4) o xfs_growfs (XFS), o usar lvextend -r la próxima vez.
  • A las preguntas del examen les encanta la trampa de reducir XFS: XFS no se puede achicar, así que reducirlo requiere respaldar, recrear el sistema de archivos más pequeño y restaurar.
  • Si una pregunta pide qué cambio sobrevive a un reinicio, ip addr add es la respuesta equivocada; los cambios persistentes vienen de los perfiles de conexión de nmcli, del YAML de netplan o de los archivos de configuración de la distribución.
  • uniq solo elimina duplicados adyacentes, así que las respuestas que envían datos sin ordenar a uniq -c suelen ser incorrectas; busca sort antes de uniq.
  • Relaciona con cuidado las letras de tar: z es gzip, j es bzip2, J es xz; y c, x y t son crear, extraer y listar.
  • virsh destroy solo fuerza el apagado de un invitado, como desconectar el cable de corriente; no elimina la VM. Para eliminar la definición se usa virsh undefine.

Términos clave

UEFI
Unified Extensible Firmware Interface: firmware moderno que arranca ejecutables EFI desde una EFI System Partition y admite Secure Boot.
ESP (EFI System Partition)
Partición de sistema EFI: una pequeña partición FAT, normalmente montada en /boot/efi, que contiene los cargadores de arranque UEFI.
GRUB2
El cargador de arranque estándar de Linux; se configura mediante /etc/default/grub y un grub.cfg generado.
initramfs
Un sistema de archivos raíz temporal y comprimido que se carga en RAM y contiene los controladores y scripts necesarios para montar el sistema de archivos raíz real.
dracut / mkinitramfs
Herramientas que construyen la imagen initramfs: dracut en la familia Red Hat y SUSE, mkinitramfs/update-initramfs en la familia Debian.
systemd target (target de systemd)
Una unidad que agrupa otras unidades en un estado del sistema, como multi-user.target o graphical.target, y reemplaza a los runlevels de SysV.
FHS
Filesystem Hierarchy Standard: la convención que define el propósito de los directorios de nivel superior de Linux.
/etc
El directorio para los archivos de configuración específicos del host.
/var
El directorio para datos variables como logs, colas, cachés y estado de aplicaciones.
/proc
Un sistema de archivos virtual que expone información de procesos y del kernel, incluidos los parámetros ajustables bajo /proc/sys.
/sys
Sysfs, un sistema de archivos virtual que expone dispositivos, controladores y objetos del kernel.
/dev
El directorio de archivos de dispositivo, como /dev/sda y /dev/null, mantenido por udev.
Kernel module (módulo del kernel)
Una pieza cargable de código del kernel (archivo .ko), como un controlador, que se puede insertar o quitar mientras el sistema funciona.
modprobe
Carga o quita (-r) un módulo junto con sus dependencias, leyendo las opciones de /etc/modprobe.d.
modinfo
Muestra la ruta del archivo de un módulo, su descripción, dependencias y parámetros admitidos.
Blacklist (lista negra)
Una directiva de modprobe.d que impide que un módulo se cargue automáticamente por su alias.
sysctl
Una herramienta para ver y establecer parámetros de tiempo de ejecución del kernel bajo /proc/sys; los valores persistentes van en /etc/sysctl.d/*.conf.
Inode (inodo)
La estructura en disco que guarda los metadatos de un archivo y los punteros a sus datos; las entradas de directorio asocian nombres con números de inodo.
Hard link (enlace duro)
Una entrada de directorio adicional para el mismo inodo; no puede cruzar sistemas de archivos y sobrevive a la eliminación de los otros nombres.
Symbolic link (enlace simbólico)
Un archivo separado que guarda una ruta hacia un destino; puede cruzar sistemas de archivos, pero se rompe si se elimina el destino.
mtime vs ctime
mtime cambia cuando cambia el contenido del archivo; ctime cambia cuando cambian metadatos como permisos o propiedad.
find -exec
Una acción de find que ejecuta un comando sobre cada archivo encontrado, donde {} se reemplaza por el nombre del archivo.
GPT
GUID Partition Table: esquema de particionado moderno que admite discos muy grandes, muchas particiones y una tabla de respaldo.
MBR
Master Boot Record: esquema de particionado heredado limitado a cuatro particiones primarias y discos de aproximadamente 2 TiB.
UUID
Un identificador único guardado en un sistema de archivos, usado en /etc/fstab para que los montajes no dependan de los nombres de dispositivo.
nofail
Una opción de fstab que permite que el arranque continúe si el dispositivo no está presente.
noexec
Una opción de fstab que impide ejecutar binarios guardados en ese sistema de archivos.
PV / VG / LV
Physical volume (un disco preparado para LVM), volume group (un conjunto de PV) y logical volume (un volumen utilizable tomado de ese conjunto).
lvextend -r
Extiende un volumen lógico y redimensiona su sistema de archivos en el mismo comando.
vgextend
Agrega un nuevo volumen físico a un grupo de volúmenes existente para aumentar su espacio libre.
mdadm
La herramienta de Linux para crear, monitorear y administrar arreglos RAID por software (/dev/mdN).
/proc/mdstat
Un archivo de estado del kernel que muestra cada arreglo RAID por software, sus miembros y el progreso de cualquier reconstrucción.
Journaling (registro por diario)
Una técnica en la que un sistema de archivos registra los cambios de metadatos pendientes para poder recuperarse de forma consistente tras una caída.
XFS
Un sistema de archivos con journaling de alto rendimiento, predeterminado en RHEL, que puede crecer en línea pero no puede reducirse.
Btrfs
Un sistema de archivos copy-on-write con subvolúmenes, instantáneas, sumas de verificación y soporte multidispositivo integrado.
resize2fs
Agranda o reduce un sistema de archivos ext2/3/4 para ajustarlo a su dispositivo.
xfs_growfs
Agranda un sistema de archivos XFS montado, indicado por su punto de montaje.
df vs du
df informa el espacio libre y usado por sistema de archivos; du suma el espacio usado por archivos y directorios.
iproute2 (ip)
El conjunto moderno para ver y cambiar interfaces, direcciones, rutas y vecinos; los cambios no son persistentes.
nmcli
Cliente de línea de comandos para NetworkManager que administra perfiles de conexión persistentes.
netplan
El sistema de configuración de red de Ubuntu basado en YAML que genera la configuración para systemd-networkd o NetworkManager.
/etc/resolv.conf
Lista los servidores DNS y los dominios de búsqueda que usa el resolvedor del sistema.
nsswitch.conf
Define el orden de las fuentes de búsqueda (files, dns, sss, etc.) para hosts, usuarios, grupos y más.
File descriptor (descriptor de archivo)
Un número que identifica un flujo abierto: 0 es stdin, 1 es stdout y 2 es stderr.
Pipe (tubería)
El operador | que envía la salida estándar de un comando a la entrada estándar de otro.
export
Marca una variable del shell para que se pase a los procesos hijos como variable de entorno.
sed
Un editor de flujo usado principalmente para buscar y reemplazar y para filtrar líneas; -i edita archivos en el lugar.
awk
Un lenguaje de análisis de patrones que divide las líneas en campos ($1, $2 ...) para filtrar y generar informes.
tar
Herramienta de archivado que agrupa archivos conservando los metadatos; -c crear, -x extraer, -t listar, -f archivo, con -z/-j/-J para gzip/bzip2/xz.
rsync
Herramienta de sincronización incremental de archivos que transfiere solo las diferencias, localmente o por SSH.
dd
Herramienta de copia a nivel de bloques usada para imágenes de disco y para escribir dispositivos en bruto; if= entrada, of= salida.
cpio
Archivador que recibe listas de archivos por stdin, comúnmente combinado con find; se usa en initramfs y en el contenido de los RPM.
xz
Un compresor que normalmente logra mayor compresión que gzip o bzip2 a costa de la velocidad.
KVM
Kernel-based Virtual Machine: módulos del kernel que usan las extensiones de virtualización de la CPU para convertir a Linux en un hipervisor.
QEMU
El emulador que proporciona el hardware virtual y, junto con KVM, ejecuta invitados a una velocidad casi nativa.
libvirt / virsh
Una API y un demonio de administración para hipervisores, y su cliente de línea de comandos para controlar invitados.
qcow2
Un formato de disco de QEMU con aprovisionamiento delgado que admite instantáneas, archivos base y compresión.
virtio
Controladores de dispositivos paravirtualizados que dan a los invitados E/S rápida de disco y red.

Dominio 2: Services and user management (20%)

Consejos para el examen

  • La trampa clásica es usermod -G sin -a: reemplaza todos los grupos suplementarios. Cuando una pregunta dice 'agregar a un grupo sin afectar las pertenencias existentes', la respuesta incluye -aG.
  • Recuerda qué archivo guarda qué: los hashes y el envejecimiento viven en /etc/shadow, los miembros suplementarios de los grupos viven en /etc/group, y los valores predeterminados para las cuentas nuevas vienen de /etc/login.defs y /etc/skel.
  • Conoce la diferencia de alcance: stop afecta el ahora, disable afecta el arranque y mask bloquea la unidad por completo hasta que se desenmascare.
  • Cuenta los campos: un crontab de usuario tiene cinco campos de tiempo antes del comando, pero /etc/crontab y los archivos de /etc/cron.d agregan un nombre de usuario como sexto campo.
  • La escalada correcta es primero SIGTERM y SIGKILL solo si el proceso lo ignora; y un zombi no se puede matar en absoluto, ya que ya está muerto, así que te ocupas de su padre.
  • apt update solo actualiza las listas de paquetes; apt upgrade es lo que realmente instala versiones más nuevas. Muchas respuestas incorrectas confunden los dos.
  • El orden estándar para compilar desde el código fuente es ./configure, make, make install; normalmente solo el último paso necesita root.
  • Lee los mapeos de -p como host:contenedor. Una pregunta que muestra -p 8443:443 significa que los clientes se conectan al host en el 8443 para llegar al 443 del contenedor.
  • Ten claros los tres roles: un pod ejecuta contenedores, un deployment mantiene en ejecución la cantidad correcta de pods y los actualiza, y un service les da una dirección de red estable.
  • En el reenvío de rsyslog, una @ significa UDP y dos @@ significan TCP; y en journalctl, -b -1 significa el arranque anterior.

Términos clave

UID / GID
Identificadores numéricos de usuario y de grupo que el kernel usa realmente para la propiedad y las comprobaciones de permisos.
Primary group (grupo primario)
El grupo asignado a un usuario en /etc/passwd y que se asigna a los archivos que el usuario crea.
Supplementary group (grupo suplementario)
Grupos adicionales a los que pertenece un usuario, listados en /etc/group, que otorgan acceso extra.
usermod -aG
Agrega un usuario a grupos suplementarios sin quitar sus pertenencias existentes.
chage
Comando que muestra y establece el envejecimiento de la contraseña y la expiración de la cuenta de un usuario.
/etc/passwd
Base de datos de cuentas legible por todos con siete campos: nombre, x, UID, GID, GECOS, directorio personal y shell.
/etc/shadow
Archivo solo para root que guarda los hashes de contraseña y los campos de envejecimiento y expiración.
/etc/group
Base de datos de grupos que lista el nombre del grupo, el GID y los miembros suplementarios.
/etc/skel
Directorio plantilla cuyos archivos se copian en los directorios personales de los usuarios nuevos.
/etc/login.defs
Configuración de valores predeterminados para las herramientas de cuentas, como rangos de UID y envejecimiento de contraseñas.
Unit (unidad)
Un objeto de configuración de systemd como .service, .socket, .timer, .mount o .target.
enable vs start
enable configura una unidad para que arranque en el boot; start la ejecuta ahora. Ninguno implica al otro.
mask
Enlaza una unidad a /dev/null para que no pueda iniciarse manualmente ni como dependencia.
Drop-in override (anulación drop-in)
Un archivo .conf en /etc/systemd/system/<unit>.d/ que anula configuraciones seleccionadas de una unidad.
daemon-reload
Le indica a systemd que vuelva a leer los archivos de unidad después de que cambien en disco.
crontab
Una tabla de tareas programadas por usuario, editada con crontab -e, que usa cinco campos de tiempo más un comando.
at
Programa un comando para que se ejecute una vez en un momento futuro; se administra con atq y atrm y lo ejecuta atd.
systemd timer (timer de systemd)
Una unidad .timer que activa una unidad .service correspondiente según un horario.
OnCalendar
Una configuración del timer que define horarios de reloj, como Mon..Fri *-*-* 02:30:00.
Persistent=true
Una opción del timer que ejecuta una tarea perdida en la siguiente oportunidad después de un periodo de inactividad.
PID / PPID
ID de proceso e ID del proceso padre, usados para identificar procesos y sus relaciones.
SIGTERM vs SIGKILL
SIGTERM (15) le pide a un proceso que termine limpiamente; SIGKILL (9) fuerza la terminación y no se puede capturar.
Nice value (valor nice)
Un ajuste de prioridad de -20 (más favorecido) a 19 (menos favorecido); solo root puede bajarlo.
Zombie process (proceso zombi)
Un proceso terminado cuyo estado de salida todavía no ha sido recogido por su padre; se muestra con el estado Z.
nohup
Ejecuta un comando inmune a las señales de colgado (hangup) para que siga ejecutándose después de que el usuario cierre sesión.
rpm / dpkg
Herramientas de paquetes de bajo nivel que instalan y consultan archivos de paquete individuales sin resolver dependencias.
dnf / apt
Gestores de paquetes de alto nivel que descargan desde repositorios y resuelven dependencias.
Repository (repositorio)
Un servidor o ubicación que aloja paquetes y metadatos firmados, configurado en /etc/yum.repos.d o /etc/apt/sources.list(.d).
rpm -qf / dpkg -S
Consultas que informan qué paquete instalado es dueño de un archivo determinado.
dnf provides
Busca en los repositorios el paquete que proporciona un archivo o comando determinado.
make
Una herramienta de compilación que lee un Makefile y ejecuta los pasos para compilar software; make install lo copia a su lugar.
./configure
Un script que verifica las dependencias de compilación y genera un Makefile, a menudo con --prefix para establecer la ruta de instalación.
pip
El instalador de paquetes de Python, que conviene usar dentro de un entorno virtual.
Flatpak
Un formato de empaquetado universal aislado, principalmente para aplicaciones de escritorio, que comúnmente se instala desde Flathub.
Snap
El formato de paquetes aislados de Canonical administrado por snapd, con actualizaciones automáticas y modos de confinamiento.
Image (imagen)
Una plantilla de solo lectura y en capas (nombre:etiqueta) a partir de la cual se crean contenedores.
Container (contenedor)
Un proceso aislado que se ejecuta a partir de una imagen con su propia capa escribible, compartiendo el kernel del host.
Port publishing (publicación de puertos)
La opción -p host:contenedor que asocia un puerto del host con un puerto dentro del contenedor.
Volume (volumen)
Almacenamiento persistente administrado por el motor de contenedores o montado desde el host, que sobrevive a la eliminación del contenedor.
Rootless container (contenedor sin root)
Un contenedor ejecutado por un usuario sin privilegios, como lo permite Podman, que limita el impacto de un compromiso.
Pod
La unidad más pequeña de Kubernetes: uno o más contenedores que comparten una dirección IP y volúmenes.
Deployment
Un objeto que declara una imagen y una cantidad de réplicas, mantiene esa cantidad de pods y realiza actualizaciones progresivas.
Service
Una IP virtual estable y un nombre DNS que balancean el tráfico hacia los pods seleccionados por etiquetas.
kubectl
El cliente de línea de comandos que se comunica con el servidor de API de Kubernetes.
Declarative configuration (configuración declarativa)
Describir el estado deseado en manifiestos y dejar que los controladores concilien el clúster para que coincida.
systemd-journald
El servicio de registro de systemd que guarda datos de log estructurados que se consultan con journalctl.
rsyslog
Un demonio syslog que enruta los mensajes por facility y prioridad hacia archivos o servidores remotos.
Facility and priority (facility y prioridad)
Categorías de syslog para el origen del mensaje (auth, cron, kern, local0...) y su gravedad (de debug a emerg).
logrotate
Una utilidad que rota, comprime y depura archivos de log según las reglas de /etc/logrotate.d.
Persistent journal (journal persistente)
Almacenamiento del journal en /var/log/journal que sobrevive a los reinicios.

Dominio 3: Security (18%)

Consejos para el examen

  • Calcula los resultados de umask restando de 666 para archivos y de 777 para directorios; una umask de 027 da archivos 640 y directorios 750.
  • Relaciona las letras con las posiciones: s en la posición del usuario es SUID, s en la del grupo es SGID, t en la de otros es el sticky bit; un + después de los permisos significa que existen ACL.
  • La respuesta de buenas prácticas casi nunca es 'deshabilitar SELinux'; busca en su lugar restorecon, semanage fcontext, semanage port o setsebool -P, y usa el modo permissive solo temporalmente para confirmar que SELinux es la causa.
  • Si una regla de firewalld funciona ahora pero desaparece después de reiniciar, se agregó sin --permanent; si una regla --permanent todavía no tiene efecto, no se recargó el firewall.
  • El orden importa al endurecer: confirma que el inicio de sesión con claves funciona antes de deshabilitar PasswordAuthentication, y mantén abierta una sesión existente mientras pruebas.
  • Elige siempre visudo (o visudo -f para un drop-in) en lugar de editar sudoers con un editor normal, y recuerda que un % en sudoers significa un grupo.
  • Recuerda los indicadores de control de PAM: requisite falla de inmediato, required falla al final de la pila y sufficient puede terminar la pila antes con éxito.
  • Una suma de verificación solo demuestra integridad; una firma demuestra integridad y autenticidad. El cifrado (LUKS, TLS) es lo que proporciona confidencialidad.
  • Después de actualizaciones legítimas hay que actualizar la línea base de AIDE, o cada binario parcheado aparecerá como un cambio y las intrusiones reales se esconderán entre el ruido.
  • Conoce el trío de herramientas de auditoría: auditctl administra las reglas, ausearch encuentra eventos específicos y aureport produce resúmenes.

Términos clave

Octal permissions (permisos octales)
Notación numérica en la que r=4, w=2, x=1 se suman para usuario, grupo y otros, como 750.
Symbolic permissions (permisos simbólicos)
Notación que usa u, g, o, a con +, - o = y r, w, x para cambiar bits específicos.
Execute on a directory (ejecución en un directorio)
Permiso para entrar a un directorio y acceder a su contenido por nombre.
chown
Cambia el propietario y/o el grupo propietario de un archivo, por ejemplo chown alice:devs file.
umask
Una máscara de bits de permiso que se quitan de los valores predeterminados (666 archivos, 777 directorios) al crear archivos nuevos.
SUID
Bit especial (4000) que hace que un ejecutable se ejecute con los privilegios de su propietario; se muestra como s en la posición de ejecución del usuario.
SGID
Bit especial (2000) que ejecuta un programa con el grupo del archivo o hace que los archivos nuevos de un directorio hereden su grupo.
Sticky bit
Bit de directorio (1000) que permite solo al propietario del archivo, al propietario del directorio o a root eliminarlo o renombrarlo.
ACL (lista de control de acceso)
Access control list: entradas de permiso adicionales por usuario o por grupo, administradas con setfacl y getfacl.
ACL mask (máscara de ACL)
La entrada de ACL que limita los permisos efectivos máximos de los usuarios nombrados, los grupos nombrados y el grupo propietario.
MAC (control de acceso obligatorio)
Mandatory access control: una política aplicada por el sistema que restringe los programas sin importar la propiedad de los archivos.
SELinux context (contexto de SELinux)
La etiqueta user:role:type:level de archivos y procesos; el tipo determina la mayoría de las decisiones de la política targeted.
restorecon
Restablece las etiquetas SELinux de los archivos a los valores predeterminados definidos en la política.
SELinux boolean (booleano de SELinux)
Un interruptor de la política que se cambia con setsebool (-P para persistente) para permitir comportamientos opcionales.
AppArmor profile (perfil de AppArmor)
Una política basada en rutas para un programa, que se ejecuta en modo enforce o complain.
netfilter
El framework del kernel de Linux que realiza el filtrado de paquetes y NAT, configurado por las herramientas de firewall.
firewalld zone (zona de firewalld)
Un nivel de confianza con nombre, con sus propios servicios y puertos permitidos, vinculado a interfaces o direcciones de origen.
--permanent
Opción de firewall-cmd que guarda un cambio en la configuración; surte efecto después de --reload.
ufw
Uncomplicated Firewall, la interfaz simplificada de Ubuntu con reglas persistentes.
nftables
El framework moderno de reglas de netfilter, administrado con nft, que reemplaza a iptables.
Key-based authentication (autenticación por claves)
Inicio de sesión con un par de claves privada/pública, donde el servidor guarda la clave pública en authorized_keys.
ssh-copy-id
Copia una clave pública al authorized_keys de una cuenta remota con los permisos correctos.
PermitRootLogin
Configuración de sshd_config que controla si root puede iniciar sesión directamente (no, prohibit-password, yes).
PasswordAuthentication
Configuración de sshd_config que habilita o deshabilita los inicios de sesión con contraseña.
sshd -t
Prueba la configuración del demonio SSH en busca de errores antes de recargarlo.
sudo
Ejecuta un comando como otro usuario (root de forma predeterminada) según las reglas de sudoers, con autenticación por usuario y registro.
visudo
Edita de forma segura los archivos sudoers con bloqueo y verificación de sintaxis.
/etc/sudoers.d
Directorio de archivos sudoers drop-in para reglas modulares.
su -
Cambia a otro usuario con un entorno de inicio de sesión completo, y requiere la contraseña de ese usuario.
polkit
Un framework de autorización que permite a procesos sin privilegios solicitar acciones privilegiadas específicas a los servicios del sistema.
PAM
Pluggable Authentication Modules: el framework que apila módulos para realizar la autenticación de los servicios de Linux.
pam_faillock
Módulo PAM que bloquea las cuentas después de intentos de autenticación fallidos repetidos.
pam_pwquality
Módulo PAM que exige reglas de complejidad y longitud de contraseñas.
SSSD
Demonio que proporciona identidades y autenticación desde LDAP, Kerberos o Active Directory, con caché.
Kerberos TGT
Ticket-granting ticket emitido por el KDC después del inicio de sesión y usado para solicitar tickets de servicio.
Hash
Un resumen de longitud fija y de un solo sentido de unos datos, usado para detectar cambios; SHA-256 es una opción común.
GPG signature (firma GPG)
Una firma creada con una clave privada que cualquiera con la clave pública puede verificar, demostrando origen e integridad.
X.509 certificate (certificado X.509)
Un documento firmado por una CA que vincula una clave pública con una identidad, usado por TLS.
CSR
Certificate signing request: contiene una clave pública y datos de identidad que se envían a una CA para que los firme.
LUKS
Linux Unified Key Setup: el formato estándar para el cifrado completo de dispositivos de bloques, administrado con cryptsetup.
Attack surface (superficie de ataque)
El conjunto total de servicios, software e interfaces que un atacante podría intentar explotar.
Secure Boot
Una función de UEFI que solo ejecuta cargadores de arranque y kernels firmados, bloqueando el código de arranque manipulado.
MOK
Machine Owner Key: una clave registrada por el usuario que se usa con shim para confiar en módulos o kernels firmados adicionales.
AIDE
Advanced Intrusion Detection Environment: un verificador de integridad de archivos que compara los archivos con una base de datos de referencia.
Patch management (gestión de parches)
El proceso de probar y aplicar regularmente actualizaciones de software para corregir vulnerabilidades.
auditd
El demonio de auditoría de Linux que registra eventos de seguridad a nivel del kernel en /var/log/audit/audit.log.
Audit rule key (-k) (clave de regla de auditoría)
Una etiqueta asociada a las reglas de auditoría para que los eventos coincidentes se puedan buscar con ausearch -k.
auid
Audit user ID: la identidad de inicio de sesión original registrada en los eventos de auditoría incluso después de sudo o su.
CIS Benchmark
Una guía de configuración basada en consenso con recomendaciones de endurecimiento puntuadas para una plataforma específica.
OpenSCAP
Un conjunto de herramientas de código abierto que evalúa sistemas contra perfiles de seguridad SCAP y genera informes.

Dominio 4: Automation, orchestration, and scripting (17%)

Consejos para el examen

  • Busca espacios alrededor de = en las asignaciones y variables sin comillas; ambos son errores deliberados comunes en las preguntas de scripts del examen.
  • Los números se comparan con -eq, -lt y -gt dentro de [ ], mientras que = y != comparan cadenas; usar > dentro de corchetes simples crea un archivo en silencio en lugar de comparar.
  • Conoce lo que atrapa cada opción del modo estricto: -e los comandos fallidos, -u las variables no definidas y pipefail los fallos ocultos dentro de las tuberías.
  • Elige el tipo de datos según la necesidad: un set para unicidad y comparaciones, un dict para búsquedas por clave-valor, una lista cuando importan el orden y los duplicados.
  • En ramas compartidas, elige revert en lugar de reset y merge en lugar de rebase; los comandos que reescriben el historial son solo para trabajo local no publicado.
  • Ansible no usa agentes y funciona por push a través de SSH; cuando una pregunta lo compara con Puppet o Chef, esa diferencia suele ser la clave.
  • Distingue los modelos: Puppet está basado en agentes y funciona por pull; Ansible no usa agentes y funciona por push; OpenTofu/Terraform aprovisionan infraestructura, y plan previsualiza mientras que apply realiza los cambios.
  • En GitOps, la respuesta para revertir casi siempre es 'revertir el commit en Git', no 'corregirlo directamente en el servidor o el clúster'.
  • Cuando una pregunta pida la mejor práctica con scripts generados por IA, elige la respuesta que combine revisión, pruebas en un entorno que no sea de producción y credenciales fuera de los prompts, no la que ejecuta el resultado directamente.

Términos clave

Shebang
La primera línea #! de un script que nombra al intérprete, como #!/bin/bash.
Positional parameters (parámetros posicionales)
$1, $2, etc., que contienen los argumentos pasados a un script; $# los cuenta y $@ los lista.
Parameter expansion (expansión de parámetros)
Sintaxis ${...} que proporciona valores predeterminados, recorta patrones o sustituye texto en variables.
Command substitution (sustitución de comandos)
Sintaxis $(comando) que se reemplaza a sí misma por la salida del comando.
Exit status ($?) (estado de salida)
El resultado de 0 a 255 del último comando, donde 0 significa éxito.
test / [ ]
Evalúa condiciones de archivos, cadenas y enteros y devuelve un estado de salida que usan if y while.
[[ ]]
La prueba extendida de Bash con coincidencia de patrones, regex (=~) y un manejo más seguro de variables.
case
Una instrucción de múltiples ramas que compara un valor con patrones glob y termina con esac.
local
Declara una variable con alcance limitado a la función actual.
Associative array (arreglo asociativo)
Un arreglo de Bash indexado por cadenas, declarado con declare -A.
set -e
Hace que el script salga cuando un comando falla fuera de un contexto condicional.
set -u
Trata el uso de una variable no definida como un error.
pipefail
Hace que el estado de salida de una tubería refleje el comando fallido más a la derecha, no solo el último comando.
trap
Registra un comando que se ejecuta ante señales o al salir el script (EXIT), a menudo para limpieza.
ShellCheck
Un analizador estático que señala errores y patrones riesgosos en scripts de shell.
list vs tuple (lista vs tupla)
Una lista es una secuencia ordenada y mutable; una tupla es ordenada pero inmutable.
set (conjunto)
Una colección desordenada de elementos únicos que admite unión, intersección y diferencia.
dict (diccionario)
Una asociación de claves únicas con valores, como {'ssh': 22}.
venv
La herramienta integrada de Python para crear entornos virtuales aislados con sus propios paquetes.
requirements.txt
Un archivo que lista las versiones de los paquetes para que pip pueda reproducir un entorno.
Commit
Una instantánea registrada de los cambios preparados, con autor, marca de tiempo, mensaje y referencia al padre.
Staging area (área de preparación)
El índice donde se preparan los cambios con git add antes de hacer commit.
merge vs rebase
merge une historiales, posiblemente con un commit de fusión; rebase vuelve a aplicar los commits sobre una nueva base para un historial lineal.
git revert
Crea un commit nuevo que deshace uno anterior sin reescribir el historial.
Pull request
Un flujo de trabajo de la plataforma que solicita la revisión y fusión de una rama, normalmente condicionado por verificaciones de CI.
Inventory (inventario)
La lista de hosts y grupos administrados, con variables opcionales, a los que apunta Ansible.
Ad hoc command (comando ad hoc)
Un comando ansible puntual que ejecuta un solo módulo contra hosts, como ansible all -m ping.
Playbook
Un archivo YAML de plays y tareas que describe el estado deseado de los hosts.
Idempotence (idempotencia)
La propiedad de que ejecuciones repetidas producen el mismo resultado y no hacen cambios una vez que el estado es correcto.
ansible-vault
Una herramienta que cifra archivos o cadenas que contienen secretos usados por Ansible.
Agent-based configuration management (gestión de configuración basada en agentes)
Herramientas como Puppet o Chef en las que un agente en cada nodo obtiene y aplica el estado deseado desde un servidor.
Puppet catalog (catálogo de Puppet)
La descripción compilada del estado deseado que un servidor Puppet envía a un agente, basada en manifiestos y en los facts del nodo.
Infrastructure as code (infraestructura como código)
Definir la infraestructura en archivos con control de versiones que las herramientas usan para crear y cambiar recursos.
plan
Comando de OpenTofu/Terraform que previsualiza los cambios necesarios para alcanzar la configuración declarada.
State file (archivo de estado)
El registro de OpenTofu/Terraform de los recursos administrados, guardado de forma segura, a menudo en un backend remoto con bloqueo.
Continuous integration (integración continua)
Compilar y probar automáticamente cada cambio fusionado en un repositorio compartido.
Continuous delivery vs deployment (entrega vs despliegue continuo)
La entrega mantiene cada cambio aprobado listo para publicarse con una puerta manual; el despliegue lo publica automáticamente.
Pipeline
Una definición con control de versiones de etapas y trabajos que compilan, prueban y despliegan código.
GitOps
Un modelo operativo en el que Git contiene el estado deseado declarado y agentes automatizados concilian los sistemas para que coincidan.
Drift (desviación)
Diferencias entre el sistema en vivo y la configuración declarada, normalmente por cambios manuales.
Human in the loop (humano en el circuito)
La práctica de que una persona revise y apruebe el resultado generado por IA antes de usarlo.
Hallucination (alucinación)
Resultado de IA que suena plausible pero es incorrecto, como una opción de comando o un paquete que no existen.
Prompt data leakage (fuga de datos por prompts)
Exposición de información sensible al incluirla en prompts enviados a un servicio de IA externo.
Sanitization (sanitización)
Reemplazar secretos y detalles identificables con marcadores antes de compartir texto o código.
Acceptable use policy (política de uso aceptable)
Las reglas de una organización sobre qué herramientas se pueden usar y qué datos se pueden compartir con ellas.

Dominio 5: Troubleshooting (22%)

Consejos para el examen

  • Si df -h muestra espacio libre pero las escrituras fallan, piensa en inodos (df -i). Si df muestra lleno pero du no encuentra los datos, piensa en archivos eliminados pero abiertos (lsof +L1).
  • Una carga promedio alta no significa automáticamente CPU alta; revisa wa e iostat, porque en Linux los procesos atascados esperando E/S también cuentan para la carga.
  • Trabaja de abajo hacia arriba: enlace e IP, puerta de enlace, IP remota, nombre DNS y luego el puerto del servicio. Si las IP funcionan pero los nombres fallan, céntrate en el DNS y en nsswitch en lugar del enrutamiento.
  • El modo de emergencia justo después de un cambio de almacenamiento casi siempre significa /etc/fstab; un kernel panic justo después de una actualización normalmente significa arrancar el kernel anterior desde GRUB.
  • Los códigos de salida en los 200 vienen de systemd antes de que se ejecute el programa, así que revisa el archivo de unidad (rutas, User=, directorios); los códigos pequeños como 1 normalmente significan que la propia aplicación informó un error en sus logs.
  • Cuando el acceso falla pero los permisos parecen correctos en un sistema con SELinux, revisa ausearch -m avc antes de tocar chmod; la solución normalmente es restorecon, semanage o un booleano, nunca deshabilitar SELinux.
  • Un arreglo que muestra [U_] en /proc/mdstat está degradado: todavía funciona, pero el miembro fallido debe reemplazarse antes de que falle otro disco.
  • Los errores de certificado 'not yet valid' en un solo host, los mensajes de Kerberos 'clock skew too great' y los códigos MFA rechazados son señales clásicas de un reloj del sistema incorrecto.
  • Los errores GPG de repositorio se corrigen importando la clave correcta y verificada, no estableciendo gpgcheck=0 ni confiando en repositorios sin firmar.
  • Revisa primero los logs y luego inspecciona: podman logs explica la mayoría de las caídas de aplicaciones, y podman inspect revela los códigos de salida, las terminaciones por OOM, los montajes y los mapeos de puertos.

Términos clave

Inode exhaustion (agotamiento de inodos)
Un sistema de archivos que se queda sin inodos, lo que bloquea los archivos nuevos aunque quede espacio libre; se ve con df -i.
Deleted-but-open file (archivo eliminado pero abierto)
Un archivo cuyo nombre se eliminó mientras un proceso todavía lo mantiene abierto, por lo que su espacio no se libera.
lsof +L1
Lista los archivos abiertos con un número de enlaces menor que uno, revelando archivos eliminados que todavía consumen espacio.
fsck / e2fsck
Herramientas de verificación y reparación para sistemas de archivos de la familia ext, que se ejecutan sobre dispositivos desmontados.
xfs_repair
La herramienta de reparación para sistemas de archivos XFS; fsck no se usa con XFS.
Load average (carga promedio)
Número promedio de procesos ejecutables más ininterrumpibles en 1, 5 y 15 minutos; compáralo con la cantidad de núcleos.
I/O wait (wa) (espera de E/S)
Tiempo de CPU inactiva mientras espera que termine la E/S de almacenamiento.
Available memory (memoria disponible)
La estimación de free de la memoria que pueden usar nuevas cargas de trabajo sin swap, incluida la caché recuperable.
sar
Herramienta de sysstat que registra e informa estadísticas históricas de CPU, memoria, disco y red.
OOM killer
Mecanismo del kernel que mata un proceso cuando el sistema se queda sin memoria, registrado en el log del kernel.
Default route (ruta predeterminada)
La entrada de la tabla de enrutamiento (default via ...) que se usa para los destinos que no coinciden con ninguna ruta más específica.
ss
Herramienta de estadísticas de sockets que lista puertos en escucha y conexiones; ss -tulpn es la forma común.
dig
Herramienta de consulta DNS que muestra los registros, los TTL y qué servidor respondió.
mtr
Combina traceroute y ping para mostrar de forma continua la pérdida y la latencia por salto.
tcpdump
Herramienta de captura de paquetes de línea de comandos que usa filtros como host, port y protocolo.
GRUB rescue prompt (prompt de rescate de GRUB)
Un shell mínimo de GRUB que se muestra cuando GRUB no encuentra su configuración o sus módulos.
Previous kernel (kernel anterior)
Un kernel instalado más antiguo que se puede seleccionar en GRUB para recuperarse de una actualización del kernel defectuosa.
rescue.target
Un target de systemd monousuario con los sistemas de archivos locales montados y servicios mínimos.
emergency.target
El target de systemd más mínimo, con el sistema de archivos raíz en solo lectura y casi ningún servicio.
chroot
Cambia el directorio raíz aparente para que puedas reparar un sistema instalado desde un medio de rescate.
203/EXEC
Estado de salida de systemd que significa que el programa de ExecStart no se pudo ejecutar (falta, no es ejecutable o tiene un intérprete incorrecto).
start-limit-hit
Un resultado de falla que significa que la unidad se reinició demasiadas veces en un intervalo corto; se limpia con systemctl reset-failed.
Requires= / After=
Configuraciones de dependencia de unidades: Requires establece una dependencia fuerte; After solo establece el orden de arranque.
Address already in use
Un error de bind que indica que otro proceso ya está escuchando en ese puerto.
Config test (prueba de configuración)
La verificación de sintaxis propia de una aplicación, como nginx -t o sshd -t, que se ejecuta antes de reiniciar un servicio.
AVC denial (denegación AVC)
Un mensaje del access vector cache de SELinux que registra una operación bloqueada por la política, guardado en el log de auditoría.
StrictModes
Una configuración de sshd (activada de forma predeterminada) que rechaza las claves cuando los permisos del directorio personal, de .ssh o de authorized_keys son demasiado abiertos.
namei -l
Muestra la propiedad y los permisos de cada componente de una ruta, revelando dónde se bloquea el acceso.
faillock
Comando que muestra y restablece los bloqueos por inicios de sesión fallidos registrados por pam_faillock.
passwd -S
Muestra el estado de la contraseña de un usuario, incluido si está bloqueada.
dmesg
Muestra el búfer circular del kernel, que contiene mensajes de detección de hardware, de controladores y de errores.
lspci -k
Lista los dispositivos PCI junto con el controlador del kernel vinculado a cada uno.
SMART
Self-Monitoring, Analysis and Reporting Technology: datos de salud informados por la unidad que se leen con smartctl.
Degraded array (arreglo degradado)
Un arreglo RAID que sigue sirviendo datos después de perder un miembro, pero sin su redundancia normal.
Reallocated sectors (sectores reasignados)
Sectores defectuosos del disco reasignados a sectores de reserva; un contador en aumento indica una unidad que está fallando.
NTP
Network Time Protocol, que sincroniza los relojes con servidores de hora por el puerto UDP 123.
chrony
La implementación común de NTP en Linux (demonio chronyd, cliente chronyc, /etc/chrony.conf).
timedatectl
Herramienta de systemd para ver y establecer la hora, la zona horaria y si la sincronización NTP está habilitada.
RTC
Real-time clock: el reloj de hardware que conserva la hora mientras el sistema está apagado.
Clock skew (desfase de reloj)
La diferencia entre los relojes de distintos sistemas; Kerberos tolera de forma predeterminada solo unos cinco minutos.
Dependency conflict (conflicto de dependencias)
Una situación en la que las versiones de paquetes requeridas no se pueden satisfacer junto con lo que está instalado.
apt --fix-broken install
Repara instalaciones incompletas o rotas instalando las dependencias faltantes.
NO_PUBKEY
Un error de apt que significa que la clave de firma del repositorio no es de confianza en el sistema.
apt-mark hold
Impide que un paquete de la familia Debian se actualice hasta que se libere.
dnf versionlock
Un complemento de dnf que fija paquetes a versiones específicas en sistemas basados en RPM.
Exit code 137 (código de salida 137)
Un proceso de contenedor terminado por SIGKILL (128 + 9), con frecuencia por límites de memoria o por el OOM killer.
podman ps -a
Lista todos los contenedores, incluidos los detenidos, con su estado e información de salida.
registries.conf
Configuración que controla los registros, incluida la forma en que se resuelven los nombres cortos de imagen.
podman system df
Resume el uso de disco de imágenes, contenedores y volúmenes.
:Z volume option (opción de volumen :Z)
Vuelve a etiquetar un directorio del host montado con una etiqueta SELinux privada para que el contenedor pueda acceder a él.
