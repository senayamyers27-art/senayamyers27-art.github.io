Permisos: chmod simbólico y octal, chown, umask

Los permisos de archivos de Linux deciden quién puede leer, cambiar o ejecutar cada archivo. Todo archivo tiene un propietario (usuario), un grupo propietario y tres conjuntos de bits de permiso para el usuario (u), el grupo (g) y los otros (o). El kernel los comprueba en orden: si eres el propietario, solo se aplican los bits de usuario; si no, si estás en el grupo, solo se aplican los bits de grupo; en caso contrario se aplican los bits de otros. Hacer esto bien es la base de la seguridad en Linux, y el examen espera que conviertas rápidamente entre notaciones.

En una salida de ls -l como -rwxr-x---, el primer carácter es el tipo de archivo y los nueve caracteres siguientes son tres tríos: usuario rwx, grupo r-x, otros ---. Para los archivos, r permite leer el contenido, w permite modificarlo y x permite ejecutarlo. Para los directorios, los significados cambian: r permite listar los nombres, w permite crear, borrar y renombrar entradas (junto con x) y x permite entrar al directorio y acceder a los archivos que contiene. Eso significa que borrar un archivo depende del permiso de escritura sobre el directorio, no sobre el propio archivo.

La notación octal asigna r=4, w=2 y x=1 y los suma por trío: rwx=7, rw-=6, r-x=5, r--=4. Así, chmod 755 script.sh da rwxr-xr-x, chmod 640 app.conf da rw-r----- y chmod 600 ~/.ssh/id_ed25519 da rw-------. La notación octal siempre establece todos los bits a la vez. La notación simbólica cambia bits concretos y deja el resto como está: chmod u+x script.sh añade ejecución para el propietario, chmod g-w file quita la escritura del grupo, chmod o=r file deja a los otros exactamente con lectura, chmod a+r file añade lectura para todos y chmod ug=rw,o= file establece varios a la vez. -R aplica los cambios de forma recursiva; con ella, la X mayúscula añade ejecución solo a los directorios y a los archivos que ya tienen ejecución para alguien, lo que evita volver ejecutable cada archivo de datos: chmod -R u=rwX,g=rX,o= /srv/data.

chown cambia la propiedad, y solo root puede ceder archivos a otro usuario. chown alice file cambia el propietario, chown alice:devs file cambia propietario y grupo, chown :devs file cambia solo el grupo (igual que chgrp devs file) y chown -R actúa de forma recursiva. Un propietario normal solo puede cambiar el grupo de un archivo a un grupo al que pertenezca.

umask establece los permisos predeterminados de los archivos recién creados enmascarando bits. Los archivos parten de 666 (sin ejecución) y los directorios de 777, y se quitan los bits de la umask. Una umask de 022 da archivos 644 y directorios 755; una umask de 027 da 640 y 750; 077 da 600 y 700. Ejecuta umask para ver el valor actual (umask -S lo muestra en forma simbólica) y umask 027 para cambiarlo en la sesión. Los valores predeterminados de todo el sistema provienen de /etc/login.defs, /etc/profile o los archivos de inicio del shell, y los servicios de systemd pueden establecer UMask= en su unidad. Una umask más estricta es un paso de endurecimiento sencillo para servidores que guardan datos sensibles. Cuando a un usuario se le niega el acceso, revisa los permisos a lo largo de toda la ruta: cada directorio padre necesita x para que el usuario pueda llegar al archivo. namei -l /path/to/file muestra en una sola vista los permisos de cada componente.

Veamos un ejemplo práctico. Un directorio de proyecto compartido debe ser legible y escribible por el grupo devs, pero invisible para todos los demás. Ejecutas chown -R root:devs /srv/project y chmod -R u=rwX,g=rwX,o= /srv/project, de modo que los directorios quedan en 770 y los archivos en 660 sin que los archivos de datos obtengan ejecución. Estableces umask 007 en el perfil del shell del equipo para que los archivos nuevos se creen como 660 y los directorios como 770. Cuando un desarrollador que no está en el grupo informa 'permission denied', namei -l /srv/project/notes.txt muestra que eso es exactamente lo que debe ocurrir. Un nuevo miembro del equipo en devs puede leer los archivos después de volver a iniciar sesión.

Errores comunes: usar chmod -R 777 para 'arreglar' el acceso, lo que permite que cualquiera cambie o reemplace archivos; ejecutar chmod -R 755 sobre datos y volver ejecutable cada archivo (usa X); olvidar que borrar un archivo requiere escritura sobre el directorio; revisar solo el archivo e ignorar el bit x de un directorio padre; y calcular la umask 'restando' cuando los bits se superponen de formas raras. El método seguro es pensarlo como quitar bits: 666 quitando 033 da 644, no 633.

Las preguntas del examen suelen dar una notación y pedir la otra, o dar una umask y pedir el resultado. Convierte cada trío por separado: 750 es rwxr-x---, 644 es rw-r--r--. 'Añadir ejecución solo para el propietario, sin cambiar nada más' es la forma simbólica u+x. 'Establecer permisos exactos' encaja con la octal. 'Cambiar propietario y grupo a la vez' es chown user:group. 'Los archivos nuevos deben ser 640' significa umask 027. 'No se puede abrir un archivo 644' apunta a un directorio padre sin x.

Términos clave

Permisos octales (octal permissions)
Notación numérica en la que r=4, w=2, x=1 se suman para usuario, grupo y otros, como en 750.
Permisos simbólicos (symbolic permissions)
Notación que usa u, g, o, a con +, - o = y r, w, x para cambiar bits concretos.
Ejecución en un directorio
Permiso para entrar en un directorio y acceder a su contenido por nombre.
X mayúscula (capital X)
Un bit simbólico de chmod que añade ejecución solo a directorios y a archivos que ya son ejecutables para alguien.
chown
Cambia el propietario y/o el grupo propietario de un archivo, por ejemplo chown alice:devs file.
umask
Una máscara de bits de permiso que se quitan de los valores predeterminados (666 para archivos, 777 para directorios) al crear archivos nuevos.
Ejemplo real

Un directorio de proyecto compartido debe ser legible y escribible por el grupo devs, pero invisible para todos los demás. Ejecutas chown -R root:devs /srv/project y chmod -R u=rwX,g=rwX,o= /srv/project, y luego estableces umask 007 en el perfil del shell del equipo para que los archivos nuevos se creen como 660 y los directorios como 770.

Consejo para el examen: Calcula los resultados de la umask quitando sus bits de 666 para archivos y de 777 para directorios; una umask de 027 produce archivos 640 y directorios 750.

Comprueba lo que sabes

¿Qué permisos da chmod 750 en forma simbólica?

rwxr-x---: el propietario lee, escribe y ejecuta, el grupo lee y ejecuta, y los otros nada.

Un usuario puede ver los permisos de un archivo, pero obtiene permiso denegado al abrirlo, aunque el archivo es 644. ¿Qué podría estar mal?

A un directorio padre le falta el permiso de ejecución (x) para ese usuario, así que no se puede recorrer la ruta.

Con una umask de 077, ¿qué permisos obtiene un archivo nuevo?

600 (rw-------), porque se quitan todos los bits de grupo y de otros del valor predeterminado 666.

Un usuario sin permiso de escritura sobre un archivo aún puede borrarlo. ¿Por qué?

Borrar está controlado por los permisos de escritura y ejecución sobre el directorio que lo contiene, no por los permisos del propio archivo.
