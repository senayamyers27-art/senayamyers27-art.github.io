Permisos: chmod simbólico y octal, chown, umask

Los permisos de archivos de Linux deciden quién puede leer, cambiar o ejecutar cada archivo. Todo archivo tiene un propietario (usuario), un grupo propietario y tres conjuntos de bits de permiso para el usuario (u), el grupo (g) y los demás (o). Configurarlos bien es la base de la seguridad en Linux, y el examen espera que conviertas entre notaciones con rapidez.

En una salida de ls -l como -rwxr-x---, el primer carácter es el tipo de archivo y los nueve siguientes son tres tripletas: usuario rwx, grupo r-x, otros ---. En los archivos, r permite leer el contenido, w permite modificarlo y x permite ejecutarlo. En los directorios los significados cambian: r permite listar los nombres, w permite crear, eliminar y renombrar entradas (junto con x), y x permite entrar al directorio y acceder a los archivos que contiene. Eso significa que eliminar un archivo depende del permiso de escritura sobre el directorio, no sobre el archivo en sí.

La notación octal asigna r=4, w=2 y x=1 y los suma por tripleta: rwx=7, rw-=6, r-x=5, r--=4. Así, chmod 755 script.sh da rwxr-xr-x, chmod 640 app.conf da rw-r----- y chmod 600 ~/.ssh/id_ed25519 da rw-------. La notación octal siempre establece todos los bits a la vez.

La notación simbólica cambia bits específicos y deja el resto como está: chmod u+x script.sh agrega ejecución para el propietario, chmod g-w file quita la escritura al grupo, chmod o=r file deja a los demás exactamente con lectura, chmod a+r file agrega lectura para todos y chmod ug=rw,o= file establece varios a la vez. -R aplica los cambios recursivamente; con esta opción, la X mayúscula agrega ejecución solo a los directorios y a los archivos que ya la tienen, lo que evita volver ejecutable cada archivo de datos: chmod -R u=rwX,g=rX,o= /srv/data.

chown cambia la propiedad, y solo root puede ceder archivos. chown alice file cambia el propietario, chown alice:devs file cambia propietario y grupo, chown :devs file cambia solo el grupo (igual que chgrp devs file) y chown -R es recursivo.

umask establece los permisos predeterminados de los archivos recién creados enmascarando (quitando) bits. Los archivos parten de 666 (sin ejecución) y los directorios de 777, y se quitan los bits de la umask. Una umask de 022 da archivos 644 y directorios 755; una umask de 027 da 640 y 750; 077 da 600 y 700. Ejecuta umask para ver el valor actual y umask 027 para cambiarlo en la sesión. Los valores predeterminados de todo el sistema vienen de /etc/login.defs, /etc/profile o los archivos de inicio del shell, y los servicios de systemd pueden establecer UMask= en su unidad. Una umask más estricta es un paso sencillo de endurecimiento para servidores que guardan datos sensibles.

Cuando a un usuario se le niega el acceso, revisa los permisos a lo largo de toda la ruta: cada directorio padre necesita x para que el usuario pueda llegar al archivo. namei -l /ruta/al/archivo muestra los permisos de cada componente en una sola vista.

Términos clave

Octal permissions (permisos octales)
Notación numérica en la que r=4, w=2, x=1 se suman para usuario, grupo y otros, como 750.
Symbolic permissions (permisos simbólicos)
Notación que usa u, g, o, a con +, - o = y r, w, x para cambiar bits específicos.
Execute on a directory (ejecución en un directorio)
Permiso para entrar a un directorio y acceder a su contenido por nombre.
chown
Cambia el propietario y/o el grupo propietario de un archivo, por ejemplo chown alice:devs file.
umask
Una máscara de bits de permiso que se quitan de los valores predeterminados (666 archivos, 777 directorios) al crear archivos nuevos.
Ejemplo real

Un directorio de proyecto compartido debe ser legible y escribible por el grupo devs, pero invisible para todos los demás. Ejecutas chown -R root:devs /srv/project y chmod -R u=rwX,g=rwX,o= /srv/project, y luego estableces umask 007 en el perfil de shell del equipo para que los archivos nuevos se creen como 660 y los directorios como 770.

Consejo para el examen: Calcula los resultados de umask restando de 666 para archivos y de 777 para directorios; una umask de 027 da archivos 640 y directorios 750.

Comprueba lo que sabes

¿Qué permisos da chmod 750 en forma simbólica?

rwxr-x---: el propietario lee/escribe/ejecuta, el grupo lee/ejecuta, los demás nada.

Un usuario puede ver los permisos de un archivo, pero recibe permiso denegado al abrirlo, aunque el archivo es 644. ¿Qué podría estar mal?

A un directorio padre le falta el permiso de ejecución (x) para ese usuario, así que no se puede recorrer la ruta.

Con una umask de 077, ¿qué permisos recibe un archivo nuevo?

600 (rw-------).
