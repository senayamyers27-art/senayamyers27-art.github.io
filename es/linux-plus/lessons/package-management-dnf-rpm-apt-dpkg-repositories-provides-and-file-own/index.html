CompTIA Linux+ XK0-006

Gestión de paquetes: dnf/rpm, apt/dpkg, repositorios, consultas de provides y de propiedad de archivos

El software de Linux se instala como paquetes: archivos que contienen ficheros más metadatos como la versión, las dependencias y los scripts de instalación. Dominan dos familias. Red Hat, Fedora, Rocky, Alma y SUSE usan paquetes RPM (RPM Package Manager), y Debian y Ubuntu usan paquetes .deb. Cada familia tiene una herramienta de bajo nivel que trabaja con archivos de paquete individuales y una herramienta de alto nivel que se comunica con los repositorios y resuelve las dependencias. (La herramienta de alto nivel de SUSE es zypper, pero las consultas de RPM son las mismas.)

En los sistemas RPM, rpm es la herramienta de bajo nivel. rpm -ivh file.rpm instala, rpm -Uvh actualiza, rpm -e name elimina, rpm -qa lista todos los paquetes instalados, rpm -qi name muestra información, rpm -ql name lista los archivos de un paquete, rpm -qf /path/file te dice qué paquete es dueño de un archivo y rpm -V name verifica los archivos instalados contra la base de datos de paquetes, informando cambios en tamaños, permisos o sumas de verificación. rpm no descarga dependencias, por eso en el día a día se usa dnf (el sucesor de yum): dnf install, dnf remove, dnf update (o upgrade), dnf search, dnf info, dnf list installed y dnf history (con dnf history undo para revertir una transacción). dnf install ./pkg.rpm instala un archivo local resolviendo aun así sus dependencias.

En los sistemas Debian, dpkg es la herramienta de bajo nivel: dpkg -i file.deb instala, dpkg -r elimina (-P purga, incluidos los archivos de configuración), dpkg -l lista los paquetes, dpkg -L name lista los archivos de un paquete y dpkg -S /path/file encuentra el paquete dueño. apt es la herramienta de alto nivel: apt update actualiza las listas de paquetes (no actualiza nada instalado), apt upgrade instala versiones más nuevas, apt full-upgrade también permite eliminaciones para resolver cambios de dependencias, y apt install, apt remove, apt purge, apt autoremove, apt search y apt show hacen lo que indican sus nombres. Los comandos más antiguos apt-get y apt-cache siguen funcionando y son comunes en scripts porque su salida es estable. Si un dpkg -i deja dependencias sin resolver, apt install -f las corrige.

Los repositorios son los servidores que alojan los paquetes y sus metadatos. En los sistemas RPM se definen en archivos .repo bajo /etc/yum.repos.d/, con líneas como baseurl=, enabled=1 y gpgcheck=1; dnf repolist los muestra y dnf config-manager puede añadirlos o habilitarlos. En los sistemas Debian se listan en /etc/apt/sources.list y en archivos bajo /etc/apt/sources.list.d/ (las versiones más nuevas usan un formato deb822 .sources). Los paquetes se firman con claves GPG (GNU Privacy Guard), y mantener habilitada la verificación de firmas es un control de seguridad importante contra software manipulado.

Dos tipos de consulta se evalúan mucho. Una consulta de propiedad de archivo pregunta de qué paquete instalado proviene un archivo: rpm -qf /etc/ssh/sshd_config o dpkg -S /usr/bin/ssh. Una consulta de provides pregunta qué paquete, instalado o no, aportaría un archivo o comando: dnf provides '*/bin/dig' (o dnf whatprovides) en sistemas RPM, y apt-file search bin/dig en sistemas Debian después de instalar apt-file y ejecutar apt-file update. Usa la primera para investigar un archivo existente y la segunda para averiguar qué instalar.

Veamos un ejemplo práctico. A un servidor Rocky Linux mínimo le falta el comando dig. dnf provides '*/bin/dig' muestra que proviene del paquete bind-utils, así que ejecutas dnf install bind-utils. Más tarde, mientras auditas un archivo de configuración modificado, rpm -qf /etc/named.conf muestra que pertenece al paquete bind, y rpm -V bind informa que su suma de verificación y su hora de modificación difieren de las originales, señaladas con 5 y T y marcado con c como archivo de configuración. Eso te indica que alguien lo editó, así que lo comparas con el respaldo antes de la siguiente ventana de cambios.

Errores comunes: pensar que apt update instala actualizaciones (solo actualiza las listas); usar rpm -ivh o dpkg -i y luego pelear a mano con las dependencias faltantes; confundir rpm -qf (qué paquete es dueño de este archivo instalado) con dnf provides (qué paquete lo aportaría); deshabilitar gpgcheck para saltarse un error de clave en lugar de importar la clave correcta; mezclar repositorios de distintas versiones de la distribución; y olvidar que dpkg -r conserva los archivos de configuración mientras que dpkg -P o apt purge los eliminan.

Las preguntas del examen a menudo dependen de la familia y del tipo de consulta. 'Qué paquete es dueño de este archivo' es rpm -qf o dpkg -S. 'Qué paquete instalo para obtener este comando' es dnf provides o apt-file search. 'Listar los archivos de un paquete instalado' es rpm -ql o dpkg -L. 'Verificar que los archivos no han cambiado' es rpm -V. 'Actualizar las listas de paquetes' es apt update; 'revertir la última transacción' es dnf history undo. 'Dónde se definen los repositorios' es /etc/yum.repos.d/ o /etc/apt/sources.list.d/.

Términos clave

rpm / dpkg
Herramientas de paquetes de bajo nivel que instalan y consultan archivos de paquete individuales sin resolver dependencias.
dnf / apt
Gestores de paquetes de alto nivel que descargan desde repositorios y resuelven dependencias.
Repositorio (repository)
Un servidor o ubicación que aloja paquetes y metadatos firmados, configurado en /etc/yum.repos.d o /etc/apt/sources.list(.d).
rpm -qf / dpkg -S
Consultas que informan qué paquete instalado es dueño de un archivo determinado.
dnf provides
Busca en los repositorios el paquete que aporta un archivo o comando determinado.
rpm -V
Verifica los archivos de los paquetes instalados contra la base de datos de paquetes e informa los cambios.
gpgcheck
Un ajuste de repositorio que exige firmas GPG válidas en los paquetes antes de instalarlos.
Ejemplo real

A un servidor Rocky Linux mínimo le falta el comando dig. dnf provides '*/bin/dig' muestra que proviene del paquete bind-utils, así que ejecutas dnf install bind-utils. Más tarde, mientras auditas un archivo de configuración modificado, rpm -qf /etc/named.conf muestra que pertenece al paquete bind y rpm -V bind informa que su suma de verificación difiere de la original.

Consejo para el examen: apt update solo actualiza las listas de paquetes; apt upgrade es el que realmente instala versiones más nuevas. Muchas respuestas incorrectas confunden los dos.

Comprueba lo que sabes

¿Qué comando muestra qué paquete instaló /usr/bin/curl en Ubuntu?

dpkg -S /usr/bin/curl, que busca el archivo en la base de datos de paquetes instalados.

¿Por qué usarías dnf install ./pkg.rpm en lugar de rpm -ivh pkg.rpm?

dnf resuelve e instala cualquier dependencia desde los repositorios configurados, mientras que rpm falla si faltan dependencias.

¿Qué hace gpgcheck=1 en un archivo .repo?

Exige que los paquetes de ese repositorio tengan firmas GPG válidas antes de instalarlos.

En un sistema RHEL, ¿cómo averiguas qué paquete aportaría el comando semanage?

dnf provides '*/semanage' (o dnf whatprovides), que busca en los metadatos de los repositorios incluso paquetes no instalados.
