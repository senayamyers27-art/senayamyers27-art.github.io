CompTIA Linux+ XK0-006

Gestión de paquetes: dnf/rpm, apt/dpkg, repositorios, consultas de provides y de propiedad de archivos

El software de Linux se instala como paquetes: archivos que contienen ficheros más metadatos como versión, dependencias y scripts de instalación. Dos familias dominan. Red Hat, Fedora, Rocky, Alma y SUSE usan paquetes RPM (RPM Package Manager), y Debian y Ubuntu usan paquetes .deb. Cada familia tiene una herramienta de bajo nivel que trabaja con archivos de paquete individuales y una herramienta de alto nivel que habla con los repositorios y resuelve dependencias.

En los sistemas RPM, rpm es la herramienta de bajo nivel. rpm -ivh file.rpm instala, rpm -Uvh actualiza, rpm -e nombre elimina, rpm -qa lista todos los paquetes instalados, rpm -qi nombre muestra información, rpm -ql nombre lista los archivos de un paquete, rpm -qf /ruta/archivo te dice qué paquete es dueño de un archivo, y rpm -V nombre verifica los archivos instalados contra la base de datos de paquetes, informando cambios de tamaño, permisos o sumas de verificación. rpm no obtiene dependencias, por eso en el día a día se usa dnf (el sucesor de yum): dnf install, dnf remove, dnf update (o upgrade), dnf search, dnf info, dnf list installed y dnf history (con dnf history undo para revertir una transacción).

En los sistemas Debian, dpkg es la herramienta de bajo nivel: dpkg -i file.deb instala, dpkg -r elimina (-P purga, incluidos los archivos de configuración), dpkg -l lista los paquetes, dpkg -L nombre lista los archivos de un paquete y dpkg -S /ruta/archivo encuentra el paquete dueño. apt es la herramienta de alto nivel: apt update actualiza las listas de paquetes (no actualiza nada instalado), apt upgrade instala versiones más nuevas, apt full-upgrade también permite eliminaciones para resolver cambios de dependencias, apt install, apt remove, apt purge, apt autoremove, apt search y apt show. Los comandos más antiguos apt-get y apt-cache todavía funcionan y son comunes en scripts.

Los repositorios son los servidores que alojan los paquetes y sus metadatos. En los sistemas RPM se definen en archivos .repo bajo /etc/yum.repos.d/, con líneas como baseurl=, enabled=1 y gpgcheck=1; dnf repolist los muestra y dnf config-manager puede agregarlos o habilitarlos. En los sistemas Debian se listan en /etc/apt/sources.list y en archivos bajo /etc/apt/sources.list.d/ (las versiones más nuevas usan un formato deb822 .sources). Los paquetes se firman con claves GPG (GNU Privacy Guard), y mantener habilitada la verificación de firmas es un control de seguridad importante contra software manipulado.

Dos tipos de consulta se evalúan mucho. Una consulta de propiedad de archivo pregunta de qué paquete instalado vino un archivo: rpm -qf /etc/ssh/sshd_config o dpkg -S /usr/bin/ssh. Una consulta de provides pregunta qué paquete, instalado o no, proporcionaría un archivo o comando: dnf provides '*/bin/dig' (o dnf whatprovides) en sistemas RPM, y apt-file search bin/dig en sistemas Debian después de instalar y actualizar apt-file. Usa la primera para investigar un archivo existente y la segunda para saber qué instalar.

Términos clave

rpm / dpkg
Herramientas de paquetes de bajo nivel que instalan y consultan archivos de paquete individuales sin resolver dependencias.
dnf / apt
Gestores de paquetes de alto nivel que descargan desde repositorios y resuelven dependencias.
Repository (repositorio)
Un servidor o ubicación que aloja paquetes y metadatos firmados, configurado en /etc/yum.repos.d o /etc/apt/sources.list(.d).
rpm -qf / dpkg -S
Consultas que informan qué paquete instalado es dueño de un archivo determinado.
dnf provides
Busca en los repositorios el paquete que proporciona un archivo o comando determinado.
Ejemplo real

Un servidor Rocky Linux mínimo no tiene el comando dig. dnf provides '*/bin/dig' muestra que viene del paquete bind-utils, así que ejecutas dnf install bind-utils. Más tarde, al auditar un archivo de configuración modificado, rpm -qf /etc/named.conf muestra que pertenece al paquete bind y rpm -V bind informa que su suma de verificación difiere de la original.

Consejo para el examen: apt update solo actualiza las listas de paquetes; apt upgrade es lo que realmente instala versiones más nuevas. Muchas respuestas incorrectas confunden los dos.

Comprueba lo que sabes

¿Qué comando muestra qué paquete instaló /usr/bin/curl en Ubuntu?

dpkg -S /usr/bin/curl.

¿Por qué usarías dnf install ./pkg.rpm en lugar de rpm -ivh pkg.rpm?

dnf resuelve e instala las dependencias desde los repositorios configurados, mientras que rpm falla si faltan dependencias.

¿Qué hace gpgcheck=1 en un archivo .repo?

Exige que los paquetes de ese repositorio tengan firmas GPG válidas antes de instalarse.
