Firewalls (cortafuegos): zonas de firewalld y --permanent, ufw, fundamentos de nftables/iptables

Un firewall de host filtra el tráfico de red que entra y sale de un sistema Linux, para que solo los servicios que deseas sean accesibles. En el kernel, el filtrado de paquetes lo realiza netfilter; las herramientas que usas son interfaces que escriben reglas de netfilter. Linux+ cubre firewalld (familia RHEL), ufw (Ubuntu) y los de más bajo nivel nftables e iptables.

firewalld organiza las reglas en zonas, cada una de las cuales representa un nivel de confianza: drop, block, public, external, internal, dmz, work, home y trusted. Cada interfaz de red o dirección de origen se asigna a una zona, y los servicios y puertos permitidos de esa zona se aplican a su tráfico. public es un valor predeterminado común. Los comandos clave usan firewall-cmd: --get-default-zone, --get-active-zones, --list-all (muestra los servicios, puertos e interfaces de la zona actual), --add-service=https, --add-port=8080/tcp, --remove-service, --zone=internal --change-interface=eth1, y las rich rules (reglas enriquecidas) para un control más fino, como permitir un servicio solo desde una subred.

La distinción crucial es entre la configuración en tiempo de ejecución (runtime) y la permanente. De forma predeterminada, firewall-cmd --add-service=http cambia solo el firewall en ejecución, y el cambio se pierde al recargar o reiniciar. Agregar --permanent escribe el cambio en la configuración, pero no lo aplica al firewall en ejecución hasta firewall-cmd --reload. El patrón habitual es ejecutar el comando dos veces (con y sin --permanent) o hacerlo permanente y recargar; --runtime-to-permanent guarda los cambios de runtime ya probados. Los servicios son nombres predefinidos que corresponden a puertos, como ssh para 22/tcp.

ufw (Uncomplicated Firewall) es la interfaz más sencilla de Ubuntu. ufw status verbose muestra el estado y las reglas, ufw default deny incoming y ufw default allow outgoing establecen las políticas, ufw allow 22/tcp o ufw allow OpenSSH abren SSH, ufw allow from 10.0.0.0/24 to any port 5432 restringe por origen, y están ufw deny, ufw delete allow 80/tcp y finalmente ufw enable. Siempre permite SSH antes de habilitar ufw en una máquina remota, o te quedarás sin acceso. Las reglas de ufw son persistentes automáticamente.

iptables es la herramienta de reglas tradicional, organizada en tablas (filter, nat, mangle) que contienen cadenas (INPUT, OUTPUT, FORWARD, PREROUTING, POSTROUTING). Las reglas se evalúan en orden y la primera coincidencia decide el destino (ACCEPT, DROP, REJECT); los paquetes que no coinciden siguen la política de la cadena. iptables -L -n -v lista las reglas e iptables -A INPUT -p tcp --dport 22 -j ACCEPT agrega una. Las reglas no son persistentes si no se guardan, mediante iptables-save o un paquete de persistencia.

nftables es el reemplazo moderno de iptables, con una sola herramienta, nft, una sintaxis más limpia y soporte para IPv4 e IPv6 en una sola familia de tablas, inet. nft list ruleset lo muestra todo. En las distribuciones actuales, firewalld usa nftables como backend y el comando iptables a menudo se traduce a nftables por debajo. Elige una sola herramienta de administración por host; mezclar firewalld, ufw y reglas escritas a mano genera conflictos confusos.

Términos clave

netfilter
El framework del kernel de Linux que realiza el filtrado de paquetes y NAT, configurado por las herramientas de firewall.
firewalld zone (zona de firewalld)
Un nivel de confianza con nombre, con sus propios servicios y puertos permitidos, vinculado a interfaces o direcciones de origen.
--permanent
Opción de firewall-cmd que guarda un cambio en la configuración; surte efecto después de --reload.
ufw
Uncomplicated Firewall, la interfaz simplificada de Ubuntu con reglas persistentes.
nftables
El framework moderno de reglas de netfilter, administrado con nft, que reemplaza a iptables.
Ejemplo real

Un nuevo servidor web RHEL debe aceptar HTTPS desde cualquier lugar y PostgreSQL solo desde la subred de aplicaciones. Ejecutas firewall-cmd --permanent --add-service=https y firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.20.0/24 service name=postgresql accept', luego firewall-cmd --reload, y lo confirmas con firewall-cmd --list-all.

Consejo para el examen: Si una regla de firewalld funciona ahora pero desaparece después de reiniciar, se agregó sin --permanent; si una regla --permanent todavía no tiene efecto, no se recargó el firewall.

Comprueba lo que sabes

¿Cómo abres de forma permanente el puerto 8443/tcp en la zona predeterminada de firewalld y lo aplicas de inmediato?

firewall-cmd --permanent --add-port=8443/tcp seguido de firewall-cmd --reload.

¿Qué debes hacer antes de ejecutar ufw enable en un servidor remoto?

Permitir SSH (por ejemplo ufw allow OpenSSH o ufw allow 22/tcp) para que la conexión no se bloquee.

¿Qué comando muestra la configuración completa de nftables?

nft list ruleset.
