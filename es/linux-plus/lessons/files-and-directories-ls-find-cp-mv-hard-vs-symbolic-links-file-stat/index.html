CompTIA Linux+ XK0-006

Archivos y directorios: ls, find, cp, mv, enlaces duros vs simbólicos, file, stat

La mayor parte de la administración diaria se reduce a encontrar, inspeccionar, copiar y mover archivos. Estos comandos aparecen por todas partes en el examen, a menudo dentro de un escenario más amplio sobre espacio en disco, permisos o solución de problemas, así que conviene saberse de memoria sus opciones más útiles y entender el modelo de inodos que hay detrás. ls lista el contenido de un directorio. ls -l da el formato largo: tipo y permisos, número de enlaces, propietario, grupo, tamaño, hora de modificación y nombre. -a muestra los archivos ocultos que empiezan con punto, -h imprime tamaños legibles para personas, -t ordena por hora de modificación, -r invierte el orden, -R recorre de forma recursiva, -d lista el propio directorio en vez de su contenido, -i muestra los números de inodo y -Z muestra los contextos de SELinux. El primer carácter del listado largo te indica el tipo: - archivo regular, d directorio, l enlace simbólico, b dispositivo de bloques, c dispositivo de caracteres, p tubería con nombre, s socket.

find busca en un árbol por casi cualquier atributo y puede actuar sobre los resultados. Ejemplos: find /etc -name '*.conf' (pon los comodines entre comillas para que el shell no los expanda; -iname ignora mayúsculas y minúsculas), find / -type f -size +100M para archivos grandes, find /home -user alice, find /var/log -mtime +30 para archivos modificados hace más de 30 días y find / -perm -4000 para archivos SUID. Añade -exec cmd {} \; para ejecutar un comando sobre cada coincidencia (o {} + para pasar muchas a la vez) y -delete para eliminar las coincidencias, con cuidado. locate es más rápido, pero busca en una base de datos preconstruida que actualiza updatedb, así que puede no encontrar archivos creados desde la última actualización.

cp src dest copia; -r copia directorios de forma recursiva, -p conserva el modo, la propiedad y las marcas de tiempo, -a (archivo) copia de forma recursiva conservando todo, incluidos los enlaces, e -i pregunta antes de sobrescribir. mv mueve o renombra; dentro del mismo sistema de archivos solo reescribe la entrada de directorio, por lo que es instantáneo incluso con archivos enormes, mientras que entre sistemas de archivos debe copiar y luego borrar. rm -r elimina directorios, rmdir elimina solo los vacíos, mkdir -p crea los directorios padre según haga falta y touch crea un archivo vacío o actualiza las marcas de tiempo.

Los enlaces son un tema favorito del examen. Los datos y metadatos de cada archivo se describen mediante un inodo, y una entrada de directorio es solo un nombre que apunta a un inodo. Un enlace duro (ln target linkname) es un segundo nombre para el mismo inodo: ambos nombres son equivalentes, el número de enlaces en ls -l aumenta y los datos sobreviven hasta que se elimina el último nombre. Los enlaces duros no pueden cruzar sistemas de archivos y normalmente no pueden apuntar a directorios. Un enlace simbólico o blando (ln -s target linkname) es un pequeño archivo independiente con su propio inodo que contiene una ruta. Puede cruzar sistemas de archivos y apuntar a directorios, pero si el destino se borra o se mueve, el enlace simbólico se rompe (queda 'colgante', dangling). readlink -f muestra a dónde se resuelve finalmente un enlace simbólico.

file name identifica el contenido examinándolo en lugar de fiarse de la extensión; por ejemplo, informa que report.pdf en realidad es texto ASCII o que un binario es un ejecutable ELF. stat name muestra los metadatos completos del inodo: tamaño, bloques, número de inodo, número de enlaces, permisos en forma octal y simbólica, propietario y las marcas de tiempo: acceso (atime), modificación (mtime, cambió el contenido) y cambio (ctime, cambiaron metadatos como los permisos). Muchos sistemas también informan una hora de creación (birth). Como ls -l muestra solo mtime de forma predeterminada, stat es la herramienta a la que recurrir cuando necesitas saber cuándo cambiaron por última vez los permisos o la propiedad.

Veamos un ejemplo práctico. Salta una alerta de disco en un servidor de archivos. Ejecutas find /srv -type f -size +1G -mtime +180 -exec ls -lh {} + para listar archivos grandes que no se han tocado en seis meses y lo confirmas con sus propietarios. Borras uno, pero df no muestra espacio liberado; stat sobre otro nombre revela que el número de enlaces era 2, así que un enlace duro en otro lugar todavía hace referencia a los mismos datos. Encontrarlo con find /srv -samefile y eliminarlo libera el espacio.

Errores comunes: olvidar poner entre comillas los comodines en find -name, de modo que el shell los expande primero; usar cp -r cuando hay que conservar la propiedad y las marcas de tiempo (usa -a); crear un enlace simbólico relativo desde el directorio equivocado, de modo que no apunta a ninguna parte; suponer que borrar un archivo libera espacio cuando otro enlace duro o un proceso abierto todavía lo retiene; y pensar que ctime significa hora de creación, cuando es la hora de cambio de metadatos.

Las preguntas del examen suelen formularse como un requisito. 'Debe funcionar entre particiones o apuntar a un directorio' significa un enlace simbólico. 'Los datos deben seguir accesibles después de borrar el nombre original' significa un enlace duro. 'Determinar el tipo real de un archivo sin importar la extensión' es file. 'Mostrar el número de inodo, el número de enlaces y todas las marcas de tiempo' es stat. 'Buscar por tamaño, propietario, antigüedad o permiso' es find, y 'una búsqueda rápida por nombre que no encontró un archivo nuevo' indica que la base de datos de locate necesita updatedb.

Términos clave

Inodo (inode)
La estructura en disco que guarda los metadatos de un archivo y los punteros a sus datos; las entradas de directorio asocian nombres con números de inodo.
Enlace duro (hard link)
Una entrada de directorio adicional para el mismo inodo; no puede cruzar sistemas de archivos y sobrevive a la eliminación de los demás nombres.
Enlace simbólico (symbolic link)
Un archivo independiente que guarda una ruta a un destino; puede cruzar sistemas de archivos, pero se rompe si se elimina el destino.
mtime vs ctime
mtime cambia cuando cambia el contenido del archivo; ctime cambia cuando cambian metadatos como los permisos o la propiedad.
find -exec
Una acción de find que ejecuta un comando sobre cada archivo encontrado, reemplazando {} por el nombre del archivo.
locate
Una búsqueda rápida por nombre de archivo que usa una base de datos construida por updatedb, por lo que puede no encontrar archivos creados recientemente.
Ejemplo real

Salta una alerta de disco en un servidor de archivos. Ejecutas find /srv -type f -size +1G -mtime +180 -exec ls -lh {} \; para listar archivos grandes que no se han tocado en seis meses, lo confirmas con los propietarios y luego los archivas. En el proceso, stat sobre un archivo muestra un número de enlaces de 2, lo que te indica que un enlace duro en otro lugar todavía hace referencia a los mismos datos, así que borrar un solo nombre no liberaría el espacio.

Consejo para el examen: Si una pregunta dice que el enlace debe funcionar entre particiones o hacia un directorio, la respuesta es un enlace simbólico; si dice que los datos deben seguir accesibles después de borrar el nombre original, la respuesta es un enlace duro.

Comprueba lo que sabes

¿Qué le pasa a un enlace simbólico cuando se borra su archivo de destino?

Se convierte en un enlace colgante que apunta a una ruta que ya no existe, así que acceder a él falla.

¿Qué comando find lista los archivos regulares en /var de más de 500 MB?

find /var -type f -size +500M, donde -type f limita los resultados a archivos regulares y +500M significa más de 500 MiB.

¿Por qué mover con mv un archivo de 50 GB dentro de un mismo sistema de archivos es casi instantáneo?

Porque solo cambia la entrada de directorio que apunta al inodo; los bloques de datos no se mueven.

¿Qué opción de cp copia un árbol de directorios conservando propiedad, permisos, marcas de tiempo y enlaces simbólicos?

cp -a (archivo), que es recursiva y conserva todos los atributos y enlaces.
