CompTIA Linux+ XK0-006

Archivos y directorios: ls, find, cp, mv, enlaces duros vs simbólicos, file, stat

La mayor parte de la administración diaria se reduce a encontrar, inspeccionar, copiar y mover archivos. Estos comandos aparecen por todas partes en el examen, a menudo dentro de un escenario más amplio, así que vale la pena saberte de memoria sus opciones más útiles.

ls lista el contenido de un directorio. ls -l da el formato largo: tipo y permisos, número de enlaces, propietario, grupo, tamaño, hora de modificación y nombre. -a muestra los archivos ocultos que empiezan con punto, -h imprime tamaños legibles para humanos, -t ordena por hora de modificación, -R recorre recursivamente, -d lista el directorio en sí en lugar de su contenido, -i muestra los números de inodo y -Z muestra los contextos de SELinux. El primer carácter del listado largo te dice el tipo: - archivo regular, d directorio, l enlace simbólico, b dispositivo de bloques, c dispositivo de caracteres, p tubería con nombre, s socket.

find busca en un árbol por casi cualquier atributo y puede actuar sobre los resultados. Ejemplos: find /etc -name '*.conf' (pon los comodines entre comillas para que el shell no los expanda), find / -type f -size +100M para archivos grandes, find /home -user alice, find /var/log -mtime +30 para archivos modificados hace más de 30 días y find / -perm -4000 para archivos SUID. Agrega -exec cmd {} \; para ejecutar un comando sobre cada coincidencia o -delete para eliminar las coincidencias, con cuidado. locate es más rápido, pero busca en una base de datos preconstruida que actualiza updatedb, así que puede no encontrar archivos nuevos.

cp origen destino copia; -r copia directorios recursivamente, -p conserva modo, propiedad y marcas de tiempo, -a (archive) copia recursivamente conservando todo, incluidos los enlaces, e -i pregunta antes de sobrescribir. mv mueve o renombra; dentro del mismo sistema de archivos solo reescribe la entrada de directorio, así que es instantáneo incluso para archivos enormes. rm -r elimina directorios y mkdir -p crea los directorios padre según sea necesario.

Los enlaces son un tema favorito del examen. Los datos y metadatos de cada archivo se describen mediante un inodo, y una entrada de directorio es solo un nombre que apunta a un inodo. Un enlace duro (ln destino nombreenlace) es un segundo nombre para el mismo inodo: ambos nombres son iguales, el número de enlaces en ls -l aumenta y los datos sobreviven hasta que se elimina el último nombre. Los enlaces duros no pueden cruzar sistemas de archivos y normalmente no pueden apuntar a directorios. Un enlace simbólico (soft link) (ln -s destino nombreenlace) es un pequeño archivo separado que contiene una ruta. Puede cruzar sistemas de archivos y apuntar a directorios, pero si el destino se elimina o se mueve, el enlace simbólico se rompe ('dangling', colgante).

file nombre identifica el contenido examinándolo en lugar de confiar en la extensión; por ejemplo, informa que report.pdf es en realidad un archivo de texto ASCII o que un binario es un ejecutable ELF. stat nombre muestra todos los metadatos del inodo: tamaño, bloques, número de inodo, número de enlaces, permisos en forma octal y simbólica, propietario y las marcas de tiempo: acceso (atime), modificación (mtime, cambió el contenido) y cambio (ctime, cambiaron los metadatos). Muchos sistemas también informan una hora de creación (birth time).

Términos clave

Inode (inodo)
La estructura en disco que guarda los metadatos de un archivo y los punteros a sus datos; las entradas de directorio asocian nombres con números de inodo.
Hard link (enlace duro)
Una entrada de directorio adicional para el mismo inodo; no puede cruzar sistemas de archivos y sobrevive a la eliminación de los otros nombres.
Symbolic link (enlace simbólico)
Un archivo separado que guarda una ruta hacia un destino; puede cruzar sistemas de archivos, pero se rompe si se elimina el destino.
mtime vs ctime
mtime cambia cuando cambia el contenido del archivo; ctime cambia cuando cambian metadatos como permisos o propiedad.
find -exec
Una acción de find que ejecuta un comando sobre cada archivo encontrado, donde {} se reemplaza por el nombre del archivo.
Ejemplo real

Se dispara una alerta de disco en un servidor de archivos. Ejecutas find /srv -type f -size +1G -mtime +180 -exec ls -lh {} \; para listar los archivos grandes que no se han tocado en seis meses, lo confirmas con los propietarios y luego los archivas. En el camino, stat sobre un archivo muestra un número de enlaces de 2, lo que te indica que un enlace duro en otro lugar todavía referencia los mismos datos, así que eliminar solo un nombre no liberaría el espacio.

Consejo para el examen: Si una pregunta dice que el enlace debe funcionar entre particiones o hacia un directorio, la respuesta es un enlace simbólico; si dice que los datos deben seguir accesibles después de eliminar el nombre original, la respuesta es un enlace duro.

Comprueba lo que sabes

¿Qué le pasa a un enlace simbólico cuando se elimina su archivo de destino?

Se convierte en un enlace colgante (dangling) que apunta a una ruta que ya no existe; acceder a él falla.

¿Qué comando find lista los archivos regulares en /var de más de 500 MB?

find /var -type f -size +500M.

¿Por qué mv de un archivo de 50 GB dentro de un mismo sistema de archivos es casi instantáneo?

Porque solo cambia la entrada de directorio que apunta al inodo; los bloques de datos no se mueven.
