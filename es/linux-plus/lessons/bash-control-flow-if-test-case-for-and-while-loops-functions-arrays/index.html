Control de flujo en Bash: if/test, case, bucles for y while, funciones, arreglos

El control de flujo permite que un script tome decisiones y repita trabajo. Con condiciones, bucles y funciones puedes convertir una lista de comandos en una herramienta que maneje muchos hosts, archivos o usuarios. El examen espera que leas estas construcciones y detectes errores en ellas.

if ejecuta un comando y se ramifica según su estado de salida: cero significa verdadero. Lo más frecuente es que el comando sea una prueba. [ ... ] (el comando test) y el [[ ... ]] de Bash evalúan expresiones; los espacios dentro de los corchetes son obligatorios. Pruebas de archivos: -e existe, -f archivo regular, -d directorio, -r/-w/-x legible, escribible, ejecutable, -s no vacío. Pruebas de cadenas: -z vacía, -n no vacía, = o == igual, != distinta. Las comparaciones de enteros usan -eq, -ne, -lt, -le, -gt, -ge, no < ni >, que dentro de corchetes simples son redirecciones. [[ ]] agrega coincidencia de patrones ([[ $host == web* ]]), expresiones regulares con =~, && y || dentro, y un manejo más seguro de variables sin comillas. (( )) evalúa aritmética: (( count > 5 )). La estructura es if ...; then ...; elif ...; then ...; else ...; fi.

case compara un valor con patrones, lo cual es más limpio que una larga cadena de if/elif, sobre todo para las opciones de línea de comandos:

case "$1" in
  start|up)   systemctl start app ;;
  stop)       systemctl stop app ;;
  *)          echo "usage: $0 {start|stop}" >&2; exit 2 ;;
esac

Cada patrón termina con ), cada bloque con ;;, | separa alternativas, * es el caso predeterminado que atrapa todo, y la instrucción completa termina con esac.

Los bucles for recorren una lista: for host in web01 web02 db01; do ssh "$host" uptime; done, archivos con un glob (for f in /var/log/*.log; do ...; done), argumentos con for arg in "$@", o al estilo C con for ((i=1; i<=5; i++)). La expansión de llaves {1..10} genera secuencias. while repite mientras un comando tenga éxito, y until repite hasta que tenga éxito. La forma más segura de procesar un archivo línea por línea es while IFS= read -r line; do ...; done < file, que conserva los espacios y las barras invertidas; recorrer con for line in $(cat file) divide en cada espacio. break sale de un bucle y continue salta a la siguiente iteración.

Las funciones agrupan código reutilizable: backup() { local src="$1"; tar -czf "/backup/$(basename "$src").tgz" "$src"; }, que se llama como un comando: backup /etc. Dentro de una función, $1, $2, etc., son los argumentos propios de la función. Declara las variables con local para que no se filtren al resto del script. return n establece el estado de salida de la función (0 a 255); para devolver datos, imprímelos con echo y captúralos con $(...). Las funciones deben definirse antes de llamarse.

Los arreglos guardan listas. Arreglos indexados: servers=(web01 web02 db01), ${servers[0]} es el primer elemento, ${servers[@]} se expande a todos los elementos (ponlo entre comillas: "${servers[@]}"), ${#servers[@]} da la cantidad y servers+=(cache01) agrega al final. Los arreglos asociativos necesitan declare -A: declare -A port=([ssh]=22 [https]=443), luego ${port[ssh]}, y ${!port[@]} lista las claves. Los arreglos son funciones de Bash y no están disponibles en el sh POSIX simple.

Términos clave

test / [ ]
Evalúa condiciones de archivos, cadenas y enteros y devuelve un estado de salida que usan if y while.
[[ ]]
La prueba extendida de Bash con coincidencia de patrones, regex (=~) y un manejo más seguro de variables.
case
Una instrucción de múltiples ramas que compara un valor con patrones glob y termina con esac.
local
Declara una variable con alcance limitado a la función actual.
Associative array (arreglo asociativo)
Un arreglo de Bash indexado por cadenas, declarado con declare -A.
Ejemplo real

Necesitas revisar el uso de disco en cada servidor de una lista. Un script lee los hosts en un arreglo con mapfile -t hosts < hosts.txt, los recorre con for h in "${hosts[@]}", ejecuta una función check_disk "$h" que usa ssh y df, y usa if (( usage > 90 )) para imprimir una advertencia solo para los hosts por encima del 90 por ciento.

Consejo para el examen: Los números se comparan con -eq, -lt y -gt dentro de [ ], mientras que = y != comparan cadenas; usar > dentro de corchetes simples crea un archivo en silencio en lugar de comparar.

Comprueba lo que sabes

¿Qué prueba comprueba que /etc/app.conf existe y es un archivo regular?

[ -f /etc/app.conf ].

¿Por qué se prefiere while IFS= read -r line; do ... done < file a for line in $(cat file)?

Lee las líneas completas intactas, mientras que el bucle for divide por espacios en blanco y expande los globs.

¿Cómo imprimes el número de elementos del arreglo users?

echo "${#users[@]}".
