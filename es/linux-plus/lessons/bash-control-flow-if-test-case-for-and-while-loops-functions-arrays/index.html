Control de flujo en Bash: if/test, case, bucles for y while, funciones, arreglos

El control de flujo permite que un script tome decisiones y repita trabajo. Con condiciones, bucles y funciones puedes convertir una lista de comandos en una herramienta que maneja muchos hosts, archivos o usuarios. El examen espera que leas estas construcciones, predigas lo que hacen y detectes errores en ellas, así que presta atención a la sintaxis exacta, en especial a los espacios y las palabras clave.

if ejecuta un comando y se ramifica según su estado de salida: cero significa verdadero. Lo más habitual es que el comando sea una prueba. [ ... ] (el comando test) y [[ ... ]] de Bash evalúan expresiones, y los espacios dentro de los corchetes son obligatorios. Pruebas de archivos: -e existe, -f archivo regular, -d directorio, -r, -w y -x legible, escribible, ejecutable, -s no vacío. Pruebas de cadenas: -z vacía, -n no vacía, = o == igual, != distinta. Las comparaciones de enteros usan -eq, -ne, -lt, -le, -gt y -ge, no < ni >, que dentro de corchetes simples son redirecciones. [[ ]] agrega coincidencia de patrones ([[ $host == web* ]]), expresiones regulares con =~, && y || en su interior, y un manejo más seguro de las variables sin comillas. (( )) evalúa aritmética: (( count > 5 )). La estructura es if ...; then ...; elif ...; then ...; else ...; fi. case compara un valor con varios patrones, lo que es más limpio que una larga cadena de if/elif, especialmente para las opciones de línea de comandos. Cada patrón termina con ), cada bloque con ;;, | separa alternativas, * es el caso predeterminado que captura todo, y la instrucción termina con esac:

case "$1" in
  start|up)   systemctl start app ;;
  stop)       systemctl stop app ;;
  *)          echo "usage: $0 {start|stop}" >&2; exit 2 ;;
esac

Los bucles for recorren una lista: for host in web01 web02 db01; do ssh "$host" uptime; done, archivos con un glob (for f in /var/log/*.log; do ...; done), argumentos con for arg in "$@", o al estilo C con for ((i=1; i<=5; i++)). La expansión de llaves {1..10} genera secuencias. while repite mientras un comando tenga éxito, y until repite hasta que tenga éxito. La forma más segura de procesar un archivo línea por línea es while IFS= read -r line; do ...; done < file, que conserva los espacios y las barras invertidas; for line in $(cat file) divide en cada espacio. break sale de un bucle y continue salta a la siguiente iteración. Las funciones agrupan código reutilizable: backup() { local src="$1"; tar -czf "/backup/$(basename "$src").tgz" "$src"; }, y se invocan como un comando: backup /etc. Dentro de una función, $1 y los demás son los argumentos propios de la función; declara las variables con local para que no se filtren; return n define el estado de la función, y para devolver datos los imprimes con echo y los capturas con $(...). Las funciones deben definirse antes de invocarse.

Los arreglos (arrays) contienen listas. Arreglos indexados: servers=(web01 web02 db01), ${servers[0]} es el primer elemento, "${servers[@]}" se expande a todos los elementos como palabras separadas, ${#servers[@]} da la cantidad y servers+=(cache01) agrega un elemento al final. mapfile -t hosts < hosts.txt lee un archivo en un arreglo, una línea por elemento. Los arreglos asociativos necesitan declare -A: declare -A port=([ssh]=22 [https]=443), luego ${port[ssh]}, y ${!port[@]} lista las claves. Los arreglos son funciones de Bash y no están disponibles en sh POSIX simple, así que un script que los use necesita un shebang de bash.

Considera un ejemplo práctico. Necesitas revisar el uso de disco en cada servidor de una lista. El script lee los hosts con mapfile -t hosts < hosts.txt y los recorre con for h in "${hosts[@]}". Una función check_disk() declara local host="$1", ejecuta ssh "$host" df --output=pcent / y quita el signo de porcentaje, y luego usa if (( usage > 90 )) para imprimir una advertencia. Un case sobre $1 permite que el mismo script acepte report o quiet, y un bucle while con sleep podría repetir la verificación hasta que todos los hosts respondan.

Errores comunes: [$x -eq 1] sin espacios, que falla; [ $a > $b ], que crea un archivo con el nombre de $b; olvidar fi, done o esac; usar = para números donde se necesita -eq; olvidar ;; en case; dejar "${arr[@]}" sin comillas; y omitir local, de modo que las variables de la función sobrescriben las globales.

Las preguntas del examen evalúan la sintaxis exacta. 'Verificar que un archivo existe y es un archivo regular' es [ -f file ], y 'es un directorio' es -d. 'Comparar números' significa -eq, -lt o -gt, o (( )). 'Muchos valores posibles de una variable' sugiere case. 'Leer un archivo línea por línea de forma segura' es while IFS= read -r line. 'Número de elementos' es ${#array[@]}, 'pares clave-valor' necesita declare -A, y 'mantener privada una variable de función' es local.

Términos clave

test / [ ]
El comando que evalúa expresiones de archivos, cadenas y enteros y devuelve 0 si es verdadera.
[[ ]]
La prueba extendida de Bash, con coincidencia de patrones, expresiones regulares =~ y un manejo más seguro de las variables sin comillas.
case
Una instrucción que compara un valor con patrones, con ;; al final de cada rama y esac al final del bloque.
Bucle while read
while IFS= read -r line; do ...; done < file, la forma segura de procesar un archivo línea por línea.
local
Declara una variable visible solo dentro de la función actual.
Arreglo asociativo (associative array)
Un arreglo de Bash indexado por cadenas, creado con declare -A.
Ejemplo real

Necesitas revisar el uso de disco en cada servidor de una lista. Un script lee los hosts en un arreglo con mapfile -t hosts < hosts.txt, los recorre con for h in "${hosts[@]}", ejecuta una función check_disk "$h" que usa ssh y df, y usa if (( usage > 90 )) para imprimir una advertencia solo para los hosts por encima del 90 por ciento, de modo que el informe de la mañana muestra únicamente los servidores que necesitan atención.

Consejo para el examen: Los números se comparan con -eq, -lt y -gt dentro de [ ], mientras que = y != comparan cadenas; usar > dentro de corchetes simples crea un archivo en silencio en lugar de comparar.

Comprueba lo que sabes

¿Qué prueba verifica que /etc/app.conf existe y es un archivo regular?

[ -f /etc/app.conf ].

¿Por qué se prefiere while IFS= read -r line; do ... done < file en lugar de for line in $(cat file)?

Lee las líneas completas e intactas, mientras que el bucle for divide en los espacios en blanco y expande los globs.

¿Cómo imprimes el número de elementos del arreglo users?

echo "${#users[@]}".

¿Qué termina cada rama de una instrucción case y qué termina la instrucción completa?

Cada rama termina con ;; y la instrucción termina con esac.
