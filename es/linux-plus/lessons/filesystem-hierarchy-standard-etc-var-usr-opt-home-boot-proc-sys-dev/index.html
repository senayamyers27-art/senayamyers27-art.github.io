CompTIA Linux+ XK0-006

Estándar de jerarquía del sistema de archivos (FHS): /etc, /var, /usr, /opt, /home, /boot, /proc, /sys, /dev

Linux tiene un único árbol de directorios que comienza en / (raíz), y cada disco, partición y sistema de archivos virtual se conecta en algún punto de él. El FHS (Filesystem Hierarchy Standard) describe qué va en cada lugar. Como casi todas las distribuciones lo siguen, conocer la estructura te dice dónde buscar un archivo de configuración, un log o un dispositivo en cualquier sistema al que inicies sesión.

/etc contiene la configuración específica del host, casi toda en texto plano: /etc/fstab, /etc/passwd, /etc/ssh/sshd_config, /etc/hosts. Si quieres cambiar cómo se comporta algo en esta máquina, el archivo probablemente está bajo /etc. Haz una copia de respaldo antes de cambios grandes. /var contiene datos variables que crecen mientras el sistema funciona: logs en /var/log, colas de correo e impresión en /var/spool, cachés de paquetes en /var/cache y estado de aplicaciones, como bases de datos, en /var/lib. Un /var lleno es una causa clásica de fallas en servicios, por eso los servidores suelen darle una partición separada.

/usr contiene la mayor parte del software instalado y de solo lectura, y los datos compartidos por los usuarios: programas en /usr/bin, bibliotecas en /usr/lib, documentación en /usr/share. El software que compilas tú mismo tradicionalmente va en /usr/local para que el gestor de paquetes nunca lo sobrescriba. En la mayoría de las distribuciones modernas, /bin, /sbin y /lib son enlaces simbólicos hacia /usr (el 'usr merge'). /opt es para paquetes de software adicionales que se instalan como un paquete autocontenido, como una aplicación de un proveedor en /opt/vendorapp.

/home contiene los directorios personales de los usuarios, como /home/alice, mientras que el directorio personal del usuario root es /root. /boot contiene lo que necesita el cargador de arranque: imágenes del kernel (vmlinuz-*), imágenes initramfs y la configuración de GRUB. Si /boot se llena de kernels antiguos, las actualizaciones pueden fallar. Otros directorios que vale la pena conocer son /tmp para archivos temporales (a menudo se vacía al arrancar), /mnt y /media para puntos de montaje, /srv para datos que sirve el sistema y /run para datos de tiempo de ejecución como archivos PID, que vive en RAM.

Tres directorios son virtuales: no están en disco, sino que los genera el kernel. /proc es el sistema de archivos de procesos: cada proceso en ejecución tiene un directorio numerado como /proc/1234, y archivos como /proc/cpuinfo, /proc/meminfo y /proc/sys/... exponen información del kernel y parámetros ajustables. /sys (sysfs) presenta una vista estructurada de dispositivos, controladores y objetos del kernel, y es de donde udev y herramientas como lsblk obtienen sus datos. /dev contiene archivos de dispositivo, gestionados por udev, que representan hardware y pseudodispositivos: /dev/sda y /dev/nvme0n1 para discos, /dev/null para descartar salida, /dev/zero para un flujo de bytes cero y /dev/urandom para bytes aleatorios.

Un buen hábito es usar man hier o man file-hierarchy, que describen la estructura en tu propio sistema. En el examen, espera preguntas que te den un tipo de archivo y te pregunten dónde se encuentra, o que describan un síntoma como un disco lleno por el crecimiento de logs y te pregunten qué directorio revisar.

Términos clave

FHS
Filesystem Hierarchy Standard: la convención que define el propósito de los directorios de nivel superior de Linux.
/etc
El directorio para los archivos de configuración específicos del host.
/var
El directorio para datos variables como logs, colas, cachés y estado de aplicaciones.
/proc
Un sistema de archivos virtual que expone información de procesos y del kernel, incluidos los parámetros ajustables bajo /proc/sys.
/sys
Sysfs, un sistema de archivos virtual que expone dispositivos, controladores y objetos del kernel.
/dev
El directorio de archivos de dispositivo, como /dev/sda y /dev/null, mantenido por udev.
Ejemplo real

Un servidor web deja de aceptar cargas de archivos. Ejecutas df -h y ves que el sistema de archivos montado en /var está al 100 por ciento. du -sh /var/* señala /var/log, donde el log de depuración de una aplicación ha crecido a muchos gigabytes. Rotar y comprimir ese log libera espacio y las cargas vuelven a funcionar.

Consejo para el examen: Recuerda que /proc y /sys no ocupan espacio en disco y se reconstruyen en cada arranque; las preguntas del examen sobre ver la CPU, la memoria o los parámetros del kernel suelen apuntar a /proc, mientras que los detalles de dispositivos y controladores apuntan a /sys.

Comprueba lo que sabes

¿Dónde esperarías encontrar un programa que compilaste tú mismo desde el código fuente, y por qué?

En /usr/local (por ejemplo /usr/local/bin), porque esa área está reservada para software instalado localmente que el gestor de paquetes no sobrescribirá.

¿Qué directorio contiene las imágenes del kernel y los archivos initramfs?

/boot.

¿Para qué se usa /dev/null?

Es un archivo de dispositivo que descarta todo lo que se escribe en él; se usa comúnmente para desechar la salida no deseada de un comando.
