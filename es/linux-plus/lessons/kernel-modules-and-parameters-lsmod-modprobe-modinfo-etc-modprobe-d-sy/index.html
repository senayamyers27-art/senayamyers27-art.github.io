Módulos y parámetros del kernel: lsmod, modprobe, modinfo, /etc/modprobe.d, sysctl

El kernel de Linux es modular. En lugar de integrar todos los controladores en una única imagen enorme, la mayoría de los controladores y funciones se distribuyen como módulos del kernel cargables, archivos que terminan en .ko (a veces comprimidos, como .ko.xz) guardados bajo /lib/modules/$(uname -r)/. El kernel, con ayuda de udev, carga un módulo automáticamente cuando aparece el hardware correspondiente, y un administrador puede cargar, descargar, inspeccionar y configurar módulos sin reiniciar. Esto mantiene el kernel pequeño y permite que una sola imagen de kernel funcione en hardware muy distinto. lsmod lista los módulos cargados actualmente, con su tamaño y una columna 'Used by' que muestra cuántos usuarios tiene cada uno y qué otros módulos dependen de él. Simplemente da formato al contenido de /proc/modules. modinfo name muestra detalles sobre un archivo de módulo: su ruta, descripción, licencia, autor, dependencias y, lo más importante, los parámetros que acepta. Esa lista de parámetros es la forma de saber qué opciones puedes configurar. Una vez cargado un módulo, los valores actuales de sus parámetros suelen aparecer bajo /sys/module/name/parameters/.

modprobe es la herramienta inteligente para cargar y quitar módulos. modprobe name carga el módulo y cualquier módulo del que dependa, usando el mapa de dependencias modules.dep construido por depmod. modprobe -r name lo quita junto con las dependencias que ya no se usan, y se niega a hacerlo si el módulo está en uso. Puedes pasar parámetros en la línea de comandos, como en modprobe name option=value. Los comandos más antiguos insmod y rmmod cargan o quitan un solo archivo de módulo por ruta y no resuelven dependencias, por eso se prefiere modprobe. Ejecuta depmod -a después de añadir manualmente un archivo de módulo para que modprobe pueda encontrarlo.

La configuración persistente de módulos vive en archivos bajo /etc/modprobe.d/ que terminan en .conf. Una línea options establece parámetros cada vez que se carga el módulo (options mymodule debug=1), y una línea blacklist impide la carga automática por alias (blacklist nouveau). La lista negra no impide un modprobe explícito ni la carga como dependencia; para bloquear también eso, los administradores añaden install name /bin/false. Para cargar un módulo en cada arranque, escribe su nombre en un archivo bajo /etc/modules-load.d/. Si el módulo se carga temprano en el arranque desde el initramfs, reconstruye el initramfs después para que el cambio quede incluido.

Los parámetros del kernel son una idea distinta: ajustes de tiempo de ejecución del propio kernel, expuestos como archivos bajo /proc/sys. El comando sysctl los lee y escribe usando nombres con puntos que reflejan la ruta, de modo que net.ipv4.ip_forward es /proc/sys/net/ipv4/ip_forward. sysctl -a los lista todos, sysctl net.ipv4.ip_forward muestra uno y sysctl -w net.ipv4.ip_forward=1 lo cambia de inmediato, pero solo hasta el reinicio. Para que sea persistente, coloca el ajuste en un archivo bajo /etc/sysctl.d/ (o en /etc/sysctl.conf) y aplícalo con sysctl --system o sysctl -p file. Los argumentos del kernel en el arranque, en cambio, van en la línea de comandos de GRUB.

# /etc/modprobe.d/local.conf
options e1000e InterruptThrottleRate=3000
blacklist nouveau

# /etc/sysctl.d/90-router.conf
net.ipv4.ip_forward = 1
vm.swappiness = 10

Veamos un ejemplo práctico. Estás convirtiendo una máquina virtual Linux en un router entre dos subredes. sysctl net.ipv4.ip_forward devuelve 0, así que ejecutas sysctl -w net.ipv4.ip_forward=1 para probar y confirmas que el tráfico fluye entre las subredes. Luego creas /etc/sysctl.d/90-router.conf con net.ipv4.ip_forward = 1 y ejecutas sysctl --system para que el ajuste sobreviva a los reinicios. Más adelante, el mismo host recibe una nueva tarjeta de red cuyo controlador necesita una tasa de interrupciones más baja. Lees las opciones aceptadas con modinfo e1000e, pruebas con modprobe -r e1000e && modprobe e1000e InterruptThrottleRate=3000 desde la consola (no a través de esa interfaz), revisas /sys/module/e1000e/parameters/ y luego añades una línea options en /etc/modprobe.d/ para que se aplique en cada carga.

Errores comunes: esperar que los cambios hechos con modprobe o sysctl -w sean persistentes; pensar que blacklist bloquea todas las formas de cargar un módulo; usar insmod y luego preguntarte por qué falta una dependencia; y editar directamente archivos de /proc/sys olvidando que esas ediciones también desaparecen al reiniciar. Otra trampa es quitar un módulo del que depende un dispositivo en funcionamiento: modprobe -r se negará mientras el contador 'Used by' sea mayor que cero, lo cual es una medida de seguridad, no un error. Por último, recuerda reconstruir el initramfs cuando el módulo en cuestión se carga antes de montar el sistema de archivos raíz.

Las preguntas del examen suelen formularse en torno a la necesidad. 'Mostrar los controladores cargados' es lsmod. 'Qué parámetros acepta este controlador' es modinfo. 'Cargar un controlador y sus dependencias' es modprobe. 'Impedir que un controlador se cargue automáticamente' es una lista negra en /etc/modprobe.d. 'Cargar en el arranque' es /etc/modules-load.d. 'Cambiar de forma persistente un parámetro ajustable del kernel, como el reenvío IP o swappiness' es un archivo en /etc/sysctl.d aplicado con sysctl --system.

Términos clave

Módulo del kernel (kernel module)
Un fragmento cargable de código del kernel (archivo .ko), como un controlador, que se puede insertar o quitar mientras el sistema funciona.
modprobe
Carga o quita (-r) un módulo junto con sus dependencias, leyendo las opciones de /etc/modprobe.d.
modinfo
Muestra la ruta del archivo de un módulo, su descripción, sus dependencias y los parámetros que admite.
depmod
Construye el mapa de dependencias modules.dep que modprobe usa para cargar dependencias.
Lista negra (blacklist)
Una directiva de modprobe.d que impide que un módulo se cargue automáticamente por su alias.
sysctl
Una herramienta para ver y establecer parámetros de tiempo de ejecución del kernel bajo /proc/sys; los valores persistentes van en /etc/sysctl.d/*.conf.
Ejemplo real

Estás convirtiendo una VM Linux en un router entre dos subredes. sysctl net.ipv4.ip_forward devuelve 0, así que ejecutas sysctl -w net.ipv4.ip_forward=1 para probar, confirmas que el tráfico fluye y luego creas /etc/sysctl.d/90-router.conf con net.ipv4.ip_forward = 1 y ejecutas sysctl --system para que el ajuste sobreviva a los reinicios.

Consejo para el examen: Cuidado con la trampa de la persistencia: los cambios hechos con modprobe y sysctl -w desaparecen al reiniciar; la persistencia se logra con /etc/modprobe.d o /etc/modules-load.d para los módulos y con /etc/sysctl.d para los parámetros del kernel.

Comprueba lo que sabes

¿Cuál es la diferencia entre insmod y modprobe?

insmod carga un solo archivo de módulo y no maneja dependencias; modprobe carga por nombre y carga automáticamente las dependencias necesarias.

¿Cómo impides de forma permanente que el controlador nouveau se cargue automáticamente?

Añade 'blacklist nouveau' a un archivo .conf en /etc/modprobe.d/ y reconstruye el initramfs si el módulo se carga temprano en el arranque.

¿Qué ruta de archivo corresponde a la clave de sysctl vm.swappiness?

/proc/sys/vm/swappiness, porque los nombres de sysctl reemplazan con puntos las barras que siguen a /proc/sys.

Añadiste una línea a /etc/sysctl.d/99-local.conf. ¿Cómo la aplicas sin reiniciar?

Ejecuta sysctl --system (o sysctl -p /etc/sysctl.d/99-local.conf), que lee los archivos de configuración y aplica sus valores.
