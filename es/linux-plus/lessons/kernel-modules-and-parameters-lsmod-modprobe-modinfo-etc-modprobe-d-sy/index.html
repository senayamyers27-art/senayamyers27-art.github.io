CompTIA Linux+ XK0-006

Módulos y parámetros del kernel: lsmod, modprobe, modinfo, /etc/modprobe.d, sysctl

El kernel de Linux es modular. En lugar de incluir cada controlador en una sola imagen enorme, la mayoría de los controladores y funciones se distribuyen como módulos del kernel cargables, archivos que terminan en .ko (a veces comprimidos, como .ko.xz) guardados en /lib/modules/$(uname -r)/. El kernel carga un módulo cuando el hardware lo necesita, y un administrador puede cargar, descargar, inspeccionar y configurar módulos sin reiniciar.

lsmod lista los módulos cargados actualmente, con su tamaño y una columna 'Used by' que muestra qué otros módulos dependen de ellos. Simplemente da formato al contenido de /proc/modules. modinfo nombre muestra detalles de un archivo de módulo: su ruta, descripción, licencia, autor, dependencias y, lo más importante, los parámetros que acepta. Esa lista de parámetros es la forma de saber qué opciones puedes configurar.

modprobe es la herramienta inteligente para cargar y quitar módulos. modprobe nombre carga el módulo y los módulos de los que depende, usando el mapa de dependencias construido por depmod. modprobe -r nombre lo quita junto con las dependencias que ya no se usan. Puedes pasar parámetros en la línea de comandos, como en modprobe nombre opcion=valor. Los comandos más antiguos insmod y rmmod cargan o quitan un solo archivo de módulo y no resuelven dependencias, por eso se prefiere modprobe.

La configuración persistente de módulos vive en archivos bajo /etc/modprobe.d/ que terminan en .conf. Una línea options establece parámetros cada vez que se carga el módulo (options mymodule debug=1), y una línea blacklist impide la carga automática por alias (blacklist nouveau). Poner en la lista negra no impide un modprobe explícito; para bloquear eso también, los administradores agregan una línea install nombre /bin/false. Para cargar un módulo en cada arranque, inclúyelo en un archivo bajo /etc/modules-load.d/. Si el módulo se necesita al principio del arranque, reconstruye el initramfs después para que el cambio quede incluido.

Los parámetros del kernel son una idea distinta: ajustes de tiempo de ejecución del propio kernel, expuestos como archivos bajo /proc/sys. El comando sysctl los lee y escribe usando nombres con puntos que reflejan la ruta, así que net.ipv4.ip_forward es /proc/sys/net/ipv4/ip_forward. sysctl -a los lista todos, sysctl net.ipv4.ip_forward muestra uno y sysctl -w net.ipv4.ip_forward=1 lo cambia de inmediato, pero solo hasta el reinicio.

Para que un cambio de sysctl sea persistente, coloca net.ipv4.ip_forward = 1 en un archivo como /etc/sysctl.d/90-forward.conf (o en /etc/sysctl.conf) y luego aplícalo con sysctl --system o sysctl -p archivo. Ejemplos comunes del examen son habilitar el reenvío IP para un router o un host de contenedores, ajustar vm.swappiness y configuraciones de endurecimiento de seguridad como ignorar las redirecciones ICMP. En cambio, los argumentos del kernel en el arranque se establecen en la línea de comandos de GRUB, no con sysctl.

Términos clave

Kernel module (módulo del kernel)
Una pieza cargable de código del kernel (archivo .ko), como un controlador, que se puede insertar o quitar mientras el sistema funciona.
modprobe
Carga o quita (-r) un módulo junto con sus dependencias, leyendo las opciones de /etc/modprobe.d.
modinfo
Muestra la ruta del archivo de un módulo, su descripción, dependencias y parámetros admitidos.
Blacklist (lista negra)
Una directiva de modprobe.d que impide que un módulo se cargue automáticamente por su alias.
sysctl
Una herramienta para ver y establecer parámetros de tiempo de ejecución del kernel bajo /proc/sys; los valores persistentes van en /etc/sysctl.d/*.conf.
Ejemplo real

Estás convirtiendo una VM Linux en un router entre dos subredes. sysctl net.ipv4.ip_forward devuelve 0, así que ejecutas sysctl -w net.ipv4.ip_forward=1 para probar, confirmas que el tráfico fluye y luego creas /etc/sysctl.d/90-router.conf con net.ipv4.ip_forward = 1 para que el ajuste sobreviva a los reinicios.

Consejo para el examen: Cuidado con la trampa de la persistencia: los cambios hechos con modprobe y sysctl -w desaparecen al reiniciar; la persistencia viene de /etc/modprobe.d o /etc/modules-load.d para los módulos y de /etc/sysctl.d para los parámetros del kernel.

Comprueba lo que sabes

¿Cuál es la diferencia entre insmod y modprobe?

insmod carga un solo archivo de módulo y no maneja dependencias; modprobe carga por nombre y carga automáticamente las dependencias necesarias.

¿Cómo impides de forma permanente que el controlador nouveau se cargue automáticamente?

Agrega 'blacklist nouveau' a un archivo .conf en /etc/modprobe.d/ y reconstruye el initramfs si el módulo se carga al principio del arranque.

¿Qué ruta de archivo corresponde a la clave de sysctl vm.swappiness?

/proc/sys/vm/swappiness.
