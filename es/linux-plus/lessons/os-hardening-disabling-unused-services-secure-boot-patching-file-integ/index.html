CompTIA Linux+ XK0-006

Endurecimiento del sistema operativo: deshabilitar servicios sin uso, Secure Boot, parches, integridad de archivos (AIDE)

Endurecer (hardening) significa reducir la superficie de ataque de un sistema: quitar lo que no se necesita, restringir lo que queda, mantener el software actualizado y vigilar los cambios no autorizados. Ningún control por sí solo detiene todos los ataques, así que el endurecimiento combina varias defensas en capas, un enfoque llamado defensa en profundidad.

Empieza por los servicios. Cada servicio de red que escucha es un posible punto de entrada, así que ejecuta solo lo que requiere el rol del servidor. ss -tulpn lista los puertos TCP y UDP en escucha con el proceso propietario, y systemctl list-unit-files --state=enabled muestra lo que arranca en el boot. Para todo lo innecesario, systemctl disable --now nombre lo detiene e impide que arranque, y systemctl mask lo bloquea por completo. Mejor aún, elimina los paquetes innecesarios con dnf o apt para que no haya nada que parchear. Los protocolos heredados en texto claro como Telnet, rsh y FTP simple deberían reemplazarse por SSH y SFTP. Las imágenes de instalación mínima facilitan esto desde el principio.

Secure Boot es una función de UEFI que verifica las firmas digitales de los componentes de arranque para que solo se ejecute código de confianza antes del sistema operativo. La mayoría de las distribuciones usan un pequeño cargador shim firmado que luego verifica GRUB y el kernel, y el kernel puede exigir módulos firmados. Esto defiende contra bootkits y rootkits que manipulan el arranque temprano. mokutil --sb-state muestra si Secure Boot está habilitado. Los módulos del kernel de terceros, como algunos controladores, deben estar firmados con una clave registrada como MOK (Machine Owner Key) o no se cargarán. Protege también el firmware y GRUB con contraseñas para que un atacante con acceso a la consola no pueda cambiar fácilmente los parámetros de arranque.

Aplicar parches corrige vulnerabilidades conocidas, y el software sin parchear es una de las formas más comunes en que se comprometen los sistemas. Aplica actualizaciones con regularidad con dnf upgrade o apt update && apt upgrade, dando prioridad a las actualizaciones de seguridad (dnf updateinfo list --security o dnf upgrade --security). Automatiza donde corresponda con dnf-automatic o unattended-upgrades. Las actualizaciones del kernel necesitan un reinicio para surtir efecto, a menos que uses un servicio de parcheo en vivo (live patching). Prueba primero las actualizaciones en sistemas que no sean de producción, programa ventanas de mantenimiento y ten un plan de reversión, como instantáneas o dnf history undo.

El monitoreo de integridad de archivos detecta cambios no autorizados en archivos importantes, una señal común de intrusión. AIDE (Advanced Intrusion Detection Environment) construye una base de datos de atributos y hashes de archivos, y luego compara los escaneos posteriores contra ella. La configuración está en /etc/aide.conf (o /etc/aide/aide.conf). Uso típico: aide --init crea la base de datos, mueves el archivo nuevo a su lugar como base de datos de referencia (por ejemplo renombrando aide.db.new.gz a aide.db.gz), y luego aide --check informa los archivos agregados, eliminados y modificados, normalmente desde una tarea diaria de cron o un timer. Después de cambios legítimos, como aplicar parches, ejecuta aide --update y reemplaza la base de datos. Guarda una copia de la base de datos fuera de línea o en solo lectura, ya que de lo contrario un atacante con root podría alterarla.

Otros pasos comunes de endurecimiento incluyen configuraciones estrictas de SSH, un firewall de host, SELinux o AppArmor en modo de aplicación, opciones de montaje restrictivas (noexec, nosuid, nodev en /tmp), configuraciones de red sensatas en sysctl, deshabilitar módulos del kernel sin uso, políticas de contraseñas sólidas y registro centralizado. Los benchmarks de endurecimiento reúnen todo esto en listas de verificación.

Términos clave

Attack surface (superficie de ataque)
El conjunto total de servicios, software e interfaces que un atacante podría intentar explotar.
Secure Boot
Una función de UEFI que solo ejecuta cargadores de arranque y kernels firmados, bloqueando el código de arranque manipulado.
MOK
Machine Owner Key: una clave registrada por el usuario que se usa con shim para confiar en módulos o kernels firmados adicionales.
AIDE
Advanced Intrusion Detection Environment: un verificador de integridad de archivos que compara los archivos con una base de datos de referencia.
Patch management (gestión de parches)
El proceso de probar y aplicar regularmente actualizaciones de software para corregir vulnerabilidades.
Ejemplo real

Al endurecer un nuevo relay de correo, ejecutas ss -tulpn y encuentras cups y un antiguo listener de rpcbind. Deshabilitas y eliminas ambos paquetes, aplicas todas las actualizaciones de seguridad con dnf upgrade --security y reinicias con el nuevo kernel, confirmas que mokutil --sb-state informa Secure Boot habilitado e inicializas AIDE para que una verificación nocturna señale cambios inesperados en /etc y /usr/bin.

Consejo para el examen: Después de actualizaciones legítimas hay que actualizar la línea base de AIDE, o cada binario parcheado aparecerá como un cambio y las intrusiones reales se esconderán entre el ruido.

Comprueba lo que sabes

¿Qué comando lista los puertos en escucha y los procesos propietarios?

ss -tulpn.

¿Contra qué amenaza defiende principalmente Secure Boot?

Contra cargadores de arranque, kernels y código de arranque temprano manipulados o maliciosos, como bootkits y rootkits.

¿Qué compara aide --check?

El estado actual de los archivos monitoreados (hashes, permisos, propiedad, tamaños) contra la base de datos de referencia guardada.
