Cuentas y grupos locales: useradd, usermod -aG, userdel, groupadd, passwd, chage

Todo proceso en Linux se ejecuta como algún usuario, y el acceso a archivos y comandos se deriva de ese usuario y sus grupos. Crear y mantener cuentas locales es trabajo básico de administración y una fuente constante de preguntas de Linux+, en especial sobre opciones que es fácil confundir. Todos estos comandos editan los archivos de cuentas por ti, lo cual es más seguro que editarlos a mano.

useradd crea una cuenta. Opciones útiles: -m crea el directorio personal (copiando archivos desde /etc/skel), -d establece una ruta personalizada para el directorio personal, -s /bin/bash establece el shell de inicio de sesión, -c 'Full Name' establece el campo de comentario (GECOS), -u establece un UID (identificador de usuario) concreto, -g establece el grupo primario y -G establece los grupos suplementarios. Que el directorio personal se cree de forma predeterminada depende de /etc/login.defs (CREATE_HOME), que varía entre distribuciones, así que pasar -m es el hábito seguro. Los sistemas de la familia Debian también tienen adduser, un envoltorio interactivo más amigable. Las cuentas de sistema para servicios se crean con useradd -r, que les da un UID del rango del sistema y, normalmente, ningún directorio personal; combínalo con -s /sbin/nologin para que nadie pueda iniciar sesión como el servicio.

passwd alice establece o cambia la contraseña de un usuario; ejecutado por un usuario normal, passwd cambia la propia. passwd -l bloquea una cuenta anteponiendo ! al hash guardado, passwd -u la desbloquea y passwd -S muestra su estado. Bloquear la contraseña no impide los inicios de sesión con clave SSH; para deshabilitar por completo una cuenta, además hazla expirar (usermod -e 1 o chage -E 0) o cambia su shell a /sbin/nologin. usermod modifica una cuenta existente. El detalle más evaluado es la pertenencia a grupos: usermod -aG wheel alice añade a alice al grupo wheel. Sin -a, -G reemplaza la lista completa de grupos suplementarios, quitándola sin aviso de cualquier grupo que no aparezca. Otras opciones: -s cambia el shell, -L/-U bloquean y desbloquean, -l cambia el nombre de inicio de sesión, -d /new/home -m mueve el directorio personal y -e YYYY-MM-DD establece una fecha de expiración de la cuenta.

userdel alice elimina la cuenta pero deja sus archivos; userdel -r alice también elimina el directorio personal y la cola de correo. Antes de borrar, considera buscar los archivos que posee en otros lugares con find / -user alice, ya que los archivos restantes mostrarán un UID sin nombre y podría heredarlos un futuro usuario que reciba ese UID. Los grupos se administran con groupadd devs, groupmod -n para renombrar, groupdel para borrar, y gpasswd -a user group o gpasswd -d user group para añadir o quitar miembros. Cada usuario tiene un grupo primario (asignado a los archivos nuevos) y cualquier cantidad de grupos suplementarios (usados para el acceso). Los cambios de grupo surten efecto en el siguiente inicio de sesión del usuario; id alice o groups alice confirman la pertenencia, y newgrp puede cambiar el grupo primario en el shell actual. chage administra el envejecimiento de contraseñas. chage -l alice muestra la política, -M 90 establece el máximo de días entre cambios, -m 1 el mínimo de días, -W 7 los días de aviso, -I los días de inactividad tras la expiración antes de deshabilitar la cuenta, -E 2026-12-31 una fecha de expiración de la cuenta y -d 0 obliga a cambiar la contraseña en el siguiente inicio de sesión, algo común al entregar una contraseña temporal a un usuario nuevo.

useradd -m -s /bin/bash -c 'Priya Shah' -G devs priya
passwd priya
chage -d 0 priya
usermod -aG docker priya
id priya

Veamos un ejemplo práctico. Una nueva desarrolladora, Priya, empieza hoy. Ejecutas los comandos anteriores: creas la cuenta con directorio personal, shell bash, comentario y el grupo devs; estableces una contraseña temporal; y la obligas a cambiarla en el primer inicio de sesión con chage -d 0. Un mes después necesita acceso a contenedores, así que usermod -aG docker priya añade el grupo, id priya lo confirma y le recuerdas que cierre sesión y vuelva a entrar. Cuando un contratista se va, bloqueas la cuenta de inmediato con usermod -L -e 1 contractor y la eliminas con userdel -r después de archivar sus archivos.

Errores comunes: usar usermod -G sin -a y borrar las pertenencias existentes; esperar que un cambio de grupo se aplique en una sesión ya abierta; suponer que passwd -l impide los inicios de sesión con clave SSH; ejecutar userdel -r antes de archivar archivos necesarios; y olvidar -m, de modo que el usuario inicia sesión sin directorio personal.

En el examen, 'añadir a un grupo sin afectar las pertenencias existentes' significa -aG; 'obligar a cambiar la contraseña en el siguiente inicio de sesión' significa chage -d 0; 'eliminar el usuario y su directorio personal' significa userdel -r; 'hacer que la cuenta expire en una fecha' significa chage -E o usermod -e; y 'el usuario todavía no puede usar el nuevo grupo' significa que debe volver a iniciar sesión.

Términos clave

UID / GID
Identificadores numéricos de usuario y de grupo que el kernel usa realmente para la propiedad y las comprobaciones de permisos.
Grupo primario (primary group)
El grupo asignado a un usuario en /etc/passwd y que se asigna a los archivos que crea el usuario.
Grupo suplementario (supplementary group)
Grupos adicionales a los que pertenece un usuario, listados en /etc/group, que otorgan acceso extra.
usermod -aG
Añade un usuario a grupos suplementarios sin quitar las pertenencias existentes.
chage
Comando que muestra y establece el envejecimiento de contraseñas y la expiración de la cuenta de un usuario.
Cuenta de sistema (system account)
Una cuenta de pocos privilegios creada con useradd -r para ejecutar un servicio, normalmente sin shell de inicio de sesión.
Ejemplo real

Una nueva desarrolladora, Priya, empieza hoy. Ejecutas useradd -m -s /bin/bash -c 'Priya Shah' -G devs priya, estableces una contraseña temporal con passwd priya y la obligas a cambiarla en el primer inicio de sesión con chage -d 0 priya. Un mes después necesita acceso a contenedores, así que ejecutas usermod -aG docker priya y le recuerdas que cierre sesión y vuelva a entrar.

Consejo para el examen: La trampa clásica es usermod -G sin -a: reemplaza todos los grupos suplementarios. Cuando una pregunta diga 'añadir a un grupo sin afectar las pertenencias existentes', la respuesta incluye -aG.

Comprueba lo que sabes

¿Qué hace chage -d 0 bob?

Establece en 0 la fecha del último cambio de contraseña de bob, obligándolo a cambiar su contraseña en el siguiente inicio de sesión.

¿Qué comando elimina al usuario carol y su directorio personal?

userdel -r carol, ya que userdel sin opciones deja el directorio personal y la cola de correo.

Después de usermod -aG sudo dave, dave todavía no puede usar sudo en su sesión actual. ¿Por qué?

La pertenencia a grupos se lee al iniciar sesión, así que debe cerrar sesión y volver a entrar (o iniciar una nueva sesión) para que se aplique el nuevo grupo.

¿Por qué passwd -l por sí solo no deshabilita por completo una cuenta?

Solo bloquea la autenticación por contraseña; los inicios de sesión con clave SSH siguen funcionando a menos que la cuenta también se haga expirar o reciba un shell nologin.
