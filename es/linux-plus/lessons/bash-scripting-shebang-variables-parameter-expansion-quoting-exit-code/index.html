CompTIA Linux+ XK0-006

Scripts en Bash: shebang, variables, expansión de parámetros, comillas, códigos de salida y $?

Un script de Bash es un archivo de texto con comandos del shell que se ejecutan en secuencia, lo que te permite automatizar cualquier cosa que puedas escribir. Las preguntas basadas en desempeño de Linux+ a menudo muestran un script corto y preguntan qué imprime o por qué falla, así que la sintaxis central debe estar bien firme.

La primera línea es el shebang, que le dice al kernel qué intérprete debe ejecutar el archivo: #!/bin/bash, o #!/usr/bin/env bash para encontrar bash en el PATH. Haz el script ejecutable con chmod +x script.sh y ejecútalo como ./script.sh; como alternativa, bash script.sh lo ejecuta sin permiso de ejecución. Ejecutarlo con source script.sh (o . script.sh) lo corre en el shell actual, así que las variables que establece permanecen después. Las líneas que empiezan con # son comentarios.

Las variables se asignan sin espacios alrededor del signo igual: name=web01. Los espacios lo rompen, porque name = web01 ejecuta un comando llamado name. Lee un valor con $name o ${name}; las llaves son necesarias cuando sigue texto, como en ${name}_backup. La sustitución de comandos captura la salida: today=$(date +%F). La aritmética usa $(( )): count=$((count + 1)). Los parámetros especiales incluyen $0 (nombre del script), $1, $2... (argumentos posicionales), $# (número de argumentos), $@ (todos los argumentos como palabras separadas), $$ (el PID del script) y $? (estado de salida del último comando). read -p 'Name: ' user lee una entrada del usuario.

La expansión de parámetros transforma variables sin llamar a herramientas externas. ${var:-default} usa un valor predeterminado si var no está definida o está vacía, ${var:=default} además lo asigna, ${var:?message} sale con un error si no está definida, ${#var} da la longitud, ${file%.txt} quita un patrón de sufijo (útil para cambiar extensiones), ${path##*/} quita el prefijo más largo hasta la última barra (como basename) y ${var/old/new} reemplaza la primera coincidencia.

Las comillas controlan cómo trata el shell los caracteres especiales. Las comillas dobles permiten la expansión de variables y comandos, pero evitan la división en palabras y el globbing: "$file" sigue siendo un solo argumento aunque contenga espacios. Las comillas simples hacen todo literal: '$HOME' imprime los cuatro caracteres tal cual. La barra invertida escapa un solo carácter. La regla general es poner entre comillas dobles cada expansión de variable, "$var" y "$@", a menos que quieras específicamente la división; muchos errores de scripts vienen de variables sin comillas que contienen espacios o comodines.

Todo comando devuelve un estado de salida de 0 a 255: 0 significa éxito y cualquier otro valor significa fallo, con el significado definido por el programa. $? contiene el estado del comando más reciente, así que revísalo de inmediato, porque el siguiente comando lo sobrescribe. Un script establece su propio estado con exit 0 o exit 1. Los operadores && y || usan los códigos de salida: mkdir /backup && cp file /backup copia solo si mkdir tuvo éxito, y ping -c1 host || echo 'down' imprime solo en caso de fallo.

#!/bin/bash
target="${1:-/var/log}"
size=$(du -sh "$target" 2>/dev/null)
status=$?
if [ "$status" -ne 0 ]; then
  echo "cannot read $target (exit $status)" >&2
  exit 1
fi
echo "$target uses ${size%%[[:space:]]*}"

Términos clave

Shebang
La primera línea #! de un script que nombra al intérprete, como #!/bin/bash.
Positional parameters (parámetros posicionales)
$1, $2, etc., que contienen los argumentos pasados a un script; $# los cuenta y $@ los lista.
Parameter expansion (expansión de parámetros)
Sintaxis ${...} que proporciona valores predeterminados, recorta patrones o sustituye texto en variables.
Command substitution (sustitución de comandos)
Sintaxis $(comando) que se reemplaza a sí misma por la salida del comando.
Exit status ($?) (estado de salida)
El resultado de 0 a 255 del último comando, donde 0 significa éxito.
Ejemplo real

Un script de respaldo falla con un archivo llamado 'Q3 report.xlsx'. La línea cp $file /backup dividió el nombre en dos argumentos. Cambiarla a cp "$file" /backup lo soluciona, y agregar if [ $? -ne 0 ]; then echo 'copy failed' >&2; exit 1; fi hace visible el fallo en los logs de la tarea de cron.

Consejo para el examen: Busca espacios alrededor de = en las asignaciones y variables sin comillas; ambos son errores deliberados comunes en las preguntas de scripts del examen.

Comprueba lo que sabes

¿Qué produce ${filename%.log} si filename es app.log?

app, porque % quita el patrón de sufijo coincidente más corto, .log.

¿Cuál es la diferencia entre echo '$HOME' y echo "$HOME"?

Las comillas simples imprimen el texto literal $HOME; las comillas dobles lo expanden a la ruta del directorio personal.

¿Por qué debes revisar $? inmediatamente después del comando que te interesa?

Porque cada comando, incluidos echo o test, sobrescribe $? con su propio estado de salida.
