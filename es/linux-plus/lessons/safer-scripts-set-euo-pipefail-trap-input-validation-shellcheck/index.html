Scripts más seguros: set -euo pipefail, trap, validación de entradas, shellcheck

Por defecto, Bash es permisivo: si un comando falla, el script continúa, una variable no definida se convierte silenciosamente en una cadena vacía y una falla al inicio de un pipeline se ignora. Esa tolerancia convierte pequeños errores en grandes daños, como un script que ejecuta rm -rf "$dir/"* cuando dir nunca se definió. Los hábitos de scripting defensivo evitan esto, y Linux+ espera que los reconozcas en el código y elijas el adecuado para un problema descrito.

set -e (errexit) hace que el script termine cuando un comando falla, a menos que la falla forme parte de una condición, como una prueba if o un comando seguido de ||. set -u (nounset) trata las referencias a variables no definidas como errores, lo que detecta errores de tipeo y argumentos faltantes. set -o pipefail hace que un pipeline devuelva el estado del último comando que falló en lugar de solo el del comando final, así que grep pattern missing.txt | sort informa la falla. Combinados, set -euo pipefail cerca del inicio es un punto de partida común de modo estricto. No es magia: algunos comandos devuelven legítimamente un valor distinto de cero (grep sin coincidencias devuelve 1), así que manéjalos con || true o con una verificación explícita. set -x imprime cada comando antes de ejecutarlo, lo que ayuda a depurar, y bash -n script.sh verifica la sintaxis sin ejecutar nada.

trap ejecuta un comando cuando el script recibe una señal o termina. trap cleanup EXIT llama a una función de limpieza sin importar cómo termine el script, lo que es ideal para eliminar archivos temporales o liberar archivos de bloqueo. trap 'echo interrupted; exit 130' INT TERM maneja Ctrl+C y la terminación, y trap '...' ERR puede registrar la línea que falló. Crea los archivos temporales de forma segura con mktemp en lugar de nombres fijos como /tmp/data, que otro usuario podría crear de antemano o convertir en un enlace simbólico que apunte a un archivo que tú terminarías sobrescribiendo.

#!/usr/bin/env bash
set -euo pipefail
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT
[[ $# -eq 1 ]] || { echo "usage: $0 <username>" >&2; exit 2; }
user=$1
[[ $user =~ ^[a-z_][a-z0-9_-]{0,31}$ ]] || { echo "invalid username" >&2; exit 2; }
getent passwd "$user" > "$tmp"

La validación de entradas trata cada argumento, variable de entorno y línea de archivo como no confiable. Verifica la cantidad de argumentos ($#), compara los valores con una lista de permitidos (allow-list) o con una expresión regular estricta, confirma que los archivos existen y que los directorios son los que esperas, y rechaza valores peligrosos como una ruta vacía o /. Pon comillas en cada expansión para que la entrada no pueda dividirse en argumentos adicionales ni expandir comodines, y usa -- antes de los nombres proporcionados por el usuario para que uno que empiece con guion no se interprete como opción (rm -- "$file"). Nunca pases la entrada a eval ni construyas comandos como cadenas, porque eso invita a la inyección de comandos. Los scripts que se ejecutan con sudo o desde cron como root merecen cuidado adicional y deben usar rutas absolutas o definir el PATH explícitamente. ShellCheck es una herramienta de análisis estático que advierte sobre errores comunes: variables sin comillas, errores como [ $a == $b ], código inalcanzable y problemas de portabilidad. Ejecuta shellcheck script.sh y corrige o suprime conscientemente cada hallazgo; las advertencias tienen códigos como SC2086 (poner comillas dobles para evitar el globbing y la división en palabras). Muchos equipos ejecutan ShellCheck en pipelines de CI (integración continua) para detectar los problemas antes de que los scripts lleguen a los servidores.

Considera un ejemplo práctico. El script anterior exige exactamente un argumento y, si no, imprime el modo de uso con el código de salida 2. Verifica el nombre de usuario contra un patrón estricto, así que una entrada como alice; rm -rf / se rechaza antes de usarse en cualquier parte. mktemp crea un archivo temporal único y el trap de EXIT lo elimina tanto si el script tiene éxito, como si falla por set -e o si se interrumpe. Si getent no encuentra al usuario, devuelve 2, y el modo estricto detiene el script ahí en lugar de continuar con un archivo vacío. Ejecutar shellcheck sobre él no informa ninguna advertencia.

Errores comunes: suponer que set -e detecta las fallas dentro de condiciones if o antes de ||, que ignora deliberadamente; olvidar que grep, al devolver 1 cuando no hay coincidencias, abortará un script estricto; usar nombres fijos para archivos temporales en /tmp; validar la entrada pero luego usarla sin comillas; depender del PATH de quien lo invoca en un trabajo de cron de root; y silenciar todas las advertencias de ShellCheck en lugar de entenderlas.

Las preguntas del examen describen un riesgo y piden el control. 'El script continuó después de que falló un comando' es set -e. 'Un error de tipeo en el nombre de una variable pasó desapercibido' o 'variable no definida' es set -u. 'Se ignoró una falla en medio de un pipeline' es pipefail. 'Eliminar siempre los archivos temporales, incluso ante un error o Ctrl+C' es trap ... EXIT con mktemp. 'Encontrar problemas de comillas y errores comunes antes de ejecutar' es ShellCheck, y 'verificar solo la sintaxis' es bash -n.

Términos clave

set -e
Termina el script cuando un comando falla fuera de una condición o de una lista con ||.
set -u
Trata el uso de una variable no definida como un error que detiene el script.
pipefail
Hace que el estado de salida de un pipeline refleje el último comando que falló en lugar de solo el final.
trap
Registra un comando para ejecutarlo ante una señal o en EXIT, usado comúnmente para la limpieza.
mktemp
Crea de forma segura un archivo o directorio temporal con un nombre único.
Validación de entradas (input validation)
Verificar los argumentos y los datos contra formatos esperados o listas de permitidos antes de usarlos.
ShellCheck
Una herramienta de análisis estático que informa errores comunes en scripts de shell con códigos como SC2086.
Ejemplo real

Un script de limpieza contenía rm -rf "$BASE_DIR"/cache/*. Al ejecutarse desde cron, BASE_DIR no estaba definida, así que apuntaba a /cache. Después de estar a punto de causar un desastre, el equipo agrega set -euo pipefail para que la variable no definida aborte el script, valida que BASE_DIR sea un directorio existente y no vacío, agrega un trap para eliminar los archivos temporales y ejecuta shellcheck en CI con cada cambio.

Consejo para el examen: Conoce lo que detecta cada opción del modo estricto: -e los comandos fallidos, -u las variables no definidas y pipefail las fallas ocultas dentro de los pipelines. set -e no se activa dentro de condiciones if ni antes de ||.

Comprueba lo que sabes

Sin pipefail, ¿qué estado de salida devuelve false | true?

0, porque solo cuenta el estado del último comando (true).

¿Cómo garantizas que un archivo temporal se elimine cuando un script termina, incluso ante un error?

Créalo con mktemp y registra trap 'rm -f "$tmp"' EXIT (o una función de limpieza).

¿Qué suele pedirte la advertencia SC2086 de ShellCheck?

Poner entre comillas dobles una expansión de variable para evitar la división en palabras y el globbing.

¿Por qué debes escribir rm -- "$file" en lugar de rm $file para nombres proporcionados por el usuario?

Las comillas mantienen el nombre como un solo argumento, y -- impide que un nombre que empieza con guion se interprete como una opción.
