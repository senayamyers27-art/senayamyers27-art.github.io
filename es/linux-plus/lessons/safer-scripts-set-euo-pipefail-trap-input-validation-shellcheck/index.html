Scripts más seguros: set -euo pipefail, trap, validación de entradas, shellcheck

De forma predeterminada, Bash es permisivo: si un comando falla, el script sigue adelante, una variable no definida se convierte silenciosamente en una cadena vacía y un fallo al principio de una tubería se ignora. Esa tolerancia convierte pequeños errores en grandes daños, como un script que ejecuta rm -rf "$dir/"* cuando dir nunca se definió. Los hábitos de programación defensiva evitan esto, y Linux+ espera que los reconozcas.

set -e (errexit) hace que el script salga cuando un comando falla, a menos que el fallo sea parte de una condición, como una prueba if o un comando seguido de ||. set -u (nounset) trata las referencias a variables no definidas como errores, detectando errores de tipeo y argumentos faltantes. set -o pipefail hace que una tubería devuelva el estado del último comando que falló en lugar de solo el del comando final, así que grep pattern missing.txt | sort informa el fallo. Combinados, set -euo pipefail cerca del inicio de un script es un punto de partida común de modo estricto. No es magia: algunos comandos devuelven legítimamente un valor distinto de cero (grep sin coincidencias devuelve 1), así que manéjalos con || true o con una comprobación explícita. set -x imprime cada comando antes de ejecutarlo, lo cual es útil para depurar, y bash -n script.sh revisa la sintaxis sin ejecutar nada.

trap ejecuta un comando cuando el script recibe una señal o termina. trap cleanup EXIT llama a una función de limpieza sin importar cómo termine el script, lo cual es ideal para eliminar archivos temporales o liberar archivos de bloqueo. trap 'echo interrupted; exit 130' INT TERM maneja Ctrl+C y la terminación, y trap '...' ERR puede registrar la línea que falló. Crea archivos temporales de forma segura con mktemp en lugar de nombres fijos como /tmp/data, que otro usuario podría crear de antemano o convertir en un enlace simbólico.

#!/usr/bin/env bash
set -euo pipefail
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT
[[ $# -eq 1 ]] || { echo "usage: $0 <username>" >&2; exit 2; }
user=$1
[[ $user =~ ^[a-z_][a-z0-9_-]{0,31}$ ]] || { echo "invalid username" >&2; exit 2; }
getent passwd "$user" > "$tmp"

La validación de entradas trata cada argumento, variable de entorno y línea de archivo como no confiable. Comprueba la cantidad de argumentos ($#), compara los valores con una lista de permitidos o una expresión regular estricta, confirma que los archivos existen y que los directorios son lo que esperas, y rechaza valores peligrosos como una ruta vacía o /. Pon entre comillas cada expansión para que la entrada no se divida en argumentos extra ni expanda comodines, y usa -- antes de los nombres de archivo que proporciona el usuario para que un nombre que empiece con guion no se trate como una opción (rm -- "$file"). Nunca pases entradas a eval ni construyas comandos como cadenas, porque eso invita a la inyección de comandos. Los scripts que se ejecutan con sudo o desde cron como root merecen un cuidado extra, y deberían usar rutas absolutas o establecer PATH explícitamente.

ShellCheck es una herramienta de análisis estático que lee un script y advierte sobre errores comunes: variables sin comillas, uso inútil de cat, errores de [ $a == $b ], código inalcanzable y muchos problemas de portabilidad. Ejecuta shellcheck script.sh y corrige o suprime conscientemente cada hallazgo; sus advertencias tienen códigos como SC2086 (usa comillas dobles para evitar el globbing y la división en palabras). Muchos equipos ejecutan ShellCheck automáticamente en pipelines de CI (integración continua) para detectar los problemas antes de que los scripts lleguen a los servidores.

Términos clave

set -e
Hace que el script salga cuando un comando falla fuera de un contexto condicional.
set -u
Trata el uso de una variable no definida como un error.
pipefail
Hace que el estado de salida de una tubería refleje el comando fallido más a la derecha, no solo el último comando.
trap
Registra un comando que se ejecuta ante señales o al salir el script (EXIT), a menudo para limpieza.
ShellCheck
Un analizador estático que señala errores y patrones riesgosos en scripts de shell.
Ejemplo real

Un script de limpieza contenía rm -rf "$BASE_DIR"/cache/*. Al ejecutarse desde cron, BASE_DIR no estaba definida, así que apuntaba a /cache. Después de salvarse por poco, el equipo agrega set -euo pipefail para que la variable no definida aborte el script, valida que BASE_DIR sea un directorio existente y no vacío, agrega un trap para eliminar los archivos temporales y ejecuta shellcheck en CI con cada cambio.

Consejo para el examen: Conoce lo que atrapa cada opción del modo estricto: -e los comandos fallidos, -u las variables no definidas y pipefail los fallos ocultos dentro de las tuberías.

Comprueba lo que sabes

Sin pipefail, ¿qué estado de salida devuelve false | true?

0, porque solo cuenta el estado del último comando (true).

¿Cómo garantizas que un archivo temporal se elimine cuando un script termina, incluso por error?

Créalo con mktemp y registra trap 'rm -f "$tmp"' EXIT (o una función de limpieza).

¿Qué suele pedirte la advertencia SC2086 de ShellCheck?

Poner entre comillas dobles una expansión de variable para evitar la división en palabras y el globbing.
