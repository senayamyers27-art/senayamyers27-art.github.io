CompTIA Linux+ XK0-006

Código fuente y paquetes de lenguajes: make, pip, paquetes aislados (Flatpak, Snap)

No todo el software llega a través de los repositorios de tu distribución. A veces compilas desde el código fuente, instalas una biblioteca con el gestor de paquetes de un lenguaje o usas un paquete universal aislado (sandboxed). Cada enfoque tiene ventajas y desventajas en actualizaciones, seguridad y orden, y Linux+ espera que sepas cómo funciona cada uno y cuándo preferirlo.

Compilar desde el código fuente normalmente sigue tres pasos. Primero, ./configure (generado por GNU Autotools) verifica los compiladores y bibliotecas y escribe un Makefile; opciones como --prefix=/usr/local eligen la ubicación de instalación. Segundo, make lee el Makefile y compila el código. Tercero, make install, normalmente ejecutado con sudo, copia los resultados a su lugar. Primero necesitas las herramientas de compilación, instaladas como grupo: dnf groupinstall 'Development Tools' en sistemas de la familia RHEL o apt install build-essential en sistemas de la familia Debian, más los paquetes de encabezados -devel o -dev de las bibliotecas que use el software. Los proyectos pueden usar otros sistemas de compilación como CMake o Meson, pero la idea es la misma.

La desventaja es que el gestor de paquetes no sabe nada del software instalado de esta forma: no hay actualizaciones de seguridad automáticas, no hay desinstalación limpia (algunos proyectos ofrecen make uninstall) y pueden surgir conflictos con archivos empaquetados. Instalar bajo /usr/local u /opt limita el daño, y verificar la suma de verificación o la firma del código fuente antes de compilar protege contra descargas manipuladas.

Los ecosistemas de lenguajes tienen sus propios gestores: pip para Python, npm para JavaScript, gem para Ruby, cargo para Rust. Con pip, pip install requests instala un paquete, pip install -r requirements.txt instala una lista con versiones fijas, pip list y pip show inspeccionan, y pip uninstall elimina. Instalar en el Python del sistema con sudo puede romper herramientas de las que depende el sistema operativo, y muchas distribuciones actuales ya lo rechazan marcando el entorno del sistema como administrado externamente. La práctica segura es un entorno virtual: python3 -m venv venv, source venv/bin/activate, y luego pip instala solo en ese proyecto. pip install --user es una alternativa para herramientas por usuario.

Los paquetes universales aislados agrupan una aplicación con sus dependencias para que un solo paquete funcione en muchas distribuciones, aislado del resto del sistema. Flatpak está orientado principalmente a aplicaciones de escritorio. Instala desde remotos como Flathub: flatpak remote-add, flatpak install flathub <app-id>, flatpak run <app-id>, flatpak update, y los permisos se pueden ajustar con flatpak override. Snap, desarrollado por Canonical y estándar en Ubuntu, funciona como el servicio snapd y maneja software tanto de escritorio como de servidor: snap install nombre, snap list, snap refresh (los snaps también se actualizan automáticamente), snap remove. Los snaps se ejecutan en modos de confinamiento, donde strict confina la aplicación y classic le da acceso normal al sistema.

La contrapartida de los paquetes aislados es un mayor uso de disco y un canal de actualización separado, a cambio de versiones más nuevas y aislamiento. En servidores, prefiere los paquetes de la distribución siempre que sea posible, porque reciben actualizaciones de seguridad coordinadas.

Términos clave

make
Una herramienta de compilación que lee un Makefile y ejecuta los pasos para compilar software; make install lo copia a su lugar.
./configure
Un script que verifica las dependencias de compilación y genera un Makefile, a menudo con --prefix para establecer la ruta de instalación.
pip
El instalador de paquetes de Python, que conviene usar dentro de un entorno virtual.
Flatpak
Un formato de empaquetado universal aislado, principalmente para aplicaciones de escritorio, que comúnmente se instala desde Flathub.
Snap
El formato de paquetes aislados de Canonical administrado por snapd, con actualizaciones automáticas y modos de confinamiento.
Ejemplo real

Un agente de monitoreo solo está disponible como código fuente. Instalas build-essential y los encabezados -dev necesarios, ejecutas ./configure --prefix=/opt/agent, make y sudo make install, y luego documentas la instalación porque dnf y apt no la rastrearán. Para sus scripts auxiliares de Python, creas un venv en /opt/agent y haces pip install de los requisitos ahí en lugar de en el Python del sistema.

Consejo para el examen: El orden estándar para compilar desde el código fuente es ./configure, make, make install; normalmente solo el último paso necesita root.

Comprueba lo que sabes

¿Por qué el software instalado con make install es más difícil de mantener que un paquete de repositorio?

El gestor de paquetes no lo rastrea, así que no recibe actualizaciones automáticas y no tiene una desinstalación limpia y registrada.

¿Cuál es la forma más segura de instalar bibliotecas de Python para un proyecto sin afectar al sistema?

Crear un entorno virtual con python3 -m venv, activarlo y hacer pip install dentro de él.

¿Qué servicio debe estar en ejecución para que funcionen los paquetes Snap?

snapd.
