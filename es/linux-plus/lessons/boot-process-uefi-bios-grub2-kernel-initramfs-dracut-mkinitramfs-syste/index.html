CompTIA Linux+ XK0-006

Proceso de arranque: UEFI/BIOS, GRUB2, kernel, initramfs (dracut, mkinitramfs), targets de systemd

Cada vez que una máquina Linux se enciende, recorre una cadena predecible de relevos: firmware, cargador de arranque, kernel, sistema de archivos inicial en RAM y, por último, el sistema init. Conocer cada etapa te permite deducir dónde se detuvo un arranque fallido y qué herramienta lo soluciona, que es exactamente como se plantean las preguntas de Linux+.

Primero viene el firmware. Las máquinas antiguas usan BIOS (Basic Input/Output System), que lee el primer sector del disco de arranque, el MBR (Master Boot Record), y ejecuta el pequeño fragmento de código de arranque guardado allí. Las máquinas modernas usan UEFI (Unified Extensible Firmware Interface), que en cambio lee una ESP (EFI System Partition), una pequeña partición con formato FAT normalmente montada en /boot/efi, y ejecuta un ejecutable EFI como grubx64.efi o shimx64.efi. UEFI también admite Secure Boot, donde el firmware solo ejecuta cargadores de arranque firmados con claves de confianza. Puedes comprobar en qué modo arrancaste buscando el directorio /sys/firmware/efi: si existe, arrancaste con UEFI.

Luego viene el cargador de arranque, casi siempre GRUB2 (GRand Unified Bootloader versión 2). GRUB muestra el menú de kernels, carga en memoria la imagen del kernel elegida (por ejemplo /boot/vmlinuz-...) y el initramfs correspondiente, y le pasa al kernel su línea de comandos, como root=UUID=... y quiet. Nunca editas directamente el grub.cfg generado. En su lugar, cambias /etc/default/grub (por ejemplo GRUB_TIMEOUT o GRUB_CMDLINE_LINUX) y lo regeneras con grub2-mkconfig -o /boot/grub2/grub.cfg en sistemas de la familia Red Hat o con update-grub (un envoltorio de grub-mkconfig) en sistemas de la familia Debian. La herramienta grubby en sistemas tipo RHEL edita los argumentos del kernel por entrada.

Después, el kernel inicializa el hardware para el que tiene controladores integrados, pero a menudo todavía no puede leer el sistema de archivos raíz real, porque el controlador de la controladora de disco, LVM, RAID o cifrado vive en un módulo dentro de ese mismo sistema de archivos. El initramfs (sistema de archivos inicial en RAM) resuelve este problema del huevo y la gallina: es un archivo comprimido que se descomprime en memoria y contiene solo los módulos y scripts necesarios para encontrar, desbloquear y montar la raíz real. Se reconstruye con dracut en Red Hat, Fedora y SUSE (dracut -f regenera la imagen para el kernel en ejecución) y con mkinitramfs o update-initramfs -u en Debian y Ubuntu. Reconstrúyelo después de agregar un controlador de almacenamiento o de cambiar la configuración del dispositivo raíz.

Una vez montada la raíz, el kernel inicia el PID 1, que en las distribuciones actuales es systemd. systemd lleva el sistema a un target, un grupo con nombre de unidades que reemplaza a los antiguos runlevels de SysV. Los más comunes son multi-user.target (servidor en modo texto, como el runlevel 3), graphical.target (escritorio, como el runlevel 5), rescue.target (monousuario con servicios básicos) y emergency.target (casi nada, con el sistema de archivos raíz en solo lectura). Consulta el predeterminado con systemctl get-default, cámbialo con systemctl set-default multi-user.target y cambia el sistema en ejecución con systemctl isolate rescue.target.

Para un cambio puntual en el arranque, presiona e en el menú de GRUB y agrega systemd.unit=rescue.target (o emergency.target) a la línea que empieza con linux, y luego presiona Ctrl+X para arrancar. Esa edición no se guarda, lo que la convierte en una forma segura de recuperar un sistema sin cambiar nada de forma permanente.

Términos clave

UEFI
Unified Extensible Firmware Interface: firmware moderno que arranca ejecutables EFI desde una EFI System Partition y admite Secure Boot.
ESP (EFI System Partition)
Partición de sistema EFI: una pequeña partición FAT, normalmente montada en /boot/efi, que contiene los cargadores de arranque UEFI.
GRUB2
El cargador de arranque estándar de Linux; se configura mediante /etc/default/grub y un grub.cfg generado.
initramfs
Un sistema de archivos raíz temporal y comprimido que se carga en RAM y contiene los controladores y scripts necesarios para montar el sistema de archivos raíz real.
dracut / mkinitramfs
Herramientas que construyen la imagen initramfs: dracut en la familia Red Hat y SUSE, mkinitramfs/update-initramfs en la familia Debian.
systemd target (target de systemd)
Una unidad que agrupa otras unidades en un estado del sistema, como multi-user.target o graphical.target, y reemplaza a los runlevels de SysV.
Ejemplo real

Después de mover el sistema de archivos raíz de un servidor a una nueva controladora RAID, este no arranca y cae en un shell de emergencia de dracut que dice que no encuentra el dispositivo raíz. Arrancas una entrada de kernel anterior desde el menú de GRUB, confirmas el nombre del módulo de la controladora con lsmod y luego ejecutas dracut -f para reconstruir el initramfs de modo que incluya el nuevo controlador. El siguiente arranque encuentra el sistema de archivos raíz con normalidad.

Consejo para el examen: Relaciona el síntoma con la etapa: si no aparece el menú de GRUB, apunta al firmware o al cargador de arranque; un error de 'cannot find root' apunta al initramfs o al argumento root=; y un arranque que se detiene en un shell de emergencia después de cargar el kernel suele apuntar a unidades de systemd o a /etc/fstab.

Comprueba lo que sabes

Editaste GRUB_CMDLINE_LINUX en /etc/default/grub en un sistema RHEL, pero el cambio no tiene efecto tras reiniciar. ¿Qué paso faltó?

Regenerar la configuración de GRUB con grub2-mkconfig -o /boot/grub2/grub.cfg (o usar grubby); /etc/default/grub solo se lee cuando se reconstruye la configuración.

¿Por qué Linux necesita un initramfs?

Porque los controladores necesarios para llegar al sistema de archivos raíz (controladora de almacenamiento, LVM, RAID, LUKS) pueden ser módulos guardados en ese mismo sistema de archivos; el initramfs los lleva en RAM para que se pueda montar la raíz real.

¿Qué comando hace que un servidor arranque en una consola de texto de forma predeterminada a partir de ahora?

systemctl set-default multi-user.target.
