CompTIA Linux+ XK0-006

Configuración de red: ip, nmcli, netplan, hostnamectl, /etc/hosts, /etc/resolv.conf, nsswitch.conf

Un servidor Linux solo es útil si puede comunicarse por la red, así que Linux+ espera que sepas ver y cambiar direcciones, rutas, nombres de host y resolución de nombres con las herramientas de las distribuciones actuales. La idea clave es que algunos comandos solo cambian el estado en ejecución, mientras que otros escriben configuración persistente. Confundirlos es la causa más común de un servidor que funciona hasta su siguiente reinicio. El comando ip del paquete iproute2 reemplazó a herramientas más antiguas como ifconfig, route y arp. ip addr show (o ip a) lista interfaces y direcciones, ip link set eth0 up habilita una interfaz, ip addr add 192.168.10.5/24 dev eth0 añade una dirección, ip route show muestra la tabla de enrutamiento, ip route add default via 192.168.10.1 establece una puerta de enlace predeterminada e ip neigh muestra la caché de vecinos ARP (Address Resolution Protocol). Los cambios hechos con ip surten efecto de inmediato, pero se pierden al reiniciar. ss -tulpn lo complementa listando los sockets en escucha.

Para ajustes persistentes, la mayoría de los sistemas de la familia RHEL y muchos de escritorio usan NetworkManager, que se controla con nmcli. NetworkManager guarda perfiles de conexión, separados de los nombres de dispositivo, y un mismo dispositivo puede tener varios perfiles. Comandos útiles: nmcli device status, nmcli connection show y un cambio a dirección estática como nmcli con mod eth0 ipv4.addresses 192.168.10.5/24 ipv4.gateway 192.168.10.1 ipv4.dns 192.168.10.53 ipv4.method manual, seguido de nmcli con up eth0 para aplicarlo. nmtui ofrece un menú de texto para las mismas tareas.

Ubuntu usa netplan: describes las interfaces en archivos YAML (YAML Ain't Markup Language) bajo /etc/netplan/, y netplan los traduce para un backend, ya sea systemd-networkd o NetworkManager. Después de editar, netplan try aplica el cambio y lo revierte automáticamente a menos que lo confirmes, lo que te protege de quedarte sin acceso a un servidor remoto; netplan apply lo aplica directamente. YAML es sensible a la sangría, así que un tabulador suelto o una clave mal alineada es un error común.

network:
  version: 2
  ethernets:
    ens3:
      addresses: [10.0.5.20/24]
      routes:
        - to: default
          via: 10.0.5.1
      nameservers:
        addresses: [10.0.5.53]

hostnamectl muestra y establece el nombre de host, escribiendo en /etc/hostname: hostnamectl set-hostname web01.example.com. /etc/hosts asocia nombres con direcciones IP de forma local, útil para laboratorios pequeños o para excepciones, por ejemplo 192.168.10.20 db01. /etc/resolv.conf lista los servidores DNS (Domain Name System) en líneas nameserver y una lista de dominios de búsqueda search. En muchos sistemas, este archivo lo genera NetworkManager o systemd-resolved, así que edita el perfil de conexión en lugar del archivo, o tu cambio se sobrescribirá. /etc/nsswitch.conf (Name Service Switch) decide el orden en que se consultan las fuentes: hosts: files dns significa revisar primero /etc/hosts y luego DNS. El mismo archivo controla las búsquedas de usuarios (passwd:) y grupos, que es como se integran las cuentas de SSSD (System Security Services Daemon) o LDAP. getent hosts name sigue a nsswitch, mientras que dig consulta DNS directamente.

Veamos un ejemplo práctico. Un servidor RHEL debe pasar a una dirección estática. Trabajando desde su consola, no por SSH, ejecutas nmcli con mod ens192 ipv4.method manual ipv4.addresses 10.0.5.20/24 ipv4.gateway 10.0.5.1 ipv4.dns 10.0.5.53 y luego nmcli con up ens192. ip a confirma la dirección, ip route muestra la ruta predeterminada y getent hosts intranet.example.com resuelve. Un nombre interno todavía apunta a una dirección antigua; dig devuelve la respuesta correcta, así que revisas /etc/hosts, encuentras una entrada obsoleta y la eliminas. Un reinicio final durante la ventana de mantenimiento demuestra que los ajustes persisten.

Errores comunes: usar ip addr add y esperar que sobreviva al reinicio; editar a mano un /etc/resolv.conf generado; probar la resolución de nombres solo con dig y pasar por alto una excepción en el archivo hosts; tabuladores en el YAML de netplan; y cambiar la dirección de la interfaz por la que estás conectado sin un plan de reversión como netplan try. Otro descuido frecuente es olvidar la longitud del prefijo, por ejemplo indicar 10.0.5.20 sin /24, lo que puede producir una máscara de red inesperada. Recuerda también que nmcli con mod solo edita el perfil guardado; nada cambia en la red hasta que vuelves a levantar la conexión o la reaplicas.

Las preguntas del examen suelen preguntar qué cambio persiste o qué archivo controla un comportamiento. 'Sobrevive al reinicio' descarta ip; la respuesta es un perfil de nmcli, el YAML de netplan o los archivos de configuración de la distribución. 'Un nombre se resuelve distinto que en DNS' apunta a /etc/hosts y al orden de nsswitch.conf. 'Establecer el nombre de host de forma permanente' es hostnamectl set-hostname. 'Aplicar cambios de red de forma segura en remoto en Ubuntu' es netplan try. 'Mostrar la tabla de enrutamiento' es ip route, y 'qué servicio escucha en un puerto' es ss -tulpn.

Términos clave

iproute2 (ip)
El conjunto moderno para ver y cambiar interfaces, direcciones, rutas y vecinos; los cambios no son persistentes.
nmcli
Cliente de línea de comandos de NetworkManager que administra perfiles de conexión persistentes.
netplan
El sistema de configuración de red de Ubuntu basado en YAML que genera ajustes para systemd-networkd o NetworkManager.
hostnamectl
Herramienta de systemd que muestra y establece de forma permanente el nombre de host del sistema.
/etc/resolv.conf
Lista los servidores de nombres DNS y los dominios de búsqueda que usa el resolvedor del sistema.
nsswitch.conf
Define el orden de las fuentes de búsqueda (files, dns, sss, etc.) para hosts, usuarios, grupos y más.
Ejemplo real

Un servidor RHEL debe pasar a una dirección estática. Trabajando desde su consola, ejecutas nmcli con mod ens192 ipv4.method manual ipv4.addresses 10.0.5.20/24 ipv4.gateway 10.0.5.1 ipv4.dns 10.0.5.53 y luego nmcli con up ens192. ip a confirma la dirección, ip route muestra la ruta predeterminada y getent hosts intranet.example.com resuelve correctamente.

Consejo para el examen: Si una pregunta te pide qué cambio sobrevive a un reinicio, ip addr add es la respuesta equivocada; los cambios persistentes provienen de perfiles de conexión de nmcli, del YAML de netplan o de los archivos de configuración de la distribución.

Comprueba lo que sabes

Un nombre se resuelve a una IP inesperada aunque DNS es correcto. ¿Qué dos archivos debes revisar?

/etc/hosts, que puede contener una excepción, y /etc/nsswitch.conf, que controla si se consultan los archivos antes que DNS.

¿Por qué netplan try es más seguro que netplan apply en un servidor remoto?

netplan try revierte la configuración automáticamente si no confirmas dentro del tiempo límite, así que un error no puede dejarte sin acceso de forma permanente.

¿Qué comando establece de forma permanente el nombre de host app02?

hostnamectl set-hostname app02, que actualiza /etc/hostname y el nombre de host en ejecución.

¿Qué comando muestra la tabla de enrutamiento, incluida la puerta de enlace predeterminada?

ip route show (o ip r), que lista rutas como 'default via 10.0.5.1 dev ens192'.
