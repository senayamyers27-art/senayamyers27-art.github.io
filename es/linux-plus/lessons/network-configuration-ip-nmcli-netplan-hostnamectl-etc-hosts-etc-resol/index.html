CompTIA Linux+ XK0-006

Configuración de red: ip, nmcli, netplan, hostnamectl, /etc/hosts, /etc/resolv.conf, nsswitch.conf

Un servidor Linux solo es útil si puede comunicarse por la red, así que Linux+ espera que sepas ver y cambiar direcciones, rutas, nombres de host y resolución de nombres con las herramientas de las distribuciones actuales. La idea clave es que algunos comandos solo cambian el estado en ejecución, mientras que otros escriben configuración persistente.

El comando ip del paquete iproute2 reemplazó a herramientas más antiguas como ifconfig, route y arp. ip addr show (o ip a) lista interfaces y direcciones, ip link set eth0 up habilita una interfaz, ip addr add 192.168.10.5/24 dev eth0 agrega una dirección, ip route show muestra la tabla de enrutamiento, ip route add default via 192.168.10.1 establece una puerta de enlace predeterminada e ip neigh muestra la caché de vecinos ARP (Address Resolution Protocol). Los cambios hechos con ip surten efecto de inmediato, pero se pierden al reiniciar.

Para configuraciones persistentes, la mayoría de los sistemas de la familia RHEL y muchos de escritorio usan NetworkManager, controlado con nmcli. NetworkManager guarda perfiles de conexión, separados de los nombres de dispositivo. Comandos útiles: nmcli device status, nmcli connection show y un cambio a dirección estática como nmcli con mod eth0 ipv4.addresses 192.168.10.5/24 ipv4.gateway 192.168.10.1 ipv4.dns 192.168.10.53 ipv4.method manual, seguido de nmcli con up eth0 para aplicarlo. nmtui ofrece un menú de texto para las mismas tareas.

Ubuntu usa netplan: describes las interfaces en archivos YAML (YAML Ain't Markup Language) bajo /etc/netplan/, y netplan los traduce para un backend, ya sea systemd-networkd o NetworkManager. Después de editar, netplan try aplica el cambio y lo revierte automáticamente a menos que lo confirmes, lo que te protege de quedarte sin acceso a un servidor remoto; netplan apply lo aplica directamente. YAML es sensible a la sangría, así que una tabulación de más o una clave mal alineada es un error común.

hostnamectl muestra y establece el nombre de host, escribiendo /etc/hostname: hostnamectl set-hostname web01.example.com. /etc/hosts asocia nombres con direcciones IP localmente, lo que es útil para laboratorios pequeños o para anulaciones, por ejemplo 192.168.10.20 db01. /etc/resolv.conf lista los servidores DNS (Domain Name System) como líneas nameserver y una lista de dominios search. En muchos sistemas este archivo lo genera NetworkManager o systemd-resolved, así que edita el perfil de conexión en lugar del archivo, o tu cambio se sobrescribirá.

/etc/nsswitch.conf (Name Service Switch) decide el orden en que se consultan las fuentes. La línea hosts: files dns significa revisar primero /etc/hosts y luego DNS; una línea también puede incluir myhostname o resolve. El mismo archivo controla las búsquedas de usuarios (passwd:) y grupos, que es como se integran las cuentas de SSSD o LDAP. Si un nombre se resuelve de forma distinta a lo que esperas, revisa el orden de nsswitch y /etc/hosts antes de culpar al DNS. Herramientas como getent hosts nombre siguen nsswitch, mientras que dig consulta el DNS directamente.

Términos clave

iproute2 (ip)
El conjunto moderno para ver y cambiar interfaces, direcciones, rutas y vecinos; los cambios no son persistentes.
nmcli
Cliente de línea de comandos para NetworkManager que administra perfiles de conexión persistentes.
netplan
El sistema de configuración de red de Ubuntu basado en YAML que genera la configuración para systemd-networkd o NetworkManager.
/etc/resolv.conf
Lista los servidores DNS y los dominios de búsqueda que usa el resolvedor del sistema.
nsswitch.conf
Define el orden de las fuentes de búsqueda (files, dns, sss, etc.) para hosts, usuarios, grupos y más.
Ejemplo real

Un servidor RHEL debe pasar a una dirección estática. Trabajando desde su consola, ejecutas nmcli con mod ens192 ipv4.method manual ipv4.addresses 10.0.5.20/24 ipv4.gateway 10.0.5.1 ipv4.dns 10.0.5.53 y luego nmcli con up ens192. ip a confirma la dirección, ip route muestra la ruta predeterminada y getent hosts intranet.example.com se resuelve correctamente.

Consejo para el examen: Si una pregunta pide qué cambio sobrevive a un reinicio, ip addr add es la respuesta equivocada; los cambios persistentes vienen de los perfiles de conexión de nmcli, del YAML de netplan o de los archivos de configuración de la distribución.

Comprueba lo que sabes

Un nombre se resuelve a una IP inesperada aunque el DNS es correcto. ¿Qué dos archivos deberías revisar?

/etc/hosts, que puede contener una anulación, y /etc/nsswitch.conf, que controla si se consultan los archivos antes que el DNS.

¿Por qué netplan try es más seguro que netplan apply en un servidor remoto?

netplan try revierte la configuración automáticamente si no confirmas dentro del tiempo límite, así que un error no puede dejarte sin acceso de forma permanente.

¿Qué comando establece de forma permanente el nombre de host app02?

hostnamectl set-hostname app02.
