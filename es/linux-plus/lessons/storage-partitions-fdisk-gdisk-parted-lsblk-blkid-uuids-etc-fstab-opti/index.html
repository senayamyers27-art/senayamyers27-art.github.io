CompTIA Linux+ XK0-006

Almacenamiento: particiones (fdisk, gdisk, parted), lsblk, blkid, UUID, opciones de /etc/fstab (nofail, noexec)

Antes de que un disco pueda guardar archivos, normalmente se divide en particiones, cada una de las cuales recibe un sistema de archivos y un punto de montaje. Linux+ espera que sepas identificar discos, crear particiones con la herramienta adecuada para el tipo de tabla de particiones y montarlas de forma confiable en el arranque.

Hay dos formatos de tabla de particiones. MBR (Master Boot Record) es el formato heredado: admite hasta cuatro particiones primarias (o tres más una partición extendida que contiene particiones lógicas) y discos de hasta unos 2 TiB con los sectores comunes de 512 bytes. GPT (GUID Partition Table) es el formato moderno que se usa con UEFI: admite discos mucho más grandes, muchas particiones (128 por defecto) y guarda una copia de respaldo de la tabla al final del disco. fdisk es una herramienta interactiva que hoy maneja tanto MBR como GPT; gdisk es una herramienta centrada en GPT con una interfaz similar; parted maneja ambos y además se puede usar en scripts, como en parted /dev/sdb mklabel gpt y parted /dev/sdb mkpart primary ext4 1MiB 100%. Dentro de fdisk, n crea, p imprime, t cambia el tipo, d elimina y w escribe; nada cambia en el disco hasta que escribes. Después, partprobe le pide al kernel que vuelva a leer la tabla.

lsblk muestra los dispositivos de bloques como un árbol: discos, sus particiones, volúmenes LVM y arreglos RAID, con tamaño, tipo y punto de montaje. lsblk -f agrega el tipo de sistema de archivos, la etiqueta y el UUID. blkid imprime los atributos de cada dispositivo de bloques, especialmente su UUID (Universally Unique Identifier) y el TYPE del sistema de archivos. Los nombres de dispositivo como /dev/sdb1 pueden cambiar cuando se agregan discos o las controladoras cambian el orden, pero el UUID de un sistema de archivos sigue siendo el mismo, por eso debes montar por UUID (o LABEL) en lugar de por nombre de dispositivo.

/etc/fstab lista los sistemas de archivos que se montan en el arranque. Cada línea tiene seis campos: dispositivo (UUID=...), punto de montaje, tipo de sistema de archivos, opciones, indicador de dump (normalmente 0) y orden de paso de fsck (1 para la raíz, 2 para los demás, 0 para omitir). Por ejemplo: UUID=3f2a... /data xfs defaults,nofail 0 2.

Las opciones importan tanto para la confiabilidad como para la seguridad. defaults significa rw, suid, dev, exec, auto, nouser y async. nofail le dice al proceso de arranque que no falle si falta el dispositivo, lo que mantiene arrancando a un servidor cuando un disco externo o de red no está presente; sin ella, un dispositivo faltante puede enviar el sistema al modo de emergencia. noexec impide ejecutar binarios desde ese sistema de archivos, un paso común de endurecimiento para /tmp o directorios de carga. nosuid ignora los bits SUID/SGID, nodev ignora los archivos de dispositivo, ro monta en solo lectura y _netdev marca los sistemas de archivos de red para que esperen a la red.

Siempre prueba las ediciones de fstab antes de reiniciar: mount -a intenta montar todo lo listado y findmnt --verify revisa el archivo en busca de errores. En sistemas con systemd, ejecuta systemctl daemon-reload después de editar fstab para que se actualicen las unidades de montaje generadas.

Términos clave

GPT
GUID Partition Table: esquema de particionado moderno que admite discos muy grandes, muchas particiones y una tabla de respaldo.
MBR
Master Boot Record: esquema de particionado heredado limitado a cuatro particiones primarias y discos de aproximadamente 2 TiB.
UUID
Un identificador único guardado en un sistema de archivos, usado en /etc/fstab para que los montajes no dependan de los nombres de dispositivo.
nofail
Una opción de fstab que permite que el arranque continúe si el dispositivo no está presente.
noexec
Una opción de fstab que impide ejecutar binarios guardados en ese sistema de archivos.
Ejemplo real

Agregas un disco de 4 TB a un servidor para respaldos. Creas una etiqueta GPT y una partición con parted, la formateas con mkfs.xfs, obtienes su UUID con blkid y agregas UUID=... /backup xfs defaults,nofail,noexec 0 2 a /etc/fstab. Ejecutar mount -a lo monta sin errores, y nofail garantiza que, si alguna vez se retira el disco, el servidor siga arrancando.

Consejo para el examen: Si un escenario pregunta por qué un servidor se quedó en modo de emergencia después de que un disco se retiró o cambió de nombre, sospecha de una entrada de fstab por nombre de dispositivo sin nofail; la solución es usar UUID= y agregar nofail donde corresponda.

Comprueba lo que sabes

¿Qué esquema de particionado deberías usar para un disco de 6 TB, y por qué?

GPT, porque MBR no puede direccionar discos de más de unos 2 TiB con sectores de 512 bytes.

¿Qué controla el último campo de una línea de /etc/fstab?

El orden de paso de fsck en el arranque: 1 para el sistema de archivos raíz, 2 para los demás sistemas de archivos, 0 para omitir la verificación.

¿Cómo encuentras el UUID de /dev/sdc1?

Ejecuta blkid /dev/sdc1 o lsblk -f.
