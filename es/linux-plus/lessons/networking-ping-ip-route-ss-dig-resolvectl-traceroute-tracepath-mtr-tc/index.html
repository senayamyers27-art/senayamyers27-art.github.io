CompTIA Linux+ XK0-006

Redes: ping, ip route, ss, dig/resolvectl, traceroute/tracepath/mtr, tcpdump, nmap

La solución de problemas de red va más rápido cuando recorres las capas en orden: ¿la interfaz está activa con la dirección correcta?, ¿puedes llegar a la puerta de enlace?, ¿funciona el enrutamiento?, ¿funciona la resolución de nombres?, ¿el servicio realmente está escuchando y se le permite el paso? Cada herramienta de abajo responde una de esas preguntas.

Empieza localmente con ip a (dirección y estado del enlace) e ip route (tabla de enrutamiento). La línea que empieza con default via es la puerta de enlace predeterminada; sin ella, solo se puede llegar a las redes conectadas directamente. ip route get 8.8.8.8 muestra exactamente qué ruta e interfaz usaría un paquete hacia esa dirección. Luego ping prueba la alcanzabilidad con el eco de ICMP (Internet Control Message Protocol): ping -c 4 192.168.1.1 para la puerta de enlace, después una IP remota y después un nombre de host. Si una IP funciona pero un nombre falla, el problema es el DNS. Recuerda que muchos firewalls bloquean ICMP, así que un ping fallido no demuestra que un host esté caído.

La resolución de nombres se prueba con dig: dig example.com muestra la respuesta, el TTL y qué servidor respondió, dig @8.8.8.8 example.com consulta a un servidor específico, dig -x 203.0.113.10 realiza una búsqueda inversa, dig MX example.com pide los registros de correo y +short recorta la salida. nslookup y host son alternativas más sencillas. En sistemas que usan systemd-resolved, resolvectl status muestra los servidores DNS por interfaz y resolvectl query nombre resuelve a través del resolvedor del sistema, mientras que resolvectl flush-caches vacía su caché. getent hosts nombre sigue nsswitch.conf, así que incluye /etc/hosts.

Las herramientas de ruta muestran dónde se detienen los paquetes. traceroute host lista cada salto de router usando valores crecientes de TTL (time to live); traceroute -T -p 443 usa TCP para atravesar firewalls que bloquean los valores predeterminados. tracepath hace un trabajo similar sin privilegios de root e informa la MTU (maximum transmission unit) de la ruta. mtr host combina ping y traceroute en una vista que se actualiza continuamente con la pérdida y la latencia por salto, excelente para problemas intermitentes. Los asteriscos en un salto pueden significar simplemente que ese router no responde, así que fíjate dónde la pérdida continúa hasta el final.

ss muestra los sockets y reemplazó al antiguo netstat. ss -tulpn lista los puertos TCP y UDP en escucha con direcciones numéricas y el proceso propietario; ss -tan muestra todas las conexiones TCP con sus estados, como ESTABLISHED o TIME-WAIT. Un servicio que escucha en 127.0.0.1:8080 acepta solo conexiones locales, mientras que 0.0.0.0:8080 o *:8080 escucha en todas las interfaces, lo cual es una razón muy común por la que un servicio no es accesible desde otros hosts.

tcpdump captura paquetes para una inspección profunda: tcpdump -i eth0 -nn port 53 muestra el tráfico DNS sin resolver nombres, host 10.0.0.5 filtra por dirección y -w capture.pcap guarda en un archivo para analizarlo en Wireshark. Ver que las solicitudes salen pero no llegan respuestas, o ver reinicios TCP, separa rápidamente los problemas locales de los remotos. nmap escanea hosts para encontrar qué puertos están abiertos, cerrados o filtrados: nmap -p 22,80,443 server revisa puertos específicos y nmap -sV identifica las versiones de los servicios. Escanear desde otro host muestra lo que la red realmente deja pasar a través de los firewalls. Escanea solo sistemas que te pertenecen o que estás autorizado a probar, ya que el escaneo no autorizado puede violar políticas y leyes.

Términos clave

Default route (ruta predeterminada)
La entrada de la tabla de enrutamiento (default via ...) que se usa para los destinos que no coinciden con ninguna ruta más específica.
ss
Herramienta de estadísticas de sockets que lista puertos en escucha y conexiones; ss -tulpn es la forma común.
dig
Herramienta de consulta DNS que muestra los registros, los TTL y qué servidor respondió.
mtr
Combina traceroute y ping para mostrar de forma continua la pérdida y la latencia por salto.
tcpdump
Herramienta de captura de paquetes de línea de comandos que usa filtros como host, port y protocolo.
Ejemplo real

Los usuarios no pueden llegar a una nueva API en el puerto 8080. ping y dig funcionan, y nmap -p 8080 desde un cliente muestra el puerto cerrado. En el servidor, ss -tlpn muestra el proceso escuchando solo en 127.0.0.1:8080. Cambiar la dirección de escucha de la aplicación a 0.0.0.0 y agregar una regla de firewalld para 8080/tcp lo resuelve.

Consejo para el examen: Trabaja de abajo hacia arriba: enlace e IP, puerta de enlace, IP remota, nombre DNS y luego el puerto del servicio. Si las IP funcionan pero los nombres fallan, céntrate en el DNS y en nsswitch en lugar del enrutamiento.

Comprueba lo que sabes

ping 8.8.8.8 tiene éxito, pero ping example.com falla. ¿Dónde es probable que esté el problema?

En la resolución de nombres: la configuración del servidor DNS, /etc/resolv.conf, systemd-resolved o nsswitch.conf.

¿Qué comando lista los puertos TCP y UDP en escucha con los nombres de los procesos?

ss -tulpn.

¿Qué significa para los clientes remotos un servicio vinculado a 127.0.0.1?

Solo acepta conexiones desde el host local, así que los clientes remotos no pueden conectarse.
