CompTIA Linux+ XK0-006

SELinux: modos, contextos, restorecon, semanage, booleanos, ausearch; perfiles y modos de AppArmor

Los permisos estándar son DAC (discretionary access control, control de acceso discrecional): el propietario decide quién obtiene acceso. SELinux (Security-Enhanced Linux) y AppArmor agregan MAC (mandatory access control, control de acceso obligatorio): una política de todo el sistema limita lo que cada programa puede hacer sin importar la propiedad de los archivos, de modo que un servidor web comprometido no puede leer archivos fuera de lo que su política permite. Los sistemas de la familia RHEL usan SELinux; Ubuntu y Debian usan AppArmor, que SUSE también usó durante años, aunque las versiones más nuevas de SUSE usan SELinux de forma predeterminada.

SELinux tiene tres modos. Enforcing aplica la política y bloquea las violaciones. Permissive permite todo, pero registra lo que se habría denegado, lo cual es útil para diagnosticar problemas. Disabled desactiva SELinux por completo. getenforce muestra el modo, sestatus da el detalle y setenforce 0 o setenforce 1 cambian entre permissive y enforcing hasta el reinicio. La configuración persistente es SELINUX= en /etc/selinux/config. Pasar de disabled a habilitado de nuevo requiere volver a etiquetar todo el sistema de archivos, y deshabilitar SELinux para que un problema desaparezca es la respuesta equivocada, tanto en el examen como en la práctica.

Cada proceso y archivo tiene un contexto, con la forma user:role:type:level, por ejemplo system_u:object_r:httpd_sys_content_t:s0. En la política targeted predeterminada, lo que importa es el tipo: el proceso de Apache se ejecuta como httpd_t y puede leer archivos etiquetados como httpd_sys_content_t. Consulta los contextos con ls -Z para archivos y ps -eZ para procesos.

Las etiquetas son el problema más común. Un archivo creado en un directorio personal y luego movido con mv conserva su etiqueta anterior, así que al servidor web se le niega el acceso. restorecon -Rv /var/www/html restablece los archivos a las etiquetas predeterminadas definidas por la política. chcon -t type file cambia una etiqueta temporalmente, pero un reetiquetado o restorecon lo deshará. Para definir un nuevo valor predeterminado para una ruta personalizada, usa semanage fcontext -a -t httpd_sys_content_t '/srv/web(/.*)?' y luego ejecuta restorecon -Rv /srv/web. semanage port -a -t http_port_t -p tcp 8081 permite que un servicio use un puerto no estándar, y semanage port -l lista las etiquetas de puertos.

Los booleanos son interruptores de encendido/apagado para comportamientos opcionales de la política. getsebool -a los lista y setsebool -P httpd_can_network_connect on permite que Apache haga conexiones de red salientes; -P lo hace persistente.

Las denegaciones se registran como mensajes AVC (access vector cache) en /var/log/audit/audit.log. ausearch -m avc -ts recent encuentra las denegaciones recientes, sealert (de setroubleshoot) las explica en lenguaje sencillo y audit2why las interpreta. audit2allow puede generar un módulo de política personalizado, pero es preferible corregir primero las etiquetas, los puertos o los booleanos.

AppArmor, en cambio, confina los programas con perfiles basados en rutas guardados en /etc/apparmor.d/. Cada perfil se ejecuta en modo enforce (las violaciones se bloquean y se registran) o en modo complain (las violaciones solo se registran). aa-status lista los perfiles cargados y sus modos, aa-enforce y aa-complain cambian el modo de un perfil, aa-disable desactiva uno y apparmor_parser -r recarga un perfil después de editarlo. Las denegaciones aparecen en el log del kernel o en el log de auditoría con apparmor="DENIED".

Términos clave

MAC (control de acceso obligatorio)
Mandatory access control: una política aplicada por el sistema que restringe los programas sin importar la propiedad de los archivos.
SELinux context (contexto de SELinux)
La etiqueta user:role:type:level de archivos y procesos; el tipo determina la mayoría de las decisiones de la política targeted.
restorecon
Restablece las etiquetas SELinux de los archivos a los valores predeterminados definidos en la política.
SELinux boolean (booleano de SELinux)
Un interruptor de la política que se cambia con setsebool (-P para persistente) para permitir comportamientos opcionales.
AppArmor profile (perfil de AppArmor)
Una política basada en rutas para un programa, que se ejecuta en modo enforce o complain.
Ejemplo real

Después de mover un sitio nuevo a /var/www/html con mv, los visitantes reciben 403 Forbidden. ls -Z muestra los archivos etiquetados como user_home_t, y ausearch -m avc -ts recent muestra que a httpd_t se le negó el acceso de lectura. Ejecutar restorecon -Rv /var/www/html los reetiqueta como httpd_sys_content_t y el sitio carga, con SELinux todavía en modo enforcing.

Consejo para el examen: La respuesta de buenas prácticas casi nunca es 'deshabilitar SELinux'; busca en su lugar restorecon, semanage fcontext, semanage port o setsebool -P, y usa el modo permissive solo temporalmente para confirmar que SELinux es la causa.

Comprueba lo que sabes

¿Qué modo de SELinux registra las denegaciones sin bloquearlas?

Permissive.

Sirves contenido web desde /srv/web. ¿Cómo haces permanente su etiqueta correcta?

semanage fcontext -a -t httpd_sys_content_t '/srv/web(/.*)?' seguido de restorecon -Rv /srv/web.

¿Cuál es el equivalente en AppArmor del modo permissive de SELinux para un solo perfil?

El modo complain, que se establece con aa-complain.
