CompTIA Linux+ XK0-006

Puppet y otras herramientas basadas en agentes; plan y apply de OpenTofu/Terraform

La gestión de configuración y el aprovisionamiento de infraestructura son trabajos relacionados pero distintos. Las herramientas de gestión de configuración mantienen correctos el software y la configuración dentro de servidores existentes. Las herramientas de aprovisionamiento de infraestructura como código (IaC) crean los propios servidores, redes y recursos en la nube. Linux+ espera que conozcas ejemplos de cada una y cómo funcionan.

Puppet es una herramienta clásica de gestión de configuración basada en agentes. Un agente de Puppet se ejecuta en cada nodo administrado y periódicamente, cada 30 minutos de forma predeterminada, contacta a un servidor Puppet (históricamente llamado master). El agente envía datos (facts) sobre el nodo, recopilados por una herramienta llamada Facter, y recibe un catálogo compilado que describe su estado deseado. Luego aplica ese estado e informa el resultado. Este modelo pull significa que los nodos corrigen la desviación (drift) automáticamente en cada ejecución, aunque nadie lance una tarea. El código de Puppet se escribe en un DSL (lenguaje específico de dominio) declarativo, en manifiestos (archivos .pp) agrupados en módulos, con recursos como package, file, service y user. Los agentes y el servidor se autentican con certificados. puppet agent -t dispara una ejecución de inmediato y muestra lo que cambió.

Chef es otra herramienta basada en agentes, que usa recetas (recipes) y libros de cocina (cookbooks) basados en Ruby, y SaltStack (Salt) usa minions que se conectan a un master, aunque también puede funcionar sin agentes. En comparación con Ansible, las herramientas basadas en agentes necesitan software instalado y mantenido en cada nodo y un servidor central, pero escalan bien y aplican el estado de forma continua. Ansible no usa agentes y funciona por push: nada se ejecuta hasta que lanzas un playbook.

Terraform, de HashiCorp, y OpenTofu, un fork de código abierto mantenido bajo la Linux Foundation, son herramientas declarativas de aprovisionamiento IaC que comparten el mismo lenguaje y flujo de trabajo. Describes recursos como máquinas virtuales, redes, registros DNS y balanceadores de carga en archivos HCL (HashiCorp Configuration Language) que terminan en .tf. Los providers son complementos que se comunican con plataformas específicas, como un proveedor de nube o un hipervisor.

El flujo de trabajo usa unos pocos comandos (tofu para OpenTofu, terraform para Terraform). init descarga los providers y prepara el directorio de trabajo. fmt y validate ordenan y revisan el código. plan compara la configuración con el estado registrado y la infraestructura real, y muestra exactamente qué se creará (+), cambiará (~) o destruirá (-), sin cambiar nada. Revisa el plan con cuidado, especialmente cualquier destrucción. apply realiza los cambios, pidiendo confirmación salvo que se apruebe automáticamente, y destroy elimina todo lo que administra la configuración.

Ambas herramientas mantienen un archivo de estado (state file) que asocia la configuración con los ID reales de los recursos. El estado puede contener valores sensibles, así que los equipos lo guardan en un backend remoto seguro con bloqueo para evitar que dos personas apliquen cambios a la vez, en lugar de hacer commit de él en Git. Los cambios hechos fuera de la herramienta crean desviación (drift), que el siguiente plan revelará e intentará revertir.

En la práctica, las herramientas se combinan: OpenTofu o Terraform aprovisionan las VM y la red, y luego Ansible o Puppet configuran el sistema operativo y las aplicaciones dentro de ellas, todo guardado en Git y ejecutado mediante un pipeline.

Términos clave

Agent-based configuration management (gestión de configuración basada en agentes)
Herramientas como Puppet o Chef en las que un agente en cada nodo obtiene y aplica el estado deseado desde un servidor.
Puppet catalog (catálogo de Puppet)
La descripción compilada del estado deseado que un servidor Puppet envía a un agente, basada en manifiestos y en los facts del nodo.
Infrastructure as code (infraestructura como código)
Definir la infraestructura en archivos con control de versiones que las herramientas usan para crear y cambiar recursos.
plan
Comando de OpenTofu/Terraform que previsualiza los cambios necesarios para alcanzar la configuración declarada.
State file (archivo de estado)
El registro de OpenTofu/Terraform de los recursos administrados, guardado de forma segura, a menudo en un backend remoto con bloqueo.
Ejemplo real

Antes de un cambio en la configuración del balanceador de carga, un pipeline ejecuta tofu plan, que muestra un recurso a cambiar y, inesperadamente, uno a destruir. Un revisor detecta que un recurso renombrado eliminaría el registro DNS de la base de datos de producción, corrige el código para mover el recurso dentro del estado y solo entonces aprueba tofu apply.

Consejo para el examen: Distingue los modelos: Puppet está basado en agentes y funciona por pull; Ansible no usa agentes y funciona por push; OpenTofu/Terraform aprovisionan infraestructura, y plan previsualiza mientras que apply realiza los cambios.

Comprueba lo que sabes

¿Qué envía un agente de Puppet al servidor al inicio de una ejecución?

Los facts del nodo recopilados por Facter, que el servidor usa para compilar el catálogo del nodo.

¿Qué comando de OpenTofu/Terraform muestra los cambios propuestos sin realizarlos?

plan.

¿Por qué el archivo de estado no debería subirse a un repositorio Git público?

Puede contener datos sensibles como contraseñas o claves y necesita bloqueo para un uso seguro en equipo; su lugar es un backend remoto seguro.
