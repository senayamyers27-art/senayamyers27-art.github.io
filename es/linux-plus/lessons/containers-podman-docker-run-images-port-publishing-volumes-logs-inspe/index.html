CompTIA Linux+ XK0-006

Contenedores: podman/docker run, imágenes, publicación de puertos, volúmenes, logs, inspect

Un contenedor es un proceso, o un grupo de procesos, que se ejecuta aislado del resto del sistema mientras comparte el kernel del host. El aislamiento proviene de los namespaces del kernel (vistas separadas de procesos, red, montajes y nombres de host) y de los cgroups (control groups, que limitan CPU y memoria). Como no hay un sistema operativo invitado que arrancar, los contenedores inician en segundos y usan muchos menos recursos que las máquinas virtuales. Linux+ espera que sepas ejecutarlos y administrarlos con Docker o Podman.

Docker usa un demonio en segundo plano, dockerd, que ejecuta los contenedores por ti, y pertenecer al grupo docker equivale en la práctica a ser root. Podman, el predeterminado en sistemas de la familia RHEL, no usa demonio y puede ejecutar contenedores rootless (sin root) como un usuario común, lo que reduce el riesgo. Su sintaxis de línea de comandos es casi idéntica, así que podman run y docker run aceptan las mismas opciones comunes.

Una imagen es una plantilla de solo lectura construida en capas, identificada por un nombre y una etiqueta como registry.example.com/team/web:1.4; si no se da una etiqueta, se asume latest. podman pull nginx descarga una imagen de un registro, podman images lista las imágenes locales, podman rmi elimina una y podman build -t myapp:1.0 . construye una a partir de un Containerfile o Dockerfile. Un contenedor es una instancia en ejecución (o detenida) de una imagen con una delgada capa escribible encima; podman ps lista los contenedores en ejecución y podman ps -a incluye los detenidos.

podman run crea e inicia un contenedor. Opciones clave: -d lo ejecuta desacoplado en segundo plano, --name web le pone nombre, -it da una terminal interactiva, --rm lo elimina al salir y -e KEY=value establece variables de entorno. La publicación de puertos usa -p puertohost:puertocontenedor, así que -p 8080:80 hace que el puerto 80 del contenedor sea accesible en el puerto 8080 del host. Sin -p, los servicios dentro del contenedor no son accesibles desde fuera del host. Los contenedores rootless no pueden usar puertos del host menores a 1024 de forma predeterminada.

Todo lo que se escribe en la capa escribible de un contenedor desaparece cuando se elimina el contenedor. Para datos persistentes usa volúmenes: -v webdata:/usr/share/nginx/html usa un volumen con nombre administrado por el motor (podman volume ls), mientras que -v /srv/site:/usr/share/nginx/html:Z monta un directorio del host (bind mount). En sistemas con SELinux, el sufijo :Z o :z vuelve a etiquetar el directorio para que el contenedor pueda acceder a él; sin él obtienes errores de permiso denegado.

Para solucionar problemas, podman logs web muestra lo que el contenedor escribió en stdout y stderr (-f sigue la salida), podman exec -it web /bin/sh abre un shell dentro de un contenedor en ejecución, podman inspect web imprime JSON (JavaScript Object Notation) detallado sobre la configuración, los montajes, la red y el estado, y podman port web muestra los puertos publicados. podman stop, start, restart y rm administran el ciclo de vida, y podman stats muestra el uso de recursos en vivo.

podman run -d --name web -p 8080:80 -v webdata:/usr/share/nginx/html nginx:stable
podman logs -f web

Términos clave

Image (imagen)
Una plantilla de solo lectura y en capas (nombre:etiqueta) a partir de la cual se crean contenedores.
Container (contenedor)
Un proceso aislado que se ejecuta a partir de una imagen con su propia capa escribible, compartiendo el kernel del host.
Port publishing (publicación de puertos)
La opción -p host:contenedor que asocia un puerto del host con un puerto dentro del contenedor.
Volume (volumen)
Almacenamiento persistente administrado por el motor de contenedores o montado desde el host, que sobrevive a la eliminación del contenedor.
Rootless container (contenedor sin root)
Un contenedor ejecutado por un usuario sin privilegios, como lo permite Podman, que limita el impacto de un compromiso.
Ejemplo real

Un equipo necesita una wiki interna rápida. Ejecutas podman run -d --name wiki -p 8081:3000 -v wikidata:/data docker.io/<image>:<tag> como usuario normal. Los colegas acceden a ella en el puerto 8081; cuando se actualiza la imagen, eliminas el contenedor y lo recreas a partir de la nueva imagen, y las páginas sobreviven porque viven en el volumen wikidata.

Consejo para el examen: Lee los mapeos de -p como host:contenedor. Una pregunta que muestra -p 8443:443 significa que los clientes se conectan al host en el 8443 para llegar al 443 del contenedor.

Comprueba lo que sabes

¿Qué pasa con los datos escritos dentro de un contenedor sin volumen cuando se elimina el contenedor?

Se pierden, porque solo viven en la capa escribible del contenedor.

¿Qué comando muestra en detalle la dirección IP, los montajes y el entorno de un contenedor?

podman inspect <container> (o docker inspect).

Menciona una ventaja de seguridad que tiene Podman sobre una configuración predeterminada de Docker.

No usa demonio y puede ejecutar contenedores rootless como un usuario común, mientras que pertenecer al grupo docker en la práctica otorga root.
