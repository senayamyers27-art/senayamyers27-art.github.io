CompTIA Linux+ XK0-006

Virtualización: KVM/QEMU, libvirt y virsh, virt-install, imágenes qcow2 vs raw

La virtualización permite que un host físico ejecute varios sistemas operativos aislados, llamados invitados o VM (máquinas virtuales). En Linux, la pila estándar de código abierto es KVM, QEMU y libvirt. Linux+ espera que sepas qué hace cada capa, administres invitados desde la línea de comandos y elijas un formato de imagen de disco.

KVM (Kernel-based Virtual Machine) es un conjunto de módulos del kernel (kvm más kvm_intel o kvm_amd) que convierte a Linux en un hipervisor tipo 1 usando las extensiones de virtualización por hardware de la CPU, Intel VT-x o AMD-V. Puedes comprobar el soporte con grep -E 'vmx|svm' /proc/cpuinfo y confirmar los módulos con lsmod | grep kvm; si las extensiones están deshabilitadas en el firmware, KVM no puede funcionar. QEMU (Quick Emulator) proporciona el resto de la máquina virtual: dispositivos emulados o paravirtualizados como discos, tarjetas de red y gráficos. Con KVM por debajo, QEMU ejecuta el código del invitado directamente en la CPU a una velocidad casi nativa. Los controladores paravirtualizados virtio para disco y red dan el mejor rendimiento al invitado.

libvirt es una capa de administración con un demonio y una API que controla QEMU/KVM (y otros hipervisores) de forma consistente. Guarda la configuración de cada invitado como XML, administra redes virtuales como la red NAT (Network Address Translation) predeterminada virbr0 y administra pools de almacenamiento. Las herramientas que se apoyan en ella incluyen virsh (línea de comandos), virt-manager (gráfica) y virt-install (creación de invitados).

Comandos útiles de virsh: virsh list --all muestra los invitados en ejecución y detenidos, virsh start web01, virsh shutdown web01 (una solicitud de apagado ordenado por ACPI), virsh destroy web01 (un apagado inmediato que no borra nada, a pesar del nombre), virsh reboot, virsh autostart web01 para que arranque junto con el host, virsh dumpxml web01 para ver la configuración, virsh edit web01 para cambiarla de forma segura y virsh console web01 para una consola serie. virsh undefine elimina la definición del invitado. virsh snapshot-create-as crea instantáneas.

virt-install crea un invitado con un solo comando, por ejemplo: virt-install --name web01 --memory 2048 --vcpus 2 --disk size=20 --cdrom /isos/installer.iso --os-variant <variant> --network network=default. osinfo-query os lista los nombres de variante válidos.

Las imágenes de disco vienen en dos formatos principales. Raw es una imagen simple byte por byte: sencilla, rápida y portátil, pero sin funciones adicionales; puede asignarse completa o como archivo disperso (sparse). qcow2 (QEMU copy-on-write versión 2) usa aprovisionamiento delgado (thin provisioning), por lo que crece a medida que se escriben datos, y admite instantáneas internas, archivos de respaldo base (backing files, una capa delgada sobre una imagen base compartida) y compresión, con un pequeño costo de rendimiento. qemu-img create -f qcow2 disk.qcow2 20G crea una, qemu-img info muestra el formato y el tamaño real, y qemu-img convert -f raw -O qcow2 in.img out.qcow2 convierte entre formatos. Elige qcow2 por flexibilidad e instantáneas; elige raw cuando importen la máxima simplicidad o el rendimiento.

Términos clave

KVM
Kernel-based Virtual Machine: módulos del kernel que usan las extensiones de virtualización de la CPU para convertir a Linux en un hipervisor.
QEMU
El emulador que proporciona el hardware virtual y, junto con KVM, ejecuta invitados a una velocidad casi nativa.
libvirt / virsh
Una API y un demonio de administración para hipervisores, y su cliente de línea de comandos para controlar invitados.
qcow2
Un formato de disco de QEMU con aprovisionamiento delgado que admite instantáneas, archivos base y compresión.
virtio
Controladores de dispositivos paravirtualizados que dan a los invitados E/S rápida de disco y red.
Ejemplo real

Necesitas una VM de prueba desechable basada en una imagen maestra (golden image). qemu-img create -f qcow2 -b golden.qcow2 -F qcow2 test01.qcow2 crea una pequeña capa que solo guarda los cambios, virt-install --import la arranca, y cuando terminan las pruebas virsh destroy y virsh undefine la eliminan mientras la imagen maestra queda intacta.

Consejo para el examen: virsh destroy solo fuerza el apagado de un invitado, como desconectar el cable de corriente; no elimina la VM. Para eliminar la definición se usa virsh undefine.

Comprueba lo que sabes

¿Cómo puedes verificar que la CPU de un host admite virtualización por hardware?

Busca el indicador vmx (Intel) o svm (AMD) en /proc/cpuinfo, por ejemplo con grep -E 'vmx|svm' /proc/cpuinfo.

¿Qué formato de disco admite instantáneas y aprovisionamiento delgado: raw o qcow2?

qcow2.

¿Qué comando de virsh hace que un invitado arranque automáticamente cuando arranca el host?

virsh autostart <guest>.
