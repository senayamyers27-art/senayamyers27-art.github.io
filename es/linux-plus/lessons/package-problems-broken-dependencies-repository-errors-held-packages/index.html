Problemas de paquetes: dependencias rotas, errores de repositorio, paquetes retenidos

Los gestores de paquetes son confiables, pero las actualizaciones y las instalaciones todavía pueden fallar. Los problemas más comunes son las dependencias que no se pueden resolver, los errores de repositorio y los paquetes retenidos deliberadamente. Leer el error con atención normalmente te dice con cuál de estos estás lidiando.

Las dependencias rotas ocurren cuando un paquete necesita una versión de una biblioteca o de otro paquete que no está disponible o que entra en conflicto con algo instalado. Las causas incluyen mezclar repositorios de distintas versiones de la distribución, instalar paquetes individuales manualmente con rpm -i o dpkg -i, repositorios de terceros que reemplazan paquetes base e instalaciones interrumpidas. En sistemas de la familia Debian, apt --fix-broken install (o apt-get -f install) intenta completar o reparar una instalación a medias, y dpkg --configure -a termina de configurar los paquetes que una interrupción dejó sin configurar. apt-cache policy nombre muestra las versiones disponibles y de qué repositorio viene cada una. En sistemas RPM, dnf informa los conflictos con claridad; dnf check encuentra problemas de dependencias en el conjunto instalado, dnf repoquery --requires nombre o rpm -qR nombre muestran lo que necesita un paquete, y opciones como --allowerasing (que permite a dnf eliminar paquetes en conflicto) o --best cambian el comportamiento del resolvedor. Lee con cuidado antes de aceptar eliminaciones. Evita forzar instalaciones con rpm --nodeps o dpkg --force-depends, que dejan el sistema inconsistente.

Las operaciones de paquetes interrumpidas dejan bloqueos o dejan la base de datos a medio cambiar. apt informa 'Could not get lock /var/lib/dpkg/lock-frontend', lo que normalmente significa que otro proceso de apt, a menudo una actualización automática, todavía está en ejecución; espera a que termine o encuéntralo con ps, en lugar de borrar los archivos de bloqueo mientras se ejecuta. Si la base de datos de RPM está dañada, rpm --rebuilddb puede reconstruirla.

Los errores de repositorio aparecen como fallas al descargar metadatos o paquetes. Los mensajes típicos incluyen errores 404 (la URL del repositorio o el nombre de la versión son incorrectos, o la versión llegó al fin de su vida útil y se movió a un archivo histórico), 'Failed to download metadata for repo' o 'Temporary failure resolving' (problemas de DNS, proxy o red, incluida una configuración de proxy faltante), errores de GPG como 'NO_PUBKEY' o 'public key not installed' (la clave de firma del repositorio no se ha importado o se ha rotado) y errores de certificado TLS, que pueden deberse a un reloj del sistema incorrecto. Revisa los archivos de repositorio en /etc/yum.repos.d/ o /etc/apt/sources.list.d/, prueba la URL con curl -I, confirma la configuración de DNS y proxy, e importa la clave correcta mediante el método documentado por el proveedor, verificando su huella digital. Los metadatos obsoletos se pueden limpiar con dnf clean all y dnf makecache, o actualizar con apt update. Deshabilitar la verificación GPG para que un error desaparezca es un riesgo de seguridad y la solución equivocada.

Los paquetes retenidos (held) son los que se impide deliberadamente actualizar, a menudo para proteger una versión del kernel o de una aplicación de la que dependen otros. En sistemas de la familia Debian, apt-mark hold nombre retiene un paquete, apt-mark showhold lista las retenciones y apt-mark unhold nombre libera uno; apt informa 'The following packages have been kept back' tanto para las retenciones como para las actualizaciones que necesitarían dependencias nuevas, lo que apt full-upgrade o un apt install nombre explícito pueden resolver. En sistemas RPM, el complemento versionlock (dnf versionlock add nombre, dnf versionlock list, dnf versionlock delete nombre) hace lo mismo, y las líneas exclude= en /etc/dnf/dnf.conf o en un archivo .repo ocultan por completo los paquetes de las actualizaciones. Cuando un paquete misteriosamente no se actualiza, busca retenciones, versionlocks y exclusiones, y pregunta por qué se establecieron antes de quitarlas.

Términos clave

Dependency conflict (conflicto de dependencias)
Una situación en la que las versiones de paquetes requeridas no se pueden satisfacer junto con lo que está instalado.
apt --fix-broken install
Repara instalaciones incompletas o rotas instalando las dependencias faltantes.
NO_PUBKEY
Un error de apt que significa que la clave de firma del repositorio no es de confianza en el sistema.
apt-mark hold
Impide que un paquete de la familia Debian se actualice hasta que se libere.
dnf versionlock
Un complemento de dnf que fija paquetes a versiones específicas en sistemas basados en RPM.
Ejemplo real

La actualización nocturna de un servidor Ubuntu informa que varios paquetes se retuvieron (kept back). apt-mark showhold lista los paquetes del kernel, retenidos hace meses durante un problema con un controlador que ya se corrigió. Después de confirmarlo con el equipo, ejecutas apt-mark unhold sobre ellos, aplicas las actualizaciones y programas un reinicio con el nuevo kernel.

Consejo para el examen: Los errores GPG de repositorio se corrigen importando la clave correcta y verificada, no estableciendo gpgcheck=0 ni confiando en repositorios sin firmar.

Comprueba lo que sabes

Un corte de energía interrumpió una instalación en Ubuntu. ¿Qué dos comandos ayudan a reparar el estado de los paquetes?

dpkg --configure -a y apt --fix-broken install.

¿Cómo listas los paquetes retenidos en un sistema de la familia Debian?

apt-mark showhold.

dnf falla con 'Failed to download metadata for repo'. Menciona dos cosas que revisar.

Dos de estas: la baseurl o la URL del mirror en el archivo .repo, el DNS y el acceso a la red o al proxy, el reloj del sistema en caso de errores TLS, y si la versión se movió a un archivo histórico.
