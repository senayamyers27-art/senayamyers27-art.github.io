Seguridad del registro de contenedores: deshabilitar el usuario administrador, roles RBAC de pull/push, private endpoints, análisis de vulnerabilidades de imágenes

Azure Container Registry (ACR) almacena las imágenes de contenedor que ejecutan AKS, App Service, Container Apps y otros servicios. Si un atacante puede hacer push a tu registro, puede plantar una imagen maliciosa que tus clústeres desplegarán sin problema; si puede hacer pull, puede encontrar secretos o código propietario dentro de las imágenes. Por eso la seguridad del registro forma parte de la cadena de suministro de software.

Todo registro tiene un usuario administrador (admin user) opcional: un único nombre de usuario (el nombre del registro) con dos contraseñas que conceden derechos completos de push y pull. Es compartido, no está ligado a ninguna persona y no puede limitarse, así que los registros no pueden mostrar quién actuó. Está deshabilitado de forma predeterminada y debe seguir así; Azure Policy puede auditar o denegar los registros que lo tengan habilitado. Usa identidades de Entra en su lugar: las personas inician sesión con az acr login, y los servicios usan identidades administradas o service principals.

La autorización usa Azure RBAC. Los roles integrados clave son AcrPull (extraer imágenes), AcrPush (extraer y enviar) y AcrDelete (eliminar imágenes), además de AcrImageSigner en las configuraciones antiguas de content trust. Los registros pueden usar el modo de permisos más nuevo con ABAC, en el que roles como Container Registry Repository Reader, Writer y Contributor pueden limitarse a repositorios específicos con condiciones; de cualquier forma, el principio es el mismo. Por ejemplo, concede a la identidad administrada del kubelet de AKS solo AcrPull (az aks update --attach-acr lo hace), y da AcrPush a la identidad de la canalización de CI/CD. Existen tokens con ámbito de repositorio y scope maps para un acceso detallado sin Entra a repositorios específicos, como para dispositivos IoT.

Las restricciones de red vienen con la SKU Premium. Puedes crear private endpoints para que al registro se llegue mediante IP privadas en tus redes virtuales, con una zona DNS privada privatelink.azurecr.io, y luego deshabilitar el acceso de red público. Premium también admite reglas de firewall de IP y, cuando se necesita, la excepción de servicios de confianza para servicios como Microsoft Defender for Cloud y ACR Tasks. Ten en cuenta que los registros tienen un endpoint de inicio de sesión y endpoints de datos, y el private endpoint cubre ambos.

El análisis de vulnerabilidades de imágenes lo proporciona Microsoft Defender for Containers (y el plan Defender CSPM para la postura de contenedores sin agente). Las imágenes se analizan cuando se envían, cuando se han extraído recientemente y según un calendario, usando Microsoft Defender Vulnerability Management. Los hallazgos aparecen como recomendaciones, como 'Azure registry container images should have vulnerabilities resolved', con CVE y versiones corregidas, y pueden correlacionarse con los contenedores en ejecución para que priorices las imágenes que realmente están desplegadas.

Medidas adicionales para la cadena de suministro: firmar las imágenes (por ejemplo con Notation y claves en Key Vault) y verificar las firmas al desplegar, restringir AKS para que solo extraiga de registros aprobados con Azure Policy, usar ACR Tasks para reconstruir las imágenes cuando se aplican parches a las imágenes base, y habilitar soft delete o directivas de retención para administrar los manifiestos sin etiqueta.

Términos clave

Admin user (usuario administrador)
Una credencial compartida del registro con derechos completos de push y pull que debe permanecer deshabilitada.
AcrPull
Un rol de Azure que permite extraer imágenes de un registro.
AcrPush
Un rol de Azure que permite enviar y extraer imágenes.
Scope map and token (scope map y token)
Funciones del registro que conceden permisos específicos por repositorio a clientes que no usan Entra.
Ejemplo real

Una auditoría descubre que el clúster de AKS extrae imágenes usando la contraseña del usuario administrador del registro guardada en un secreto de Kubernetes. Asocias el registro al clúster para que la identidad del kubelet obtenga AcrPull, das AcrPush al service principal de la canalización, deshabilitas el usuario administrador, agregas un private endpoint con el acceso público deshabilitado en el registro Premium y habilitas el análisis de Defender for Containers.

Consejo para el examen: El acceso en tiempo de ejecución con mínimo privilegio es AcrPull; las canalizaciones necesitan AcrPush. Los private endpoints y las reglas de firewall requieren la SKU Premium. El análisis de CVE de imágenes viene de Defender for Containers, no de ACR por sí solo.

Comprueba lo que sabes

¿Por qué deshabilitar el usuario administrador de ACR?

Es una credencial compartida con derechos completos que no puede limitarse ni atribuirse a una persona.

¿Qué rol debe tener la identidad del kubelet de un clúster de AKS en el registro?

AcrPull.

¿Qué SKU de ACR admite private endpoints?

Premium.
