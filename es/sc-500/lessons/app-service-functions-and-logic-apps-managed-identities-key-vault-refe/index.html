Microsoft Certified: Cloud and AI Security Engineer Associate (replaces Azure Security Engineer Associate / AZ-500) SC-500

App Service, Functions y Logic Apps: identidades administradas, referencias de Key Vault, restricciones de acceso, solo HTTPS y TLS mínimo, autenticación (Easy Auth)

Azure App Service (aplicaciones web y API), Azure Functions y Logic Apps Standard son servicios de plataforma que comparten gran parte de la misma plataforma de hospedaje y configuración de seguridad. El examen espera que sepas reforzarlos en cinco áreas.

Las identidades administradas dan a la aplicación una identidad de Entra para llamar a Key Vault, Storage, SQL, Service Bus y otros servicios sin credenciales almacenadas. Habilita la identidad asignada por el sistema o por el usuario en la hoja Identity y luego concédele roles del plano de datos en los destinos. Los conectores de Logic Apps también pueden autenticarse con la identidad administrada de la logic app cuando el conector lo admite.

Las referencias de Key Vault (Key Vault references) permiten que la configuración de la aplicación obtenga secretos de Key Vault sin cambios en el código. En lugar del valor del secreto, el app setting contiene una referencia como @Microsoft.KeyVault(VaultName=myvault;SecretName=DbPassword), o una forma equivalente usando el SecretUri del secreto. La plataforma usa la identidad administrada de la aplicación para obtener el valor, así que la identidad necesita Key Vault Secrets User (RBAC) o una directiva de acceso Get para secretos. Si la referencia omite la versión, la aplicación toma las versiones nuevas en aproximadamente un día, o al reiniciarse. Si el vault tiene restricciones de red, la aplicación necesita VNet integration y enrutar a través de la red virtual. Esta es la respuesta estándar para 'mantener la cadena de conexión fuera de la configuración'.

Las restricciones de acceso (access restrictions) filtran el tráfico de entrada a la aplicación mediante reglas de permitir y denegar ordenadas por prioridad sobre intervalos de IP, service tags (por ejemplo, permitir solo AzureFrontDoor.Backend más una comprobación del encabezado con el ID de Front Door) o subredes de redes virtuales mediante service endpoints. El sitio de herramientas avanzadas (SCM o Kudu, usado para el despliegue) tiene su propio conjunto de reglas, que puede heredar las reglas del sitio principal. Para aplicaciones totalmente privadas, usa un private endpoint para el tráfico de entrada y establece el acceso de red público en deshabilitado; usa VNet integration para el tráfico de salida hacia recursos privados.

La configuración de seguridad del transporte incluye HTTPS Only, que redirige todas las solicitudes HTTP a HTTPS; la versión mínima de TLS de entrada, que debe ser 1.2 o superior; y la configuración de FTPS, donde la mejor opción es deshabilitar por completo FTP y FTPS, junto con la autenticación básica para la publicación, y desplegar mediante canalizaciones autenticadas con Entra. Puedes vincular dominios personalizados con certificados administrados o de Key Vault.

La autenticación y autorización integradas, conocidas como Easy Auth, permiten que la plataforma gestione el inicio de sesión antes de que las solicitudes lleguen a tu código. Agregas un proveedor de identidad, normalmente Microsoft Entra ID (otros incluyen cuentas Microsoft, Google, Facebook, X, Apple y cualquier proveedor OpenID Connect), y eliges qué ocurre con las solicitudes no autenticadas: redirigir al inicio de sesión, o devolver 401 o 403 en el caso de las API. La plataforma valida los tokens, administra las sesiones y pasa las notificaciones (claims) del usuario a la aplicación en encabezados. Es ideal cuando necesitas proteger una aplicación rápidamente sin escribir código de autenticación, y puede combinarse con Conditional Access mediante Entra.

Defender for App Service, habilitado en Defender for Cloud, agrega detección de amenazas para estas aplicaciones, como la detección de DNS colgantes (dangling DNS) y alertas sobre solicitudes sospechosas y web shells.

Términos clave

Key Vault reference (referencia de Key Vault)
Un valor de app setting con la forma @Microsoft.KeyVault(...) que la plataforma resuelve usando la identidad administrada de la aplicación.
Access restrictions (restricciones de acceso)
Reglas de permitir y denegar ordenadas por prioridad que filtran el tráfico de entrada a una aplicación de App Service o Function.
HTTPS Only
Una configuración que redirige todas las solicitudes HTTP a HTTPS.
Easy Auth
La autenticación integrada de App Service que inicia la sesión de los usuarios mediante proveedores de identidad antes de que las solicitudes lleguen al código.
VNet integration (integración con VNet)
Una función que permite que una aplicación haga llamadas de salida hacia una red virtual para llegar a recursos privados.
Ejemplo real

Una aplicación web guarda su cadena de conexión SQL en app settings sin protección, permite TLS 1.0 y está abierta a internet. Habilitas su identidad asignada por el sistema, mueves el secreto a Key Vault y reemplazas el ajuste por una referencia de Key Vault, estableces HTTPS Only y TLS mínimo 1.2, deshabilitas FTP y las credenciales de publicación básicas, agregas restricciones de acceso que permiten solo la service tag de Front Door y activas la autenticación con Entra ID mediante Easy Auth.

Consejo para el examen: Las referencias de Key Vault necesitan una identidad administrada con acceso de lectura a los secretos, y los vaults con restricciones de red necesitan VNet integration. El filtrado de entrada se hace con restricciones de acceso o private endpoints; el alcance de salida hacia una VNet es VNet integration. Proteger una aplicación sin cambios en el código apunta a Easy Auth.

Comprueba lo que sabes

Una referencia de Key Vault muestra un estado de error. ¿Qué dos cosas debes revisar primero?

Que la identidad administrada de la aplicación tenga permiso para leer el secreto, y que la aplicación pueda llegar al vault si la red del vault está restringida.

¿Cómo te aseguras de que solo el tráfico de tu Azure Front Door llegue a una aplicación web?

Agregando una restricción de acceso que permita la service tag AzureFrontDoor.Backend con una comprobación del encabezado X-Azure-FDID para el ID de tu Front Door, o usando un private endpoint con Front Door Premium.

¿Qué configuración obliga a los navegadores que usan HTTP a pasar a HTTPS?

HTTPS Only.
