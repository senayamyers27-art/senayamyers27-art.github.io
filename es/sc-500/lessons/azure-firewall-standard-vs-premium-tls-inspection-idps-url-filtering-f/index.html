Azure Firewall (Standard vs Premium: inspección TLS, IDPS, filtrado de URL), Firewall Manager y directiva de firewall, tunelización forzada con rutas definidas por el usuario

Azure Firewall es un firewall de red administrado, con estado y de alta disponibilidad que despliegas en una subred dedicada llamada AzureFirewallSubnet, normalmente en una red virtual hub. Las redes spoke envían su tráfico a través de él para que puedas permitir, denegar y registrar de forma central los flujos este-oeste y norte-sur. Viene en las SKU Basic, Standard y Premium; este examen se centra en Standard frente a Premium.

Azure Firewall procesa las reglas en colecciones de tres tipos. Las reglas DNAT traducen el tráfico de entrada que llega a la IP pública del firewall a una dirección privada, por ejemplo para publicar un servidor. Las reglas de red (network rules) filtran por origen, IP de destino, puerto y protocolo (capas 3 y 4), y pueden usar service tags y grupos de IP. Las reglas de aplicación (application rules) filtran el tráfico saliente HTTP, HTTPS y SQL por nombre de dominio completo (FQDN) y por etiquetas FQDN como WindowsUpdate. El procesamiento va primero por DNAT, luego red y luego aplicación, y dentro de cada tipo por la prioridad de la colección. Standard también incluye filtrado basado en inteligencia de amenazas, que alerta sobre el tráfico hacia y desde direcciones IP y dominios maliciosos conocidos o lo deniega, y puede actuar como proxy DNS para que el filtrado por FQDN en las reglas de red funcione de forma fiable.

Premium agrega funciones para entornos muy sensibles. La inspección TLS (TLS inspection) descifra el tráfico HTTPS saliente y este-oeste usando un certificado de CA intermedia que guardas en Key Vault, lo inspecciona y lo vuelve a cifrar; los clientes deben confiar en esa CA. IDPS (sistema de detección y prevención de intrusiones) usa firmas para detectar y, opcionalmente, bloquear intentos de explotación, comunicaciones de malware y otros ataques, en modo Alert o Alert and deny; inspecciona el tráfico cifrado solo cuando la inspección TLS está activada. El filtrado de URL (URL filtering) extiende el filtrado por FQDN a la ruta completa de la URL, como permitir www.contoso.com/docs pero no otras rutas, lo cual requiere inspección TLS para HTTPS. Las categorías web permiten admitir o denegar clases de sitios (apuestas, redes sociales); Standard puede usar categorías basadas en FQDN, mientras que Premium puede coincidir con URL completas.

Lo mejor es guardar las reglas en una directiva de firewall (firewall policy), un recurso de Azure independiente que puede asociarse a uno o varios firewalls. Las directivas admiten herencia: una directiva primaria (base) administrada por el equipo central de seguridad puede contener las reglas de toda la organización, y las directivas secundarias de cada región o equipo las heredan y agregan las suyas. Las funciones Premium requieren una directiva Premium. Azure Firewall Manager es la herramienta de administración central que te permite aplicar directivas a muchos firewalls en VNets hub y en secured hubs de Virtual WAN, e integrar proveedores de seguridad como servicio de terceros.

Para que el tráfico pase realmente por el firewall usas rutas definidas por el usuario (user-defined routes, UDR) en tablas de rutas asociadas a las subredes spoke: una ruta para 0.0.0.0/0 con tipo de próximo salto Virtual appliance y la IP privada del firewall. La tunelización forzada (forced tunneling) es una idea relacionada pero distinta: enviar el propio tráfico del firewall con destino a internet a un dispositivo local u otro appliance en lugar de salir directamente. Requiere una subred aparte, AzureFirewallManagementSubnet, para que el tráfico de administración del firewall siga llegando a Azure, y es mejor configurarla al momento del despliegue.

Términos clave

Application rule (regla de aplicación)
Una regla de Azure Firewall que permite o deniega el tráfico saliente por FQDN o etiqueta FQDN.
TLS inspection (inspección TLS)
Una función Premium que descifra y vuelve a cifrar el tráfico HTTPS usando un certificado de CA intermedia desde Key Vault.
IDPS
Detección y prevención de intrusiones basada en firmas en Azure Firewall Premium.
Firewall policy (directiva de firewall)
Un recurso que contiene las reglas y la configuración del firewall, reutilizable entre firewalls y con herencia primaria-secundaria.
User-defined route (ruta definida por el usuario)
Una ruta personalizada, como 0.0.0.0/0 hacia la IP privada del firewall, que invalida las rutas del sistema de Azure.
Ejemplo real

Un banco exige que el HTTPS saliente de las cargas de trabajo se inspeccione en busca de malware y se restrinja a rutas de URL específicas. Despliegas Azure Firewall Premium en el hub, creas una directiva de firewall Premium con inspección TLS usando un certificado de CA en Key Vault, habilitas IDPS en modo Alert and deny, agregas reglas de aplicación basadas en URL y asocias a las subredes spoke una tabla de rutas que envía 0.0.0.0/0 al firewall.

Consejo para el examen: Inspección TLS, IDPS y filtrado de URL completas significan Premium. Un firewall sin una UDR 0.0.0.0/0 en las subredes spoke no inspecciona nada. La tunelización forzada requiere la AzureFirewallManagementSubnet.

Comprueba lo que sabes

¿Qué SKU se necesita para bloquear solicitudes a una ruta de URL específica de un sitio HTTPS?

Premium, porque el filtrado de URL en HTTPS requiere inspección TLS.

¿Cómo te aseguras de que las VMs de un spoke envíen el tráfico de internet a través del firewall del hub?

Asociando a las subredes spoke una tabla de rutas con una ruta 0.0.0.0/0 con próximo salto Virtual appliance hacia la IP privada del firewall.

¿Cómo puede un equipo central aplicar reglas base mientras los equipos regionales agregan las suyas?

Usando una directiva de firewall primaria con las reglas base y directivas secundarias que la heredan, administradas mediante Firewall Manager.
