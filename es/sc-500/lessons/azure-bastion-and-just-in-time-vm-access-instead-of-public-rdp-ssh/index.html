Azure Bastion y acceso just-in-time a VMs en lugar de RDP/SSH públicos

Exponer RDP (TCP 3389) o SSH (TCP 22) a internet es una de las causas más comunes del compromiso de VMs. Los escáneres automatizados encuentran los puertos de administración abiertos en minutos y empiezan intentos de fuerza bruta y password spray, y las vulnerabilidades de los servicios de acceso remoto se explotan con regularidad. Dos funciones de Azure eliminan la necesidad de puertos de administración públicos: Azure Bastion y el acceso just-in-time (JIT) a VMs.

Azure Bastion es un servicio PaaS totalmente administrado que despliegas en una red virtual, en una subred dedicada llamada AzureBastionSubnet. Los administradores se conectan al portal de Azure por HTTPS (TCP 443), seleccionan una VM y abren una sesión RDP o SSH en el navegador; luego Bastion se conecta a la dirección IP privada de la VM. Las VMs no necesitan dirección IP pública ni agente. Microsoft se encarga de reforzar y aplicar parches a Bastion. Las SKU se diferencian en funciones: Developer (gratuita, limitada, infraestructura compartida), Basic, Standard (agrega compatibilidad con cliente nativo mediante la CLI de Azure, conexión basada en IP, vínculos compartibles, transferencia de archivos y escalado de hosts) y Premium (agrega grabación de sesiones y despliegue solo privado). Bastion puede llegar a VMs en redes virtuales emparejadas. El acceso requiere roles Reader en la VM, en su NIC y en el recurso de Bastion, así que Azure RBAC controla quién puede usarlo, y Conditional Access protege el inicio de sesión en el portal.

El acceso just-in-time a VMs es una función de Microsoft Defender for Servers Plan 2 en Defender for Cloud. Bloquea los puertos de administración agregando reglas de denegación en los NSG (y reglas de Azure Firewall cuando corresponde) para los puertos elegidos. Cuando un administrador necesita acceso, lo solicita en el portal, mediante PowerShell o la API, indicando el puerto, la IP de origen y la duración dentro de un máximo configurado. Si el solicitante tiene los permisos de RBAC adecuados (como Microsoft.Security/locations/jitNetworkAccessPolicies/initiate/action), Defender for Cloud agrega temporalmente una regla de permiso de mayor prioridad para su IP de origen y la quita cuando vence el tiempo. Cada solicitud queda registrada en el registro de actividad de Azure.

Las dos funciones resuelven problemas ligeramente distintos y pueden combinarse. Bastion elimina por completo las IP públicas y la exposición a internet; el acceso se hace mediante el portal o el cliente nativo sobre TLS. JIT mantiene los puertos cerrados de forma predeterminada y los abre solo brevemente para un origen específico, lo que es útil cuando una VM debe conservar una IP pública o cuando los administradores usan otras rutas, como una VPN. JIT también puede aplicarse a la ruta de Bastion en diseños reforzados.

Otros pasos de refuerzo: exigir el inicio de sesión con Entra ID en las VMs (las extensiones AADLoginForWindows o AADSSHLoginForLinux con los roles Virtual Machine Administrator Login o User Login) para que RDP y SSH usen credenciales de Entra y Conditional Access, deshabilitar la autenticación con contraseña para SSH en Linux y usar la recomendación de Defender for Cloud 'Management ports should be closed on your virtual machines' para encontrar las VMs expuestas.

Términos clave

Azure Bastion
Un servicio administrado que proporciona RDP y SSH a las VMs desde el navegador o un cliente nativo sobre TLS, sin IP públicas en las VMs.
AzureBastionSubnet
El nombre de subred dedicada que se requiere para desplegar Azure Bastion.
Just-in-time VM access (acceso just-in-time a VMs)
Una función de Defender for Servers Plan 2 que mantiene cerrados los puertos de administración y los abre temporalmente para solicitudes aprobadas.
Management port (puerto de administración)
Un puerto para la administración remota, como 3389 (RDP) o 22 (SSH).
Ejemplo real

Defender for Cloud informa que 40 VMs tienen RDP abierto a internet. Despliegas Azure Bastion Standard en la VNet del hub, quitas las IP públicas de las VMs, eliminas las reglas de NSG que permiten 3389 desde Any y das a los administradores Reader en las VMs y en Bastion. Para tres appliances que deben conservar IP públicas, habilitas JIT con un máximo de tres horas.

Consejo para el examen: Sin IP públicas en las VMs y RDP/SSH desde el navegador por 443: Azure Bastion en AzureBastionSubnet. Puertos cerrados hasta una solicitud aprobada y con límite de tiempo: JIT, que necesita Defender for Servers Plan 2.

Comprueba lo que sabes

¿A qué puerto deben llegar los clientes para las conexiones de Azure Bastion a través del portal?

TCP 443 (HTTPS) hacia Bastion; a los puertos RDP y SSH de las VMs se llega de forma privada desde Bastion.

¿Qué plan de Defender incluye el acceso just-in-time a VMs?

Defender for Servers Plan 2.

¿Qué cambia JIT cuando se aprueba una solicitud?

Agrega al NSG (o al firewall) una regla de permiso temporal de mayor prioridad para el puerto y la IP de origen solicitados, y la quita después de la duración.
