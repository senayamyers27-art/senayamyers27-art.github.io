VPN de sitio a sitio y de punto a sitio, secured hubs de Virtual WAN, Microsoft Entra Private Access (ZTNA)

Las redes híbridas necesitan formas seguras de conectar sitios locales y usuarios remotos con Azure. Azure VPN Gateway proporciona túneles cifrados a través de internet usando IPsec e IKE. Se despliega en una subred que debe llamarse GatewaySubnet.

Una VPN de sitio a sitio (site-to-site, S2S) conecta toda una red local con una red virtual de Azure mediante un túnel IPsec/IKE entre la puerta de enlace VPN de Azure y un dispositivo VPN local con dirección IP pública. Defines una puerta de enlace de red local (local network gateway: la IP del dispositivo local y los prefijos de direcciones) y una conexión con una clave precompartida o, donde se admita, autenticación con certificados. Las puertas de enlace basadas en rutas admiten BGP y varios túneles; las puertas de enlace activo-activo mejoran la disponibilidad. Puedes aplicar directivas IPsec/IKE personalizadas para exigir algoritmos más fuertes. ExpressRoute es la alternativa privada que no pasa por internet, y puedes agregar IPsec sobre ExpressRoute cuando se requiere cifrado en esa ruta.

Una VPN de punto a sitio (point-to-site, P2S) conecta dispositivos cliente individuales, como una laptop en casa, con la red virtual. Los protocolos incluyen OpenVPN, IKEv2 y SSTP. La autenticación puede usar certificados, RADIUS (que puede integrarse con directorios existentes y MFA) o Microsoft Entra ID con el Azure VPN Client, que solo funciona con OpenVPN y permite que Conditional Access y MFA protejan el inicio de sesión en la VPN. La autenticación con Entra es la opción moderna y centrada en la identidad.

Azure Virtual WAN es un servicio de redes administrado por Microsoft que combina la conectividad de sucursales (S2S), usuarios (P2S), ExpressRoute y VNet a VNet mediante hubs regionales con enrutamiento de tránsito automático. Cuando despliegas Azure Firewall en un hub de Virtual WAN y lo administras con Firewall Manager, se convierte en un secured virtual hub (hub virtual protegido). Luego, routing intent y las directivas de enrutamiento te permiten enviar el tráfico de internet, el tráfico privado (entre VNets y sucursales) o ambos a través del firewall del hub, sin mantener UDR en cada spoke. También pueden integrarse socios de seguridad de terceros para el tráfico de internet.

Las VPN tradicionales dan al usuario conectado un acceso amplio a la red, lo que permite a un atacante que compromete una laptop moverse lateralmente. El acceso a la red de Zero Trust (Zero Trust network access, ZTNA), en cambio, concede acceso por aplicación después de verificar la identidad y el dispositivo, y nunca coloca al usuario 'en la red'. Microsoft Entra Private Access, parte de la oferta Global Secure Access (Security Service Edge) de Microsoft, proporciona ZTNA a aplicaciones privadas locales o en cualquier nube. Un cliente de Global Secure Access en el dispositivo envía el tráfico de los segmentos de aplicaciones privadas definidos (por FQDN o IP y puerto) al perímetro de Microsoft, que lo reenvía mediante conectores ligeros instalados cerca de las aplicaciones. Como cada aplicación es una aplicación empresarial en Entra, puedes aplicar directivas de Conditional Access por aplicación, incluidos los requisitos de MFA y de dispositivo conforme, y usar Quick Access para reemplazar ampliamente una VPN heredada antes de segmentar más.

El servicio hermano, Microsoft Entra Internet Access, es una puerta de enlace web segura para el tráfico de internet y de Microsoft 365; juntos forman la solución SSE de Microsoft.

Términos clave

Site-to-site VPN (VPN de sitio a sitio)
Un túnel IPsec/IKE que conecta el dispositivo VPN de una red local con una puerta de enlace VPN de Azure.
Point-to-site VPN (VPN de punto a sitio)
Una VPN desde dispositivos cliente individuales hacia una red virtual de Azure usando OpenVPN, IKEv2 o SSTP.
Secured virtual hub (hub virtual protegido)
Un hub de Virtual WAN con Azure Firewall administrado por Firewall Manager, con routing intent para inspeccionar el tráfico.
ZTNA
Zero Trust network access (acceso a la red de Zero Trust), que concede acceso por aplicación después de verificar la identidad y el dispositivo en lugar de acceso a toda la red.
Microsoft Entra Private Access
El servicio ZTNA de Microsoft que publica aplicaciones privadas mediante Global Secure Access con Conditional Access por aplicación.
Ejemplo real

Los trabajadores remotos de una empresa usan una VPN heredada que da acceso completo a la red. La empresa despliega conectores de Microsoft Entra Private Access en el centro de datos, define el FQDN y el puerto de la aplicación de finanzas como una aplicación privada y crea una directiva de Conditional Access que exige MFA resistente al phishing y un dispositivo conforme para esa aplicación. Los usuarios llegan solo a la aplicación de finanzas, no a toda la red.

Consejo para el examen: Todo un sitio hacia Azure: sitio a sitio. Laptops individuales: punto a sitio (con autenticación de Entra para MFA y Conditional Access). Inspección central del tráfico de Virtual WAN: secured hub con routing intent. Acceso por aplicación sin VPN a nivel de red: Entra Private Access.

Comprueba lo que sabes

¿Qué método de autenticación P2S te permite aplicar Conditional Access al inicio de sesión en la VPN?

La autenticación con Microsoft Entra ID con el Azure VPN Client sobre OpenVPN.

¿Qué convierte un hub de Virtual WAN en un secured hub?

Desplegar en él Azure Firewall (o un proveedor de seguridad compatible) y administrarlo con Firewall Manager.

¿Cómo reduce ZTNA el movimiento lateral en comparación con una VPN tradicional?

Los usuarios obtienen acceso solo a aplicaciones específicas después de la verificación, no una ruta hacia toda la red.
