Microsoft Certified: Cloud and AI Security Engineer Associate (replaces Azure Security Engineer Associate / AZ-500) SC-500

MFA y directiva de métodos de autenticación, métodos resistentes al phishing (FIDO2, passkeys, Windows Hello), fuerzas de autenticación

La autenticación multifactor (MFA) exige dos o más de: algo que sabes (contraseña o PIN), algo que tienes (teléfono, llave de seguridad) y algo que eres (huella digital, rostro). Así, una contraseña robada por sí sola no basta. En Microsoft Entra ID puedes exigir MFA mediante los valores predeterminados de seguridad (security defaults, una línea base gratuita de todo o nada) o, para un control más fino, mediante directivas de Conditional Access. La antigua configuración de MFA por usuario es heredada y debe evitarse en favor de Conditional Access.

La directiva de métodos de autenticación, en Entra ID > Protection > Authentication methods, es donde decides qué métodos están permitidos y para quién. Los métodos incluyen Microsoft Authenticator (notificaciones push con coincidencia de números e inicio de sesión sin contraseña desde el teléfono), passkeys (FIDO2), Windows Hello for Business, autenticación basada en certificados, Temporary Access Pass, tokens OATH de software y hardware, SMS y llamada de voz, y códigos de un solo uso por correo electrónico para invitados. Cada método se puede habilitar para todos los usuarios o para grupos específicos, con opciones propias de cada método. Microsoft ha ido migrando los tenants de la antigua configuración de métodos de MFA heredada y de restablecimiento de contraseña de autoservicio a esta única directiva unificada.

No toda la MFA es igual. Los códigos SMS, las llamadas de voz y las aprobaciones push simples pueden interceptarse, sufrir SIM swapping o ser aprobadas por un usuario cansado durante un ataque de fatiga de MFA (MFA fatigue). Los kits de phishing de adversario en el medio (adversary-in-the-middle) también pueden retransmitir códigos de un solo uso en tiempo real. Los métodos resistentes al phishing lo impiden usando criptografía de clave pública vinculada al origen del sitio real, de modo que un dominio parecido no puede obtener una credencial utilizable. Los métodos resistentes al phishing en Entra son las llaves de seguridad FIDO2 y las passkeys (incluidas las passkeys en Microsoft Authenticator), Windows Hello for Business y la autenticación basada en certificados (tarjetas inteligentes). Temporary Access Pass es un código de tiempo limitado que se usa para incorporar o recuperar estos métodos sin contraseña.

Las fuerzas de autenticación (authentication strengths) permiten que Conditional Access exija un conjunto específico de métodos en lugar de solo 'MFA'. Hay tres fuerzas integradas: Multifactor authentication strength (cualquier combinación de MFA), Passwordless MFA strength (métodos sin contraseña como el inicio de sesión desde el teléfono con Authenticator, Windows Hello y FIDO2) y Phishing-resistant MFA strength (FIDO2/passkeys, Windows Hello for Business y MFA basada en certificados). También puedes crear fuerzas personalizadas, por ejemplo permitiendo solo llaves FIDO2 con AAGUID específicos (identificadores del modelo de autenticador). En una directiva de Conditional Access eliges Grant > Require authentication strength en lugar de Require multifactor authentication.

Un diseño sensato es: exigir la fuerza resistente al phishing para los administradores y para el acceso al portal de Azure y a las API de administración, exigir al menos MFA para todos, deshabilitar SMS y voz cuando sea posible, activar la coincidencia de números y el contexto adicional en Authenticator, y usar un Temporary Access Pass para iniciar a los usuarios nuevos en passkeys.

Términos clave

Authentication methods policy (directiva de métodos de autenticación)
La directiva de Entra ID que habilita o deshabilita cada método de inicio de sesión para todos los usuarios o para grupos seleccionados.
Phishing-resistant MFA (MFA resistente al phishing)
Métodos vinculados criptográficamente al sitio legítimo, como llaves FIDO2, passkeys, Windows Hello for Business y autenticación basada en certificados.
Passkey (llave de acceso)
Una credencial FIDO2 almacenada en una llave de seguridad o en un dispositivo que inicia sesión con una clave privada desbloqueada con PIN o biometría.
Authentication strength (fuerza de autenticación)
Un control de concesión de Conditional Access que exige combinaciones específicas de métodos, como la fuerza integrada de MFA resistente al phishing.
Temporary Access Pass (pase de acceso temporal)
Un código de acceso de tiempo limitado que se usa para registrar o recuperar métodos seguros sin contraseña.
Ejemplo real

Después de que un atacante usó una página de adversario en el medio para robar tokens de sesión de un administrador que aprobó un push de Authenticator, el equipo de seguridad crea una directiva de Conditional Access para todos los roles de administrador que exige la fuerza de autenticación Phishing-resistant MFA, y entrega llaves FIDO2 registradas mediante un Temporary Access Pass.

Consejo para el examen: Si la pregunta pide protección contra phishing o fatiga de MFA, 'exigir MFA' no basta; elige la fuerza de autenticación resistente al phishing con FIDO2/passkeys, Windows Hello for Business o autenticación basada en certificados. SMS y voz nunca son resistentes al phishing.

Comprueba lo que sabes

¿Qué control de concesión de Conditional Access te permite exigir específicamente llaves FIDO2?

Require authentication strength, usando la fuerza integrada Phishing-resistant MFA o una fuerza personalizada limitada a FIDO2.

¿Por qué es vulnerable una notificación push sin coincidencia de números?

Los usuarios pueden aprobar solicitudes que no iniciaron, como en los ataques de fatiga de MFA, y los códigos o aprobaciones pueden retransmitirse a través de proxies de phishing.

¿Cómo registra una passkey un usuario nuevo que no tiene contraseña?

Un administrador emite un Temporary Access Pass, que el usuario usa para iniciar sesión una vez y registrar la passkey.
