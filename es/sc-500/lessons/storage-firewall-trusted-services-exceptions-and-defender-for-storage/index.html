Firewall de Storage, excepciones de servicios de confianza y Defender for Storage (supervisión de actividad, análisis de malware, detección de amenazas a datos confidenciales)

De forma predeterminada, los endpoints de una cuenta de almacenamiento aceptan conexiones desde cualquier red, y dependen solo de la autorización para proteger los datos. El firewall de Storage (la hoja Networking) agrega una capa de red. El acceso de red público puede estar Enabled from all networks, Enabled from selected virtual networks and IP addresses, o Disabled. Con redes seleccionadas, agregas subredes de redes virtuales (que necesitan el service endpoint Microsoft.Storage) e intervalos de IP públicas en formato CIDR; no se pueden usar intervalos de IP privadas en las reglas de IP. Con Disabled, solo los private endpoints pueden llegar a la cuenta. Las reglas de red se aplican en todos los protocolos, incluidos REST y SMB, y una solicitud debe pasar tanto el firewall como la autorización.

Algunos servicios de Azure no pueden colocarse en tu red virtual pero aun así necesitan llegar a la cuenta, por ejemplo Azure Backup, los registros de diagnóstico de Azure Monitor, Event Grid o Azure Site Recovery. La excepción 'Allow Azure services on the trusted services list to access this storage account' los deja pasar, normalmente cuando se autentican con una identidad administrada. Las reglas de instancia de recurso (resource instance rules) son una opción más precisa: permiten una instancia de recurso específica, como un área de trabajo de Synapse o un Data Factory en particular, según su identidad administrada. Otras excepciones permiten leer los registros y las métricas desde cualquier red.

Microsoft Defender for Storage es el plan de Defender for Cloud para cuentas de almacenamiento. No usa agentes y no afecta el rendimiento. La supervisión de actividad analiza la telemetría del plano de datos y del plano de control para generar alertas ante comportamientos sospechosos: acceso desde un nodo de salida de Tor o una IP maliciosa conocida, acceso anónimo inusual, volúmenes inusuales de extracción o eliminación de datos, acceso desde una ubicación inusual, uso sospechoso de SAS y cambios que abren un contenedor al acceso público.

El análisis de malware (malware scanning) inspecciona los blobs en busca de contenido malicioso. El análisis al cargar (on-upload) revisa los blobs a medida que se escriben, usando motores de Microsoft Defender Antivirus que se ejecutan en el entorno de Microsoft, así que nunca es necesario descargar el archivo a una VM. Los resultados se escriben como etiquetas de índice de blob (blob index tags) y pueden enviarse a Event Grid, a un área de trabajo de Log Analytics y a las alertas de Defender for Cloud. Luego puedes automatizar una respuesta, como mover o eliminar los archivos infectados, con una Function o una Logic App, o usar la opción integrada de eliminación temporal de blobs maliciosos. También existe el análisis a petición (on-demand). El análisis de malware se factura por gigabyte analizado y puedes fijar un límite mensual por cuenta.

La detección de amenazas a datos confidenciales (sensitive data threat detection) usa los tipos de información confidencial de Microsoft Purview para descubrir qué cuentas contienen datos como números de tarjetas de crédito o datos personales, y eleva la gravedad y la prioridad de las alertas cuando la actividad sospechosa involucra esas cuentas. Esto ayuda a un SOC a centrarse en los incidentes que más importan.

Habilita el plan a nivel de suscripción para que las cuentas nuevas queden cubiertas automáticamente, y reemplaza la configuración por cuenta solo cuando sea necesario. Las alertas aparecen en Defender for Cloud, pueden transmitirse a Microsoft Sentinel y llegan al portal de Defender XDR como incidentes.

Términos clave

Storage firewall (firewall de Storage)
Reglas de red que restringen qué subredes, intervalos de IP públicas o private endpoints pueden llegar a una cuenta de almacenamiento.
Trusted services exception (excepción de servicios de confianza)
Una configuración del firewall que permite que los servicios de Azure de la lista, como Azure Backup, omitan las reglas de red.
Resource instance rule (regla de instancia de recurso)
Una regla de firewall que permite que una instancia de recurso de Azure específica, identificada por su identidad administrada, acceda a la cuenta.
Malware scanning (análisis de malware)
Una función de Defender for Storage que analiza los blobs cargados en busca de malware y etiqueta o alerta según los resultados.
Sensitive data threat detection (detección de amenazas a datos confidenciales)
Priorización de Defender for Storage que usa los tipos de información confidencial de Purview para señalar amenazas a cuentas que contienen datos confidenciales.
Ejemplo real

Un portal web permite a los clientes subir documentos a una cuenta de almacenamiento. Configuras el acceso público en redes seleccionadas, permitiendo solo la subred de la aplicación, habilitas Defender for Storage con análisis de malware al cargar, y usas una suscripción de Event Grid para disparar una Function que mueve cualquier blob etiquetado como malicioso a un contenedor de cuarentena.

Consejo para el examen: No se pueden agregar intervalos de IP privadas al firewall de IP de Storage; usa reglas de VNet o private endpoints. Si un servicio de Microsoft como Azure Backup falla después de cerrar el firewall, la solución es la excepción de servicios de confianza o una regla de instancia de recurso.

Comprueba lo que sabes

¿Qué debe tener una subred antes de que puedas agregarla como regla de red virtual de Storage?

El service endpoint Microsoft.Storage habilitado en esa subred.

¿Dónde se guardan en el blob los resultados del análisis de malware de Defender for Storage?

Como etiquetas de índice de blob, y también pueden enviarse a Event Grid, Log Analytics y alertas de Defender for Cloud.

¿Cómo permites que pase por el firewall un Data Factory específico, pero no todos los servicios de confianza?

Agregando una regla de instancia de recurso para ese recurso de Data Factory.
