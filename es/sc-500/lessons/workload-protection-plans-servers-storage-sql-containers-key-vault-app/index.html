Planes de protección de cargas de trabajo (Servers, Storage, SQL, Containers, Key Vault, App Service, AI) y manejo de alertas

La administración de la postura encuentra debilidades antes de un ataque; la protección de cargas de trabajo detecta los ataques mientras ocurren. En Defender for Cloud, la protección de cargas de trabajo en la nube viene en planes de pago separados que habilitas por suscripción en la página Environment settings > Defender plans. Habilitarlos a nivel de suscripción cubre los recursos existentes y futuros de ese tipo. Cada plan usa señales adecuadas para su carga de trabajo.

Defender for Servers protege las VMs y las máquinas habilitadas para Arc mediante Microsoft Defender for Endpoint, la administración de vulnerabilidades y, en el Plan 2, JIT, FIM y el análisis de malware sin agente. Defender for Storage detecta accesos sospechosos y exfiltración de datos, y ofrece análisis de malware de las cargas. Defender for Databases cubre Azure SQL, SQL en máquinas, bases de datos relacionales de código abierto y Cosmos DB, con alertas como inyección SQL y fuerza bruta, además de evaluación de vulnerabilidades. Defender for Containers cubre las amenazas en tiempo de ejecución de Kubernetes y las vulnerabilidades de las imágenes. Defender for Key Vault señala accesos inusuales a secretos. Defender for App Service detecta ataques contra aplicaciones web, como actividad de web shells y DNS colgantes. Defender for Resource Manager vigila las operaciones de administración en busca de actividad sospechosa, y Defender for APIs protege las API publicadas en API Management. Defender for AI services detecta jailbreaks y otras amenazas a los despliegues de modelos de IA.

Cuando un plan detecta algo, crea una alerta de seguridad. Cada alerta tiene una gravedad (High, Medium, Low o Informational), una descripción, los recursos afectados, las tácticas de MITRE ATT&CK, evidencia como direcciones IP o líneas de comando de procesos, y los pasos de respuesta recomendados. Las alertas relacionadas se correlacionan en incidentes. Las alertas aparecen en la página Security alerts de Defender for Cloud y en el portal de Microsoft Defender XDR, donde las alertas de Defender for Cloud se integran con las señales de endpoints, identidades y correo en incidentes unificados.

Una rutina sólida de manejo de alertas: clasificar por gravedad y por la importancia del activo afectado; abrir la alerta para leer la evidencia y la pestaña 'take action', que enumera los pasos de mitigación, las recomendaciones relacionadas que la habrían evitado y las opciones para desencadenar automatización; investigar con registros en Log Analytics o Sentinel; contener (por ejemplo, aislar una máquina mediante Defender for Endpoint, rotar una clave, bloquear una IP); y luego cambiar el estado de la alerta a Active, In progress o Resolved (o Dismissed para los falsos positivos).

El ajuste reduce el ruido. Las reglas de supresión de alertas (suppression rules) descartan automáticamente las alertas que cumplen condiciones como el tipo de alerta, el recurso o la IP, para actividad benigna conocida, como una prueba de penetración. La supresión debe ser acotada y con límite de tiempo. La automatización de flujos de trabajo (workflow automation) puede ejecutar una Logic App cuando se dispara una alerta, y las notificaciones por correo (en Environment settings) envían las alertas de gravedad alta a personas designadas y a los propietarios de la suscripción. La exportación continua transmite las alertas a Log Analytics o Event Hubs, y el conector de datos de Defender for Cloud las lleva a Microsoft Sentinel.

También puedes generar alertas de ejemplo (sample alerts) desde la página Security alerts para probar tu canal de notificaciones y automatización sin un ataque real.

Términos clave

Cloud workload protection (protección de cargas de trabajo en la nube)
Detección de amenazas en tiempo de ejecución para tipos de recursos específicos, proporcionada mediante los planes de Defender for Cloud.
Security alert (alerta de seguridad)
Una detección de actividad sospechosa con gravedad, evidencia, tácticas de MITRE e indicaciones de respuesta.
Suppression rule (regla de supresión)
Una regla que descarta automáticamente las alertas que cumplen condiciones definidas, usada para actividad benigna conocida.
Sample alerts (alertas de ejemplo)
Alertas de prueba generadas a petición para validar las notificaciones y la automatización.
Ejemplo real

Una alerta de gravedad High informa 'Access from a Tor exit node to a Key Vault'. El analista revisa la evidencia, ve el token de una identidad administrada usado desde una IP inesperada, rota los secretos a los que podía llegar, restringe el vault a un private endpoint y marca la alerta como Resolved. Por separado, se agrega una regla de supresión, con fecha de caducidad, para una prueba de penetración programada desde un intervalo de IP conocido.

Consejo para el examen: Los planes se habilitan por suscripción en Defender plans; habilítalos a nivel de suscripción para cubrir los recursos futuros. Usa reglas de supresión para las alertas benignas conocidas, workflow automation para responder y alertas de ejemplo para probar. Las alertas también aparecen como incidentes en Defender XDR.

¿Cómo evitas que una actividad benigna conocida genere alertas todos los días?

Creando una regla de supresión de alertas de alcance reducido, idealmente con fecha de caducidad.
