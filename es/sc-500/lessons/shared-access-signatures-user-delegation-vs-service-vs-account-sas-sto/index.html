Firmas de acceso compartido: SAS de delegación de usuario vs de servicio vs de cuenta, directivas de acceso almacenadas y revocación

Una firma de acceso compartido (shared access signature, SAS) es una cadena de consulta de URL firmada que concede acceso limitado y con tiempo definido a recursos de almacenamiento sin compartir una clave de cuenta ni requerir que el cliente tenga una identidad de Entra. Es típica para permitir que un navegador suba un archivo directamente, o para dar a un socio acceso temporal de lectura a un contenedor. El token codifica permisos (lectura, escritura, listado, eliminación, etc.), una hora de inicio y de caducidad, el recurso y, opcionalmente, las direcciones IP y el protocolo permitidos (solo HTTPS); luego una firma demuestra que la emitió alguien con derecho a hacerlo.

Hay tres tipos. Una user delegation SAS (SAS de delegación de usuario) se firma con una clave de delegación de usuario obtenida con credenciales de Microsoft Entra. Funciona para Blob storage (incluido Data Lake Storage Gen2), y los permisos que concede están limitados por los permisos de RBAC de la identidad que la creó. Como está respaldada por Entra ID, sigue funcionando cuando Shared Key está deshabilitado y su creación es atribuible. Microsoft la recomienda como la SAS más segura. Una service SAS (SAS de servicio) se firma con una clave de cuenta y concede acceso a recursos de un solo servicio (blob, cola, tabla o archivo). Una account SAS (SAS de cuenta) también se firma con una clave de cuenta, pero puede conceder acceso a varios servicios y a operaciones de nivel de servicio, así que es el tipo más amplio.

La revocación es el punto débil. Una SAS es solo una cadena, y cualquiera que la tenga puede usarla hasta que caduque. Para las SAS firmadas con clave tus opciones son limitadas: regenerar la clave de cuenta que la firmó (lo que rompe toda SAS firmada con ella y toda aplicación que use esa clave) o esperar a que caduque. Para una user delegation SAS, puedes revocar todas las claves de delegación de usuario de la cuenta, o la SAS deja de funcionar si su creador pierde los permisos de RBAC necesarios.

Una directiva de acceso almacenada (stored access policy), definida en un contenedor, cola, tabla o recurso compartido de archivos, te da un control más fino sobre las SAS de servicio. La SAS hace referencia a la directiva por su nombre en lugar de incluir su propio inicio, caducidad y permisos. Cambiar la caducidad de la directiva a una fecha pasada, o eliminar la directiva, invalida de inmediato toda SAS vinculada a ella sin tocar las claves de cuenta. Cada contenedor admite hasta cinco directivas de acceso almacenadas. Las directivas de acceso almacenadas no se admiten para user delegation SAS ni para account SAS.

Buenas prácticas: prefiere la user delegation SAS, usa solo HTTPS, mantén una caducidad corta, concede los permisos mínimos sobre el recurso más reducido, restringe los intervalos de IP cuando sea posible, usa directivas de acceso almacenadas cuando debas usar SAS de servicio, configura una directiva de caducidad de SAS en la cuenta para que se marquen los tokens de larga duración, y supervisa los registros de almacenamiento en busca de usos inesperados de SAS. Nunca pegues un token SAS en tickets, repositorios de código ni chats.

Términos clave

User delegation SAS (SAS de delegación de usuario)
Una SAS de Blob firmada con una clave obtenida mediante credenciales de Entra ID, limitada por los permisos de RBAC de su creador.
Service SAS (SAS de servicio)
Una SAS firmada con una clave de cuenta que concede acceso a recursos de un único servicio de almacenamiento.
Account SAS (SAS de cuenta)
Una SAS firmada con clave que puede abarcar varios servicios y operaciones de nivel de servicio.
Stored access policy (directiva de acceso almacenada)
Una directiva con nombre en un contenedor, cola, tabla o recurso compartido a la que pueden hacer referencia los tokens de SAS de servicio, lo que permite cambiarlos o revocarlos de forma centralizada.
Ejemplo real

Un socio necesita subir archivos a un contenedor durante un mes. Creas una directiva de acceso almacenada llamada partner-upload con permisos de escritura y creación, y luego generas una SAS de servicio que hace referencia a ella. Cuando la colaboración termina antes de tiempo, eliminas la directiva y la SAS del socio deja de funcionar al instante, sin regenerar las claves de cuenta.

Consejo para el examen: SAS más segura: user delegation. Revocar una SAS de servicio sin rotar claves: directiva de acceso almacenada. Revocar una SAS ad hoc firmada con clave: regenerar la clave que la firmó. La SAS de cuenta no puede usar directivas de acceso almacenadas.

Comprueba lo que sabes

¿Qué tipo de SAS sigue funcionando cuando la autorización Shared Key está deshabilitada?

Una user delegation SAS, porque está firmada con una clave de delegación de usuario derivada de Entra.

¿Cómo revocas una sola SAS de servicio que se emitió sin directiva de acceso almacenada?

No puedes revocar solo ese token; debes regenerar la clave de cuenta que la firmó o esperar a que caduque.

¿Cuál es la ventaja de una directiva de acceso almacenada?

Te permite cambiar o revocar de forma centralizada todos los tokens SAS vinculados a ella editando o eliminando la directiva.
