Funciones de Defender CSPM: análisis de rutas de ataque, cloud security explorer, análisis sin agente, reglas de gobernanza

Un entorno grande puede producir miles de recomendaciones. Tratarlas todas como igual de urgentes es imposible, así que Defender CSPM agrega contexto: qué debilidades se conectan realmente en una ruta que un atacante podría usar y qué recursos importan más. Todo esto se basa en el grafo de seguridad en la nube (cloud security graph), una base de datos de tus recursos, identidades, exposición de red, vulnerabilidades, secretos y confidencialidad de los datos, además de las relaciones entre ellos.

El análisis de rutas de ataque (attack path analysis) usa el grafo para encontrar cadenas de condiciones explotables desde un punto de entrada hasta un objetivo crítico. Una ruta típica dice algo así: una VM expuesta a internet con una vulnerabilidad de gravedad alta tiene una identidad administrada con permisos sobre una cuenta de almacenamiento que contiene datos confidenciales. Cada ruta muestra el punto de entrada, los pasos, el objetivo, el nivel de riesgo y las recomendaciones específicas que romperían la cadena. Corregir un eslabón, como quitar la IP pública o reducir los permisos de la identidad, puede eliminar toda la ruta. Las rutas se recalculan periódicamente y puedes verlas en Attack path analysis en el portal. Los puntos de estrangulamiento (choke points), donde muchas rutas pasan por un mismo recurso, son especialmente valiosos de corregir.

Cloud security explorer te permite consultar el grafo por tu cuenta con un generador visual de consultas, sin escribir código. Eliges un tipo de recurso y agregas condiciones y relaciones, por ejemplo 'máquinas virtuales expuestas a internet que tienen vulnerabilidades de gravedad alta y tienen permisos sobre key vaults', o 'imágenes de contenedor con CVE críticas que se ejecutan en Kubernetes'. Hay plantillas de consulta integradas para preguntas de riesgo comunes. Sirve para la búsqueda proactiva de combinaciones riesgosas que ninguna recomendación individual expresa.

El análisis sin agente (agentless scanning) inspecciona las cargas de trabajo sin instalar nada. Para las VMs, Defender for Cloud toma una instantánea de los discos, la analiza fuera de banda en un entorno controlado por Microsoft y luego la elimina; encuentra el software instalado, las vulnerabilidades, los secretos (como claves SSH o credenciales de la nube que quedaron en el disco) y, con Defender for Servers Plan 2, malware. Para los contenedores, el descubrimiento sin agente mapea los clústeres de Kubernetes y las imágenes. Como no hay agente, la cobertura es rápida y no afecta el rendimiento de la carga de trabajo. Funciona en Azure, AWS y GCP. Lo configuras en los ajustes del plan y puedes excluir máquinas por etiqueta.

Las reglas de gobernanza (governance rules) convierten los hallazgos en trabajo con responsables. Una regla asigna automáticamente un propietario (por ejemplo, el valor de la etiqueta Owner del recurso) y un plazo de corrección a las recomendaciones que cumplen condiciones como la gravedad o el ámbito del recurso, opcionalmente con un período de gracia que mantiene sin efecto la puntuación de seguridad hasta la fecha límite. Los propietarios reciben notificaciones semanales por correo de las tareas abiertas y vencidas, y el informe de gobernanza muestra el avance por propietario y ámbito. Así es como un equipo central de seguridad impulsa la corrección en muchos equipos de aplicaciones.

Otras funciones de Defender CSPM que puedes encontrar: postura de seguridad consciente de los datos (descubrimiento de datos confidenciales en almacenamiento y bases de datos, que se usa para elevar el riesgo de las rutas hacia datos confidenciales), postura de seguridad de IA, información de seguridad de DevOps que vincula repositorios de código con recursos en la nube, e información de administración de permisos.

Términos clave

Cloud security graph (grafo de seguridad en la nube)
La base de datos de Defender CSPM de recursos, exposiciones, identidades y relaciones que se usa para el análisis con contexto.
Attack path analysis (análisis de rutas de ataque)
Descubrimiento automático de cadenas explotables desde un punto de entrada hasta un activo crítico, con correcciones para romperlas.
Cloud security explorer
Un generador de consultas para buscar en el grafo de seguridad combinaciones riesgosas de condiciones.
Governance rule (regla de gobernanza)
Una regla que asigna propietarios y fechas límite a las recomendaciones coincidentes y hace seguimiento de la corrección.
Choke point (punto de estrangulamiento)
Un recurso por el que pasan muchas rutas de ataque, lo que lo convierte en una corrección de alto valor.
Ejemplo real

El análisis de rutas de ataque muestra una VM expuesta a internet que ejecuta un servidor web vulnerable cuya identidad administrada tiene Storage Blob Data Reader en una cuenta de almacenamiento donde el descubrimiento de datos confidenciales encontró registros de clientes. Quitas la asignación de rol de la identidad, lo que rompe la ruta, y luego creas una regla de gobernanza que asigna todas las recomendaciones de VM de gravedad alta al propietario indicado en la etiqueta con una fecha límite de 14 días.

Consejo para el examen: Cadenas automáticas y priorizadas de extremo a extremo: análisis de rutas de ataque. Tu propia pregunta ad hoc sobre el grafo: cloud security explorer. Análisis basado en instantáneas sin agentes: agentless scanning. Propietarios y fechas límite: reglas de gobernanza. Todo requiere Defender CSPM, no la CSPM básica.

Comprueba lo que sabes

¿Qué función de Defender CSPM usarías para listar todas las VMs expuestas a internet con CVE críticas y acceso a key vaults?

Cloud security explorer.

¿Cómo inspecciona una VM el análisis sin agente sin tener un agente?

Toma instantáneas de los discos de la VM, analiza la instantánea fuera de banda y luego la elimina.

¿Qué agrega una regla de gobernanza a una recomendación?

Un propietario asignado y una fecha límite de corrección, con notificaciones y seguimiento del avance.
