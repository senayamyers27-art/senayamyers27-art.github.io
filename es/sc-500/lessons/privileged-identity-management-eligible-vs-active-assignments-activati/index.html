Privileged Identity Management: asignaciones elegibles vs activas, activación con MFA, aprobación y justificación, revisiones de acceso

Microsoft Entra Privileged Identity Management (PIM) proporciona acceso privilegiado justo a tiempo (just-in-time). En lugar de que alguien tenga Global Administrator u Owner de suscripción todo el día, lo tiene solo cuando lo necesita, por un tiempo limitado y con un registro de auditoría. PIM requiere licencias de Microsoft Entra ID P2 o Entra ID Governance para los usuarios que se benefician de él. Cubre tres tipos de roles: roles de Microsoft Entra, roles de recursos de Azure (Azure RBAC en el ámbito de grupo de administración, suscripción, grupo de recursos o recurso) y pertenencia o propiedad de grupos mediante PIM for Groups.

Una asignación elegible (eligible) significa que el usuario puede activar el rol, pero no tiene permisos hasta que lo haga. Una asignación activa (active) significa que los permisos están en vigor ahora. Ambas pueden ser permanentes o con límite de tiempo (con fecha de inicio y de fin). El patrón recomendado son asignaciones elegibles y con límite de tiempo para los administradores, y solo las cuentas de emergencia (break-glass) tienen Global Administrator activo permanente.

Cuando un usuario elegible activa un rol (en el portal, en My roles, o mediante la API), PIM aplica la configuración del rol que definiste. Las opciones comunes son: duración máxima de la activación (por ejemplo, unas pocas horas), exigir autenticación multifactor de Azure al activar o exigir un contexto de autenticación de Conditional Access; exigir un texto de justificación; exigir un número de ticket; y exigir aprobación. Si se requiere aprobación, los aprobadores designados reciben una notificación y deben aprobar antes de que el rol se active. La activación termina automáticamente cuando vence la duración, y los usuarios pueden desactivarla antes.

PIM también envía notificaciones (por ejemplo, cuando se activa o se asigna un rol), mantiene un historial de auditoría de asignaciones y activaciones y genera alertas sobre configuraciones riesgosas, como demasiados Global Administrators, roles asignados fuera de PIM o roles que nunca se activan. Estas alertas son una forma rápida de encontrar privilegios permanentes.

Las revisiones de acceso (access reviews) forman parte de Entra ID Governance y se integran con PIM. Puedes programar una revisión periódica de quién tiene un rol privilegiado, pidiendo a los propios usuarios, a sus gerentes o a revisores específicos que confirmen que el acceso sigue siendo necesario. Las opciones incluyen duración, recurrencia, qué sucede si los revisores no responden (mantener, quitar o aplicar recomendaciones) y si los resultados se aplican automáticamente. Quitar de esta forma las asignaciones elegibles y activas innecesarias mantiene pequeña la población privilegiada con el tiempo.

En un laboratorio abrirás Microsoft Entra ID > Identity Governance > Privileged Identity Management, elegirás Microsoft Entra roles, abrirás un rol como Security Reader, editarás su configuración para exigir MFA y justificación, agregarás una asignación elegible para un usuario de prueba y luego iniciarás sesión como ese usuario para activarlo.

Términos clave

Eligible assignment (asignación elegible)
Una asignación de PIM que permite a un usuario activar un rol cuando lo necesita; no otorga permisos hasta que se activa.
Active assignment (asignación activa)
Una asignación de rol cuyos permisos están en vigor en este momento, ya sea de forma permanente o por un tiempo definido.
Activation (activación)
El paso justo a tiempo en el que un usuario elegible activa un rol, sujeto a la configuración de MFA, justificación, ticket o aprobación.
Access review (revisión de acceso)
Una comprobación programada en la que los revisores confirman o quitan el acceso continuo de los usuarios a un rol, grupo o aplicación.
Ejemplo real

Una ingeniera de nube es elegible para Owner en la suscripción de producción. Durante una interrupción del servicio lo activa por dos horas, completa MFA, escribe una justificación que hace referencia al ticket del incidente y espera la aprobación del gerente de guardia. El rol vence por sí solo, y el registro de auditoría guarda quién lo aprobó y por qué.

Consejo para el examen: Elegible es 'puede activar', activo es 'lo tiene ahora'. Si una pregunta pide cómo eliminar el acceso de administrador permanente y a la vez conservar la capacidad de hacer trabajo de administración, la respuesta es convertir las asignaciones activas permanentes en elegibles en PIM.

Comprueba lo que sabes

¿Qué licencia requiere PIM?

Microsoft Entra ID P2 (o Entra ID Governance) para los usuarios que usan PIM o se benefician de él.

¿Qué opciones de configuración de rol de PIM ayudan a garantizar que una persona real y autorizada active Owner?

Exigir MFA (o un contexto de autenticación) al activar, exigir justificación e información de ticket, y exigir la aprobación de aprobadores designados.

¿Cómo confirmas periódicamente que los Global Administrators elegibles aún necesitan el rol?

Creando una revisión de acceso periódica para ese rol en PIM o Identity Governance y configurándola para quitar el acceso a los usuarios denegados o no revisados.
