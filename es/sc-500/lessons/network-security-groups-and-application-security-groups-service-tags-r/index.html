Grupos de seguridad de red y grupos de seguridad de aplicaciones, etiquetas de servicio, prioridad de reglas y reglas predeterminadas

Un grupo de seguridad de red (network security group, NSG) es un filtro de paquetes con estado para las redes virtuales de Azure. Contiene reglas de seguridad de entrada y de salida y puede asociarse a una subred, a una interfaz de red (NIC) o a ambas. Con estado (stateful) significa que el tráfico de retorno de una conexión permitida se permite automáticamente, así que solo escribes una regla para la dirección en la que se inicia la conexión.

Cada regla tiene una prioridad (un número de 100 a 4096), un nombre, un origen y un destino (direcciones IP, intervalos CIDR, service tags o grupos de seguridad de aplicaciones), puertos, protocolo (TCP, UDP, ICMP o Any) y una acción Allow o Deny. Las reglas se procesan en orden de prioridad, empezando por el número más bajo, y el procesamiento se detiene en la primera coincidencia. Así, un Deny en 200 gana a un Allow en 300 para el mismo tráfico.

Todo NSG tiene reglas predeterminadas con prioridades de 65000 a 65500 que no puedes eliminar, solo invalidar con reglas de número más bajo. De entrada: AllowVNetInBound (tráfico desde la etiqueta VirtualNetwork), AllowAzureLoadBalancerInBound y DenyAllInBound. De salida: AllowVnetOutBound, AllowInternetOutBound y DenyAllOutBound. El efecto práctico es que el tráfico dentro de la red virtual (y de redes emparejadas o conectadas por VPN) está permitido, el tráfico de entrada desde internet está denegado y el tráfico de salida hacia internet está permitido hasta que lo restrinjas.

Cuando hay NSG tanto en la subred como en la NIC, el tráfico de entrada lo evalúa primero el NSG de la subred y luego el de la NIC; el de salida va primero por la NIC y luego por la subred. El tráfico debe estar permitido por ambos. Un error común es abrir un puerto en el NSG de la NIC y olvidar el NSG de la subred.

Las etiquetas de servicio (service tags) son nombres administrados por Microsoft para grupos de prefijos IP, como Internet, VirtualNetwork, AzureLoadBalancer, Storage, Sql, AzureMonitor o versiones regionales como Storage.WestEurope. Microsoft actualiza los prefijos automáticamente, así que evitas mantener largas listas de IP. Por ejemplo, una regla de salida que permite Storage en 443 y una regla de menor prioridad que deniega Internet permite que las VMs lleguen a Azure Storage pero a nada más en internet.

Los grupos de seguridad de aplicaciones (application security groups, ASG) te permiten agrupar NICs por rol de la carga de trabajo, como asg-web y asg-db, y usar esos nombres como orígenes y destinos en las reglas de NSG. En lugar de reglas con direcciones IP que cambian a medida que las VMs escalan, escribes 'permitir asg-web hacia asg-db en 1433'. Una NIC puede pertenecer a varios ASG, pero todas las NICs de un ASG deben estar en la misma red virtual.

Usa las reglas de seguridad efectivas (effective security rules) y IP flow verify de Network Watcher para ver qué regla está afectando realmente a una VM.

Términos clave

Network security group (grupo de seguridad de red)
Un conjunto con estado de reglas de permitir y denegar que se aplica a subredes o NICs.
Rule priority (prioridad de regla)
Un número de 100 a 4096; los números más bajos se procesan primero y gana la primera coincidencia.
Service tag (etiqueta de servicio)
Una etiqueta mantenida por Microsoft que representa los prefijos IP de un servicio o categoría de Azure, como Storage o Internet.
Application security group (grupo de seguridad de aplicaciones)
Una agrupación lógica de NICs que se usa como origen o destino en reglas de NSG en lugar de direcciones IP.
Ejemplo real

Una aplicación de tres capas tiene VMs web, de aplicación y de base de datos en una subred. Creas ASG para cada capa y un NSG con reglas: permitir Internet hacia asg-web en 443 (prioridad 100), permitir asg-web hacia asg-app en 8080 (110), permitir asg-app hacia asg-db en 1433 (120) y denegar VirtualNetwork hacia asg-db en cualquier puerto (200), para que los servidores web no puedan llegar directamente a la base de datos.

Consejo para el examen: Gana el número de prioridad más bajo y la evaluación se detiene en la primera coincidencia. Las reglas predeterminadas permiten todo el tráfico de VNet a VNet, así que la microsegmentación dentro de una VNet necesita reglas de denegación explícitas con números de prioridad inferiores a 65000. Entrada: subred y luego NIC; salida: NIC y luego subred.

Comprueba lo que sabes

Un NSG tiene Allow TCP 3389 con prioridad 300 y Deny any con prioridad 200 para el mismo origen. ¿Se permite RDP?

No, el Deny en 200 se evalúa primero y coincide.

¿Qué regla predeterminada permite el tráfico entre VMs en redes virtuales emparejadas?

AllowVNetInBound, porque la etiqueta de servicio VirtualNetwork incluye los espacios de direcciones emparejados y conectados.

¿Por qué usar ASG en lugar de direcciones IP en las reglas?

Las reglas siguen los roles de las cargas de trabajo, así que escalar las VMs o cambiar sus IP no requiere modificar reglas.
