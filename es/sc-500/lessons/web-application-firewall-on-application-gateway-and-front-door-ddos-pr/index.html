Web Application Firewall en Application Gateway y Front Door, DDoS Protection

Un firewall de aplicaciones web (web application firewall, WAF) inspecciona las solicitudes HTTP y HTTPS en la capa 7 y bloquea ataques web comunes como la inyección SQL, el cross-site scripting, la inclusión remota de archivos y las violaciones de protocolo. Complementa, pero no reemplaza, la programación segura. Azure Web Application Firewall puede ejecutarse en dos lugares. En Azure Application Gateway, un balanceador de carga regional de capa 7, protege aplicaciones en una región, normalmente dentro de una red virtual o delante de ella. En Azure Front Door, un servicio perimetral global con puntos de entrada anycast, filtra el tráfico en el perímetro de Microsoft antes de que llegue a tus orígenes, lo cual encaja con aplicaciones globales y detiene el tráfico malicioso cerca de su origen.

Ambos usan una directiva de WAF (WAF policy). Los conjuntos de reglas administrados (managed rule sets) los mantiene Microsoft: el OWASP Core Rule Set (CRS) o el Microsoft Default Rule Set (DRS), además del conjunto de reglas Bot Manager para bots buenos y malos conocidos. Puedes deshabilitar o cambiar la acción de reglas individuales y agregar exclusiones para campos de la solicitud que provocan falsos positivos. Las reglas personalizadas (custom rules) se evalúan antes que las reglas administradas y permiten coincidir por dirección IP, geografía, encabezados de la solicitud, cadenas de consulta o métodos, con limitación de velocidad (rate limiting) para frenar a los clientes que superan un umbral.

Una directiva de WAF se ejecuta en modo Detection, que registra las coincidencias sin bloquear, o en modo Prevention, que bloquea. Empieza en Detection, revisa los registros (el registro del firewall de Application Gateway o el registro de WAF de Front Door en Log Analytics), ajusta las exclusiones y luego cambia a Prevention. Los conjuntos de reglas más recientes usan puntuación de anomalías (anomaly scoring): cada regla que coincide suma a una puntuación y la solicitud se bloquea cuando la puntuación supera un umbral, lo que reduce los falsos positivos.

Azure DDoS protection defiende contra ataques de denegación de servicio distribuida. Toda IP pública de Azure recibe sin costo una protección básica a nivel de infraestructura. Azure DDoS Protection (el nivel Network Protection, habilitado mediante un plan de protección contra DDoS asociado a redes virtuales) agrega ajuste adaptativo basado en tu perfil de tráfico, telemetría y métricas de ataques, alertas, informes de mitigación de ataques y registros de flujo, acceso al equipo DDoS Rapid Response y créditos de protección de costos por el escalado durante un ataque documentado. DDoS IP Protection es una opción por IP pública con las funciones principales de mitigación pero menos extras. DDoS Protection cubre ataques volumétricos y de protocolo en las capas 3 y 4.

Los dos servicios trabajan juntos: DDoS Protection absorbe las inundaciones en la capa de red, mientras que el WAF maneja los ataques de la capa de aplicación, incluidas las inundaciones de capa 7 mediante reglas personalizadas de limitación de velocidad. El perímetro global de Front Door también absorbe de forma natural grandes volúmenes.

En el laboratorio probablemente desplegarás un Application Gateway WAF_v2 con una directiva de WAF en modo Detection, enviarás una solicitud que contenga una cadena de prueba inofensiva que se parezca a un patrón de inyección y leerás la coincidencia en los registros del firewall.

Términos clave

Web application firewall (firewall de aplicaciones web)
Un filtro de capa 7 que inspecciona las solicitudes HTTP en busca de ataques como inyección SQL y cross-site scripting.
Managed rule set (conjunto de reglas administrado)
Reglas de WAF mantenidas por Microsoft basadas en el OWASP Core Rule Set o en el Microsoft Default Rule Set.
Custom rule (regla personalizada)
Una regla de WAF definida por el usuario, evaluada antes que las reglas administradas, que coincide con condiciones como IP, geografía o velocidad.
Detection mode (modo de detección)
Un modo de WAF que registra las coincidencias de reglas sin bloquear las solicitudes.
DDoS Network Protection
El nivel de pago de Azure DDoS que agrega ajuste adaptativo, telemetría, respuesta rápida y protección de costos para los recursos de una VNet.
Ejemplo real

Un sitio minorista global sufre ráfagas de credential stuffing y sondeos ocasionales de inyección. Lo colocas detrás de Azure Front Door con una directiva de WAF que usa el Microsoft Default Rule Set y las reglas de Bot Manager, agregas una regla personalizada de limitación de velocidad en la ruta de inicio de sesión, lo ejecutas en Detection durante una semana para ajustar las exclusiones y luego cambias a Prevention.

Consejo para el examen: Global, perímetro, multirregión: WAF en Front Door. Regional, dentro de una VNet: WAF en Application Gateway. Inundaciones de capa 3/4: DDoS Protection. Las reglas personalizadas se procesan antes que las administradas, y el modo Detection nunca bloquea.

Comprueba lo que sabes

Una nueva directiva de WAF está causando falsos positivos en un campo de formulario. ¿Qué debes hacer?

Agregar una exclusión para ese campo de la solicitud (o ajustar la regla específica), idealmente ejecutando primero en modo Detection.

¿Qué agrega DDoS Network Protection sobre la protección básica gratuita?

Ajuste adaptativo, telemetría y alertas de ataques, informes de mitigación, soporte de respuesta rápida y protección de costos.

¿Qué ubicación del WAF bloquea los ataques lo más cerca posible del atacante en una aplicación multirregión?

Azure Front Door, porque filtra en el perímetro global de Microsoft.
