Panel de cumplimiento normativo: Microsoft cloud security benchmark y cómo agregar estándares

Los auditores y los reguladores preguntan si tu entorno cumple con marcos específicos: PCI DSS para datos de tarjetas, ISO 27001, NIST SP 800-53, SOC 2, los CIS benchmarks y muchos otros. El panel de cumplimiento normativo (regulatory compliance dashboard) de Defender for Cloud asigna las evaluaciones técnicas que ya realiza a los controles de esos marcos, para que puedas ver qué controles se cumplen, cuáles fallan y qué recursos son los responsables.

La base es el Microsoft cloud security benchmark (MCSB). Es el conjunto propio de buenas prácticas de seguridad de Microsoft para Azure y multinube, organizado en dominios de control como seguridad de red, administración de identidades, acceso con privilegios, protección de datos, administración de activos, registro y detección de amenazas, respuesta a incidentes, administración de postura y vulnerabilidades, seguridad de endpoints, copia de seguridad y recuperación, seguridad de DevOps y gobernanza. El MCSB se asigna de forma predeterminada a cada suscripción y conector, y es lo que genera las recomendaciones predeterminadas y la puntuación de seguridad. Se asigna a otros marcos como CIS y NIST, así que mejorar frente al MCSB también te acerca a ellos.

Cada estándar del panel se muestra como una lista de controles. Cada control está vinculado a una o más evaluaciones automatizadas (las mismas recomendaciones que ves en otras partes). Un control aparece como aprobado cuando todas sus evaluaciones están en buen estado, como fallido cuando alguna falla, y en gris o como manual cuando no hay evaluaciones automatizadas, porque muchos controles, como tener un programa de concienciación en seguridad, requieren evidencia humana. Puedes certificar los controles manuales, descargar informes de cumplimiento y resúmenes en PDF, y abrir los propios informes de auditoría de Microsoft mediante el vínculo de informes de auditoría del portal.

Para agregar estándares, abre Environment settings, selecciona la suscripción, el grupo de administración o el conector, y elige Security policies (el texto exacto del portal varía con el tiempo). Con Defender CSPM habilitado, puedes agregar estándares del sector y normativos desde un amplio catálogo para Azure, AWS y GCP. En Azure, el estándar se asigna internamente como una iniciativa de Azure Policy, así que también aparece en el cumplimiento de Azure Policy. También puedes crear estándares personalizados formados por tu propia selección de recomendaciones o por recomendaciones personalizadas. La CSPM básica te limita principalmente al MCSB.

Advertencia importante: un panel completamente en verde no significa que estés certificado. Solo refleja comprobaciones técnicas automatizadas. El cumplimiento también depende de los procesos, la documentación y el criterio de los auditores, y la cobertura depende de qué planes de Defender y qué recursos estén incluidos.

Para informes a escala, la exportación continua puede transmitir el estado de cumplimiento normativo a Log Analytics, y los workbooks de Defender for Cloud muestran el cumplimiento a lo largo del tiempo.

Términos clave

Microsoft cloud security benchmark
El estándar de seguridad predeterminado de Microsoft en Defender for Cloud, que cubre las buenas prácticas de Azure y multinube.
Regulatory compliance dashboard (panel de cumplimiento normativo)
La vista de Defender for Cloud que asigna las evaluaciones a los controles de los estándares seleccionados.
Standard (estándar)
Un conjunto de controles de cumplimiento, como PCI DSS o ISO 27001, asignado a un ámbito en Defender for Cloud.
Custom standard (estándar personalizado)
Un conjunto de recomendaciones definido por el usuario y agrupado como estándar para su seguimiento.
Ejemplo real

Tu empresa procesa pagos con tarjeta en dos suscripciones. Con Defender CSPM habilitado, agregas PCI DSS como estándar a esas suscripciones en Environment settings. El panel muestra un control fallido de cifrado de la transmisión, vinculado a aplicaciones web que permiten TLS 1.0; las corriges, adjuntas evidencia para los controles manuales y descargas el informe para el auditor.

Consejo para el examen: El MCSB es el estándar predeterminado e impulsa la puntuación de seguridad. Agregar otros estándares normativos se hace en Environment settings y en general requiere Defender CSPM. En Azure, los estándares se implementan como iniciativas de Azure Policy. Un panel en verde no es una certificación.

Comprueba lo que sabes

¿Qué estándar se asigna de forma predeterminada a todas las suscripciones en Defender for Cloud?

El Microsoft cloud security benchmark.

¿Por qué algunos controles no muestran evaluaciones automatizadas?

Cubren procesos o procedimientos que no pueden comprobarse técnicamente y requieren certificación manual.

¿Cómo se implementa en las suscripciones de Azure un estándar normativo agregado?

Como una iniciativa de Azure Policy asignada al ámbito.
