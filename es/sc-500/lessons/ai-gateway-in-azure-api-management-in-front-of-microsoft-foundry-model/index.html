AI Gateway en Azure API Management delante de los modelos de Microsoft Foundry: autenticación con identidad administrada, límites de tokens, registro

Cuando muchas aplicaciones llaman directamente a modelos de IA, cada una necesita claves del modelo, cada una puede consumir tokens sin límite y nadie tiene un registro central del uso. Azure API Management (APIM) puede actuar como puerta de enlace de IA (AI gateway) delante de los endpoints de modelos de Microsoft Foundry y Azure OpenAI para resolverlo. Los clientes llaman al endpoint de APIM; APIM aplica directivas y reenvía las solicitudes al backend del modelo. Microsoft usa el término 'AI gateway' para este conjunto de capacidades de IA generativa en APIM.

Las directivas de APIM son instrucciones XML en las secciones inbound, backend, outbound y on-error de una API. Para escenarios de IA, las más importantes son las directivas de autenticación, límite de tokens, métricas de tokens, balanceo de carga y almacenamiento en caché.

La autenticación se divide en dos saltos. De APIM al modelo, usa la identidad administrada de APIM en lugar de una clave de API: habilita una identidad asignada por el sistema o por el usuario en la instancia de APIM, concédele un rol como Cognitive Services OpenAI User (o el rol de usuario equivalente de Foundry) en el recurso del modelo y agrega la directiva authentication-managed-identity con el recurso de Cognitive Services como audiencia. Luego puedes deshabilitar por completo la autenticación basada en claves (local) en el recurso del modelo. De los clientes a APIM, exige como mínimo claves de suscripción de APIM y, preferiblemente, valida tokens de Entra con la directiva validate-jwt o validate-azure-ad-token para que cada llamador tenga una identidad. Así, ninguna aplicación tiene jamás una clave del modelo.

Los límites de tokens protegen el presupuesto y la capacidad. La directiva llm-token-limit (y la más antigua azure-openai-token-limit) aplica una tasa de tokens por minuto y, opcionalmente, una cuota de tokens en un período más largo, por clave de contador, como el ID de suscripción o la IP del cliente. Las solicitudes que superan el límite reciben una respuesta 429 Too Many Requests. Puede estimar los tokens del prompt antes de enviar la solicitud, bloqueando pronto los prompts demasiado grandes. Esto protege contra el wallet abuse y contra que una sola aplicación ruidosa deje sin recursos a las demás.

El registro y las métricas dan visibilidad. La directiva llm-emit-token-metric envía los recuentos de tokens del prompt, de la respuesta (completion) y totales a Application Insights con dimensiones personalizadas como cliente, API o usuario, para que puedas hacer refacturación interna (chargeback) y detectar anomalías. La configuración de diagnóstico de APIM puede enviar los registros de la puerta de enlace, incluido el registro de solicitudes y respuestas de LLM donde esté habilitado, a un área de trabajo de Log Analytics. Ten cuidado: registrar prompts completos puede capturar datos personales, así que aplica controles de retención y acceso.

Otras funciones de la puerta de enlace incluyen grupos de backends con balanceo de carga y disyuntores (circuit breakers) entre varios despliegues de modelos o regiones, caché semántica para reutilizar respuestas a prompts similares, y directivas de seguridad de contenido que llaman a Azure AI Content Safety antes de reenviar las solicitudes. Colocar APIM en una red virtual con private endpoints hacia los modelos mantiene el tráfico privado.

Términos clave

AI gateway (puerta de enlace de IA)
El conjunto de capacidades de Azure API Management para gobernar y proteger el acceso a los endpoints de modelos de IA.
authentication-managed-identity
Una directiva de APIM que obtiene un token de Entra usando la identidad administrada de APIM para llamar a un backend.
llm-token-limit
Una directiva de APIM que aplica tasas de tokens por minuto y cuotas de tokens por clave, devolviendo 429 cuando se superan.
Token metrics (métricas de tokens)
Recuentos de tokens de prompt, de respuesta y totales que APIM emite a Application Insights para supervisión y refacturación interna.
Ejemplo real

Cinco aplicaciones internas comparten un despliegue de Azure OpenAI, y un script descontrolado consumió el presupuesto del mes. Colocas APIM delante del modelo, concedes a la identidad administrada de APIM el rol de usuario de OpenAI, deshabilitas las claves locales en el modelo, aplicas llm-token-limit por suscripción y emites métricas de tokens a Application Insights para que el uso de cada equipo sea visible.

Consejo para el examen: La autenticación de APIM al modelo usa la identidad administrada de APIM más un rol de RBAC, lo que te permite deshabilitar las claves de API del modelo. La protección contra el uso excesivo es la directiva de límite de tokens (429 al superarlo); la visibilidad del uso es la directiva de métricas de tokens más Application Insights y Log Analytics.

Comprueba lo que sabes

¿Cómo puede APIM llamar a un modelo de Foundry sin guardar una clave de API?

Habilitando la identidad administrada de APIM, concediéndole el rol de usuario del modelo y usando la directiva authentication-managed-identity.

¿Qué respuesta recibe un cliente cuando supera el límite de tokens configurado?

HTTP 429 Too Many Requests.

¿Por qué hay que tener cuidado al registrar prompts y respuestas completos?

Pueden contener datos personales o confidenciales, así que el registro necesita controles de acceso y límites de retención.
