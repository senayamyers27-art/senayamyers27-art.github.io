Trusted launch: arranque seguro, vTPM y supervisión de la integridad del arranque

Parte del malware más peligroso se ejecuta incluso antes de que arranque el sistema operativo. Los bootkits y rootkits manipulan el cargador de arranque o el kernel para cargarse primero, esconderse del antivirus y sobrevivir a la reinstalación de aplicaciones. Trusted launch es un tipo de seguridad de Azure para máquinas virtuales de Generación 2 que defiende contra estos ataques con tres funciones que trabajan juntas. Es el tipo de seguridad predeterminado para las nuevas VMs Gen2 en la mayoría de los escenarios, y no tiene costo adicional.

Secure Boot (arranque seguro) es una función del firmware UEFI. Al iniciar, el firmware comprueba que cada componente de arranque (el cargador de arranque, el kernel y los controladores del kernel) esté firmado por un editor de confianza. Si un componente fue manipulado o no está firmado, no se carga. Esto bloquea directamente muchos bootkits y rootkits. Algunas distribuciones de Linux o kernels personalizados necesitan componentes firmados para arrancar con Secure Boot habilitado, y esa es la principal consideración de compatibilidad.

El Trusted Platform Module virtual (vTPM) es una versión virtualizada de un TPM 2.0 de hardware, dedicada a la VM. Proporciona un lugar seguro para claves y certificados y registra mediciones de la cadena de arranque en sus registros de configuración de plataforma (PCR). El arranque medido (measured boot) significa que cada etapa calcula el hash de la siguiente y guarda el resultado en el vTPM, creando un registro exacto de lo que se ejecutó durante el inicio. El vTPM también habilita funciones del invitado como BitLocker con protección TPM, Windows Credential Guard y la seguridad basada en virtualización (VBS), y cumple requisitos como el prerrequisito de TPM de Windows 11.

La supervisión de la integridad del arranque (boot integrity monitoring) usa atestación remota. La extensión Guest Attestation de la VM envía la evidencia del arranque medido del vTPM a Microsoft Azure Attestation, que la compara con una línea base conocida como buena. Luego Microsoft Defender for Cloud informa del estado de arranque de la VM: si la atestación falla, por ejemplo porque un componente de arranque cambió inesperadamente, Defender for Cloud genera una recomendación o alerta para que puedas investigar. Instalar la extensión (Defender for Cloud puede hacerlo por ti) y tener una identidad administrada asignada por el sistema son requisitos previos para la supervisión.

Trusted launch requiere imágenes de VM de Generación 2 y tamaños de VM compatibles. Puedes habilitarlo al crear una VM (Security type: Trusted launch virtual machines, con las casillas de Secure Boot y vTPM), y las VMs Gen1 existentes pueden actualizarse a Gen2 con trusted launch en los casos compatibles. Azure Policy y las recomendaciones de Defender for Cloud pueden auditar que las VMs usen trusted launch, Secure Boot y vTPM.

No confundas trusted launch con las VMs confidenciales. Las VMs confidenciales van más allá usando entornos de ejecución de confianza basados en hardware (como AMD SEV-SNP o Intel TDX) para cifrar la memoria de la VM y aislarla del host y del hipervisor. Trusted launch protege la integridad del arranque; la computación confidencial protege los datos en uso.

Términos clave

Trusted launch
Un tipo de seguridad de Azure para VMs Gen2 que combina Secure Boot, vTPM y supervisión de la integridad del arranque.
Secure Boot (arranque seguro)
Una función UEFI que carga solo componentes de arranque firmados por editores de confianza.
vTPM
Un TPM 2.0 virtual que almacena claves y registra los valores del arranque medido de la VM.
Boot integrity monitoring (supervisión de la integridad del arranque)
Atestación remota de las mediciones de arranque de una VM, informada como estado de salud en Defender for Cloud.
Measured boot (arranque medido)
Registrar en el TPM los hashes de cada etapa del arranque para poder verificar después la cadena de inicio.
Ejemplo real

Una línea base de seguridad exige que todos los servidores Windows nuevos resistan los bootkits y admitan BitLocker con TPM. Los despliegas como VMs Gen2 con trusted launch, habilitas Secure Boot y vTPM, dejas que Defender for Cloud instale la extensión Guest Attestation y asignas una directiva que audita las VMs que no usan trusted launch.

Consejo para el examen: Componentes de arranque firmados: Secure Boot. Claves y mediciones: vTPM. Detectar una cadena de arranque manipulada: supervisión de la integridad del arranque mediante Guest Attestation y Defender for Cloud. Trusted launch requiere VMs Gen2; cifrar la memoria en uso corresponde a las VMs confidenciales, no a trusted launch.

Comprueba lo que sabes

¿Qué componente de trusted launch impide que se ejecute un cargador de arranque no firmado?

Secure Boot.

¿Qué debe instalarse para que Defender for Cloud informe de la integridad del arranque?

La extensión Guest Attestation (con una identidad administrada en la VM).

¿Qué generación de VM requiere trusted launch?

Generación 2.
