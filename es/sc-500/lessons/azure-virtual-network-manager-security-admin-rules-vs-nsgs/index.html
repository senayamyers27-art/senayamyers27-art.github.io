Reglas de administrador de seguridad de Azure Virtual Network Manager vs NSG

En una organización grande, cada equipo de aplicaciones suele administrar los NSG de sus propias subredes. Eso es flexible, pero dificulta que un equipo central de seguridad garantice que cierto tráfico, como RDP y SSH de entrada desde internet, esté bloqueado en todas partes. Azure Virtual Network Manager (AVNM) resuelve esto permitiendo que un equipo central defina configuraciones de conectividad y de seguridad una sola vez y las despliegue en muchas redes virtuales, suscripciones y regiones.

AVNM trabaja con grupos de red (network groups), que son conjuntos de redes virtuales reunidos de forma estática (tú las eliges) o dinámica (mediante condiciones de Azure Policy, como todas las VNets con la etiqueta env=prod). El ámbito del administrador, uno o varios grupos de administración o suscripciones, determina qué VNets puede gobernar. Luego creas configuraciones y las despliegas en las regiones elegidas; nada cambia hasta que se confirma (commit) un despliegue.

Una configuración de administrador de seguridad (security admin configuration) contiene colecciones de reglas de administrador de seguridad (security admin rules). Se parecen a las reglas de NSG (prioridad, dirección, protocolo, puertos, origen y destino), pero tienen un lugar distinto en la evaluación y tres acciones posibles. Allow permite el tráfico, y luego los NSG se siguen evaluando y pueden denegarlo. Deny bloquea el tráfico y los NSG no pueden invalidarlo. Always Allow permite el tráfico y omite la evaluación de los NSG, así que los NSG no pueden bloquearlo; eso es útil para garantizar que el tráfico de supervisión o de administración siempre pase.

La idea clave es el orden de evaluación: las reglas de administrador de seguridad se evalúan antes que las reglas de NSG. Eso significa que un Deny central para el tráfico procedente de internet hacia el puerto 3389 gana sin importar lo que cualquier equipo de aplicaciones ponga en su NSG. Los NSG siguen siendo importantes para las reglas detalladas y específicas de cada aplicación que los equipos mantienen por su cuenta. Piensa en las reglas de administrador de seguridad como barreras de protección para toda la organización y en los NSG como controles locales.

Otras diferencias: los NSG se asocian a subredes o NICs una por una, mientras que las reglas de administrador de seguridad se aplican a todas las VNets de un grupo de red, incluidas las VNets nuevas que se unen a un grupo dinámico. Los NSG los administran los propietarios de los recursos con permisos de red; las reglas de administrador de seguridad las administra quien tenga derechos sobre el Network Manager. Las reglas de administrador de seguridad se aplican incluso a subredes que no tienen ningún NSG.

AVNM también proporciona configuraciones de conectividad (topologías hub-and-spoke o de malla con emparejamiento automático) y configuraciones de enrutamiento, pero para este examen lo principal es el comportamiento de las reglas de administrador de seguridad.

Términos clave

Azure Virtual Network Manager
Un servicio central que agrupa redes virtuales y les despliega configuraciones de conectividad y seguridad a escala.
Network group (grupo de red)
Un conjunto estático o dinámico (basado en directivas) de redes virtuales al que se dirigen las configuraciones de AVNM.
Security admin rule (regla de administrador de seguridad)
Una regla administrada de forma central que se evalúa antes que los NSG, con acciones Allow, Deny o Always Allow.
Always Allow
Una acción de administrador de seguridad que permite el tráfico y omite para él la evaluación de los NSG.
Ejemplo real

El equipo de seguridad crea un grupo de red dinámico con todas las VNets etiquetadas env=prod en 30 suscripciones y despliega una regla de administrador de seguridad que deniega el tráfico de entrada desde la etiqueta de servicio Internet en los puertos 22 y 3389. Un desarrollador que más tarde agrega una regla de NSG que permite RDP desde cualquier lugar descubre que las conexiones siguen fallando, porque la regla de administrador se evalúa primero.

Consejo para el examen: El orden es reglas de administrador de seguridad y luego NSG. Un Deny en la capa de administrador no puede invalidarse; Allow todavía permite que los NSG denieguen; Always Allow omite por completo los NSG. Elige AVNM cuando una pregunta pida aplicar reglas de forma central que los equipos locales no puedan eludir.

Comprueba lo que sabes

Una regla de administrador de seguridad permite TCP 443 y un NSG lo deniega. ¿Qué ocurre?

El tráfico se deniega, porque Allow en la capa de administrador sigue pasando el tráfico a la evaluación del NSG.

¿Qué acción garantiza que el tráfico de supervisión llegue a las VMs aunque un NSG lo bloquee?

Always Allow.

¿Cómo pueden las nuevas VNets de producción recibir automáticamente las reglas de administrador de seguridad?

Usando un grupo de red dinámico cuya condición de Azure Policy coincida con ellas, como una etiqueta.
