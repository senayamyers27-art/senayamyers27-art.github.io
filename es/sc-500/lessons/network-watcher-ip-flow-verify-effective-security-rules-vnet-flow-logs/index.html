Network Watcher: IP flow verify, reglas de seguridad efectivas, registros de flujo de VNet y análisis de tráfico

Azure Network Watcher es un conjunto regional de herramientas para supervisar y diagnosticar las redes IaaS. Se habilita automáticamente por región cuando creas una red virtual. Para los ingenieros de seguridad responde dos tipos de preguntas: ¿por qué se permite o bloquea este tráfico? y ¿qué tráfico está fluyendo realmente?

IP flow verify comprueba si un paquete con un origen, destino, puerto y protocolo dados se permitiría hacia o desde la NIC de una VM específica. Evalúa las reglas de NSG efectivas (y las reglas de administrador de seguridad) y devuelve Allow o Deny junto con el nombre de la regla que tomó la decisión. Úsalo cuando alguien diga 'no puedo conectarme en el puerto 443' para saber en segundos si la causa es un NSG.

Effective security rules (reglas de seguridad efectivas) muestra el conjunto combinado de reglas aplicadas a una NIC, fusionando el NSG de la subred, el NSG de la NIC y las reglas predeterminadas, incluida la expansión de service tags y ASG en prefijos. Es la forma de ver la directiva real cuando se superponen varias capas. Para problemas de enrutamiento está la herramienta relacionada Next hop y la vista de rutas efectivas de la NIC, que revelan si una UDR está enviando el tráfico a un firewall o a un agujero negro.

Otros diagnósticos incluyen Connection troubleshoot (prueba una conexión de extremo a extremo e informa dónde falla), Connection monitor (pruebas continuas de accesibilidad y latencia), la captura de paquetes (registra el tráfico en una VM mediante la extensión de Network Watcher) y VPN troubleshoot para problemas de la puerta de enlace.

Los registros de flujo (flow logs) registran metadatos del tráfico IP: IP de origen y destino, puertos, protocolo, si el flujo se permitió o se denegó, y recuentos de bytes y paquetes. Los NSG flow logs fueron la versión original y se registraban por NSG. Los VNet flow logs son el enfoque más nuevo y el recomendado: se habilitan a nivel de red virtual, subred o NIC, capturan el tráfico exista o no un NSG, y además registran las decisiones de las reglas de administrador de seguridad y el estado de cifrado del cifrado de red virtual. Microsoft ha anunciado el retiro de los NSG flow logs en favor de los VNet flow logs. Los registros de flujo se escriben como JSON en una cuenta de almacenamiento, con una configuración de retención.

Traffic analytics (análisis de tráfico) procesa los registros de flujo y envía resultados agregados y enriquecidos a un área de trabajo de Log Analytics, con un intervalo de procesamiento como cada 10 minutos o cada hora. Sus paneles y las tablas subyacentes muestran los principales emisores (top talkers), el tráfico hacia y desde internet, los flujos desde IP maliciosas conocidas, los puertos abiertos, las tendencias del tráfico bloqueado y el tráfico por región y aplicación. Puedes consultar los datos con KQL y enviarlos a Microsoft Sentinel.

Flujo de trabajo típico: habilitar los VNet flow logs hacia una cuenta de almacenamiento con traffic analytics activado, y luego usar IP flow verify y effective security rules cuando surja un problema de conexión concreto.

Términos clave

IP flow verify
Una herramienta de Network Watcher que comprueba si un paquete específico se permite o se deniega hacia o desde una VM y nombra la regla que decide.
Effective security rules (reglas de seguridad efectivas)
La vista combinada de todas las reglas de NSG y predeterminadas que realmente se aplican a una NIC.
VNet flow logs (registros de flujo de VNet)
Registros de flujo capturados a nivel de red virtual, subred o NIC, independientes de los NSG, almacenados en una cuenta de almacenamiento.
Traffic analytics (análisis de tráfico)
Una función que agrega los registros de flujo en Log Analytics para paneles, consultas e información sobre amenazas.
Ejemplo real

Después de un cambio, un servidor de aplicaciones ya no puede llegar a su base de datos en 1433. IP flow verify informa Deny por la regla DenyAppOut del NSG de la NIC. Effective security rules confirma que tiene un número de prioridad más bajo que la regla de permiso prevista. Corriges la prioridad, y más tarde traffic analytics muestra que los flujos de la base de datos vuelven.

Consejo para el examen: ¿Se permite un paquete específico y qué regla decidió? IP flow verify. ¿Qué reglas están vigentes en una NIC? Effective security rules. ¿Hacia dónde va el tráfico? Next hop. ¿Qué tráfico fluyó históricamente? Flow logs con traffic analytics.

Comprueba lo que sabes

¿Qué herramienta nombra la regla de NSG exacta que bloquea una conexión a una VM?

IP flow verify.

¿Cuál es una ventaja de los VNet flow logs sobre los NSG flow logs?

Se habilitan en la VNet, la subred o la NIC y capturan el tráfico incluso sin un NSG, incluidas las decisiones de las reglas de administrador de seguridad.

¿Dónde guarda traffic analytics sus resultados procesados?

En un área de trabajo de Log Analytics, donde pueden consultarse con KQL.
