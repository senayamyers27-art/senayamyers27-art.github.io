Microsoft Certified: Cloud and AI Security Engineer Associate (replaces Azure Security Engineer Associate / AZ-500) SC-500

Conditional Access: usuarios e identidades de carga de trabajo, aplicaciones en la nube, condiciones (riesgo de inicio de sesión, ubicaciones, plataforma del dispositivo), controles de concesión y de sesión, modo solo informe

Conditional Access (acceso condicional) es el motor de directivas de Microsoft Entra ID. Después del primer factor de autenticación, evalúa señales sobre el inicio de sesión y decide si lo permite, exige algo más o lo bloquea. Piensa en cada directiva como una instrucción si-entonces: si estas asignaciones y condiciones coinciden, entonces aplica estos controles de acceso. Requiere Microsoft Entra ID P1; las condiciones basadas en riesgo necesitan P2.

Las asignaciones definen a quién y a qué se dirige la directiva. Los usuarios se pueden incluir o excluir por usuario, grupo, rol de directorio o tipo de invitado. También se pueden seleccionar identidades de carga de trabajo (entidades de servicio de aplicaciones de un solo tenant), por ejemplo para impedir que una entidad de servicio inicie sesión fuera de rangos de IP conocidos; eso requiere licencias de Workload Identities Premium. Los recursos de destino (antes aplicaciones en la nube) pueden ser todos los recursos, aplicaciones específicas como Office 365 o la Windows Azure Service Management API, acciones de usuario como registrar información de seguridad, o contextos de autenticación. Siempre excluye al menos una cuenta de emergencia (break-glass) de las directivas de bloqueo.

Las condiciones acotan cuándo se aplica una directiva. El riesgo de inicio de sesión y el riesgo de usuario provienen de Entra ID Protection. Las ubicaciones son ubicaciones con nombre (named locations) definidas por rangos de IP o países, y se pueden marcar como de confianza. Las plataformas de dispositivo incluyen Android, iOS, Windows y macOS. Otras condiciones incluyen aplicaciones cliente (navegador, aplicaciones móviles y clientes de escritorio, o clientes de autenticación heredada), filtro para dispositivos y riesgo interno (insider risk). Si hay varias condiciones, todas deben coincidir.

Los controles de concesión (grant controls) deciden el acceso. Puedes bloquear el acceso o concederlo exigiendo uno o todos de los siguientes: autenticación multifactor, una fuerza de autenticación (authentication strength), un dispositivo marcado como compatible en Intune, un dispositivo unido a Microsoft Entra híbrido, una aplicación cliente aprobada, una directiva de protección de aplicaciones, cambio de contraseña o términos de uso. Los controles de sesión (session controls) definen lo que sucede después de conceder el acceso: frecuencia de inicio de sesión, sesión persistente del navegador, restricciones aplicadas por la aplicación, Conditional Access App Control mediante Microsoft Defender for Cloud Apps y la configuración de evaluación continua de acceso (continuous access evaluation).

Cuando aplican varias directivas, se aplican todas. El bloqueo gana sobre todo lo demás, y deben cumplirse todos los requisitos de concesión de todas las directivas que coincidan. Por eso una directiva de bloqueo demasiado amplia puede dejar fuera a los administradores.

El modo solo informe (report-only) te permite activar una directiva en un estado de evaluar sin aplicar. Los registros de inicio de sesión muestran lo que la directiva habría hecho (éxito, error o acción del usuario requerida) y el libro de trabajo Conditional Access insights and reporting resume el impacto. La herramienta What If del portal simula un inicio de sesión para que veas qué directivas se aplicarían. El patrón de implementación seguro es: crear en modo solo informe, revisar los registros, hacer un piloto en un grupo y luego cambiar a On.

Directivas de referencia clásicas que debes reconocer: exigir MFA para todos los administradores, exigir MFA para la administración de Azure, bloquear la autenticación heredada, exigir MFA para inicios de sesión riesgosos, exigir cambio de contraseña ante riesgo de usuario alto y exigir dispositivos compatibles para aplicaciones sensibles.

Términos clave

Conditional Access policy (directiva de acceso condicional)
Una regla si-entonces en Entra ID que evalúa señales de inicio de sesión y aplica controles de concesión o de sesión.
Grant control (control de concesión)
La parte de una directiva que bloquea el acceso o lo concede solo si se cumplen requisitos como MFA o un dispositivo compatible.
Session control (control de sesión)
Un control que limita la sesión después de conceder el acceso, como la frecuencia de inicio de sesión o las restricciones aplicadas por la aplicación.
Named location (ubicación con nombre)
Un conjunto de rangos de IP o países que se usa como condición; se puede marcar como de confianza.
Report-only mode (modo solo informe)
Un estado de la directiva que registra lo que sucedería sin aplicar la directiva.
Ejemplo real

Quieres MFA para cualquiera que administre recursos de Azure desde fuera de la oficina. La directiva se dirige a todos los usuarios excepto las cuentas de emergencia, se dirige a la Windows Azure Service Management API, establece las ubicaciones en cualquier ubicación excepto la ubicación con nombre de confianza de la oficina y concede el acceso exigiendo MFA. La ejecutas en modo solo informe durante una semana, revisas los registros de inicio de sesión y luego la activas.

Consejo para el examen: Recuerda la lógica de evaluación: se aplican todas las directivas que coinciden, el bloqueo siempre gana y las exclusiones prevalecen sobre las inclusiones. Si un escenario advierte sobre dejar a todos fuera, la respuesta suele incluir el modo solo informe, What If y exclusiones de cuentas de emergencia.

Comprueba lo que sabes

¿Qué licencia se necesita para usar el riesgo de inicio de sesión como condición de Conditional Access?

Microsoft Entra ID P2, porque el riesgo de inicio de sesión proviene de Entra ID Protection.

Dos directivas aplican a un inicio de sesión: una exige MFA y la otra exige un dispositivo compatible. ¿Qué debe cumplir el usuario?

Ambos requisitos, porque se aplican los controles de concesión de todas las directivas que coinciden.

¿Cómo puedes medir el impacto de una nueva directiva antes de aplicarla?

Habilitándola en modo solo informe y revisando los registros de inicio de sesión y el libro de trabajo de insights, o simulando inicios de sesión específicos con la herramienta What If.
