Backup y restauración de etcd con etcdctl/etcdutl y la PKI de etcd; apuntar el static Pod de etcd a un directorio de datos restaurado

Como etcd guarda todo el estado del clúster, un snapshot de etcd es un backup de la configuración del clúster. El CKA suele pedirte que tomes uno en una ruta determinada y que más tarde restaures uno. Necesitas conocer las herramientas, los certificados y cómo volver a apuntar el static Pod de etcd.

etcdctl es el cliente que se comunica con un etcd en ejecución por la red. En un clúster de kubeadm, etcd exige TLS mutuo, así que pasas tres archivos de /etc/kubernetes/pki/etcd: la CA, y un certificado y una clave de cliente. La forma más sencilla de encontrar las rutas y el endpoint correctos es leerlos de /etc/kubernetes/manifests/etcd.yaml (mira --listen-client-urls, --trusted-ca-file, --cert-file y --key-file). En la mayoría de las instalaciones de kubeadm, el certificado de servidor funciona como certificado de cliente, y también existe un certificado dedicado healthcheck-client.

# el endpoint por defecto es el puerto de cliente local 2379; agrega --endpoints si etcd está en otro lugar
ETCDCTL_API=3 etcdctl \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /opt/backup/etcd.db
etcdutl snapshot status /opt/backup/etcd.db -w table

etcdutl es la utilidad offline que trabaja directamente sobre archivos. En las versiones actuales de etcd, la restauración y el estado de los snapshots se hacen con etcdutl, y el antiguo etcdctl snapshot restore está obsoleto. Una restauración no sobrescribe la base de datos en ejecución; construye un nuevo directorio de datos a partir del snapshot: etcdutl snapshot restore /opt/backup/etcd.db --data-dir /var/lib/etcd-restored. No se necesitan flags de TLS porque no contacta a ningún servidor.

Ahora apunta etcd a los datos restaurados. Edita /etc/kubernetes/manifests/etcd.yaml. El directorio de datos aparece en el flag --data-dir y en el volumen hostPath llamado etcd-data. El cambio más simple y confiable es actualizar el path del hostPath a /var/lib/etcd-restored (y también el flag, si además cambias la ruta de montaje). Guarda el archivo; el kubelet reinicia etcd con el estado anterior. El API server puede tardar un minuto en reconectarse, así que kubectl puede fallar brevemente. Si se queda atascado, revisa con crictl ps y crictl logs en el nodo.

Trata los archivos de snapshot como altamente sensibles: contienen todos los Secrets del clúster, sin cifrar a menos que hayas habilitado el cifrado en reposo (encryption at rest). Guárdalos con permisos restrictivos y fuera del nodo.

Términos clave

etcdctl
El cliente de red para un etcd en ejecución; se usa para snapshot save, member list y endpoint health.
etcdutl
La utilidad offline de etcd para trabajar con archivos de datos, incluidos snapshot restore y status.
Data directory (directorio de datos)
La ubicación en disco de la base de datos de etcd, definida por --data-dir y montada mediante un volumen hostPath.
etcd PKI
La CA y los certificados separados en /etc/kubernetes/pki/etcd que se usan para el TLS mutuo de etcd.
Ejemplo real

Después de tomar un snapshot en /opt/snap.db, un compañero borra el namespace payments. Ejecutas etcdutl snapshot restore /opt/snap.db --data-dir /var/lib/etcd-from-backup, cambias el hostPath etcd-data en etcd.yaml a ese directorio, esperas a que etcd y el API server se reinicien, y kubectl get ns vuelve a mostrar payments.

Consejo para el examen: snapshot save falla con un error de TLS o de deadline si omites --cacert, --cert o --key; copia las rutas directamente del manifiesto de etcd en lugar de adivinarlas. Para la restauración, recuerda que el volumen hostPath es lo que realmente decide qué directorio del host ve etcd.

Comprueba lo que sabes

¿snapshot restore sobrescribe la base de datos de etcd en ejecución?

No. Crea un nuevo directorio de datos; luego apuntas etcd hacia él.

¿Dónde puedes consultar el endpoint y las rutas de certificados que necesita etcdctl?

En el manifiesto del static Pod de etcd, /etc/kubernetes/manifests/etcd.yaml.
