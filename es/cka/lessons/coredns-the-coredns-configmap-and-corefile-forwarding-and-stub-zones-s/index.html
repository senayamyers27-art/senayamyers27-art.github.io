CoreDNS: el ConfigMap coredns y el Corefile, reenvío y stub zones, registros DNS de Services y Pods, y dnsPolicy

CoreDNS es el servidor DNS del clúster. En los clústeres de kubeadm se ejecuta como el Deployment coredns en kube-system, expuesto por un Service que por compatibilidad sigue llamándose kube-dns, normalmente en la décima dirección del Service CIDR (10.96.0.10 con el valor predeterminado de kubeadm). El kubelet escribe esa dirección en el /etc/resolv.conf de cada Pod.

Su configuración es el Corefile, guardado en el ConfigMap coredns. Cada bloque de servidor indica las zonas que atiende y una cadena de plugins. Un bloque predeterminado típico para la zona raíz incluye errors, health, ready, el plugin kubernetes que responde por cluster.local y las zonas inversas, las métricas de prometheus, forward . /etc/resolv.conf para enviar todo lo demás a los resolvers upstream del nodo, cache, loop, reload y loadbalance.

.:53 {
    errors
    health
    ready
    kubernetes cluster.local in-addr.arpa ip6.arpa {
       pods insecure
       fallthrough in-addr.arpa ip6.arpa
    }
    forward . /etc/resolv.conf
    cache 30
    loop
    reload
    loadbalance
}
corp.internal:53 {
    forward . 10.0.0.53
}

Para enviar un dominio privado a un servidor DNS específico, lo que se llama una stub zone, agrega un bloque de servidor separado para esa zona con su propio forward, como hace el bloque corp.internal de arriba. Para cambiar los resolvers upstream de todo lo demás, cambia el destino de forward .. Edita con kubectl -n kube-system edit cm coredns; el plugin reload toma el cambio después de un breve retraso, o puedes ejecutar kubectl -n kube-system rollout restart deploy coredns.

Conoce los formatos de los registros. Un Service normal obtiene un registro A (o AAAA) <svc>.<ns>.svc.cluster.local que apunta a su ClusterIP, y registros SRV para los puertos con nombre, _<port>._<proto>.<svc>.<ns>.svc.cluster.local. El nombre de un headless Service se resuelve en las IP de sus Pods, y los Pods de un StatefulSet obtienen <pod>.<svc>.<ns>.svc.cluster.local. Los Pods tienen registros de la forma 10-244-1-5.<ns>.pod.cluster.local, su IP con guiones. El resolv.conf de los Pods incluye los dominios de búsqueda <ns>.svc.cluster.local svc.cluster.local cluster.local y ndots:5, por eso un simple web funciona dentro del mismo namespace y web.other funciona entre namespaces.

El dnsPolicy de un Pod controla esto. ClusterFirst (el predeterminado) usa el DNS del clúster y reenvía los demás nombres hacia arriba. Default hereda el resolv.conf del nodo, así que los nombres del clúster no se resuelven. ClusterFirstWithHostNet es lo que necesitan los Pods con hostNetwork: true para seguir usando el DNS del clúster. None ignora todo eso y usa solo el dnsConfig que proporciones (nameservers, searches, options).

Términos clave

Corefile
La configuración de CoreDNS, guardada en el ConfigMap coredns, formada por bloques de servidor y plugins.
forward plugin (plugin forward)
Envía a los resolvers upstream las consultas para las que CoreDNS no es autoritativo.
Stub zone (zona stub)
Un bloque de servidor que reenvía un dominio específico a servidores DNS designados.
dnsPolicy
Ajuste del Pod que elige el comportamiento de DNS ClusterFirst, Default, ClusterFirstWithHostNet o None.
Ejemplo real

Los desarrolladores necesitan que los nombres *.corp.internal se resuelvan desde los Pods, pero los resolvers de los nodos no los conocen. Agregas un bloque corp.internal:53 { forward . 10.0.0.53 } al ConfigMap coredns, esperas a que se recargue, y nslookup db.corp.internal desde un Pod de prueba ahora devuelve la dirección interna.

Consejo para el examen: El Service se llama kube-dns, pero los Pods y el ConfigMap se llaman coredns. dnsPolicy Default no es el predeterminado; el predeterminado es ClusterFirst.

Comprueba lo que sabes

¿Cuál es el nombre DNS completo del Service api en el namespace shop?

api.shop.svc.cluster.local.

¿Qué dnsPolicy debería usar un Pod con hostNetwork para resolver los Services del clúster?

ClusterFirstWithHostNet.

¿Cómo reenvías un único dominio privado a un servidor DNS específico?

Agrega en el Corefile un bloque de servidor para esa zona con su propia directiva forward.
