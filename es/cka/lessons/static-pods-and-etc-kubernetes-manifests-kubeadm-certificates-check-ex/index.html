Static Pods y /etc/kubernetes/manifests; certificados de kubeadm (check-expiration, renew) y archivos kubeconfig

Un static Pod es un Pod que el kubelet ejecuta directamente a partir de un archivo de manifiesto en disco, sin que intervengan el API server ni el scheduler. El kubelet vigila un directorio, /etc/kubernetes/manifests en los clústeres de kubeadm (definido por staticPodPath en la configuración del kubelet en /var/lib/kubelet/config.yaml). Coloca un archivo YAML de Pod ahí y el kubelet lo inicia; borra el archivo y el kubelet lo detiene.

kubeadm usa esto para ejecutar el propio control plane: etcd.yaml, kube-apiserver.yaml, kube-controller-manager.yaml y kube-scheduler.yaml viven en ese directorio. Así se resuelve el problema del huevo y la gallina, porque el API server no puede programarse a sí mismo. El kubelet también crea un mirror Pod de solo lectura en la API para que puedas ver los static Pods con kubectl; sus nombres terminan con el nombre del nodo, como kube-apiserver-cp1. Borrar el mirror Pod con kubectl no tiene un efecto duradero, y editarlo no tiene ningún efecto. Para cambiar un componente del control plane, edita el archivo en el nodo; el kubelet lo detecta y recrea el Pod.

kubeadm también construye una PKI (infraestructura de clave pública) privada en /etc/kubernetes/pki: la CA del clúster, el certificado de servidor del API server, los certificados de cliente del API server para hablar con el kubelet y con etcd, la CA de front-proxy y una CA de etcd separada en pki/etcd. Los certificados de cliente que genera kubeadm son válidos por un año por defecto, mientras que las CA duran mucho más.

Revisa el vencimiento con kubeadm certs check-expiration. Renueva con kubeadm certs renew all (o uno solo, como kubeadm certs renew apiserver). Después de renovar, los static Pods del control plane deben reiniciarse para cargar los archivos nuevos; un enfoque común es sacar los manifiestos del directorio por un momento (unos 20 segundos, para que el kubelet lo note) y luego volver a ponerlos. Reiniciar solo el kubelet no reinicia los contenedores en ejecución. kubeadm también renueva los certificados automáticamente durante kubeadm upgrade apply, que es una de las razones por las que los clústeres que se actualizan con regularidad rara vez llegan al vencimiento.

Los archivos kubeconfig lo unen todo. Un kubeconfig contiene clusters (URL del servidor y CA), users (credenciales como un certificado de cliente) y contexts (un cluster más un user más un namespace opcional). kubeadm escribe admin.conf, super-admin.conf en versiones recientes, controller-manager.conf, scheduler.conf y kubelet.conf en /etc/kubernetes. La mayoría de estos incrustan certificados de cliente, por lo que también se renuevan con kubeadm certs renew; kubelet.conf es la excepción, porque apunta al propio certificado de cliente del kubelet, que el kubelet rota automáticamente. Tu propio ~/.kube/config suele ser una copia de admin.conf, así que después de renovar quizá necesites copiarlo de nuevo.

Términos clave

Static Pod (Pod estático)
Un Pod gestionado directamente por un kubelet a partir de un archivo en su staticPodPath, no por el API server.
Mirror Pod (Pod espejo)
El objeto de API de solo lectura que crea el kubelet para que un static Pod sea visible con kubectl.
kubeadm certs check-expiration
Lista cada certificado gestionado por kubeadm y cuándo vence.
Kubeconfig context (contexto)
Una combinación con nombre de un cluster, un user y un namespace por defecto.
Ejemplo real

Una tarea te pide ejecutar un Pod de nginx en node01 que sobreviva incluso si el API server está caído. Te conectas por SSH a node01, confirmas staticPodPath en /var/lib/kubelet/config.yaml, escribes un manifiesto de Pod en ese directorio y kubectl get pods muestra nginx-node01 unos segundos después.

Consejo para el examen: Para cambiar un flag del control plane, edita el manifiesto en /etc/kubernetes/manifests de ese nodo, nunca el mirror Pod mediante kubectl. Guarda una copia de respaldo del manifiesto fuera de ese directorio, porque cada archivo YAML que haya dentro se trata como un Pod.

Comprueba lo que sabes

¿Cómo averiguas de qué directorio lee un kubelet los static Pods?

Mira staticPodPath en el archivo de configuración del kubelet, normalmente /var/lib/kubelet/config.yaml.

¿Qué vigencia por defecto tienen los certificados de cliente emitidos por kubeadm y cómo los renuevas?

Un año; ejecuta kubeadm certs renew all y reinicia los componentes del control plane.

¿Qué pasa si haces kubectl delete del mirror Pod de un static Pod?

El kubelet recrea el mirror Pod porque el archivo de manifiesto sigue en el disco.
