Problemas de acceso al clúster: contexts de kubeconfig, certificados vencidos y connection refused en el 6443

Antes de poder arreglar nada necesitas llegar al clúster correcto. El CKA usa varios clústeres, y cada tarea te dice qué context usar. Los problemas de acceso también son un tema de troubleshooting por derecho propio.

kubectl lee su configuración de ~/.kube/config por defecto, de los archivos listados en la variable de entorno KUBECONFIG o de --kubeconfig. Un kubeconfig tiene clusters, users y contexts, y un current-context. Conoce bien estos comandos.

kubectl config get-contexts
kubectl config current-context
kubectl config use-context prod-admin@prod
kubectl config set-context --current --namespace=app
kubectl config view --minify          # solo el context activo
kubectl --kubeconfig /etc/kubernetes/admin.conf get nodes

En el examen, ejecuta antes que nada el comando use-context que aparece al inicio de cada tarea. Trabajar en el clúster equivocado es una de las formas más fáciles de perder puntos, porque tu respuesta correcta termina en un lugar donde el evaluador no mira.

Los mensajes de error apuntan a la capa que falló. 'connection refused' en el puerto 6443 significa que nada está escuchando en esa dirección: el API server está caído, el kubeconfig tiene el host o el puerto equivocados, o estás en una máquina que no puede llegar a él. Revisa la línea server: del cluster activo con kubectl config view --minify, y luego en el control plane usa crictl ps -a | grep kube-apiserver y sus logs, o ss -tlnp | grep 6443 para ver si algo está escuchando. Un timeout en lugar de un rechazo sugiere un firewall o una IP equivocada.

'x509: certificate has expired or is not yet valid' significa que un certificado de la cadena está fuera de su período de validez. Si venció el certificado de cliente de tu kubeconfig, necesitas uno nuevo; si vencieron los certificados del API server, todos los clientes fallan. En los clústeres de kubeadm ejecuta kubeadm certs check-expiration, luego kubeadm certs renew all, reinicia los static Pods del control plane y copia el /etc/kubernetes/admin.conf actualizado a ~/.kube/config. 'not yet valid' también puede significar que el reloj del nodo está mal. 'x509: certificate signed by unknown authority' significa que los datos de la CA en el kubeconfig no coinciden con el clúster, a menudo por copiar un kubeconfig de otro clúster.

Por último, distingue las dos fallas de autenticación y autorización. 'Unauthorized' (HTTP 401) es de autenticación: el servidor no acepta tus credenciales, como un token revocado o un certificado de la CA equivocada. 'Forbidden' (HTTP 403) es de autorización: el servidor sabe quién eres, pero RBAC no permite la acción. Para Forbidden, revisa los bindings con kubectl auth can-i; para Unauthorized, revisa las credenciales del kubeconfig.

Términos clave

Context (contexto)
Una entrada del kubeconfig que combina un cluster, un user y un namespace opcional.
KUBECONFIG
Variable de entorno que lista los archivos kubeconfig que kubectl debe combinar.
Unauthorized vs Forbidden
401 significa que falló la autenticación; 403 significa autenticado pero no permitido por RBAC.
kubeadm certs renew
Comando que renueva los certificados gestionados por kubeadm, incluidos los incrustados en los kubeconfigs.
Ejemplo real

Una mañana, todos los comandos de kubectl fallan con un error x509 de vencimiento en un clúster de laboratorio construido hace un año y nunca actualizado. kubeadm certs check-expiration muestra que todo venció ayer. Ejecutas kubeadm certs renew all, reinicias los Pods del control plane sacando los manifiestos y volviéndolos a poner, copias admin.conf a ~/.kube/config y el acceso vuelve.

Consejo para el examen: Refused significa que nada escucha (API server caído o dirección equivocada); x509 significa certificados; Unauthorized significa credenciales; Forbidden significa RBAC. El error te dice qué capa arreglar.

Comprueba lo que sabes

¿Cómo ves solo los detalles del context activo actualmente?

kubectl config view --minify.

¿Cuál es la diferencia entre una respuesta Unauthorized y una Forbidden?

Unauthorized es una autenticación fallida; Forbidden significa que la identidad es conocida pero RBAC deniega la acción.
