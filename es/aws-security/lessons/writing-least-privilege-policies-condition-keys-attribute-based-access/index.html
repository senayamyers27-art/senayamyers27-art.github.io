AWS Certified Security – Specialty SCS-C03

Escribir políticas de mínimo privilegio: condition keys, control de acceso basado en atributos con etiquetas y variables de política

Mínimo privilegio significa que cada identidad tiene solo los permisos que necesita, solo sobre los recursos que necesita y solo bajo las condiciones que necesita. IAM te da tres palancas: acciones específicas, ARNs de recursos específicos y condiciones.

Las condition keys acotan cuándo aplica una sentencia. Las claves globales incluyen aws:SourceIp, aws:SourceVpc y aws:SourceVpce para el origen de red, aws:SecureTransport para TLS, aws:MultiFactorAuthPresent y aws:MultiFactorAuthAge para MFA, aws:PrincipalOrgID y aws:ResourceOrgID para la pertenencia a la organización, aws:RequestedRegion para regiones y aws:CalledVia para solicitudes que hacen los servicios en tu nombre. Las claves de servicio agregan detalle, como s3:prefix, kms:ViaService o ec2:InstanceType. Los operadores de condición como StringEquals, StringLike, ArnLike, IpAddress, Bool y Null, y los operadores de conjuntos ForAllValues y ForAnyValue, controlan la comparación.

El control de acceso basado en atributos (ABAC) usa etiquetas en lugar de listar recursos. Una política puede permitir acciones cuando aws:ResourceTag/project es igual a ${aws:PrincipalTag/project}, así que un ingeniero con la etiqueta project=blue solo puede gestionar recursos blue. Usa aws:RequestTag y aws:TagKeys para controlar qué etiquetas se pueden poner al crear, y niega los cambios a las etiquetas que otorgan acceso, o los usuarios podrían volver a etiquetarse para entrar a otros proyectos. Las etiquetas del principal pueden venir de IAM, o como session tags desde tu proveedor de identidad mediante federación, lo que hace que ABAC escale con tu directorio.

Las variables de política insertan valores de la solicitud en las políticas. arn:aws:s3:::home-bucket/${aws:username}/* da a cada usuario IAM su propio prefijo, y ${cognito-identity.amazonaws.com:sub} hace lo mismo para identidades de Cognito. Valida las políticas con la validación de políticas de IAM Access Analyzer, que marca errores y permisos demasiado amplios, y pruébalas con el policy simulator antes de desplegarlas.

Términos clave

Condition key
Valor con nombre en el contexto de la solicitud, como aws:SourceIp, que una condición de política puede evaluar.
ABAC
Control de acceso basado en atributos: otorgar acceso comparando etiquetas de principales y recursos.
Variable de política
Marcador como ${aws:username} que IAM reemplaza con un valor de la solicitud.
Session tags
Etiquetas que se pasan al asumir un rol o al federar y que actúan como etiquetas del principal en esa sesión.
Ejemplo real

Una empresa con 300 equipos de proyecto escribe una sola política ABAC: los ingenieros pueden iniciar, detener y reiniciar instancias EC2 solo donde la etiqueta de proyecto coincide con la suya, pueden crear instancias solo con la etiqueta de su proyecto y no pueden cambiar las etiquetas de proyecto. Los equipos nuevos no necesitan políticas nuevas, solo etiquetas desde el proveedor de identidad.

Consejo para el examen: Las preguntas de ABAC suelen incluir una trampa donde los usuarios podrían cambiar sus propias etiquetas o las de un recurso. La respuesta completa también restringe las acciones de etiquetado.

Comprueba lo que sabes

¿Qué condition key limita una política a solicitudes de tu propia organización de AWS?

aws:PrincipalOrgID.

¿Cómo ayuda una variable de política a dar a cada usuario una carpeta privada en S3?

El ARN del recurso incluye ${aws:username}, así que el allow de cada usuario aplica solo al prefijo con su nombre.
