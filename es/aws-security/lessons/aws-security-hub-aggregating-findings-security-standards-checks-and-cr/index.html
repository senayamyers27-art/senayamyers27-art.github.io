AWS Certified Security – Specialty SCS-C03

AWS Security Hub: agregación de hallazgos, verificación de estándares de seguridad y agregación entre regiones

AWS Security Hub te da un solo lugar para ver y gestionar hallazgos de seguridad. Recopila hallazgos de servicios de AWS como GuardDuty, Inspector, Macie, IAM Access Analyzer, Firewall Manager y Config, y de productos de socios, y los guarda en un formato común, el AWS Security Finding Format (ASFF). AWS también ha ido ampliando Security Hub para correlacionar señales y presentarlas en el Open Cybersecurity Schema Framework (OCSF), y la parte de verificación de configuración ahora se llama Security Hub CSPM (cloud security posture management). Las habilidades de abajo aplican de cualquier forma.

Security Hub también ejecuta sus propias verificaciones. Cuando habilitas un estándar de seguridad, como AWS Foundational Security Best Practices, el CIS AWS Foundations Benchmark, PCI DSS o NIST SP 800-53, evalúa tus recursos con controles basados en reglas de AWS Config y genera un hallazgo por cada verificación fallida, además de un puntaje de seguridad. Eso significa que el registro de Config debe estar activo para los tipos de recursos que revisan los controles.

A escala, operas Security Hub desde una cuenta de administrador delegado con configuración central, de modo que los estándares y controles se definen una sola vez para la organización. La agregación entre regiones vincula las regiones a una región principal, así que los hallazgos y sus actualizaciones de cada región vinculada aparecen, y se pueden gestionar, en ese único lugar. Los insights son agrupaciones guardadas, como 'recursos con más hallazgos críticos'. Las custom actions envían hallazgos seleccionados a EventBridge para una respuesta que tú construyes, y las automation rules actualizan campos como la severidad o el estado del flujo de trabajo, o suprimen hallazgos, en cuanto llegan.

Ten claro lo que Security Hub no es. No es un motor que detecta amenazas en los logs (eso es GuardDuty), y no guarda logs crudos (eso es CloudTrail, CloudWatch Logs o Security Lake). Es el agregador, el verificador de postura y el centro del flujo de trabajo. Las preguntas que piden 'una vista de hallazgos entre cuentas y regiones' o 'calificar cuentas frente a buenas prácticas' apuntan aquí.

Términos clave

ASFF
AWS Security Finding Format, el formato JSON que Security Hub usa para los hallazgos de todas las fuentes.
Estándar de seguridad
Conjunto de controles, como CIS o AWS Foundational Security Best Practices, que Security Hub verifica contra tus recursos.
Agregación entre regiones
Ajuste que lleva los hallazgos de las regiones vinculadas a una región de agregación.
Automation rule
Regla que actualiza o suprime automáticamente los hallazgos que cumplen criterios cuando Security Hub los recibe.
Ejemplo real

Una empresa con cuentas en cuatro regiones define eu-west-1 como su región de agregación y habilita AWS Foundational Security Best Practices mediante configuración central. Una automation rule baja la severidad de una excepción conocida en las cuentas sandbox, y una custom action envía hallazgos seleccionados a un flujo de tickets a través de EventBridge.

Consejo para el examen: Si una pregunta dice que los controles de Security Hub no muestran datos, revisa si AWS Config está registrando los tipos de recursos correspondientes. Muchas verificaciones dependen de Config.

Comprueba lo que sabes

¿Qué servicio debe estar activo para que funcionen la mayoría de las verificaciones de estándares de Security Hub?

AWS Config, registrando los tipos de recursos que evalúan los controles.

¿Cuál es la diferencia entre una custom action y una automation rule?

Una custom action envía hallazgos elegidos a EventBridge cuando un analista los selecciona; una automation rule cambia o suprime automáticamente los hallazgos que coinciden al llegar.
