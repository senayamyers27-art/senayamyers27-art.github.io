AWS Certified Security – Specialty SCS-C03

Centralizar y analizar logs: CloudWatch Logs Insights, Athena sobre S3, Amazon Security Lake y OpenSearch

Los logs solo son útiles si puedes guardarlos de forma segura y buscarlos rápido. La mayoría de las organizaciones envía los logs de todas las cuentas a una cuenta central de log archive, donde el bucket tiene políticas estrictas, versionado y a veces Object Lock, y solo unos pocos roles de seguridad pueden leerlo. Desde ahí, varias herramientas ayudan a buscar.

CloudWatch Logs Insights es un lenguaje de consultas interactivo para datos que ya están en CloudWatch Logs. Una consulta como fields @timestamp, srcAddr | filter action = "REJECT" | stats count() by srcAddr | sort count() desc lista en segundos los orígenes bloqueados más ruidosos. Es ideal para datos recientes y operativos. Para visibilidad entre cuentas, la observabilidad entre cuentas de CloudWatch o los subscription filters pueden enviar eventos de log a una cuenta central, a Lambda o, mediante Amazon Data Firehose, a S3 u OpenSearch.

Amazon Athena consulta los datos en su lugar en S3 con SQL estándar y cobra por datos escaneados. Es la forma clásica de consultar logs de largo plazo de CloudTrail, flow logs, ALB o WAF. Particionar por fecha y cuenta, y usar formatos columnares como Parquet, mantiene las consultas rápidas y baratas. Amazon OpenSearch Service indexa logs para búsqueda de texto completo y dashboards, lo que conviene a un centro de operaciones de seguridad que quiere búsqueda y visualizaciones casi en tiempo real.

Amazon Security Lake construye un data lake de seguridad por ti. Recopila logs de fuentes de AWS como CloudTrail, VPC Flow Logs, logs del Route 53 Resolver, hallazgos de Security Hub, logs de auditoría de EKS y logs de WAF, y de fuentes de terceros, los normaliza al Open Cybersecurity Schema Framework (OCSF) en Apache Parquet y los guarda en buckets de S3 en tu propia cuenta con reglas de lifecycle. Los suscriptores, como Athena, OpenSearch o un SIEM de un socio, obtienen acceso de consulta o a los datos. En el examen, 'normalizar a OCSF' y 'un data lake propio entre cuentas y herramientas de terceros' significan Security Lake.

Términos clave

CloudWatch Logs Insights
Lenguaje de consultas y consola para buscar y agregar datos en CloudWatch Logs.
Amazon Athena
Motor SQL serverless que consulta los datos donde están en S3 y cobra por datos escaneados.
OCSF
Open Cybersecurity Schema Framework, un esquema abierto y neutral para eventos de seguridad.
Amazon Security Lake
Servicio que recopila y normaliza datos de seguridad a OCSF en un data lake de S3 propiedad del cliente.
Ejemplo real

Una empresa guarda dos años de logs de CloudTrail en un bucket central. Para la alerta de anoche, los analistas usan Logs Insights sobre la copia en CloudWatch; para la pregunta de un auditor sobre un cambio de hace un año, ejecutan una consulta de Athena sobre particiones por fecha. Un SIEM nuevo se suscribe a Security Lake para leer datos normalizados de todas las cuentas.

Consejo para el examen: Relaciona el período y el formato con la herramienta: logs operativos recientes en CloudWatch, Logs Insights; archivos de largo plazo en S3, Athena; data lake normalizado entre fuentes, Security Lake; dashboards de búsqueda de texto completo, OpenSearch.

Comprueba lo que sabes

¿Cómo abaratas las consultas de Athena sobre años de logs de CloudTrail?

Particionando la tabla por fecha y cuenta y usando un formato columnar para que cada consulta escanee menos datos.

¿Dónde guarda Security Lake sus datos?

En buckets de S3 en tu propia cuenta, en formato OCSF como Apache Parquet.
