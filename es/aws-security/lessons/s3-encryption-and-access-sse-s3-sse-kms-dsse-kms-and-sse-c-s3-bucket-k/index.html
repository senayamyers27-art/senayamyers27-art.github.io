AWS Certified Security – Specialty SCS-C03

Cifrado y acceso en S3: SSE-S3, SSE-KMS, DSSE-KMS y SSE-C, S3 Bucket Keys, Block Public Access y Object Ownership

Amazon S3 guarda más datos sensibles que cualquier otro servicio de AWS en la mayoría de las empresas, así que sus controles de cifrado y acceso aparecen constantemente.

Todos los objetos nuevos se cifran en reposo por defecto. SSE-S3 usa claves administradas por completo por S3 y es el valor por defecto. SSE-KMS usa una clave de KMS, administrada por AWS o por el cliente; con una customer managed key controlas la key policy, puedes deshabilitar la clave y ves cada uso en CloudTrail. DSSE-KMS aplica dos capas independientes de cifrado para cargas cuyas reglas exigen protección de doble capa. SSE-C usa una clave que el cliente envía con cada solicitud por HTTPS; S3 la usa y luego la olvida, así que el cliente debe administrar las claves y no puede perderlas. El cifrado del lado del cliente, donde cifras antes de subir, es otra opción. El ajuste de cifrado por defecto del bucket aplica a los objetos nuevos que no especifican uno, y las bucket policies pueden exigir un tipo específico con la condición s3:x-amz-server-side-encryption.

SSE-KMS con tasas de solicitudes altas puede alcanzar las cuotas de solicitudes de KMS y aumentar los costos. S3 Bucket Keys resuelven esto: S3 obtiene de KMS una clave de corta duración a nivel de bucket y la usa para crear data keys para muchos objetos, lo que reduce mucho las llamadas a KMS. El encryption context pasa a usar el ARN del bucket en lugar del ARN del objeto, lo que importa para las condiciones de las key policies y las búsquedas en CloudTrail.

Los controles de acceso trabajan juntos. S3 Block Public Access tiene cuatro ajustes (bloquear e ignorar ACLs públicas, bloquear y restringir bucket policies públicas) a nivel de cuenta y de bucket, y está activado por defecto en los buckets nuevos. Object Ownership con bucket owner enforced deshabilita las ACLs, así que solo las políticas controlan el acceso y el dueño del bucket es dueño de cada objeto; es el valor por defecto en los buckets nuevos. Los access points dan políticas y controles de red separados por aplicación, y las presigned URLs dan acceso temporal a un objeto con los permisos de quien firma. Mantén las bucket policies con mínimo privilegio y revísalas con IAM Access Analyzer.

Términos clave

SSE-KMS
Cifrado del lado del servidor de S3 con una clave de AWS KMS, con control mediante key policy y registro en CloudTrail.
DSSE-KMS
Cifrado del lado del servidor de doble capa con claves de KMS, que aplica dos capas de cifrado a los objetos.
S3 Bucket Key
Clave a nivel de bucket que reduce las solicitudes y los costos de KMS con SSE-KMS.
Bucket owner enforced
Ajuste de Object Ownership que deshabilita las ACLs para que el dueño del bucket sea dueño de todos los objetos.
Ejemplo real

Una plataforma de datos guarda logs en un bucket con SSE-KMS usando una customer managed key y Bucket Keys activadas, lo que reduce los costos de KMS en más del 90 por ciento. Block Public Access está activo a nivel de cuenta, las ACLs están deshabilitadas y una bucket policy niega las cargas que no usan SSE-KMS con esa clave.

Consejo para el examen: Necesitas control y auditoría de la clave: SSE-KMS con una customer managed key. Necesitas menor costo de KMS a escala: Bucket Keys. El cliente debe tener la clave y AWS no debe guardarla: SSE-C.

Comprueba lo que sabes

¿Qué tipo de cifrado de S3 se aplica por defecto a los objetos nuevos?

SSE-S3.

¿Qué cambia en el encryption context de KMS cuando se activan las Bucket Keys?

Usa el ARN del bucket en lugar del ARN de cada objeto.
