AWS Certified Security – Specialty SCS-C03

Planes de respuesta a incidentes y runbooks en AWS: fases de respuesta, runbooks de Systems Manager Automation y OpsCenter

Un plan de respuesta a incidentes dice quién hace qué cuando algo sale mal. La mayoría de los marcos, incluidos NIST SP 800-61 y la AWS Security Incident Response Guide, usan fases similares: preparar; detectar y analizar; contener, erradicar y recuperar; y aprender del incidente. El plan nombra roles como el comandante del incidente y el responsable de comunicaciones, define niveles de severidad y lista contactos, incluido AWS Support y, si lo usas, el servicio AWS Security Incident Response, que puede clasificar hallazgos y conectarte con equipos de respuesta de AWS.

Un playbook cubre un tipo de incidente, como claves IAM expuestas, una instancia EC2 comprometida, un bucket de S3 público o ransomware sobre datos. Un runbook es el procedimiento paso a paso dentro de él. En la nube, los runbooks deben automatizarse lo más posible, porque las acciones mediante API son rápidas, consistentes y quedan registradas.

AWS Systems Manager Automation ejecuta runbooks escritos como documentos. AWS ofrece muchos ya hechos, como AWS-DisableS3BucketPublicReadWrite o runbooks para aislar una instancia, y puedes escribir los tuyos en YAML con pasos que llaman a APIs de AWS, ejecutan scripts, esperan aprobación o se ramifican según los resultados. Los runbooks de Automation pueden dispararse con reglas de EventBridge, con la remediación de AWS Config o por una persona, y pueden ejecutarse en varias cuentas y regiones. Systems Manager OpsCenter reúne los problemas operativos como OpsItems, los vincula con los recursos y runbooks relacionados y da a quienes responden un solo lugar para seguir y resolver un problema.

Los planes también deben cubrir a las personas y el trabajo forense. Algunos equipos usan notebooks de Jupyter, por ejemplo en Amazon SageMaker AI, para guardar consultas de investigación repetibles. Sin importar las herramientas, el examen valora los planes que están escritos, automatizados donde se puede, practicados y actualizados después de cada incidente.

Términos clave

Playbook
Plan para manejar un tipo de incidente, con su detección, puntos de decisión y runbooks.
Runbook
Procedimiento paso a paso, idealmente automatizado, para realizar una tarea de respuesta.
Systems Manager Automation
Servicio que ejecuta documentos de runbook con pasos que llaman a APIs de AWS y scripts, disparados manualmente o por eventos.
OpsCenter
Capacidad de Systems Manager que sigue los problemas operativos como OpsItems con recursos y runbooks relacionados.
Ejemplo real

Una empresa escribe un playbook para buckets de S3 públicos. Una regla de AWS Config detecta el problema, la remediación automática ejecuta AWS-DisableS3BucketPublicReadWrite, se crea un OpsItem con los detalles del bucket y el ingeniero de guardia revisa CloudTrail para ver quién hizo el cambio.

Consejo para el examen: Cuando una pregunta pide que una respuesta sea consistente y repetible, prefiere un runbook automatizado (Systems Manager Automation, Step Functions o Lambda) disparado por un evento antes que una lista de verificación manual.

¿Cuál es la diferencia entre un playbook y un runbook?

Un playbook cubre cómo manejar un tipo de incidente; un runbook es un procedimiento específico paso a paso que se usa dentro de él.
