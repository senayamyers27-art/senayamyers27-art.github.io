AWS Certified Security – Specialty SCS-C03

Manejo de evidencia forense: S3 Object Lock, cadena de custodia y etiquetado de evidencia

La evidencia puede terminar en un caso judicial, un reclamo al seguro o la revisión de un regulador. Solo es útil si puedes demostrar que se recopiló correctamente y que no se cambió después. De eso se trata el manejo forense.

Guarda la evidencia en una cuenta forense dedicada, en un bucket de S3 con versionado y S3 Object Lock. El modo compliance hace que cada versión de objeto sea de escritura única y lectura múltiple durante el período de retención, y nadie, ni siquiera el usuario root, puede eliminarla ni acortar el período. Los legal holds pueden mantener bloqueados objetos específicos sin fecha de fin hasta que se quiten. Cifra con una clave de KMS cuya política permita descifrar solo a los roles forenses, activa los data events de CloudTrail para el bucket para que cada acceso quede registrado y bloquea el acceso público.

Mantén una cadena de custodia: quién recopiló cada elemento, cuándo, de qué recurso, cómo se transfirió y quién accedió a él desde entonces. Calcula hashes, como SHA-256, al recopilar imágenes de memoria, exportaciones de logs o imágenes de disco, y regístralos, para poder demostrar después que el archivo no cambió. Etiqueta snapshots, volúmenes e instancias con el ID del incidente, quién recopiló y la hora, para que la evidencia sea fácil de encontrar y la automatización de limpieza no la elimine. Guarda copias de los datos relevantes de CloudTrail, flow logs y logs de aplicación del período del incidente, ya que las reglas de lifecycle normales podrían eliminarlos.

Trabaja sobre copias, no sobre originales. Crea volúmenes a partir de snapshots en la cuenta forense y asócialos en modo de solo lectura a una instancia de análisis aislada. Comparte los snapshots cifrados usando una customer managed key que la cuenta forense pueda usar, porque los snapshots cifrados con una AWS managed key no se pueden compartir entre cuentas.

Términos clave

Cadena de custodia
Registro de quién recopiló, transfirió, guardó y accedió a cada pieza de evidencia, y cuándo.
Legal hold
Ajuste de S3 Object Lock que impide eliminar una versión de objeto hasta que se quite, sin fecha fija de fin.
Hash
Huella de longitud fija de un archivo, como SHA-256, que se usa para demostrar que no cambió.
WORM
Write once, read many: almacenamiento que no se puede modificar ni eliminar después de escribirse.
Ejemplo real

Después de una brecha, el equipo copia las imágenes de memoria y los snapshots de EBS a la cuenta forense. El hash SHA-256 de cada archivo se anota en el registro del caso, los objetos se guardan con Object Lock en modo compliance durante siete años y el acceso requiere un rol forense cuyo uso queda registrado por los data events de CloudTrail.

Consejo para el examen: Los snapshots cifrados con la AWS managed key por defecto de EBS no se pueden compartir con otra cuenta. Para compartir evidencia, la respuesta incluye una customer managed key que la cuenta forense pueda usar, o volver a cifrar la copia.

Comprueba lo que sabes

¿Por qué registrar un hash al recopilar evidencia?

Permite demostrar después que la evidencia no cambió desde que se recopiló.

¿Cuál es la diferencia entre un período de retención de Object Lock y un legal hold?

Un período de retención tiene fecha de fin; un legal hold no la tiene y se mantiene hasta que se quita explícitamente.
