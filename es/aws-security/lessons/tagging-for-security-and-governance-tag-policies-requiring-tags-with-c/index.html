AWS Certified Security – Specialty SCS-C03

Etiquetado para seguridad y gobierno: tag policies, exigir etiquetas con condiciones y backup policies

Las etiquetas son rótulos clave-valor en los recursos. Para la seguridad hacen mucho más que informar costos: controlan permisos ABAC, la selección de backups, el dimensionamiento de incidentes y la clasificación de datos. Por eso tener etiquetas consistentes y confiables es un objetivo de gobierno.

Las tag policies de AWS Organizations estandarizan las etiquetas: definen las claves permitidas con su uso exacto de mayúsculas, los valores permitidos y qué tipos de recursos deben respetarlas. Puedes ver informes de cumplimiento y, para algunos tipos de recursos, puedes imponer la política para que crear o actualizar una etiqueta con un valor no conforme falle. Pero una tag policy por sí sola no exige que una etiqueta exista; los recursos se pueden seguir creando sin ninguna etiqueta.

Para exigir una etiqueta al crear, usa condiciones en IAM o en SCPs. Una sentencia deny para ec2:RunInstances con la condición "Null": {"aws:RequestTag/DataClassification": "true"} bloquea los lanzamientos sin esa etiqueta, y aws:TagKeys con ForAllValues limita qué claves de etiqueta se pueden poner. Protege las etiquetas que otorgan acceso: niega ec2:CreateTags y ec2:DeleteTags sobre las claves de proyecto o clasificación salvo a un rol de plataforma, o los usuarios podrían volver a etiquetar recursos para ganar acceso. Los controles proactivos de Control Tower y las reglas de CloudFormation Guard también pueden revisar las etiquetas antes del despliegue, y la regla de Config required-tags informa los recursos que no las tienen.

Las backup policies, otro tipo de política de administración de Organizations, definen de forma central los planes de AWS Backup: calendarios, retención, acciones de copia a otras cuentas o regiones y qué recursos se incluyen, normalmente seleccionados por etiqueta, como backup=daily. Se aplican a las cuentas automáticamente, así que cada base de datos etiquetada recibe backup sin configuración por cuenta. Juntas, las tag policies, las condiciones que exigen etiquetas y las backup policies hacen que las etiquetas sean lo bastante confiables para basar decisiones de seguridad en ellas.

Términos clave

Tag policy
Política de Organizations que estandariza claves y valores permitidos de etiquetas en todas las cuentas.
aws:RequestTag
Condition key para las etiquetas incluidas en una solicitud de creación o etiquetado.
aws:TagKeys
Condition key que lista las claves de etiqueta de una solicitud, usada para limitar qué claves se pueden poner.
Backup policy
Política de Organizations que despliega planes de AWS Backup en todas las cuentas, a menudo seleccionando recursos por etiqueta.
Ejemplo real

Una empresa aplica una tag policy que define DataClassification con los valores public, internal y confidential, una SCP que niega crear instancias EC2 y bases de datos RDS sin esa etiqueta, y una backup policy que hace backup diario de cada recurso etiquetado confidential con copias a una bóveda en la cuenta de backup.

Consejo para el examen: Las tag policies estandarizan, no exigen. Cuando una pregunta dice 'impedir la creación sin una etiqueta', la respuesta es una SCP o política IAM con una condición aws:RequestTag.

Comprueba lo que sabes

¿Por qué negar las acciones de etiquetado sobre etiquetas de control de acceso?

Porque si no, los usuarios podrían cambiar etiquetas para darse acceso mediante políticas ABAC.

¿Cómo suele elegir los recursos una backup policy?

Por etiquetas, como backup=daily, definidas en la selección de recursos de la política.
