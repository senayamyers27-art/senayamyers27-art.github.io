AWS Certified Security – Specialty SCS-C03

Estrategia multicuenta: AWS Organizations, unidades organizativas, landing zones de AWS Control Tower y cuentas de seguridad dedicadas

Una cuenta de AWS es el límite de aislamiento más fuerte que ofrece AWS: los recursos, IAM y las cuotas están separados por defecto. Por eso las organizaciones maduras usan muchas cuentas, agrupadas y gobernadas de forma central, en lugar de una sola cuenta con muchas cargas de trabajo.

AWS Organizations agrupa las cuentas bajo una cuenta de administración. Las cuentas se ubican en unidades organizativas (OUs), como Security, Infrastructure, Workloads (con hijas Prod y Non-prod), Sandbox, Suspended y Forensics, y las políticas asociadas a una OU aplican a cada cuenta dentro de ella. La cuenta de administración paga las facturas, crea cuentas y gestiona políticas; como las SCPs no la restringen, no debería ejecutar cargas de trabajo y muy pocas personas deberían usarla. Habilita el trusted access para los servicios y registra administradores delegados para que la mayor parte del trabajo ocurra en otro lugar.

Las cuentas de seguridad dedicadas son estándar. Una cuenta de log archive recibe los logs de CloudTrail, Config y otros de todas las cuentas en buckets que pocos pueden modificar. Una cuenta de herramientas de seguridad (audit) es el administrador delegado de GuardDuty, Security Hub, Inspector, Macie, Detective, la agregación de Config e IAM Access Analyzer, y tiene roles de lectura y de respuesta hacia las demás cuentas. Algunas organizaciones agregan una cuenta forense y una cuenta de red para la conectividad compartida y la inspección.

AWS Control Tower automatiza esto. Configura una landing zone con la OU Security, una cuenta de log archive y una de auditoría, un trail de CloudTrail y Config para la organización, IAM Identity Center y Account Factory para crear cuentas nuevas con una línea base estándar. Gestiona controles (guardrails) de tres tipos: controles preventivos implementados con SCPs y RCPs, controles detectivos implementados con reglas de Config y controles proactivos que revisan los recursos antes del despliegue con CloudFormation hooks. Control Tower muestra drift cuando alguien cambia la configuración por fuera de él. Account Factory for Terraform (AFT) y Customizations for Control Tower agregan tus propias líneas base.

Términos clave

Unidad organizativa
Grupo de cuentas en AWS Organizations al que se le pueden asociar políticas.
Landing zone
Línea base multicuenta bien diseñada con cuentas compartidas, registro, identidad y barreras.
Cuenta de log archive
Cuenta dedicada que guarda los logs de todas las cuentas con protecciones estrictas.
Control de Control Tower
Barrera preventiva, detectiva o proactiva gestionada por Control Tower.
Ejemplo real

Una startup que pasa de tres a 60 cuentas configura Control Tower. Los equipos nuevos piden cuentas mediante Account Factory, que las ubica en la OU Workloads con CloudTrail, Config, acceso por Identity Center y controles preventivos ya activos, mientras el equipo de seguridad trabaja solo desde la cuenta de auditoría.

Consejo para el examen: La cuenta de administración debería estar casi vacía y usarse muy poco. Las respuestas que ejecutan herramientas de seguridad o cargas de trabajo en la cuenta de administración suelen ser incorrectas cuando existe la opción de un administrador delegado.

Comprueba lo que sabes

¿Qué dos cuentas compartidas crea una landing zone de Control Tower?

Una cuenta de log archive y una cuenta de auditoría (herramientas de seguridad).

¿Cuáles son los tres tipos de controles de Control Tower?

Preventivos, detectivos y proactivos.
