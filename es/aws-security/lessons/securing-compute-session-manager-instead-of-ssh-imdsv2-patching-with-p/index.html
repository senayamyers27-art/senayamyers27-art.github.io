AWS Certified Security – Specialty SCS-C03

Proteger el cómputo: Session Manager en lugar de SSH, IMDSv2, parches con Patch Manager e imágenes endurecidas

La seguridad del cómputo en AWS consiste en reducir cómo llegan las personas y los atacantes a las instancias, proteger las credenciales que hay en ellas y mantener el software al día. Systems Manager ofrece la mayoría de las herramientas.

Session Manager da acceso interactivo de shell o PowerShell mediante el SSM Agent, que hace conexiones HTTPS salientes hacia Systems Manager. No se necesitan puertos de entrada, bastion hosts ni claves SSH. El acceso se controla con políticas IAM, las sesiones pueden registrarse en S3 y CloudWatch Logs y cifrarse con KMS, y hay reenvío de puertos. Las instancias necesitan el agente, un instance profile con la política AmazonSSMManagedInstanceCore y una ruta de red hacia Systems Manager, por internet o mediante interface endpoints. EC2 Instance Connect Endpoint es otra opción para SSH a instancias privadas sin IPs públicas.

El servicio de metadatos de la instancia (IMDS) en 169.254.169.254 entrega las credenciales temporales del rol de la instancia. IMDSv1 responde solicitudes GET simples, que las fallas de server-side request forgery (SSRF) pueden aprovechar. IMDSv2 exige un token de sesión obtenido con una solicitud PUT y enviado en un encabezado, lo que bloquea la mayoría de los ataques SSRF y de proxies abiertos, y un hop limit de 1 evita que los contenedores lleguen a él. Exige IMDSv2 en las plantillas de lanzamiento y en las instancias existentes, hazlo cumplir con la condición ec2:MetadataHttpTokens en SCPs, o fíjalo como valor por defecto de la cuenta o de la organización con declarative policies.

Patch Manager escanea e instala parches según un calendario usando patch baselines y maintenance windows, e informa el cumplimiento. Construye imágenes endurecidas con pipelines de EC2 Image Builder que aplican ajustes al estilo CIS, instalan agentes y ejecutan pruebas, para que cada instancia arranque desde un estado confiable. Trata las instancias como reemplazables: vuelve a desplegar desde una imagen nueva en lugar de cambiar servidores a mano. Para contenedores y Lambda, usa imágenes base mínimas, escanéalas y da a cada tarea o función su propio rol de mínimo privilegio.

Términos clave

Session Manager
Capacidad de Systems Manager que da acceso de shell auditado sin puertos de entrada abiertos ni claves SSH.
IMDSv2
Versión basada en tokens del servicio de metadatos de la instancia que protege las credenciales contra SSRF.
Patch baseline
Conjunto de reglas de Patch Manager que define qué parches están aprobados para instalarse.
EC2 Image Builder
Servicio que automatiza la construcción, el endurecimiento y las pruebas de imágenes de máquina.
Ejemplo real

Después de que una prueba de penetración encuentra una falla SSRF, una empresa exige IMDSv2 en todas las instancias con una declarative policy, elimina SSH de todos los security groups y pasa a los administradores a Session Manager con las sesiones registradas en un bucket de S3 cifrado. Las AMIs nuevas salen de un pipeline de Image Builder que se parcha cada semana.

Consejo para el examen: Sin puertos abiertos, sin claves, con sesiones auditadas: Session Manager. Proteger las credenciales del rol de la instancia contra SSRF: exigir IMDSv2.

Comprueba lo que sabes

¿Qué necesita una instancia administrada por Session Manager?

El SSM Agent, un instance profile con los permisos necesarios de Systems Manager y acceso de red a los endpoints de Systems Manager.

¿Por qué IMDSv2 detiene la mayoría de los ataques SSRF?

La solicitud falsificada del atacante no puede hacer el PUT con el encabezado especial necesario para obtener un token de sesión.
