AWS Certified Security – Specialty SCS-C03

Fuentes de logs para detección: VPC Flow Logs, query logs de Route 53 Resolver, server access logs de S3 y access logs de ELB y CloudFront

CloudTrail te informa sobre las llamadas a la API, pero muchos ataques aparecen primero en logs de red, de DNS o de solicitudes. Saber qué log responde qué pregunta es una habilidad clave para el examen, porque las respuestas a menudo solo difieren en la fuente de logs que nombran.

Los VPC Flow Logs capturan metadatos del tráfico IP en interfaces de red, subredes o VPCs completas: direcciones y puertos de origen y destino, protocolo, bytes, paquetes y si el tráfico fue ACCEPT o REJECT. Van a CloudWatch Logs, S3 o Amazon Data Firehose, y puedes agregar campos personalizados como flags TCP o los IDs de VPC y subred. Nunca contienen el contenido de los paquetes; para paquetes completos usas VPC Traffic Mirroring. Los query logs del Route 53 Resolver registran las consultas DNS que hacen los recursos de una VPC a través del Resolver, incluido el nombre consultado y la respuesta, y así detectas consultas a dominios maliciosos o de túneles.

Los server access logs de S3 registran las solicitudes hechas a un bucket y se entregan en modalidad de mejor esfuerzo a otro bucket. Los data events de CloudTrail para S3 suelen ser mejores para seguridad, porque se entregan de forma confiable e incluyen todos los detalles de identidad, pero los access logs pueden agregar campos como tiempos de solicitud y son gratuitos salvo el almacenamiento. Los access logs de Elastic Load Balancing registran cada solicitud a un Application o Network Load Balancer, incluida la IP del cliente, la ruta, el código de estado y detalles de TLS, y se entregan a S3. Los standard logs y real-time logs de CloudFront muestran solicitudes en el borde. Los logs de AWS WAF registran cada solicitud inspeccionada y qué regla coincidió.

Otras fuentes incluyen CloudWatch Logs desde el agente de CloudWatch en las instancias, los logs de auditoría del plano de control de EKS, los logs de bases de datos RDS y los logs de funciones Lambda. El patrón para las preguntas: conexiones de red y tráfico bloqueado, flow logs; nombres consultados, query logs del Resolver; solicitudes HTTP en el balanceador, access logs de ELB; qué regla bloqueó una solicitud web, logs de WAF; contenido de paquetes, Traffic Mirroring.

Términos clave

VPC Flow Logs
Registros de metadatos del tráfico IP en interfaces, subredes o VPCs, incluido ACCEPT o REJECT, sin contenido de paquetes.
Resolver query logging
Función que registra las consultas DNS que los recursos de una VPC hacen al Route 53 Resolver.
Server access logs de S3
Logs de mejor esfuerzo de las solicitudes hechas a un bucket de S3, entregados a otro bucket.
Traffic Mirroring
Función de VPC que copia los paquetes de red reales de una interfaz a un destino de monitoreo.
Ejemplo real

GuardDuty marca una instancia por exfiltración por DNS. El analista revisa los query logs del Resolver y ve miles de subdominios largos y aleatorios de un mismo dominio, y luego usa los flow logs para descubrir que la instancia también abrió conexiones a una IP inusual. Traffic Mirroring hacia un sensor captura el contenido para un análisis más profundo.

Consejo para el examen: Los flow logs muestran REJECT para el tráfico bloqueado por un security group o una network ACL, pero no cuál lo bloqueó, y nunca muestran nombres DNS ni contenido. Elige el log que realmente contiene el dato que pide la pregunta.

Comprueba lo que sabes

¿Qué log mostraría que una instancia consultó un dominio de malware conocido?

Los query logs del Route 53 Resolver.

¿Por qué los data events de CloudTrail para S3 suelen preferirse a los server access logs para seguridad?

Se entregan de forma confiable con todos los detalles de identidad de IAM, mientras que los access logs son de mejor esfuerzo.
