AWS Certified Security – Specialty SCS-C03

Responsabilidad compartida y revisiones de seguridad: el pilar de seguridad de Well-Architected, Trusted Advisor y modelado de amenazas

La seguridad en AWS es compartida. AWS es responsable de la seguridad de la nube: las instalaciones, el hardware, la red y la capa de virtualización, y en los servicios administrados también los sistemas operativos y el software de plataforma que ejecuta. Tú eres responsable de la seguridad en la nube: tus datos, identidades y accesos, la configuración de red, las opciones de cifrado y todo lo que instalas. La división se mueve según el servicio. En EC2 aplicas parches al sistema operativo invitado; en RDS AWS aplica parches al host y al software de base de datos, tú eliges cuándo aplicar las actualizaciones del motor y sigues controlando el acceso de red, los usuarios y el cifrado; en Lambda o S3 principalmente configuras el acceso y la protección de datos.

El pilar de seguridad del AWS Well-Architected Framework da principios de diseño: implementar una base de identidad fuerte, mantener la trazabilidad, aplicar seguridad en todas las capas, automatizar las buenas prácticas de seguridad, proteger los datos en tránsito y en reposo, mantener a las personas lejos de los datos y prepararse para eventos de seguridad. Sus áreas de buenas prácticas, fundamentos de seguridad, gestión de identidades y accesos, detección, protección de infraestructura, protección de datos, respuesta a incidentes y seguridad de aplicaciones, se corresponden de cerca con los dominios del examen. La Well-Architected Tool hace una revisión estructurada de una carga de trabajo y registra los riesgos y los planes de mejora.

AWS Trusted Advisor inspecciona tus cuentas y recomienda mejoras en costos, rendimiento, fiabilidad, límites de servicio, excelencia operativa y seguridad. Las verificaciones de seguridad incluyen puertos abiertos en security groups, MFA de root, access keys expuestas, permisos de buckets de S3 y uso de IAM; el conjunto completo de verificaciones requiere los planes de soporte Business, Enterprise On-Ramp o Enterprise. Trusted Advisor se puede ver para toda una organización y se integra con Security Hub.

El modelado de amenazas busca debilidades de diseño antes de construir. Dibuja los flujos de datos y los límites de confianza de una carga de trabajo, y luego pregunta qué puede salir mal, a menudo usando STRIDE (suplantación, manipulación, repudio, divulgación de información, denegación de servicio, elevación de privilegios), qué vas a hacer al respecto y si lo hiciste bien. Los resultados se convierten en requisitos: controles, logs y pruebas. Las revisiones deben repetirse cuando cambia la arquitectura.

Términos clave

Modelo de responsabilidad compartida
División de las tareas de seguridad entre AWS (de la nube) y el cliente (en la nube).
Pilar de seguridad
Sección del Well-Architected Framework con principios y buenas prácticas de seguridad.
Trusted Advisor
Servicio de AWS que revisa las cuentas y recomienda mejoras, incluidas verificaciones de seguridad.
STRIDE
Nemotécnico de modelado de amenazas: suplantación, manipulación, repudio, divulgación de información, denegación de servicio y elevación de privilegios.
Ejemplo real

Antes de lanzar un portal de reclamos nuevo, el equipo hace una sesión de modelado de amenazas y descubre que cualquier usuario de soporte podría leer los documentos subidos. Agrega ABAC en S3, escaneo con Macie y data events de CloudTrail, luego completa una revisión Well-Architected y corrige dos elementos de alto riesgo marcados por Trusted Advisor.

Consejo para el examen: En las preguntas de responsabilidad compartida, pregúntate si el cliente siquiera puede llegar al componente. Si no puedes iniciar sesión en él, como el sistema operativo del host de RDS o el hipervisor, es trabajo de AWS.

Comprueba lo que sabes

En Amazon EC2, ¿quién aplica parches al sistema operativo invitado?

El cliente.

¿Qué significa la 'R' de STRIDE, y qué función de AWS ayuda a abordarla?

Repudio (repudiation); el registro, como CloudTrail con validación de integridad, ayuda a demostrar quién hizo qué.
