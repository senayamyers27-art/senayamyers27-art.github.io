AWS Certified Security – Specialty SCS-C03

Secretos y certificados: rotación en Secrets Manager, SecureString de Parameter Store y AWS Private CA

Las aplicaciones necesitan contraseñas de bases de datos, claves de API y certificados. Ponerlos en el código, en AMIs o en variables de entorno provoca filtraciones. AWS ofrece almacenes administrados que cifran los secretos con KMS, controlan el acceso con IAM y registran cada lectura en CloudTrail.

AWS Secrets Manager guarda secretos y los rota. La rotación administrada maneja servicios compatibles como Amazon RDS y Aurora sin código propio, y la rotación basada en Lambda cubre todo lo demás, siguiendo los pasos de crear, establecer, probar y finalizar para que las aplicaciones nunca vean un secreto a medio rotar. Para RDS y Aurora también puedes dejar que RDS administre la contraseña del usuario maestro en Secrets Manager. Los secretos pueden tener políticas de recurso para el acceso entre cuentas, pueden replicarse a otras regiones para recuperación ante desastres y se cifran con una clave de KMS que eliges; para el acceso entre cuentas usa una customer managed key. Las aplicaciones llaman a GetSecretValue en tiempo de ejecución, a menudo con caché del lado del cliente.

Systems Manager Parameter Store guarda configuración y secretos como parámetros. Los parámetros SecureString se cifran con KMS. Los parámetros estándar son gratuitos; los avanzados agregan tamaños mayores y parameter policies como notificaciones de expiración. Parameter Store no tiene rotación integrada, así que sirve para valores de configuración y secretos que cambian poco o que rotas con tu propio proceso. Parameter Store también puede referenciar secretos de Secrets Manager.

AWS Private CA ejecuta una autoridad certificadora privada administrada para TLS interno, TLS mutuo, identidades de dispositivos e IAM Roles Anywhere. Puedes construir una jerarquía con una CA raíz y CAs subordinadas, emitir certificados mediante ACM (donde los certificados privados pueden renovarse automáticamente) o directamente, y publicar la revocación mediante CRLs u OCSP. Protege la CA con políticas IAM estrictas, porque cualquiera que pueda emitir certificados puede suplantar servicios. El modo de certificados de corta duración reduce el costo y la necesidad de revocación para certificados que duran solo días.

Términos clave

Rotación en Secrets Manager
Reemplazo automático del valor de un secreto según un calendario usando rotación administrada o basada en Lambda.
SecureString
Tipo de parámetro de Parameter Store cifrado con una clave de KMS.
AWS Private CA
Servicio administrado de autoridad certificadora privada para emitir certificados internos.
Lista de revocación de certificados
Lista firmada de certificados que una CA revocó antes de su vencimiento.
Ejemplo real

La contraseña de RDS de una aplicación vive en Secrets Manager con rotación administrada cada 30 días. La app la lee mediante el cliente con caché, así que la rotación no necesita volver a desplegar. Los microservicios internos usan TLS mutuo con certificados de AWS Private CA, y los feature flags están en Parameter Store como parámetros estándar.

Consejo para el examen: Rotación automática de credenciales de bases de datos: Secrets Manager. Configuración cifrada y barata sin rotación: SecureString de Parameter Store. Certificados internos: AWS Private CA.

Comprueba lo que sabes

¿Qué necesitas para compartir un secreto de Secrets Manager con otra cuenta?

Una política de recurso en el secreto que permita a esa cuenta y una customer managed key de KMS cuya política también la permita.

¿Parameter Store rota automáticamente los valores SecureString?

No. No tiene rotación integrada; necesitarías un proceso propio o Secrets Manager.
