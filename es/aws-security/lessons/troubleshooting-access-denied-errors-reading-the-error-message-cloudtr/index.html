AWS Certified Security – Specialty SCS-C03

Diagnóstico de errores de acceso denegado: leer el mensaje de error, CloudTrail, el IAM policy simulator y verificaciones entre cuentas

Los errores de acceso denegado son el problema de IAM más común, y el examen te da mensajes de error, políticas y escenarios para diagnosticar. Un enfoque tranquilo y paso a paso encuentra la causa rápido.

Empieza por el mensaje de error. Muchos servicios de AWS ahora dicen qué tipo de política causó la negación y si fue implícita o explícita: por ejemplo 'with an explicit deny in a service control policy', 'because no identity-based policy allows the action' o 'with an explicit deny in a resource-based policy'. Eso te lleva directo a la SCP, a la política de identidad o a la política del recurso. Los mensajes de autorización codificados de EC2 se pueden decodificar con aws sts decode-authorization-message.

Luego revisa CloudTrail. El evento de la llamada fallida muestra el principal exacto (usuario, rol y nombre de sesión), la acción, el recurso, la IP de origen y el código de error, AccessDenied o UnauthorizedOperation. A menudo la sorpresa es que la llamada la hizo un rol distinto del que esperabas, para otro recurso o en otra región. Confirma quién eres con aws sts get-caller-identity.

Después prueba. El IAM policy simulator evalúa las políticas de identidad, los boundaries, las SCPs y, de forma opcional, las políticas de recursos para un principal, una acción y un recurso, y muestra qué sentencia permitió o negó. Recuerda a los sospechosos habituales: un deny explícito en una SCP, RCP, boundary, session policy, bucket policy o key policy; una barrera sin allow para la acción; una condición que no coincide, como falta de MFA, VPC de origen equivocada o etiqueta equivocada; una key policy de KMS que no permite al principal cuando los datos están cifrados; y, en llamadas entre cuentas, un allow faltante en uno de los lados. Las ACLs de S3, los ajustes de Object Ownership y las endpoint policies de VPC también son causas ocultas frecuentes.

Términos clave

AccessDenied
Código de error que se devuelve cuando falla una verificación de autorización de una solicitud.
Policy simulator
Herramienta de IAM que evalúa políticas para un principal, una acción y un recurso y explica el resultado.
decode-authorization-message
Comando de STS que decodifica el motivo detallado de algunos errores de acceso denegado codificados.
get-caller-identity
Llamada de STS que devuelve la cuenta, el ARN y el ID de usuario de las credenciales en uso.
Ejemplo real

Una función Lambda recibe AccessDenied al leer un objeto de S3 aunque su rol permite s3:GetObject. CloudTrail muestra que la solicitud llegó por un VPC endpoint cuya política permite solo ciertos buckets, y el objeto está cifrado con una clave de KMS cuya política no incluye el rol. Corregir ambas cosas resuelve el error.

Consejo para el examen: Para datos cifrados, el acceso necesita permiso tanto sobre los datos (S3, EBS, RDS) como sobre la clave de KMS. Muchas preguntas de 'tengo s3:GetObject pero igual recibo AccessDenied' son en realidad preguntas de KMS o de endpoint policies.

Comprueba lo que sabes

Un error dice 'no identity-based policy allows the action'. ¿Dónde lo corriges?

Agregando un allow a la política basada en identidad del principal (o un allow adecuado en una política basada en recursos).

¿Qué comando confirma qué rol está usando realmente tu CLI?

aws sts get-caller-identity.
