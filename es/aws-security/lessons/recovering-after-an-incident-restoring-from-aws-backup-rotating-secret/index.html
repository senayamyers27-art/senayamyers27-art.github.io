AWS Certified Security – Specialty SCS-C03

Recuperarse después de un incidente: restaurar desde AWS Backup, rotar secretos y aplicar las lecciones aprendidas

La contención detiene el daño; la recuperación devuelve el negocio a la normalidad sin dejar que el atacante vuelva a entrar. La regla clave es reconstruir desde fuentes confiables en lugar de confiar en algo que el atacante tocó.

Reconstruye la capacidad de cómputo desde imágenes confiables y parchadas mediante infraestructura como código, en lugar de limpiar una instancia comprometida. Restaura los datos desde backups tomados antes del compromiso. AWS Backup centraliza los planes de backup entre servicios y cuentas, y las copias entre cuentas y entre regiones protegen contra un atacante que elimine los backups en la cuenta de origen. AWS Backup Vault Lock, sobre todo en modo compliance, impide que alguien elimine puntos de recuperación o acorte la retención, algo vital contra el ransomware. Las logically air-gapped vaults agregan otra capa al mantener los backups en una bóveda aislada que se puede compartir para la recuperación. Prueba las restauraciones con regularidad, porque un backup sin probar es solo una esperanza.

Rota todo lo que el atacante pudo ver: contraseñas de bases de datos y claves de API en Secrets Manager, access keys de IAM, claves privadas de TLS y cualquier token guardado en hosts comprometidos. Si una clave de KMS pudo usarse indebidamente, revisa su key policy y sus grants y considera volver a cifrar los datos con una clave nueva. Elimina toda la persistencia encontrada durante el dimensionamiento, incluidos usuarios, roles, trust policies, funciones Lambda y reglas programadas que creó el atacante.

Por último, haz una revisión posterior al incidente sin culpas. Arma una línea de tiempo, identifica la causa raíz y pregunta qué lo habría detectado o evitado antes. Convierte las respuestas en acciones concretas: nuevas reglas de Config o SCPs, planes de protección de GuardDuty, mejores alertas, runbooks actualizados y capacitación. Mide el tiempo para detectar, contener y recuperar, para que la próxima respuesta sea más rápida.

Términos clave

AWS Backup
Servicio que gestiona de forma central planes de backup y puntos de recuperación entre servicios y cuentas de AWS.
Backup Vault Lock
Ajuste que impone retención de escritura única en una bóveda de backup, impidiendo eliminar puntos de recuperación.
Causa raíz
La debilidad de fondo que permitió un incidente, a diferencia de sus síntomas.
Revisión posterior al incidente
Reunión sin culpas después de un incidente para documentar la línea de tiempo, las causas y las mejoras.
Ejemplo real

Un ransomware cifra archivos en un servidor de archivos basado en EC2. El equipo reconstruye el servidor desde una AMI dorada, restaura los datos desde un punto de recuperación de AWS Backup guardado en una bóveda bloqueada en otra cuenta, rota las contraseñas de las cuentas de servicio en Secrets Manager y agrega un plan de GuardDuty Malware Protection como lección aprendida.

Consejo para el examen: Las respuestas de recuperación restauran desde backups limpios y reconstruyen desde imágenes confiables; las que limpian y reutilizan el sistema comprometido son trampas. Para backups que ni los administradores puedan eliminar, busca Vault Lock en modo compliance.

Comprueba lo que sabes

¿Por qué copiar los backups a otra cuenta?

Para que un atacante que controla la cuenta de origen no pueda eliminarlos.

Después de contener una instancia cuyo rol podía leer un secreto de base de datos, ¿qué debes rotar?

El secreto de la base de datos, porque el atacante pudo haberlo leído.
