AWS Certified Security – Specialty SCS-C03

Descubrimiento y enmascaramiento de datos sensibles: Amazon Macie y data protection policies de CloudWatch Logs

No puedes proteger datos sensibles que no sabes que tienes. Los datos personales, los números de tarjeta y las credenciales suelen terminar en buckets y logs inesperados. Amazon Macie encuentra esos datos en S3, y la protección de datos de CloudWatch Logs los enmascara en los logs.

Amazon Macie evalúa continuamente la postura de seguridad de tus buckets de S3: cuáles son públicos, compartidos con otras cuentas, sin cifrar o replicados, y genera policy findings. Para el contenido, usa managed data identifiers, que detectan muchos tipos de datos como nombres, direcciones, números de pasaporte, datos bancarios, números de tarjeta de crédito y credenciales de muchos países, además de custom data identifiers que defines con expresiones regulares y palabras clave, y allow lists para ignorar valores de prueba conocidos. El descubrimiento automatizado de datos sensibles toma muestras de objetos de todo tu entorno cada día y arma un puntaje de sensibilidad para cada bucket, a un costo manejable. Los sensitive data discovery jobs escanean por completo los buckets elegidos, una vez o de forma programada, y generan sensitive data findings con la ubicación de las coincidencias. Los hallazgos van a EventBridge y a Security Hub. Con Organizations, un administrador delegado ejecuta Macie para todas las cuentas.

Las data protection policies de CloudWatch Logs auditan y enmascaran datos sensibles en los eventos de log al ingerirlos. Eliges managed data identifiers como direcciones de correo, direcciones IP, números de tarjeta de crédito o claves secretas de AWS, y los valores que coinciden se enmascaran en la consola y en los resultados de consultas. Los principales con el permiso logs:Unmask pueden ver los valores originales. Los hallazgos sobre datos detectados se pueden enviar a otro log group, a S3 o a Firehose. Esto reduce el riesgo de que ingenieros de soporte o herramientas de logs vean secretos que una aplicación registró por error.

El descubrimiento es un punto de partida. Una vez que Macie muestra dónde están los datos sensibles, aplica controles: cifrado con una customer managed key, bucket policies estrictas, Block Public Access, eliminación por lifecycle cuando los datos ya no se necesitan y alertas de prevención de pérdida de datos.

Términos clave

Managed data identifier
Patrón de detección integrado de Macie para un tipo de dato sensible.
Custom data identifier
Patrón definido por el usuario, como una expresión regular con palabras clave, para que Macie lo detecte.
Descubrimiento automatizado de datos sensibles
Muestreo de objetos de Macie en todos los buckets para estimar dónde hay datos sensibles.
logs:Unmask
Permiso que deja a un principal ver valores enmascarados por una data protection policy de CloudWatch Logs.
Ejemplo real

Después de una fusión, una empresa activa Macie mediante su administrador delegado. El descubrimiento automatizado marca un bucket olvidado lleno de pasaportes escaneados; un job dirigido lo confirma. El equipo cifra y restringe el bucket, y una data protection policy de CloudWatch Logs ahora enmascara los números de tarjeta que un servicio estaba registrando.

Consejo para el examen: Encontrar datos sensibles en S3: Macie. Encontrar amenazas: GuardDuty. Encontrar vulnerabilidades: Inspector. El examen suele mostrar los tres como opciones.
