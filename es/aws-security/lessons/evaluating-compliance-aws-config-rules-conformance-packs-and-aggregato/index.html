AWS Certified Security – Specialty SCS-C03

Evaluar el cumplimiento: reglas de AWS Config, conformance packs y aggregators

Cumplimiento significa demostrar que los recursos están configurados como dicen tus políticas, no una vez sino de forma continua. AWS Config es el servicio central para esto.

El recorder de Config captura configuration items de los tipos de recursos compatibles cada vez que cambian, construyendo un historial de cada recurso y sus relaciones. Eliges qué tipos registrar, lo que afecta el costo, y un delivery channel envía snapshots e historial a S3 y notificaciones a SNS. Con este historial puedes responder '¿cómo era este security group el martes pasado, y quién lo cambió?', vinculándolo con eventos de CloudTrail.

Las reglas de Config evalúan los recursos contra los ajustes deseados. Las reglas administradas por AWS cubren verificaciones comunes, como s3-bucket-public-read-prohibited, restricted-ssh, encrypted-volumes, iam-root-access-key-check, cloudtrail-enabled y rds-storage-encrypted. Las reglas personalizadas usan funciones Lambda o sintaxis de políticas Guard. Las reglas se ejecutan cuando cambia la configuración, de forma periódica o ambas, y pueden evaluar recursos de forma proactiva antes de crearlos. Cada recurso se marca COMPLIANT o NON_COMPLIANT, y las acciones de remediación con Systems Manager Automation pueden corregir problemas de forma manual o automática.

Los conformance packs agrupan reglas y acciones de remediación en un solo paquete, a menudo a partir de plantillas de ejemplo de AWS mapeadas a marcos como CIS, NIST, PCI DSS o HIPAA operational best practices, y se pueden desplegar en toda una organización desde la cuenta de administración o de administrador delegado. Un aggregator reúne datos de configuración y cumplimiento de muchas cuentas y regiones en una sola cuenta, para tener un solo dashboard y consultas avanzadas con sintaxis parecida a SQL. Security Hub se apoya en Config para sus verificaciones de estándares, y Audit Manager puede usar las evaluaciones de Config como evidencia. Recuerda que Config informa y remedia la configuración; no impide las llamadas a la API, que es trabajo de las SCPs, RCPs, declarative policies e IAM.

Términos clave

Configuration item
Registro en un momento dado de la configuración de un recurso capturado por AWS Config.
Regla de Config
Verificación que evalúa si los recursos cumplen una configuración deseada.
Conformance pack
Colección de reglas de Config y acciones de remediación desplegada e informada como una unidad.
Aggregator
Recurso de Config que reúne datos de configuración y cumplimiento de varias cuentas y regiones.
Ejemplo real

Una empresa de pagos despliega un conformance pack de PCI DSS operational best practices en todas las cuentas de su OU de datos de titulares de tarjetas. Un aggregator en la cuenta de seguridad muestra un 97 por ciento de cumplimiento, y la remediación automática cierra en minutos cualquier security group que abra SSH a internet.

Consejo para el examen: Controles detectivos que informan la configuración: reglas de Config. Un paquete de ellas en toda la organización: conformance packs. Una vista de todas las cuentas: aggregator. Bloquear la acción de entrada no es trabajo de Config.

Comprueba lo que sabes

¿Qué determina el costo del registro de AWS Config?

Principalmente la cantidad de configuration items registrados y de evaluaciones de reglas, que depende de los tipos de recursos y de cuán seguido cambian.

¿Cómo ves en un solo lugar el cumplimiento de Config de 50 cuentas?

Creando un aggregator en una cuenta central que cubra la organización.
