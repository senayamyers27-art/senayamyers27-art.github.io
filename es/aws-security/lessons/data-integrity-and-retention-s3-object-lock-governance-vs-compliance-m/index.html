AWS Certified Security – Specialty SCS-C03

Integridad y retención de datos: S3 Object Lock modo governance vs compliance, versionado, MFA Delete y AWS Backup Vault Lock

Algunos datos no deben cambiarse ni eliminarse: registros financieros, logs de auditoría, evidencia y backups. El ransomware y los empleados malintencionados apuntan justamente a estos, así que AWS ofrece controles de escritura única y lectura múltiple (WORM).

El versionado de S3 conserva cada versión de un objeto, así que las sobrescrituras y eliminaciones se pueden deshacer; una eliminación solo agrega un delete marker. Pero un usuario con privilegios aún puede eliminar versiones. MFA Delete exige el código MFA del usuario root para eliminar versiones de forma permanente o cambiar el estado del versionado, y solo root puede activarlo mediante la API o la CLI, lo que limita su practicidad.

S3 Object Lock agrega protección WORM real en buckets con versionado. Cada versión de objeto puede tener un período de retención en uno de dos modos. En modo governance, los usuarios con el permiso s3:BypassGovernanceRetention que envían el encabezado de bypass pueden eliminar la versión o acortar la retención, así que protege contra la mayoría de los usuarios y de los errores y deja una salida de emergencia. En modo compliance, nadie, incluido el usuario root, puede eliminar la versión bloqueada ni acortar su retención hasta que expire; solo se puede extender. Un legal hold es un bloqueo independiente de encendido y apagado sin fecha de fin. Se puede definir una retención por defecto en el bucket, y Object Lock se puede activar en buckets existentes. Object Lock fue evaluado para regulaciones como SEC 17a-4.

AWS Backup Vault Lock aplica la misma idea a los backups. En modo governance, los usuarios con los permisos adecuados pueden quitar el bloqueo. En modo compliance, después de un período de gracia (cooling-off) de al menos tres días, el bloqueo se vuelve inmutable: nadie puede eliminar puntos de recuperación antes de que termine su retención ni cambiar el bloqueo. Combina Vault Lock con copias de backup entre cuentas y, cuando convenga, logically air-gapped vaults, para que un atacante que toma la cuenta de producción no pueda destruir los backups.

Términos clave

Modo governance de Object Lock
Retención que la mayoría de los usuarios no puede anular, pero que pueden anular los principales con un permiso de bypass.
Modo compliance de Object Lock
Retención que nadie, ni siquiera root, puede acortar ni quitar hasta que expire.
Legal hold
Marca de Object Lock que impide la eliminación hasta que se quite, sin fecha de expiración.
Backup Vault Lock
Función de AWS Backup que impone retención WORM a los puntos de recuperación de una bóveda.
Ejemplo real

Un bróker guarda registros de operaciones en un bucket de S3 con Object Lock en modo compliance y una retención por defecto de siete años. Su bóveda de AWS Backup para bases de datos usa Vault Lock en modo compliance, con copias en una cuenta de backup separada, así que ni una credencial de administrador robada puede borrar el historial.

Consejo para el examen: La diferencia clave: governance se puede omitir con un permiso; compliance no lo puede omitir nadie, ni siquiera root. Si la pregunta dice 'incluido el usuario root', elige el modo compliance.

Comprueba lo que sabes

¿Qué permiso deja a un usuario eliminar un objeto bloqueado en modo governance?

s3:BypassGovernanceRetention, usado con el encabezado de bypass de governance.

¿Qué debe estar activado en un bucket antes de poder usar Object Lock?

El versionado.
