AWS Certified Security – Specialty SCS-C03

Cifrar almacenes de datos: cifrado por defecto de EBS, cifrado de RDS, Aurora y DynamoDB, y cifrar recursos existentes sin cifrar

La mayoría de los almacenes de datos de AWS cifran en reposo con KMS, pero los detalles de cuándo y cómo puedes activar el cifrado cambian, y esos detalles son los que evalúan las preguntas del examen.

Los volúmenes y snapshots de Amazon EBS, y los datos que se mueven entre la instancia y el volumen, se cifran cuando eliges una clave de KMS. El cifrado por defecto de EBS es un ajuste de la cuenta por región que cifra cada volumen nuevo y cada copia de snapshot con la clave por defecto o una elegida; no cambia los volúmenes existentes. Para cifrar un volumen existente, toma un snapshot, cópialo con el cifrado activado, crea un volumen a partir de la copia y haz el cambio. Los snapshots de volúmenes cifrados están cifrados, y los volúmenes creados a partir de ellos también.

El cifrado de Amazon RDS y Aurora se elige al crear el recurso y cubre el almacenamiento, los backups automáticos, los snapshots y las réplicas de lectura. No puedes activarlo en el lugar en una instancia existente sin cifrar. La ruta habitual es tomar un snapshot, copiarlo con cifrado y restaurar una instancia nueva cifrada, o migrar con AWS DMS para tener un tiempo de inactividad mínimo. Las réplicas de lectura entre regiones de bases de datos cifradas usan una clave en la región de destino. Transparent Data Encryption (TDE) está disponible para Oracle y SQL Server cuando se requiere.

Amazon DynamoDB siempre cifra las tablas en reposo; solo eliges entre una AWS owned key (por defecto), una AWS managed key o una customer managed key, y puedes cambiar entre ellas. El cifrado en reposo de Amazon EFS se elige al crear el sistema de archivos, y el cifrado en tránsito se configura con la opción TLS del mount helper. S3 cifra todos los objetos nuevos por defecto, y los objetos existentes sin cifrar se pueden volver a cifrar con S3 Batch Operations copiando los objetos sobre sí mismos. Usa reglas de AWS Config como encrypted-volumes y rds-storage-encrypted, condiciones en SCPs y controles de Security Hub para detectar y evitar recursos sin cifrar.

Términos clave

Cifrado por defecto de EBS
Ajuste de cuenta y región que cifra todos los volúmenes EBS nuevos y las copias de snapshots.
Copia de snapshot con cifrado
Método para crear una copia cifrada de datos de EBS o RDS sin cifrar.
Transparent Data Encryption
Cifrado del motor de base de datos para Oracle y SQL Server que cifra los archivos de datos.
S3 Batch Operations
Función que ejecuta una acción, como copiar con un nuevo cifrado, sobre muchos objetos de S3.
Ejemplo real

Una auditoría encuentra tres instancias de RDS y 50 volúmenes EBS sin cifrar. El equipo activa el cifrado por defecto de EBS en cada región, reemplaza los volúmenes mediante copias cifradas de snapshots y migra cada base de datos restaurando una copia cifrada del snapshot durante una ventana de mantenimiento. Una regla de Config ahora marca cualquier recurso nuevo sin cifrar.

Consejo para el examen: Ningún almacén de datos de AWS te deja pasar en el lugar un volumen EBS o una instancia RDS existentes de sin cifrar a cifrados. La respuesta casi siempre es snapshot, copia cifrada, restauración o volumen nuevo.

Comprueba lo que sabes

¿Activar el cifrado por defecto de EBS cifra los volúmenes existentes?

No. Solo afecta a los volúmenes y copias de snapshots creados después.

¿Las tablas de DynamoDB pueden estar sin cifrar?

No. DynamoDB siempre cifra en reposo; solo eliges qué tipo de clave se usa.
