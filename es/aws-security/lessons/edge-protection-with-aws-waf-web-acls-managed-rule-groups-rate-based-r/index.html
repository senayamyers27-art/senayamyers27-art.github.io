AWS Certified Security – Specialty SCS-C03

Protección en el borde con AWS WAF: web ACLs, managed rule groups, rate-based rules y amenazas del OWASP Top 10

AWS WAF es un firewall de aplicaciones web. Inspecciona las solicitudes HTTP y HTTPS antes de que lleguen a tu aplicación y las permite, bloquea, cuenta o desafía. Asocias una web ACL (web access control list) a un recurso protegido: una distribución de CloudFront, un Application Load Balancer, una REST API de API Gateway, una API GraphQL de AppSync, un user pool de Cognito, un servicio de App Runner o una instancia de Verified Access.

Una web ACL contiene reglas evaluadas por orden de prioridad, más una acción por defecto para las solicitudes que no coinciden con ninguna regla. Las reglas pueden comparar IP sets, países, encabezados, query strings, cuerpos, rutas URI, etiquetas puestas por reglas anteriores y patrones de inyección SQL y cross-site scripting. Cada web ACL tiene un límite de capacidad medido en web ACL capacity units (WCUs), porque las reglas complejas cuestan más. Los managed rule groups de AWS te dan protecciones mantenidas sin escribir reglas: el core rule set para ataques comunes del OWASP Top 10, known bad inputs, reglas para bases de datos SQL y para sistemas operativos específicos, la lista de reputación de IPs de Amazon, listas de IPs anónimas y grupos pagos como Bot Control, la prevención de toma de cuentas y la prevención de fraude en la creación de cuentas. Los vendedores del Marketplace también ofrecen rule groups.

Las rate-based rules cuentan las solicitudes de cada origen en una ventana de tiempo y bloquean o desafían a los orígenes que superan un límite. También pueden agregar por otras claves, como un encabezado, una cookie o un argumento de query, lo que ayuda contra el credential stuffing y el scraping. Las acciones CAPTCHA y challenge verifican que el cliente sea un navegador real.

Empieza las reglas nuevas en modo Count, observa los logs y las métricas, y luego cambia a Block, para no bloquear a clientes reales. Envía los logs de WAF a CloudWatch Logs, S3 o Firehose (el nombre del destino debe empezar con aws-waf-logs-) para ver qué regla coincidió con cada solicitud. Firewall Manager puede aplicar políticas de WAF en todas las cuentas de una organización. Recuerda que WAF protege solo el tráfico web de capa 7; no filtra SSH ni puertos de bases de datos.

Términos clave

Web ACL
Conjunto de reglas de AWS WAF y una acción por defecto asociado a un recurso web protegido.
Managed rule group
Conjunto de reglas de WAF mantenido por AWS o por un vendedor del Marketplace, como el core rule set.
Rate-based rule
Regla de WAF que bloquea o desafía a los orígenes cuyo número de solicitudes supera un límite en una ventana de tiempo.
Acción Count
Acción de WAF que registra las coincidencias sin bloquear, usada para probar reglas de forma segura.
Ejemplo real

Una tienda en línea recibe avalanchas de intentos de inicio de sesión. El equipo agrega una rate-based rule limitada a la ruta /login, el core rule set administrado por AWS y el rule group known bad inputs en modo Count, revisa los logs de WAF durante una semana y los cambia a Block. Luego una política de Firewall Manager aplica la misma web ACL a cada ALB de la organización.

Consejo para el examen: Inyección SQL, XSS, bots maliciosos e inundaciones HTTP apuntan a AWS WAF; un DDoS grande de capa de red apunta a Shield; el tráfico que no es HTTP apunta a security groups, network ACLs o Network Firewall.

Comprueba lo que sabes

¿A qué recursos se puede asociar una web ACL de AWS WAF?

CloudFront, ALB, REST APIs de API Gateway, AppSync, user pools de Cognito, App Runner y Verified Access.

¿Por qué desplegar primero las reglas nuevas de WAF en modo Count?

Para ver qué bloquearían con el tráfico real y evitar bloquear a usuarios legítimos antes de pasar a Block.
