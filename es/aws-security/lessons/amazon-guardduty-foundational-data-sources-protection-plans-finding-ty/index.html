AWS Certified Security – Specialty SCS-C03

Amazon GuardDuty: fuentes de datos fundamentales, planes de protección, tipos de hallazgos y un administrador delegado para la organización

Amazon GuardDuty es un servicio administrado de detección de amenazas. Analiza continuamente la actividad de tus cuentas con inteligencia de amenazas, detección de anomalías y aprendizaje automático, y genera hallazgos cuando algo parece malicioso, como una instancia que se comunica con un servidor de comando y control conocido, credenciales usadas desde una ubicación inusual o minado de criptomonedas.

Las fuentes de datos fundamentales de GuardDuty son los management events de CloudTrail, los VPC Flow Logs y los logs de consultas DNS del Route 53 Resolver. Las lee de sus propios flujos independientes, así que no necesitas activar ni guardar esos logs para que GuardDuty funcione, y hacerlo no cambia sus hallazgos. Los planes de protección opcionales amplían la cobertura: S3 Protection (data events de CloudTrail para S3), EKS Protection (logs de auditoría de Kubernetes), Runtime Monitoring (un agente que ve procesos y actividad de archivos en EC2, EKS y ECS), Malware Protection para volúmenes de EC2 y para objetos nuevos de S3, RDS Protection (actividad de inicio de sesión) y Lambda Protection (actividad de red de las funciones). GuardDuty también puede correlacionar varias señales en hallazgos de secuencia de ataque que describen un ataque de varias etapas.

Los tipos de hallazgos siguen un patrón: ThreatPurpose:ResourceType/ThreatFamily.Mechanism!Artifact, por ejemplo UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS o CryptoCurrency:EC2/BitcoinTool.B!DNS. Cada hallazgo tiene una severidad (baja, media, alta o crítica), el recurso afectado y detalles como la IP remota. Los hallazgos van a la consola, a EventBridge para automatización y a Security Hub. Puedes agregar trusted IP lists y threat lists, y crear suppression rules para hallazgos benignos conocidos.

En una organización, la cuenta de administración designa un administrador delegado, normalmente una cuenta de herramientas de seguridad. Esa cuenta puede habilitar GuardDuty y los planes de protección elegidos para todos los miembros existentes, activarlo automáticamente en las cuentas nuevas y ver los hallazgos de todos los miembros. GuardDuty es regional, así que lo habilitas en cada región que usas, incluidas las que no esperas usar, porque a los atacantes les gustan las regiones tranquilas.

Términos clave

Fuentes de datos fundamentales
Management events de CloudTrail, VPC Flow Logs y logs de DNS que GuardDuty analiza desde sus propios flujos.
Plan de protección
Función opcional de GuardDuty que agrega una fuente de datos o una capacidad de escaneo, como S3 Protection o Runtime Monitoring.
Suppression rule
Filtro que archiva automáticamente los hallazgos que cumplen criterios, usado para actividad benigna conocida.
Administrador delegado
Cuenta miembro a la que la cuenta de administración da permiso para gestionar un servicio en toda la organización.
Ejemplo real

Un equipo de seguridad designa su cuenta de herramientas como administrador delegado de GuardDuty y activa auto-enable con S3 Protection y Runtime Monitoring. Dos semanas después, un hallazgo muestra que la instancia de prueba de un desarrollador consulta el dominio de un pool de minado; una regla de EventBridge abre un ticket automáticamente.

Consejo para el examen: Si una respuesta dice que debes habilitar VPC Flow Logs o el registro de DNS antes de que GuardDuty pueda usarlos, es incorrecta. Recuerda también que GuardDuty detecta e informa; no bloquea tráfico por sí mismo.

Comprueba lo que sabes

¿Qué función de GuardDuty detectaría lecturas sospechosas de objetos de S3?

S3 Protection, que analiza los data events de CloudTrail para S3.

¿Cómo te aseguras de que las cuentas creadas el mes próximo tengan GuardDuty?

Con un administrador delegado con auto-enable para los nuevos miembros de la organización, en cada región.
