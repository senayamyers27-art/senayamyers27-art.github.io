AWS Certified Security – Specialty SCS-C03

Conectividad privada: gateway e interface VPC endpoints, endpoint policies, PrivateLink y segmentación con Transit Gateway

Muchas cargas de trabajo solo necesitan hablar con servicios de AWS y entre sí, no con internet. La conectividad privada mantiene ese tráfico en la red de AWS, elimina la necesidad de NAT e internet gateways y agrega lugares donde aplicar políticas.

Los gateway endpoints existen para Amazon S3 y DynamoDB. Se agregan como rutas en las tablas de rutas, no cuestan nada y mantienen el tráfico privado. Los interface endpoints, basados en AWS PrivateLink, colocan interfaces de red elásticas con direcciones IP privadas en tus subredes para la mayoría de los demás servicios de AWS, como KMS, Secrets Manager, STS y Systems Manager, y para servicios ofrecidos por otras cuentas o socios. Tienen security groups y, con private DNS, el nombre de host normal del servicio resuelve a las direcciones privadas. Se cobran por hora y por GB.

Las endpoint policies son políticas de estilo recurso en el endpoint que limitan lo que se puede hacer a través de él, por ejemplo permitir solo el acceso a los buckets de S3 propios de la empresa, lo que ayuda a evitar que se copien datos a un bucket de un atacante. Del otro lado, las políticas de recursos pueden exigir que las solicitudes lleguen por un endpoint o una red determinada: aws:SourceVpce para un endpoint específico, aws:SourceVpc para una VPC y aws:VpcSourceIp para una dirección privada. Un perímetro de datos común combina endpoint policies (recursos de confianza), políticas de recursos (redes e identidades de confianza, con aws:PrincipalOrgID) y SCPs o RCPs.

PrivateLink también te permite publicar tu propio servicio detrás de un Network Load Balancer para consumidores en otras VPCs o cuentas, sin peering ni problemas de CIDR superpuestos, y los consumidores solo pueden llegar a ese servicio. Transit Gateway conecta muchas VPCs y redes on-premises mediante un hub. Sus tablas de rutas te permiten segmentar el tráfico, por ejemplo mantener separadas las VPCs de producción y de desarrollo mientras ambas llegan a una VPC de servicios compartidos y a una VPC central de inspección.

Términos clave

Gateway endpoint
Endpoint gratuito basado en tablas de rutas para acceso privado a S3 o DynamoDB.
Interface endpoint
Interfaz de red elástica con IP privada que da acceso a un servicio mediante PrivateLink.
Endpoint policy
Política en un VPC endpoint que limita qué acciones y recursos se pueden alcanzar a través de él.
aws:SourceVpce
Condition key que contiene el ID del VPC endpoint por el que llegó una solicitud.
Ejemplo real

La VPC de analítica de un banco no tiene internet gateway. Llega a S3 por un gateway endpoint cuya política permite solo los buckets de la organización del banco, y llega a KMS y STS por interface endpoints. La bucket policy de datos niega cualquier solicitud que no llegue por el endpoint de la VPC de analítica.

Consejo para el examen: S3 o DynamoDB sin costo por hora: gateway endpoint. Otros servicios: interface endpoint. Restringir qué buckets se alcanzan desde la VPC: endpoint policy. Restringir desde qué red se alcanza un bucket: bucket policy con aws:SourceVpce.

Comprueba lo que sabes

¿Qué dos servicios admiten gateway endpoints?

Amazon S3 y Amazon DynamoDB.

¿Cómo evita PrivateLink los problemas de rangos CIDR superpuestos?

Los consumidores llegan al servicio mediante un endpoint en su propia VPC, así que no se necesita enrutamiento entre las VPCs.
