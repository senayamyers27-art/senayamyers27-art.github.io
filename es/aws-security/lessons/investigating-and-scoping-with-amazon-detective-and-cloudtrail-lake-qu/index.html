AWS Certified Security – Specialty SCS-C03

Investigar y dimensionar con Amazon Detective y consultas de CloudTrail Lake

Una vez confirmada una alerta, las siguientes preguntas son: ¿cómo empezó, qué más tocó el atacante y cuándo comenzó? Este dimensionamiento decide qué tan grande debe ser la respuesta.

Amazon Detective ayuda a responder esas preguntas de forma visual. Construye automáticamente un grafo de comportamiento a partir de management events de CloudTrail, VPC Flow Logs, hallazgos de GuardDuty y, de forma opcional, logs de auditoría de EKS y otras fuentes, y guarda hasta un año de historial. Para cualquier entidad, como un rol IAM, un usuario, una instancia EC2, una dirección IP o un bucket de S3, muestra la actividad en el tiempo, el comportamiento nuevo comparado con una línea base, los hallazgos relacionados y las otras entidades con las que interactuó. Desde un hallazgo de GuardDuty o Security Hub puedes saltar directamente a Detective. Detective agrupa hallazgos relacionados en finding groups, lo que te ayuda a ver un ataque como un todo en lugar de muchas alertas. Funciona mejor en toda una organización mediante un administrador delegado.

CloudTrail Lake responde preguntas precisas con SQL. Por ejemplo, listar cada llamada a la API hecha por un ID de access key en los últimos seis meses en todas las cuentas, cada llamada CreateAccessKey o AttachRolePolicy de un principal sospechoso, o todas las llamadas desde una dirección IP. Como el event data store es inmutable y puede abarcar una organización, también sirve como fuente de evidencia. Athena sobre archivos de CloudTrail en S3 puede hacer un trabajo parecido donde Lake no está configurado.

Un buen dimensionamiento también revisa qué podía hacer el principal, no solo qué hizo, revisando sus políticas y los hallazgos de IAM Access Analyzer, y usa los flow logs para encontrar movimiento lateral entre instancias. Valida cada hallazgo antes de actuar: los hallazgos de GuardDuty son señales, y Detective o las consultas de logs confirman si la actividad fue realmente maliciosa.

Términos clave

Grafo de comportamiento
Modelo de Detective que vincula entidades y su actividad, construido a partir de logs y hallazgos.
Finding group
Agrupación de Detective de hallazgos y entidades relacionadas que probablemente pertenecen a un mismo evento de seguridad.
Event data store
Almacén de eventos de CloudTrail Lake que se puede consultar con SQL.
Dimensionamiento
Determinar el alcance de un incidente: cuentas, recursos, datos y período afectados.
Ejemplo real

Desde un hallazgo de GuardDuty sobre llamadas inusuales a la API, el analista abre Detective y ve que el rol fue asumido desde una IP nueva dos días antes y se usó para listar buckets en tres cuentas. Luego una consulta de CloudTrail Lake lista cada llamada a nivel de objeto desde esa IP, lo que le dice al equipo exactamente qué datos pudieron leerse.

Consejo para el examen: Detective es para investigación visual y relaciones en el tiempo; CloudTrail Lake y Athena son para consultas exactas; GuardDuty lanza la alerta. Fíjate en el verbo de la pregunta: investigar y visualizar, consultar o detectar.

Comprueba lo que sabes

¿Qué servicio usarías para ver todas las entidades con las que interactuó una IP sospechosa durante dos semanas?

Amazon Detective.

¿Por qué CloudTrail Lake puede buscar en muchas cuentas a la vez?

Un event data store de organización reúne los eventos de todas las cuentas miembro en un solo almacén consultable.
