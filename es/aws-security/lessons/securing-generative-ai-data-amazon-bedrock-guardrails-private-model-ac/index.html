AWS Certified Security – Specialty SCS-C03

Proteger los datos de IA generativa: guardrails de Amazon Bedrock, acceso privado a modelos con VPC endpoints y registro de invocaciones

SCS-C03 agrega seguridad para cargas de IA generativa y aprendizaje automático. Los principios son los mismos que para cualquier carga de trabajo, mínimo privilegio, redes privadas, cifrado y registro, más controles nuevos sobre lo que entra y sale de un modelo.

Amazon Bedrock da acceso a modelos fundacionales mediante una API. Por diseño, tus prompts y respuestas no se usan para entrenar los modelos base ni se comparten con los proveedores de modelos, y los datos se cifran en tránsito y en reposo; puedes usar customer managed keys de KMS para recursos como modelos personalizados, knowledge bases y agentes. Controla quién puede llamar a qué modelos con IAM, usando acciones como bedrock:InvokeModel y ARNs de recursos para modelos específicos, y usa SCPs para bloquear modelos o regiones no aprobados en toda la organización.

Mantén el tráfico privado con interface VPC endpoints (PrivateLink) para Bedrock y endpoint policies que limiten qué modelos o acciones se pueden usar a través de ellos. Activa el registro de invocaciones del modelo para enviar prompts, respuestas y metadatos a CloudWatch Logs o S3 para auditoría y detección de abuso, y protege esos logs como datos sensibles, ya que pueden contener información personal. CloudTrail registra las llamadas a la API de Bedrock.

Amazon Bedrock Guardrails filtra entradas y salidas. Los content filters bloquean categorías dañinas y detectan ataques de prompt como jailbreaks y prompt injection. Los denied topics detienen conversaciones sobre los temas que elijas. Los word filters bloquean términos específicos. Los sensitive information filters detectan información de identificación personal y patrones regex personalizados y pueden bloquearlos o enmascararlos en prompts y respuestas. Las contextual grounding checks marcan respuestas que no están respaldadas por los datos de origen, y las automated reasoning checks pueden validar respuestas contra reglas. Para retrieval-augmented generation, protege las fuentes de datos de la knowledge base (por ejemplo S3 con roles de mínimo privilegio), porque el modelo puede revelar cualquier cosa que pueda recuperar. Un razonamiento similar aplica a SageMaker AI: aislamiento de red, notebooks solo en VPC, volúmenes cifrados y cifrado entre contenedores para el entrenamiento.

Términos clave

Bedrock Guardrails
Filtros configurables para prompts y respuestas, incluidos filtros de contenido, temas, palabras e información sensible.
Registro de invocaciones del modelo
Ajuste de Bedrock que registra prompts, respuestas y metadatos en CloudWatch Logs o S3.
Prompt injection
Ataque que esconde instrucciones en la entrada para que un modelo ignore sus reglas previstas.
Retrieval-augmented generation
Patrón en el que un modelo responde usando documentos recuperados de una knowledge base.
Ejemplo real

El chatbot de soporte de un banco en Bedrock funciona desde subredes privadas a través de un interface endpoint cuya política permite solo un modelo aprobado. Un guardrail enmascara los números de cuenta y bloquea el asesoramiento de inversiones como denied topic, y los logs de invocación van a un bucket de S3 cifrado que revisa el equipo de seguridad.

Consejo para el examen: Evitar que el modelo revele PII: Guardrails con sensitive information filters. Mantener el tráfico fuera de internet: interface VPC endpoint. Registrar qué se preguntó y respondió: registro de invocaciones. Limitar qué modelos se usan: IAM y SCPs.

Comprueba lo que sabes

¿Los prompts de Bedrock se usan para entrenar los modelos fundacionales subyacentes?

No. Bedrock no usa los prompts ni las respuestas de los clientes para entrenar los modelos base ni los comparte con los proveedores de modelos.

¿Qué función de Guardrails ayuda contra los intentos de jailbreak?

Los content filters con detección de ataques de prompt.
