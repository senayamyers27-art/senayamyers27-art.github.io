AWS Certified Security – Specialty SCS-C03

Identidad del personal: IAM Identity Center, permission sets, federación SAML 2.0, aprovisionamiento SCIM y MFA

La identidad del personal es cómo los empleados y contratistas inician sesión en AWS. El enfoque recomendado es un solo lugar central para las identidades, credenciales de corta duración y ningún usuario IAM para personas.

AWS IAM Identity Center (sucesor de AWS Single Sign-On) se habilita en la cuenta de administración, normalmente con un administrador delegado. Su fuente de identidad puede ser el directorio integrado de Identity Center, Active Directory (AWS Managed Microsoft AD o un AD propio mediante AD Connector) o un proveedor de identidad externo como Microsoft Entra ID, Okta o Google Workspace mediante SAML 2.0. Con un IdP externo, el aprovisionamiento SCIM (System for Cross-domain Identity Management) mantiene sincronizados usuarios y grupos automáticamente, así que cuando RR. HH. deshabilita a alguien en el IdP, pierde el acceso a AWS.

El acceso se define con permission sets: colecciones de políticas administradas por AWS, administradas por el cliente y en línea, un permissions boundary opcional y una duración de sesión. Cuando asignas un grupo y un permission set a una cuenta, Identity Center crea un rol IAM correspondiente (con el prefijo AWSReservedSSO) en esa cuenta. Los usuarios inician sesión en el portal de acceso de AWS, eligen una cuenta y un rol, y obtienen credenciales temporales para la consola o la CLI (aws configure sso). Los atributos del IdP se pueden pasar como session tags para ABAC.

Exige MFA en Identity Center o en el IdP, y prefiere métodos resistentes al phishing como llaves de seguridad FIDO2 y passkeys. Identity Center también puede dar inicio de sesión único a aplicaciones SAML y a aplicaciones administradas por AWS. La federación SAML directa de IAM por cuenta sigue funcionando, pero no escala a muchas cuentas y necesita proveedores de identidad y roles separados en cada una.

Términos clave

IAM Identity Center
Servicio de AWS para el inicio de sesión central del personal y el acceso a varias cuentas y aplicaciones.
Permission set
Plantilla de políticas que Identity Center convierte en roles en las cuentas asignadas.
SCIM
Estándar para crear y eliminar automáticamente usuarios y grupos entre sistemas.
SAML 2.0
Estándar basado en XML para intercambiar afirmaciones de autenticación entre un proveedor de identidad y un servicio.
Ejemplo real

Una empresa conecta Identity Center con su tenant de Okta mediante SAML y SCIM. El grupo Developers recibe un permission set PowerUser en las cuentas de desarrollo y ReadOnly en producción. Cuando un ingeniero se va, deshabilitarlo en Okta le quita en minutos el acceso a las 40 cuentas de AWS.

Consejo para el examen: Muchas cuentas más un IdP corporativo existente: IAM Identity Center con SAML y SCIM. Los usuarios IAM para personas, o configuraciones SAML por cuenta, suelen ser la respuesta incorrecta a escala.

Comprueba lo que sabes

¿Qué crea Identity Center en una cuenta cuando asignas un permission set?

Un rol IAM con las políticas del permission set, que los usuarios asumen desde el portal de acceso.

¿Qué agrega SCIM a la federación SAML?

La creación, actualización y eliminación automática de usuarios y grupos, para que los cambios en el IdP lleguen a AWS.
