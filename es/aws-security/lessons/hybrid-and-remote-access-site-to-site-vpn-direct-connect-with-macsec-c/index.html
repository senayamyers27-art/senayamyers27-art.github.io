AWS Certified Security – Specialty SCS-C03

Acceso híbrido y remoto: Site-to-Site VPN, Direct Connect con MACsec, Client VPN y Verified Access

Las cargas de trabajo rara vez viven solo en AWS. Oficinas, centros de datos y personal remoto necesitan acceso, y cada ruta debe estar cifrada y controlada.

AWS Site-to-Site VPN crea túneles IPsec por internet entre tu customer gateway y un virtual private gateway o un Transit Gateway. Cada conexión tiene dos túneles para redundancia, y el tráfico va cifrado. AWS Direct Connect ofrece un enlace de red privado y dedicado desde tus instalaciones hasta AWS, con rendimiento constante, pero no está cifrado por defecto. Para cifrarlo puedes ejecutar una Site-to-Site VPN sobre una public o transit virtual interface de Direct Connect, lo que da IPsec en capa 3, o usar MACsec, que cifra en capa 2 entre tu router y el dispositivo de AWS Direct Connect en conexiones dedicadas compatibles de mayor velocidad. Muchos diseños mantienen una VPN como ruta de respaldo de Direct Connect.

AWS Client VPN es un servicio administrado basado en OpenVPN para usuarios individuales. Autentica con Active Directory, federación SAML o autenticación mutua con certificados, y las reglas de autorización y los security groups limitan a qué redes puede llegar cada grupo. Los logs de conexión van a CloudWatch Logs.

AWS Verified Access sigue un modelo zero trust: en lugar de poner a los usuarios en una red, verifica cada solicitud a una aplicación según políticas que usan la identidad del usuario (de IAM Identity Center u otro proveedor OIDC) y la postura del dispositivo (de socios de gestión de dispositivos). Los usuarios llegan a aplicaciones web internas y, cada vez más, a aplicaciones que no son HTTP, sin VPN, y cada solicitud queda registrada. En el examen, 'sin VPN' más 'identidad y postura del dispositivo' significa Verified Access, mientras que 'conectar dos redes' significa Site-to-Site VPN o Direct Connect.

Términos clave

Site-to-Site VPN
VPN IPsec con dos túneles entre un gateway on-premises y AWS.
Direct Connect
Conexión de red privada y dedicada a AWS que no está cifrada por defecto.
MACsec
Cifrado de capa 2 IEEE 802.1AE disponible en conexiones dedicadas compatibles de Direct Connect.
Verified Access
Servicio zero trust que da acceso a aplicaciones por solicitud según la identidad y la postura del dispositivo.
Ejemplo real

Un minorista conecta su centro de datos con un Direct Connect de 10 Gbps usando MACsec, mantiene una Site-to-Site VPN como respaldo, da a los administradores Client VPN con inicio de sesión SAML y deja que el personal de las tiendas llegue a una aplicación web interna de inventario mediante Verified Access con verificación de postura del dispositivo.

Consejo para el examen: Direct Connect es privado pero no está cifrado. Cifrar sobre él significa MACsec (capa 2) o VPN sobre Direct Connect (IPsec, capa 3).

Comprueba lo que sabes

¿Cuántos túneles tiene cada conexión de Site-to-Site VPN?

Dos, para redundancia.

¿Qué dos señales pueden usar las políticas de Verified Access?

La identidad del usuario y la postura de seguridad del dispositivo.
