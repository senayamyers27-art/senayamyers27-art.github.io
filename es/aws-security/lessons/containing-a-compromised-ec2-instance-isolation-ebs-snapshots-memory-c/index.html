AWS Certified Security – Specialty SCS-C03

Contener una instancia EC2 comprometida: aislamiento, snapshots de EBS, captura de memoria y preservación de evidencia

Cuando una instancia EC2 está comprometida tienes dos objetivos que tiran en direcciones opuestas: detener el daño rápido y conservar la evidencia. Un buen runbook logra ambos en el orden correcto.

Primero protege la instancia de la automatización. Activa la protección contra terminación, etiquétala con un ID de incidente y quítala de su grupo de Auto Scaling (o ponla en standby) y de los target groups del balanceador, para que no sea reemplazada y eliminada ni atienda usuarios. Registra sus metadatos, como su ID, direcciones IP, security groups, rol IAM y AMI.

Después, aíslala. Reemplaza sus security groups por un grupo de aislamiento sin reglas de entrada ni de salida, o solo con una regla que permita tus herramientas forenses. Conoce el detalle: los security groups son stateful, y las conexiones que ya se están rastreando no se cortan al quitar reglas. La guía de AWS es aplicar primero un grupo que permita todo el tráfico desde 0.0.0.0/0, lo que hace que los flujos no sean rastreados, y luego cambiar al grupo de aislamiento, o agregar reglas deny en la network ACL de la subred, que son stateless y cortan el tráfico de inmediato. Considera también desasociar o restringir el rol IAM de la instancia y revocar sus sesiones.

Luego recopila evidencia. La memoria es volátil, así que captúrala primero desde la instancia en ejecución con una herramienta de adquisición de memoria, a menudo ejecutada mediante Systems Manager para no necesitar SSH. Después toma snapshots de todos los volúmenes EBS asociados y etiquétalos. No detengas, reinicies ni termines la instancia antes de capturar la memoria. Copia la evidencia a la cuenta forense, registra los hashes y un registro de cadena de custodia, y analiza los snapshots creando volúmenes asociados a una instancia forense allí. Solo después de la investigación terminas la instancia y despliegas una limpia desde una imagen confiable.

Términos clave

Security group de aislamiento
Security group sin reglas o con reglas mínimas que se usa para desconectar una instancia comprometida de la red.
Conexión rastreada
Flujo que un security group stateful recuerda y que sigue abierto aun después de quitar las reglas que lo permitían.
Captura de memoria
Obtener una copia de la RAM de un sistema en ejecución para preservar evidencia volátil.
Protección contra terminación
Ajuste de EC2 que impide terminar una instancia mediante la API o la consola hasta que se desactive.
Ejemplo real

Inspector y GuardDuty marcan un servidor web. El runbook en Step Functions activa la protección contra terminación, lo separa del grupo de Auto Scaling, aplica un grupo de aislamiento y un deny en la network ACL, ejecuta una captura de memoria mediante Systems Manager, toma snapshots de los volúmenes y los comparte con la cuenta forense.

Consejo para el examen: Cualquier respuesta que detenga o termine la instancia antes de capturar la memoria pierde evidencia. Y si la sesión de un atacante sobrevive a un cambio de security group, la explicación es el rastreo de conexiones; una network ACL lo resuelve.

Comprueba lo que sabes

¿Por qué quitar una instancia comprometida de su grupo de Auto Scaling?

Para que el grupo no la termine y la reemplace, destruyendo evidencia, y para que deje de recibir tráfico.

¿Cuál es el orden correcto: snapshot de EBS o captura de memoria?

Primero la captura de memoria, porque se pierde al detener o reiniciar; después los snapshots de los volúmenes.
