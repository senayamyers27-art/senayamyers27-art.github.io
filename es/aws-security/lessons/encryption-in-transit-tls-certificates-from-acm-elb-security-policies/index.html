AWS Certified Security – Specialty SCS-C03

Cifrado en tránsito: certificados TLS de ACM, security policies de ELB, exigir aws:SecureTransport y cifrado entre nodos

El cifrado en tránsito protege los datos mientras se mueven entre usuarios, servicios y nodos, para que no se puedan leer ni cambiar en la red. En AWS eso significa sobre todo Transport Layer Security (TLS), más funciones de cifrado integradas en servicios específicos.

AWS Certificate Manager (ACM) proporciona certificados TLS para servicios integrados como Elastic Load Balancing, CloudFront y API Gateway. Los certificados públicos se validan por DNS o por correo; los validados por DNS se renuevan automáticamente mientras el registro de validación siga en su lugar. Los certificados para CloudFront deben estar en us-east-1. ACM también importa certificados de terceros, pero esos no se renuevan automáticamente, así que monitorea su vencimiento con la métrica de días hasta la expiración o con reglas de AWS Config. Para servicios internos, AWS Private CA emite certificados privados.

Los balanceadores de carga terminan TLS o lo dejan pasar. En un listener TLS de un Application Load Balancer o Network Load Balancer, la security policy decide qué versiones de TLS y qué cifrados se permiten; elige una política que permita solo TLS 1.2 y 1.3, o una política FIPS o post-cuántica cuando se requiera. Redirige HTTP a HTTPS en el listener del ALB. Para cifrado de extremo a extremo, vuelve a cifrar hacia los destinos por HTTPS, o usa un listener TCP en un NLB para dejar pasar TLS sin tocarlo cuando el destino debe ver la conexión original o hacer TLS mutuo. Los ALBs también admiten TLS mutuo (mTLS) con un trust store.

Exige TLS con políticas. Una política de bucket, cola o tema puede negar cualquier solicitud donde aws:SecureTransport sea false. RDS y Aurora pueden exigir TLS con parámetros como rds.force_ssl. Dentro de los clústeres, activa el cifrado específico de cada servicio entre nodos: por ejemplo, security configurations de EMR con cifrado en tránsito, cifrado nodo a nodo en ElastiCache y OpenSearch, y cifrado entre contenedores en el entrenamiento de SageMaker AI. El tráfico entre instancias de muchos tipos modernos basados en Nitro también se cifra automáticamente a nivel de hardware dentro de una región.

Términos clave

ACM
AWS Certificate Manager, que aprovisiona, despliega y renueva certificados TLS para servicios de AWS.
Security policy de ELB
Conjunto predefinido de versiones del protocolo TLS y cifrados que acepta el listener de un balanceador.
aws:SecureTransport
Condition key que es true cuando una solicitud llega por TLS.
TLS mutuo
TLS en el que tanto el cliente como el servidor presentan certificados para autenticarse mutuamente.
Ejemplo real

Una API de salud debe usar solo TLS 1.2 o superior. El equipo elige una security policy TLS 1.2+ en el ALB, redirige el puerto 80 al 443, vuelve a cifrar hacia los destinos por HTTPS, agrega a los buckets de S3 un deny cuando aws:SecureTransport es false y activa el cifrado nodo a nodo en su dominio de OpenSearch.

Consejo para el examen: Para exigir TLS en S3, usa un Deny explícito cuando aws:SecureTransport es false; un Allow con true no basta porque otras sentencias podrían seguir permitiendo HTTP.

Comprueba lo que sabes

¿Qué certificados de ACM se renuevan automáticamente?

Los certificados emitidos por ACM validados por DNS (con el registro aún presente) y en uso; los importados no.

¿Por qué usar un listener TCP de NLB en lugar de un listener TLS?

Para dejar pasar el tráfico cifrado sin cambios hacia los destinos, por ejemplo cuando los destinos deben terminar TLS ellos mismos.
