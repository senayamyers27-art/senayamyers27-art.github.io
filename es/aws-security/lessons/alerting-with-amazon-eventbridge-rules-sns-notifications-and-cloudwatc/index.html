AWS Certified Security – Specialty SCS-C03

Alertas con reglas de Amazon EventBridge, notificaciones de SNS y metric filters de CloudWatch Logs

La detección se desperdicia si nadie se entera. AWS ofrece dos caminos principales desde un evento hasta una persona o una respuesta automatizada: reglas de EventBridge que reaccionan a eventos individuales, y metric filters de CloudWatch con alarmas que reaccionan a patrones y conteos.

Amazon EventBridge recibe eventos de los servicios de AWS en el event bus por defecto, incluidos hallazgos de GuardDuty, hallazgos de Security Hub, cambios de cumplimiento de Config, hallazgos de Inspector y, a través de CloudTrail, la mayoría de las llamadas a la API. Una regla tiene un event pattern, un documento JSON que compara campos como source, detail-type y valores dentro de detail, por ejemplo hallazgos de GuardDuty con severidad de al menos 7. Los destinos incluyen temas de SNS, funciones Lambda, máquinas de estados de Step Functions, colas de SQS, Systems Manager Automation y event buses de otras cuentas, que es como muchas empresas envían los hallazgos de todas las cuentas a una cuenta central de seguridad.

Amazon SNS entrega notificaciones por correo, SMS, endpoints HTTPS, Lambda o SQS, y a herramientas de chat mediante Amazon Q Developer in chat applications (antes AWS Chatbot). Protege los temas con una topic policy y cifrado, y recuerda que las suscripciones por correo deben confirmarse.

Los metric filters de CloudWatch Logs convierten datos de log en números. Si CloudTrail se entrega a un log group de CloudWatch Logs, un filtro puede contar eventos como { ($.errorCode = "AccessDenied") || ($.errorCode = "*UnauthorizedOperation") }, el uso de la cuenta root, inicios de sesión en la consola sin MFA o cambios en security groups y network ACLs. Una alarma de CloudWatch sobre esa métrica notifica a SNS cuando se cruza un umbral. Son las alarmas clásicas del benchmark CIS. Elige EventBridge cuando cada evento individual importa de inmediato, y un metric filter con alarma cuando te interesan los conteos en el tiempo.

Términos clave

Event pattern
Filtro JSON de una regla de EventBridge que selecciona qué eventos disparan sus destinos.
Metric filter
Patrón de CloudWatch Logs que convierte los eventos de log que coinciden en una métrica de CloudWatch.
Tema de SNS
Canal de publicación y suscripción que distribuye notificaciones a suscriptores como correo o Lambda.
Event bus entre cuentas
Event bus de EventBridge en otra cuenta que recibe eventos, usado para centralizar eventos de seguridad.
Ejemplo real

Cada cuenta miembro tiene una regla de EventBridge que reenvía los hallazgos de GuardDuty y Security Hub a un bus central en la cuenta de seguridad. Allí, una regla envía los hallazgos críticos a un tema de SNS para avisar a la guardia, y un metric filter de CloudWatch sobre el organization trail dispara una alarma cuando aparecen más de 20 errores AccessDenied en cinco minutos.

Consejo para el examen: Para 'alertar cuando X ocurra una vez, casi en tiempo real', elige una regla de EventBridge; para 'alertar cuando X ocurra más de N veces', elige un metric filter y una alarma. Una consulta programada casi nunca es la respuesta más rápida.

Comprueba lo que sabes

¿Qué debe existir antes de usar un metric filter sobre eventos de CloudTrail?

El trail debe entregar los eventos a un log group de CloudWatch Logs.

¿Cómo pueden llegar los hallazgos de 50 cuentas a la automatización de una cuenta de seguridad?

Con reglas de EventBridge en cada cuenta que envían los eventos a un event bus central en la cuenta de seguridad, o usando la vista de administrador delegado del servicio.
