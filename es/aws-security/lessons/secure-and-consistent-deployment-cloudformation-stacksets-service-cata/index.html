AWS Certified Security – Specialty SCS-C03

Despliegue seguro y consistente: CloudFormation StackSets, Service Catalog y escaneo de infraestructura como código

Los ajustes de seguridad aplicados a mano se desvían y se olvidan. La infraestructura como código (IaC) hace que las configuraciones seguras sean repetibles, revisables y comprobables, y el examen espera que conozcas las herramientas de AWS para desplegarla de forma segura a escala.

AWS CloudFormation despliega plantillas como stacks. Los StackSets despliegan la misma plantilla en muchas cuentas y regiones. Con permisos service-managed, los StackSets usan Organizations y pueden desplegar automáticamente en cada cuenta que se une a una OU destino, que es como las líneas base, como roles de respuesta a incidentes, reglas de Config o ajustes de registro, llegan a las cuentas nuevas. Las stack policies protegen los recursos críticos de actualizaciones, la protección contra terminación evita eliminaciones accidentales y la detección de drift muestra los recursos cambiados por fuera de CloudFormation. Despliega con un service role de CloudFormation para que los usuarios no necesiten permisos amplios.

AWS Service Catalog permite que un equipo central publique productos aprobados, como una base de datos cifrada o un stack web endurecido, en portfolios compartidos con cuentas o usuarios. Un launch constraint nombra un rol IAM que Service Catalog usa para crear los recursos, así que los usuarios finales pueden lanzar un producto sin tener los permisos subyacentes. Los template constraints limitan las opciones de parámetros, como los tipos de instancia permitidos.

Escanea las plantillas antes de desplegarlas. cfn-lint revisa la sintaxis y las buenas prácticas. AWS CloudFormation Guard (cfn-guard) evalúa las plantillas contra reglas de policy as code, por ejemplo que cada bucket de S3 bloquee el acceso público y cada volumen esté cifrado, y puede hacer fallar un pipeline de CI/CD. Los CloudFormation Hooks ejecutan verificaciones durante el despliegue y pueden bloquear recursos no conformes; los controles proactivos de Control Tower los usan. Los escáneres de código abierto cubren también Terraform y CDK. Escanea además el código en busca de secretos y revisa los cambios con pull requests, para que la revisión de seguridad sea parte de cada despliegue y no algo posterior.

Términos clave

StackSet
Función de CloudFormation que despliega una plantilla en varias cuentas y regiones.
Permisos service-managed
Modo de StackSets que usa Organizations y puede desplegar automáticamente en cuentas nuevas de las OUs destino.
Launch constraint
Ajuste de Service Catalog que asigna el rol IAM usado para lanzar un producto.
CloudFormation Guard
Herramienta de policy as code que valida plantillas contra reglas.
Ejemplo real

Un equipo de plataforma guarda todas las plantillas en Git. Los pull requests ejecutan cfn-lint y reglas de cfn-guard; los merges despliegan mediante un rol de pipeline. Un StackSet service-managed agrega la línea base de seguridad a cada cuenta nueva, y los desarrolladores lanzan bases de datos RDS aprobadas desde Service Catalog sin tener ellos mismos rds:CreateDBInstance.

Consejo para el examen: Todas las cuentas, incluidas las futuras: StackSets con permisos service-managed y despliegue automático. Dejar que los usuarios desplieguen sin permisos amplios: launch constraints de Service Catalog. Detectar problemas antes del despliegue: Guard o Hooks.

Comprueba lo que sabes

¿Qué informa la detección de drift?

Los recursos cuya configuración real difiere de lo que define el stack de CloudFormation.

¿Cómo puede un usuario de Service Catalog lanzar un producto que crea roles IAM sin tener iam:CreateRole?

El rol del launch constraint del producto tiene ese permiso y Service Catalog lo usa para crear los recursos.
