AWS Certified Security – Specialty SCS-C03

Identidad de aplicaciones y clientes: user pools vs identity pools de Amazon Cognito, y Amazon Verified Permissions

Las aplicaciones tienen sus propios usuarios: clientes de una tienda, usuarios de una app móvil, socios de un portal. Estas identidades no deberían ser usuarios IAM. Amazon Cognito y Amazon Verified Permissions se encargan de su autenticación y autorización.

Un user pool de Cognito es un directorio de usuarios y un servicio de inicio de sesión. Maneja el registro, el inicio de sesión, las políticas de contraseñas, la verificación de correo y teléfono, MFA, la recuperación de cuentas y la federación con proveedores sociales (como Google o Apple) y proveedores empresariales SAML u OIDC. Después del inicio de sesión emite JSON Web Tokens: un ID token sobre el usuario, un access token para tus APIs y un refresh token. API Gateway y los Application Load Balancers pueden validar estos tokens directamente. Las funciones de protección contra amenazas pueden detectar credenciales comprometidas y adaptar la autenticación según el riesgo.

Un identity pool de Cognito (identidades federadas) intercambia un token, de un user pool, un proveedor social, SAML u OIDC, por credenciales temporales de AWS asumiendo un rol IAM. Puedes asignar roles distintos a usuarios autenticados y no autenticados (invitados), elegir roles por reglas o por claims del token y usar etiquetas del principal para acceso detallado. Variables de política como ${cognito-identity.amazonaws.com:sub} pueden limitar a cada usuario a su propio prefijo de S3 o a sus ítems de DynamoDB. Recuerda: user pool es quién es el usuario; identity pool son credenciales de AWS.

Amazon Verified Permissions se encarga de la autorización detallada dentro de tu aplicación. Escribes políticas en Cedar, un lenguaje de políticas abierto, por ejemplo permitir a los editores actualizar documentos en carpetas que les pertenecen, las guardas en un policy store y llamas al servicio con un principal, una acción, un recurso y un contexto para obtener allow o deny. Se integra con los user pools de Cognito como fuente de identidad y se puede usar como authorizer de API Gateway. Mantener las reglas fuera del código las hace más fáciles de auditar y cambiar.

Términos clave

User pool
Directorio de usuarios de Cognito que autentica usuarios y emite tokens JWT.
Identity pool
Función de Cognito que intercambia tokens de identidad por credenciales temporales de AWS mediante roles IAM.
JWT
JSON Web Token, un token firmado que lleva afirmaciones sobre un usuario.
Cedar
Lenguaje de políticas abierto que usa Amazon Verified Permissions para la autorización de aplicaciones.
Ejemplo real

Una app de fotos usa un user pool de Cognito para iniciar sesión con Apple y Google. Su identity pool da a cada usuario autenticado credenciales temporales que permiten subir archivos solo a photos/${cognito-identity.amazonaws.com:sub}/. Las reglas para compartir, como quién puede ver un álbum, son políticas Cedar evaluadas por Verified Permissions.

Consejo para el examen: Inicio de sesión y tokens: user pool. Credenciales de AWS para usuarios de la app: identity pool. Reglas de negocio sobre quién puede hacer qué dentro de la app: Verified Permissions.

Comprueba lo que sabes

¿Un user pool por sí solo permite que una app móvil suba directamente a S3?

No. Emite JWTs; se necesita un identity pool para cambiarlos por credenciales de AWS.

¿Qué lenguaje usa Verified Permissions?

Cedar.
