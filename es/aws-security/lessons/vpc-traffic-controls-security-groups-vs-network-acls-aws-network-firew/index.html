AWS Certified Security – Specialty SCS-C03

Controles de tráfico en la VPC: security groups vs network ACLs, AWS Network Firewall y Route 53 Resolver DNS Firewall

Dentro de una VPC tienes varias capas de control de tráfico, cada una con una función distinta. Elegir la correcta es una tarea frecuente en el examen.

Los security groups se asocian a interfaces de red elásticas, como las de instancias EC2, bases de datos RDS y funciones Lambda en una VPC. Son stateful, así que el tráfico de retorno se permite automáticamente, y solo contienen reglas allow; todas las reglas se evalúan juntas. Una regla puede referenciar otro security group como origen, que es la forma más limpia de decir 'la base de datos acepta el 3306 solo desde la capa de aplicación'. Las network ACLs se asocian a subredes, son stateless, así que debes permitir el tráfico de retorno en puertos efímeros, y contienen reglas allow y deny numeradas que se evalúan en orden, donde gana la primera coincidencia. Usa network ACLs para bloqueos amplios a nivel de subred, como negar un rango CIDR hostil, y security groups para reglas precisas por carga de trabajo.

AWS Network Firewall es un firewall stateful administrado que despliegas en subredes dedicadas, enrutando el tráfico por sus endpoints con tablas de rutas. Admite reglas stateless, reglas stateful con firmas de prevención de intrusiones compatibles con Suricata, listas de dominios permitidos y denegados para HTTP y TLS (usando el SNI) e inspección de TLS. Normalmente se despliega en una VPC central de inspección conectada con Transit Gateway, para inspeccionar en un solo lugar todo el tráfico de salida y el tráfico este-oeste. Firewall Manager puede desplegarlo en varias cuentas.

Route 53 Resolver DNS Firewall filtra las consultas DNS que los recursos de una VPC envían al Route 53 Resolver. Los rule groups comparan listas de dominios, incluidas listas administradas por AWS de dominios de malware, botnets y amenazas, y pueden bloquear (con un NXDOMAIN o una respuesta personalizada), alertar o permitir. Es la herramienta correcta para frenar la exfiltración por DNS y las consultas a dominios maliciosos, sin importar qué direcciones IP usen esos dominios. Recuerda las capas: DNS Firewall para nombres, Network Firewall para inspección profunda y filtrado de tráfico por dominio, network ACLs para bloqueos por IP en la subred y security groups para reglas por carga de trabajo.

Términos clave

Security group
Firewall stateful y solo de allow asociado a interfaces de red.
Network ACL
Firewall stateless de subred con reglas allow y deny numeradas que se evalúan en orden.
AWS Network Firewall
Servicio administrado de firewall stateful y prevención de intrusiones desplegado en subredes de la VPC.
DNS Firewall
Función del Route 53 Resolver que bloquea o alerta sobre consultas DNS de dominios listados.
Ejemplo real

Una empresa enruta la salida de 30 VPCs por una VPC central de inspección con Network Firewall, permitiendo solo los dominios aprobados de actualizaciones de software y ejecutando reglas IPS. DNS Firewall bloquea dominios maliciosos conocidos, y las instancias de la aplicación aceptan tráfico de base de datos solo desde el security group de la capa de aplicación.

Consejo para el examen: Negar una IP específica: network ACL. Referenciar otra capa: security group. Filtrar por dominio o IPS sobre el tráfico: Network Firewall. Bloquear consultas DNS: DNS Firewall.

Comprueba lo que sabes

¿Por qué las network ACLs deben permitir puertos efímeros?

Son stateless, así que el tráfico de retorno al puerto efímero del cliente necesita su propia regla allow.

¿Cómo filtra Network Firewall el tráfico HTTPS por dominio sin descifrarlo?

Lee el Server Name Indication (SNI) en el handshake de TLS.
