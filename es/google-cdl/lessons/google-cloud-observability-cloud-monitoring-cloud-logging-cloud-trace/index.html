Google Cloud Observability: Cloud Monitoring, Cloud Logging, Cloud Trace y Error Reporting

No puedes operar un servicio confiable sin saber cómo se comporta. La observabilidad (observability) es la capacidad de entender el estado interno de un sistema a partir de los datos que produce, principalmente métricas, logs y trazas. Google Cloud Observability (antes conocido como Stackdriver y después como Cloud Operations suite) es un conjunto de servicios integrados para esto. Gran parte de los datos se recopila automáticamente de los servicios de Google Cloud, y los agentes o las bibliotecas recopilan más desde las VMs y las aplicaciones.

Cloud Monitoring recopila métricas: mediciones numéricas a lo largo del tiempo, como el uso de CPU, el número de solicitudes, la latencia y la tasa de errores, desde los servicios de Google Cloud, las aplicaciones, otras nubes y los sistemas on-premises. Puedes crear tableros, crear verificaciones de tiempo de actividad (uptime checks) que prueban si un endpoint responde desde ubicaciones de todo el mundo y definir políticas de alertas que notifican a las personas por correo electrónico, SMS, herramientas de chat o sistemas de gestión de incidentes cuando se cumplen ciertas condiciones. También admite definir SLOs y dar seguimiento a los presupuestos de error.

Cloud Logging recopila, almacena y te permite buscar entradas de log de los servicios de Google Cloud, las VMs, los contenedores y las aplicaciones, incluidos los Cloud Audit Logs. El Logs Explorer te permite filtrar y consultar los logs, las métricas basadas en logs convierten patrones de los logs en métricas para generar alertas, y los log sinks envían los logs a Cloud Storage, BigQuery o Pub/Sub para su retención a largo plazo o su análisis.

Cloud Trace es un sistema de rastreo distribuido. Sigue solicitudes individuales mientras viajan por distintos servicios, registrando cuánto tarda cada paso, lo que ayuda a encontrar el origen de la latencia en arquitecturas de microservicios. Error Reporting agrupa y cuenta los errores y las fallas de las aplicaciones para que los desarrolladores vean qué problemas son nuevos o más frecuentes. Cloud Profiler analiza el uso de CPU y memoria del código en ejecución para encontrar funciones ineficientes.

Juntas, estas herramientas apoyan las prácticas de SRE: medir SLIs, generar alertas sobre los síntomas que sienten los usuarios, investigar incidentes y mejorar el rendimiento. La distinción clave: las métricas te dicen que algo está mal, los logs te dicen qué pasó y las trazas muestran en qué se fue el tiempo de una solicitud.

Términos clave

Observability (observabilidad)
La capacidad de entender el estado interno de un sistema a partir de sus métricas, logs y trazas.
Cloud Monitoring
Recopila métricas y ofrece tableros, verificaciones de tiempo de actividad y alertas.
Cloud Logging
Recopila, almacena, busca y enruta datos de logs.
Cloud Trace
Rastreo distribuido que muestra cuánto tarda cada paso de una solicitud a través de los servicios.
Ejemplo real

Los clientes reportan que el proceso de pago es lento. Una alerta de Cloud Monitoring confirma que la latencia subió, Cloud Trace muestra que la mayor parte del retraso está en las llamadas al servicio de inventario y Cloud Logging revela errores repetidos de tiempo de espera en la conexión a la base de datos de ese servicio. El equipo corrige el pool de conexiones en menos de una hora.

Consejo para el examen: Métricas, tableros y alertas: Cloud Monitoring. Buscar y almacenar logs: Cloud Logging. Encontrar la latencia entre microservicios: Cloud Trace. Agrupar los errores de las aplicaciones: Error Reporting.

Comprueba lo que sabes

¿Qué herramienta mostraría qué microservicio está haciendo lenta una solicitud?

Cloud Trace.

¿Cómo puedes conservar logs durante años por cumplimiento y a bajo costo?

Enviándolos con un log sink a Cloud Storage (por ejemplo, en una clase de almacenamiento más fría) o a BigQuery para su análisis.
