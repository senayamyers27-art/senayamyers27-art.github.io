Bases de datos, data warehouses y data lakes: para qué sirve cada uno

Tres tipos de almacén de datos aparecen una y otra vez en el examen. No son rivales; la mayoría de las organizaciones usan los tres para tareas distintas.

Una base de datos (database) está diseñada para dar soporte a aplicaciones con muchas lecturas y escrituras pequeñas y rápidas de datos actuales. Esto se llama procesamiento de transacciones en línea (OLTP, online transaction processing): hacer un pedido, actualizar el saldo de una cuenta, guardar un perfil de usuario. Las bases de datos relacionales (Cloud SQL, AlloyDB, Spanner) usan tablas y SQL y garantizan la consistencia mediante transacciones. Las bases de datos no relacionales o NoSQL (Firestore, Bigtable) usan otros modelos, como documentos o columnas anchas, para lograr flexibilidad o una escala masiva.

Un data warehouse (almacén de datos analítico) está diseñado para el análisis. Reúne datos limpios y estructurados de muchas fuentes, a menudo incluidos datos históricos, y está optimizado para consultas complejas que recorren grandes cantidades de datos, lo que se conoce como procesamiento analítico en línea (OLAP, online analytical processing). Preguntas como '¿Cuáles fueron las ventas por región y producto en los últimos cinco años?' corresponden a un warehouse. BigQuery es el data warehouse serverless de Google Cloud.

Un data lake (lago de datos) almacena grandes volúmenes de datos sin procesar en su formato original, estructurados, semiestructurados y no estructurados, a bajo costo y a escala. Los datos se guardan primero y se les da estructura después, cuando se usan (esquema en la lectura, schema on read). Los data lakes apoyan la ciencia de datos, el aprendizaje automático y usos futuros que todavía no se conocen. En Google Cloud, Cloud Storage es la base habitual de un data lake.

Los enfoques se superponen cada vez más. Un lakehouse combina el almacenamiento abierto y de bajo costo de un lake con la gobernanza y el rendimiento SQL de un warehouse. En Google Cloud, BigQuery puede consultar datos almacenados en Cloud Storage en formatos abiertos, y las herramientas de gobernanza pueden administrar ambos a la vez.

Para elegir, pregúntate para qué son los datos. Para ejecutar una aplicación: base de datos. Para analizar datos limpios en reportes y tableros: warehouse. Para guardar grandes cantidades de datos sin procesar de muchos tipos para procesarlos después y para ML: lake.

Términos clave

Database (OLTP, base de datos)
Un almacén optimizado para muchas transacciones pequeñas y rápidas que hacen funcionar una aplicación.
Data warehouse (OLAP)
Un almacén optimizado para consultas analíticas sobre grandes cantidades de datos estructurados e históricos.
Data lake (lago de datos)
Un repositorio de datos sin procesar de cualquier tipo, guardados en su formato original para procesarlos más tarde.
Lakehouse
Un enfoque que combina el almacenamiento de un data lake con la administración y la analítica SQL al estilo de un warehouse.
Ejemplo real

La aplicación de reservaciones de una aerolínea escribe cada reservación en una base de datos relacional. Cada noche las reservaciones se cargan en BigQuery, donde los analistas estudian rutas y precios. Los archivos sin procesar de los sensores de vuelo y las fotos de mantenimiento se guardan en un data lake en Cloud Storage para que los ingenieros los usen en proyectos de aprendizaje automático.

Consejo para el examen: Si el escenario trata de las transacciones diarias de una aplicación, elige una base de datos. Si trata de análisis y reportes a partir de varias fuentes, elige un warehouse (BigQuery). Si trata de almacenar a bajo costo datos sin procesar de tipos mixtos, elige un lake (Cloud Storage).

Comprueba lo que sabes

¿Qué almacén es el mejor para analizar cinco años de ventas provenientes de muchos sistemas?

Un data warehouse como BigQuery.

¿Qué significa 'esquema en la lectura' (schema on read) en un data lake?

Los datos se guardan sin procesar, y la estructura se aplica solo cuando alguien los lee y los procesa.
