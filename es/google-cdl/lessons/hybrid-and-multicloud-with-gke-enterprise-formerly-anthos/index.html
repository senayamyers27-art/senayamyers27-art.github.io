Nube híbrida y multinube con GKE Enterprise (antes Anthos)

Muchas organizaciones ejecutan aplicaciones en varios entornos: sus propios centros de datos, Google Cloud, otras nubes públicas y ubicaciones en el borde (edge), como tiendas o fábricas. Pueden hacerlo por regulación, latencia, inversiones existentes, fusiones o para evitar depender de un solo proveedor. El desafío es que cada entorno tiene sus propias herramientas, configuraciones de seguridad y procesos de operación, así que los equipos dedican tiempo a lidiar con la inconsistencia en lugar de generar valor.

Los contenedores y Kubernetes ofrecen una base común, porque las mismas imágenes de contenedor y los mismos conceptos de Kubernetes funcionan en todas partes. Pero ejecutar muchos clústeres en muchos lugares sigue requiriendo administración centralizada. GKE Enterprise, la evolución de lo que antes se llamaba Anthos, es la plataforma de Google Cloud para administrar flotas (fleets) de clústeres de Kubernetes en Google Cloud, en centros de datos on-premises (sobre VMware o bare metal), en otras nubes públicas y en sitios del borde.

Con GKE Enterprise, un equipo de plataforma puede ver y administrar todos los clústeres desde la consola de Google Cloud como una flota, aplicar políticas de configuración y seguridad de forma consistente desde un repositorio Git central (para que todos los clústeres tengan la misma configuración), administrar la seguridad y el tráfico entre servicios con una malla de servicios (service mesh), y usar las mismas herramientas de observabilidad e implementación en todas partes. Los desarrolladores obtienen una forma única y consistente de construir e implementar sin importar dónde se ejecute la aplicación.

Esto apoya varias estrategias. Una empresa puede modernizar primero sus aplicaciones en contenedores on-premises y moverlas después a la nube con pocos cambios. Puede ejecutar cargas de trabajo donde los datos deben permanecer, como en una planta de fabricación, y administrarlas de forma centralizada. Puede usar más de una nube sin duplicar sus herramientas operativas.

Otras funciones de Google Cloud también apoyan la nube híbrida y la multinube, como Cloud Interconnect y Cloud VPN para la conectividad privada, y BigQuery Omni para analizar datos en otras nubes. Para el examen, la frase 'administración consistente de aplicaciones en on-premises y en varias nubes' apunta a GKE Enterprise.

Términos clave

GKE Enterprise
La plataforma de Google Cloud para administrar clústeres de Kubernetes en Google Cloud, on-premises, otras nubes y el borde (antes Anthos).
Fleet (flota)
Un grupo lógico de clústeres de Kubernetes que se administran juntos.
Service mesh (malla de servicios)
Una capa que administra la comunicación segura, el tráfico y la observabilidad entre servicios.
Policy as code (políticas como código)
Definir políticas de configuración y seguridad en archivos con control de versiones que se aplican automáticamente.
Ejemplo real

Un fabricante global ejecuta clústeres de Kubernetes en cada fábrica para sistemas de control de baja latencia, en Google Cloud para la analítica y en otra nube que llegó con una subsidiaria adquirida. Con GKE Enterprise, un solo equipo de plataforma aplica las mismas políticas de seguridad a todos los clústeres desde un único repositorio Git.

Consejo para el examen: La administración, las políticas y la seguridad consistentes en on-premises, Google Cloud y otras nubes corresponden a GKE Enterprise. El nombre anterior, Anthos, todavía puede aparecer en materiales de estudio.

Comprueba lo que sabes

¿Qué problema resuelve GKE Enterprise?

La administración inconsistente entre entornos; administra clústeres de Kubernetes y políticas de forma consistente en Google Cloud, on-premises, otras nubes y el borde.

¿Por qué los contenedores son una buena base para la nube híbrida y la multinube?

Las mismas imágenes de contenedor y los mismos conceptos de Kubernetes funcionan en todos los entornos, lo que hace portables las cargas de trabajo.
