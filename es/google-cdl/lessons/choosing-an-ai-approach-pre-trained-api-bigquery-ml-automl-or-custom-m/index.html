Elegir un enfoque de IA: API preentrenada, BigQuery ML, AutoML o modelo personalizado

Google Cloud ofrece varias formas de agregar IA, y el examen pregunta con frecuencia cuál conviene a un escenario. La elección equilibra cuatro cosas: qué tan común o único es el problema, los datos que tienes, las habilidades del equipo y qué tan rápido necesitas resultados.

Las APIs preentrenadas, como Vision, Natural Language, Speech-to-Text y Translation, y los modelos generativos listos para usar no necesitan ningún entrenamiento. Elígelos cuando la tarea es común (leer texto en imágenes, traducir, transcribir, detectar sentimiento) y el equipo quiere resultados de inmediato sin experiencia en ML. La contrapartida es una personalización limitada.

BigQuery ML conviene para datos de negocio estructurados que ya están en BigQuery, cuando los analistas saben SQL. Las tareas típicas son pronósticos, clasificación como la predicción de abandono y segmentación de clientes. Evita mover los datos y no requiere nuevas habilidades de programación.

AutoML en Vertex AI conviene para problemas específicos de tu negocio, como reconocer tus propios productos o clasificar tus propios documentos, cuando tienes datos etiquetados pero poca experiencia en ML. Produce un modelo personalizado con mucho menos esfuerzo que escribir tu propio código de entrenamiento.

El entrenamiento personalizado en Vertex AI conviene para problemas únicos, complejos o estratégicamente importantes donde necesitas control total, y tienes científicos de datos y tiempo. Ofrece la mayor flexibilidad y el mayor potencial de diferenciación, al costo más alto en habilidad y esfuerzo.

Una forma útil de pensarlo es como una escalera de esfuerzo. Empieza con la opción más sencilla que cubra la necesidad y sube solo cuando no alcance. Una empresa podría empezar con la Translation API, pasar a adaptar las traducciones con su propio glosario y construir un modelo personalizado solo si el caso de negocio lo justifica. Para la IA generativa hay una escalera parecida: dar prompts a un modelo fundacional, fundamentarlo (grounding) en los datos de la empresa, ajustarlo (tuning) y, solo en raras ocasiones, entrenar un modelo desde cero. Considera también comprar una solución terminada, como un producto de IA para centros de contacto, en lugar de construirla.

Términos clave

Build vs buy (construir o comprar)
Decidir si desarrollar una solución internamente o usar un producto o servicio existente.
Customization (personalización)
Qué tanto se puede adaptar un modelo a los datos y necesidades específicos de una organización.
Time to value (tiempo para obtener valor)
Qué tan rápido un enfoque empieza a dar resultados de negocio.
Tuning (ajuste)
Adaptar un modelo preentrenado o fundacional con ejemplos adicionales para una tarea específica.
Ejemplo real

Un minorista usa la Translation API para traducir su sitio web, BigQuery ML para pronosticar la demanda semanal a partir de tablas de ventas, AutoML para reconocer sus propios productos en fotos de anaqueles y un modelo personalizado construido por su equipo de ciencia de datos para su motor central de precios.

Consejo para el examen: Lee las pistas: 'sin experiencia en ML, tarea común' es una API preentrenada; 'analistas de SQL, datos en BigQuery' es BigQuery ML; 'datos etiquetados propios, poca experiencia' es AutoML; 'único, control total, científicos de datos' es entrenamiento personalizado.

Comprueba lo que sabes

Un equipo de analistas de SQL quiere segmentar a los clientes usando datos en BigQuery. ¿Qué enfoque conviene?

BigQuery ML, usando un modelo de clustering creado con SQL.

¿Por qué empezar con la opción de IA más sencilla que cubra la necesidad?

Da valor más rápido con el menor costo y la menor habilidad; las opciones más complejas solo se justifican cuando las más sencillas no pueden cumplir el requisito.
