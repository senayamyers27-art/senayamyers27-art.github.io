Elegir el cómputo para una carga de trabajo: VMs vs. contenedores vs. serverless

Google Cloud te ofrece un espectro de opciones de cómputo. En un extremo, controlas todo y administras todo; en el otro, no administras casi nada pero aceptas las convenciones de la plataforma. El examen con frecuencia da la descripción de una carga de trabajo y pregunta qué opción encaja, así que ayuda tener un proceso de decisión claro.

Elige máquinas virtuales en Compute Engine cuando necesites control total sobre el sistema operativo, el kernel o el software instalado; cuando hagas lift and shift de una aplicación existente sin cambios; cuando el licenciamiento del software lo exija; o cuando la carga de trabajo necesite configuraciones de hardware específicas. La contrapartida es que tú parchas, aseguras y escalas el sistema operativo, aunque los grupos de instancias administrados ayudan.

Elige contenedores en GKE cuando tengas aplicaciones en contenedores que se beneficien de Kubernetes: muchos microservicios que cooperan, estrategias complejas de red o de implementación, cargas de trabajo con estado, o el deseo de portabilidad entre nubes y on-premises usando el estándar de Kubernetes. GKE Autopilot elimina la administración de nodos, pero sigues trabajando con conceptos de Kubernetes.

Elige serverless cuando quieras el menor trabajo operativo. Cloud Run es una opción predeterminada sólida para aplicaciones web, APIs y trabajos sin estado en contenedores, sobre todo con tráfico variable o con picos, porque escala a cero. Cloud Run functions conviene para tareas pequeñas impulsadas por eventos. App Engine conviene para aplicaciones web basadas en código.

Considera también las opciones especializadas: Google Cloud VMware Engine para los entornos VMware existentes, y Bare Metal Solution para las cargas de trabajo que necesitan servidores físicos dedicados.

Una regla práctica es usar la opción más administrada que cumpla los requisitos. Que Google administre más significa menos trabajo que no te diferencia y, a menudo, menor costo con tráfico variable, lo que deja a los equipos libres para enfocarse en las funciones. Muévete hacia las VMs solo cuando necesites el control que dan. Muchas organizaciones usan las tres: VMs para sistemas heredados, GKE para plataformas complejas y Cloud Run para servicios nuevos.

Términos clave

Compute spectrum (espectro de cómputo)
El rango que va desde las VMs de IaaS (mayor control) hasta serverless (menor administración).
Stateless (sin estado)
Una aplicación que no guarda datos de sesión localmente, de modo que cualquier instancia puede atender cualquier solicitud.
Operational overhead (carga operativa)
El trabajo necesario para ejecutar, parchar, escalar y asegurar la infraestructura.
Portability (portabilidad)
La capacidad de ejecutar la misma carga de trabajo en distintos entornos.
Ejemplo real

Una empresa que moderniza tres sistemas mantiene su ERP con licencia en VMs de Compute Engine, mueve su plataforma de pedidos de 30 servicios a GKE Autopilot y construye una nueva API para socios en Cloud Run porque el tráfico es impredecible y el equipo es pequeño.

Consejo para el examen: Usa el servicio más administrado que cubra la necesidad. Control total del sistema operativo o aplicación heredada sin cambios: Compute Engine. Funciones de Kubernetes y portabilidad: GKE. Sin estado, con picos y con operación mínima: Cloud Run.

Da dos razones para elegir Compute Engine en lugar de serverless.

Necesidad de control total del sistema operativo, un lift and shift sin cambios, requisitos de licenciamiento o configuraciones de hardware especiales (dos cualesquiera).
