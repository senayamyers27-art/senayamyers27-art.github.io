Bases de datos relacionales en Google Cloud: Cloud SQL, AlloyDB y Spanner

Las bases de datos relacionales almacenan datos en tablas de filas y columnas con relaciones definidas, usan SQL y admiten transacciones que mantienen los datos consistentes: o se aplica todo el cambio o no se aplica nada. Hacen funcionar la mayoría de las aplicaciones de negocio, desde tiendas en línea hasta la banca. Google Cloud ofrece tres servicios relacionales administrados principales, y el examen te pide elegir entre ellos.

Cloud SQL es un servicio completamente administrado para MySQL, PostgreSQL y SQL Server. Google se encarga del aprovisionamiento, los parches, los respaldos, la replicación y la conmutación por error (failover), así que los equipos dejan de dedicar tiempo a la administración rutinaria de bases de datos. Es el destino natural cuando mueves la base de datos de una aplicación existente a la nube con pocos cambios (un replatform). Cloud SQL escala bien para la mayoría de las cargas de trabajo regionales, principalmente pasando a máquinas más grandes (escalado vertical) y agregando réplicas de lectura.

AlloyDB for PostgreSQL es una base de datos completamente administrada y compatible con PostgreSQL, diseñada para cargas de trabajo exigentes. Busca un alto rendimiento para el trabajo transaccional y consultas analíticas rápidas sobre los mismos datos. Conviene a organizaciones que quieren compatibilidad con PostgreSQL pero necesitan más rendimiento del que ofrece una instancia estándar de PostgreSQL administrado.

Spanner es una base de datos relacional completamente administrada que escala horizontalmente, agregando capacidad al sumar nodos, mientras mantiene una consistencia fuerte. Puede abarcar varias regiones y está construida para una disponibilidad muy alta. Admite SQL y transacciones como una base de datos tradicional, pero a una escala global que normalmente requeriría particionar (sharding) a mano. Los usos típicos son sistemas financieros globales, inventarios, videojuegos y cualquier aplicación que haya superado la capacidad de un solo servidor de base de datos.

Una forma sencilla de elegir: una aplicación existente en MySQL, PostgreSQL o SQL Server con escala normal, elige Cloud SQL. Aplicaciones PostgreSQL que necesitan mayor rendimiento o un trabajo mixto transaccional y analítico, considera AlloyDB. Datos relacionales que deben escalar horizontalmente o atender a usuarios en todo el mundo con consistencia fuerte, elige Spanner. Database Migration Service ayuda a mover bases de datos existentes a Cloud SQL y AlloyDB.

Términos clave

Relational database (base de datos relacional)
Una base de datos que almacena datos en tablas relacionadas y usa SQL y transacciones.
Cloud SQL
Bases de datos administradas MySQL, PostgreSQL y SQL Server.
AlloyDB
Una base de datos administrada, de alto rendimiento y compatible con PostgreSQL.
Spanner
Una base de datos relacional con escalado horizontal y consistencia fuerte que puede abarcar varias regiones.
Ejemplo real

Una tienda en línea regional mueve su base de datos MySQL a Cloud SQL y deja de preocuparse por los respaldos y los parches. Años después, tras expandirse a tres continentes, mueve su sistema de pedidos a Spanner para que los pedidos de todas las regiones se escriban en una sola base de datos consistente sin sharding manual.

Consejo para el examen: Palabras clave: 'MySQL/PostgreSQL/SQL Server existente, cambios mínimos' significa Cloud SQL; 'global, escala horizontal, consistencia fuerte' significa Spanner; 'compatible con PostgreSQL, alto rendimiento' significa AlloyDB.

Comprueba lo que sabes

¿Qué servicio relacional conviene a una aplicación distribuida globalmente que necesita consistencia fuerte?

Spanner.

¿Qué motores de base de datos admite Cloud SQL?

MySQL, PostgreSQL y SQL Server.
