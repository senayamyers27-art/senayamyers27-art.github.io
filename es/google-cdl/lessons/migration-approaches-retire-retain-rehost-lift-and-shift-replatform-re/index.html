Enfoques de migración: retirar, retener, rehospedar (lift and shift), replataformar, refactorizar y reimaginar

Cuando las organizaciones planean una migración a la nube, eligen un enfoque para cada aplicación. La industria a menudo los describe como las 'R'. La capacitación de Google Cloud usa términos como lift and shift (levantar y mover), move and improve (mover y mejorar) y refactor o rebuild (refactorizar o reconstruir); el examen espera que relaciones cada enfoque con una situación y entiendas el equilibrio entre velocidad y beneficio.

Retirar (retire) significa apagar una aplicación que ya no se necesita. Las evaluaciones a menudo encuentran sistemas sin uso o duplicados; retirarlos ahorra dinero y reduce el tamaño de la migración. Retener (retain) significa dejar una aplicación donde está por ahora, por ejemplo debido a una inversión reciente en hardware, una regulación o una dependencia que no está lista para moverse.

Rehospedar (rehost), o lift and shift, mueve una aplicación a la nube tal como está, normalmente de servidores on-premises a VMs de Compute Engine, sin cambios en el código. Es el enfoque más rápido y es común cuando hay que cerrar un centro de datos pronto. Da algunos beneficios, como no tener hardware que administrar, pero pocos beneficios nativos de la nube. Herramientas como Migrate to Virtual Machines ayudan a automatizarlo.

Replataformar (replatform), o move and improve, hace cambios puntuales para obtener beneficios de la nube sin rediseñar la arquitectura. Algunos ejemplos son mover una base de datos autoadministrada a Cloud SQL, o empaquetar una aplicación en un contenedor para ejecutarla en GKE. Equilibra el esfuerzo y el beneficio.

Refactorizar (refactor), o rediseñar la arquitectura (re-architect), cambia el código y el diseño de la aplicación, por ejemplo dividiendo un monolito en microservicios o haciéndola serverless. Requiere el mayor esfuerzo pero da la mayor agilidad, escalabilidad y eficiencia de costos. Reimaginar (reimagine), o reconstruir (rebuild), va más allá al rediseñar el propio proceso de negocio o producto, a menudo reemplazando por completo la aplicación antigua, a veces con un producto SaaS (recomprar, repurchase).

La mayoría de las organizaciones usan varios enfoques a la vez. Un camino común es rehospedar rápidamente para salir de un centro de datos y luego modernizar con el tiempo las aplicaciones más importantes.

Términos clave

Rehost (lift and shift, rehospedar)
Mover una aplicación a la nube sin cambiarla, normalmente a VMs.
Replatform (move and improve, replataformar)
Hacer cambios puntuales durante la migración, como adoptar una base de datos administrada.
Refactor (refactorizar)
Cambiar el código y la arquitectura de una aplicación para que sea nativa de la nube.
Retire (retirar)
Dar de baja una aplicación que ya no se necesita en lugar de migrarla.
Ejemplo real

Una aseguradora debe salir de su centro de datos en seis meses. Retira 15 aplicaciones sin uso, rehospeda 60 en Compute Engine, replataforma su base de datos de pólizas a Cloud SQL, retiene un mainframe por ahora y planea refactorizar su portal de clientes en microservicios durante el próximo año.

Consejo para el examen: Fecha límite y sin tiempo para cambios: rehospedar. Cambios pequeños para usar servicios administrados: replataformar. Reescribir para obtener beneficios nativos de la nube: refactorizar. Sin uso: retirar. Todavía no se mueve: retener.

Comprueba lo que sabes

¿Qué enfoque es el más rápido pero da la menor cantidad de beneficios nativos de la nube?

Rehospedar (lift and shift).

Una aplicación se mueve a Compute Engine y su base de datos a Cloud SQL sin cambios en el código. ¿Qué enfoque es?

Replataformar (move and improve).
