Máquinas virtuales con Compute Engine: tipos de máquina, grupos de instancias administrados y escalado automático

Compute Engine es la oferta de infraestructura como servicio (IaaS) de Google Cloud para máquinas virtuales (VMs). Una VM se comporta como un servidor físico: eliges una imagen de sistema operativo (Linux o Windows), un tipo de máquina y discos, y tienes control total sobre el software instalado. Compute Engine es el destino habitual de las migraciones lift and shift y de las cargas de trabajo que necesitan un sistema operativo específico, ajustes del kernel o software con licencia.

Los tipos de máquina (machine types) definen cuánta CPU virtual (vCPU) y memoria tiene una VM. Google Cloud los organiza en familias: de propósito general para la mayoría de las cargas de trabajo, optimizadas para cómputo para trabajo intensivo en CPU, optimizadas para memoria para bases de datos grandes en memoria, y optimizadas para aceleradores con GPUs para ML y gráficos. Si ningún tipo predefinido encaja, los tipos de máquina personalizados te permiten elegir el número exacto de vCPUs y la cantidad de memoria, lo que evita pagar por recursos que no necesitas. Puedes conectar discos persistentes, que conservan los datos independientemente de la VM, en varios niveles de rendimiento.

Una sola VM es un punto único de falla y no puede crecer para cubrir la demanda. Los grupos de instancias administrados (MIGs, managed instance groups) resuelven esto. Defines una plantilla de instancia (instance template), que describe la configuración de la VM, y el MIG crea y administra un grupo de VMs idénticas a partir de ella. Los MIGs ofrecen escalado automático (autoscaling), agregando VMs cuando sube la carga (por ejemplo, según el uso de CPU o las solicitudes por segundo) y quitándolas cuando baja. Ofrecen autorreparación (autohealing), recreando las VMs que no pasan una verificación de estado. Admiten actualizaciones graduales (rolling updates) para implementar una plantilla nueva poco a poco. Un MIG regional distribuye las VMs entre zonas para lograr mayor disponibilidad.

Los MIGs normalmente se colocan detrás de un balanceador de carga de Cloud Load Balancing, que distribuye el tráfico entre las VMs sanas, y puede ser global para que los usuarios lleguen a la región más cercana.

Compute Engine cobra por segundo de uso en la mayoría de las VMs y ofrece formas de reducir el costo, como los descuentos por uso continuo, los descuentos por compromiso de uso y las Spot VMs, que se cubren en la sección de operaciones. El nivel gratuito incluye una VM pequeña e2-micro en algunas regiones de EE. UU., suficiente para un primer laboratorio.

Términos clave

Compute Engine
El servicio IaaS de Google Cloud para ejecutar máquinas virtuales.
Machine type (tipo de máquina)
La configuración de vCPU y memoria de una VM, predefinida o personalizada.
Managed instance group (MIG, grupo de instancias administrado)
Un grupo de VMs idénticas creadas a partir de una plantilla, con escalado automático, autorreparación y actualizaciones graduales.
Instance template (plantilla de instancia)
Una definición reutilizable de la configuración de una VM que se usa para crear VMs en un MIG.
Ejemplo real

Un sitio de venta de boletos ejecuta sus servidores web en un grupo de instancias administrado regional detrás de un balanceador de carga global. Durante una preventa, el escalado automático hace crecer el grupo de 4 a 40 VMs en tres zonas, y cuando una VM falla, la autorreparación la reemplaza sin que haya que llamar a nadie.

Consejo para el examen: El escalado automático y el reemplazo de VMs que fallan apuntan a un grupo de instancias administrado. El control total del sistema operativo apunta a Compute Engine y no a las opciones serverless.

Comprueba lo que sabes

¿Qué hace la autorreparación en un grupo de instancias administrado?

Recrea las VMs que no pasan su verificación de estado, para que el grupo vuelva automáticamente a un estado sano.

¿Cuándo usarías un tipo de máquina personalizado?

Cuando ningún tipo predefinido coincide con las vCPUs y la memoria que necesita una carga de trabajo, para evitar pagar por recursos sin usar.
