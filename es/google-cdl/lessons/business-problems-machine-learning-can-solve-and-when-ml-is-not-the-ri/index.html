Problemas de negocio que el aprendizaje automático puede resolver, y cuándo el ML no es la herramienta adecuada

El aprendizaje automático es poderoso, pero es una herramienta para tipos específicos de problemas. Un líder digital debe poder detectar dónde el ML agrega valor y dónde son mejores los enfoques más simples.

El ML funciona bien cuando hay un patrón en los datos demasiado complejo para escribirlo como reglas, y muchos ejemplos de ese patrón. Los usos de negocio clásicos incluyen predecir resultados (qué clientes probablemente abandonarán, cuánto inventario necesitará una tienda la próxima semana), clasificar elementos (spam o no, qué departamento debe atender un ticket, si una transacción parece fraudulenta), recomendar productos o contenido, detectar anomalías (lecturas de sensores o pagos inusuales) y entender datos no estructurados (leer documentos, reconocer objetos en imágenes, transcribir llamadas). La IA generativa agrega resumir, redactar, traducir, responder preguntas y escribir código.

El ML también es valioso cuando la escala o la velocidad superan lo que pueden hacer las personas. Una persona puede revisar unos cientos de reclamos de seguros al día; un modelo puede calificar millones y marcar los inusuales para revisión humana. Eso libera a las personas para tareas de criterio y de contacto con los clientes.

El ML no es la herramienta adecuada cuando las reglas son conocidas y exactas, como calcular impuestos, intereses o envíos según una fórmula publicada; el código normal es más barato, más rápido y siempre correcto. Es una mala opción cuando hay pocos o ningún dato relevante, cuando los datos no reflejan la situación que enfrentará el modelo, o cuando cada decisión debe ser completamente explicable y un modelo no puede ofrecer eso. También es innecesario cuando un reporte o tablero sencillo respondería la pregunta.

Antes de empezar un proyecto de ML, define el problema de negocio y cómo se medirá el éxito, confirma que existen datos adecuados y considera si un servicio preentrenado ya lo resuelve. Los proyectos de ML son experimentos: planea para iterar, monitorear y reentrenar, porque el mundo cambia y la precisión de un modelo puede degradarse con el tiempo.

Términos clave

Classification (clasificación)
Predecir a qué categoría pertenece un elemento, como fraude o no fraude.
Forecasting (pronóstico)
Predecir valores numéricos futuros, como la demanda del próximo mes.
Anomaly detection (detección de anomalías)
Encontrar datos que difieren significativamente de los patrones normales.
Model drift (deriva del modelo)
Una caída en la precisión de un modelo con el tiempo a medida que los datos del mundo real se alejan de los datos de entrenamiento.
Ejemplo real

Una empresa de telecomunicaciones quiere predecir qué clientes cancelarán. Tiene cinco años de historial de uso y cancelaciones, así que construye un modelo de abandono (churn) y da ofertas de retención a los clientes de alto riesgo. No usa ML para calcular las facturas mensuales, que siguen reglas de precios fijas.

Consejo para el examen: Las respuestas distractoras del examen a menudo sugieren ML para tareas con reglas exactas. Elige ML cuando los patrones son complejos y hay muchos datos; elige código normal cuando la lógica es conocida.

Comprueba lo que sabes

Da tres problemas de negocio adecuados para ML.

Tres cualesquiera: predicción de abandono, pronóstico de demanda, detección de fraude, recomendaciones, comprensión de documentos o imágenes, detección de anomalías.

¿Por qué el ML es una mala opción para calcular el impuesto sobre las ventas?

Las reglas son exactas y conocidas, así que el código normal da resultados correctos; un modelo solo podría aproximarlos.
