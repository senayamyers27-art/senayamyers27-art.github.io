Amenazas comunes en la nube: configuraciones erróneas, credenciales comprometidas, phishing, malware y ransomware

Conocer las amenazas comunes ayuda a los líderes a invertir en los controles correctos. Muchos incidentes en la nube no se deben a ataques sofisticados contra el proveedor, sino a debilidades del lado del cliente.

La configuración errónea (misconfiguration) es una de las principales causas de exposición de datos en la nube. Algunos ejemplos son buckets de almacenamiento que por error se pueden leer públicamente, bases de datos accesibles desde internet, reglas de firewall abiertas a todas las direcciones, logs desactivados y usuarios con muchos más permisos de los que necesitan. Como los recursos en la nube son fáciles de crear, los errores pueden propagarse rápidamente. Las defensas incluyen configuraciones seguras por defecto, políticas de la organización que bloquean configuraciones riesgosas, infraestructura como código con revisión y herramientas como Security Command Center que detectan configuraciones erróneas.

Las credenciales comprometidas (compromised credentials) ocurren cuando los atacantes obtienen contraseñas, claves de API o claves de cuentas de servicio, por ejemplo por la reutilización de contraseñas filtradas en otro lugar o por claves publicadas accidentalmente en repositorios de código. Con credenciales válidas, los atacantes parecen usuarios legítimos. Las defensas incluyen una autenticación multifactor sólida, evitar claves de larga duración, el mínimo privilegio y el monitoreo de actividad inusual.

El phishing engaña a las personas para que revelen credenciales o ejecuten software malicioso, normalmente mediante correos o mensajes que se hacen pasar por una persona o un servicio de confianza. La verificación en dos pasos resistente al phishing, como las llaves de seguridad, es una de las defensas más eficaces, junto con la capacitación de concientización.

El malware es software malicioso, como virus, troyanos y spyware. El ransomware es un malware que cifra los datos de una organización y exige un pago para restaurarlos, y a menudo también amenaza con publicar los datos robados. Las defensas incluyen aplicar parches, limitar los privilegios, proteger los equipos de usuario (endpoints), filtrar el correo y, de forma crucial, tener respaldos que los atacantes no puedan alterar ni borrar, para poder restaurar los datos sin pagar.

Otras amenazas incluyen los ataques de denegación de servicio que saturan los servicios, las amenazas internas de empleados que abusan de su acceso y los ataques a las cadenas de suministro de software. La defensa en profundidad, que se trata en la siguiente lección, significa que ningún control por sí solo tiene que detenerlo todo.

Términos clave

Misconfiguration (configuración errónea)
Un ajuste inseguro, como el acceso público o permisos demasiado amplios, a menudo hecho por error.
Phishing
Mensajes engañosos diseñados para que las personas revelen credenciales o ejecuten malware.
Ransomware
Malware que cifra los datos y exige un pago para restaurar el acceso.
Compromised credentials (credenciales comprometidas)
Contraseñas, claves o tokens obtenidos por un atacante y usados para hacerse pasar por un usuario legítimo.
Ejemplo real

Un desarrollador sube por accidente la clave de una cuenta de servicio a un repositorio de código público. En pocas horas, los atacantes la usan para crear VMs para minar criptomonedas. La empresa revoca la clave, cambia a autenticación sin claves para su pipeline y activa alertas sobre la creación inusual de recursos.

Consejo para el examen: La mayoría de las brechas en la nube se deben a problemas del lado del cliente: configuraciones erróneas y credenciales robadas. Las defensas más sólidas son la configuración segura, el mínimo privilegio y la autenticación multifactor resistente al phishing.

Comprueba lo que sabes

¿Cuál es la defensa más eficaz para no perder datos por un ransomware?

Respaldos protegidos que los atacantes no puedan cambiar ni borrar, que permitan restaurar sin pagar, junto con la aplicación de parches y el mínimo privilegio.

Da dos ejemplos de configuración errónea en la nube.

Un bucket de almacenamiento con lectura pública, una base de datos abierta a internet, reglas de firewall que permiten todas las direcciones o permisos excesivos (dos cualesquiera).
