Datos estructurados, semiestructurados y no estructurados

Los datos vienen en distintas formas, y la forma determina dónde conviene almacenarlos y cómo se analizan. El examen espera que reconozcas los tres tipos principales y los relaciones con los servicios de Google Cloud.

Los datos estructurados (structured data) se ajustan a un esquema fijo de filas y columnas, donde cada registro tiene los mismos campos con tipos definidos. Las tablas de clientes, los pedidos, las transacciones bancarias y los registros de inventario son estructurados. Son fáciles de consultar con SQL y normalmente se almacenan en bases de datos relacionales como Cloud SQL, AlloyDB o Spanner, o en un data warehouse como BigQuery para su análisis.

Los datos semiestructurados (semi-structured data) tienen cierta organización, como etiquetas o claves, pero no un esquema rígido. Distintos registros pueden tener distintos campos, y los campos pueden estar anidados. Los documentos JSON, XML, los logs de aplicaciones y muchos mensajes de eventos son semiestructurados. Las bases de datos de documentos como Firestore los almacenan de forma natural, y BigQuery también puede almacenar y consultar campos anidados y repetidos, así como JSON.

Los datos no estructurados (unstructured data) no tienen un modelo predefinido: imágenes, video, audio, correos electrónicos, PDFs, documentos escaneados y texto libre. Constituyen la mayor parte de los datos que crean las organizaciones. Normalmente se almacenan como objetos en Cloud Storage. Para analizarlos a menudo se necesita IA: la Vision API puede etiquetar imágenes o leer el texto que contienen, Speech-to-Text puede transcribir llamadas y la Natural Language API puede encontrar el sentimiento o las entidades en un texto. Una vez procesados, los resultados se convierten en datos estructurados que puedes consultar.

La línea entre los tipos no siempre es nítida, y un mismo proyecto suele usar los tres. Un sistema de atención al cliente podría tener registros de tickets estructurados, logs de eventos JSON semiestructurados y grabaciones de llamadas no estructuradas. Elegir el almacenamiento correcto para cada tipo, y conectarlos para su análisis, es una parte central de la transformación de datos en Google Cloud.

Términos clave

Structured data (datos estructurados)
Datos organizados en un esquema fijo de filas y columnas, fáciles de consultar con SQL.
Semi-structured data (datos semiestructurados)
Datos con etiquetas o claves pero con un esquema flexible, como JSON o XML.
Unstructured data (datos no estructurados)
Datos sin un modelo predefinido, como imágenes, video, audio y texto libre.
Schema (esquema)
La definición de los campos, los tipos y las relaciones de un conjunto de datos.
Ejemplo real

Una aseguradora guarda los registros de pólizas en Cloud SQL (estructurados), los eventos de su aplicación móvil como JSON en BigQuery (semiestructurados) y las fotos de daños de autos en Cloud Storage (no estructurados). Pasa las fotos por un modelo de imágenes y guarda los resultados como campos estructurados para el análisis de reclamos.

Consejo para el examen: Las imágenes, el video, el audio y los documentos son no estructurados y normalmente van en Cloud Storage. JSON y los logs son semiestructurados. Las tablas con columnas fijas son estructuradas.

Comprueba lo que sabes

Un registro de pedido en JSON con campos opcionales, ¿es estructurado, semiestructurado o no estructurado?

Semiestructurado: tiene claves pero no un esquema rígido.

¿Dónde se almacenan normalmente en Google Cloud los datos no estructurados, como el video?

En Cloud Storage, como objetos dentro de un bucket.
