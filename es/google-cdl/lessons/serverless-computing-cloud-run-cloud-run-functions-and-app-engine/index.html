Computación serverless: Cloud Run, Cloud Run functions y App Engine

La computación serverless (sin servidor) permite a los desarrolladores ejecutar código sin aprovisionar ni administrar servidores. La plataforma se encarga de la infraestructura, los parches del sistema operativo, el escalado y la disponibilidad. Las aplicaciones escalan automáticamente con la demanda, a menudo hasta cero cuando están inactivas, y pagas los recursos usados mientras se atienden solicitudes o eventos. Los servidores siguen existiendo, pero son responsabilidad exclusiva del proveedor. Serverless permite a los equipos pequeños entregar rápido y evita pagar por capacidad ociosa.

Cloud Run es una plataforma completamente administrada para ejecutar contenedores. Proporcionas una imagen de contenedor, o código fuente que Cloud Run convierte en una, y te da un endpoint HTTPS. Aumenta y reduce el número de instancias según las solicitudes entrantes, incluso hasta cero, y factura los recursos usados. Como ejecuta contenedores estándar, puedes usar cualquier lenguaje o biblioteca, y la misma imagen podría ejecutarse en GKE o en otro lugar. Conviene para aplicaciones web, APIs, microservicios y trabajos que se ejecutan hasta terminar.

Cloud Run functions (antes Cloud Functions) ejecuta fragmentos de código de un solo propósito, escritos en los lenguajes admitidos, en respuesta a eventos: una solicitud HTTP, un archivo nuevo en un bucket de Cloud Storage, un mensaje publicado en Pub/Sub o un cambio en una base de datos. Solo escribes la función; la plataforma se encarga de todo lo demás. Es ideal para código de integración y automatización ligera, como redimensionar una imagen subida o enviar una notificación cuando se hace un pedido.

App Engine es la plataforma como servicio original de Google Cloud para aplicaciones web. Los desarrolladores implementan código en los lenguajes admitidos y App Engine administra el entorno de ejecución, el escalado y las versiones, incluida la división del tráfico entre versiones. Muchas aplicaciones todavía lo usan, mientras que Cloud Run suele ser la opción para los nuevos servicios en contenedores.

Serverless no es ideal para todo. Las cargas de trabajo que necesitan control total del sistema operativo, hardware especial, procesos de larga duración que siempre deben estar encendidos o redes muy específicas pueden encajar mejor en VMs o en GKE.

Términos clave

Serverless (sin servidor)
Ejecutar código sin administrar servidores, con escalado automático y precios de pago por uso.
Cloud Run
Una plataforma serverless administrada para ejecutar contenedores que escala automáticamente, incluso hasta cero.
Cloud Run functions
Funciones serverless impulsadas por eventos que se ejecutan en respuesta a disparadores como solicitudes HTTP o archivos nuevos.
Scale to zero (escalar a cero)
No ejecutar ninguna instancia, y no generar costo de cómputo, cuando no hay tráfico.
Ejemplo real

Un sitio de noticias ejecuta su API en Cloud Run para que escale cuando surge una gran noticia y baje a cero durante la noche. Cuando una periodista sube una foto a Cloud Storage, una Cloud Run function crea automáticamente las miniaturas. El equipo nunca parcha un servidor.

Consejo para el examen: Aplicación web o API en contenedor sin infraestructura que administrar y con escalado a cero: Cloud Run. Un fragmento pequeño de código disparado por un evento: Cloud Run functions. Plataforma de aplicaciones web basada en código: App Engine.

Comprueba lo que sabes

¿Qué hace que un servicio sea serverless?

No hay servidores que administrar, escala automáticamente (a menudo hasta cero) y se factura por uso.

¿Qué opción serverless usarías para ejecutar código cada vez que llega un mensaje a Pub/Sub?

Cloud Run functions, disparada por el evento de Pub/Sub.
