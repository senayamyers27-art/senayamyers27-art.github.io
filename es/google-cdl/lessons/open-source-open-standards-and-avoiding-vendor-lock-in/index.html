Código abierto, estándares abiertos y cómo evitar la dependencia de un proveedor

La dependencia de un proveedor (vendor lock-in) ocurre cuando alejarse de un proveedor se vuelve tan costoso o difícil que en la práctica te quedas atrapado. Puede venir de formatos de datos propietarios, APIs que solo existen en una plataforma, habilidades que no se transfieren o contratos. A los líderes les preocupa la dependencia porque debilita su posición de negociación y hace más difícil adoptar mejor tecnología más adelante.

El software de código abierto (open source) es software cuyo código fuente está disponible públicamente para usarlo, modificarlo y compartirlo bajo una licencia. Los estándares abiertos (open standards) son especificaciones publicadas, como SQL o HTTP, que implementan muchos proveedores. Construir sobre ellos significa que tus aplicaciones, datos y habilidades pueden moverse entre entornos con menos retrabajo.

Google tiene una larga trayectoria creando y contribuyendo a proyectos de código abierto que hoy se usan ampliamente. Kubernetes, el sistema de orquestación de contenedores, nació en Google, hoy lo gestiona la Cloud Native Computing Foundation y está disponible en todas las nubes principales y on-premises. TensorFlow es un framework de aprendizaje automático de código abierto. Apache Beam, el modelo de programación detrás de Dataflow, permite que el mismo pipeline se ejecute en varios motores. Google Cloud también ofrece versiones administradas de sistemas de código abierto populares, como Cloud SQL para MySQL y PostgreSQL, Dataproc para Apache Spark y Hadoop, y Memorystore para Redis.

La apertura es una parte deliberada de la estrategia de Google Cloud. Apoya los diseños híbridos y multinube, permite a los clientes traer sus herramientas y su gente existentes, y reduce el riesgo de adoptar la plataforma. Productos como GKE Enterprise se basan en Kubernetes para que las mismas prácticas se apliquen en Google Cloud, en tu propio centro de datos y en otras nubes.

El código abierto no es la única forma de reducir la dependencia. También ayudan rutas claras para exportar datos, formatos de archivo estándar como Parquet o CSV, y diseños que separan la lógica de negocio de los servicios específicos del proveedor. Pero el examen normalmente relaciona 'evitar la dependencia' y 'portabilidad' con el código abierto y Kubernetes.

Términos clave

Vendor lock-in (dependencia de un proveedor)
Dependencia de un solo proveedor que hace que cambiar sea costoso o difícil.
Open source (código abierto)
Software cuyo código está disponible abiertamente para usarlo, modificarlo y compartirlo bajo una licencia.
Open standard (estándar abierto)
Una especificación disponible públicamente que cualquiera puede implementar, como SQL.
Portability (portabilidad)
La capacidad de mover aplicaciones y datos entre entornos con pocos cambios.
Ejemplo real

Una empresa de medios preocupada por la dependencia construye sus servicios como contenedores en Kubernetes y guarda sus datos analíticos en formatos abiertos. Cuando más adelante un regulador le pide un plan de salida, la empresa puede demostrar que los mismos contenedores ya se ejecutan en un clúster de prueba en su propio centro de datos.

Consejo para el examen: Cuando una pregunta mencione portabilidad, flexibilidad entre entornos o evitar la dependencia de un proveedor, busca código abierto, estándares abiertos o Kubernetes en las respuestas.
