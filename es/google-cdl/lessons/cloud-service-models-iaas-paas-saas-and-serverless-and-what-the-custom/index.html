Modelos de servicio en la nube: IaaS, PaaS, SaaS y serverless, y qué administra el cliente en cada uno

Los servicios en la nube se agrupan según qué parte de la pila administra el proveedor por ti. Piensa en la pila de abajo hacia arriba: instalaciones, hardware físico, redes, virtualización, sistema operativo, entorno de ejecución y middleware, aplicación y, finalmente, datos y acceso. Mientras más arriba administre el proveedor, menos trabajo tienes y menos control tienes.

La infraestructura como servicio (IaaS, infrastructure as a service) te da máquinas virtuales, discos y redes. El proveedor opera las capas físicas y la virtualización; tú instalas y parchas el sistema operativo, los entornos de ejecución y las aplicaciones. Compute Engine es la oferta de IaaS de Google Cloud. Elige IaaS cuando necesites control total, por ejemplo para una aplicación heredada que espera un sistema operativo en particular.

La plataforma como servicio (PaaS, platform as a service) te da una plataforma administrada a la que llevas tu código y tus datos. El proveedor opera el sistema operativo y el entorno de ejecución, maneja el escalado y aplica los parches. App Engine es un PaaS clásico de Google Cloud. Los desarrolladores ganan velocidad porque se enfocan en el código, no en los servidores.

El software como servicio (SaaS, software as a service) es una aplicación completa que se usa a través de internet, como Google Workspace (Gmail, Docs, Drive). El proveedor lo opera todo; tú administras tus usuarios, la configuración y los datos.

Serverless (sin servidor) es una forma de usar servicios en la nube en la que no aprovisionas ni administras servidores en absoluto, la capacidad escala automáticamente (a menudo hasta cero) y pagas por el uso real, como solicitudes o tiempo de cómputo. Cloud Run (contenedores), Cloud Run functions (código impulsado por eventos) y BigQuery (analítica) son serverless. Los servicios serverless a menudo se describen como una forma de PaaS, y algunos servicios de datos administrados se comportan como SaaS para los desarrolladores.

Elegir un modelo es un equilibrio entre control y comodidad. IaaS da el mayor control y la mayor responsabilidad. SaaS da el menor de ambos. Muchas organizaciones los combinan: SaaS para el correo, PaaS o serverless para aplicaciones nuevas e IaaS para las cargas de trabajo que todavía no pueden cambiar.

Términos clave

IaaS
Infraestructura como servicio: máquinas virtuales, almacenamiento y redes, y el cliente administra el sistema operativo y lo que está por encima.
PaaS
Plataforma como servicio: un entorno de ejecución administrado al que el cliente lleva su código y sus datos.
SaaS
Software como servicio: una aplicación completa entregada a través de internet.
Serverless (sin servidor)
Servicios sin servidores que administrar, con escalado automático y facturación de pago por uso.
Ejemplo real

Una empresa ejecuta un sistema de inventario antiguo en Compute Engine porque necesita una versión específica de sistema operativo, construye su nuevo portal de clientes en Cloud Run y da a su personal Google Workspace para el correo. Usa IaaS, serverless y SaaS lado a lado.

Consejo para el examen: Relaciona productos con modelos: Compute Engine es IaaS, App Engine es PaaS, Cloud Run y Cloud Run functions son serverless, Google Workspace es SaaS. El cliente siempre administra sus datos y el acceso, en todos los modelos.

Comprueba lo que sabes

¿Qué modelo de servicio le da al cliente el mayor control sobre el sistema operativo?

IaaS, como Compute Engine, donde el cliente instala y administra el sistema operativo.

¿Qué tres rasgos definen a serverless?

No hay servidores que aprovisionar ni administrar, escalado automático (a menudo hasta cero) y pagar solo por el uso real.
