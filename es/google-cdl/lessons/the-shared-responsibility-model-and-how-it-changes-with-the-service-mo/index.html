El modelo de responsabilidad compartida y cómo cambia según el modelo de servicio

En la nube, la seguridad y las operaciones se comparten entre el proveedor y el cliente. El modelo de responsabilidad compartida (shared responsibility model) describe quién hace qué. Malinterpretarlo es una causa común de incidentes: a veces los clientes suponen que el proveedor protege cosas que en realidad son trabajo del cliente.

Google siempre es responsable de la seguridad de la infraestructura subyacente: los centros de datos físicos, el hardware, la red global y la capa de virtualización que aísla a los clientes. Google diseña sus propios servidores y equipos de red y los opera con controles físicos y operativos estrictos.

El cliente siempre es responsable de sus propios datos, de decidir quién puede acceder a ellos (identidades y permisos) y de cómo configura los servicios que usa. Si un cliente hace público un bucket de almacenamiento por error, o le da a un empleado mucho más acceso del necesario, eso está del lado del cliente, aunque el servicio en sí sea seguro.

Entre esos dos extremos fijos, la división se mueve según el modelo de servicio. Con IaaS, como Compute Engine, el cliente también administra el sistema operativo invitado, los parches, el software instalado y las reglas de firewall de red. Con PaaS y serverless, como App Engine o Cloud Run, Google también administra el sistema operativo y el entorno de ejecución, así que el cliente se enfoca en el código de la aplicación, la configuración y los datos. Con SaaS, como Google Workspace, Google opera toda la aplicación y el cliente administra usuarios, configuración y datos.

Google Cloud describe su enfoque como destino compartido (shared fate): además de trazar una línea, ofrece configuraciones seguras por defecto, planos de referencia (blueprints), orientación y herramientas para ayudar a los clientes a hacer bien su parte. Para el examen, recuerda dos cosas. Primero, subir de IaaS a SaaS reduce la responsabilidad del cliente pero nunca la elimina. Segundo, los datos, el acceso y la configuración siempre se quedan con el cliente.

Términos clave

Shared responsibility model (modelo de responsabilidad compartida)
La división de las tareas de seguridad y operación entre el proveedor de nube y el cliente.
Shared fate (destino compartido)
El enfoque de Google Cloud de ayudar activamente a los clientes a asegurar su parte mediante configuraciones por defecto, herramientas y orientación.
Security of the cloud (seguridad de la nube)
La tarea del proveedor: instalaciones físicas, hardware, red y virtualización.
Security in the cloud (seguridad en la nube)
La tarea del cliente: datos, identidades, acceso y configuración.
Ejemplo real

Una empresa ejecuta una aplicación web en Compute Engine y no parcha el sistema operativo durante un año. Un atacante explota una vulnerabilidad antigua. Como el sistema operativo es responsabilidad del cliente en IaaS, la corrección le toca a la empresa. Mover la aplicación a Cloud Run trasladaría a Google la aplicación de parches del sistema operativo.

Consejo para el examen: Cualquier respuesta que diga que el proveedor se vuelve responsable de los datos del cliente o de las decisiones de acceso es incorrecta. La pregunta suele evaluar qué capa pasa al proveedor conforme vas de IaaS a PaaS a SaaS.

Comprueba lo que sabes

¿Quién aplica los parches al sistema operativo invitado de una VM de Compute Engine?

El cliente, porque Compute Engine es IaaS.

¿Qué responsabilidades se quedan con el cliente incluso en SaaS?

Sus datos, sus usuarios y el acceso de estos, y la configuración que elige.
