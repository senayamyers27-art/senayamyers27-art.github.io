Bases de datos no relacionales en Google Cloud: Firestore y Bigtable

Las bases de datos no relacionales, o NoSQL, almacenan datos en modelos distintos de las tablas relacionadas. Sacrifican algunas funciones relacionales, como los joins complejos, a cambio de flexibilidad o de una escala muy grande. Los dos principales servicios NoSQL administrados de Google Cloud en el examen son Firestore y Bigtable, y resuelven problemas bastante distintos.

Firestore es una base de datos de documentos serverless. Los datos se almacenan como documentos, que son conjuntos de campos parecidos a JSON, organizados en colecciones. Los documentos de una misma colección pueden tener campos distintos, así que el esquema puede evolucionar fácilmente conforme cambia una aplicación. Firestore escala automáticamente sin servidores que administrar, y tiene funciones pensadas para aplicaciones web y móviles: listeners en tiempo real que envían los cambios a los clientes conectados, soporte sin conexión para que una aplicación siga funcionando sin red y se sincronice después, y bibliotecas cliente que funcionan con Firebase. Es una buena opción para perfiles de usuario, estado de juegos, chat, catálogos de productos y otros datos de aplicaciones.

Bigtable es una base de datos NoSQL de columnas anchas (wide-column) construida para cantidades muy grandes de datos con latencia baja y constante y un rendimiento de lectura y escritura muy alto. Los datos se almacenan en tablas con filas identificadas por una sola clave de fila (row key) y columnas agrupadas en familias; las filas pueden tener muchas columnas y las celdas vacías no cuestan nada. Es ideal para datos de series de tiempo, lecturas de sensores IoT, datos de mercados financieros, tecnología publicitaria y personalización, y es el tipo de sistema que impulsa grandes servicios de Google. Es compatible con la API de código abierto Apache HBase.

La clave para elegir es la carga de trabajo. Firestore conviene para datos de aplicaciones web y móviles, donde importan la flexibilidad, la sincronización en tiempo real y la cero administración, y los volúmenes son de moderados a grandes. Bigtable conviene para conjuntos de datos analíticos y operativos enormes, a menudo de terabytes a petabytes, donde lo que más importa es el rendimiento y la latencia a escala y el acceso es principalmente por clave.

Ninguno de los dos es un data warehouse. Para analítica SQL sobre grandes conjuntos de datos sigues usando BigQuery, que también puede consultar datos almacenados en Bigtable.

Términos clave

NoSQL
Bases de datos que usan modelos distintos de las tablas relacionales, como documentos, clave-valor o columnas anchas.
Firestore
Una base de datos de documentos NoSQL serverless con actualizaciones en tiempo real y soporte sin conexión para aplicaciones.
Bigtable
Una base de datos NoSQL de columnas anchas para cargas de trabajo muy grandes, de baja latencia y alto rendimiento.
Row key (clave de fila)
El identificador único que se usa para almacenar y recuperar filas en Bigtable, y que determina cómo se organizan los datos.
Ejemplo real

Una empresa de fitness guarda el perfil y los planes de entrenamiento de cada usuario en Firestore para que la aplicación móvil se actualice al instante en el teléfono y el reloj del usuario. Las lecturas de ritmo cardiaco de millones de dispositivos portátiles, que llegan cada segundo, van a Bigtable con una clave formada por el dispositivo y la marca de tiempo.

Consejo para el examen: Aplicación móvil o web, sincronización en tiempo real, modo sin conexión: Firestore. Datos masivos de series de tiempo o IoT con alto rendimiento y baja latencia: Bigtable. Ninguno es la respuesta para analítica SQL, que es BigQuery.
