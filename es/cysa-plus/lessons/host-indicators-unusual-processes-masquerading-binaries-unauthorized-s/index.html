CompTIA CySA+ CS0-004

Indicadores de host: procesos inusuales, binarios disfrazados, software no autorizado, persistencia (servicios, tareas programadas, run keys)

Los indicadores de host son señales de compromiso en un endpoint o servidor individual. Mientras que los indicadores de red te dicen que algo se está comunicando, los indicadores de host te dicen qué se está ejecutando, cómo llegó ahí y cómo sobrevive a un reinicio. Las herramientas EDR, Sysmon y los comandos integrados son tus fuentes principales.

Los procesos inusuales destacan por su nombre, ubicación, proceso padre, usuario o comportamiento. Las relaciones padre-hijo son especialmente reveladoras: Microsoft Word generando powershell.exe o cmd.exe sugiere una macro maliciosa, y un proceso de servidor web generando una shell sugiere una web shell. Otras señales de alerta incluyen procesos que se ejecutan desde carpetas temporales o con permisos de escritura del usuario, procesos sin descripción ni firma, líneas de comando codificadas y un uso de CPU alto e inesperado, que puede indicar criptominería. En Windows puedes inspeccionar procesos con el Administrador de tareas, Process Explorer o tasklist; en Linux con ps aux y top.

El masquerading (disfraz) ocurre cuando el malware se hace pasar por un programa legítimo. Los trucos comunes incluyen usar un nombre de sistema real en la carpeta equivocada (un svchost.exe legítimo vive en System32 y lo lanza services.exe, no desde el AppData de un usuario), nombres ligeramente mal escritos como scvhost.exe, dobles extensiones como invoice.pdf.exe y copias renombradas de herramientas administrativas legítimas. Verificar la ruta del archivo, la firma digital, el hash y el proceso padre normalmente lo expone.

El software no autorizado es cualquier cosa no aprobada para el entorno: herramientas de acceso remoto, crackeadores de contraseñas, utilidades de hacking o simplemente aplicaciones sin licencia. Puede haberlo instalado un atacante, o un usuario que generó un riesgo sin mala intención. Las listas de aplicaciones permitidas (allow listing) y las herramientas de inventario de software ayudan a detectarlo y prevenirlo.

La persistencia es la forma en que un atacante mantiene el acceso después de reinicios o cierres de sesión. En Windows los mecanismos más comunes son servicios nuevos (evento 7045 del log de System, evento 4697 de Security), tareas programadas (evento 4698 cuando la auditoría de tareas está habilitada; lístalas con schtasks /query) y las Run keys del registro, como HKLM\Software\Microsoft\Windows\CurrentVersion\Run y la clave HKCU equivalente, que lanzan programas al iniciar sesión. Otras opciones incluyen las carpetas de inicio, las suscripciones a eventos WMI y las cuentas nuevas. En Linux, revisa los cron jobs, las unidades de servicio de systemd, los archivos de perfil de la shell y las llaves SSH no autorizadas en authorized_keys. La herramienta Autoruns de Sysinternals lista casi todas las ubicaciones de inicio automático de Windows en un solo lugar.

Cuando encuentres un elemento sospechoso, reúne su ruta, hash, firma, fecha de creación y proceso padre, luego verifica su reputación y busca el mismo indicador en el resto de los equipos antes de limpiarlo.

Términos clave

Masquerading (disfraz)
Disfrazar archivos o procesos maliciosos con nombres, íconos o ubicaciones que imitan a los legítimos.
Persistence (persistencia)
Técnicas que usa un atacante para mantener el acceso a un sistema a través de reinicios, cierres de sesión o cambios de credenciales.
Run key
Una ubicación del registro de Windows cuyas entradas lanzan programas automáticamente cuando el sistema arranca o un usuario inicia sesión.
Autoruns
Una utilidad de Sysinternals que muestra los programas configurados para iniciarse automáticamente en muchas ubicaciones de Windows.
Parent-child process (proceso padre-hijo)
La relación entre un proceso y el proceso que lo lanzó, usada para detectar cadenas de ejecución anormales.
Ejemplo real

El EDR señala un svchost.exe ejecutándose desde C:\Users\Public con winword.exe como padre. El svchost real se ejecuta desde System32 bajo services.exe. El analista encuentra una Run key que apunta al mismo archivo y una tarea programada que lo vuelve a crear cada hora, elimina ambas después de recolectar evidencia y busca el hash del archivo en otras máquinas.

Consejo para el examen: Las preguntas del examen a menudo dependen de la ubicación y del proceso padre: un nombre de sistema correcto en la carpeta equivocada o bajo el padre equivocado es masquerading. También recuerda que el evento 7045 significa que se instaló un servicio nuevo.

Comprueba lo que sabes

Menciona tres mecanismos de persistencia de Windows que un analista debería revisar.

Servicios, tareas programadas y Run keys del registro (también carpetas de inicio y suscripciones WMI).

¿Por qué es sospechoso que Excel lance PowerShell?

Las aplicaciones de Office normalmente no inician shells; esta cadena suele indicar una macro maliciosa o un exploit en un documento.

¿Qué herramienta lista la mayoría de las ubicaciones de inicio automático de Windows a la vez?

Autoruns de Sysinternals.
