CompTIA CySA+ CS0-004

Indicadores de host: procesos inusuales, binarios disfrazados, software no autorizado, persistencia (servicios, tareas programadas, run keys)

Los indicadores de host son señales de compromiso en un endpoint o servidor individual. Los indicadores de red te dicen que algo se está comunicando; los indicadores de host te dicen qué se está ejecutando, cómo llegó ahí y cómo sobrevive a un reinicio. Tus fuentes principales son las herramientas de detección y respuesta en endpoints (EDR), System Monitor (Sysmon) y los logs del sistema operativo, además de los comandos integrados cuando revisas una sola máquina.

Los procesos inusuales destacan por su nombre, ubicación, proceso padre, cuenta de usuario o comportamiento. Las relaciones padre-hijo son especialmente reveladoras. Microsoft Word generando powershell.exe o cmd.exe sugiere una macro maliciosa, y un proceso de servidor web que genera una shell sugiere una web shell. Otras señales de alerta incluyen procesos que se ejecutan desde carpetas temporales o en las que el usuario puede escribir, ejecutables sin descripción ni firma digital, líneas de comandos largas y codificadas, y un uso alto y sostenido de CPU que podría indicar criptominería. En Windows puedes inspeccionar los procesos con el Administrador de tareas, Sysinternals Process Explorer o tasklist; en Linux, con ps aux y top.

El enmascaramiento (masquerading) ocurre cuando el malware se disfraza de un programa legítimo. Los trucos comunes incluyen usar un nombre de sistema real en la carpeta equivocada (un svchost.exe genuino vive en System32 y lo inicia services.exe, no la carpeta AppData de un usuario), nombres ligeramente mal escritos como scvhost.exe, extensiones dobles como invoice.pdf.exe y copias renombradas de herramientas administrativas legítimas. Revisar la ruta completa, la firma digital, el hash del archivo y el proceso padre normalmente lo expone. El software no autorizado es cualquier cosa no aprobada para el entorno: herramientas de acceso remoto, crackeadores de contraseñas, utilidades de hacking o simplemente aplicaciones sin licencia. Puede instalarlo un atacante o un usuario bien intencionado que generó un riesgo sin malicia. Las listas de aplicaciones permitidas (application allow listing) y las herramientas de inventario de software ayudan a detectarlo y prevenirlo.

La persistencia es la forma en que un atacante mantiene el acceso después de reinicios o cierres de sesión. En Windows, los mecanismos más comunes son los servicios nuevos (evento 7045 del log del Sistema, evento 4697 de Seguridad), las tareas programadas (evento 4698 de Seguridad cuando la auditoría de tareas está habilitada; puedes listarlas con schtasks /query) y las claves Run del registro, como HKLM\Software\Microsoft\Windows\CurrentVersion\Run y la clave HKCU equivalente, que ejecutan programas al iniciar sesión. Otras opciones incluyen las carpetas de inicio, las suscripciones a eventos de Windows Management Instrumentation (WMI) y las cuentas nuevas. En Linux, revisa los trabajos de cron, las unidades de servicio de systemd, los archivos de perfil de la shell y las llaves SSH inesperadas en authorized_keys. La herramienta Autoruns de Sysinternals lista casi todas las ubicaciones de inicio automático de Windows en una sola vista, lo que la convierte en una forma rápida de detectar algo nuevo.

Cuando haces el triaje de un host, sigue un orden consistente para no pasar nada por alto. Primero, lista los procesos en ejecución con sus rutas, procesos padre, usuarios y líneas de comandos. Segundo, revisa las conexiones de red con netstat o ss y vincula cada una con un proceso. Tercero, enumera las ubicaciones de inicio automático: servicios, tareas programadas, claves Run, carpetas de inicio, trabajos de cron y unidades de systemd. Cuarto, compara el software instalado con el inventario aprobado. Para cada elemento sospechoso, registra su hash y revisa su reputación, y luego compáralo con un sistema de referencia confiable de la misma versión; una diferencia que existe en una sola máquina suele ser la pista más interesante.

Considera un ejemplo práctico. El EDR marca un svchost.exe que se ejecuta desde C:\Users\Public con winword.exe como proceso padre. Como el svchost real se ejecuta desde System32 bajo services.exe, ya sospechas de enmascaramiento. Antes de limpiar cualquier cosa, recolectas evidencia: el hash del archivo, la ruta, el estado de la firma, la hora de creación, el documento padre y una captura de memoria si la política lo exige. Autoruns muestra una clave Run que apunta al mismo archivo, y el programador de tareas contiene una tarea que lo vuelve a crear cada hora. Eliminas ambos mecanismos de persistencia, pones el archivo en cuarentena, buscas en toda la flota el mismo hash, la misma ruta y el mismo nombre de tarea, y agregas una regla de detección para aplicaciones de Office que generen ejecutables desde carpetas públicas.

Errores comunes: decidir que un proceso es seguro porque su nombre es conocido, sin revisar la ruta ni el proceso padre; eliminar el malware antes de recolectar evidencia y de buscar otros hosts infectados; limpiar la carga útil pero pasar por alto un segundo mecanismo de persistencia, de modo que la infección regresa; tratar el software no autorizado como siempre malicioso en lugar de como un problema de política que hay que investigar; y olvidar las ubicaciones de persistencia de Linux como cron y authorized_keys.

Las preguntas del examen con frecuencia dependen de la ubicación y del proceso padre. 'Nombre de sistema correcto, carpeta equivocada' o 'binario del sistema mal escrito' apuntan a enmascaramiento. 'Aplicación de Office que generó PowerShell' apunta a un documento malicioso. 'Evento 7045' significa que se instaló un servicio nuevo; 'clave Run' o 'tarea programada que vuelve a crear un archivo' apuntan a persistencia. 'Herramienta de acceso remoto no aprobada en una estación de trabajo' apunta a software no autorizado, con las listas de aplicaciones permitidas como control preventivo. 'Uso alto y sostenido de CPU sin actividad del usuario' sugiere criptominería.

Términos clave

Enmascaramiento (masquerading)
Disfrazar malware como un programa legítimo mediante un nombre confiable, un error de escritura, una extensión doble o una herramienta renombrada.
Proceso padre-hijo (parent-child process)
La relación entre un proceso y el que lo inició, que a menudo revela cadenas de ejecución maliciosas.
Persistencia (persistence)
Cualquier mecanismo que permite que el código de un atacante sobreviva a reinicios, cierres de sesión o cambios de credenciales.
Clave Run (Run key)
Una ubicación del registro cuyas entradas ejecutan programas automáticamente al arrancar o cuando el usuario inicia sesión.
Event ID 7045
El evento del log del Sistema de Windows que registra la instalación de un servicio nuevo.
Autoruns
Una herramienta de Sysinternals que lista los programas configurados para iniciarse automáticamente en muchas ubicaciones de Windows.
Lista de aplicaciones permitidas (application allow listing)
Un control que solo permite ejecutar software aprobado y bloquea los programas no autorizados.
Ejemplo real

El EDR marca un svchost.exe que se ejecuta desde C:\Users\Public con winword.exe como proceso padre. El svchost real se ejecuta desde System32 bajo services.exe. El analista recolecta el hash y el documento padre, encuentra una clave Run que apunta al mismo archivo y una tarea programada que lo vuelve a crear cada hora, elimina ambas después de recolectar la evidencia y busca el hash y el nombre de la tarea en toda la flota.

Consejo para el examen: Un nombre de sistema correcto en la carpeta equivocada o bajo el proceso padre equivocado es enmascaramiento. El evento 7045 significa que se instaló un servicio nuevo, y siempre busca más de un mecanismo de persistencia antes de declarar limpio un host.

Comprueba lo que sabes

¿Qué proceso padre inicia normalmente svchost.exe y desde qué carpeta se ejecuta?

Lo inicia services.exe y se ejecuta desde C:\Windows\System32.

¿Por qué es sospechoso que Word ejecute powershell.exe?

Word no tiene ninguna razón normal para iniciar una shell, así que normalmente significa una macro maliciosa o un exploit en un documento.

Nombra tres mecanismos de persistencia de Windows.

Servicios nuevos, tareas programadas y claves Run del registro; otros incluyen las carpetas de inicio y las suscripciones a eventos de WMI.

¿Qué debes hacer antes de eliminar un binario sospechoso?

Recolectar evidencia como el hash, la ruta, la firma, el proceso padre y las marcas de tiempo, y luego buscar los mismos indicadores en otros hosts.
