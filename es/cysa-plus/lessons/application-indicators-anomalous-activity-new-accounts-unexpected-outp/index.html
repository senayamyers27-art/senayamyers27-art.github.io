CompTIA CySA+ CS0-004

Indicadores de aplicación: actividad anómala, cuentas nuevas, salidas inesperadas, cadenas de inyección en logs web

Los indicadores de aplicación son señales de compromiso que aparecen en cómo se comporta el software más que en la actividad cruda de red o de host. A menudo son la primera pista de que una aplicación web, una base de datos o un sistema de negocio está bajo ataque, y requieren que sepas cómo luce lo normal para esa aplicación.

La actividad anómala es un comportamiento que se aparta de la línea base de la aplicación: un usuario que exporta miles de registros cuando normalmente consulta unos pocos, inicios de sesión en horarios inusuales o desde países nuevos, un aumento repentino de errores, o llamadas a la API en un orden que ningún cliente real haría. Los logs de aplicación, los logs de auditoría de bases de datos y los logs de acceso del servidor web registran esto. Una avalancha de respuestas HTTP 401 o 403 sugiere fuerza bruta o sondeo del control de acceso, mientras que muchos errores 500 pueden significar que alguien está enviando entradas malformadas para encontrar una debilidad.

Las cuentas nuevas son un indicador clásico, especialmente las que tienen derechos administrativos y se crean fuera del proceso normal de aprovisionamiento, en horarios extraños o con nombres que imitan cuentas de servicio. Los atacantes crean cuentas para conservar el acceso aunque se cierre el punto de entrada original. Compara los eventos de creación de cuentas con los tickets de cambio y los registros de RR. HH. Los cambios de privilegios inesperados, como un usuario normal que de pronto tiene un rol de administrador, merecen la misma atención.

La salida inesperada ocurre cuando una aplicación devuelve algo que no debería: mensajes de error de la base de datos que revelan nombres de tablas, stack traces, datos de otros usuarios, listados de directorios o respuestas inusualmente grandes. Las anomalías de salida pueden significar que un atacante encontró una falla de inyección o un control de acceso roto, o que se están extrayendo datos a través de la aplicación. Un salto repentino en el tamaño de las respuestas de un endpoint en particular vale la pena investigarlo.

Las cadenas de inyección en logs web son fragmentos de payloads de ataque visibles en URLs, parámetros o encabezados. Debes reconocerlas, no fabricarlas. Las señales de SQL injection incluyen caracteres de comilla seguidos de palabras clave de SQL como OR 1=1, UNION SELECT, o marcadores de comentario como --. Los intentos de cross-site scripting contienen etiquetas <script> o manejadores de eventos como onerror=. El directory traversal aparece como secuencias repetidas de ../, a menudo codificadas en URL como %2e%2e%2f, apuntando a archivos como /etc/passwd. La inyección de comandos muestra caracteres de shell como ;, | o && seguidos de comandos del sistema. Los atacantes codifican los payloads para evadir filtros, así que a menudo es necesario decodificarlos con una herramienta como CyberChef.

Encontrar un payload en un log prueba un intento, no un éxito. Revisa el código de respuesta, el tamaño de la respuesta y la actividad posterior desde el mismo origen para decidir si el ataque funcionó.

Términos clave

Baseline (línea base)
Un registro del comportamiento normal usado para juzgar si la actividad actual es anómala.
Directory traversal (recorrido de directorios)
Un ataque que usa secuencias como ../ para acceder a archivos fuera de la raíz web.
URL encoding (codificación URL)
Representar caracteres como códigos hexadecimales con porcentaje, como %27 para una comilla simple, que los atacantes usan para ocultar payloads.
Stack trace (traza de pila)
Salida de error detallada que muestra rutas internas del código, lo que puede filtrar información a los atacantes.
Ejemplo real

Un log de acceso web muestra una sola IP solicitando /products?id=5%27%20UNION%20SELECT... decenas de veces. La mayoría de las solicitudes devuelven 500, pero las últimas devuelven 200 con respuestas diez veces más grandes de lo normal. El analista lo trata como una SQL injection probablemente exitosa, bloquea la IP en el WAF y pide a los desarrolladores que revisen la consulta.

Consejo para el examen: Aprende a reconocer patrones de payloads después de decodificar la URL: ' OR 1=1 y UNION SELECT para SQLi, <script> para XSS, ../ para traversal, y ; o | para inyección de comandos. Una respuesta 200 con un tamaño anormal sugiere éxito.

Comprueba lo que sabes

¿Qué indica una entrada de log que contiene %2e%2e%2f%2e%2e%2fetc%2fpasswd?

Un intento de directory traversal, ya que %2e%2e%2f se decodifica como ../ y el objetivo es el archivo passwd de Linux.

¿Por qué una cuenta de administrador nueva creada a las 3 a. m. sin ticket de cambio es un indicador de compromiso?

Los atacantes crean cuentas privilegiadas para tener persistencia, y una creada fuera de los procesos y horarios normales probablemente no está autorizada.

¿Una cadena de inyección en un log prueba que el ataque tuvo éxito?

No. Muestra un intento; revisas los códigos de estado, los tamaños de respuesta y la actividad posterior para juzgar el éxito.
