CompTIA CySA+ CS0-004

Controles compensatorios, segmentación y excepciones para sistemas que no se pueden parchar

A veces la corrección adecuada para una vulnerabilidad no se puede aplicar. Un dispositivo médico puede estar certificado solo con una versión específica del sistema operativo, un controlador industrial puede necesitar una parada de planta para actualizarse, un fabricante puede haber dejado de dar soporte a un producto, o un parche puede romper una aplicación crítica. En estos casos igual tienes que gestionar el riesgo, y CySA+ evalúa cómo hacerlo.

Un control compensatorio es una salvaguarda alternativa que reduce el riesgo cuando el control principal no es viable. Debe abordar la misma amenaza, ofrecer un nivel de protección comparable y estar documentado. Algunos ejemplos son restringir el acceso de red al servicio vulnerable, deshabilitar la funcionalidad vulnerable, agregar una firma a un sistema de prevención de intrusiones (IPS) o una regla a un web application firewall (WAF) para bloquear patrones de exploit conocidos, exigir una autenticación más fuerte delante del sistema, usar allow listing de aplicaciones para que solo se ejecute software aprobado, y aumentar el monitoreo con alertas específicas para intentos de explotación.

La segmentación es uno de los controles compensatorios más eficaces. Ubica los sistemas que no se pueden parchar en su propio segmento de red o VLAN, permite mediante reglas de firewall solo las conexiones específicas que necesitan (por ejemplo, una estación de administración en un puerto) y bloquea por completo el acceso a internet cuando sea posible. Un sistema aislado puede seguir siendo vulnerable, pero muchos menos atacantes pueden alcanzarlo. El air gapping, la separación física total de otras redes, es la forma extrema y se usa en algunos entornos OT y clasificados, aunque los medios extraíbles y las laptops de mantenimiento todavía pueden cruzar esa brecha.

Cuando una vulnerabilidad va a permanecer, las organizaciones usan un proceso formal de excepción (a veces llamado excepción de riesgo o waiver). Una buena excepción registra la vulnerabilidad y los sistemas afectados, por qué no puede remediarse, los controles compensatorios implementados, el riesgo residual, quién es dueño de ese riesgo y lo aceptó (un dueño del negocio con autoridad, no el analista) y una fecha de vencimiento o revisión. Las excepciones nunca deberían ser permanentes por defecto; las circunstancias cambian, y un parche o un reemplazo puede volverse posible.

Tu papel como analista es identificar los sistemas que no se pueden parchar, recomendar controles compensatorios adecuados, verificar que esos controles realmente funcionen (por ejemplo, confirmando que las reglas de firewall bloquean el acceso desde las redes de usuarios) y asegurarte de que la excepción se registre y se revise. Los escáneres deben configurarse para anotar las excepciones aceptadas y así no generar tickets duplicados sin fin, sin dejar de reportar si la situación empeora, por ejemplo si aparece un nuevo exploit.

A largo plazo, el objetivo suele ser reemplazar o actualizar el sistema. Incluye los sistemas al final de su vida útil en el presupuesto y la planificación para que los controles compensatorios sigan siendo un puente y no una muleta permanente.

Términos clave

Compensating control (control compensatorio)
Una salvaguarda alternativa que ofrece una reducción de riesgo comparable cuando el control principal no puede implementarse.
Risk exception (excepción de riesgo)
Una decisión documentada y aprobada de permitir que una vulnerabilidad conocida permanezca temporalmente, con justificación y controles.
Air gap (aislamiento físico)
Aislamiento físico de un sistema o red respecto de otras redes, incluida internet.
Virtual patching (parcheo virtual)
Bloquear la explotación de una vulnerabilidad con un control de red como una regla de IPS o WAF en lugar de cambiar el software.
Ejemplo real

Una estación de trabajo de resonancia magnética de un hospital ejecuta un sistema operativo sin soporte porque el fabricante no ha certificado una actualización. El equipo de seguridad la traslada a una VLAN dedicada a la que solo puede llegar el servidor de imágenes, bloquea el acceso a internet, aplica allow listing de aplicaciones y agrega alertas para cualquier conexión nueva. El jefe del departamento firma una excepción de riesgo que vence en doce meses, a la espera de una actualización del fabricante.

Consejo para el examen: Cuando una pregunta dice que un sistema no se puede parchar, busca la segmentación u otro control compensatorio más una excepción documentada; respuestas como simplemente ignorarlo o desconectar un sistema crítico suelen ser incorrectas.

Comprueba lo que sabes

¿Qué hace que un control sea un control compensatorio válido?

Aborda el mismo riesgo con una protección comparable cuando el control original no puede implementarse, y está documentado.

¿Qué debe incluir el registro de una excepción de riesgo?

La vulnerabilidad y los sistemas, la justificación, los controles compensatorios, el riesgo residual, la aprobación del dueño del riesgo responsable y una fecha de vencimiento o revisión.

¿Por qué la segmentación es eficaz para los sistemas que no se pueden parchar?

Limita drásticamente quién puede alcanzar el sistema vulnerable, lo que reduce la probabilidad de explotación.
