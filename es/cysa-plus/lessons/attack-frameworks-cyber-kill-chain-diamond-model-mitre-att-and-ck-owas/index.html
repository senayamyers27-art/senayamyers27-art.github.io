CompTIA CySA+ CS0-004

Frameworks de ataque: Cyber Kill Chain, Diamond Model, MITRE ATT&CK, OWASP Testing Guide, OSSTMM

Los frameworks de ataque dan a los analistas un vocabulario común para describir cómo se desarrollan los ataques y una estructura para encontrar brechas en las defensas. En lugar de decir que el atacante entró e hizo cosas malas, puedes indicar a qué fase o táctica pertenece cada acción, comparar incidentes y verificar si tus detecciones cubren cada etapa. CySA+ espera que sepas qué modela cada framework, en qué se diferencian y cuándo recurrirías a cada uno.

La Cyber Kill Chain de Lockheed Martin describe una intrusión como siete fases secuenciales: reconocimiento (reconnaissance, investigar al objetivo), armamentización (weaponization, combinar un exploit con una carga útil), entrega (delivery, enviarlo, por ejemplo por correo electrónico o mediante un enlace malicioso), explotación (exploitation, activar la vulnerabilidad), instalación (installation, establecer malware o persistencia), comando y control, a menudo abreviado C2 (un canal remoto de regreso al atacante), y acciones sobre los objetivos (actions on objectives, robo de datos, destrucción o ransomware). La idea clave es que romper cualquier eslabón detiene el ataque, por lo que los defensores asignan controles a cada fase, idealmente deteniendo los ataques lo antes posible. Su limitación es que es lineal y está centrada en intrusiones perimetrales basadas en malware, por lo que se ajusta peor a las amenazas internas, al abuso de la nube y a los ataques que solo usan credenciales válidas.

El Diamond Model of Intrusion Analysis (modelo de diamante) describe cada evento de intrusión con cuatro características centrales en las esquinas de un diamante: adversario (adversary), capacidad (capability, herramientas y malware), infraestructura (infrastructure, direcciones IP, dominios y servidores utilizados) y víctima (victim). Las aristas conectan características relacionadas, de modo que si conoces una pieza de infraestructura puedes pivotar para encontrar otras víctimas o capacidades vinculadas a ella. Las metacaracterísticas incluyen marca de tiempo, fase, resultado, dirección, metodología y recursos. Los analistas lo usan para vincular eventos en hilos de actividad, agrupar intrusiones relacionadas y apoyar la atribución de campañas.

MITRE ATT&CK (Adversarial Tactics, Techniques and Common Knowledge) es una base de conocimiento amplia y actualizada regularmente sobre el comportamiento real de los adversarios. Está organizada como una matriz: las columnas son tácticas (los objetivos del adversario, como acceso inicial, ejecución, persistencia, escalamiento de privilegios, evasión de defensas, acceso a credenciales, descubrimiento, movimiento lateral, recolección, comando y control, exfiltración e impacto), y las celdas son técnicas y subtécnicas con identificadores como T1053 para tarea o trabajo programado. Cada entrada incluye ejemplos de procedimientos, ideas de detección y mitigaciones. Los analistas usan ATT&CK para mapear detecciones y encontrar brechas de cobertura, planificar cacerías de amenazas (threat hunts), describir incidentes con precisión y emular adversarios en pruebas. Existen matrices separadas para empresas, dispositivos móviles y sistemas de control industrial (ICS). A diferencia de la Kill Chain, las tácticas de ATT&CK no son una secuencia estricta; los atacantes se mueven libremente entre ellas.

En este objetivo también aparecen dos metodologías de prueba. La OWASP Web Security Testing Guide, del Open Worldwide Application Security Project, es una metodología detallada para probar aplicaciones web que agrupa las pruebas en áreas como recopilación de información, configuración, gestión de identidades, autenticación, autorización, gestión de sesiones, validación de entradas, manejo de errores, criptografía, lógica de negocio y pruebas del lado del cliente. El Open Source Security Testing Methodology Manual (OSSTMM), de ISECOM, es una metodología revisada por pares para probar la seguridad operacional de forma amplia, que abarca los canales humano, físico, inalámbrico, de telecomunicaciones y de redes de datos, con énfasis en resultados medibles y repetibles.

Considera un ejemplo práctico. Después de un incidente de phishing, lo mapeas a ATT&CK: un adjunto de spearphishing para el acceso inicial, ejecución por parte del usuario, una clave Run del registro para la persistencia y protocolos web sobre HTTPS para el C2. Comparar ese mapa con las reglas de tu SIEM (security information and event management) revela que no hay detección para cambios en las claves Run, así que agregas una regla basada en la telemetría de endpoints. Usando el Diamond Model, pivotas desde el dominio de C2 (infraestructura) y descubres dos eventos anteriores contra otros departamentos que usaron el mismo dominio. Para la presentación a la dirección, describes el ataque con las fases de la Kill Chain porque la historia lineal es fácil de seguir.

Errores comunes: tratar ATT&CK como una secuencia de pasos igual que la Kill Chain; confundir la esquina de capacidad del Diamond Model (herramientas) con la infraestructura (desde dónde se alojaron o controlaron las herramientas); suponer que la Kill Chain cubre bien las amenazas internas; y confundir OWASP, que trata sobre aplicaciones web, con OSSTMM, que trata sobre pruebas de seguridad operacional en muchos canales. Recuerda también que los frameworks describen y organizan; no son herramientas de detección en sí mismos.

La redacción del examen suele delatar el framework. Siete fases lineales, armamentización o romper la cadena apuntan a la Kill Chain. Adversario, capacidad, infraestructura y víctima, o pivotar entre ellos, apuntan al Diamond Model. Tácticas, técnicas, procedimientos, identificadores de técnicas, mapas de calor de cobertura de detección o emulación de adversarios apuntan a ATT&CK. Una metodología para probar una aplicación web apunta a la guía de pruebas de OWASP, y una metodología científica y amplia de pruebas de seguridad operacional apunta a OSSTMM.

Términos clave

Cyber Kill Chain
Modelo lineal de siete fases de Lockheed Martin para una intrusión, desde el reconocimiento hasta las acciones sobre los objetivos.
Diamond Model
Un modelo de análisis de intrusiones que vincula adversario, capacidad, infraestructura y víctima en cada evento.
MITRE ATT&CK
Una base de conocimiento de tácticas y técnicas de adversarios que se usa para mapear detecciones, cacerías e incidentes.
Táctica (tactic)
En ATT&CK, el objetivo del adversario en un punto del ataque, como la persistencia o el movimiento lateral.
Técnica (technique)
En ATT&CK, una forma específica en que un adversario logra una táctica, identificada con un ID como T1053.
OWASP Web Security Testing Guide
Una metodología para probar la seguridad de aplicaciones web en áreas como autenticación y validación de entradas.
OSSTMM
Una metodología revisada por pares para pruebas medibles de seguridad operacional en los canales humano, físico, inalámbrico y de red.
Ejemplo real

Un SOC construye un mapa de calor de cobertura de ATT&CK etiquetando cada regla del SIEM y del EDR con su ID de técnica. El mapa muestra una buena cobertura de ejecución y C2, pero casi nada para acceso a credenciales. El equipo prioriza nuevas detecciones para el volcado de credenciales y programa un ejercicio de purple team que emula las técnicas de acceso a credenciales de un grupo de amenazas conocido para validarlas.

Consejo para el examen: Fases lineales significa Kill Chain; cuatro esquinas y pivoteo significa Diamond Model; tácticas e IDs de técnicas significa ATT&CK. OWASP es para aplicaciones web, OSSTMM es para pruebas amplias de seguridad operacional.

Comprueba lo que sabes

Un analista vincula el dominio de un atacante con otras dos víctimas pivotando desde la infraestructura. ¿Qué framework se está usando?

El Diamond Model, que conecta adversario, capacidad, infraestructura y víctima para que los analistas puedan pivotar entre ellos.

¿Cuál es una limitación clave de la Cyber Kill Chain?

Es lineal y está centrada en el malware y el perímetro, por lo que se ajusta mal a las amenazas internas y a los ataques en la nube o que solo usan credenciales.

Quieres encontrar brechas en la cobertura de detección por técnica. ¿Qué framework se ajusta mejor?

MITRE ATT&CK, porque sus tácticas e IDs de técnicas te permiten mapear cada detección y ver las técnicas no cubiertas.

¿Qué metodología elegirías para planificar una evaluación de una aplicación web?

La OWASP Web Security Testing Guide, ya que está diseñada específicamente para probar aplicaciones web.
