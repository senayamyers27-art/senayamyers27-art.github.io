CompTIA CySA+ CS0-004

Registro de eventos: ingesta de logs, sincronización de tiempo (NTP), niveles de log, Event IDs de Windows, Sysmon, logs de autenticación de Linux

Los logs son la evidencia principal del analista. Si un sistema no registra un evento, o el log nunca llega a tu plataforma central, no puedes detectarlo ni investigarlo. CySA+ espera que sepas cómo se recolectan los logs, por qué sus marcas de tiempo deben coincidir y qué eventos específicos importan.

La ingesta de logs es el proceso de recolectar logs de las fuentes (servidores, firewalls, endpoints, servicios en la nube) y llevarlos a un almacén central como un SIEM. Las fuentes pueden enviar eventos mediante syslog, agentes o reenviadores (forwarders), o la plataforma puede extraerlos mediante APIs. Durante la ingesta, los logs se analizan y se normalizan para que campos como la IP de origen y el nombre de usuario signifiquen lo mismo entre distintos fabricantes. Centralizar los logs también los protege, porque un atacante que borra los logs locales no puede eliminar fácilmente la copia que ya se envió a otro lugar.

La sincronización de tiempo es esencial para la correlación. Si un firewall está tres minutos adelantado respecto a un controlador de dominio, una línea de tiempo construida con ambos mostrará los eventos en el orden equivocado. El Network Time Protocol (NTP) mantiene los relojes alineados con una fuente de tiempo confiable, y la buena práctica es registrar las marcas de tiempo en UTC (Tiempo Universal Coordinado) o con un desfase de zona horaria explícito. Syslog también define niveles de severidad del 0 al 7: emergency, alert, critical, error, warning, notice, informational y debug. Los números más bajos son más severos. Registrar solo las severidades altas ahorra almacenamiento pero puede ocultar detalles útiles; debug rara vez se deja activado en producción.

En Windows, el log de Security registra eventos clave por ID. Memoriza estos: 4624 inicio de sesión exitoso, 4625 inicio de sesión fallido, 4634 o 4647 cierre de sesión, 4648 inicio de sesión con credenciales explícitas, 4672 privilegios especiales asignados a un nuevo inicio de sesión (un inicio de sesión con nivel de administrador), 4688 nuevo proceso creado, 4720 cuenta de usuario creada, 4728 o 4732 miembro agregado a un grupo de seguridad, 4740 cuenta bloqueada, 7045 nuevo servicio instalado (log de System) y 1102 log de auditoría borrado. Una ráfaga de eventos 4625 seguida de un 4624 sugiere un ataque exitoso de adivinación de contraseñas; un 1102 siempre vale la pena investigarlo.

Sysmon (System Monitor) es una herramienta gratuita de Microsoft Sysinternals que agrega telemetría de endpoint mucho más rica al registro de eventos de Windows. Su event ID 1 registra la creación de procesos con la línea de comandos, hashes y proceso padre; el ID 3 registra conexiones de red; el ID 7 cargas de imágenes; el ID 8 CreateRemoteThread; el ID 10 acceso a procesos (por ejemplo, una herramienta que lee la memoria de LSASS); el ID 11 creación de archivos; los IDs 12 a 14 eventos del registro; y el ID 22 consultas DNS. Tú controlas lo que registra con un archivo de configuración XML.

En Linux, los eventos de autenticación van a /var/log/auth.log en Debian y Ubuntu o a /var/log/secure en sistemas de la familia Red Hat, y en hosts con systemd también puedes consultar el journal con journalctl. Busca líneas como Failed password for invalid user de sshd, Accepted publickey y entradas de sudo que muestran qué comando ejecutó un usuario como root. Los comandos last y lastb resumen los inicios de sesión exitosos y fallidos.

Términos clave

NTP
Network Time Protocol: sincroniza los relojes de los sistemas para que las marcas de tiempo de distintos dispositivos puedan correlacionarse con precisión.
Normalization (normalización)
Convertir logs de distintos formatos a nombres de campos y estructuras comunes durante la ingesta.
Event ID 4625
Evento del log de Security de Windows que registra un intento fallido de inicio de sesión.
Sysmon
Un servicio de Sysinternals que registra actividad detallada de procesos, red, archivos y registro en el registro de eventos de Windows.
auth.log / secure
Archivos de log de Linux que registran la actividad de autenticación, como inicios de sesión SSH y el uso de sudo.
Ejemplo real

Durante una investigación de password spraying, un analista encuentra cientos de eventos 4625 en muchas cuentas desde una misma IP, y luego un 4624 con logon type 10 (interactivo remoto) para una cuenta. Como el reloj del equipo VPN no usaba NTP, sus entradas estaban desfasadas ocho minutos, y el analista tuvo que corregir eso antes de demostrar que la sesión VPN provenía de la misma IP.

Consejo para el examen: Espera preguntas que te den un event ID y te pregunten qué ocurrió. 4624 éxito, 4625 fallo, 4688 creación de proceso, 4720 cuenta creada, 1102 log borrado, y en Sysmon el 1 creación de proceso y el 3 conexión de red son los más evaluados.

Comprueba lo que sabes

¿Por qué es importante NTP para la investigación de incidentes?

Mantiene los relojes consistentes para que los eventos de distintos sistemas puedan correlacionarse en una línea de tiempo precisa.

¿Qué event ID de Windows indica que se borró el log de auditoría de Security?

El event ID 1102, que a menudo señala que un atacante está borrando sus huellas.

¿Dónde buscarías fallos de inicio de sesión SSH en un servidor Ubuntu?

En /var/log/auth.log (o mediante journalctl para el servicio ssh).
