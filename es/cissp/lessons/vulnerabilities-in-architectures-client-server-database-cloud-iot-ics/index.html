ISC2 CISSP 2024 outline

Vulnerabilidades en arquitecturas: cliente, servidor, base de datos, nube, IoT, ICS/OT, virtualización, contenedores y serverless

Toda arquitectura tiene puntos débiles característicos. El examen describe un entorno y espera que reconozcas sus vulnerabilidades típicas y las mitigaciones correspondientes. La lección de fondo es entender dónde reside la confianza y dónde los atacantes pueden abusar de ella.

Los sistemas basados en el cliente, como los equipos de escritorio, los navegadores y las apps móviles, enfrentan descargas maliciosas, software sin parches, almacenamiento local inseguro de datos en caché y applets o scripts que se ejecutan con demasiados privilegios. Las mitigaciones incluyen aplicar parches, protección de endpoints, listas de aplicaciones permitidas (allow-listing) y nunca confiar solo en la validación del lado del cliente. Los sistemas basados en servidor enfrentan servicios expuestos, configuraciones incorrectas y problemas de control del flujo de datos; endurécelos, minimiza sus servicios y monitoréalos.

Las bases de datos tienen problemas específicos. La agregación (aggregation) consiste en combinar datos individualmente poco sensibles para revelar algo más sensible. La inferencia (inference) consiste en deducir información sensible a partir de datos que tienes permitido ver. Las contramedidas incluyen la poliinstanciación (polyinstantiation: mantener varios registros en distintos niveles de clasificación para que los usuarios con menor autorización no puedan inferir los datos ocultos), la supresión de celdas, el ruido y la perturbación, y las vistas de base de datos que restringen lo que ven los usuarios. Los ataques de inyección y los privilegios excesivos son fallas técnicas comunes.

Los sistemas en la nube trasladan parte de la responsabilidad a los proveedores según un modelo de responsabilidad compartida: el proveedor protege la infraestructura subyacente, mientras que el cliente protege lo que configura, como identidades, datos y configuraciones de acceso. Las fallas más comunes en la nube son configuraciones incorrectas del cliente, como almacenamiento expuesto públicamente, permisos demasiado amplios y claves de acceso filtradas. La multitenencia (multi-tenancy) añade el riesgo de fallas de aislamiento entre clientes. Los sistemas distribuidos y los sistemas paralelos a gran escala añaden complejidad en la consistencia de datos y la confianza entre nodos.

Los dispositivos de Internet de las cosas (IoT) suelen tener credenciales predeterminadas débiles, aplicación limitada de parches, comunicaciones inseguras y largas vidas útiles. Los sistemas de control industrial y la tecnología operativa (ICS/OT), como los sistemas SCADA, los controladores lógicos programables (PLC) y los sistemas de control distribuido, priorizan la disponibilidad y la seguridad física de las personas, usan protocolos heredados diseñados sin autenticación y no pueden parcharse ni reiniciarse fácilmente. Las mitigaciones incluyen la segmentación de red (mantener OT separada de TI), un control estricto del acceso remoto, el monitoreo pasivo y los controles compensatorios. Los sistemas embebidos comparten muchas de estas preocupaciones.

Los sistemas virtualizados dependen del hipervisor para el aislamiento. Los riesgos incluyen el escape de máquina virtual (VM escape: salir de un invitado para llegar al host o a otros invitados), la proliferación de VM (VM sprawl: máquinas virtuales no gestionadas y sin parches) y las interfaces de administración débiles. Los contenedores comparten el kernel del host, así que una falla del kernel o un contenedor privilegiado puede afectar a todo; los riesgos también incluyen imágenes vulnerables o no confiables, secretos incrustados en las imágenes y una orquestación demasiado permisiva. Las mitigaciones incluyen imágenes mínimas y confiables, el escaneo de imágenes, ejecutar como usuario no root y aislar las cargas de trabajo. Serverless (función como servicio) elimina la gestión de servidores, pero introduce riesgos como roles de funciones con privilegios excesivos, inyección mediante datos de eventos, dependencias inseguras y menor visibilidad para el monitoreo.

Los microservicios, la computación de alto rendimiento y la computación en el borde (edge) o en la niebla (fog) también aparecen en el temario. Los hilos comunes son: entender los límites de confianza, minimizar los privilegios, endurecer las configuraciones y mantener la visibilidad mediante registros y monitoreo.

Términos clave

Aggregation (agregación)
Combinar datos individualmente menos sensibles para derivar información de mayor sensibilidad.
Inference (inferencia)
Deducir información sensible a partir de datos a los que un usuario está autorizado a acceder.
Polyinstantiation (poliinstanciación)
Almacenar varias versiones de un registro en distintos niveles de clasificación para evitar la inferencia.
VM escape (escape de máquina virtual)
Un ataque en el que el código de una máquina virtual sale de ella para acceder al hipervisor o a otros invitados.
Shared responsibility model (modelo de responsabilidad compartida)
La división de las tareas de seguridad entre un proveedor de nube y su cliente, que varía según el modelo de servicio.
Ejemplo real

Una empresa de manufactura conecta los PLC de su fábrica a la red corporativa para generar reportes. Una revisión de riesgos descubre que los controladores usan un protocolo heredado sin autenticación y no pueden parcharse rápidamente, así que el equipo los coloca detrás de un firewall industrial en una zona separada, permite solo flujos de datos unidireccionales hacia un servidor de reportes y añade monitoreo pasivo de la red.

Consejo para el examen: Para ICS/OT, el examen favorece la segmentación y los controles seguros para la disponibilidad por encima de los parches o el escaneo activo. Para la nube, recuerda que la configuración incorrecta del cliente es la falla más común bajo la responsabilidad compartida.

Comprueba lo que sabes

¿Qué contramedida de bases de datos impide que los usuarios con menor autorización infieran la existencia de datos clasificados?

La poliinstanciación, que mantiene distintas versiones de los registros para distintos niveles de clasificación.

¿Por qué una vulnerabilidad del kernel puede afectar a todos los contenedores de un host?

Los contenedores comparten el kernel del sistema operativo del host, a diferencia de las máquinas virtuales, que tienen sus propios kernels.
