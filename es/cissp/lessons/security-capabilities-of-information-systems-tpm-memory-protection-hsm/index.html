Capacidades de seguridad de los sistemas de información: TPM, protección de memoria y HSM

El hardware y los sistemas operativos modernos incluyen capacidades de seguridad integradas que el software por sí solo no puede proporcionar. El examen CISSP espera que sepas qué hace cada una y cuándo usarla. Varias de estas capacidades se basan en la idea de una raíz de confianza en hardware (hardware root of trust): un componente pequeño y confiable sobre cuya integridad se construye todo lo demás.

Un Trusted Platform Module (TPM) es un criptoprocesador seguro, normalmente un chip en la tarjeta madre o firmware integrado en el procesador. Genera y almacena claves que no pueden extraerse fácilmente, y registra mediciones (hashes) de los componentes de arranque en los registros de configuración de la plataforma (platform configuration registers). Esto permite el arranque medido (measured boot) y la atestación remota (remote attestation), en la que un sistema demuestra a otra parte qué software arrancó. Un TPM puede sellar (seal) una clave para que solo se libere si las mediciones de arranque coinciden con los valores esperados, y así es como las herramientas de cifrado de disco completo pueden proteger una unidad: si la cadena de arranque fue manipulada, la clave no se libera. Un TPM está vinculado a un solo dispositivo.

Un módulo de seguridad de hardware (HSM) es un dispositivo dedicado y resistente a la manipulación, a menudo un appliance de red o una tarjeta de expansión, que genera, almacena y usa claves criptográficas con alto rendimiento para muchas aplicaciones. Las autoridades de certificación, los sistemas de pago y los servicios de gestión de claves usan HSM para que las claves privadas nunca salgan en texto claro del hardware protegido. Los HSM a menudo se validan conforme a estándares como FIPS 140, y los proveedores de nube ofrecen servicios de claves respaldados por HSM. La distinción clave: un TPM protege una computadora; un HSM sirve claves para muchos sistemas y aplicaciones.

La protección de memoria impide que los procesos interfieran entre sí y con el sistema operativo. Las técnicas incluyen el aislamiento de procesos, en el que cada proceso tiene su propio espacio de direcciones virtuales; los anillos de protección (protection rings), en los que el kernel se ejecuta en el anillo más privilegiado (ring 0) y las aplicaciones en un anillo menos privilegiado (ring 3); la prevención de ejecución de datos (data execution prevention), que marca áreas de memoria como no ejecutables para que los datos inyectados no puedan ejecutarse como código; y la aleatorización del diseño del espacio de direcciones (ASLR), que aleatoriza dónde se cargan el código y los datos, lo que dificulta explotar de forma confiable los ataques de corrupción de memoria.

En el mismo objetivo aparecen otras capacidades. El arranque seguro (secure boot) verifica las firmas digitales de los componentes de arranque para que solo se cargue código confiable. Los entornos de ejecución confiables y los enclaves seguros aíslan el procesamiento sensible incluso del sistema operativo principal. La virtualización proporciona aislamiento entre sistemas invitados mediante el hipervisor. La base de computación confiable (TCB, trusted computing base) es el conjunto total de hardware, firmware y software que aplica la seguridad; el monitor de referencia (reference monitor) es el concepto de un componente siempre invocado, a prueba de manipulaciones y verificable que media cada acceso, y el núcleo de seguridad (security kernel) es su implementación.

El cifrado, las interfaces y la tolerancia a fallos también cuentan como capacidades del sistema. Restringir las interfaces, como limitar qué opciones de menú ve un usuario, y construir redundancia para que las fallas no comprometan la seguridad se derivan de los principios de diseño vistos anteriormente.

Términos clave

Trusted Platform Module (TPM)
Un criptoprocesador seguro vinculado a un dispositivo que almacena claves y mediciones de arranque para el sellado y la atestación.
Hardware security module (HSM) (módulo de seguridad de hardware)
Un dispositivo resistente a la manipulación que genera, almacena y usa de forma segura claves criptográficas para muchas aplicaciones.
Reference monitor (monitor de referencia)
Un concepto abstracto de un componente que media todo acceso entre sujetos y objetos, es a prueba de manipulaciones y es verificable.
Address space layout randomization (ASLR) (aleatorización del espacio de direcciones)
Una protección de memoria que aleatoriza dónde se cargan el código y los datos para obstaculizar los exploits de corrupción de memoria.
Ejemplo real

Una empresa cifra sus laptops usando claves selladas en el TPM de cada dispositivo, de modo que si alguien manipula el cargador de arranque (bootloader), la unidad permanece bloqueada. Su autoridad de certificación interna guarda sus claves raíz y emisoras dentro de un HSM, para que ningún administrador pueda copiar la clave privada a un archivo.

Consejo para el examen: TPM equivale a un dispositivo, integridad del arranque y claves de disco selladas; HSM equivale a almacenamiento centralizado y de alto volumen de claves y operaciones criptográficas para muchas aplicaciones. El monitor de referencia debe ser a prueba de manipulaciones, invocarse siempre y ser lo bastante pequeño para verificarse.

Comprueba lo que sabes

¿Qué componente usaría una autoridad de certificación para proteger sus claves de firma?

Un módulo de seguridad de hardware (HSM), que mantiene las claves privadas en hardware resistente a la manipulación y realiza las operaciones de firma internamente.

¿Qué detiene la prevención de ejecución de datos?

Impide que se ejecute código en regiones de memoria marcadas como datos, lo que bloquea muchos ataques que inyectan código en buffers.
