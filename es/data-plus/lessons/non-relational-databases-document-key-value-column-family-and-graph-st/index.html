Bases de datos no relacionales: almacenes de documentos, clave-valor, familias de columnas y grafos

Las bases de datos no relacionales, a menudo llamadas bases de datos NoSQL, almacenan los datos en modelos distintos a las tablas relacionadas. Se hicieron populares para cargas de trabajo que necesitan un esquema flexible, una escala enorme repartida en muchos servidores o un modelo de datos que las tablas manejan con dificultad. Como analista quizá no las diseñes, pero necesitas reconocer cada tipo y saber qué problema resuelve, porque los datos que analizas pueden venir de una de ellas.

Un almacén de documentos (document store) guarda cada registro como un documento autocontenido, normalmente JSON o una forma binaria de JSON. Un documento de cliente puede contener los datos del cliente más un arreglo anidado de direcciones y preferencias, y distintos documentos de la misma colección pueden tener campos diferentes. Los almacenes de documentos son adecuados para catálogos de productos, gestión de contenidos y back ends de aplicaciones cuya forma cambia a menudo. MongoDB es un ejemplo conocido.

Un almacén clave-valor (key-value store) es el modelo más simple: guardas un valor bajo una clave única y lo recuperas por esa clave, muy rápidamente. A la base de datos no le importa qué hay dentro del valor. Los datos de sesión, los carritos de compra, las preferencias de usuario y las cachés son usos típicos. La desventaja es que no puedes consultar fácilmente por nada que no sea la clave, así que no es adecuado para análisis ad hoc.

Un almacén de familias de columnas (column-family o wide-column) organiza los datos en filas que pueden tener cada una un conjunto grande y variable de columnas agrupadas en familias, y distribuye los datos entre muchos nodos. Es adecuado para volúmenes de escritura muy altos, como lecturas de sensores, logs de eventos y series de tiempo a gran escala. Apache Cassandra y HBase son ejemplos. No lo confundas con el almacenamiento columnar de los data warehouses analíticos y los archivos Parquet, que guardan cada columna junta para acelerar las consultas de agregación.

Una base de datos de grafos (graph database) almacena nodos (entidades como personas o cuentas) y aristas (relaciones como sigue a, pagó a o conoce a), cada uno con propiedades. Las consultas que recorren relaciones de varios saltos, como amigos de amigos, redes de fraude o rutas de recomendación, son rápidas en un grafo, pero en SQL necesitan muchos self-joins. Cuando un escenario del examen enfatiza las relaciones entre entidades, piensa en grafos.

Los sistemas no relacionales a menudo sacrifican la consistencia estricta y los esquemas fijos a cambio de flexibilidad y escala. Cuando extraigas datos de ellos para analizarlos, espera tener que aplanar estructuras anidadas y manejar campos faltantes antes de cargarlos en tablas.

Términos clave

Document store (almacén de documentos)
Una base de datos NoSQL que almacena documentos autocontenidos, a menudo anidados y parecidos a JSON, con campos flexibles.
Key-value store (almacén clave-valor)
Una base de datos NoSQL que guarda y recupera valores mediante una clave única, optimizada para búsquedas rápidas.
Column-family store (almacén de familias de columnas)
Una base de datos NoSQL distribuida cuyas filas contienen conjuntos variables de columnas agrupadas en familias, adecuada para cargas de escritura intensas.
Graph database (base de datos de grafos)
Una base de datos que almacena nodos y relaciones como datos de primera clase, optimizada para recorrer conexiones.
Ejemplo real

Un comercio en línea guarda su catálogo de productos en un almacén de documentos porque cada tipo de producto tiene atributos diferentes, los carritos de compra en un almacén clave-valor para búsquedas en milisegundos, y una base de datos de grafos que vincula clientes, dispositivos y tarjetas de pago para que el equipo de fraude detecte una misma tarjeta usada en muchas cuentas sin relación entre sí.

Consejo para el examen: Relaciona la palabra clave con el tipo: registros JSON flexibles significa documentos; búsqueda solo por ID significa clave-valor; escrituras masivas de series de tiempo significa familias de columnas; relaciones y saltos significa grafos.

Comprueba lo que sabes

Un equipo necesita encontrar cuentas conectadas con un defraudador conocido a través de dispositivos compartidos hasta tres pasos de distancia. ¿Qué tipo de base de datos es adecuado?

Una base de datos de grafos, porque almacena las relaciones directamente y recorre varios saltos de manera eficiente.

¿Por qué un almacén clave-valor es una mala fuente para análisis ad hoc?

Solo puedes recuperar valores por clave, así que filtrar o agregar según el contenido de los valores requiere extraer primero todos los datos.
