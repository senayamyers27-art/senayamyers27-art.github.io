CompTIA Data+ DA0-002

Escribir consultas SQL: SELECT, WHERE, ORDER BY, GROUP BY y HAVING

SQL es la habilidad práctica más importante para Data+. Debes poder leer una consulta, predecir su resultado y detectar errores. Las cláusulas principales se escriben en un orden pero se procesan en otro, y esa diferencia explica la mayoría de los errores.

SELECT enumera las columnas o expresiones que quieres, y FROM indica la tabla. WHERE filtra filas individuales con condiciones como amount > 100, region = 'West', order_date BETWEEN '2025-01-01' AND '2025-03-31', status IN ('Open','Pending'), name LIKE 'Sm%' y email IS NULL. Recuerda que NULL significa desconocido: = NULL nunca coincide, así que debes usar IS NULL o IS NOT NULL. DISTINCT elimina las filas duplicadas del resultado, y AS le da un alias a una columna.

GROUP BY agrupa las filas que comparten valores en una sola fila por grupo, y las funciones de agregación resumen cada grupo: COUNT, SUM, AVG, MIN y MAX. Cada columna seleccionada debe estar en el GROUP BY o dentro de una función de agregación. COUNT(*) cuenta filas, mientras que COUNT(column) cuenta los valores no nulos de esa columna, y COUNT(DISTINCT column) cuenta los valores únicos.

HAVING filtra los grupos después de la agregación, así que es donde van las condiciones sobre agregados. WHERE no puede usar SUM ni COUNT porque se ejecuta antes de agrupar. ORDER BY ordena el resultado final, de forma ascendente por defecto o con DESC para orden descendente, y muchas bases de datos permiten añadir LIMIT (o TOP) para devolver solo las primeras filas.

SELECT region, COUNT(*) AS orders, SUM(amount) AS revenue
FROM orders
WHERE order_date >= '2025-01-01'
GROUP BY region
HAVING SUM(amount) > 100000
ORDER BY revenue DESC;

El orden lógico de procesamiento es FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY. Por eso un alias definido en SELECT normalmente se puede usar en ORDER BY pero no en WHERE. Cuando una consulta devuelva algo inesperado, recórrela en este orden: qué filas sobreviven al WHERE, cómo se agrupan, qué grupos sobreviven al HAVING y cómo se ordena el resultado. También verás expresiones CASE, que funcionan como una lógica si-entonces dentro de una consulta, por ejemplo CASE WHEN amount >= 1000 THEN 'Large' ELSE 'Small' END.

Términos clave

WHERE
Una cláusula que filtra filas individuales antes de agrupar.
GROUP BY
Una cláusula que combina en grupos las filas con los mismos valores para agregarlas.
HAVING
Una cláusula que filtra grupos después de la agregación, lo que permite condiciones sobre funciones de agregación.
Aggregate function (función de agregación)
Una función como COUNT, SUM, AVG, MIN o MAX que resume muchas filas en un solo valor.
Ejemplo real

Un gerente de ventas pide las regiones con más de 100,000 en ingresos este año, de mayor a menor. El primer borrador del analista ponía SUM(amount) > 100000 en la cláusula WHERE y daba un error; mover esa condición a HAVING después de GROUP BY region devolvió las tres regiones que cumplían, en el orden correcto.

Consejo para el examen: Una condición sobre una sola fila significa WHERE; una condición sobre un total, un conteo o un promedio significa HAVING. Las comparaciones con NULL necesitan IS NULL, nunca = NULL.

Comprueba lo que sabes

¿Cuál es la diferencia entre COUNT(*) y COUNT(email)?

COUNT(*) cuenta todas las filas; COUNT(email) cuenta solo las filas en las que email no es NULL.

¿Por qué no puedes escribir WHERE AVG(score) > 80?

WHERE se procesa antes de agrupar, cuando los agregados todavía no existen; usa HAVING AVG(score) > 80 después de GROUP BY.
