CompTIA Data+ DA0-002

Formatos de archivo: CSV, TSV, JSON, XML, Parquet, hojas de cálculo y archivos planos

Los datos se mueven entre sistemas en archivos con más frecuencia de lo que imaginas, y cada formato tiene costumbres que necesitas conocer. Elegir el formato correcto, o leerlo correctamente, evita columnas rotas, pérdida de precisión y consultas lentas.

Un archivo plano (flat file) es cualquier archivo simple que contiene registros sin las relaciones ni los índices de una base de datos, normalmente un registro por línea. CSV (valores separados por comas) es el archivo plano más común: cada línea es una fila y las comas separan los campos. Los campos que contienen comas se encierran entre comillas dobles, y una comilla dentro de un campo se duplica. TSV usa tabulaciones en lugar de comas, lo que evita conflictos con las comas del texto. Ambos son legibles por personas y compatibles con todo, pero no llevan tipos de datos. Cada valor es texto hasta que la herramienta que lo lee adivina, y así es como se estropean los ceros a la izquierda y las fechas. Fíjate en la codificación de caracteres (UTF-8 es la opción segura por defecto), el delimitador y si la primera fila es un encabezado.

Los archivos de ancho fijo (fixed-width) son otro formato plano, en el que cada campo ocupa posiciones de caracteres determinadas. Los sistemas mainframe y bancarios antiguos todavía los generan, y necesitas un documento de diseño (layout) para interpretarlos.

JSON (JavaScript Object Notation) representa objetos como pares clave-valor y arreglos entre llaves y corchetes. Es el formato habitual de las API web y admite anidamiento, así que un pedido puede contener una lista de artículos. XML usa etiquetas de apertura y cierre con atributos opcionales. Es más extenso que JSON, pero sigue siendo común en integraciones empresariales y configuración, y puede validarse contra un esquema (XSD). Ambos son semiestructurados y normalmente hay que aplanarlos para el análisis tabular.

Parquet es un formato binario columnar y comprimido diseñado para analítica. Guarda los valores de cada columna juntos, con sus tipos de datos, así que una consulta que necesita tres de cincuenta columnas lee solo esas tres, y los valores similares se comprimen bien. Parquet es común en data lakes y data warehouses en la nube. No puedes leerlo en un editor de texto, pero herramientas como pandas, Spark y los motores de los warehouses lo leen de forma nativa.

Las hojas de cálculo (XLSX) pueden contener varias hojas, fórmulas y formato. Son prácticas para compartir y para análisis pequeños, pero tienen límites de filas, y las celdas combinadas, las notas en el área de datos y los tipos inconsistentes las hacen poco confiables como fuente de datos. Expórtalas o límpialas hasta obtener una tabla ordenada antes de hacer un trabajo serio.

Términos clave

CSV
Comma-separated values (valores separados por comas): un archivo plano de texto con un registro por línea y campos delimitados por comas.
JSON
Un formato de texto de pares clave-valor y arreglos que admite anidamiento; común en las API.
Parquet
Un formato de archivo binario, columnar y comprimido, que guarda los tipos de datos y está hecho para consultas analíticas.
Delimiter (delimitador)
El carácter que separa los campos en un archivo plano, como una coma, una tabulación o una barra vertical (pipe).
Ejemplo real

Un ingeniero de datos recibe cada día una exportación CSV de 5 GB que tarda mucho en recorrerse. Convertirla a Parquet en el data lake reduce mucho el tamaño del archivo, conserva los tipos de columna y permite que las consultas de los analistas lean solo las columnas que usan, así que una consulta de ingresos mensuales termina en segundos.

Consejo para el examen: Columnar más comprimido más analítica significa Parquet. Datos anidados de una API significa JSON. Intercambio tabular simple, universal y sin tipos significa CSV.

Comprueba lo que sabes

Un campo de un CSV contiene el texto 'Portland, OR'. ¿Cómo debe escribirse para que no se divida en dos campos?

Encierra el campo entre comillas dobles: "Portland, OR".

¿Por qué Parquet es más rápido que CSV para una consulta que suma una columna?

Parquet guarda cada columna por separado y comprimida, así que el motor lee solo esa columna; un CSV debe leerse completo, fila por fila.
