Proceso de control de cambios: solicitudes de cambio, evaluación de impacto, comité de control de cambios, aprobación, implementación y comunicación de cambios

El cambio es normal en los proyectos: los requisitos se aclaran, las prioridades del negocio cambian y aparecen problemas. Lo importante es que los cambios estén controlados. El control de cambios es el proceso formal para proponer, evaluar, aprobar o rechazar y luego implementar cambios en las líneas base aprobadas del proyecto para alcance, cronograma y costo. Sin él, los pequeños cambios no registrados se acumulan y el proyecto se aleja de lo acordado.

El proceso suele seguir los mismos pasos. Primero, alguien identifica la necesidad y presenta una solicitud de cambio, una descripción escrita de qué debe cambiar y por qué. Segundo, el project manager la registra en el registro de cambios (change log) para poder darle seguimiento. Tercero, el project manager y el equipo realizan una evaluación de impacto: qué efecto tendrá el cambio en el alcance, el cronograma, el costo, la calidad, los recursos y el riesgo, y qué pasa si no se realiza. Cuarto, el cambio pasa a quien toma la decisión según el plan de gestión de cambios, a menudo un comité de control de cambios (CCB) integrado por el patrocinador y los interesados clave. El CCB lo aprueba, lo rechaza o lo pospone.

Si el cambio se aprueba, el project manager actualiza las líneas base y los documentos afectados (enunciado del alcance, WBS, cronograma, presupuesto, registro de riesgos) y luego implementa el cambio como cualquier otro trabajo. Por último, la decisión se comunica a todos los afectados, incluida la persona que la solicitó. Los cambios rechazados y pospuestos también se registran, con el motivo, para que la misma solicitud no siga apareciendo una y otra vez.

Algunas organizaciones permiten que el project manager apruebe cambios pequeños dentro de tolerancias acordadas, por ejemplo hasta dos días o un monto pequeño en dólares, y envían los más grandes al CCB. El plan de gestión de cambios elaborado durante la planificación define estos umbrales, los formularios que se deben usar y quiénes integran el comité. Observa que el project manager rara vez aprueba solo los cambios significativos y nunca le dice simplemente al equipo que empiece a trabajar en una solicitud no aprobada.

Términos clave

Change request (solicitud de cambio)
Una propuesta formal para modificar el alcance, el cronograma, el costo u otra línea base del proyecto.
Impact assessment (evaluación de impacto)
El análisis de cómo un cambio propuesto afectaría el alcance, el cronograma, el costo, la calidad, los recursos y el riesgo.
Change control board (CCB) (comité de control de cambios)
El grupo autorizado para aprobar, rechazar o posponer las solicitudes de cambio del proyecto.
Change log (registro de cambios)
Un registro de cada solicitud de cambio con su estado, decisión y fecha.
Ejemplo real

Una gerente de marketing pide una nueva vista móvil en un proyecto de portal web. El project manager registra la solicitud en el change log, el equipo estima tres semanas adicionales y $12,000, y el CCB la aprueba. El project manager actualiza las líneas base del enunciado del alcance, el cronograma y el presupuesto, agrega el trabajo al plan y envía una actualización a todos los interesados explicando la nueva fecha de salida a producción (go-live).

Consejo para el examen: Cuando alguien pide un cambio, el primer paso casi nunca es «hacerlo» ni «rechazarlo». Es documentar la solicitud y evaluar su impacto. Después de la aprobación, el siguiente paso es actualizar las líneas base y comunicar.

Comprueba lo que sabes

¿Quién aprueba normalmente un cambio que afecta la línea base de costos más allá de la tolerancia del project manager?

El comité de control de cambios o la autoridad designada en el plan de gestión de cambios, que a menudo incluye al patrocinador.

Ayer se aprobó un cambio. ¿Qué dos cosas debe hacer el project manager antes o mientras el equipo lo implementa?

Actualizar las líneas base y los documentos del proyecto afectados, y comunicar la decisión a los interesados.
