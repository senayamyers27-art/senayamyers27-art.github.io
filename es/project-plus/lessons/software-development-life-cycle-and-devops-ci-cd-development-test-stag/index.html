CompTIA Project+ PK0-005

Ciclo de vida del desarrollo de software y DevOps: CI/CD, entornos de desarrollo, pruebas, staging y producción, y gestión de liberaciones

Cuando un proyecto construye o modifica software, sigue un ciclo de vida del desarrollo de software (SDLC). Una forma común tiene estas fases: planificación, análisis de requisitos, diseño, desarrollo (programación), pruebas, despliegue y mantenimiento. El SDLC puede ejecutarse en estilo cascada, completando cada fase antes de la siguiente, o de forma iterativa e incremental como en ágil, donde cada sprint incluye un poco de cada fase.

El software pasa por entornos separados para proteger a los usuarios reales. El entorno de desarrollo es donde los desarrolladores escriben el código y hacen pruebas unitarias. El entorno de pruebas o QA es donde los testers ejecutan pruebas funcionales, de integración y de regresión. El entorno de staging (preproducción) replica producción lo más fielmente posible y se usa para la validación final, las pruebas de rendimiento y las pruebas de aceptación del usuario (UAT). Producción es el entorno en vivo que usan los usuarios reales con datos reales. Mantenerlos separados evita que cambios no probados dañen el negocio, y el acceso a producción debe estar estrictamente controlado. Los entornos de prueba deben usar datos enmascarados o sintéticos, no datos personales reales.

DevOps es una cultura y un conjunto de prácticas que une desarrollo y operaciones para entregar cambios de forma más rápida y confiable. La integración continua (CI) significa que los desarrolladores fusionan el código en un repositorio compartido con frecuencia, y cada fusión dispara una compilación y pruebas automatizadas, de modo que los problemas se detectan temprano. La entrega continua (continuous delivery) significa que cada cambio que pasa el pipeline está listo para liberarse con una aprobación manual; el despliegue continuo (continuous deployment) lo libera automáticamente. La infraestructura como código, el monitoreo automatizado y los ciclos de retroalimentación rápidos son otras prácticas de DevOps. DevSecOps agrega la seguridad al pipeline, por ejemplo con el escaneo automatizado del código y de las dependencias.

La gestión de liberaciones (release management) planifica y controla cómo llegan los cambios a producción: qué entra en cada liberación, su número de versión, las notas de la versión, el calendario de despliegue, la decisión go/no-go, la comunicación a los usuarios y el plan de reversión. Incluso con automatización, las liberaciones a producción normalmente siguen pasando por el proceso de gestión de cambios de la organización. Las estrategias de despliegue como los despliegues por fases, los pilotos y los despliegues blue-green (cambiar el tráfico entre dos entornos idénticos) reducen el riesgo.

Términos clave

SDLC
Software development life cycle (ciclo de vida del desarrollo de software): planificación, requisitos, diseño, desarrollo, pruebas, despliegue y mantenimiento.
Continuous integration (CI) (integración continua)
Fusionar el código con frecuencia, con compilaciones y pruebas automatizadas en cada cambio.
Staging environment (entorno de staging)
Un entorno de preproducción que replica producción para las pruebas finales y la UAT.
Release management (gestión de liberaciones)
Planificar, programar y controlar el despliegue de las versiones de software a producción.
DevSecOps
Prácticas de DevOps con la seguridad integrada en el pipeline y en cada etapa de la entrega.
Ejemplo real

Un equipo que construye una aplicación de reservas ejecuta un pipeline de CI que compila y prueba cada commit. Las compilaciones que pasan se despliegan automáticamente en el entorno de pruebas. Al final de cada sprint, una versión candidata pasa a staging, donde los usuarios del negocio realizan la UAT. Después de que el comité asesor de cambios la aprueba, la versión se despliega en producción el martes por la noche con notas de la versión y un plan de reversión.

Consejo para el examen: La UAT ocurre en staging o en pruebas, nunca primero en producción. CI = compilación y pruebas automatizadas en cada commit. Los pipelines automatizados siguen pasando por la gestión de cambios para las liberaciones a producción.

Comprueba lo que sabes

¿Cuál es la diferencia entre la entrega continua y el despliegue continuo?

La entrega continua mantiene cada cambio aprobado por el pipeline listo para liberarse con una aprobación manual; el despliegue continuo lo libera a producción automáticamente.

¿Por qué staging debe replicar producción fielmente?

Para que las pruebas y la UAT revelen los mismos problemas que ocurrirían en producción, sin afectar a los usuarios reales.
