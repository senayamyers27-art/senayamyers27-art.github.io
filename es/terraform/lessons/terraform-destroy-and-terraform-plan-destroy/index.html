`terraform destroy` y `terraform plan -destroy`

terraform destroy elimina todos los objetos gestionados por la configuración y el estado actuales. Es la forma de desmontar un entorno temporal, limpiar después de un laboratorio o retirar un stack por completo. Como elimina infraestructura real, sigue el mismo patrón de seguridad que apply: muestra un plan de todo lo que se va a destruir y espera a que escribas yes.

terraform destroy es un alias práctico de terraform apply -destroy. Los dos se comportan igual. Ambos aceptan -auto-approve para omitir el aviso y opciones de planificación como -var y -var-file, que podrías necesitar si se requieren variables para evaluar la configuración. Ambos aceptan también -target, que destruye solo el recurso indicado y todo lo que depende de él, aunque el uso dirigido debería ser excepcional.

terraform plan -destroy crea un plan de destrucción especulativo: muestra lo que se eliminaría sin eliminar nada. Puedes guardarlo con -out y aplicarlo más tarde con terraform apply FILE, lo que le da a la destrucción el mismo patrón de revisar y luego aplicar que a los cambios normales. Esto es útil en pipelines que desmontan entornos de vista previa.

terraform plan -destroy -out=destroy.tfplan
terraform show destroy.tfplan
terraform apply destroy.tfplan

Destroy recorre el grafo de dependencias en sentido inverso. Si una instancia depende de una subred, que depende de una red, Terraform elimina primero la instancia, luego la subred y después la red. En los planes de destrucción, cada recurso se muestra con el símbolo -, y el resumen cuenta solo destrucciones. Los data sources no se destruyen, porque Terraform nunca los creó; solo se leen.

Destroy solo afecta a los objetos rastreados en el estado de esta configuración. Los recursos creados a mano, o gestionados por otra configuración con su propio estado, no se tocan. Por eso eliminar un archivo de estado no es una forma de proteger recursos ni de eliminarlos. Si quieres que desaparezca un solo recurso, el método habitual es simplemente quitar su bloque de la configuración y aplicar; Terraform planea destruirlo.

Protege los objetos críticos con lifecycle { prevent_destroy = true }. Cualquier plan que destruiría ese recurso, incluido terraform destroy, falla con un error. Es necesario quitar el ajuste del código antes de poder destruirlo, lo que obliga a hacer un cambio deliberado y revisado. Algunos providers también ofrecen sus propios argumentos de protección contra eliminación en recursos como las bases de datos.

Términos clave

terraform destroy
Comando que destruye todos los recursos gestionados por la configuración; es un alias de terraform apply -destroy.
plan -destroy
Crea un plan de destrucción para previsualizarlo, y opcionalmente guardarlo, sin destruir nada.
Reverse dependency order (orden inverso de dependencias)
Destroy elimina los dependientes antes que los objetos de los que dependen.
prevent_destroy
Ajuste de lifecycle que hace fallar cualquier plan que destruiría el recurso.
Ejemplo real

Cada pull request de un proyecto web obtiene un entorno de vista previa. Cuando el pull request se cierra, el pipeline ejecuta terraform plan -destroy -out=destroy.tfplan, registra el plan y lo aplica, eliminando de forma limpia los contenedores, el registro DNS y la base de datos de la vista previa.

Consejo para el examen: terraform destroy equivale a terraform apply -destroy. terraform plan -destroy solo previsualiza. Para eliminar un recurso en el trabajo normal, borra su bloque y aplica en lugar de usar destroy con -target.

Comprueba lo que sabes

¿Cuál es la diferencia entre terraform destroy y terraform plan -destroy?

Destroy (como apply -destroy) elimina los recursos después de la aprobación; plan -destroy solo muestra, y puede guardar, un plan de destrucción sin cambiar nada.

¿terraform destroy eliminará una máquina virtual que alguien creó en la consola y que no está en el estado?

No. Destroy solo afecta a los objetos rastreados en el estado de la configuración.
