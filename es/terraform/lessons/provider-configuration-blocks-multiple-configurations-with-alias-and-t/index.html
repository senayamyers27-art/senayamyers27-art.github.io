Bloques de configuración de providers, varias configuraciones con `alias` y el meta-argumento `provider`

Declarar un provider en required_providers le dice a Terraform qué instalar. Un bloque provider le dice cómo configurar ese provider: qué región o endpoint usar, qué cuenta o proyecto y, a veces, cómo autenticarse. Los bloques provider pertenecen al módulo raíz; los módulos hijos reutilizables normalmente no deben contenerlos y, en su lugar, reciben las configuraciones de quien los llama.

provider "aws" {
  region = "us-east-1"
}

provider "aws" {
  alias  = "west"
  region = "us-west-2"
}

El primer bloque es la configuración predeterminada del provider aws. Cualquier recurso de AWS que no indique otra cosa la usa. El segundo bloque es una configuración adicional que se distingue con alias. Puedes tener una predeterminada y tantas configuraciones con alias como necesites, para distintas regiones, cuentas o credenciales. Si solo tienes bloques con alias y ninguno predeterminado, los recursos que no especifican un provider recurren a una configuración predeterminada vacía, que puede fallar si faltan ajustes obligatorios.

Para elegir una configuración no predeterminada, usa el meta-argumento provider en un bloque resource o data, con la referencia <PROVIDER>.<ALIAS>, escrita como referencia sin comillas, no como una cadena entre comillas. Un meta-argumento es un argumento que interpreta el propio Terraform y que funciona en cualquier tipo de recurso, a diferencia de los argumentos específicos de cada provider.

resource "aws_s3_bucket" "replica" {
  provider = aws.west
  bucket   = "example-replica-bucket"
}

Para los módulos, pasas las configuraciones con el mapa providers en el bloque module, como providers = { aws = aws.west }. Un módulo que necesita más de una configuración del mismo provider declara los nombres adicionales con configuration_aliases dentro de su entrada de required_providers.

Las credenciales merecen cuidado. Los bloques provider pueden aceptar claves directamente, pero escribir secretos de forma fija en archivos .tf los pone en el control de versiones. Prefiere variables de entorno, archivos de credenciales compartidos, identidad de instancia o de carga de trabajo, o credenciales dinámicas de HCP Terraform o Vault. Los argumentos del provider pueden usar variables de entrada y datos de otras fuentes, pero los valores deben conocerse durante la planificación; una configuración de provider que depende de atributos que aún no se han creado puede causar problemas, así que mantén simples los ajustes del provider.

Las razones comunes para usar alias incluyen desplegar en varias regiones, gestionar recursos en varias cuentas con distintos roles asumidos y crear un recurso de DNS o certificado que debe vivir en una región específica mientras el resto del stack vive en otra.

Términos clave

provider block (bloque provider)
Configuración de un provider, como la región, el endpoint o los ajustes de autenticación, que normalmente se coloca en el módulo raíz.
alias
Un argumento que da nombre a una configuración adicional, no predeterminada, del mismo provider.
provider meta-argument (meta-argumento provider)
Un argumento en un bloque resource o data, como provider = aws.west, que selecciona una configuración específica del provider.
Meta-argument (meta-argumento)
Un argumento que maneja el propio Terraform y que puede usarse en cualquier tipo de recurso, como count, for_each, depends_on, provider y lifecycle.
Ejemplo real

Una empresa mantiene su aplicación en eu-west-1, pero debe crear un certificado en us-east-1 para su red de distribución de contenido. Agrega un segundo bloque provider aws con alias = "use1" y configura provider = aws.use1 solo en el recurso del certificado.

Consejo para el examen: La referencia es aws.west, no "aws.west" ni aws-west. Los recursos sin argumento provider usan la configuración predeterminada (sin alias).

Comprueba lo que sabes

¿Cómo creas dos configuraciones del mismo provider en un solo módulo?

Escribe dos bloques provider para él y dale a uno (o a más) un alias; el que no tiene alias es el predeterminado.

¿Cómo usa un recurso una configuración de provider no predeterminada?

Configurando el meta-argumento provider como <name>.<alias>, por ejemplo provider = google.europe.
