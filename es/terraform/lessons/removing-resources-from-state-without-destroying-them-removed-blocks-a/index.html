Eliminar recursos del estado sin destruirlos: bloques `removed` y `terraform state rm`

A veces quieres que Terraform deje de gestionar un objeto sin eliminarlo. Quizá otro equipo se hará cargo de una base de datos, el recurso se está trasladando a otra configuración de Terraform o se importó por error. Si simplemente eliminas el bloque resource, Terraform planeará destruir el objeto real, porque el estado todavía lo contiene y la configuración ya no. Necesitas en cambio una forma de olvidarlo.

La forma declarativa, agregada en Terraform 1.7, es el bloque removed. Tiene un argumento from que nombra la dirección del recurso (o módulo), y un bloque lifecycle cuyo argumento destroy decide qué ocurre. Con destroy = false, Terraform elimina el objeto del estado y deja intacta la infraestructura real. Al mismo tiempo, eliminas el bloque resource original.

removed {
  from = aws_instance.legacy

  lifecycle {
    destroy = false
  }
}

Como pasa por plan y apply, la eliminación se previsualiza (el plan dice que Terraform ya no gestionará el objeto, pero que no se destruirá), se revisa en un pull request y se aplica de forma consistente en cada entorno. Un bloque removed también puede apuntar a un módulo completo, como from = module.old_app. Configurar destroy = true en su lugar equivale a eliminar el bloque resource de forma normal: Terraform destruye el objeto. Los bloques removed también pueden llevar provisioners de tiempo de destrucción si necesitas una acción de limpieza.

La forma más antigua e imperativa es terraform state rm ADDRESS. Elimina la entrada del estado de inmediato, sin plan. Por ejemplo, terraform state rm aws_instance.legacy o terraform state rm module.old_app para un módulo completo. El objeto real sigue funcionando, y Terraform simplemente deja de saber de él. También debes eliminar el bloque resource de la configuración; de lo contrario, el siguiente plan intentará crear un objeto nuevo para esa dirección. Como otros comandos de estado, admite -dry-run, y con un backend local escribe un archivo de respaldo.

Un escenario común combina esto con la importación: para mover un recurso de la configuración A a la configuración B, elimínalo del estado de A (con un bloque removed o state rm) e impórtalo en B con un bloque import. Ten en cuenta que olvidar un objeto no lo elimina, así que los costos continúan; asegúrate de que alguien o algo más sea su dueño después.

Términos clave

removed block (bloque removed)
Un bloque de configuración que le dice a Terraform que deje de gestionar una dirección, destruyéndola o no según el destroy de lifecycle.
destroy = false
El ajuste de lifecycle del bloque removed que elimina el objeto del estado dejando la infraestructura real en su lugar.
terraform state rm
Un comando de la CLI que elimina de inmediato la entrada de un recurso del estado sin afectar al objeto real.
Unmanaged resource (recurso no gestionado)
Un objeto real que existe pero no está rastreado en ningún estado de Terraform.
Ejemplo real

El equipo de datos se hará cargo de un bucket de analítica que creó el equipo de plataforma. El equipo de plataforma elimina el bloque resource del bucket, agrega un bloque removed con destroy = false y aplica. Luego el equipo de datos agrega un bloque import para el mismo bucket en su propia configuración.

Consejo para el examen: Eliminar solo un bloque resource significa destruir. Para dejar de gestionar sin eliminar, usa un bloque removed con destroy = false o terraform state rm.

Comprueba lo que sabes

¿Qué pasa si eliminas un bloque resource y ejecutas terraform apply?

Terraform destruye el objeto real, porque todavía está en el estado pero ya no en la configuración.

¿Qué ajuste de lifecycle en un bloque removed conserva el objeto real?

destroy = false.
