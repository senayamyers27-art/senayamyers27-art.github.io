Dependencias explícitas con `depends_on`; reglas de `lifecycle`: `create_before_destroy`, `prevent_destroy`, `ignore_changes`, `replace_triggered_by`

La mayoría de las dependencias son implícitas, creadas por referencias. A veces un recurso depende de otro sin usar ninguno de sus atributos. El ejemplo clásico es una instancia cuya aplicación, al arrancar, llama a una API de la nube usando un rol; la instancia debe esperar a que se adjunte la política de permisos del rol, pero sus argumentos nunca referencian la política. depends_on declara explícitamente esa dependencia oculta.

resource "aws_instance" "app" {
  ami                  = var.ami_id
  instance_type        = "t3.small"
  iam_instance_profile = aws_iam_instance_profile.app.name
  depends_on           = [aws_iam_role_policy.app_s3]
}

depends_on recibe una lista de referencias a recursos, data sources o módulos, escritas como referencias sin comillas, no como cadenas. Funciona en recursos, data sources, módulos y outputs. Úsalo como último recurso y agrega un comentario que explique por qué: hace que Terraform planifique de forma más conservadora, ya que más valores pueden quedar desconocidos hasta el apply, y oculta a los lectores la verdadera razón de la dependencia.

El bloque lifecycle es un bloque de meta-argumento anidado que cambia cómo maneja Terraform los cambios de un recurso. Tiene cuatro ajustes en los que se centra el examen.

create_before_destroy = true invierte el orden de reemplazo predeterminado: el objeto nuevo se crea primero y el anterior se destruye después, lo que reduce el tiempo de inactividad. Requiere que el recurso permita dos copias a la vez, así que los nombres que deben ser únicos a menudo necesitan un sufijo generado. prevent_destroy = true hace que Terraform rechace cualquier plan que destruiría el recurso, incluidos los reemplazos y terraform destroy, lo que protege bases de datos y objetos similares de accidentes. Solo funciona mientras el bloque esté en el código; si alguien elimina todo el bloque del recurso, el ajuste se va con él y el recurso puede destruirse.

ignore_changes lista los atributos cuyas diferencias Terraform debe ignorar después de la creación, como etiquetas aplicadas por otro sistema o un número deseado ajustado por un autoscaler. Usa ignore_changes = all para ignorar todos los atributos, de modo que Terraform solo cree y destruya el objeto. replace_triggered_by lista referencias a otros recursos gestionados o a sus atributos; cuando cualquiera de ellos cambia o se reemplaza, este recurso también se reemplaza. Es la forma declarativa de decir reconstruye esta instancia cada vez que cambie ese archivo de configuración o esa plantilla.

lifecycle {
  create_before_destroy = true
  prevent_destroy       = true
  ignore_changes        = [tags["LastScanned"], desired_count]
  replace_triggered_by  = [terraform_data.app_version]
}

El bloque lifecycle también puede contener bloques precondition y postcondition para verificaciones personalizadas, que se cubren con las condiciones personalizadas. Los ajustes de lifecycle se procesan mientras Terraform construye el grafo de dependencias, así que create_before_destroy, prevent_destroy e ignore_changes solo aceptan valores literales, no variables de entrada ni expresiones calculadas.

Términos clave

depends_on
Meta-argumento que declara una dependencia explícita que ninguna referencia a un atributo expresa.
create_before_destroy
Ajuste de lifecycle que crea el objeto de reemplazo antes de destruir el anterior.
prevent_destroy
Ajuste de lifecycle que hace fallar con un error cualquier plan que destruya el recurso.
ignore_changes
Ajuste de lifecycle que lista los atributos cuyo drift Terraform no debe intentar corregir.
replace_triggered_by
Ajuste de lifecycle que reemplaza el recurso cuando cambian los recursos o atributos referenciados.
Ejemplo real

Un servicio de autoscaling cambia el desired_count de un servicio de contenedores a lo largo del día, y cada plan intenta restablecerlo. Agregar lifecycle { ignore_changes = [desired_count] } permite que el autoscaler sea dueño de ese valor mientras Terraform gestiona todo lo demás del servicio.

Consejo para el examen: Usa depends_on solo para dependencias ocultas. Recuerda que prevent_destroy no impide la destrucción si se elimina todo el bloque del recurso, y que los valores de lifecycle deben ser literales, no variables.

Comprueba lo que sabes

¿Cuándo deberías usar depends_on?

Solo cuando un recurso depende de otro de una forma que ninguna referencia a un atributo expresa, como una aplicación que necesita que primero exista una política de permisos.

¿Qué ajuste de lifecycle usarías para que Terraform deje de revertir las etiquetas que agrega otra herramienta?

ignore_changes, listando los atributos de etiquetas (o tags) que se deben ignorar.

¿Qué hace replace_triggered_by?

Fuerza el reemplazo del recurso cada vez que cambia cualquier recurso gestionado o atributo referenciado.
