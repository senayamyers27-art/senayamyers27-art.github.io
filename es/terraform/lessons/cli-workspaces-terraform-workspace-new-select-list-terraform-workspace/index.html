Workspaces de la CLI: `terraform workspace new/select/list` y `terraform.workspace`

Un workspace de la CLI permite que una configuración y un backend contengan varios estados independientes. Todo directorio de trabajo empieza en un workspace llamado default. Cuando creas otro workspace, Terraform inicia para él un estado separado y vacío, así que el mismo código puede gestionar una segunda copia de la infraestructura sin que las dos interfieran.

Los comandos son sencillos. terraform workspace new NAME crea un workspace y cambia a él. terraform workspace select NAME cambia a uno existente (las versiones más recientes también aceptan -or-create). terraform workspace list muestra todos los workspaces con un asterisco junto al actual, y terraform workspace show muestra solo el nombre del actual. terraform workspace delete NAME elimina un workspace; no puedes eliminar default ni el workspace en el que estás, y Terraform se niega a eliminar uno cuyo estado todavía rastrea recursos a menos que lo fuerces.

$ terraform workspace new dev
Created and switched to workspace "dev"!
$ terraform workspace list
  default
* dev

Dónde viven los estados depende del backend. Con el backend local, el workspace default usa terraform.tfstate, y los demás workspaces usan terraform.tfstate.d/NAME/terraform.tfstate. Los backends remotos que admiten workspaces guardan cada estado bajo una clave derivada; por ejemplo, el backend S3 usa un prefijo como env:/NAME/ delante de la key. No todos los backends admiten varios workspaces.

Dentro de la configuración, la expresión terraform.workspace devuelve el nombre del workspace actual. Puedes usarla para variar nombres y tamaños: name = "app-${terraform.workspace}" o instance_type = terraform.workspace == "prod" ? "m5.large" : "t3.micro". Esto ayuda a evitar colisiones de nombres cuando dos workspaces crean recursos similares.

Entiende los límites. Los workspaces de la CLI comparten el mismo código, el mismo backend y normalmente las mismas credenciales, así que no son una frontera fuerte entre entornos. Una persona con acceso al estado de dev normalmente tiene acceso al estado de prod, y es fácil ejecutar un comando en el workspace equivocado. HashiCorp recomienda los workspaces de la CLI para copias de corta duración, como probar un cambio, y directorios separados o backends separados (o workspaces de HCP Terraform) para entornos de larga duración que necesitan credenciales y controles de acceso distintos.

No confundas los workspaces de la CLI con los workspaces de HCP Terraform. Un workspace de HCP Terraform es un objeto mucho más completo, con sus propias variables, permisos e historial de ejecuciones, y se parece más a un directorio de trabajo separado que a un workspace de la CLI.

Términos clave

CLI workspace (workspace de la CLI)
Un estado separado y con nombre para la misma configuración y el mismo backend, gestionado con los comandos terraform workspace.
default workspace (workspace default)
El workspace en el que empieza toda configuración; no se puede eliminar.
terraform.workspace
Una expresión que devuelve el nombre del workspace actual para usarlo en la configuración.
terraform.tfstate.d
El directorio donde el backend local guarda el estado de los workspaces que no son default.
Ejemplo real

Un desarrollador quiere probar un cambio en un balanceador de carga sin tocar el entorno dev compartido. Ejecuta terraform workspace new lb-test, aplica, comprueba el resultado, luego ejecuta terraform destroy, vuelve con terraform workspace select default y elimina el workspace lb-test.

Consejo para el examen: Los workspaces de la CLI separan solo el estado, no las credenciales ni los backends; no se recomiendan como frontera de aislamiento para entornos de producción.

Comprueba lo que sabes

¿Dónde guarda el backend local el estado de un workspace llamado staging?

En terraform.tfstate.d/staging/terraform.tfstate.

¿Qué workspace nunca se puede eliminar?

El workspace default.

¿Cómo haces que los nombres de los recursos incluyan el nombre del workspace?

Interpola terraform.workspace, por ejemplo name = "app-${terraform.workspace}".
