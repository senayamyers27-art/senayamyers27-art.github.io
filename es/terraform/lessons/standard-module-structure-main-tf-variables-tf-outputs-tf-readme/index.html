Estructura estándar de un módulo: main.tf, variables.tf, outputs.tf, README

A Terraform no le importa cómo se llaman tus archivos; lee todos los archivos .tf de un directorio. A las personas, en cambio, les importa mucho. HashiCorp documenta una estructura estándar de módulo para que cualquiera que abra un módulo, o el Terraform Registry al mostrarlo, sepa dónde buscar. Seguirla es lo esperado para los módulos que publicas y una buena práctica para los internos.

La disposición mínima recomendada tiene tres archivos de configuración más la documentación. main.tf es el punto de entrada principal y contiene los recursos principales (o las llamadas a módulos anidados). variables.tf contiene todos los bloques variable, cada uno con una description y un type, para que quienes lo llaman puedan ver toda la interfaz de entrada en un solo lugar. outputs.tf contiene todos los bloques output, también con descripciones. Un README.md explica qué hace el módulo, cómo usarlo y cualquier suposición. Se espera un archivo LICENSE para los módulos compartidos públicamente.

terraform-aws-network/
  README.md
  LICENSE
  main.tf
  variables.tf
  outputs.tf
  versions.tf        # bloques terraform y required_providers
  modules/
    subnet/          # módulos anidados
  examples/
    basic/           # configuraciones raíz de ejemplo

Los módulos más grandes agregan algunas piezas convencionales. Muchos equipos ponen el bloque terraform con required_version y required_providers en un archivo versions.tf. Los módulos anidados van en un subdirectorio modules/, y un módulo anidado sin README se trata como interno. Las configuraciones de ejemplo que muestran cómo llamar al módulo van en examples/, cada una como su propio pequeño módulo raíz. Las pruebas pueden vivir en un directorio tests/ para el framework terraform test.

Publicar en el Terraform Registry público agrega reglas propias. El módulo debe vivir en un repositorio público de GitHub con un nombre de la forma terraform-PROVIDER-NAME, como terraform-aws-network, seguir la estructura estándar y tener etiquetas de versionado semántico como v1.0.0, que el registro convierte en versiones publicadas. El registro lee el README, las entradas y los outputs y genera la documentación automáticamente, lo que es una razón por la que importan las descripciones claras en variables y outputs.

Una buena estructura va más allá de los nombres de archivo. Un módulo bien diseñado hace una sola tarea, expone solo las entradas que quienes lo llaman realmente necesitan, ofrece valores predeterminados sensatos, exporta los IDs y endpoints que necesitarán los consumidores y deja la configuración de providers a quien lo llama. También debe evitar escribir de forma fija valores como regiones o números de cuenta, para que el mismo módulo pueda reutilizarse en distintos entornos.

Términos clave

main.tf
El archivo principal convencional de un módulo, que contiene sus recursos principales y sus llamadas a módulos.
variables.tf
El archivo convencional que contiene las declaraciones de variables de entrada de un módulo, que forman su interfaz de entrada.
outputs.tf
El archivo convencional que contiene las declaraciones de outputs de un módulo, que forman su interfaz de salida.
terraform-PROVIDER-NAME
La convención de nombres de repositorio requerida para los módulos publicados en el Terraform Registry público.
Ejemplo real

Un ingeniero hereda un módulo en el que todos los recursos, variables y outputs están mezclados en archivos llamados a.tf, b.tf y misc.tf. Reorganizarlo en main.tf, variables.tf con descripciones, outputs.tf y un README con un ejemplo de uso permite a sus compañeros entenderlo y llamarlo sin leer cada línea.

Consejo para el examen: Los nombres de archivo son una convención, no un requisito: Terraform fusiona todos los archivos .tf de un directorio, pero la estructura estándar (main, variables, outputs, README) es lo que esperan el registro y los revisores.

Comprueba lo que sabes

¿Terraform requiere un archivo llamado main.tf?

No. Terraform carga todos los archivos .tf del directorio; main.tf es solo una convención de nombres.

¿Qué formato de nombre debe usar un repositorio de GitHub para publicar un módulo en el registro público?

terraform-PROVIDER-NAME, por ejemplo terraform-aws-vpc.
