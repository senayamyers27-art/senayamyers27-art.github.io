Valores de output y valores locales

Los valores de output y los valores locales dan nombre a expresiones, pero miran en direcciones distintas. Los outputs exponen valores de un módulo a quien lo usa. Los locals nombran valores intermedios dentro de un módulo para evitar repeticiones, y no pueden establecerse desde fuera.

output "web_ip" {
  value       = aws_instance.web.public_ip
  description = "Public IP of the web server."
}

output "db_password" {
  value     = random_password.db.result
  sensitive = true
}

Un bloque output necesita un value, y puede tener description, sensitive, un depends_on para las raras dependencias ocultas y verificaciones precondition. En el módulo raíz, los outputs se muestran al final de terraform apply y se guardan en el estado. Puedes leerlos más tarde con terraform output, uno de ellos con terraform output web_ip, la cadena sin comillas con terraform output -raw web_ip, y todos como JSON con terraform output -json. Los outputs sensibles se muestran como <sensitive> en el resumen del apply y en el listado simple de terraform output, pero terraform output -raw y -json los muestran en texto plano, porque el propio valor está en el estado.

En un módulo hijo, los outputs son la única forma de devolver valores al módulo que lo llama. Si un módulo llamado network declara output "subnet_ids", el módulo raíz usa module.network.subnet_ids. Todo lo que no se exporte como output es invisible fuera del módulo. Los outputs de un módulo raíz también pueden leerse desde otra configuración mediante el data source terraform_remote_state o, en HCP Terraform, el data source tfe_outputs, que es como stacks separados comparten valores como los IDs de red.

Los valores locales se declaran en un bloque locals (en plural) y se referencian con local.NAME (en singular), una diferencia de escritura que al examen le gusta evaluar.

locals {
  name_prefix = "${var.project}-${var.environment}"
  common_tags = {
    Project     = var.project
    Environment = var.environment
    ManagedBy   = "terraform"
  }
}

resource "aws_s3_bucket" "logs" {
  bucket = "${local.name_prefix}-logs"
  tags   = local.common_tags
}

Los locals brillan cuando de otro modo la misma expresión se repetiría, o cuando dar nombre a una expresión compleja hace más claro el código. Pueden referenciar variables, recursos, data sources y otros locals. A diferencia de las variables, no pueden ser anulados por quien llama al módulo, por un archivo tfvars ni por la línea de comandos, lo que los convierte en un buen lugar para valores que deben calcularse de forma consistente. Sin embargo, abusar de ellos puede hacer que el código sea más difícil de seguir, ya que los lectores deben saltar a la definición para ver qué es un valor.

Para resumir el trío: las variables son las entradas de un módulo, los locals son sus nombres de trabajo privados y los outputs son sus valores de retorno.

Términos clave

Output value (valor de output)
Un valor con nombre que exporta un módulo; se muestra en el módulo raíz y se accede como module.NAME.OUTPUT en los módulos hijos.
Local value (valor local)
Una expresión con nombre definida en un bloque locals y referenciada como local.NAME, que solo puede usarse dentro de su módulo.
terraform output
Comando que lee del estado los valores de output del módulo raíz, con las opciones -raw y -json.
terraform_remote_state
Data source que lee los outputs del módulo raíz del estado de otra configuración.
Ejemplo real

La configuración de un equipo de redes exporta como output private_subnet_ids. La configuración de un equipo de aplicaciones lee esos outputs con un data source de remote state y usa un mapa local common_tags para que todos los recursos reciban las mismas etiquetas Project y Environment.

Consejo para el examen: El bloque es locals, pero la referencia es local.name. Los valores de un módulo hijo solo son accesibles mediante outputs, como module.NAME.OUTPUT_NAME.

Comprueba lo que sabes

¿Cómo lee un módulo raíz un valor producido dentro de un módulo hijo llamado db?

El hijo debe declarar un output, por ejemplo endpoint, y el raíz lo referencia como module.db.endpoint.

¿Se puede anular un valor local con -var?

No. Los locals son internos del módulo; solo las variables de entrada pueden establecerse desde fuera.
