El backend local predeterminado y los archivos `terraform.tfstate` y `terraform.tfstate.backup`

Terraform debe recordar qué objetos reales pertenecen a qué bloques resource, junto con sus atributos actuales. Guarda esa memoria en el estado. Sin estado, Terraform no podría saber si aws_instance.web ya existe ni a cuál de las muchas instancias en la nube corresponde. Dónde y cómo se guarda el estado lo controla el backend.

Si no configuras ningún backend, Terraform usa el backend local. Guarda el estado en un archivo llamado terraform.tfstate en la raíz de tu directorio de trabajo. El archivo es JSON y contiene una versión del formato, la versión de Terraform que lo escribió, un número de serie que aumenta con cada cambio, un ID de lineage que identifica el historial de este estado, los outputs del raíz y una lista de recursos con todos sus atributos. Puedes abrirlo y leerlo, pero nunca debes editarlo a mano; usa en su lugar los comandos de estado de Terraform.

Cada vez que Terraform escribe un estado nuevo, el backend local primero guarda la versión anterior como terraform.tfstate.backup. Si un apply sale mal o el estado se corrompe, ese backup te da un paso de historial desde el cual recuperarte. Sin embargo, es solo un paso: la siguiente escritura sobrescribe el backup. El historial de versiones real viene de backends remotos con versionado, como un bucket de S3 con el versionado habilitado o HCP Terraform.

Cuando usas workspaces de la CLI con el backend local, el workspace default sigue usando terraform.tfstate, mientras que los demás workspaces guardan su estado en terraform.tfstate.d/WORKSPACE_NAME/terraform.tfstate. También puedes hacer que el backend local apunte a otro archivo con su argumento path, o cambiar la ubicación para un solo comando con los antiguos indicadores -state, aunque esos indicadores son heredados y no se recomiendan.

El backend local está bien para aprender y para experimentos de una sola persona, pero tiene serias desventajas para los equipos. El estado existe solo en una laptop, así que los compañeros no pueden ejecutar Terraform de forma segura; perder la laptop significa perder el estado. Contiene secretos en texto plano. Y a menos que tengas cuidado, termina incluido en un commit de Git. Agrega *.tfstate y *.tfstate.* a .gitignore, y pasa a un backend remoto con bloqueo y cifrado en cuanto participe más de una persona o un pipeline de CI.

El estado también mejora el rendimiento y rastrea metadatos como las dependencias entre recursos, que Terraform necesita para destruir los objetos en el orden correcto incluso después de que elimines su configuración. Por eso el estado es esencial, no una caché que puedas tirar.

Términos clave

State (estado)
El registro de Terraform que asocia los recursos de la configuración con objetos reales, con sus atributos y metadatos.
Local backend (backend local)
El backend predeterminado, que guarda el estado en un archivo en el disco local.
terraform.tfstate
El archivo de estado JSON que el backend local escribe en el directorio de trabajo.
terraform.tfstate.backup
Una copia del estado anterior que el backend local escribe antes de reemplazar terraform.tfstate.
Ejemplo real

Una estudiante ejecuta terraform apply en una laptop y luego formatea la laptop. Los recursos en la nube siguen existiendo, pero terraform.tfstate desapareció, así que Terraform ya no sabe de ellos y el siguiente apply intentaría crear duplicados. Importarlos de nuevo o haber guardado el estado en un backend remoto habría evitado el problema.

Consejo para el examen: Sin bloque backend significa el backend local, que escribe terraform.tfstate más un terraform.tfstate.backup de un solo paso en el directorio de trabajo.

Comprueba lo que sabes

¿Qué archivo contiene la versión anterior del estado local?

terraform.tfstate.backup, que se escribe antes de guardar cada estado nuevo.

¿Por qué no se debe hacer commit de terraform.tfstate en Git?

Puede contener secretos en texto plano y no se puede bloquear, así que compartirlo por Git conlleva el riesgo de filtraciones y cambios en conflicto.
