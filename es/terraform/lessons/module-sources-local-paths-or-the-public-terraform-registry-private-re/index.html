Orígenes de módulos: rutas locales (`./` o `../`), el Terraform Registry público, registros privados, y URLs de Git y HTTP

Todo bloque module necesita un argumento source que le diga a Terraform dónde encontrar el código del módulo. El formato de la cadena source decide cómo lo obtiene Terraform, así que debes poder reconocer cada forma a simple vista. El source debe ser una cadena literal; no puedes construirlo a partir de variables.

Las rutas locales empiezan con ./ o ../, como source = "./modules/network". El punto inicial es obligatorio, porque una cadena sin él se interpreta como una dirección de registro. Los módulos locales no se descargan ni se copian; Terraform los lee directamente del disco, así que los cambios surten efecto en el siguiente plan sin reinstalar. No pueden tener un argumento version, ya que simplemente forman parte de tu código.

Los orígenes del Terraform Registry público usan la forma NAMESPACE/NAME/PROVIDER, por ejemplo terraform-aws-modules/vpc/aws. Terraform los descarga durante terraform init, y deberías fijarlos con una restricción version. Los orígenes de registros privados agregan delante el hostname del registro: HOSTNAME/NAMESPACE/NAME/PROVIDER. El registro privado de HCP Terraform usa app.terraform.io/ORG/NAME/PROVIDER. Los registros privados le dan a una organización un catálogo curado de módulos aprobados y las mismas funciones de versionado que el registro público.

Los orígenes de control de versiones te permiten obtener un módulo de un repositorio Git. Terraform reconoce formas abreviadas como github.com/org/repo y direcciones Git genéricas con el prefijo git::, como git::ssh://git@example.com/org/repo.git. Una doble barra selecciona un subdirectorio dentro del repositorio (repo.git//modules/vpc), y una consulta ?ref= selecciona una rama, etiqueta o commit. Terraform también admite Mercurial y orígenes de archivos comprimidos, como una URL HTTP a un archivo zip o tar, así como buckets de S3 y GCS.

module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 5.0"
}

module "app" {
  source = "../modules/app"
}

module "dns" {
  source = "git::ssh://git@example.com/infra/dns.git?ref=v1.2.0"
}

Elegir un origen es una cuestión de confianza y control de cambios. Las rutas locales son adecuadas para módulos que viven en el mismo repositorio. El registro público ofrece módulos de la comunidad y de socios, así que revísalos antes de usarlos y fija las versiones. Un registro privado es la respuesta organizacional para compartir módulos aprobados. Los orígenes Git funcionan en cualquier lugar, pero debes fijar una etiqueta o un commit con ref para obtener builds repetibles.

Términos clave

source argument (argumento source)
El argumento obligatorio del bloque module que le dice a Terraform dónde encontrar el código del módulo.
Registry source (origen de registro)
Una dirección de módulo con la forma NAMESPACE/NAME/PROVIDER, precedida de un hostname en los registros privados.
Local path source (origen de ruta local)
Una ruta de módulo que empieza con ./ o ../ y que Terraform lee directamente del disco sin descargarla.
Double-slash subdirectory (subdirectorio con doble barra)
La sintaxis // en una dirección source que selecciona un subdirectorio dentro de un repositorio o archivo comprimido descargado.
Ejemplo real

Un ingeniero escribe source = "modules/network" y Terraform intenta descargarlo del registro público y falla. Cambiarlo a source = "./modules/network" hace que Terraform lo trate como una ruta local y lea el código del repositorio.

Consejo para el examen: Conoce las formas de las direcciones: ./ o ../ significa local, tres partes separadas por barras significan registro público, un hostname más tres partes significa registro privado, y git:: o ?ref= significa un origen Git.

Comprueba lo que sabes

¿Cuál es el formato del origen de un módulo de un registro privado?

HOSTNAME/NAMESPACE/NAME/PROVIDER, por ejemplo app.terraform.io/example-org/vpc/aws.

¿Por qué la ruta de un módulo local debe empezar con ./ o ../?

Sin el punto inicial, Terraform interpreta la cadena como una dirección de registro en lugar de un directorio local.

¿Se puede establecer el argumento source a partir de una variable?

No. Debe ser una cadena literal, porque Terraform resuelve los orígenes durante init, antes de evaluar las variables.
