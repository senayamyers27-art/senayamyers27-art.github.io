Revisar outputs y dependencias con `terraform output -json` y `terraform graph`

Las configuraciones de Terraform rara vez están solas. Los scripts, los pipelines y otras herramientas necesitan valores que produjo Terraform, y las personas necesitan entender cómo dependen los recursos unos de otros. Dos comandos ayudan: terraform output -json para compartir resultados de forma legible por máquina, y terraform graph para visualizar las dependencias.

terraform output -json muestra todos los outputs del módulo raíz como un objeto JSON. Cada output aparece con su value, su type y un indicador sensitive. A diferencia de la vista de texto predeterminada, la forma JSON incluye los valores sensibles en texto plano, ya que está pensada para programas. También puedes pedir un solo output: terraform output -json subnet_ids muestra solo ese valor como JSON, lo que es útil para listas y mapas que -raw no puede mostrar.

$ terraform output -json | jq -r '.web_ip.value'
203.0.113.10

$ terraform graph | dot -Tsvg > graph.svg

En la práctica, los pipelines usan terraform output -json para pasar valores a pasos posteriores, como entregar el endpoint de un clúster a un job de despliegue o escribir un archivo de inventario para una herramienta de gestión de configuración. Como los outputs vienen del estado, el comando es rápido y no contacta a los providers. Protege el lugar donde termine el JSON, ya que puede contener secretos.

terraform graph muestra el grafo de dependencias de Terraform en el lenguaje DOT que usa Graphviz. Cada nodo es un recurso, data source, provider o elemento de módulo, y cada arista muestra que uno depende de otro. Terraform construye este grafo a partir de las referencias entre bloques (dependencias implícitas) y de depends_on (dependencias explícitas), y luego lo usa para decidir el orden de creación y destrucción y qué operaciones pueden ejecutarse en paralelo. Pasar la salida al comando dot de Graphviz genera una imagen que puedes inspeccionar. La opción -type muestra el grafo para una operación concreta, como plan o apply.

¿Por qué importa esto para el mantenimiento? Un grafo hace visible el acoplamiento oculto: puedes ver que un cambio en un security group afectará a las instancias, o que un módulo depende del output de otro módulo. Ayuda a explicar por qué Terraform quiere reemplazar algo o por qué un apply ocurre en un orden concreto, y es útil cuando agregas depends_on para confirmar que la arista realmente aparece. En configuraciones grandes el grafo puede ser enorme, así que filtra o céntrate en un módulo al leerlo.

Juntos, estos comandos permiten buenas revisiones: los outputs te dicen qué produjo la configuración, y el grafo te dice cómo se conectan las piezas.

Términos clave

terraform output -json
Muestra los outputs raíz como JSON con los campos value, type y sensitive, revelando los valores sensibles.
terraform graph
Muestra el grafo de dependencias de la configuración o del plan en formato DOT.
DOT / Graphviz
Un lenguaje de descripción de grafos y el conjunto de herramientas (incluido el comando dot) que lo convierte en una imagen.
Implicit dependency (dependencia implícita)
Una dependencia que Terraform deduce de una expresión que referencia los atributos de otro recurso.
Ejemplo real

Un pipeline de CI aplica la infraestructura y luego ejecuta terraform output -json > outputs.json. La siguiente etapa lee de ese archivo el nombre DNS del balanceador de carga y el endpoint de la base de datos para configurar el despliegue de la aplicación, sin copiar valores a mano.

Consejo para el examen: terraform output -json muestra los valores sensibles en texto plano; terraform graph produce DOT, que renderizas con Graphviz.

Comprueba lo que sabes

¿Qué formato produce terraform graph?

DOT, el lenguaje de descripción de grafos de Graphviz.

¿terraform output -json oculta los outputs sensibles?

No. La salida JSON incluye los valores sensibles en texto plano junto con un indicador sensitive.
