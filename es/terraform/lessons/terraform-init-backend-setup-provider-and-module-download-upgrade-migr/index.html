`terraform init`: configuración del backend, descarga de providers y módulos, `-upgrade`, `-migrate-state`, `-reconfigure`, `-backend-config`

terraform init prepara un directorio de trabajo para que los demás comandos puedan ejecutarse. Es el primer comando que ejecutas en una configuración nueva o recién clonada, y lo ejecutas de nuevo cada vez que agregas o cambias providers, módulos o ajustes del backend. Es seguro ejecutarlo repetidamente; nunca cambia tu infraestructura.

Init hace tres tareas principales. Inicializa el backend, leyendo el bloque backend (o el bloque cloud para HCP Terraform) y conectándose al lugar donde se guarda el estado. Instala los módulos referenciados por bloques module, copiando los módulos del registro y de Git en .terraform/modules; los módulos de ruta local se referencian en su lugar. E instala los providers según lo requieran required_providers y el archivo de bloqueo, escribiendo o actualizando .terraform.lock.hcl. Todo lo descargado va dentro del directorio .terraform.

-upgrade le indica a init que ignore las versiones ya seleccionadas y elija las versiones más recientes de providers y módulos que permitan tus restricciones. Úsalo deliberadamente cuando quieras actualizar, y luego revisa y confirma con commit el cambio del archivo de bloqueo.

Cuando cambias la configuración del backend, por ejemplo al pasar del estado local a un backend de almacenamiento en la nube, init lo detecta y pregunta qué hacer con el estado existente. -migrate-state copia el estado existente al nuevo backend y pide confirmación. -reconfigure hace lo contrario: ignora la configuración del backend guardada y el estado existente, y configura el nuevo backend desde cero, sin migrar nada. Usa -reconfigure cuando apuntas a un backend que ya contiene el estado correcto, o cuando quieres empezar de cero intencionalmente; usarlo por error puede hacer que parezca que tus recursos desaparecieron del estado.

-backend-config proporciona ajustes del backend en el momento de init, lo que se llama configuración parcial. Puedes dejar algunos argumentos fuera del bloque backend y pasarlos como pares -backend-config="key=value" o como un archivo de ajustes. Esto es útil para mantener los valores específicos de cada entorno, o las credenciales, fuera del código confirmado, ya que los bloques backend no pueden usar variables.

terraform {
  backend "s3" {}
}
terraform init \
  -backend-config="bucket=acme-tfstate" \
  -backend-config="key=network/prod.tfstate" \
  -backend-config="region=us-east-1"

Otras opciones útiles incluyen -input=false para la automatización, de modo que init falle en lugar de pedir datos. Si init falla, los demás comandos informarán que el directorio no está inicializado o que faltan plugins requeridos, lo cual es tu señal para ejecutarlo de nuevo.

Términos clave

terraform init
Comando que inicializa un directorio de trabajo: configura el backend e instala módulos y providers.
-migrate-state
Opción de init que copia el estado existente a un backend recién configurado.
-reconfigure
Opción de init que configura el backend desde cero, ignorando los ajustes guardados y sin migrar el estado.
Partial configuration (configuración parcial)
Dejar los ajustes del backend fuera del código y proporcionarlos con -backend-config en el momento de init.
Ejemplo real

Un equipo supera el estado local. Agrega un bloque backend s3, ejecuta terraform init -migrate-state, confirma el aviso y su estado existente se copia al bucket. Luego los compañeros ejecutan un simple terraform init en clones nuevos y ven el mismo estado.

Consejo para el examen: -migrate-state mueve el estado al nuevo backend; -reconfigure no. -upgrade cambia las versiones de providers y módulos. Ninguna de las opciones de init cambia la infraestructura real.

Comprueba lo que sabes

Cambiaste el bloque backend y quieres que tu estado actual se copie a la nueva ubicación. ¿Qué opción de init usas?

terraform init -migrate-state.

¿Por qué usarías -backend-config en lugar de escribir los valores en el bloque backend?

Los bloques backend no pueden usar variables, así que la configuración parcial te permite proporcionar ajustes específicos del entorno o secretos en el momento de init sin incluirlos en un commit.
