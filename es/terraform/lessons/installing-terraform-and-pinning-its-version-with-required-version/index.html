Instalar Terraform y fijar su versión con `required_version`

Terraform se distribuye como un único binario ejecutable llamado terraform. No hay ningún servidor que ejecutar ni base de datos que instalar; colocas el binario en algún lugar de tu PATH y lo ejecutas. HashiCorp publica builds para Linux, macOS y Windows en varias arquitecturas de procesador, y también repositorios de paquetes para que puedas instalarlo y actualizarlo con herramientas como apt, yum o dnf, Homebrew en macOS o Chocolatey en Windows. Muchos equipos también usan un gestor de versiones para que distintos proyectos puedan usar distintas versiones de Terraform.

Después de instalarlo, confirma que funciona con terraform version (o terraform -version). La salida muestra la versión de Terraform, la plataforma y, cuando se ejecuta en un directorio inicializado, las versiones de los providers en uso. Si hay una versión más reciente disponible, también te lo indica. terraform -help lista los subcomandos, y terraform -install-autocomplete configura el autocompletado con tabulador en la shell.

Como el comportamiento y las funciones de Terraform cambian entre versiones, una configuración debe indicar con qué versiones de Terraform funciona. Esa es la tarea del ajuste required_version dentro del bloque terraform de nivel superior. Recibe una cadena de restricción de versión, y Terraform compara el binario en ejecución con ella antes de hacer cualquier otra cosa. Si la versión en ejecución no cumple la restricción, comandos como init, plan y apply se detienen con un error que explica la discrepancia.

terraform {
  required_version = ">= 1.12.0, < 2.0.0"
}

¿Por qué fijar la versión? Imagina que un compañero con una versión más reciente de Terraform aplica una configuración y el archivo de estado se escribe de una forma que una versión anterior no espera, o que una configuración depende de una función del lenguaje disponible solo en versiones recientes. Una restricción clara convierte un fallo confuso en un error inmediato y legible. También documenta para los lectores futuros contra qué versión se escribió el código. Fijar de forma demasiado estricta, como un = 1.12.1 exacto, obliga a todos a actualizar al mismo tiempo, así que la mayoría de los equipos usa un rango o una restricción pesimista como ~> 1.12.

Dos detalles se evalúan con frecuencia. Primero, required_version restringe solo la versión de la CLI de Terraform, no la de los providers; los providers se fijan por separado en required_providers. Segundo, los ajustes del bloque terraform deben ser valores literales; no puedes usar variables de entrada ni otras expresiones dentro de required_version. Los módulos hijos también pueden declarar required_version, y todos los módulos de la configuración deben quedar satisfechos.

En HCP Terraform, un workspace tiene su propio ajuste de versión de Terraform que elige qué binario ejecuta las operaciones remotas, y esa versión debe seguir cumpliendo el required_version de la configuración.

Términos clave

terraform block (bloque terraform)
El bloque de nivel superior para ajustes sobre el propio Terraform, como required_version, required_providers y backend.
required_version
Una restricción de versión que la CLI de Terraform en ejecución debe cumplir; de lo contrario, los comandos fallan.
terraform version
Comando que muestra la versión de Terraform instalada, la plataforma y, en un directorio inicializado, las versiones de los providers.
Version constraint (restricción de versión)
Una cadena de una o más condiciones, como >= 1.12.0, < 2.0.0, que una versión debe cumplir.
Ejemplo real

Un contratista con una instalación antigua de Terraform ejecuta terraform plan en tu repositorio. Como la configuración dice required_version = "~> 1.12", Terraform se detiene de inmediato con un error de versión no compatible, y el contratista actualiza en lugar de recibir errores de sintaxis confusos provocados por funciones más nuevas del lenguaje.

Consejo para el examen: Recuerda la división: required_version fija la CLI de Terraform; required_providers fija los providers. Ninguno acepta variables, porque el bloque terraform solo admite valores literales.

Comprueba lo que sabes

¿Dónde se declara required_version y qué restringe?

En el bloque terraform de nivel superior; restringe qué versiones de la CLI de Terraform pueden ejecutar la configuración.

¿Puedes configurar required_version = var.tf_version?

No. Los ajustes del bloque terraform deben ser constantes literales, no variables ni expresiones.
