Usar `count` y `for_each` en bloques module

Desde Terraform 0.13, los meta-argumentos count y for_each funcionan en los bloques module además de en los recursos. Permiten que un solo bloque module cree varias instancias de un módulo completo, cada una con su propia copia de todos los recursos del módulo. Así es como produces en serie un conjunto de entornos, buckets o servicios similares sin copiar código.

Con count, das un número entero y Terraform crea esa cantidad de instancias, indexadas desde cero. Dentro del bloque module, count.index da el número actual, que puedes usar para variar las entradas. Las instancias se direccionan como module.NAME[0], module.NAME[1] y así sucesivamente. count también funciona como interruptor de encendido/apagado: count = var.enable_monitoring ? 1 : 0 incluye u omite todo el módulo.

Con for_each, das un mapa o un set de cadenas, y Terraform crea una instancia por elemento. each.key y each.value están disponibles dentro del bloque. Las instancias se direccionan por clave, como module.bucket["logs"]. Como cada instancia está ligada a una clave estable y no a una posición, eliminar un elemento del medio de la colección destruye solo esa instancia; con count, eliminar un elemento desplaza todos los índices posteriores y puede causar reemplazos no deseados.

module "bucket" {
  source   = "./modules/bucket"
  for_each = toset(["logs", "backups", "assets"])
  name     = "example-${each.key}"
}

output "bucket_arns" {
  value = { for k, m in module.bucket : k => m.arn }
}

Como un módulo con count o for_each es una colección, lees los outputs con un índice o una clave: module.bucket["logs"].arn, o los recorres como en el ejemplo. Los valores usados en count y for_each deben conocerse en el momento del plan; no puedes basarlos en atributos que solo existen después del apply, como un ID generado. Un bloque module no puede usar count y for_each juntos.

Una restricción que debes recordar: un módulo que contiene sus propios bloques provider (un módulo legacy) no puede usarse con count, for_each ni depends_on. Esta es otra razón para mantener la configuración de providers en el módulo raíz y pasarla hacia abajo. Al convertir una llamada a un solo módulo existente a for_each, las direcciones de los recursos cambian, así que usa un bloque moved (por ejemplo, de module.bucket a module.bucket["logs"]) para evitar destruir y recrear los recursos.

Términos clave

count on a module (count en un módulo)
Crea un número de instancias del módulo direccionadas por índice, como module.web[0].
for_each on a module (for_each en un módulo)
Crea una instancia del módulo por cada clave de mapa o elemento de set, direccionada por clave, como module.web["blue"].
each.key / each.value
Valores disponibles dentro de un bloque con for_each que identifican el elemento actual.
Legacy module (módulo legacy)
Un módulo que contiene sus propios bloques provider; no puede usarse con count, for_each ni depends_on.
Ejemplo real

Una empresa ejecuta el mismo servicio en tres regiones. En lugar de tres bloques module, usa for_each sobre un mapa de nombres de regiones a rangos CIDR y pasa each.value como rango de red. Agregar una cuarta región es un cambio de una línea en el mapa.

Consejo para el examen: Prefiere for_each sobre count cuando las instancias son distintas y pueden eliminarse individualmente; los índices de count se desplazan cuando se elimina un elemento del medio.

Comprueba lo que sabes

¿Cómo lees el output endpoint de la instancia con clave prod en un módulo con for_each llamado app?

module.app["prod"].endpoint.

¿Cómo puede usarse count para hacer que un módulo sea opcional?

Establece count = var.enabled ? 1 : 0 para que el módulo tenga una instancia o ninguna.

¿Qué tipo de módulo no puede usar count ni for_each?

Un módulo que incluye sus propios bloques de configuración de providers.
