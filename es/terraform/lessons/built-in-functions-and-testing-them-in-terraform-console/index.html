Funciones integradas y cómo probarlas en `terraform console`

Terraform incluye una biblioteca de funciones integradas que llamas dentro de las expresiones con la sintaxis name(arg1, arg2). No puedes escribir tus propias funciones en el lenguaje de Terraform; usas las integradas, más cualquier función que proporcione un provider, llamada con la sintaxis provider::NAME::FUNCTION(...). El examen espera que reconozcas las funciones comunes por categoría y que sepas cómo experimentar con ellas.

Vale la pena conocer las categorías principales con uno o dos ejemplos de cada una. Numéricas: min, max, abs, ceil, floor. De cadenas: upper, lower, format, join, split, replace, trimspace, substr. De colecciones: length, concat, merge, lookup, element, flatten, keys, values, contains, distinct, coalesce, zipmap. De codificación: jsonencode, jsondecode, yamlencode, base64encode. Del sistema de archivos: file, fileexists, templatefile. De fecha y hora: timestamp, formatdate. De hash y criptografía: sha256, md5, bcrypt. De redes IP: cidrsubnet, cidrhost, cidrnetmask. De conversión de tipos: tostring, tonumber, tolist, toset, tomap, además de try y can para manejar errores.

Algunos comportamientos se evalúan con frecuencia. lookup(map, key, default) devuelve el default cuando falta la clave. element(list, index) vuelve al principio cuando el índice pasa del final, a diferencia de list[index], que da error. merge combina mapas, y los mapas posteriores ganan en las claves duplicadas. file lee un archivo en el momento del plan; las rutas relativas conviene construirlas con path.module, y templatefile(path, vars) renderiza un archivo de plantilla con variables. timestamp() devuelve un valor nuevo en cada ejecución, así que usarlo en argumentos de recursos provoca cambios constantes.

terraform console abre un prompt interactivo donde puedes evaluar expresiones contra tu configuración. Ejecútalo en un directorio de trabajo inicializado, escribe una expresión y ve el resultado. Conoce tus variables, locals y, si existe estado, los atributos de tus recursos, así que puedes inspeccionar aws_instance.web.private_ip o probar una expresión for antes de ponerla en el código. Sal con exit o Ctrl+D. También puedes pasarle una expresión mediante una tubería (pipe) para verificaciones con scripts.

$ terraform console
> cidrsubnet("10.0.0.0/16", 8, 1)
"10.0.1.0/24"
> lookup({a = 1}, "b", 0)
0
> join("-", ["app", "prod"])
"app-prod"
> exit

Vale la pena entender el ejemplo de cidrsubnet(prefix, newbits, netnum): suma newbits a la longitud del prefijo, aquí 16 más 8 da /24, y luego elige la subred número netnum dentro de ese rango. Se usa mucho para dividir subredes a partir de un bloque de direcciones de red sin escribir cada una de forma fija.

Cuando encuentres una función desconocida en una pregunta, razona a partir de su nombre y su categoría, y luego comprueba su comportamiento en console durante tus laboratorios. Saber que console existe, y que evalúa expresiones sin cambiar nada, es en sí mismo un punto probable del examen.

Términos clave

Built-in function (función integrada)
Una función proporcionada por Terraform, como join o cidrsubnet, que puede llamarse en expresiones; no se admiten funciones definidas por el usuario.
terraform console
Comando interactivo para evaluar expresiones contra la configuración y el estado actuales sin hacer cambios.
lookup
Función que devuelve un valor de un mapa por su clave, o un default cuando falta la clave.
cidrsubnet
Función que calcula el rango de direcciones de una subred dentro de un bloque CIDR más grande.
Ejemplo real

Antes de escribir un módulo que crea una subred por zona de disponibilidad, una ingeniera abre terraform console y prueba [for i in range(3) : cidrsubnet("10.20.0.0/16", 4, i)] para comprobar que los rangos salen como espera.

Consejo para el examen: Terraform no admite funciones definidas por el usuario en HCL. Para probar el comportamiento de una función, usa terraform console, que evalúa expresiones sin modificar la infraestructura.

Comprueba lo que sabes

¿Qué devuelve lookup(var.sizes, "xl", "medium") si var.sizes no tiene la clave xl?

"medium", el default indicado como tercer argumento.

¿Puedes definir tu propia función en una configuración de Terraform?

No. Solo puedes usar funciones integradas y funciones proporcionadas por providers.
