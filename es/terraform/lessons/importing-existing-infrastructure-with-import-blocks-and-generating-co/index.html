Importar infraestructura existente con bloques `import` y generar configuración con `terraform plan -generate-config-out`

Muchas organizaciones adoptan Terraform cuando ya tienen infraestructura construida a mano o con otras herramientas. Importar pone esos objetos existentes bajo la gestión de Terraform registrándolos en el estado y asociándolos con bloques resource, sin recrear nada. Desde Terraform 1.5, la forma recomendada es el bloque declarativo import.

Un bloque import tiene dos argumentos obligatorios: to, la dirección del recurso que debe ser dueño del objeto, e id, el identificador específico del provider del objeto real, como un ID de instancia o el nombre de un bucket. Los IDs de importación varían según el tipo de recurso, así que revisa la documentación del recurso, que normalmente tiene una sección de importación que muestra el formato esperado.

import {
  to = aws_s3_bucket.logs
  id = "example-company-logs"
}

La gran ventaja frente al comando antiguo es que las importaciones pasan por el flujo de trabajo normal de plan y apply. terraform plan muestra exactamente qué objetos se importarán junto con cualquier otro cambio, los revisores pueden verlos en un pull request, y no se escribe nada en el estado hasta que aplicas. Puedes importar muchos recursos a la vez, y los bloques import aceptan for_each para importar conjuntos de objetos similares. Después de un apply exitoso, los bloques import pueden dejarse en su lugar (son idempotentes) o eliminarse.

Escribir a mano los bloques resource correspondientes suele ser la parte más difícil. Terraform puede redactarlos por ti. Si un bloque import apunta a un recurso que todavía no tiene bloque resource, ejecuta terraform plan -generate-config-out=generated.tf. Terraform consulta al provider y escribe el HCL de los recursos faltantes en ese archivo nuevo (el archivo no debe existir previamente). El código generado es un punto de partida: revísalo, elimina los atributos que no quieras gestionar, reemplaza los valores fijos por referencias y variables, y muévelo a tus archivos habituales.

El flujo de trabajo típico es: escribir los bloques import; ejecutar plan con -generate-config-out; editar la configuración generada; ejecutar plan de nuevo hasta que muestre solo importaciones y ningún cambio inesperado; y luego aplicar. Un plan que también muestra actualizaciones significa que tu configuración todavía no coincide del todo con el objeto real, y aplicar lo cambiaría.

Vale la pena recordar dos límites. La importación lleva un objeto real a una dirección de recurso, así que no debes importar el mismo objeto en dos direcciones, lo que llevaría a una gestión en conflicto. Y no se garantiza que la configuración generada sea perfecta, especialmente para atributos que entran en conflicto entre sí, así que una revisión cuidadosa es esencial.

Términos clave

import block (bloque import)
Un bloque declarativo con to e id que le indica a Terraform que ponga un objeto existente bajo una dirección de recurso durante plan y apply.
Import ID (ID de importación)
El identificador específico del provider de un objeto existente, como un ID de instancia o el nombre de un bucket.
-generate-config-out
Un indicador de terraform plan que escribe en un archivo nuevo el HCL generado para los destinos de importación que no tienen bloques resource.
Adopting infrastructure (adoptar infraestructura)
Poner recursos creados manualmente bajo la gestión de Terraform sin recrearlos.
Ejemplo real

Una empresa tiene cuarenta buckets de S3 creados a mano. Un ingeniero escribe un bloque import con for_each sobre los nombres de los buckets, ejecuta terraform plan -generate-config-out=buckets.tf, ordena el código generado en una llamada a módulo, confirma que el plan muestra solo importaciones y aplica. Ahora los buckets están gestionados sin tiempo de inactividad.

Consejo para el examen: Los bloques import se revisan en el plan y se aplican como otros cambios; -generate-config-out escribe HCL inicial en un archivo que no debe existir previamente.

Comprueba lo que sabes

¿Cuáles son los dos argumentos obligatorios de un bloque import?

to (la dirección del recurso) e id (el identificador del objeto existente).

¿Por qué se prefiere un bloque import al antiguo comando import?

Funciona mediante plan y apply, así que las importaciones se previsualizan, se revisan, pueden hacerse en masa y pueden generar configuración.
