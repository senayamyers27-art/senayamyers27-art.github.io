`terraform plan`: refresh, diff y símbolos (`+`, `-`, `~`, `-/+`), planes guardados con `-out`

terraform plan crea un plan de ejecución: una previsualización de lo que Terraform cambiaría. No cambia la infraestructura real. Plan funciona en tres etapas. Primero lee el estado actual. Luego, de forma predeterminada, hace un refresh (actualización): le pide a cada provider los atributos actuales de cada objeto gestionado, para poder ver el drift hecho fuera de Terraform. Por último, compara la configuración con esa vista actualizada y determina qué acciones harían que la realidad coincida con el código.

La salida del plan lista cada recurso afectado con un símbolo y una descripción. Los símbolos principales son: + crear; - destruir; ~ actualizar en el lugar, donde solo se muestran los atributos cambiados con sus valores anteriores y nuevos; -/+ destruir y luego crear un reemplazo, porque se cambió un argumento que no se puede cambiar en un objeto en vivo; y +/- crear primero el reemplazo y luego destruir el anterior, cuando create_before_destroy está configurado. Los data sources que deben leerse durante el apply aparecen con <=.

  # aws_instance.web must be replaced
-/+ resource "aws_instance" "web" {
      ~ ami  = "ami-old" -> "ami-new" # forces replacement
      ~ id   = "i-0abc" -> (known after apply)
    }

Plan: 1 to add, 0 to change, 1 to destroy.

Lee las anotaciones. # forces replacement marca el argumento que provocó el reemplazo. (known after apply) significa que el valor solo se conocerá cuando el provider cree o actualice el objeto, como un ID nuevo. (sensitive value) significa que el valor está oculto porque está marcado como sensible. La línea final de resumen cuenta las adiciones, los cambios y las destrucciones; un reemplazo cuenta como una adición y una destrucción.

El plan también informa el drift. Si el refresh encuentra que un objeto cambió fuera de Terraform, la salida primero indica los cambios detectados y luego muestra lo que Terraform haría para volver a alinear el objeto con la configuración.

De forma predeterminada, el plan se muestra y se descarta. Con -out=FILE, Terraform guarda el plan en un archivo para que exactamente esas acciones puedan aplicarse más tarde con terraform apply FILE. Esto importa en los pipelines, donde un plan se revisa y aprueba y luego se aplica sin volver a calcularse. El archivo guardado es binario; míralo con terraform show FILE, o con terraform show -json FILE para herramientas. Contiene la configuración completa, los valores de las variables y posiblemente secretos, así que protégelo como el estado.

Útil para la automatización: -detailed-exitcode hace que plan termine con 0 cuando no hay cambios, 1 cuando hay un error y 2 cuando hay cambios, para que un script pueda detectar drift. -input=false evita que se pidan variables faltantes.

Términos clave

Execution plan (plan de ejecución)
La previsualización de Terraform de las acciones de crear, actualizar, reemplazar y destruir necesarias para coincidir con la configuración.
-/+ (replace, reemplazar)
Símbolo del plan que significa que el objeto existente se destruirá y se creará uno nuevo.
(known after apply)
Anotación del plan para valores que el provider solo determinará cuando se lleve a cabo el cambio.
Saved plan (plan guardado)
Un plan escrito con -out=FILE que puede aplicarse más tarde exactamente como se revisó.
Ejemplo real

Un plan que debía cambiar las etiquetas de una instancia muestra -/+ y un reemplazo. Al leer con más atención, el ingeniero ve # forces replacement junto al ID de la subred, se da cuenta de que una variable apunta a la subred equivocada y lo corrige antes de que se destruya ningún servidor.

Consejo para el examen: Memoriza los símbolos: + crear, - destruir, ~ actualizar en el lugar, -/+ reemplazar (destruyendo primero), +/- reemplazar (creando primero), <= leer. Plan nunca cambia la infraestructura, aunque sí hace refresh desde los providers.

Comprueba lo que sabes

¿Qué significa ~ en la salida del plan?

Que el recurso se actualizará en el lugar, sin destruirse.

¿Cómo garantizas que se apliquen exactamente las acciones revisadas?

Guarda el plan con terraform plan -out=FILE y aplica ese archivo con terraform apply FILE.
