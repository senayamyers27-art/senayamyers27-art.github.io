`terraform apply`: aprobación interactiva, `-auto-approve` y aplicar un archivo de plan guardado

terraform apply ejecuta los cambios para que la infraestructura real coincida con la configuración. Puede ejecutarse en dos modos: sin archivo de plan, en el que crea un plan nuevo y pide aprobación, o con un archivo de plan guardado, en el que lleva a cabo exactamente ese plan.

En el primer modo, apply ejecuta los mismos pasos que plan: refresh, comparación y cálculo de las acciones. Muestra el plan y luego se detiene con un aviso que pregunta si quieres realizar estas acciones, indicando que solo se aceptará yes. Cualquier otra respuesta, incluida y, cancela. Esta aprobación interactiva es tu última oportunidad de detectar una destrucción o un reemplazo inesperados.

-auto-approve omite el aviso y aplica de inmediato. Está pensado para automatización en la que la aprobación ya ocurrió en otro lugar, como un pull request revisado, o para entornos desechables. Usarlo en producción desde una laptop elimina la verificación de seguridad, así que trátalo con cuidado. Apply sin archivo de plan también acepta opciones de planificación como -var, -var-file, -target, -replace y -refresh-only.

En el segundo modo, terraform apply tfplan aplica un plan guardado antes con terraform plan -out=tfplan. No hay aviso de aprobación, porque ejecutar plan y guardar el archivo se considera el paso de aprobación. No puedes pasar nuevos valores de variables; quedaron fijados cuando se hizo el plan. Si el estado cambió desde que se creó el plan, por ejemplo porque otra persona aplicó entre medio, Terraform rechaza el plan obsoleto y debes planificar de nuevo. Este patrón de dos pasos es el estándar para los pipelines: planificar, revisar y luego aplicar el archivo revisado.

terraform plan -out=tfplan
terraform show tfplan
terraform apply tfplan

Durante el apply, Terraform recorre el grafo de dependencias, creando, actualizando y eliminando recursos en orden y ejecutando en paralelo las operaciones independientes. Después de cada cambio, escribe el resultado en el estado. Apply no es una transacción: si ocurre un error a mitad de camino, los cambios que ya tuvieron éxito se mantienen y el estado los registra. Corrige el problema y aplica de nuevo; Terraform retoma desde el estado actual en lugar de empezar de cero. Un recurso cuya creación falló parcialmente puede marcarse como tainted y reemplazarse en la siguiente ejecución.

Cuando apply termina, muestra un resumen como Apply complete! Resources: 2 added, 0 changed, 0 destroyed. seguido de los valores de los outputs del módulo raíz, con los outputs sensibles mostrados como <sensitive>. El bloqueo del estado se mantiene durante todo el apply, así que un segundo apply contra el mismo estado espera o falla en lugar de chocar.

Términos clave

terraform apply
Comando que lleva a cabo un plan para crear, actualizar o destruir infraestructura y registra los resultados en el estado.
-auto-approve
Omite la confirmación interactiva yes; pensado para automatización con aprobación en otro lugar.
Stale plan (plan obsoleto)
Un plan guardado cuyo estado cambió desde que se creó; Terraform se niega a aplicarlo.
Tainted (contaminado)
Marca en el estado para un recurso que se sabe dañado, como después de una creación fallida, de modo que se reemplazará.
Ejemplo real

Un pipeline de releases ejecuta terraform plan -out=tfplan, publica terraform show tfplan en un canal de chat y espera una aprobación manual. Una vez aprobado, ejecuta terraform apply tfplan, que aplica sin pedir confirmación y exactamente como se revisó.

Consejo para el examen: Aplicar un archivo de plan guardado no pide aprobación y no acepta nuevas variables. Sin archivo de plan, apply pide confirmación a menos que se use -auto-approve, y solo la palabra exacta yes permite continuar.

Comprueba lo que sabes

¿terraform apply tfplan pide confirmación?

No. Aplicar un plan guardado se considera ya aprobado, así que continúa sin aviso.

Un apply falla después de crear tres de cinco recursos. ¿Qué pasa con esos tres?

Se mantienen y quedan registrados en el estado; apply no es transaccional, y el siguiente apply continúa desde el estado actual.
