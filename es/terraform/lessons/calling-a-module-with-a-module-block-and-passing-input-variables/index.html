Llamar a un módulo con un bloque `module` y pasar variables de entrada

Usar un módulo en tu configuración se llama llamarlo, y lo haces con un bloque module. La etiqueta después de module es un nombre local que tú eliges, como module "web_server". Ese nombre es la forma de referirte a esta instancia concreta del módulo en otras partes, y puedes llamar al mismo origen de módulo varias veces con distintos nombres para construir varias copias con distintos ajustes.

Dentro del bloque, algunos argumentos están reservados por el propio Terraform. source (obligatorio) indica de dónde viene el código, y version fija una versión de un módulo del registro. Los meta-argumentos count, for_each, providers y depends_on funcionan en los bloques module de forma muy parecida a como lo hacen en los recursos. Cualquier otro argumento que escribas en el bloque establece una de las variables de entrada del módulo, usando el nombre de la variable como nombre del argumento.

module "web_server" {
  source        = "./modules/server"
  instance_type = "t3.small"
  subnet_id     = aws_subnet.public.id
  tags          = { team = "web" }
}

En este ejemplo, el módulo hijo en ./modules/server debe declarar variable "instance_type", variable "subnet_id" y variable "tags". Si pasas un argumento que el módulo no declara, Terraform informa un error de argumento no admitido. Si el módulo declara una variable sin default y no la pasas, Terraform informa que falta un argumento obligatorio. Las variables con default son opcionales, y solo las estableces cuando quieres un valor distinto. Terraform comprueba cada valor contra la restricción type de la variable y cualquier regla de validación.

Los valores de entrada pueden ser cualquier expresión: literales, variables del módulo que llama (var.env), atributos de recursos (aws_subnet.public.id) u outputs de otros módulos (module.network.subnet_ids). Cuando pasas un atributo de un recurso o el output de otro módulo, Terraform registra automáticamente una dependencia, así que crea primero los objetos de los que depende. Rara vez necesitas depends_on en un módulo; úsalo solo para dependencias ocultas que Terraform no puede ver a partir de las referencias.

Después de agregar o cambiar el source de un bloque module, debes ejecutar terraform init (o terraform get) para que Terraform instale el módulo. Cambiar solo los valores de entrada no necesita un nuevo init; basta con plan y apply. El plan mostrará los recursos del módulo hijo con direcciones que empiezan por module.web_server., lo que es una forma rápida de confirmar que tu llamada funcionó como esperabas.

Términos clave

module block (bloque module)
Un bloque que llama a un módulo hijo, dándole un nombre local, un source y valores para sus variables de entrada.
Input variable (variable de entrada)
Una variable declarada en el módulo hijo que quienes lo llaman establecen como argumento en el bloque module.
Required input (entrada obligatoria)
Una variable de módulo sin default; quienes llaman deben proporcionarla o Terraform informa un error.
Meta-arguments (meta-argumentos)
Argumentos que maneja el propio Terraform en un bloque module: source, version, count, for_each, providers y depends_on.
Ejemplo real

Un equipo llama dos veces al mismo módulo ./modules/server, como module "web" y module "api", pasando valores distintos de instance_type y subnet_id. Terraform construye dos conjuntos independientes de recursos, direccionados como module.web.aws_instance.this y module.api.aws_instance.this.

Consejo para el examen: Los argumentos de un bloque module (salvo los meta-argumentos) se corresponden uno a uno con los bloques variable del hijo; una variable obligatoria faltante o un argumento no declarado son ambos errores.
