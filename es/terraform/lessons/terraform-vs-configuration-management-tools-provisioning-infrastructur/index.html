Terraform frente a las herramientas de gestión de configuración: aprovisionar infraestructura frente a configurar el software dentro de los servidores

Terraform es una herramienta de aprovisionamiento. Crea, actualiza y elimina objetos de infraestructura mediante APIs: redes, máquinas virtuales, balanceadores de carga, bases de datos, registros DNS. Las herramientas de gestión de configuración como Ansible, Chef, Puppet y Salt se centran en lo que ocurre dentro de un servidor una vez que existe: instalar paquetes, escribir archivos de configuración, gestionar usuarios y servicios, y mantenerlos en la condición deseada con el tiempo.

El límite no es perfectamente nítido. Ansible puede crear recursos en la nube, y Terraform puede pasar un script de arranque a una máquina virtual nueva. Pero cada herramienta está diseñada en torno a un modelo diferente. Terraform rastrea objetos en un archivo de estado y planifica cambios contra APIs. Las herramientas de gestión de configuración normalmente se conectan a los hosts, a menudo por SSH o mediante un agente, y hacen converger el sistema operativo y las aplicaciones hacia una configuración descrita, repetidamente si es necesario.

En la práctica, los equipos las combinan. Terraform construye la máquina virtual y la red, y luego pasa el relevo a una herramienta de gestión de configuración o evita que haga falta una. Los patrones de relevo comunes incluyen pasar scripts de user_data o cloud-init que se ejecutan en el primer arranque, hacer que la nueva instancia se registre en un servidor de gestión de configuración, o generar un archivo de inventario para Ansible a partir de los outputs de Terraform.

Terraform sí ofrece provisioners, como remote-exec para ejecutar comandos por SSH o WinRM y local-exec para ejecutar un comando en la máquina que ejecuta Terraform. HashiCorp documenta los provisioners como último recurso. Terraform no puede modelar lo que hizo un script, así que no puede planificar cambios sobre él, detectar drift dentro del servidor ni deshacerlo de forma limpia. Si un provisioner de tiempo de creación falla, el recurso se marca como tainted (contaminado) y se reemplaza en el siguiente apply. Prefiere cloud-init, imágenes preconstruidas o una herramienta de gestión de configuración adecuada.

Una tercera opción evita por completo la configuración en el lugar: construir una imagen de máquina con todo preinstalado, por ejemplo con HashiCorp Packer, y hacer que Terraform lance instancias a partir de esa imagen. Cuando el software necesita cambiar, construyes una imagen nueva y reemplazas las instancias. Ese es el patrón de infraestructura inmutable que se cubre en la siguiente lección.

resource "aws_instance" "web" {
  ami       = var.golden_image_id
  user_data = file("${path.module}/cloud-init.yaml")
  ...
}

Términos clave

Provisioning (aprovisionamiento)
Crear y gestionar los propios recursos de infraestructura, como servidores y redes, normalmente mediante APIs.
Configuration management (gestión de configuración)
Instalar y mantener software y ajustes dentro de servidores existentes, como hacen Ansible, Chef, Puppet o Salt.
Provisioner
Un bloque de Terraform como local-exec o remote-exec que ejecuta comandos; es un último recurso porque sus efectos no se rastrean.
cloud-init / user_data
Un mecanismo para pasar un script o una configuración de primer arranque a una máquina virtual nueva.
Ejemplo real

Un equipo de operaciones usa Terraform para crear 20 servidores web y un balanceador de carga, y pasa la dirección de cada servidor a un inventario de Ansible. Luego Ansible instala el software del servidor web y endurece (hardening) el sistema operativo, y se ejecuta de nuevo cada semana para corregir cualquier drift dentro de los hosts.

Consejo para el examen: Cuando el examen pregunte qué herramienta es mejor para crear redes e instancias en la nube, elige Terraform; para gestionar paquetes y archivos dentro de servidores en ejecución, elige la gestión de configuración. Los provisioners son un último recurso.

Comprueba lo que sabes

¿Por qué HashiCorp llama a los provisioners un último recurso?

Terraform no puede modelar ni planificar lo que hace un script, así que no puede detectar drift ni revertirlo; se prefieren alternativas declarativas como cloud-init, imágenes o la gestión de configuración.

¿Qué le pasa a un recurso si su provisioner de tiempo de creación falla?

Se marca como tainted, así que Terraform planea reemplazarlo en el siguiente apply.
