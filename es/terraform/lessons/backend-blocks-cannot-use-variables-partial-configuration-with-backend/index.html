Los bloques backend no pueden usar variables; configuración parcial con `-backend-config`

Terraform inicializa el backend antes de evaluar cualquier otra cosa de la configuración, porque necesita el backend para leer el estado. En ese momento temprano, las variables de entrada, los locals y los data sources todavía no se han procesado. Como resultado, un bloque backend no puede contener referencias como var.bucket, local.key ni ninguna otra expresión que dependa de valores de la configuración. Solo se permiten valores literales, y Terraform informa un error si intentas usar una variable ahí.

Esa restricción crea un problema práctico. A menudo quieres que el mismo código use un bucket o una key distintos para cada entorno, y desde luego no quieres claves de acceso escritas de forma fija en el control de versiones. La respuesta es la configuración parcial: deja algunos o todos los argumentos del backend fuera del bloque y proporciónalos al ejecutar terraform init.

Hay tres formas de proporcionar los valores faltantes. Puedes pasar pares clave/valor en la línea de comandos con -backend-config="KEY=VALUE", repitiendo el indicador para cada argumento. Puedes pasar la ruta de un archivo con -backend-config=PATH, donde el archivo contiene los argumentos en formato HCL (a menudo con un nombre como prod.s3.tfbackend). O, si ejecutas init de forma interactiva y faltan valores obligatorios, Terraform los pide. Muchos backends también leen ciertos ajustes, especialmente las credenciales, de variables de entorno.

# backend.tf
terraform {
  backend "s3" {}
}

# prod.s3.tfbackend
bucket = "example-prod-state"
key    = "app/terraform.tfstate"
region = "us-east-1"

$ terraform init -backend-config=prod.s3.tfbackend

Un bloque backend vacío como backend "s3" {} es válido y común; declara el tipo de backend y deja todos los ajustes para init. Terraform fusiona los valores del bloque, de los archivos y de la línea de comandos. La configuración final fusionada se guarda en .terraform/terraform.tfstate y en los archivos de plan guardados, así que ten en cuenta que los secretos pasados de esta forma se escriben en el disco local. Para las credenciales, las variables de entorno o la cadena de credenciales estándar de la plataforma suelen ser una mejor opción.

La configuración parcial funciona bien con los pipelines de CI, que pueden llamar a terraform init -backend-config=env/${ENV}.tfbackend para cada entorno mientras el código de Terraform permanece idéntico. También mantiene los detalles específicos de cada entorno o sensibles fuera del código compartido. El bloque cloud de HCP Terraform tiene una limitación similar y, en su lugar, puede leer ajustes de variables de entorno como TF_CLOUD_ORGANIZATION y TF_WORKSPACE.

Términos clave

Partial configuration (configuración parcial)
Dejar algunos argumentos del backend fuera del bloque backend y proporcionarlos en el momento de terraform init.
-backend-config
Un indicador de init que proporciona ajustes del backend, ya sea como pares KEY=VALUE o como la ruta a un archivo de configuración.
Backend configuration file (archivo de configuración del backend)
Un archivo HCL con argumentos del backend que se pasa con -backend-config, a menudo con el sufijo .tfbackend.
Early evaluation (evaluación temprana)
La razón por la que los backends no pueden usar variables: los backends se inicializan antes de que se evalúen las variables y los locals.
Ejemplo real

Un pipeline despliega el mismo código en dev y prod. El bloque backend es solo backend "azurerm" {}. El job de dev ejecuta terraform init -backend-config=dev.tfbackend y el de prod usa prod.tfbackend, cada uno apuntando a una cuenta de almacenamiento y una key distintas, con credenciales que provienen de la identidad administrada del pipeline.

Consejo para el examen: Si una pregunta muestra var. dentro de un bloque backend, la respuesta es que no está permitido; usa en su lugar archivos -backend-config o pares clave/valor en init.

Comprueba lo que sabes

¿Por qué un bloque backend no puede referenciar variables de entrada?

El backend se inicializa antes de que Terraform evalúe las variables y los locals, así que solo se permiten valores literales.

Nombra dos formas que acepta el indicador -backend-config.

Un par KEY=VALUE como -backend-config="bucket=my-state", o la ruta a un archivo que contiene argumentos del backend.
