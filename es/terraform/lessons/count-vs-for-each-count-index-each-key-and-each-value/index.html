`count` frente a `for_each`, `count.index`, `each.key` y `each.value`

Tanto count como for_each son meta-argumentos que crean varias instancias de un recurso, data source o módulo a partir de un solo bloque. Se parecen, pero identifican las instancias de forma distinta, y esa diferencia decide cuál deberías usar.

count recibe un número entero. Terraform crea esa cantidad de instancias, direccionadas por índice: aws_instance.web[0], aws_instance.web[1] y así sucesivamente. Dentro del bloque, count.index da el índice actual, empezando en cero.

resource "aws_instance" "web" {
  count         = 3
  ami           = var.ami_id
  instance_type = "t3.micro"
  tags = { Name = "web-${count.index}" }
}

for_each recibe un mapa o un set de cadenas. Terraform crea una instancia por elemento, direccionada por clave: aws_iam_user.dev["alice"]. Dentro del bloque, each.key es la clave del mapa o el elemento del set, y each.value es el valor del mapa; para un set, each.value es lo mismo que each.key. Una lista no se acepta directamente, así que envuélvela en toset().

resource "aws_iam_user" "dev" {
  for_each = toset(["alice", "bob", "carol"])
  name     = each.key
}

resource "aws_s3_bucket" "b" {
  for_each = { logs = "private", site = "public" }
  bucket   = "acme-${each.key}"
  tags     = { Access = each.value }
}

La diferencia clave aparece cuando cambia la colección. Supón que usaste count con una lista de tres nombres de usuario y eliminas el primero. Todos los nombres restantes bajan un índice, así que Terraform ve los índices 0 y 1 como cambiados y el índice 2 como eliminado. Eso puede significar renombrar o reemplazar objetos que no pretendías tocar. Con for_each, cada instancia está ligada a una clave estable; eliminar alice destruye solo ["alice"] y deja en paz a bob y carol.

Así que la regla general es: usa count cuando las instancias son casi idénticas e intercambiables, o cuando quieres un simple interruptor de encendido/apagado con count = var.enabled ? 1 : 0. Usa for_each cuando cada instancia tiene una identidad distinta o ajustes distintos. Un bloque no puede usar count y for_each a la vez. En ambos casos, el número de instancias, o las claves en el caso de for_each, deben conocerse en el momento del plan; no puedes basarlos en atributos que solo se conocen después del apply, como los IDs de recursos que se están creando en la misma ejecución.

Las referencias también funcionan de forma distinta. Un recurso con count es una lista, así que aws_instance.web[*].id obtiene todos los IDs. Un recurso con for_each es un mapa, así que usas aws_s3_bucket.b["logs"].arn para uno, o values(aws_s3_bucket.b)[*].arn o una expresión for para todos.

Términos clave

count
Meta-argumento que crea un número de instancias direccionadas por índice entero.
count.index
El índice, empezando en cero, de la instancia actual en un bloque con count.
for_each
Meta-argumento que crea una instancia por cada elemento de un mapa o set, direccionada por clave.
each.key / each.value
En un bloque con for_each, la clave y el valor del elemento actual; son idénticos para los sets.
Ejemplo real

Un equipo gestiona las cuentas de desarrolladores con count sobre una lista de nombres. Cuando un desarrollador se va y se elimina del inicio de la lista, el plan quiere renombrar otras dos cuentas. Cambian a for_each = toset(var.developers), moviendo las entradas de estado existentes a las nuevas claves con bloques moved, y las eliminaciones futuras solo afectan a la persona que se va.

Consejo para el examen: for_each acepta mapas y sets de cadenas, no listas, y da claves estables. Los índices de count se desplazan cuando se eliminan elementos del medio. No puedes usar ambos en un mismo bloque.

Comprueba lo que sabes

¿Por qué for_each suele ser más seguro que count para una lista de usuarios con nombre?

Las instancias se identifican por nombre, así que eliminar un usuario afecta solo a esa instancia; con count, eliminar un elemento desplaza los índices y cambia otras instancias.

En un for_each sobre toset(["a", "b"]), ¿qué son each.key y each.value para el primer elemento?

Ambos son "a", porque en un set la clave y el valor son iguales.
