Opciones de planificación: `-var`, `-var-file`, `-target`, `-refresh=false`, `-refresh-only`, `-replace`

terraform plan acepta opciones que cambian las entradas o el comportamiento de la planificación. La mayoría funciona de la misma manera en terraform apply, porque apply sin un archivo de plan guardado primero crea un plan.

-var y -var-file proporcionan valores de variables de entrada. -var 'instance_count=3' establece una variable en la línea de comandos. -var-file=prod.tfvars carga valores desde un archivo. Puedes repetir cualquiera de las dos opciones; cuando la misma variable se establece más de una vez, gana la última en la línea de comandos. Estos valores de línea de comandos tienen la precedencia más alta, por encima de las variables de entorno y de los archivos que se cargan automáticamente, como terraform.tfvars. Un patrón típico es un archivo de variables por entorno, como dev.tfvars y prod.tfvars.

-target=ADDRESS limita la planificación a un recurso o módulo y a todo aquello de lo que depende, por ejemplo -target=aws_instance.web o -target=module.network. Terraform muestra una advertencia cuando lo usas, porque el resultado es una vista parcial que ignora otros cambios pendientes y puede dejar la configuración y el estado desalineados. HashiCorp lo recomienda solo para situaciones excepcionales, como recuperarse de un error o sortear un bug de un provider, no para uso rutinario.

-refresh=false omite el paso de refresh y planifica solo a partir del estado. Es más rápido en configuraciones grandes, pero Terraform no notará el drift, así que el plan puede ser incorrecto si algo cambió fuera de Terraform.

-refresh-only crea un tipo de plan diferente. En lugar de proponer cambios a la infraestructura, propone actualizar el estado para que coincida con lo que informan los providers. Úsalo para revisar el drift: terraform plan -refresh-only muestra lo que cambió fuera de Terraform, y terraform apply -refresh-only acepta esos cambios en el estado sin tocar ningún objeto real. Esto reemplaza al antiguo comando terraform refresh, que actualizaba el estado sin mostrártelo primero y está obsoleto.

-replace=ADDRESS obliga a Terraform a planificar el reemplazo de una instancia de recurso específica aunque su configuración no haya cambiado, por ejemplo cuando una máquina virtual no está sana. Puede repetirse para varios recursos.

terraform plan -var-file=prod.tfvars -var 'instance_count=5'
terraform plan -target=module.network
terraform plan -refresh-only
terraform apply -replace='aws_instance.web[0]'

Pon entre comillas las direcciones que contienen corchetes o comillas para que tu shell no las interprete. Recuerda también que un plan guardado ya contiene sus valores de variables y opciones, así que estos se establecen al ejecutar plan, no al aplicar el archivo guardado.

Términos clave

-var / -var-file
Opciones que establecen valores de variables de entrada en la línea de comandos o desde un archivo; tienen la precedencia más alta y gana la última.
-target
Limita la planificación a recursos o módulos específicos y sus dependencias; solo para uso excepcional.
-refresh-only
Modo de plan o apply que actualiza el estado para que coincida con la infraestructura real sin cambiar esa infraestructura.
-replace
Fuerza el reemplazo de una instancia de recurso específica en el plan.
Ejemplo real

Una administradora sospecha que alguien cambió a mano un ajuste de un balanceador de carga. Ejecuta terraform plan -refresh-only, ve el atributo con drift y decide si aceptarlo en el estado con apply -refresh-only o actualizar el código, en lugar de dejar que un apply normal lo revierta en silencio.

Consejo para el examen: -refresh=false omite la comprobación de la realidad; -refresh-only hace solo esa comprobación y actualiza el estado. terraform refresh está obsoleto en favor de apply -refresh-only.

Comprueba lo que sabes

¿Qué cambia terraform apply -refresh-only?

Solo el archivo de estado, actualizándolo para que coincida con la infraestructura real; no se crea, modifica ni destruye ninguna infraestructura.

Si -var-file=prod.tfvars y un -var 'size=large' posterior establecen ambos size, ¿qué valor se usa?

large, porque las opciones de la línea de comandos se procesan en orden y gana el último valor.
