El bloque `required_providers`: direcciones `source` (hostname/namespace/type) y restricciones `version`

Todo provider que usa un módulo debe declararse en un bloque required_providers anidado dentro del bloque terraform. Cada entrada asocia un nombre local, que es como te refieres al provider dentro de este módulo, con dos ajustes clave: la dirección source, que indica dónde encontrar el provider, y una restricción version, que indica qué versiones son aceptables.

terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
    random = {
      source  = "hashicorp/random"
      version = ">= 3.5"
    }
  }
}

Una dirección source tiene tres partes: HOSTNAME/NAMESPACE/TYPE. El hostname es el registro que distribuye el provider. Es opcional y su valor predeterminado es registry.terraform.io, el Terraform Registry público, así que hashicorp/aws es una forma abreviada de registry.terraform.io/hashicorp/aws. El namespace es la organización o persona que publica el provider, como hashicorp para los providers que mantiene HashiCorp o integrations para el provider de GitHub. El type es el nombre corto del provider, como aws, azurerm o github, y por convención coincide con el prefijo de los tipos de recursos de ese provider.

Los registros privados usan un hostname distinto. Una organización que usa el registro privado de HCP Terraform, por ejemplo, escribiría un source cuyo hostname es la dirección de HCP Terraform seguida del nombre de la organización y el tipo del provider. El formato es el mismo; solo cambia el host. Terraform también puede configurarse para instalar providers desde mirrors (réplicas) locales, lo que es útil en redes sin acceso a internet.

El nombre local, la clave de la izquierda como aws, normalmente coincide con el type, y es lo que usas en los bloques provider "aws" y lo que Terraform compara con los prefijos de los tipos de recursos. Solo necesita ser único dentro del módulo. Si dos providers de namespaces distintos comparten el mismo nombre de type, puedes darle a uno de ellos un nombre local diferente.

El argumento version acepta una cadena de restricción, que se explica en detalle en la siguiente lección. Las restricciones de required_providers se combinan entre todos los módulos de la configuración: si el módulo raíz pide >= 5.0 y un módulo hijo pide < 6.0, Terraform elige la versión más reciente que cumpla ambas. La versión realmente seleccionada se registra luego en el archivo de bloqueo de dependencias.

Si usas un recurso sin declarar su provider, Terraform asume un source hashicorp/<prefix>. Eso funciona para los providers propios de HashiCorp, pero falla o elige el provider equivocado para todos los demás, así que declara siempre los providers de forma explícita. La buena práctica es que los módulos reutilizables indiquen una versión mínima y que los módulos raíz también establezcan un límite superior.

Términos clave

required_providers
Bloque dentro de terraform que declara el nombre local, la dirección source y la restricción de versión de cada provider.
Source address (dirección source)
El identificador HOSTNAME/NAMESPACE/TYPE que le indica a Terraform desde dónde descargar un provider.
Namespace (espacio de nombres)
La parte de la dirección source que corresponde al publicador, como hashicorp o el nombre de una empresa o usuario.
Local name (nombre local)
El nombre de un provider específico del módulo, usado en los bloques provider y asociado a los prefijos de los tipos de recursos.
Ejemplo real

Un equipo agrega el provider de Datadog. Declara datadog = { source = "DataDog/datadog", version = "~> 3.0" } en required_providers, ejecuta terraform init, y Terraform lo descarga del registro público porque no se indicó ningún hostname.

Consejo para el examen: Si una pregunta muestra source = "hashicorp/aws" y pide la dirección completa, el hostname predeterminado oculto es registry.terraform.io.

Comprueba lo que sabes

¿Cuáles son las tres partes de la dirección source de un provider y cuál es opcional?

Hostname, namespace y type; el hostname es opcional y su valor predeterminado es registry.terraform.io.

Si el módulo raíz requiere aws versión >= 5.0 y un módulo hijo requiere < 5.40, ¿qué elige Terraform?

La versión disponible más reciente que cumpla ambas restricciones, que luego se registra en el archivo de bloqueo.
