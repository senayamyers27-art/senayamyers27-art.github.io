Contenido del estado: atributos de los recursos, incluidos valores sensibles, en JSON plano

El archivo de estado es un documento JSON. Abre un terraform.tfstate local en un editor de texto y verás una versión del formato, la versión de Terraform que lo escribió, un número de serie (serial) que aumenta con cada escritura, un identificador de linaje (lineage) que une todas las versiones de un mismo estado, los outputs del módulo raíz y una lista resources. Cada entrada de recurso registra su modo (managed o data), tipo, nombre, provider y una o más instancias con todos los valores de sus atributos y sus dependencias.

El punto de seguridad importante es que el estado contiene todos los atributos que Terraform conoce, y eso incluye los valores sensibles. El argumento de contraseña de un recurso de base de datos, el resultado de un random_password generado, las claves privadas creadas por el provider tls y las claves de acceso devueltas por un recurso de identidad se guardan todos, en texto plano, en el archivo de estado. Marcar una variable o un output con sensitive = true oculta el valor en la salida del plan y en la consola, pero no lo elimina ni lo cifra en el estado.

{
  "version": 4,
  "serial": 7,
  "resources": [
    {
      "mode": "managed",
      "type": "random_password",
      "name": "db",
      "instances": [ { "attributes": { "result": "(plaintext secret here)" } } ]
    }
  ]
}

Por esto, debes tratar el estado como datos sensibles. No hagas commit de terraform.tfstate ni de su backup en Git; agrégalos a .gitignore. Guarda el estado en un backend remoto que cifre los datos en reposo y en tránsito y restrinja quién puede leerlos, como HCP Terraform, o un bucket de almacenamiento en la nube con cifrado, versionado y políticas de acceso estrictas. Limita qué personas y pipelines pueden leer el estado, ya que leer el estado puede equivaler a leer todos los secretos que contiene. Los archivos de plan guardados también contienen datos sensibles y necesitan el mismo cuidado.

Las versiones más recientes de Terraform reducen cuántos secretos llegan al estado. Los valores efímeros (ephemeral), como las variables de entrada efímeras y los recursos efímeros, existen solo durante una ejecución y nunca se escriben en el estado ni en los archivos de plan. Los argumentos de solo escritura (write-only) permiten que un provider acepte un valor, como una contraseña, que Terraform envía a la API pero no guarda. Usar un gestor de secretos y leer los secretos en tiempo de ejecución, en lugar de generarlos en Terraform, es otra forma de mantenerlos fuera del estado.

Para inspeccionar el estado de forma segura, usa la CLI en lugar de abrir el archivo: terraform state list muestra las direcciones de los recursos, terraform state show ADDRESS muestra los atributos de un recurso con los valores sensibles ocultos, y terraform show -json da una vista legible por máquina. terraform output -json revela en texto plano los valores de los outputs sensibles, lo que es útil para scripts, pero debe manejarse con cuidado.

Términos clave

terraform.tfstate
El archivo de estado local predeterminado, un documento JSON que registra los recursos gestionados y sus atributos.
sensitive (sensible)
Un indicador en variables y outputs que oculta los valores en la salida de la CLI; los valores igual se guardan en el estado.
Ephemeral value (valor efímero)
Un valor que existe solo durante una ejecución de Terraform y nunca se persiste en el estado ni en los archivos de plan.
Serial and lineage (serial y lineage)
Metadatos del estado: el serial aumenta con cada escritura, y el lineage identifica el historial de un único estado.
Ejemplo real

Un escaneo de seguridad de un repositorio público encuentra un terraform.tfstate incluido en un commit que contiene la contraseña del administrador de una base de datos. El equipo rota la contraseña, elimina el archivo del historial, agrega los archivos de estado a .gitignore y mueve el estado a un backend remoto cifrado con acceso restringido.

Consejo para el examen: sensitive = true oculta los valores en la salida, no en el estado. La protección correcta para los secretos en el estado es un backend seguro, cifrado y con control de acceso, además de valores efímeros o argumentos de solo escritura cuando estén disponibles.

Comprueba lo que sabes

¿Una variable marcada con sensitive = true se cifra en el archivo de estado?

No. Se oculta en la salida del plan y de la CLI, pero el estado la guarda en JSON de texto plano, así que el propio estado debe protegerse.

Nombra dos formas de mantener un secreto completamente fuera del estado en las versiones recientes de Terraform.

Usar valores efímeros (variables o recursos efímeros) o argumentos de solo escritura, que Terraform no persiste.
