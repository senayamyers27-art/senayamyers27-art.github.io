Pasar configuraciones de providers a los módulos con el argumento `providers`

Los recursos de un módulo hijo necesitan una configuración de provider, como un provider de AWS configurado para una región y una cuenta concretas. De forma predeterminada, un módulo hijo hereda automáticamente las configuraciones de provider predeterminadas (sin alias) de su padre. Si tu módulo raíz tiene un solo bloque provider "aws", cada módulo que usa recursos de AWS lo usa discretamente. Esa herencia implícita cubre la mayoría de las configuraciones simples.

Las cosas cambian cuando tienes más de una configuración del mismo provider. Creas configuraciones adicionales con el meta-argumento alias, por ejemplo un segundo provider de AWS para otra región: provider "aws" { alias = "west" region = "us-west-2" }, referenciado como aws.west. Las configuraciones con alias nunca se heredan implícitamente. Para que un módulo use una, la pasas explícitamente con el argumento providers en el bloque module.

provider "aws" {
  region = "us-east-1"
}

provider "aws" {
  alias  = "west"
  region = "us-west-2"
}

module "replica" {
  source = "./modules/bucket"
  providers = {
    aws = aws.west
  }
}

El argumento providers es un mapa. La clave es el nombre del provider tal como lo ve el módulo hijo, y el valor es una configuración de provider del módulo que llama. En el ejemplo, todo lo que en ./modules/bucket usa aws recibe la configuración de us-west-2. Una vez que estableces providers para un módulo, Terraform usa solo las asociaciones que listaste, así que incluye todos los providers que necesita el módulo.

Algunos módulos necesitan dos configuraciones del mismo provider a la vez, por ejemplo para configurar la replicación entre un bucket de origen y un bucket de destino en regiones distintas. Un módulo así declara los nombres adicionales que espera con configuration_aliases dentro de su entrada de required_providers, como configuration_aliases = [aws.src, aws.dst]. Quien llama asocia entonces ambos: providers = { aws.src = aws.east, aws.dst = aws.west }.

La buena práctica es que los módulos hijos reutilizables no contengan sus propios bloques provider. La configuración de providers pertenece al módulo raíz, y los módulos hijos declaran solo sus requisitos de required_providers (source y restricciones de versión). Los módulos que contienen bloques provider se llaman módulos legacy (heredados) y no pueden usarse con count, for_each ni depends_on. También causan problemas al eliminarlos, porque Terraform necesita la configuración del provider para destruir los recursos del módulo. Mantener los providers en el raíz y pasarlos hacia abajo les da a quienes llaman el control sobre regiones, cuentas y credenciales.

Términos clave

Provider alias (alias de provider)
Una configuración adicional con nombre de un provider, creada con el meta-argumento alias y referenciada como PROVIDER.ALIAS.
providers argument (argumento providers)
Un mapa en un bloque module que asigna las configuraciones de provider de quien llama a los nombres de provider que usa el módulo hijo.
Implicit provider inheritance (herencia implícita de providers)
El comportamiento predeterminado en el que los módulos hijos usan automáticamente las configuraciones de provider predeterminadas, sin alias, del padre.
configuration_aliases
Un ajuste de required_providers en un módulo hijo que declara nombres adicionales de configuración de provider que quien llama debe pasar.
Ejemplo real

Un módulo de recuperación ante desastres crea una base de datos principal en una región y una réplica en otra. Declara configuration_aliases = [aws.primary, aws.replica], y el módulo raíz lo llama con providers = { aws.primary = aws, aws.replica = aws.dr }, así que una sola llamada al módulo construye recursos en dos regiones.

Consejo para el examen: Las configuraciones de provider predeterminadas se heredan automáticamente; las que tienen alias nunca se heredan y deben pasarse con el mapa providers en el bloque module.

Comprueba lo que sabes

Tu módulo raíz define el provider aws con alias eu. ¿Cómo haces que el módulo logs lo use?

Agrega providers = { aws = aws.eu } al bloque module "logs".

¿Por qué los módulos reutilizables deben evitar sus propios bloques provider?

La configuración de providers le corresponde a quien llama; los módulos con bloques provider no pueden usar count, for_each ni depends_on y son difíciles de eliminar de forma segura.
