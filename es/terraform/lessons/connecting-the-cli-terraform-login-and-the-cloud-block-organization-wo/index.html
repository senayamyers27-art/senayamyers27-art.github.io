Conectar la CLI: `terraform login` y el bloque `cloud` (organización, workspaces por nombre o por etiquetas)

Para usar HCP Terraform desde tu terminal, deben cumplirse dos cosas: la CLI debe poder autenticarse en HCP Terraform, y la configuración debe indicar a qué organización y workspaces pertenece. terraform login se encarga de lo primero; el bloque cloud se encarga de lo segundo.

terraform login abre una página en el navegador donde generas un token de API para tu cuenta de usuario, y luego te pide que lo pegues en la terminal. La CLI guarda el token en un archivo de credenciales en tu perfil de usuario, llamado credentials.tfrc.json, en el directorio .terraform.d en Linux y macOS (en el directorio de datos de aplicaciones en Windows). El token se guarda en texto plano, así que protege ese archivo. De forma predeterminada, el comando apunta al hostname estándar de HCP Terraform; para Terraform Enterprise, pasa el hostname: terraform login tfe.example.com. terraform logout elimina el token guardado.

En la automatización no hay navegador, así que los pipelines proporcionan el token de otra forma: mediante una variable de entorno llamada TF_TOKEN_ seguida del hostname con los puntos reemplazados por guiones bajos (por ejemplo TF_TOKEN_app_terraform_io), o mediante un archivo de configuración de la CLI. Para CI, un token de equipo o de organización o una cuenta de servicio dedicada suele ser mejor que un token personal.

terraform {
  cloud {
    organization = "example-org"
    workspaces {
      tags = ["app", "aws"]
    }
  }
}

El argumento organization del bloque cloud nombra la organización. Dentro de workspaces, elige una de dos estrategias. Con name = "app-prod", la configuración se asocia a exactamente un workspace de HCP Terraform, que se crea en init si no existe. Con tags, la configuración se asocia a cada workspace que tenga todas las etiquetas listadas. El modo de etiquetas permite que una configuración sirva a varios workspaces, como app-dev y app-prod; cambias entre ellos con terraform workspace list y terraform workspace select, y terraform workspace new crea un workspace nuevo con esas etiquetas. No puedes establecer name y tags a la vez.

Después de escribir el bloque, ejecuta terraform init. Terraform se autentica con tu token, se conecta a la organización y configura el workspace. Si antes usabas estado local o el de otro backend, init ofrece migrarlo. A partir de entonces, terraform plan y apply se ejecutan de forma remota o local según el modo de ejecución del workspace, y el estado se guarda en el workspace.

Las variables de entorno pueden completar o anular los ajustes del bloque, lo que es útil para los pipelines: TF_CLOUD_ORGANIZATION, TF_CLOUD_HOSTNAME, TF_CLOUD_PROJECT y TF_WORKSPACE. Eso permite incluso un bloque cloud {} vacío con todos los detalles proporcionados por el entorno.

Términos clave

terraform login
Un comando que obtiene un token de API de HCP Terraform mediante el navegador y lo guarda localmente para la CLI.
credentials.tfrc.json
El archivo local donde terraform login guarda los tokens de API en texto plano.
TF_TOKEN_hostname
Una variable de entorno que proporciona un token de API para un host dado, como TF_TOKEN_app_terraform_io.
Workspace tags mapping (asociación de workspaces por etiquetas)
Usar tags en el bloque cloud para que una configuración se asocie a varios workspaces de HCP Terraform.
Ejemplo real

Una desarrolladora clona un repositorio con un bloque cloud que usa tags = ["billing"]. Ejecuta terraform login, pega un token, ejecuta terraform init y luego terraform workspace select billing-dev para trabajar en el workspace de dev antes de que un colega aplique en billing-prod desde un pull request revisado.

Consejo para el examen: terraform login guarda un token en credentials.tfrc.json; en CI usa TF_TOKEN_<host> en su lugar. En el bloque cloud, workspaces usa name (uno) o tags (varios), nunca ambos.

Comprueba lo que sabes

¿Cómo se autentica un job de CI en HCP Terraform sin terraform login?

Estableciendo una variable de entorno como TF_TOKEN_app_terraform_io con un token de API.

¿Qué hace tags en el bloque workspaces del bloque cloud?

Asocia la configuración a todos los workspaces que tienen esas etiquetas, para que puedas cambiar entre ellos con terraform workspace select.
