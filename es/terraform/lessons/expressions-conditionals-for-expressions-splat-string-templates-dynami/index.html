Expresiones: condicionales, expresiones `for`, splat `[*]`, plantillas de cadenas y bloques `dynamic`

Las expresiones calculan valores en Terraform. Además de los literales y las referencias, un puñado de formas de expresión te permiten tomar decisiones, transformar colecciones y generar bloques repetidos sin escribir un programa de propósito general. Una expresión condicional usa la forma condition ? true_value : false_value. Por ejemplo, instance_type = var.environment == "prod" ? "m5.large" : "t3.micro". Ambos resultados deben ser del mismo tipo, o convertibles a uno, porque Terraform debe conocer el tipo del resultado. Un modismo común es count = var.create_bucket ? 1 : 0 para hacer que un recurso sea opcional.

Una expresión for transforma una colección en otra. Los corchetes producen una lista o tupla; las llaves producen un objeto o mapa, usando => entre la clave y el valor. Una cláusula if opcional filtra elementos.

upper_names = [for n in var.names : upper(n)]
port_by_svc = { for k, s in var.services : k => s.port }
public_only = [for s in var.servers : s.name if s.public]

Una expresión splat es una forma abreviada de una expresión for común. aws_instance.web[*].id significa lo mismo que [for i in aws_instance.web : i.id]: toma una lista de objetos y devuelve una lista con un atributo de cada uno. Funciona con listas, sets y tuplas, como los recursos creados con count. No funciona directamente con mapas, así que para un recurso con for_each usas values(aws_instance.web)[*].id o una expresión for.

Las plantillas de cadenas incrustan expresiones en cadenas. La interpolación, "${var.project}-logs", inserta un valor. Las directivas agregan lógica: %{ if var.enabled }on%{ else }off%{ endif } y %{ for ip in var.ips }${ip} %{ endfor }. Las cadenas de varias líneas usan la sintaxis heredoc, de <<EOT a EOT, y la forma <<-EOT elimina la sangría inicial común. Para escribir un ${ literal, lo escapas como $${. Para plantillas más grandes, guárdalas en un archivo separado y renderízalas con la función templatefile.

Un bloque dynamic genera bloques anidados repetidos dentro de un recurso, como varias reglas ingress en un security group, a partir de una colección. La etiqueta nombra el tipo de bloque anidado, for_each proporciona la colección y un bloque content describe cada uno. Dentro, el iterador lleva el nombre de la etiqueta del bloque a menos que configures iterator.

dynamic "ingress" {
  for_each = var.allowed_ports
  content {
    from_port   = ingress.value
    to_port     = ingress.value
    protocol    = "tcp"
    cidr_blocks = ["10.0.0.0/8"]
  }
}

Los bloques dynamic hacen flexibles los módulos, pero abusar de ellos hace que el código sea difícil de leer. HashiCorp aconseja usarlos principalmente para ocultar detalles en módulos reutilizables y escribir los bloques anidados de forma literal cuando sea posible. Solo pueden generar bloques anidados dentro de un bloque resource, data, provider o provisioner, no recursos completos, ni bloques de meta-argumentos como lifecycle.

Términos clave

Conditional expression (expresión condicional)
condition ? a : b, que elige uno de dos valores según un booleano.
for expression (expresión for)
Una expresión que construye una lista o un mapa transformando, y opcionalmente filtrando, otra colección.
Splat expression (expresión splat)
La forma abreviada [*] que extrae un atributo de cada elemento de una lista, como aws_instance.web[*].id.
String template (plantilla de cadena)
Una cadena con interpolación ${...} o directivas %{...}.
dynamic block (bloque dynamic)
Una construcción que genera bloques anidados repetidos a partir de una colección usando for_each y content.
Ejemplo real

Un módulo de security group acepta una lista de puertos. Un bloque dynamic "ingress" produce una regla por puerto, y un output usa una expresión for para devolver un mapa de descripciones de reglas, de modo que quienes lo llaman pueden agregar puertos sin editar el módulo.

Consejo para el examen: Debes saber qué produce cada tipo de corchete: [for ...] da una lista o tupla, {for ... : k => v} da un mapa u objeto. Splat funciona con listas, no con mapas, y dynamic genera bloques anidados, no recursos.

Comprueba lo que sabes

Escribe una expresión que devuelva los IDs de todas las instancias de un recurso basado en count, aws_instance.web.

aws_instance.web[*].id, equivalente a [for i in aws_instance.web : i.id].

Dentro de dynamic "ingress" sin iterator configurado, ¿cómo te refieres al elemento actual?

Como ingress.value (e ingress.key para su clave o índice).
