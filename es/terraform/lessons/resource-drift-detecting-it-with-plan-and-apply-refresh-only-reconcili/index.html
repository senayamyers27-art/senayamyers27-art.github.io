Drift de recursos: detectarlo con `plan` y `apply -refresh-only`, y reconciliar la configuración

El drift (deriva) ocurre cuando la infraestructura real ya no coincide con lo que Terraform registró por última vez. Alguien edita un security group en la consola, un proceso de autoscaling cambia un ajuste o un recurso se elimina a mano. Terraform no vigila tu infraestructura de forma continua, así que el drift permanece invisible hasta la próxima vez que Terraform compruebe.

Esa comprobación es el paso de refresh. De forma predeterminada, terraform plan y terraform apply primero hacen refresh: le piden a los providers el estado actual de cada objeto gestionado y actualizan la vista en memoria de Terraform. Luego el plan compara la configuración con esa vista actualizada. Si alguien cambió algo, el plan muestra una nota de que hubo objetos que cambiaron fuera de Terraform, seguida de las acciones necesarias para volver a alinear la realidad con tu configuración. Un recurso eliminado aparece como que necesita crearse de nuevo.

A veces quieres ver o aceptar el drift sin cambiar la infraestructura. terraform plan -refresh-only muestra cómo cambiaría el estado para coincidir con la realidad, sin proponer ningún cambio en la infraestructura. terraform apply -refresh-only hace lo mismo y, después de que lo apruebas, escribe esos valores actualizados en el archivo de estado. Nunca crea, modifica ni destruye objetos reales. Esto reemplazó al antiguo comando terraform refresh, que actualizaba el estado sin mostrarte qué cambiaría ni pedir aprobación, y que ahora está obsoleto.

$ terraform plan -refresh-only
Note: Objects have changed outside of Terraform
  # aws_security_group.web has changed
  ~ ingress = [...]

Detectar el drift es la mitad del trabajo; reconciliarlo es la otra mitad. Tienes dos opciones. Si el cambio manual fue incorrecto, simplemente ejecuta un terraform apply normal, y Terraform devuelve el recurso a lo que dice tu configuración. Si el cambio manual fue correcto (por ejemplo, una corrección de emergencia que debe quedarse), actualiza la configuración para que coincida con él y luego ejecuta plan para confirmar que no hay cambios. Usar solo apply -refresh-only únicamente actualiza el estado; en el siguiente plan normal, Terraform seguirá intentando revertir el objeto si la configuración no coincide.

Para reducir el drift, limita el acceso a la consola para los recursos que gestiona Terraform, haz los cambios mediante revisión de código y usa lifecycle { ignore_changes = [...] } para los atributos que legítimamente se gestionan en otro lugar, como un número deseado ajustado por un autoscaler. Las evaluaciones de estado (health assessments) de HCP Terraform también pueden ejecutar la detección de drift de forma programada y avisarte.

Términos clave

Drift (deriva)
Una diferencia entre la infraestructura real y el estado que Terraform registró por última vez, normalmente por cambios hechos fuera de Terraform.
Refresh (actualización)
El paso en el que Terraform lee de los providers el estado actual de los objetos gestionados antes de planificar.
-refresh-only
Un modo de plan o apply que solo actualiza el estado para que coincida con la infraestructura real, sin cambiar ningún recurso.
ignore_changes
Un ajuste de lifecycle que le indica a Terraform que ignore los cambios en atributos específicos al planificar.
Ejemplo real

Durante un incidente, un ingeniero abre el puerto 8443 en un security group desde la consola. El siguiente terraform plan informa que el grupo cambió fuera de Terraform y propone eliminar la regla. Como el cambio debe quedarse, el equipo agrega la regla a la configuración, y el siguiente plan no muestra cambios.

Consejo para el examen: apply -refresh-only solo actualiza el estado y nunca cambia la infraestructura; para conservar un cambio manual de forma permanente también debes actualizar la configuración.

Comprueba lo que sabes

¿Qué comando actualiza el estado para que coincida con la infraestructura real sin cambiar ningún recurso?

terraform apply -refresh-only.

¿Qué pasa si ejecutas un terraform apply normal después de que alguien cambió manualmente un recurso gestionado?

Terraform planea devolver el recurso a lo que dice la configuración.

¿Qué comando antiguo reemplaza -refresh-only?

terraform refresh, que está obsoleto porque actualizaba el estado sin revisión.
