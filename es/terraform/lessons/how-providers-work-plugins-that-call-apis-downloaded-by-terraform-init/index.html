Cómo funcionan los providers: plugins que llaman a APIs, descargados por `terraform init` desde el Terraform Registry

Un provider es un programa separado, normalmente escrito en Go con el framework de plugins de HashiCorp, que sabe cómo gestionar una plataforma. Terraform core inicia el proceso del provider cuando lo necesita y se comunica con él mediante un protocolo RPC local. El provider recibe solicitudes como valida esta configuración de recurso, planifica este cambio, crea este objeto o lee el estado actual de este objeto, y convierte cada una en llamadas a la API de la plataforma, usando las credenciales y los ajustes de su configuración de provider.

Cada provider define un schema (esquema): los tipos de recursos y data sources que ofrece, sus argumentos y atributos, qué argumentos son obligatorios u opcionales, cuáles calcula la plataforma y qué cambios fuerzan un reemplazo. Terraform core usa el schema para comprobar los tipos de tu configuración, y la documentación del provider en el registro se genera a partir de él, por eso cada página de recurso lista referencias de argumentos y atributos.

Los providers se instalan con terraform init. Init lee required_providers de cada módulo, resuelve una versión que cumpla todas las restricciones y el archivo de bloqueo, descarga el paquete para tu sistema operativo y arquitectura, lo verifica y lo coloca en .terraform/providers dentro del directorio de trabajo. De forma predeterminada, los paquetes vienen del Terraform Registry público en registry.terraform.io, pero init también puede usar registros privados, mirrors de red, mirrors del sistema de archivos o un directorio compartido de caché de plugins configurado en el archivo de configuración de la CLI para evitar descargar el mismo provider en cada proyecto.

$ terraform init
Initializing provider plugins...
- Finding hashicorp/aws versions matching "~> 5.0"...
- Installing hashicorp/aws v5.x.y...
- Installed hashicorp/aws v5.x.y (signed by HashiCorp)
Terraform has created a lock file .terraform.lock.hcl

La salida también te dice quién firmó el paquete. Terraform verifica las firmas de los providers durante la instalación desde un registro, lo que ayuda a asegurar que ejecutas la build genuina del publicador.

Como los providers se versionan de forma independiente de Terraform, un nuevo servicio en la nube puede recibir soporte mediante una versión del provider sin esperar una versión de Terraform. También significa que las actualizaciones de providers pueden cambiar el comportamiento, por eso fijas versiones y revisas los cambios del archivo de bloqueo.

Una vez instalados, los providers se usan en cada plan y apply. Durante la planificación, Terraform le pide a cada provider que lea el estado actual de los objetos gestionados (refresh) y que calcule el cambio planificado para cada recurso. Durante el apply, le pide al provider que lleve a cabo cada cambio, en orden de dependencias, y registra en el estado los atributos devueltos.

Términos clave

Provider schema (esquema del provider)
La definición del provider de sus tipos de recursos, data sources, argumentos y atributos.
Plugin cache (caché de plugins)
Un directorio compartido opcional donde init guarda los paquetes de providers para reutilizarlos entre directorios de trabajo.
Provider mirror (mirror de providers)
Una copia local o de red de los paquetes de providers que se usa en lugar del registro público, por ejemplo en redes aisladas.
Computed attribute (atributo calculado)
Un valor establecido por el provider o la plataforma después de la creación, como un ID, en lugar de por tu configuración.
Ejemplo real

Una persona nueva en el equipo clona el repositorio y ejecuta terraform plan. Falla, diciendo que los providers requeridos no están instalados. Después de ejecutar terraform init, el provider de AWS se descarga en .terraform/providers con la versión registrada en el archivo de bloqueo, y ahora plan funciona.

Consejo para el examen: Los providers se instalan con terraform init, no con plan ni apply, y de forma predeterminada vienen del Terraform Registry público. Agregar o cambiar un provider siempre requiere ejecutar init de nuevo.

Comprueba lo que sabes

¿Dónde coloca terraform init los plugins de providers descargados?

En el directorio .terraform/providers dentro del directorio de trabajo, a menos que se configure una caché de plugins compartida.

¿Qué parte de Terraform traduce un cambio planificado en llamadas a la API?

El plugin del provider; Terraform core le envía solicitudes por RPC y él llama a la API de la plataforma.
