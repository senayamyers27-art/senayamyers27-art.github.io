Alcance de las variables: los módulos hijos solo ven los valores que se les pasan; los outputs se leen como `module.NAME.OUTPUT`

Los módulos son cajas selladas. Un módulo hijo no puede ver las variables, los locals, los recursos ni los data sources del módulo que lo llama, y quien llama no puede entrar en el hijo para leer sus recursos directamente. La única forma de entrar es mediante las variables de entrada, y la única forma de salir es mediante los outputs. Este alcance estricto es lo que hace que un módulo sea predecible y reutilizable, porque su comportamiento depende solo de los valores que recibe.

Considera un módulo raíz con variable "region". Un módulo hijo que escribe var.region se refiere a su propia variable region, no a la del raíz. Si el hijo no declara una, la referencia es un error. Para que el valor del raíz esté disponible, el hijo debe declarar variable "region" y quien llama debe pasarla en el bloque module: region = var.region. La misma regla se aplica a las variables de entorno establecidas con TF_VAR_region: solo establecen variables del módulo raíz, nunca variables de módulos hijos directamente.

En el otro sentido, un hijo expone datos con bloques output. Quien llama lee esos outputs usando la sintaxis module.MODULE_NAME.OUTPUT_NAME. Si el módulo usa count, lo indexas (module.web[0].ip), y con for_each usas la clave (module.web["blue"].ip). Todo lo que el hijo no exporta se mantiene privado; no puedes escribir module.network.aws_vpc.this.id en una expresión.

# modules/network/outputs.tf
output "vpc_id" {
  value = aws_vpc.this.id
}

# main.tf del módulo raíz
resource "aws_security_group" "app" {
  vpc_id = module.network.vpc_id
}

Solo los outputs del módulo raíz se muestran después de terraform apply y con terraform output. Si quieres que el valor de un módulo hijo aparezca ahí, el módulo raíz debe volver a exportarlo con su propio output, como output "vpc_id" { value = module.network.vpc_id }. Este es un escenario muy común del examen: un valor existe en el output de un módulo hijo, pero no aparece en la línea de comandos porque el raíz nunca lo pasó hacia arriba.

Como los valores fluyen solo a través de interfaces explícitas, leer variables.tf y outputs.tf de un módulo te dice todo lo que necesitas para usarlo. Diseñar buenos módulos significa elegir esa interfaz con cuidado: exponer las entradas que quienes llaman realmente necesitan cambiar y los outputs que consumirán otras partes del sistema, como IDs, ARNs y endpoints, y mantener todo lo demás como interno.

Términos clave

Module scope (alcance del módulo)
La regla de que cada módulo tiene su propio espacio de nombres y ve solo sus propias variables, locals y recursos.
Output value (valor de output)
Un valor que un módulo exporta con un bloque output, que quien lo llama puede leer como module.NAME.OUTPUT.
Re-exporting (volver a exportar)
Declarar un output del módulo raíz cuyo valor es un output de un módulo hijo, para que aparezca en terraform output.
TF_VAR_ environment variable (variable de entorno TF_VAR_)
Una variable de entorno que establece una variable de entrada del módulo raíz; no llega directamente a los módulos hijos.
Ejemplo real

Un ingeniero ejecuta terraform output esperando ver el endpoint de la base de datos, pero no aparece nada. El endpoint es un output de module.db, y el módulo raíz nunca lo volvió a exportar. Agregar output "db_endpoint" { value = module.db.endpoint } en el raíz lo hace visible.

Consejo para el examen: Los valores bajan solo mediante los argumentos del bloque module y suben solo mediante los outputs; un hijo nunca puede leer directamente los valores var. del padre.

Comprueba lo que sabes

¿Cómo lee el módulo raíz el output subnet_ids de un módulo llamado network?

Con module.network.subnet_ids.

¿Por qué el output de un módulo hijo no aparece en terraform output?

terraform output muestra solo los outputs del módulo raíz; el raíz debe declarar su propio output que referencie el output del hijo.

Un módulo hijo referencia var.env, pero el raíz establece TF_VAR_env. ¿El hijo recibe el valor?

No automáticamente. El hijo debe declarar la variable env y el raíz debe pasarla en el bloque module.
