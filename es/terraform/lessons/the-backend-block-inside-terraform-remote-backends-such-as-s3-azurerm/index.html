El bloque `backend` dentro de `terraform {}`: backends remotos como S3, azurerm, gcs, consul y pg

Un backend decide dónde guarda Terraform el estado y, en algunos backends, cómo bloquea ese estado. Eliges uno con un bloque backend anidado dentro del bloque terraform de nivel superior del módulo raíz. Solo se puede configurar un backend por configuración, y solo importa el backend del módulo raíz; los módulos hijos no pueden tener el suyo propio.

Los backends remotos ponen el estado en un lugar compartido, duradero y con control de acceso, que es lo que necesitan los equipos. Todas las personas y todos los pipelines leen y escriben el mismo estado, el bloqueo evita las escrituras simultáneas y el servicio de almacenamiento puede proporcionar cifrado e historial de versiones. Terraform también lee y escribe el estado remoto en memoria siempre que puede, en lugar de dejar copias en el disco.

terraform {
  backend "s3" {
    bucket       = "example-tf-state"
    key          = "network/terraform.tfstate"
    region       = "us-east-1"
    encrypt      = true
    use_lockfile = true
  }
}

Los backends comunes que debes reconocer son estos. s3 guarda el estado como un objeto en un bucket de Amazon S3; key es la ruta del objeto, encrypt habilita el cifrado del lado del servidor, y el bloqueo usa un archivo de bloqueo en S3 (use_lockfile) o, en configuraciones antiguas, una tabla de DynamoDB. azurerm guarda el estado como un blob en un contenedor de Azure Storage, usando storage_account_name, container_name y key, y bloquea con leases de blobs. gcs guarda el estado en un bucket de Google Cloud Storage con bucket y prefix, y admite bloqueo. consul guarda el estado en el almacén clave/valor de HashiCorp Consul bajo una path. pg guarda el estado en una base de datos PostgreSQL. Hay otros, como http y kubernetes, y el backend local es el predeterminado cuando no se configura ninguno.

Cambiar el bloque backend requiere volver a inicializar. Después de agregarlo o editarlo, terraform init configura el backend y, si ya existe estado en otro lugar, ofrece copiarlo (consulta -migrate-state). Terraform registra los ajustes del backend activo en .terraform/terraform.tfstate dentro del directorio oculto .terraform; este pequeño archivo no es tu estado real y no debe confundirse con él.

Las credenciales del backend, como las claves de acceso a la nube, no deben escribirse en el bloque backend. Proporciónalas con las variables de entorno o los archivos de credenciales habituales al estilo de los providers, o con configuración parcial en el momento de init. HCP Terraform se configura con un bloque cloud separado en lugar de un bloque backend, y las configuraciones más antiguas todavía pueden usar el backend remote para el mismo servicio.

Términos clave

Backend
El componente que determina dónde se guarda el estado de Terraform y si puede bloquearse.
backend block (bloque backend)
Un bloque dentro de terraform {} que selecciona un tipo de backend y establece sus argumentos; solo uno por módulo raíz.
Remote backend (backend remoto)
Un backend que guarda el estado en un servicio compartido como S3, Azure Storage, GCS, Consul o PostgreSQL.
key (s3/azurerm)
La ruta o el nombre del blob bajo el cual se guarda el archivo de estado en el bucket o contenedor.
Ejemplo real

Un equipo pasa del estado local al backend s3. Agrega un bloque backend "s3" con el bucket, la key, la región, encrypt = true y bloqueo, ejecuta terraform init, acepta el aviso para copiar el estado existente y, desde entonces, cada ingeniero y el pipeline de CI comparten el mismo estado bloqueado.

Consejo para el examen: El bloque backend va dentro de terraform {}, solo en el módulo raíz, y cualquier cambio en él requiere ejecutar terraform init de nuevo.

Comprueba lo que sabes

¿Dónde se coloca un bloque backend?

Dentro del bloque terraform de nivel superior del módulo raíz.

¿Qué backend guarda el estado en Azure Storage y bloquea con leases de blobs?

El backend azurerm.

¿Qué debes ejecutar después de cambiar los ajustes del backend?

terraform init, que reconfigura el backend y puede migrar el estado existente.
