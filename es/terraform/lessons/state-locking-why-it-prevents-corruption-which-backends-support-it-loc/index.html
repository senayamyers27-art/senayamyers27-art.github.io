Bloqueo del estado: por qué evita la corrupción, qué backends lo admiten, `-lock-timeout` y `terraform force-unlock`

Imagina a dos ingenieros ejecutando terraform apply contra el mismo estado en el mismo momento. Ambos leen el mismo estado inicial, ambos hacen cambios en la nube y ambos intentan escribir un estado nuevo. El que escribe segundo sobrescribe al primero, y el estado ya no coincide con la realidad. El bloqueo del estado evita esto permitiendo que se ejecute solo una operación a la vez que pueda escribir el estado.

Cuando un backend admite bloqueo, Terraform adquiere el bloqueo automáticamente antes de cualquier operación que pueda escribir el estado, como plan, apply, destroy, import y los subcomandos de state que cambian el estado, y lo libera al final. Si otra persona tiene el bloqueo, tu comando falla con un error que muestra el ID del bloqueo, quién lo tiene, la operación y cuándo se tomó. No tienes que hacer nada para habilitar el bloqueo aparte de elegir un backend que lo admita.

No todos los backends admiten bloqueo. El backend local bloquea usando el bloqueo de archivos del sistema operativo. Entre los backends remotos, azurerm usa leases de blobs, gcs usa un archivo de bloqueo en el bucket, consul y pg (PostgreSQL) admiten bloqueo de forma nativa, y HCP Terraform bloquea los workspaces durante las ejecuciones. El backend s3 históricamente necesitaba una tabla de DynamoDB separada para el bloqueo; las versiones más recientes de Terraform pueden usar en su lugar un archivo de bloqueo en el propio bucket de S3 con use_lockfile = true, y el enfoque con DynamoDB se está retirando gradualmente. Revisa siempre la documentación del backend, porque un backend sin bloqueo te deja expuesto.

Dos indicadores controlan el comportamiento del bloqueo. -lock-timeout=DURATION, como -lock-timeout=5m, le dice a Terraform que siga reintentando durante ese tiempo antes de rendirse, lo que es útil en CI, donde los jobs podrían superponerse brevemente. El comportamiento predeterminado es fallar de inmediato. -lock=false deshabilita el bloqueo para un comando; es peligroso y debe evitarse salvo en situaciones de recuperación poco comunes.

$ terraform force-unlock 6f1c2a3b-9d4e-4a7b-8c21-0e5f7d9a1b22
Do you really want to force-unlock?
  Only 'yes' will be accepted to confirm.

A veces queda un bloqueo abandonado, por ejemplo si se cancela un job de CI o una laptop pierde la red en medio de un apply. terraform force-unlock LOCK_ID lo elimina. Recibe el ID de bloqueo que muestra el mensaje de error y solo desbloquea el estado de la configuración actual. Úsalo solo cuando estés seguro de que ninguna otra operación se está ejecutando realmente; forzar el desbloqueo de una ejecución activa provoca exactamente la corrupción que el bloqueo debía evitar.

Términos clave

State locking (bloqueo del estado)
Una función del backend que permite solo una operación de Terraform que escriba el estado a la vez, para evitar la corrupción.
-lock-timeout
Un indicador que hace que Terraform reintente adquirir un bloqueo ocupado durante un tiempo dado antes de fallar.
terraform force-unlock
Elimina manualmente un bloqueo abandonado usando su ID de bloqueo; solo debe usarse cuando no hay ninguna operación en ejecución.
Lock ID (ID de bloqueo)
El identificador que se muestra en un error de bloqueo y que force-unlock necesita para liberar ese bloqueo específico.
Ejemplo real

Un job de CI que aplica cambios de red se cancela a mitad de camino y deja bloqueado el backend S3. El siguiente pipeline falla con un error de bloqueo. Después de confirmar en el sistema de CI que ningún job sigue ejecutándose, una ingeniera ejecuta terraform force-unlock con el ID de bloqueo del error y luego vuelve a ejecutar el pipeline.

Consejo para el examen: El bloqueo es automático en los backends que lo admiten. force-unlock necesita el ID de bloqueo y es un último recurso; -lock-timeout espera un bloqueo en lugar de fallar de inmediato.

Comprueba lo que sabes

¿Qué argumento requiere terraform force-unlock?

El ID del bloqueo que se va a eliminar, que se muestra en el mensaje de error de bloqueo.

Tu pipeline a veces falla porque otro job tiene el bloqueo brevemente. ¿Qué indicador ayuda?

-lock-timeout, por ejemplo -lock-timeout=5m, para que Terraform reintente en lugar de fallar de inmediato.

¿Necesitas habilitar manualmente el bloqueo en un backend que lo admite?

No. Terraform adquiere y libera los bloqueos automáticamente para las operaciones que podrían escribir el estado.
