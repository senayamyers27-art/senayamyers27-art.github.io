Variables de entrada: `type`, `default`, `description`, `sensitive`, `nullable` y precedencia de valores (TF_VAR_, tfvars, auto.tfvars, -var)

Las variables de entrada son los parámetros de un módulo. Permiten que el mismo código sirva a distintos entornos, regiones o equipos sin editarlo. Declaras cada una con un bloque variable y te refieres a ella como var.NAME.

variable "instance_count" {
  type        = number
  default     = 2
  description = "Number of web servers to run."
  nullable    = false

  validation {
    condition     = var.instance_count > 0
    error_message = "instance_count must be at least 1."
  }
}

variable "db_password" {
  type      = string
  sensitive = true
}

Los argumentos: type restringe qué valores se aceptan, como string, number, bool o tipos complejos como list(string); Terraform convierte los valores compatibles y rechaza los demás. default proporciona un valor cuando no se da ninguno, lo que hace que la variable sea opcional; una variable sin default es obligatoria. description documenta el propósito para los usuarios y para la documentación del módulo. sensitive = true oculta el valor en la salida de plan y apply, y todo lo que se derive de él también se trata como sensible, pero igual se guarda en el estado. nullable controla si se permite null; su valor predeterminado es true, y con nullable = false quien pase null obtiene el default en su lugar. Un bloque validation agrega reglas personalizadas con un mensaje de error útil. Las versiones más recientes también admiten ephemeral = true para valores que nunca deben persistirse.

Los valores pueden proporcionarse de varias formas, y cuando la misma variable se establece en más de un lugar, Terraform usa esta precedencia, de menor a mayor, en la que las fuentes posteriores anulan a las anteriores:

1. Variables de entorno llamadas TF_VAR_<name>, p. ej. TF_VAR_region=us-east-1
2. terraform.tfvars, si existe
3. terraform.tfvars.json, si existe
4. Archivos *.auto.tfvars y *.auto.tfvars.json, en orden léxico del nombre de archivo
5. Opciones -var y -var-file en la línea de comandos, en el orden dado

Solo terraform.tfvars, terraform.tfvars.json y los archivos que terminan en .auto.tfvars o .auto.tfvars.json se cargan automáticamente. Cualquier otro archivo, como prod.tfvars, debe pasarse con -var-file. Si una variable obligatoria no tiene valor en ninguna fuente, Terraform lo pide de forma interactiva, o falla si se ejecuta con -input=false. Los defaults se usan solo cuando ninguna fuente proporciona un valor.

En HCP Terraform, las variables del workspace también pueden proporcionar valores; se envían como variables de Terraform o de entorno en cada ejecución. Para los secretos, prefiere variables de entorno o un gestor de secretos en lugar de hacer commit de archivos .tfvars que contengan contraseñas, y marca esas variables como sensibles para que no aparezcan en los logs.

Para los módulos hijos, las variables se establecen como argumentos en el bloque module, y ninguna de las fuentes de precedencia anteriores se les aplica directamente; solo el módulo raíz lee los archivos tfvars y las variables TF_VAR_.

Términos clave

Input variable (variable de entrada)
Un parámetro de un módulo declarado con un bloque variable y referenciado como var.NAME.
TF_VAR_ environment variable (variable de entorno TF_VAR_)
Una variable de entorno llamada TF_VAR_<name> que establece una variable del módulo raíz; tiene la precedencia más baja.
terraform.tfvars
Archivo de definiciones de variables que Terraform carga automáticamente desde el directorio del módulo raíz.
nullable
Ajuste de variable (true de forma predeterminada) que controla si se acepta null; cuando es false, null se reemplaza por el default.
sensitive (sensible)
Ajuste de variable que oculta el valor en la salida de la CLI, pero no lo mantiene fuera del estado.
Ejemplo real

Un pipeline establece TF_VAR_region=us-east-1 en su entorno, el repositorio tiene terraform.tfvars con region = "eu-west-1", y el ingeniero ejecuta terraform plan -var region=ap-south-1. Terraform usa ap-south-1, porque los valores de la línea de comandos tienen la precedencia más alta.

Consejo para el examen: Precedencia de menor a mayor: variables de entorno TF_VAR_, terraform.tfvars, terraform.tfvars.json, *.auto.tfvars en orden léxico, y luego -var y -var-file. Los archivos que no siguen esos patrones de nombre solo se cargan mediante -var-file.

Comprueba lo que sabes

Si region se establece tanto en terraform.tfvars como en override.auto.tfvars, ¿cuál gana?

override.auto.tfvars, porque los archivos *.auto.tfvars se cargan después de terraform.tfvars y tienen precedencia.

¿Qué pasa cuando una variable no tiene default y no se proporciona ningún valor?

Terraform lo pide de forma interactiva, o da error si la entrada está deshabilitada con -input=false.

¿sensitive = true mantiene el valor de una variable fuera del archivo de estado?

No. Solo lo oculta en la salida de la CLI; el valor igual puede guardarse en el estado.
