Paralelismo y el grafo de dependencias durante el apply

Terraform no procesa los recursos uno por uno en el orden de los archivos. Construye un grafo de dependencias: un grafo acíclico dirigido (un grafo con direcciones y sin ciclos) en el que cada nodo es un recurso, data source, provider, variable, output u objeto similar, y cada arista significa que un nodo debe procesarse antes que otro. Las aristas provienen de las referencias entre bloques, como una subred que usa aws_vpc.main.id, y de los argumentos explícitos depends_on.

Cuando planificas o aplicas, Terraform recorre este grafo. Cualquier nodo cuyas dependencias estén completas puede empezar. Los recursos que no dependen entre sí, como diez buckets de almacenamiento no relacionados, pueden crearse al mismo tiempo. Los recursos en una cadena, como red, luego subred y luego instancia, se procesan en secuencia. Durante destroy el grafo se recorre en sentido inverso, así que los dependientes se eliminan antes que aquello de lo que dependen.

Terraform limita cuántas operaciones se ejecutan a la vez. De forma predeterminada realiza hasta 10 operaciones concurrentes. Puedes cambiarlo con -parallelism=n en plan, apply y destroy. Aumentarlo puede acelerar configuraciones grandes con muchos recursos independientes. Reducirlo, incluso a -parallelism=1, puede ayudar cuando la API de un provider impone límites de tasa (rate limits), al depurar para ver las operaciones una por una, o cuando la máquina que ejecuta Terraform tiene pocos recursos. El ajuste controla solo la concurrencia; nunca cambia el orden que requieren las dependencias.

terraform apply -parallelism=4
terraform graph | dot -Tsvg > graph.svg

terraform graph muestra el grafo de dependencias en el lenguaje DOT, que herramientas como Graphviz pueden convertir en una imagen. Es una forma práctica de entender por qué Terraform ordena las cosas como lo hace o de detectar una dependencia inesperada.

Si una operación falla durante el apply, Terraform deja de iniciar nuevas operaciones que dependan de ella, deja terminar las operaciones que ya están en curso y registra en el estado todo lo que tuvo éxito. El error se informa al final. Por eso un apply puede dejar algunos recursos creados y otros no, y por eso el siguiente apply simplemente continúa desde el estado registrado.

Los ciclos no están permitidos. Si el recurso A referencia a B y B referencia a A, directamente o a través de una cadena, Terraform informa un error de ciclo durante el plan. La solución es reestructurar: a menudo moviendo un atributo a un recurso separado, como una regla de security group separada en lugar de una regla en línea, para que la dependencia vaya en un solo sentido.

Términos clave

Dependency graph (grafo de dependencias)
Grafo acíclico dirigido de los objetos de la configuración que Terraform usa para ordenar las operaciones.
-parallelism
Opción que establece el número máximo de operaciones concurrentes durante plan, apply o destroy; el valor predeterminado es 10.
terraform graph
Comando que genera el grafo de dependencias en formato DOT para visualizarlo.
Cycle (ciclo)
Una dependencia circular entre objetos que hace imposible ordenar el grafo; Terraform la informa como error.
Ejemplo real

Un apply que crea 200 registros DNS falla una y otra vez con errores de limitación (throttling) de la API del provider de DNS. Ejecutar terraform apply -parallelism=2 distribuye las solicitudes para que el provider ya no las limite, a costa de una ejecución más lenta.

Consejo para el examen: El paralelismo tiene un valor predeterminado de 10 y cambia cuántas operaciones se ejecutan a la vez, nunca el orden. El orden viene del grafo: referencias implícitas más depends_on, invertido para destroy.

Comprueba lo que sabes

¿Qué decide el orden en que Terraform crea los recursos?

El grafo de dependencias construido a partir de las referencias y depends_on; los recursos independientes pueden crearse de forma concurrente.

¿Por qué podrías reducir -parallelism?

Para evitar límites de tasa o throttling de la API, para simplificar la depuración o para reducir la carga en la máquina que ejecuta Terraform.
