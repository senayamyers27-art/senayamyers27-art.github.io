Variables y variable sets; variables de Terraform frente a variables de entorno; variables sensibles

Las ejecuciones de HCP Terraform ocurren en workers remotos, así que los valores que necesita tu configuración (variables de entrada y credenciales) deben guardarse en HCP Terraform y no en tu laptop. Los defines en cada workspace, o los compartes entre workspaces con variable sets.

Cada variable tiene una categoría. Una variable de Terraform establece una variable de entrada declarada en tu configuración, exactamente como un valor en un archivo .tfvars; su clave debe coincidir con el nombre del bloque variable. Puedes marcarla como HCL para que el valor se interprete como una lista, un mapa u otro tipo complejo en lugar de una cadena simple. Una variable de entorno se exporta a la shell de la ejecución, que es la forma de pasar credenciales de providers como las claves de acceso a la nube, ajustes de Terraform como TF_LOG o valores TF_VAR_name. Elegir la categoría equivocada es un error común: una credencial de provider establecida como variable de Terraform no la verá el provider.

Cualquier variable puede marcarse como sensible. Las variables sensibles son de solo escritura en HCP Terraform: después de guardarlas, nadie puede volver a leer su valor mediante la interfaz o la API, ni siquiera los administradores; solo puedes reemplazarlas. Igual se usan durante las ejecuciones y se ocultan en los logs donde Terraform sabe que son sensibles. Este es el lugar correcto para secretos como los tokens, pero recuerda que si tu configuración escribe el valor en un atributo de un recurso, aun así puede terminar en el estado.

Los variable sets son grupos reutilizables de variables. Creas un set una vez, por ejemplo las credenciales de la nube para una cuenta sandbox, y lo aplicas a workspaces específicos, a proyectos completos o globalmente a todos los workspaces de la organización. Actualizar el set actualiza todos los workspaces que lo usan, lo que facilita mucho la rotación de credenciales.

Cuando la misma variable se define en más de un lugar, se aplican reglas de precedencia. En general, un variable set aplicado directamente a un workspace o a su proyecto pierde frente a una variable definida en el propio workspace; los sets limitados a un proyecto ganan a los sets globales; y un variable set marcado como prioritario anula las variables del workspace e incluso los valores de la propia ejecución, lo que permite a los administradores imponer ciertos valores. Los valores de los archivos *.auto.tfvars de la configuración también participan, y las variables del workspace tienen precedencia sobre ellos. Si una pregunta te pide qué valor gana, busca primero los sets prioritarios, luego los valores específicos del workspace y después los sets más amplios.

Las variables de entorno en HCP Terraform también son la forma de configurar cosas como las credenciales dinámicas de providers (por ejemplo, variables que empiezan por TFC_ y que habilitan la función) y la forma de proporcionar TF_CLI_ARGS para agregar indicadores a los comandos en las ejecuciones remotas.

Términos clave

Terraform variable (category) (variable de Terraform, categoría)
Una variable del workspace que establece una variable de entrada de Terraform declarada en la configuración.
Environment variable (category) (variable de entorno, categoría)
Una variable del workspace exportada a la shell de la ejecución, usada para credenciales de providers y ajustes de Terraform.
Sensitive variable (variable sensible)
Una variable de solo escritura cuyo valor no puede verse después de guardarse, pero está disponible para las ejecuciones.
Variable set
Un grupo reutilizable de variables que se aplica a workspaces seleccionados, a proyectos o a toda la organización.
Ejemplo real

Un equipo guarda el ID de la clave de acceso y el secreto de su proveedor de nube como variables de entorno sensibles en un variable set limitado a su proyecto. Cuando se rotan las claves, una sola edición actualiza todos los workspaces del proyecto, y nadie puede volver a leer el secreto anterior ni el nuevo desde la interfaz.

Consejo para el examen: Las credenciales de los providers van en variables de entorno, no en variables de Terraform. Las variables sensibles son de solo escritura; los variable sets prioritarios anulan los valores del workspace.

Comprueba lo que sabes

¿Qué categoría de variable debe contener las credenciales del proveedor de nube?

Variable de entorno, porque los providers leen las credenciales del entorno de la ejecución.

¿Puede un propietario de la organización leer el valor de una variable sensible después de guardarla?

No. Las variables sensibles son de solo escritura; pueden reemplazarse, pero no verse.

¿Qué te permite hacer un variable set?

Definir variables una vez y aplicarlas a muchos workspaces, a proyectos completos o a toda la organización.
