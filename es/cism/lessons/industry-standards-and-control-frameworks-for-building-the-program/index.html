ISACA Certified Information Security Manager (CISM) 2026 exam content outline

Normas de la industria y marcos de control para construir el programa

Un marco de control es un catálogo estructurado de controles, organizado por temas, que una organización puede usar para elegir y adaptar controles. Usar uno evita reinventar controles, da un lenguaje común con auditores y socios y facilita demostrar a los reguladores que el programa es razonable. CISM espera que conozcas las opciones principales y cómo usarlas, no que memorices números de controles.

ISO/IEC 27002 ofrece controles agrupados en los temas organizacional, de personas, físico y tecnológico, con guía para cada uno. Apoya a ISO/IEC 27001, cuyo Anexo A lista los mismos controles; las organizaciones eligen cuáles aplican y registran la elección en una declaración de aplicabilidad. NIST SP 800-53 es un catálogo grande y detallado muy usado por las agencias federales de EE. UU. y sus proveedores, con líneas base para sistemas de impacto bajo, moderado y alto. Los CIS Critical Security Controls son una lista más corta y priorizada de salvaguardas técnicas agrupadas en grupos de implementación según el tamaño y la madurez de la organización.

Las normas sectoriales y temáticas se suman a estas. PCI DSS aplica a los datos de tarjetas de pago; el NIST Privacy Framework y las leyes de privacidad dan forma a los controles de privacidad; los marcos específicos de nube, como la Cloud Controls Matrix de la Cloud Security Alliance, mapean las responsabilidades en la nube. Muchas organizaciones deben cumplir varios a la vez.

La práctica clave es la adaptación. La evaluación de riesgos determina qué controles se necesitan y qué tan fuertes deben ser. Un marco es un menú, no la obligación de implementar cada elemento. Los controles que no aplican se excluyen con una razón documentada; se agregan controles adicionales donde los riesgos de la organización lo exigen.

El mapeo de controles vincula un control interno con los requisitos de varios marcos, por ejemplo un solo proceso de revisión de accesos que cumple ISO/IEC 27001, SOC 2 y la regla de un regulador. Este enfoque de 'probar una vez, cumplir muchas' reduce el esfuerzo duplicado. Recuerda que ningún marco garantiza la seguridad y adoptarlo nunca transfiere la responsabilidad; da estructura a un programa basado en riesgos.

Términos clave

Marco de control
Un catálogo estructurado de controles que las organizaciones eligen y adaptan a sus riesgos.
Adaptación (tailoring)
Ajustar los controles de un marco a los riesgos específicos de una organización, excluyendo o agregando controles con razones documentadas.
Mapeo de controles
Vincular controles internos con requisitos de varios marcos para que un control cumpla varias obligaciones.
CIS Critical Security Controls
Un conjunto priorizado de salvaguardas técnicas agrupadas en grupos de implementación.
Ejemplo real

Una startup fintech debe cumplir PCI DSS, aprobar auditorías SOC 2 y responder cuestionarios de clientes basados en ISO/IEC 27001. El gerente de seguridad construye un único conjunto de controles internos, mapea cada control a los tres marcos y programa las pruebas para que cada control se pruebe una sola vez y la evidencia se reutilice en todas las auditorías.

Consejo para el examen: Los marcos se eligen y adaptan con base en la evaluación de riesgos; nunca la reemplazan y nunca garantizan que no ocurran filtraciones.

Comprueba lo que sabes

¿Por qué adoptar un marco de control reconocido?

Para usar un conjunto estructurado y probado de controles y un lenguaje común, adaptado a los riesgos de la organización.

¿Para qué sirve el mapeo de controles?

Para mostrar que un control interno cumple requisitos de varios marcos, lo que reduce el esfuerzo duplicado.
