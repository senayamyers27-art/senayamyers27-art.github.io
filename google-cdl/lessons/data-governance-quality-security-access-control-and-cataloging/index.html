Data governance: quality, security, access control and cataloging

▶ Watch the overview video

Last reviewed September 25, 2026

Data governance is the set of policies, roles and tools that make sure data is accurate, secure, discoverable and used appropriately. Without it, organizations collect more data but trust it less: nobody knows which table is correct, sensitive data leaks to the wrong people, and regulators ask questions nobody can answer. Good governance is what makes data safe and useful at the same time.

Governance has several parts. Data quality means data is accurate, complete, consistent and up to date; poor quality leads to wrong decisions and poor ML models. Ownership and stewardship mean each data set has someone accountable for it. Security and privacy mean sensitive data such as personal or financial information is protected and handled according to law and policy. Lifecycle management decides how long data is kept and when it is deleted. Lineage records where data came from and how it was transformed, which helps with trust and audits.

Access control is central. In Google Cloud, IAM decides who can view or change data at the project, dataset, table or bucket level, and BigQuery adds column-level and row-level security so, for example, only HR can see salary columns. Following least privilege limits damage from mistakes or compromised accounts. Sensitive Data Protection can discover and classify sensitive data such as credit card numbers and can mask or de-identify it.

Cataloging makes data discoverable. A data catalog records what data exists, where it lives, what it means, who owns it and how sensitive it is, so analysts can find trusted data instead of creating copies. In Google Cloud, Dataplex provides data cataloging, quality checks, lineage and governance across data lakes and warehouses.

Governance should enable, not only restrict. The goal is that the right people can quickly find and use trustworthy data, while sensitive data stays protected.

Key terms

Data governance
Policies, roles and tools that keep data accurate, secure, discoverable and properly used.
Data lineage
A record of where data came from and how it was transformed.
Data catalog
An inventory of data assets with descriptions, owners and classifications so people can find them.
Column-level security
Restricting access to specific columns, such as sensitive fields, in a table.
Real-world example

A healthcare provider catalogs all its datasets in Dataplex, tags patient identifiers as sensitive, restricts those columns in BigQuery to a small clinical group, and runs automatic quality checks. Analysts can now find approved datasets in minutes instead of asking around.

Exam tip: Questions about finding trusted data, knowing who owns it, tracking where it came from and limiting who sees sensitive fields are all about data governance.

Check yourself

Name four parts of data governance.

Any four of: data quality, ownership, security and privacy, access control, lifecycle and retention, lineage, cataloging.

How can BigQuery let most analysts query a table but hide one sensitive column?

Use column-level security (policy tags) so only authorized users can read that column.
