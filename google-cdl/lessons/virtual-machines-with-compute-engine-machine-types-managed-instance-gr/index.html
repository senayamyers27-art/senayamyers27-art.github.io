Virtual machines with Compute Engine: machine types, managed instance groups and autoscaling

▶ Watch the overview video

Last reviewed September 25, 2026

Compute Engine is Google Cloud's infrastructure as a service (IaaS) offering for virtual machines (VMs). A VM behaves like a physical server: you choose an operating system image (Linux or Windows), a machine type and disks, and you have full control over the software installed. Compute Engine is the usual landing place for lift-and-shift migrations and for workloads that need a specific OS, kernel settings or licensed software.

Machine types define how much virtual CPU (vCPU) and memory a VM has. Google Cloud organizes them into families: general-purpose for most workloads, compute-optimized for CPU-heavy work, memory-optimized for large in-memory databases, and accelerator-optimized with GPUs for ML and graphics. If no predefined type fits, custom machine types let you choose the exact number of vCPUs and amount of memory, which avoids paying for resources you do not need. You can attach persistent disks, which keep data independently of the VM, in several performance levels.

A single VM is a single point of failure and cannot grow to meet demand. Managed instance groups (MIGs) solve this. You define an instance template, which describes the VM configuration, and the MIG creates and manages a group of identical VMs from it. MIGs provide autoscaling, adding VMs when load rises (for example on CPU utilization or requests per second) and removing them when load falls. They provide autohealing, recreating VMs that fail a health check. They support rolling updates to deploy a new template gradually. A regional MIG spreads VMs across zones for higher availability.

MIGs are usually placed behind a Cloud Load Balancing load balancer, which spreads traffic across healthy VMs, and can be global so users reach the nearest region.

Compute Engine charges per second of use for most VMs, and offers ways to lower cost, such as sustained use discounts, committed use discounts and Spot VMs, covered in the operations section. The free tier includes a small e2-micro VM in some US regions, which is enough for a first lab.

Key terms

Compute Engine
Google Cloud's IaaS service for running virtual machines.
Machine type
The vCPU and memory configuration of a VM, predefined or custom.
Managed instance group (MIG)
A group of identical VMs created from a template with autoscaling, autohealing and rolling updates.
Instance template
A reusable definition of a VM's configuration used to create VMs in a MIG.
Real-world example

A ticketing site runs its web servers in a regional managed instance group behind a global load balancer. During a sale, autoscaling grows the group from 4 to 40 VMs across three zones, and when one VM crashes, autohealing replaces it without anyone being paged.

Exam tip: Automatic scaling and replacement of failed VMs points to a managed instance group. Full control of the OS points to Compute Engine rather than serverless options.

Check yourself

What does autohealing do in a managed instance group?

It recreates VMs that fail their health check, so the group returns to a healthy state automatically.

When would you use a custom machine type?

When no predefined type matches the vCPU and memory a workload needs, to avoid paying for unused resources.
