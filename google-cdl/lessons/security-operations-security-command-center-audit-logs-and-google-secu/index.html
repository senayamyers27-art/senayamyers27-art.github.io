Security operations: Security Command Center, audit logs and Google Security Operations

▶ Watch the overview video

Last reviewed September 25, 2026

Security operations (SecOps) is the continuous work of detecting, investigating and responding to threats. Preventive controls are never perfect, so organizations need visibility into what is happening and the ability to react quickly. Google Cloud provides tools at several levels.

Security Command Center is Google Cloud's built-in security and risk management platform. It gives a central view across an organization's projects of assets, misconfigurations (such as public buckets or open firewall ports), vulnerabilities (such as outdated software on VMs or web app flaws), and active threats (such as a VM mining cryptocurrency or unusual IAM grants). It prioritizes findings and recommends fixes, and it can check the environment against compliance benchmarks. Higher tiers add more detection capabilities.

Cloud Audit Logs record who did what, where and when in Google Cloud. Admin Activity audit logs record configuration changes, such as creating a VM or changing IAM policies; they are always on and cannot be disabled. Data Access audit logs record reads and writes of user data and are mostly off by default because of their volume; you enable them where needed. System Event logs record Google-initiated changes, and Policy Denied logs record access refused by security policies. Logs are viewed in Cloud Logging's Logs Explorer and can be exported to BigQuery or other tools for long-term analysis. Audit logs answer questions like 'who deleted this instance?' and support investigations and compliance.

Google Security Operations (formerly Chronicle) is a cloud-native security operations platform that combines SIEM (security information and event management) and SOAR (security orchestration, automation and response). It ingests large volumes of security telemetry from cloud, on-premises and other sources, enriches it with Google threat intelligence, including from Mandiant, detects threats, and automates response workflows.

Other services help too, such as Sensitive Data Protection to discover sensitive information and Web Security Scanner for app vulnerabilities. Mandiant provides incident response and threat intelligence expertise.

Key terms

Security Command Center
Google Cloud's central platform for security posture, vulnerabilities, misconfigurations and threat detection.
Cloud Audit Logs
Logs recording administrative actions and data access in Google Cloud.
SIEM
Security information and event management: collecting and analyzing security logs to detect threats.
SOAR
Security orchestration, automation and response: automating investigation and response steps.
Real-world example

Security Command Center flags that a new Cloud Storage bucket is publicly readable and that a VM shows signs of cryptomining. The security team checks the Admin Activity audit logs to see which account created the bucket and made it public, removes public access and isolates the VM.

Exam tip: Posture and threats across Google Cloud projects: Security Command Center. Who did what and when: Cloud Audit Logs (Admin Activity is always on). Enterprise-wide SIEM and SOAR: Google Security Operations.

Which audit logs are always on and cannot be disabled?

Admin Activity audit logs.

What does Security Command Center provide?

A central view of assets, misconfigurations, vulnerabilities and threats across an organization, with prioritized findings and recommendations.
