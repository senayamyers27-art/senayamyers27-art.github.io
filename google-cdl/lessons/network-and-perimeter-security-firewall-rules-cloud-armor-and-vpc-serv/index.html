Network and perimeter security: firewall rules, Cloud Armor and VPC Service Controls

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Even in a zero trust world, network controls remain an important layer of defense in depth. Google Cloud provides several, each protecting against different threats.

A Virtual Private Cloud (VPC) is a customer's private network in Google Cloud, spanning regions, in which resources such as VMs get internal IP addresses. VPC firewall rules and firewall policies allow or deny traffic to and from resources based on addresses, ports, protocols, network tags or service accounts. Good practice is to deny by default and allow only what is needed, for example allowing HTTPS from the internet only to the load balancer and SSH only from Identity-Aware Proxy rather than from anywhere. Firewall policies can also be applied centrally at the organization or folder level. Cloud NGFW adds more advanced inspection features.

Cloud Armor protects internet-facing applications and websites that sit behind Google Cloud's external load balancers. It provides protection against distributed denial-of-service (DDoS) attacks, using the scale of Google's edge network to absorb large volumes of traffic, and it acts as a web application firewall (WAF) with preconfigured rules for common attacks such as SQL injection and cross-site scripting. Rules can also block or allow traffic by IP address or geographic region and limit request rates. Because it works at the edge, attacks are stopped before they reach the application.

VPC Service Controls addresses a different risk: data exfiltration from Google Cloud managed services such as Cloud Storage and BigQuery. It lets you draw a service perimeter around projects and services. Requests to access data from outside the perimeter, or to copy data to resources outside it, are blocked even if the caller has valid IAM credentials. This helps contain the damage from stolen credentials or malicious insiders.

Private connectivity options such as Private Google Access and Private Service Connect let workloads reach Google services without using public IP addresses, and Cloud VPN and Cloud Interconnect provide secure connections to on-premises networks.

Key terms

VPC firewall rules
Rules that allow or deny network traffic to and from resources in a VPC network.
Cloud Armor
Google Cloud's DDoS protection and web application firewall for applications behind external load balancers.
Web application firewall (WAF)
A filter that blocks common web attacks such as SQL injection and cross-site scripting.
VPC Service Controls
Service perimeters around Google Cloud services that reduce the risk of data exfiltration.
Real-world example

An online store puts its site behind a global load balancer with Cloud Armor, which absorbs a large DDoS attack and blocks SQL injection attempts. Its customer data in BigQuery sits inside a VPC Service Controls perimeter, so a stolen analyst credential cannot be used to copy tables to an outside project.

Exam tip: DDoS and web attacks against a public site: Cloud Armor. Data being copied out of managed services even with valid credentials: VPC Service Controls. Allowing or denying traffic to VMs by port and address: firewall rules.

Check yourself

Which service protects a public web app from SQL injection and DDoS at Google's edge?

Cloud Armor.

What does VPC Service Controls protect against that IAM alone does not?

Data exfiltration by someone with valid credentials, by blocking access and copying across the service perimeter.
