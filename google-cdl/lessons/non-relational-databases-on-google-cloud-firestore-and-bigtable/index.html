Non-relational databases on Google Cloud: Firestore and Bigtable

▶ Watch the overview video

Last reviewed September 25, 2026

Non-relational, or NoSQL, databases store data in models other than related tables. They trade some relational features, such as complex joins, for flexibility or very large scale. Google Cloud's two main managed NoSQL services on the exam are Firestore and Bigtable, and they solve quite different problems.

Firestore is a serverless document database. Data is stored as documents, which are sets of fields similar to JSON, organized in collections. Documents in the same collection can have different fields, so the schema can evolve easily as an app changes. Firestore scales automatically with no servers to manage, and it has features built for web and mobile apps: real-time listeners that push changes to connected clients, offline support so an app keeps working without a connection and syncs later, and client libraries that work with Firebase. It is a good fit for user profiles, game state, chat, product catalogs and other app data.

Bigtable is a wide-column NoSQL database built for very large amounts of data with consistently low latency and very high read and write throughput. Data is stored in tables with rows identified by a single row key, and columns grouped into families; rows can have many columns and empty cells cost nothing. It is ideal for time-series data, IoT sensor readings, financial market data, ad-tech and personalization, and it is the kind of system that powers large Google services. It is compatible with the open source Apache HBase API.

The key to choosing is the workload. Firestore suits application data for web and mobile, where flexibility, real-time sync and zero administration matter and volumes are moderate to large. Bigtable suits huge analytical and operational data sets, often terabytes to petabytes, where throughput and latency at scale matter most and access is mainly by key.

Neither is a data warehouse. For SQL analytics across large data sets you still use BigQuery, which can also query data stored in Bigtable.

Key terms

NoSQL
Databases that use models other than relational tables, such as documents, key-value or wide columns.
Firestore
A serverless NoSQL document database with real-time updates and offline support for apps.
Bigtable
A wide-column NoSQL database for very large, low-latency, high-throughput workloads.
Row key
The single identifier used to store and retrieve rows in Bigtable, which determines how data is organized.
Real-world example

A fitness company stores each user's profile and workout plans in Firestore so the mobile app updates instantly across the user's phone and watch. Heart-rate readings from millions of wearables, arriving every second, go into Bigtable keyed by device and timestamp.

Exam tip: Mobile or web app, real-time sync, offline: Firestore. Massive time-series or IoT data with high throughput and low latency: Bigtable. Neither is the answer for SQL analytics, which is BigQuery.

Check yourself

Which service suits billions of sensor readings per day with low-latency reads by device?

Bigtable.

Name two Firestore features aimed at mobile apps.

Real-time listeners that push updates to clients, and offline support with later sync.
