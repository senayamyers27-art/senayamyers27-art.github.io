Zero trust and defense in depth

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Traditional security used a castle-and-moat model: a strong perimeter firewall protected the corporate network, and anything inside was trusted. That model fits poorly today. People work from home and on the move, applications run in the cloud and are reached over the internet, and an attacker who gets inside the perimeter, for example through a phished laptop, can move around freely.

Zero trust is a security model that removes implicit trust based on network location. Its motto is 'never trust, always verify'. Every request to access an application or data is authenticated and authorized based on who the user is, the security state of their device and the context of the request, such as location and time, regardless of whether it comes from the office network or a coffee shop. Access is granted with least privilege, for the specific resource, and is continuously evaluated.

Google adopted this approach internally after a sophisticated attack in 2009, and called its implementation BeyondCorp. Google employees access internal applications without a traditional VPN; access decisions depend on user identity and device state. Google Cloud offers these ideas to customers, for example through Identity-Aware Proxy, which checks identity and context before allowing access to applications and VMs, and through Chrome Enterprise Premium (previously BeyondCorp Enterprise).

Defense in depth is a complementary principle: use multiple layers of independent security controls so that if one fails, others still protect the asset. Layers in Google Cloud might include strong identity and two-step verification, IAM with least privilege, organization policies, network firewalls and Cloud Armor, encryption at rest and in transit, VPC Service Controls, logging and threat detection, and backups. An attacker who steals a password still faces 2SV; one who bypasses a firewall still lacks permissions; one who reaches the data still finds it encrypted and their actions logged.

Together, zero trust and defense in depth replace the idea of one strong wall with continuous verification and layered protection.

Key terms

Zero trust
A model that grants no implicit trust based on network location and verifies every request.
BeyondCorp
Google's implementation of zero trust, allowing access based on user and device rather than network.
Defense in depth
Layering multiple independent security controls so one failure does not expose the system.
Identity-Aware Proxy (IAP)
A Google Cloud service that checks identity and context before granting access to applications and VMs.
Real-world example

A consulting firm stops requiring a VPN for its internal apps. Each request passes through Identity-Aware Proxy, which checks the employee's identity, 2SV and whether the laptop is company-managed and up to date. A contractor's personal device is refused even with a valid password.

Exam tip: Zero trust: verify every request by identity and context, not network location. Defense in depth: several layers of controls. If a question describes 'trusting everything inside the network', it describes the old perimeter model.

Check yourself

What is the main idea of zero trust?

No implicit trust from network location; every access request is verified using identity, device and context, with least privilege.

Why is defense in depth valuable?

If one control fails or is bypassed, other independent layers still protect the data or system.
