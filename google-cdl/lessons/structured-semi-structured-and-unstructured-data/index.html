Structured, semi-structured and unstructured data

▶ Watch the overview video

Last reviewed September 25, 2026

Data comes in different shapes, and the shape decides where it is best stored and how it is analyzed. The exam expects you to recognize the three main types and match them to Google Cloud services.

Structured data fits a fixed schema of rows and columns, where every record has the same fields with defined types. Customer tables, orders, bank transactions and inventory records are structured. It is easy to query with SQL and is typically stored in relational databases such as Cloud SQL, AlloyDB or Spanner, or in a data warehouse such as BigQuery for analysis.

Semi-structured data has some organization, such as tags or keys, but not a rigid schema. Different records can have different fields, and fields can be nested. JSON documents, XML, application logs and many event messages are semi-structured. Document databases such as Firestore store it naturally, and BigQuery can store and query nested and repeated fields and JSON as well.

Unstructured data has no predefined model: images, video, audio, emails, PDFs, scanned documents and free text. It makes up most of the data organizations create. It is usually stored as objects in Cloud Storage. To analyze it you often need AI: the Vision API can label images or read text in them, Speech-to-Text can transcribe calls, and the Natural Language API can find sentiment or entities in text. Once processed, the results become structured data you can query.

The line between the types is not always sharp, and one project often uses all three. A customer support system might hold structured ticket records, semi-structured JSON event logs and unstructured call recordings. Choosing the right storage for each type, and connecting them for analysis, is a core part of data transformation on Google Cloud.

Key terms

Structured data
Data organized in a fixed schema of rows and columns, easily queried with SQL.
Semi-structured data
Data with tags or keys but a flexible schema, such as JSON or XML.
Unstructured data
Data with no predefined model, such as images, video, audio and free text.
Schema
The definition of the fields, types and relationships in a data set.
Real-world example

An insurer stores policy records in Cloud SQL (structured), mobile app events as JSON in BigQuery (semi-structured) and photos of car damage in Cloud Storage (unstructured). It runs the photos through an image model and saves the results as structured fields for claims analysis.

Exam tip: Images, video, audio and documents are unstructured and usually go in Cloud Storage. JSON and logs are semi-structured. Tables with fixed columns are structured.

Check yourself

Is a JSON order record with optional fields structured, semi-structured or unstructured?

Semi-structured: it has keys but not a rigid schema.

Where is unstructured data such as video usually stored in Google Cloud?

In Cloud Storage, as objects in a bucket.
