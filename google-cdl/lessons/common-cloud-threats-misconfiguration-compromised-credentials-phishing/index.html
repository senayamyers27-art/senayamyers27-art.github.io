Common cloud threats: misconfiguration, compromised credentials, phishing, malware and ransomware

▶ Watch the overview video

Last reviewed September 25, 2026

Knowing the common threats helps leaders invest in the right controls. Many cloud incidents are not caused by sophisticated attacks on the provider but by weaknesses on the customer's side.

Misconfiguration is one of the leading causes of cloud data exposure. Examples include storage buckets made publicly readable by mistake, databases reachable from the internet, firewall rules open to all addresses, logging turned off, and users with far more permissions than they need. Because cloud resources are easy to create, mistakes can spread quickly. Defenses include secure defaults, organization policies that block risky settings, infrastructure as code with review, and tools such as Security Command Center that detect misconfigurations.

Compromised credentials occur when attackers obtain passwords, API keys or service account keys, for example through reuse of passwords leaked elsewhere or keys accidentally published in code repositories. With valid credentials, attackers look like legitimate users. Defenses include strong multi-factor authentication, avoiding long-lived keys, least privilege and monitoring for unusual activity.

Phishing tricks people into revealing credentials or running malicious software, usually through emails or messages that impersonate a trusted person or service. Phishing-resistant two-step verification, such as security keys, is one of the most effective defenses, together with awareness training.

Malware is malicious software, such as viruses, trojans and spyware. Ransomware is malware that encrypts an organization's data and demands payment to restore it, often also threatening to publish stolen data. Defenses include patching, limiting privileges, protecting endpoints, email filtering and, crucially, backups that attackers cannot alter or delete, so data can be restored without paying.

Other threats include denial-of-service attacks that overwhelm services, insider threats from employees misusing access, and attacks on software supply chains. Defense in depth, discussed in the next lesson, means no single control has to stop everything.

Key terms

Misconfiguration
An insecure setting, such as public access or overly broad permissions, often made by mistake.
Phishing
Deceptive messages designed to trick people into revealing credentials or running malware.
Ransomware
Malware that encrypts data and demands payment to restore access.
Compromised credentials
Passwords, keys or tokens obtained by an attacker and used to impersonate a legitimate user.
Real-world example

A developer accidentally commits a service account key to a public code repository. Within hours, attackers use it to create VMs for cryptocurrency mining. The company revokes the key, switches to keyless authentication for its pipeline, and enables alerts on unusual resource creation.

Exam tip: Most cloud breaches trace back to customer-side issues: misconfiguration and stolen credentials. The strongest defenses are secure configuration, least privilege and phishing-resistant multi-factor authentication.

Check yourself

What is the most effective defense against losing data to ransomware?

Protected backups that attackers cannot change or delete, allowing restore without paying, along with patching and least privilege.

Give two examples of cloud misconfiguration.

A publicly readable storage bucket, a database open to the internet, firewall rules allowing all addresses, or excessive permissions (any two).
