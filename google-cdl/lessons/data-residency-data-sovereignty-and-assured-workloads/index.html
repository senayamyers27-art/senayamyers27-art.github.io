Data residency, data sovereignty and Assured Workloads

▶ Watch the overview video

Last reviewed September 25, 2026

Many organizations, especially in the public sector, healthcare and finance, must meet rules about where data is stored and who can access it. These rules come from national laws, industry regulations and customer contracts, and they are a common concern when moving to the cloud.

Data residency is the physical or geographic location where data is stored and processed. In Google Cloud, you control residency mainly by choosing regions and multi-regions when you create resources, for example storing a bucket in europe-west3 (Frankfurt). To enforce it across an organization, administrators use the resource locations organization policy constraint, which stops anyone from creating resources outside allowed locations.

Data sovereignty is a broader, legal concept: data is subject to the laws of the country where it is located, and organizations and governments want assurance about which jurisdictions can compel access to it and who controls it. Sovereignty concerns include where data is stored, who holds the encryption keys, which personnel can access systems and from where, and whether operations could be affected by foreign laws. Google Cloud addresses these with data location controls, customer-managed and external encryption keys, access controls and transparency features, and, in some countries, sovereign cloud offerings delivered with local partners.

Assured Workloads is a Google Cloud service that helps customers run regulated workloads by applying a set of controls for a chosen compliance regime, such as specific government, healthcare or regional requirements. When you create an Assured Workloads folder, it enforces controls such as data location restrictions, restrictions on which products can be used, and limits on which Google personnel can provide support, for example only personnel in certain countries or with certain background checks. It monitors for violations of these controls.

Residency and sovereignty are part of the customer's compliance responsibility. Google provides the tools, but the customer must choose locations and configure controls correctly.

Key terms

Data residency
The geographic location where data is stored and processed.
Data sovereignty
The principle that data is subject to the laws of the country where it is located, including control over who can access it.
Assured Workloads
A Google Cloud service that applies controls, such as data location and personnel access, for regulated workloads.
Resource locations constraint
An organization policy that restricts the locations where resources can be created.
Real-world example

A German public agency must keep citizen data in the EU and limit support access to EU personnel. It creates an Assured Workloads folder for the relevant EU regime, which restricts resource locations to EU regions and applies personnel access controls, and it uses external keys it holds itself.

Exam tip: Residency is about where data sits, set by choosing regions and enforced with the resource locations policy. Sovereignty adds who controls and can access it under which laws. Regulated workloads with location and personnel controls point to Assured Workloads.

Check yourself

How can an organization prevent any project from creating resources outside the EU?

Set the resource locations organization policy constraint to EU locations at the organization node.

Name two controls Assured Workloads can enforce.

Data location restrictions, restrictions on available products, and limits on which Google personnel can access or support the workload (any two).
