Encryption at rest and in transit, and key management with Cloud KMS

▶ Watch the overview video

Last reviewed September 25, 2026 · Leer en español

Encryption transforms readable data into ciphertext that can only be read with the right key. It protects confidentiality even if storage media or network traffic are accessed by someone unauthorized. Google Cloud applies encryption by default in two states.

Encryption at rest protects stored data. All customer data stored in Google Cloud is encrypted at rest by default, with no action needed from the customer, using strong encryption (AES-256). Data is split into chunks, each encrypted with its own data encryption key, and those keys are themselves encrypted by key encryption keys managed in Google's key management systems. This layered approach is called envelope encryption.

Encryption in transit protects data moving across networks. Google encrypts and authenticates data in transit between its data centers and at various layers within them, and services use TLS for connections from users and applications. Customers should also use HTTPS for their own applications and encrypted connections such as Cloud VPN for traffic from on-premises.

Some organizations need more control over the keys, for regulation or internal policy. Google Cloud offers several options. Google-managed keys are the default: Google handles everything. Customer-managed encryption keys (CMEK) are keys the customer creates and manages in Cloud Key Management Service (Cloud KMS). The customer controls rotation schedules, permissions and can disable or destroy a key, which makes data protected by it unreadable. Keys can be protected in hardware security modules with Cloud HSM. With Cloud External Key Manager (EKM), keys are held in a key management system outside Google, so the customer can refuse access. Customer-supplied encryption keys (CSEK), where the customer provides the key with requests, are supported by some services.

More control brings more responsibility: if a customer destroys or loses its key, Google cannot recover the data. Most organizations use the default, and choose CMEK or external keys for specific compliance needs. Cloud KMS also logs key use, which helps with audits.

Key terms

Encryption at rest
Encrypting stored data; on by default for all customer data in Google Cloud.
Encryption in transit
Encrypting data as it moves across networks, for example with TLS.
CMEK
Customer-managed encryption keys: keys the customer creates and controls in Cloud KMS.
Cloud KMS
Google Cloud's service for creating, managing, rotating and using cryptographic keys.
Real-world example

A financial firm's policy requires that it can revoke access to its data at any time. It creates keys in Cloud KMS with a 90-day rotation schedule and uses them as CMEK for its BigQuery datasets and Cloud Storage buckets. Disabling a key would make that data unreadable, even to services processing it.

Exam tip: Encryption at rest is on by default; customers do not need to enable it. Choose CMEK in Cloud KMS when a question stresses customer control over key rotation, disabling or destroying keys.

Check yourself

Does a customer have to turn on encryption at rest in Google Cloud?

No. All customer data is encrypted at rest by default with Google-managed keys.

What is the risk of managing your own keys?

If the key is destroyed or lost, the data it protects cannot be recovered, even by Google.
