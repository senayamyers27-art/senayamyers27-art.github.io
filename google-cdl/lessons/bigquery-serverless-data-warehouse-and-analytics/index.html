BigQuery: serverless data warehouse and analytics

▶ Watch the overview video

Last reviewed September 25, 2026

BigQuery is Google Cloud's fully managed, serverless data warehouse. You load or stream data into it, or point it at data in other places, and query it with standard SQL. There are no servers, clusters or indexes to manage, and it can scan very large data sets, terabytes and beyond, quickly. It is one of the most important products for the data section of the exam.

Its architecture separates storage from compute. Data is stored in a columnar format, which means a query reads only the columns it needs, and processing power is allocated on demand from a very large shared pool. Because the two are separate, you can store a lot of data cheaply and pay for processing only when you run queries. Pricing has two parts: storage, and compute for queries, either on-demand by bytes processed or through reserved capacity. That is why good practice is to select only the columns you need and to use partitioned tables, instead of writing SELECT * over everything.

BigQuery does more than store tables. Data can arrive in batches or in real time through streaming. It can query data that stays in Cloud Storage or even in other clouds, through external tables. BigQuery ML lets analysts create and use machine learning models with SQL. Built-in geospatial functions, a large collection of public datasets, and connections to Looker, Looker Studio and spreadsheets make results easy to use.

Access is controlled with IAM at the project, dataset, table and even row and column level, and data is encrypted at rest by default. Many data sources, including Google Ads and other SaaS tools, can be loaded on a schedule with the BigQuery Data Transfer Service.

You can try it at no cost with the BigQuery sandbox, which offers a free monthly allowance of storage and query processing without a credit card. Querying a public dataset is a good first lab.

Key terms

Data warehouse
A central store of cleaned, structured data optimized for analytical queries.
Serverless
No infrastructure to provision or manage; capacity is allocated automatically.
Columnar storage
Storing data by column, so queries read only the columns they need.
BigQuery sandbox
A no-cost way to try BigQuery within free monthly limits, without a billing account.
Real-world example

A streaming music service loads billions of play events into BigQuery each day. Analysts write SQL to find which songs are gaining listeners by country, marketing builds a Looker Studio dashboard on the results, and a data scientist trains a churn model with BigQuery ML in the same place.

Exam tip: For large-scale SQL analytics without managing infrastructure, the answer is BigQuery. Cloud SQL runs applications' transactions; BigQuery analyzes data across the business.

Check yourself

Why does BigQuery separate storage and compute?

So each can scale independently: data is stored cheaply, and processing is allocated only when queries run.

What is one simple way to reduce BigQuery query cost?

Select only the needed columns (avoid SELECT *) and filter on partitioned columns so fewer bytes are processed.
