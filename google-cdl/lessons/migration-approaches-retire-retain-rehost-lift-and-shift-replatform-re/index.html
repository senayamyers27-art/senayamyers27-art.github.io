Google Cloud Certified Cloud Digital Leader Cloud Digital Leader · Domain 4: Modernize infrastructure and applications with Google Cloud

Migration approaches: retire, retain, rehost (lift and shift), replatform, refactor and reimagine

▶ Watch the overview video

Last reviewed September 25, 2026

When organizations plan a cloud migration, they choose an approach for each application. The industry often describes these as the 'Rs'. Google Cloud's training uses terms such as lift and shift, move and improve, and refactor or rebuild; the exam expects you to match each approach to a situation and understand the trade-off between speed and benefit.

Retire means shutting down an application that is no longer needed. Assessments often find unused or duplicate systems; retiring them saves money and reduces the migration's size. Retain means keeping an application where it is for now, for example because of a recent hardware investment, a regulation or a dependency that is not ready to move.

Rehost, or lift and shift, moves an application to the cloud as it is, typically from on-premises servers to Compute Engine VMs, with no code changes. It is the fastest approach and is common when a data center must be closed quickly. It delivers some benefits, such as no hardware to manage, but few cloud-native ones. Tools such as Migrate to Virtual Machines help automate it.

Replatform, or move and improve, makes targeted changes to gain cloud benefits without re-architecting. Examples include moving a self-managed database to Cloud SQL, or packaging an application in a container to run on GKE. It balances effort and benefit.

Refactor, or re-architect, changes the application's code and design, for example breaking a monolith into microservices or making it serverless. It takes the most effort but gives the most agility, scalability and cost efficiency. Reimagine, or rebuild, goes further by redesigning the business process or product itself, often replacing the old application entirely, sometimes with a SaaS product (repurchase).

Most organizations use several approaches at once. A common path is to rehost quickly to exit a data center, then modernize the most important applications over time.

Key terms

Rehost (lift and shift)
Moving an application to the cloud without changing it, usually onto VMs.
Replatform (move and improve)
Making targeted changes, such as adopting a managed database, while migrating.
Refactor
Changing an application's code and architecture to be cloud native.
Retire
Decommissioning an application that is no longer needed instead of migrating it.
Real-world example

An insurer must leave its data center in six months. It retires 15 unused applications, rehosts 60 onto Compute Engine, replatforms its policy database to Cloud SQL, retains a mainframe for now, and plans to refactor its customer portal into microservices over the next year.

Exam tip: Deadline and no time for changes: rehost. Small changes to use managed services: replatform. Rewrite for cloud-native benefits: refactor. Unused: retire. Not moving yet: retain.

Check yourself

Which approach is fastest but gives the fewest cloud-native benefits?

Rehost (lift and shift).

An app moves to Compute Engine and its database moves to Cloud SQL without code changes. Which approach?

Replatform (move and improve).
