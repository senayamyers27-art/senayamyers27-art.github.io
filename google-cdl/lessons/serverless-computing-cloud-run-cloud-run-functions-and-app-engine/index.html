Serverless computing: Cloud Run, Cloud Run functions and App Engine

▶ Watch the overview video

Last reviewed September 25, 2026

Serverless computing lets developers run code without provisioning or managing servers. The platform handles infrastructure, operating system patching, scaling and availability. Applications scale automatically with demand, often down to zero when idle, and you pay for the resources used while handling requests or events. Servers still exist, but they are entirely the provider's concern. Serverless lets small teams deliver quickly and avoids paying for idle capacity.

Cloud Run is a fully managed platform for running containers. You provide a container image, or source code that Cloud Run builds into one, and it gives you an HTTPS endpoint. It scales the number of instances up and down with incoming requests, including to zero, and bills for the resources used. Because it runs standard containers, you can use any language or library, and the same image could run on GKE or elsewhere. It suits web applications, APIs, microservices and jobs that run to completion.

Cloud Run functions (formerly Cloud Functions) runs single-purpose pieces of code, written in supported languages, in response to events: an HTTP request, a new file in a Cloud Storage bucket, a message published to Pub/Sub, or a change in a database. You write just the function; the platform handles everything else. It is ideal for glue code and lightweight automation, such as resizing an uploaded image or sending a notification when an order is placed.

App Engine is Google Cloud's original platform as a service for web applications. Developers deploy code in supported languages and App Engine manages the runtime, scaling and versions, including traffic splitting between versions. It is still used by many applications, while Cloud Run is often the choice for new containerized services.

Serverless is not ideal for everything. Workloads that need full control of the operating system, special hardware, long-running processes that must always be on, or very specific networking may fit VMs or GKE better.

Key terms

Serverless
Running code without managing servers, with automatic scaling and pay-per-use pricing.
Cloud Run
A managed serverless platform for running containers that scales automatically, including to zero.
Cloud Run functions
Event-driven serverless functions that run in response to triggers such as HTTP requests or new files.
Scale to zero
Running no instances, and incurring no compute cost, when there is no traffic.
Real-world example

A news site runs its API on Cloud Run so it scales up when a big story breaks and down to zero overnight. When a journalist uploads a photo to Cloud Storage, a Cloud Run function automatically creates thumbnails. The team never patches a server.

Exam tip: Containerized web app or API with no infrastructure to manage and scale to zero: Cloud Run. Small piece of code triggered by an event: Cloud Run functions. Code-based web app platform: App Engine.

Check yourself

What makes a service serverless?

No servers to manage, automatic scaling (often to zero) and pay-per-use billing.

Which serverless option would you use to run code each time a message arrives in Pub/Sub?

Cloud Run functions, triggered by the Pub/Sub event.
