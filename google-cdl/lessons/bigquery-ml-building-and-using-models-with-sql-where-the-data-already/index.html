BigQuery ML: building and using models with SQL where the data already lives

▶ Watch the overview video

Last reviewed September 25, 2026

Many organizations keep their most valuable business data in BigQuery, and many of their analysts know SQL well but not Python or ML frameworks. BigQuery ML closes that gap: it lets you create, train, evaluate and use machine learning models with SQL statements, directly inside BigQuery.

The workflow looks like normal SQL. You write a CREATE MODEL statement that names the model type and selects the training data from a table, and BigQuery trains it. ML.EVALUATE reports how accurate the model is, and ML.PREDICT applies it to new rows, returning predictions as query results you can join, store or show in a dashboard. For example, a model could predict whether each customer will buy again, based on their past orders.

BigQuery ML supports common model types, including linear regression for predicting numbers, logistic regression for yes-or-no classification, clustering to group similar customers, time-series forecasting for demand, and recommendation models. It can also connect to models hosted in Vertex AI, including generative AI models, so analysts can call them from SQL, for example to summarize text columns.

The key advantages are speed and simplicity. Data does not have to be exported to a separate ML system, which saves time, reduces copies of sensitive data and keeps existing access controls. Analysts can build useful models without waiting for scarce data scientists. Training uses BigQuery's scalable processing, and you pay through normal BigQuery pricing.

BigQuery ML is not meant for every problem. Highly customized deep learning, unusual model architectures or complex unstructured data are better handled with Vertex AI custom training. But for many structured-data business predictions, it is the quickest path from data to results. You can try it in the BigQuery sandbox with a small public dataset.

Key terms

BigQuery ML
A BigQuery feature for creating, training and using ML models with SQL.
CREATE MODEL
The SQL statement that defines and trains a model in BigQuery ML.
ML.PREDICT
The BigQuery ML function that applies a trained model to data to produce predictions.
Logistic regression
A model type that predicts the probability of a yes-or-no outcome.
Real-world example

A subscription box company's analysts write a CREATE MODEL query on two years of customer data in BigQuery to predict who is likely to cancel. They run ML.PREDICT each week and feed the results into a Looker Studio dashboard for the retention team, all without moving any data.

Exam tip: SQL-skilled analysts plus data already in BigQuery plus a common prediction task equals BigQuery ML. It avoids moving data and needs no Python.

Check yourself

What are two benefits of BigQuery ML?

Analysts can use SQL instead of learning new tools, and data stays in BigQuery with no export, keeping it secure and saving time.

Which BigQuery ML function returns predictions?

ML.PREDICT.
