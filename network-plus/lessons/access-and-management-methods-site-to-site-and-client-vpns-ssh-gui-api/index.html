Access and management methods: site-to-site and client VPNs, SSH, GUI, API, console, jump box, in-band vs out-of-band

Explain it simpler

Network devices need to be managed, which means someone has to log in and change settings. There are several ways to do that. You can connect over the network with an encrypted remote session, use a web page, or let a program make changes automatically for you. You can also plug a cable straight into the device, which works even when the network is broken. Companies often make administrators go through one guarded computer first, so every login is checked and recorded. And they keep a separate backup path, like a phone line, for when the main network fails. It is like having a front door key, a back door key and a spare key with a trusted neighbor, so a single lost key never locks you out.

It is 11:40 p.m. and you are working from home for Harborview Hotels. You type one more line into the access list on the router at the Lakeshore property, two hundred miles away, press Enter, and your SSH session freezes. The access list you just applied blocked your own management traffic. The router is still passing guest traffic, but you can no longer talk to it, and the nearest staff member who knows what a console cable is arrives at 9 a.m. The hotel's booking system needs a change on that router before morning. Is there another way in, and why should it have been planned long before tonight?

Administrators need secure ways to reach networks and manage devices, and they need a way in even when the network itself is broken. Every management method is also a potential attack path, because whoever controls the management interface controls the device. Network+ expects you to know the options, when to use each, and the security trade-offs: which methods encrypt, which scale, and which still work during an outage.
