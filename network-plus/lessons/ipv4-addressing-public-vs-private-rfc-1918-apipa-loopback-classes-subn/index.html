Explain it simpler

Every device on a network needs an address, like a house needs a street address. An IPv4 address is four numbers from 0 to 255, such as 192.168.10.25. Part of the address names the neighborhood (the network) and the rest names the house (the device); the subnet mask says where that split falls. Some address ranges are private, meant for use inside homes and offices, and many organizations reuse the same private numbers because they never appear directly on the internet. A few special addresses have fixed meanings: 127.0.0.1 always means 'this computer,' and an address starting 169.254 means the device could not get an address handed to it automatically. Subnetting means dividing one big neighborhood into smaller ones sized to fit.

It is Monday morning at Elm Grove Public Library, and Keisha at the circulation desk calls: 'The checkout PC says it has internet, but nothing loads.' You walk over and run ipconfig. The address reads 169.254.33.7, there is no default gateway, and the mask is 255.255.0.0. Ten minutes later, the branch manager forwards an email from the county: the new children's wing needs its own subnet for 70 devices, and the network team must carve it out of the existing address block without wasting space. Two problems, one skill. Before you touch DHCP or start drawing subnets, can you read what those numbers are already telling you?

An IPv4 address is 32 bits written as four decimal octets, such as 192.168.10.25. A subnet mask, such as 255.255.255.0 or /24 in CIDR notation, marks which bits are the network portion and which identify the host. Hosts with the same network portion are on the same subnet and talk directly using ARP (Address Resolution Protocol) and switching; anything else goes to the default gateway. Almost every troubleshooting question eventually depends on reading an address and mask correctly, so this is one of the most important skills for the exam.
