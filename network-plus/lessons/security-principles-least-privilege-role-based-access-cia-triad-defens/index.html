Security principles: least privilege, role-based access, CIA triad, defense in depth, zero trust, segmentation

Explain it simpler

Security principles are the big ideas behind every security tool. Instead of memorizing products, you learn a few rules that explain why each tool exists. Protect three things: keeping secrets secret, keeping data correct, and keeping systems working. Give each person only the access their job needs. Use several layers of protection, so if one fails another still helps. Never assume someone is safe just because they are inside the building or network; check every time. And split the network into separate zones, so a problem in one area cannot spread everywhere. Think of a ship built with watertight compartments: a hole in one compartment floods that section, but the ship stays afloat.

At 10:12 on a Wednesday, the receptionist at Willow Creek Architects opens an attachment that looks like a courier invoice. Within seconds, her PC starts encrypting files. You are the only network person on duty, and your heart sinks as you picture the project archives, the finance server and the plotters all on the same flat network. Then you remember last year's redesign: the reception VLAN, the trimmed-down accounts, the endpoint agent, the alerts feeding the security dashboard. Will any of it matter now? The answer depends less on any single product than on a handful of principles someone chose to follow.

Security principles are the ideas behind every specific control. Firewalls, virtual local area networks (VLANs), multifactor authentication (MFA) and encryption are tools; principles tell you why and where to use them. When an exam question describes a situation and asks which principle applies, or which design is best, these concepts are what it is testing. They also help in real work, because when you face an unfamiliar product or situation, you can still reason about it from the principles.
